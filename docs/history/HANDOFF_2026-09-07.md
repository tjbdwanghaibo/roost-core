## 2. 方法：承诺回退（promise revert）与 gap map

C2（空洞测试）单元的核心动作：把一条守卫 `if <cond> { return err }` 改成 `if (<cond>) && false {`，跑包测试；**还绿就是没人测这条承诺**。

脚本化版本：

```bash
# 采样一个或多个包，每包最多 N 条守卫；输出 GREEN（无覆盖）/ red / skip（编译不过）/ HANG
python3 scripts/gapmap/revertsample.py --max 20 --timeout 300 ./pkg ...
# 全仓，写 gapmap-report.md（nightly 用的就是它）
scripts/gapmap.sh --max 20
```

手工回退验证（单元第 5 步）用的一段循环，直接可复用：

```bash
S=/tmp/rv; mkdir -p $S; T='TestA|TestB'
for spec in pkg/file.go:123 pkg/file.go:130; do
  f=${spec%%:*}; ln=${spec##*:}; cp "$f" "$S/rv.bak"
  python3 - "$f" "$ln" <<'EOF'
import sys,re
p=sys.argv[1]; ln=int(sys.argv[2]); L=open(p).read().split('\n'); s=L[ln-1]
m=re.match(r'^(\s*)if (.*) \{$',s); assert m, s
L[ln-1]=m.group(1)+'if ('+m.group(2)+') && false {'; open(p,'w').write('\n'.join(L))
EOF
  n=$(go test -timeout 120s ./pkg/ -run "$T" 2>&1 | grep -c '^\s*--- FAIL\|build failed\|panic:')
  echo "$spec => $n"; cp "$S/rv.bak" "$f"
done
```

### 2.1 方法坑（每条都真踩过，账本第 9 节有原文）

| 坑 | 后果 | 做法 |
| --- | --- | --- |
| `a \|\| b && false` | 只关掉了 b | 条件必须整体加括号 |
| `if init; cond {` | 简单替换编译不过 | 写成 `if init; (cond) && false {`，或按文本改 |
| 跨行 `if` 条件 | 按行号的脚本断言失败 | 按文本中和（`) != 1 {` → `) != 1 && false {`） |
| 同一文本出现两次 | 文本替换只命中第一处，守卫被遮蔽 | 按行号改 |
| zsh `for x in $var` | 不分词，整个字符串是一个 spec，首轮全 0 | 用字面量列表或 `${=var}` |
| macOS 没有 `timeout` 二进制 | `timeout 120 go test` 命令不存在，grep 计数 0，看着像全没覆盖 | 用 `go test -timeout 120s` |
| 夹具让别的规则先拒绝 | 回退后测试仍红，误以为覆盖了 | 夹具要让被测规则是**唯一**可能的拒绝者：重封 CRC、重算摘要、合法载荷、`expectPlayerID=0` |
| "去掉守卫仍红"不一定是覆盖 | 下游同文案拒绝（前门冗余） | 记为"冗余"，不算红；能用副作用区分就加断言（如"被换掉的动作 Start 不得被调用"） |
| 回退后是 panic 而不是错误 | 计数里要算上 `panic:` | grep 模式含 `panic:`、`build failed` |
| 采样器跑的时候新建文件 | 早期 `gapmap.sh` 收尾 `git clean` 会删掉 | 已改成只还原已跟踪文件；仍别在采样时写文件 |
| 提交链用 `;` | 编译不过的测试被推上去（U-0084） | `go vet ./p && go test ./p && git add -A && git commit && git push` |
| `EntityKind` 是 uint8，掩码 255 | `uint64(kind) > EntityKindMask` 永远假 | 记为不可达，不要硬凑测试 |
