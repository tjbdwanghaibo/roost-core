# 修复后的组合契约复核

在修复改变错误返回、有效期、取消或关闭所有权时使用。这里只增加2026-10-04独立复审暴露的缺口；已有红绿、race、真实资源和提交规则继续按主skill执行。

1. **新增错误必须追到调用方。** 某store从吞掉拒绝改为返回stale/conflict时，检查Layered/ReadThrough、Kit/生成消费者怎样处理；覆盖不同读取来源、L1有效/过期/禁用窗口、删除后重建，以及远端成功但本地拒绝。断言调用方拿到的值、版本和提交结果，不能只断言新错误返回正确。新增竞争guard同时验证应拒绝和应成功：真正遗漏清理键要拒绝；同布局首次创建、重复删除、读后过期且清理清单仍覆盖当前键时不得误报，加入公开Layered/生成消费者而非只测底层。
2. **取消与关闭看最终状态。** 首次超时→被阻塞工作结束→新的有效context重试→资源真实关闭/可接管，至少形成一条有界回归；同时考虑永久退订错误、重复停止及callback重入。SDK Close若还要发RPC，读取其实际context来源与取消顺序；“Done已关闭/引用被保留”均不证明服务端已释放或还能重试。无连接替身不能验收连接drain。
3. **有效期和替身检查可观察后果。** 多hash Patch须检查未修改兄弟的TTL与整条Get的值/held，包含缺引用节点的控制。唯一索引比较正常值之外的missing/null/sparse；替身与后端差异若放过真实后端会拒绝的数据，要登记缺陷或明确拒绝不支持的场景，不能只写一条范围说明。
4. **已知退化不降格。** 写入42却读回0且held=true、候选lease残留阻止接管、重试永不收敛等违反既有承诺的事实，登记RR或追加同根因残余；只有缺少证据的场景才能写“未验证”。用户接受的边界必须有明确来源。观察夹具通过只证明现象，不证明行为正确。
5. **验证是场景清单。** 每个结论对应触发/预期/实际/源码SHA/资源/执行结果；分别列原触发、邻近分支与未执行外部资源。阻塞测试用自身有界等待给出行为失败，不能把包超时或编译失败当红。包/文件/叶子数量只作辅助，复用历史证据先核对影响路径及接口契约，不能只看被测文件hash。
6. **合并与验收分列。** 用提交祖先关系确认修复已包含；合并后检查双方同文件逻辑/参数并运行受影响场景，报告“已合并、原触发验证、组合/外部验证”三个状态。修复批次跑根包`GOWORK=off go test -count=1 .`并查看main的ci本身；旧CI红不能遮蔽新错误，运行中不能称绿。当前API/关闭语义/指标变化搜索使用指南、README、面板和生成器说明，改整句话，不能只划掉旧指标而保留错误行为描述；历史报告保留并追加更正。

本清单不扩大修复授权，不要求无关模块重审或等待CI。资源不可用时保留待验状态与复跑条件，不用弱替身宣称外部验收。仓库复盘记录：`docs/review/REVIEW-2026-10-04-fix-audit-retrospective.md`。
