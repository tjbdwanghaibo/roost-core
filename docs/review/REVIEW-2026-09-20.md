## 本轮新增问题

2. RR-20260920-02：latest-only datagram 覆盖已经提交 dirty 的 room delta；
3. RR-20260920-03：玩家租约 compare 与 expire/delete 分离，存在 ABA；

W-2026-09-20-01 已由“再观察”转 RR-02，原因是现有 Core 测试稳定证明 same-stream 中间 datagram 被覆盖，而 room/entitysync 在入队成功时已经提交 dirty，二者组合足以解释最后字段永久缺失。W-2026-09-19-01 转 RR-01，但更正了根因：负版本转换有保护，直接失败的是未编码的 uint64 checksum。

## 实现与架构评价

本批新增功能的大方向是好的：versionstore 把值与二级索引收进同一 Lua，activity 把“尝试”归到实际领取者，Saga 的 Admit hook 让所有权拒绝发生在 inbox claim 前。这些修复都在减少跨层窗口。

本轮五项问题有一个共同模式：上层把“下层接受”当成状态已经安全交接，但下层实际提供的是可覆盖队列、租约或有限编码域。

- room 把 enqueue 当成交付基线，而 datagram 队列允许覆盖；
- player owner 把 SID 相等当成实例所有权，而租约没有 incarnation/fence；
- remote commit 把 Go 的 uint64 类型域直接当成 BSON 类型域；
- platform 把逐项继续处理当成 poison 已隔离，而固定页首仍可被占满。

后续实现应把这些“接受之后谁承担完成责任”写进类型和原子操作，而不是只靠注释约定。完整机制和分步验收见[增量、租约与持久化边界](IMPLEMENTATION-DELTA-TRANSPORT-AND-LEASE-FENCING.md)。
