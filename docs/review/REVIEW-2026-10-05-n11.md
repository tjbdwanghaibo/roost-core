## 4. 观察（不改行为）

- **O1** `BlockIndex` 每块一把锁，多块查询（`QueryRect` / `QueryBlocks` / `RangeBlocks`）不是快照：跨块 Move 与查询交错时，一直在查询范围内的 id 可能两块都没读到。唯一调用方 AOI 单线程使用，无触发路径；补了注释说明，不立 RR。
- **O2** `GridTerrain.RectBlocked` 遍历全部障碍，与矩形面积无关；障碍多时偏贵，正式调用方未使用。
- **O3** `FindPath` 的邻点 ±1 与曼哈顿距离对自定义 Terrain 在 int64 极值处会回绕；`GridTerrain` 的 bounds 从 0 开始，不受影响。
- **O4** game-demo `PathFindSystem.Stop` 无锁置 `terrain = nil`，与 `Path` / `Place` 并发会是数据竞争；已知调用方（`enter_scene` handler、刷新系统）都在 Scene 的 Nest 锁内，本轮未穷举所有入口。
- **O5** Tick 期间对不在堆里的 id 调 `RemoveTimer` / `ChangeTimer` 一律返回 true（含不存在的 id），推迟执行时找不到就静默放弃。返回值语义是“已接受”，不是“已生效”；保持推迟是为了“同 handler 新建再取消”成立。
- **O6** 同一期限的定时器触发顺序由堆决定（确定但不是登记顺序）。World 的 `pin` 让同一 Tick 武装的节点期限完全相同；目前 World 只有一种定时器、彼此无依赖。若业务需要 FIFO，应在 `timerHeap.Less` 用 ID 作第二键，属行为变化，待需求。
- **O7** 存储的节点类型没有注册 handler 时，到期即删除（发 ChangeDelete），无日志；以后移除一种定时器类型会静默丢掉存量节点。
- **O8** `startActivity` 返回的 stop 函数不幂等（第二次调用永久阻塞在 `<-done`），由 `Service.Shutdown` 调用后置 nil 保证只调一次；`Init` 在 `startActivity` 之后失败时，两条循环不会被停止（归 N01 / N14 的 Init 失败收尾）。
- **O9** `tickWorld` / `openCurrentWindow` 用 `time.Now()`，不跟 `time.logic_offset`（`clock.Now`）；两端一致，所以 World 堆内部自洽，但用逻辑时间偏移测活动窗口时窗口不动。该配置项没有文档。
- **O10** `logicClock` 以毫秒存偏移（`Milliseconds()` 向零截断）：`Set(t)` 之后的 `Now()` 可能比 t 早不到 1ms。没有调用方使用 `Set`；`time.logic_offset` 通常是整秒。
- **O11** `index` 包仓内零调用方，见方向判断。

## 5. 方向判断

- **World 定时器堆（NC-140）是“组件内存不随 Nest 回滚”的第三次出现**：NC-61（属性层，N07）、N09 观察 O1（skill Runtime 状态）、本轮 NC-140。每次都在模板 / 组件里单独登记 undo。这说明缺的是一条框架契约：Nest 只回滚 DAO，组件内存要么能从 DAO 派生、要么自己登记逆操作，而生成器与组件模板对此没有任何提示或检查。建议维护者在两条方向里选一条：①（代价小）在 roost-coding 与组件模板注释里写明“组件内存是 DAO 的派生缓存，凡在 `rollback=undo/state` handler 里改它的方法，第一次修改前登记 `RecordUndo`”，并在 codegen 的 component 模板里给出骨架；②（代价大）让 Nest 在回滚后调用组件的“从 DAO 重建”钩子（`OnRollback`），把逆操作从逐个组件手写改为一个统一入口——需要改 entity / nest 接口，属核心线。本轮按 NC-61 的既有做法修，不改核心。
- **timer 的“Tick 期间推迟一切”**：NC-141 与 NC-147 都来自同一个简化——用一个 `running` 布尔把 Tick 期间的全部操作推迟。修复只把“目标仍在堆里”的情形改为立即生效、重入只由最外层收尾，没有增加新状态；若以后再出现 Tick 期间语义问题，应把推迟队列改成按节点身份的显式状态（pending add / firing），而不是继续加分支。
- **index**：零调用方的公开泛型包，本轮三条 P3 都是合法输入上的 panic / 静默丢写，修复很小。建议维护者决定保留（作为公开 API 维护）还是移除；移除是破坏性 API 变化，需要发版说明。

## 6. 本轮没有做 / 没有验

- 真实 WAL / Mongo 三进程链路里让 `ArmActivity` / `TickWorldTimers` 的提交被拒（本轮用 `nest.RunIsolatedTransaction` + 拒绝的 committer，与 NC-61 同一机制）；Nest 对可重试拒绝重排重跑 handler 的路径只由同一 undo 机制推出。
- 多进程同时加载同一 World 时各自堆的一致性（属 World 归属 / 静态绑定，不在本单元）。
- AOI 并发使用 `BlockIndex` 的场景（AOI 声明不并发安全）。
- game-demo 场景系统所有入口是否都在 Scene 锁内（O4）。
