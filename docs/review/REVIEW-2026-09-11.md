## 扩展发现与实现判断

新增 RR-20260911-01（P2）：Mail 墓碑只按计数保留，没有保证覆盖信封有效期。200 条新的结算淘汰记录可以在旧信封仍有效时挤掉旧身份；独立测试 400 秒后得到 token-202。原短序列修复有效与此风险仍存在可以同时成立。作者已披露残余形状，本轮补了可运行证据并建立单独追踪。

新增 RR-20260911-02（P3）：Mailbox.clone 遗漏新增 map，公开读取副本可修改内存存储的墓碑。只确认 MemoryStore 场景，不把其影响扩大到 Redis 持久化。

远程事务修复让等待者直接持有 trackedRemoteTransaction 返回的指针，首次读取和唤醒读取都不再依赖 map 条目继续存在，读写仍用 txMu；这比仅对 nil 返回 Unknown 更符合已经完成的等待调用契约。TTL 用例直接向 prune 函数传入未来清理时间，不依赖 sleep，也没有手删 tracker。

技能修复将 CompletedCastOrder 单独拷贝入快照，恢复按记录顺序筛选终态、去重，缺项沿序列化 Cast 顺序追加。当前新快照的原端到端场景通过。旧快照缺字段只能沿旧 ID 顺序退化，无法恢复历史上从未保存的信息；未宣称旧快照跨版本能补出原完成顺序。

RootEvent/ProcLedger 的恢复保留、category 改值后的实际存储键迁移、finalizer 停机交接仍需独立场景。本轮只确认读到 RootEvent 恢复后按 ID 排序，未建立非单调合法输入的完整前史，不据此新增 bug，也不写成已验证无问题。
