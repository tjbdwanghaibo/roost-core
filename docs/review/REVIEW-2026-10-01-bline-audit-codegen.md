## §4 确定的缺陷

### D1 · P2 · 有 schema 但 `configs/table` 尚无 CSV 的工程，`roost generate` / `project sync` / `generate --check` 从通过变为失败（v1.17.2 → HEAD 回归）

- **现象**：HEAD `roost generate` 报 `generator config-data: open configs/table/item.csv: no such file or directory`，exit 1；同一输入 v1.17.2 的 `roost` exit 0（跳过 config-data）。`project sync` 与 `--check` 同样失败（二者都运行生成器）。
- **触发**：标准脚手架（`roost project new … -mods configdata`，`configs/data/_manifest.json` 总会被写出）+ 在 `configs/schema` 写一个 `//roost:table` 类型 + `configs/table` 为空或不存在。实验目录 `scratchpad/audit-codegen/nocsv-head`（HEAD，失败）、`nocsv-old`（v1.17.2 二进制通过；同目录换 HEAD 二进制失败）；删掉 `_manifest.json` 后 HEAD 才通过（`nocsv-head2.log`），但脚手架 / sync 会把它写回。
- **根因**：`153cac3d` 把 `codegen/internal/roost/generate.go` 的 config-data 生成器从“CSV 目录空则跳过”改为“CSV 目录空但 `_manifest.json` 存在就跑 tablegen”（HEAD `generate.go:107-116`）。目的是让零 meta 的 JSON 退役能进入暂存树，但它同时覆盖了“meta 非空、CSV 还没写”这一旧版容忍的状态：`tablegen.convertCSVToJSON` 对每个 meta 无条件 `readCSVRecords(csvDir/meta.File)`（`tablegen/main.go:365`），文件不存在即失败。manifest 永远存在，所以旧的跳过分支实际已死。

## §5 疑点与不一致

1. **servicerpc 孤儿匹配依赖 `-dir`/`-out` 字面拼写**（`run.go:184`，`regenerateCommand`）：同一目录用 `-dir .` 与 `-dir ./rpc` 生成的文件互不认账，`-check` 对不认账的孤儿 exit 0（§2 实测）。RR-01 已写“不同字面路径调用同一目录也可能不匹配”；`roost generate` 固定用 `-dir ./internal/rpc/<name>`，`go:generate` 指令自带拼写，所以正式链路自洽。保留为疑点：CI 门禁在指令拼写被改动后会静默放过旧产物。
2. **protocol 直接 CLI 的半失败**：空定义 + bootstrap 路径不可写时，六份旧输出已删、bootstrap 未写（§2 实测）。RR-02 的“先验证模块与空 bootstrap 内容，再退役旧输出，最后写入”只覆盖内容校验，不覆盖写失败；记录另有“直接 CLI 的多文件删除不是跨文件原子操作”，`roost generate` 走暂存不受影响。不登记。
