## 实际验证

Go 1.27.0，Windows amd64，CGO_ENABLED=1；临时 go.work 指向三仓，不修改模块依赖。旧、新用例均通过临时 Go overlay 注入。

| 验证 | 结果 |
| --- | --- |
| 原 Remote 64 个真实 batch、Stop 后 Close | PASS，包 1.593s |
| 原 Nest 已注册 handler 的延迟 Request 停机 | PASS，包 1.596s |
| remoteentity / nest 完整包 race，无 overlay | PASS，2.661s / 2.729s |
| 原 Mail 副本隔离；适配新拒绝契约的原容量 API 序列 | 两项 PASS |
| 新 Mail 拒绝原子性 | FAIL：插入已生效、墓碑 200→201、版本未变、Unread 少 1；同次 overlay 包 1.101s |
| Mail 完整包 race，无 overlay | PASS，2.064s |
| 新 Remote 64 个 Close 与 Stop 同时放行 | PASS，1.628s；Stop 与所有 Close 结束后 queue/slots 均为 0 |
| 新 Nest 真实 Request 内部重排停机、停机后重排 | 两项 PASS，包 1.613s；明确 ErrNestStopped，后者仅一次回复 |
| Mail 仅隔离 Update 回调输入的对照 | PASS，2.046s；同一拒绝序列状态与版本完全不变 |

Mail 容量旧测试曾以“墓碑已消失”作为到达缺陷的前置诊断，因此不能原样将该诊断失败视为修复失败。本轮保留相同公开 API churn 序列，允许新的 ErrClaimHistoryFull 中断，并改为断言原身份仍在、信封仍有效且领取返回 ErrAlreadyClaimed。副本隔离复现行为未改变。测试全文和命令见[附录](../bug/REPRO-2026-09-11-03.md)。

## 新增覆盖与结论

- U-0173 将外部 Close 纳入停止屏障，源码证明 stopping 检查与 WaitGroup 注册在同一锁下；新增并发用例补上原先仅测停止前/后的窗口。单次交错验证不是所有调度穷举。
- U-0172 的统一回复也覆盖内部重排队列。用真实 Nest Request、合法 handler 和待完成的实体组迁移状态触发自动重排，再关闭；handler 未执行且请求取得停止错误。没有人为替换 dispatcher 队列。
- U-0171 对新领取记录保持期限；旧无窗口墓碑仍按计数老化，这是修复说明已披露的风险，本轮未动态迁移验证。
- 新 [RR-20260911-05](../bug/REVIEW-2026-09-11-03.md) 表明容量拒绝需要同时证明对象所有权与原子性。U-0170 只解决读取副本，并未覆盖 Update 输入。

本轮没有新性能基准，不将上轮测量重新标为当前性能验收。真实 Redis/Mongo、Linux 压力、慢持久化 ticket/回调、混合版本迁移仍未验证。下一轮优先复核新 P3 修复，再继续真实后端停机交接或 completion 慢确认路径。[进度](PROGRESS.md)与[Mail 实现学习](IMPLEMENTATION-MAIL-RETENTION-AND-ATOMIC-REFUSAL.md)已更新。
