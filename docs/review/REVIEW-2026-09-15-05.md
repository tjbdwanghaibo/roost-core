## 机制、设计和性能

已沿 room.flushStateBatch → entitysync.DistributeBatch → RoomEnvelopeSink → RoomTransportSink → AtomicBatchTransport 阅读本轮边界；新增深入的实际实现为 AsyncTransport.AdmitBatch。原子性应分别看 dirty/version、帧号、传输 object refs、队列准入和剔除通知，而不是只看最终 error。

RoomEnvelopeSink 仅在下游成功后推进计数；RoomTransportSink 对 object refs 建临时 plans；AsyncTransport 在所有队列校验通过后统一入队。这些边界的拒绝对照正常。慢消费者策略会在整体结果确定前执行不可撤销的连接剔除，所以通知不能随着失败结果一起丢弃。

性能源码观察：RoomEnvelopeSink 每实例串行准入；RoomTransportSink 使用 256 room 分片锁；AsyncTransport 先复制载荷再获取队列锁，避免持锁编码但失败批次仍有复制开销。并发房间碰撞、实际吞吐和尾延迟未测量，不据此登记性能 bug。

flushStateBatch 对准备失败的主体重排队，仍可能分发其余成功准备的主体：当前批次原子性针对 prepared 集合，不是房间 tick 所有主体的快照原子性。本轮作为源码边界记录，未将其定性为 bug。学习文档见[房间准入与剔除交接](IMPLEMENTATION-ROOM-ADMISSION-AND-EVICTION.md)。
