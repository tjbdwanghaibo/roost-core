# RR-20261004-06：etcd Campaign 在 session 建好后的失败 / 取消分支不再撤销 lease，候选键或领导键残留到 TTL（缺省 60s），其他候选选不上

日期：2026-10-04。基线：v1.19.0（`74e1ba39`）。来源：[B 线 NC 修复独立复审（第二组）§3](../review/REVIEW-2026-10-04-nc-audit-2.md)。等级 **P2**。状态：已确认，未修复。

## 现象、根因与修复约束

NC-11 修复引入的回退。根因 `1502f973` 的 `etcd/driver/election.go:122/132/138/147/154` 在 `session.Close()` 之前先 `cancelSession()`；etcd SDK 的 `Session.Close` 用同一个已取消的 ctx 发 Revoke，立即以 Canceled 失败。真实 etcd：v1.19.0 `lease_ttl_after_failed_campaign=59 candidate_keys=1`（日志 `LeaseRevoke … context canceled`），修前 `1502f973^` `ttl=-1 keys=0`；成功与取消竞争分支里另一候选 3 秒内选不上。修复约束：失败 / 取消分支不能先取消 Revoke 用的 ctx——删掉 Close 前的 `cancelSession()`，caller 已取消的分支改为 `Orphan()` 后由 election 持有一个唯一、有时限的 Revoke 任务；保留 NC-11 “setup 取消与长期 session 分离”的承诺。真实 etcd 回归（`/opt/homebrew/bin/etcd`）。

测试草稿在审计 scratchpad `audit-nc2-drafts/`（未入库）。

## 修复（2026-10-04）

状态：**已修复，本地验证通过（含真实 etcd v3.7.1），未发版。** 修复记录：[docs/bugfix/RR-20261004-06.md](../bugfix/RR-20261004-06.md)。

五个失败分支不再先 `cancelSession()`，统一交给 `election.abandon`：同步 `Orphan()` 停 keepalive，再由 election 用 `cli.Ctx()` 派生、5s 截止的独立 context 发唯一一个 Revoke；caller 还在等就等它结束（返回时键已删除），caller 已取消就立即返回，下一次 Campaign 入场等这个 Revoke，关闭 client 会取消它。只删 `cancelSession()` 不够：caller 已取消的分支里 AfterFunc 桥已经取消了 `sessionCtx`。正常 Resign 与 NC-11 的 setup 取消承诺不变。

真实 etcd 回归 `etcd/driver/real_etcd_election_promises_test.go`（integration tag）修前三条全红（`lease_ttl_after_failed_campaign=59 candidate_keys=1`、`other_campaign_err=context deadline exceeded first_lease_ttl=56`、`standby_lease_ttl=57`），修后 `ttl=-1`、另一候选即时当选；单元回归 `etcd/driver/election_revoke_promises_test.go`。
