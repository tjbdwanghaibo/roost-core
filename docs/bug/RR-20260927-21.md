# RR-20260927-21：同一 Guard 内自己撤销的新建实体，外层再建同 ID 被当成暂时锁冲突，可回滚事务空转重排到上限

日期：2026-09-27。基线：`ffcf902`（v1.17.1）。来源：第五轮独立审计（[REVIEW-2026-09-27-audit5](../review/REVIEW-2026-09-27-audit5.md) N1）。等级 **P4**。引入：RR-20260926-81 修复。状态：已复现，未修复。

触发：可回滚 handler（state + strict）内先 `RunIsolatedTransaction`，其中新建 X 后让独立事务失败；独立事务回滚撤销 X，撤销收尾挂在**同一个 Guard** 上，要等整个 handler 释放才执行；外层随后再新建同一个 X。
`entity/manager_factory.go` `CreateInScope` 的 `capturer != nil && errors.Is(err, ErrEntityRemoved)` 分支（RR-81）把它当成别的持有者造成的暂时冲突，返回 `ErrLockTimeout` + `ErrCreatedEntityLockConflict`；
而这个冲突在一次执行内是确定的，每次重排都重现：handler 执行 401 次、耗时约 2.2s，最终回复按 USER_GUIDE §4 判别表属于“可重试”，调用方重试会再空转一轮。memory handler 只执行 1 次，但文案写“locked by another holder”，实际是它自己。
修前（`36745f7`）两种 handler 都 `attempts=1`、回复 `entity removed: … is being removed`。

审计员探针输出（`aud6-logs/probe81.txt`）：HEAD `PROBE P81 meta=state/strict: attempts=401 elapsed=2.229s ... lockTimeout=true conflict=true removed=false`；基线 `attempts=1 elapsed=1ms ... removed=true`。

修复约束：区分“撤销收尾挂在当前 Guard 上（本 handler 自己撤销的）”与“别的持有者撤销 / Destroy 收尾中”。前者是确定失败：不重排、回复带可 `errors.Is(ErrEntityRemoved)` 的错误并说明是本 handler 内已撤销的同 ID，
文案不得写 another holder；后者保持 RR-81（可回滚整条回滚重排，不可回滚按 RR-64 返回冲突哨兵）。不在快 worker 上等待；RR-48/64/81 回归不回退；USER_GUIDE 判别表同步。
