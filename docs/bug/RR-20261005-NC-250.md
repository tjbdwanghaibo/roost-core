# NC-250：定义缺失 fence 时，重试退避中的步骤没有关闭为“放弃”，之后生效的成功被静默丢弃

2026-10-06，基线 `897a1dd9`。**P3**。状态：已复现，已修复（见文末）。[本轮](../review/REVIEW-2026-10-06-n06s5.md) · [证据](../bugfix/evidence/NC-250/)。来源：N06 S5 剩余项“deadline / compensation / Resume 与晚 receipt 的其余交错”。

## 触发与差异

`saga/engine.go` `processClaimed` 的定义缺失分支（基线 :717-733）把记录 fence 到 `ManualRequired`，`CloseOperation` 传的是 `record.OperationKey`。
协调器在等结果（`Waiting`）时它是当前操作；步骤正在重试退避时（上一次尝试超时或可重试失败、`Attempt > 0`）`retryState` 已把 `OperationKey` 清空，传进去的是空串。

- 预期（SAGA.md「原生步骤执行契约」第 4 条）：协调器在“重试用尽、saga 截止、人工 `Compensate` 或定义缺失时”关闭操作，tombstone 记“放弃关闭”，
  同一事务删掉它仍排队的命令；之后到达的成功说明那一步已生效却不在 `CompletedSteps` 里、不会被补偿，记 ERROR 与
  `saga.completion.late_after_abandon_total`。
- 实际：退避中被 fence 时不写 tombstone、不删排队命令。较早尝试的成功之后到达，`Complete` 走 `completeNotWaiting`，
  `CompletionHistory` 既无回执也无 tombstone，返回 `ErrNotWaiting`：原生结果流按永久错误 Term，普通结果流 nak 到 `MaxDeliver`，都不告警。
  被放弃尝试的排队命令照常发布（步骤侧按过期 ack，无害）。

同形态的两个出口在 U-0280 已按 `Attempt > 0` 补了关闭：截止分支（基线 :734-742）与人工 `Compensate`（基线 :390-394）。定义缺失是第三个出口，漏了。

## 影响

滚动升级期间某个协调器缺少某个定义版本，领到一条退避到期的记录就会 fence 它。退避中的那次操作仍可能生效：Mongo 步骤的 handler 在截止前开始、之后提交；
原生步骤截止前已投影、completion effect 发布延迟。修好定义后运维按 T-226 `Resume`：已有完成步骤时进入补偿，补偿不含这一步；没有人被告知这一步生效过。
概率低（需要定义缺失 + 退避中 + 迟到生效三者同时），后果是一笔静默的、未被补偿的业务效果，与 U-0280 告警要覆盖的情形相同。

## 复现

`saga/definition_fence_abandon_promises_test.go` `TestDefinitionFenceDuringBackoffAbandonsTheOperation`：正式 `MongoStore`（mongotest），
有定义的协调器派发第一次尝试并判超时进入退避，没有定义的协调器领到它 fence 到 `ManualRequired`，第一次尝试的成功随后到达；正向、补偿两个方向。修前（全文 [red-before.txt](../bugfix/evidence/NC-250/red-before.txt)）：
