# RR-20260926-11：已提交的 Remote 事务发布失败后重放，被同实体更新的 fence 拒绝，WAL 投影永久卡住

**当前状态：已修复并完成适用本地验证，未提交/发布。** 见[修复与边界](../bugfix/RR-20260926-11.md)。以下保留原审查基线。

日期：2026-09-26。基线：main `aaada47`。等级 **P1**（全部实体的持久投影停止，只能重启恢复；一次瞬时 NATS 抖动即可触发）。
状态：已复现（探针，已删除），源码已核对，未修复。来源：上线前复审（Remote 持久权威）。

## 触发条件（生产串行装配即可）

1. WAL 记录 tx1 的 Mongo 原子事务已提交，投影器随后调 `Manager.ApplyRemoteCommits` 发布时瞬时失败（NATS 发布或 `MarkRemoteCommitPublished` 出错），
   tracker 置为 Indeterminate，`Project` 返回错误。
2. finalizer 看到 Indeterminate，回源后端得到 Applied，自行发布并标记 Committed，释放 write gate（Strict 写在等待者被唤醒后立即执行，通常快于投影器 10ms 起步的退避）。
3. 同一实体排队的下一个写者进入，`GrantWrite` 拿到更大的 fence，并在 `remoteentity/batch.go:293` 写入活实体的版本向量。
4. 投影器重试 tx1：`checkTransaction` 判定已应用，再次调 `ApplyRemoteCommits`，其中 `afterRemoteCommit` 用 tx1 的旧 fence 更新活实体。

另一条路径：若启用 D2 并行窗口（`dataengine/engine/projector_remote.go:103-111`，只 ack 连续成功前缀、成功后缀会重放），成功后缀中的热点实体同样会卡住
（正式装配里并行实际未开启，见 RR-20260926-21）。

## 预期 vs 实际

预期：已提交、已发布事务的重放幂等，WAL 能 ack。

实际：`entity/entity_remote.go:88-89` 见旧 fence < 当前 fence 返回 `ErrRemoteFenced`；`remoteentity/transaction_manager.go:441-445` 把它包成
`ErrRemotePersistenceIndeterminate`；`dataengine/engine/mongo_projection.go:130-133` 返回错误。该错误不在 `projector.go:338` 的 fatal 类里，
投影器按 `projector_replay.go:150-160` 无限退避重试，WAL 头部永远不能 ack，其后所有实体、所有记录都无法投影。新写者自己的记录排在后面且占着 gate，
活实体 fence 不会回退，形成自锁；只有重启（无 wrapper，重放跳过活实体更新）能恢复。

## 根因（代码）

`remoteentity/transaction_manager.go:684-713` 的 `afterRemoteCommit` 对“重放的已提交事务”也无条件更新活实体并 Acknowledge，
没有区分“已被更新代际取代（stale fence，应视为已完成）”与“真正失败”。

## 复现

审查 agent 探针（`remoteentity` 包内，mongotest 伪 Mongo + 真实 nestwal WAL + 真实 `engine.Projector`/`MongoStore`，已删除，源码未保留）：

```text
单元级（Manager + MongoCommitter，MarkRemoteCommitPublished 注入一次失败）：
projector retry #1..#3: remote entity persistence outcome is indeterminate / remote entity: writer fenced
端到端串行（生产装配 Backend 作 atomic store；投影重试调成 300ms 只为让竞态确定）：
projector stats: unacked=2 projected=0 failures=13 fatal=0 lastErr="... remote publication: remote entity persistence outcome is indeterminate\nremote entity: writer fenced"
tx2 strict commit 超时
端到端并行窗口（MongoCommitter 作 remoteStore）：
unacked=2 projected=2 failures=97 fatal=0 lastErr="... writer fenced"
```

复审方已按源码核对 `entity_remote.go:88`、`transaction_manager.go:441-445,684-713` 的行为；未独立重跑探针。

## 实施方向（约束）

- 重放已提交事务时，活实体已处于更新代际应视为该事务的本地效果已被覆盖，不能返回可重试错误；也不能把真正的失败吞掉。
- 不放宽 `SetRemoteVersionVector` 对 stale fence 的拒绝（它保护的是持有过期租约的写者）；区分应发生在重放/发布路径。
- 与 D2 并行窗口的后缀重放一并覆盖。

## 验收覆盖点

- 发布注入一次失败 + finalizer 抢先完成 + 同实体下一写者拿到新 fence：投影器重试后 ack，无无限重试；新写者正常提交。
- 真正的发布失败仍保持可重试且最终发布；stale fence 写者仍被拒绝。
