# RR-20260928-10：install.sh 升级失败时自动回滚到不含 `configs/data` 的旧 release，回滚也过不了 readiness（推断）

日期：2026-09-28。基线：本地 main `e10b950`。来源：批次 18 核对 RR-20260928-05 兼容性时的源码推断。等级 **P3（推断，待实证）**：升级失败时自动回滚失败，服务停在不可用状态。引入：RR-20260928-05（unit 的 `WorkingDirectory` 改为 `$APP_ROOT/current`）。状态：已确认（源码），未实跑。

生成的 `install.sh` 在切换 `current` 之前就改写了 systemd unit；升级失败触发自动回滚时 unit 不回退、`current` 切回旧 release，而 RR-20260928-05 之前安装的旧 release 里没有 `configs/data`，用 configdata 的服务回滚后同样 `stat dir configs/data` 失败，
结局是“rollback also failed readiness”；此前手工在 `$APP_ROOT/configs/data` 放过数据的部署修前能回滚、修后不能。

修复约束：先在临时根下按生成的 `install.sh` 演练“新版本 readiness 失败 → 自动回滚”（不调用 systemctl、不写系统目录，沿用 RR-20260928-05 的演练手法）证实；证实后让回滚可用——例如回滚时一并回退 unit，或旧 release 缺 `configs/data` 时从新 release / `$APP_ROOT/configs/data` 补齐后再回滚，或在切换前拒绝（二选一论证）；加生成器回归；`rollback.sh` 的手工回滚同样核对。
