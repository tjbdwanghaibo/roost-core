# RR-20260928-10：install.sh 升级失败时自动回滚到不含 `configs/data` 的旧 release，回滚也过不了 readiness（推断）

日期：2026-09-28。基线：本地 main `e10b950`。来源：批次 18 核对 RR-20260928-05 兼容性时的源码推断。等级 **P3（推断，待实证）**：升级失败时自动回滚失败，服务停在不可用状态。引入：RR-20260928-05（unit 的 `WorkingDirectory` 改为 `$APP_ROOT/current`）。状态：已确认（源码）；2026-09-28 临时根演练实证，已修复（见文末）。

生成的 `install.sh` 在切换 `current` 之前就改写了 systemd unit；升级失败触发自动回滚时 unit 不回退、`current` 切回旧 release，而 RR-20260928-05 之前安装的旧 release 里没有 `configs/data`，用 configdata 的服务回滚后同样 `stat dir configs/data` 失败，
结局是“rollback also failed readiness”；此前手工在 `$APP_ROOT/configs/data` 放过数据的部署修前能回滚、修后不能。

修复约束：先在临时根下按生成的 `install.sh` 演练“新版本 readiness 失败 → 自动回滚”（不调用 systemctl、不写系统目录，沿用 RR-20260928-05 的演练手法）证实；证实后让回滚可用——例如回滚时一并回退 unit，或旧 release 缺 `configs/data` 时从新 release / `$APP_ROOT/configs/data` 补齐后再回滚，或在切换前拒绝（二选一论证）；加生成器回归；`rollback.sh` 的手工回滚同样核对。

## 实证与修复（2026-09-28）

实证：基线 `f617a95`，在临时根下按生成的脚本演练（PATH 替身代替 root / systemctl，不写系统目录，不连任何外部服务；服务是只带 configdata 的最小生成工程，本机编译的真实二进制，无依赖即可到 readiness）。先用 RR-20260928-05 之前的 install.sh（`c5857a5` 生成器）装 v1，运维在 `$APP_ROOT/configs/data` 放好数据表，v1 正常就绪；再用基线 install.sh 装一个起不来的 v2：

```text
deployment health check failed for zz19p-game-1003 version v2; rolling back
rollback also failed readiness; manual recovery required
install v2 exit=1
current -> <root>/opt/roost/zz19p-game-1003/releases/v1
unit loaded:    WorkingDirectory=<root>/opt/roost/zz19p-game-1003/current
cwd resolved: <root>/opt/roost/zz19p-game-1003/releases/v1
"err":"mod config_data start: configdata: stat dir configs/data: stat configs/data: no such file or directory"
```

推断成立。`rollback.sh` 同样：v2 正常升级后 `rollback.sh game 1003 v1` 在新 unit 下起 v1，报 `rollback target failed readiness; restored previous release`（exit 1，切回 v2，服务可用，但回不到 v1）。对照：两次都用基线 install.sh 安装时自动回滚正常。

根因：`codegen/internal/roost/render_deploy.go`（基线行号）install.sh 在 `:141` 直接覆盖 `$UNIT_PATH`，`:197-198` 切换 `current` 后 `daemon-reload`；`:207` 回滚只把 `current` 切回上一个 release 再 restart，unit 仍是新版本写的那份。rollback.sh `:364` / `:381` 同样只切 `current`。

状态：**已修复**（本地提交，未推送 / 发布）。每个 release 的 unit 记在 `$APP_ROOT/units/<version>.service`，覆盖前先把正在用的那份记给当前 release，自动回滚与 rollback.sh 切换 `current` 时一并装回目标 release 的 unit 并 `daemon-reload`。见[修复记录](../bugfix/RR-20260928-10.md)。
