# NC-114：presentation reset 不经过 VisibilityPolicy，不可见施法者的持续表现、目标与坐标发给所有 observer

2026-10-05，基线 `855c2a38236f4efc9575fa9ba84bf8bf4100daf3`。P2（可见性泄漏：observer 看不到的实体，其正在进行的 cast / process 表现、目标 ID 与位置、方向经 reset 下发；仓内没有 skillsync 正式调用方，定级不因后果轻）。状态：已复现，未修复。[本轮](../review/REVIEW-2026-10-05-n09-batch2.md)。

## 触发与差异

`Coordinator` 在两处生成 `roost.skill.presentation` 的 reset：

- `prepareFlush` 的 presentation 游标过期分支（`skill/skillsync/coordinator.go:320-334`）：`coordinator.runtime.PresentationSnapshot()` 直接交给 `projector.PresentationResetPacket`；
- `Recover` 的 provider `snapshotPacket`（`coordinator.go:454-455`）：同样直接投影。

`PresentationSnapshot`（`skill/presentation_recovery.go:35-81`）列出全部 Running / Suspended 且带视觉的 cast 与 process，`Anchor` 带施法者 / owner、目标 / lifecycle 实体，process 还带 `Position` / `Direction`。两处都不调用 `VisibilityPolicy`；而同一 observer 的增量 presentation 每条都经 `FilterPresentation`（`coordinator.go:335-345`）：施法者不可见整条丢弃，目标不可见清零，`RedactSpatial` 清空坐标。state 流的快照也经 `FilterStateSnapshot`。

预期（`docs/skill/architecture-and-migration.md` 第 54 行“Coordinator 先执行 VisibilityPolicy，再用 Projector 生成强类型 Packet”；`visual-sync-production-guide.md` §12 第 2 条“新增 Runtime 字段不会自动泄漏”）：reset 与增量使用同一 observer 策略。实际：presentation 游标过期或客户端重连恢复时，observer 收到全部持续表现。

## 影响

PvP / 战争迷雾类玩法里，掉线重连或 presentation 积压的 observer 能看到隐身 / 视野外单位正在引导的技能、目标与投射物坐标。过滤是服务端唯一的边界，客户端无法自行补救。

## 验收覆盖点

两条 reset 路径都按 observer 过滤（不可见来源整条去掉、不可见目标清零、空间字段按策略清除），可见条目照常恢复；策略返回错误时 fail-closed 并计 `VisibilityFailures`；自定义 `VisibilityPolicy` 不需要新增方法也能得到同样的过滤。本轮没有做真实传输（kit syncstream / NATS）端到端。
