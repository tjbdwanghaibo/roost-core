# RR-20261005-NC-74：工程运行期写进工程目录的 `.dev/` 日志与 `data/wal` 被当成应用输入，dev-run 期间 `roost generate` / `project sync` 一律报 inputs changed

日期 2026-10-05。基线 main `80802200`。等级 **P3**。状态：已复现（正式入口回归；N07 第二批另有 game-demo 实跑），未修复。来源：N07 第二批移交（[记录](../review/REVIEW-2026-10-05-noncore-n07b.md#移交-n08不在本批修)，[复现](../bugfix/evidence/noncore-bugfix-20261005-n07b/n08-generate-devdir.txt)）；N08 codegen（[本轮](../review/REVIEW-2026-10-05-n08-codegen.md)）。

## 触发与实际

`make dev-run`（生成的 `deploy/dev/run.sh`，`DEV_DIR=".dev"`）把各进程日志写在工程内 `.dev/*.log`；生成的 `configs/service/config.<svc>.yaml` 把 DataEngine WAL 放在 `data/wal/dataengine`（相对工程根）。生成的 `.gitignore` 也把 `.dev/` 列为运行期产物。进程运行期间执行 `roost generate`（N07 记录的“改 CSV 后让开关生效”那一步）或 `roost project sync`：

```
project inputs changed while code generation was running: .dev/game.log, data/wal/dataengine/000001.wal; rerun the command
```

只能先停掉服务。WAL 目录还会被整份复制进每一棵暂存树。正式入口回归 `TestGenerateAndSyncIgnoreTheProjectsRuntimeOutput`（新增；替身 `go mod tidy` 与 sync 提交前钩子扮演正在写日志 / WAL 的进程）修前 generate、sync 两条红，控制（生成期间改应用自有配置仍被拒绝）通过。

## 根因

`codegen/internal/roost/generate.go:455` `skippedProjectDirectory` 只按名字跳过 `.git / bin / dist / log / .testcache / .roost-*`，`copyProject` 与 `snapshotProjectInputs` 共用它；`.dev` 与 `data/wal` 不在其中。`planStagedProjectCommit` 对真实工程的遍历（`project.go:298`）又是另一份更短的名单（`.git / bin / dist / log`）。三处对“什么属于工程”的边界不一致：只把 `.dev` 加进复制 / 快照的名单，提交计划会把暂存树里没有、内容里恰好引用了 “Code generated” 的运行期文件当成退役的生成物删掉（负对照见证据 `nc74-negative.txt`）。

## 影响与定级

不会写坏工程，只是运行时无法生成 / 同步，定 P3。不能按目录名跳过 `data`：`configs/data` 是生成器的输出。

## 范围

只覆盖生成器自己生成的运行期位置（`.dev`、默认 WAL 目录 `data/wal`）；用户把 WAL 或日志配到工程内其他位置时仍会触发，需要按配置判断，本条不做。观察：生成的 `.gitignore` 没有 `data/`（WAL）一行。
