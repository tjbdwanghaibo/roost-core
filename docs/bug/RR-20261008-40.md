# RR-20261008-40：KCP E2E 停机先取消网络，误报在途机器人发送失败

日期：2026-10-08。基线：d30c3f02（v1.23.1之后仅文档回填）。等级P3，验收契约缺陷；已修复、目标验证通过，未发版。来源：[Lockstep验收观察](../review/REVIEW-2026-10-08-client-lockstep-validation.md)。

位置：`sync/lockstep/e2e_gate_test.go`。原始偶发观察不直接当生产缺陷；本轮在macOS用受控时序复现其前提。复现不依赖Windows。测试 `TestE2EBotShutdownWaitsForInFlightOutput` 的原失败如下（原始日志另存artifacts）：

```text
--- FAIL: TestE2EBotShutdownWaitsForInFlightOutput (0.00s)
    --- FAIL: TestE2EBotShutdownWaitsForInFlightOutput/graceful (0.00s)
        e2e_shutdown_promises_test.go:44: shutdown canceled in-flight output: robot lockstep: submit input for frame 2: context canceled
FAIL
FAIL	github.com/tjbdwanghaibo/roost-core/sync/lockstep	0.471s
FAIL
```

测试主动取消 context 时，机器人可能已经取出一帧并正在提交输入。生产机器人如实返回取消错误，E2E 却把自己发起的取消记作业务失败。期望先排空在途，再释放网络依赖；真正业务错误不能消失。

修复见[RR-20261008-40](../bugfix/RR-20261008-40.md)。完整验收与平台范围见[本轮收口](../review/FOLLOWUP-MAC-LINUX-2026-10-08.md)。
