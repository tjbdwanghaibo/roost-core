## RR-20260919-10：交付链反例

图谱与源码给出的完整生产链是：

```text
Kit Server.run
  → sweepGroup
    → DeliveringActivities
    → DueDispatches
    → AttemptDispatch (CAS: Attempts++, NextAttemptAt)
    → RetireDelivered
```

`AttemptDispatch` 的生产 caller 只有这条链，没有传输 callee。现有测试 `TestSweepRetriesDispatchesAcrossRounds` 明确断言两轮 sweep 后 `Attempts == 2`；`TestDeliveringIndexRetiresAtTerminalStates` 明确把反复 sweep 推进到 `DispatchExhausted`。专项复跑：

```text
go test -race ./service/global/activity \
  -run 'Test(SweepRetriesDispatchesAcrossRounds|DeliveringIndexRetiresAtTerminalStates|DispatchIsRetriedAckedAndFinallyExhausted)$' \
  -count=1
PASS
```

Codegen 游戏侧 `applyDispatches` 只调用两个精确 key：`ID(now-WindowSeconds)` 和 `ID(now)`。当 owed key 是 `now-2*WindowSeconds` 时调用集合不包含它，这是不依赖时序的静态反例。
