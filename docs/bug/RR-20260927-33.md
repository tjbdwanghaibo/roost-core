# RR-20260927-33：生成的 docker compose 所有服务起不来：`tmpfs` 用 YAML flow 序列书写，被逗号拆成 4 项

日期：2026-09-27。基线：本地 main `21555fd`。来源：OPEN-ITEMS 批次 7（本机 docker compose 实跑 C04 / B34 与 v1.16.1 升级演练 B32）。等级 **P2**（用生成的 compose 部署即不可用）。引入：修前即有（v1.17.1 中存在）。状态：已复现；已修复（[修复记录](../bugfix/RR-20260927-33.md)，批次 14，分支 `fix-r8-b14`），本地提交，未推送。

`codegen/internal/roost/render_cicd.go:451` 输出 `tmpfs: [/tmp:rw,noexec,nosuid,size=64m]`，YAML flow 序列按逗号拆成 `/tmp:rw`、`noexec`、`nosuid`、`size=64m` 四项，
`docker compose up` 报 `invalid mount path: 'noexec' mount path must be absolute`。CI 只跑 `docker compose config --quiet`，抓不到。

修复约束：输出为单条挂载（例如 `tmpfs: ["/tmp:rw,noexec,nosuid,size=64m"]` 或块序列）；加生成器回归：按 YAML 解析生成的 compose，断言每个服务 `tmpfs` 恰好一项且以 `/` 开头；
全仓核对其他 flow 序列里含逗号的值（`security_opt`、`command` 等）；已生成工程经 `project sync` 更新（compose 是生成物）。
