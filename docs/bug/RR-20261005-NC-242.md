# NC-242：actionflow Update 的 fn panic 让 runner 永远处在“回调中”，之后所有变更不再执行

2026-10-06，基线 `81d7cb16`，分支 `revn10b`（N10 第二批）。P2（ai / actionflow 仓内无生产使用方；hotcode 由 Nest 全局 handler 与 game-demo 使用）。状态：已复现、已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-242.md) · [本轮](../review/REVIEW-2026-10-06-noncore-n10b.md)。

## 触发与差异

`actionflow/action_runner.go:274-288`（基线）B7 起 Update 不在回调里时先置 `executing = true` 再调 fn，fn 返回后 `drain()` 复位；fn 没有 recover。fn panic 时 panic 穿出 Update，`executing` 永远为真。

预期：与动作回调（Start / Tick / Cancel 都经 `recoverActionPanic`）一致，fn 的失败不破坏 runner 状态；B7 之前 Update 直接调 fn，panic 只是向上传播、不留状态。

实际：之后每次 Start / Enqueue / Tick / End 都被当成“回调里”的延后命令，返回 ID 与 nil 却永远不执行；排满 MaxDeferredCommands 后一律 ErrDeferredQueueFull。
