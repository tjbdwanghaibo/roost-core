# RR-20260925-07：Nest 跨池顺序与慢阶段本地执行边界

日期：2026-09-25。基线：RR-20260925-06 已实施后的本地工作树；未部署。影响 Nest、Remote 内存提交失败和冷加载链路。

## 问题与源码证据

旧 `Dispatcher.TrySendMsg` 将普通、Broadcast、Cost、Remote 分配给 main/hb/cost/remote 四个独立哈希池。先准入的同 ID RemoteAccess/Cost 消息处于慢准备时，后准入的普通消息可以直接执行；Entity 锁仅保证互斥，不能恢复准入 FIFO。Multi/Broadcast 只按首个 Key 哈希，也不能覆盖其他显式目标的顺序。

旧 Remote 内存持久模式 Commit 失败会调用 `rollbackRemoteEntries` 并获取 Entity.GetMutex()；把整个 Commit 放到慢 worker 会让异常路径仍取得业务本地锁。EntityRepository 冷加载直接调用 manager.Create，初始化与发布也跟着 I/O 的执行位置走。

用户确认的目标：慢池不得执行 Nest handler、Entity Guard/本地锁或生命周期业务回调。快慢资源共用准入顺序；慢池自身不按 ID 分槽。

跨池全目标 FIFO 属于本次新增的顺序保证：旧方案只保证每池内的同 Key，不把新契约反写成旧版本已发布承诺。本记录同时跟踪慢执行边界修正，与详细重构方案关联。

## 复现/回归

`GOCACHE=/tmp/roost-nest-go-cache GOWORK=off go test -race ./nest -run 'Test(TwoPools|SlowPool|SlowLoad|RemoteStages)' -count=20`

事件屏障先阻塞慢准备，再准入相同/交叉目标和无关快请求：相同目标必须等待；无关快请求必须完成；快 worker 被占用时慢加载完成也不能自己执行 handler。验证共享慢 worker、满队列、取消/Fence、关闭批次和停机。

旧版缺陷以旧路由分支和调用链为证据；没有声称把新增调度器测试直接运行在旧版获得修前红灯。修后以上并发测试 20 次通过。

状态：已修复并完成包级并发回归，真实负载结果见 [修复记录](../bugfix/RR-20260925-07.md)。

本地执行边界的负对照：临时 overlay 仅恢复 Remote 回滚与 EntityRepository 发布的就地调用，两项新增测试分别因未委派回滚、未发生本地交接而失败；当前七包 race 通过。跨池调度仍以源码证据和新调度器行为测试为准，不混用负对照结论。
