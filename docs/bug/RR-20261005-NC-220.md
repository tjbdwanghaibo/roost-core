# NC-220：缓存型快照点不按采样上下文检查——process_start 写在 phase 流程里能编译（有 owned spawn 时每次施法 ErrProgramInvariant），实体引用流程局部变量时落到 LOWER_UNRESOLVED

2026-10-06，基线 `57c0b3b6`（origin/main）。P2（编译通过、每次施法失败；或静默退化成“第一次读到的值”；局部变量的情形 fail-closed 但诊断定位在 `$`）。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-220.md)。[本轮](../review/REVIEW-2026-10-06-n09-batch5.md)。

## 机制

`read_attribute` 的 `cast_start` / `phase_start` / `process_start` 是缓存型快照点：整个读取（包括实体）在采样点求值写进缓存，之后读缓存（`runtime_eval.go` 的 `captureSnapshots` / `shouldCacheSnapshot`）。采样点各有自己的求值上下文：

| 采样点 | 在哪里采样 | 求值上下文 |
| --- | --- | --- |
| cast_start | `runtime.go` startLocked（memory 默认值之后） | 施法；没有流程局部变量 |
| phase_start | `executor.go` executeCast 每进一个 phase | 施法；没有流程局部变量 |
| process_start | `process_owned.go` `captureOwnedProcessSnapshots`，每个 owned 实体进程启动时采样**全部** process_start 计划 | `detachedProcessCast`：没有施法输入、memory，局部变量全是 missing |

`compile_snapshot.go` 的 `runSnapshotPass` 只查属性存在、采样点在 catalog 允许的列表里，不查读取写在哪里、实体能否在采样点求值。

## 触发与差异

| 定义 | 编译 | 执行 |
| --- | --- | --- |
| phase 流程里 `read_attribute{entity:"$input.target", snapshot:"process_start"}`，同一施法里有 owned spawn | 通过 | Activate 返回 `skill: immutable program invariant failed`（进程启动采样时在进程上下文里求 `$input.target`，`evalReference` 越界） |
| 同上，实体是 `$memory.who` | 通过 | 同上 |
| phase 流程里 process_start，没有任何进程 | 通过 | 不采样，按 `shouldCacheSnapshot` 在第一次读时写缓存——“第一次读到的值”，不是任何进程的启动值 |
| select 消费体里 `read_attribute{entity:"$local.t", snapshot:"cast_start"}`（phase_start 同） | `LOWER_UNRESOLVED at $`：`reference "$local.t" has no compiled slot or handle (an earlier compiler pass accepted a name it did not resolve)` | — |
| 进程回调里 process_start 读回调自己 select 的局部变量 | 同上 | — |

后两行是 fail-closed，但 B3 的 `LOWER_UNRESOLVED` 按定义表示“前面的 pass 漏查”，位置也只有 `$`。

## 复现

正式回归（修前）`TestCompileRejectsSnapshotsThatCannotBeCapturedWhereTheyAreRead` 六个子用例全部失败：前三个 `compiled; diagnostics=[]skill.Diagnostic(nil)`，后三个 `missing error ATTRIBUTE_SNAPSHOT_INVALID at ….read_attribute.entity in [… Code:"LOWER_UNRESOLVED", Path:"$" …]`。探针：第一行定义 Activate 返回 `skill: immutable program invariant failed`；`$memory.who` 同。

## 验收覆盖点

上表定义以 `ATTRIBUTE_SNAPSHOT_INVALID` 定位到 `.read_attribute.snapshot`（process_start 不在进程回调里）或 `.read_attribute.entity`（引用 `$local.*`）。控制：phase 流程里 cast_start 读 `$caster` 照常施法；进程回调里 process_start 读 `$owner` 取进程启动时的值（启动后把属性 5 改为 40，两次 tick 伤害都是 5），current 取改后的值（第二次 40）。

## 观察（不改行为）

process_start 的实体按“整个读取在采样点求值”解释：回调里 `entity: "$event.target"` 取的是进程启动事件的 target（lifecycle 实体），不是每次回调的事件 target。这与 cast_start 的口径一致，记入本轮 O27。
