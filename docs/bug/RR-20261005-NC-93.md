# NC-93：选主正常 Resign 不受调用方预算约束，etcd 无响应时最多阻塞到 session TTL（默认 60s）

2026-10-05，基线 `be7bcc18`（N03 源码与 `7922e428` 相同）。**P3**（潜伏：`71c6fb6b` 起 kit 不再发布选举工厂，仓内没有生产调用方；后果是停机 / 交接路径的预算被突破，定级低是因为没有触发路径，不是后果轻）。状态：已复现（真实 etcd），未修复。[本轮](../review/REVIEW-2026-10-05-noncore-n03.md) · [证据](../review/evidence/noncore-review-20261005-n03/README.md)。此前在 [noncore-08](REVIEW-2026-10-04-noncore-08.md) 与 [etcd 机制](../review/IMPLEMENTATION-ETCD-SNAPSHOT-WATCH-AND-LIFETIME.md) 作为观察记录（“正常 Resign 仍可能等待 SDK 默认 TTL 60 秒的 Revoke”），本轮补出稳定反例。

## 触发与差异

`IElection.Resign(ctx)` 在 etcd 无响应（进程暂停 / 网络分区 / 过载）时被调用，例如停机时放弃领导权。

- 预期：与 Campaign（NC-11）、Discovery.Deregister 一致，等待受调用方 ctx 约束；超出预算返回 ctx 错误，lease 由 election 继续负责撤销或等 TTL 过期。
- 实际：`election.Resign`（`etcd/driver/election.go:301-317`）先 `elect.Resign(ctx)`（受 ctx 约束），再 `session.Close()`（`:311`）。SDK `concurrency.Session.Close` 用 session 自己的 context 加 TTL 秒的超时发 Revoke（etcd client v3.7.1 `concurrency/session.go:108-115`；`createWithEtcd` 未设 TTL，默认 60s），完全不看调用方 ctx。

## 复现（真实 etcd，临时单节点，随机端口，数据目录随用例删除）

`TestRevn03ProbeResignBudgetFrozenEtcd`：Campaign 成功后 `SIGSTOP` etcd，`Resign(500ms)`：

```
Resign(500ms) with frozen etcd: err=still blocked after 20s elapsed=20.000663958s is_leader=false
Resign ignored its 500ms budget: 20.000663958s
--- FAIL: TestRevn03ProbeResignBudgetFrozenEtcd
```

对照：同样冻结 etcd，`Discovery.Deregister(500ms)` 在 500ms 返回 `context deadline exceeded`，解冻后重试成功、键清零；健康 etcd 上正常 Resign 后 lease TTL=-1、候选键 0、另一候选立即当选（服务端资源清理成立）。

## 影响

- 调用方给停机 / 交接的预算（如 App 每个 Mod 的停止预算）被这一步突破至多 60s。
- 本地状态已在前面结束（`is_leader=false`），阻塞只是等 Revoke；但调用方无法在预算内拿回控制权。

## 验收覆盖点

- 冻结 / 不可达的 etcd 上，`Resign(ctx)` 在 ctx 到期后返回 ctx 错误；本地领导权已结束（IsLeader=false、LeaderChan 关闭）。
- lease 撤销由 election 持有、自带截止（与 RR-20261004-06 的放弃路径同一机制）；下一次 Campaign 等它结束。
- 健康 etcd 上正常 Resign：返回 nil，lease 已撤销、键已删除，另一候选能立即当选；正常 Close 的 Revoke 不被提前取消（`TestEtcdLifetimeNormalResignDoesNotCancelRevoke`）。

本轮没做：多节点 etcd 的分区 / leader 切换；Resign 的 Delete 结果未知时（请求已到服务端但回复丢失）领导键是否残留只按 TTL 兜底。
