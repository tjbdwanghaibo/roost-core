# RR-20260927-03：demo 开发脚本登记游戏服不传 `redis.db` / `password`；demo 玩家 id 计数键写死、不带键前缀

日期：2026-09-27。基线：main `d4234c9`。来源：[OPEN-ITEMS-2026-09-27](../review/OPEN-ITEMS-2026-09-27.md) A03 + A04（均为 [bf-56 §未验证项与观察](../bugfix/RR-20260926-56.md) 的观察项）。
等级 **P4**（开发脚本 / demo 模板）。状态：已修复（见下）。

## 现象

1. **A03**：生成的 `deploy/dev/run.sh` 在 `start` 末尾调用 `register_game_server`，用 `accountctl upsert-server` 把游戏服登记到 account 服务的 Redis。
   开发配置 `redis.db` 非 0（或有密码）时，登记写进了 db 0（或连不上）；account 服务在自己的 db 里查不到服务器，机器人 / 客户端 `CreateRole` 报
   `account: server is invalid`。bf-56 在集成环境（db 13）实际撞到，当时手工 `accountctl -redis-db 13` 绕过。
2. **A04**：game-demo 的玩家 id 分配器在固定键 `roost:demo:player_id` 上 `INCR`，不带 `account.key_prefix`。同一个 Redis db 上前缀不同的多份部署共用一个计数器；
   按前缀清理一份部署时这个键被漏掉（bf-56 清理 db 13 时列为“不带配置前缀”的键）。

## 根因（`d4234c9` 行号）

1. `codegen/internal/roost/render_dev_run.go:122-132` `register_game_server`：awk 只从 `config.account.yaml` 读 `redis.addr` 与 `account.key_prefix`，
   调 `accountctl -redis … -prefix …`；`accountctl` 早有 `-redis-db` / `-redis-password`（`demo/cmd/accountctl/main.go.tmpl:32-33`），脚本没传，取默认 db 0、无密码。
2. `demo/internal/service/account/collaborators.go.tmpl:54` `const playerIDCounterKey = "roost:demo:player_id"`，`:91` `Incr(ctx, playerIDCounterKey)`；
   注释说“故意不从 key_prefix 派生，免得改前缀后计数器归零”。但账号、角色、服务器登记都在 `account.key_prefix` 下（`kit/service/account/redis_store.go:53-85`），
   改前缀而不迁数据时账号库本身就丢了；计数器单独放在前缀外，只换来“多部署共用、按前缀清理漏掉”。
   `demo/README.md:398` 也按固定键描述。

## 修复约束（清单推荐）

- A03：awk 同时读 `redis.db`（以及 `password`），传 `-redis-db`（与 `-redis-password`）。
- A04：计数键改为从 `account.key_prefix` 派生；同时改 README。主会话要求：写清兼容性——已部署 demo 的键名会变，需给迁移或兼容读法。
