## RR-20260909-03：Assembly 停机未完成就丢失 Runtime，重试虚报成功

**P2，已复现，未修复。** Core `df76988f059de8827f20026f4f718fd61ae057ce`。

**位置：** `dataengine/engine/assembly.go:161–164` 调用 runtime.Shutdown 后，无论结果如何都清空 `a.runtime`；下次调用在 `runtime == nil` 时返回 nil。Kit `dataengine/mod.go` 的 StopWithContext 直接转发到该方法。

**触发：** Runtime 所属 worker 的底层操作尚未返回，停机 context 已取消/到期。Runtime.Shutdown 返回错误，但 worker 仍在退出过程中；随后用新 context 再次 Shutdown。

**期望：** 停机尚未完成时保留可继续等待/清理的对象。重试应等待完成或报告未完成，不能仅因丢失引用就宣告成功。

**实际：** 第一次返回 context.Canceled 后 Runtime() 已变 nil；第二次 Shutdown 立即返回 nil，而 Outbox worker.done 尚未关闭。

```text
FAIL TestReviewAssemblyRetainsIncompleteShutdown
second Shutdown returned success while outbox worker is still active; Runtime()=<nil>
```

**证据：** 使用真实 NewOutboxWorker、Runtime.Shutdown 和 Assembly.Shutdown。测试 Store 仅在 Claim 中延迟返回，控制停机期限短于底层退出；不是伪造 Shutdown 返回值。普通和 `-race` 两次运行均在上述业务断言失败，未报告数据竞争。测试 finally 释放阻塞并直接关闭持有的 worker，未留下进程内工作者。

**影响与边界：** Assembly 丢失继续收尾的句柄，重复停机的成功结果不能证明依赖已不再被使用。若调用方据此释放底层资源，生命周期顺序可能失真。本轮没有证明永久 goroutine 泄漏、WAL 丢数据或生产停机必现；底层操作恢复后 worker 仍可能自行退出。测试构造的是仅带 Outbox 的 Runtime，以隔离退出所有权，没有执行完整 Mongo/JetStream Assembly.Start。

**建议：** 明确区分 stopping 与 stopped，并在确知退出完成后释放 Runtime 引用。不能机械地把“err != nil”当作未完成的唯一信号：某些错误可能在资源已关闭后返回；应对组件关闭完成状态和重试语义作明确约定。保留本测试，并覆盖超时后恢复、重复 Shutdown 等场景。

## RR-20260909-04：同包多个 Entity 生成同名注册符号，消费者编译失败

**P2，已复现，未修复。** Codegen `b8f4ebfddf2282e4d1ac2a5e07928ecbebe21e9a`，消费者联调 Core 为上述 SHA。

**位置：** `internal/entity/main.go:86` 为解析到的每个实体分别生成文件；`internal/entity/gen.go:299` 和 `:304` 无条件为每个文件声明包级 `registerEntityOnce`、`RegisterEntity`。

**触发：** 同一个 Go 包内放置两个合法、不同 Kind 的 `//roost:entity` 实体，执行独立工具 `go run ./cmd/entity -dir <consumer>`。

**期望：** 生成结果可编译；如果产品只支持每包一个实体，至少应在写文件前明确拒绝不支持的输入，而非成功生成互相冲突的产物。

**实际：** 生成器 exit 0，写出 clan_gen_wire.go 与 guild_gen_wire.go；消费者编译 exit 1：

```text
guild_gen_wire.go:12:5: registerEntityOnce redeclared in this block
    clan_gen_wire.go:12:5: other declaration of registerEntityOnce
guild_gen_wire.go:17:6: RegisterEntity redeclared in this block
    clan_gen_wire.go:17:6: other declaration of RegisterEntity
```

**对照：** 同一个 Guild 输入单独位于包内时，生成、消费者编译及新生成的 RemoteCommitGuards 测试均通过。双实体版本只增加一份重命名为 Clan、使用不同 Kind/Collection 的定义，错误来源是固定注册名。源码 fixture 的 Category=6 不符合当前 Core 限制，本轮只在临时消费者改为合法 Category=2 后完成对照；没有把无效 fixture 的 panic 误报成生成器功能问题。

**影响：** 在一个包中组织多个实体，或为已有实体包添加第二实体时，生成命令成功但业务构建被阻断。该固定命名在新增 guard tests 之前已存在，不将其错误归因于最近的测试生成功能。历史 U-0026 修复的是另一个 lifecycle 包中的 FromRegistry 重名，不是本项，未重开旧单元。

**建议：** 按实体名命名内部注册函数/Once，再生成一个去重的包级聚合入口，保持 registry 收集器与已有消费者兼容；或者明确并验证单实体包限制。回归应实际编译多实体消费者，不能只检查每个文件单独 gofmt 成功。后续修改时同时考虑新 companion test 对 RegisterEntity 的调用。
