# RR-20261005-NC-204：glsvet 对不存在、根不存在或解析失败的目录静默按 0 违例通过

日期 2026-10-05。基线 main `8597046c`。等级 **P3**。状态：已复现，未修复。来源：N15（`cmd/glsvet` 由 N09 移入）。

## 触发与实际

`cmd/glsvet/main.go:94-100` `vetDirectory`：`parser.ParseDir` 出错就 `return 0 // not a Go directory`。但没有 Go 文件的目录 ParseDir 不报错；会报错的是目录不存在 / 读不了，以及有文件解析失败——这时连同目录里其他文件的违例一起被丢弃。`expandArgument`（`:71-92`）对 `<dir>/...` 的根走查错误同样忽略。新增 `cmd/glsvet/inputs_promises_test.go` 修前：

```
--- FAIL: TestMissingDirectoryArgumentFails
    glsvet …/no-such-package: exit 0, output ""; want exit 2 naming the missing directory (nothing was vetted)
    glsvet …/no-such-package/...: exit 0, output ""; …
--- FAIL: TestUnparsableFileFailsInsteadOfSkippingTheDirectory
    glsvet on a directory with an unparsable file exited 0; output ""
```

## 影响与定级

glsvet 是 ci.yml、framework-compat、upgrade-compat 与生成工程的门禁，只看退出码；参数路径拼错 / 包改名后门禁永远绿。定 P3（编译失败通常先被 go build 拦住，路径漂移没有别的检查）。

## 验收

不存在的参数 / 根以 2 退出并点名；解析失败的文件被报告、退出非 0；没有 Go 文件的目录照常通过。
