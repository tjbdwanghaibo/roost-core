# RR-20261006-28：生成工程不能整体切到 Redis Cluster——生产校验只认 redis.addr，accountctl 与 dev run.sh 只会连单机

2026-10-06，基线 main `0db819b0`。P3（部署阻断：只配 `redis.cluster_addrs` 的生产配置启动失败；登记游戏服的工具对着 Cluster 只能写进槽恰好在所连节点上的键，其余 MOVED，机器人建角报 `account: server is invalid`）。来源：[真实进程演练](../bugfix/REAL-PROCESS-DRILLS-2026-10-06.md)第 ⑥ 项（App 锁方案 §13 “Redis Cluster 下的真实进程演练”）准备环境时发现。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261006-28.md)。

## 触发与差异

框架侧 Redis Mod、单实例锁连接、各服务的 hash tag 校验都按 `redis.cluster_addrs`（逗号串或 YAML 列表，`kit/mods.RedisClusterAddrs`，NC-190）切 Cluster，`cluster_addrs` 优先于 `addr`。生成工程里还有三处只认单机：

1. **生产校验**（`app/config_validation.go:104-107`）：game / instance / account / match_group / global 在 `env: production` 下必须写 `redis.addr`。只配 `cluster_addrs` 的生产配置启动失败：`config: production game requires redis.addr`。要过校验只能再写一个 `addr`——它被 Cluster 配置覆盖、不起作用，正是 NC-192 要删掉的“写上只为让校验放行”的设置。
2. **`cmd/accountctl`**（`demo/cmd/accountctl/main.go.tmpl`）：只有 `-redis <addr>`，用单机客户端。对着 Cluster 的节点写服务器记录，只有键槽恰好在这个节点上才成功。真实 3 主 3 从 Cluster 上（演练环境，修前模板生成的 `bin/accountctl`）逐个节点试：

   ```
   == seed 48400   accountctl: upsert server: MOVED 14044 127.0.0.1:48402
   == seed 48401   accountctl: upsert server: MOVED 14044 127.0.0.1:48402
   == seed 48402   （成功：这个节点正好是槽 14044 的主）
   == seed 48403   accountctl: upsert server: MOVED 14044 127.0.0.1:48402
   == seed 48404 / 48405 同上
   ```
3. **`deploy/dev/run.sh` 的 `register_game_server`**（`codegen/internal/roost/render_dev_run.go:122-136`）：从 `config.account.yaml` 只读 `redis.addr`，读不到就用 `127.0.0.1:6379`——account 配成 Cluster 时把游戏服登记到本机另一个 Redis（或连不上）。

不属于本条的（设计如此，Init 时点名报错，演练记录里列为切换清单）：activity / platform / rank 的 `key_prefix` 与 `remote_entity.lock_key` 在 Cluster 下必须带 hash tag。
