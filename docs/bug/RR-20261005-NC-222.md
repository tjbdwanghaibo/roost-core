# NC-222：非 spawn 效果上的 `process` / `on` 能编译，Runtime 从不启动进程、回调从不执行

2026-10-06，基线 `57c0b3b6`。P3（作者写的进程与回调被静默丢弃；presentation plan 里还会出现进程挂载点）。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-222.md)。[本轮](../review/REVIEW-2026-10-06-n09-batch5.md)。

## 机制

线格式里 `process` 与 `on` 是 effect flow 的键，任何效果都能写（`compile_normalize.go:303`）。`lower.go` 的 `lowerEffect` 对 `flow.callbacks != nil || flow.process != nil` 一律生成进程模板（`hasProcess`、`processTemplate`），`presentation.go` 据此生成进程挂载点；但只有 spawn 会启动实体进程（`executor.go` 的 `spawnOperation` → `runtime_owned_process.go` `executeOwnedSpawn` → `startEntityProcess`），damage / heal 等分支只执行效果本身。编译期没有“process / on 只能写在 spawn 上”的规则。

## 复现

正式回归（修前）`TestCompileRejectsProcessesOnEffectsThatDoNotSpawn` 三个子用例全部 `compiled; diagnostics=[]skill.Diagnostic(nil)`。探针：damage 带 area `process` + `on.enter` heal，施法后目标只受 1 点伤害，没有任何进程，回调没有执行。

## 验收覆盖点

非 spawn 效果上的 `process` 报 `SHAPE_INVALID at <effect flow>.process`，`on` 报 `SHAPE_INVALID at <effect flow>.on`。spawn + process + on 的全部 fixture 与性质测试种子照常编译、执行（控制）。

## 修复

已修复、声明场景验证，未发版：[修复记录](../bugfix/RR-20261005-NC-222.md)。
