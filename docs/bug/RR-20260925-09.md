# RR-20260925-09：Remote 回滚 panic 遗留 Entity 本地锁

日期：2026-09-25；基线：RR-07 双池实施后的未提交工作树，未部署。影响 Remote 内存提交失败回滚到 Nest 快池的路径，等级 P1。状态：已修复，见[修复记录](../bugfix/RR-20260925-09.md)。

`Manager.rollbackRemoteEntries` 获取 Entity 本地锁后调用自定义 `RollbackRemoteCommit`，然后显式 Unlock。若钩子 panic，Unlock 被跳过；即使外层捕获 panic，后续其他 goroutine 访问相同 Entity 仍被锁阻塞，消耗快 worker。

预期：钩子异常仍释放本次获取的锁，不改变 panic 的传播方式。

`TestRemoteRollbackPanicReleasesLocalLock` 构造 panic 钩子，外层捕获后由另一个 goroutine TryLock，必须成功。锁支持同 goroutine 重入，最初用原 goroutine 探测会误判通过，已改成跨 goroutine 的有效验证。临时 Go overlay 只恢复旧 Lock/hook/Unlock 实现，测试失败并报告 `rollback panic leaked Entity local lock`；当前源码通过。

命令：`GOCACHE=/tmp/roost-nest-go-cache GOWORK=off go test ./remoteentity -run '^TestRemoteRollbackPanicReleasesLocalLock$' -count=1`。负对照源码和实际日志保留在 `artifacts/perf/nest/two-pool-review-20260925/transaction_manager-before.go.txt` 与 `rollback-before.log`；overlay 不修改工作树。
