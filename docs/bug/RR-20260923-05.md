# RR-20260923-05：Stop/Close 等待 Flush 忽略 deadline，并允许旧循环未退出就重启

- 日期：2026-09-23；等级：P1；模块：Sync。
- 基线：`967bc69` + 前一轮 R1～R3 与 RR-01～03 工作树。
- 状态：已复现、修复并通过定向回归与模块 race 验证，未发布。[修复记录](../bugfix/RR-20260923-05.md)。

## 触发、预期与实际

另一个 Flush 阻塞在 Push，此时用有 deadline 的 context 调用 Stop 或 Close；或停止超时后再次 Start。预期等待遵守 context，周期 Push 收到取消，旧循环退出及最终 Flush 完成前拒绝重启。

flushMu.Lock 不可取消，Close 即使 Stop 超时仍继续等待它；Stop 在旧循环退出前把 running 清零，Start 可以创建第二个循环。周期 Push 使用 Background，不能收到停止取消。

## 证据

`go test ./sync/entitysync -run 'TestStopAndCloseRespectDeadlineWhileAnotherFlushIsInFlight|TestStopCancelsPushAndPreventsRestartUntilItReturns' -count=1`。修前 Stop/Close 的已取消 context 复现均在一秒观察窗口内未返回；之后测试加强为等待期间到期，并新增取消 Push 与重启屏障测试。测试位于 `sync/entitysync/inflight_promises_test.go`，用 Push 回调或通道固定交错。

相关实现：`sync/entitysync/` 下的 manager.go、flush.go、errors.go。影响边界及行为迁移见修复记录。
