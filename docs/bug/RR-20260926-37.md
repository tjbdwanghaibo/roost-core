# RR-20260926-37：Remote strict 确认超时后 postRemoteCommit 永不执行——实体 Sync 永久冻结、AfterCommit 丢失

日期：2026-09-26。基线：v1.17.0（`8811c02`）。等级 P2。状态：已复现（periodic / on_change），未修复。

## 根因

本地持久提交成功（`nest/execution.go:215-218` 置 `remoteCommitted`），`remoteentity/batch.go:456-466` strict 等待超时标 indeterminate 返回错误 → `nest/msg.go:88-108` committed=false
跳过 postRemoteCommit（Sync Confirm、AfterCommit）；finalizer `processDeferredRemoteClose`（`transaction_manager.go:252-290`）Applied/Committed 时只发布、对账、释放，与原消息回调无连接；
Nest 只对 `ErrCommitIndeterminate` Fence（`execution.go:45-47`）。后续同实体事务串在未确认 gate 后（`entity/sync_commit.go:39-46,99-104`）。

复现：[REPRO-2026-09-26-04](REPRO-2026-09-26-04.md) §5 `tx1 reply: … indeterminate: context deadline exceeded`、`SyncCommitReady=false afterCommit=0 nestFence=<nil>`、tx2 成功仍 `no frame … sync frozen`。

## 修复约束（维护者 2026-09-26 批准：finalizer 放行）

postRemoteCommit 随 deferredRemoteClose 交给 finalizer：拿到持久结论后**只执行一次**；Applied / Committed 经本地执行器执行 Sync Confirm 与 AfterCommit；Rejected 丢弃 Sync 门并按 RR-28 隔离；
停机排空拿不到结论时门保持冻结。AfterCommit 在回复失败之后延迟执行的语义写入文档与 CHANGELOG。不得在无持久结论时 Confirm。
