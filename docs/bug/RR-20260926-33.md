# RR-20260926-33：WAL fsync 失败后仍信任后续 fsync——Ack / ticker 在 terminal 后推进 checkpoint 与 DurableLSN，重启拒绝打开；票据错误未包 ErrCommitIndeterminate

日期：2026-09-26。基线：v1.17.0（`8811c02`）。等级 P2（后果同 RR-16：断电或 I/O 错误后拒绝打开需人工处理）。状态：已复现，未修复。来源：v1.17.0 疑点核实。

## 触发与根因

writer 或 ticker 的 fsync 返回 EIO（坏盘、云盘摘挂、thin 卷 ENOSPC）。Linux ≥4.13 同一 fd 的错误只报告一次，下一次 fsync 返回 0。
- `nestwal/wal.go:474-511` Ack 不检查 `w.terminal()`，只依赖本次 `syncActive` 返回值。
- `wal.go:1106-1120` `syncActiveLocked` fsync 失败保留 `unsynced=true`，下一次再 fsync 成功即清 `unsynced` 并 `resolveDurableLocked`；`active == nil` 时不论 `unsynced` 直接返回 nil。
- `wal.go:1122-1132` `syncAndCloseActive` 失败后仍把 active 置 nil，在途 Ack 得到 nil。
- `wal.go:496` Ack 自身 fsync 首次失败时 `setTerminal(err)` 未包 `ErrCommitIndeterminate`，违反 `nest/transaction.go:102-106` 票据错误契约；`nest/execution.go:45` 只对该错误 Fence。
- terminal 后 ticker 仍 fsync，把 DurableLSN 推过已判不确定的记录。

## 复现（[REPRO-2026-09-26-04](REPRO-2026-09-26-04.md) §1、§1b，需探针缝）

```text
strict append after injected EIO: err=nest: transaction commit outcome is indeterminate … input/output error ; terminal=… unsynced=true
Ack(fence=1/512) on terminal WAL: err=<nil>; stored checkpoint=1/512; fsync calls=2
reopen after lost writeback: err=nestwal: corrupt log  acknowledgement is beyond recovered WAL end   （对照不 ack：reopen err=<nil>）
in-flight Ack after failed final sync: err=<nil>; Close err=…EIO; stored checkpoint=1/256
Ack first fsync failure: ticket err Is(ErrCommitIndeterminate)=false
ticker after terminal: fsync calls=2 unsynced=false DurableLSN=1 terminal!=nil=true
```

## 修复约束（维护者 2026-09-26 批准推荐方向）

fsync 失败为粘滞错误：terminal 后 `syncActiveLocked` 直接返回 terminal、不再 Sync、不清 `unsynced`、不推进 DurableLSN；ticker 停止 fsync；`active==nil && unsynced` 返回错误；
Ack 在 `checkpointMu` 内先查 terminal 再 sync 再存 checkpoint（保持 RR-16 顺序）；Ack 的 sync 失败包 `ErrCommitIndeterminate`（与 ticker / processBatch / drainAndClose 一致）；
干净关闭后在途 Ack 遇 `active==nil && !unsynced` 仍返回 nil；不降低 strict / pipelined 语义。回归须用正式测试缝注入 fsync 失败。
