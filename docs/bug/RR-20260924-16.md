# RR-20260924-16：FlushRemoteAll 丢失被淘汰的完成结果

日期：2026-09-24；基线 `967bc69` 加 DataEngine 优化工作树。等级 P2。状态：已复现、修复并验证，未发布；[修复记录](../bugfix/RR-20260924-16.md)。

FlushRemoteAll 只保存调用时 pending 的事务 ID，再逐个调用 waitRemoteTransaction。等待第一笔时，其他事务可能已完成并被容量淘汰；后续按 ID 查找会创建全新 pending tracker 或返回 ErrRemoteOverloaded。预期调用开始时的事务均完成后返回成功，实际可能错误超载或等到超时。

复现使用容量 2、两个 pending 事务以及 select 入口屏障：完成两个旧事务，准入两个新事务以淘汰旧记录，再恢复等待。无任意 sleep。`TestFlushRemoteAllKeepsTrackersAcrossConcurrentEviction` 修前报 `original transactions completed but FlushAll returned remote entity: capacity exceeded`。日志 `/tmp/roost-remote-red.log`。

```sh
GOCACHE=/tmp/roost-nest-go-cache GOWORK=off go test ./remoteentity \
  -run '^TestFlushRemoteAllKeepsTrackersAcrossConcurrentEviction$' -count=1
```

根因原位于 `remoteentity/transaction_manager.go` 的 FlushRemoteAll；已移至同包 `transaction_tracking.go`。单笔 wait 已有保留 tracker 指针的保护，但批量 Flush 的 ID 快照没有沿用该所有权。
