# NC-111：Cancel / Interrupt / Release 中途出错后 cast 停在半终止状态，永久占住施法者窗口

2026-10-05，基线 `be7bcc1853020d9f744360d78831abd0ddf990a3`。P2（施法者之后所有非 concurrent 主动技能都返回 `ErrCasterBusy`，且没有可用的出路；需要 cancel 回调失败、进程停止失败或 Release 时付费失败，仓内没有正式 Runtime 调用方）。状态：已复现、已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-111.md)。[本轮](../review/REVIEW-2026-10-05-n09-batch1.md)。

## 触发与差异

`skill/runtime_cast_window.go`：

- `Cancel`（:233-265）先 `cancelPhaseTasks`、`phaseToken++`，再执行 phase 的 `cancel` 回调；回调返回错误时直接 `return err`，没有 `stopProcesses`、没有释放 policy 槽位、没有 `markAbilityCastFinished`、窗口阶段不变。cast 已经没有任何任务，永远不会再推进；它的 `windowStage` 仍是 preparing / committed，`casterWindowBusyLocked`（:14-25）一直为真。再次 `Cancel` 会重跑同一个回调并再次失败。
- `Interrupt`（:284-311）同样在 `stopProcesses` 出错时提前返回。
- `releaseCast`（:325-360）对 charge 先撤任务、推进 token，再 `prepareCastWindow(cast, "release")`；后者把阶段置为 preparing 后付费，付费失败直接返回。charge 的 `auto_release` 任务已被撤掉，cast 不再自动释放，施法者被占住直到调用方碰巧重试 Release 或 Cancel。同一错误经排程任务（auto release）走 `failScheduledCast` 会终止 cast，手动路径与排程路径不一致。toggle / hold 的 release 回调出错同理。

预期：已经开始改动 cast 的 Cancel / Interrupt / Release 出错时，cast 进入失败终态并完成全部收尾，错误照常返回。

## 复现

`skill/runtime_cast_terminal_promises_test.go`（基线代码上）：

```
--- FAIL: TestCancelCallbackFailureStillEndsTheCast
    runtime_cast_terminal_promises_test.go:104: cast after failed cancel: status=suspended stage=preparing, want failed
--- FAIL: TestChargeReleaseFailureStillEndsTheCast
    runtime_cast_terminal_promises_test.go:136: cast after failed release: status=running stage=preparing, want failed
```

探针：Cancel 失败后推进 20 tick，cast 仍为 suspended / preparing；`Activate` 返回 `skill: caster already has an active cast window`；再次 `Cancel` 返回同一个 `insufficient resource`。

## 影响

施法者被永久锁死（cancel 回调失败的情况下无法自救）；`activeCastCount` 被占用，长期运行逼近 `MaxActiveCasts`。
