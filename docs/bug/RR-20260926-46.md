# RR-20260926-46：已持久提交但释放失败的回复没有“已提交”哨兵，调用方无法区分已提交与未提交

日期：2026-09-26。基线：v1.17.0（`8811c02`）。等级 P3（语义）。状态：已复现，未修复。

提交后 Close 失败时回复仅 `nest: finish remote write batch: remote entity release is incomplete`，不满足 `errors.Is(ErrAfterCommitFailed)`；`ErrRemoteReleaseIncomplete` 在 Abort 路径同样出现（`remoteentity/transaction_manager.go:458`）；
调用方只能猜，重试可能重复执行。复现：[REPRO-2026-09-26-04](REPRO-2026-09-26-04.md) §11。

修复约束（维护者 2026-09-26 批准：沿用 ErrAfterCommitFailed）：提交之后发生的释放 / 回调错误统一包 `nest.ErrAfterCommitFailed`（`nest/nest.go:43`），保留原因 `errors.Is` 链；未提交路径不得带该哨兵。

## 修复（2026-09-26）

状态：已修复，本地验证通过，已本地提交，未推送/发布。详见[修复记录](../bugfix/RR-20260926-46.md)。
`Msg.remoteConfirmed` 只在本地与 Remote 都确认提交后置位，`dispatchNest` 回复前把此后的释放/回调错误统一包 `ErrAfterCommitFailed`（保留原因链）；
Abort、确认结果未知与拒绝的回复不带哨兵。修前红：`committed_then_close_failed` 与提交后 release hook panic 两例 `errors.Is(ErrAfterCommitFailed)=false`。
