# RR-20260927-20：nest 包 25 个用例单独用 -count>1 运行时 panic duplicate handler

日期：2026-09-27。基线：`d4234c9`（v1.17.1 之后的文档提交）。来源：[OPEN-ITEMS-2026-09-27](../review/OPEN-ITEMS-2026-09-27.md) A07；
最早在 [bf-32 §验证](../bugfix/RR-20260926-32.md)、[bf-35 §验证](../bugfix/RR-20260926-35.md)、[bf-48 §验证](../bugfix/RR-20260926-48.md)、
[bf-59 §验证](../bugfix/RR-20260926-59.md) 被当作“既有限制”绕开。等级 **P4**（测试卫生，不影响生产代码）。状态：已复现，未修复（最终状态见文末修复节）。

## 现象

```text
$ GOWORK=off go test -count=2 -run '^TestRollbackStateRestoresDaoAndDirty$' ./nest      # 基线 d4234c9
--- FAIL: TestRollbackStateRestoresDaoAndDirty (0.00s)
panic: nest: duplicate handler "test_rollback_state" [recovered, repanicked]
	.../nest/nest_test.go:856 +0x3a8
FAIL	github.com/tjbdwanghaibo/roost-core/nest	0.519s
```

`TestIndeterminateCommitDoesNotRollback`（`nest_test.go:1053`，panic 在 `:1071`）、`TestPipelinedCommitReleasesLocksBeforeDurable`
（`pipelined_commit_test.go:105`，panic 在 `:124`）同样失败。整包 `-count=2` 通过——排在它们后面的用例开头调用了
`ResetHandlersForTest()`，碰巧把残留清掉了。

影响：修复方和审计方不能对这些用例单独 `-count=N` 做重复 / 抖动复验，只能挑“可重复的用例”或跑整包（RR-32/35/48/59 的验证节都因此缩小了范围）。

## 根因

`nest/handler.go:50-63` `RegisterHandlerWithMeta` 写的是进程级 `handlerMap`，同名第二次注册返回 `duplicate handler`，
`MustRegisterHandler*` 把它变成 panic。下列用例直接用包级注册、又没在收尾时 `ResetHandlersForTest()`（`handler.go:157`），
同一进程的第二轮注册同名 handler 就 panic。全包逐个用例单独 `-count=2` 扫描（`go test -c` 后逐个 `-test.run '^名$' -test.count=2`，229 个 Test）
命中 25 个：

| 文件 | 用例（func 所在行） |
| --- | --- |
| `nest/nest_test.go` | `TestRegisterAndDispatchHandler`:406、`TestRollbackStateRestoresDaoAndDirty`:838、`TestRollbackAfterCommitRunsOnSuccess`:882、`TestRollbackUndoRestoresStateAndDirty`:923、`TestStrictCommitFailureRollsBack`:964、`TestStrictCommitSuccessKeepsState`:1010、`TestIndeterminateCommitDoesNotRollback`:1053、`TestSyncUsesRequestSyncWait`:1131、`TestSyncCarriesCurrentContextIntoHandler`:1158、`TestNestTracePropagatesContextAndRecordsEvents`:1206、`TestDispatchRecordsLockHoldAndFlagsSlowHandlers`:1470 |
| `nest/pipelined_commit_test.go` | `TestPipelinedCommitReleasesLocksBeforeDurable`:105、`TestPipelinedEnqueueRejectionRollsBack`:187、`TestPipelinedIndeterminateAbandonsWithoutRollback`:228、`TestPipelinedRequiresCapableCommitter`:275、`TestPipelinedAllowlistGatesHandlers`:308、`TestPipelinedCascadedReadGatesBothRepliesInOrder`:350 |
| `nest/pipelined_async_test.go` | `TestAsyncCompletionFreesWorkerDuringDurableWait`:45、`TestAsyncCompletionKeepsSameEntityCommitOrder`:124、`TestAsyncCompletionIndeterminateRepliesErrorWithoutRollback`:197、`TestAsyncCompletionShutdownDeliversPendingReplies`:236、`TestAsyncCompletionKeepsOrderWhenPumpIsSaturated`:295 |

| `nest/sync_modes_test.go` | `TestNestOnChangeRunsWithoutWaitingForInterval`:109、`TestNestSyncTracksCastEntityUntilAdmission`:243 |

同一扫描对 nest 的全部 Benchmark（`-test.benchtime=1x -test.count=2`）以及其他在测试里调用 `nest.MustRegisterHandler*` 的包
（`saga`、`skill/combatcomponent`、`codegen/internal/nest`）全部通过，不在本条范围。

codebase-memory 图谱已过期（generation 09-26），以上以当前源码与实跑为准。

## 修复约束（清单推荐）

只改测试：这些用例在注册后 `t.Cleanup(ResetHandlersForTest)`，或改用每个用例唯一的 handler 名；不改生产注册语义与导出 API。
验收：每个改过的用例单独 `-count=3`，`./nest` 整包 `-race -count=3`。
