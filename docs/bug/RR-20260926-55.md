# RR-20260926-55：同一 tick 内 Leave 后立即 Join 因 subject 仍在 retiring 返回 ErrSubjectRetiring，快速重连玩家本次进不了复制场景

日期：2026-09-26。基线：本地 main `2330d57`（RR-30、33～47 修复合并后，未推送）。来源：修复合并后独立审计。等级 P3（基线即有；RR-40 未放大）。状态：已复现（2330d57 与 49f20ee 均 20/20），未修复。

复现：[REPRO-2026-09-26-05](REPRO-2026-09-26-05.md) §6：`join right after the settle's leave failed 20/20 times`，`scene: register subject …: entitysync: subject is retiring`。另：换成 AsyncTransport 时 resync 遇 `ErrSessionOpening/Closing` 只 Warn 不重试。

修复约束：Join 遇 retiring 时在退役完成后完成登记（排队到退役完成回调或下一 tick 重试，有界），不丢失本次 Join；resync 遇可重试会话错误按有界退避重试；回归覆盖快速重连。

## 修复（2026-09-26）

已修复，按上方修复约束实现，见[修复记录](../bugfix/RR-20260926-55.md)。entitysync 新增正式入口 `Manager.RegisterAfterRetirement(state, done)`：subject 退役中时
把登记排到退役完成（最后一个 remove 交付或最后一个订阅者会话关闭）的同一步，done 报告结果；每个 subject 至多一个排队，再次 Unregister / 被替换 / 状态关闭 /
Manager 关闭时取消。demo scene 的 Join 改用它，排队完成后按代际复查再让政策重说被拒的订阅；会话打开遇 `ErrSessionClosing` / `ErrSessionOpening`
（新增 `entitysync.SessionOpenRetryable`）按 25ms 起翻倍、上限 1s、至多 8 次退避重试，按代际复查、离开或 Close 后取消。REPRO §6 快速重连回归修前红
（`subject is retiring`）、修后玩家进入复制场景；`-race -count=10` 绿。已本地提交，未推送/发布。
