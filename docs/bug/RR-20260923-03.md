# RR-20260923-03：满容量会话合法替换对象，因 subject ID 排序被关闭

- 日期：2026-09-23；基线：`967bc69`（M-18），Go 1.27.0 / darwin arm64。
- 范围：`sync/entitysync/session.go`；等级：P2。
- 状态：已修复、定向回归与模块 race 验证通过，未发布。见[修复记录](../bugfix/RR-20260923-03.md)。

## 触发与根因

设置 `Limits.MaxObjects=1`，会话先收到 subject 100。同一 tick 退订 100、订阅 1，最终持有量仍为 1。

`session.encode` 原本按 subject ID 排序，导致先为 1 allocate，后为 100 release。allocate 看到旧对象仍在，返回 `ErrObjectLimit`；Manager 将它当成会话编码失败并关闭会话。反向以 100 替换 1 则成功，同样的业务操作结果取决于 ID 大小。

## 复现证据

测试：[session_capacity_promises_test.go](../../sync/entitysync/session_capacity_promises_test.go)。

```sh
go test ./sync/entitysync -run '^TestFullSessionCanReplaceAnObjectRegardlessOfSubjectID$' -count=1
```

修前 100→1 失败，报告 `legal replacement got 0 frames`，统计为 `Sessions:0`、`SessionsLost:1`；1→100 对照成功。
预期：先发 remove，再发 create；引用复用时 generation 变化，BaseTick 连续，会话继续存活。
