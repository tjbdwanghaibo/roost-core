# RR-20260926-39：被持久拒绝而隔离的 Remote 实体没有重新加载入口——一次瞬时错误后本进程内直到重启都不可写

日期：2026-09-26。基线：v1.17.0（`8811c02`）。等级 P2（可用性）。状态：源码判定，未修复。RR-28 修复后的行为缺口。
（最终状态见文末修复节：**已修复，随 v1.17.1 发布**，详见[修复记录](../bugfix/RR-20260926-39.md)。上面的“状态”是登记时的原值，保留不改。——2026-09-27 回写，OPEN-ITEMS A13②）

## 根因

`remoteentity/transaction_manager.go:354-365` `settleRejectedRemoteEntries` 保持 Quarantined；唯一解除 `acknowledgeRemoteCommit`（`:1012`）需新提交，而写准入对 Quarantined 返回 `ErrRemoteFenced`
（`batch.go:256-265`）；被拒写未推进版本不触发重载；`ManagerAccess.Get` 实例已存在时返回原实例（`entity/manager_access.go:85-92,291-304`）。唯一通用办法 `ManagerAccess.Destroy(..., false)` 未被定为入口。
`ErrRemoteFenced` 与真正 fence 同一错误，业务无法区分。回归 `TestRejected*IsNotCarriedByNextWrite` 用测试专用 `loader.add(reloaded)` 换实例（`rejected_memory_quarantine_test.go:188-189`）。

## 修复约束（维护者 2026-09-26 批准：拒绝收尾后框架自动仅内存卸载）

拒绝收尾、释放 gate 后，框架在正确执行位置（快池持锁 / 本地执行入口，不在慢池取 Entity 锁、不在快池阻塞）对该实例执行仅内存 Destroy（不删持久数据），下次访问从权威重载；
Sync 按 remove-before-create 回收订阅者视图；处理在途引用与并发访问；卸载失败保持隔离并可重试。不能在内存 ≠ 权威时解冻（RR-28 复核约束）。

## 修复（2026-09-26）

状态：已修复，本地验证通过，已本地提交，未推送/发布。详见[修复记录](../bugfix/RR-20260926-39.md)。
持久拒绝收尾（回滚 + 隔离）并释放 gate 后，框架经 `NestMgr.RunLocal`（与 RR-30 驱逐同一个 `LocalExecutorBinder` 接线）在快池对旧实例执行仅内存卸载
（`ManagerAccess.Unload`，与 RR-30 驱逐共用；`DestroyReasonMemoryUnload`），旧实例保持隔离、从不解冻；下一次访问经 loader 从权威重载；Sync 按 RR-30 规则
关闭旧状态、订阅保持，重载后 Rebind 强制全量；卸载失败保持隔离并重试；loader 不支持卸载时维持旧行为。修前红：四种持久级别下旧实例都未被卸载，
下一写者持续 `ErrRemoteFenced`。
