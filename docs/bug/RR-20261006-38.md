# RR-20261006-38：生成的 `shutdown` 段写着 `serve_wait_timeout`，没有任何代码读它

2026-10-07，基线 `66d72a33`（main）。P3（配置文件里有一个看起来能调、实际不生效的键：运维调它等 Serve 退出更久或更短，什么都不会发生；
停机预算的生成注释也没有把它算进 `total_timeout`）。来源：A4 ①（维护者第十三轮要求本版完成，[方案](../feature/A4-1-MOD-CONFIG-SCHEMA-2026-10-07.md)）
把生成器的配置段接上 Mod 的声明后，`TestGeneratedConfigsMatchDeclarations` 第一次运行即发现。状态：已复现；已修复、声明场景验证，未发版。
[修复](../bugfix/RR-20261006-38.md)。

## 机制

`codegen/internal/roost/shutdown_budget.go` 的 `renderShutdownConfig`（基线第 242、256 行）在每个服务配置的 `shutdown:` 段末尾写
`serve_wait_timeout: 5s`。App 停机时取消 Serve 的 ctx 后直接进入停机（`app/app.go` 的 `--- Graceful shutdown ---`），没有任何“等 Serve 返回多久”
的配置；app、kit 的非测试源码里没有一处读 `shutdown.serve_wait_timeout`：

```text
$ grep -rn "serve_wait" --include='*.go' .   # 基线 66d72a33，排除测试
codegen/internal/roost/shutdown_budget.go:242:			"  total_timeout: %s\n  serve_wait_timeout: 5s\n",
codegen/internal/roost/shutdown_budget.go:256:		"  total_timeout: %s\n  serve_wait_timeout: 5s\n",
$ grep -rn "serve_wait" --include='*.go' app kit | wc -l
0
```

codegen 的测试把这一行当作 `shutdown:` 段的结束标记（`shutdown_budget_test.go`、`shutdown_budget_promises_test.go`），所以它一直留着。

## 触发 / 预期 / 实际

- 触发：`roost project new` 生成任意服务配置。
- 预期：生成器写进配置文件的每个键都有读取方（A4 ①：配置段从 Mod 的声明生成）。
- 实际：`shutdown.serve_wait_timeout` 没有声明、没有读取方。

## 复现

A4 ① 的生成配置检查（`codegen/internal/roost/config_declarations_promises_test.go`）在生成器仍写这一行时（变异 M5：把这一行加回 `renderShutdownConfig`）：

```text
--- FAIL: TestGeneratedConfigsMatchDeclarations (0.03s)
    config_declarations_promises_test.go:84: configs/service/config.account.yaml: config: shutdown.serve_wait_timeout is not a key any framework mod declares (misspelled? nothing would read it)
    config_declarations_promises_test.go:84: configs/service/config.account.prod.example.yaml: config: shutdown.serve_wait_timeout is not a key any framework mod declares (misspelled? nothing would read it)
```

## 根因与方向

生成器的配置段是手写字符串，与运行时读取没有对照——A4 ① 要消灭的那一类漂移。修复删掉这一行，生成的配置段改由声明渲染并由检查守住。
