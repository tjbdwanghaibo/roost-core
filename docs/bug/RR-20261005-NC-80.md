# NC-80：httpserver.JSON 先写成功状态再编码，编码失败变成 2xx 空体

2026-10-05，基线 `50e9a4e853641f348c879b85c282af9c5813f656`。P2。状态：已复现、已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-80.md) · [本轮](../review/REVIEW-2026-10-05-noncore-n02.md) · [证据](../bugfix/evidence/noncore-bugfix-20261005-n02/README.md)。

## 触发与影响

`httpserver.JSON`（基线 `httpserver/server.go:211`）先 `WriteHeader(status)`，再 `json.NewEncoder(w).Encode(value)` 并丢弃错误。Encoder 只在整段编码成功后写出字节，所以值里有 NaN/±Inf、channel/func、`MarshalJSON` 返回错误时：状态已是 2xx，响应体为空，服务端无日志。`MarshalJSON` panic 时状态同样已发出，recover 中间件追加的 500 错误体落进 200 响应（`superfluous WriteHeader`）。

受影响的正式链路（图谱 trace_path inbound JSON 共 15 个调用者，09-30 代际，已用当前源码补证）：

- 生成 Webroute：`//roost:web` → `codegen/cmd/webroute` 生成 `RegisterRoutes` → `webroute.RegisterModules/Registrar` → `httpserver.Engine` → `webroute.WriteResult`（`webroute/route.go:173`）→ `JSON`。业务已执行，`httpclient.DoJSON` 因 200 且 body 为空返回 `nil`，调用方拿到零值当成功（`httpclient/client.go:200`）。
- Kit Ops：`OpsMod` Init→Provide→Start 的 `/admin/execute`（`kit/ops/ops_mod.go:291`）把业务 `admin.Result.Data` 交给 `JSON`；GM 命令已执行（副作用已发生），运维收到 200 空体。`/statsz` 等同一出口。

0/0 胜率、平均值除零是业务里真实会出现的 NaN；对外部客户端来说这是“成功但没有内容”的静默失败，重试与否都无法判断。

## 复现

正式 CLI 生成的独立 module、Registrar 注册、真实回环 HTTP、`httpclient` 消费：`calls=2 err=<nil> out={WinRate:0}`。overlay 5 种不可编码值全部 `status=200 body=""`（panic 情形为 200 + 错误体），`httpclient err=<nil>`；正式 Ops 装配 `executed=1 status=200 body=""`。可编码值字节形状控制通过。原文见 [证据](../bugfix/evidence/noncore-bugfix-20261005-n02/README.md)。

## 根因

响应的状态码属于编码结果的一部分，却在编码之前提交；编码错误被 `_ =` 吞掉，调用方无从得知。
