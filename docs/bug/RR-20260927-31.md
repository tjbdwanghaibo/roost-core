# RR-20260927-31：Cast 捕获失败被业务吞掉后事务照常提交（RR-20260927-11 的同类，修前即有）

日期：2026-09-27。基线：本地 main `001b03b`。来源：第六轮独立审计（审计记录随第二路合并后写入 `docs/review/REVIEW-2026-09-27-audit6.md`）。等级 **P3**：动态取得的实体未进入回滚 / 持久化参与，却随事务提交。引入：修前即有。状态：已修复（[修复记录](../bugfix/RR-20260927-31.md)，分支 `fix-r8-b13`，基线 `a136c98`），本地提交，未推送。

`nest/cast.go` 取锁后 `tx.CaptureEntities(lockedNow)` 失败只把错误还给业务（`:188-192` 附近），没有事务级“必须失败”记号；业务吞掉错误继续执行时事务照常提交。
审计探针 `TestAud8CastCaptureFailureSwallowed`：`reply=ok/<nil> commits=1 pilot=55`。

修复约束：与 RR-20260927-11 同一机制——Cast 捕获失败在 `RollbackTx` 上记“必须失败”，handler 结束时并入错误、整条回滚，不是锁超时、不重排；锁已取得的实体按既有路径释放；RR-11 / RR-73 / RR-26 回归不回退；USER_GUIDE §4 同步。
