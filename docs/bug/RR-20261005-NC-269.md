# NC-269：TaskPool 先 Shutdown 再 Start 之后再也停不下来；Shutdown 后 Start 把池标成 running 却拒绝一切任务

2026-10-06，基线 `dc877c04`，分支 `revleft`（N11～N13 留项与小防护）。**P3**。来源：N13 观察 O9（生命周期部分）。状态：已复现，已修复（见文末）。[本轮](../review/REVIEW-2026-10-06-revleft.md) · [证据](../bugfix/evidence/noncore-bugfix-20261006-revleft/README.md)。

## 触发与差异

`goroutine/task_pool.go`（基线 :96-130）：Start 只看 `running` CAS；Shutdown 用 `closeOnce`，`running` 为 false 时 once 照样执行却不关任何 worker。

1. 未 Start 就 Shutdown，然后 Start：worker 起来读未关闭的 channel；之后每次 Shutdown 因 once 已执行都不关 worker，等满超时返回错误——池永远停不下。
2. Start → Shutdown → Start：CAS 成功、起读已关闭 channel 的 worker（立即退出），`IsRunning()` 为 true，之后 Submit 全部报 worker closed。

- 预期：池一次性；Shutdown 之后 Start 无效；Shutdown 总能停下已启动的 worker。
- 实际：见上。零调用方。`totalTasks` 在入队后才加（统计瞬间 completed > total）没有确定性红测试，未改，见本轮记录。
