# NC-91：轻量 RPC 被派发队列拒绝时不回包，调用方等满超时；开了可靠总线还会被当成消息写进死信

2026-10-05，基线 `be7bcc18`（N03 源码与 `7922e428` 相同）。**P2**（过载 / 停机窗口里“明确没有执行”被报告成“超时、结果未知”，调用方等满整段预算；死信里混入无法重放的 RPC 请求）。状态：已复现（真实 NATS + 包内），未修复。[本轮](../review/REVIEW-2026-10-05-noncore-n03.md) · [证据](../review/evidence/noncore-review-20261005-n03/README.md)。

## 触发与差异

轻量 RPC（`Bus.Call` / `CallTo` / `CallAsync`，或 ServiceRPC 默认传输）到达服务端时，Bus 派发池拒绝了它：worker 队列满（`worker.ErrWorkerQueueFull`），或派发器不在运行（停止开始到退订完成之间，`b.pool` 已置空）。

- 预期：服务端已经确定不执行，应像“无 handler”（`bus/bus.go:862-872`）和“非法请求信封”（`:727-735`）那样立即回一个失败 envelope，调用方拿到明确拒绝。死信队列只承载异步消息（`ReliableStore` 只给消息 inbox / DLQ，见[通信机制](../review/IMPLEMENTATION-MESSAGING-RPC-BUDGET-AND-TERMINAL-OWNERSHIP.md)）。
- 实际：`dispatchTask`（`bus/bus.go:761-789`）对 RPC 任务与消息一视同仁：只记日志 / 指标并 `deadLetter`，**不回包**。调用方一直等到自己的超时，得到 `nats: request timeout`——它无法知道请求根本没被执行。开了可靠总线时，RPC 请求被写进 `(ToModule="", MsgName=method)` 的死信桶；`DeadLetterEntry` 不保存 reply / SessionId，`RequeueDeadLetters` 会把它当普通消息发到 `srv.<sid>`（`bus/bus.go:228-239`、`bus/reliable.go:258-274`），只会再次落进“no handler”死信。

## 复现

真实 NATS（`TestRevn03ProbeLightweightRPCFullQueue`，worker_num=1，先用 1100 个 `CallAsync` 塞满 1024 的队列，handler 阻塞）：

```
ERROR bus: dispatch task failed module="" msg=Block msg_id=... err="worker: queue full"
call refused by full queue: err=rpc: revn03q....rpc.rvq.Block failed after 1 attempts: nats: request timeout elapsed=2.00182475s
```

包内（`TestRevn03ProbeRefusedRPCGoesToDLQAndRequeuesAsMessage`，派发器未运行、可靠总线开启）：

```
no reply sent to the RPC caller
dead letters for the RPC request: 1 [{MsgID:m1 ... ToModule: MsgName:mail.Send ... Reason:dispatcher not running ...}]
requeue would publish to roost.srv.7 as module message to_module="" msg_name="mail.Send" session_id=""
```

## 影响

- 过载时所有被拒绝的调用方都等满预算（ServiceRPC 默认 3s），并按“结果未知”处理：可能重试（放大过载）或把一次确定的拒绝当成需要对账的不确定结果。
- 停机窗口内到达的请求同样无回包，调用方不能及时换实例。
- 死信面板 / admin 计数里出现永远无法成功重放的 RPC 请求；`RequeueDeadLetters` 报告“已重放 N 条”而实际全部再次失败。

## 验收覆盖点

- 队列满 / 派发器未运行时，带 reply 的 RPC 立即收到失败 envelope（`decodeRPCResponse` 得到远端错误而不是超时）。
- RPC 请求不进入死信；普通消息的派发失败仍照旧写死信（`TestReliableDispatchDropGoesToDeadLetter`）。
- 没有 reply 的 RPC（不应出现）不 panic，只计数。

本轮没做：JetStream RPC 不经过这个池（见 NC-90）；容量 / 背压策略本身（队列长度、是否需要按方法隔离）不在本条范围。
