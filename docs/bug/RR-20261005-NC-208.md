# RR-20261005-NC-208：toxic 用例 POST /reset 清掉同一 toxiproxy 上别人的毒

日期 2026-10-05。基线 main `8597046c`。等级 **P3**。状态：已复现（本 agent 自起 toxiproxy / redis / nats），未修复；已修复、声明场景验证（redis/driver、kit/nats；kit/dataengine 同根因未改，留核心线），未发版（见文末）。来源：N04 观察 6、共同要求“共享环境保护”，N15 转确认。

## 触发与实际

toxiproxy 的 `POST /reset` 删除**所有**代理上的毒并启用全部代理。以下用例在开头、清理和用例中途调用它：

- `redis/driver/lock_toxic_integration_test.go:63-64,124,175,218`（共享 `redis` 代理）；
- `kit/nats/jetstream_rpc_toxic_integration_test.go:106-107,176`（共享 `nats-1..3` 代理）；
- `kit/dataengine/toxic_integration_test.go:43-44,71,131,168,223`（同上，DataEngine 核心边界，本线不改）。

在自起 toxiproxy 上先建一个别人的代理 `bystander-n15` 与毒 `someone-elses-latency`，各跑一条用例（`-run` 精确到单条）：

```
before: bystander toxics=["someone-elses-latency"]
ok  	…/redis/driver
after redis/driver: bystander toxics=[]
ok  	…/kit/nats
after kit/nats: bystander toxics=[]
```

（[脚本](../review/evidence/noncore-review-20261005-n15/toxreset_red.sh) · [输出](../review/evidence/noncore-review-20261005-n15/nc208-red.txt)。）同一隔离环境上别的会话正在注入的故障被撤掉：对方的故障用例可能在“没有故障”的情况下通过（假绿），或在半途恢复而失败。N04 观察 6 提到的 `remoteentity/process_lock_integration_test.go` 实际已自建代理、不调用 `/reset`（`:289`），不在本条。

## 根因

用例把环境脚本建的共享代理当成自己独占的：用固定代理名注入，用全局 reset 收尾。versionstore（NC-100）、mongo/driver（NC-101）与 remoteentity 的新用例已改为“自建随机端口代理、只删自己的”。

## 影响与定级

测试设施问题，造成并行会话的验收失真。P3。

## 验收

用例自建唯一命名的随机端口代理并在清理时删除，不再调用 `/reset`，也不在共享代理上加毒；bystander 代理的毒在用例前后保持不变；原用例断言不变。

## 修复（2026-10-05）

已修复、声明场景验证（redis/driver、kit/nats；kit/dataengine 同根因未改，留核心线），未发版。[修复记录](../bugfix/RR-20261005-NC-208.md)。以上原始现象与修前红保留不改。

## 补修（kit/dataengine）

2026-10-05，基线 `6c1538be`：`kit/dataengine/toxic_integration_test.go` 的三条 `TestToxicNATS*` 照 kit/nats 改为自建随机端口代理、只删自己的毒、清理时删代理；fixture 的 `ignore_discovered_servers` 改为“凡不是直连地址就打开”。修前在自起 toxiproxy 上每条用例之后 bystander 毒被清空（`bystander toxics=[]`），修后保持 `["someone-elses-latency"]`。本条至此全部修复、声明场景验证，未发版，三条用例不再需要独占环境。[补修记录](../bugfix/RR-20261005-NC-208.md#补修kitdataengine)。
