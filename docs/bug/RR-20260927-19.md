# RR-20260927-19：game-demo 场景重开复制会话失败后只记 Warn，没有可观测的计数

日期：2026-09-27。基线：main `d4234c9`。来源：[OPEN-ITEMS-2026-09-27 C18](../review/OPEN-ITEMS-2026-09-27.md)（前序边界：

## 现象与根因

推送失败后玩家仍有活跃连接时，场景重开它的复制会话（`demo/internal/service/game/scene.go.tmpl:662` `reopenLocked`）；Join 时会话尚未能打开（`:331`）也走同一
条重试链（`:361` `reopenLater`）。“稍后重试”（`SessionOpenRetryable`）最多试 `sessionReopenAttempts`（8）次；用尽，或遇到不是“稍后”的拒绝
（例如会话数达上限），`:677` 只记一条 Warn 就返回：玩家留在场景（别人仍看得到它），自己的视图要等下次登录才回来。

这是维护者接受的语义（清单 C18：接受“重试用尽记 Warn，下次登录恢复”），缺的是运营能看到的量：每个玩家一条 Warn，没有低基数指标，
告警与看板无法按比率发现“一批玩家在线却没有视图”。

## 修复约束（清单推荐，维护者 2026-09-27 决定按推荐执行）

接受现有语义（不继续重试、不踢下线）；在重试用尽 / 拒绝时除 Warn 外加一个低基数计数。

## 修复（2026-09-27）

状态：**已修复，未发布**（本地提交，未推送）。放弃重开时计 `scene_session_reopen_failed_total`，标签只有 `reason`：`exhausted`（“稍后重试”用尽）
或 `refused`（不是“稍后”的拒绝）；Warn 同时带上 `reason`。计数经进程默认指标注册表（`app.NewRegistry` 装的 `mods.ModMetrics`），由 ops 端点导出。
修前（计数调用去掉）红：`counted 0 on scene_session_reopen_failed_total{reason=exhausted}, want 1`。详见[修复记录](../bugfix/RR-20260927-19.md)。
