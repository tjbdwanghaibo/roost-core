# RR-20260925-06 Remote 慢操作占用 Nest 业务 worker

日期：2026-09-25；范围：Nest / Remote 正式调度链；等级：P2；状态：已修复；80 TPS × 10 分钟全量验收通过，21/21 故障矩阵通过，未部署。

## 触发与证据

Remote 请求与 Cost 业务共用 cost pool。`NestDispatch` 在同一个 worker 中执行 `prepareRemoteSnapshots`、`PrepareRemoteWriteBatch`、handler，以及 `finishRemoteWriteBatch` 的 Commit/Close。Remote 获取或后置确认发生网络等待时，同一 hash 槽的无关 Cost 业务无法执行，扩大业务排队与 sync timeout 风险。

此前 RR-20260925-05 消除了 Projector 跨实体串行，但没有解决 Nest 的这个执行资源耦合。期望是 Remote 前后置 I/O 使用独立慢操作资源，实体 Guard 只属于业务逻辑 worker，并保持 Remote 完成后回复。

复现使用 `TestRemoteStagesDoNotBlockCostLogicWorker`：单 cost worker、单 remote worker，分别在 Prepare / Commit / Close 设置可控屏障，随后发送无关本地 Cost 请求；屏障未释放时，本地请求应该完成，Remote 请求不应提前回复。负对照通过 Go overlay 禁用新增 Remote 分流、恢复原 cost 路径，三个阶段均因本地请求不能完成而失败；真实源码不被 overlay 修改。

## 根因与边界

等待网络的 goroutine 与执行 handler 的 worker 没有分离。不能仅延长请求 timeout，也不能无限创建 goroutine 或提前释放 Remote 写门。严格事务 WAL 持久准入仍需要原有锁内契约，本项没有把全部存储等待都移出业务 worker。
