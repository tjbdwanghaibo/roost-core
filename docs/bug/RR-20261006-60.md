# RR-20261006-60：手写 `HandlerMeta` 忘写 `Durability` 被当成 memory，要到运行期才报错

2026-10-07，基线 `b3ff8fcc`。P3（注册期能拦住的声明错误拖到运行期第一次改持久字段才暴露；不丢数据——RR-20261006-41 之后 memory 事务改持久字段会被整笔拒绝）。来源：框架文档审查 F02-8（[登记表](../review/FRAMEWORK-DOCS-FINDINGS-2026-10-07.md)），RR-20261006-41 后续发现（[修复记录“后续”一节](../bugfix/RR-20261006-41.md)）。维护者 2026-10-07 选 A：`Rollback` 不为 none 时必须显式写 `Durability`，注册时报错。
状态：已复现；已修复（`2a8b2e64`，[修复](../bugfix/RR-20261006-60.md)），未发版。

## 机制

1. `nest.DurabilityPolicy` 是 `dataengine.Durability` 的别名，`DurabilityMemory` 是 iota 的 0（基线 `nest/transaction.go:17-27`），所以 `HandlerMeta.Durability` 的零值就是 memory。
2. `//roost:nest` 标记缺省是 async（`codegen/internal/nest/gen.go` `rollbackMeta`），生成的 meta 总写明 durability；手写 `HandlerMeta{Rollback: RollbackUndo}` 则静默得到 undo + memory。
3. `validateHandlerMeta`（基线 `nest/handler.go:38-49`）只拦“durable 但 rollback=none”，undo/state + 零值 durability 原样收下。
4. RR-20261006-41 之后 memory 事务改持久字段在提交点被拒，于是这类遗漏要到运行期第一次改持久字段才报错——`skill/combatcomponent` 的两个用例就是这样撞上的。
5. 不能简单地“`Rollback != none` 且 durability 为 0 就拒”：显式写 `DurabilityMemory` 与不写在同一类型下无法区分，而 `rollback=undo durability=memory` 是生成器会产出、契约允许的组合（只改 nopersist 字段的 memory 事务）。
