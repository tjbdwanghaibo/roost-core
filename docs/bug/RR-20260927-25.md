# RR-20260927-25：自定义 `lock.Mutex` 为不可比较的值类型时，`holding` 的接口比较 panic

日期：2026-09-27。基线：`d4234c9`（批次 4 修复方复现），现 main `00f67c7`。来源：[OPEN-ITEMS-2026-09-27](../review/OPEN-ITEMS-2026-09-27.md) B06。等级 **P4**：框架实现都是指针（`lock/reentrant_mutex.go:28`、`lock/lock.go:28`），只影响自定义 Mutex。引入：RR-20260926-67（按实例判断是否已持有）。状态：已复现，未修复。

`entity/entity_guard.go` `holding` 用 `current.GetMutex() == ent.GetMutex()` 比较接口值；自定义 Mutex 是含 func 字段的值类型、同 ID 两个实例各持一份时，`RequireEntity` panic：
`runtime error: comparing uncomparable type entity.funcFieldMutex`。

修复约束：比较前先判定动态类型可比较（`reflect.TypeOf(x).Comparable()`），不可比较时按“不是同一把锁”处理（或按实体实例身份比较，二选一论证）；不引入每次加锁的反射开销到热路径（先比较指针形态、必要时才走反射），RR-67 回归不回退。

红探针（批次 4）：

```go
package entity

import (
	"sync"
	"testing"
	"time"
)

// 探针 OPEN-ITEMS B06：自定义 lock.Mutex 是含 func 字段的值类型（不可比较）时，Guard 的 holding 比较是否 panic。
type funcFieldMutex struct {
	id     int64
	mu     *sync.Mutex
	onLock func()
}

func (m funcFieldMutex) TryLock() bool { return m.mu.TryLock() }
func (m funcFieldMutex) Lock()         { m.mu.Lock() }
func (m funcFieldMutex) LockWithTimeout(time.Duration) bool {
	m.mu.Lock()
	return true
}
func (m funcFieldMutex) Unlock()       { m.mu.Unlock() }
func (m funcFieldMutex) LockId() int64 { return m.id }

func TestProbeB06UncomparableMutexValue(t *testing.T) {
	id := mustBuildTestEntityID(t, 6801, testEntityCategoryPlayer, EntityKindNone)
	oldMu := funcFieldMutex{id: id, mu: &sync.Mutex{}, onLock: func() {}}
	freshMu := funcFieldMutex{id: id, mu: &sync.Mutex{}, onLock: func() {}}
	old := &testEntity{EntityBase: NewEntityBaseWithMutex(id, testEntityCategoryPlayer, false, oldMu, EntityKindNone)}
	fresh := &testEntity{EntityBase: NewEntityBaseWithMutex(id, testEntityCategoryPlayer, false, freshMu, EntityKindNone)}
	guard := newEntityGuard()
	if !guard.RequireEntity(old) {
		t.Fatal("setup")
	}
	defer func() {
		if r := recover(); r != nil {
			t.Fatalf("RequireEntity(fresh) panicked: %v", r)
		}
	}()
	if !guard.RequireEntity(fresh) {
		t.Fatal("RequireEntity(fresh) = false")
	}
	guard.ReleaseAll()
}
```
