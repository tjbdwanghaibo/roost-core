# RR-20260924-23：Remote 冷准入脱离调用方取消，多实体重复计算预算

状态：已复现、修复并验证，未发布。修复见 [同编号记录](../bugfix/RR-20260924-23.md)。

## 触发与影响

首次对 Remote Entity 调用 `PrepareRemoteWriteBatch` 或 `ClaimRemoteOwnership`，构造 wrapper 时会以 `fctx.BaseContext()` 读取权威状态。调用者取消请求后，这次读取仍继续等待，其他等待同一 wrapper 的请求也受影响。真实 Redis 网络延迟会把冷路径放大成可观察的请求延迟。

此外，多实体写入逐个进入 `beginWrite`，无调用方 deadline 时各自重新获得完整 `OpTimeout`；已有较长 deadline 时又跳过框架预算。配置的准入上界因此不能约束整批请求。

## 根因与证据

- `manager.go:getOrCreate` 在本地对象构造中执行脱离请求 context 的 RPC。
- `batch.go:PrepareRemoteWriteBatch` 未在批次入口建立共同 deadline。
- `beginWrite` 和 `ownershipContext` 将“已有 deadline”误当成“已满足框架预算”。

新增 `admission_context_test.go`：冷写入、冷 ownership 两条公开入口修前均报 `cold ownership read detached from caller cancellation`；三个实体的批量准入修前报 `each entity received a fresh operation budget`。修后均通过，另断言调用方一分钟 deadline 不能覆盖配置的 100ms 上界。

[RR-20260920-08](../bugfix/RR-20260920-08.md) 修复了实体写闸排队预算，但当时没有覆盖冷构造 RPC 和整批预算。本条补足这些边界，不否定原写闸回归。
