# RR-20260927-34：生成的生产镜像 / compose / k8s 都没有提供 `configs/data`，容器启动即失败并反复重启

日期：2026-09-27。基线：本地 main `21555fd`。来源：OPEN-ITEMS 批次 7（本机 docker compose 实跑 C04 / B34 与 v1.16.1 升级演练 B32）。等级 **P2**（用生成的镜像部署即不可用）。引入：修前即有。状态：已复现，未修复。

`config_data.dir` 生成为相对路径 `configs/data`（`codegen/internal/roost/catalog.go:31`），Dockerfile 运行阶段只拷二进制与 healthprobe（`codegen/internal/roost/render.go:1044-1045`），
compose / k8s 只挂 `config.yaml`。容器启动：`mod config_data start: configdata: stat dir configs/data: no such file or directory`，随后按 restart 策略反复重启。

修复约束：让生产镜像自带配置数据并与 `config_data.dir` 一致（例如运行阶段 `COPY --from=build /src/configs/data /app/configs/data` 并设 `WORKDIR /app`，或在容器用的配置里把 `config_data.dir` 设为镜像内绝对路径——二选一论证，
考虑 k8s 以 ConfigMap / 卷覆盖数据的做法与热更新）；加生成器回归（Dockerfile 含数据拷贝且路径与配置一致）；本机 compose 实跑验证（只用本地镜像，不拉取、不推送）。
