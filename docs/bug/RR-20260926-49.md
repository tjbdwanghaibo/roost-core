# RR-20260926-49：已持久提交的事务若回复错误链中含锁超时类错误，会被 requeueTransientDispatch 重新准入——已提交事务可能被重复执行

日期：2026-09-26。基线：本地 main `2330d57`（RR-30、33～47 修复合并后，未推送）。来源：修复合并后独立审计。等级 **P2（潜在）**：机制已确认，真实可达路径未确认（真实 remoteentity Close、提交回调、快池续行目前不产生这两类错误；提交回调 panic 以 %v 包装丢链）。基线同样。状态：替身复现，未修复。

`nest/group_transition.go:353` `requeueTransientDispatch`（`nest/nest_dispatch.go:96` 调用）只判 `ErrLockTimeout` / `ErrEntityLockGroupChanged`，不看 `ErrAfterCommitFailed`。
复现：[REPRO-2026-09-26-05](REPRO-2026-09-26-05.md) §2：替身批次 Close 返回包裹 ErrLockTimeout 的错误 → `handler runs=401`，回复 `nest: transaction committed but after-commit work failed: … lock timeout`。

修复约束：已持久提交（错误带 `ErrAfterCommitFailed` 或 Msg 显式已提交状态）的事务一律不重新准入；提交回调 panic 用 %w 保留错误链。

## 修复（2026-09-26）

状态：**已修复，未发布**（本地提交，未推送）。`Msg` 记录“本条消息自己的事务已越过提交点”（strict / memory 持久提交成功、
pipelined 记录被 WAL 接纳、memory 快路径已准入；嵌套独立事务不认领），`dispatchNest` 在该状态、Remote 已持久提交 / 结果未知，
或错误链带 `ErrAfterCommitFailed` / `ErrCommitIndeterminate` 时不再重新准入；`runCommitCallback` 以 `%w` 保留 panic 原因链。
修前红：§2 替身 handler 执行 401 次；纯本地 strict 提交后 release hook 抛出带锁超时的错误同样执行 401 次、持久提交 401 次
（值 10→411，说明本地路径实际可达）；AfterCommit panic 原因 `errors.Is=false`。详见[修复记录](../bugfix/RR-20260926-49.md)。
