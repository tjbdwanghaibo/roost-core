# RR-20260924-04：广播释放异常漏归还引用并中断后续实体

- 日期 / 基线：2026-09-24，`967bc69` 加 Nest N1 / RR-03 工作树；等级 P2。
- 范围：Nest 广播逐实体清理，与是否启用 Sync 无关。
- 状态：已复现、已修复；验证见 [修复记录](../bugfix/RR-20260924-04.md)，未提交、未发布。

## 触发与差异

一次广播包含实体 A、B。A 的 EntityManager release hook 抛出 panic。

预期：A 的锁和 Touch 引用都归还，异常被记录在逐实体恢复边界内，B 继续执行。广播原有 handler panic 和缺失实体逻辑都遵循逐实体隔离。

实际：`broadcastDispatch` 在一个 defer 内先 `recover`，再 `ReleaseEntity`，最后 `UnTouch`。ReleaseEntity 内的 hook panic 发生在 recover 调用之后，跳过 UnTouch 并逃出整个广播；A 保留 Touch 引用，B 不执行。Guard 自身会解开 A 的 mutex，但不能代替 Nest 配对 UnTouch。

根因位置：[nest_dispatch.go](../../nest/nest_dispatch.go) 的 `broadcastDispatch`。与 [RR-20260924-02](RR-20260924-02.md) 的组锁泄漏是不同资源和恢复边界；不能以组锁修复已通过推断广播已经覆盖。

## 最小复现

Go 1.27.0，darwin/arm64。[dispatch_lifecycle_test.go](../../nest/dispatch_lifecycle_test.go) 使用真实 EntityManager hook、Guard 和继承 EntityBase 的引用计数探针，无 sleep：

```sh
GOCACHE=/tmp/roost-nest-go-cache GOWORK=off go test ./nest \
  -run TestBroadcastReleasePanicBalancesTouchesAndContinues -count=1 -timeout=30s
```

修前实际输出：

```text
release panic escaped per-entity boundary: release hook
broadcast calls = [10200033], want both entities
entity 10200033 touches/untouches = 1/0, want 1/1
entity 10201057 touches/untouches = 0/0, want 1/1
```

影响是异常广播的后续实体漏执行及引用滞留。未推断所有 release hook 都会失败，也未将正常成功广播描述成有问题。
