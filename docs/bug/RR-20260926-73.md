# RR-20260926-73：memory（不可回滚）handler 内 Cast 等锁期间目标被摘除，返回锁超时后整条重排，已做的修改重复生效

日期：2026-09-27。基线：本地 main `736bdb2`（RR-64～72 合并后，未推送）。来源：第三轮修复后独立审计（[REVIEW-2026-09-27-audit3](../review/REVIEW-2026-09-27-audit3.md)）。等级 **P3**（生产可达）。引入：修前即有（`2373e21` 同样）。状态：已复现，未修复。
（最终状态见文末修复节：**已修复，随 v1.17.1 发布**，详见[修复记录](../bugfix/RR-20260926-73.md)。上面的“状态”是登记时的原值，保留不改。文中“复核残留”的后续处理以 [OPEN-ITEMS-2026-09-27](../review/OPEN-ITEMS-2026-09-27.md) 为准。——2026-09-27 回写，OPEN-ITEMS A13②）

路径：memory handler 先改声明实体 → Cast 更高锁组实体（锁序允许，`RequireEntity` 等待）→ 等待期间目标被 Destroy 或仅内存卸载
（生产上 DataEngine 驱逐、RR-39 持久拒绝卸载都会发生）→ 取得锁后见实体已摘除，`nest/cast.go:171` 返回 `ErrLockTimeout` →
业务照常返回 → `nest/nest_dispatch.go:101` `requeueAllowed` 放行（`nest/msg.go:227` 只排除越过提交点与 RR-64 的新建冲突）→ 整条重排。
不可回滚的 handler 修改不撤销，重执行就是重复修改；目标若随后被重新加载，第二次执行可能成功，结果是静默的重复修改。
复现：[REPRO-2026-09-26-07](REPRO-2026-09-26-07.md) §1：memory `attempts=2 declared.Value=3`（初值 1），回复 `entity not found`；state_strict 对照 `Value=1`。

修复约束（沿用维护者 2026-09-27 对 RR-64 的决定：返回错误，不重排）：
- 不可回滚的 handler（memory 快路径，或本事务 / 外层消息事务为 RollbackNone）一旦开始执行，任何锁超时 / 组迁移类暂时性错误都不再自动重排，
  回复带可 `errors.Is` 的哨兵，调用方能判别“框架没有重排、修改未回滚”（可复用或并列 `ErrCreatedEntityLockConflict` 的形状，修复方论证选择）；
  handler 开始执行前的准入阶段失败仍照常重排。
- Cast 取得锁后发现目标已摘除，返回可 `errors.Is(ErrEntityNotFound)` 的错误（目标已不在），不再伪装成锁超时；可回滚事务仍整条回滚后按原规则处理。
- 不得在快 worker 上新增阻塞等待；锁序、RR-48/49/64/65 的既有语义不回退。

## 修复（2026-09-27）

状态：**已修复，未发布**（本地提交，未推送）。按修复约束（沿用 RR-64 的“返回错误，不重排”）实现：`Msg` 新增“不能回滚的 handler 已开始执行”
事实（memory 快路径调用业务前、带 Remote 批次的 RollbackNone 事务调用业务前置位），`requeueAllowed` 据此不再重排；本该重排的锁超时 /
组迁移类错误回复新哨兵 `nest.ErrNonRollbackNotRequeued`（原因链保留）。handler 之前的准入失败不置位，照常重排。Cast 取得锁后发现目标已
摘除时返回 `fmt.Errorf("%w: …", ErrEntityNotFound)`，不再是 `ErrLockTimeout`；可回滚事务整条回滚、按原规则不重排。
修前红（§1 探针改写，基线 `62fdbe6`）：memory `attempts=2 declared.Value=3 (want 1/2)`、state_strict `attempts=2`；memory handler 返回锁超时 /
组迁移三类错误 `attempts=2 declared.Value=3`；带 Remote 批次的 memory handler `attempts=2 value=3 batches=2`。详见[修复记录](../bugfix/RR-20260926-73.md)。
