# RR-20261001-01：ci.yml 的 Redis job 只设 `REDIS_ADDR`，09-29 service 修复的 Redis 变体静默 SKIP 或落回 Memory 替身

日期：2026-10-01。基线：main `db4b7009`。来源：对 B 线 service 修复的独立复审（[REVIEW-2026-10-01-bline-audit-service-1](../review/REVIEW-2026-10-01-bline-audit-service-1.md) 操作提示）。等级 **P2**：与 RR-20260922-03 同类——Redis job 看起来绿，实际 9 个测试文件的 Redis 变体没有跑（account / mail / platform / chat / directory / rank / activity / session），覆盖承诺不成立。状态：已修复（见[修复记录](../bugfix/RR-20261001-01.md)）。

## 触发条件、预期与实际

- 触发：CI 的 `service-redis` job 只导出 `REDIS_ADDR`；09-29 的修复把 Redis 变体挂在 `ROOST_REVIEW_REDIS`、`ROOST_REDIS_TEST_ADDR`、`ROOST_REVIEW3_BACKEND=redis`、`ROOST_REVIEW4_BACKEND=redis` 上（`rg 'os.Getenv\("ROOST_REVIEW' kit/service service` 9 个文件）。
- 预期：Redis job 跑到这些变体，skip 守卫能发现没跑。
- 实际：变量未设 → `t.Skip` 或直接构造 Memory store（例如 `kit/service/account/rr_20260929_round3_test.go:74`、`service/mail/rr_20260929_round3_test.go:18` 的 `ROOST_REVIEW3_BACKEND != "redis"` 分支）；守卫只匹配输出里的 `REDIS_ADDR`，看不见这些 skip。

## 根因（到行）

`.github/workflows/ci.yml` Redis job `env:` 只有 `REDIS_ADDR`；“no Redis test was skipped” 守卫的正则只有 `REDIS_ADDR`。`integration_coverage_promises_test.go` 原来只钉包清单（RR-20260922-03），不钉变量名。

## 修复约束

- job 导出测试文件实际读取的每个门变量；守卫正则覆盖它们；根包加一条测试把“测试文件里 `os.Getenv` 的 Redis 门变量”钉到 ci.yml 的 `env:` 上，以后新审查轮再加变量名就会红。
