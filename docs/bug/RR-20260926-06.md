# RR-20260926-06：快池内调用框架阻塞等待入口没有 fail-fast，只会静默阻塞或死锁

日期：2026-09-26。基线：main `a22c5a5`。等级 P2（可用性；后果是整池不可用，定级不高是因为正式链路需误用才触发）。
状态：已确认（源码判定 + 关联 RR-20260926-03 的实跑复现），未修复。来源：维护者复审要求。

## 契约

roost-coding “Nest 与 Entity”：快池内不得阻塞等待；“投递到快池并同步等待”只属于慢 worker；
框架自带的等待入口在快 worker 上被调用属于编程错误，**应直接 panic（fail-fast）**，不能静默阻塞。
维护者 2026-09-26 明确要求：快池里调用阻塞的入口直接 panic。

## 现状（预期 vs 实际）

框架没有“当前 goroutine 是快 worker”的标记，所有等待入口都不检查调用位置：

| 入口 | 快 worker 上被调用时的实际行为 | 位置 |
| --- | --- | --- |
| `entity.RunLocal`（ctx 带慢阶段执行器） | 投递快续行并 `<-call.done` 等待：快池 worker 数个并发即全池死锁，Guard 不释放，Shutdown 排不空（RR-20260926-03） | `entity/local_executor.go:22-31`，`nest/remote_dispatch.go:62-77` |
| `ManagerAccess.Get/GetMany` 冷路径（ctx 未带 `LoadedEntitiesOnly`） | 在快 worker 上执行 loader I/O，或在 `<-flight.done` 等待同实体在途加载 | `entity/manager_access.go:97`（只有带标记才拒绝）、`:128-133` |
| 生成的 lifecycle `Get/GetOrCreate`、handler 直接持有的 `ManagerAccess` | 同上；只有 `msg.getter` 被 `loadedGetter` 包装 | `nest/nest_dispatch.go:147-149` |
| `remoteWriteBatch.Commit` 的 strict 等待 | 设计上在慢阶段；快阶段若被直接调用会在 `waitRemoteTransaction` 阻塞，当前无检查 | `remoteentity/batch.go:453`、`remoteentity/transaction_tracking.go:119` |
| handler 内 `Nest.Request*` | **已拒绝**：返回 `ErrSyncInHandler`，不阻塞 | `nest/client.go:191-193` |

`fctx.InNestHandler()`（`fctx/context.go:81-84`）只判断 `Meta.Source == "nest"`，不区分快、慢阶段，
不能直接作为“快 worker”判据。快 worker 的上下文由 `nest/dispatch_queue.go:219`（`WithSource("worker")`）
与 `nest/nest_dispatch.go:192`（`Source: "nest"`）建立，续行由 `nest/remote_dispatch.go:35` 用快照恢复。

## 影响

误用（包括 RR-20260926-03 那种上下文泄漏）不会在调用点报错，而是表现为请求超时、快池吞吐塌陷、
Guard 长时间持有、停机超时；定位只能靠 goroutine 堆栈。调用点的 panic 会带出栈和入口名，
并被 Nest 既有的 recover 点（`nest/nest_dispatch.go:50,153`、`nest/remote_dispatch.go:39`）转成请求错误，
走正常回滚与 Guard 释放，不会让进程退出。

## 实施方向（约束，不是命令）

- 快 worker 与快续行执行期间建立显式“快阶段”标记（区别于慢阶段）；慢阶段注入的执行器不随快照进入快阶段。
- 列举框架自带的等待入口（上表前四项及实现时新发现的）逐个在入口处检查，命中即 panic，消息包含入口名与 handler；
  不做全局 hook，也不拦截业务自写的任意阻塞 RPC（roost-coding 已写明框架不自动隔离）。
- **显式豁免**：当前契约内的锁内 WAL 准入等既有行为不属于本条，修复时要列出豁免清单，不能一刀切 panic。
- `Nest.Request*` 目前返回 `ErrSyncInHandler`（已有测试 `TestNestHandlerRejectsNestedSyncDispatch` 依赖 `errors.Is`）。
  是否统一改为 panic 是行为变化，修复时由维护者决定并在 CHANGELOG 标注。
- 与 RR-20260926-03 的关系：03 的修复让快阶段的本地步骤就地执行、冷加载被拒绝；本条保证以后再出现同类误用时在调用点立即失败。

## 验收覆盖点

- 快 worker（含 Slow 消息的快续行）上调用上表每个入口：立即 panic，请求得到含入口名的错误，Guard 释放，loader 调用次数为 0。
- 慢 worker 上相同调用保持原行为（RunLocal 投递快续行、冷加载正常）。
- 快池 1 worker 时上述请求不导致 Shutdown 超时。
- 豁免清单中的入口在快阶段不 panic。

本轮只做了源码判定，没有写 panic 的原型实现。
