# RR-20260926-77：RR-46/53/65 之后的“是否已提交”判别指引与停机文档不准确

日期：2026-09-27。基线：本地 main `736bdb2`（RR-64～72 合并后，未推送）。来源：第三轮修复后独立审计（[REVIEW-2026-09-27-audit3](../review/REVIEW-2026-09-27-audit3.md)）。等级 **P4**（文档）。引入：RR-65 新哨兵 / RR-66 文档。状态：已确认，未修复。
（最终状态见文末修复节：**已修复，随 v1.17.1 发布**，详见[修复记录](../bugfix/RR-20260926-77.md)。上面的“状态”是登记时的原值，保留不改。——2026-09-27 回写，OPEN-ITEMS A13②）

1. `docs/USER_GUIDE.md` 等处 RR-46/53 的“是否已提交，看有没有 `ErrAfterCommitFailed`”已不准确：RR-65 的 `ErrNestedTransactionCommitted` 保留原因链，
   外层原因为锁超时时回复同时满足 `errors.Is(ErrLockTimeout)` 而不带 `ErrAfterCommitFailed`，按旧指引写重试的仓外调用方会重复执行已提交的独立事务。
2. 可回滚事务“`ErrCreatedEntityLockConflict` 与 `ErrLockTimeout` 并存 = 已重排、次数耗尽”的说明，在外层已有嵌套提交又遇新建冲突（回滚但未重排）时不成立。
3. `docs/DEPLOYMENT.md` §8“调大 `dataengine.shutdown_timeout` 后执行 sync 即重算宽限期”不准确：生成公式用常量 30s，sync 不读该配置，只有 doctor WARN。

修复约束：只改文档与导出符号的 godoc：给出一张“回复错误 → 是否可能已提交 → 能否重试”的判别表（覆盖 `ErrAfterCommitFailed`、`ErrNestedTransactionCommitted`、
`ErrCreatedEntityLockConflict`、`ErrLockTimeout`、`ErrCommitIndeterminate` 及 RR-73～75 新哨兵），规则为“带任一‘可能已提交’哨兵即不得重试”；DEPLOYMENT 改为如实描述。

## 修复（2026-09-27）

状态：**已修复，未发布**（本地提交，未推送）。只改文档与导出符号的 godoc：`docs/USER_GUIDE.md` §4 新增“回复错误判别”表（11 行，
覆盖 `ErrCommitIndeterminate`、`entity.ErrRemotePersistenceIndeterminate`、`ErrAfterCommitFailed`、`ErrNestedTransactionCommitted`、RR-73～75 的
`ErrNonRollbackNotRequeued` / `ErrNestedTransactionRollbackConflict` / `ErrNestedTransactionInRemoteMessage`、`ErrCreatedEntityLockConflict` 两种形态、
`ErrLockTimeout` 类、`ErrCommitRejected`），规则“自上而下取第一个命中行，带任一‘可能已提交’哨兵即不得重试”；RR-46/53 那句改为指向判别表；
RR-48 一段补“嵌套已提交时两者并存但未重排”的例外；`nest` 包 5 个既有哨兵的 godoc 补“是否可能已提交 / 能否重试”。
`docs/DEPLOYMENT.md` §8 改为如实描述：sync 不读 `dataengine.shutdown_timeout`（公式按 30s 常量），须同时手动调大 `total_timeout`；doctor 只 WARN。
