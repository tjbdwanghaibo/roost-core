# RR-20261004-10：game-demo 刷新回合里“租约丢失 → 重新认领”逐个等撤离，一批租约同时丢失时把刷新循环占住超过租约，且排在后面的续租确认让本地窗口越过 Redis 键

日期：2026-10-04。基线：main `9bf20e28`（`playerowner.go.tmpl` 与 v1.19.2 `4ee44f34` 逐字相同，即 RR-20260921-03 / 04 修复之后）。等级 **P2**（与 RR-20260921-04 同级；见下方后果第二条）。
来源：[W-2026-10-04-03](WANTED.md)（[RR-20260921-04 修复记录](../bugfix/RR-20260921-04.md) §未验证项）。状态：已确认，已修复（本地提交，未推送、未发版）。

## 触发

可控时钟、`fakeLeaseTable`：本进程持有 8 个玩家与 1 个旁观者的租约；8 把同时在 Redis 里消失（进程停顿、Redis 被清、续租连续失败后键过期），没人接手；
每次撤离都要等满一份 `evictBudget`（实体被长事务占住，`EntityManager.Destroy` 等实体锁不读 ctx）。下一次 `renew`。

## 预期

- 一次刷新回合占住刷新循环的时间 `< Lease − RefreshInterval`（与 RR-20260921-04 的归还回合同一约束：前一次续租若没被确认，窗口只剩这么多）。
- 本回合被确认续租的租约，本地窗口不晚于 Redis 键的 TTL（`Refresh` 时设定的 `Lease`）。
- 丢失租约的玩家，无论这一轮有没有轮到重新认领，都不被 `Admit` 放行（RR-20260920-09 / RR-20261001-07）。

## 实际（修前红，基线实现 + 新回归）

```text
$ GOWORK=off go test -race -count=1 ./internal/service/game/ -run 'TestARefreshPass' -v

    playerowner_test.go:1383: the bystander's local window ends 1m0s after the renewal that set its key's TTL (Lease 30s): it was confirmed after the re-claims, and admits writes after the key can have expired
    playerowner_test.go:1403: the pass should have reached some of the lost leases and left the rest: started=9 deferred=[]

--- FAIL: TestARefreshPassStopsWaitingForRetakesWhenItsBudgetRunsOut (0.81s)
```

`-race -count=20`：两条 20/20 红。第一条的 9 次撤离 = 8 次重新认领 + 回合末尾对旁观者的一次闲置归还（时钟已被拨过 `HandBackIdle`）。
旁观者那一行随 `Refresh` 结果顺序（map 迭代序）变化：排在重新认领之后确认时本地窗口晚于 Redis 键 10s～40s；排在最前时窗口不越界，但回合结束时已耗尽
（核实探针另见 `confirmed lease has -5s left and admission needs 5s`）。两种都违反预期。

## 根因（基线行号，`demo/internal/service/game/playerowner.go.tmpl`）

- `:528-608` `renew`：`:529` 对 `Refresh` 的结果**逐个**处理；default 分支 `:558` `interrupt` → `:559` `Claim`，`Claim` 跨间断时 `:1017` `dropResident(ctx, …)`
  等到 `:455` `evictWait`（= `evictBudget` 5s）。N 把同时丢失 → N × 5s，跑在 `refreshLoop:510` 唯一的 goroutine 上，期间没有续租。RR-20260921-04 只给 `:607` `handBackIdle` 加了 `handBackPassBudget`（`:367`、`:679`、`:688`），重新认领在预算之外。
- 同一循环里 `:532` `confirmRenewal` → `:806` `validUntil = now() + Lease`：窗口从**确认时刻**起算，而 Redis 在 `Refresh` 时就设好了 TTL。排在若干次重新认领之后的 Held 结果，
  本地窗口比键晚到期“前面等过的时间”——本进程在键可能已过期、别的进程可以合法接手之后仍放行写入（RR-20260920-04“只根据确认过的续租回答”被绕过）。RR-20260921-04 的预算推导
  （“回合之前的续租把每把租约确认到 `Lease`”）也以续租先于等待为前提。

## 修复约束

- 续租确认先于一切等待：先处理完全部 `Refresh` 结果（Held 确认、Err 只记、丢失的 `interrupt` 并入列表），再做重新认领与归还。
- 重新认领与 RR-20260921-04 的归还共用一份回合预算（`handBackPassBudget`），重新认领在前；撤离等待受预算 ctx 约束（不只是记账）。
- 超预算没轮到的丢失租约留到下一轮：保持 `interrupted`（`Admit` 拒绝）、不碰副本、不关连接——与“Redis 没答复重新认领”同一结局；轮到但副本扔不掉的仍按 RR-20261001-07 `abandon`，不放行 stale 副本。
- 不在快池阻塞；刷新循环自己的 `Claim` 仍不会等到进行中的归还（归还在重新认领之后、同一 goroutine）。RR-20260921-03 / 04、RR-20261001-07、RR-20260930-23、RR-20260920-12 的回归保持绿。
