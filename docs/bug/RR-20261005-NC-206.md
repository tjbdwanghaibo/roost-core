# RR-20261005-NC-206：生成的 .gitignore 不忽略 data/wal，WAL 段会被 git add -A 提交

日期 2026-10-05。基线 main `8597046c`。等级 **P3**。状态：已复现，未修复；已修复、声明场景验证，未发版（见文末）。来源：N08 观察 O7、NC-74 记录“观察”，N15 转确认。

## 触发与实际

NC-74 之后生成器把 `data/wal`（DataEngine 默认 WAL `data/wal/dataengine`，第二个进程 `data/wal/dataengine-<sid>`）与 `.dev` 一样当作运行期输出（`codegen/internal/roost/generate.go:476-480` `skippedProjectDirectory`）。生成的 `.gitignore`（`codegen/internal/roost/render.go:32`）有 `.dev/`，没有 WAL 目录。新增 `gitignore_runtime_promises_test.go` 用真实 `git check-ignore` 修前：

```
generated .gitignore does not ignore data/wal/dataengine/000001.wal, which generation itself treats as runtime output
generated .gitignore does not ignore data/wal/dataengine-2/000001.wal, …
```

## 影响与定级

`make dev-run` 后 `git add -A` 会把 WAL 段（玩家数据、可能很大）提交进业务仓库。生成器与版本控制对“什么属于工程”的边界不一致。定 P3。

## 验收

新工程的 .gitignore 忽略 `data/wal/` 下全部内容；`configs/data`、`data/` 下其他文件不被忽略。已有工程的 .gitignore 归用户所有、sync 不覆盖，需要手工补一行（写进 CHANGELOG）。

## 修复（2026-10-05）

已修复、声明场景验证，未发版。[修复记录](../bugfix/RR-20261005-NC-206.md)。以上原始现象与修前红保留不改。
