# NC-262：robot 超时之后才到的应答被当成推送分发

2026-10-06，基线 `dc877c04`，分支 `revleft`（N11～N13 留项与小防护）。**P3**。来源：N12 观察 O8 后半。状态：已复现，已修复（见文末）。[本轮](../review/REVIEW-2026-10-06-revleft.md) · [证据](../bugfix/evidence/noncore-bugfix-20261006-revleft/README.md)。

## 触发与差异

`robot/session/session.go` `dispatch`（基线 :252-263）：seq 非 0 的包找不到 pending 时落到下面的推送分发，同 msg id 的 `WaitPush` 等待者与推送 handler 收到这条旧应答。传输层约定 seq 0 才是推送（`transport.Packet` 注释），game-demo 的 playertcp 适配器也只把服务端推送标成 seq 0。

- 预期：Call 已经超时 / 放弃之后到达的应答丢弃。
- 实际：请求与应答共用 msg id 的协议里（`RegisterCall` 文档允许 `respID == reqID`），旧应答被当成推送，`wait_push` 节点拿到错误的消息、推送 handler 多处理一条。

## 复现

`robot/session/session_promises_test.go `TestALateResponseIsNotDeliveredAsAPush`（先让 Call 超时，再依次送入迟到应答与真推送）`。修前（[原文](../bugfix/evidence/noncore-bugfix-20261006-revleft/nc261-262-red.txt)）：

```
--- FAIL: TestALateResponseIsNotDeliveredAsAPush (0.02s)
    session_promises_test.go:196: WaitPush delivered "late response", want the push: a response that arrived after its Call timed out was delivered as a push
    session_promises_test.go:201: push handler saw ["late response" "push"], want only [push]: the late response reached the push handler
```
