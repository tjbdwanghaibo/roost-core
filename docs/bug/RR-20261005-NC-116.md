# NC-116：Applier 开新 epoch 时拒绝 BaseSequence 非零的 full 包后 pendingEpoch 不复位，之后永远 ErrApplyInProgress

2026-10-05，基线 `855c2a38236f4efc9575fa9ba84bf8bf4100daf3`。P3（客户端 Applier 永久不可用，只能重建；需要一个畸形 full 包触发，服务端 History 不会产生，仓内没有正式调用方）。状态：已复现、已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-116.md)。[本轮](../review/REVIEW-2026-10-05-n09-batch2.md)。

## 触发与差异

`Applier.admit`（`skill/skillsync/applier.go:177-215`）在第一包或 epoch 切换时先置 `applier.pendingEpoch = packet.Epoch`（`:190`、`:195`），之后才检查 full 包 `BaseSequence != 0`（`:204-206`）并返回 `ErrPacketShape`。这条返回不经过 `Apply` 的收尾（`Apply` 在 `admit` 出错时直接返回，`applier.go:114-117`），`pendingEpoch` 不再清零。此后每个包在 `:177-179` 得到 `ErrApplyInProgress`。

预期（`applier.go:79-81` 注释“reentrant/concurrent application returns ErrApplyInProgress and can be retried”）：被拒绝的包不改变 Applier 状态，下一份合法 full 能恢复。实际：永久卡死。

## 复现

`skill/skillsync/applier_epoch_admission_promises_test.go`（基线代码上）：

```
--- FAIL: TestRejectedFullPacketDoesNotWedgeTheApplier (0.00s)
    applier_epoch_admission_promises_test.go:36: first epoch: valid full after a rejected one = {Applied:false Duplicate:false Sequence:0 Epoch:0}, skillsync: another packet is being applied to the stream (epoch 0); the rejected packet wedged the applier
```

## 影响

传输损坏、旧版本服务端或恶意包让一个客户端的 skill 同步永久停摆，重试与 Recover 都无效。

## 验收覆盖点

第一包与 epoch 切换两种情形下，被拒绝的 full 包之后合法 full 能应用；其他拒绝路径（schema、observer、gap、epoch mismatch）本来不置 pendingEpoch，保持不变。
