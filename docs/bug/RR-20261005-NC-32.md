# RR-20261005-NC-32：恢复后的嵌套子对象更新漏出持久化

2026-10-05，P2。发现基线 `c3aa0eddf67be234ba742188c53d18bbc1be9604`。范围为正式 DAO 生成器的嵌套 wire 恢复，不是 MigrationRunner 的提交准入复发。

## 承诺与反例

DAO 经 `RestorePersisted` / `Unmarshal` 装载后，可达子对象在 Nest 事务内的 setter 应向 DAO 传播 persist dirty 并进入提交记录。现有独立嵌套对象的 BSON roundtrip 只能验证原址恢复，不能替代 DAO 的转换链。

修前正式金样运行新增九项：DAO map / slice / pointer 三种父入口 × 子对象 map / slice / pointer 三种入口，均失败：`loaded child level=99 but commit records=0, want 1`。独立正式 DAO CLI 消费补查指针父对象和值父对象下的三种子入口，六项也失败：`persisted descendant changed to 99 but commit records=0, want 1`。两组均在真实 Nest 事务内修改，编译与 vet 成功，无 race、panic 或整包超时，不能把初期夹具失败当作产品红。

## 根因与影响

[template_nested.go](../../codegen/internal/dao/template_nested.go) 的 `FromBSONDoc` 原先调用 `setBSONDoc`，先把深层子对象绑定到局部父变量 `s` 的 `Mark`，再按值返回 `s`；指针转换继续复制到 `v`，值字段也会被赋值复制。DAO 的 `Init` 只为最终父对象设置顶层通知，没有递归修复子对象指向旧临时父对象的回调。

[DirtyHook](../../dataengine/hook.go) 的通知是每个结构体自己的函数槽，不是共享状态。结果是加载值正确、深层内存更新正确，但最终 DAO 看不到该更新。影响普通冷加载，也包括迁移后重新加载及使用同一 wire 恢复的回滚/同步入口；本轮新红严格覆盖上述两组声明入口，不据此宣称所有组合都已验收。它不把历史已漏写的数据自动补回。

图谱 generation 为 `2026-09-30T11:58:14Z`，相关路径无记录缺口但 metadata_changed；本结论使用当前源码、正式生成物和执行反例，不依赖旧图谱的完整性。

## 修复方向

转换只恢复未绑定的数据，最终父对象就位后才递归绑定可达子对象。保留唯一父归属检查，不能用关闭 `daoBindDirty` 冲突保护或让后绑定者覆盖前者来掩盖复制问题。不增加保存入口、反射修补或 DirtyHook 共享指针。
