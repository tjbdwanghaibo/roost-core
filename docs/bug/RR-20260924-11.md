# RR-20260924-11：DataEngine 启动/关闭与失败清理缺少统一所有权

2026-09-24；基线 `967bc69` 加前两批工作树；P1（资源泄漏和运行中入口被拆除）；状态：已修复，未发布。[修复](../bugfix/RR-20260924-11.md)。

五类问题均已复现：

1. Runtime 重复 Start 重新 ConfigureLoader，随后因 DeleteAdmitter 已注册失败，拆除 loader、关闭 Outbox；正常运行中的 runtime 被重复启动破坏。
2. Assembly 并发 Start 各自 Open 相同 WAL，7/8 次 directory locked，未复用已启动实例。
3. Assembly Start 停在 EnsureStream 时，Shutdown 看到 runtime=nil 直接返回成功；Start 之后仍可发布 ready 实例。
4. 启动恢复期间 context 取消，Assembly 用同一个已取消 context 调 Shutdown，未完成清理就丢弃局部 runtime。后续 Shutdown 返回成功，但同目录 WAL 无法再打开。
5. Projector.CloseWAL=false 时，Assembly/Runtime 没有回收自己创建的 WAL，停机后目录仍锁定。

预期：启停有可取消的串行所有权，重复启动幂等；停止是单个 Runtime 的终态；失败清理受 deadline 约束，但未完成时必须保留责任以便重试。Assembly 在一次完整 Shutdown 后可以重新构造新 Runtime。

回归位于 `dataengine/engine/lifecycle_test.go`。前四类错误中的 1/2/3 与 WAL 所有权第 5 类先由原实现复现；第 4 类修正故障夹具拦截实际 FindOneAndUpdate 后，在原 Assembly 上独立复现 `failed startup leaked WAL: directory is already locked`。未把夹具未命中引起的测试失败当成产品证据。
