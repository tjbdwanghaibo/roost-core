# RR-20260930-13：`SetEntityVersion` 不做检查就改写 StateVersion，同一 fence 下可以回退

日期：2026-09-30。基线：`4784ef82`。来源：REMAINING §3 N26（RR-20260927-15 §未验证项），维护者 2026-09-30 拍板“做”。等级 **P3**：RR-20260927-15 给 `SetRemoteVersionVector` 加的“同 fence 不回退”有一条绕过入口；仓内生产代码只有 `remoteentity/transaction_manager.go` 一处死分支调用它，实际触发要靠自定义 / 手写代码。状态：已复现；2026-09-30 已修复，未发版，见文末“修复”。

## 触发

实体版本向量已推进到 `{StateVersion: 5, LockFence: 7}`，随后调用 `SetEntityVersion(4)`（迟到的调用、或业务按旧值回写）。

## 预期

与 `SetRemoteVersionVector` 同一规则（RR-20260927-15）：这个入口从不换 fence，同一 fence 下更小的 StateVersion 被拒绝、向量不变；相等 / 更大照常写入。

## 实际

直接 CAS 改写，版本回到 4。回归 `entity/set_entity_version_no_rewind_promises_test.go` 在基线上（只用旧 API，无返回值）：

```text
--- FAIL: TestSetEntityVersionRejectsRewindUnderSameFence (0.00s)
    --- FAIL: TestSetEntityVersionRejectsRewindUnderSameFence/lower_version (0.00s)
        set_entity_version_no_rewind_promises_test.go:32: after SetEntityVersion(4): vector={StateVersion:4 MarkerEpoch:1 LockFence:7 RouteEpoch:1}, want {StateVersion:5 MarkerEpoch:1 LockFence:7 RouteEpoch:1} (a lower StateVersion under the same fence must not be written)
```

## 根因

`entity/entity_remote.go:46` `RemoteEntityBase.SetEntityVersion`：CAS 循环里只把 `next.StateVersion` 换成入参，没有与 `current.StateVersion` 比较；接口方法 `IThreadSafeRemoteEntity.SetEntityVersion(int64)` 也没有返回值可以报告拒绝。

## 修复约束

1. 同 fence 回退拒绝：`v < current.StateVersion` 返回 `ErrRemoteVersionConflict`，不写入；相等 / 更大照常。
2. 拒绝要能被调用方看到：接口与实现改为 `SetEntityVersion(int64) error`；仓内调用方（`remoteentity/transaction_manager.go` 的非向量分支）处理错误，与向量分支一样再核对 `remoteReceiptObsolete`。
3. 不放宽 `SetRemoteVersionVector` 的判据，不改 `AdvanceVersion`（DAO Tracker 的原子 CAS，另一条入口，已是“版本相等直接成功、更小拒绝”）。
4. 回归：更小 / 负数 / 相等 / 更大四种；`entity` 与 `remoteentity` 既有用例不变。
