# NC-224：spawn 进程每一步重新求值的字段按施法作用域检查——`area.from` / tracking / follow 目标等读 `$input` / `$memory` / `$local` 能编译，下一 tick 起 Advance 返回 ErrProgramInvariant

2026-10-06，基线 `57c0b3b6`。P2（编译通过；Activate 正常，从下一 tick 起每次 Advance 失败并让该进程以失败终止）。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-224.md)。[本轮](../review/REVIEW-2026-10-06-n09-batch5.md)。

## 机制

所有进程都是 spawn 启动的 owned 实体进程（`ProcessScopeEntity`；`ProcessScopeCast` / `ProcessScopePhase` 已无创建点）。进程字段在两个上下文里求值：

- 启动那一步：`startEntityProcess(cast, …)` 用**施法本身**调 `stepProcessMotion` / `stepAreaMembership`；
- 之后每一步：`advanceOwnedProcesses` 用 `detachedProcessCast(process)`——没有施法输入、memory（`evalReference` 对 `referenceInput` / `referenceMemory` 越界返回 `ErrProgramInvariant`），局部变量是进程自己的 missing 帧。

每一步重新求值的字段：area 选择（from / shape / filters，`process_area.go` `stepAreaMembership` → `buildSelectRequest`）、motion 的 follow 帧目标、tracking 目标、carry 目标、path 点、orbit 锚点、parabola 目的地，以及没有绑定到进程数值属性的数值字段（`resolveProcessNumeric` 先查绑定）。numeric track 的值与绑定的数值字段只在启动时（`initializeProcessNumeric`）求值一次。

编译期：`compile_typecheck.go` 在施法作用域里检查这些字段（`$owner` 等进程回调名字在那里不可见），`compile_owned_entity.go` 的 `validateDetachedCallbacks` 只检查 `on` 回调。AI 生成约束（`docs/skill/ai-skill-system-prompt.md`）写明“Entity-scoped processes cannot read expired Cast memory or input”，但对进程字段没有落实。

## 触发与差异

| 字段 | 编译 | 执行 |
| --- | --- | --- |
| area `from: "$input.target"` | 通过 | Activate 正常；`Advance` 第一次返回 `skill: immutable program invariant failed` |
| area `from: "$memory.who"` | 通过 | 同上 |
| tracking `target: "$input.target"` | 通过 | 同上 |
| follow 帧 `target: "$input.target"` | 通过 | 同上 |
| select each 里 spawn，area `from: "$local.t"` | 通过 | 下一步局部变量是 missing，选择失败 |

由 N09 第五批补的性质测试种子 `seed.process_start_read` 变异出：`$.phases[0].on.enter.steps[1].process.area.from=$input.target: compiled without errors but advance[0] 1: skill: immutable program invariant failed`。

`motion_test.go` 的 path（`points: "$input.path"`）与 parabola（`destination: "$input.position"`）两个用例用内部 harness 以施法本身逐步推进，掩盖了这一点；经正式 spawn 路径同样在第二步失败。

## 复现

正式回归（修前，临时还原 `compile_owned_entity.go`）`TestCompileRejectsCastValuesInOwnedProcessFields` 五个子用例全部 `compiled; diagnostics=[]skill.Diagnostic(nil)`；性质测试 `TestCompiledMutationsNeverHitProgramInvariant` 报上面那条。

## 验收覆盖点

上表字段报 `INPUT_UNAVAILABLE` 定位到引用本身（如 `.process.area.from`、`.process.motion.steering.target`）。控制：`$caster` 系列（两个上下文里都是施法者）的 area 与 tracking 进程跑满时长不出错。
