## 触发条件、预期与实际

- 触发：两个部署的 Remote Mod 连同一个 Redis db，同一 `RemoteSnapshotKey`（tenant、kind、entity id、scope、policy 相同，例如两边都从同一个种子数据起服）。
- 预期：每个部署只看到自己发布的 L2 快照。
- 实际：`remoteentity/snapshot_l2.go:198-200`（`d4234c9`）的 `remoteSnapshotL2Key` 固定生成 `remote_entity:snapshot:<tenant>:<kind>:<id>:<scope>:<policy>`，
  `Get` / `Set`（CAS）/ `Delete` / `DeleteAtVersion` 都用这个键；`remoteentity/assemble.go:108` 以它装配正式 Manager，没有任何配置能改。
  一个部署读到另一个部署的快照；另一个部署的更高版本还会让本部署的 CAS 静默丢弃自己的发布（`accepted == 0`）。
