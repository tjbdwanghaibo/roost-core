# NC-190：写错类型的配置值被静默读成零值——`singleton.enabled: on` 关掉单实例锁、不带单位的时长读成纳秒并通过校验

2026-10-05，基线 `f6245613`。**P2**（`singleton.enabled: on` / `yes` 让同 sid 单实例保护静默关闭，`nats.reliable.enabled: yes` 静默关掉可靠总线；其余实例是启动期该报却没报的配置错误）。状态：已复现，未修复（修复见文末）。[本轮](../review/REVIEW-2026-10-05-n14.md) · [证据](../review/evidence/noncore-review-20261005-n14/README.md)。来源：N01/S4 观察 O9、U-0280 审查观察，本轮核实。

## 触发与差异

运维手写配置，用了 YAML 1.1 风格的布尔（`on` / `yes` / `off`），或把时长写成数字（`ttl: 15`），或把 `redis.cluster_addrs` 写成 YAML 列表。

| 写法 | 预期 | 实际（基线源码） |
| --- | --- | --- |
| `singleton.enabled: on` / `yes` / `ture` | 启动校验报 `singleton.enabled` 不是布尔值 | yaml.v3 按 YAML 1.2 读成字符串，`cfg.GetBool`（`app/singleton.go:116`）经 `cast.ToBool` 读成 false，`validate` 在 `!enabled` 时直接返回 nil（`:133-135`），**单实例锁关闭、没有任何告警** |
| `nats.reliable.enabled: yes`、`mongo.require_replica_set: off` | 同上 | 读成 false：可靠总线不启用（`kit/nats/nats_mod.go:108`）、副本集检查关闭（`kit/mongo/mongo_mod.go:53-55`） |
| `singleton.ttl: 15`、`renew_interval: 3`、`guard: 5`、`startup_wait: 30` | 报“时长要带单位” | `GetDuration` 读成 15ns / 3ns / 5ns / 30ns，`validate` 的“为正”与三条关系全部成立（`app/singleton.go:142-169`），锁 TTL 被 `redis.CompareAndSet` 抬到 1ms，续期节拍 3ns |
| `remote_entity.lock_ttl: 15`（`validateDurationIfSet` 覆盖的键） | 同上 | 15ns，正数，通过（`app/config_validation.go:264-271`） |
| `saga.step_defaults.timeout: 5` | 同上 | 5ns，`readStepBudget` 只查 `> 0`（`kit/saga/step_budgets.go:111-115`），`StepBudgets.Validate` 也只查负数，每次尝试几乎立刻超时 |
| 服务 Mod 的 `mods.Duration` / `RequiredDuration`（`mail.claim_ttl: 30`、`abc`） | 同上 | `30` → 30ns 原样返回；`abc` → `GetDuration` 得 0，`Duration` 返回兜底值（`kit/mods/service_servicemods.go:81-105`），与它注释里“写错的值不能静默读成默认值”的承诺相反 |
| `redis.cluster_addrs: [a:1, b:2]` 或 `a:1, b:2` | Cluster，地址 `a:1`、`b:2` | 列表经 `GetString` 读成空串（`kit/redis/redis_mod.go:53`）：Redis Mod 退回 `localhost:6379` 单机，`mods.ValidateClusterKeyPrefix` 以为不是 Cluster、跳过 hash tag 校验；逗号后有空格时拆出 `" b:2"` |

根因：viper 的 `GetBool` / `GetDuration` / `GetString` 经 `spf13/cast` 宽松转换，转换失败返回零值、不报错；`cast.ToDuration` 对不含单位字母的数字补 `ns`。框架的启动校验与这些读取点都只检查转换后的值。

## 复现

正式回归（修复前在基线上运行，原文见 [nc190-red.txt](../review/evidence/noncore-review-20261005-n14/nc190-red.txt)）：

```

    ValidateServiceConfig = <nil>; want an error naming singleton.enabled (viper reads the value as false and the switch is silently off)
--- FAIL: .../reliable_bus_yes      ValidateServiceConfig = <nil>; want an error naming nats.reliable.enabled ...
--- FAIL: .../replica_set_check_off ValidateServiceConfig = <nil>; want an error naming mongo.require_replica_set ...
--- FAIL: TestValidateServiceConfigRejectsADurationWithoutAUnit/singleton_all_unitless
    ValidateServiceConfig = <nil>; want an error naming singleton.ttl
--- FAIL: TestServiceDurationsRefuseValuesWithoutAUnit
    Duration(claim_ttl: 30) = 30ns, <nil>; want an error naming mail.claim_ttl
--- FAIL: TestStepBudgetDurationsRefuseValuesWithoutAUnit
    timeout: 5 -> {Timeout:5ns MaxAttempts:5 BackoffMin:100ms BackoffMax:5s}, <nil>; want an error naming saga.step_defaults.timeout
--- FAIL: TestClusterAddrsAcceptAYAMLListAndTrimEntries
    cluster_addrs: a:1, b:2 -> cluster=true addrs=["a:1" " b:2"], want Cluster [a:1 b:2]
```

对照（修复前后都通过）：`true` / `True` / `"true"` / `1` / `0` 被接受；带单位的时长与代码里 `Set` 的 `time.Duration` 被接受；`singleton.renew_interval: abc` 已被“must be positive”拒绝。

## 影响

- 生成的配置都写 `true` / `false` 与带单位的时长，触发需要手改配置；但单实例锁是同 sid 双写的唯一保护，`on` 写法让它静默失效（方向 fail-open），所以定 P2。
- 其余实例在启动期就能拒绝，却变成运行期难以归因的现象（锁 1ms 过期反复 fail-stop、saga 步骤全部超时补偿、连到本机单点 Redis）。

## 验收覆盖点

- 框架读取的布尔开关（单实例锁、可靠总线、副本集检查、ops、日志等）设了非布尔值时，启动校验点名报错；原来接受的写法照常接受。
- `singleton.*` 四个时长、`validateDurationIfSet` 覆盖的键、`saga.step_defaults` / `saga.steps` 时长、`mods.Duration` / `RequiredDuration` 拒绝不带单位与解析不了的值，`0` 与 `time.Duration` 值行为不变。
- `redis.cluster_addrs` 接受逗号串与 YAML 列表，去掉空白；Redis Mod、单实例锁连接与 Cluster hash tag 校验读同一份地址。
- 不在本条范围：kit 各 Mod 里其余直接 `cfg.GetDuration` 的约 80 处读取（见运行记录观察 O1 与方向判断）。
