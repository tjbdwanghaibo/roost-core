# NC-131：本机兴趣表只是被过期条目占满时，Remote 健康检查一直报 capacity exhausted

2026-10-05，基线 `a80be80c`。**P3**（可观测性 / 可用性：健康 Fail 可能让编排器摘流量或重启进程；读取本身不受影响）。状态：已复现，未修复。[本轮](../review/REVIEW-2026-10-05-n05-revn05.md) · [证据](../review/evidence/noncore-review-20261005-n05/README.md)。

## 触发与差异

一段时间内读取的不同远程 key 数达到 `remote_entity.snapshot_interest_keys`（默认 65536），之后读取停止或只读已有 key。

- 预期：兴趣过期（`snapshot_interest_ttl`，默认 30s）后不再占容量，健康检查恢复 OK。
- 实际：本机兴趣表 `localInterests` 只在“新建兴趣且表满”（`remoteentity/transaction_manager.go:832-838`）或每 1024 次续租（`:851-855`）时清理过期条目；`Manager.Stats`（`remoteentity/assembly.go:34-36`）直接取 map 长度；`kit/remoteentity/remote_entity_mod.go:251-253` 在 `local_interests >= snapshot_interest_keys` 时返回 `StatusFail "capacity exhausted"`。没有新读取就永远不清理，健康永远 Fail。

## 复现

`kit/remoteentity/interest_health_promises_test.go`（上限 4、TTL 40ms，读满后等租期过去）：

```
Stats().LocalInterests = 4 after every interest expired, want 0
health after every interest expired = fail (capacity exhausted wrappers=0 local_interests=4 transactions=0 active_transactions=0), want ok
```

对照：表里 4 条都有效时报 Fail（既有容量告警，修复前后都成立）。

## 验收覆盖点

- 全部兴趣过期后 `Stats().LocalInterests` 为 0、健康 OK；表满且有效时仍 Fail。
- 清理沿用 `pruneLocalInterestsLocked`（同时撤销本机注册表里自己的 lease），不新增状态。
