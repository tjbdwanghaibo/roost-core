# RR-20260928-09：pipelined handler 带 Remote 批次、Remote 被明确拒绝时不交 finalizer，持有被拒修改的实例不隔离、不卸载

日期：2026-09-28。基线：本地 main `e10b950`。来源：批次 18 修复方范围外发现。等级 **P2**：被拒绝的 Remote 修改留在内存实例里继续可写，违背 RR-28 / RR-39 / RR-58 / RR-62“持久拒绝后隔离并从权威重载”的契约。引入：修前即有。状态：已复现（探针），未修复。

pipelined handler 带 Remote 批次时 nest 以 `outcome.Durability=3` 走 strict 等待路径；Remote 明确拒绝时等待得到 `ErrRemoteRejected`，而 `remoteentity/batch.go:508` 只认 `Durability == 2`、`:512` 只认 Durability 0，
`indeterminate` 与 `rejected` 都不置位，`DeferUntilDurableOutcome` 返回 false，`Close` 不交 finalizer，也不卸载持有被拒修改的实例。回复本身正确（判别表第 4 行）。
红探针：`GOWORK=off go test -tags probe -run TestZZProbePipelinedRemote -v ./remoteentity`，输出 `PROBE durability=3 ... row=4 ... deferTook=0`。

修复约束：pipelined（Durability 3）的 Remote 结论处理与 strict（Durability 2）一致——明确拒绝时按 RR-58 / RR-62 回滚 Remote 部分、隔离并卸载实例（从权威重载）、放行 Sync 门；结果未知时交 finalizer；
全仓核对其他按 `Durability == 2` 判定 strict 语义的地方（remoteentity / nest / kit），逐处论证是否同样要包含 3；不在快 worker 上新增等待；RR-28 / 37 / 38 / 39 / 58 / 62 与 RR-20260928-03 / 08 回归不回退。

func (m probeDeferRecorder) PrepareRemoteWriteBatch(ctx context.Context, ids []int64) (entity.RemoteWriteBatch, error) {
	b, err := m.boundedConfirmManager.PrepareRemoteWriteBatch(ctx, ids)
	if err != nil {

type probeDeferBatch struct {
	boundedConfirmBatch
	took *atomic.Int32
	dur  *atomic.Int32
}

func (b probeDeferBatch) FinalizeLocked(o entity.RemoteTransactionOutcome) error {
	b.dur.Store(int32(o.Durability))
	return b.boundedConfirmBatch.FinalizeLocked(o)
}
func (b probeDeferBatch) DeferUntilDurableOutcome(fn func(bool)) bool {
	ok := b.boundedConfirmBatch.DeferUntilDurableOutcome(fn)
	if ok {
		b.took.Add(1)
	}
	return ok
}
