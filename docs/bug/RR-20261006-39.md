# RR-20261006-39：Host 不声明能力表时 Runtime 跳过能力准入，包装型 Host 能绕过核对直接施法

2026-10-07，基线 `82dfe672`（main，B3 ③ `cd8ed341` 之后）。P3（能力准入是 B3 ③ 的承诺：Program 需要的能力不在 Host 的表里，在启动 / 注册时就拒绝、不扣费；
这个分支让它对一类 Host 不成立，失败回到施法中途、扣费之后）。来源：v1.23.0 发版前维护者要求“交给 review 前不留能绕过检查的分支”，
B3 ③ 方案 §5 自己写明的跳过分支。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261006-39.md)。

## 机制

`skill/runtime_host_capability.go` 的 `hostCoversProgram`（基线第 30～33 行）：

```go
provider, ok := host.(HostCapabilityProvider)
if !ok || program == nil {
	return nil
}
```

Host 没实现 `HostCapabilityProvider` 就当作通过。`skill.RecordingHost` / `skill.ReplayHost` 没实现它，所以被它们包着的 Host 即使如实声明了
“没有召唤物”，准入也被跳过；业务自己写的 Host 漏写这个方法同理。

## 触发 / 预期 / 实际

- 触发：summon 技能（cost 10 mana，默认环境编译）交给 ①一个不声明能力表的 Host，②`RecordingHost` 包着一个如实声明没有召唤物、也不实现 `OwnedEntityRuntimeHost` 的 Host。
- 预期：`Activate` 在准入处返回 `ErrHostCapabilityMissing`，mana 仍是 100。
- 实际：两者都执行到 summon 才由类型断言返回 `ErrHostContractViolation`，mana 已扣到 90。

## 根因与方向

能力表是可选接口，“没声明”被解释成“不核对”。方向：能力表并进 `Host` 接口，每个 Host 都声明（包装型转发），删掉跳过分支。
