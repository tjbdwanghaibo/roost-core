# NC-232：停机开始之后才发生的 RuntimeFailure 不进 run 的返回值，进程以 0 退出

2026-10-06，基线 `c8ecbabb`。**P3**。状态：已复现，已修复（见文末）。[本轮](../review/REVIEW-2026-10-06-n01b.md) · [证据](../bugfix/evidence/noncore-bugfix-20261006-n01b/README.md)。来源：[N01/S4 观察 O1](../review/REVIEW-2026-10-05-n01s4.md)。

## 触发与差异

`App.run` 的 `select`（基线 `app/app.go:366-381`）因信号（或 Serve 退出）醒来之后，不再读 `runtimeFailure.Done()`，结尾也不看 `runtimeFailure.Err()`。停机期间发生的 fail-stop——DataEngine 投影 / WAL fatal、Remote 释放 fatal、续期判定失锁——只经 `OnFail` 围栏 Nest、写一条 Error 日志，`run` 返回 nil。

- 预期：fail-stop 出现在返回值里（进程非零退出）。启动期间的同类失败已经由 `startupFailure` 返回错误（基线 `:182-187`），Serve 期间的由 `Done` 分支并入；只有停机开始之后的这一段被漏掉。
- 实际：`run` 返回 nil，退出码 0。

## 影响

安全动作（Nest 围栏、失锁不 Release）照常发生，不影响数据；影响的是运维信号：部署脚本、systemd `Restart=on-failure`、告警按退出码判断，“停机期间 DataEngine fatal”（下次启动要重放、可能需要人工核对）被当成干净退出。

## 复现

`app/late_runtime_failure_promises_test.go` `TestRuntimeFailureDuringShutdownIsReturned`（单实例锁 harness，Service.Shutdown 期间 `Fail`）。修前：

```
--- FAIL: TestRuntimeFailureDuringShutdownIsReturned (0.00s)
    late_runtime_failure_promises_test.go:27: run error = <nil>, want the runtime failure that happened during shutdown
```

对照 `TestRuntimeFailureThatStartsTheShutdownIsReturnedOnce`（失败先于信号，经 Done 并入且只出现一次）修前修后都绿。
