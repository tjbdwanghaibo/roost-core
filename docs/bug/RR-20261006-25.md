# RR-20261006-25：停机 lifecycle hook 超时的错误只报阶段，不点名卡住的 hook

2026-10-06，基线 main `37338490`。P4（可观测性：同一阶段有多个 hook——Ops 的就绪位、configdata、业务登记的——时运维无从定位卡住的是哪一个；[T-264](../TROUBLESHOOTING.md) 的判别要求“看是哪个 phase 与 hook 名字”，错误里却没有名字）。来源：[真实进程演练](../bugfix/REAL-PROCESS-DRILLS-2026-10-06.md)第 3 项（NC-231 / APP-8，维护者要求“日志点出超时的 hook”）。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261006-25.md)。

## 触发与差异

`service.stopping` / `service.stopped` 的某个 hook 不配合 ctx、在 `shutdown.total_timeout` 内不返回。NC-231 之后 run 按预算返回，错误来自 `App.emitLifecycleWithin`（`app/app.go:824`）：`app: lifecycle service.stopping hooks did not return within the shutdown budget: context deadline exceeded`。它在另一个 goroutine 里调 `lifecycle.Registry.EmitAll`，看不到当前跑到哪个 hook。

- 预期：错误（随 `app run failed` 写进文件日志）点名没有返回的 hook。
- 实际：只有阶段名。

真实进程（game-demo，`drill-stuck-service.stopping` / `drill-stuck-service.stopped`）修前日志：

```
22:26:18.752 ERRO app run failed err=app: lifecycle service.stopping hooks did not return within the shutdown budget: context deadline exceeded
22:26:42.881 ERRO app run failed err=app: lifecycle service.stopped hooks did not return within the shutdown budget: context deadline exceeded
```

## 复现

`app/shutdown_hooks_promises_test.go` `TestShutdownLifecycleHooksStayWithinTheShutdownBudget` 加断言“错误含卡住的 hook 名”。修前（`GOWORK=off go test ./app/ -run TestShutdownLifecycleHooksStayWithinTheShutdownBudget -count=1`）：

```
--- FAIL: TestShutdownLifecycleHooksStayWithinTheShutdownBudget/service.stopping (0.30s)
    shutdown_hooks_promises_test.go:93: run error = app: lifecycle service.stopping hooks did not return within the shutdown budget: context deadline exceeded, want it to name the hook that did not return ("blocking-service.stopping")
--- FAIL: TestShutdownLifecycleHooksStayWithinTheShutdownBudget/service.stopped (0.31s)
    shutdown_hooks_promises_test.go:93: run error = app: lifecycle service.stopped hooks did not return within the shutdown budget: context deadline exceeded, want it to name the hook that did not return ("blocking-service.stopped")
```
