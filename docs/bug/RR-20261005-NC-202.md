# RR-20261005-NC-202：toxiproxy 的 pid 文件不校验所有权，down / reset 会杀掉复用该 pid 的无关进程

日期 2026-10-05。基线 main `8597046c`。等级 **P3**。状态：已复现，未修复。来源：N15。

## 触发与实际

隔离环境的 mongo / nats / redis 都经 `read_owned_pid` 认领（命令行须含 ` <根>/`），陈旧 pid 指向别人的进程时拒绝。toxiproxy 例外：`kit/scripts/integration/lib/toxiproxy.sh:26-30` `toxiproxy_running` 只看 pid 是否存活，`:86-96` `toxiproxy_down` 直接 `kill -TERM`。toxiproxy 崩溃 / 机器重启后 pid 被复用时，`down` / `reset` 杀掉无关进程；`toxiproxy_running` 为真还会让 `up` 跳过启动、让 env.sh 导出不存在的代理地址。

```
toxiproxy_running=true (pid 57408 is: sleep 300)
toxiproxy_down exit=0
RESULT: bystander pid 57408 KILLED
```

（[脚本](../review/evidence/noncore-review-20261005-n15/toxipid_red.sh) · [输出](../review/evidence/noncore-review-20261005-n15/nc202-red.txt)：临时根、偏移 31000，pid 文件写入本脚本自起的 sleep。）

## 根因

`toxiproxy.sh:59-61` 的注释认为“命令行里没有根目录，没法按 read_owned_pid 认领”，于是完全不认领。实际命令行 `toxiproxy-server -host 127.0.0.1 -port <API 端口>` 里的 API 端口按偏移唯一，可以作为所有权标识。

## 影响与定级

杀错进程（开发机上的任意进程），定 P3：需要 pid 复用才触发。

## 验收

pid 指向的进程不是本环境的 toxiproxy（命令名 + API 端口）时，running 为假、down 拒绝并保留该进程；本环境的 toxiproxy 照常停止。
