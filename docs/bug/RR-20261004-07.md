# RR-20261004-07：NatsMod 停止时 Bus 超过预算后保留 bus / asm 以便重试，但 `Bus.StopWithContext` 第一次就丢了 pool 并缓存超时错误，重试永远失败，Assembly（NATS 连接、RPC 回调池）永不关闭

日期：2026-10-04。基线：v1.19.0（`74e1ba39`）。来源：[B 线 NC 修复独立复审（第二组）§3](../review/REVIEW-2026-10-04-nc-audit-2.md)。等级 **P3**。状态：已确认，未修复。

## 现象、根因与修复约束

NC-09 修复引入。根因 `3560a19b` 的 `kit/nats/nats_mod.go:161-164` Bus 停止失败即返回；`bus/bus.go:316-352` `Bus.StopWithContext` 首次调用丢弃 pool 引用并缓存错误。实测 v1.19.0 handler 退出后重试仍 `context deadline exceeded asm_retained=true`，修前同一测试通过（修前至少会硬关闭）。记录与 CHANGELOG “取消后保留资源供再次排空”的承诺不成立。修复约束：`Bus.StopWithContext` 可重新等待（保留 pool / 等待句柄直到真正排空，错误不缓存成终态），NatsMod 重试能最终关闭 Assembly；或者第二次停止时明确硬关闭并报告。同时处理复审 S2：回调里再调 `Stop()` 不得自锁（修前立即返回）。

测试草稿在审计 scratchpad `audit-nc2-drafts/`（未入库）。

## 修复（2026-10-04）

**状态：已修复（A 线，本地验证通过，已提交，未推送、未发版）。** 记录：[docs/bugfix/RR-20261004-07.md](../bugfix/RR-20261004-07.md)。

采用“`Bus.StopWithContext` 可重新等待”：teardown 只做一次，超预算只返回 ctx 错误并保留 pool，之后的调用继续等同一次排空，排空后才定终态；NatsMod 只在 ctx 错误时保留 bus / asm，终态错误（如退订失败，同一前提的第二个反例）合并后照常关闭 Assembly。复审 S2：`RPCClient.Stop()` / `Bus.Stop()` 在停止已发起时立即返回；S1 写出了确定性红（两个测试缝），`drainCallbacks` 在 Wait 前加 `callbackMu` 屏障并改正注释；S4 两个回归加有界等待。修前红：`retry_after_handler_exit_err=context deadline exceeded asm_retained=true`（`TestNatsModStopRetryAfterBusBudgetClosesAssembly`），修后 `-race` 与真实 NATS 只读用例通过。原始现象与结论不变。
