# NC-216：skillsync.NegotiateSchema 在一边 Min 为 0（空区间）时仍返回版本，结果不被那一边 Contains

2026-10-05，基线 `c10cc9ac`。P3（公开协商 API 的结果与 `SchemaRange.Contains` / `NewApplier` 的空区间口径不一致；仓内只有测试调用）。状态：已复现，未修复。[本轮](../review/REVIEW-2026-10-05-n09-batch4.md)。

## 触发与差异

`SchemaRange.Contains`（`skill/skillsync/schema.go:26-28`）把 `Min == 0` 当作空区间；`NewApplier`（`applier.go:104-106`）把 `SupportedSchema.Min == 0` 当作“未配置”。`NegotiateSchema`（`schema.go:30-43`）先取 `max(Min)`、`min(Max)`，只在合并后的 `minimum == 0` 时失败：

```
server={0 5} client={2 3} -> 3 <nil> serverContains=false clientContains=true
server={2 3} client={0 5} -> 3 <nil> serverContains=true clientContains=false
```

单边 `Min > Max`（`{4 2}`）仍会被 `minimum > maximum` 拒绝。

## 验收覆盖点

协商出的版本必须同时被两边 `Contains`；任一边空区间（Min 为 0 或 Min > Max）返回 `ErrSchemaNegotiationFailed`；两边有效时取交集最大值（控制）。
