# NC-266：loadtest 运行被 profile 的 Duration 截断时停止原因记成 completed

2026-10-06，基线 `dc877c04`，分支 `revleft`（N11～N13 留项与小防护）。**P3**。来源：N12 观察 O11。状态：已复现，已修复（见文末）。[本轮](../review/REVIEW-2026-10-06-revleft.md) · [证据](../bugfix/evidence/noncore-bugfix-20261006-revleft/README.md)。

## 触发与差异

Duration 只在 runner 内部生效：`robot/runner/runner.go` `Run`（基线 :212-215）在 manager 交来的 ctx 上再套 `WithTimeout`。`robot/loadtest/manager.go` `execute` 结束时 `stopReasonFromContext(rec.ctx)` 读的是 manager 自己的 run ctx（`WithCancel(rootCtx)`，基线 :436），看不到这次到期，于是记 `completed`。N12 真实网关 `-duration 1s` 那次即 `stop_reason=completed`。

- 预期：Duration 到期 → `stop_reason=duration`；在 Duration 内自然跑完 → `completed`。
- 实际：两者都是 `completed`，报告无法区分“全部跑完”与“时间到被截断”。（阈值判定由 NC-161 兜住，停止原因仍错。）
