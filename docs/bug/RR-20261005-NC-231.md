# NC-231：停机阶段的生命周期 hook 不受 shutdown.total_timeout 约束，一个忽略 ctx 的 hook 让停机永远不返回

2026-10-06，基线 `c8ecbabb`。**P3**（需要业务登记一个不配合 ctx 的停机 hook；框架自带的只有 Ops 的就绪位 hook）。状态：已复现，已修复（见文末）。[本轮](../review/REVIEW-2026-10-06-n01b.md) · [证据](../bugfix/evidence/noncore-bugfix-20261006-n01b/README.md)。来源：N01 留项“Group 非协作回调 / 停止预算”。

## 触发与差异

`App.run`（`app/app.go`，基线 :414-421 与 :469-475）在停机路径上**同步**调用 `emitLifecycle(shutdownCtx, service.stopping)` 与 `emitLifecycle(shutdownCtx, service.stopped)`；`lifecycle.Registry.EmitAll` 逐个同步调用 hook（`lifecycle/lifecycle.go:111-128`）。hook 是公开扩展点（`ModLifecycle` 能力），业务可以在 service.stopping 上做“通知外部系统 / 摘流量”之类的 I/O。

- 预期：与 Service.Shutdown、Mod 停机相同的三步停机②——在停机总预算内等，超时如实返回“不完整”并保留依赖；hook 不配合 ctx 时 App 杀不掉它，但 run 必须按预算返回。
- 实际：hook 忽略 ctx 时 run 永远不返回：service.stopping 卡住时 Service.Shutdown 不被调用、Mod 不停；续期一直在跑、单实例锁一直持有，进程挂到部署侧 SIGKILL（k8s 宽限期 = total + 5s）；service.stopped 卡住时 Release 也排在它之后。
