# RR-20261006-68：兴趣续租在条带锁里同步广播，总线一慢，同条带其他 key 的读（含 L1 命中）全部排队

2026-10-07，基线 `c78d0c34`（main）。P2（读延迟随同步总线变慢放大到最长 `syncbus.publish_timeout`，缺省 5s）。来源：[FRAMEWORK-DOCS-FINDINGS-2026-10-07](../review/FRAMEWORK-DOCS-FINDINGS-2026-10-07.md) F05-1（探针已证实），条件与证据见 [impl/05 §10.2 第 1 条](../framework/impl/05-remote-mirror.md)。
状态：已复现；已修复（`a9bb8923`，[修复](../bugfix/RR-20261006-68.md)），未发版。

## 机制

1. `SnapshotClient.ReadSnapshot` 每次读先 `RenewInterest`（`remoteentity/snapshot_client.go` 基线 :194），续租入口 `renewInterest` 取 `localInterestLocks[EntityID % 64]`（:263-265）。
2. 本机租约剩余不足一半时，在这把条带锁里调 `publishInterest`（:299）经同步总线广播；JetStream 卡住时最长等 `syncbus.publish_timeout`。
3. 同条带的其他 key——包括不需要续租的 L1 命中——都要先拿这把锁，排队等这次发布。`ReleaseInterest` 同样在锁内发布。
