# RR-20261005-NC-200：gapmap.sh 收尾的 `git checkout -- .` 丢掉运行前已有的未提交跟踪修改

日期 2026-10-05。基线 main `8597046c`。等级 **P2**。状态：已复现，未修复。来源：N15（[本轮](../review/REVIEW-2026-10-05-n15.md)）。

## 触发与实际

工作树里有尚未提交的跟踪文件修改（正在写的代码 / 文档），本地执行 `scripts/gapmap.sh`（nightly-gapmap 之外的手工运行）。取样器每次改完都会把文件写回原样，但收尾检查 `git status --short --untracked-files=no` 不区分“取样留下的”与“运行前就有的”，只要非空就 `git checkout -- .`：

```
gapmap: tracked files left modified after sampling — a neutralized guard had a side effect; restoring:
 M NOTES.txt
RESULT: uncommitted work LOST
```

（[复跑脚本](../review/evidence/noncore-review-20261005-n15/gapmap_red.sh) · [输出](../review/evidence/noncore-review-20261005-n15/nc200-red.txt)：临时仓库、提交后改 NOTES.txt，再跑 gapmap。）

## 根因

`scripts/gapmap.sh:24-28`：恢复逻辑假设运行前跟踪文件是干净的，但脚本开头没有检查这一前提。注释写“Restore only TRACKED files the sampler may have left modified”，实际恢复的是全部被修改的跟踪文件。

## 影响与定级

本地未提交工作被无提示丢弃，不可恢复（`git checkout` 不进 stash / reflog），定 P2。CI（干净 checkout）不受影响。

## 验收

运行前已有跟踪修改时拒绝启动（或只恢复取样器自己改过的文件），已有修改保持原样；干净树上原行为不变。
