# NC-146：零值 OrderedIndex 静默丢弃写入，nil *OrderedIndex 写入 panic

2026-10-05，基线 `23f82dbccfd5171373470ab942f33177ed4f4eed`。P3（仓内零调用方）。状态：已复现、已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-146.md)。[本轮](../review/REVIEW-2026-10-05-n11.md)。

## 触发与差异

`Index` 的零值可直接用（`ensureLocked`），nil `*Index` 是空索引。`OrderedIndex` 把数据放在 `index *Index` 指针里（`index/index.go:123`），只有 `NewOrderedIndex` 会填：零值的 `Upsert` 转发给 nil `*Index` 直接返回，写入静默丢失、随后 `Get` 查不到；nil `*OrderedIndex` 的 `Upsert` / `Get` / `Len` 解引用 panic，而 `Query` 有 nil 守卫——同一类型的方法对 nil 行为不一致。

## 复现

`TestZeroOrderedIndexIsUsable`：

```
index_promises_test.go:86: Get after Upsert on a zero OrderedIndex = "", false
```
