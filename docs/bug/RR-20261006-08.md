# RR-20261006-08：mongotest 的 `$in` 不支持具名切片操作数（O-S5-6）

2026-10-06，基线 `8a292a5a`。P3（测试替身与真实驱动不一致：真实驱动正常，替身报 `ErrUnsupported`，`saga.MongoStore.ClaimDue` 在替身上不可用，saga 用例只能绕开）。来源：N06 S5 review 观察 O-S5-6（[记录](../review/REVIEW-2026-10-06-n06s5.md)），收尾盘点 A14。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261006-08.md)。

## 机制

`mongo/mongotest/mongotest.go` `valueList` 只认 `bson.A`、`[]any`、`[]string`，其余报 `ErrUnsupported: $in operand %T`。真实驱动把任意切片 / 数组编码成 BSON 数组、元素按 Kind 编码（只有元素类型恰好是 `byte` 的切片 / 数组编成二进制）。`ClaimDue` 的候选查询是 `{"status": {"$in": []Status{...}}}`（`saga.Status` 底层 `uint8`），在替身上直接失败。saga 的两处用例因此绕开：`coordinator_takeover_review_test.go` 只跑领取的第二段，`step_operation_promises_test.go` 跳过领取直接 `processClaimed`。

## 触发与差异

`Find(ctx, {"label": {"$in": []namedLabel{"b"}}})`：预期匹配；实际 `ErrUnsupported`。`[]int64` 同样被拒；`[]saga.Status` 被拒。

## 复现

`TestInAcceptsNamedSlices`（`mongo/mongotest/in_named_slice_promises_test.go`）修前（子项按 map 顺序，两次运行各报一项）：

```
in_named_slice_promises_test.go:46: named_string_slice: Find: mongofake: unsupported construct: $in operand []mongotest.namedLabel
in_named_slice_promises_test.go:47: plain_int64_slice: Find: mongofake: unsupported construct: $in operand []int64
```

saga 用例改走 `ClaimDue`、替身未修时：`coordinator_takeover_review_test.go:92: mongofake: unsupported construct: $in operand []saga.Status`。

## 修复

[修复记录](../bugfix/RR-20261006-08.md)：`valueList` 用 reflect 展开切片 / 数组，元素换成底层内置类型；去掉 saga 用例的绕行。
