## RR-20260909-03：Assembly 重试停机

保存以下代码为临时 assembly_review_test.go。测试复用同包 projector_test.go 的
projectorOutboxFake/newProjectorOutboxFake/failingOutboxPublisher；真实 OutboxWorker
执行 run/Close，存储 Claim 的返回由通道控制。构造只包含 Outbox 的 Runtime，隔离
Assembly 的引用管理；这不是完整 Assembly.Start 或真实 Mongo 故障实验。

```go
package engine
import (
 "context"
 "errors"
 "testing"
 "time"
)
type reviewSlowClaimStore struct {
 *projectorOutboxFake
 entered chan struct{}
 release chan struct{}
}
func (s *reviewSlowClaimStore) Claim(ctx context.Context, _ string, _ time.Time, _ int, _ time.Duration) ([]OutboxItem,error) {
 close(s.entered)
 <-s.release
 return nil,ctx.Err()
}
func TestReviewAssemblyRetainsIncompleteShutdown(t *testing.T) {
 store:=&reviewSlowClaimStore{projectorOutboxFake:newProjectorOutboxFake(),entered:make(chan struct{}),release:make(chan struct{})}
 worker,err:=NewOutboxWorker(store,failingOutboxPublisher{},OutboxWorkerOptions{Owner:"review"})
 if err!=nil {t.Fatal(err)}
 worker.Start(context.Background())
 <-store.entered
 defer func(){close(store.release);if err:=worker.Close(context.Background());err!=nil {t.Error(err)}}()
 runtime:=&Runtime{Outbox:worker}
 assembly:=&Assembly{runtime:runtime}
 ctx,cancel:=context.WithCancel(context.Background());cancel()
 if err:=assembly.Shutdown(ctx);!errors.Is(err,context.Canceled){t.Fatalf("first shutdown=%v",err)}
 select {case <-worker.done:t.Fatal("worker exited before release");default:}
 // Retrying with a fresh but bounded context must still wait or report an
 // incomplete shutdown; success while a worker remains active is false.
 retryCtx,retryCancel:=context.WithTimeout(context.Background(),10*time.Millisecond);defer retryCancel()
 retryErr:=assembly.Shutdown(retryCtx)
 if retryErr==nil {t.Fatalf("second Shutdown returned success while outbox worker is still active; Runtime()=%v",assembly.Runtime())}
 if assembly.Runtime()!=runtime {t.Fatal("lost runtime ownership after incomplete shutdown")}
}
```

建立 overlay.json，键指向实际审查 Core 的 dataengine/engine 下一个不存在的 Go 测试文件：

```json
{"Replace":{"<core>/dataengine/engine/review_external_test.go":"<temp>/assembly_review_test.go"}}
```

在 Core 审查工作树中运行：

```powershell
$env:GOTOOLCHAIN='go1.27.0'
$env:GOWORK='off'
go test -overlay '<temp>/overlay.json' ./dataengine/engine -run '^TestReviewAssemblyRetainsIncompleteShutdown$' -count=1 -timeout=30s
# 本轮另加 -race 复核，也在同一业务断言失败。
```

首次 Shutdown 错误必须为 context.Canceled，worker.done 必须仍未关闭；重试不能返回 nil。
即便断言失败，defer 仍解除阻塞并完成 worker.Close，不以泄漏测试 goroutine 作为证据。

## RR-20260909-04：同包双实体消费者

下方 PowerShell 步骤从当前 Codegen 已有 fixture 派生输入。必须将路径指向报告所列审查 SHA；
尤其 Core 的 `<core>` 可指向本轮 detached worktree。不要将测试消费者建在正式业务目录。

```powershell
$reviewTemp=Join-Path $env:TEMP ('roost-multi-entity-'+[guid]::NewGuid().ToString('N'))
$reviewCore='<core>'
$reviewCodegen='D:/whb_s/cube-codegen'
$single=Join-Path $reviewTemp 'single'
$multiple=Join-Path $reviewTemp 'multiple'
New-Item -ItemType Directory -Path $single,$multiple | Out-Null
$guild=(Get-Content (Join-Path $reviewCodegen 'internal/entity/testdata/remote/guild.go') -Raw).Replace('Category: 6','Category: 2')
[IO.File]::WriteAllText((Join-Path $single 'guild.go'),$guild)
[IO.File]::WriteAllText((Join-Path $multiple 'guild.go'),$guild)
[IO.File]::WriteAllText((Join-Path $multiple 'clan.go'),$guild.Replace('Guild','Clan').Replace('guilds','clans').Replace('201','202'))
[IO.File]::WriteAllText((Join-Path $single 'go.mod'),"module example.com/reviewsingle`n`ngo 1.27.0`n`nrequire github.com/tjbdwanghaibo/roost-core v1.15.2`n")
[IO.File]::WriteAllText((Join-Path $multiple 'go.mod'),"module example.com/reviewmulti`n`ngo 1.27.0`n`nrequire github.com/tjbdwanghaibo/roost-core v1.15.2`n")
$env:GOTOOLCHAIN='go1.27.0'
$env:GOWORK='off'
Set-Location $reviewCodegen
go run ./cmd/entity -dir $single
go run ./cmd/entity -dir $multiple
# 两个生成命令均应成功；正式业务模块不写 replace。
$env:GOWORK=Join-Path $reviewTemp 'go.work'
go work init $reviewCore $single $multiple
Set-Location $single
go test ./... -count=1 -timeout=60s
# 当前结果：单实体测试成功，包括生成的 TestGuildRemoteCommitGuards。
Set-Location $multiple
go test -run='^$' ./... -timeout=60s
# 当前结果：exit 1，RegisterEntity 与 registerEntityOnce 重复声明。
```

Category 调整只保证 fixture 满足当前 Core 的有效范围，不改框架规则。两个实体具有不同
类型名、Kind 和 Collection；它们共用包这一点触发了生成器包级固定名冲突。
