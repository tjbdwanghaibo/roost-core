# RR-20261006-21：起过进程的启动失败后，进程记录留在被复用的 cast ID 名下，Checkpoint 报 corrupt

2026-10-06，基线 `37338490`（main）+ 补测草稿 `5b4d49f5`。P2（一次失败启动之后 Runtime 再也取不出 checkpoint）。来源：发版文档 SKILL-1 review 检查点“charge enter 失败后 owned 进程在宿主侧是否留下实体”的补测（分支 `sktest2`，恢复自 `wip/sktest`）。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261006-21.md)。

## 机制

- `skill/runtime.go:440-447`（基线）`startLocked`：`prepareCast` 出错、cast 未提交时，`failCastLocked` 停掉 cast 起的进程，然后删 cast、`nextCastID--` 把 ID 还给下一个 cast（NC-110）。
- 停掉的进程记录不删：`stopProcess`（`skill/process.go:189-226`）只把状态改成 cancelled，entity 进程还把 `Program` 清成 nil（`:211`）；记录留在 `runtime.processes`，`CastID` 仍是被还回去的 ID。
- `Checkpoint` 序列化进程时用 `resolveProcessProgram`（`skill/runtime_checkpoint.go:571`）找程序：`Program` 为 nil 就取 `runtime.casts[CastID].program`，cast 已删 → nil → `checkpointProcessMap`（`:682`）返回 `ErrCheckpointCorrupt`。这条记录永远不会再被删，之后每一次 `Checkpoint` 都失败。
- 下一个拿到同一 ID 的 cast 名下多出一条不属于它的记录。
- 宿主停不下进程（`StopProcess` 出错）时，运行中的记录同样留下，并被下一个复用 ID 的 cast 接走：那个 cast 停进程时会连它一起停，failed 的原 cast 却已不存在。

## 触发 / 预期 / 实际

- 触发：charge 技能的 enter 先 spawn 一个 summon 进程，随后同一 enter 里付费失败（提交前失败）。
- 预期（NC-110 对排程任务的承诺扩到进程）：Start 返回 `(0, 原错误)`；宿主侧进程已停；Runtime 不在被复用的 ID 名下留下进程记录；之后 checkpoint 正常。宿主停不下进程时，cast 不能消失、ID 不能复用。
- 实际：见下。宿主侧进程确实停了、cancel 回调只跑一次（这两条断言修前就通过）。

## 可达性

任何 enter 里先起 entity 进程（summon / area，`startEntityProcess`）、之后在提交前失败的技能（付费不足、目标失效、宿主拒绝）都会触发；生产 checkpoint 之后一直失败。同根因的另一面（进程结束后的 cast 永不回收）见 [RR-20261006-23](RR-20261006-23.md)。
