# NC-113：CombatComponent.Combatant / InitCombatant 共享 ElementMultipliersBP map，事务外改动权威战斗状态

2026-10-05，基线 `be7bcc1853020d9f744360d78831abd0ddf990a3`。P3（需要调用方原地修改读到的副本或自己传入的 map；仓内没有正式调用方，但多实体共用一份配置模板是常见写法）。状态：已复现、已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-113.md)。[本轮](../review/REVIEW-2026-10-05-n09-batch1.md)。

## 触发与差异

`skill/combatcomponent/component.go:220-221` 注释承诺 “Combatant returns a copy of the vitals block”，实现是结构体值拷贝；`combat.Combatant.ElementMultipliersBP` 是 `map[Element]int64`（`skill/combat/damage.go:55`），副本与 DAO 共享同一张 map。`InitCombatant`（:302-306）同样把调用方的 map 原样存进 DAO。

调用方对副本或对自己传入的 map（例如多个实体共用的配置模板）做原地修改，就绕过了 `undoVitals`、`markDirty`：改动不进回滚、不标持久化 / 同步脏位，直到下一次 vitals 写入才被顺带落盘；共用模板时一处修改同时改掉所有实体。

预期：读到的是独立副本；InitCombatant 存的是调用方 map 的拷贝。

## 复现

`skill/combatcomponent/combatant_copy_promises_test.go`（基线代码上）：

```
combatant_copy_promises_test.go:28: mutating the caller's template changed the stored multiplier to 1, want 12000
combatant_copy_promises_test.go:34: mutating the returned copy changed the stored multiplier to 0, want 12000
```

## 本轮已排除

combatcomponent 自身的回滚：RollbackUndo handler 失败、RollbackUndo 提交被拒、RollbackState handler 失败、RollbackState 提交被拒四种组合下，DAO 字节、属性当前值（含 buff 授予）与 tracker 版本都恢复（探针，结论见本轮记录）；BSON 持久化与 patch 对 map 字段往返正确。
