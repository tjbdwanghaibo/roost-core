# NC-221：被动技能永远不能触发的前提不在编译期检查——input_schema 不是 none / entity、proc_policy.max_depth 为 0

2026-10-06，基线 `57c0b3b6`。P3（编译通过，每次触发都被 `passive_suppressed` 静默压制；不损坏状态）。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-221.md)。[本轮](../review/REVIEW-2026-10-06-n09-batch5.md)。

## 机制

被动由 `ActivatePassive` 按触发事件入队，`executePassiveActivation`（`runtime_proc.go`）执行：

- 深度：`task.Event.ProcDepth >= plan.proc.MaxDepth` 时压制为 `max_depth`。根事件深度为 0，`max_depth: 0` 的被动对任何事件都压制。`compile_shape.go` 只要求 `max_depth` 非负。
- 输入：`passiveCastInput` 只填 `CastInput.Target = event.Target`（且只在有 `$input.target` 槽时）。输入是 position / direction / direction_position / entity_position / two_point / drag / path 的被动，`freezeCastInput` 必然返回 `ErrCastInputInvalid`，压制为 `unavailable`。编译期不查被动的 input_schema。

## 复现

正式回归（修前）`TestCompileRejectsPassivesThatCanNeverActivate` 五个子用例全部 `compiled; diagnostics=[]skill.Diagnostic(nil)`。探针：同一被动（施法内对自己造成 1 点伤害）`max_depth 0`、`position`、`direction` 输入三种情形 ActivatePassive 返回 nil、推进 3 tick 后 `CastCount()==0`、生命不变；`none` / `entity` 输入照常施法。

## 验收覆盖点

`max_depth < 1` 报 `SHAPE_INVALID at $.activation.proc_policy.max_depth`；被动的 input_schema 不是 none / entity 报 `INPUT_UNAVAILABLE at $.input_schema`。控制：none 与 entity 输入、max_depth 1 的被动照常触发，entity 输入拿到事件 target。
