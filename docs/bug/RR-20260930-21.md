# RR-20260930-21：提交后释放 Redis 锁失败，versionedLock 本地 `acquired` 不清，同一实体在本进程内永久不可写

日期：2026-09-30。基线：main `19b26d27`。来源：B27 第 2 批端到端补测（RR-20260926-46 的“后续验证”）在正式生成链路上暴露。等级 **P2**：一次瞬时 Redis 故障之后，即使 Redis 恢复、锁 TTL 早已过期，本进程对该实体的每次写都被本地状态拒绝，只能重启进程。状态：**已确认，未修复**。

## 触发条件、预期与实际

- 触发：Remote 写提交后释放 Redis 锁时 Redis 出错（用尽 `UnlockWithRetry` 重试）；之后 Redis 恢复，锁按 TTL（用例 3s）自然过期。
- 预期：下一次写在 TTL 过期后能重新取锁（或者释放失败时就清掉本地持有状态，让下一次 `TryLock` 去问 Redis）。
- 实际（`bash scripts/test-remote-generated.sh`，去掉 `codegen/internal/entity/testdata/remoteflow/after_commit_test.go:224` 的 `t.Skip` 后）：
  `the entity stayed unwritable for 10s after a failed unlock (LockTTL 3s, Redis healthy again, 50 attempts): last=remote_entity: shared lock 4611686018437337009: versioned lock already acquired`。

## 根因（到行）

`remoteentity/versioned_lock.go:236-275` `UnlockWithRetry` 只在 Redis 答复 0 时清本地 `acquired`；Redis 错误用尽重试后返回 `lastErr`、`acquired` 仍为 true。下一次 `beginWrite` 的 `rMu.Lock`（`remoteentity/batch.go:165-167`）→ `TryLock`（`versioned_lock.go:108-110`）只看本地状态就拒绝、不问 Redis；能清 `acquired` 的只有 Touch / Refresh 看到租约失效（`:355-405`），写之间无人 Touch。

## 暴露用例（已入库，`t.Skip` 引用本编号）

## 修复约束

- 释放失败不能伪造“已释放”：Redis 上锁可能仍在，本地必须进入“持有状态未知”并让下一次 `TryLock` 以 Redis 为准（例如本地清 `acquired` 但保留 token，`TryLock` 先向 Redis 尝试，被拒则按已有的“别人持有”路径处理）；续期 goroutine 的登记按 RR-20260926-43 的代际规则处理。
- 不放宽版本比较、不跳过 fence；去掉用例的 `t.Skip` 作为绿，并补一条 `remoteentity` 包内用 Redis 替身的确定性回归。
