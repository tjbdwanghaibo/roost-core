# RR-20261005-NC-71：`roost project diff` 与 `project upgrade --dry-run` 漏列 sync 将改写的三份应用自有配置；生成工程文档与 `roost help project` 称 sync / upgrade 不改配置

日期 2026-10-05。基线 main `50e9a4e853641f348c879b85c282af9c5813f656`。等级 **P3**。状态：已复现（正式 CLI 与正式入口回归），已修复、声明场景验证，未发版（见文末）。来源：N08 codegen 非核心 review（[本轮](../review/REVIEW-2026-10-05-n08-codegen.md)），在“旧工程显式 upgrade”实跑中发现。

## 触发

- 服务的 Mod 集合变化（`roost.yaml` 增减 Mod、`add mod` / `add saga` / `add access` 之后、手改 `uses`），或旧工程升级跨过停机预算公式的变化（例如 v1.18.0 生成的工程升级到当前生成器：公式多了 “3s for the singleton release”）。
- 用户先跑 `roost project diff` 或 `roost project upgrade --dry-run` 预览，再跑 `project sync` / `project upgrade`。

## 预期

预览就是将要发生的变化：`codegen/docs/CODEGEN_REFERENCE.zh-CN.md:82` 写 “roost project diff # 只显示将发生的变化”，`--dry-run` 的帮助是 “preview an upgrade without writing files or resolving dependencies”。预览列出的文件集合应等于随后 sync / upgrade 实际改写的集合（不含 upgrade 之后的 go.mod / go.sum 依赖解析）。

## 实际

sync 在渲染模板之前，会把应用自有配置里未手改的生成 `shutdown:` 块刷新到当前 Mod 的计划（RR-20260926-66/80：`configs/service/config.<svc>.yaml`、`config.<svc>.prod.example.yaml`、`deploy/k8s/base/secret.<svc>.example.yaml`），模板的宽限期再按刷新后的值渲染。预览不做这一步，这三份文件从不出现在预览里。

正式 CLI：

- v1.18.0 生成、pin `core: v1.18.0` 的工程（`-mods configdata,mongo,nats,dataengine,nest`），当前生成器 `project upgrade -core v1.20.0 --dry-run` 列 17 个文件；实际 upgrade 改写 19 个文件加 `roost.yaml`。漏列 `configs/service/config.game.yaml`、`configs/service/config.game.prod.example.yaml`、`deploy/k8s/base/secret.game.example.yaml`（`total_timeout` 56s → 59s 及其注释）。
- 同一工程升级后在 `game` 加 `redis`：`project diff` 列 10 个，`project sync` 改写 13 个，漏列同样三份。

正式入口回归（新增 `codegen/internal/roost/diff_preview_promises_test.go`）修前红：

```
diff_preview_promises_test.go:93: project diff previewed 11 files, the sync rewrote 14
     missing from the preview: [configs/service/config.game.prod.example.yaml configs/service/config.game.yaml deploy/k8s/base/secret.game.example.yaml]
diff_preview_promises_test.go:134: upgrade --dry-run previewed 11 files, the upgrade rewrote 14
     missing from the preview: [configs/service/config.game.prod.example.yaml configs/service/config.game.yaml deploy/k8s/base/secret.game.example.yaml]
```

同时两处说明与行为相反：生成工程 `docs/USAGE.zh-CN.md`（`codegen/internal/roost/render_docs.go:523`）写 “project diff 只预览受控模板；sync 不覆盖业务拥有的 Service 实现和配置”；`roost help project`（`codegen/internal/roost/help.go:73`）写 “upgrade 只覆盖 codegen 受控文件”。

## 根因

- `codegen/internal/roost/doctor.go:852-853`（`diffManifest`，`project diff` 与 `upgrade --dry-run` 共用）：`renderProject(m.withConfiguredShutdown(root))` 用磁盘上的旧配置值渲染；`doctor.go:879` 对已存在的非 Owned 文件直接 `continue`，三份配置是应用自有文件，因此永不列出。
- `codegen/internal/roost/project.go:204`：`SyncProject` 在暂存树里先 `refreshGeneratedShutdownConfigs(stage, manifest)`、再渲染并把刷新过的配置随同提交（RR-20260926-80 把刷新挪进暂存树时只改了 sync，没有同步预览）。

## 影响与定级

sync 改的只是“与生成器写出时逐字一致、未手改”的块，不会覆盖用户手改的值，所以不是数据破坏，定 P3。代价是预览不可信：用户在预览里确认“配置不会动”，sync 却改了应用自有配置（其中 secret 示例常被复制成真实部署配置），生成文档还明确说 sync 不改配置。

## 范围与未做

- 预览只对比文件集合；生成器输出（DAO / Entity / registry 等）本来就不在 `project diff` 范围内，由 `roost generate --check` 检查，本条不改这一分工，只把文档写准。
- 依赖解析（go.mod / go.sum）不属于 `--dry-run` 预览，保持不变。
- 本轮另记的相邻观察（upgrade 依赖解析失败后的半升级状态与提示文字、生成失败错误里的暂存路径）见[本轮记录](../review/REVIEW-2026-10-05-n08-codegen.md)，不并入本条。

## 修复（2026-10-05）

已修复、声明场景验证，未发版：`diffManifest` 先对三份配置副本做与 sync 相同的 shutdown 块刷新，再按刷新值渲染；生成文档 / help / 参考文档写准改写范围。[修复记录](../bugfix/RR-20261005-NC-71.md)。以上原始现象与修前红保留不改。
