# RR-20260924-03：动态 Cast 的事务保护错误依赖 Sync 接线

- 日期 / 基线：2026-09-24，`967bc69` 加双模式 Sync/Nest 工作树；等级 P1。
- 范围：Nest handler 动态 Cast 的本地实体、回滚与 pipelined 提交。
- 状态：已复现、已修复并验证，未提交、未发布；[修复记录](../bugfix/RR-20260924-03.md)。

## 触发、预期与实际

业务 handler 持有主实体，通过 `CastOne` / `CastMulti` 锁定另一实体并修改 DAO。没有安装 `NestOptionWithEntitySync` 时：

1. `RollbackState` handler 返回错误或 strict committer 拒绝提交，只恢复主实体，动态实体保留失败操作的值和同步 dirty。
2. handler 调用 `ReleaseCast` 会提前解锁动态实体，后续回滚/持久化准备可能已失去锁保护。
3. pipelined 只提前释放 dispatch 最初取得的锁，动态实体仍被锁住直到 WAL 等待结束；动态实体的 `LastCommitLSN` 也没有更新。

预期：业务事务的实体集合包含成功 Cast 取得的实体，不因是否启用客户端同步而改变。回滚在锁内完成；pipelined 准入后写入涉及实体的 LSN，并在等待 WAL 前释放全部本次业务锁。

## 根因与证据

修前 `nest/cast.go` 把 `tx.CaptureEntities(lockedNow)` 放在 `CurrentSyncMutation() != nil` 条件内；`ReleaseCast` 也只对 Sync 作用域延迟释放。`invokeWithTransaction` 的 Guard 全量释放同样被 observer 条件包围，LSN 则只覆盖初始参数和启用 Sync 的实体。

原执行入口位于 `nest/rollback.go`；本轮同包整理后在 [execution.go](../../nest/execution.go)。并未以代码搬迁代替修复。

最小回归：[cast_transaction_test.go](../../nest/cast_transaction_test.go)。前两个子用例运行真实 Nest Request，最后一个使用真实 Cast/Guard 和可控 ticket，在读取 `Done()` 前观察锁和水位，不用 sleep 构造顺序。

环境：Go 1.27.0，darwin/arm64。

```sh
GOCACHE=/tmp/roost-nest-go-cache GOWORK=off go test ./nest \
  -run 'TestCast(TransactionRollbackWithoutSync|PipelinedReleasesAndStampsWithoutSync)$' \
  -count=1 -timeout=30s
```

修前实际失败：

```text
handler_error / commit_rejected:
  dynamic entity released before transaction outcome
  rollback values = 10/99, want 10/20
  rolled-back dynamic entity retained sync dirty: 1
pipelined:
  dynamic entity still locked during durable wait
  dynamic entity LSN = 0, want 1
```

两个 Request 子用例的前后值与 tracker 均验证；pipelined 用例检查等待开始之前的状态，不把最终请求完成后才释放算作通过。本轮未穷尽动态远端实体、跨进程故障和全部自定义 participant。
