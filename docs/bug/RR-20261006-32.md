# RR-20261006-32：施法里的衍生物停止被宿主拒绝后，同一请求里再停一次，cancel 回调跑两遍

2026-10-07，基线 `57c87634`（main）。P3（只在宿主 `StopSpawn` 失败时触发；后果是衍生物回调的副作用重复——回血、伤害、资源、实体指令各多执行一次，或在启动失败的衍生物上执行成功路径从不执行的 cancel 回调）。来源：停止入口统一（维护者 2026-10-07，[方案](../feature/REFACTOR-2026-10-06-skill-spawn-stop-unified.md)）实施中，登记表逐入口让宿主拒绝停止时发现。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261006-32.md)。

## 机制

- `terminateSpawn`（基线 `skill/spawn.go:282`）先跑回调（`callbackLive` 只看 `Status == SpawnRunning`，`:295`），再调宿主 `StopSpawn`。宿主拒绝时状态不变，仍是 running。
- 施法里的停止入口——Interrupt / Cancel（`skill/runtime_cast_window.go:254`、`:297` 的 `stopSpawns`）、goto、施法收尾（`stopFinishingSpawns`）、衍生物启动失败的清理（`skill/spawn_owned.go:59`、`:71`、`:86`，`skill/runtime_owned_spawn.go` 两处）——出错后不处理记录，把错误一路返回，最后进 `failCastLocked`（`skill/scheduler.go:482`）的 `stopSpawns(cast, true)`：记录仍是 running，于是**再请求一次停止，回调再跑一遍**，宿主在同一 tick 被打第二次。
- 移交时 lifecycle 已失效（`handoffEntitySpawns`）同理：错误返回后记录仍是 running，下一 tick 的 `reapUnhandedEntitySpawns` 再停一次、再跑 cancel 回调。
- 启动失败的清理第一次停止用 `StopCauseFailure`、不跑回调；`failCastLocked` 的第二次停止带 `"cancel"` 回调。宿主停得了时这个衍生物从不跑 cancel，停不了时却跑——同一个失败启动的结果取决于宿主应答。

## 触发 / 预期 / 实际

- 触发：summon 带 cancel 回调（给拥有者回 1 点血计数）；宿主拒绝下一次 `StopSpawn`；分别经 Interrupt、summon 的 enter 回调失败（启动失败清理）、owned 实体事务提交失败、移交时 lifecycle 已失效触发停止。
- 预期：回调只跑一次（启动失败清理零次）；被拒绝的停止交给 Runtime 退避重试（RR-20261006-21 后续的承诺：重试只重发宿主停止）。
- 实际：Interrupt 与移交两条 cancel 回调跑 2 次；启动失败、提交失败两条跑 1 次（应为 0）；宿主在同一 tick 被打两次，或下一 tick 立即再打。

## 可达性

任何带 entity 衍生物（summon / area / 飞行物）回调的技能，宿主在 Interrupt / Cancel / goto / 施法收尾 / 衍生物启动失败 / 移交时 `StopSpawn` 出错即触发。同根因（失败处理散在入口里）的另一面是 `Shutdown` / `RemoveProgram` 停不下时 Runtime 不再重试，按维护者“停止入口统一”的决定一并处理，不另编号。
