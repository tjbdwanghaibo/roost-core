# NC-140：World 定时器堆不随 Nest 事务回滚，撤回的武装 / 触发让截止时间丢失

2026-10-05，基线 `23f82dbccfd5171373470ab942f33177ed4f4eed`。P2（game-demo 模板；需要事务失败或提交被拒绝，正常路径不触发；后果是活动收尾截止时间在内存或持久化里丢失，直到重启或永远不再触发）。状态：已复现、已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-140.md)。[本轮](../review/REVIEW-2026-10-05-n11.md)。

## 触发与差异

`demo/game/handler/arm_activity.go.tmpl:18` 与 `tick_world_timers.go.tmpl:20` 都是 `rollback=undo durability=strict`。`TimerComponent`（`demo/game/entities/world/timer_component.go.tmpl`）的 `timer.Scheduler` 堆是组件内存，Nest 的 undo 只覆盖生成 DAO（与 NC-61 属性层同一机制缺口）：

- 武装事务失败 / 提交被拒：DAO 的 `timers` 被撤回，堆里却留着节点。`PendingActivityPhase` 报告“已武装”，此后每 5 秒的 `openCurrentWindow` 都被当成重复武装拒绝，存储里始终没有这条截止时间：不重启时它仍从内存触发，但在触发前重启（“It survives a restart”正是组件的承诺）就彻底消失。
- 触发事务失败 / 提交被拒（`Tick` 已 `heap.Pop` 并发出 `ChangeDelete`，handler 已记录 effect）：DAO 节点与 effect 一起被撤回，堆里却已没有节点。下一次 Tick 什么都不触发，本服不再上报这个窗口的 close 阶段，直到重启后从 DAO 重建。

预期：堆与 DAO 一起回到事务开始时的样子。

## 复现

生成工程（`roost project new … -template game-demo`，replace 到基线源码）`game/entities/world/timer_rollback_test.go` 的 `TestTheTimerHeapRollsBackWithTheTransaction`，提交被拒与 handler 后续失败各两叶：

```
timer_rollback_test.go:49: rolled back, but the heap still holds node 1: every later arm is refused as a repeat and the stored World has no deadline
timer_rollback_test.go:86: the rolled-back tick took the deadline out of the heap: its effect was rolled back too, so nothing reports the phase until a restart
```

原文见 [证据](../bugfix/evidence/noncore-bugfix-20261005-revn11/red-nc140-nc142-world.txt)。

## 约束

沿用 NC-61 的做法：组件在第一次改堆之前向当前可回滚事务登记逆操作（`(*RollbackTx).RecordUndo`），逆操作按事务开始时的快照重建堆；只在确实会改堆时快照，不让每秒的空 Tick 付出复制成本。真实 WAL / Mongo 三进程链路的拒绝路径本轮未跑。
