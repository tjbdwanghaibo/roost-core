# RR-20260928-13：CRLF 行尾的 k8s Secret 示例被 `add mod` / `add saga` / `add transport tcp` 静默跳过

日期：2026-09-28。基线：本地 main `d66eeeb`。来源：第八轮独立审计（[REVIEW-2026-09-28-audit8](../review/REVIEW-2026-09-28-audit8.md)）。等级 **P4**。引入：RR-20260928-07 的新入口（停机块刷新对 CRLF 同样跳过，修前即有）。状态：已复现；**已修复**（[修复记录](../bugfix/RR-20260928-13.md)，本地提交未推送）。

`editKubernetesSecretExampleConfig` 以 `strings.Count(body, "\n  config.yaml: |\n") != 1` 定位，CRLF（如 Windows `core.autocrlf=true` 检出）时直接返回、不改也不提示：
`add mod err=<nil> ... prodHasRedis=true secretHasRedis=false secretUnchanged=true`。另：Secret 不可解析时 `add transport tcp` 整体失败回滚、`add mod` 静默跳过，处理不一致（审计疑点 D2）。

修复约束：定位与改写对 CRLF 与 LF 等价（按原行尾写回），与其他配置文件的 CRLF 处理一致（仓内已有 CRLF 回归可参照）；认不出结构时各命令统一给出可见提示（WARN，不静默；是否失败按 `add transport tcp` 与 `add mod` 的既有语义论证统一）；停机块刷新 `refreshGeneratedShutdownConfigs` 的 CRLF 同样处理；加回归。
