# RR-20260927-04：doctor 停机 WARN 对非正时长的判定与运行时不一致；“Set it to”建议值不读配置里的 dataengine 预算

日期：2026-09-27。基线：main `d4234c9`。来源：[OPEN-ITEMS-2026-09-27](../review/OPEN-ITEMS-2026-09-27.md) A08 + A09。
A08 见 [bf-80 §复核后的补修](../bugfix/RR-20260926-80.md)（自报“非正时长仍按覆盖不了判定，本次未改”）；A09 见 [bf-77 §决策与实现](../bugfix/RR-20260926-77.md) 与
[bf-80 §未验证项 / 风险](../bugfix/RR-20260926-80.md)（两边互指对方范围，都没修）。等级 **P4**（doctor 提示，不影响生成物与运行时）。状态：已修复（见下）。

## 现象

1. **A08**：`shutdown.total_timeout: 0s`（或负值）时 App 按 30s 停机，doctor 的 WARN 却按 0 判定：框架服务（6 个 Mod，只需 18s）被报
   `total_timeout 0s cannot cover 6 Mods … Set it to 23s`，game 服务的 WARN 写的是 0s 而不是实际运行的 30s。同一函数里的 FAIL 判定早按 30s 算，两处口径不一。
   同类：`dataengine.shutdown_timeout: 0s` 时 kit/dataengine 按 30s 停，doctor 按 0 算，total 实际不够时给 OK（漏报）。
2. **A09**：WARN 末尾 `Set it to` 的建议值是生成公式值（dataengine 按常量 30s）。把 `dataengine.shutdown_timeout` 调到 60s 后，括号里的所需已经按 60s 算成 126s，
   建议值仍是 101s——比当前值还小，照着改完仍然 WARN。

## 根因（`d4234c9` 行号）

`codegen/internal/roost/shutdown_budget.go` `checkShutdownBudgets`：

- `:426` `parseConfigDuration(settings.Shutdown.TotalTimeout, appDefaultShutdownTotal)` 只在键为空时用 30s，`0s` / `-5s` 原样返回（`:548-553`），`:451` 用它比较；
  FAIL 分支经 `configuredShutdownTotal` → `configTotalTimeout`（`:170-178`）按 `<= 0 → appDefaultShutdownTotal` 处理。App：`app/app.go:313-316`。
- `:438` 读 `dataengine.shutdown_timeout` 同样不处理非正值；kit/dataengine 的读法是 `duration(value, 30s)`（`kit/dataengine/mod.go:216`、`:474-479`，`value > 0` 才用）。
- `:463-464` 建议值 `seconds(plan.total)`，`plan` 来自 `serviceShutdownPlan`（`:99-112`），其中 dataengine 固定 `generatedDataEngineShutdownTimeout`（`:41`、`:106`）。
  `:448` 已经按配置算出 `declared`，但只用于判定和括号里的文字。

## 修复约束（清单推荐）

- A08：WARN 分支也走同一个“非正值按 30s”规则。
- A09：doctor 已解析配置，建议值改用配置里的 dataengine 预算；`project sync` 的生成公式保持不变（OPEN-ITEMS D11）。
