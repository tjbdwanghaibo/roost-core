# RR-20260926-42：`dataengine.shutdown_timeout` 在 App 停机路径不生效，实际预算为总时长按剩余 mod 均分（4～7.5s 而非配置的 30s）

日期：2026-09-26。基线：v1.17.0（`8811c02`）。等级 P3（配置语义被违反；截断后记录留在 WAL，不丢数据）。状态：已复现，未修复。
（最终状态见文末修复节：**已修复，随 v1.17.1 发布**，详见[修复记录](../bugfix/RR-20260926-42.md)。上面的“状态”是登记时的原值，保留不改。——2026-09-27 回写，OPEN-ITEMS A13②）

`kit/dataengine/mod.go:276-290` 只有兼容 `Stop()` 读 `shutdownTimeout`；App 只走 `StopWithContext`（`app/app.go:477`），预算为 `modStopContext` 的 `剩余/(i+1)`（`:450-465`），总时长来自 `shutdown.total_timeout`（`:313`）。
生成配置 `shutdown_timeout: 30s`（`codegen/internal/roost/catalog.go:63`）、kit/README §3.4 称默认 30s。复现：总 30s 时共享 5 / 7 / 10 个 mod 分别 7.5s / 6s / 4.29s。

## 修复约束（维护者 2026-09-26 批准：总时限内优先分配给声明预算的 mod）

App 支持 mod 通过可选接口声明所需停机预算，在 `shutdown.total_timeout` 内优先分配（总和不超过总时长；不足时按声明比例缩放并告警），其余 mod 均分剩余；dataengine 声明 `shutdown_timeout`。

## 修复（2026-09-26）

状态：已修复（基线 `49f20ee` + RR-34 `35060cc`），已本地提交，未推送/发布。新增 `app.ModStopBudgetProvider`，App 每停一个 Mod 按剩余时间
重新规划：声明的 Mod 优先拿到声明值，未声明的 Mod 以 5s 基准均分其余；需求超过剩余时全部按比例缩放并 Warn；服务专属一段为之后的
共享 Mod 保留声明预算；无声明时与原“剩余 / 剩余 mod 数”等价。`kit/dataengine` 声明 `dataengine.shutdown_timeout`。
总 90s、声明 20s 时 5 / 7 / 10 个 mod 的 dataengine 均得 20s（修前 22.5s / 18s / 12.9s）；默认 30s/30s 时得 20s / 18s / 15s 并告警（修前 7.5s / 6s / 4.29s）。
为避免未声明 Mod 拿到零截止时间，“不足”的判定计入每个未声明 Mod 5s 基准，这一取舍与是否上调生成默认 `total_timeout` 待维护者确认。
见[修复记录](../bugfix/RR-20260926-42.md)。
