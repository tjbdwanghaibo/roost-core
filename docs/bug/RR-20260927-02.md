# RR-20260927-02：生成的 player TCP `CloseSessions` 永远返回 0

日期：2026-09-27。基线：main `d4234c9`。来源：[OPEN-ITEMS-2026-09-27](../review/OPEN-ITEMS-2026-09-27.md) A02（[REVIEW-2026-09-27-audit2](../review/REVIEW-2026-09-27-audit2.md) §疑点“生成传输 closeSessions 恒返回 0”）。
等级 **P4**：返回值唯一的消费方只把它写进日志。状态：已修复（见下）。

## 现象

`Runtime.CloseSessions(playerID, reason)` 的 godoc 说“reports how many it closed”，实际对任何玩家、任何会话数都返回 0。
game-demo 的所有权围栏（`demo/internal/service/game/playerowner.go.tmpl:686`）把它写进日志字段 `sessions_closed`（`:703`），fail-closed 断开了几个连接，日志都写 0。

## 根因（`d4234c9` 行号）

`codegen/internal/roost/render_player_tcp.go`（生成 `internal/access/player/tcp/server_gen.go`）：

- `:939-952` `closeSessions` 对每个会话 `if err := current.Close(reason); err == nil { closed++ }`；
- `:1039-1048` `session.Close` 在 `closeOnce` 里把 `closeErr` 置为 `reason`（nil 时补成 `gateway.ErrSessionClosed`）再 `errors.Join` 连接关闭错误，返回 `closeErr`——永远非 nil。

所以 `closed++` 从不执行。计数看的是“Close 的返回值”，而 Close 的返回值是关闭原因，不是“这次调用是否关掉了它”。

## 修复约束（清单推荐）

按“是否真的关掉了这个会话”计数（例如 `closeOnce` 首次执行时计数），不看 `closeErr`。
