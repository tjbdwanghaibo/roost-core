# RR-20260924-05：异步提交完成可能早于 Entity 解锁

- 日期 / 基线：2026-09-24，`967bc69` 加已完成的 Nest N1/N2a 工作树；等级 P1。
- 范围：pipelined async completion，WAL ticket 在释放锁之前完成。
- 状态：已复现、已修复，未提交、未发布；见 [修复记录](../bugfix/RR-20260924-05.md)。

## 触发、预期与实际

事务在锁内提交已完成的 ticket，完成池立即取得任务；dispatch worker 此时仍在 EntityManager release hook 中。预期完成池等待实体释放，再执行 AfterCommit 和回复。原实现只有同主实体排序链，没有本事务的解锁屏障，AfterCommit 可以在另一个 goroutine 持锁时执行，并提前回复。

根因在 [pipelined_completion.go](../../nest/pipelined_completion.go) 的 `prepareCompletion` 与 [execution.go](../../nest/execution.go) 的交接顺序。SyncMutation 自己的 released 条件不能代替所有业务 AfterCommit 的顺序保证。

## 修前复现

[completion_unlock_test.go](../../nest/completion_unlock_test.go) 使用真实 Engine、EntityManager release hook 和自动完成的测试 committer。通道阻塞 release hook，AfterCommit 在另一 goroutine 尝试取得实体锁；负向检查窗口为 20ms。修前实际失败：

```text
AfterCommit ran before release completed (lock free=false)
```

```sh
GOCACHE=/tmp/roost-nest-go-cache GOWORK=off go test ./nest \
  -run '^TestAsyncCompletionWaitsForEntityRelease$' -count=1
```

这不表示所有 ticket 都抢先完成，但快速 WAL、完成池与慢 release hook 的组合可以触发错误顺序。
