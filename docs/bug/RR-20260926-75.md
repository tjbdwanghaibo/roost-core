# RR-20260926-75：带 Remote 批次的消息里，嵌套独立事务替外层 finalize 并提交 Remote 批次

日期：2026-09-27。基线：本地 main `736bdb2`（RR-64～72 合并后，未推送）。来源：第三轮修复后独立审计（[REVIEW-2026-09-27-audit3](../review/REVIEW-2026-09-27-audit3.md)）。等级 **P3（潜在）**：仓内无调用方。引入：修前即有。状态：已复现，未修复。

带 Remote 批次的消息里调用 `RunIsolatedTransaction`：批次 `FinalizeLocked` 收到嵌套事务的 outcome，外层自己的 finalize 因 `remoteFinalized`
已置位被跳过（`nest/execution.go:182`）；`nest/execution.go:262` 置 `remoteCommitted`，外层失败时批次仍 Commit（Commit=1、Abort=0），
回复误带 `ErrAfterCommitFailed` 而外层提交数为 0：失败消息的 Remote 修改被发布，回复又误报“已提交”。复现：[REPRO-2026-09-26-07](REPRO-2026-09-26-07.md) §1。

修复约束（维护者 2026-09-27 批准：拒绝）：消息带 Remote 批次（或嵌套事务会触及 Remote 实体）时，嵌套独立事务直接返回可 `errors.Is` 的新哨兵，
不 finalize、不改 `remoteFinalized` / `remoteCommitted`；Remote 批次只随消息自己的事务 Commit 或 Abort。不引入嵌套独立批次。

## 修复（2026-09-27）

状态：**已修复，未发布**（本地提交，未推送）。按修复约束（拒绝）实现：`invokeWithTransaction` 入口若当前消息已有自己的在途事务
（`txInFlight`，即本次调用是嵌套事务）且带 Remote 批次，直接返回新哨兵 `nest.ErrNestedTransactionInRemoteMessage`：`call` 不执行，
不经过 `finalizeRemoteWriteBatch` / `commitDurable`，`remoteFinalized` / `remoteCommitted` 不变；批次只随消息自己的事务 Commit / Abort。
嵌套事务触及 remote-managed 实体而消息没有批次时，既有的 `ErrDurableRemoteWriteUnsupported`（捕获时拒绝）不变。
修前红（§1 探针 3b 改写，基线 `62fdbe6`）：三个子用例都 `FinalizeLocked handlers=[rr75_iso_in_remote] isolatedRuns=1 isolatedCommits=1`，
外层失败时回复 `transaction committed but after-commit work failed`。详见[修复记录](../bugfix/RR-20260926-75.md)。
