# RR-20260930-20：handler 业务失败后 release hook panic，回复丢失业务错误、只剩 hook 错误

日期：2026-09-30。基线：main `19b26d27`。来源：B27 第 2 批端到端补测（RR-20260926-53 / RR-20260926-32 的“后续验证”）在正式生成链路上暴露。等级 **P2**：业务已按约回滚（RR-53 承诺的“不带哨兵、值回滚”成立），但调用方拿到的错误被替换成 `release hook failed after commit`，无法据此判别——判别表按“提交后 hook 失败”走，实际什么都没提交。状态：**已确认，未修复**。

## 触发条件、预期与实际

- 触发：handler 返回业务错误（事务回滚），随后该消息释放实体时 `OnEntityRelease` 钩子 panic。async / strict / pipelined 的本地消息，以及带 Remote 批次的 strict 消息都如此。
- 预期：回复保留业务错误（`errors.Is` 可判），hook panic 作为附加信息（日志或 `errors.Join`）；不得带 `ErrAfterCommitFailed`。
- 实际（`bash scripts/test-dataengine-generated.sh`，去掉 `codegen/internal/entity/testdata/dataengine/after_commit_test.go:107` 的 `t.Skip` 后）：
  `rolled-back strict transaction with a release hook panic replied persistflow: release hook failed after commit: want the business error kept`（三种策略同）；
  Remote 形态（`codegen/internal/entity/testdata/remoteflow/after_commit_test.go:149`）：`replied remoteflow: release hook failed after the Remote commit`。

## 根因（到行）

handler 返回业务错误 → `dispatchLoadedEntities` 的 `defer release()`（`nest/nest_dispatch.go:404-406`）→ `releaseDispatchEntities` → `Guard.ReleaseEntity` → `runOnEntityRelease`（`entity/entity_guard.go:62-73`，不 recover）→ panic 传到 `runNestLogic` 的 recover（`nest/nest_dispatch.go:203-209`，`err = recoveredErr`），在途的 handler 错误被整个替换。

## 暴露用例（已入库，`t.Skip` 引用本编号）

- `codegen/internal/entity/testdata/dataengine/after_commit_test.go` `TestGeneratedDataEngineRolledBackReleaseHookPanicKeepsBusinessError`
- `codegen/internal/entity/testdata/remoteflow/after_commit_test.go` `TestGeneratedRemoteRolledBackReleaseHookPanicKeepsBusinessError`

## 修复约束

- 回复以业务错误为主，hook 失败以 `errors.Join` 或 `%w` 链附加，`errors.Is(err, 业务错误)` 必须成立；已提交路径的 `ErrAfterCommitFailed` 语义（RR-53）不变。
- 修复落在 nest 派发 / Guard 释放的错误合并处，不在生成模板里特判；去掉两条用例的 `t.Skip` 作为绿。

## 修复（2026-09-30）

状态：**已修复**，本地验证通过（包内回归 + 两条生成链路端到端），本地提交，未推送 / 未发版。修复记录：[bugfix/RR-20260930-20](../bugfix/RR-20260930-20.md)。
修法：`dispatchLoadedEntities` 的兜底释放在自己的 recover 边界里跑，hook 的 panic 以 `errors.Join` 并进在途的业务错误；`runNestLogic` / `dispatchNest` 的 recover 改为并入而非覆盖已有 `err`。
已提交路径的 `ErrAfterCommitFailed` 语义（RR-20260926-53 / 32）不变。两条端到端用例的 `t.Skip` 已去掉。
