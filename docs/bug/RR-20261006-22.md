# RR-20261006-22：presentation reset 的进程条目用 lifecycle 实体冒充 PrimaryTarget，与增量交给策略的事件不一致

2026-10-06，基线 `37338490`（main）。P3（默认 `EntityVisibilityPolicy` 不受影响；按 `PrimaryTarget` 决定去留的自定义策略会在 reset 里放出增量里挡住的进程表现）。来源：发版文档 SKILL-3 review 检查点“reset 里的 process 条目没有专门用例，核对 `activePresentationEvent` 还原出的事件形状与 Runtime 增量里的 process 事件一致”的补测（分支 `sktest2`）。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261006-22.md)。

## 机制

- 增量：`emitProcessPresentation`（`skill/presentation.go:170`）经 `appendPresentation`（`:200`）发事件，`PrimaryTarget = cast.primaryTarget`。仍归施法的进程，cast 是真正的施法，`PrimaryTarget` 是施法目标；移交后经 `detachedProcessCast`（`skill/process_owned.go:109`），`primaryTarget` 是 lifecycle 实体。`Anchor.Target` 两种情况都是 lifecycle 实体。
- reset：`PresentationSnapshot`（`skill/presentation_recovery.go:35`）的 `ActivePresentation` 不带 PrimaryTarget；`activePresentationEvent`（`skill/skillsync/coordinator.go:495-499`，基线）把 `PrimaryTarget` 填成 `entry.Anchor.Target`，注释也写“PrimaryTarget 与 Anchor.Target 是目标 / lifecycle 实体”。
- 仍归施法的进程，reset 交给 `FilterPresentation` 的事件与增量不同；策略若按 `PrimaryTarget` 判定，两条路径结论相反（NC-114 的承诺是两条路径同一规则）。

## 触发 / 预期 / 实际

- 触发：施法者 1 对目标 2 施法，enter 召出带 area 视觉的陷阱（lifecycle 实体 3），施法还在 wait；observer 的策略挡住 `PrimaryTarget == 2` 的表现；走一次 Recover。
- 预期：reset 交给策略的事件与 Runtime 增量同形（`PrimaryTarget` 2），增量被挡则 reset 不发这条进程表现。
- 实际：reset 交给策略 `PrimaryTarget 3`，增量被挡、reset 却发了出去。已移交的进程（`PrimaryTarget` 本来就是 lifecycle）一致；默认 `EntityVisibilityPolicy` 只用 `PrimaryTarget` 做脱敏、不决定去留，结论一致。

## 可达性

只影响自定义 `VisibilityPolicy` 里按 `PresentationEvent.PrimaryTarget` 决定去留的实现，且只在施法仍在进行、进程未移交时；仓内策略（`AllowAllVisibility`、`EntityVisibilityPolicy`）不这样用。
