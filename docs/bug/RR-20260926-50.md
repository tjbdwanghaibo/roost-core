# RR-20260926-50：WAL terminal 后同一被跳过的原生步骤每轮重投都再次排入驱逐；terminal 前已进入等待的冷加载拿不到 WAL 错误

日期：2026-09-26。基线：本地 main `2330d57`（RR-30、33～47 修复合并后，未推送）。来源：修复合并后独立审计。等级 P3。引入：RR-20260926-30 修复（与 RR-33 交互）。状态：已复现，未修复。

- 投影器按退避重试 ReplayPass，每轮从 checkpoint 重投；`ProjectFenced` 读到持久 skipped 标记而 `pendingTransactions` 中该项仍 fenced → 每轮 append 一条驱逐（`dataengine/engine/projector_replay.go:164` → `fenced_step.go:90-117`，`:109` 不判重）：驱逐队列无界增长直到关闭、`dataengine.fence.evictions.started.total` 重复累加；驱逐稍后成功时多余项可能卸载刚从 Mongo 重载的新对象（多一次重载与全量）。Close 仍立即返回、屏障解除。
  复现：[REPRO-2026-09-26-05](REPRO-2026-09-26-05.md) §3：`after 5 failed passes: eviction queue=4 eviction attempts so far=1` → `queued for eviction 4 extra time(s)`。
- terminal 前已进入 `WaitEntityProjection` 等该驱逐的调用方要等到自身 ctx 截止或关闭（`entity_projection.go:96-107` 只在等待前后检查），得不到“立即拿到 WAL 错误”。

修复约束：驱逐按事务身份去重（同一被跳过记录只登记一次）；WAL terminal / fatal 时唤醒全部等待方并返回可判别错误（与 RR-10 复核补修一致）。

## 修复（2026-09-26）

状态：已修复（基线 `3e26f91`），已本地提交，未推送/发布。按修复约束实现：`startStaleEviction` 在 `heldMu` 下按事务身份登记驱逐（`entityProjection.evicting`），
重投读到同一条被跳过的记录不再入队、不再计数，驱逐成功后不会再卸载刚重载的新对象；`nestwal.WAL.Terminated()` 在 WAL terminal 时关闭，Projector 监听它
（以及 checkpoint 返回的 `ErrCommitIndeterminate`），先写 terminal 错误再经 `completeAllTickets` 唤醒全部待投影等待方与系统票据，`reserve` 同锁复查，
等待方拿到 `errors.Is(err, nest.ErrCommitIndeterminate)` 的错误。修前 `after 5 failed passes the same skipped step waits in the eviction queue 4 more time(s)`、
`a waiter that entered WaitEntityProjection before the WAL went terminal is still blocked on the pending eviction`（fake ack 与真实 WAL fsync EIO 各一条）。
见[修复记录](../bugfix/RR-20260926-50.md)。
