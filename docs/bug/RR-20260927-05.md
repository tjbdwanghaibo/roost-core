# RR-20260927-05：生成的 player TCP Mod 不声明停机预算，只拿 3s 保底

日期：2026-09-27。基线：main `d4234c9`。来源：[OPEN-ITEMS-2026-09-27](../review/OPEN-ITEMS-2026-09-27.md) C05（[bf-66 §未验证项](../bugfix/RR-20260926-66.md)“是否让它声明预算属另一项行为变化，未做”；
[REVIEW-2026-09-27-audit2](../review/REVIEW-2026-09-27-audit2.md) §疑点 RR-51 项）。维护者 2026-09-27 决定 C 类按推荐执行：让它声明 `StopBudget() = ShutdownTimeout`，生成公式与 doctor 同步计入。
等级 **P3**（停机时玩家连接排空可能被截断）。状态：已修复（见下）。

## 现象

App 停机按“声明预算的 Mod 拿声明值、未声明的每个至少 3s 保底”规划（RR-42 / RR-51）。生成的 player TCP Mod（`accessplayertcp`）没有实现
`app.ModStopBudgetProvider`，只得到保底份额（game-demo 的 game 服务约 3.7s），低于它自己的 `player_access.tcp.shutdown_timeout: 10s`（该值只约束兼容 `Stop()`）；
保底 3s 与 `nest.request_timeout` 3s 也没有余量：在途请求用满 3s 时，服务器 `Stop` 等不到连接排空就超时，并按 App 的语义中断后续关闭。

## 根因（`d4234c9` 行号）

- `codegen/internal/roost/render_player_tcp.go:204`（`Config.ShutdownTimeout`）、`:229`（默认 10s）、`:248`（读配置）、`:362-366`（`Stop` 用它）：
  只有 `Stop` / `StopWithContext`，没有 `StopBudget()`；文件末尾的接口断言只有 `app.Mod`、`app.ModStopperWithContext`。
- 全仓唯一实现 `StopBudget` 的是 `kit/dataengine/mod.go:292-297`（返回 `dataengine.shutdown_timeout`，未 Init 为 0）。
- 生成公式 `codegen/internal/roost/shutdown_budget.go:99-112` 与 doctor（`:436-450`）只把 dataengine 当声明方；`app/stop_budget_generated_test.go:14` 的注释写明 accessplayertcp 只得约 3s。

## 修复约束（清单 §H 推荐，维护者已定）

player TCP Mod 声明 `StopBudget() = ShutdownTimeout`；生成公式（`total_timeout = 声明预算之和 + 3s × 未声明 Mod 数 + 5s`）与 doctor 同步计入（game 服务 total 相应增加）；
更新所有写死数值的文档与测试钉值，写清兼容性。
