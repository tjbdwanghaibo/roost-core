# RR-20261006-65：lockstep 机器人只在缓冲溢出时追帧，缺口不够大时整局卡住

2026-10-07，基线 `a7285da6`。P1（压测机器人：丢包超过冗余深度但不足以撑满 256 帧乱序缓冲时 `Next` 永久停住，局卡到超时；`demo/cmd/loadtest/main.go.tmpl` 的注释声称会主动要历史）。来源：框架文档审查 F04-9。维护者 2026-10-07 选 A。
状态：已复现；已修复（`99a3e99f`，[修复](../bugfix/RR-20261006-65.md)），未发版。

## 机制

1. `LockstepBot.HandleBroadcast` / `HandleFrames` 只在 `FrameAssembler.Ingest` 返回错误（缓冲溢出）时调 `requestCatchup`（基线 `robot/lockstep.go:150-156`），从不看 `Gap()`。
2. 连续丢包超过冗余深度时，后续包里的帧进缓冲、`Next` 停在缺口；要等缓冲攒满 256 帧（10ms 帧约 2.5 秒）才第一次请求。
3. 请求被服务端放弃（追帧发送连续失败）后，`catchupFrom == from` 让之后同一缺口的请求全被静默去重，永不重发。
