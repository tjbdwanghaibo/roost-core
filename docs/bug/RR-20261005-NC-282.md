# NC-282：cast_start / phase_start 读取的实体是可缺省引用时，读取处的 exists 守卫在采样点不生效，缺省即施法失败

2026-10-06，基线 `0aeb5ab6`。P2（编译通过；可缺省的值缺省时 Activate（cast_start）或进入 phase（phase_start）`ErrRuntimeTypeMismatch`，作者写的守卫不起作用）。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-282.md)。[本轮](../review/REVIEW-2026-10-06-n09-batch6.md)。

## 机制

cast_start / phase_start 的整个读取（包括实体）在采样点求值（`runtime_eval.go` `captureSnapshots`），之后读缓存。类型检查在读取处检查实体：`if exists($primary_target)` 的 then 分支里 `$primary_target` 被收窄为非可缺省，读取通过。采样点上没有这个守卫：`$primary_target` 缺省（无目标施法）或 null 默认值的 memory 求成 missing，`entityValue.Entity()` 失败 → `ErrRuntimeTypeMismatch`，整个施法失败。NC-220 只拒绝了局部变量与 process_start 的位置，没有覆盖可缺省的实体。

## 触发与差异

`{"flow":"if","condition":{"op":"exists","args":["$primary_target"]},"then":{damage $primary_target amount read_attribute($primary_target, cast_start)}}`，无目标施法：修前编译通过，Activate `skill: runtime value type mismatch`；`phase_start` 同样；把实体换成 null 默认值的 `$memory.who` 同样。`current` 版本正常（在读取处求值，守卫生效）。

## 复现

`TestCompileRejectsOptionalEntitiesInCachedReads` 四个子用例修前全部 `… compiled; casting without it: skill: runtime value type mismatch`。

## 验收覆盖点

`ATTRIBUTE_SNAPSHOT_INVALID` 于 `….read_attribute.entity`，提示改用 current。控制 `TestGuardedOptionalReadsAtCurrentStillRun`：守卫 + current 照常；非可缺省的 memory（默认 `$caster`）照常用 cast_start。
