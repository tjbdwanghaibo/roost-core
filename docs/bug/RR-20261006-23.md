# RR-20261006-23：起过进程的 cast 在进程结束后也永不回收，超过 CompletedCastLimit 后 checkpoint 恢复判 corrupt

2026-10-06，基线 `37338490`（main）+ 补测草稿 `5b4d49f5`。P2（live Runtime 无界增长；一局里起过进程的施法累计超过 `CompletedCastLimit`（默认 2048）后 checkpoint 无法恢复）。来源：补 SKILL-1 第三条（[RR-20261006-21](RR-20261006-21.md)）时核对进程记录的生命周期。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261006-23.md)。

## 机制

- 进程停止后记录从不删除：`stopProcess`（`skill/process.go:189`）只改状态；`terminateOwnedProcess`、`RemoveProgram`、`Shutdown`（`skill/process_owned.go:493-575`）只删 `ownedProcesses` 里的条目，`runtime.processes` 里的记录一直在。
- `castEvictableLocked`（`skill/runtime_retention.go:75-90`，基线）把 cast 名下**任何**进程记录（不论是否在运行）当作“仍被引用”，`pruneCompletedCastsLocked` 跳过它。
- 结果：起过 entity 进程的 cast，进程结束、移交的条目也删了，仍永远留在 `runtime.casts` 与完成队列里；完成队列超过 `CompletedCastLimit` 后，`restoreCheckpointPayload` 的上限校验（`skill/runtime_checkpoint.go:1041`）判 `ErrCheckpointCorrupt`。

NC-117 修了“提交前失败的 cast 不进完成队列”；这里是进了队列、却因为已停的进程记录永远回收不了。

## 触发 / 预期 / 实际

- 触发：`CompletedCastLimit: 3`，先放一个召唤 100 tick 的技能（施法 2 tick 后结束、进程移交并继续运行），再放 8 次召唤 4 tick 的技能，每次推进到进程到期。
- 预期：只有仍在运行的进程钉住 cast；保留的 cast 不超过上限 + 被钉住的那一个；checkpoint 能恢复；长进程结束后它的 cast 也能回收。
- 实际：9 个 cast、9 条进程记录全部保留，恢复判 corrupt。

## 可达性

所有用 summon / area 进程的技能。默认上限 2048：一局里这类施法累计超过 2048 次后 checkpoint 不能恢复，此前 cast 与进程记录随施法次数线性增长。
