# RR-20260926-19：租约 fence 失效导致 WAL 记录被整体跳过时，其中的 Remote 事务永远得不到结论，写权限、锁与额度被永久占住

**当前状态：已修复并完成适用本地验证，未提交/发布。** 见[修复与边界](../bugfix/RR-20260926-19.md)。以下保留原审查基线。

日期：2026-09-26。基线：main `aaada47`。等级 P2（实体永久隔离、同实体后续写入超时；共享模式下 Redis 锁被续期，全集群写不了该实体）。
状态：已复现（端到端探针，已删除），源码已核对，未修复。来源：上线前复审（Remote 持久权威）。

## 触发条件

同一 Nest 事务里既有 `RemoteWriteBatch`，又带 lease fence receipt（例如 `saga.BindCommand(..., fences...)`，`saga/nest.go:79-86`，无互斥校验）；投影时租约已失效。

## 预期 vs 实际

预期：记录被跳过即等于其中 Remote 事务被拒绝，应回滚内存并释放 gate / 锁 / 写额度。

实际：
- `dataengine/engine/mongo_projection.go:83-92`、`:127-128` 只写一个 `Skipped` 事务标记即返回 nil，WAL 正常 ack，不调用 `ApplyRemoteCommits`，也不 complete tracker
  （有意设计，`TestMongoStoreSkippedLeaseFenceNeverPublishesRemoteCommit` 断言 applied==0）。
- Manager 侧 tracker 停在 Admitted；`remoteentity/transaction_tracking.go:177-182` 对非 Indeterminate 状态直接返回 tracker 状态，不查后端。
- `remoteentity/transaction_manager.go:255-309` 的 finalizer 因此永远“隔离 + 退避重试”：write gate、ownershipMu 读锁、写额度被永久占住，实体保持 quarantined；
  共享模式下 Redis 锁还被 async touch 一直续期。Strict 调用方只看到超时。

## 复现

审查 agent 端到端探针（已删除，源码未保留）：

```text
strict remote commit after skipped projection: commit timed out
projector={... Projected:1 WALUnacked:0 ...} manager status=1(Admitted) mgr={... ActiveTransactions:1 WritesInFlight:1 ...} live=quarantined
同实体下一次写入超时
```

复审方已按源码核对 `mongo_projection.go:83-92` 与 `transaction_tracking.go:177-182`。

## 实施方向（约束）

- 投影层跳过记录时必须给其中的 Remote 事务一个确定结论（拒绝），并让 Manager 回滚内存、释放 gate / 锁 / 额度；或在准入时禁止 Remote 写与 lease fence 同事务。
- 不能伪造提交；结论需持久（Skipped 标记）并可被 finalizer 回源读取。

## 验收覆盖点

- 同事务 Remote 写 + 过期 lease fence：记录被跳过，Remote 事务状态为 Rejected，gate/锁/额度释放，实体恢复可写。
- 租约有效时行为不变。


## 2026-09-26 修复更新

已按当前源码核实并修复，适用本地回归通过；原始审查证据保留。见[修复记录](../bugfix/RR-20260926-19.md)。采用原问题允许的“准入时禁止组合”。生成 Entity 的 RollbackRemoteCommit 不保存完整跨实体前像，不能宣称支持投影阶段事后撤销内存事务。自定义 remoteStore 回放历史混合记录必须实现 RejectRemoteCommitsInTransaction，否则明确报错且不 ack。
