# RR-20260926-12：生成工程的 `syncbus:` 配置段被 kit/syncbus 整段忽略，配置的 JetStream 静默退回普通 NATS

**当前状态：已修复并完成适用本地验证，未提交/发布。** 见[修复与边界](../bugfix/RR-20260926-12.md)。以下保留原审查基线。

日期：2026-09-26。基线：main `aaada47`。等级 **P1（建议）**（生成工程声明的持久同步总线静默降级为至多一次的普通 NATS，跨进程同步消息在断连时可丢，且无任何报错）。
引入：`0e1b469`（ARCH-10 命名收尾，RoomMod → SyncBusMod），未发布。状态：已确认（源码 + CI 日志），未修复。

## 触发条件

用当前生成器（`roost project new`，含 `syncbus` mod，Remote 等依赖它）生成工程并启动。

## 预期 vs 实际

预期：生成的 `configs` 里 `syncbus: {transport: jetstream, prefix: roost.sync, storage: file, replicas: 1, publish_timeout: 3s}` 生效。

实际：`kit/syncbus` 只读 `room.*` 与 legacy `sync.*` 两个段，`syncbus.*` 整段被忽略，transport 回落默认的普通 NATS，prefix 用默认 `roost.room`。
CI（framework-compat，run 36217352984）服务日志：`"syncbus mod: started","transport":"nats"`。

## 根因（代码）

- `codegen/internal/roost/catalog.go:55`：生成的配置段名为 `syncbus:`。
- `kit/syncbus/mod.go:23-37`：`roomConfigSection = "room"`、`legacyConfigSection = "sync"`，`configKey` 只在这两个段里查找；
  注释仍写 “Config lives under the "room" section”。改名时生成器与 mod 的配置段没有同步，也没有“未知段”告警。

## 影响

所有用当前生成器创建、依赖 syncbus 的工程（包括 Remote 实体跨进程同步）以为使用 JetStream 持久投递，实际是普通 NATS：
断连 / 重启窗口内的同步消息丢失且不可重放；prefix 不符还会与同 NATS 上其他部署撞主题。生成工程的冒烟测试不会发现（功能在无故障时照常工作）。

## 实施方向（约束）

- 生成器与 kit/syncbus 使用同一配置段名；已有部署的 `room` / `sync` 段需要兼容读取或明确迁移说明。
- 配了未被读取的段应当可观测（启动日志 / 校验失败），避免再次静默降级。

## 验收覆盖点

- 新生成工程启动日志 `transport=jetstream`、prefix 为配置值；删掉配置段时行为按文档默认。
- 旧 `room:` / `sync:` 段的工程行为不变或有明确告警。
- 生成工程测试断言 syncbus 实际 transport（而不只是能启动）。
