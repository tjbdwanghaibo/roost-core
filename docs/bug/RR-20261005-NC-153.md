# NC-153：VisualPlanCache 的共享加载用第一个调用者的 ctx——第一个调用者取消后，同时在等的其他调用者（ctx 仍有效）也拿到 `context.Canceled`

2026-10-05，基线 `45d4bc1c`。P3（客户端表现资源加载；同一 plan 并发加载时一个调用者断开让其他调用者失败，失败条目会被删除、重试可恢复）。状态：已复现、已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-153.md)。[本轮](../review/REVIEW-2026-10-05-n09-batch3.md)。

## 触发与差异

`VisualPlanCache.Acquire`（`skill/presentation_asset_cache.go:109-154`）：第一个调用者创建条目并同步执行 `cache.load(ctx, …)`（`:124-127`），`load` 把**这个调用者的 ctx** 交给 `preload` → `acquireAsset` → `Loader.Preload`（`:180`、`:210`、`:265`）。后到的调用者只 `refs++` 并等 `entry.ready`（`:135-143`），醒来后直接返回 `entry.err`（`:146-150`）。资产层同形：`acquireAsset` 的创建者用自己的 ctx 调 `Preload`，等待者返回创建者的错误（`:292-300`）。

`docs/skill/skill-implementation-guide.md` §11.3 / `visual-sync-production-guide.md` §8 把缓存描述为“并行 preload、引用计数、预留引用”，取消只应作用于取消者本人（roost-coding：取消等待不等于撤销业务）。

## 复现（探针，基线代码）

Loader 的 Preload 阻塞到放行或 ctx 结束；A 用可取消 ctx 发起，B 用 `context.Background()` 在同一 plan 上等待（refs == 2 后），取消 A：

```
first = preload "asset-impact": context canceled
second (uncancelled ctx) = preload "asset-impact": context canceled
```

## 影响

多个会话同时请求同一表现 plan 时，任一请求方断线 / 超时让其他会话的加载一起失败，且错误满足 `errors.Is(err, context.Canceled)`，调用方会误判为自己被取消。

## 验收覆盖点

plan 层与资产层：创建者取消后，ctx 仍有效的等待者得到成功的 lease（重新加载），取消者本人得到 ctx 错误；等待者自己取消仍立即返回；加载真实失败（Loader 返回错误）时等待者照常拿到该错误；引用计数与 unload 在这些路径后归零。
