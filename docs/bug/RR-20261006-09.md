# RR-20261006-09：robot Stage 先缩后扩，新机器人复用刚停掉的机器人的序号与 PlayerID

2026-10-06，基线 `53fd9e9c`。P3（压测工具；两个机器人同时以一个玩家身份在线，压测结果失真，网关可能把旧会话踢掉或拒绝新登录）。来源：N12 观察 O9（[REVIEW-2026-10-05-n12-revn12](../review/REVIEW-2026-10-05-n12-revn12.md)），维护者第十二轮决定“robot Stage 序号只增不回收”。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261006-09.md)。

## 机制

`robot/runner/runner.go` `runPopulation`：`launchUpTo` 给新机器人编号 `index := launched + i + 1`，`shrinkTo` 缩容时把 `launched` 减回去（`launched--` 并关掉末尾机器人的 stop 通道）。Stage 先缩到 1 再扩回 3，扩容从 `launched+1 = 2` 起编号——正是刚刚停掉的 2、3 号。被停的机器人只是收到 stop，还在收尾（场景被取消、关会话、登出），新机器人已经以同一序号、同一 PlayerID（`IdentityProvider(index)`）登录。

## 触发与差异

looping 执行器、`Count: 3`、Stages `[{Target: 1}, {Target: 3}]`：预期 5 个机器人用 5 个不同序号；实际序号 `[1 2 3 2 3]`。

## 复现

`TestStageRegrowDoesNotReuseOrdinals`（`robot/runner/stage_ordinal_promises_test.go`）修前：

```
--- FAIL: TestStageRegrowDoesNotReuseOrdinals (0.06s)
    stage_ordinal_promises_test.go:48: robot ordinal 2 was handed out twice across the stages (launch order [1 2 3 2 3]); a regrown stage must not reuse the ordinal (and player id) of a robot it just stopped
```

## 修复

[修复记录](../bugfix/RR-20261006-09.md)：序号只增不回收，单独记已发出的最大序号。
