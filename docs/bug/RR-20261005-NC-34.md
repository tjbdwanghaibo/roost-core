# RR-20261005-NC-34：兴趣消息可修改信封身份之外的订阅

2026-10-05，P2；发现基线 `b2232db528de9947a2cf1cccaed79e7a9e29d2dc`。

## 承诺、反例与根因

Remote interest 的发布格式是 Upsert：Key 为完整 snapshot key 与 ConsumerSID 的哈希，Version 为 ExpiresAt；renew/release 由 payload.Release 区分，Generation 负责订阅代际比较。

[InterestReplicaStore](../../remoteentity/interest.go) 原先只解码并调用注册表，未将 payload 与信封交叉校验。通过正式 BindSync/Replicator，续租和撤销各改变 scope、ConsumerSID、ExpiresAt、Op 四项，共八反例：外层两层信封一致，续租把预置 lease 的 generation10 改11，撤销把该 lease 删除，返回 nil。即使注册表的代际比较本身正确，仍会对错误的对象执行操作。

[红日志](../bugfix/evidence/noncore-bugfix-20261005-13/red.txt)显示实际副作用。错误兴趣可能使快照发布过滤跳过仍需更新的消费者，或给错误对象续租；本轮未制造真实 broker/跨服务丢更新来夸大证据。该适配器不同于已修的 SnapshotReplicaStore，属于新的接收入口缺口。

## 状态追加

已修复、声明场景已验证，未发版。在注册表变化前检查合法 key/SID、Upsert、哈希 key 与 ExpiresAt。合法 Generation=0、旧 release 不撤销新 generation、正式合法撤销及空 payload 的无副作用兼容均通过。[修复](../bugfix/RR-20261005-NC-34.md) · [接续审查](../review/REVIEW-2026-10-05-noncore-23.md)。这不增加发布者认证，也不把 ExpiresAt 当作代际排序版本。
