# NC-213：chain 的 `allow_repeat` / `hop_interval_ticks` 与 attribute_modifier 的 `stack_policy` / `max_stacks` 编译、算进摘要，却从不传给 Host

2026-10-05，基线 `c10cc9ac`。P3（作者写的语义被静默丢掉；不会让施法失败，但行为与定义不符）。状态：已确认（源码判定 + 探针）；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-213.md)。[本轮](../review/REVIEW-2026-10-05-n09-batch4.md)。与 [NC-151](RR-20261005-NC-151.md)（phase recast / timeout 只编译不执行）同一类。

## 触发与差异

对 `program*.go` 里每个字段在 Runtime 侧（排除 lower / digest / inspect / compile*）找读取点，下列字段只有写、没有读：

| 字段 | 编译 / lower | Runtime / Host |
| --- | --- | --- |
| chain `allow_repeat`、`hop_interval_ticks` | `wire_select.go:351-361` 解码，`lower.go:432` 写进 `shapeProgram`，`program_digest.go:22-23` 进摘要 | `runtime_select.go:350-352` 构造 `ChainSelectShape{Origin, HopRange, MaxTargets}`；`host.go:143-147` 的 `ChainSelectShape` 没有这两个字段，Runtime 也没有按间隔排 hop |
| attribute_modifier `stack_policy`、`max_stacks` | `wire_effect.go:334-345` 解码，`lower.go:593` 写进 `attributeModifierOperation`，`program_digest.go:267` 进摘要；值不做任何校验（`"zz"`、`-3` 都接受） | `runtime_cast.go:90` 构造的 `AttributeModifierCommand`（`host_combat.go:122-133`）没有这两个字段；MemoryHost 与 combatcomponent 都按独立实例叠加 |

NC-152 的记录已经注意到 chain `hop_interval_ticks` “与 0 相同（一次跳完）”，当时只处理了负值。

## 复现

`hop_interval_ticks: 3` 的 chain 在同一 tick 打完所有目标；`allow_repeat: true` 与 `false` 生成完全相同的 `SelectRequest`；`stack_policy:"zz", max_stacks:-3` 的 attribute_modifier 编译通过、施法成功。正式回归（修前）`TestCompileRejectsFieldsTheRuntimeDoesNotExecute` 四个子用例都是 `compiled; diagnostics=[]skill.Diagnostic(nil)`。

## 影响

写了“每跳间隔 3 tick 的连锁闪电”或“最多叠 3 层的属性加成”的技能，编译与启动都通过，运行时间隔和叠层上限都不存在。

## 实施方向（约束与候选）

A. 实现：`ChainSelectShape` 增加 `AllowRepeat`，Runtime 按 `hop_interval_ticks` 分 tick 执行 hop；`AttributeModifierCommand` 增加叠层策略并让两个 Host 实现——都需要维护者定语义（hop 间隔里目标死亡 / 离开、叠层与 status 的关系）。
B. 编译期 fail-closed（与 NC-151 方向 B 一致）：只接受 Runtime 实际执行的默认值（`allow_repeat:false`、`hop_interval_ticks:0`、不写 `stack_policy` / `max_stacks`），其它值报诊断，等维护者决定是否做 A。
