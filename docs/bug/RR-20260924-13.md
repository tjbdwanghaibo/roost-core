# RR-20260924-13：慢 Outbox 发布耗尽失败后的重试窗口

日期：2026-09-24；基线：`967bc69` 加当前 DataEngine 工作树。等级：P2。状态：已复现、已修复，未发布；[修复记录](../bugfix/RR-20260924-13.md)。

OutboxWorker.RunOnce 在领取整批前记录 now，发布失败后仍使用这个旧时刻计算 available_at。若 Mongo claim、前面的消息或当前 Publish 耗时超过退避时间，写入的重试时刻已在过去。下一轮能立即再次领取失败消息，配置的指数退避无法保护慢 Broker。

预期：每条失败消息从 Publish 返回失败起至少等待 RetryMin × 指数退避（上限 RetryMax）。实际：一次 5 秒的 Publish timeout，RetryMin=1 秒，失败消息被安排到 4 秒以前。

受控时钟测试 `TestOutboxRetryDelayStartsAfterFailedPublish` 使用 MongoOutboxStore + mongotest，模拟每次发布耗时 5 秒，不使用真实 sleep。在失败后 999ms 再执行 RunOnce，修前错误地领取并再次发布。后续轮次检查 1/2/4/4 秒窗口及退避上限。

```sh
GOWORK=off go test ./dataengine/engine -run '^TestOutboxRetryDelayStartsAfterFailedPublish$' -count=1
```

修前输出：`claimed before retry delay 1s elapsed: count=1 err=<nil>`。原始日志 `/tmp/roost-dataengine-recovery/retry-red.log`。影响的是失败重试频率，不是 WAL/Mongo 投影的原子性；不据此声称消息永久丢失。
