# RR-20261005-NC-72：`roost help cfggen` 让 cfggen 输出到 tablegen 的 `configs/generated`，照做后包重复声明、`roost generate` 失败

日期 2026-10-05。基线 main `50e9a4e853641f348c879b85c282af9c5813f656`。等级 **P3**（文档 / 帮助缺陷，误导使用者）。状态：已复现（正式 CLI 与正式入口回归），未修复。来源：N08 codegen 非核心 review（[本轮](../review/REVIEW-2026-10-05-n08-codegen.md)）。

## 触发

默认 features（`protocol,config,entity,nest,event,dao,errcode`，`codegen/internal/roost/manifest.go:169`）的工程里，用户按 `roost help cfggen` 的 Usage 原样执行：

```
go run github.com/tjbdwanghaibo/roost-core/codegen/cmd/cfggen@latest -meta ./configs/schema/cfg.yaml -out ./configs/generated -pkg generated
```

`codegen/docs/CODEGEN_REFERENCE.zh-CN.md` §8 给的是同一条命令。

## 预期

帮助给出的命令在 roost 生成的工程里可以直接用；`roost next`（`codegen/internal/roost/next_optional.go:68`）给的是 `-out configs/cfg`，两处入口应一致。

## 实际

`configs/generated` 是 tablegen 的输出目录（`roost generate` 的 config-go 步骤，`codegen/internal/roost/generate.go:153-155`），里面已有 `gen_table_config.go`（`package generated`，声明 `RegisterGeneratedConfigData` 与带 `//roost:register phase=config` 的 `RegisterConfigData`）。cfggen 写出的 `cfg_gen.go` 声明同名函数，结果（game-demo 工程实跑）：

```
configs/generated/gen_table_config.go:27:6: RegisterGeneratedConfigData redeclared in this block
	configs/generated/cfg_gen.go:22:6: other declaration of RegisterGeneratedConfigData
configs/generated/gen_table_config.go:58:6: RegisterConfigData redeclared in this block
generator registry: registry: example.com/n08demo/configs/generated.RegisterConfigData is marked twice (…/cfg_gen.go:40 and …/gen_table_config.go:58)
```

正式入口回归 `TestCfggenHelpUsageCoexistsWithTheProjectGenerators`（新增）按帮助里的 `-out` / `-pkg` 在生成工程里跑 `cfggen.Run`，再跑 `Generate`，修前红：

```
cfggen_help_promises_test.go:54: roost generate after following roost help cfggen (-out ./configs/generated): generator registry: registry: example.com/planet/configs/generated.RegisterConfigData is marked twice (…:40 and …:34)
```

## 根因

`codegen/internal/roost/help.go:259`（cfggen 主题的 Usage）与 `codegen/docs/CODEGEN_REFERENCE.zh-CN.md:408-409` 选了 tablegen 已占用的目录和包名；cfggen 与 tablegen 生成的入口函数名相同（两者都对接 `configdata` 的同一套注册约定），同包必然冲突。`roost next`、`codegen/docs/CFGGEN_META.zh-CN.md`、`codegen/README.md` 用的是独立目录（`configs/cfg` / `./cfg`）。

## 影响与定级

编译期立即失败、不会带病上线，定 P3；但帮助是新用户第一次接触 cfggen 的入口，失败信息指向重复声明，不容易想到是目录选错。

## 范围与未做

- 只修正帮助与参考文档的目录 / 包名；不改 cfggen 或 tablegen 的生成形状（让两者在同包共存需要改入口名，属于另一项设计决定）。
- 观察：`codegen/docs/CFGGEN_META.zh-CN.md`、`codegen/README.md`、`CODEGEN_REFERENCE` 多处仍写合仓前的模块路径 `github.com/tjbdwanghaibo/roost-codegen/cmd/...`，取到的是冻结的旧仓；本条没有逐处替换，单列在[本轮记录](../review/REVIEW-2026-10-05-n08-codegen.md)。
