## RR-20260909-05：Enqueue 重放返回其他 Subject 的 Ticket

- 基线：Kit `c4e7cef1029fb6326fa88b84c622f059bc62c0c4`。
- 位置：`service/match/queue_store.go:197–201`；对照 `service/match/store.go:59–67` 和 `queue_store.go:313`。
- 触发：同一 Queue，player:1 使用 requestID 入队；player:2 使用相同 requestID 入队。
- 实际：Requests 只按 requestID 查询，命中后直接返回原 Ticket，不比较 Subject。第二个玩家得到 player:1 的 Ticket/Score，且未建立自己的入队请求。
- 期望：不同归属的键冲突被拒绝，或采用明确的按 Subject 隔离的幂等命名空间；同一玩家正常重试仍复用原票。
- 证据：真实内存 Store 测试先验证同归属重放成功，再验证 Ticket API 对另一玩家返回 ErrNotPermitted，最后 Enqueue 却成功返回另一玩家票据。候选数仍为 1。独立测试确定性失败，原包 race 测试通过。
- 影响：业务若在同队列使用会碰撞的请求键，会串票、错误回包或丢失该次入队意图。这是服务 API 的归属一致性问题；没有证据表明其直接暴露给未认证公网客户端。
- 建议：在返回命中票据之前验证归属，并覆盖同归属重试、异归属冲突、过期票据三类场景。若更改存储键空间，应定义旧数据兼容策略。

## RR-20260909-06：多 Entity 配合显式 -output 静默覆盖生成结果

- 基线：Codegen `aa072edb35a0b97d234e0155142e36295c5f21d1`；消费者连接本轮 Core 源码。
- 位置：`internal/entity/main.go:93–99`。
- 触发：同目录两个有效 Entity，调用 `entity -dir <目录> -output <目录>/entities_gen_wire.go`。
- 实际：循环对每个 Entity 使用同一个输出路径；工具成功退出并两次报告生成同一路径。后者覆盖前者，连同伴随测试文件；本次消费者编译报 `undefined: RegisterEntity`。
- 期望：明确拒绝多实体单文件模式，或将该包内容聚合后一次写出；成功退出应留下完整可编译产物。
- 证据：两个输入分别为有效 remote Guild/Clan（不同类型编号，合法 Category=2）。默认模式生成并执行消费者测试成功；显式输出模式生成退出 0、消费者编译退出 1。
- 影响：使用公开输出选项的多实体消费者无法构建，前一个实体的生成声明丢失。未声称默认模式仍有问题。
- 关联：RR-20260909-04 的默认多实体重名问题已独立验收通过；用户[原修复说明](../bugfix/RR-20260909-04.md)已指出显式输出边界。本条将该边界补为可复现问题，不重新打开原根因。
- 建议：先确定输出契约，再对真实 CLI 产物编译；仅检查每实体符号唯一无法覆盖文件覆盖问题。
