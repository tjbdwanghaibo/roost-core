# RR-20261006-34：`Shutdown` / `RemoveProgram` 遇到同一轮里被待停止上限删掉的记录，空指针 panic

2026-10-07，基线 `443d08f6`（main）。P2（进程崩溃：panic 发生在持有 Runtime 锁的停机 / 移除入口里；只在宿主拒绝 `StopSpawn`、且待停止条目到达 `MaxStopPendingSpawns` 时触发，宿主故障正是停机时最可能出现的情况）。引入：`3fad5b6e`（停止入口统一，2026-10-07，未发版）——之前 `Shutdown` / `RemoveProgram` 停不下时把记录留成 running，不会进入待停止、不会触发上限删除。来源：衍生物分区存放（[方案](../feature/REFACTOR-2026-10-07-skill-spawn-partition.md)）实施中逐个核对“取 ID 列表 → 逐个取回记录”的循环时发现。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261006-34.md)。

## 机制

- `Shutdown`（基线 `skill/spawn_owned.go:542`）与 `RemoveProgram`（`:505`）先收一份 ID 列表（含已在待停止的记录），按 ID 逐个 `runtime.spawns[id]` 取回、请求停止。
- 前一个衍生物被宿主拒绝时，`requestSpawnStop` → `enterStopPendingLocked` 先调 `makeRoomForStopPendingLocked`（`skill/runtime_spawn_stop.go:79`）：待停止条目已到 `MaxStopPendingSpawns` 时删掉最早的一条（先删已到重试上限的，没有就删最早仍在重试的），记 `skill.spawn.stop_pending_dropped.total`、写 Error 日志。
- 被删的可能正是列表里后面那一个。循环走到它时 `runtime.spawns[id]` 是 nil，`Shutdown` 读 `spawn.handedOff`（`:559`）、`RemoveProgram` 读 `spawn.CastID`（`:520`），空指针 panic。`retrySpawnStopsLocked` 的同形循环判了空，这两处没有。

## 触发 / 预期 / 实际

- 触发：`MaxStopPendingSpawns: 1`；两个召唤的 minion 衍生物 1、2 已移交；衍生物 2 的 lifecycle 实体消失、tick 回收被宿主拒绝 → 2 进待停止（占满上限）；宿主继续拒绝，调用 `Shutdown`（或对同一程序 `RemoveProgram`）。
- 预期：衍生物 1 被拒、转入待停止，上限删掉 2（告警），入口返回宿主的错误；之后 Runtime 退避重试停掉 1。
- 实际：循环走到 2，panic。

## 可达性

宿主停不下衍生物（宿主故障、网络分区）且待停止条目累积到上限（默认 256）时，任何一次 `Shutdown` / `RemoveProgram` 只要列表里有比被拒的那个 ID 更大的待停止记录就会触发。其余“取 ID 列表 → 逐个取回”的循环已逐个核对：`retrySpawnStopsLocked`、`advanceOwnedSpawns` 判了空；`stopScopedSpawns`、`handoffEntitySpawns`、`reapUnhandedEntitySpawns`、`reapInvalidOwnedSpawns`、`reapOwnedSpawns` 的列表只含运行中的记录，它们只在自己被处理时才会进待停止，上限删除只删待停止记录，处理到它们之前不会被删；`executeOwnedSummon` 的清理经 `requestSpawnStop`，对 nil 记录直接返回。
