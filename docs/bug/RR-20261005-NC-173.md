# NC-173：etcd Deregister 等注册循环不看 ctx；Assembly.Close 撤销失败仍关闭 client，重试必然失败

2026-10-05，基线 `origin/main` `25bb0d66`。**P3**。来源：[NC-83 修复记录](../bugfix/RR-20261005-NC-83.md#仓内其他同形停机实现只读核对未修)、[REVIEW-2026-10-04-noncore-08 疑点](REVIEW-2026-10-04-noncore-08.md)。状态：已修复（[记录](../bugfix/RR-20261005-NC-173.md)），未发版。

## 是否已被 b67d5945 / NC-93 修掉

没有。`b67d5945` 只把 Revoke 的“lease not found”判为注销已达成，并在循环退出后再取消一次 keepalive；`89a102db`（NC-93）只改选举 `Resign`。两者都没碰 `lifecycleMu`、`waitLoopDone` 与 `Assembly.Close` 的顺序。

## 触发与差异

1. `etcd/driver/discovery.go:195` `Deregister` 持 `lifecycleMu`（普通 Mutex）后调用 `waitLoopDone`（`:354`，裸 `<-done`，且先把 `loopDone` 置 nil）。注册循环在 lease lost 后的重注册里可能卡在不受 loop ctx 约束的步骤：Grant 成功、Put 因取消失败后，`revokeSetupLease` 用自带的 5s 截止撤销 setup lease。etcd 无响应时，Deregister 越过调用方预算最多约 5s。
2. `etcd/driver/assembly.go:72` `Close`：`Deregister(ctx)` 失败（例如 etcd 冻结、撤销耗尽预算）后照样 `Client.Close()`。Discovery 自己保留了登记以便重试，但用新 ctx 重试 `Close` 时 Revoke 跑在已关闭的连接上，必然返回 `grpc: the client connection is closing`，键留到 TTL。

## 正式调用方与触发路径

- kit `EtcdMod.StopWithContext` → `Assembly.Close(ctx)`；App 一次停机不重试。第 2 点的“重试必然失败”只出现在直接调用方；第 1 点在 App 停机里表现为 EtcdMod 越过预算（App 的 `stopModSafely` 按预算返回、放弃那个 goroutine，判定停机不完整，单实例锁不释放）。
- 真实触发：etcd 无响应（冻结 / 网络分区）期间停机；第 1 点还需要停机时注册循环正处于 lease lost 后的重注册。

## 复现

- 包内（`etcd/driver/deregister_budget_promises_test.go`）：`Deregister ignored its context while waiting for the registration loop`；`Close closed the etcd client although the lease was not revoked`、`retry Close = etcd Discovery: revoke: grpc: the client connection is closing`。
- 真实 etcd（`startStoppableEtcd` 私有进程，SIGSTOP 冻结，`-tags integration -run TestRealEtcdAssemblyCloseRetriesTheRevokeAfterAFrozenBudget ./etcd/driver/`，修前实现）：

  ```
  budgeted Close against a frozen etcd: err=etcd Discovery: revoke: context deadline exceeded elapsed=500ms client_open=false
  retry Close after the thaw: err=etcd Discovery: revoke: rpc error: code = Canceled desc = grpc: the client connection is closing
  ```

## 复核后的补修（2026-10-05，A3 停机契约骨架发现）

触发：A3 把 `Assembly.Close` 套进共用停机契约骨架（`internal/stopcontract`），第 4 步“已停完的对象再调用返回 nil”失败：

```
--- FAIL: TestAssemblyCloseStopContract (0.10s)
    stop_contract_test.go:99: stopcontract: Stop after a completed stop = context canceled, want nil
```

根因：`etcd/driver/client.go` `Client.Close` 直接调用 `clientv3.Client.Close`，后者不幂等——第二次关闭已关闭的 gRPC 连接返回 `context.Canceled`。`Assembly.Close` 在注销成功之后每次都关 client，于是完成停机后的第二次 `Close`（例如 `EtcdMod.Stop()` 之后又 `StopWithContext`）报停机失败。影响：只有直接重复调用方会看到一条 `etcd mod: stop failed ... context canceled`；App 每个 Mod 只停一次，不受影响。等级沿用 P3。状态：**已修复（含残余补修），未发版**。[修复记录](../bugfix/RR-20261005-NC-173.md#复核后的补修2026-10-05a3-停机契约骨架发现)
