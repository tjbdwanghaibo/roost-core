# RR-20261007-03：glsvet 漏查方法 handler 的异步执行

- 日期：2026-10-07；等级：P2；来源：框架登记表 F02-3。
- 基线：`85a13d4c`（规范提交 `1d6816d8` 不改变 Go 行为）。
- 状态：已复现、已修复；本地目标回归通过，未发布。

## 触发、预期与实际

带 roost:nest 标记的方法 handler 内启动 goroutine，或把接收者捕获到 worker 闭包。预期报告违规，实际返回零条。两个不同类型的同名方法都含 goroutine 时预期两条，实际零条。

## 根因

`cmd/glsvet/main.go:386`：handler 枚举与 isNestHandler 都排除了带接收者的声明；闭包捕获集合也未计入 receiver。简单把方法放入名字 map 又会产生同名覆盖。
CBM 代际为 2026-09-30，相关文件 metadata_changed；以上按本轮工作树源码核对，不以旧图谱行号为证据。

## 修前证据

命令：`GOWORK=off go test ./cmd/glsvet -run TestMethodHandlerConcurrencyChecks -count=1`。这是修改实现前实际运行的行为失败；首次缓存权限失败不计入红测。

