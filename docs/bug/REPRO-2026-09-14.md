## WAL 调度屏障

复制审查基线 nestwal/wal.go 到临时目录，仅将 writerLoop 的 `w.processBatch(w.collectBatch(first))` 替换为：

```go
batch := w.collectBatch(first)
if reviewBeforeProcess != nil { reviewBeforeProcess() }
w.processBatch(batch)
```

不改其他分支。overlay.json 的 Replace 同时映射原 nestwal/wal.go 到该临时副本，并映射 nestwal/review_close_test.go 到下面测试。屏障只模拟收批后 goroutine 被暂停，不能把它描述为原源码自带测试钩子。测试使用现有 testOptions/testRecord；各子测试顺序运行、关闭 writer 后清理 hook，未使用并行子测试。

运行 `go test -race -count=1 -overlay <wal.json> ./nestwal -run '^TestReviewSync' -v -timeout=60s`。本轮实际分两次执行：DuringClose 两场景，一绿一红；AfterCompletedClose 一绿。下面给出完整可复跑文件，不伪称已单次运行组合。


## 真实 Redis 与两个独立 L1

以下是实际执行文件的必要 helper 与本轮新增测试，移除未运行的历史测试和对应未使用 import，逻辑未改。依赖当前 remoteentity 包已有 indeterminateTransferSetup；独立 cache 实例共享 Redis，并非不同操作系统进程。

本轮临时 Redis 配置为 bind 127.0.0.1 / port 15999 / save 空字符串 / appendonly no / dir 当前临时目录；启动先核对实例日志。设置 ROOST_REVIEW_REDIS=127.0.0.1:15999，用 overlay 将 remoteentity/review_real_test.go 映射至本文件，然后运行 `go test -race -count=1 -overlay <real.json> ./remoteentity -run '^TestReviewReal(CrossCacheDeleteBoundary|ModesRecovery)$' -v -timeout=90s`。

CrossCache 测试断言“B 能重写旧 L2 而 A 自己仍挡住”，PASS 是边界存在证据，不能说全局删除协议通过。Modes 六个子场景分别检查失败时错误、黑屏时拒绝准入、恢复后 live 状态与准入；Redis Lua 真实执行，错误由适配器注入。结束 DBSIZE=0，关闭本次实例 SHUTDOWN NOSAVE。
