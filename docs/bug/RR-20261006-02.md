# RR-20261006-02：默认值为 null 的实体持久状态，`modify_state set` 每次都报类型不匹配

2026-10-06，基线 `8a292a5a`。P2（编译通过的合法定义，第一次写入就失败，施法以 `ErrRuntimeTypeMismatch` 终止）。来源：O33 实施时发现（[表方案 §8.1](../feature/SKILL-EVAL-CONTEXT-TABLE-2026-10-06.md)，当时用 `$caster` 默认值绕开、未登记），收尾第 3 批 A4 登记。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261006-02.md)。

## 语义

entity 状态（以及 snapshot_token 状态、类型为 entity / position / snapshot_token 的 shared 状态）的 null 默认值只表示“还没写过”，状态的类型仍是声明的类型；`set` 写入同类型的值是合法写法，编译器也接受（`stateOperationAllowed` 对任何类型放行 `set`）。

## 机制

- 编译：null 默认值是 `nullValueIR`，类型 `{Base: valueKindNull, Optional: true}`；lower 原样变成 `nullProgramValue{typ: Base=valueKindNull}`（`skill/lower.go` `lowerValue`）。shared 状态的缺省默认值 `defaultStateValueIR` 对 entity / position / snapshot_token 也给 null。
- Runtime：`executeStateMutation` 把 `evalStateDefault` 的结果（`MissingRuntimeValue(Base=valueKindNull)`）原样放进 `StateMutationCommand.Default`（`skill/runtime_state.go`）。
- Host：`MemoryHost.ModifyState` 在状态不存在时 `before = Default`，`applyStateOperation` 的 `set` 分支 `before.typ.Base != operand.typ.Base` → `ErrRuntimeTypeMismatch`（`skill/memory_host_state.go:122-124`）。所以第一次写入必失败，之后也永远写不进去。

## 触发与差异

entity 状态 `{"type":"entity","scope":"owner","default":null,…}`，施法流程 `modify_state set value=$input.target`：预期写入成功、状态里是目标实体；实际 Activate 返回 `skill: runtime value type mismatch`。

## 复现

`TestNullDefaultEntityStateCanBeSet`（`skill/state_null_default_promises_test.go`）修前：

```
--- FAIL: TestNullDefaultEntityStateCanBeSet (0.00s)
    state_null_default_promises_test.go:28: modify_state set on a null-default entity state reported a type mismatch: skill: runtime value type mismatch
```

## 同形分支

- `skill/runtime_ability.go` `applyAbilityNumericOperation` 的 `set`：只处理 int64，操作数先经 `validAbilityMutationValue` 检查类型与量纲，没有“缺省值类型”参与，不受影响。
- `skill/runtime_cast.go` `executeMemory`：`clear` 用声明类型的缺省值；`set` 直接覆盖、不比较前值类型；`add` 先查 present（缺省即 `ErrRuntimeValueMissing`，编译期 memory pass 已保证初始化），不受影响。
- `skill/combatcomponent/adapter.go` `applyResource` 的 `set`：资源是 int64，与 RuntimeValue 类型无关，不受影响。
- 读路径 `ReadState` 返回默认值：缺省值进表达式前就被 `ErrRuntimeValueMissing` 拦下、`exists` 只看 present，类型不同不改变结果；修复后统一为声明类型。

## 修复

[修复记录](../bugfix/RR-20261006-02.md)：Runtime 交给 Host 的状态默认值缺省时换成声明类型的缺省值。
