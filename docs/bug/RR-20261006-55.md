# RR-20261006-55：事件派发出错时 Runtime 卡住；付费之后派发失败，已付费的施法被删、费用不退

2026-10-07，基线 `47abe511`。P2（一个路由配置错误让整个 Runtime 永久停在同一个事件上；B3 ③“扣费之前拒绝”被绕过）。来源：框架文档审查 F08-H+ H1，[08-skill 实现](../framework/impl/08-skill.md) §11.2 H1。
状态：已复现；已修复（`50a0fe88`，[修复](../bugfix/RR-20261006-55.md)；根事件表满仍按原约定原地重试，见修复记录“决策”），未发版。

## 机制

1. `collectHostEvents` / `drainHostEvents` 先 `dispatchEvent` 再推进 `eventCursor`（基线 `skill/scheduler.go:346-352`、`skill/runtime_event.go:3-19`）。`dispatchEvent` 把第一个入队失败的被动候选的错误整个返回（基线 `skill/runtime_dispatch.go:51-58`，只吞 `ErrCastInputInvalid`）。
2. `PassiveRouter` 给出一个 Host 能力表覆盖不了的被动 Program 时，`enqueuePassive` 准入失败：cursor 停在这个事件前，之后每次 `Advance` 在同一事件上报同一错误；排在前面已入队的候选每次重试再入队一次、根事件计数每次加一。
3. 施法付费 `payCostList` 先 `PayCosts` 再 `drainHostEvents`（基线 `skill/runtime_turn.go:23-28`）：付费事件派发失败时 `costsPaid` 未置位，`startLocked` 把未提交的启动删掉、ID 回收，费用已扣、不退；之后每次带 cost 的施法都扣费再失败。
