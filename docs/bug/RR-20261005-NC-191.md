# NC-191：Mongo Mod 启动时把带口令的 `mongo.uri` 原样写进日志

2026-10-05，基线 `f6245613`。**P2**（安全：数据库口令进入日志文件 / 日志采集；不影响数据）。状态：已复现，未修复（修复见文末）。[本轮](../review/REVIEW-2026-10-05-n14.md) · [证据](../review/evidence/noncore-review-20261005-n14/README.md)。

## 触发与差异

`mongo.uri` 带账号口令（`mongodb://user:password@host/...`）。`fmongo.Config`（`mongo/config.go:6-18`）只有 `URI`，没有单独的用户名 / 口令字段，所以这是给 Mongo 配凭据的唯一方式（生产 Secret 示例里的 `mongo.uri` 由运维填）。

- 预期：连接日志可以记录主机、用户名、选项，不记录口令。
- 实际：`kit/mongo/mongo_mod.go:100` `slog.Info("mongo mod: connected", "uri", m.cfg.URI)` 每次 Start 原样记录整条 URI；生成配置 `log.file: true` / `json: true`，口令落进本机日志文件与采集管道。

同类检查：Redis Mod 只记 `addr`（口令是独立的 `redis.password`）；NATS Mod 不记 URL；etcd Mod 记 `endpoints`（不含凭据）。

## 复现

`kit/mongo/uri_log_promises_test.go`（不拨号的替身，Start 只调 Ping），修复前原文见 [nc191-red.txt](../review/evidence/noncore-review-20261005-n14/nc191-red.txt)：

```
uri_log_promises_test.go:63: Start logged the Mongo password: "... msg=\"mongo mod: connected\" uri=\"mongodb://roost:s3cret-pw@db1:27017,db2:27017/?replicaSet=rs0\"\n"
```

## 验收覆盖点

- `mongodb://` 多主机、`mongodb+srv://`、无选项三种 URI 下 Start 日志不含口令，仍含主机与用户名。
- 不带凭据的 URI 日志不变。
- 未覆盖：驱动自身错误信息是否回显 URI（mongo-driver 的 `ApplyURI` 解析错误等）——本轮没查，见运行记录。
