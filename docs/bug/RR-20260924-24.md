# RR-20260924-24：Redis Cluster 已选主，客户端仍访问旧主

日期：2026-09-24；基线 967bc69 加当前 Remote 优化工作树。P1，影响 Redis Cluster 上的 Remote 锁及其他 Redis 命令。已复现并修复，未发布；[修复记录](../bugfix/RR-20260924-24.md)。

## 复现

`ROOST_REMOTE_CLUSTER_IT=1 go test -race -tags=integration ./remoteentity -run '^TestRealRemoteRedisClusterFailover$' -count=1 -timeout=150s -v`。

夹具独立启动 3 主 3 从 Redis Cluster，先确认实际 replica 已收到锁 owner 和 fence，再强杀持有该槽位的主节点。Redis 日志确认 23:40:46 选主成功，但客户端在随后的 20 秒重试窗口仍返回原主 17380 的 connection refused，接管失败。原始证据 `/tmp/remote-cluster-routing-red.log`。

## 根因

当前 go-redis v9.22.0 的写命令路由沿用已缓存 slot master；连接错误路径标记节点失败却没有立即刷新拓扑，而默认周期刷新间隔为 60 秒。框架直接透传命令，因而实际恢复可能超出 Remote 默认 30 秒准入预算。网络错误不意味着 Lua 未执行，不能通过无条件重放写命令来掩盖这个问题。
