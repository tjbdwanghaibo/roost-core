# RR-20260926-13：Remote 事务已提交但释放远端锁失败时，postRemoteCommit 被跳过，相关实体 Sync 永久冻结、业务 AfterCommit 丢失

日期：2026-09-26。基线：main `aaada47`。等级 P2（同步冻结直到实体卸载；需释放失败才触发）。
状态：已复现（复审方二次实跑），未修复。来源：上线前复审（Nest/Sync）。

## 触发条件

Remote 事务 WAL 已提交、`batch.Commit` 成功，但 `batch.Close` 返回错误，例如 Redis 解锁重试耗尽返回 `ErrRemoteReleaseIncomplete`
（`remoteentity/transaction_manager.go:368`）。

## 预期 vs 实际

预期：事务已确定提交，释放失败只作为错误报告（roost-coding：“成功准入后不能因释放/回复失败回滚已接受事务”）；Sync 提交屏障放行，AfterCommit 执行。

实际：`nest/msg.go:89-95` 只在 `err == nil && dispatchErr == nil` 时执行 `runPostRemoteCommit`；而 `batch.Close` 的错误已在 `:88` 被 join 进 `err`。
`syncMutation.Confirm` 与业务 AfterCommit 都挂在这个队列上（`nest/execution.go:148` 注册，`nest/rollback.go:425` 转入 postRemoteCommit），于是该 SyncMutation 永不 Confirm。
之后每个新提交屏障都链到这个未就绪节点（`entity/sync_commit.go:99` 只跳过已就绪的头），`entity/subject_sync.go:462` 一直返回 `ErrSyncCommitPending`。
periodic 与 on_change 相同。该实体（含同事务的本地实体）客户端同步冻结直到卸载；以该提交条件排队的 Interest 位置事实也不生效。屏障链不会无限增长（就绪节点被跳过），无内存泄漏。

## 复现

探针源码见 [REPRO-2026-09-26-02](REPRO-2026-09-26-02.md) §2。复审方 2026-09-26 在 `aaada47` 导出副本上实跑：


## 实施方向（约束）

- “事务已提交”与“释放是否成功”分开判断：已提交即执行 postRemoteCommit（Confirm、AfterCommit），释放失败另行报告并交由既有收尾路径处理。
- 不因释放失败回滚或伪造状态；postRemoteCommit 仍需在快池执行（经 localExecutor），且不得违反快池不阻塞约束。

## 验收覆盖点

- Commit 成功 + Close 失败：请求返回释放错误，但 SyncCommitReady 放行、后续帧交付、AfterCommit 执行一次。
- Commit 失败 / Abort 路径行为不变。
