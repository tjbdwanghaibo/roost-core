# NC-261：robot Session.Call 的发送不受 ctx 约束，写阻塞时 Call 越过自己的超时

2026-10-06，基线 `dc877c04`，分支 `revleft`（N11～N13 留项与小防护）。**P3**。来源：N12 观察 O8 前半。状态：已复现，已修复（见文末）。[本轮](../review/REVIEW-2026-10-06-revleft.md) · [证据](../bugfix/evidence/noncore-bugfix-20261006-revleft/README.md)。

## 触发与差异

`robot/session/session.go` `call`（基线 :125-129）同步调用 `conn.WritePackets`，之后才 `select ctx.Done()`。服务端不读、TCP 发送缓冲满时写一直阻塞，Call 直到会话被关闭才返回；同文件的 `Notify` 已经用 `sendWithContext`（goroutine + select）受 ctx 约束，Call 没有。

- 预期：Call 在调用方 ctx 到期时返回 ctx 错误（剧本节点的 Timeout、runner 的停止都依赖它）。
- 实际：阻塞到会话关闭；剧本超时与 runner 的 Stop 预算都被越过。

触发：被测服务卡住不读 socket（压测时网关过载正是这种形态）。

## 复现

`robot/session/session_promises_test.go `TestCallReturnsWhenTheWriteBlocksPastItsContext`（可控 Conn，写阻塞到放行）`。修前（[原文](../bugfix/evidence/noncore-bugfix-20261006-revleft/nc261-262-red.txt)）：
