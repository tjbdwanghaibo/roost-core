# RR-20261006-57：`versions.codegen` 下限仍是 v1.15.0，生成的 Makefile 跑不存在或过旧的生成器

2026-10-07，基线 `a9c211e9`。P2（钉 v1.15.x 的工程 `make sync / generate / check-generated / doctor / ci` 全部失败；钉 v1.16～v1.22 的用比 core 旧的生成器改写工程）。来源：框架文档审查 F12 G2（[12-codegen 实现](../framework/impl/12-codegen.md) §11 G2）。
状态：已复现；已修复（`410392e0`，[修复](../bugfix/RR-20261006-57.md)），未发版。

## 机制

1. 合仓后生成器是 `roost-core/codegen/cmd/roost`，“codegen 版本”就是 roost-core 版本；v1.15.x 的 roost-core 不含这个包（实测 `go run …/codegen/cmd/roost@v1.15.0` → `does not contain package`）。
2. 清单校验接受 `versions.codegen ≥ v1.15.0`（基线 `codegen/internal/roost/manifest.go:86-90`、`:389`）；Makefile `ROOST := go run $(CODEGEN_MODULE)/cmd/roost@$(CODEGEN_VERSION)`，`CODEGEN_VERSION` 取 `versions.codegen`（基线 `render.go:873-875`、`:1044-1049`）。
3. 一个工程里两个号描述同一个模块：core 钉 v1.23.0、codegen 默认 latest 时生成器又比 core 新。
4. framework-compat 的 minimum lane 写 `-codegen-version v1.15.0`，但只用当场构建的二进制、不跑 make，抓不到。
