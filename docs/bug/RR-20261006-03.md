# RR-20261006-03：checkpoint 恢复仍接受 `phase_timeout` 任务（O20）

2026-10-06，基线 `8a292a5a`。P3（只能由伪造或非本实现产生的 checkpoint 触发；恢复成功后该任务执行时 `ErrProgramInvariant`，施法失败）。来源：N09 第三批 O20（[记录](../review/REVIEW-2026-10-05-n09-batch3.md)），维护者 B3④ 定“保持方向 B”，收尾第 3 批 A5 登记。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261006-03.md)。

## 机制

- phase 计时保持方向 B：`timeout_ticks > 0` 编译期拒绝（NC-151），Runtime 没有任何调度 `phaseTimeoutTask` 的代码（`git log -S` 显示自 V1.9 起只有 checkpoint 编解码与 `scheduledTaskIdentity` 引用它）。
- `skill/runtime_checkpoint.go:1132-1133` `restoreCheckpointTask` 仍把 `kind: "phase_timeout"` 恢复成 `phaseTimeoutTask`，`skill/scheduler.go:42` 的类型也还在；恢复出来的任务在调度时落到不认识的分支。

## 触发与差异

把一个合法 checkpoint 里某个施法任务的 `kind` 改为 `phase_timeout` 并重算 checksum：预期 `ErrCheckpointCorrupt`；实际 `RestoreRuntime` 返回成功。

## 复现

`TestCheckpointRestoreRejectsPhaseTimeoutTask`（`skill/checkpoint_phase_timeout_promises_test.go`）修前：

```
--- FAIL: TestCheckpointRestoreRejectsPhaseTimeoutTask (0.00s)
    checkpoint_phase_timeout_promises_test.go:68: checkpoint with a phase_timeout task restored with err=<nil>; phase timeouts are rejected at compile time, so the task must be refused as corrupt
```

## 修复

[修复记录](../bugfix/RR-20261006-03.md)：恢复时按 corrupt 拒绝，删除 `phaseTimeoutTask` 类型。
