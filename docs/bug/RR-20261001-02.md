# RR-20261001-02：`service/mail` `sameSendIntent` 用 `reflect.DeepEqual`，nil 与空切片判为不同，自定义 EnvelopeStore 下同 RequestID 恢复永久 `ErrConflict`

日期：2026-10-01。基线：main `2308e37f`。来源：[B 线 service 修复独立复审 §3](../review/REVIEW-2026-10-01-bline-audit-service-1.md)（RR-20260929-16 邻接）。等级 **P3**（潜伏）：内置 Redis 存储两边都是 JSON nil 不触发；把 nil `Attachment` 还原成 `[]byte{}` 的自定义 `EnvelopeStore` 下，RR-16 的同 `RequestID` 恢复永远报 `reserved envelope differs or is missing`。状态：已确认，未修复。

## 触发条件、预期与实际

- 触发：自定义 `EnvelopeStore` 把 nil 切片存成空切片；同一 `RequestID` 再次 `Send`（RR-20260929-16 的恢复路径）。
- 预期：内容相同（nil 与空等价）→ 恢复成功。
- 实际：`service/mail/send_intent.go:7` `sameSendIntent` 用 `reflect.DeepEqual`，`nil != []byte{}` → `ErrConflict: reserved envelope differs or is missing`（复审探针已复现）。

## 修复约束

逐字段比较：`[]byte` 用 `bytes.Equal`、切片用 `slices.Equal`、map 按键值；不放宽 ID / 期限 / 正文等的严格拒绝。补 nil / 空两例回归（Memory + 真实 Redis）。
