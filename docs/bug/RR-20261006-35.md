# RR-20261006-35：带索引的 versionstore 写，索引分数是 NaN 时值写进去了、索引没动，调用方拿到错误

2026-10-07，基线 `66d72a33`（main）。P3（只在 `RedisIndex.Entry` 返回 NaN 时触发；仓内两个带索引的 store——platform 订单、activity dispatch——分数都由整数时间换算，现有调用方到不了，属于契约漏洞）。来源：A2 ③ versionstore 写令牌实施中核对“服务端错误回复是否证明脚本没改键”时发现（[方案](../feature/A2-3-VERSIONSTORE-WRITE-TOKEN-2026-10-07.md)）。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261006-35.md)。

## 机制

- `redis.CompareAndSet` 带 `Index` 时发 `compareAndSetIndexedScript`（`redis/cas.go:79`）：比较通过后先 `SET` / `PSETEX` 值，再 `ZADD` 索引。
- 分数按 `strconv.FormatFloat(score, 'f', -1, 64)` 发出，NaN 变成 `"NaN"`。Redis 的 `ZADD` 拒绝 NaN（`ERR value is not a valid float`）——这时脚本里的 `SET` 已经执行，Redis 脚本出错不回滚。
- 结果：值已写入（版本 +1），索引条目没动，`RedisStore.Update` / `Create` 返回服务端错误。破坏 RR-20260919-04 的承诺“索引条目当且仅当 compare-and-set 生效时移动”，调用方看到失败的写其实生效了。
- 替身 `versionstore/fake_redis_test.go` 用 Go 的 `ParseFloat` 解析分数，NaN 被当成合法分数写进索引，所以单测里看不见（lessons“比被测实现更正确的替身会把缺陷藏起来”）。

## 触发 / 预期 / 实际

- 触发：`RedisConfig.Index.Entry` 对某个值返回 `math.NaN()`，对该值调 `Update` / `Create`。
- 预期：写不发生（值、版本、索引都不变），返回可判别的错误。
- 实际：值写入（v2），索引不变，返回 `ERR value is not a valid float`。

## 复现

基线代码，真实 Redis（`scripts/mirror-local.sh` 私有环境的单机 Redis）：

```text
$ GOWORK=off go test -tags integration -count=1 -run NaN -v ./versionstore/
    write_token_integration_test.go:219: a NaN index score: update applied=false err=ERR value is not a valid float script: 2deb7cee6d6074b90e0086b5a2a33539849b83d7, on @user_script:21.; Redis holds [hello nan] / v2 (want nothing written)
--- FAIL: TestRealRedisAnIndexedWriteWithANaNScoreChangesNothing (0.00s)
```

替身改忠实（ZADD 拒绝 NaN 时 SET 已生效）后，单测同样变红：

```text
    index_score_promises_test.go:40: an update whose index score is NaN returned applied=false err=ERR value is not a valid float script: on @user_script and the store holds {Value:{Name:a Total:1} Version:2} (want nothing written, ErrCASInvalidCommand)
--- FAIL: TestAnIndexedWriteWithANaNScoreChangesNothing (0.00s)
```

`redis-cli` 直接验证脚本行为：`EVAL 'redis.call("SET",KEYS[1],"v"); redis.call("ZADD",KEYS[2],ARGV[1],"m")' 2 v z NaN` 报错后 `GET v` 为 `"v"`、`ZCARD z` 为 0；`+Inf` 是合法分数。
