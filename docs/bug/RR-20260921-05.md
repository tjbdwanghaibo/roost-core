# RR-20260921-05：本仓 `go:generate` 产物没有任何 CI 步骤校验；codegen 四个运行期守卫默认 exit 2 且无人调用

日期：2026-09-21 登记（[REVIEW-2026-09-21-02](REVIEW-2026-09-21-02.md) §RR-20260921-05、[REPRO-2026-09-21-02](REPRO-2026-09-21-02.md)，由 CARRYOVER A12 升级）；
2026-10-04 核实仍存在，并发现同根的守卫脚本问题（[REVIEW-2026-10-04-open-triage](../review/REVIEW-2026-10-04-open-triage.md) §2.3 / §2.4）。
基线：v1.19.1 之后的 main `00bffd2a`。等级 **P2**（守卫缺失，非运行期行为缺陷）。
状态：已修复，未发版（见[修复记录](../bugfix/RR-20260921-05.md)）。

本文件是该 RR 的独立主记录；09-21 的原始分析与实测仍以上面两份聚合报告为准，这里只汇总，不改写。

## 一、生成物无人校验（09-21 登记，10-04 核实）

- 触发：本仓 13 处 `//go:generate`（`kit/service/{chat,match,mail,platform,account,global/activity,rank,global,session}`、
  `service/{match,mail,session}`、`codegen/internal/roost/add_rpc.go:141`，后者为 no-op），产物 `*_gen.go` 提交在仓里。
- 预期：生成器或其输入改了而产物没跟上、或有人手改了产物时，CI 红。
- 实际：`.github/workflows/ci.yml` 没有任何一步跑 `go generate` 再比对工作树；`generate --check` 只跑在**生成工程**那棵树上
  （`framework-compat.yml:147`、`demo-publish.yml:55`、`release.yml:114`）；`nightly*.yml`、`scripts/pretag.sh` 也没有。
  10-04 实测：给 `service/session/session_rpc_gen.go` 追加内容后 `go build` + `go vet` 通过，只有 `go generate` 能把它恢复——
  漂移只有 generate + diff 能抓。09-21 已有一次实例（合仓后产物 import 顺序不规范，靠人手动重生成才发现，`c74edcd`）。

## 二、同根：codegen 运行期守卫合仓后默认即失败，且无人调用（10-04 发现）

- `codegen/scripts/{dao-golden-runtime,attribute-runtime,entity-sync-runtime,cfggen-golden-runtime}.sh` 是
  RR-20260917-05 / 06、RR-20260918-01、U-0224 **唯一的运行期证明**（codegen 自身测试只比文本）。
- 四个脚本都从 `codegen/scripts/source-head-check.sh` 里 `sed` 出 `core_pin="${ROOST_CORE_PIN:-vX}"`；
  `6d04aea4`（2026-09-20，发布链收拢成一个模块一个版本）删掉了那一行。不设 `ROOST_CORE_PIN` 时四个脚本全部
  `cannot determine the roost-core pin`、exit 2。
- `attribute-runtime.sh` 的 `core_dir` 缺省 `$here/../roost-core`，是三仓时代的兄弟目录，合仓后不存在，本地 replace 静默不生效。
- 全仓 workflow / 脚本无调用方。设 `ROOST_CORE_PIN=v1.19.1` 后四个都通过——当前功能无回归，缺的是闸。

## 根因

同一个：守卫在仓里，CI 不跑它。没人跑的守卫会坏（脚本取 pin 的来源被删），坏了也没人知道；没人跑的生成也就没人比对。

## 修复约束（10-04 核实给出）

- `ci.yml` 加一步：重新生成全部 `go:generate`，工作树有变化即失败并打印脏文件；根包测试钉住这一步。
- 守卫脚本恢复取 pin 的能力，pin 来自仓内权威来源（不硬编码版本号）；`attribute-runtime.sh` 的 `core_dir` 改为单仓路径；
  某个 workflow 调用这四个脚本；根包测试钉住"每个 `codegen/scripts/*-runtime.sh` 都被某个 workflow 调用"。
- 验收：故意改脏一个 `*_gen.go`，该步骤必须红。
