# NC-152：tick 字段的非负校验只覆盖一部分——cooldown / phase timeout / repeat interval / add_status 时长 / chain hop 间隔的负值能编译，负 wait 被拒却定位到 `$`

2026-10-05，基线 `45d4bc1c`。P3（作者错误在启动期不被发现：负 repeat 间隔每次施法 ErrProgramInvariant、负冷却等于没有冷却、负状态时长每次 Host 报错；诊断位置错误）。状态：已复现，未修复。[本轮](../review/REVIEW-2026-10-05-n09-batch3.md)。

## 触发与差异

`Tick` 是 `int64`（`wire_definition.go:3`），wire 不限制符号。非负规则分散在各处：`compile_shape.go:8-10`（global_cooldown）、`:14-16`（cast window）、`:54-63`（policy）、typecheck 的 `over_ticks`、motion / budget 各自的 duration 检查。缺口：

| 字段 | 编译 | 运行时 |
| --- | --- | --- |
| `cooldown_ticks` | 通过（`Inspect` 显示 -5） | `runtime_cast_window.go:122` 记 `currentTick-5`，冷却立即结束 |
| `phases[].timeout_ticks` | 通过 | 无作用（见 NC-151） |
| repeat `interval_ticks` | 通过 | 第一次迭代效果已提交后 `executor.go:171` 排到过去，`scheduler.go:230` 返回 `ErrProgramInvariant`，cast 失败 |
| add_status `duration_ticks` | 通过 | MemoryHost `memory_host_status.go:39-40`“status duration must be positive”，每次施法失败 |
| chain `hop_interval_ticks` | 通过 | 与 0 相同（一次跳完），无害但非法值被接受 |
| wait `ticks` | **拒绝**，但 `$ BUDGET_EXCEEDED: lifetime_ticks budget 9223372036854775807 exceeds limit 36000` | — |

最后一行：`saturatingTickAdd`（`compile_budget.go:191-196`）把负数当作溢出返回 MaxInt64，诊断落在整体生命期 `$`，没有指向 `wait.ticks`。

## 复现（探针，基线代码）

把 37 个 fixture 里每个 `*_ticks` / `tick(s)` 数值字段逐一改成 -1 再编译：`cooldown_ticks` 37/37、`timeout_ticks` 37/37、status `duration_ticks` 3/3（status_cleanse / status_modifier / status_steal）、chain `hop_interval_ticks` 1/1 编译通过；其余字段被各自的检查拒绝。repeat `interval_ticks: -2`（fixture 里没有）手写探针：

```
activate err=skill: immutable program invariant failed health=99
```

## 影响

游戏服启动期 CompileAll 的 fail-fast 承诺对这些错误不成立，问题推迟到玩家施法时；负冷却静默放开技能频率。

上表每个字段为负时编译失败，诊断路径指向该字段；合法 0 值与既有 fixture 不受影响。
