# NC-122：actionflow 动作启动失败、Cancel 里重入启动别的动作时，新动作成了孤儿

2026-10-05，基线 `197f7bb9`。P3（需要动作在启动失败的 Cancel 回调里重入 ActionList；后果是已 Start 的动作不再被 Tick、也不会被结束 / 取消，失败动作重复发离开切换，排队路径上还重复 OnEnded 并越过孤儿启动下一项；目前无生产使用方）。状态：已复现、已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-122.md) · [本轮](../review/REVIEW-2026-10-05-noncore-n10.md)。

## 触发与差异

`actionflow/action_runner.go:308-309`（基线）启动失败分支：

```go
cancelErr := r.callCancel(entry.Action, now, "start failed")
unit.cur = nil          // 不检查 Cancel 期间 unit.cur 是否已被重入改掉
r.transition(entry, false)
```

同文件 `finish`（`:332`）在调 Cancel 之后会检查 `unit.cur != entry` 并返回 `ErrReentrantMutation`；U-0100 的 `TestActionRunnerReportsReentrantMutationFromEachCallback` 钉住了 Start / Tick / Cancel / transition 四处重入，启动失败后的 Cancel 没覆盖。

触发：动作 Start 返回错误，它的 Cancel 里调 `runner.Start(next)`（嵌套 Start 看到当前位仍是失败动作，先 finish 它再装上 next）。预期：外层识别重入、返回带 `ErrReentrantMutation` 的错误，`next` 留在当前位。实际：外层把 `unit.cur` 清空，`next` 已 Start、发过激活切换，却从当前位上消失；排队路径（Freeze → Enqueue → Recover）还会再发一次 OnEnded，并启动队列里的下一项。
