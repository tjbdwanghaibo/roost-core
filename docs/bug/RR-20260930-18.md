# RR-20260930-18：game-demo 的 `Service.Shutdown` 用 `context.Background()` 关场景，停止重载不受 App 停机时限约束

日期：2026-09-30。基线：main `4784ef82`。来源：[REMAINING-2026-09-28](../review/REMAINING-2026-09-28.md) §3 N31，维护者 2026-09-30 拍板“改用 App 给的停机 ctx”；原始观察是 [audit6 §疑点](../review/REVIEW-2026-09-27-audit6.md)（RR-18 一条，未登记）。
等级 **P3**：demo 模板缺陷，生成的 game-demo 工程受影响；框架本身不受影响。状态：已修复（本地提交，未推送 / 未发版），见 [修复记录](../bugfix/RR-20260930-18.md)。

图谱说明：codebase-memory 图谱 `Users-whb-roost-roost-core` 状态 ready；`demo/**/*.go.tmpl` 有 4 个文件 parse_partial（不含本条涉及的 `service.go.tmpl` / `scene.go.tmpl`），行号与结论以当前源码为准。

## 触发条件 / 预期 / 实际

App 收到 SIGTERM，`app.go:313` 以 `shutdown.total_timeout` 建 `shutdownCtx`，`:330` 用它调用 `svc.Shutdown(shutdownCtx)`。game 服务的 `Shutdown` 最后关场景：`Scene.Close(ctx)` → `stopUnloadResync(ctx)`（停止“卸载后重载”，等待在途重载）与 `manager.Close(ctx)`（replication manager 排空）。

预期：这两步在 App 的停机时限内结束；超时就放弃等待，让 Mod 停机与进程退出照常进行，不越过部署侧宽限期（compose `stop_grace_period` / systemd `TimeoutStopSec` = total_timeout + 5s）。

实际：`demo/internal/service/game/service.go.tmpl:243` `func (s *Service) Shutdown(context.Context) error` 忽略参数，`:293` `s.scene.Close(context.Background())`。一次卡住的 stop / Close 会一直等到部署侧 SIGKILL。正常情况下 worker 在 ctx 取消后返回、Nest 仍在运行，等待有界，所以 audit6 记为疑点而非缺陷；修前就有。

修前红（基线 `4784ef82` 生成的 game-demo，只加测试模板；`GOWORK=off go test -count=1 -run TestShutdownClosesTheSceneUnderTheAppsStopDeadline ./internal/service/game/`）：

```text
--- FAIL: TestShutdownClosesTheSceneUnderTheAppsStopDeadline (0.00s)
    service_shutdown_test.go:42: Scene.Close ran under a context with no deadline; Shutdown must pass the App's stop context on, not context.Background()
FAIL
FAIL	example.com/planet/internal/service/game	0.583s
```

## 根因（基线行号）

`demo/internal/service/game/service.go.tmpl:243`、`:293`：见上。`Init`（`:106`）在 `registry.Register(SceneCapability, scene)` 失败时也 `scene.Close(context.Background())`——这是启动失败的清理，`app.Service.Init(registry)` 没有 ctx 可传，App 在 Init 失败后按 Mod 逆序停机，不受停机预算约束，属于另一类，不在本条范围（记在修复记录的未验证项）。

## 修复约束

1. `Shutdown(ctx)` 把 ctx 传给 `Scene.Close`，不再用 `context.Background()`。
2. 回归按模板测试的既有 harness 写在 `demo/**/*_test.go.tmpl`：用带截止的 ctx 调 `Shutdown`，`Scene.Close` 收到的 ctx 带同一截止（可取消）。
3. 不改 `Scene.Close` / `stopUnloadResync` 的语义（它们已经按 ctx 放弃等待，见 `scene.go.tmpl` `Close` 的注释）。
