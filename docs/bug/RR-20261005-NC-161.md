# NC-161：robot loadtest 阈值把“没有样本”判成通过——一个场景都没完成或耗时直方图被丢弃时，CI 门禁假绿

2026-10-05，基线 `45d4bc1c`。**P2**（门禁假绿：Threshold 是 CI 消费的程序化门禁）。状态：**已复现，未修复**。[本轮](../review/REVIEW-2026-10-05-n12-revn12.md)。

## 触发、预期与实际

- 预期：阈值违反即判失败（`robot/loadtest/manager.go` Threshold 注释：any violation marks the run failed —— the programmatic gate CI consumes）；没有数据就没有可判定的值，不能算通过。
- 实际：`evaluate`（`manager.go:493-520`，基线）
  - `error_rate` = Failure /（Success+Failure），分母为 0 时 `statsSnapshot` 记 0（`:587-592`），0 ≤ Max；
  - 分位数取 `metrics.HistogramQuantile`，序列不存在时返回 0（`metrics/metrics.go:281-293`），0 ≤ Max。
- 两条真实触发：
  1. `-duration` 短于场景耗时：所有机器人在场景中途被取消，Success = Failure = 0，`error_rate` 与 `p95` 都“通过”，运行判 finished。
  2. 长期运行的控制面（`AllowAdminStart`，每次运行带 `run` 标签）累计约 1000～2048 次运行后，`robot.runner.scenario.cost` 触到每指标 2048 条序列上限（`metrics.go:508-533`），新运行的直方图被丢弃，之后每次运行的分位数阈值都按 0 通过。

```text
threshold_no_samples_promises_test.go:35: a run with no completed scenario ended finished/completed
  thresholds=[{error_rate Max:0 Actual:0 Violated:false} {p95 Max:1 Actual:0 Violated:false}]; want failed/threshold
threshold_no_samples_promises_test.go:76: p95 judged on a dropped histogram: state=finished
  thresholds=[{p95 Max:10 Actual:0 Violated:false}]; want violated
```

## 根因

`evaluate` 不区分“值为 0”与“没有值”：样本数既不来自 runner 的完成计数，也不来自直方图的观测数；metrics 也没有暴露直方图的观测数。

## 验收覆盖点

没有完成场景时 `error_rate` 判违反；成功场景为 0 或直方图序列缺失时分位数阈值判违反，结果写明原因；有样本时判定不变（现有用例）。没做：per-run 序列的生命周期（运行结束后删除）——见运行记录观察。
