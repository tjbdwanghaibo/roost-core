# RR-20261006-30：被钉住的终态 cast 多于 CompletedCastLimit 时，checkpoint 恢复判 corrupt

2026-10-06，基线 `90c92caf`（main）。P3（默认 `CompletedCastLimit` 2048 大于 `MaxOwnedProcesses` 128，默认配置下要靠停止失败的进程才会凑够；把上限调小的部署一次 checkpoint 就可能恢复不了）。来源：RR-20261006-21 后续（Runtime 重试停止）实施中，“checkpoint 发生在待停止期间”的用例。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261006-30.md)。

## 机制

- `pruneCompletedCastsLocked`（`skill/runtime_retention.go`）在完成队列超过 `CompletedCastLimit` 时回收第一个可回收的 cast；仍被引用的（排程任务、policy、运行中的进程，RR-20261006-23）跳过。全部被引用时直接返回，队列可以合法地长于上限。
- 恢复（`skill/runtime_checkpoint.go` `restoreCheckpointPayload` 末尾，基线约 `:1041`）却无条件要求 `len(completedCastOrder) <= CompletedCastLimit`，否则 `ErrCheckpointCorrupt`。live Runtime 合法持有的状态写出的 checkpoint 恢复不了。

## 触发 / 预期 / 实际

- 触发：`CompletedCastLimit: 1`，两次施法各召出一个寿命 100 tick 的召唤、施法结束后移交，两个 cast 都被运行中的进程钉住；`Checkpoint` 后 `RestoreRuntime`。
- 预期：恢复成功（与 RR-20261006-23 的承诺一致：被引用的 cast 不回收、checkpoint 可恢复）。
- 实际：`skill: runtime checkpoint is corrupt`。

## 复现

`GOWORK=off go test ./skill -run TestHandedOffProcessesBeyondTheCompletedLimitStillRestore -count=1`（`skill/runtime_process_retention_promises_test.go`，修复实现撤回、只留测试）：

```text
--- FAIL: TestHandedOffProcessesBeyondTheCompletedLimitStillRestore (0.00s)
    runtime_process_retention_promises_test.go:111: restore with two pinned casts and CompletedCastLimit 1: skill: runtime checkpoint is corrupt
FAIL
```

停止失败的进程转为待停止后同样钉住 cast（RR-20261006-21 后续），`TestPinnedCastsBeyondTheCompletedLimitStillRestore`（两个 failed cast、上限 1）在旧检查下同样报 corrupt。

## 可达性

需要被钉住的终态 cast 数超过 `CompletedCastLimit`：移交后仍在运行的 owned 进程（受 `MaxOwnedProcesses` 约束）加上待停止的进程（受 `MaxStopPendingProcesses` 约束）。部署把 `CompletedCastLimit` 调到这两者之和以下时可达。
