# RR-20260926-74：外层可回滚事务的回滚覆盖嵌套独立事务已持久提交的内存值 / tracker 版本

日期：2026-09-27。基线：本地 main `736bdb2`（RR-64～72 合并后，未推送）。来源：第三轮修复后独立审计（[REVIEW-2026-09-27-audit3](../review/REVIEW-2026-09-27-audit3.md)）。等级 **P3（潜在）**：仓内生产调用（`entity/entity_delete.go:92`）只在 memory 外层走到，业务直接调导出 API `RunIsolatedTransaction` 可触发。引入：修前即有。状态：已复现，未修复。

外层 RollbackState / RollbackUndo 事务里，嵌套独立事务改写并持久提交了外层已登记回滚快照的实体；外层随后失败，`nest/rollback.go:819-840`
按外层快照恢复值 / tracker 版本，覆盖了已持久的结果。RollbackState：值与版本都回退；RollbackUndo：值保留、版本回退（RR-65 自己的 undo_strict 回归也有此分叉，只是没断言）。
后果（推断）：下一次写以旧 `ExpectedVersion` 投影撞版本冲突，走跳过 / 卸载 / 重载。复现：[REPRO-2026-09-26-07](REPRO-2026-09-26-07.md) §1。

修复约束（维护者 2026-09-27 批准：拒绝）：嵌套独立事务要写（捕获 / 持久）外层可回滚事务已登记回滚快照的实体时，返回可 `errors.Is` 的新哨兵，
嵌套事务不提交、自身回滚；不改外层快照（不做“改基准”）。memory 外层（仓内删除路径）行为不变。拒绝要发生在嵌套事务写任何持久记录之前。
