# RR-20260925-04：Remote 原子投影后又开启只读 Mongo 事务

2026-09-25，当前工作树；P2，Remote/DataEngine 正式投影链路。

`MongoStore.Project` 先通过 `ApplyRemoteCommitsInTransaction` 把 DAO、快照和 Remote 回执一起落库，提交成功后调用 `Manager.ApplyRemoteCommits` 发布。原来的 `CommitRemoteBatch` 无条件 StartSession/WithTransaction，事务内才发现回执已存在并返回。因此正式每笔 Remote 投影除首次原子事务外，还付出第二次只读事务往返。

实际运行跟踪：`unified-diagnostic-20260925`，1000 实体/1000 worker，500 笔预热+600 笔计时请求。Go trace 记录第二次事务路径 1100 次网络等待累计约 10.847 秒，首次 DataEngine 事务提交路径约 10.191 秒。累计等待跨并发活动，不是端到端百分比。诊断本身有 52 个超时，没有全量验收标记，不能当作通过样本。

影响：增加串行投影服务时间，接近容量上限时积压与请求超时。最初减少 ownership 读取/限制堆栈并未解决这一开销；全量中间样本和失败对照保留。

回归：已提交事务重放时将 `StartSession` 注入错误。禁用事务外快路的负对照稳定失败 `replay must not open another transaction`；最终实现无需新 session 即能返回原回执。摘要不同复用 TxID 仍拒绝。

状态：已修复，相关 race/vet 通过；最终真实矩阵与负载见 [报告](../feature/REMOTE-UNIFIED-2026-09-25.md)。[修复说明](../bugfix/RR-20260925-04.md)。
