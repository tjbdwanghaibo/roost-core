# RR-20260923-02：tick 部分交付后重试，内容基线和帧时钟与客户端分叉

- 日期：2026-09-23；基线：`967bc69`（M-18），Go 1.27.0 / darwin arm64。
- 范围：`sync/entitysync/manager.go`、`session.go`；等级：P1。
- 状态：已修复、定向回归与模块 race 验证通过，未发布。见[修复记录](../bugfix/RR-20260923-02.md)。

## 两个触发

1. 同一 subject 有两个会话。会话 1 的 delta 已准入，会话 2 的 Push 返回 `ErrRetryLater`。Manager abort 内容捕获，但会话 1 的订阅已结算为 live。下一次发出的 delta 仍以 abort 前的内容版本为基线，与会话 1 已应用的版本不符。
2. 满容量会话在同一 tick 删除旧对象、加入新对象，需要发送多帧。第一帧成功，第二帧返回 `ErrRetryLater`。原实现等全部帧成功后才采纳会话副本，因此已经发出的帧时钟和引用变化被忘掉，重试重复使用旧 BaseTick。

预期：每个成功 Push 都是不可撤回的交付事实；重试内容必须有可应用的基线，帧时钟必须延续已交付前缀。
影响：遵守版本链的客户端拒绝后续更新；未严格校验的客户端可能重复应用增量，服务端与客户端状态失去一致解释。

## 复现证据

测试：[partial_retry_promises_test.go](../../sync/entitysync/partial_retry_promises_test.go)。通过明确的 Push 调用次数/会话错误控制失败，不使用 sleep。

```sh

```
