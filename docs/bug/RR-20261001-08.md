# RR-20261001-08：chat 无游标的最新页在普通容量淘汰后也报 `Gap=true`，并每次打 `history.gap.<kind>` 指标

日期：2026-10-01。基线：main `32f69b2d`。来源：[W-2026-10-01-03](WANTED.md)（B 线修复独立复审分流，维护者 2026-10-01 拍板“做”）。等级 **P3**。状态：已确认，未修复。

## 位置、现象与修复约束

- 位置：`kit/service/chat`（RR-20260929-27 的 `Page.Gap` 语义扩大）。
- 现象：复审探针实证——只是正常容量淘汰、没有洞的最新页也 `Gap=true`，指标每次都计；记录与 CHANGELOG 只提“页内 / 尾部洞”。
- 修复约束：只有游标落在已淘汰区间、或页内序号不连续时才 `Gap=true`；无游标最新页不算；指标只在真正的洞上计。回归：写满容量 + 1 条，无游标取最新页 → `Gap=false` 且无指标；带已淘汰游标 → `Gap=true`。

## 修复（2026-10-01）

状态改为**已修复**（Memory + 隔离真实 Redis 验证，已提交，未推送、未发版）。记录：[docs/bugfix/RR-20261001-08.md](../bugfix/RR-20261001-08.md)。

- 根因是 `store.go:616-617` `pageOf` 无 `AfterSeq` 分支里的 `(!page.HasMore && selected[0].Seq > 1)`：容量淘汰永远从 ring 头部丢，溢出过的频道头部序号永远 > 1，于是无游标最新页与 `BeforeSeq` 翻到保留边缘都报 `Gap=true`，`History` 每次照打 `history.gap.<kind>`。
- 修法：删掉这个条件。`Gap` 现在只在三种情形为真——页内序号不连续、游标点名的消息已不在（`AfterSeq+1` 已淘汰，或 `BeforeSeq-1` 已淘汰）、尾部缺失（ring 最后一条 < `LatestSeq`，含 ring 被年龄清理清空）；无游标最新页在普通容量淘汰后 `Gap=false`、不计指标。`AfterSeq` 恰为最后一条已淘汰序号时不算洞（客户端已看过它）。
- 修前红：`latest_page_gap_promises_test.go:64: the latest page after plain capacity eviction reported a gap: {… HasMore:false Gap:true OldestSeq:2 LatestSeq:5}`（Memory 与真实 Redis 同文）；修后 `./kit/service/chat/` race 两后端全绿，RR-20260929-27 的页内 / 尾部洞回归不改、仍绿。
