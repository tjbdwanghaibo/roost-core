# NC-194：Mod 没拿到 saga 定义时，大小写混写的 `saga.steps` 覆盖静默不生效

2026-10-05，基线 `f6245613`。**P3**（按步骤调大的重试次数 / 超时不生效，步骤按默认预算运行；触发需要手写的大小写混写类型名，且定义不经 `kitsaga.NewMod` 传入）。状态：已复现，未修复。[本轮](../review/REVIEW-2026-10-05-n14.md) · [证据](../review/evidence/noncore-review-20261005-n14/README.md)。来源：U-0280 审查观察，本轮核实。

## 触发与差异

- `kitsaga.NewMod()` 不带定义（`codegen/internal/roost/render.go:485-486`：项目没有登记 saga 时就这样生成），业务之后用生成的 `Register(engine)` 或直接 `Engine.Register` 登记 `Definition{Type: "GiftItem", Steps: [{Name: "Debit"}]}`；
- 配置 `saga.steps.GiftItem.Debit.max_attempts: 15`。

viper 把配置键一律转成小写。`StepBudgetsFromConfig`（`kit/saga/step_budgets.go:57-84`）在 `definitions` 为空时直接以小写的 `{giftitem, debit}` 作覆盖键；`Engine.Register` 调 `StepBudgets.Resolve`（`saga/record.go:116-120`），按定义里原样的 `{GiftItem, Debit}` 精确查找，查不到。

- 预期：覆盖生效（15 次），或至少启动时报错。
- 实际：步骤按默认 5 次运行，无告警。函数注释“写错名字的覆盖不会静默失效”只对拿到定义的情况成立；这里名字没写错。

拿到定义时（生成工程的正常路径，`kitsaga.NewMod(kitsaga.CombineDefinitions(...)...)`）`known` 表按小写匹配后还原成定义里的写法，不受影响；生成的 saga 类型名是蛇形小写，也不受影响。

## 复现

`kit/saga/step_override_case_promises_test.go`，修复前原文见 [nc194-red.txt](../review/evidence/noncore-review-20261005-n14/nc194-red.txt)：

```
step_override_case_promises_test.go:29: withDefinitions=false: GiftItem/Debit max_attempts = 5, want the configured 15 (overrides map[{giftitem debit}:{0s 15 0s 0s}])
```

## 验收覆盖点

- 无定义时大小写混写的类型 / 步骤名覆盖生效；有定义时不变；精确匹配优先于不区分大小写的匹配。
- 只差大小写的两个类型（`Gift` 与 `gift`）同时登记时，无法从配置区分——记录写明，不在本条修。
