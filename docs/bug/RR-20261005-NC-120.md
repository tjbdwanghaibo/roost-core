# NC-120：ai Controller 冻结期间丢弃动作 / 任务结束通知，行为树 Recover 后永远停在 Running

2026-10-05，基线 `197f7bb9`。P2（框架自带的 BehaviorStrategy + TaskflowAction 组合永久卡死：叶子等的那条结束通知被丢，Recover 之后树一直 Running、不再决策；仓内与生成工程目前没有 ai 的生产使用方）。状态：已复现、已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-120.md) · [本轮](../review/REVIEW-2026-10-05-noncore-n10.md)。

## 触发与差异

`ai/controller.go:138`（基线）`ready()` = 非 nil、**未冻结**、未切换、有策略；`OnActionEnd`（`:107`）与 `OnMissionEnd`（`:115`）和 `Tick` 共用它，冻结时直接 return。

`BehaviorStrategy`（`ai/behavior_strategy.go`）的说明是“action/mission completions are buffered and handed to the next tick's context”，`TaskflowAction` 发起动作后停在 Running，直到 `TakeActionEnd` 拿到同 ID 的结束。动作在冻结期间照常会结束（业务 `EndAllAction`、被同组新动作替换、取消；actionflow 的冻结组也照常处理 End 并发 OnEnded），这条通知是叶子得知结果的唯一来源。

触发：Tick 发起动作 → `Freeze()`（场景切换 / 断线等）→ 动作结束、`OnActionEnd` 被调用 → `Recover()` → 之后任意多次 Tick。预期：Recover 后第一次 Tick 消费这条结束，树完成并重新决策。实际：通知已丢，叶子永远 Running，`OnResult` 不再触发、不再发起新动作。

## 本条不涉及

切换策略期间（`switching`）丢弃通知不变：那时结束的是旧策略的动作。新策略 `Init` 里发起的动作会被随后的 `EndActions` 一并结束（观察 O-T3，只补注释）。
