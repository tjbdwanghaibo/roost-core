# NC-101：mongo.transaction_timeout 不约束提交，网络在回调之后黑洞时 WithTransaction 一直阻塞到网络恢复

2026-10-05，基线 `be7bcc18`。**P2**（可用性：DataEngine 投影 / Remote 提交 / saga / effect inbox 的事务在网络分区下无界阻塞，超出配置的事务窗口与停机预算）。状态：**已复现（真实 Mongo 8.0.28 副本集 + toxiproxy），未修复**。[本轮](../review/REVIEW-2026-10-05-n04-revn04.md)。

## 触发、预期与实际

- 触发：事务回调已执行完，`commitTransaction` 发出时到主节点的连接黑洞（toxiproxy `timeout` 毒，upstream 吞请求或 downstream 吞回复）。
- 预期：`mongo.Config.TransactionTimeout`（`mongo/config.go:12` “maximum driver retry window per transaction”，生成配置 `transaction_timeout: 30s`）限住整次 `WithTransaction`，到时返回错误。
- 实际：`mongo/driver/session.go:18-34`（基线）把带截止的 ctx 交给驱动便捷 API `mongo.Session.WithTransaction`。驱动 v2.6.0 以 `newBackgroundContext(ctx)` 调 `CommitTransaction`（`mongo/session.go:208-231`），提交重试只看驱动自己的 120s 计时器（客户端未设 CSOT `Timeout`），且只在两次尝试之间检查：调用方的截止时间对提交不起作用。

```text
# transaction_timeout=3s（探针），网络在 40s / 150s 时恢复
stream=upstream   elapsed=40s     err=<nil>                         committed_docs=1
stream=downstream elapsed=30s     err=server selection error: context deadline exceeded ...  committed_docs=1
stream=upstream   elapsed=2m30.1s err=operation timed out: (NoSuchTransaction) ... [TransientTransactionError] committed_docs=0
# 正式回归 transaction_timeout=2s，30s 看门狗恢复网络
upstream:   elapsed=30.2s  committed=1 err=<nil>   → returned after 30.2s (bound 4s); the commit is not bounded
downstream: elapsed=29.79s committed=1 err=server selection error ...
```

阻塞时长等于网络恢复时刻（150s 一例已超过驱动自己的 120s），不是任何配置值。downstream 一例服务端已经提交、调用方 30s 后拿到无标签的 server selection 错误。

## 影响

调用方（`dataengine/engine/mongo_projection.go`、`mongo_load.go`、`remoteentity/mongo_committer.go`、`saga/*`、`nestwal/effect_inbox.go`）都依赖持久身份 / 回执做未知结果的重试，正确性不受影响；问题是时间：投影 worker、Remote 写许可、saga 协调器在分区期间被占住且不受 `transaction_timeout` 约束，停机等待在途事务可能超出部署宽限期。

## 验收覆盖点

提交阶段受 `transaction_timeout` 约束（upstream / downstream 两种黑洞）；回调 TransientTransactionError 重跑、写错误中止的既有真实 Mongo 用例不变；超时返回的错误可识别为结果未知（`UnknownTransactionCommitResult` 标签或 `context.DeadlineExceeded`），服务端可能已提交。没做：分片集群（mongos）、主从切换期间的提交、`transactionLifetimeLimitSeconds` 与短窗口的组合。

## 修复（2026-10-05）

状态更新：**已修复、声明场景验证，未发版**。`mongo/driver` session 自实现与驱动相同的重试规则，提交使用带 `transaction_timeout` 截止的 ctx；红绿与验证见[修复记录](../bugfix/RR-20261005-NC-101.md)。上文“未修复”为登记时点。

## 复审追加（2026-10-05）

独立审查发现修复只限住 `WithTransaction`：提交因截止失败后驱动保留事务状态，调用方 `defer EndSession(ctx)` 会补发无界的 abort，网络黑洞时阻塞到恢复（2s 窗口实测 30s / 25s）。已在同一编号下补修（`EndSession` 的 abort 有 5s 上限），见[修复记录·复审追加](../bugfix/RR-20261005-NC-101.md#复审追加2026-10-05独立审查-81659082)。
