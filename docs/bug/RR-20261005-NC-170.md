# NC-170：manager Engine 停止超时后重试报告成功，同一次调用还在过期 ctx 下继续停它的依赖

2026-10-05，基线 `origin/main` `25bb0d66`。**P3**。来源：[NC-83 修复记录 · 仓内其他同形停机实现](../bugfix/RR-20261005-NC-83.md#仓内其他同形停机实现只读核对未修)（基于 `3d4fe9f3` 的只读扫描），本轮在当前源码上核实。状态：已修复（[记录](../bugfix/RR-20261005-NC-170.md)），未发版。

## 触发与差异

`manager/engine.go:213` `stopStarted`（`kit/manager` `ManagerMod.StopWithContext` → `Engine.Stop` 经此停止）在锁内把 `e.started` 换成空切片，再逐个 `stopOne`。

- 某个实现 `IManagerStopperWithContext` 的 manager 在停机预算内没停完（`StopWithContext` 返回 `context.DeadlineExceeded`）：
  1. 同一次调用继续用已过期的 ctx 停更早启动的 manager——它的依赖。只实现 `Stop()` 的依赖会被真正停掉，而依赖它的 manager 仍在运行。
  2. 再调用一次 `Stop(ctx)`：`started` 已是空列表，直接返回 nil。manager 实际仍在运行。
- 并发的第二个 `Stop` 看到空列表立即返回 nil，而第一个调用还在停。

预期（roost-coding 生命周期“三步停机”）：没停完的 manager 与它的依赖都保留，返回 ctx 错误；用新 ctx 重试从它继续等。

## 正式调用方与触发路径

- App（`app/app.go` `stopModsReverseBefore`）对每个 Mod 只调用一次 `StopWithContext`，返回 ctx 错误时判定停机不完整、中断后续 Mod 并保留它们（`stopIncomplete`），**不会重试**。所以“重试报成功”只在直接调用 `Engine.Stop` / `ManagerMod.StopWithContext` 的代码（测试、工具、自定义停机编排）里出现。
- 第 1 点在 App 的一次停机里就会发生：`stopModSafely` 在预算到期时返回，但 Mod 的 goroutine 继续执行 `stopStarted` 的循环，用过期 ctx 停依赖。真实触发需要某个 manager 的 `StopWithContext` 超过它分到的停机预算（例如等外部 I/O）。
- 影响面是进程退出前的短窗口：依赖被释放后，仍在运行的 manager 可能访问已停的单例，表现为停机期间的错误或 panic。

## 复现

`manager/stop_retry_promises_test.go`（channel 控制 manager 排空，不用 sleep）。修前：

```
dependency stopped 1 time(s) while its dependent was still draining (stopped under usage=true)
retry Stop reported success while manager "dependent" was still running (calls=1)
dependent still running after a successful Stop
concurrent Stop reported success while the first Stop was still draining
```
