# RR-20260926-64：memory（RollbackNone）handler 内新建实体遇锁冲突时不回滚却整条重排，此前业务修改被重复执行

日期：2026-09-27。基线：本地 main `7706419`（RR-48～63 合并后，未推送）。来源：第二轮修复后独立审计。等级 **P2（潜在）**。引入：RR-20260926-48 修复。状态：已复现，未修复。

`entity/entity_guard.go:293` lockCreated 只 try-lock → `nest/rollback.go:719-722` memoryHandlerCreates 返回锁超时 → `nest/execution.go:167` 强制回滚只对非 RollbackNone 生效 → `nest/nest_dispatch.go:95-99` memory 失败不置已准入、照常重排（5ms × 至多 400 次）。
修复方称“与 Cast 既有语义相同”不成立：Cast 违反锁序返回 `ErrCastDeadlockRisk` 不重排（`nest/cast.go:131-155`），满足锁序时阻塞等待。
复现：[REPRO-2026-09-26-06](REPRO-2026-09-26-06.md) §1：修后 `attempts=36 … declared.Value=36 (want 1)`；修前 `attempts=1`（但快 worker 被阻塞，即 RR-48 原问题）。

修复约束（维护者 2026-09-27 批准：返回错误，不重排）：无回滚的 handler 内新建实体遇冲突时，把可 `errors.Is` 的锁冲突错误返回给调用方，消息不自动重执行；锁序允许时仍有序等待；可回滚事务保持 RR-48 的“整条回滚后重排”。
