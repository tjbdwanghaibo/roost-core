## 位置、现象与修复约束

- 位置：`demo/internal/service/game/playerowner.go.tmpl`（`Claim` 的 `errStaleCopyKept` 结局与 `confirmRenewal`），RR-20260930-23 修复之后。
- 现象：`errStaleCopyKept` 后 `snapshot()` 仍含该玩家，下一轮 `Refresh`（CompareAndExpire 自己 token）返回 Held → `confirmRenewal` 清掉 `interrupted` 并延长 `validUntil`，之后 `Admit` 对仍驻留的 stale 副本放行。

## 修复（2026-10-01）

状态：**已修复**（本地提交，未推送、未发版）。记录：[docs/bugfix/RR-20261001-07.md](../bugfix/RR-20261001-07.md)。

- 根因确认（基线模板 `demo/internal/service/game/playerowner.go.tmpl`，main `815ac535`）：`Claim` `:866-876` 扔副本失败只“不确认”，`local[playerID]`（刷新循环 `:504` `interrupt` 留下的、`interrupted=true` 的状态）仍在；`snapshot()` `:979` 把它交给下一轮 `Refresh` `:483`，自己的 token 续成功 → `confirmRenewal` `:654` → `confirmLocked` `:682-684` 延长 `validUntil`、清 `interrupted` → `Admit` `:785` 对仍驻留的 stale 副本放行。
- 修法：`Claim` 在 `dropResident` 失败后调用新的 `abandon(playerID)`——若该玩家的本地状态此刻仍会被 `Admit` 拒绝（没有被并发的另一次成功认领确认过），就把它从 `local` 删掉。此后 `snapshot()` 不含他、`Refresh` 不续、`confirmRenewal` 不会被调用、`Admit` 持续拒绝（无状态），Redis 里的租约按“进程持有着它死掉”的结局自己过期。**恢复点只有一个**：下一次 `Claim`（重连登录或后台消费者的 `Owns`）的 `dropResident` 等到那次清除做完（加入在途的 eviction，或新跑一次发现已无常驻副本）再 `confirmClaim`。
- 回归 `TestAClaimWhoseCopyCannotBeDroppedIsNotRevivedByTheNextRenewal`（`playerowner_test.go.tmpl`）：阻塞 evictor 让 `dropResident` 超时 → 时钟推进一个 `RefreshInterval` 再 `renew` → 断言 `Admit` 仍拒绝、该玩家不在这轮 `Refresh` 的询问名单里、再推进一个 `Lease` 仍拒绝；放开 evictor 后下一次 `Claim` 回到服务。修前在基线模板生成的工程上红：`playerowner_test.go:803: the next renewal put the player back in service while the stale copy is still resident: <nil>`。
