# RR-20260926-54：实体共享加载使用领头调用方的 ctx，RR-36 登录预算（2s）会截断同一 flight 内预算更长的等待方

日期：2026-09-26。基线：本地 main `2330d57`（RR-30、33～47 修复合并后，未推送）。来源：修复合并后独立审计。等级 P3（基线即有的领头方语义，RR-36 放大）。状态：源码判定，未修复。
（最终状态见文末修复节：**已修复，随 v1.17.1 发布**，详见[修复记录](../bugfix/RR-20260926-54.md)。上面的“状态”是登记时的原值，保留不改。——2026-09-27 回写，OPEN-ITEMS A13②）

`entity/manager_access.go:195` 共享加载用领头者 ctx；EnterGame 以 2s 登录预算领头时，同 flight 中预算更长的等待方（如同一玩家的 Nest 慢阶段准备）在 2s 时得到 DeadlineExceeded。

修复约束：共享加载使用与调用方解耦的 ctx（`context.WithoutCancel` 派生 + 框架加载超时 / 停机取消），每个等待方按自己的 ctx 离开；最后一个等待方离开不取消在途加载（加载结果进入缓存 / 注册）。

## 修复（2026-09-26）

状态：已修复（基线 `3e26f91`，RR-51 提交之后），已本地提交，未推送/发布。按修复约束实现：`ManagerAccess.loadEntityShared` 在独立 goroutine 上以
`context.WithoutCancel(领头方 ctx)` 派生的 ctx 加载，只受 `entity.DefaultEntityLoadTimeout`（30s，`ConfigureLoadTimeout` 可改）与 loader 注销（DataEngine 停机，
Cause `ErrEntityLoaderStopped`）约束；每个等待方按自己的 ctx 离开，最后一个离开也不取消加载，结果照常进入 EntityManager。领头方离开后发布改走 Nest 绑定给
ManagerAccess 的 `NestMgr.RunLocal`（不再用已结束消息的快续行）。回归：领头方短预算截止、同 flight 长预算等待方拿到结果（entity 与真实 Nest 各一条），停机取消，
框架上限；修前红、修后 `-race -count=20` 绿；RR-36 生成工程回归的“第二次登录是新加载”断言随新语义改为加入在途加载。见[修复记录](../bugfix/RR-20260926-54.md)。
