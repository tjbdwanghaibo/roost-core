# RR-20260927-13：卸载后重载与共享加载超时的可调参数没有接到 kit 配置

日期：2026-09-27。基线：`d4234c9`。来源：[OPEN-ITEMS-2026-09-27](../review/OPEN-ITEMS-2026-09-27.md) C13（[bf-59](../bugfix/RR-20260926-59.md) “未验证项与边界”、
[bf-54](../bugfix/RR-20260926-54.md) “兼容性 / 默认值变化”）。等级 P4（缺省值可用；部署无法按规模调整）。状态：已复现，已修复。
codebase-memory 图谱停在 09-26，已过期；以源码为准。

## 现象与根因

- `kit/nest/nest_mod.go:175`：Nest Mod 启动时 `ConfigureUnloadResync(m.entitySync, entity.UnloadResyncConfig{})`，固定零值（Workers 4 / Attempts 5 / QueueCapacity 4096 的框架默认）。
- `entity/manager_access.go:76` `ConfigureLoadTimeout`（共享冷加载的框架上限，缺省 `DefaultEntityLoadTimeout` 30s，`:40`）没有任何生产调用方。
- 生成配置（`codegen/internal/roost/catalog.go` 的 `nest:` 段）与 USER_GUIDE 都没有对应键。

## 修复约束（清单 §H 推荐，维护者 2026-09-27 决定按推荐执行）

kit 暴露 `UnloadResyncConfig`（Workers / Attempts / 队列）与共享加载超时的配置键，缺省值不变。

## 修复（2026-09-27）

状态：**已修复，未发布**（worktree 分支 `fix-r7-ent` 本地提交）。新键 `nest.unload_resync.{workers,attempts,queue_capacity}` 与 `nest.entity_load_timeout`；
缺省 / 0 行为不变，负值在 Init 拒绝；生成配置写出与默认相同的值。详见[修复记录](../bugfix/RR-20260927-13.md)。
