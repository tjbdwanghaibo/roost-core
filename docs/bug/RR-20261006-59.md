# RR-20261006-59：生成的 RPC 客户端 affinity 不生效，带 affinity 的方法随机分发

2026-10-07，基线 `a9c211e9`。P1（match 7 个、activity 11 个带 `affinity` 的方法实际随机路由：同一队列 / 活动的操作落到不同副本，进程内锁形同虚设，退回跨副本竞争）。来源：框架文档审查 F09-R1（[09-kit-services 实现](../framework/impl/09-kit-services.md) §11.1，探针 `Call=4 CallTo=0`）。
状态：已复现；已修复（`8dd984eb`，[修复](../bugfix/RR-20261006-59.md)），未发版。

## 机制

1. 生成的 `BusClient.call` 固定 `c.rpc.CallChecked(ctx, 0, …)`（基线 `codegen/internal/servicerpc/template.go:205`）；sid=0 走 `bus.Call` 队列组，随机一个实例接（`servicerpc/client.go:145`），从不调用 picker。
2. 生成的 `NewBusClient` 用 `servicerpc.NewBusClient`，不带 discovery；`PickServer` / `CallDiscoveredChecked` 在非测试代码里零调用。方法上的 `WithAffinityKey` 与构造里的 `WithKeyAffinity` 都在，但没人读。
3. 守卫 `TestAnAffinityMarkerReachesTheGeneratedClient` 只比对生成文本里有这两行，看不到调用路径。
