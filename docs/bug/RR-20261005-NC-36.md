# RR-20261005-NC-36：权威读只验原始结果的最低版本

2026-10-05，P2；发现基线 `40d89ac68b8a2247173e94ef55c02fdf23da1d6f`。

## 承诺、反例与根因

[LoadAuthoritative](../../entity/remote_snapshot.go) 的成功结果必须达到 minVersion。原实现只检查 loader 的结果，没有检查 Publish 后实际保留的 L1；Publish 按 epoch 拒绝旧结果时，会将 ErrStaleWrite 作为正常“不覆盖”处理。

公开 Get 两种强读取模式：缓存合法 epoch2/version2，权威返回相同键 epoch1/version4，最低版本4。旧实现正确保留 epoch2，却将其 version2 当作满足最低版本的成功结果。`minimum version violated after admission: found=true version=2 err=<nil>`。正式 SnapshotReplicaStore 遇 gap 后的权威回填，同样将该状态错误返回成功。[读取红测](../bugfix/evidence/noncore-bugfix-20261005-14/red.txt)、[消费红测](../bugfix/evidence/noncore-bugfix-20261005-14/consumer-red.txt)。

不声称正常业务会重置持久版本；这是 API 返回的最低版本后置条件，与缓存既有 epoch 准入规则组合后仍须成立。不能通过放宽 epoch 防护来满足它。

## 状态追加

已修复、声明场景已验证，未发版。最终 L1 达不到最低版本返回 ErrRemoteSnapshotStale，不覆盖较新 epoch；随后同 epoch 合法 version4/消费者 version9 能恢复。[修复与兼容](../bugfix/RR-20261005-NC-36.md)。
