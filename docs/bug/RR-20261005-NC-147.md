# NC-147：handler 内重入 Tick 提前结束外层 Tick 的推迟语义

2026-10-05，基线 `23f82dbccfd5171373470ab942f33177ed4f4eed`。P3（潜伏：仓内没有在 handler 里再调 Tick 的调用方）。状态：已复现、已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-147.md)。[本轮](../review/REVIEW-2026-10-05-n11.md)。

## 触发与差异

`timer/scheduler.go:178-184`：Tick 无条件 `s.running = true`，结束时无条件 `s.running = false` 并执行全部推迟操作。handler 里再调 Tick 时，内层结束就把外层的 running 清掉、提前执行了外层登记的推迟操作；回到外层 handler，“取消正在触发的自己”不再被推迟，查不到节点返回 false，外层随后按返回值把它重新排上。

## 复现

`TestReentrantTickKeepsTheOuterTickSemantics`：

```
scheduler_promises_test.go:192: cancelling the firing timer after a re-entrant tick returned false
```

## 约束

内层 Tick 照常触发到期节点，但只有最外层 Tick 负责清 running 与执行推迟操作。
