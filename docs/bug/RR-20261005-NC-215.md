# NC-215：两个参考 Host 与 Runtime 都拒绝的取值能编译——attribute_modifier 的 operation / 时长、add_status 时长 0、resource operation、负的 cost 字面量、attribute_compare 的 op

2026-10-05，基线 `c10cc9ac`。P3（编译通过、施法每次失败或 filter 静默全不匹配；不损坏状态）。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-215.md)。[本轮](../review/REVIEW-2026-10-05-n09-batch4.md)。

## 触发与差异

| 取值 | 编译期 | 执行侧 |
| --- | --- | --- |
| attribute_modifier `operation` 不是 `add` / `mul_bp` | 不查；catalog 的 `AttributeCatalogEntry.ModifierOperations` 没有读取方 | MemoryHost `memory_host_status.go:185-187`、combatcomponent `status_bridge.go:460-462` 都返回 `unsupported modifier operation` |
| attribute_modifier `duration_ticks <= 0` | 不查（NC-152 只覆盖了 add_status 等字段的负值） | 两个 Host 都返回 `modifier duration must be positive` |
| add_status `duration_ticks` 为 0 | NC-152 只拒绝负值 | MemoryHost `memory_host_status.go:38-40`、combatcomponent `status_bridge.go:342-344` 都要求正数 |
| resource `operation` 不在 set / add / spend / sub | 不查 | MemoryHost `memory_host_effect.go:99-110`、combatcomponent `adapter.go:133-145` 都返回 `unsupported resource operation` |
| cost / sustain cost 字面量为负 | 类型检查只要求 resource 数量类型 | Runtime 自己在 `runtime_turn.go:17-19` 返回 `ErrRuntimeTypeMismatch` |
| attribute_compare `op` 不是 eq / ne / lt / lte / gt / gte | 不查（status 比较 filter 有 `validCompareOperation`） | MemoryHost `compareInt` 默认分支返回 false，filter 静默全部不匹配 |

shield 的 `duration_ticks` 两个 Host 不一致（MemoryHost 要求正数，combatcomponent 忽略），不在本条范围。

## 复现

正式回归（修前）`TestCompileRejectsValuesEveryHostRejects` 七个子用例全部 `compiled; diagnostics=[]`；探针在 MemoryHost 上施法分别得到 `unsupported modifier operation "set"`、`modifier duration must be positive`、`status duration must be positive`、`unsupported resource operation "mul_bp"`、`runtime value type mismatch`，attribute_compare 的 `op:"zz"` 施法成功但没有选中任何目标。

## 验收覆盖点

上表每种取值编译期以 `SHAPE_INVALID` 定位到字段；合法取值（`mul_bp` 修饰、正时长、`spend`、零 cost、`gte` 比较）照常编译并施法成功（控制）。
