# RR-20260928-12：回滚时正在运行的新版本进程按旧 release unit 的 TimeoutStopSec 被停（推断）

日期：2026-09-28。基线：本地 main `d66eeeb`。来源：第八轮独立审计（[REVIEW-2026-09-28-audit8](../review/REVIEW-2026-09-28-audit8.md)）。等级 **P4（推断）**：打破 RR-66 的停机预算契约，停机中的在途请求可能失败（WAL 能承受崩溃）。引入：RR-20260928-10。状态：已确认（建模），未在真 systemd 上验证，未修复。

`codegen/internal/roost/render_deploy.go` 生成的 rollback.sh 在 `systemctl restart` 之前 `use_unit "$TARGET"`（装入目标 unit 并 `daemon-reload`），install.sh 失败路径 `use_unit "$PREVIOUS" || true` 同样在 restart 之前；
按 systemd 语义 reload 之后的 stop 使用新装载 unit 的 TimeoutStopSec，于是正在运行的新版本进程按旧 release 较短的预算被停，超时 SIGKILL。审计探针（systemctl 替身记录 restart 前被停进程目录与已装载 unit 的 TimeoutStopSec）：
`stop running=$APP_ROOT/releases/v2 TimeoutStopSec=7`（rollback.sh v1 时 v2 进程按 v1 unit 的 7s 被停）。另：rollback.sh 切换 `current` 后 `use_unit` 没有 `|| true`，set -e 下 install / daemon-reload 失败会留下 `current` 已切换、进程未重启。

修复约束：改为 `systemctl stop`（按当前 unit）→ `use_unit` → `systemctl start`，停机窗口不变；`use_unit` 失败时恢复 `current` 与 unit 并报错；install.sh 失败路径同样处理；沿用 RR-10 的临时根演练加回归（替身记录停机时的 unit）；RR-10 回归不回退。
