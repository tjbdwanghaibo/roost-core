# NC-61：game-demo 属性层不随事务回滚，失败后的下一次提交持久化虚高属性

2026-10-05，基线 `50e9a4e853641f348c879b85c282af9c5813f656`。P2（玩家属性数据被污染并持久化；只在升级 / 换装事务失败或提交被拒绝时触发，属于生成的 game-demo 模板业务层，不是框架核心，定级不是因为后果轻）。状态：已复现、已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-61.md) · [本轮](../review/REVIEW-2026-10-05-noncore-n07.md)。

## 触发与差异

`demo/game/entities/player/profile_component.go.tmpl:112-116` 的注释承诺：LevelUp “raises the base layer, recomposes Final over it and writes both back — all inside this transaction, so a rollback takes the attributes with the level”。`equip_item.go.tmpl` 同样承诺 “a rollback takes the numbers back with the equipment”。

实际：属性层是 `AttributeComponent.container` 里的组件内存（`attribute_component.go.tmpl:99-110`、`:116-141`、`:168`），不是 DAO 字段，也没有登记任何 Nest 回滚参与（`nest.RecordUndo` / `RollbackParticipant`）。`rollback=undo` 只撤回生成 DAO setter 记录的逆操作：等级、经验、`attr_base` / `attr_final` 回到旧值，容器里的 Base 已 `LevelUp`、Final 已重组，保持升级后的数值。

触发：AddExp 升级后 `effects.EmitPlayerLevelUp` 失败（`:117`），handler 后续步骤失败，或 handler 成功但提交 / WAL 准入被拒绝；可回滚事务的暂时性失败重排（`TestRollbackHandlerTransientFailureStillRequeues`）会重跑 handler，在已升级的容器上再升一次。换装 `RefreshGear` 同理。

## 复现

生成 game-demo（`roost project new ... -template game-demo`，replace 到基线源码）后跑新增 `TestAttributeLayersRollBackWithTheTransaction`（handler 返回错误、committer 拒绝两种）：

```
attribute_component_test.go:238: rolled back to level 0 but the base layer kept the level-up: HP 110 attack 12, want HP 100 attack 10
```

去掉前两条断言后看持久后果：回滚后再成功升一级，

```
attribute_component_test.go:242: rolled back but the final layer kept the level-up: HP 110 power 35, want HP 100 power 30
attribute_component_test.go:261: level 1 stored base HP 120, want 110
```

即 1 级玩家的 `attr_base` 被持久化成 2 级的数值，此后每次失败都叠加一层。原文见[证据](../bugfix/evidence/noncore-bugfix-20261005-n07/README.md)。

## 本轮没做

没有在真实 WAL / Mongo 的三进程链路上跑（单测用 `nest.RunIsolatedTransaction` 的 undo + strict 路径，committer 拒绝模拟准入失败）；没有审嵌套 `RunIsolatedTransaction` 内改属性、外层再回滚的组合（RR-20260926-74 已拒绝内层写外层快照实体）。
