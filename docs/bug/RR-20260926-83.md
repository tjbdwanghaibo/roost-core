# RR-20260926-83：entity 包测试不能重复运行（-count>1 时 9 个用例失败）

日期：2026-09-27。基线：本地 main `0c4bead`。来源：RR-81/82 修复方范围外发现，主会话复现。等级 **P4**（测试卫生，同 RR-82）。状态：已复现，未修复。
（最终状态见文末修复节：**已修复，随 v1.17.1 发布**，详见[修复记录](../bugfix/RR-20260926-83.md)。上面的“状态”是登记时的原值，保留不改。——2026-09-27 回写，OPEN-ITEMS A13②）

`GOWORK=off go test -count=2 ./entity` 第二轮失败 9 个用例：`TestNewEntity_Create`、`TestEntityManagerCreateUsesInstanceDependencies`、`TestEntityManagerCreateInScopeLocksBeforePublication`、
`TestBuildEntity_LifetimePolicy`、`TestNewEntity_Load`、`TestDestroyEntity`、`TestEntityGuardsRefuseNoneKindMissingFactoriesAndLateGeneratorChanges`、`TestBuiltEntityPolicyUsesKindPolicy`、`TestBuilderDefaultLifetimeFollowsKindPolicy`。示例：

```text
--- FAIL: TestNewEntity_Create (0.00s)
    entity_factory_test.go:99: NewEntity: entity id: invalid: kind 3 category is not registered
```

第一轮用例对全局 kind / category / builder 注册表的写入（或清理）改变了第二轮的前提。影响：entity 包只能跑定向用例的 `-count>1`，整包抖动检测不可用。

修复约束：只改测试（同 RR-82）——各用例使用互不冲突的 kind，或在同一处统一登记夹具、`t.Cleanup` 恢复；不改生产注册语义、不新增导出 API；`GOWORK=off go test -race -count=3 ./entity` 稳定通过。

## 修复（2026-09-27）

状态：**已修复，未发布**（本地提交，未推送）。

机制：根因是两处“收尾清空全局表”——`remote_view_test.go:9` 的 `t.Cleanup(ResetEntityRegistryForTest)` 清空整张 kind 注册表，
category 用例的 `t.Cleanup(resetEntityCategoriesForTest)` 把所有 kind 的锁档清零；init() 与 `sync.Once` 只在第一轮注册，第二轮前提就没了。
改为包内统一夹具 `isolateEntityRegistry(t)`（测试文件内、未导出）：进入时记下每个 kind 的记录指针、锁档与 category 集合，`t.Cleanup` 原样放回，
只撤销本用例自己的登记。去掉整表清空后暴露的被掩盖问题一并处理：两个假定 kind 从未注册的用例（201；152～154，第二轮 builder 重复注册 panic）
改用该夹具；kind 231 两个用例撞号（换 239）；“未链接 kind”取了已被注册的 200（换 250）；delta schema 44001 重复注册（用例收尾撤销）。生产注册语义与导出 API 未变。

修前红（基线 `9009268`，`GOWORK=off go test -count=2 ./entity`）：第二轮 9 个用例失败，如 `entity_factory_test.go:99: NewEntity: entity id: invalid: kind 3 category is not registered`、
`kind_policy_builder_promises_test.go:41: entity id: invalid: kind 211 category is not registered`，`TestBuilderDefaultLifetimeFollowsKindPolicy` 在 `:66` 空指针 panic，整包中止。
