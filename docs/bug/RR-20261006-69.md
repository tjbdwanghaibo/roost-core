# RR-20261006-69：Remote 提交的发布失败让 owner 的 WAL 投影队头阻塞，其后普通 DAO 一起停住

2026-10-07，基线 `c78d0c34`（main）。P1（同步总线不可用期间，owner 进程全部 WAL 投影停住，strict 写等待超时成结果未知）。来源：F05-2（推断），[impl/05 §10.2 第 2 条](../framework/impl/05-remote-mirror.md)。
状态：已复现（推断成立）；已修复（`a9bb8923`，[修复](../bugfix/RR-20261006-69.md)），未发版。

## 机制

1. `MongoStore.ProjectFenced` 在一个 Mongo 事务里写普通 DAO 与 Remote 提交（Remote 落成 outbox `Applied`），事务提交后调 `remoteApplier.ApplyRemoteCommits` 发布（`dataengine/engine/mongo_projection.go` 基线 :156-159）。
2. 发布（`afterRemoteCommit`：缓存 / 同步总线；`MarkRemoteCommitPublished`）失败时 `ApplyRemoteCommits` 返回 `ErrRemotePersistenceIndeterminate`（`remoteentity/transaction_manager.go` 基线 :661-669）。
3. 它不在投影器的 fatal 列表里（`dataengine/engine/projector.go` :393-400），投影器退避重试同一条记录；WAL 按序确认，其后所有记录（含普通 DAO）都等。此时 Mongo 已是 Applied，发布本可单独补。RR-20260926-11 的修复记录写了“真正的发布失败保持可重试且最终发布”，没评估队头阻塞。
