# NC-243：actionflow 替换动作时旧动作 Cancel panic，新动作不启动也不结束（N10 O-A4）

2026-10-06，基线 `81d7cb16`，分支 `revn10b`（N10 第二批）。P2（ai / actionflow 仓内无生产使用方；hotcode 由 Nest 全局 handler 与 game-demo 使用）。状态：已复现、已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-243.md) · [本轮](../review/REVIEW-2026-10-06-noncore-n10b.md)。

## 触发与差异

`actionflow/action_runner.go:494-509`（基线）`applyStart` 替换当前动作时 `finish(..., cancel=true)` 返回错误（旧动作 Cancel panic）就整体返回。此时 finish 已清当前位、发了旧动作的 OnEnded。

预期：B7 承诺“拿到 ID 的动作一定有结论”；Start 的错误应表示请求的动作没有在运行。

实际：回调里发起的 Start 已把 ID 和 nil 交给调用方，执行时新动作既不启动也没有 OnEnded，按 ID 等结束的 `ai.TaskflowAction` / `PlanMission` 永远等不到；直接调用返回 (0, err)，组空着，排队项也没有推进（finish 用的是 startNext=false）。

## 复现

`actionflow/update_and_replace_promises_test.go`（修前，[原文](../bugfix/evidence/noncore-bugfix-20261006-n10b/red-actionflow.txt)）：

```
deferred_start: update_and_replace_promises_test.go:87: the action whose ID was handed out never started: starts=0 ended=0 (B7: an ID always reaches a conclusion)
direct_start: update_and_replace_promises_test.go:103: Start replacing an action whose Cancel panics = (0, taskflow: action cancel panic: cancel exploded), want an ID and nil
```
