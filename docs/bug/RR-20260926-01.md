# RR-20260926-01：Sync policy 失败丢失 LastError

日期：2026-09-26。基线：main `8ce21a5`。等级 P2。
状态：已复现并修复，见[修复记录](../bugfix/RR-20260926-01.md)。
（最终状态：**已修复，随 v1.17.0 发布**，详见[修复记录](../bugfix/RR-20260926-01.md)。上面的“状态”是登记时的原值，保留不改。——2026-09-27 回写，OPEN-ITEMS A13②）

注册的 policy 返回错误后，Flush 返回该错误并增加 FlushFailures，但 LastError 仍是 nil
或上一条错误。运行循环的使用者只能看到计数增加，无法通过 Manager 查询本次失败原因。
预期每次已经执行的失败 Flush 都应留下原因，且一次 Flush 只计一次失败。

根因是 `sync/entitysync/flush.go` 的 applyPolicies 提前返回路径单独记账，未调用
setLastError；其他路径各自维护计数，容易遗漏。与传输故障、内容捕获失败不是同一个根因。

最小复现：

```sh
GOCACHE=/tmp/roost-nest-go-cache GOWORK=off go test ./sync/entitysync \
  -run TestPolicyFailureRetainsCauseAndCountsOnce -count=1
```

修前输出 `lost policy failure: count=1 last=<nil>`；证据保存在本机
`artifacts/perf/sync/fairness-validation/policy-before.txt`。工具链 Go 1.27.0 / Darwin arm64。

历史性能样本曾记录 FlushFailures=1，但缺少错误原因。此次原 main 上 4 次同参数恢复复跑
均为 0，不能把历史错误认定为 policy 故障或停机取消。此记录只证明并修复原因留存缺陷。
