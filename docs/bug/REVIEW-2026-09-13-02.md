## RR-20260913-05 / P2：L2 版本冲突被当成可降级故障吞掉

位置：[entity/remote_snapshot.go](../../entity/remote_snapshot.go):186–195 固定 `IgnoreRemoteError: true`；[cache/read_through.go](../../cache/read_through.go):182–195 对 remote.Set 的所有错误统一降级，再写 L1。

触发：L2 已保存同 key/epoch/version 的 payload A；一个 L1 为空的进程 Publish payload B。L2 的 Set 正确返回 `ErrRemoteVersionConflict`，但通过 RemoteSnapshotCache 调用时错误被吞掉，Publish 返回 nil，L1=B、L2=A。直接 L2 冲突拒绝作为前置对照已通过。

影响：同一快照版本在不同进程返回不同内容，且发布方收到成功。即使上游冲突属于异常输入，缓存已经有明确冲突契约，不能将其变成正常降级。此处不证明数据库写入冲突或未授权发布。

建议：区分可容忍的网络/可用性错误和不可吞掉的一致性错误。保留网络故障下 L1 可用的能力，同时向上返回语义冲突并禁止该值进入 L1。不要全局简单关闭 IgnoreRemoteError 而破坏既有降级策略。

## RR-20260913-06 / P2：L2 回填绕过同版本内容冲突检查

位置：[cache/read_through.go](../../cache/read_through.go):146–148 的 L2 命中直接 `setLocal(value)`；[entity/remote_snapshot.go](../../entity/remote_snapshot.go):173–179 的 Stale 只比较 epoch/version，不比较相同版本内容；Publish 的专用冲突检查在 :315–320，但回填不经过它。

确定性交错：L1 为空，读操作在 L2 捕获 payload A 后暂停；另一路 Publish 同版本 payload B 成功写入 L1；释放之前的 L2 响应。实际回填将 L1 改回 A，没有任何错误。测试在 Get 返回前后用 channel 屏障控制，非概率竞态。L2 替身返回的是读开始时已捕获的值，允许 Set 与这次读响应交错；没有用替身替换 L1 或 Publish。

期望：回填与发布遵循相同的“同版本内容不变”规则，冲突拒绝或转入明确恢复；不允许绕过检查直接覆盖已发布快照。影响是并发读取与推送路径对同一版本形成不同语义，和 RR-05 的吞错路径不同。

建议：所有 L1 入站路径共用原子的版本/内容校验，包括 L2 回填与 delta/full Publish；不要只在 Publish 外层加锁后认为所有写入都串行。回填的 Set 错误不能无条件忽略；若旧版本已被新值替代，明确选择重新读取赢家或返回契约错误。

## RR-20260913-07 / P2：L2 同版本校验遗漏 schema/codec

位置：[remoteentity/snapshot_l2.go](../../remoteentity/snapshot_l2.go):15–30。CAS 比较 marker/route/version/checksum，没有比较 schema/codec；checksum 只取 payload 字节。

触发：保存 version=1、schema=1、codec=1、payload=A，再保存版本/代际/字节相同但 schema=2 的值。实际 Set 返回 nil，L2 schema 变成 2；本地 RemoteSnapshotCache.Publish 对同样输入会拒绝。测试使用现有 snapshotRedisFake，对照实际 Lua 的字段比较确认一致；本轮没有执行真实 Redis Lua，不作数值精度或 Redis 并发保证。

影响：同一版本字节的解释方式可改变，跨进程解码契约分叉。codec 与 schema 共享遗漏机制；本轮实测 schema 变更，codec 分支为源码同因推断，不冒称另做实测。

建议：将 schema/codec 等决定解释方式的字段纳入相同版本冲突比较，保证 L1/L2 规则一致。Redis 层需要真实脚本测试；不要仅修改替身让测试变绿。

## RR-20260913-08 / P2：快照绝对过期时间未参与读取准入

位置：[entity/remote_snapshot.go](../../entity/remote_snapshot.go):75、96–98 定义 ExpiresAt/Expired；构造缓存 :181–191 只使用固定 TTL，Get :244–269 未检查 envelope.ExpiresAt；[remoteentity/snapshot_l2.go](../../remoteentity/snapshot_l2.go):80–94 解码保留该字段但不拒绝过期。

触发：设置 ExpiresAt 为过去一秒、缓存 TTL 为一分钟，Publish 后 Cached Get 仍返回 found=true 且 `Expired(now)==true`。不依靠等待时间到期，测试没有脆弱 sleep。期望在准入或读取时拒绝已过期值，或按读模式进行权威回填，而不是把已经过期的业务快照当成正常命中。

影响限定为设置了非零 ExpiresAt 的调用方；默认未设置该字段的快照不由本测试证明受影响。容器 TTL 是本机缓存保留时间，不能替代 envelope 的绝对有效期，也不应通过回填延长后者。

建议：以两种有效期较早者控制可用性；校验直接发布、L2 回填与权威加载返回值。过期后 Cached 可 miss，Monotonic/权威模式按契约回填；明确同版本刷新有效期是否允许，补充边界测试。
