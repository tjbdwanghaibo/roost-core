# NC-154：skillcompose.ValidateCandidate 对空或重复的 candidate source 判 invalid 却不给诊断

2026-10-05，基线 `45d4bc1c`。P3（校验报告自相矛盾：`Valid=false`、`Diagnostics` 为空，生成器拿不到失败原因）。状态：已复现，未修复。[本轮](../review/REVIEW-2026-10-05-n09-batch3.md)。

## 触发与差异

`skill/skillcompose/validator.go:25-31`：

```go
for _, source := range candidate.Sources {
	if source.SkillID == "" || source.GameplayDigest == "" || gotSources[source.SkillID] != "" {
		report.Valid = false
		continue
	}
	…
}
```

其余每个拒绝分支都追加一条 `Diagnostic`。空 / 重复的 source 被跳过后，若去重后的集合恰好与合同相等，`PROVENANCE_MISMATCH` 也不会出现。

## 复现（探针，基线代码）

合同来源 `a`；candidate.Sources = `[a, a]` 或 `[a, {"" , "x"}]`，其余字段合法：

```
blank: valid=false diags=[]
```

## 影响

`ValidationReport` 是给生成器的反馈（doc.go：“validate every generated candidate before compilation”），无诊断的拒绝无法定位、无法让生成器修正。

## 验收覆盖点

两种输入都得到 `PROVENANCE_MISMATCH` 诊断；合法 candidate 仍 `Valid=true`、无诊断。

## 修复

未修复。
