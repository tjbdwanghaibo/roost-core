# NC-280：memory 默认值读另一个 memory——编译结果取决于 map 遍历顺序，编译通过时每次 Activate 类型不匹配

2026-10-06，基线 `0aeb5ab6`。P2（同一份定义有时编译通过、有时被拒；编译通过且被读的槽位排在后面时每次施法在 Activate 失败）。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-280.md)。[本轮](../review/REVIEW-2026-10-06-n09-batch6.md)。

## 机制

- Runtime：`runtime.go` Activate 按槽位顺序（lower 按名字排序）逐个求 memory 默认值，写进 `cast.memory[index]`；求到第 i 个时，后面的槽位还是零值 `RuntimeValue{}`。
- 编译期：`compile_typecheck.go` `runTypeCheckPass` 在 `for name, declaration := range context.artifacts.ir.memory` 的同一个循环里一边填 `checker.memory[name]`，一边用 `checker.baseScope()`（含当时已填的 `$memory.*`）检查默认值。Go 的 map 遍历顺序随机：另一个 memory 的名字在不在作用域里每次编译都可能不同。

## 触发与差异

| 定义 | 修前编译 | 修前执行 |
| --- | --- | --- |
| `a` 默认 `$memory.b`，`b` 默认 `$caster` | 40 次里约 3 次通过，其余 `REFERENCE_UNKNOWN` | 通过的那几次：每次 Activate `skill: runtime value type mismatch`（a 在 b 之前求值，读到零值） |
| `b` 默认 `$memory.a`，`a` 默认 `$caster` | 40 次里约 32 次通过 | 通过时能执行（a 排在前面） |

## 复现

`skill/eval_context_promises_test.go` `TestCompileRejectsMemoryDefaultsReadingMemoryDeterministically`（每种顺序编译 40 次）。修前：`later slot reads an earlier one: attempt 0 compiled (cast error <nil>); the compile result must not depend on map order`；另一种顺序被拒时诊断是 `REFERENCE_UNKNOWN … is not visible in this scope`。修前探针：`a→b` 编译 3/40、施法 `runtime value type mismatch`。

## 验收覆盖点

两种顺序每次都被拒，`INPUT_UNAVAILABLE` 定位到 `$.memory.<name>.default`，消息点名求值上下文 `memory_default` 与表项 `$memory.*`。控制：默认值读 `$input.target`、`$caster`、`$cast.mode` 照常编译、执行。

## 修复

[修复记录](../bugfix/RR-20261005-NC-280.md)：求值上下文表的 memory_default 列没有 `$memory.*`；类型检查在全部 memory 类型就位后按名字顺序、用 `scopeFor(evalMemoryDefault)` 检查默认值；Runtime 在 memory_default 上下文里求默认值。
