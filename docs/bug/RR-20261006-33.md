# RR-20261006-33：源文档 digest 丢掉接口字段的类型与 `json:"-"` 字段，只差效果类型 / 消耗数量的两个定义摘要相同

2026-10-07，基线 `443d08f6`（main）。P3（`ProgramIdentityView.SourceDocumentDigest` 承诺标识“源文档”，框架内没有用它做身份判断，只经 `InspectIdentity` 暴露；影响拿它判断“源文件变没变”的调用方：改了效果类型、消耗数量、cast window 表达式等，摘要不变，会被当成同一份源文档）。来源：召唤物改名（[重构记录](../feature/REFACTOR-2026-10-07-skill-summon-rename.md) §6）时发现，维护者要求交给 review 前闭环，本轮修。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261006-33.md)。

## 机制

- `canonicalDefinitionDigest`（基线 `skill/canonical_definition.go:10`）对 `Definition` 做 `json.Marshal` 再求摘要，注释认为“Definition 是封闭的 Wire 树，json 编码确定”。
- `Definition` 里大量字段是接口（`EffectDefinition`、`FlowDefinition`、`ValueDefinition`、`ActivationDefinition`、`CastPolicyDefinition`、`InputSchemaDefinition`、select 的 consume / shape / filter、motion 各部分），具体类型就是文档里的 `"type"` / `"flow"` / `"mode"` 判别字段。`encoding/json` 编码接口值只写具体类型的字段、不写类型名，字段集合相同的两个具体类型编码完全一样。用 go/types 枚举，同形的有：`SetMemoryEffectDefinition` / `AddMemoryEffectDefinition`、`HoldPolicyDefinition` / `TogglePolicyDefinition`、`Entity` / `DirectionInputSchemaDefinition`、`Position` / `EntityPosition` / `DirectionPositionInputSchemaDefinition`、`Drag` / `TwoPointInputSchemaDefinition`、`Line` / `RectangleShapeDefinition`、`Single` / `AbilitySet` / `StatusSet` / `OwnedEntitiesShapeDefinition`（空结构）、`AbilityTag` / `OwnedEntityTagFilterDefinition`。
- 带 `json:"-"` 的字段被整个跳过：`Cost.Amount`（`skill/wire_definition.go:29`，含 toggle / hold 的 sustain costs）、`CastWindowDefinition.WindupTicksExpression` / `RecoveryTicksExpression`（`skill/wire_cast_window.go:11`、`:16`）。这些字段由各自的 UnmarshalJSON 填，规范编码从来没写过它们。

## 触发 / 预期 / 实际

- 触发：同一份定义只改一处——效果 `set_memory` → `add_memory`；消耗 `amount` 10 → 20；windup / recovery 表达式；策略 hold ↔ toggle；输入 entity ↔ direction、drag ↔ two_point；形状 line ↔ rectangle、single ↔ owned_entities；过滤器 ability_tag ↔ owned_entity_tag。
- 预期：源文档变了，`SourceDocumentDigest` 变。
- 实际：十种改法摘要全部不变；端到端 `set_memory` → `add_memory` 时 gameplay digest 变、源文档 digest 不变（与改名记录 §6 的实测一致）。

## 可达性

任何拿 `InspectIdentity(program).SourceDocumentDigest` 判断源文件是否变化的调用方（发布流水线、缓存键、审计）；框架内部不读它（gameplay / presentation digest 不经过它，Program 查找按 gameplay digest）。
