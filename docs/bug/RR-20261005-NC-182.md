# NC-182：FastMap 遍历回调里改已有键触发重排，交出零值键、漏键

2026-10-05，基线 `f6245613441d16aafec33870166a4ec14f1ca15b`。P3（潜伏：game-demo 的 `map=fast` 字段遍历都先收集再改，没有触发路径；业务按 Go map 的习惯在 `RangeX` 回调里 `SetX` 就会把不存在的键写进提交）。状态：已复现，未修复。[本轮](../review/REVIEW-2026-10-05-n13.md)。

## 触发与差异

`safemap/fast.go`：

- `Set`（:49-64）先 `ensureWritable` 再查键：装载率到阈值时，改一个**已有**键也会 `rehash`，换掉 `keys` / `values` / `states` 三个数组。
- `Range`（:113-125）`for i, state := range m.states` 固定的是旧 `states`，却每次读 `m.keys[i]` / `m.values[i]`——重排后是新数组里同下标的槽，可能是空槽（零值键）、别的键，或越界。
- `Clear`（:103-111）把 `keys` / `values` 置 nil，回调里 `Clear` 后下一轮 `m.keys[i]` 下标越界 panic。

生成 DAO 的 `RangeX` 对 `map=fast` 直接转发 `FastMap.Range`（`codegen/internal/dao/testdata/golden/gen_variety_dao.go` 的 `RangeFastItems`），`SetX` 走 `FastMap.Set` 并 `MarkPersistSet`。于是 `RangeItems(func(k, v) { SetItems(k, v*10) })` 在 6/8 装载时：键 0 被交出三次、回调把 `items[0]=0` 写进 map 与提交记录，键 2、5、6 没被改。

预期：遍历只交出真实存在的键，每个未被删除的原有键恰好一次；回调里改已有键、插入、删除、Clear 都不破坏遍历（插入的新键是否被交出不承诺，与 Go map 相同）。

## 复现

`safemap/fastmap_range_promises_test.go` 的 `TestFastMapRangeToleratesWritesFromTheCallback`：

```
update_every_existing_key: Range delivered map[0:3 1:1 3:1 4:1], want each of [1 2 3 4 5 6] exactly once
insert_keys_until_the_table_grows: Range delivered key 0, which was never in the map
clear_from_the_callback: Clear inside Range panicked: runtime error: index out of range [2] with length 0
```

生成 DAO 组合（golden `VarietyDao`，一次性模块 replace 到基线）：`seen=map[0:3 1:1 3:1 4:1] len=7 phantom_key0=true`，提交记录的 `SetBSON` 含 `fast_items.0 = 0`。原文见[证据](../bugfix/evidence/noncore-bugfix-20261005-revn13/red-nc182-generated-dao.txt)。

## 约束

`FastMap` 为外层锁保护的热路径设计，不改成复制快照（每次遍历分配）；修在 `Set` 的检查顺序与 `Range` 对“表被换掉”的处理，不改生成器与模板。
