# RR-20260930-15：`holding` 直接比较实体接口值，不可比较的值类型实体实现会 panic

日期：2026-09-30。基线：`4784ef82`。来源：REMAINING §3 N29（RR-20260927-25 §未验证项），维护者 2026-09-30 拍板“契约 + 启动期校验，不改热路径的比较”。等级 **P3**：仓内与生成物的实体都是指针，触发要靠手写的值类型实体实现；一旦触发是运行期 panic（`comparing uncomparable type`），发生在 Guard 取锁的热路径上。状态：已复现；2026-09-30 已修复，未发版，见文末“修复”。

## 触发

1. 一个值类型的实体实现（例如 `type valueEntity struct{ *entity.EntityBase; onClear func() }`，值接收者方法），含 func / map / slice 等不可比较字段。
2. 它被注册的 builder 构建出来（`BuildEntity`）或手工 `EntityManager.Add` 进入框架。
3. 同一 Guard 上同 ID 的两个实例相遇（Destroy 后同 ID 重建、重复构建），`entity/entity_guard.go` `holding` 执行 `current == ent`。

## 预期

实体实现必须是指针（契约）；不是指针的实现在进入框架的入口就被拒绝并点名类型，不会走到 Guard 的比较。

## 实际

两个入口都不检查，值类型实体照常发布。回归 `entity/entity_pointer_contract_promises_test.go` 在基线上：

```text
--- FAIL: TestValueTypeEntityIsRejectedAtRegistrationAndPublish (0.00s)
    --- FAIL: TestValueTypeEntityIsRejectedAtRegistrationAndPublish/manager_add (0.00s)
        entity_pointer_contract_promises_test.go:32: TryAdd accepted a value-type entity implementation (entity.valueTypeEntity): the guard compares instances and would panic on this type
    --- FAIL: TestValueTypeEntityIsRejectedAtRegistrationAndPublish/registered_builder (0.00s)
        entity_pointer_contract_promises_test.go:52: BuildEntity accepted a builder that returns a value-type entity (entity.valueTypeEntity)
```

仓内还真有一个值类型实体替身：`kit/nest/entity_sync_test.go` 的 `reloadedEntity`（值接收者 `Base()`），`entity_sync_resync_test.go:76` 把它 `manager.Add` 进 EntityManager——校验加上后该用例 panic（见修复记录），证明入口校验能抓住这类实现。

## 根因

`entity/entity_guard.go:325`（基线）`holding`：`current == ent` 直接比较接口值；`:561` `doReleaseEntity` 的 `current == ent` 同样。RR-20260927-25 / 30 只把 Mutex 的比较改成可比较性安全的 `sameMutex`，实体本身的比较没有处理。实体进入框架的两个入口 `entity/entity_factory.go` `BuildEntity`（builder 返回后只校验 Remote 策略）与 `entity/entity_manager.go` `TryAdd`（只查 nil / removing / 重复）都没有类型校验。

## 修复约束

1. 契约写明“实体实现必须是指针”（USER_GUIDE §3、`holding` 注释）。
2. 入口校验一次：`BuildEntity`（builder 返回后）与 `EntityManager.TryAdd`（`Add` 经它）用 `reflect.TypeOf(e).Kind() != reflect.Pointer` 拒绝，错误带可 `errors.Is` 的哨兵并点名类型；可比较的值类型同样拒绝（值类型经接口传递每次都是拷贝，“同一实例”没有意义）。
3. **不改热路径的比较**：`holding` / `doReleaseEntity` 的 `==` 保持。
4. 回归：值类型实现在两个入口都被拒绝并点名类型；指针实体照常接受；仓内值类型替身改为指针。
