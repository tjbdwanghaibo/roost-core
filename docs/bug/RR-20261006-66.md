# RR-20261006-66：协调器在别的进程时，EmitStart 只按 4 MiB 校验，超过 saga.max_payload_bytes 的启动意图随业务事务提交

2026-10-07，基线 `a7285da6`（main）。P3（意图被协调器拒绝后由启动消费者 Term + ERROR 兜底，但业务的 Nest 事务已提交）。来源：RR-20261006-43 的“未验证 / 风险”与 [FRAMEWORK-DOCS-FINDINGS-2026-10-07](../review/FRAMEWORK-DOCS-FINDINGS-2026-10-07.md) 第 90 行维护者决定（“补 S7 跨进程上限为共享配置”）。
状态：已复现；已修复（`133a4e88`），未发版。[修复](../bugfix/RR-20261006-66.md)。

## 机制

1. RR-20261006-43 让 `NewStartEffect` 按 `startDataLimit(type)` 校验 `Data`，上限来自 `Engine.Register` 写进的按类型进程表（`saga/nest.go`）。
2. 发起方（调 `EmitStart` 的 Nest 服务）与协调器（`kit/saga` Mod）常在不同进程：发起方进程里没有这个类型的 Engine，表里查不到，退回线上硬上限 4 MiB。
3. `saga.max_payload_bytes` 只有 `kit/saga` 声明、只有协调器读；发起方没有办法知道协调器的上限。超过它（缺省 64 KiB）的意图随业务事务提交，协调器 `StartSaga` 返回 `ErrInvalidRecord`，启动消费者 Term 并告警，业务已无法回滚。
