# NC-268：TopologicalSortCache 与调用方共享依赖切片

2026-10-06，基线 `dc877c04`，分支 `revleft`（N11～N13 留项与小防护）。**P3**。来源：N13 观察 O4（切片别名部分）。状态：已复现，已修复（见文末）。[本轮](../review/REVIEW-2026-10-06-revleft.md) · [证据](../bugfix/evidence/noncore-bugfix-20261006-revleft/README.md)。

## 触发与差异

`container/topologic_sort.go`：`RegisterCompDependency`（基线 :31）保存调用方的变参切片——`deps...` 传入的就是调用方的数组；`GetCompDependencies`（基线 :126）返回内部切片。任一方改动都直接改了登记的依赖，且不使排序缓存失效。

- 预期：登记之后的依赖只经登记接口改变。
- 实际：调用方复用自己的切片或改返回值，依赖被悄悄改掉。零调用方（`manager/order.go` 已因此不用它）。同层节点顺序随 map 变化（O4 前半）未改：没有承诺顺序，见本轮记录。
