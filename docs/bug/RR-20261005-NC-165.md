# NC-165：log.Close 只关文件，默认 logger 仍写已关闭的文件——只配文件 sink 时进程退出原因与停机尾部日志全部丢失

2026-10-05，基线 `45d4bc1c`。**P3**（可观测性：缺省配置 stdout + file 时只是文件少了最后几行；只配文件时退出原因哪里都没有）。状态：**已复现，未修复**。[本轮](../review/REVIEW-2026-10-05-n12-revn12.md)。

## 触发、预期与实际

- 触发：`app.run` 返回前 `defer flog.Close()`（`app/app.go:155`），之后生成的 main 用 `slog.Error("server exit", "err", err)` 写退出原因（`codegen/internal/roost/render.go:300-303`）；停机超时分支（`app.go:432-438`）直接返回，仍在运行的 Serve / Shutdown / Mod 继续打日志。
- 预期：关闭文件 sink 之后的日志仍有去处。
- 实际：`log.Close`（`log/log.go:108-117`，基线）只关文件，`slog.Default` 仍是写这个文件的 handler；写已关闭文件的错误被 slog 吞掉。`log.stdout: false` 时这些行哪里都没有，进程带退出码 1 消失；缺省 stdout + file 时 stdout 有、文件里没有最后的退出原因。

```text
close_fallback_promises_test.go:65: after Close of a file-only sink "server exit" went nowhere (stderr="")
```

## 根因

Init 建立的默认 logger 把文件与控制台写进同一个 handler；Close 撤下文件时没有重建默认 logger。

## 验收覆盖点

只配文件时 Close 之后的日志写到 stderr；配了控制台输出时 Close 之后仍写控制台；Close 前的行仍在文件里。没做：让 app.run 在关闭前把最终错误写进文件（app.go 属 N01 / singleton 另一线，见运行记录观察）。
