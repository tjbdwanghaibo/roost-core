# RR-20261004-08：连接 drain 超出停止预算后 `Assembly.Close` 已硬关闭连接却只返回 ctx 错误，NatsMod 保留 `m.asm`，重试永远拿到 `ErrConnectionClosed`、引用永不置空

日期：2026-10-04。基线：main `a1c1af3e`（v1.19.1 之后，含 RR-20261004-07 修复）。来源：[W-2026-10-04-02](WANTED.md)（RR-20261004-07 修复记录 §未验证项）。等级 **P3**。状态：已确认，已修复（见下）。

## 触发

1. NatsMod 持有已连接的 Assembly；连接上有订阅，其 handler 仍在处理消息、订阅队列里还有待处理消息（或者连接在停止前已经被服务端断开且不再重连）。
2. `NatsMod.StopWithContext(短预算)`：RPC 停止成功，`Client.DrainWithContext` 等订阅排空，预算用完 → `c.conn.Close()` 硬关闭连接并返回 ctx 错误。
3. 再次 `NatsMod.StopWithContext(...)`（任意预算）。

## 预期

连接已经被硬关闭、资源已释放，停止流程要能收敛：要么第一次停止就报告“已关闭但未完整排空”的终态并释放 `m.asm`，要么之后的停止返回 nil 并释放引用。与 RR-20261004-07 的规则一致：只有 ctx 错误且资源仍由对象持有时才保留供再次排空，终态错误照常释放。

## 根因（基线 `a1c1af3e` 行号）

- `nats/driver/assembly.go:66-69`（`f928bb2f`）：`Client.DrainWithContext` 失败后 `a.Client.Close()` 硬关闭连接，却原样返回 drain 错误；预算用完时这是裸 ctx 错误，调用方无法区分“RPC 回调等待超预算、连接仍在”（`assembly.go:62-63`，可再次排空）与“连接已关闭”（终态）。
- `kit/nats/nats_mod.go:176-179`（第 179 行 `return err` 由 `3560a19b`，NC-09 引入）：`asm.Close` 返回任何错误都保留 `m.asm` 并返回，前提是“再次停止能继续排空”；对已关闭的连接不成立。
- `nats/driver/client.go:159-161`：重试时 `c.conn.Drain()` 命中 nats.go v1.53.1 `Conn.Drain` 首个分支（`nats.go:6309-6311`，`isClosed()` → `ErrConnectionClosed`），重试永远失败。停止前连接已被服务端关闭 / 正在重连时第一次停止就落到这里（`ErrConnectionClosed` / `ErrConnectionReconnecting`），同样被保留。

## 修复约束

- `Assembly.Close` 在连接 drain 失败（含超预算）后返回 `errors.Is` 可判的终态（仍保留对 ctx 错误的 `errors.Is` 匹配，调用方报告不变）；RPC 回调等待的 ctx 错误保持“保留供再次排空”。
- NatsMod：终态错误报告并释放 `m.asm`，之后的停止返回 nil；RPC 回调等待超预算时仍保留。
- 不改变 `Client.DrainWithContext` / `IClient` 语义，不新增 goroutine。
