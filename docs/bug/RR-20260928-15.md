# RR-20260928-15：生成的 player TCP 测试在“认证 ack 之后、会话登记之前”断言会话

日期：2026-09-28。基线：`b8a401a`（已推送，v1.17.2 之后的 main）。来源：[REMAINING-2026-09-28](../review/REMAINING-2026-09-28.md) §6 N70（framework-compat run 36367611936，`generated-consumer (source-head, full)`），同类残留见同文 §5 N62。
等级 **P4**：测试缺陷，产品行为不变；影响是 framework-compat 与生成工程的测试偶发失败，门禁因此给不出结论。状态：已修复（本地，`fix-r12-n70`，未推送 / 未发布），见下。

## 现象

CI 上生成工程的 `internal/access/player/tcp` 报：

```text
--- FAIL: TestAConnectionThatCannotTakeAPushIsClosedAndTheOthersKeepIt
    server_gen_test.go:556: active sessions = 1, want 2
```

`51fc7ee` 上同一 lane 通过，只出现过一次。本地在 `b8a401a` 生成的 game-demo 上复现到了（`-race -count=500`，同时并行跑 3 个 `internal/service/game` race 测试二进制作为负载；开跑前机器 1 分钟 load 4.2）：500 次里失败 1 次，失败文本与 CI 逐字相同。

```text
--- FAIL: TestAConnectionThatCannotTakeAPushIsClosedAndTheOthersKeepIt (0.00s)
    server_gen_test.go:556: active sessions = 1, want 2
FAIL
```

## 根因（`b8a401a` 行号）

生成的服务器 `serveConnection`（`codegen/internal/roost/render_player_tcp.go:763-764`）先写认证 ack，再 `registerSession`。测试的 `dialAuthenticated` 读到 ack 就返回，这时服务器那一侧的 goroutine 可能还没执行 `registerSession`。`waitReleased` 等的是连接槽和按 IP 的计数，它们在 accept 时就已占上，说明不了会话有没有登记。

与 [RR-20260927-02 §后续更正](../bugfix/RR-20260927-02.md) 是同一原因。那次只给 `TestCloseSessionsCountsTheSessionsItClosed` 加了有界等待（`:1662-1667`），同一模板里其余用例拨号之后直接推送或计数：

| 用例（生成 `server_gen_test.go`） | 模板行 | 会话未登记时的表现 |
| --- | --- | --- |
| `TestAConnectionThatCannotTakeAPushIsClosedAndTheOthersKeepIt` | `:1568-1569` | `active sessions = 1, want 2`（N70） |
| `TestAPushNoConnectionTakesFailsAndClosesThemAll` | `:1595-1605` | 第二个会话晚登记：计数先为 0 就结束循环，`waitClosed` 等不到它的关闭事件 |
| `TestAPushThatFailsBeforeWritingClosesNoConnection` | `:1620-1625` | 推送返回 `ErrSessionNotFound` 而不是 `context.Canceled`，或计数不为 2 |
| `TestASessionPushThatCannotBeWrittenClosesThatSession` | `:1640-1646` | `PushSession("stalled")` 返回 not found，循环提前结束 |
| `TestAnExpiringCallerDeadlineClosesNoHealthyConnection` | `:1796-1815` | 计数不为 2，第一轮就结束循环并报错 |

game-demo 的 `internal/service/game/scene_connections_test.go`（模板 `demo/internal/service/game/scene_connections_test.go.tmpl`）有同样的依赖。两个用例只等了被测玩家的连接登记（`:266`、`:336`），没等 mover 的（`:264`、`:333`）。mover 未登记时，下一个玩家 `Join` 做的 `sweepLocked` 会把它当成已断线移出场景，推送给它也会失败。

为了逐个确认，在 `b8a401a` 的生成工程里把 `registerSession` 前临时插入 50ms 延迟（只是探针，没有提交；`server_gen.go` 事后复原）。结果正好是上表 5 个用例失败，`TestCloseSessionsCountsTheSessionsItClosed` 因为已有等待而通过：

```text
--- FAIL: TestAConnectionThatCannotTakeAPushIsClosedAndTheOthersKeepIt (0.05s)
    server_gen_test.go:556: active sessions = 0, want 2
--- FAIL: TestAPushNoConnectionTakesFailsAndClosesThemAll (2.00s)
    server_gen_test.go:608: session closes seen map[], want one each for [first second]
--- FAIL: TestAPushThatFailsBeforeWritingClosesNoConnection (0.05s)
    server_gen_test.go:628: cancelled push = player tcp: session not found: player 7, want context.Canceled
--- FAIL: TestASessionPushThatCannotBeWrittenClosesThatSession (0.05s)
    server_gen_test.go:663: active sessions = 0 after the session's write failed, want 1
--- FAIL: TestAnExpiringCallerDeadlineClosesNoHealthyConnection (0.05s)
    server_gen_test.go:855: active sessions = 0 after 1 refused pushes, want 2
```

只让 mover（9851 / 9861）延迟 300ms 登记时，两个 scene 用例失败：

```text
    scene_connections_test.go:305: members=1 removes seen by the mover=0: the reconnected player must stay in the scene
--- FAIL: TestAStalledOldConnectionDoesNotResetTheLiveClient (1.11s)
    scene_connections_test.go:358: a player none of whose connections takes a frame is still in the scene: members=1 removes=0
--- FAIL: TestAPlayerWhoseEveryConnectionStallsLeavesTheScene (0.30s)
```

codebase-memory 图谱已过期（generation 09-26），以上行号与结论来自当前源码和实跑。

## 修复约束

只改生成的测试，不改服务器的 ack / 登记顺序（产品行为）。断言前加有界等待，等到会话都已登记，写法与 `TestCloseSessionsCountsTheSessionsItClosed` 相同。生成器测试要断言模板里有这个等待。生成工程里该用例在并行负载下 `-race -count=500` 通过。
