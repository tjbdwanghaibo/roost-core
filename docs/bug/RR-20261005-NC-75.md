# RR-20261005-NC-75：tablegen 的 `ref=` 在哪里都不检查；`-json -check` 不按 schema 规则校验，直接改 JSON 再 reload 绕过 required / unique / min

日期 2026-10-05。基线 main `80802200`。等级 **P2**（悬空引用的配置能加载上线）。状态：已复现（tablegen 运行期门与单测），ref 与 `-check` 已修复、声明场景验证，未发版；运行时 required 存在性待决定（见文末）。来源：N07 第二批移交 H2e（[记录](../review/REVIEW-2026-10-05-noncore-n07b.md)：删掉 spawn 的 `template` 后 reload 被接受，按 template 0 刷怪）；N08 codegen（[本轮](../review/REVIEW-2026-10-05-n08-codegen.md)）。

## 触发与实际

1. **ref 不检查**：schema 写 `` SceneID int32 `ref:"scene"` ``（`CODEGEN_REFERENCE` 的 tablegen 例子就是这一行）。`validateRows`（`codegen/internal/tablegen/main.go:546-553`）注释说 ref “需要所有表都加载，是生成 loader 的职责”，但生成的 `RegisterTable`（`main.go:728` 模板）只有 `Name / File / Key`，没有任何校验。新增运行期门 `codegen/scripts/tablegen-runtime.sh`（对 pin 的 v1.20.0 core）修前红：

```
roundtrip_test.go:73: reload with a dangling scene_id = <nil>, want a reference error
--- FAIL: TestDanglingRefIsRejectedOnLoadAndReload/monster_points_at_no_scene
--- FAIL: TestDanglingRefIsRejectedOnLoadAndReload/the_scene_it_points_at_is_removed
```

2. **`-check` 名不副实**：flag 帮助是 “check generated JSON files against current table metadata”，`checkJSONFiles`（`main.go:481`）只 `json.Unmarshal`。N07 第二批（NC-64）把 game-demo 的热更说明改成“线上直接改 `configs/data/*.json` 再 reload”，这条路上没有任何东西按 schema 查 required / unique / min；configdata 只拿到类型化的行，分不清缺列和零值。新增 `TestCheckJSONEnforcesTheDeclaredRules` 修前 6 子测试全红（缺 required 键、required 为 null、主键重复、unique 重复、低于 min、表文件不是行列表）。

## 影响与定级

悬空的 ref 能通过 `roost generate`、冷加载与热更进入线上快照，业务按 id 取不到目标（或按零值处理），定 P2。required / unique / min 在 CSV → JSON 时仍检查，只是直接改 JSON 的路径无人检查。

## 未做 / 需要决定

运行时（reload 时）的 required 存在性检查本条不实现：configdata 的 `Validate` / `ValidateTable` 只看到类型化的行，缺列与零值无法区分（`Spawn.CenterX = 0` 是合法值，不能按零值拒绝）。候选：A. configdata `TableDef` 增加“必需 JSON 键”并在解码时一次检查，tablegen 生成它——新 API，生成工程的 Core 下限要随发版升高；B. 生成的 `ValidateTable` 再读一次原始 JSON 查键——不需新 API，但两次读之间文件可能被替换。交维护者选择；本条先让 `-check` 成为 reload 前可用的校验入口。

## 修复（2026-10-05）

ref（生成的 `ValidateTable`）与 `-json -check` 已修复、声明场景验证，未发版；运行时 required 存在性仍待维护者在上面 A / B 之间选择。[修复记录](../bugfix/RR-20261005-NC-75.md)。以上原始现象与修前红保留不改。

## 后续：运行时 required（维护者决定 B10，2026-10-06）

维护者选方案 A，并要求规则统一由运行时加载层强制、生成期只作提前反馈、两处用同一份规则声明。已实施、未发版：configdata 新增 `TableDef.Rules` / `ObjectDef.Rules`（`FieldRule`），required / unique / min / enum 在每次 Load / Reload 对原始 JSON 检查，ref 在全部表加载后检查；规则的表示与检查是叶子包 `configdata/rules`，tablegen 的 CSV 转换、`-check` 与生成的 loader 共用。本记录“未做 / 需要决定”一节与修复记录“未做”里的运行时 required、运行时 min / 非主键 unique 由此完成；object 文件的 ref 仍不支持（schema 生成期拒绝）。端到端：生成 game-demo 删掉 spawn 的 template 后 `gm.config.reload` 被拒（`configdata: table spawn row 1 (key 1) field template: required: missing or null`），版本与刷怪不变。[方案与实施](../feature/B10-C2-CONFIG-RULES-AND-RELOAD-VISIBILITY-2026-10-06.md)。
