# RR-20260926-02：Nest 快阶段允许冷加载占用逻辑 worker

日期：2026-09-26；基线 main `8ce21a5`；等级 P1；状态：已修复，验证见[修复记录](../bugfix/RR-20260926-02.md)。

普通消息的声明目标缺失，或慢准备后 handler 动态 Cast 访问一个未准备的目标时，
Nest 的 getter 会调用 ManagerAccess.Get/GetMany。内存未命中便进入 AggregateLoader，
甚至等待同实体的 singleflight。前者占住快 worker，动态 Cast 路径还可能持有 Guard。
这违反已明确的两池边界：慢池只准备 I/O，快池负责 Entity 本地锁和业务执行。

根因是 Getter 没有执行阶段约束，preparedGetter 只缓存显式目标，未命中直接回退 base。
不能在 handler 执行一半时把 goroutine 转到慢池；已经执行的业务也不能自动重试。

回归入口：`go test -race ./entity ./nest -run 'TestLoadedOnlyLookup|TestFastLogicMarksGetter'`。
测试分别验证不调用 loader、不加入已有 flight、预加载后可读，以及普通/慢消息内动态缺失的错误。
