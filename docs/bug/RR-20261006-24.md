# RR-20261006-24：nats 驱动 Close 之后的订阅、JetStream 与 RPC CallAsync 返回的错误 errors.Is 不到 fnats.ErrClosed

2026-10-06，基线 main `37338490`。P3（违反 [RR-20261006-10](RR-20261006-10.md) 统一口径第 3 条“Close 之后的其他调用返回该驱动可 `errors.Is` 的已关闭错误”；停机后仍在跑的组件按 `errors.Is(err, fnats.ErrClosed)` 判断“已经关了、别重试”时会误判为其他错误）。来源：[真实进程演练](../bugfix/REAL-PROCESS-DRILLS-2026-10-06.md)第 4 项，kit NatsMod 接真实 NATS 的 Close 用例首跑即红（RR-10 修复时只用不可达地址验证了 Publish）。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261006-24.md)。

## 触发与差异

连接关闭（`Assembly.Close` / `NatsMod.StopWithContext` / `Client.Close`）之后调用：

| 调用 | 预期 | 实际（基线源码） |
| --- | --- | --- |
| `Client.Subscribe` / `QueueSubscribe` | `errors.Is(err, fnats.ErrClosed)` | 原样返回 nats.go 的 `ErrConnectionClosed`（`nats/driver/client.go:119`、`:139`），文本同为 `nats: connection closed`，`errors.Is` 不到 |
| `JetStreamClient.EnsureStream` / `Publish` / `Subscribe` | 同上 | 原样返回（`nats/driver/jetstream.go:37`、`:50`、`:71`、`:80`） |
| `RPCClient.CallAsync`，RPC 已随 Assembly.Close 停止 | 同上 | 回调只拿到 `fnats.ErrCancelled`（`nats/driver/rpc.go:190`、`:217`），与“停止时在途调用被取消”同一个错误 |
| `RPCClient.CallAsync`，只关了连接 | 同上 | `rpc: subscribe inbox: nats: connection closed`（`:206`），`errors.Is` 不到 |

Publish / Request / RPC.Call 在 RR-10 后已经映射，这几处漏了。
