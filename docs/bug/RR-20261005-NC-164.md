# NC-164：statslog 的 entity.count_by_kind / count_by_category 在某类实体全部卸载后停在最后一次的非零值

2026-10-05，基线 `45d4bc1c`。**P3**（可观测性：/metrics 与 JSONL 不一致）。状态：**已复现，未修复**。[本轮](../review/REVIEW-2026-10-05-n12-revn12.md)。

## 触发、预期与实际

- 触发：某个 kind / category 的实体全部卸载（例如所有玩家下线）。
- 预期：`publishGauges` 注释承诺 JSONL 文件、/metrics 与面板说的是同一件事（`kit/statslog/statslog.go:175-180`，基线）。
- 实际：`collectEntityStats`（`:437-459`）只为当前有实体的键计数，计数为 0 的键不在 map 里；`publishGauges`（`:181-197`）只遍历 map，上一次的非零值永远留在 gauge 上。JSONL 里该 kind 消失（= 0），/metrics 一直报旧人数。

```text
gauge_lifecycle_promises_test.go:95: entity.count_by_kind{kind=2} = 2 after every kind-2 entity unloaded; the record says 0
gauge_lifecycle_promises_test.go:98: entity.count_by_category{category=2} = 2 after the category emptied; the record says 0
```

## 根因

gauge 的生命周期跟着“这次采集出现过的键”走，而 metrics registry 没有删除序列的入口，缺席不会让 gauge 归零。

## 验收覆盖点

曾经发布过、本次缺席的键写回 0；仍有实体的键照常。
