## 机制

1. **N1**：`observability/grafana-roost-overview.json` 的“Durable wait / 外化闸门推迟”面板，第二条线查的是 `entitysync_flush_gate_deferred_total`。源码只写 `entitysync_durability_gate_deferred_total`（`sync/entitysync/flush.go`），所以这条线永远为空：持久化落后导致整个 subject 暂缓发送时，面板上看不到。`docs/TROUBLESHOOTING.md` T-100 写的也是旧名。
2. **N2 ①**：demo 仪表盘模板（`demo/deploy/dev/observability/grafana/dashboards/roost-demo.json.tmpl`）用 `sum by (subject)` 聚合 `nats_jetstream_terminal_total`。这个指标只带 `reason` 标签（`nats/driver/jetstream.go`，取值 `permanent` / `max_deliver`），结果面板只剩一条 `subject=""` 的线，分不出两种终止原因。demo README 模板同样写成 `{subject}`，而且只说了“重试 20 次仍失败”，漏了 `permanent`。
3. **N2 ②**：demo README 说 `bus_rpc_*` 只在 `nats.reliable.enabled` 时计数，实际的开关是 `nats.rpc.transport: jetstream`（`kit/nats/nats_mod.go` `jetStreamRPC`）。
4. 根因是结构缺口（F11 N3）：这几处的指标名和标签都是手写字符串，没有任何测试拿它们和源码对照。
