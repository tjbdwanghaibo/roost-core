# RR-20260926-28：Durability 0 的 Remote 写在事务从未到达 Mongo 时，finalizer 永远拿不到结论，写权限/锁/额度被永久占住

日期：2026-09-26。基线：main `985d5ba`。等级 P2（写额度泄漏累积为全局 `ErrRemoteOverloaded`；实体永久隔离）。引入：RR-20260926-20 修复（修前资源会释放）。
状态：已复现（修前修后对照），未修复。

## 触发条件

DurabilityMemory 的 Remote 写，后端返回瞬时错误，但事务实际从未提交到 Mongo（发出前 ctx 已过期、网络断开、StartSession 失败、驱动 abort 后超时）。

## 预期 vs 实际

预期：不确定结果最终要有结论；gate、锁、写额度最终释放。
实际：错误判为不确定（`remoteentity/transaction_manager.go:429,435`），batch 不回滚，Close 转交 finalizer（`batch.go:460,534`）；finalizer 只在
Applied / Committed / Rejected 时收尾（`transaction_manager.go:237-262`）；`MongoCommitter.CommitStatus` 对不存在的事务永远返回 Unknown
（`mongo_committer.go:206-207`）；Durability 0 没有 WAL 重放，无任何路径使其变确定 → 永远“隔离 + 退避重试”，gate、ownershipMu 读锁、写额度一直占用。

## 复现

[REPRO-2026-09-26-03](REPRO-2026-09-26-03.md) §4（`-race`，后端 `CommitRemoteBatch` 直接返回 `context.DeadlineExceeded`、不提交）：

```text
985d5ba: status after 2s=0(Unknown) owner=quarantined slots=1 ；同实体下一次 PrepareRemoteWriteBatch: context deadline exceeded
aaada47: slots=0，下一次准入立即被拒（隔离但 gate 与额度已释放）
```

## 实施方向与验收

- 对 Durability 0 的 Unknown，finalizer 以相同事务 `_id` 持久写入 Rejected 记录挡住迟到提交（与 `RejectRemoteCommitsInTransaction` 同机制），
  写入成功（或读到已 Applied）后按结论回滚/确认并释放；不能伪造提交、不能在未拿到持久结论前释放。
- 回归：从未提交 → 有限时间内 Rejected、回滚、slots=0、实体可写；已提交丢回复 → 仍 Committed（`TestMemoryLostCommitReplyKeepsFinalizerOwnership` 保持）。
