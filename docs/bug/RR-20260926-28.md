# RR-20260926-28：Durability 0 的 Remote 写在事务从未到达 Mongo 时，finalizer 永远拿不到结论，写权限/锁/额度被永久占住

日期：2026-09-26。基线：main `985d5ba`。等级 P2（写额度泄漏累积为全局 `ErrRemoteOverloaded`；实体永久隔离）。引入：RR-20260926-20 修复（修前资源会释放）。
状态：已复现（修前修后对照），未修复。

## 触发条件

DurabilityMemory 的 Remote 写，后端返回瞬时错误，但事务实际从未提交到 Mongo（发出前 ctx 已过期、网络断开、StartSession 失败、驱动 abort 后超时）。

## 预期 vs 实际

预期：不确定结果最终要有结论；gate、锁、写额度最终释放。
实际：错误判为不确定（`remoteentity/transaction_manager.go:429,435`），batch 不回滚，Close 转交 finalizer（`batch.go:460,534`）；finalizer 只在
Applied / Committed / Rejected 时收尾（`transaction_manager.go:237-262`）；`MongoCommitter.CommitStatus` 对不存在的事务永远返回 Unknown
（`mongo_committer.go:206-207`）；Durability 0 没有 WAL 重放，无任何路径使其变确定 → 永远“隔离 + 退避重试”，gate、ownershipMu 读锁、写额度一直占用。

## 复现

[REPRO-2026-09-26-03](REPRO-2026-09-26-03.md) §4（`-race`，后端 `CommitRemoteBatch` 直接返回 `context.DeadlineExceeded`、不提交）：

```text
985d5ba: status after 2s=0(Unknown) owner=quarantined slots=1 ；同实体下一次 PrepareRemoteWriteBatch: context deadline exceeded
aaada47: slots=0，下一次准入立即被拒（隔离但 gate 与额度已释放）
```

## 实施方向与验收

- 对 Durability 0 的 Unknown，finalizer 以相同事务 `_id` 持久写入 Rejected 记录挡住迟到提交（与 `RejectRemoteCommitsInTransaction` 同机制），
  写入成功（或读到已 Applied）后按结论回滚/确认并释放；不能伪造提交、不能在未拿到持久结论前释放。
- 回归：从未提交 → 有限时间内 Rejected、回滚、slots=0、实体可写；已提交丢回复 → 仍 Committed（`TestMemoryLostCommitReplyKeepsFinalizerOwnership` 保持）。

## 修复（2026-09-26）

状态：已修复，适用本地验证通过（基线 main `87d9499`），已本地提交，未推送/发布。详见[修复记录](../bugfix/RR-20260926-28.md)。

- 根因按当前源码确认：`transaction_manager.go:237-262` 只在 Applied/Committed/Rejected 收尾，`mongo_committer.go:206-207` 对不存在的事务返回
  Unknown，Durability 0 没有 WAL 让它变确定。
- 修复：finalizer 对 Durability 0 的 Unknown 调用新增的 `MongoCommitter.RejectUnresolvedRemoteCommits`，以同一事务 `_id` 持久写入 Rejected
  挡住迟到提交；插入撞键则读回真实状态（Applied 发布、Committed 确认，不回滚）。拿到 Rejected 后在实体本地锁内回滚，只把本事务造成的隔离
  退到 Recovering 并作废 marker，再释放 gate/锁/写额度；任何无结论的情况仍隔离重试。Durability 1/2 的 Unknown 不写拒绝，仍由 WAL 投影收敛。
- 修前红：`TestMemoryNeverCommittedTransientErrorGetsDurableRejection` →
  `same entity stays blocked after never-committed memory write: context deadline exceeded (owner=quarantined slots=1)`；修后该用例与相关回归
  `-race -count=20` 通过。
- 行为变化：finalizer 的 Rejected 收尾（全部持久级别）不再让实体永久停在 Quarantined。未验证：真实 Mongo 上拒绝插入与在途事务的互斥时序；
  finalizer 回滚在实体本地锁内就地执行，不是投递到 Nest 快池。

### 复核更正（2026-09-26）

上一条中“拿到 Rejected 后……只把本事务造成的隔离退到 Recovering”与“finalizer 的 Rejected 收尾不再让实体永久停在 Quarantined”已撤回。
复核确认：生成实体 rollback 是 no-op、下一次提交按整份 DAO ReplaceOne，解冻会把被拒绝的内存修改写进 Mongo（`9a4ef81` 上
`TestRejected*IsNotCarriedByNextWrite` 四条全红，Mongo 终态 `a=rejected;b=second`，期望 `a=;b=second`）。另查实基线 `87d9499` 已有同类泄漏：
Durability 1 在 finalizer 首轮即读到 Rejected 时实体从未被隔离。现行为：Rejected 收尾回滚后隔离批次内实体直到重新加载，gate/锁/写额度照常释放，
下一写者立即得到 `ErrRemoteFenced`；原验收“实体可写”改为“重新加载后可写”。详见[修复记录的复核更正](../bugfix/RR-20260926-28.md#复核更正2026-09-26)。
