# RR-20261005-NC-40：原生完成信封未绑定目标 Saga 路由

2026-10-05；P2；基线 main `cb11be90`；**已复现、已修复，声明场景已验证，未发版**。N06 原生完成 consumer 的新问题。

## 反例与影响

payload 是等待中 `target` 的合法完成结果，信封 Topic 分别为 `saga.result.other`、`saga.result.`、`saga.result.target.extra`。已有 `NewCompletionEffect` 的规范路由应为 `saga.result.target`。

预期：路由不一致永久拒绝，在 `Complete` 前停止，不推进 Saga 或写 completion/operation receipt；修正路由后仍能正常完成及重投幂等。

实际三项全红：`foreign route="saga.result.other" was not refused permanently: <nil>`；`foreign route mutated saga: version=2 status=pending`；`foreign route recorded completion: recorded=true err=<nil>`。测试连接正式 MongoStore；最终回归还经过公开 `SubscribeNestCompletions` 的 handler，而非只测比较函数。[红绿证据](../bugfix/evidence/noncore-bugfix-20261005-16/README.md)。

基线 `saga/nest_completion_consumer.go:104` 仅在解码前做 `HasPrefix`，解码后直接调用 `Complete`。宽订阅接收多 Saga，不能把前缀正确当成 payload 与信封身份一致。错误发布源/损坏信封可结算与其路由不同的 Saga。

## 修复与限制

解码合法完成后，精确要求 `envelope.Topic == CompletionEffectTopicPrefix + completion.SagaID`，再交给状态机；错误仍保留 `errors.Is`，使用既有 Permanent 进入 NATS settle。[修复](../bugfix/RR-20261005-NC-40.md)。

这是格式/身份一致性校验，不是签名、鉴权或任意内部发布者隔离；EffectID/Key/Headers 与真实 broker Subject 的权限不由此保证。合法发送 API/线格式和 WAL 均不变；真实 broker Term/重连未在本机验收。
