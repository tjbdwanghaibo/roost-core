# RR-20260924-14：事务内 Put 重复键被误处理为可重试超时

日期：2026-09-24；基线：`967bc69` 加 DataEngine 工作树。等级：P1。状态：已复现、修复、验证，未发布；[修复记录](../bugfix/RR-20260924-14.md)。

多文档 Project 先查询业务事务 marker，再依次 applyMutation。当 Put 的版本谓词无法匹配已有 `_id` 时，upsert 报重复键，Mongo 已中止整个 transaction。旧 applyPut 仍调用 classifyNoMatch，在同一 session 内 FindOne，收到事务失效/暂态错误；驱动重试最终耗尽 15 秒 transaction timeout，而不是报告确定的版本冲突。Projector 无法进入预期的 fatal 冲突边界。

真实复现：两个实体、两个集合、四笔连续事务；第三笔最后一个 Put 故意使用 expected=8/next=9，存储版本为 2。批量路径正确回滚后逐笔判断，前两笔成功，但第三笔返回 deadline exceeded。

`TestRealLocalMultiBatchLateConflictRollsBackThenAcknowledgesPrefix` 修前输出 `fallback n=2 ... context deadline exceeded`，耗时 15.90s。日志 `/tmp/dataengine-batch-real.log`。预期为 ErrProjectionConflict、确认前两笔、保留失败及后继记录，所有文档停在版本 2。

```sh
source /tmp/roost-dataengine-it/env.sh
GOCACHE=/tmp/roost-nest-go-cache GOWORK=off go test -race -tags=integration ./kit/dataengine \
  -run '^TestRealLocalMultiBatchLateConflictRollsBackThenAcknowledgesPrefix$' -count=1 -v
```

根因在原多文档 Project/applyPut 路径；本轮新批量降级测试暴露它，不是批量 Mongo 事务部分提交。未观察到部分落库或数据丢失。
