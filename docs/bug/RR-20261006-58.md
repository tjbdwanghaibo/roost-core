# RR-20261006-58：工程在仓库子目录时 `generate --changed` 几乎不跑生成器还报成功

2026-10-07，基线 `a9c211e9`。P2（改过的定义没有重新生成，命令报成功，之后 `--check` / CI 才发现）。来源：框架文档审查 F12 G3（[12-codegen 实现](../framework/impl/12-codegen.md) §11 G3）。
状态：已复现；已修复（`a461ee2f`，[修复](../bugfix/RR-20261006-58.md)），未发版。

## 机制

1. `gitChanged` 取 `git status --porcelain --untracked-files=all` 的路径（基线 `codegen/internal/roost/generate.go:590-609`）；porcelain v1 的路径**相对仓库根**，带空格等的路径被引号包住。
2. `filterChanged` 拿它和相对**工程根**的前缀（`db/def/`、`protocol/def/` …）比较（`:611-631`）：工程在子目录时 `sub/proj/db/def/x.go` 永远不匹配，除 `Always` 的 registry 外全部被过滤。
3. rename 只取 `->` 右侧：定义文件移出生成器输入时，该生成器不会运行去回收旧产物。
4. 两个函数都没有用例。
