# NC-51：activity sweep 对已确认 Keys 不校验键合法 / 归属，跨组键被并入本组 Delivering 后永久残留

2026-10-05，基线 `50e9a4e8`。P3（潜伏：本包从不写出这种条目，只有存量坏记录 / 人工修复写错组时触发）。状态：已复现、已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-51.md) · [本轮](../review/REVIEW-2026-10-05-n06-revn06.md)。

RR-20261001-09 残余（10-05 第 27 轮）给 `AdvanceExpired` 的 **Opening** 条目加了“键合法且属于本组才读写 Activities / 其他窗口”的边界；同一函数里的 **已确认 Keys** 循环（`kit/service/global/activity/service.go:787-802`）没有：它对窗口里任何键直接 `Activities.Get`，complete 的进 heal + prune，collecting 且过期的由本组 sweep `completeExpired`。于是 group-a 窗口里混进 group-b 的键时：

1. group-a 的 sweep 按自己的时钟结算 group-b 的活动并建派发（写别的组的数据）；
2. 该键被并入 **group-a** 的 Delivering；
3. `RetireDelivered`（`:450`）按键自身的 GroupID 更新 **group-b** 的窗口（`:475`），对 group-a 无操作却返回 `true`；group-a 的 Delivering 永远留着它，每 20s 一轮活动 / 派发读取与窗口写。

非法键（如空 ActivityID）则因 `Get` 读不到被直接剪掉——与 Opening 的“跳过、保留给运维”策略不一致。

探针另证：跨组键进 group-a Delivering 后，三轮 `RetireDelivered` 均 `ok=true`，group-a `Delivering:[group-b/x/close]` 不变。

影响：坏记录下跨组写与永久残留 / 周期性无效 I/O；不阻塞本组其他活动、不丢派发。没做：已有 Delivering 残留不自动清（需运维），`RetireDelivered` 返回值“未在该窗口也报 true”的语义只记观察；真实 Redis / Cluster 未跑（纯窗口逻辑，Memory 足以判定）。

## 复核后的补修（2026-10-06，维护者决定 B9）

NC-51 只补了 `AdvanceExpired` 的已确认 Keys 循环；同一不变量在相邻读者里仍没有成立（N06 S3 留项、观察 4，基线 `4f0bab75`）：

1. `DeliveringActivities` 原样交出 Delivering 里别的组 / 不合法的键，sweep 对它们读活动、读派发，再由 `RetireDelivered` 按键自身的 GroupID **写别的组的窗口**；本组那一条永远移不走（本条主记录“探针另证”的那一半）。
2. `PendingActivities`（Coordinator RPC，game 可调）原样交出 Keys / Opening 里的坏键。
3. `RetireDelivered` 对“键不在 Delivering”也回报 true。
