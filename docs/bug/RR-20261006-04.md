# RR-20261006-04：文件 outbox 不清理崩溃遗留的 `outbox-*.tmp`（O6，资源泄漏）

2026-10-06，基线 `8a292a5a`。P3（资源泄漏：每次写入中途崩溃留一个临时文件，不计入 `MaxRecords`，永不回收）。来源：N09 第二批 O6（[记录](../review/REVIEW-2026-10-05-n09-batch2.md)），收尾第 3 批 A6 登记。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261006-04.md)。

## 机制

- `skill/skillsync/file_outbox.go` `PutRecord`：`os.CreateTemp(dir, "outbox-*.tmp")` → 写入 → fsync → `replaceFile`（unix `os.Rename`，windows `MoveFileExW(REPLACE_EXISTING|WRITE_THROUGH)`）→ 目录 fsync；只在本次调用失败时 `defer` 删除自己的临时文件。
- 进程在写入与替换之间崩溃时临时文件留在目录里；`NewFileOutboxStoreWithOptions` 与 `LoadRecords` 只看 `.packet`，从不扫描 `.tmp`。unix 与 windows 两份实现在这一点上相同（差别只在替换与目录 fsync）。

## 触发与差异

目录里有 `os.CreateTemp` 生成的 `outbox-<数字>.tmp`（写了一半、未替换），重新打开 store：预期遗留文件被删除、其他文件不动、记录照常装载；实际遗留文件一直在。

## 复现

`TestFileOutboxOpenRemovesCrashLeftoverTemporaryFiles`（`skill/skillsync/file_outbox_tmp_cleanup_promises_test.go`）修前：

```
--- FAIL: TestFileOutboxOpenRemovesCrashLeftoverTemporaryFiles (0.03s)
    file_outbox_tmp_cleanup_promises_test.go:67: crash leftover outbox-2862453243.tmp survived reopening the outbox (stat err=<nil>)
```

## 修复

[修复记录](../bugfix/RR-20261006-04.md)：打开 store 时删除确认是本 outbox 生成的临时文件。
