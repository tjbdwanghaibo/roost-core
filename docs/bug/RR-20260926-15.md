# RR-20260926-15：同一 SessionID 关闭后立即重开，AsyncTransport 把新会话绑到正在注销的旧队列上，新会话被当作传输失败静默丢弃

**当前状态：已修复并完成适用本地验证，未提交/发布。** 见[修复与边界](../bugfix/RR-20260926-15.md)。以下保留原审查基线。

日期：2026-09-26。基线：main `aaada47`。等级 P2（重连后客户端收不到同步；若业务重连沿用同一 SessionID 且先 Close 后 Open，则每次重连都可能命中，建议上线前修复）。
状态：已复现（复审方二次实跑 5 次中 3 次；审查 agent 5/5），未修复。与已修复的 RR-20260925-10（Manager 层继承旧订阅）不是同一问题。

## 触发条件

生成工程的正式链路：`entitysync.AsyncTransport` 包 `nettransport.AsyncTransport`（`codegen/internal/roost/render.go:210`）。
先 `CloseSession(id)`（含会话因传输失败被 loseSession 关闭），再用同一 id `OpenSession`。

## 预期 vs 实际

预期：新会话正常收帧；否则 `OpenSession` 返回错误。

实际：`RemoveSession` 只异步取消旧队列（`sync/nettransport/channel.go:200-211`，`queue.cancelNow()`），旧条目要等 worker 退出的 `workerDone`
才从 map 删除（`:510-518`）。在此之前 `RegisterSession` 返回 `ErrSessionAlreadyExists`（`:174-175`），`sync/entitysync/transport.go:79-80` 把它当成功吞掉。
新会话于是绑定在正在关闭的旧队列上，或旧队列删除后新队列根本没注册；随后第一次 Push 得到 `ErrSessionNotRegistered`，会话被 loseSession 并触发 SessionLost。
`OpenSession`、`Flush` 都返回 nil，全程静默。

## 复现

探针源码见 [REPRO-2026-09-26-02](REPRO-2026-09-26-02.md) §4。复审方 2026-09-26 在 `aaada47` 导出副本实跑 `-count=5`：3 次失败、2 次通过。

```text
GOWORK=off go test -race ./sync/entitysync -run TestProbeAsyncTransportSameIDReopen -count=5 -v
reopen err=<nil> subscribe err=<nil> flush err=<nil>; SessionLost calls=1; downstream sends=1; SessionsLost=1
reopened session with the same id was lost by the transport          （失败 3 次）
reopen err=<nil> subscribe err=<nil> flush err=<nil>; SessionLost calls=0; downstream sends=2; SessionsLost=0   （通过 2 次）
```

审查 agent 另一轮输出 `downstream sends=0`（新会话一帧未发）。

## 实施方向（约束）

- 同 ID 重开必须与旧队列的注销有明确先后：等旧队列真正移除后再注册，或让注册识别“正在关闭”的旧条目；不能把 `ErrSessionAlreadyExists` 一律当成功。
- 不在快池阻塞等待（roost-coding）；保持会话失败为终态、字节额度只归还一次。

## 验收覆盖点

- Close 后立即同 ID Open：新会话收到帧，无 SessionLost；`-race -count` 多次稳定。
- 真正的重复注册（旧会话仍活跃）仍返回错误或按契约处理。


## 2026-09-26 修复更新

已按当前源码核实并修复，适用本地回归通过；原始审查证据保留。见[修复记录](../bugfix/RR-20260926-15.md)。复用 SessionID 的调用者应在旧发送退出后重试，或为新连接分配新 ID；不在快池等旧发送。
