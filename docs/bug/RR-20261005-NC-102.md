# NC-102：mongotest 唯一索引把数组当一个值比较，放过真实 Mongo 会拒绝的重复，也误报真实 Mongo 接受的写入

2026-10-05，基线 `be7bcc18`。**P3**（替身与后端语义差异；当前生产唯一索引都是标量字段，定级低是因为没有生产触发路径）。状态：**已复现（真实 Mongo 8.0.28 副本集对照），未修复**。[本轮](../review/REVIEW-2026-10-05-n04-revn04.md)。

## 触发、预期与实际

真实 Mongo 的唯一索引在数组上建 multikey：每个元素各一个键；路径穿过文档数组时取每个元素的子字段。`mongo/mongotest/mongotest.go:978-1031`（基线）`uniqueKey` / `checkUniqueFieldsLocked` 用 `lookupPath` 取整个值、`valuesEqual` 最后以 `fmt.Sprint` 比较；源码注释自己写着 “Array values (multikey) are still compared whole, not per element”——只有范围说明，替身仍给出判定。

隔离副本集对照（同一 `fmongo.IndexModel{Unique: true}`、同序写入）：

| 用例 | 真实 Mongo | mongotest |
| --- | --- | --- |
| `tags:[1,2]` 后 `tags:[2,3]` | ok, dup | ok, ok（放过重复） |
| `tags:[1,2]` 后 `tags:2` | ok, dup | ok, ok（放过重复） |
| `m:[{n:1}]` 后 `m:[{n:2}]`（索引 `m.n`） | ok, ok | ok, dup（误报） |
| 数组无交集 / 自身重复元素 / 文档数组共享子值 / 内嵌文档字段顺序 / int32 与 double / 空数组与缺字段 | 一致 | 一致 |

按[组合契约复核](../agent-skills/roost-coding/references/fix-contract-review.md)第 3 条，替身放过真实后端会拒绝的数据要登记缺陷或明确拒绝不支持的场景。

## 影响

生产唯一索引（`saga/mongo_store.go:74`、`saga/dataengine_step_inbox.go:112`、`dataengine/engine/mongo_store.go:116`）都是标量字段，game-demo 模板测试里的 mongotest 用法不在数组上建唯一索引，所以当前没有测试因此误绿。新增“唯一索引里含数组字段”的模型时，测试会在 mongotest 上通过、生产撞 11000（或反过来）。

## 验收覆盖点

唯一索引路径上出现数组（终值或中间容器、单键或 compound、写入 / 更新 / 建索引扫描存量）时明确返回 `ErrUnsupported`；标量重复、索引外数组、既有 null / sparse 语义不变。没做：实现 multikey 语义本身。
