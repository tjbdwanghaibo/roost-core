# RR-20260930-24：game-demo 活动租约丢失后永不重取，`activity: lease not renewed` 每 5s 一条直到停机

日期：2026-09-30。基线：main `fdba6c55`。来源：B27 第 3 批真实环境端到端（`drill-rr02.sh` / `drill-rr23.sh` 里 `SIGSTOP` game > 30s 后观察到）。等级 **P3**：进程停顿超过活动租约 TTL 后活动系统对该 game 永久失效（不再 sweep / 发放），只告警不自愈；同一次停顿里 etcd `Discovery: lease lost` 1s 后就自动重注册，形成对照。状态：**已确认，未修复**。

## 触发条件、预期与实际

- 触发：game 进程 `SIGSTOP` > 30s（`DefaultLeaseTTL`）后 `SIGCONT`。
- 预期：续租失败发现租约过期后重新 `AcquireLease`（无人持有就重取，有人持有就退到 standby 并继续尝试），日志给出一次性的状态变化。
- 实际：`WARN activity: lease not renewed game_sid=1300 err="remote.570108: global: lease has expired"` 每 5s 一条持续到停机，活动租约再也不属于任何进程。

## 根因（到行）

`internal/service/game/activity.go`（模板 `demo/internal/service/game/activity.go.tmpl`）`renewLease` 对续租错误只 Warn，没有区分“租约已过期”与瞬时错误，也没有重新 `AcquireLease` 的路径。

## 附带观察（不单独登记）

`kill -9` 后 30s 内重启，Init 失败于 `activity: acquire lease for game 1300: remote.570110: global: conflict`（旧租约未到期），`run.sh start` 不重试，第 4 次（+34s）才成功；失败的启动已把 saga Mod 起过。修复时看是否让 acquire 在 Init 里等到 TTL 到期或改为启动后异步获取。

## 修复约束

- 续租错误分类：`lease has expired` / 不持有 → 重新 acquire（成功则恢复 owner 角色、失败则按 standby 周期重试）；瞬时错误 → 下一周期再续。日志只在状态变化时打。
- 回归：模板测试用可控时钟 / 替身让租约过期，断言重取成功后 sweep 继续。
