## 现象

外层 RollbackState / RollbackUndo 事务里，`RunIsolatedTransaction` 不经 `MarkPersist`，直接 `CurrentRollbackTx().AddMutation(...)`
写外层已快照的声明实体。嵌套事务照常提交（1 条持久记录）；外层随后失败回滚：state 外层把内存值恢复成 1，持久是 100，分叉。

## 根因（`d4234c9` 源码；codebase-memory 图谱停在 09-26，已过期，以下来自源码）

- `nest/rollback.go:297-323` `AddMutation` 是导出方法，把原始 mutation 直接追加到 `tx.mutations`，不登记 DAO 参与方。
- `nest/rollback.go:618-645` `refuseWriteUnderEnclosingRollback` → `restoresWriteOf` 只遍历 `tx.participantOrder`（`MarkPersist*` 登记的 DAO），
  原始 mutation 不在其中，检查放行；`durableCommit`（`:589`）随后把记录交给 committer。

## 修复约束（清单 §H C06 推荐，维护者 2026-09-27 决定按推荐执行）

与 RR-74 同一“拒绝”：嵌套独立事务的原始 mutation 按 EntityID 命中外层已快照的实体时，同样返回 `ErrNestedTransactionRollbackConflict`，
拒绝发生在写任何持久记录之前；RR-74 的 memory 外层行为不变；仓内生产调用 `nest/msg.go:57`、`nest/persist_change.go:304` 不受影响。
