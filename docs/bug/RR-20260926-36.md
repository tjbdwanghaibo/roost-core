# RR-20260926-36：冷登录等待投影无超时——投影持续失败时登录挂起、占连接槽，重连累积直至耗尽

日期：2026-09-26。基线：v1.17.0（`8811c02`）。等级 P2。状态：已复现，未修复。RR-10 修复后的新行为。
（最终状态见文末修复节：**已修复，随 v1.17.1 发布**，详见[修复记录](../bugfix/RR-20260926-36.md)。上面的“状态”是登记时的原值，保留不改。——2026-09-27 回写，OPEN-ITEMS A13②）

## 根因

生成 demo `enter_game.go.tmpl:57` `GetOrCreate(context.Context(), …)` 的 ctx 为 `codegen/internal/roost/render_player_tcp.go:660` 的 `connectionCtx`（仅 server 停止时取消）→
`entity/manager_access.go:85-110` → `dataengine/engine/entity_repository.go:112-118` → `Projector.WaitEntityProjection`（`entity_projection.go:70-95`）；投影器无限退避（`projector_replay.go:198-226`）。
连接读循环（`render_player_tcp.go:698-714`）同步 Dispatch，挂住期间不读 socket、占 connectionSlots 与按 IP 计数；`session` 无 cancel（`:827`），重连 `registerSession`（`:745`）只关旧 conn。

复现：[REPRO-2026-09-26-04](REPRO-2026-09-26-04.md) §4 `after 2s: wait still blocked, store attempts=132 fatal=<nil>`。

## 修复约束

预算放在正式生成传输层：每次 Dispatch 派生有截止的 ctx（新增配置项，默认与 `nest.request_timeout` 对齐），`session.Close` 取消本连接 ctx；EnterGame 的 Claim + GetOrCreate 另给登录预算。
不在 demo 特判；等待方超时离开不取消共享加载 flight（现状满足）。

## 修复（2026-09-26）

已修复，按上方修复约束实现，见[修复记录](../bugfix/RR-20260926-36.md)。生成 TCP 传输每次 Dispatch 派生 `player_access.tcp.dispatch_timeout`
截止的 ctx（缺省取 `nest.request_timeout`，生成配置 3s），`session.Close` 取消本连接 ctx；EnterGame 的 Claim + GetOrCreate 另用
`player_access.tcp.login_timeout`（生成配置 2s，须 ≤ dispatch），超出回 `login_timeout`（100021）。共享加载 flight 未改（等待方离开不取消）。
生成工程回归修前红、修后 `-race -count=10` 绿；已本地提交，未推送/发布。
