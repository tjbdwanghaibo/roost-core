# RR-20260925-12：现有对象全量刷新被冷恢复预算阻塞

日期：2026-09-25。基线：main `646ce63` 加此前快照调度优化工作树。
等级：P2。状态：已定位并修复，验收见[修复记录](../bugfix/RR-20260925-12.md)。

触发：会话已收到实体，随后 Profile 变化、撤回尚未交付的 remove，或 RetryLater 后需要
全量修复；同时新对象快照预算已耗尽。订阅进入 kindSnapshot，但客户端引用仍存在，
线上应该发送 ObjectUpdate + Full。捕获预选和准入却仅根据 kindSnapshot/entryCreate
限流，现有对象因此停在旧视图，和首次入场快照一起等待。

预期：新对象恢复预算保护客户端对象创建突发；已经持有对象的视图替换应走更新路径，
保留 Full 内容并受帧硬上限和可靠队列背压约束。实际：额度不足时连现有对象更新也不发送。
此处明确收窄恢复预算语义，原有总量治理由传输队列负责，不把全部 Full 内容都当成新建对象。

确定性复现：

```bash

  -run TestExistingObjectRefreshDoesNotWaitForColdSnapshotBudget -count=1
```

实体 1 的 Full 更新并继续延后实体 2。修前三个子场景（对象数、字节数、每会话额度）
全部报告 `existing object refresh waited for cold snapshot budget: frames=0`。
