# NC-211：施法先结束、area 进程已移交后，回调里的 `finish` 让 Advance 返回 ErrProgramInvariant 并中断这一 tick

2026-10-05，基线 `c10cc9ac`。P2（编译通过的定义在运行期触发不变量失败；Advance 在 tick 中途返回，同一 tick 余下的 owned 进程与排程任务被推迟到下一次 Advance）。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-211.md)。[本轮](../review/REVIEW-2026-10-05-n09-batch4.md)。

## 触发与差异

编译期：spawn 出的 area 进程（entity 作用域）回调允许 `finish`——`compile_owned_entity.go:30-31` 的 `allowAreaFinish`，`:159` 只对 `cancel` 回调例外。语义见 `TestAreaCallbackFinishStopsRemainingSignals`：finish 结束拥有它的施法，并停止本 area 余下的信号。

运行期：施法自己先结束时（enter 里 spawn 之后直接 finish，或 wait 比 area 短），`beginCastRecovery → handoffEntityProcesses`（`process_owned.go:195-237`）把仍在运行的 entity 进程标为 `handedOff` 并移到 `ownedProcesses`。之后成员进入 / 离开 / 停止时的 leave 回调再执行 finish，`runOwnedProcessCallback`（`process_owned.go:449-457`）：

```go
if control.kind != flowContinue {
	if control.kind != flowFinish || template.area == nil || process.handedOff {
		return ErrProgramInvariant
	}
```

错误经 `dispatchOwnedProcessSignals` → `advanceOwnedProcesses` / `terminateProcess` 一路返回到 `Advance`（`scheduler.go:268-311`）：host 已推进、`currentTick` 已更新，同一轮里排在后面的 owned 进程没有 step、到期排程任务没有执行。出错的进程随后被停止，下一次 Advance 能继续，但这一次调用以不变量错误失败。

## 复现

`area_membership.json` 把 `wait 2 then finish` 改成直接 `finish`、area 加 `emit_leave_on_stop: true`（leave 回调是 `finish`）：编译零诊断，`Activate` 成功、施法 finished、owned 进程 1 个；`Advance(2)`（area 到期，停止时发 leave）返回 `skill: immutable program invariant failed`。在 fixture 变异属性测试里加入这个种子（`seed.area_handoff`），种子本身和它的大部分编译通过的变异（约 200 个）都触发同一错误。

正式回归（修前）：

```
--- FAIL: TestHandedOffAreaFinishEndsOnlyTheAreaProcess/leave_after_handoff
    Advance(2) = skill: immutable program invariant failed; a compiled area finish must not fail the runtime
--- FAIL: TestHandedOffAreaFinishEndsOnlyTheAreaProcess/enter_after_handoff
    Advance(1) = skill: immutable program invariant failed; a compiled area finish must not fail the runtime
```

控制 `TestLiveAreaFinishStillFinishesTheCast`（施法存活时 finish 结束施法）修前通过。

## 影响

“陷阱 / 光环在某个成员离开时结束”这类定义，只要施法比 area 先结束（最常见的写法：spawn 后立即 finish），运行期就会让宿主的 `Advance` 报不变量错误。宿主若把 Advance 错误当致命错误处理（不变量失败通常应如此），整场对局因一个编译通过的技能中止。

## 验收覆盖点

移交后的 leave / enter 回调 finish 不再让 Advance 出错，只结束本 area 进程（余下信号停止、进程被回收）；施法存活时 finish 结束施法的既有语义不变。

## 实施方向（约束与候选）

A. Runtime：移交后（或拥有者施法已终态）的 finish 没有施法可结束，按“area 回调完成”处理——停止本 area 余下的信号并停止进程，与施法存活时的规则一致。
B. 编译期：禁止 entity 作用域 area 回调里的 finish——会拒绝 `area_membership.json` 等施法存活时合法的写法，不取。
