# RR-20260927-15：非 authority 兼容装配里，已提交 Remote 事务的迟到重放在同一 fence 下把活实体的 StateVersion 写回旧值

日期：2026-09-27。基线：`d4234c9`（v1.17.1 之后）。来源：[OPEN-ITEMS-2026-09-27](../review/OPEN-ITEMS-2026-09-27.md) C32
（[v1.17.0 triage §核实后判为非问题](../review/REVIEW-2026-09-26-v1170-triage.md) RR-11 项的“残留加固：同 fence 下拒绝 StateVersion 回退”）。
等级 P3：只影响 ownership store 不实现 `WriteAuthority`（没有 `GrantWrite`）的兼容装配；正式 kit 装配（`MongoCommitter` 权威）每次写递增 fence，不受影响。
状态：已复现，已修复（见[修复记录](../bugfix/RR-20260927-15.md)）。codebase-memory 图谱过期（09-26），本记录以当前源码为准。

## 触发条件

1. 兼容装配：`Manager.SetOwnershipStore` 给的是不实现 `WriteAuthority` 的 store，本节点独占写（非 marked）。`remoteentity/batch.go:296`
   （`d4234c9`）在这种装配下沿用实体当前的 `LockFence`，fence 不随写入递增。
2. 已提交事务 tx1（Base 0 → Next 1）的迟到重放（投影器重试 / outbox 回放 / finalizer 发布）进入 `acknowledgeRemoteCommit`
   （`remoteentity/transaction_manager.go:1176` 起）：`:1182` `remoteReceiptObsolete` 在活实体版本恰等于 `NextVersion` 时判“未过期”。
3. 判定之后、`:1187` `SetRemoteVersionVector` 之前，同实体的下一笔 tx2 在同一 fence 下提交，活实体版本推进到 2。

## 预期与实际

- 预期：迟到重放不改变已被更新事务推进的版本向量（与正式装配里旧 fence 被拒绝后重新判为过期一致）。
- 实际：`entity/entity_remote.go:88` 只拒绝更小的 fence；同 fence、更小 StateVersion 被接受，向量从 `{StateVersion:2}` 写回 `{StateVersion:1}`。
  之后下一写者以 BaseVersion=1 准备，与权威（2）冲突被拒，实体需要重载才能恢复写入。

## 复现

`remoteentity/same_fence_version_regression_promises_test.go` `TestSameFenceReplayCannotRewindStateVersion`：替身实体在第一次 `SetRemoteVersionVector` 前停住，
让 tx1 的重放停在判定之后，其间 tx2 提交（前提断言两笔 fence 相同、版本到 2），再放行重放。`d4234c9` 上：

```text
same_fence_version_regression_promises_test.go:87: late replay of tx1 rewound the version vector under the same fence: {StateVersion:2 MarkerEpoch:1 LockFence:0 RouteEpoch:1} -> {StateVersion:1 MarkerEpoch:1 LockFence:0 RouteEpoch:1}
```

## 根因

`RemoteEntityBase.SetRemoteVersionVector`（`entity/entity_remote.go:82-96`，`d4234c9`）的单调性检查只看 `LockFence`；`acknowledgeRemoteCommit` 的
“再次核对”（`:1189`）只在 Set 返回错误时执行，同 fence 回退不报错，核对不会发生。

## 修复约束（清单推荐，维护者 2026-09-27 决定按推荐执行）

同 fence 下拒绝 StateVersion 回退；只影响非 authority 兼容装配。不放宽 stale fence 拒绝，不改变正式装配的行为。
