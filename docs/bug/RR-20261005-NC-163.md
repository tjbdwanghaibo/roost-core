# NC-163：robot 的 websocket 拨号不看 ctx 与 DialTimeout，握手不回时 connect 永远不返回、Stop 也停不下

2026-10-05，基线 `45d4bc1c`。**P3**（压测工具可用性：机器人卡死、取消无效）。状态：**已复现，未修复**。[本轮](../review/REVIEW-2026-10-05-n12-revn12.md)。

## 触发、预期与实际

- 触发：`transport.Config{Type: "ws"}` 指向接受 TCP 却不回 HTTP 升级响应的端点（把 ws 机器人指到 TCP 玩家端口、网关卡住、黑洞代理）。
- 预期：`Config.DialTimeout`（`Normalize` 缺省 5s）与 `Dial(ctx, …)` 的 ctx 约束整次拨号，和 tcp 拨号一致。
- 实际：`dialWebSocket(_ context.Context, …)`（`robot/transport/transport.go:153-169`，基线）丢掉 ctx，用 `websocket.DialConfig`（内部 `context.Background()`），没有任何超时；握手无限阻塞。

```text
dial_bounds_promises_test.go:78: websocket dial still blocked after 3s (ctx 1m0s, DialTimeout 200ms): the handshake ignores both
dial_bounds_promises_test.go:78: websocket dial still blocked after 3s (ctx 200ms, DialTimeout 1m0s): the handshake ignores both
```

## 根因

x/net v0.58 已提供 `Config.Dialer` 与 `Config.DialContext(ctx)`，实现没有使用；参数名 `_` 直接说明 ctx 被丢弃。

## 验收覆盖点

DialTimeout 或 ctx 先到期都让拨号在期限内返回错误；正常 websocket 端点仍能握手并往返一个包。
