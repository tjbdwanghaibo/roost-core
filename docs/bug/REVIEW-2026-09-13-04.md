## RR-20260913-08：权威读取仍可返回过期快照

U-0175 在 [entity/remote_snapshot.go](../../entity/remote_snapshot.go):257 起检查 layered.Get 返回值的 Expired，修好了 Cached 命中的原触发；这部分有效。

但同文件的以下出口不经过该检查：

- Get 的 Linearizable 分支 :251 直接返回 LoadAuthoritative。
- Monotonic miss/expired 分支 :268 返回 loadMonotonic，后者返回 LoadAuthoritative 的结果。
- LoadAuthoritative :230–240 调用 loader、Publish 后直接 local.Get 返回，没有 expiry 验证。

**新增确定性验证：** loader 返回已过期但其他字段合法的快照，分别以 Monotonic 和 Linearizable 调用公开 Get。两者都返回 found=true、err=nil，且结果 Expired(now)==true。这不是绕过公共 API 的裸缓存实验。

另一个恢复交错：先缓存一份过期值；loader 返回同版本/同内容但新的未来有效期。Publish 的同版本去重分支忽略过期元数据而直接返回 nil，LoadAuthoritative 再读旧 L1，最终仍返回过期值。产品可以决定是否允许同版本延长有效期，但无论选择拒绝还是接受，都不应成功返回已经过期的旧快照。

```text
mode=1 returned expired authoritative snapshot
mode=3 returned expired authoritative snapshot
fresh authority result replaced by expired same-version L1
```

影响与原 RR-08 相同，故保留编号，修改状态为部分修复，不另造重复问题。bugfix 原文中“它们最终都要经过 Get，所以行为一致”的说明与当前提前返回路径不符；本轮保留用户原文，在这里追加核验结论。

建议：统一所有对外 read 结果的有效期后置条件；包括 loader 原始值与实际被 Publish 保留的 L1 值。拒绝/返回 miss/回填应有界，避免持续过期的权威响应造成无限递归。补齐 Cached、Monotonic、Linearizable、直接 LoadAuthoritative 与同版本元数据策略测试。
