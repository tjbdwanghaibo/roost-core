# NC-263：日志轮转打不开新分片时整行丢失；控制台写失败时文件也收不到；两者都没有计数

2026-10-06，基线 `dc877c04`，分支 `revleft`（N11～N13 留项与小防护）。**P3**。来源：N12 观察 O6。状态：已复现，已修复（见文末）。[本轮](../review/REVIEW-2026-10-06-revleft.md) · [证据](../bugfix/evidence/noncore-bugfix-20261006-revleft/README.md)。

## 触发与差异

1. `log/rotation.go` `Write`（基线 :56-66）：`rotateLocked` 打开新分片失败（EMFILE、ENOSPC、目录权限）就返回错误，这一行丢弃——即使当前分片仍可写；并且之后每一行都重试一次 `MkdirAll + OpenFile`。
2. `log/log.go` `Init`（基线 :89-92）：控制台和文件同时配置时用 `io.MultiWriter`，它在第一个写失败处停止；控制台排在前面，控制台出错时文件也收不到这一行。
3. slog 吞掉 handler 的写错误，丢行在任何地方都看不到。

- 预期：一个 sink 出错不影响其余 sink；轮转失败时继续写当前分片并限频重试；失败可数。
- 实际：见上。触发：轮转时刻文件描述符耗尽 / 磁盘满 / 日志目录权限被改；控制台是已关闭的管道或 `log.output` 指向出错的 writer。
