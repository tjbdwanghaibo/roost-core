# NC-142：ScheduleActivityPhase 对已过期截止时间报告“已武装”，实际什么都没武装

2026-10-05，基线 `23f82dbccfd5171373470ab942f33177ed4f4eed`。P3（潜伏：唯一调用方 `openCurrentWindow` 只武装当前窗口，closeAt 总在 now 之后至少 1 秒；回归用例是空断言）。状态：已复现、已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-142.md)。[本轮](../review/REVIEW-2026-10-05-n11.md)。

## 触发与差异

`demo/game/entities/world/timer_component.go.tmpl:154-159`：`at` 不晚于 `now` 时把 `delay` 置 0，注释承诺“arm it for the next tick”；但 `timer.NewTimer` 对 `delay <= 0` 返回 0、不建节点（`timer/scheduler.go` NewTimer 首行）。方法仍返回 `(0, true)`：handler 回复“已武装”，堆和 DAO 里都没有节点，这个窗口的 close 阶段永不上报。

已有 `TestADeadlineThatIsAlreadyPastStillFires` 只断言 `armed` 与 Tick 后“剩余 0 个节点”——节点本来就不存在，所以它在缺陷上通过。

## 复现

生成工程 `TestAnOverdueDeadlineIsArmedAndFires`（过期一小时、恰好到期两叶）：

```
timer_rollback_test.go:131: ScheduleActivityPhase reported armed with node id 0
timer_rollback_test.go:134: reported armed, but no node is pending: the window this deadline closes is never reported
```

## 约束

在模板里把过期截止时间武装成最小正延迟（持久化以毫秒存，取 1ms），下一次 Tick 触发；不改 `timer.NewTimer` 对非正延迟的拒绝契约。同时把空断言的旧用例改成断言节点存在与 effect。
