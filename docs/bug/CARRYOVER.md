### A→结案：判为非缺陷，不做

| 原 # | 条目 | 判定理由 |
| --- | --- | --- |
| A3 | 毒药订单没有运维面；推后固定 15 分钟 | 两半都不是缺陷。索引条目上没地方记尝试次数 → 做指数退避要改存储格式，代价大于收益；固定 15 分钟是个合理的默认。真需要时是 feature |
| A4 | 空闲场景不重试被拒的 subscribe | demo 没有场景级定时 tick 是**模板的有意简化**。重试搭下一次场景事件的便车，在一个有人在玩的场景里就是够的；空场景里没人需要那份订阅 |
| A5 | 租约没有世代号 | 现行近似（"有没有间断"代替"中间有没有人写过"）是**安全方向的**近似：代价是偶尔多扔一份没人碰过的副本，也就是一次冷加载。世代号要改 Redis 的值格式，为省一次冷加载不值 |
| A9 | 活动窗口未开时贡献被静默丢弃 | 丢点本身是有意的（一个窗口少一点不是失败的副本），缺的只是一个指标。**可观测性缺口，不是缺陷**。想加就加，一行 `metrics.IncCounter` |
| A10 | demo-publish 的发布内容变了 | U-0274 里已经写清楚的取舍，并且 README 里对读者说明了。要恢复原路径需要带 `workflow` scope 的 PAT——那是账号决定，不是代码问题 |
| A11 | 测试侧的重复要不要收敛（`fakeBus` ×2、`assertWALReplay*` ×2、errcode 契约 ×8） | **判为不收敛**，并且理由要留下来：共享一份替身，就是把"替身比实现更宽容"的风险集中到一处。这个仓库栽过这个跟头（`snapshotRedisFake` 用 Go 的 `ParseUint` 比 Lua 的 `tonumber` 精确，`markerEvalStub` 同理，两个跨语言缺陷因此长期不可见）。逐字相同的两份替身，代价是改两次；共享的一份，代价是两边一起瞎 |
| A13 | 同层内的小工具重复（`snakeCase`×2、`isNilInterface`×2、`toSnake`×4、`parseKV`×2…） | 均早于合仓，都是十行以内的纯函数，没有一处因为漂移出过问题。收敛它要跨层加一个 util 包，那比重复本身更贵 |
