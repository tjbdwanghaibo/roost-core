# RR-20261006-31：移交后的进程停止被宿主拒绝时，Runtime 的 tick 停在原地，所有施法一起冻住

2026-10-06，基线 `90c92caf`（main）。P2（宿主一次停止失败，这个 Runtime 上全部施法、被动、owned 进程停止推进，直到宿主恢复；宿主一直失败则永久冻住，期间每次 `Advance` 都打一次宿主）。来源：RR-20261006-21 后续（Runtime 重试停止）实施中核对 `failCastLocked` 之外的停止失败路径。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261006-31.md)。

## 机制

- tick 驱动的停止：`advanceOwnedProcesses`（`skill/process_owned.go`）里移交后的进程到期 / lifecycle 失效（`reapInvalidOwnedProcesses` → `terminateOwnedProcess`）、步进失败（`failOwnedProcess`）、area 回调 finish，以及未移交 entity 进程的 lifecycle 消失（`reapUnhandedEntityProcesses` → `terminateProcess`）。
- 宿主 `StopProcess` 出错时这些路径把错误一路返回 `Advance`；进程仍是 running、仍到期，仍在 owned 表里。
- 下一次 `Advance(t+1)`：`nextOwnedProcessTick` 报告这个进程在当前 tick 到期，循环先走 `advanceOwnedProcesses`（`skill/scheduler.go` `Advance` 的 `else if ownedFound && ownedDue <= runtime.currentTick` 分支），再次停止、再次失败、再次返回——`advanceHost` 永远走不到，`currentTick` 不动，排程任务与其他 owned 进程都不推进。

## 触发 / 预期 / 实际

- 触发：tap 技能召出寿命 4 tick 的召唤并立即 finish（进程移交），宿主前三次 `StopProcess` 失败；逐 tick `Advance(1..8)`。
- 预期：失败那一次 `Advance` 返回错误，之后 Runtime 照常前进，停止交给有界重试（维护者 2026-10-06 决定：技能自己启动的东西由技能自己收尾）。
- 实际：`Advance(4..6)` 全部返回错误、`currentTick` 停在 4，宿主在同一 tick 被连打四次；第四次停止成功后才恢复。宿主一直失败时永久冻住。

## 复现

修前代码上的探针（与修复提交里的 `TestHandedOffProcessStopFailureDoesNotFreezeTheRuntime` 同一场景，宿主失败 3 次；`stopRetryHost` 见 `skill/runtime_process_stop_retry_promises_test.go`）：

## 可达性

任何带 owned 进程（summon / area）的技能，宿主在进程到期或 lifecycle 失效时 `StopProcess` 出错即触发。`Shutdown` / `RemoveProgram` 的停止失败由调用方重试，不在此列。
