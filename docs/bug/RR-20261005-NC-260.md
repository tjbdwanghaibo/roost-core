# NC-260：Mongo 客户端已断开时 Mongo Mod 的 Stop 永远失败（mongo-driver Disconnect 不幂等）

2026-10-06，基线 `dc877c04`，分支 `revleft`（N11～N13 留项与小防护）。**P3**。来源：小防护 B（与 NC-173 残余、NC-233 同类）。状态：已复现，已修复（见文末）。[本轮](../review/REVIEW-2026-10-06-revleft.md) · [证据](../bugfix/evidence/noncore-bugfix-20261006-revleft/README.md)。

## 触发与差异

`kit/mongo/mongo_mod.go` `StopWithContext`（基线 :116-133）只在 `client.Close` 返回 nil 时交出 client；`mongo/driver/client.go` `Client.Close`（基线 :103）直接返回 `mongo.Client.Disconnect` 的结果。mongo-driver v2.6.0 的 `Topology.Disconnect` 用 CAS 从 connected 切到 disconnecting，第二次调用返回 `ErrTopologyClosed`（对外包成 `mongo.ErrClientDisconnected`）。客户端一旦已经断开（别处关过一次），之后每次 Stop 都调 Disconnect、都得到 “client is disconnected”。

- 预期（[停机契约](../feature/REFACTOR-2026-10-05-shared-stop-contract.md)第 4 步）：资源已经释放的停止入口再调用返回 nil。
- 实际：永远返回 “client is disconnected”，调用方无法区分“还没释放”与“早已释放”。

正式调用方：App 每次停机只调一次 Mod 的 Stop，Mod 自己关的那次成功后会置空 client；没有生产触发路径（与 NC-233 相同定级）。仓内没有其他代码对 `fmongo.IMongo` 调 `Close`（`rg '\.Close\(ctx\)'` 核对）。驱动的 `Disconnect` 对各 server 断开时的 ctx 错误自己忽略，所以“首次 Close 因预算失败、重试必然失败”的 NC-173 形态在 Mongo 上不存在。
