# NC-112：失败的 toggle / hold / charge cast 不释放 policy 槽位，下次激活变成对失败 cast 的 toggle-off

2026-10-05，基线 `be7bcc1853020d9f744360d78831abd0ddf990a3`。P2（玩家的新激活不开始技能，却执行失败 cast 的 release 效果、起冷却；失败 cast 被改写为 finished 并永不回收；需要 policy 类 cast 的排程任务失败，仓内没有正式 Runtime 调用方）。状态：已复现，未修复。[本轮](../review/REVIEW-2026-10-05-n09-batch1.md)。

## 触发与差异

policy 类 cast 进入等待时登记 `activePolicies[caster, skill] = cast.id` 并置 `policyActive`（`runtime_cast_policy.go:13-17`）。排程任务失败走 `failScheduledCast`（`scheduler.go:479-485`）或通用错误分支（`scheduler.go:470-475`）：标 failed、撤任务、停进程、`markAbilityCastFinished`，**不调用 `releasePolicySlot`**。v1.5.0 修过 Cancel / Interrupt 不释放槽位（`releasePolicySlot` 的注释），失败路径没有跟上。

之后 `startLocked`（`runtime.go:378-386`）对 toggle 看到 `activePolicies` 里的失败 cast 仍 `policyActive`，调用 `releaseCast(active, "toggle_off")`；`releaseCast` 与 `Cancel` / `Interrupt` 只看 `logicalFinished` 和窗口阶段，不看 `status == CastFailed`，于是对失败 cast 执行 release 回调、起冷却、改成 finished，并把旧 ID 当作这次激活的结果返回。`castEvictableLocked`（`runtime_retention.go:60`）拒绝回收 `policyActive` 的 cast，失败 cast 在此之前一直滞留。

预期：失败终态释放 policy 槽位；任何外部 API 都不再对失败 cast 执行回调。

## 影响

失败的引导 / 开关技能之后，下一次激活被吞掉并打出 release 伤害、进入冷却；失败事实被覆盖为 finished，检查、同步与回放看到的终态与实际不符。
