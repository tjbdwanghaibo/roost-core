# RR-20260930-23：进程续租中断后重取租约，仍连着的玩家被当作过期副本丢弃，之后在场景里既看不见也不被看见

日期：2026-09-30。基线：main `fdba6c55`。来源：B27 第 3 批真实环境端到端（RR-20260927-23 / RR-20260926-70 的场景演练 `drill-rr23.sh`，两次一致）。等级 **P2**：Redis 分区或长停顿（> 30s 租约）恢复后，仍在线的玩家从此收不到任何同步帧、别人也看不到它，直到重新登录；`OnEntityLoaded → Rebind`（RR-20260927-23）在这条路径上没有效果。状态：**已确认，未修复**。

## 触发条件、预期与实际

- 触发：两个 game 进程；玩家 P、观察者 Q 都在 game1 的场景里；`SIGSTOP` game1 40s（超过 30s 租约），P 改在 game2 登录，`SIGCONT` game1；之后 P 回 game1 登录，Q 自己发 `move`。
- 预期：Q 的连接仍活着，续租中断恢复后 Q 要么被围栏并关闭连接（像 P 那样得到明确信号），要么重新绑定回场景继续收帧；P 重新登录的全量快照里有 Q，Q `move` 后 P 收到 create / delta。
- 实际：game1 记 `WARN player owners: lease had lapsed and was retaken; the stale copy was dropped`，Q 的连接没有被关，但此后 Q 收不到任何帧（P 的 remove、P 重新登录后的 create、两次 move delta、Q 自己 `move code=0` 的 delta 都没有）；P 重新登录的全量里没有 Q；Q `move` 后 P 也没收到 create。直到 Q 重新登录。

## 根因（到行）

`internal/service/game/playerowner.go`（模板 `demo/internal/service/game/playerowner.go.tmpl`）`renew` 的 default 分支 → `Claim` → `!continuous` → `dropResident` → `EvictPlayer` → `Destroy`：租约不连续时把常驻副本整个销毁，但没有关闭该玩家的连接、也没有把它重新绑定回场景（RR-20260927-23 的 Rebind 只在 `OnEntityLoaded` 触发，这里实体是被 Destroy 而不是重载）。

## 修复约束

- 二选一并写明理由：不连续续租后对仍在线的玩家做与围栏同样的处理（关闭连接、让客户端重连——语义最简单、与 P 一致），或者把重取租约后的副本按“重新加载”处理并触发 Rebind（要保证 stale 副本的状态不会覆盖 game2 已写的权威）。不得让连接活着却脱离场景。
- 复现脚本：`scratchpad/b27-batch3/drill-rr23.sh`（两个进程 + SIGSTOP），修后要能在模板测试或该演练上证明；演练输出抄进记录。

## 修复（2026-10-01）

状态：**已修复**（本地提交，未推送、未发版）。记录：[docs/bugfix/RR-20260930-23.md](../bugfix/RR-20260930-23.md)。

- 选方案 (a)：`PlayerOwners.renew` 取回租约（`case mine`）之后像围栏一样 `CloseSessions`，日志 `lease had lapsed and was retaken; the stale copy was dropped` 新增 `sessions_closed`；副本在预算内扔不掉的结局（`Claim` 错误包着 `errStaleCopyKept`）同样关连接。客户端重连走正常登录：`Admit` 已确认、无间断、不再扔副本，实体从 Mongo 冷加载后 `Join`。理由：与围栏 P 一致、语义最简单，且取回的前提就是副本已销毁，不会用 stale 副本覆盖 game2 写过的权威；(b) 做不到这个证明。关闭只在刷新循环，不在 `Claim`（登录路径的 Claim 会关掉正在登录的连接）。
- 红 → 绿：模板回归 `TestARetakenLeaseClosesTheSessionsThatLivedThroughTheGap` / `TestARetakeWhoseCopyCannotBeDroppedStillClosesTheSessions` 修前 `closed=[]` 失败；修后生成工程 `go test -race ./internal/service/game/` ok，`./codegen/internal/roost/` ok。
