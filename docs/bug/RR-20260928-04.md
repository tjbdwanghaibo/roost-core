# RR-20260928-04：stats_log 在容器 / systemd 里从不落盘也不告警

日期：2026-09-28。基线：本地 main `149eaac`。来源：批次 14 compose 实跑。等级 **P3**：运营统计日志静默丢失。引入：修前即有。状态：已复现（容器内运行 75 秒后 `/app/log` 不存在），未修复。

生成配置 `stats_log.dir: log` 为相对路径，容器里对应只读的 `/app/log`；`kit/statslog/statslog.go` 中 `_ = m.FlushOnce()` 吞掉写错误。systemd 部署 `ProtectSystem=strict` 同理。

修复约束：写失败不再静默（Warn + 低基数计数，必要时 Init 时校验目录可写并 fail-fast，二选一论证）；生成的部署物给 stats_log 一个可写位置（compose / k8s 挂可写卷或 `emptyDir`，systemd `StateDirectory` / `LogsDirectory`，或配置改为绝对路径），与 `read_only: true` 兼容；本机 compose 实跑验证文件落盘。

## 修复（2026-09-28）

状态：**已修复**（本地提交，未推送 / 发布）。修法与验证见 [修复记录](../bugfix/RR-20260928-04.md)：statslog 启动即探测、写失败 WARN（同一错误只告警一次）+ 计数 `stats_log.write_failures`，不 fail-fast；生成的镜像 / compose / k8s / systemd 各给相对的 `stats_log.dir`（`log`）一个可写位置，service 配置不变。本机 compose 实跑 10 个服务文件全部落盘。
