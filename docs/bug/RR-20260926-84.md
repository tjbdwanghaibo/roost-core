# RR-20260926-84：消息事务返回后、批次收尾前调用 RunIsolatedTransaction 被当成消息自己的事务

日期：2026-09-27。基线：本地 main `8d06d80`（RR-73～80 合并后，未推送）。来源：第四轮修复后独立审计（[REVIEW-2026-09-27-audit4](../review/REVIEW-2026-09-27-audit4.md)）。等级 **P3（潜在）**：仓内无调用方。引入：修前即有（`62fdbe6` 输出相同）；RR-75/76 的修复只覆盖 handler 内（`txInFlight`）。状态：已复现，未修复。
（最终状态见文末修复节：**已修复，随 v1.17.1 发布**，详见[修复记录](../bugfix/RR-20260926-84.md)。上面的“状态”是登记时的原值，保留不改。——2026-09-27 回写，OPEN-ITEMS A13②）

`nest/execution.go:134` 以 `!msg.txInFlight` 判定“消息自己的事务”，RR-75 的拒绝只在 `:101 msg.txInFlight` 时生效；`nest/nest_dispatch.go:204-205` 的 Guard post-release 回调与
`runAfterUnlock` 运行时当前消息仍在上下文里、`txInFlight` 已复位，Remote 批次要到 `:76 finishRemoteWriteBatch` 才收尾。此时独立事务认领消息（`tx.dispatch = msg`）：
Remote 消息外层失败时批次被 Commit、回复误报 `ErrAfterCommitFailed`；纯本地消息外层已回滚也误报“已提交”；回调内独立事务结果未知不 fence（`execution.go:254` 的 `tx.dispatch == nil` 分支未走到）。
USER_GUIDE §4 判别表第 1 行与 `ErrNestedTransactionInRemoteMessage` 的 godoc 在这个窗口里不成立。复现：[REPRO-2026-09-26-08](REPRO-2026-09-26-08.md) §1。

修复约束（沿用维护者 2026-09-27 对 RR-75 的“拒绝”）：消息自己的事务一旦结束（提交、回滚或失败），在该消息的收尾阶段（post-release、解锁后回调、批次收尾之前）调用 `RunIsolatedTransaction`，
不得认领消息、不得触碰 Remote 批次与 Msg 上的提交事实：带 Remote 批次的消息返回 `ErrNestedTransactionInRemoteMessage`；纯本地消息按不认领消息的嵌套独立事务处理（RR-65 标记与 RR-76 fence 同样适用），
或同样拒绝——二选一由修复方论证。不在快 worker 上新增等待；RR-65/73～76 回归不回退。

## 修复（2026-09-27）

状态：**已修复，未发布**（本地提交，未推送）。按修复约束实现：“消息自己的事务”改由入口判定——只有 `invokeHandlerTransaction`
（经 `invokeWithTransaction`）能认领当前派发的消息；`RunIsolatedTransaction` 与新建事务的 `RunDetachedTransaction` 在任何时刻都不认领，
不再靠 `txInFlight` 的时序区分。带 Remote 批次的消息在收尾阶段（Guard post-release、解锁后回调，批次收尾之前）调用返回
`ErrNestedTransactionInRemoteMessage`，函数体不执行、批次与 Msg 上的 Remote 事实不变；纯本地消息选“不认领消息的嵌套独立事务”，
RR-65 的 `nestedTxCommitted` 与 RR-76 的 fence 同样适用（论证见修复记录）。USER_GUIDE §4 判别表第 1 / 3 / 4 / 10 行与相关哨兵 godoc 同步。
修前红（基线 `9009268`，§1 探针 A / A2 改写）：Remote 外层失败 `FinalizeLocked=[rr84_iso_in_closing] isolatedCommits=1 batch Commit=1 Abort=0
reply=nest: transaction committed but after-commit work failed: outer business failed`；纯本地外层失败 / 锁超时回复误带 `ErrAfterCommitFailed`；
回调内结果未知 `FenceError=<nil>`。详见[修复记录](../bugfix/RR-20260926-84.md)。
