# RR-20261005-NC-73：`roost id` / `roost add errcode` 用正则找错误码，和 errcode 生成器口径不同——别名导入的定义被漏掉、注释里的文字被算成占用

日期 2026-10-05。基线 main `be7bcc18`（含 N07 的 NC-63 修复 `3d4fe9f3`）。等级 **P3**。状态：已复现（正式 CLI 与正式入口回归），未修复。来源：[RR-20261005-NC-63 修复记录“残余”](../bugfix/RR-20261005-NC-63.md#残余)明确交给 N08；N08 codegen review（[本轮](../review/REVIEW-2026-10-05-n08-codegen.md)）。

## 触发与实际

`codegen/internal/roost/id.go:15` 的 `errcode\.Define\(\s*([0-9]+)\s*,` 是 `ScanIDs` 唯一的错误码来源；`NextID`（`roost id next errcode`、`roost add errcode`、`add_rpc.go:66`）、`CheckIDs`（`roost id check`、doctor `doctor.go:88`）和 `add.go` 的显式 ID 冲突检查都用它。errcode 生成器自 NC-63 起按 AST 读取（`codegen/internal/errcode/main.go` 的 `errcodeLocalName` / `isErrcodeDefine`），认别名与点导入，不认注释和字符串。

game-demo 工程实跑（[证据](../review/evidence/noncore-review-20261005-n08/cli-id-errcode.txt)）：

1. `internal/errors` 里加 `import ec ".../errcode"` + `ec.Define(100000, …)`：`roost id next errcode` 仍给 100000；`roost add errcode Probe` 写出 `errcode.Define(100000, …)` 并以 0 退出；`roost id check` 报 “IDs are valid”；之后 `roost generate` 才失败：`generator errcode: duplicate errcode 100000: internal/errors/aliased.go and internal/errors/probe.go`。
2. 只加一个注释文件 `// errcode.Define(100003, "bag_full_old", "x")`：`roost id check` 报 `duplicate errcode id 100003: internal/errors/bag_full.go and internal/errors/commented.go`，而生成器认为没有冲突。

正式入口回归 `TestIDToolsSeeErrcodeDefinitionsTheWayTheGeneratorDoes`（新增）修前三处红：

```
roost id next errcode handed out 100000 again although ec.Define(100000, …) (aliased import) already uses it
roost id check with 100000 defined twice (aliased and plain import) = <nil>, want a duplicate
roost id check counted a comment / string as a definition: duplicate errcode id 100000: internal/errorsprobe/lookalike.go and internal/errorsprobe/lookalike.go
```

## 根因

ID 工具和生成器各有一套“什么算错误码定义”的实现；NC-63 只把生成器改成 AST，`id.go` 的正则留在原处（NC-63 记录已点名）。

## 影响与定级

冲突最终会在 `roost generate` 报出，不会带着重复错误码上线，定 P3；代价是 `roost add errcode` / `roost add rpc` 分配到已占用的码、`roost id check` / doctor 漏报或误报，修复者得手工找号。

## 范围

只涉及 errcode 一种 ID；protocol / entity / component 的 `//roost:` 标记 ID 仍按标记正则扫描，本条不改。
