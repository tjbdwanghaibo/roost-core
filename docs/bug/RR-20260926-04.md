# RR-20260926-04：字节软预算下大对象只能作为窗口首个准入，轮转游标停在最后准入者，大对象被持续插队而饿死

日期：2026-09-26。基线：main `a22c5a5`（对照 `8ce21a5` 结果相同，不是本批引入）。等级 P2（可用性：对象永不出现在客户端；默认预算关闭）。
状态：已复现，未修复。

## 触发条件

配置 `SnapshotBudget.MaxBytes`；某个冷创建对象 X 的编码大于本窗口剩余字节额度（包括大于 `MaxBytes` 的合法大对象）；
同一类别（新入场 / 恢复）里在 X 之后还有别的候选被准入——跨会话（其他会话持续有小对象）或同会话内（新 subject ID 单调递增）都可以。

## 预期 vs 实际

预期：roost-coding “软预算保证合法大对象最终有进度”；`SnapshotBudget` 注释（`sync/entitysync/snapshot_budget.go:111`）
“单包超过软预算时允许它独占一次额度以保证进度”；新入场 / 恢复之间和会话之间公平。

实际：X 只有在本窗口一个都还没准入时（`used.objects == 0`）才能进；而下一窗口的起点取“最后一个被准入的候选”之后。
只要 X 之后还有候选被准入，下一窗口的起点就又落在 X 前面（或 X 所在会话之后），X 永远排不到窗口首位。
每个窗口 X 仍被重新捕获和编码（`SnapshotsCaptured` 持续增长），是重复工作。

## 根因（代码）

- `sync/entitysync/snapshot_budget.go:265-268`：字节检查 `limit.MaxBytes > 0 && used.objects > 0 && bytes > limit.MaxBytes-used.bytes` 时 `continue`，
  不记录“有一个被跳过的大对象”，也不停止准入后续候选。
- `sync/entitysync/snapshot_budget.go:273-274`：每准入一个候选就把 `m.snapshotCursor[class]` 设为它的会话、
  `batch.snapshotAfter[class]` 设为它的 subject，于是游标越过了被跳过的 X。
- `sync/entitysync/snapshot_budget.go:176-182`：下一窗口从游标之后开始（`order[start] <= cursor` 时前进）；
  `sync/entitysync/snapshot_requests.go:89-120` 迭代器先吐完一个会话的全部候选再进入下一个会话。
- 同会话内：会话内游标停在最后准入的 subject ID，新 ID 总在 X 之前被准入并占用额度。

## 复现

探针源码与输出见 [REPRO-2026-09-26](REPRO-2026-09-26.md) §2（`a22c5a5` 与 `8ce21a5` 输出一致）：

- 有限积压：3 会话，`{MaxBytes:300, PerSessionObjects:1}`；X=1000 字节，会话 2 最先订阅；会话 1、3 各 30 个 10 字节对象。
  输出 `tick=1..30 s1=1 s2=0 s3=1`，`tick=31 ... bigDelivered=true`——最先请求的大对象等了 31 轮。
- 持续新增：会话 1、3 每窗口各加 1 个小对象，periodic 与 on_change 都
  `big snapshot for session 2 never delivered in 80 windows; ... SnapshotsCaptured=240 SnapshotsDeferred=80`。
- 单会话：新 ID 单调递增（大于或小于 X）时 35～60 轮内都未交付；ID 随机分布在 X 两侧时第 10 轮游标绕回 X 才交付。
  单会话探针在 90 个对象处停止，避开默认每会话 100 个对象的上限。

命令：`GOWORK=off go test ./sync/entitysync -run 'TestProbeRRLargeSnapshot' -count=1 -v`（探针为临时文件，已删除，源码在附录）。

## 影响

默认 `SnapshotBudget` 字节预算关闭，交接文档里的正式 AOI/恢复压测只用对象数预算，不受影响；启用字节预算且有持续进场 / 进视野流量时，
大对象（如大背包、大场景物件）可能永远不出现在客户端，并在每个窗口重复编码。

## 实施方向（约束）

- 被字节额度挡下的大对象需要一个能保证“有限窗口内获得首位”的规则，同时不破坏类别轮转、会话公平与 RR-20260925-12/13 的边界。
- 游标推进不能越过被跳过而未准入的候选，或需要单独记住它。
- 大对象未获准入的窗口不应重复编码。

## 验收覆盖点

- 上述三类探针（跨会话有限积压、持续新增、单会话单调 ID）在有限窗口内交付 X，其他会话 / 对象仍有进度。
- 超过 `MaxBytes` 的单个合法对象独占一个窗口后交付；超硬上限的对象仍明确失败。
- `SnapshotsCaptured` 不随被挡窗口数线性增长。
