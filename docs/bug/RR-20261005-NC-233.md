# NC-233：Redis Mod 关闭出错后，再调 Stop 永远不会成功

2026-10-06，基线 `c8ecbabb`。**P3**（App 每次停机只调一次 Mod 的 Stop，当前没有生产触发路径；违反停机契约“再调用返回 nil”）。状态：已复现，已修复（见文末）。[本轮](../review/REVIEW-2026-10-06-n01b.md) · [证据](../bugfix/evidence/noncore-bugfix-20261006-n01b/README.md)。来源：[N14 观察 O3](../review/REVIEW-2026-10-05-n14.md)。

## 触发与差异

`kit/redis/redis_mod.go` `StopWithContext`（基线 :111-121）只在 `asm.Close()` 返回 nil 时把 `m.asm` 置空。go-redis v9.22.0 的 `ConnPool.Close` 先 CAS 置 closed、关闭并清空全部连接，再返回第一个关连接错误（`internal/pool/pool.go` `Close`）：**返回错误时连接池同样已经关闭**，之后每次 `Close` 都返回 `redis: client is closed`。

- 预期（[停机契约](../feature/REFACTOR-2026-10-05-shared-stop-contract.md)第 4 步）：资源已经释放的停止入口再调用返回 nil；Close 的错误报告一次。
- 实际：第一次 Close 出错之后，每次 Stop 都返回 `redis: client is closed`，调用方无法区分“还没释放”与“早已释放”。

## 复现

`kit/redis/stop_retry_promises_test.go` `TestRedisModStopConvergesAfterACloseError`（先关闭一次底层客户端制造 Close 的错误返回）。修前：

```

```
