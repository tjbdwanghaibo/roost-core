# RR-20261006-56：标记键名拼错被静默忽略，生成物取缺省值

2026-10-07，基线 `a9c211e9`。P1（持久化语义被静默降级：`durabilty=strict` 生成 async，崩溃窗口内已回复的事务可能丢；`dbscop=sid` 写进全局库）。来源：框架文档审查 F12 G1（[12-codegen 实现](../framework/impl/12-codegen.md) §11 G1）与 F09-R4 中 servicerpc 的 marker 拼写一项。
状态：已复现；已修复（`63573f33`，[修复](../bugfix/RR-20261006-56.md)），未发版。

## 机制

1. `//roost:nest` 的 `parseMarkerOptions` 收下任意键（基线 `codegen/internal/nest/parse.go:463-474`），只读 `rollback` / `durability` / `sync` / `target(s)`；`rollbackMeta` 对空 durability 取 `nest.DurabilityAsync`。
2. `//roost:dao` / `//roost:redisdao` / `//roost:attribute` / `//roost:proto|protocol|msg|view` 的 `parseKV`、`//roost:table|object` 的 `parseMarkerOptions`、`//roost:rpc` 的 `parseOptions`（基线 `servicerpc/parse.go:204-215`）同样只取认识的键：`dbscope` 缺省 `global`，`ttl` / `version` / `mode` / `affinity` 同理。只有值被校验。
3. `//roost:register` 在 `phase=` 之后才查未知键，`phse=entity` 报成“缺 phase=”；`//roost:web` 报错不带文件和行。只有 entity / mirror 完整拒绝未知键（`entity/parse.go:286-288` 的注释写明了原因）。
4. protocol 用 `^//[a-z]+:msg` 等手写正则、`id.go` 用 `//[a-z]+:`，接受任意小写前缀，绕开 `marker` 包（G5 一项）。
