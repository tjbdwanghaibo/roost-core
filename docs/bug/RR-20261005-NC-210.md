# NC-210：set_memory / add_memory / clear_memory 的 name 不查是否声明，lower 落到槽位 0——有别的 memory 时静默改写它，没有时每次施法 ErrProgramInvariant；bool memory 上的 add_memory 也能编译

2026-10-05，基线 `c10cc9ac`（skill 目录与 `bfd353c0` 相同）。P2（编译通过的定义静默改写另一个 memory 槽位且不经类型检查，或在运行期返回“不可变 Program 不变量失败”）。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-210.md)。[本轮](../review/REVIEW-2026-10-05-n09-batch4.md)。

## 触发与差异

memory 效果的名字在编译链上没有一处检查：

- 类型检查 `compile_typecheck.go:422-429` 只在 `c.memory[typed.name]` 找到时才检查 value 类型，找不到直接跳过；`clear_memory`（`:506`）什么都不查。
- 初始化分析 `compile_memory.go:84-95` 对未声明的名字同样跳过。
- lower 取槽位用 map 零值：`lower.go:597-601` 的 `memory: c.memory[effect.name]`，未声明的名字得到 `MemoryIndex(0)`。

Runtime 的 `executeMemory`（`runtime_cast.go:106-131`）只检查下标越界：

- 定义里有别的 memory（槽位 0 存在）：未声明名字的 set_memory 把值写进槽位 0，值的类型没有被检查过（bool 写进 int 槽位）。
- 定义里没有 memory：`int(operation.memory) >= len(cast.memory)` 返回 `ErrProgramInvariant`。

另一个缺口：`add_memory` 只检查 value 与 memory 同类型，不检查 memory 是 int。bool memory 上的 `add_memory` 编译通过，运行期 `CheckedAddRuntimeValues`（`runtime_value.go:171-177`）每次返回 `ErrRuntimeTypeMismatch`。

## 复现

探针：对 36 个 fixture 做单点变异（删除键、数值改写、同键词表替换、跨 fixture 子树移植），编译无 error 的变异在 MemoryHost 上施法、推进到 40 tick 并做 checkpoint。基线代码上 31226 个变异、14062 个编译通过，**唯一一类 ErrProgramInvariant** 就是本条：例如 `charge_projectile.json` 删掉 `memory.charged`（enter 仍 `set_memory charged`），`Activate` 返回 `skill: immutable program invariant failed`；把任意 fixture 的一个 effect 换成 `{"type":"set_memory","name":"charged","value":true}` 同样如此（80 个失败变异全部属于这一类）。

正式回归（修前）：

```
--- FAIL: TestCompileRejectsMemoryEffectsOnUndeclaredOrNonIntMemory
    set undeclared compiled; diagnostics=[]skill.Diagnostic(nil)
    add undeclared compiled; diagnostics=[]skill.Diagnostic(nil)
    clear undeclared compiled; diagnostics=[]skill.Diagnostic(nil)
    set without any memory compiled; diagnostics=[]skill.Diagnostic(nil)
    add on bool memory compiled; diagnostics=[]skill.Diagnostic(nil)
```

## 影响

memory 名字写错（拼写、改名后漏改）的技能通过 game-demo 启动期 CompileAll 的 fail-fast，运行时要么悄悄改坏另一个 memory（之后读它的分支走错，`add_memory` 在被写成 bool 的槽位上再失败），要么每次施法失败。

## 验收覆盖点

三种 memory 效果的未声明名字在编译期以 `REFERENCE_UNKNOWN` 定位到 `.name`；`add_memory` 要求 int memory；声明过的名字照常编译、写自己的槽位（控制）。

## 实施方向（约束与候选）

在类型检查里对三种效果统一做“名字已声明”检查（与 `$memory.x` 引用的检查同一处），lower 不再依赖 map 零值。
