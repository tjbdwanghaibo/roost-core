# RR-20260930-22：game-demo gift 发放的收件人检查读 `dataengine.database`，而 Player DAO 固定写 `db=game`

日期：2026-09-30。基线：main `fdba6c55`。来源：B27 第 3 批真实环境端到端（RR-20260927-03 机器人在非 0 `redis.db` 下实跑）暴露。等级 **P2**：把 `dataengine.database` 改成非 `game`（README 自己推荐的隔离做法）后，所有赠礼 saga 都以“收件人从未进过游戏”补偿，功能不可用；默认配置下两者恰好同名才没暴露。状态：**已确认，未修复**。

## 触发条件、预期与实际

- 触发：生成的 game-demo 工程，`dataengine.database` 配成 `b27b3_09302023`（非 `game`），`go run ./cmd/loadtest -count 6 …`。
- 预期：`send_gift` 的 saga 完成（`completed`），收件人拿到物品。
- 实际：6/6 `expect_gift: gift saga ended compensated, want completed`，saga completion `"error":"recipient has never entered the game"`。

## 根因（到行）

`demo/internal/service/game/gift_saga.go.tmpl:95` `gameDatabase, _, _ := effectSettings(registry)`（= `dataengine.database`），`:487` 用它对 `player` 集合 `FindOne`；而 Player DAO 按 `demo/db/def/player.go.tmpl` 的 `//roost:dao coll=player db=game` 生成 `PlayerDaoDBName = "game"`。两处只在默认 `game` 时一致。README §“看四处”也写明 `db.player` 在 `db=game` 而非 `dataengine.database`。

## 修复约束

- 收件人检查改用 DAO 生成的库名常量（或 DAO 本身），不再从 `dataengine.database` 推断；同一模板内其他直接拼库名读 DAO 集合的地方一并核对。
- 回归：模板测试里 `dataengine.database != game` 时 gift 仍 `completed`。
- 已有工程：demo 文件“应用所有”，或手改 `gift_saga.go` 一处；CHANGELOG 写明。
