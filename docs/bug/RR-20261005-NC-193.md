# NC-193：启动失败时 Service 已启动的部分没停完，App 就停 Mod、释放单实例锁

2026-10-05，基线 `f6245613`。**P3**（违反三步停机“排空后才释放依赖”；进程随后退出，窗口为 Mod 停机时长，主要后果是已释放锁之后旧组件仍在跑、以及不配合 ctx 的收尾让进程卡死在启动失败上）。状态：已复现，未修复（修复见文末）。[本轮](../review/REVIEW-2026-10-05-n14.md) · [证据](../review/evidence/noncore-review-20261005-n14/README.md)。来源：N11 观察 O8，本轮核实并扩展到同一收尾路径。

## 触发与差异

`App.run`（`app/app.go`）在 Mod 全部启动之后调用 `Service.Init`：

1. **Init 返回错误**（`:325-330`）：App 不调用 `Service.Shutdown`，直接逆序停 Mod，`singletonReleasable = true` 释放锁。game-demo 的 `Init`（`demo/internal/service/game/service.go.tmpl`）是逐步启动的：场景 `Start`、spawner、PlayerOwners `Start`、matchmaker、赠礼消费者、开关监听、在线状态、`startActivity`（`:198`，起 World tick 与窗口两条循环）……之后任何一步失败（`startActivityPhaseConsumer` 订阅失败 `:206`、`registerGMCommands` 失败 `:213`、`Register` 重名）都直接 `return`，前面启动的循环与订阅仍在跑；`Service` 接口（`app/service.go`）也没有约定“Init 失败时自己收尾”。
2. **Init 成功之后的启动失败**（启动期间 RuntimeFailure、`PhaseServiceStarted` 失败，`:331-347`）：App 同步调用 `svc.Shutdown(cleanupCtx)`（5s）。Shutdown 不配合 ctx 时 `run` 永远不返回；Shutdown 超时返回错误后，仍照常停 Mod 并释放锁。正常停机路径（`:430-439`）恰好相反：Shutdown 不完整就保留 Mod、不释放锁，因为“Serve 或 Shutdown 还可能访问它们”。

- 预期：与正常停机同一规则——Service 的组件先停（Init 失败也要收回已启动的部分）；收尾在预算内没完成时不拆 Mod、不释放锁，`run` 在预算内返回错误。
- 实际：见上。

## 复现

`app/startup_cleanup_promises_test.go`（单实例锁 harness），修复前原文见 [nc193-red.txt](../review/evidence/noncore-review-20261005-n14/nc193-red.txt)：

```

    startup_cleanup_promises_test.go:126: mods stopped 1 times while Service.Shutdown had not finished; the service may still be using them
--- FAIL: TestStartupCleanupThatDoesNotFinishKeepsTheModsAndTheLock/uncooperative (20.00s)
    startup_cleanup_promises_test.go:117: run did not return 15s after a startup failure whose Service.Shutdown never finished
```

## 影响

- 锁释放后旧进程的 activity 循环、场景复制等仍可能写 Redis / 发 NATS，直到进程退出；新进程此时可以拿锁（窗口很短，但正是单实例锁要排除的形态）。
- 依赖（Nest、NATS、Redis 客户端）在仍在跑的组件底下关闭，组件报错 / panic 的日志掩盖真正的启动失败原因。
- 不配合 ctx 的 Shutdown 让一次启动失败变成进程挂起，直到部署侧超时杀掉。

## 验收覆盖点

- Init 返回错误：Shutdown 被调用一次，在 Mod 停止之前；随后 Mod 停止、锁释放。
- 启动失败收尾（Init 失败与 Init 之后失败两条）：Shutdown 超出收尾预算（配合 / 不配合 ctx 两种）时，`run` 在预算内返回启动错误 + 收尾不完整，Mod 不停、锁不释放；收尾完成时行为与现在相同（既有 #10 用例）。
- 仓内全部 `app.Service` 实现的 `Shutdown` 能容忍部分初始化（生成的 servicerpc Server、`renderService`、game / game-demo、examples）。
