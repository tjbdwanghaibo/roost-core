# NC-162：robot 重连后再次 EnsurePushCapture 是空操作，新会话上没有 push handler，之后的推送被静默丢掉

2026-10-05，基线 `45d4bc1c`。**P3**（压测 / 集成机器人在重连后误报“没收到”，掩盖或伪造服务端问题；生产服务器不受影响）。状态：**已复现，未修复**。[本轮](../review/REVIEW-2026-10-05-n12-revn12.md)。

## 触发、预期与实际

- 触发：剧本里再跑一次 `connect`（`robot/action/builtin.go:48` → `Context.SetSession`，注释明写“reconnect”），之后再执行安装 capture 的步骤（例如 game-demo 的 `scene_watch` → `EnsurePushCapture("scene", MsgEntitySync, …)`）。
- 预期：重连后的安装在新会话上注册 handler，重连后服务端重发的全量 EntitySync 被收下。
- 实际：`SetSession` 关闭旧会话，旧会话 `closeWithErr` 清空自己的 handler 表（`robot/session/session.go:335`）；`EnsurePushCapture`（`robot/robot.go:150-170`，基线）只看黑板上的 `capture:<key>` 标记，标记要到 `Context.Close` 才删，于是重连后的安装返回 nil 却什么都没注册。新会话收到的推送没有 handler，按设计静默丢弃（`session.go:285`）。

```text
capture_reconnect_promises_test.go:74: a push on the reconnected session reached the capture 0 times; want 1
  (EnsurePushCapture after reconnect must register on the new session)
```

## 影响

所有“重连 + 订阅推送”的剧本（场景复制恢复、聊天推送、战斗帧）在重连后都收不到推送，表现为 `"pos_x" never arrived` 一类失败——与 [REVIEW-2026-09-22](REVIEW-2026-09-22.md) 里排查过的现象同形，容易被当成服务端复制缺陷。当前仓内 demo 剧本只 connect 一次，没有现成触发。

## 验收覆盖点

重连后再次安装在新会话上生效；同一会话上重复安装仍幂等（一条推送只投递一次）。真实网关上的重连恢复见运行记录。
