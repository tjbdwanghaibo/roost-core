# RR-20261006-63：一个慢的追帧客户端能卡死整个 lockstep 房间的 `Tick`

2026-10-07，基线 `a7285da6`。P2（`Reliable` 直接接 KCP / QUIC——`RoomConfig.Reliable` 注释推荐的接法——且 `Tick` 的 ctx 无期限时，对端停住即全房停帧）。来源：框架文档审查 F04-7。维护者 2026-10-07 选 A。
状态：已复现；已修复（`99a3e99f`，[修复](../bugfix/RR-20261006-63.md)），未发版。

## 机制

1. `Tick` 在房间唯一的 goroutine 上同步调用 `pumpCatchup`，后者对每个追帧会话 `r.reliable.SendReliable(ctx, …)`，用的是调用方的 ctx（基线 `sync/lockstep/room.go:424`）。
2. `KCPTransport.SendReliable` 只在 ctx 有期限时设写期限；kcp-go 的 `Write` 在发送窗口满时阻塞，直到期限或取消。对端不 ACK 时一直阻塞。
3. demo 用 `context.Background()` 调 `Tick`；房间的所有座位都等这一个客户端，帧不再切、广播不再发。
