# NC-270：game-demo PathFindSystem.Stop 无锁清空 terrain，与场景外的并发寻路数据竞争

2026-10-06，基线 `dc877c04`，分支 `revleft`（N11～N13 留项与小防护）。**P3（潜伏）**。来源：N11 观察 O4。状态：已复现，已修复（见文末）。[本轮](../review/REVIEW-2026-10-06-revleft.md) · [证据](../bugfix/evidence/noncore-bugfix-20261006-revleft/README.md)。

## 触发与差异

`demo/game/scene/runtime/pathfind.go.tmpl`（基线）`Stop` 无锁执行 `p.terrain = nil`；`Path` / `Place` 先判 `p.terrain == nil` 再用，两次读之间被置 nil 会解引用空指针，并发读写本身是数据竞争。

入口穷举（当前源码，`rg` 含 `.tmpl`）：

| 调用方 | 是否持 Scene 锁 | 与 Stop 的先后 |
| --- | --- | --- |
| `handler/enter_scene.go.tmpl` → `area.PathFind().Place` | 是（Nest 目标 `ISceneEntity`） | `EntityManager.Destroy` 先取实体互斥锁、`SetRemoved` 后才解锁并调 `OnDestroy`（`entity/entity_manager.go:214-286`），在途事务先于 Stop 结束，之后的事务拿不到已移除实体 |
| `handler/move_player.go.tmpl` → `area.Terrain()` | 是 | 同上；且只用 TerrainSystem（自带锁） |
| `service/game/spawner.go.tmpl` → `Refresh().Due` → `RefreshSystem.place` → `pathFind.Place` | 否（spawner 定时器） | RefreshSystem 最后启动、最先停止；`Due` 持 `RefreshSystem.mu` 调 `Place`，`RefreshSystem.Stop` 取同一把锁并置 `stopped`，所以 PathFind.Stop 之前在途的 `Due` 已结束、之后的 `Due` 直接返回 |

结论：现有入口都与 Stop 有先后，不会触发。但 Scene 实体的注释明确承诺系统访问器 “safe to call from anywhere: an endpoint, the spawner's timer, the AOI tick”，地形系统也确实自带锁；只有 PathFind 的 Stop 违背了这条，任何新的无锁调用方（AOI tick、endpoint）都会撞上。
