# RR-20260923-01：等待新快照的订阅被当作从未交付，退订后残留客户端对象

- 日期：2026-09-23；基线：`967bc69`（M-18），Go 1.27.0 / darwin arm64。
- 范围：`sync/entitysync`；等级：P2。
- 状态：已修复、定向回归与模块 race 验证通过，未发布。见[修复记录](../bugfix/RR-20260923-01.md)。

## 触发与影响

会话已经收到 subject 的快照；随后切换 profile，或者撤回尚未发送 remove 的退订；在下一次 Flush 前再次退订或退役 subject。

预期：客户端持有旧对象，必须收到原 ObjectRef 的 ObjectRemove。
实际：订阅直接删除，下一 tick 没有删除通知。客户端保留幽灵对象，会话引用表也继续占用容量。

## 根因

`Manager.Subscribe` 在换 profile 和撤回退订时将订阅标记为 `kindSnapshot`。这个状态表示“下一次需要全量”，并不等于“客户端从未收到对象”。
`Manager.Unsubscribe` 和 `Unregister` 却以 `kindSnapshot` 判断无需 remove，混淆了订阅意图与已交付事实。已交付事实保存在 `session.objects`。

## 复现证据

测试：[subscription_removal_promises_test.go](../../sync/entitysync/subscription_removal_promises_test.go)。

```sh
go test ./sync/entitysync -run '^TestPendingSnapshotStillRemovesAnAlreadyDeliveredObject$' -count=1
```

修前四个组合均失败：`profile_change/unsubscribe`、`profile_change/unregister`、`resubscribe/unsubscribe`、`resubscribe/unregister`，均报告 `session 1 received 0 frame(s), want 1`。
同场对照：从未接收对象的会话不应收到 remove；修后两类会话均满足预期。

这组复现是顺序调用，不依赖竞态或真实网络。
