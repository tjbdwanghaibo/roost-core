# RR-20260926-35：handler 内 CreateInScope 新建实体不在提交边界内——回滚 / 拒绝后仍存在并被同步；pipelined 下持久化前外发

日期：2026-09-26。基线：v1.17.0（`8811c02`）。等级 P2（客户端看到从未提交的实体；未持久内容外发）。状态：已复现，未修复。

## 根因

`entity/manager_factory.go:30-53` CreateInScope 不把新实体加入 SyncMutation（Include），也不 `tx.CaptureEntities`；动态 Cast 两者都做（`nest/cast.go:176-184`）。
kit 不自动接 `DurableWatermark`（`kit/nest/entity_sync.go:25-56`；唯一入口 `nestwal/runtime.go:37-44`，仅 demo scene 手动接）。

## 复现（[REPRO-2026-09-26-04](REPRO-2026-09-26-04.md) §3、§3b）

- pipelined 无水位：handler 内新实体 `SyncCommitReady=true`（已有实体 false），锁释放后、durable 前帧中出现新实体 `frame subjects=map[<created>:77]`，durableLSN=0。
- handler 报错回滚：已有实体回到 10，新实体仍发布在 EntityManager。
- strict commit 被拒：新实体帧 `map[<created>:55]` 仍发给客户端。接上水位（`TestZZProbeCreateInScopeWithWatermark`）可挡住 (a)。

## 修复约束（维护者 2026-09-26 批准推荐方向）

事务内 CreateInScope 与动态 Cast 相同：Include + CaptureEntities；回滚 / 拒绝时撤销发布（移除新实体、不持久、Sync 不外发或按 remove-before-create 回收）。
kit 在 committer 为 pipelined 时自动接 `DurableLSN` 水位（或配置缺失时拒绝启动，二者择一并说明）。事务外 CreateInScope 行为不变。
