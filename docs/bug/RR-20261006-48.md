# RR-20261006-48：Interest 排队事实就绪后、应用前同 id 被 Leave / Hide，之后每次 Flush 都失败

2026-10-07，基线 `47abe511`（main，v1.23.0 之后）。P1（卡住：一个 Manager 上所有 subject 停发，停机走不到 Close）。来源：框架文档审查 [FRAMEWORK-DOCS-FINDINGS-2026-10-07](../review/FRAMEWORK-DOCS-FINDINGS-2026-10-07.md) 的 F04-1，[04-sync 实现 §10.2](../framework/impl/04-sync.md#102-本篇写作时发现的源码疑点待闭环)。
状态：已复现；已修复（提交见 [修复记录](../bugfix/RR-20261006-48.md)），未发版。

## 机制

1. `Interest` 处于排队模式（用过 `QueueMove` / `QueueRelation`）。某 id 的位置事实已就绪（提交已确认），还没到下一次政策阶段。
2. 业务对同一 id 调 `Leave` 或 `Hide`：它们只改 AOI 与关系源，不碰 `in.facts`（基线 `sync/entitysync/policy/interest.go:251-300`）。
3. 下一次 Flush 的政策阶段，`applyQueued` 对这条事实调 `MoveSubject` 得到 `ErrInterestUnknown`，事实被留下并阻塞该 id，错误返回（基线 `policy/interest_queue.go:93-109`）。
4. `applyPolicies` 失败 → `Flush` 在取 pending 之前返回（基线 `sync/entitysync/flush.go:93-95`）。事实没有 TTL，之后每次 Flush 一样：这个 Manager 上所有 subject 不再出帧；run 循环吞错（`manager.go:737-739`），`Stop` 的最后一次 Flush、`Drain`、kit `StopWithContext` 一直报错，走不到 `Close`（`kit/nest/nest_mod.go:328-330`）。
