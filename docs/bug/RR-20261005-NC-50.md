# NC-50：account 建角补偿（释放 slot / 取消名字预约）失败不计数，Config.Metrics 承诺的“failed rollback”信号已丢失

2026-10-05，基线 `50e9a4e8`。P3（可观测性）。状态：已复现、已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-50.md) · [本轮](../review/REVIEW-2026-10-05-n06-revn06.md)。

`kit/service/account/service.go:56-64` 的 `Config.Metrics` 注释把“失败的回滚”列为两个“不是便利”的信号之一：它留下一个挡住该账号在该区服建角的 slot，错误虽然返回，但“没人聚合的返回错误”正是它当年隐形的原因。`bdbb61bc`（RR-20260929-19 持久建角计划）删掉了旧 `rollback()` / `rollbackRole()` 和其中的 `Dropped("rollback.failed")`，但补偿仍然存在：`create_role.go:92`（名字已被他人 committed 时释放死计划）、`:113`（预约被他人提交时释放未 admitted 计划）、`:157`（外来 player id 时 `Names.Cancel` + 释放）。三处失败都只 `errors.Join` 返回，不计任何指标；`create_role_tail_test.go:75` 仍断言 `dropped:rollback.failed == 0`，断言的是一个不会再产生的事件。

触发：死计划的 `DeleteIf` 失败一次（存储抖动）。修前（Memory 与隔离真实 Redis 同文）：

```text
pending_creation_other_name_promises_test.go:287: a failed compensation counted 0 times, want 1; accepted:create_role=1, accepted:login=2, refused:create_role:name_taken=1
```

影响：slot 被留下时没有任何聚合信号；与同轮 [RR-20261001-06 残余](../bugfix/RR-20261001-06.md#复核后的补修2026-10-05)叠加时，换名请求还不会再尝试释放，账号就无声地卡在该区服。定级 P3：不丢数据、不放权，错误仍返回给调用方。

没做 / 没验：全仓“每个服务都有 CAS 冲突率”（kit/service/README 第 6 条）的系统核对——account、activity 两包没有任何 `Conflict` 上报，但其他服务也只在 insert-only 碰撞处上报，属于框架级口径，单列为观察，不在本条修。
