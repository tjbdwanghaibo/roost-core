# NC-244：hotcode LoadPlugin 拒绝以 hotcode.Bundle 接口变量导出的 PatchBundle（变量遮蔽）

2026-10-06，基线 `81d7cb16`，分支 `revn10b`（N10 第二批）。P2（ai / actionflow 仓内无生产使用方；hotcode 由 Nest 全局 handler 与 game-demo 使用）。状态：已复现、已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-244.md) · [本轮](../review/REVIEW-2026-10-06-noncore-n10b.md)。

## 触发与差异

`hotcode/plugin.go:39-48`（基线）`if ptr, ok := sym.(*Bundle); ok && ptr != nil { bundle = *ptr; ok = bundle != nil }` 里 `ok` 是 if 语句新声明的变量，赋值写的是内层；外层 `ok` 仍为 false。插件写 `var PatchBundle hotcode.Bundle = ...` 时 Lookup 得到 `*hotcode.Bundle`，第一次断言失败，只能走这个分支。

预期：包注释与 Bundle 注释要求“导出名为 PatchBundle、动态类型实现接口的符号”；代码专门为接口变量写了指针分支，应能加载。

实际：这种导出方式一律报 `PatchBundle ... does not implement hotcode.Bundle`。之前本仓不构建 .so（U-0149 记“不可测”），分支从没执行过；本批在本机 macOS 用 `go build -buildmode=plugin` 构建最小插件第一次跑到。
