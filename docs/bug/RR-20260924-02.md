# RR-20260924-02：release hook panic 泄漏 Nest 组锁和 scope

- 日期 / 基线：2026-09-24，core `967bc69` 加工作树；等级 P1。
- 范围：Nest group lock 路径及 Entity release hook。
- 状态：已复现、已修复并验证，未发布；[修复记录](../bugfix/RR-20260924-02.md)。

## 触发与实际行为

组锁模式先取得 groupEntry，安装 goroutine group scope，再逐个获取 Entity 锁。正常释放时，先释放 Entity，随后才清理 group scope 和 groupEntry。若 EntityManager 注册的 release hook panic，后面的普通语句被跳过。

部分加锁失败也可触发：第一个实体加锁成功，第二个实体被其它 goroutine 占用；回退释放第一个实体时 hook panic，尚未返回的加锁函数同样跳过组锁清理。

EntityGuard 的单实体释放 defer 会解开该实体锁，Nest 外层恢复也能清理余下实体，但组锁不在 EntityGuard 中，因此仍残留。后续其它 worker 访问同组可能持续失败/重排，原 goroutine 的 scope 也可能污染后续逻辑。

## 复现与根因

新增 [group_release_panic_test.go](../../nest/group_release_panic_test.go)，使用真实 EntityManager hook；部分加锁场景通过 channel 确认第二个实体被另一 goroutine 持有，不靠 sleep。

```sh
GOWORK=off go test ./nest -run TestGroupReleasePanic -count=1
```

修前输出 `group scope leaked: 9800` 与 `group lock entries leaked: 1`。先只修正常释放后，partial-acquire 子用例仍失败，进一步补齐加锁期间的失败清理。

根因：`nest/group_lock.go: lockDispatchEntitiesWithGroup` 的 releaseScope / locks.release 缺少 panic-safe 所有权管理；panic 来源经 `releaseDispatchEntities → EntityGuard.ReleaseEntity → runOnEntityRelease` 传播。预期保留异常反馈，同时必须归还全部框架组锁资源。
