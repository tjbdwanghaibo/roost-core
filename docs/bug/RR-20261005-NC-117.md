# NC-117：提交前失败的 cast 不进完成队列，永不回收；累计超过 CompletedCastLimit 后 checkpoint 无法恢复

2026-10-05，基线 `855c2a38236f4efc9575fa9ba84bf8bf4100daf3`。P2（Runtime 状态无界增长并随每份 state 快照下发；之后 checkpoint 恢复判 corrupt，按文档 shard 不能开放。定 P2 是因为仓内没有正式 Runtime 调用方，不是因为后果轻）。状态：已复现，未修复。[本轮](../review/REVIEW-2026-10-05-n09-batch2.md)。

## 触发与差异

`trackCompletedCastLocked`（`skill/runtime_retention.go:20-32`）只把 `CastFinished` 与“已提交的 `CastFailed`”放进 `completedCastOrder`：

```go
if cast.status != CastFinished && !(cast.status == CastFailed && cast.committed) {
    return
}
```

提交前失败的 cast（施法窗口里 commit 时付费不足 → `failScheduledCast`；NC-111 修复后 Cancel / Interrupt / Release 回调失败 → `failCastLocked`）因此不进队列，`pruneCompletedCastsLocked` 永远看不到它，cast 一直留在 `runtime.casts`。只有 `startLocked` 的提交前失败会显式删除（`runtime.go:433-439`）。

checkpoint 恢复却把**所有** finished / failed cast 当作完成（`runtime_checkpoint.go:862`），再以 `len(completedCastOrder) > CompletedCastLimit` 判 corrupt（`runtime_checkpoint.go:1023`）。

预期（`RuntimeOptions.CompletedCastLimit` 注释与 `docs/skill/production-readiness.md`：“bounds inspectable terminal casts”）：终态 cast 有界保留；live 与恢复后的保留集合一致。实际：提交前失败的 cast 无界累积；累计超过上限（默认 2048）后，任何一份 checkpoint 都恢复失败。上限以内时，恢复后的 Runtime 会回收 live Runtime 从不回收的 cast，两者状态分叉（重新 checkpoint 的字节不同）。

## 复现

`skill/runtime_failed_cast_retention_promises_test.go`（基线代码上），`cast_window_interrupt.json`（commit tick 付 5 mana），施法者 mana 为 0，`CompletedCastLimit: 2`，连续 5 次施法在 commit 时失败：

```
--- FAIL: TestUncommittedFailedCastsStayWithinTheCompletedCastLimit (0.00s)
    runtime_failed_cast_retention_promises_test.go:46: retained casts = 5 (completed queue 0) after 5 pre-commit failures; CompletedCastLimit is 2
    runtime_failed_cast_retention_promises_test.go:54: restore after pre-commit failures: skill: runtime checkpoint is corrupt
```

探针另见：Cancel 回调失败、Release 付费失败之后 checkpoint → 恢复 → 再 checkpoint，`completed_cast_order` 由空变为 `[1]`（已删）。

## 影响

长期运行的对局里“读条到点蓝不够”是常见玩法路径：失败 cast 无界占内存、拖慢每次 state 快照与 checkpoint，并被同步给客户端；过了上限之后崩溃恢复 / 迁移恢复全部失败。这是 NC-110～112 修复后对终止路径与 checkpoint 一致性核对时发现的：NC-111 让 Cancel / Release 失败进入 failed 终态，同时扩大了这条路径。

## 验收覆盖点

提交前失败的 cast 与其他终态 cast 一样进入完成队列、按 `CompletedCastLimit` 回收；checkpoint 恢复成功且重建的完成队列与 live 相同；`startLocked` 删除并复用 ID 的失败启动不在完成队列里留下条目。
