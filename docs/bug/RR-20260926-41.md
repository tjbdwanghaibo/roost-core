# RR-20260926-41：nestwal 启动只按长度判撕裂尾——末段零填充尾部 ≥20 字节即拒绝打开

日期：2026-09-26。基线：v1.17.0（`8811c02`）。等级 P3（取决于文件系统：ext4 data=writeback、部分网络盘 / 云盘、VM 快照可能出现零尾）。状态：已复现，未修复。

`nestwal/wal.go:1238-1246` 只有“读到字节 < 20（帧头长）”或“帧 end 超 limit”算撕裂；帧头 magic / 版本无效一律 `ErrCorrupt`。
复现（[REPRO-2026-09-26-04](REPRO-2026-09-26-04.md) §1）：零尾 5 / 19 字节 open 成功，20 / 4096 字节 `invalid frame header`——判据自相矛盾。NEST_TRANSACTION_WAL.md §5 承诺只截断最后段不完整尾帧。

## 修复约束（同时满足才截断，否则仍 ErrCorrupt）

仅最后一段；坏点严格位于 checkpoint fence 之后（依赖 RR-16 / RR-33 已修）；坏点形态为自坏帧头所在对齐块（4 KiB）起全零，而非 CRC 不符的非零数据；截断坏点后全部内容并告警、打指标。
残余风险（已 fsync 未 ack 的 strict 记录若被介质整块清零会被当撕裂吞掉）写入文档。
