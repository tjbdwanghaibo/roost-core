# RR-20261004-13：roost 替用户跑的 go 命令超时 / 取消时只杀 `go` 本身，compile / link / git 孙进程留在暂存目录里，缓冲输出时 `Wait` 被孙进程的管道拖住、超时形同虚设

日期：2026-10-04。基线：main `28b161e3`（v1.19.2 之后）。来源：[W-2026-10-04-06](WANTED.md)（RR-20261004-12 调查时的观察）。等级 **P3**。状态：已确认，已修复（见下）。

## 触发

1. `roost doctor` 的 `go mod verify` / `go list` / `go test -run=^$` 超过各自时限（2 / 2 / 5 分钟），或 `roost project deps` / `roost generate` 的 `go get` / `go mod tidy` 超过 `dependencyUpdateTimeout`（5 分钟）。
2. 此时 `go` 正在跑它起的子进程（compile / asm / link，`go get` 的 git / 下载）。

## 预期

超时即结束：调用在时限后有界时间内返回失败，命令起的整棵进程树都已退出，不再有进程以命令的 `Dir`（`project deps` 期间是 `.roost-deps-*`，`generate` 期间是 `.roost-generate-*` 暂存树）为工作目录；之后用新的 context 重跑能正常完成，暂存目录可删。

## 实际

`exec.CommandContext` 的默认取消只 `Process.Kill()` `go` 本身，不设 `WaitDelay`：

- 孙进程被过继给 init / launchd 继续运行，工作目录仍是暂存树。macOS 实测：`go build -a std` 进行中 `kill -9` go，0.5 秒后 compile 子进程（ppid 已变 1）仍在跑。Windows 上进程的当前目录不可删除（同族 [RR-20261004-12](RR-20261004-12.md)），调用方的 `defer os.RemoveAll(stage)` 失败、暂存目录残留。
- 输出是 `bytes.Buffer` 时（doctor 的 `CombinedOutput`；`generate` 把 `TidyProjectDependencies` 的输出暂存在 buffer 里），`Wait` 要等管道 EOF，而孙进程握着继承的 stdout / stderr，调用一直阻塞到孙进程自己结束——超时不再界定这次调用。

macOS 上的修前红（替身 `go` 起一个 30 秒的孙进程后 `wait`；见 [修复记录](../bugfix/RR-20261004-13.md)）：

## 根因（基线 `28b161e3` 行号）

- `codegen/internal/roost/doctor.go:136-139`：`runDoctorGoCommand` `exec.CommandContext(ctx, "go", args...)` + `CombinedOutput()`，无 `WaitDelay`、无进程组。调用方 `doctor.go:71-75`。
- `codegen/internal/roost/dependencies.go:162-167`：`runDependencyCommand` 同上，`Run()`；调用方 `tidyProjectDependencies`（`dependencies.go:106-107`，经 `generate.go:252` 在 `.roost-generate-*` 上、输出为 `bytes.Buffer`）与 `updateFrameworkDependencies`（`dependencies.go:134-151`，经 `updateFrameworkDependenciesTransactional` 在 `.roost-deps-*` 上，CLI 传入 `os.Stdout` / `os.Stderr`）。

## 修复约束

- 超时 / 取消要杀整棵树，并给 `Wait` 有界上限；不以加长超时或忽略删除错误代替。
- 放进独立进程组会让终端的 Ctrl-C 不再直达 `go`：一次 Ctrl-C 仍须结束 roost（行为同前），且不能留下 `go` 子树。

## 修复（2026-10-04）

**状态：已修复（worktree，本地验证通过，已提交，未推送、未发版）。** 记录：[docs/bugfix/RR-20261004-13.md](../bugfix/RR-20261004-13.md)。新增 `runCommandTree`（`command_tree*.go`）：`WaitDelay` 5 秒；Unix 新进程组 + 取消时 `kill(-pgid, SIGKILL)`，运行期间接住 SIGINT / SIGTERM / SIGHUP，杀树后以默认动作重新发给自己；Windows 取消时 `taskkill /T /F`。两处调用都换成它。
