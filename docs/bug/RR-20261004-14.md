## 触发

可控时钟、`fakeLeaseTable` 加一个 `Claim` 钩子（记录“Redis 被问的时刻”，或让 `Claim` 落地后仍返回错误 = SetNX 落地、回复丢失）：

1. **跨间断认领 + 慢撤离**：登录（`Claim`）、后台消费者（`Owns` → `Claim`）或刷新循环的重新认领（`retakeOne` → `claim`）跨间断，`store.Claim` 设下键 TTL 后 `dropResident` 等满一份 `evictBudget`（实体被长事务占住）才完成。
2. **慢 `Refresh`**：续租往返本身花了 3s（逐个玩家 `CompareAndExpire`、Redis 卡顿）后答 Held。
3. **认领丢回复（W 条目“另记”）**：
   - 刷新循环路径：键过期 → `renew` 把玩家标 `interrupted` 并重新认领 → `store.Claim` 的 SetNX 落地但返回错误 → 下一轮 `renew`；
   - 后台路径：已登录玩家的续租连续 `Err` 超过 `Lease`（窗口跑完、键过期）→ Redis 恢复，后台 `Owns` → `Claim` 的 SetNX 落地但返回错误 → 下一轮 `renew`。

## 预期

- 准入在“设键那次请求发出的时刻 + `Lease` − `AdmissionGuard`”之前收口：`AdmissionGuard` 是留给在途事务的，最后一刻放行的事务要在键可能过期（别的进程可以合法接手）之前结束（RR-20260920-04，`AdmissionGuard` 常量注释）。
- 有过间断的租约，在间断前的副本被扔掉之前不放行（RR-20260920-09 / RR-20261001-07）；`Refresh` 答 Held 不能替代这一步。

## 根因（基线 `5d1cb974` 行号，`demo/internal/service/game/playerowner.go.tmpl`）

- `:888` `confirmLocked`：`state.validUntil = owners.now().Add(playerroute.Lease)`——窗口从**确认时刻**起算。
  - `claim:1118` `store.Claim`（SetNX 或对自己键的 `CompareAndExpire`）设下键 TTL；`:1126-1145` 跨间断时 `dropResident` 最多等 `evictWait`（`evictBudget` 5s）；`:1149` `confirmClaim` 才起算——本地窗口比键多一份撤离等待，准入一直开到键过期那一刻，`AdmissionGuard` 被整个吃掉。
  - `renew:556` `store.Refresh` 逐个玩家往返，`:559` `confirmRenewal` 在整批返回之后起算——`Refresh` 有多慢，窗口就比键多多少（无上界，取决于 Redis 往返）。RR-20261004-10 把确认挪到等待之前，没有处理 `Refresh` 自身的耗时。
- “另记”：`claim:1119-1121` `store.Claim` 报错直接返回，不记任何东西；token 按进程固定（RR-20260920-03），落地的 SetNX 让键重新是“我们的”。
  下一轮 `renew:559` 对 Held 一律 `confirmRenewal` → `confirmLocked` 清 `interrupted`、延长窗口：刷新循环路径上已标 `interrupted` 的玩家被清掉标记；后台路径（窗口已跑完、未标 `interrupted`）被续回服务。两条都跳过了 `:1126` 的撤离。

## 修复约束

- 本地窗口从“设键那次请求发出的时刻”起算：认领在 `store.Claim` 之前取时刻，续租在 `Refresh` 之前取时刻；不新增等待、不改锁顺序。
- 认领丢回复不能由下一轮续租“确认”：跨间断认领报错时把仍有本地状态、且租约此刻不可服务的玩家记为 `interrupted`；`Refresh` 对 `interrupted` 的租约答 Held 时不确认，而按丢失的租约在回合预算内重新认领（扔副本再确认）。
- 接受侧：键从未中断的租约（例如只因撤离进行中被 `Admit` 拒绝，RR-20261004-11）在认领报错后不受影响。
- RR-20260920-09 / 12、RR-20260921-03 / 04、RR-20260930-23、RR-20261001-07、RR-20261004-10 / 11 的回归保持绿。
