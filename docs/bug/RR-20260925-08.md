# RR-20260925-08：小等待队列提前拒绝可并发请求

日期：2026-09-25；基线：RR-07 双池实施后的未提交工作树，未部署。影响 Nest 双池准入，等级 P1。状态：已修复，见[修复记录](../bugfix/RR-20260925-08.md)。

`dispatchQueue.admit` 原先只按尚未被 worker 取走的消息数检查 QueueCap；就绪且可使用 worker 的消息也占等待预算。1024 worker / 16 等待位时，若突发准入早于 worker 被 Go 调度，第 17 条独立 ID 消息就报满，尽管执行额度尚未使用。热 ID 填满等待预算也会错误拒绝有空闲执行额度的独立 ID。

预期：并发额度与额外等待额度独立；满足全部 ID 前驱的消息可以预留执行额度。被 ID 前驱阻塞的请求始终使用等待预算，不能借空闲 worker 掩盖热点积压。

在 Go 1.27.0、Apple M5 上，`TestWorkerBudgetAdmitsBurstBeforeWorkersRun` 确定性启用准入而不启动消费 goroutine，模拟准入突发先于 worker 运行；修前快/慢两组均在第 17 条失败。`TestWorkerBudgetDoesNotReserveWorkersForBlockedIDs` 同样复现旧预算错误。原始日志和旧源码保留在 `artifacts/perf/nest/two-pool-review-20260925/`。

复现命令：`GOCACHE=/tmp/roost-nest-go-cache GOWORK=off go test ./nest -run TestWorkerBudget -count=1`。修前日志为旧调度器配新增测试运行所得；现在相同测试通过。另有真实启动 1024 慢 goroutine、阻塞全部 worker、填满 16 个等待位、拒绝超额请求、释放并排空的回归；不是 Remote 吞吐压测。
