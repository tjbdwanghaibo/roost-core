# RR-20260924-08：pipelined 内联完成吞掉 AfterCommit 错误

- 日期 / 基线：2026-09-24，`967bc69` 加 Nest N1～N4 工作树；复现时 RR-07 已修复。
- 范围 / 等级：pipelined inline 和完成队列满降级；P2。
- 状态：已复现、已修复，未提交、未发布。[修复记录](../bugfix/RR-20260924-08.md)。

## 预期与实际

WAL 成功，AfterCommit callback 抛出 panic。事务已经提交，预期其后回调继续运行，回复 ErrAfterCommitFailed，不能伪装为成功或回滚。

原 RollbackTx.Commit 以“当前 goroutine 还有 Guard scope”判断是否应推迟回调。pipelined 已提前释放全部锁，但 scope 要到 NestDispatch 最外层收尾才移除；因此 inline/saturated 将回调追加到 Guard，返回 nil，先发送成功回复。随后 Guard 执行回调时只记录 panic 日志，调用者收不到失败。

队列满时，complete 还在真正的回调执行前释放同主实体的完成排序位置。完成池路径没有这个 Guard，行为因是否降级而不同。

## 修前证据

```sh
GOCACHE=/tmp/roost-nest-go-cache GOWORK=off go test ./nest \
  -run '^TestPipelinedInlineCompletionReportsCallbackFailure$' -count=1 -timeout=20s
```

生产 NestDispatch + 自动完成 ticket + callback panic，三个模式对比。修前 queued 通过，inline 和 saturated 实际失败：

```text
inline: reply=committed, want ErrAfterCommitFailed
saturated: reply=committed, want ErrAfterCommitFailed
```

根因在 [rollback.go](../../nest/rollback.go) 的 Commit 回调调度，与 [execution.go](../../nest/execution.go)、[pipelined_completion.go](../../nest/pipelined_completion.go) 的实际解锁边界不一致。现有单独 RollbackTx.Commit 测试没有生产 dispatch 的 Guard，不能发现此缺口。
