# RR-20260926-65：handler 内 RunIsolatedTransaction 已提交后外层消息因锁超时重排，独立事务被再次提交

日期：2026-09-27。基线：本地 main `7706419`（RR-48～63 合并后，未推送）。来源：第二轮修复后独立审计。等级 P3（修前即有，RR-48 扩大触发面：吞掉 Create 冲突后强制回滚重排）。状态：已复现，未修复。
（最终状态见文末修复节：**已修复，随 v1.17.1 发布**，详见[修复记录](../bugfix/RR-20260926-65.md)。上面的“状态”是登记时的原值，保留不改。——2026-09-27 回写，OPEN-ITEMS A13②）

`nest/execution.go:121-127` 嵌套事务不认领 Msg（有意）→ `nest/nest_dispatch.go:95-99` 重排。复现：[REPRO-2026-09-26-06](REPRO-2026-09-26-06.md) §1：`attempts=2 isolatedRuns=2 isolatedCommits=2`（修前修后同）；吞掉冲突时 `attempts=20 … isolatedCommits=20`。仓内唯一生产调用 `dataengine/engine/entity_delete.go:92`（无 RollbackTx 时）。

修复约束（维护者 2026-09-27 批准，与 RR-64 同规则）：消息执行期间任一嵌套独立事务已持久提交，则该消息不再自动重排（按“已越过提交点”处理，回复带可判别错误）。

## 修复（2026-09-27）

状态：**已修复，未发布**（本地提交，未推送）。按修复约束实现：不认领消息的嵌套独立事务在 `commitDurable` 里持久提交（committer 接受了非空记录）
或结果未知时，在当前派发消息上记 `nestedTxCommitted`；它并入 RR-49 的 `transactionPastCommitPoint`，消息不再自动重排；消息自己的事务没有提交时
回复包新哨兵 `nest.ErrNestedTransactionCommitted`（保留原因链，不带 `ErrAfterCommitFailed`）。独立事务被拒绝 / 没有写内容时外层照旧可重排。
修前红：§1 P-C 改写的回归在 strict / memory / pipelined 三种外层下均 `attempts=2 isolatedRuns=2 isolatedCommits=2`。详见[修复记录](../bugfix/RR-20260926-65.md)。
