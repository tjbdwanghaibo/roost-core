# RR-20260926-05：快照额度在任何 Push 之前对全部会话预扣，RetryLater / 取消后本窗口额度被未尝试的会话占满

日期：2026-09-26。基线：main `a22c5a5`（`8ce21a5` 同一探针通过，是 a22c5a5 引入的回退）。等级 P2（恢复吞吐损失一个窗口；不破坏结算契约）。
状态：已复现，未修复。

## 触发条件

Flush 中 Transport 对某个会话返回 `ErrRetryLater`，或 ctx 已取消且 Push 出错（Stop 取消在途 Push、AsyncTransport 已关闭等）；
on_change 模式下同一预算窗口内会再次 Flush。另一个入口：准入循环里“会话已变更，跳过”的分支。

## 预期 vs 实际

预期：冷快照额度（对象 / 字节 / 每会话 / 轮转位置）只按真正尝试或准入的会话结算。`8ce21a5` 在逐会话循环中、各自 Push 前才扣，
失败时只扣当前会话。

实际：a22c5a5 在准入循环之前对整张 work 一次性调用 `m.scheduleSnapshots(work, plan)`，立即累加 `m.windowAllowance`、
`m.windowSessions`、`m.snapshotCursor`、`m.snapshotNextClass`；随后第一个会话 Push 即 RetryLater 返回，后面的会话没尝试，
却已占满额度并推进了轮转位置。同窗口第二次 Flush 交付 0 帧。

## 根因（代码）

- `sync/entitysync/flush.go:265`：`m.scheduleSnapshots(work, plan)` 在 `for _, sid := range sessionIDs` 之前执行。
- `sync/entitysync/snapshot_budget.go:246-275`：计划阶段即写入窗口额度、每会话计数与游标（`:270-274`）。
- `sync/entitysync/flush.go:340-348`：RetryLater / 取消路径 `abortAll` 后直接返回，没有退回未尝试会话的额度与游标。
- `sync/entitysync/flush.go:271`：会话已变更而 `continue` 的分支同样已被计费。

## 复现

探针源码与输出见 [REPRO-2026-09-26](REPRO-2026-09-26.md) §3：3 个会话各 1 个冷对象，`{MaxObjects:3}`，on_change、Interval=1h；
第一次 Flush 注入 `ErrRetryLater`，同窗口再 Flush 一次。

```text

         same-window second Flush: frames=0 CreatesAdmitted=0 SnapshotsDeferred=3 PendingSnapshots=3   --- FAIL
8ce21a5: after RetryLater: windowAllowance={objects:1 bytes:109} windowSessions=map[1:1] snapshotCursor=1 delivered=0
         same-window second Flush: frames=2 CreatesAdmitted=2 SnapshotsDeferred=1 PendingSnapshots=1   --- PASS
```

命令：`GOWORK=off go test ./sync/entitysync -run TestProbeRRRetryLaterPrechargesWindowBudget -count=1 -v`（探针已删除，源码在附录）。

## 影响

只影响当前一个预算窗口：恢复吞吐少一个窗口，轮转跳过未尝试的会话。只有全部帧成功才结算的契约没有被破坏（`flush.go:354`）。
相关但更早就存在的：会话因编码 / Push 失败被关闭时已扣额度不退（`8ce21a5` 同样），修复时一并考虑。

## 实施方向（约束）

- 额度与游标的写入要与“实际尝试 / 准入”对齐，或在 RetryLater / 取消 / 会话变更路径上退回未尝试部分；
  保留 a22c5a5 的数量预选与字节准入同序（`plan.order`）和类别公平。

## 验收覆盖点

- 上述探针：同窗口第二次 Flush 能交付未尝试会话的冷对象。
- RetryLater 发生在第 k 个会话时，只有前 k 个会话被计费，游标不越过未尝试会话。
- 会话变更跳过的分支不计费；既有 `recovery_fairness_test.go`、`snapshot_requests_test.go` 保持通过。

## 复核残留（2026-09-26，基线 985d5ba，未修复）

游标轮转时仍会越过未尝试会话：4 会话、游标在 2、计划顺序 3→4→1，会话 3 返回 RetryLater 后游标推进到 1，跳过从未尝试的会话 4（同窗口剩余额度给了会话 2）。根因：commitSnapshotAttempts 按计划顺序推进游标，而实际 Push 按会话 ID 顺序。修复方测试都从游标 0 开始。输出：`retry flush: attempted=[1 3] windowSessions=map[1:1 3:1] cursor=[1 0]`、`same-window second flush delivered=[1 2]`。
