# NC-123：hotcode 并发 Replace / Revert 留下互相矛盾的补丁点状态

2026-10-05，基线 `197f7bb9`。P3（两个运维同时操作、或 `hotcode.load_plugin` 与 `hotcode.revert` 交错时，补丁点可能永久停在“当前是原函数、Meta 却是补丁版本”或“当前是补丁、Meta 为空”；`hotcode.list` 报的 Patched 与 Meta 互相矛盾，运维据此判断“现在跑的是哪个补丁”会出错。实际执行的函数始终是某一次写入的完整函数，不会调用到半个函数）。状态：已复现、已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-123.md) · [本轮](../review/REVIEW-2026-10-05-noncore-n10.md)。

## 触发与差异

`hotcode/registry.go`（基线）每个补丁点用三个独立原子值：`current`（`:43`）、`meta`（`:44`）、`gen`（`:45`）。`Replace` 依次 `current.Store` / `meta.Store` / `gen.Add`（`:135-137`），`Revert` 依次写原函数 / 空 Meta / `gen.Add`（`:146-148`），两者之间没有互斥；`List` 也分别读三者（`:172-179`）。

交错 `Replace.fn → Revert.fn → Revert.meta → Replace.meta` 之后，current 是原函数、meta 是 v2；反过来则是补丁函数配空 Meta。生产入口：game-demo 把 `hotcode.RegisterAdminCommands` 挂在 GM admin 上（`demo/internal/service/game/gm.go.tmpl:494`），admin 命令可并发执行；Nest 每个全局 handler 都是补丁点（`nest/handler.go:60`）。

## 复现

没有可注入的调度点，用有界轮数（100000）的并发对撞 `hotcode/concurrent_patch_promises_test.go`：修前 5 次普通运行 + 1 次 `-race` 全部撞出（两种形状都出现过），[原文](../bugfix/evidence/noncore-bugfix-20261005-n10/red.txt)：

```
round 3708: torn patch point: resolve=1 patched=false meta={Version:v2 ...} generation=2
```

探针阶段另见 `resolve=2 patched=true meta={Version: ...}`。
