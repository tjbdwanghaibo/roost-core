# RR-20261006-13：glsvet 的 A1 提示看不见经同包 helper 函数登记的 undo

2026-10-06，基线 `87d8d91e`。P3（静态检查盲区，只影响提示，不影响运行；A1 规范“组件里不登记 undo”可以被一个包级 helper 绕过而不被发现）。来源：v1.23.0 双文档 DAO 部分的源码观察（[impl-saga-drv-dao-rem.md](../release/v1.23.0/impl-saga-drv-dao-rem.md) “glsvet A1 提示的盲区”），协调者 2026-10-06 派给 `fixn`。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261006-13.md)。

## 机制

`cmd/glsvet/main.go` `componentUndoHints`（基线 `:691`）只在组件方法（接收者类型名以 `Component` 结尾或匿名嵌入 `ComponentBase`）的方法体里找名字为 `RecordUndo` / `RecordUndoToken` / `DeferRollback` 的调用。组件方法调用同包包级函数、由那个函数登记 undo 时，组件方法体里没有这三个名字，提示不出现；与 A1 直接违例是同一件事（组件持有需要回滚的内存状态、自己登记逆操作）。

同一工具的停止类函数提示（`cmd/glsvet/stophints.go`，A3）已经“跟进一层同包 helper”，A1 提示没有。

## 触发 / 预期 / 实际

- 触发：`func (c *BuffComponent) push(v int) { c.stack = append(c.stack, v); rememberPop(c) }`，`rememberPop` 是同包包级函数，里面 `nest.CurrentRollbackTx().RecordUndo(...)`。
- 预期：在 `push` 调 `rememberPop` 处打印 A1 `hint:`。
- 实际：无提示。
