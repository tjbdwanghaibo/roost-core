# RR-20261006-29：game-demo 每个活动窗口开头最多 5s 里通关不计入活动，机器人判失败

2026-10-06，基线 main `0db819b0`。P3（每 300 秒一次的确定性缺口：这段时间的通关丢掉活动贡献，`finish_dungeon` 回不出窗口 id；loadtest 只要有机器人落在缺口里就 `rc=1`，演练与 CI 跨窗口边界时随机变红）。来源：[真实进程演练](../bugfix/REAL-PROCESS-DRILLS-2026-10-06.md)第 ⑥ 项（Redis Cluster 下重跑时起跑恰在 23:05:00 前）。与 Cluster 无关，单机同样发生。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261006-29.md)。

## 触发与差异

活动窗口按业务时钟每 `gameactivity.WindowSeconds`（300s）滚一次，窗口 id 由时钟现算。协调方那里的窗口由 game 的 `runActivity` 循环每 `activityLoopInterval`（5s）`OpenActivity` 一次（`demo/internal/service/game/activity.go.tmpl`）。所以每个边界之后最长 5s，时钟所在的窗口在协调方还不存在；这段时间里 `Contribute` 的 `ApplyProgress` 得到 `activity: not found`（`CodeMissing`），`finish_dungeon` 把贡献当作“尽力而为”丢掉、只记 Warn，响应里没有 `ActivityID`，机器人断言 “the clear did not say which activity window took its point” 失败。

真实进程（3 主 3 从 Cluster 演练，P1 23:04:57 起，机器人 23:04:59 起跑）：

```
23:04:59.036 INFO activity: window open activity_id=race-1791298800 closes_at=1791299100
23:05:03.197 WARN finish_dungeon: clear not contributed to the activity player_id=100001 activity_id=race-1791299100 err=remote.620102: activity: not found
……（23:05:03.2～23:05:04.0 共 5 条）
23:05:04.077 INFO activity: window open activity_id=race-1791299100 closes_at=1791299400
loadtest A end rc=1 runner: stop started=10 success=4 failure=6（5 个 finish_dungeon；另 1 个因为少了 5 个机器人排队落单，poll_match 超时）
```

- 预期：通关时窗口还没开，贡献也记进时钟所在的窗口（窗口 id 由时钟决定，“开窗”只是让协调方知道它存在）。
- 实际：贡献丢失。`finish_dungeon` 的注释说“窗口少一点不是失败的副本”，但这一点并不是因为什么失败而丢，只是开窗循环还没轮到。

## 复现

`demo/internal/service/game/activity_test.go.tmpl` `TestAClearInTheFirstSecondsOfAWindowStillCounts`：协调方只接受已开窗口的进度（没开答 `ErrMissing`），上一个窗口开着，时钟进入下一个窗口 1 秒。修前（生成工程里 `GOWORK=off go test -count=1 -run TestAClearInTheFirstSecondsOfAWindowStillCounts ./internal/service/game/`）：

```
--- FAIL: TestAClearInTheFirstSecondsOfAWindowStillCounts (0.00s)
    --- FAIL: TestAClearInTheFirstSecondsOfAWindowStillCounts/activity-on (0.00s)
        activity_test.go:168: a clear 1s into window race-1791299400 was refused: activity: not found
```
