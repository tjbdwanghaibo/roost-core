# RR-20260926-21：正式装配下 Remote 并行投影从未开启（`remoteentity.Backend` 未转发 `SupportsConcurrentRemoteCommits`），Remote 吞吐验收未在正式装配上测得

日期：2026-09-26。基线：main `aaada47`。等级 P2（性能与验收口径；不影响一致性）。
状态：已确认（源码 + 探针），未修复。来源：上线前复审（Remote 持久权威）。

## 现象

`MongoStore.SupportsRemoteParallelProjection`（`dataengine/engine/mongo_projection.go:143-151`）要求 remoteStore 与 publisher 都实现
`SupportsConcurrentRemoteCommits() bool`。仓内只有 `*remoteentity.MongoCommitter`（`mongo_committer.go:428`）与 `*remoteentity.Manager`（`transaction_manager.go:916`）实现。

正式链路里 remoteStore 是 `*remoteentity.Backend`：`remoteentity/assemble.go:77-86,109`（`AtomicStore` = backend）→ `mods.ModRemoteEntityAtomicStore`
→ `kit/dataengine/mod.go:242-246`（`deps.RemoteStore`）。`remoteentity/backend.go` 没有转发该方法，于是正式装配下 `parallel=false`，
RR-20260925-05 的并行投影与九项 D2 滑动窗口在生成工程 / kit 装配中都不生效。审查 agent 探针输出：`production wiring (Backend as atomic store) parallel=false`。

## 验收口径的影响

Remote 性能入口 `scripts/perf/remote.sh` / `remote-capacity.sh` 运行 `scripts/test-remote-generated.sh`，其流程
`codegen/internal/entity/testdata/remoteflow/flow_test.go:157,245` 把 `remoteentity.NewMongoCommitter(...)` **直接**交给 `store.SetRemoteProjection`，
并设置 `RemoteProjectionWorkers`（`:260`），即测量时并行投影是开启的，而正式 kit 装配是关闭的。因此交接文档 §4 的 Remote 30 分钟 80TPS、120/160TPS 容量、
RR-20260925-05 的 “30 分钟 59.997 TPS” 等结论**不代表正式装配**，需要在正式装配上复测后再作为上线依据。

## 实施方向（约束）

- 让正式装配传给 DataEngine 的 remoteStore 如实声明并发能力（转发或改为传递实现者），或在装配时显式检测并报告；不能为了开并行放宽冲突屏障 / 连续前缀 ack。
- 性能测试入口应走与生产相同的装配路径，或在报告中写明差异。

## 验收覆盖点

- kit 装配下 `SupportsRemoteParallelProjection()==true`（或文档明确为串行）。
- 正式装配同口径复测 Remote 持续与容量阶梯，更新交接文档 §4。
