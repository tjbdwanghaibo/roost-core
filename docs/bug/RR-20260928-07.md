# RR-20260928-07：k8s Secret 示例缺 `saga` 与 `player_access` 段，按示例部署时 saga 按 8 GiB 默认建流失败、玩家 TCP 默认关闭

日期：2026-09-28。基线：本地 main `e80d88e`。来源：批次 16（RR-20260928-06 演练时发现）。等级 **P3**。引入：修前即有。状态：已复现，**已修复**（2026-09-28，分支 `fix-r9-b17`，本地提交，未推送 / 发布），见[修复记录](../bugfix/RR-20260928-07.md)。

`renderKubernetesSecretExample` 按 Mod 目录渲染；`saga` 段（`appendModConfigSections`，add saga 时追加）与 `player_access` 段（`ensurePlayerTCPConfig` 事后追加）只写进开发配置与 prod 示例。
实跑用 Secret 示例的 config 起 game：`mod saga start: saga: ensure stream: nats: API error: code=500 err_code=10047 description=insufficient storage resources available`（按代码默认 8 GiB 建 `ROOST_SAGA`）；缺 `player_access` 时玩家 TCP 默认关闭。

修复约束：Secret 示例与 prod 示例由同一份配置源渲染（事后追加的段也进 Secret），加生成器回归：Secret 示例内嵌的 `config.yaml` 与 prod 示例键集合一致（允许 Secret 独有的敏感值占位）；旧工程 sync 是否更新（Secret 示例是否脚手架写一次）如实写明。

注：本次实证中修复方的探测按默认值连到了共享的 `saga` 库（一次幂等的集合 / 索引确认）并对既有 `ROOST_SAGA` 流做了 ensure（被服务端拒绝）；事后核对 `ROOST_SAGA` 的创建时间、512 MiB 上限、112 条消息、5 个消费者均未变，`saga` 库无业务文档写入。之后的演练须先把 saga 库名 / 流前缀改到隔离名再启动。
