# RR-20261006-62：lockstep 广播预算不扣传输开销，满载时整个房间的广播被拒

2026-10-07，基线 `a7285da6`。P1（`NewRoom` 接受的配置在满载时每一帧对所有接收者都被传输以 `ErrPayloadTooLarge` 拒绝——预算检查本来要防的“整房间变黑”）。来源：框架文档审查 F04-6。维护者 2026-10-07 选 A。
状态：已复现；已修复（`4ce70763`，[修复](../bugfix/RR-20261006-62.md)），未发版。

## 机制

1. `RoomConfig.MaxDatagramBytes` 缺省 `DefaultMaxDatagramBytes = 1232`（基线 `sync/lockstep/room.go:41-43`），注释说“与 UDP 传输默认包上限一致”。
2. 但 1232 是 AEAD UDP 传输**加密后**的包长（`DefaultUDPMaxPacketBytes`），载荷还要扣 16 字节头 + 16 字节 GCM 标签；KCP / QUIC 的默认载荷上限是 1200（`nettransport.DefaultMaxDatagram`）。
3. `NewRoom` 的最坏包估算按 1232 放行，最坏包落在 1201..1232 的配置能构造成功；满载时 `SendDatagram` 对每个接收者都返回 `ErrPayloadTooLarge`。Room 不知道发送器的真实上限，也没有途径知道。
