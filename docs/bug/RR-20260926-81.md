# RR-20260926-81：rollbackable handler 内新建实体冲突回滚后，同 ID 新建拿到 ErrEntityRemoved 作为最终错误（RR-48 回归偶发失败）

日期：2026-09-27。基线：本地 main `9a473cd`（RR-73～80 合并后，未推送）。来源：RR-73～77 修复方范围外发现，主会话复现。等级 **P3**。引入：RR-20260926-48 修复（修前该路径是永久死锁）。状态：已复现，未修复。

RR-48 的回归 `TestHandlerCreateCrossOrderResolvesWithoutDeadlock`（`nest/create_lock_order_promises_test.go`）在 `62fdbe6` 与 `9a473cd` 上都偶发失败。
主会话复现：`GOWORK=off go test -race -count=300 -run TestHandlerCreateCrossOrderResolvesWithoutDeadlock ./nest`：

```text
--- FAIL: TestHandlerCreateCrossOrderResolvesWithoutDeadlock (0.08s)
    create_lock_order_promises_test.go:137: h2: want ok or ErrEntityExists, got ret=<nil> err=entity manager: entity removed: 10097605 is being removed
    create_lock_order_promises_test.go:141: want exactly one winner and one ErrEntityExists, got winners=1 losers=0 results=map[h1:{h1 ok <nil>} h2:{h2 <nil> 0xc00034a2a0}]
```

现象：两个 RollbackState + strict handler 反序新建 X、Y，冲突方整条回滚、撤销已发布的新建实体后重新准入；某次执行里 `access.Create` 撞上
`entity/entity_manager.go:113-114` 的 `removing` 分支，返回 `ErrEntityRemoved`（“is being removed”）。该错误不是锁超时类，消息不重排，作为最终业务错误回复。
即：回滚撤销发布（移出 Manager）尚未完成时，同 ID 的新建已经可以进入 `TryAdd`，观察到“正在移除”的中间态。业务侧同形状（冲突回滚后重试新建同一 ID）会拿到调用方无法区分的失败。

修复约束：
- 根因先定位到行：撤销发布与“释放新建实体锁 / 重新准入”之间的先后关系，写进修复记录。
- 不在快 worker 上同步等待移除完成（roost-coding 快池不阻塞）。
- 可回滚事务内，新建撞上本框架撤销中的同 ID 应与 RR-48 的锁冲突同样处理（整条回滚后重新准入），或由撤销在释放锁之前完成移除使该中间态不可观测，二选一由修复方论证；
  不可回滚事务按 RR-64 返回 `ErrCreatedEntityLockConflict`，不重排。RR-48/49/64/65/67/73 回归不回退。
- 回归以事件顺序钉住中间态（不靠 `-count=300` 碰概率），原用例 `-race -count=300` 须稳定通过。

## 修复（2026-09-27）

状态：**已修复，未发布**（本地提交，未推送）。

机制：采用约束中的第二种——Nest handler 内（Guard 绑定了 `CreatedEntityCapturer`）新建时 `TryAdd` 撞上 `removing` 标记（同 ID 的上一个实例
撤销 / 销毁收尾未完），`CreateInScope` 归还本次取得的锁后改由 capturer 给 RR-48 / RR-64 的新建锁冲突错误：可回滚事务得到
`ErrLockTimeout` + `ErrCreatedEntityLockConflict`，整条回滚后重新准入；不能回滚的 handler 得到只带 `ErrCreatedEntityLockConflict` 的错误，不重排。
不在快 worker 上等待收尾；Nest 之外仍返回 `ErrEntityRemoved`（RR-57 的 GetOrCreate 有界重试不变）。

修前红（`nest/created_entity_revoke_window_promises_test.go`，事件顺序钉住“锁已释放、removing 仍在”的窗口）：

```text

    created_entity_revoke_window_promises_test.go:208: memory B inside the revoke window: reply err=entity manager: entity removed: 10225605 is being removed (ErrEntityRemoved=true); want ErrCreatedEntityLockConflict without ErrLockTimeout (RR-64 shape)
```
