# RR-20261006-50：syncstream 重启与恢复——首条 WAL 半截打不开、回放不恢复活动时间、Recover 覆盖 provider 的 schema 版本

2026-10-07，基线 `47abe511`（main，v1.23.0 之后）。P1（(a) History 永久打不开、(b) 重启后误删活跃流）/ P2（(c) 载荷与标签不一致）。来源：[FRAMEWORK-DOCS-FINDINGS-2026-10-07](../review/FRAMEWORK-DOCS-FINDINGS-2026-10-07.md) 的 F04-15，[04-sync 实现 §10.2](../framework/impl/04-sync.md#102-本篇写作时发现的源码疑点待闭环)。
状态：已复现；已修复（提交见 [修复记录](../bugfix/RR-20261006-50.md)），未发版。

## 机制

- **(a)** 目录里还没有 checkpoint，第一条 WAL 只写了半截（崩溃 / 断电，`Record` 从未返回成功）。`Load` 因 `wal-1` 非空把 `Epoch` 置 0，等第一条完整记录来定（基线 `syncstream/file_journal.go:119-124`）；回放跳过半尾、一条完整记录也没有，`Epoch` 仍为 0，`Import` 报 `epoch is required`（`syncstream.go:591-593`），History 永久打不开，只能人工删 `wal-1`。半尾在 Load 时也不计数、不告警（nestwal 打开时截断未确认尾部并计数告警）。
- **(b)** 回放 Append / Acknowledge 不更新 `LastActivityUnixNano`（`file_journal.go:495-539`），重启后流的活动时间停在 checkpoint 时；首次 `SweepIdle` 把 checkpoint 之后活跃过、但 checkpoint 时已超过 `IdleTTL` 的流当作空闲删掉。
- **(c)** `Recover` 用请求方的 `SchemaVersion` 覆盖 provider 返回包上的版本（`syncstream.go:378-380`）。按自己 schema 编码并如实标版本的 provider（skillsync 的 projector 不看请求的版本，`skill/skillsync/coordinator.go:442-466`）发出的 Full 标签与载荷不符，之后生产方按真实 schema 发的 delta 被 `ErrSchemaTransitionRequiresFull` 拒绝，直到下一个 Full。
