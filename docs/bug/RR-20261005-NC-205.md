# RR-20261005-NC-205：origin 不可达时 pretag 跳过“远端没有同名 tag”检查并报告 ready

日期 2026-10-05。基线 main `8597046c`。等级 **P3**。状态：已复现，未修复。来源：N15。

## 触发与实际

`scripts/pretag.sh:49`：`git ls-remote --exit-code --tags origin … >/dev/null 2>&1` 只把退出码 0 当“已存在”。`--exit-code` 在没有匹配时返回 2，网络 / 认证 / 远端错误返回 128，后者也走进“不存在”分支，检查被静默跳过。origin 指向不存在的仓库时：

```
pretag: framework release manifest names v1.99.0
…
pretag: example.com/pretagred@v1.99.0 is ready to tag
pretag exit=0
```

（[脚本](../review/evidence/noncore-review-20261005-n15/pretag_red.sh) · [输出](../review/evidence/noncore-review-20261005-n15/nc205-red.txt)。）

## 影响与定级

脚本注释说明重打已发布 tag 比坏 tag 更糟（proxy 已缓存旧内容）。之后的 `git push` 对已存在的远端 tag 通常会被拒绝，所以是纵深防御失效，定 P3。

## 验收

ls-remote 返回 2 才算“远端没有”；其他非 0 退出码让 pretag 失败并说明无法核对远端。
