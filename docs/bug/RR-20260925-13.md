# RR-20260925-13：冷快照窗口边界随晚醒漂移

日期：2026-09-25。基线：main `646ce63` 加本轮 Sync 工作树。等级 P2。
状态：已复现并修复，见[修复记录](../bugfix/RR-20260925-13.md)。

on_change 预算用尽后，由 Flush 检查窗口到期。旧实现每次用实际执行的 `now` 作为下一窗口
起点，执行晚到的时间因此叠加到后续窗口。即使之后按原边界唤醒，也可能再次被拒绝，降低
恢复额度释放速率。该问题与业务 20Hz 频率和网络发送耗时无关，不等同于所有超标样本根因。

确定性复现：10ms 窗口在 t=17ms 才检查，旧实现把下一边界推到 27ms；t=20ms 即使检查也
不会释放下一窗口额度。应跳到当前固定时间窗口，下一边界保持 20ms。长时间空闲不积攒额度。

`go test ./sync/entitysync -run TestSnapshotWindowDoesNotDriftOrAccumulate -count=1`
在还原旧窗口赋值后失败：`late wake shifted next boundary or retained usage`。
产物收录在 `artifacts/perf/sync/final-closeout/window-before.txt`。

根因：`sync/entitysync/snapshot_budget.go:refreshSnapshotWindow` 用实际检查时间重新锚定窗口。
固定窗口仍是软预算，不承诺任意滑动 50ms 内的严格带宽上限，也不承诺端到端 50ms。
