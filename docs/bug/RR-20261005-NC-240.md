# NC-240：ai Parallel 结果已定仍 Tick 后面的子节点，发起没人要的动作再打断（或留下孤儿）

2026-10-06，基线 `81d7cb16`，分支 `revn10b`（N10 第二批）。P3（ai / actionflow 仓内无生产使用方；hotcode 由 Nest 全局 handler 与 game-demo 使用）。状态：已复现、已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-240.md) · [本轮](../review/REVIEW-2026-10-06-noncore-n10b.md)。

## 触发与差异

`ai/nodes.go:38-60`（基线）Parallel 每拍把全部未完成子节点 Tick 一遍，循环结束后才按策略判定；RequireAll 第一个子节点失败、RequireOne 第一个子节点成功时，结果在第一个子节点就已确定，后面的子节点照样被 Tick，随后 `Reset()` 打断它们。

预期：结果确定后同一拍不再 Tick 后面的子节点（注释：“fails as soon as any child fails”）。

实际：排在后面的 `TaskflowAction` 先发起一个动作，同一拍就被 Reset：配了 `OnInterrupt` 时“启动即取消”（多一对 Start / Cancel / OnEnded），没配时动作成为没有叶子等待的孤儿，一直占着动作组。
