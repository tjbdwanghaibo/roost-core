# RR-20261004-03：RefHMap Patch 只续期根到叶路径上的 hash，兄弟 hash 过期后 `Get` 返回部分记录且 `ok=true`

日期：2026-10-04。基线：v1.19.0（`74e1ba39`），main `2f111e9b`。来源：[B 线 NC 修复独立复审（第三组）§3](../review/REVIEW-2026-10-04-nc-audit-3.md)。等级 **P2**。状态：已确认，未修复。

## 现象、根因与修复约束

D3：NC-18 把根标量 Patch 的旧缺陷扩大到所有嵌套路径。根因 `cache/ref_hmap.go:87-90`（Patch Lua 只对 KEYS 路径 `PEXPIRE`）与 `decodeRefHMapNode`（`:632-663`，被引用但不存在的子 hash 留零值）。真实 Redis 实测写入的 `Other.X=42` 读回 0。可达：生成的 ref-hmap DAO（TTL 恒 > 0）。修复约束：Patch 对 `__keys` 注册表全部键 ∪ 路径键续期；可选地 Get 遇到被引用但缺失的子 hash 报 miss / 损坏。真实 Redis 回归。

复审报告里有修前 / v1.19.0 实测输出与会红的测试草稿（探针文件在审计 scratchpad，未入库）。

## 修复（2026-10-04）

状态：**已修复，本地验证通过（含真实 Redis 与临时 3 主 Redis Cluster 探针），已提交，未推送、未发版。** 修复记录：[RR-20261004-03](../bugfix/RR-20261004-03.md)。

- 根治：Patch 的 Lua 在根到叶路径之后声明记录布局里其余全部 hash，对全部声明键 `PEXPIRE`；注册表并入全部布局键（与 Set 写的注册表一致），没有 `__keys` 的旧数据被 Patch 后 Delete 不再漏删兄弟 hash（复审 §6 未验证分支，修前真实 Redis 实测漏删 2 个 hash）。
- 兜底：Get 遇到被引用、按布局写入时必然非空（该层有非指针字段）却已不存在的子 hash，整条记录报 miss，不返回部分值；覆盖修复前写入、兄弟已过期的数据，以及 pipeline 读取跨过同一过期时刻的情形。
- 回归 `cache/ref_hmap_patch_ttl_promises_test.go`：真实 Redis 5 个子用例修前全红（D3 原样两条读回 `other=&{X:0}`、兄弟 TTL 未续期、缺兄弟仍 `ok=true`、旧数据 Delete 漏删），包内替身 1 条修前红；修后全绿。原失败文本与结论不改。
