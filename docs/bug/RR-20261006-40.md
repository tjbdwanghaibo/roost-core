# RR-20261006-40：game-demo 业务代码读的配置键没有声明（doctor WARN），生成工程不在“读了没声明 / 声明了没读”守卫范围内

2026-10-07，基线 `82dfe672`（main，A4 ① `d1226825` 之后）。P3（声明之外的读取让 App 启动检查与 doctor 都看不到这些键：写错类型、拼错、漏写，
要到业务代码第一次读才暴露；新生成工程的 doctor 带一行无法消除的 WARN）。来源：v1.23.0 发版前维护者要求“交给 review 前不留能绕过检查的分支和 WARN”，
A4 ① 方案 §6“未完成 / 后续”自己列出的两项。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261006-40.md)。

## 机制

1. game-demo 的 game 业务代码直接读 viper：`activity.go` 读 `sid` / `server_type` / `activity.groups_file` / `activity.key_prefix`，`controller.go` 读
   `platform.payment_secret` / `sid`，`gift_saga.go` / `level_up_mail.go` 读 `saga.*` / `dataengine.*`（并手抄一份缺省值），`playerowner.go` / `gm.go` /
   `spawner.go` 读 `sid`；`purchase_drain.go` 经 kit 的 `platform.KeyPrefix(cfg)` 读 `platform.key_prefix`——game 进程没有任何 Mod 声明它。生成器写的
   `game/lifecycle/world_singleton.go`（`codegen/internal/roost/framework_services.go`）读 `sid`。
2. App 的启动检查与 `--print-config` 只收 Mod 的声明（`app/config_schema.go` 的 `checkConfig` / `ServiceConfigSchema` 只遍历 Mod），业务服务没有地方声明。
3. doctor 的 `config-schema` 只认生成器快照里的框架声明（`codegen/internal/roost/config_schema_doctor.go`），对 game 配置里的 activity.* / platform.* 报
   “no mod of game declares …”。
4. “读了没声明 / 声明了没读”的守卫（`app/config_declarations_promises_test.go`）只扫 app 与 kit。

## 触发 / 预期 / 实际

- 触发：`roost project new … -template game-demo`，replace 到仓库后跑 `roost project doctor`。
- 预期：零 WARN；生成工程的代码读配置只经声明。
- 实际：

```text
WARN  config-schema:game   configs/service/config.game.yaml: no mod of game declares activity.groups_file, activity.key_prefix, platform.key_prefix, platform.payment_secret (another service's keys, or read by business code); configs/service/config.game.prod.example.yaml: …; deploy/k8s/base/secret.game.example.yaml: …
```

用 `configschema.UndeclaredReads` 扫同一工程：16 处直接读取（`game/controllers/player/controller.go:207`、`:218`，`game/lifecycle/world_singleton.go:20`，
`internal/service/game/activity.go:103`、`:109`、`:115`、`:146`，`gift_saga.go:655`、`:658`、`:661`，`gm.go:150`，`level_up_mail.go:103`、`:106`、`:109`，
`playerowner.go:115`，`spawner.go:186`）。

## 根因与方向

业务代码没有声明配置的位置（生成的 bootstrap 没有业务 Mod 的注册位，App 只收 Mod 的声明），业务声明又只有编译后的进程知道、doctor 读不到。方向：
业务服务与 Mod 同样声明（`app.ModConfigSchema`）；doctor 编译工程、经 `--print-config-schema` 读回进程声明；守卫实现挪到叶子包，codegen 与 doctor 对生成工程用同一份。
