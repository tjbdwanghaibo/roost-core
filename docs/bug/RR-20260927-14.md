## 现象与根因

- `entity/unload_resync.go:49-57`：默认 Workers=4、QueueCapacity=4096、Attempts=5、退避 100ms~2s；每次尝试是一次共享冷加载，受框架上限 30s 约束。
  bf-59 自查写“有界但可能是分钟级”；按代码推算默认上界约 43 小时（见修复记录），期间订阅者停在旧内容上。
- 只有累计计数 `UnloadResyncStats`（Scheduled / Reloaded / Retracted / Failures / Overflow），看不到此刻的积压；entity 包不产出任何指标。
