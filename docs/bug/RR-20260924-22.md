# RR-20260924-22：fence 分配失败遗留无 TTL 的 owner

日期：2026-09-24；基线 `967bc69` 加前轮优化工作树；等级 P2。已复现、修复、验证，未发布。[修复](../bugfix/RR-20260924-22.md)。

versionedTryLockLua 先 HSETNX owner，再 INCR fence，最后设置 TTL。Redis Lua 出错不会回滚之前的写入。计数溢出时 Go 返回错误、本地未取得锁，但 Redis 已留下 owner，新建 hash 还没有 TTL，后续申请一直被拒绝。

TestRealVersionedLockCounterFailureDoesNotLeaveOwner 在专属 key 将 counter 预置 MaxInt64。修前申请失败后 HGET owner 仍返回非空 token，预期没有残留 owner。日志 `/tmp/roost-remote-lock-redis-red.log`。

```sh
source /tmp/roost-dataengine-it/env.sh
GOCACHE=/tmp/roost-nest-go-cache GOWORK=off go test -tags=integration ./remoteentity -run '^TestRealVersionedLockCounterFailureDoesNotLeaveOwner$' -count=1 -v
```

根因位于 remoteentity/versioned_lock_lua.go 的写入顺序；不应靠客户端清理不确定是否属于自己的租约。
