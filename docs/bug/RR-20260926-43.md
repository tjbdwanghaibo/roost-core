# RR-20260926-43：versionedLock 异步续期重启窗口——新代际 TryLock 见旧 touchActive 未清而不启动续期，新租约 TTL 后过期

日期：2026-09-26。基线：v1.17.0（`8811c02`）。等级 P3（安全由 Mongo fence 兜底；后果为本进程写被 fence / Unlock NotOwned）。状态：已复现（注入必现；无注入 20000 次约 0.47%），未修复。
（最终状态见文末修复节：**已修复，随 v1.17.1 发布**，详见[修复记录](../bugfix/RR-20260926-43.md)。上面的“状态”是登记时的原值，保留不改。——2026-09-27 回写，OPEN-ITEMS A13②）

旧续期 goroutine 在 Touch 中把 `acquired` 置 false（`remoteentity/versioned_lock.go:350-355`）后要到 defer 才清 `touchActive`（`:423-428`）；持有方释放时 `releaseRemoteEntries` 见 `!IsAcquired`
跳过 Unlock（`transaction_manager.go:449`）不等旧 goroutine；下一写者 TryLock 落在窗口内时 `startAsyncTouchLocked`（`:405-408`）见 `touchActive` 为 true 不启动续期。
复现：[REPRO-2026-09-26-04](REPRO-2026-09-26-04.md) §9。

修复约束：`touchActive` 按代际（token）绑定，或在置 `acquired=false` 的同一临界区清除，或 TryLock 在旧 goroutine 退出后补启动；不引入每次加锁新 goroutine 泄漏。

## 修复（2026-09-26）

状态：**已修复，未发布**（本地提交，未推送）。异步续期按锁代际（token）绑定：`touchActive bool` 换成 `touchGeneration string`；
`TryLock` 为新 token 启动续期时取消仍登记的旧代际 goroutine（不等待），旧 goroutine 只以自己的 token 续期、只清除自己的登记，
Unlock / Close 等待全部续期 goroutine 退出，不按加锁次数累积。
回归 `TestVersionedLockNewGenerationRenewsWhileOldTouchGoroutineExits`（状态注入必现）与
`TestVersionedLockTouchRestartStressNoLostRenewal`（20000 次无注入，修前漏启动 364 次，修后 0 次，`-race -count=20` 通过）。
详见[修复记录](../bugfix/RR-20260926-43.md)。
