# RR-20260926-76：嵌套独立事务结果未知时框架不 fence

日期：2026-09-27。基线：本地 main `736bdb2`（RR-64～72 合并后，未推送）。来源：第三轮修复后独立审计（[REVIEW-2026-09-27-audit3](../review/REVIEW-2026-09-27-audit3.md)）。等级 **P3**。引入：修前即有。状态：已复现，未修复。

`mgr.Fence` 只在消息自己的事务返回结果未知时触发（`nest/execution.go:46`）。嵌套独立事务的 committer 返回 `ErrCommitIndeterminate`、业务吞掉后，
外层 undo_strict 照常提交、回复 `ok`、`FenceError=<nil>`，后续请求照常受理。仓内 `admitLocalEntityDelete` 自己调 `runtime.fail`，所以仓内删除路径安全；
业务直接调用（疑点：`skill/combatcomponent` 的 `RunDetachedTransaction`）不安全。复现：[REPRO-2026-09-26-07](REPRO-2026-09-26-07.md) §1。

修复约束：与消息自己的事务同一规则——嵌套独立事务提交结果未知时，框架在返回业务之前 fence 引擎（与 `execution.go:46` 相同的 fence 入口与错误），
不依赖业务是否吞错；RR-65 的“已提交 / 结果未知不重排、回复带 `ErrNestedTransactionCommitted`”保持。
