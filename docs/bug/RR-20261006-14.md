2026-10-06，基线 `b549e4df`。P3（守卫失明，不是已发生的错误写：当前生产代码没有这种 helper；但守卫是方向 ① “所有步骤状态转移只走 stepTransition”唯一的强制点，

## 机制

`saga/step_transition_guard_test.go`（修前）按语法（`go/ast`）检查：

- `store.Apply` 的参数检查只对接收者是 `Engine` 的方法做（`engineMethod`），包级函数里的 `s.Apply(ctx, r)` 不检查；
- “改写 stepTransition 结果”只认同一函数里被 `stepTransition(...)` 赋值过的变量，函数参数上的字段赋值不报。

于是：包级 helper `func h(ctx, s Store, r ApplyRequest) error { r.CloseOperation = ""; _, err := s.Apply(ctx, r); return err }`，
Engine 出口写 `return h(ctx, e.store, stepTransition(record, after, transition{...}))`——出口里没有 `.Apply` 调用、没有字面量，helper 不是 Engine 方法、
改的是参数，守卫两个用例都通过，而写进 Store 的请求丢掉了 stepTransition 决定的放弃关闭。

## 触发与差异

预期：任何绕过 stepTransition 决定的写法都让守卫失败。实际：上面这种 helper 写法守卫通过。
