# RR-20260926-14：事务已持久提交后 AfterCommit 失败，Remote 批次仍被 Abort：远端实体在锁外被回滚为事务前状态并标 Rejected，与持久层分叉

**当前状态：已修复并完成适用本地验证，未提交/发布。** 见[修复与边界](../bugfix/RR-20260926-14.md)。以下保留原审查基线。

日期：2026-09-26。基线：main `aaada47`。等级 P2（需一次 panic 触发；后果是远端内存/状态与 Mongo 分叉，维护者可考虑上调）。
状态：已复现（复审方二次实跑），未修复。来源：上线前复审（Nest/Sync）。

## 触发条件

Remote 消息在 strict 路径上 WAL 已提交，但 `tx.Commit()` 返回 `ErrAfterCommitFailed`——某个 AfterAdmission 回调 panic
（例如 `dataengine/engine/entity_delete.go:72` 删除收尾里 `Destroy` 触发的业务 OnDestroy panic），或后置 panic 被 recover 成 err。

## 预期 vs 实际

预期：事务已提交，Remote 批次走 Commit，或只报告错误。

实际：`nest/execution.go:223` 原样返回错误；`nest/msg.go:83-84` 见 `dispatchErr != nil` 调 `batch.Abort`；真实实现 `remoteentity/batch.go:481-488`
执行 `rollbackFinalizedLocked`，把远端实体内存状态回滚到事务前并把事务状态写成 Rejected。这一步在慢 worker 上、Guard 已释放、未经 `RunLocal`，
违反“慢池不执行本地回滚 / 不取 Entity 本地锁”的契约，并与下一个业务竞争。同时 WAL 里的远端变更照常投影进 Mongo：内存、远端状态、持久层三者不一致。
postRemoteCommit 也被跳过，RR-20260926-13 的 Sync 冻结同样出现。对照：Durability 0 的 Commit 失败分支用了 `RunLocal`（`batch.go:462`），Abort 路径没有。

## 复现

探针源码见 [REPRO-2026-09-26-02](REPRO-2026-09-26-02.md) §3。复审方 2026-09-26 实跑：

```text
GOWORK=off go test -race ./nest -run TestProbeRemoteAbortAfterDurableCommit -count=1 -v
reply=nest: transaction committed but after-commit work failed: lifecycle finalizer panic
WAL record committed: mutations=1; local value=11; remote batch Commit called=false Abort called=true

```

## 实施方向（约束）

- `ErrAfterCommitFailed` 表示事务已提交：Remote 批次必须走 Commit（或保留为不确定交给 finalizer），不能 Abort。
- 任何远端实体内存回滚都必须回到快池、持锁执行。
- 与 RR-20260926-13 一起处理 postRemoteCommit 的执行条件。

## 验收覆盖点

- strict + AfterAdmission panic：请求报 `ErrAfterCommitFailed`，Remote 批次 Commit 被调用、Abort 不被调用，远端状态与 Mongo 一致，Sync 不冻结。
- 真正未提交的失败仍 Abort，且回滚在快池持锁执行。
