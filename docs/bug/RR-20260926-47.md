# RR-20260926-47：RR-25 准入判定在发送方 goroutine 调用 Getter，自定义 Getter 不遵守 LoadedEntitiesOnly 时同步 I/O 并串行化延迟派发

日期：2026-09-26。基线：v1.17.0（`8811c02`）。等级 P3（契约依赖）。状态：已复现，未修复。

`nest/slow_load.go:122-156` 在 `TrySendMsg`（`nest/dispatcher.go:258`）对每个声明目标调 `getter.Get`；探针模拟加载 200ms：异步 TrySendMsg 在发送方阻塞 200.7ms；
延迟派发在单个 delay loop goroutine 上准入，三条 10ms 延迟消息在 212 / 413 / 614ms 完成（锁超时 requeue 同走 delay loop，`group_transition.go:387`）。
复现：[REPRO-2026-09-26-04](REPRO-2026-09-26-04.md) §12。性能：已加载单目标准入探测 24.7ns/op、0 alloc（不构成退化）。

修复约束（维护者 2026-09-26 批准：改用是否已加载查询接口）：准入探测改用不做加载的查询接口（如 `IsLoaded`，ManagerAccess 实现）；自定义 Getter 未实现时退回旧行为（不判冷、不自动转慢），不依赖其遵守契约。

## 修复（2026-09-26）

状态：**已修复，未发布**（本地提交，未推送）。按修复约束实现：新增可选接口 `entity.LoadedChecker{ IsLoaded(id) bool }`，
`ManagerAccess` 实现为一次内存查找（无 loader 时视为无需加载）；Nest 只在 Getter 实现它时安装准入冷目标判定，判定不再调用 `Get`。
未实现的自定义 Getter 退回 RR-25 之前的行为：准入不判冷、不自动转慢、准入后也不原位转慢，冷目标返回 `ErrColdLoadInLogic`。
ManagerAccess 下 RR-25 的自动转慢、原位迁移与同 ID 顺序不变，原有回归全部通过；准入判定同机微基准（新基准，真实 ManagerAccess）
已加载单目标 15.83ns → 11.58ns、冷目标 111.3ns / 3 alloc → 17.0ns / 0 alloc。详见[修复记录](../bugfix/RR-20260926-47.md)。
