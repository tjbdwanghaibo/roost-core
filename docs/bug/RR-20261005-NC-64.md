# NC-64：game-demo 的开关热更说明指向 CSV，照做后 reload 返回 ok、开关不变

2026-10-05，基线 `3d4fe9f3`（origin/main，N07 第一批之后）。P3 文档缺陷（kill switch 的运维步骤写错：照说明改了表、reload 成功，开关却没动；GM 的 HTTP 面 `/admin/commands` 只列命令名，这段说明只在生成的源码里，所以定 P3，不是因为后果轻）。状态：已复现（真实进程）、已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-64.md) · [本轮](../review/REVIEW-2026-10-05-noncore-n07b.md)。

## 触发与差异

生成的 game-demo 里有三处告诉运维“改表 + reload”就能翻开关：

- `demo/internal/service/game/gm.go.tmpl:415`（`gm.config.reload` 的说明）：“which is also how a kill switch edited in configs/table/featureflag.csv takes effect”；
- `gm.go.tmpl:458`（`gm.flag.set` 的说明）：“to make it stick, edit configs/table/featureflag.csv and reload”；
- `demo/internal/service/game/flags.go.tmpl:27`、`demo/game/flags/flags.go.tmpl:11-13`：“editing the table and reloading is the normal way to flip one”“the store is rebuilt from it on every config reload”。

实际：`Store.ReloadWithReason`（`configdata/configdata.go:781`）只从 `config_data.dir`（`configs/data`）读 JSON；CSV 到 JSON 的转换只在 `roost generate`（cfggen/tablegen）里做，reload 从不读 CSV。文件名还写错了（真实文件是 `feature_flag.csv`）。发布物只带 `configs/data`（RR-20260928-05 的 release 清单），线上根本没有 CSV 可改。

后果：值班时按说明改 CSV → `gm.config.reload` 返回 `ok:true`、版本号前进、日志打出 `feature flags published` → 开关仍是旧值。应急关商店 / 关刷怪的操作静默失效。

## 复现（真实进程）

本机生成 game-demo，DAO 库名改成唯一名字，接隔离 Mongo / NATS / Redis（`~/.roost-it/roost-dataengine-it`）和私有 etcd，起 global + game 两个进程，经 ops admin 执行：

```
## S0 ... edit configs/table/feature_flag.csv (purchase -> false), no roost generate, then gm.config.reload
purchase,false,"The store. ..."
{"name":"gm.config.reload","ok":true,"data":{"flags":2,"reason":"s0-csv-only","version":2},...}
flags version 2 {'activity': True, 'monster_spawn': True, 'purchase': True}
```

对照：改 `configs/data/feature_flag.json`（S1）或改 CSV 后跑 `roost generate` 再 reload（S4）开关都翻了。原文见[证据](../bugfix/evidence/noncore-bugfix-20261005-n07b/e2e-reload.txt)。

## 本轮没做

没有改 reload 的行为（让 reload 读 CSV 会把转换期校验搬进运行时，属于设计选择）；`roost generate` 在 `make dev-run` 运行中因为 `.dev/*.log` 变化而拒绝执行，属于 N08（见本轮报告“移交 N08”），本条只修说明。
