# RR-20261006-06：saga 步骤预算的已知表按小写建，只差大小写的类型 / 步骤名静默互相覆盖

2026-10-06，基线 `8a292a5a`。P3（需要注册只差大小写的 saga 类型或步骤名才触发；覆盖落到哪一个取决于定义顺序）。来源：收尾盘点 A12。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261006-06.md)。

## 机制

`kit/saga/step_budgets.go` `StepBudgetsFromConfig` 用 `strings.ToLower(definition.Type)` / `strings.ToLower(step.Name)` 建已知表（修前 46、51 行）——viper 读出的配置键一律小写，只能这样对上。两个定义的类型只差大小写（`gift_item` / `Gift_Item`），或同一定义里两个步骤只差大小写时，后写入的条目覆盖先写入的，`saga.steps.gift_item.debit` 的覆盖落在后注册的那个上，另一个静默拿不到。

## 触发与差异

定义 `gift_item` 与 `Gift_Item`，配置 `saga.steps.gift_item.debit.max_attempts: 15`：预期报歧义错误；实际成功，覆盖落在 `Gift_Item`。

## 复现

`TestStepBudgetConfigRejectsNamesThatDifferOnlyInCase`（`kit/saga/step_budgets_test.go`）修前：

```
step_budgets_test.go:116: types: err=<nil> overrides=map[{Gift_Item debit}:{0s 15 0s 0s}], want an ambiguity error
```

## 修复

[修复记录](../bugfix/RR-20261006-06.md)：建表时遇到只差大小写的不同名字直接报错。
