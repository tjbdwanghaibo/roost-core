# RR-20260924-20：旧解锁回复清除新一代本地状态

日期：2026-09-24；基线 `967bc69` 加前轮优化工作树；等级 P2。已复现、修复、验证，未发布。[修复](../bugfix/RR-20260924-20.md)。

UnlockWithRetry 的 Redis 请求按 token 隔离，但成功与 NotOwned 回复均无条件设置本地 acquired=false，成功还覆盖 version。两个重叠解锁中，另一个操作结束并重新申请锁后，先前挂起的回复会破坏新代状态；预期只能更新本次 token 的本地状态。

TestDelayedUnlockCannotClearReacquiredGeneration 用屏障控制成功/拒绝旧回复。修前分别为 `held=false version=7 fence=2`、`held=false version=9 fence=2`，新代本应仍持锁。日志 `/tmp/roost-remote-generation-red.log`。

```sh
GOCACHE=/tmp/roost-nest-go-cache GOWORK=off go test ./remoteentity -run '^TestDelayedUnlockCannotClearReacquiredGeneration$' -count=1
```

根因位于 remoteentity/versioned_lock.go；已有 Touch/Refresh 的 token 防护没有覆盖 Unlock 的回包路径。
