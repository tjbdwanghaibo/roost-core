# RR-20260927-09：Remote 提交路径与 ValidateEntityRegistry 不拒绝“remote=managed + dbscope=sid”，手写实体可绕过 RR-45 的装配校验

日期：2026-09-27。基线：`d4234c9`（v1.17.1 之后的残留清单提交）。来源：[OPEN-ITEMS-2026-09-27](../review/OPEN-ITEMS-2026-09-27.md) A10 + C15
（[bf-45](../bugfix/RR-20260926-45.md) “未验证项”“决策·未采用”自报的后续加固点）。等级 P3（只有手写实体、注册的 DAO 工厂与实际 DAO 不一致时可达；
生成工程由生成期校验挡住）。状态：已复现，已修复（见下）。

codebase-memory 图谱停在 09-26，已过期；本记录全部以 `d4234c9` 源码与实跑为准。

## 现象与根因

RR-20260926-45 禁止托管实体使用 `dbscope=sid` 的 DAO，拒绝点只有两处：codegen 实体生成器，以及 `remoteentity.Assemble` / `Assembly.Start` 调用的
`validateRemoteManagedDaoScopes`（`remoteentity/assemble.go:260`），后者只实例化注册表里的 `DaoBuilders`。

- **提交路径**：mutation 的 `DatabaseScope` 来自实体实际持有的 DAO（生成模板 `codegen/internal/entity/gen.go:584/610`），
  `FinalizeLocked`（`remoteentity/batch.go:338`，校验在 `:390` 调 `RemoteCommit.Validate`）与 `RemoteCommit.Validate`（`entity/remote_protocol.go:267`）
  都不看 `DatabaseScope`；投影按它选库（`remoteentity/mongo_payload.go:36,39` → `MongoCommitter.dataDB` 的 sid 分支）。手写实体的 `DaoBuilders`
  漏报 sid DAO 时装配校验放行，提交写进提交方的 `db_<sid>`，另一进程按本服 sid 加载——回到 RR-45 的“提交与加载选库不一致”。
- **ValidateEntityRegistry**（`entity/category_order.go:197`）：生成 registry 聚合在全部注册之后调用的整表校验，不检查 DAO 作用域；
  不装 Remote 的进程（例如只跑 DataEngine）带着这个组合启动，要到装配 Remote 时才暴露。

## 修复约束（清单 §H 推荐，维护者 2026-09-27 决定按推荐执行）

提交路径与装配校验对 `remote=managed` + sid 作用域 DAO fail-fast；错误可 `errors.Is`；与 RR-45 / 60 / 71 的既有校验一致，不重复报错。

## 修复（2026-09-27）

状态：**已修复，未发布**（worktree 分支 `fix-r7-ent` 本地提交）。哨兵与校验规则移到 entity（`entity.ErrRemoteManagedServerScopedDAO`、
`entity.ValidateRemoteManagedDaoScopes`，`remoteentity.ErrRemoteManagedServerScopedDAO` 为同一个值）；`ValidateEntityRegistry` 按同一规则逐个违规 DAO 报一次；
`FinalizeLocked` 在 WAL 准入之前拒绝带 `dbscope=sid` 的 mutation / delete 并回滚已定稿条目。投影 / 重放路径不拒绝。详见[修复记录](../bugfix/RR-20260927-09.md)。
