# RR-20260926-40：demo scene 重连期间旧连接推送失败把已通过新连接重新 Join 的玩家移出场景

日期：2026-09-26。基线：v1.17.0（`8811c02`）。等级 P2（demo 模板 / 生成物）。状态：生成工程探针复现，未修复。
（最终状态见文末修复节：**已修复，随 v1.17.1 发布**，详见[修复记录](../bugfix/RR-20260926-40.md)。上面的“状态”是登记时的原值，保留不改。——2026-09-27 回写，OPEN-ITEMS A13②）

## 根因

`codegen/internal/roost/render_player_tcp.go:772-788` pushPlayer 向玩家所有会话推送、任一失败整体报错 → entitysync 关闭会话回调 `sessionLost` → `dropAsync` → `Leave`
（`demo/internal/service/game/scene.go.tmpl:431-447,322-341`），不看 ActiveSessions，移出兴趣集、注销 subject、关闭会话。同类 TOCTOU：`watchSessions`（`:143-155`）先查 ActiveSessions 再异步 Leave。

复现：[REPRO-2026-09-26-04](REPRO-2026-09-26-04.md) §7 `members=1 ActiveSessions(9702)=1`（新连接仍活，玩家已被移出）。

## 修复约束（维护者 2026-09-26 批准：Leave 带 Join 代际并复查）

Leave 携带 Join 代际 / 令牌，执行时复查“该代际仍是当前且确实没有活跃会话”，否则丢弃；旧会话推送失败而仍有活跃会话时不 Leave（必要时对仍活跃会话重同步）。watchSessions 同样按代际判定。

## 修复（2026-09-26）

已修复，按上方修复约束实现，见[修复记录](../bugfix/RR-20260926-40.md)。scene 每次 Join 分配代际，断线（`SessionLost` / 会话关闭事件）登记代际后
在 `transitions` 锁内复查“代际仍是当前且确实没有活跃连接”才 Leave，否则丢弃；旧连接推送失败而仍有活跃连接时重开复制会话并经新的
`policy.Interest.Resubscribe` 重同步。REPRO §7 探针改写为模板测试，修前红、修后 `-race -count=10` 绿，正常离线仍 Leave；已本地提交，未推送/发布。
