# NC-63：errcode 扫描静默跳过非字面量 / 别名导入的 Define，且不查重名

2026-10-05，基线 `50e9a4e853641f348c879b85c282af9c5813f656`。P2（导出的错误码表缺项、重复检查被绕过；生成门禁静默放行）。状态：已复现、已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-63.md) · [本轮](../review/REVIEW-2026-10-05-noncore-n07.md)。

## 触发与差异

`codegen/docs/CODEGEN_REFERENCE.zh-CN.md` §13：errcode 扫描“导出编号、名称和消息；重复 code/name 或非常量调用失败”。基线 `codegen/internal/errcode/main.go`：

- `:71` 预筛选只认文本 `errcode.Define`，`:95-97` 只认选择子左侧标识符恰为 `errcode`：`import ec ".../errcode"` 后的 `ec.Define(...)` 整个文件被跳过。
- `:99-110` 编号不是整数字面量、名字或消息不是字符串字面量时 `return true`，**静默跳过**，不是失败。`errcode.Define(CodeSoldOut, ...)` 不进 `docs/generated/errcode.csv`，也不参与重复检查。
- `:143-147` 只查重复 code，不查重复 name。

后果：客户端据以映射的导出表缺项；被跳过的定义与别处同号时不报冲突，运行时 `IntError.Is` 按 code 比较，两个不同含义的错误互相 `errors.Is` 成立。`roost id check` 用同样的字面量正则（`codegen/internal/roost/id.go:15`），同样看不见这些定义。

## 复现

新增 `TestExtractDefinitionsRefusesWhatItCannotRead` 修前 5 叶子全部被接受：

```
scan accepted it and exported 0 definitions        (常量编号 / 常量名字 / 别名导入+常量编号)
scan accepted it and exported 1 definitions: ... 500101 guild.b   (别名导入的 500101 与另一文件 500101 未报重复)
scan accepted it and exported 2 definitions: ... "shared" ...     (同名两码)
```

原文见[证据](../bugfix/evidence/noncore-bugfix-20261005-n07/README.md)。框架 kit/service 的定义用常量编号，但它们不在业务工程扫描根内，不受影响；生成的 game-demo 21 处定义全部是字面量。
