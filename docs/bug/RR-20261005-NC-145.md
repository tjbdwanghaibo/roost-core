# NC-145：OrderedIndex 默认排序对不同动态类型的接口键 panic

2026-10-05，基线 `23f82dbccfd5171373470ab942f33177ed4f4eed`。P3（仓内零调用方；K 为 `any` 等接口类型、同一值下有不同动态类型或 nil 键时触发，是否触发取决于 sort 的比较顺序）。状态：已复现，未修复。[本轮](../review/REVIEW-2026-10-05-n11.md)。

## 触发与差异

`index/index.go:153-166` `defaultLess` 只看左操作数的 Kind，就对右操作数调用 `Int()` / `Uint()` / `Float()`：右边是 string、uint、nil 时 reflect panic；左边是 string 时 `vb.String()` 不 panic，却把不同类型拿去比较格式化串，结果也不是全序。`Query`（遍历）因此在合法输入上 panic。

## 复现

`TestDefaultOrderHandlesKeysOfDifferentDynamicTypes`：

```
index_promises_test.go:50: rotation 0: Query panicked: reflect: call of reflect.Value.Uint on string Value
```

## 约束

同类型保持自然序（不回退已修的数值序）；类型不同先按类型确定性排序，nil 排最前。
