# RR-20260926-82：dataengine/engine 包测试不能重复运行（-count>1 时 TestEntityRepositoryRefusesEachUnloadableAggregate 失败）

日期：2026-09-27。基线：本地 main `9a473cd`（RR-73～80 合并后，未推送）。来源：RR-73～77 修复方范围外发现，主会话复现。等级 **P4**（测试卫生）。引入：RR-20260926-71 前后的 kind 注册夹具。状态：已复现，未修复。
（最终状态见文末修复节：**已修复，随 v1.17.1 发布**，详见[修复记录](../bugfix/RR-20260926-82.md)。上面的“状态”是登记时的原值，保留不改。——2026-09-27 回写，OPEN-ITEMS A13②）

`GOWORK=off go test -count=2 ./dataengine/engine`：

```text
--- FAIL: TestEntityRepositoryRefusesEachUnloadableAggregate (0.00s)
        entity_repository_load_promises_test.go:124: LoadEntity = dataengine repository: entity aggregate not found: entity=1333197; want <nil> containing "no builder for entity kind 243"
```

单跑该用例 `-count=2` 通过，整包第二轮失败：同包其他用例写入的全局注册状态（kind 243 的 builder / kind 定义）在第一轮之后残留，改变了第二轮的加载路径。
影响：门禁与审计无法对该包做 `-count>1` 的重复运行 / 抖动检测（RR-73～77 修复方因此只跑了 `-count=1`）。

修复约束：只改测试——用到全局注册表的用例各自使用互不冲突的 kind 或在 `t.Cleanup` 里撤销注册（若注册表无撤销入口，用测试专用的未导出入口，不新增导出 API）；
`GOWORK=off go test -race -count=3 ./dataengine/engine` 稳定通过；不改生产注册语义。

## 修复（2026-09-27）

状态：**已修复，未发布**（本地提交，未推送）。只改测试，生产注册语义与导出 API 不变。

机制：残留状态来自 kind 冲突——`fenced_step_resync_test.go` 的 `fencedResyncKind` 也是 243，与 `dataEngineNoBuilderKind` 相同；
它在第一轮给 243 注册了 builder，第二轮“kind 没有 builder”的前提就不成立。改为同包未用的 248。修掉它后整包重复运行又暴露
`TestSkippedFencedStepIsQueuedForEvictionOnce` 的时序假设（驱逐 worker 尚未取走第一项时队列长度为 1，被当成“多排了一次”），
改为第一轮后等 worker 取走那一项再断言。
