# NC-223：v1.20.2 起“对每个选中目标读它自己的属性”编译失败（B3 回归）——lowerSnapshots 用空作用域 lower 全部快照计划的实体

2026-10-06，基线 `57c0b3b6`。P2（合法定义启动期编译失败；game-demo 的 `CompileAll` 会因此启动失败）。**回归**：B3（`023eb276`，随 v1.20.2 发布）。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-223.md)。[本轮](../review/REVIEW-2026-10-06-n09-batch5.md)。

## 机制

`compile_snapshot.go` 为每个 `read_attribute` 建一个快照计划，`lower.go` 的 `lowerSnapshots` 把**全部**计划（不分采样点）lower 进 `Program.snapshots`，实体用 `c.lowerValue(plan.Entity, nil)`——空作用域。运行期只有 cast_start / phase_start / process_start 的计划会被采样（`captureSnapshots`），current / each_tick / on_hit / on_event 的计划只是随 Program 记录（进 gameplay digest）。

B3 之前，空作用域里查不到的 `$local.t` 退成同名 builtin（从未被求值），定义能编译、执行正确（读取处的 `attributeReadProgramValue` 用的是带作用域 lower 出的实体）。B3 让 `$local.` 引用查不到时报 `LOWER_UNRESOLVED`，于是 select / repeat / effect result 的局部变量作为 `read_attribute` 的实体时，任何采样点都编译失败。

## 触发与差异

select each 消费体里 `damage $local.t amount=read_attribute{entity:"$local.t", attribute:"ability_power", snapshot:"current"}`：

- v1.20.1（`023eb276^`）：编译通过，每个目标按自己的属性受伤（新回归在该提交上通过）。
- v1.20.2 / origin/main：`LOWER_UNRESOLVED at $: reference "$local.t" has no compiled slot or handle (an earlier compiler pass accepted a name it did not resolve)`。

N09 第四批的变异性质测试与 B3 的 lower 查找回归都没有以局部变量为实体的读取种子，所以没有发现。

## 复现

正式回归（修前）`TestReadsOfALocalEntityAtNonCachedPointsCompileAndRun` 四个子用例（current / each_tick / on_hit / on_event）全部 `unexpected diagnostic: … Code:"LOWER_UNRESOLVED", Path:"$" …`；同一文件在 `023eb276^` 的临时 worktree 上四个子用例全部通过。
