# NC-264：Prometheus 导出的标签值转义不符合 exposition 格式

2026-10-06，基线 `dc877c04`，分支 `revleft`（N11～N13 留项与小防护）。**P3**。来源：N12 观察 O4。状态：已复现，已修复（见文末）。[本轮](../review/REVIEW-2026-10-06-revleft.md) · [证据](../bugfix/evidence/noncore-bugfix-20261006-revleft/README.md)。

## 触发与差异

`metrics/prometheus.go` `prometheusLabels`（基线 :105）用 `strconv.Quote` 生成标签值：制表符写成 `\t`、不可打印字符写成 `\u....`、非法 UTF-8 写成 `\x..`。文本 exposition 格式的标签值只定义 `\\`、`\"`、`\n` 三种转义，其余字符原样写出。

- 预期：任何标签值都按格式转义，抓取器读回原值。
- 实际：抓取器遇到未定义的转义整页解析失败（`invalid escape sequence`），或把值读成另一个字符串。当前仓内标签多为代码常量与数字 ID，但 `msg`、`method`、`key` 等标签的值来自请求 / 业务 key，含控制字符时整个 `/metrics` 抓取失败。
