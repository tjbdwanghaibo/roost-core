# RR-20260926-32：Remote 事务持久提交后 Entity release hook panic，“是否已提交”靠错误类型推断，已提交事务被 Abort（RR-14 根因未修完）

日期：2026-09-26。基线：main `985d5ba`（aaada47 同样，既有缺陷）。等级 P2（远端内存回滚、事务标 Rejected、postRemoteCommit 跳过、Sync 冻结）。
状态：已复现（修前修后相同），未修复。

## 触发条件

strict 的 Remote 消息持久提交之后，业务注册的 Entity release hook panic：`nest/nest_dispatch.go:328-330` 的 `defer release()` →
`entity/entity_guard.go:300-304`（`ReleaseEntity` 无 recover）→ runNestLogic 把 panic 变成 dispatchErr（不是 `ErrAfterCommitFailed`）。

## 预期 vs 实际

预期：已持久提交的 Remote 批次走 Commit；hook panic 只作为错误报告。
实际：`nest/msg.go:84` 按 `dispatchErr` 的错误类型判断 → Abort → 远端内存回滚、Rejected、Sync 冻结（同 RR-13 症状）。

## 实施方向与验收

- 在 Msg 上记录“持久提交成功”的显式状态，finish 只看该状态决定 Commit / Abort，不再按错误分类推断。
- 回归：提交后 release hook panic → Commit 被调用、Abort 未调用、Sync 不冻结、回复带 hook 错误；未提交失败仍 Abort。
