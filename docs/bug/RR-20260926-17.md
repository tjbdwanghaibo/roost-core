# RR-20260926-17：Projector / Runtime（以及 nestwal Committer）停机不等待也不拒绝外部发起的 Flush / ReplayPass，旧回放在 WAL 交出后写 checkpoint，使新拥有者的 checkpoint 回退

日期：2026-09-26。基线：main `aaada47`。等级 P2（重启后已 ack 记录重放，单 mutation 快路可能被判冲突进入 fatal；需并发 + 重试停机触发）。
状态：已复现（探针，已删除；engine 10/10、nestwal 3/3），源码已核对，未修复。来源：上线前复审（DataEngine 生命周期）。

## 触发条件

调用方经公开入口发起投影（`kit/dataengine.Mod.Flush` → `Runtime.Flush` → `Projector.Flush`，或直接 `Projector.ReplayPass`），同时 Shutdown；
第一次 Shutdown 因截止时间未完成、按契约重试 Shutdown；之后 Assembly 重新 Start，或新进程使用同一 WAL 目录。

## 预期 vs 实际

预期：Shutdown 返回 nil 表示该 WAL 上已无投影 / ack 活动，WAL 唯一所有权已交出。`dataengine/engine/runtime.go:183-184` 的注释本身写着
“先等重放退出，避免 writer 关闭与重放仍在执行的 ack 交错”。

实际：
- `Projector.Close`（`dataengine/engine/projector.go:383-401`）只等后台 run 的 `done`，不获取 `flushGate` / `replayGate`，没有 closed 标志；
  `Flush` / `ReplayPass` 不检查关闭（`projector.go:285-313`、`projector_replay.go:16`）。
- `Runtime.stop` 在 `projectorClosed` 后即关闭 WAL（`runtime.go:185-190`）。
- `WAL.Replay` / `WAL.Ack` 不检查 closed（`nestwal/wal.go:472`、`:500`），关闭后仍能读段并写 `ack-N.chk`。
- 于是重试的 Shutdown 返回 nil、Assembly 丢弃 runtime，而外部回放仍在存储调用里；放行后它用已关闭的旧 WAL、旧 generation 写 checkpoint，覆盖新拥有者同槽位更靠后的 fence。
- 同根因：`nestwal/committer.go:308-328` 的 `Committer.Close` 只等 run，不等 `flushSem` / `replaySem` 中外部 `Flush` / `replayPass` 的持有者（`committer.go:244,390`）。

## 复现

审查 agent 探针（已删除，源码未保留）：真实临时 WAL，存储只对 Background ctx 阻塞；外部 `rt.Flush(Background)` 与 `Assembly.Shutdown(50ms)` 并发，
再 `Shutdown(Background)`；然后 `nestwal.Open` 同目录追加并 ack，放行旧回放，最后重开。

```text

second Shutdown: <nil> runtimeRetained=false

nestwal 版本（c.Flush(Background) 与 c.Shutdown(50ms) 并发，再 c.Close(Background)），3/3：
first Shutdown: nestwal: apply transaction ...01: context deadline exceeded
Close retry: <nil>
WAL reopened by a new owner while the old committer's flush is still applying
```

复审方已按源码核对 `projector.go:383-401`、`runtime.go:183-190`。

## 实施方向（约束）

- Close 后拒绝新的外部 Flush / ReplayPass，并等待已进入的调用退出后才报告已关闭、才关闭 WAL；等待须遵守调用方截止时间，超时保留 runtime 继续回收（RR-20260924-09/11 的既有语义）。
- 关闭后的 WAL 不再接受 Replay / Ack。

## 验收覆盖点

- 上述并发 + 重试停机场景：第二次 Shutdown 只有在外部回放退出后才返回 nil；新拥有者 checkpoint 不回退。
- nestwal Committer 同样场景。
