# RR-20260926-27：快池断言 panic 在 DataEngine 删除准入被当作“结果未知”，整个进程被 fence

日期：2026-09-26。基线：main `985d5ba`。等级 P2（一次误用即 fence 全进程；修复前同路径不 fence）。引入：RR-20260926-06 修复。
状态：已复现，未修复。

## 触发条件

默认 handler（无 RollbackTx，Memory）在快阶段用 `ManagerAccess.Destroy` 或生成 lifecycle `Destroy(deletePersisted=true)` 删除 AutoPersist 的 Remote 托管实体。

## 预期 vs 实际

预期：快池断言 panic 发生在任何副作用之前，应返回确定拒绝（`ErrBlockingInFastWorker`，`DeleteAdmissionImmediate`），实体保留在内存。
实际：`dataengine/engine/entity_delete.go:43-44` → `remoteentity/batch.go:43` 断言 panic → `entity_delete.go:26-31` recover 后标 `DeleteAdmissionIndeterminate`
并 `runtime.fail(err)` → kit `onFatal` 执行 `Nest.Fence` + RuntimeFailure（`kit/dataengine/mod.go:357-375`）；`entity/entity_manager.go:223-233` 摘除实体；
错误用 `%v` 格式化丢了 `errors.Is` 链。

## 复现

[REPRO-2026-09-26-03](REPRO-2026-09-26-03.md) §3：`GOWORK=off go test ./dataengine/engine -run TestProbeFastWorkerRemoteDelete -v`

```text
Destroy err=dataengine delete: admission panic: fctx: blocking operation in fast worker: remoteentity.PrepareRemoteWriteBatch (handler=default_handler)
fatal calls=1 ; entity still in memory=false; is ErrBlockingInFastWorker=false   FAIL
```

## 实施方向与验收

- 删除准入对“副作用前的快池断言”返回确定拒绝，不 fence、不摘除、保留 `errors.Is(ErrBlockingInFastWorker)`；真正的未知结果仍按不确定处理。
- 回归：上述场景 fatal=0、实体仍在内存、错误可判别；慢阶段删除行为不变。
