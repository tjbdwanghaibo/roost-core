# RR-20261004-01：`versionedLock.TryLock` 取锁没有拿到 Redis 明确答复时不记录 token，脚本若已执行，实体在本进程内不可写直到 LockTTL

日期：2026-10-04。基线：main `17ae93be`。来源：[W-2026-10-04-01](WANTED.md)（harness 区间核验负对照 `ROOST_REMOTE_REQUEST_TIMEOUT=15ms` 一次运行的 reject 校验失败于 `remote_entity: shared lock …: versioned lock not acquired`，复跑未复现）。
等级 **P2**：单个 Remote 实体在本进程内最长 `LockTTL`（压测与正式缺省 24h，`remoteentity/config.go:80`）不可写，与 [RR-20260930-21](RR-20260930-21.md) 同级。状态：**已确认（包内替身与真实 Redis 均红），已修复**，见下。

## 触发条件、预期与实际

- 触发：`beginWrite` → `rMu.Lock` → `TryLock` 的取锁脚本 `versionedTryLockLua` 已在 Redis 执行（owner 已是本次 token、fence 计数器已递增），但客户端没拿到回复：ctx 截止（`remote_entity.request_timeout` 很短或 Redis 慢）、连接断开、或脚本还在路上、稍后才落地。
- 预期：下一次 `TryLock` 以 Redis 为准——owner 是本锁对象自己没拿到回复的那一代，就重新取得（新 token、新 fence、新代际）；被别人持有走 NotAcquired；空闲正常取得。
- 实际：`TryLock` 用一枚新 token 争锁，Lua 只认 `owner == false` 或 RR-21 的 `releaseUnknownToken`，于是 `{0,0,0}` → `ErrVersionedLockNotAcquired`；`Lock` 的重试预算（默认 5 次退避）远等不到 TTL，这个实体的每次写都回 `remote_entity: shared lock <id>: versioned lock not acquired`，直到 LockTTL 过期。

三条 PASS 是守护：别人持有时不挤掉对方；释放未知之后又有取锁没发出去时仍能取回释放未知的那一代；迟到的旧代脚本挤不掉已取得的新代际。

## 根因（基线 `17ae93be` 行号）

- `remoteentity/versioned_lock.go:120-125` `TryLock`：`token := generateToken()` → `Eval(versionedTryLockLua, …, token, ttlMs, l.releaseUnknownToken)`，`err != nil` 直接 `return`；这次 token 不留在任何地方，脚本是否已执行无从核对。
- `:45` / `:302-310`：唯一能让 Lua 认出"自己的旧代"的 `releaseUnknownToken` 只由 `releaseOutcomeUnknown`（释放无答复，RR-20260930-21）写入；取锁无答复没有对应路径。
- `remoteentity/versioned_lock_lua.go:11`：取得条件只有 `owner == false or (ARGV[3] ~= "" and owner == ARGV[3])`，单个精确 token。
- 后果链：`remoteentity/batch.go:165-167` `beginWrite` 的 `rMu.Lock` 失败即拒绝这次写；`Lock`（`versioned_lock.go:171-210`）对 NotAcquired 按"别人持有"退避重试，预算用完返回；锁对象随 wrapper 常驻，LockTTL（缺省 24h）内无人续期也无人释放这枚租约。

## 修复约束

- 不伪造持有：没拿到答复的那一代不能当成本地已持有（不登记续期、不发许可）；只能让下一次 `TryLock` 交 Lua 由 Redis 判定。
- 不放宽 fence / 版本：重新取得是新一代，新 token、新 fence（authority 模式下仍由 `GrantWrite` 发 Mongo 许可），版本缓存不补写。
- 续期代际按 [RR-20260926-43](../bugfix/RR-20260926-43.md)；旧代迟到回复（含迟到落地的取锁脚本）不得破坏新代状态（[RR-20260924-20](RR-20260924-20.md)）。
- 与 RR-20260930-21 共用同一条"以 Redis 为准"的 Lua 判定，不另起机制；释放未知之后再有取锁未知时，两者都要能取回。
