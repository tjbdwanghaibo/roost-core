# RR-20260925-10：同 ID 重开会话可能继承旧订阅

日期：2026-09-25；基线：09-25 快慢双池收尾后的未提交工作树，Sync 反向索引实施过程中发现。等级 P1，影响 Sync 会话隔离。状态：已复现并修复，未发布；见[修复记录](../bugfix/RR-20260925-10.md)。

触发：CloseSession 从 sessions 移除旧会话后，在外部 SessionClosed 回调中暂停；新连接以相同 SessionID OpenSession；旧 subject 订阅尚待关闭流程清理，此时执行 Flush。

预期：新会话在业务重新授权 Subscribe 前不收到旧订阅。实际：Flush 只检查 SessionID 是否存在，未比对 subscription.lifetime，把旧订阅的数据编码给新会话。

确定性复现 `TestFlushDoesNotSendOldSubscriptionToReopenedSession`：通过 channel 控制关闭回调，重开但不 Subscribe。修前失败 `reopened session received 1 frames without subscribing`。命令：

```
GOCACHE=/tmp/roost-nest-go-cache GOWORK=off go test ./sync/entitysync -run '^TestFlushDoesNotSendOldSubscriptionToReopenedSession$' -count=1
```

原始失败日志归档于 `artifacts/perf/sync/session-recovery-20260925/stale-subscription-before.log`。根因位于 `sync/entitysync/flush.go` 的关闭订阅清理分支；不是协议解码或 AOI 计算错误。
