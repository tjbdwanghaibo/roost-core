# RR-20260926-25：生成的 Nest sender 与 demo 模板从不走 Slow，快阶段禁冷加载后，冷实体上的正式业务（saga 扣减/补偿、GM 发放）固定失败

日期：2026-09-26。基线：main `985d5ba`（本地提交）。等级 **P1**（离线玩家的补偿失败进入 ManualRequired——道具退不回；GM 发放失败）。
来源：985d5ba 上线前复审（业务链路）。引入：RR-20260926-02（a22c5a5）快阶段禁冷加载 + RR-06（985d5ba）覆盖全部实体访问入口，codegen 与模板未跟上。
状态：已复现，未修复。

## 触发条件

业务向“已持久化但不在内存”的实体发普通 Nest 请求。demo 中常态：进程重启后所有玩家为冷；`handBackIdle` 驱逐闲置 20 秒无连接玩家
（`demo/internal/service/game/playerowner.go.tmpl:479-514`）；`Owns` 为离线玩家就地拿租约（`:763-789`）。

## 预期 vs 实际

预期：离线玩家的 saga 补偿、GM 发放正常执行（冷目标由慢阶段预加载）。
实际：返回 `ErrColdLoadInLogic`（985d5ba 起为 panic，见 RR-26）；gift saga 重投到截止后 ManualRequired，GM 直接报错。

受影响：`gift_saga.go.tmpl:445`（`Sync_GiftDebit`）、`:464`（`Sync_GiftRefund`）、交接 `:323-325`；`gm.go.tmpl:186`、`:205`。

## 根因

- 快阶段只读已加载实体：`nest/nest_dispatch.go`（`loadedGetter`）+ `entity/manager_access.go:99-104`。
- 进入慢池只有显式 `SendOptionSlow()` 或 Remote（`nest/dispatcher.go:253`、`nest/remote_dispatch.go:24-34`），不按“目标是否已加载”分流。
- 生成的 sender 不暴露 `SendOpt`，唯一入口是 handler 名加 `_cost` 后缀（`codegen/internal/nest/parse.go:562-566`）；demo 无一 handler 如此，
  全仓非测试代码没有一处调用 `SendOptionSlow`（`git grep SendOptionSlow` 只有定义）。九项文档写了“显式收紧须提供迁移说明”，codegen / 模板未跟上。

## 复现

探针见 [REPRO-2026-09-26-03](REPRO-2026-09-26-03.md) §1：`GOWORK=off go test -race -run TestZZProbeDefaultSenderToColdEntity -v ./nest`

```text
985d5ba: default (no Slow) ... err=entity: cold load forbidden in logic ... loads=0 ； with Slow: ret=ok loads=1
8ce21a5: default (no Slow) ... ret=ok err=<nil> loads=1
```

## 实施方向（约束）

- 正式链路上冷目标必须走慢阶段预加载：由 dispatch 在准入时按声明目标是否已加载自动分流到慢准备，或由生成 sender 正式暴露 Slow。
  不能恢复“快 worker 上冷加载”（违反快池不阻塞）。
- 自动分流时声明目标仍按统一准入建立同 ID 顺序；未声明的动态目标保持 RR-02 语义。

## 验收覆盖点

- 生成 sender 对冷目标（未在内存、已持久化）发请求：成功、loader 在慢 worker 执行、快池无 I/O。
- demo：重启后 gift 补偿、GM AddItem 对离线玩家成功。

## 修复（2026-09-26）

状态：**已修复，未发布**（本地提交，未推送）。按维护者选定方向实现：Nest 在统一准入时对 Single/Multi/MultiGroup 的声明目标做只读内存判定
（Getter 的 LoadedEntitiesOnly 契约），有未加载且可由 loader 加载的目标就走慢阶段预加载，业务代码与生成 sender 不变，同 ID 顺序仍在准入处建立。
准入之后、handler 取 Guard 之前被驱逐（读取 / 引用 / 取锁三个窗口）时，同一条已准入作业原位转到慢池准备，保留同 ID 顺序位置，不重新准入、
不在快 worker 上冷加载。未声明的动态目标保持 RR-02 语义；Broadcast 不变；`SendOptionSlow` 保留。
回归 `TestDefaultSenderPreparesColdDeclaredTargetsOnSlowWorker`、`TestDeclaredTargetEvictedAfterAdmissionMovesToSlowKeepingOrder`（nest）；
另用正式生成 DAO/Entity + 本地集成 Mongo 的临时测试验证冷目标 → 慢池加载 → 等待投影 → 快池执行。demo 进程级重启场景未端到端运行。
详见[修复记录](../bugfix/RR-20260926-25.md)。
