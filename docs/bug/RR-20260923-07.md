# RR-20260923-07：不同政策相互撤销订阅，Group 关闭误退役共享实体

- 日期：2026-09-23；等级：P2；模块：Sync。
- 基线：`967bc69` + 前一轮 R1～R3 与 RR-01～03 工作树。
- 状态：已复现、修复并通过定向回归与模块 race 验证，未发布。[修复记录](../bugfix/RR-20260923-07.md)。

## 触发、预期与实际

Group、Interest 或多个 Direct 同时要求同一 (session, subject)，其中一个来源离开或关闭。预期只释放该来源的订阅，其他来源需要的内容继续同步，共享实体保持注册。

Manager 只保存一个 profile，政策都调用同一个 Unsubscribe；Group.RemoveSubject/Close 还直接 Unregister 整个实体。一个来源能撤掉其他来源需要的内容。

## 证据

`go test ./sync/entitysync/policy -run 'TestPoliciesReleaseOnlyTheirOwnSubscriptions' -count=1`。修前 leave/remove/close/direct 四个子场景全部失败。测试位于 `sync/entitysync/policy/group_ownership_promises_test.go`，按明确的成员添加、失败重试或来源释放顺序验证状态。

相关实现：`sync/entitysync/` 下的 subscriptions.go、subject.go、policy/direct.go、policy/group.go、policy/interest.go。影响边界及行为迁移见修复记录。
