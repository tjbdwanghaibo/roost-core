# RR-20261005-NC-38：Saga Resume 代际未持久化

2026-10-05，P2；发现基线 `af2f67fbb75e34110f59e4603e0046eedf7e358d`。

## 承诺与根因

[Record.Incarnation / commandID](../../saga/record.go) 与 [Resume](../../saga/engine.go) 承诺恢复后的派发 ID 与旧生命周期分离。原生记录已有 Incarnation，Resume 会递增，但 [Mongo recordDoc 及双向转换](../../saga/mongo_store.go) 没有此字段。

Resume 返回 incarnation1，重新读取权威记录却是0；下一次派发复用旧 CommandID。原失败回执内容相同时 ApplyDuplicate 返回旧等待记录，业务再次卡住；内容不同则可能 identity conflict。不能以新的返回对象证明已经持久化。

## 原始反例

正式 Engine→MongoStore→BSON→新 Store/Engine→processClaimed→outbox→Complete，后端 mongotest；正向 failed 与补偿 manual_required 两条均失败：`persisted generation=0, want 1`、`redispatch reused old command ID "resume:1:0:1" at generation 1`（补偿为 `resume:2:0:1`）。第二次同内容失败回执返回 waiting，未再次进入修复状态。[原始输出](../bugfix/evidence/noncore-bugfix-20261005-15/resume-red.txt)。无循环和任意 sleep，显式调用既有状态处理入口控制顺序。

既有 TestResumeMintsCommandIDsDisjointFromPreviousLife 只用内存 Store，不经过正式持久字段映射，因而没暴露这个缺口。不是新增 Resume 协议或改变幂等身份定义。
