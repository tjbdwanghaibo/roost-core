## 机制

1. 生成器接受 `//roost:nest rollback=state|undo durability=memory`，产出 `nest.HandlerMeta{Rollback: RollbackState|RollbackUndo, Durability: DurabilityMemory}`
   （`codegen/internal/nest/gen.go:202-226`）；手写 `RegisterHandlerWithMeta` 同样可以。注册校验只拒绝“非 memory 却不回滚”（`nest/handler.go:45`）。
2. 这种 handler 走事务路径（`nest/execution.go` 的 `invokeHandlerTransaction`，只有 `RollbackNone + DurabilityMemory` 且无 Remote 批次才走 memory 快路径），
   有 `RollbackTx`，生成 DAO 的持久 setter 调 `nest.MarkPersist` 成功，改动登记进事务本地的 `PersistChange`（`nest/persist_change.go` 的 `persistChange`）。
3. 提交点 `durableCommit` 对“memory 且没有 effect”直接返回 nil（基线 `nest/rollback.go:586-601`），不调 `prepareCommitRecord`：`PrepareMutation` 不调用、
   committer 不调用，`PersistChange` 随 `commit()` 清空。旁边的注释“Memory-only handlers persist through entity release hooks”（`:587`）早已不成立：
   仓内 `RegisterOnEntityRelease` 没有生产调用方，release 也不编码 BSON（F02-6 / F03-1 注释项）。
4. 结果：内存是新值、DAO 的持久版本不前进、库里是旧值；此后别的事务只改其他字段时 Patch 不带这些字段，实体重新加载后回到旧值。
   带 Remote 批次的 memory handler（`rollback=none` 也有 `RollbackTx`）改了**本地**实体的持久字段同样如此：Remote 批次认领的只有 Remote 实体的 DAO，
   本地 DAO 的改动无处可去，批次照常 Commit。`AddMutation` 加的本地 mutation、`AddReceipt` 绑定的 receipt 在同一分支同样被丢弃。

文档写的是“`durability=memory` 的 handler 不能修改 persistent 字段”（`codegen/docs/NEST_RUNTIME.zh-CN.md:80`、`codegen/docs/CODEGEN_REFERENCE.zh-CN.md:234`、
`NEST_TRANSACTION_WAL.md` §3），源码只在 `rollback=none`（快路径没有事务，setter 以 `ErrTransactionClosed` panic）时强制。

## 触发 / 预期 / 实际

- 触发：`HandlerMeta{Rollback: RollbackState 或 RollbackUndo, Durability: DurabilityMemory}` 的 handler 调持久 setter（`MarkPersist`），handler 返回 nil。
- 预期：契约“memory handler 不能改持久字段”成立——要么拒绝，要么持久化；不能回复成功却丢掉改动。
- 实际（`nest/memory_persistent_write_promises_test.go`，基线代码，`GOWORK=off go test ./nest -run TestMemoryTransactionPersistentWrite -count=1 -v`）：


handler 内新建实体并改其持久字段、带 Remote 批次的 memory handler 改本地持久字段，修前同样回复成功（新建的实体仍发布；Remote 批次 Commit 1 次），原文见修复记录。

## 根因与方向

memory 分支是“没有要持久的东西”的快捷返回，但没有核对事务里是否真的没有要持久的东西。方向（维护者选 A）：在这个提交点按事务本地的持久登记检查，
有就整笔拒绝、点名实体与字段，按回滚策略撤销内存修改。
