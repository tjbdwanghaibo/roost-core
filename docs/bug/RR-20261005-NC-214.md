# NC-214：status / attribute / resource 名字在 effect、filter、cost 里不查 catalog，lower 兜底成 handle 0——add_status / resource / cost 每次施法失败，remove_status / has_status / attribute_modifier / attribute_compare 静默作用在 handle 0 上

2026-10-05，基线 `c10cc9ac`。P2（编译通过的定义要么每次施法失败，要么静默做错事）。状态：已复现；已修复、声明场景验证，未发版。[修复](../bugfix/RR-20261005-NC-214.md)。[本轮](../review/REVIEW-2026-10-05-n09-batch4.md)。

## 触发与差异

lower 用三个 map 查找把名字换成 handle，找不到时返回零值（`lower.go:924-934`）：

```go
func lookupStatusHandle(artifacts *compileArtifacts, key string) StatusHandle {
	return artifacts.authority.statuses[key]
}
```

调用点：costs / sustain costs（`lower.go:228, 231`）、has_status / missing_status 与 attribute_compare filter（`:459, :461`）、add_status / remove_status（`:580, :582`）、attribute_modifier（`:593`）、resource effect（`:595`）。这些名字在编译期没有任何检查（`rg 'authority\.(statuses|attributes|resources)\[' compile*.go` 只命中 status_instance select 的 `status_id`、spawn 的属性覆盖与 snapshot 的 read_attribute）。同类名字里 damage_type、element、gameplay tag、collision、unit template 都在编译期以 `CAPABILITY_UNKNOWN` 拒绝。attribute_modifier 找不到属性时类型检查也跳过 value（`compile_typecheck.go:414-417`）。

## 复现（基线代码，MemoryHost，名字写成 `missing`）

| 位置 | 编译 | 施法 |
| --- | --- | --- |
| add_status `status` | 通过 | `skill: unknown status handle 0`，cast failed |
| resource `resource` | 通过 | `skill: combat handle is not authorized`，cast failed |
| costs / sustain_costs `resource` | 通过 | `combat handle is not authorized` |
| remove_status `status` | 通过 | 成功，什么也没移除 |
| has_status filter `status` | 通过 | 成功，按 handle 0 过滤 |
| attribute_modifier `attribute` | 通过 | 成功，修饰加在属性 handle 0 上 |
| attribute_compare filter `attribute` | 通过 | 成功，比较属性 handle 0 |

fixture 变异属性测试（宽口径：记录 ErrProgramInvariant 之外的非输入类错误）里 `ammo_on_kill` / `cast_window_interrupt` / `status_*` 删除或改写这些名字都落在这一类。正式回归（修前）`TestCompileRejectsUnknownCatalogNames` 八个子用例全部 `compiled; diagnostics=[]`。

## 影响

名字拼错或 catalog 改名后，技能通过 game-demo 启动期的 CompileAll，运行时每次施法失败，或者更糟——静默对错误的 handle 生效（属性修饰、状态检查都不报错）。

## 验收覆盖点

上表每个位置的未知名字在编译期以 `CAPABILITY_UNKNOWN` 定位到对应字段；catalog 里存在的名字照常编译并在 MemoryHost 上施法成功（控制）。
