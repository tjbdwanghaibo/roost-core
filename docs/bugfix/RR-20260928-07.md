# RR-20260928-07：k8s Secret 示例与生产示例同源，事后追加的 `saga` / `player_access` 等段也进 Secret

问题：[RR-20260928-07](../bug/RR-20260928-07.md)（批次 16 演练时发现，见 [RR-20260928-06 修复记录](RR-20260928-06.md)“另外发现”）。日期 2026-09-28。基线 `611dab1`，分支 `fix-r9-b17`。
状态：**已修复**（本地提交，未推送 / 发布）。codebase-memory 图谱过期（09-26），本轮以当前源码、`rg` 与生成物实测为准。

## 根因（基线行号）

- `codegen/internal/roost/render_deploy.go:714` `renderKubernetesSecretExample`：Secret 示例在建工程时按 Mod 目录 `renderServiceConfig(m, service, true)` 渲染一次、缩进四格嵌进 `stringData.config.yaml`，之后它是脚手架（`render.go:63` 非受控，sync 不重写）。
- 建工程之后改生产示例的入口只写开发配置与生产示例两份：
  - `codegen/internal/roost/render.go:584-638` `appendModConfigSections`（`add mod`，`add saga` 经 `add.go:70`、`:218` 调用），目标只有 `:601-602` 两项；
  - `codegen/internal/roost/add.go:131-152` `add transport tcp`：`ensurePlayerTCPConfig` 只对开发配置与生产示例各调一次。
- game-demo 的脚手架步骤里正好有 `add saga`（GiftItem）与 `add transport tcp`，所以它的 game 生产示例有 `saga:` / `player_access:`，Secret 没有；普通工程 `add mod redis` 之后的 `redis:` 段、`add saga` 带进来的 `mongo` / `nats` / `nest` / `dataengine` / `persistence` 段同样不进 Secret。
- 同类的另外两处入口原本就写 Secret：`shutdown_budget.go` 的 `shutdownConfigTargets`（停机块刷新，sync 时执行）和 RR-20260928-06 的 `appendDemoGameConfig`。

## 决策

按修复约束，Secret 示例嵌入的 config 与生产示例由同一份文本驱动：每个事后改生产示例的入口，把**同一个编辑**也施加到 Secret 内嵌的 `config.yaml` 上。

- 新 `editKubernetesSecretExampleConfig(root, service, edit)`（`render_deploy.go`）：取出 `  config.yaml: |` 之后缩进四格的块（到第一行缩进不足四格的非空行为止，其后原样保留），去缩进交给 `edit`，结果重新缩进写回；内容不变不写。Secret 不存在（没有 k8s 目标）或找不到恰好一个该块（被手工改写结构）时跳过，与停机块刷新“认不出就不动”的做法一致。
- `appendModConfigSections`：追加逻辑抽成 `appendMissingConfigBlocks(body, sections, production)`，生产示例与 Secret 用同一函数、同一份 `productionizeConfig` 后的文本；顶层键已存在就不追加（手改保留、重复执行无操作）；改到的 Secret 路径进返回列表。
- `add transport tcp`：`ensurePlayerTCPConfig` 的 YAML 合并部分抽成 `mergePlayerTCPConfig(text, name, enabled)`（文件包装负责 CRLF、写盘与路径，错误文本不变），对 Secret 内嵌 config 施加同样的 `enabled: false` 合并；Secret 纳入该命令的备份 / 回滚集合，改到时进返回列表（返回路径数 14 → 15，`TestAddPlayerTCPTransportIsExplicitAndProductionGuarded` 随之更新并核对 Secret 的内容）。
- 没有采用“每次都用生产示例整体覆盖 Secret”：Secret 示例是脚手架，整体覆盖会吞掉对它的手改；逐段同编辑只补缺的键。
- `config enable|disable player-tcp` 不动：它按 `--file`（默认开发配置）只翻一个标量，生产示例与 Secret 都保持 `enabled: false`。
- Secret 独有的敏感值占位目前没有；回归里用显式的 `secretOnlyConfigKeys`（空）表示允许项。

修后新生成 game-demo 的 `secret.game.example.yaml` 内嵌 config 与 `config.game.prod.example.yaml` **逐字节相同**（去四格缩进后比较）；其余 9 个服务原本就相同。
