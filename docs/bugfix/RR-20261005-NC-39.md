# NC-39 修复：原始启动摘要与运行状态分离

[问题](../bug/RR-20261005-NC-39.md) · [本轮](../review/REVIEW-2026-10-05-noncore-26.md) · [复跑/红绿](evidence/noncore-bugfix-20261005-16/README.md)。已修复、声明场景验证，未发版。

## 实现与取舍

`saga/engine.go` 的 StartSaga 先规范化 ID、业务键、UTC 毫秒 deadline，然后用固定 JSON 字段顺序（type/business_key/definition_version/data/deadline_at）算完整 SHA-256 十六进制摘要。ID 是“未指定或与现有 ID 一致”的独立条件；Now 只是调度钩子，不参与原始身份。nil/空 Data 沿用原先相等语义。

`saga/record.go` 增加字符串 `StartDigest`；Clone 按值保存。`saga/mongo_store.go` 增加 optional BSON 字段并在两方向映射，Create/Get/GetByBusinessKey/List/ClaimDue/Apply 全记录链保留。成功步骤更新 Data、失败/补偿、Resume 改 deadline 都从原记录 Clone，不改摘要。Store 接口补中文保存契约；无新接口、缓存、网络调用、自动重试或业务状态转换。

不只比较业务键：那会隐蔽不同原始意图；不把初始 Data 再存一份：摘要固定大小且不复制持久 payload；不在重投时重算旧运行数据作为原始值：来源无法证明。稳定摘要结构独立于未来 StartRequest 新选项，变更其身份格式必须另作兼容方案。

## 兼容与恢复

- 新记录从首次 Create 保存摘要；自定义 Store 必须原样保存该新增字段，旧 writer 完整 Replace 会丢失它，协调 writer 需统一升级。
- 旧 BSON 缺字段默认为空，既有调度/完成/Resume 仍可使用。只有 version=1、pending/forward、第0步、completed/attempt/incarnation=0 的旧初始记录，并且数据与期限相同，才接受重复。
- 已推进的旧记录没有可信原始意图，重复启动收紧为 `ErrIdentityConflict`，即使传入值刚好等于当前状态也拒绝。该错误不代表 Saga 执行被撤销；先用 Get/List 查看当前进度，不盲目改业务键重新执行。补摘要须核对可信原始 WAL/请求并另审具名 CAS 迁移，不自动回填。
- 新增公开 Record 字段会影响手写全字段序列化/严格消费方；不是 command/completion wire 改版，不需要重生成 DAO/Entity。只升级 runtime 不能修正自定义 Store 丢字段。

## 验证与漏检改进

原8叶子全红→绿：两后端×推进/完成/Resume换期限/清期限；重投不改版本、状态、当前数据、当前截止时间。另8兼容控制覆盖 nil/空、UTC毫秒、ID/业务键规范化、自动 ID 后显式指定、不同 data/deadline/version/id、缺字段旧初始/已推进记录。BSON实际存在摘要、List返回保存身份。

取消/回调重跑组合额外检查摘要保存、状态/receipt/outbox原子性与新 ctx 重试，见本轮机制文档与矩阵。先前回归只验证启动附近，未跨过会修改被比较字段的生命周期；后续幂等审查必须列“原始身份、当前状态、持久表示”，覆盖进度变化后同/异意图。

真实 Mongo 网络/未知提交、旧版本混跑、历史迁移与长期容量未验证；没有性能基准。新增 JSON/hash 只在启动/重投计算，不能由此宣称吞吐无变化。
