# RR-20260926-50 修复：被跳过的原生步骤按事务身份只登记一次驱逐；WAL terminal 唤醒全部投影等待方

问题：[RR-20260926-50](../bug/RR-20260926-50.md)。日期 2026-09-26。实施基线：本地 main `3e26f91`（RR-48～63 登记后）。
状态：已修复，本地验证通过，已本地提交，未推送/发布。与 [RR-20260926-59](RR-20260926-59.md) 同一组（驱逐 / 卸载 / 重载路径），各自一笔提交。

## 根因（基线行号）

1. **驱逐不判重**：投影器按退避重试 `ReplayPass`，每轮从 checkpoint 重投。被跳过的原生步骤在 ack 失败后每轮都会再读到（`MongoStore.ProjectFenced`
   读持久 skipped 标记，返回 `skipped=true`），`projector_replay.go:164` 每条都调 `startStaleEviction`；`fenced_step.go:90-117` 只看
   `pendingTransactions[id].fenced`，不判断这笔记录是否已交给驱逐 worker，于是每轮 append 一项、`dataengine.fence.evictions.started.total` 每轮 +1。
   驱逐成功后 `completeProjection` 撤掉待投影项，但队列里的多余项仍各自执行一次 `evictEntities`：生产装配下 `evictStaleEntities` 按 ID 取当前常驻
   对象卸载——那已经是刚从 Mongo 重载的新对象（多一次卸载、重载与 Sync 全量），`StaleEvictions` 也被重复计数。
2. **WAL terminal 不唤醒等待方**：`WaitEntityProjection`（`entity_projection.go:96-107`）只在等待前后调 `projectionUsable()`；等待中只听 `item.done`、
   调用方 ctx 与 Projector 关闭。RR-10 复核补修让投影 fatal 经 `completeAllTickets` 唤醒全部等待方，但 WAL terminal 没有同等信号：terminal 之后
   `Ack` 恒失败、准入恒失败，本进程不会再推进任何记录，而驱逐若也在重试（Nest 已 fence，`RunLocal` 恒失败），在 terminal 之前已进入等待的冷加载
   只能等到自己的截止时间或 Close。

## 修复（按维护者约束）

约束：驱逐按事务身份去重（同一被跳过记录只登记一次）；WAL terminal / fatal 时唤醒全部等待方并返回可判别错误（与 RR-10 复核补修一致）。

1. **去重**（`dataengine/engine/fenced_step.go`、`entity_projection.go`）：`entityProjection` 新增 `evicting`（`heldMu` 保护）。`startStaleEviction`
   在 `heldMu` 写锁下检查并置位：已登记的直接返回 true（屏障与冷加载等待照旧由那一次驱逐解除），不入队、不计数；实体 ID 列表 `slices.Clone`
   后交给 worker。驱逐完成后记录已不在待投影表里，之后的重投走原有 `!fenced` 分支（按普通投影完成处理，不再驱逐）。
2. **WAL terminal 信号**（`nestwal/wal.go`）：`WAL.Terminated() <-chan struct{}`，在首个 terminal 错误写入（`setTerminal` 的 CAS 胜者）后、与
   `failPendingTickets` 同一处关闭；正常 Close 不关闭它。
3. **Projector 唤醒**（`dataengine/engine/projector.go`、`projector_replay.go`、`entity_projection.go`）：
   - `NewProjector` 起一个 `watchWALTerminal`（`ManualReplay` 也起，Projector 关闭即退出）：`Terminated()` 关闭时以 `wal.Healthy()`（即 terminal 错误）
     调 `walTerminated`。
   - checkpoint 的 `ack` 失败若 `errors.Is(corenest.ErrCommitIndeterminate)`（nestwal.Ack 只在 WAL 已 terminal 或本次 fsync 失败、随即粘滞为 terminal 时
     返回它）同样调 `walTerminated`，覆盖替换过 ack 钩子的装配。
   - `walTerminated` 与 fatal 同一不变量：`walTerminalOnce` 内先写 `walTerminalErr`（`errMu`），再 `completeAllTickets(err)` 唤醒全部待投影实体等待方与
     `CommitSystem` 票据（屏障随 `finishEntitiesLocked` 一并解除）；`reserve` 在 `heldMu` 下复查 `walTerminal()`，唤醒扫描之后不会再登记新的等待项；
     `projectionUsable()` 与 `Healthy()` 也返回它。
   - 错误为 `dataengine projector: WAL is terminal, this process will not confirm pending projections: <terminal>`，保留
     `errors.Is(err, corenest.ErrCommitIndeterminate)`：已准入记录的投影结果对本进程未知（可能已落库、ack 丢失），不是明确失败。
   - 驱逐 worker 在 terminal 后照旧重试到成功或关闭（成功时 `completeProjection` 对已撤掉的待投影项是空操作）；没有为 terminal 另加停止分支。

未采用：给 `WaitEntityProjection` 再加 terminal channel 的 select 分支（有“先写错误、再扫描唤醒、reserve 同锁复查”的不变量，全部等待项都会被关闭，
多一个分支只是重复，与 RR-10 取舍一致）；轮询 `Healthy()`（最长 IdlePoll 才发现，且 Healthy 还包含可恢复的磁盘 / 积压告警）；把 terminal 当作
cancel `projector.ctx`（会与 Close 混为 `ErrRuntimeStopped`，不可判别）。

## 兼容性

- 行为：WAL terminal 后 `WaitEntityProjection` / `CommitSystem` 票据立即以上述错误结束（原先等到截止时间或 Close）；terminal 之后的准入在 `reserve`
  以同一错误拒绝（原先由 `wal.Append` 返回 terminal，错误身份相同）。被跳过的原生步骤在 ack 失败重投期间 `dataengine.fence.evictions.started.total` 与
  `StaleEvictions` 每笔只计一次。
- 新增导出 API：`nestwal.(*WAL).Terminated()`。无配置、持久格式变化。

## 对抗性自查

- **去重与屏障解除时机**：`evicting` 与 `fenced` 在同一个 `entityProjection` 上、同一把 `heldMu` 下读写；屏障与等待仍只由那一次驱逐的
  `completeProjection`（或 discard / fatal / terminal / 关闭的统一扫描）解除，去重不引入新的释放路径。驱逐完成后的重投看不到待投影项，不会再驱逐
  新对象。
- **terminal 与驱逐并发**：terminal 扫描撤掉待投影项后，仍在重试的驱逐成功时 `completeProjection` 是空操作；扫描之后的准入被 `reserve` 同锁拒绝，
  不会登记无人唤醒的等待项。
- **快慢池**：改动都在 Projector 后台 goroutine / 慢阶段等待方一侧；`watchWALTerminal` 不取实体锁、不投递快池。
- **误判 terminal**：只认 `ErrCommitIndeterminate`（nestwal 的 terminal 错误身份，RR-33 起 Ack / ticker / 写线程一致）；checkpoint 文件写失败
  （`nestwal: store acknowledgement`）不带它，仍按可恢复失败重试。
