# RR-20260929-19：建角未知结果恢复

状态：已实施，Memory/真实 Redis 原触发及正式回归通过；未发版。基线 `23f92d735b9a9023a0330fb2b8bc0514c4cff29f`。[原问题](../bug/REVIEW-2026-09-29-services-03.md#rr-20260929-19) · [本批验证与升级](SERVICE-BUGFIX-2026-09-29-03.md)。

## 根因与最终行为

初始 Slots.Create、Roles.Create、Names.Commit 的错误都可能发生在写入后；旧流程没有持久创建身份，直接返回或补偿会留下空 slot、孤儿角色或没有角色的 committed 名字。

现有 slot 增加值类型 RoleCreation：随机 ID、预分配 PlayerID、名字、创建时间、Name Claim、Admitted。新角色保存同一 CreationID。实现位于 `kit/service/account/create_role.go`，不增加数据库、包或新的必填 store。调用链：

1. 校验账号/区服/名字，读取 slot；不存在时分配角色 ID，insert-only 保存计划。分配失败/零 ID 不持久化任何创建状态，竞争输家分配的 ID 可以留下合法空洞。
2. 对 pending slot，只有同一个去空白名字可以继续；并发重试共享计划和 PlayerID。不同名字仍拒绝。旧空 slot 没有 CreationID，返回 ErrConflict 等待对账。
3. 名字 owner 使用 `slotKey/creationID`；把 Claim 与 Admitted 通过 slot CAS 持久化后，才能 Roles.Create。旧 worker 不能覆盖更新后的预约 Token。
4. Roles.Create 没创建时必须 Get，不能把接口的空返回当既有角色。匹配 CreationID/账号/区服/名字才接受重放；确定的外部 ID 冲突才能 Token-fenced Cancel 和 identity-fenced slot 清理。
5. 名字 Commit 或角色写入错误均保留计划，下一次请求继续。Commit 早于旧 slot 快照时，重新读 slot 的持久 Claim 验证已提交名字归属。
6. 最后回填 slot.PlayerID；写后错误保留 RR-12 的权威读回，读回也失败返回角色恢复身份及错误。同名完成后重试返回原角色，覆盖成功回复丢失；不同名字仍 ErrRoleLimit。

一旦 Admitted，普通/未知错误不会删除可能已提交的角色。只有确定的建角前名字冲突、或确定的 foreign allocator ID 可补偿，slot 删除复用 ConditionalDeleter，按 CreationID/发布状态/适用 admission 状态校验。New 要求 Slots 保留 DeleteIf 能力，包装器不能丢失。

未发布的新角色会被 SelectRole、ValidateSession、UpdateProfile 拒绝。RoleCreationID 为空的旧角色按旧已发布语义兼容；不给旧记录猜造创建证明。

## 回归与恢复边界

正式 `rr_20260929_round3_test.go` 验证三种写后错误、三种写前控制、复用同 ID、重新 New(Service) 后恢复、16 个并发重试、pending 角色不可使用、旧空 slot 拒绝猜测、名字被新 owner 占用后保留证明。账号定向 race 重复 15 次通过；真实 Redis 再跑原触发/控制、服务重建和并发重试通过。旧最终 slot 写后错误和读回失败的钩子明确针对 PlayerID 发布写入，业务断言保留。

原来“角色写后有 error 就必须全部消失”的测试改为“保留唯一恢复计划并能同 ID 恢复”，这是正确区分未知结果的契约变化；没有靠吞错或删除反例恢复绿灯。测试覆盖恢复入口和持久重用，不等于真实断电/HA 验证。

持久 JSON 为新增字段，没有自动生产迁移。旧空 slot、旧孤儿角色、旧无角色 committed 名字必须先读取账号/区服、slot、角色、目录状态做离线对账，确认无在途创建/有效角色后，由维护者选择补全关联或释放；保留记录和审计，不按 age/PlayerID=0 批量删除。

新的 pending 角色若名字预约过期后被别人提交，保留 intent 并拒绝角色登录，需要业务对账；不自动抢名字或丢角色。没有后台扫描器，正常恢复入口是同名 CreateRole 重试。不同名字/旧 legacy intent 不能盲目重试替换。新的名字 Owner 带 creationID，运维必须读当前 Entry.Owner，不再由旧 slotKey 猜 owner。
