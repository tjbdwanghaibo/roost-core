# RR-20261006-02 修复：状态默认值缺省时按 state 声明类型交给 Host

[问题](../bug/RR-20261006-02.md)。收尾第 3 批 A4（分支 `cb3`）。已修复、声明场景验证，未发版。

## 根因

`skill/runtime_state.go` `evalStateDefault` 把 null 默认值原样求值成 `MissingRuntimeValue(Base=valueKindNull)` 交给 Host；`skill/memory_host_state.go:122-124` 的 `set` 比较 `before.typ.Base != operand.typ.Base`，状态不存在时 before 就是这个 null 类型的默认值，第一次写入必报 `ErrRuntimeTypeMismatch`。null 默认值的语义是“还没写过”，状态类型仍是声明类型，所以错在 Runtime 交出的默认值丢了类型，而不是 Host 的类型比较。

## 决策

- **采用**：`evalStateDefault` 改收 `stateReferenceProgram`，求得的默认值缺省（not present）时返回 `MissingRuntimeValue(state.typ)`。私有状态与 shared 状态（缺省默认值同样是 null）都经这一处；读路径 `ReadState` 返回的缺省默认值也随之带声明类型。`StateMutationCommand` 注释写明 Default 的类型契约。
- **未采用**：① lower 时把 null 默认值改成声明类型——`programValueDigest` 把 null 的类型算进摘要，会改变 gameplay digest，而 digest 是私有状态的 `StateHandle` 一部分，已持久的状态会失联。② 在 `applyStateOperation` 里放行“before 缺省且是 null 类型”——只修 MemoryHost，`state_changed` 事件的 Before 仍是 null 类型，其他 Host 实现还会再撞；Host 的类型比较本身是对的。
- 同形分支（`runtime_ability.go:397`、`runtime_cast.go:113`、`combatcomponent/adapter.go:134`）逐一核对，不受影响，理由见问题记录。

## 文件与行为

- `skill/runtime_state.go`：`evalStateDefault(cast, state)`，缺省时换声明类型。
- `skill/host_state.go`：`StateMutationCommand` 注释（Default 的类型契约）。
- `skill/state_null_default_promises_test.go`：回归。

## 兼容

Program、摘要、checkpoint 格式不变。行为放宽：以前每次失败的 `set` 现在成功；`state_changed` / `state_cleared` 事件与 `StateMutationResult.Before` 在状态不存在时的缺省值类型由 null 变为声明类型（都是 not present，值不变）。

## 验证

- 修前红：`GOWORK=off go test ./skill -run TestNullDefaultEntityStateCanBeSet -count=1` → `modify_state set on a null-default entity state reported a type mismatch: skill: runtime value type mismatch`。
- 修后绿：同命令通过；第一次施法写入目标实体、Before 是 entity 类型缺省值，第二次施法 `exists(read_state)` 读到并打伤目标。
