# NC-102 修复：mongotest 唯一索引路径上遇到数组时明确拒绝

问题：[RR-20261005-NC-102](../bug/RR-20261005-NC-102.md)。证据：[nc102-probe](evidence/noncore-bugfix-20261005-revn04/nc102-probe.txt)。

## 决策

替身不实现 multikey，就不能给出与真实 Mongo 相反的判定。新增 `uniqueFieldValue`：沿索引路径逐层读取，终值或中间容器是 `bson.A` / `[]any` 时返回 `ErrUnsupported`（“unique index path … reaches an array (multikey index)”）。`uniqueKey` 与存量扫描 `checkUniqueFieldsLocked` 都走它，所以写入、更新和建索引扫描存量三个入口一致。缺字段 / null / sparse（RR-20261004-05）规则不变。

未采用：实现 multikey（按元素建键、文档数组子字段展开、嵌套数组）——生产没有需要它的唯一索引，实现成本与再次失真的风险都不值得；拒绝符合[组合契约复核](../agent-skills/roost-coding/references/fix-contract-review.md)第 3 条“明确拒绝不支持的场景”。

## 文件与行为

- `mongo/mongotest/mongotest.go`：`uniqueKey` 返回 error；新增 `uniqueFieldValue`；删去“数组整体比较”的范围说明，改为 NC-102 注释。
- 回归：`mongo/mongotest/unique_array_promises_test.go`（三组实测分歧、建索引扫描存量数组、更新把唯一键改成数组、compound 含数组成员均 ErrUnsupported；标量重复、索引外数组照旧）。

兼容性：用 mongotest 在数组字段上建唯一索引的测试现在得到 ErrUnsupported。全仓使用 mongotest 的包（dataengine/engine、kit/dataengine、kit/saga、nestwal、remoteentity、saga、根包）均通过；game-demo 模板中的 mongotest 用法不在数组上建唯一索引。

## 未验证 / 风险

没有实现 multikey 语义本身；其他 mongotest 查询算子对数组的语义不在本条范围。
