# RR-20261005-NC-70 修复：中断 go 命令时，先删掉命令所在的暂存树再重发信号

[问题](../bug/RR-20261005-NC-70.md) · [证据](../review/evidence/noncore-review-20261005-n08/README.md) · [本轮](../review/REVIEW-2026-10-05-n08-codegen.md)。2026-10-05，基线 `be7bcc18`（审查基线 `50e9a4e8`）。状态：已修复、声明场景验证，未发版。

## 根因

暂存树只由创建者的 `defer os.RemoveAll(stage)` 收尾（`codegen/internal/roost/dependencies.go:39-43`、`generate.go:224-228`）；`runCommandTree`（`command_tree.go`）在 go 命令运行期间接住 SIGINT / SIGTERM / SIGHUP，杀树后重发信号让进程照旧死于信号——defer 因而永远不运行。拦截信号的地方不知道暂存树，持有暂存树的调用方没有机会运行。

## 决策

- `command_tree.go` 新增进程级登记表：`removeOnInterrupt(stage) (release func())` 由暂存树创建者调用，`release` 幂等注销；`removeInterruptedStage(dir)` 在 `runCommandTree` 接住中断、`Wait` 返回（整棵树已死）、`signal.Stop` 之后、重发信号之前调用，**只删除包含本次命令 `Dir` 的那一棵登记树**。这棵树的所有者此刻正阻塞在这次调用上，没有别的代码在读它或从它提交；同进程里其他并发操作的暂存树不受影响。
- `updateFrameworkDependenciesTransactional`（`.roost-deps-*`，覆盖 project deps / sync / upgrade / new）与 `GenerateTransactional`（`.roost-generate-*`）在 `defer os.RemoveAll(stage)` 之后登记；非信号退出仍由原 defer 删除。
- 删除是尽力而为（进程马上死于信号，没有报告对象）。若进程里别处也接了该信号、重发没有结束进程，`runCommandTree` 照旧返回 “interrupted by …” 错误：两处调用方都立即返回错误（期间 `rollbackDependencyUpdate` 可能在已删除的暂存路径下重建 go.mod，随后被原 defer 删掉），不会在已删除的暂存树上继续规划提交。

### 未采用的方案

1. **CLI 入口统一接管信号、转成 context 取消、走正常回滚后再重发**：最彻底，也能覆盖生成器 / 复制 / 提交窗口；但要给 `GenerateTransactional` / `UpdateFrameworkDependencies` / doctor 加 ctx，并改写 cb11be90 的中断用例。按要求复用 cb11be90，不在本条重做，列入方向判断。
2. **`runCommandTree` 见到 `.roost-` 前缀的 `Dir` 就删**：隐式靠目录名猜所有权，也会误删调用方不打算交出的目录。
3. **下次运行时清理旧的 `.roost-*` 兄弟目录**：可能删掉另一个仍在运行的 roost 的暂存树；也不解决“这次留下”的问题。

## 文件与行为

- `codegen/internal/roost/command_tree.go`：`interruptStages`、`removeOnInterrupt`、`removeInterruptedStage`，`runCommandTree` 中断分支多一步删除；注释写明 RR 编号与“只删本次命令所在那一棵”的理由。
- `codegen/internal/roost/dependencies.go`、`generate.go`：各一行 `defer removeOnInterrupt(stage)()`。
- 新增 `codegen/internal/roost/interrupt_stage_promises_test.go`（`//go:build unix`）：重新执行测试二进制扮演 roost，PATH 上的替身 `go` 起长寿孙进程并记录工作目录；等替身报告后向 roost 进程组发 SIGINT。断言：死于 SIGINT、孙进程消失、工程旁无 `.roost-*`、工程 `go.mod` 未变；之后换成立即成功的 go 重跑同一命令成功且无残留。子测试 `deps`（`UpdateFrameworkDependencies`）与 `generate`（`GenerateTransactional`），走正式入口。

## 兼容性

退出码、错误文本、“死于信号”的语义与 go 进程树处理不变；Windows 上 `runCommandTree` 不接管信号，行为不变。无 API、生成物或持久格式变化。

## 组合契约复核

- 取消后最终状态：中断 → 暂存树删除 → 新进程重跑成功、无残留（用例覆盖）。
- 再次 Stop：删除期间若再来一次同类信号，`signal.Stop` 已恢复默认动作，进程立刻死，暂存树可能只删了一部分。窗口为一次 `RemoveAll`，未单独覆盖。
- 并发：登记表加锁，`release` 用 `sync.Once` 幂等；只删包含 `Dir` 的那一棵，并发的其他暂存树不动。

## 未验证项 / 残余

- 生成器、`copyProject`、提交阶段被中断时仍无信号处理，暂存树可能残留（[问题记录](../bug/RR-20261005-NC-70.md#范围与未做)、本轮 O6）。
- Windows 未实跑；`systemd` 等真实 supervisor 只用 SIGTERM 模拟。

## 之后：B6 取代本修复的机制（2026-10-06）

维护者决定 B6 把信号所有权收到 CLI 入口（`roost.Main`）：第一次信号取消 ctx，命令走正常错误路径、暂存树由创建者的 defer 删除，命令返回后入口再重抛信号。本修复的登记表（`interruptStages` / `removeOnInterrupt` / `removeInterruptedStage`）与 `runCommandTree` 的中断分支一并删除；本条的回归 `TestInterruptedCommandRemovesItsStagingTree` 断言不变，子进程改经 `Main` 跑正式命令行，`-race -count=3` 通过。上文“未验证项 / 残余”第一条（生成器、`copyProject`、提交阶段，N08 O6）由 `interrupt_phases_promises_test.go` 覆盖并修复。[方案与实施](../feature/B6-CLI-SIGNAL-OWNERSHIP-2026-10-06.md)
