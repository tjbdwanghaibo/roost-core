# NC-210 修复：memory 效果的名字在类型检查里统一检查

[问题](../bug/RR-20261005-NC-210.md) · [本轮](../review/REVIEW-2026-10-05-n09-batch4.md)。已修复、声明场景验证，未发版。

## 根因与决策

`compile_typecheck.go` 的 set / add_memory 只在名字找到时检查 value，clear_memory 什么都不查；lower（`lower.go:597-601`）用 `c.memory[name]` 的零值取槽位。新增 `typeChecker.declaredMemory`，三种效果共用：未声明的名字报 `REFERENCE_UNKNOWN` 到 `….name`；`add_memory` 另要求 memory 是 int（`CheckedAddRuntimeValues` 只接受 int），否则 `TYPE_MISMATCH`。

未采用：让 lower 对查不到的名字 panic——那是方向判断第 2 条（全部 lower 查找改成 fail-fast），需要逐个确认前置检查后统一做；本条只补缺的检查。

## 文件与行为

`skill/compile_typecheck.go`。写错 memory 名字、或对非 int memory 用 add_memory 的定义在启动期编译失败；合法定义不变。测试输入 `compile_lifetime_test.go`（parallel finish）与 `compile_budget_test.go`（repeat 超限）原来用未声明的 `clear_memory x` 当填充，现在声明 `x`，断言不变。
