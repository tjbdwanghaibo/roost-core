# NC-211 修复：移交后 area 回调的 finish 只结束本 area 进程

[问题](../bug/RR-20261005-NC-211.md) · [本轮](../review/REVIEW-2026-10-05-n09-batch4.md)。已修复、声明场景验证，未发版。

## 根因与决策

编译器允许 spawn 出的 area 回调 finish（“结束拥有它的施法 + 停止本 area 余下信号”），但不知道施法会不会先结束；施法先结束时进程已移交，`runOwnedProcessCallback`（`process_owned.go`）对 `process.handedOff` 与终态拥有者返回 `ErrProgramInvariant`。

采用方向 A：Runtime 处理这个合法状态。finish 时拥有者施法仍存活就照旧结束施法；已移交或拥有者已终态时只置 `areaCallbackFinishedCast`（停止本 area 余下信号）。`advanceOwnedProcesses` 在派发信号后看到这个标记，按施法存活时 `startEntityProcess` 的同一规则停止进程（`StopCauseCancel`，不跑 end / cancel 回调）；停止过程中（`terminateProcess` 的 leave）触发的 finish 本来就在停止路径上。

未采用：编译期禁止 entity 作用域 area 回调 finish——会拒绝 `area_membership.json` 这类施法存活时合法的定义。

## 文件与行为

`skill/process_owned.go`。施法存活时的行为不变（`TestAreaCallbackFinishStopsRemainingSignals`、`TestAreaFinalLeaveFinishSuppressesTerminalCallback`、新控制 `TestLiveAreaFinishStillFinishesTheCast`）；移交后的 finish 不再让 Advance 报错，area 进程在这一 tick 停止并回收。checkpoint 形状不变（标记只在同一次 Advance 内生效，进程随即停止）。

## 回归

`skill/area_handoff_finish_promises_test.go`：`TestHandedOffAreaFinishEndsOnlyTheAreaProcess` 两个子用例修前：

```
leave_after_handoff: Advance(2) = skill: immutable program invariant failed; a compiled area finish must not fail the runtime
enter_after_handoff: Advance(1) = skill: immutable program invariant failed; a compiled area finish must not fail the runtime
```

修后 ok（finish 只执行一次、owned 进程回收为 0）。变异性质测试的 `seed.area_handoff` 种子修前基线与其变异都报 `advance[0] 3: …invariant failed`，修后 ok。

## 未验证

只用 MemoryHost 与 `areaSnapshotHost` 控制成员进出；没有在 combatcomponent 宿主上跑 owned 进程（它不实现 `OwnedEntityRuntimeHost`）。
