# NC-223 修复：快照计划的实体取读取处 lower 出的值

[问题](../bug/RR-20261005-NC-223.md) · [本轮](../review/REVIEW-2026-10-06-n09-batch5.md)。已修复、声明场景验证，未发版。B3（`023eb276`）引入的回归。

## 根因与决策

`lowerSnapshots` 用空作用域 lower 全部快照计划的实体；B3 之后空作用域里的 `$local.` 查不到即 `LOWER_UNRESOLVED`。修法（`skill/lower.go`）：`lowerValue` lower `read_attribute` 时把读取处（带作用域）lower 出的实体按源路径记进 `loweringContext.readEntities`，`lowerSnapshots` 用它生成计划的实体；没有记录的计划（不应出现）仍按空作用域 lower，查不到照样报错（并带上计划的源路径而不是 `$`）。

为什么这样：

- 缓存型采样点的计划实体 NC-220 之后不再含局部变量，读取处与空作用域 lower 出的值相同；
- 其余采样点的计划运行期不采样，只随 Program 记录、进 gameplay digest，实体取读取处的值是唯一有意义的选择；
- 对今天能编译的定义输出逐字段不变：42 个既有种子修前修后 gameplay / presentation digest 逐一相同（临时探针比对 origin/main 与本分支）。

未采用：① 只 lower 缓存型采样点的计划——会改变所有含 current 读取的技能的 gameplay digest，checkpoint 按 (id, digest) 找 Program，升级后旧 checkpoint 找不到；② 恢复 B3 之前退成同名 builtin 的行为——那正是 B3 要消灭的“查不到就兜底”。

## 文件与行为

`skill/lower.go`。以局部变量为实体的非缓存型读取恢复为可编译（与 v1.20.1 的执行结果相同）。这类定义的 gameplay digest 与 v1.20.1 不同（计划实体从 builtin 占位变为局部变量引用）；v1.20.2 根本编译不了它们，所以不存在 v1.20.2 的 checkpoint。

## 回归

`TestReadsOfALocalEntityAtNonCachedPointsCompileAndRun` 四个子用例修前全部 `unexpected diagnostic: … LOWER_UNRESOLVED … Path:"$"`，修后 ok（两个目标分别按 7 / 11 受伤）；同一用例在 `023eb276^` 上通过（回归证据）。B3 的 `TestLowerRefusesEveryUnresolvedLookup`（逐表删条目）照常通过。性质测试新增种子 `seed.local_attribute_read`。

## 兼容性

恢复 v1.20.1 可编译的定义；其余定义输出不变。若有部署在 v1.20.1 上保存了含这类技能的 checkpoint，升级后这些 cast 的 Program 查找会因 digest 不同而失败（与任何改变 gameplay digest 的升级相同），需要先排空。
