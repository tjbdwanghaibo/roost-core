# RR-20261006-19 修复：可靠 RPC 的 method 标签有界（有界证明 + 断言测试）

问题：[RR-20261006-19](../bug/RR-20261006-19.md)。分支 `oa`，基线 `ac913a60`，未发版。

代码阅读：codebase-memory generation 09-30（`bus/jetstream_rpc.go`、`bus/bus.go` metadata_changed），`callJetStreamRPC` 的入站调用（`CallReliable`、`CallToReliable`、
`callReliableSubject`、`callJetStreamRPCAsync`）经 `trace_path` 定位后以当前源码核对；仓内可靠调用只经 `servicerpc.BusClient.Call` 进入。

## 决策：有界而不是删除

method 没有注销（`HandleRpc` 只注册，没有撤销单个方法的入口），按维护者要求给出有界证明并用断言测试固定，而且界由 Bus 自己保证、不依赖调用方守规矩：

| 一侧 | 指标 | 标签取值 | 上界 |
| --- | --- | --- | --- |
| 被调方 | `bus_rpc_request_total{method,result}`、`bus_rpc_consumer_delivery{method}` | 本进程 `HandleRpc` 注册过的方法；envelope 里其他名字一律 `_unregistered`（日志仍记原名） | 注册的方法数 + 1 |
| 调用方 | `bus_rpc_pending{method}`、`bus_rpc_call_total{method,result}`，以及 `pendingByMethod` | 每个 Bus 前 256 个不同方法用原名；之后的新方法记 `_other`，第一次溢出 Warn 一次（限、标签、第一个溢出的方法） | 256 + 1 |

- 为什么调用方用上限而不是“注册”：调用方不知道对端注册了哪些方法；按“收到过响应”判定会让启动时对端不在的真实方法丢标签。
- 为什么 256：框架生成的全部 RPC 客户端都用生成的方法常量，全仓 57 个（session 6、mail 8、match 7、global 5、activity 11、rank 6、account 6、chat 5、platform 3），
  远在上限内；`bus_rpc_call_total` 每个方法有若干个 result，256 个方法仍在注册表每指标 2048 以内，所以兜底的上限不会再丢真实方法的序列。
- 为什么不在空闲时删除 `bus_rpc_pending{method}`：`DeleteSeries` 在注册表写锁下扫全部序列，按调用频率删建会把每次 RPC 变成两次全表扫描；而 method 本身没有生命周期终点。
- 调用本身不受影响：线上的 `MsgName` / subject 仍是真实方法，只有指标标签合并。
- 只有 JetStream 可靠 RPC 路径有这些带 method 的指标（轻量 request/reply 不计）。

## 改动

- `bus/jetstream_rpc.go`：`jetStreamRPCMethodLabelLimit` / `jetStreamRPCOtherMethod` / `jetStreamRPCUnregisteredMethod` 与注释里的有界证明；
  `jetStreamRPCCallerMethodLabel`（`sync.Map` 快路径，首次出现时在锁下计数）；`callJetStreamRPC` 用标签记 pending 与 call_total；
  `onJetStreamRPCRequest` 在读 envelope 后先查注册表，按注册与否定标签（handler 查找从后面挪到这里，同一次读）。
- `bus/rpc_method_label_bound_promises_test.go`（新）。

## 兼容

- 被调方收到未注册方法的请求，指标从 `method="<原名>"` 变为 `method="_unregistered"`（`result="no_handler"` 等）；日志仍是原名。
- 一个 Bus 调用超过 256 个不同方法时，之后的新方法计入 `method="_other"`。生成的客户端不会触发。

## 验证（`GOWORK=off`）

- 修前红：见问题记录。
- 修后：`TestCallerRPCMethodLabelsAreBounded`（300 个方法：两个指标的 method 标签与 `pendingByMethod` 都 ≤ 257，前面的方法保留自己的标签，
  `_other` 的 ok 计数 = 44）、`TestServedRPCMethodLabelsAreTheRegisteredMethods`（300 个伪造方法：两个指标只有 `mail.List` 与 `_unregistered`，`no_handler` 计 300，注册方法 ok 计 1）；
  原有 JetStream RPC 用例（按方法的 pending、超时清零、投递次数）照常。`go test -race -count=3 ./bus` ok；`go vet ./bus`；根包、`go build ./... && go vet ./...`。

## 未验证 / 风险

- 多个 Bus 同进程时各自 256（标签不带 Bus 身份，同名方法写同一序列，这是修前就有的共享，生产每进程一个 Bus）。
