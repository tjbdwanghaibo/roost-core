# RR-20260926-68 修复：调用方截止在第一个字节写出前到期的推送按“写前拒绝”处理，不关闭连接

问题：[RR-20260926-68](../bug/RR-20260926-68.md)（复现 [REPRO-2026-09-26-06 §4](../bug/REPRO-2026-09-26-06.md)）。前序：[RR-52 修复](RR-20260926-52.md)。
日期 2026-09-27；实施基线 main `2373e21` + RR-66 提交 `fb00df8`。状态：已修复、本地验证通过，已本地提交，未推送/未发布。

## 根因

生成 TCP 传输 `writeFrame`（`codegen/internal/roost/render_player_tcp.go` → 生成 `internal/access/player/tcp/server_gen.go`）在写锁内复查
`ctx.Err()` 后，把写截止设为 `min(now + write_timeout, ctx 截止)`。ctx 恰好在复查之后、写系统调用之前到期时，`WriteTo` 立即
`i/o timeout`、写出 0 字节，却和“写到一半失败”一样包成 `errConnectionBroken`，`pushPlayer` / `pushSession` 随即 `dropBrokenSession`
关闭这条正在正常读数据的连接。一个字节都没写出时流仍与客户端同步，不是连接的错。触发者是带截止的调用方（聊天 deliver 用请求 ctx、
停机最后的 Flush）。

## 决策（按维护者批准的修复约束：超时且写出 0 字节按“写前拒绝”处理；部分写出仍视为连接损坏）

`writeFrame` 记下本次写截止是否来自调用方（ctx 截止早于 `now + write_timeout`），并保留 `WriteTo` 的写出字节数：

| 情形 | 判定 | 连接 |
| --- | --- | --- |
| 写出 0 字节 + `os.ErrDeadlineExceeded` + 截止来自调用方 | 写前拒绝：返回包裹 `context.DeadlineExceeded` 与原错误的错误，不带 `errConnectionBroken` | 保留 |
| 写出 0 字节 + `write_timeout` 本身到期 | 连接损坏（RR-52：连一个字节都写不进 `write_timeout` 就断开） | 关闭 |
| 写出部分字节（无论哪个截止） | 连接损坏（流已错位） | 关闭 |
| 其他写错误（RST、EPIPE、已关闭） | 连接损坏 | 关闭 |

约束里“超时且 0 字节”限定为**调用方截止**的超时：若 `write_timeout` 到期、0 字节也算写前拒绝，一条发送缓冲恰好被之前的帧写满的半死连接
每次推送都会 0 字节超时，永远不会被关闭——这正是 RR-52 修的循环。约束的备选“连接判定只用 write_timeout”与这里等价：调用方截止只能让
推送被拒绝，不能让连接被判损坏。

写前拒绝的推送在 `pushPlayer` 中属于 `refused`：返回错误、不关闭任何连接（与 ctx 已结束、payload 超限同一分支）；不计 `player_tcp_write_error_total`
（与早先的 ctx 检查一致）。调用方用 `errors.Is(err, context.DeadlineExceeded)` 仍能识别。`Reply` 用连接 ctx（无截止）写回，不受影响。

未采用：写截止只用 `write_timeout`、忽略调用方截止（调用方截止就不再约束写阻塞时长，违背 `TestWriteFrameHonorsEarlierContextDeadline`
的既有契约）；在写前再查一次 ctx（检查与系统调用之间的窗口仍在，只是变窄）。

## 交付前对抗性自查

- **不误关**：只有“0 字节 + 截止类错误 + 截止来自调用方”三者同时成立才免于关闭；0 字节时流未被写入任何字节，客户端视角与“这帧没发”完全相同。
- **不漏关**：`write_timeout` 自身到期（缓冲写满的半死连接）即便 0 字节仍关闭；部分写出（任何截止）仍关闭；非超时错误（RST / EPIPE / 已关闭）仍关闭。
  回归逐一覆盖（脚本化连接 + 真实 pipe），RR-52 真实 TCP 回归保持绿。调用方持续用很短截止推送一条半死连接时它不会被这些推送关闭，
  但下一次不带截止或截止更长的推送、读循环的 `idle_timeout` 仍会发现它——这是“调用方截止只能拒绝推送”的直接结果，写进注释。
- **连接槽唯一释放**：本次不改 `dropBrokenSession` / `serveConnection`；写前拒绝不调用任何关闭路径，连接槽、按 IP 计数与关闭事件仍只由读循环的
  defer 释放一次。REPRO 回归断言无关闭事件、两条连接都仍注册。
- **时间判定**：`callerDeadline` 用同一次 `time.Now()` 算出的 `writeDeadline` 比较，不因两次取时间不一致误判；截止相等时按 `write_timeout` 处理（关闭），偏保守。

## 后续验证（2026-09-30，B27 第 3 批）

来源：[REMAINING-2026-09-28 §1.1 B27 分批第 3 行](../review/REMAINING-2026-09-28.md)（“未验证项”第 1 条：真实客户端 / 集成环境里聊天 deliver、停机 Flush 的临界截止）。基线 `96f0f7c5`。环境与生成工程同 [RR-20260926-25 同批追加节](RR-20260926-25.md)。脚本与输出：scratchpad `b27-batch3/drill-rr68.sh`、`rr68-drill.log`（第 4 链）、`rr68-drill-chain3.log`、`rr68-game.log`。
