# NC-121 修复：丢弃排队动作时逐个发 OnEnded（取消）

问题：[RR-20261005-NC-121](../bug/RR-20261005-NC-121.md)。2026-10-05，分支 `revn10`，基线 `197f7bb9`。

## 根因

`actionflow/action_runner.go:218 / :225 / :240-249`（基线）三处丢弃排队项只改切片，不发结束事件；而入队时已发 OnQueued、ID 已返回调用方，排队项启动失败的路径（`:314`）也会发 OnEnded。

## 决策

- 三处统一走新的 `discardQueued(unit, match, reason)`：先把命中项移出队列，再逐个 `OnEnded`，状态一律 `ActionStatusCanceled`（从未启动的动作没有别的合理结果），消息沿用调用方给的 reason；`ClearQueue` 没有 reason，用 `"queue cleared"`。
- 从未启动的动作不调 `Cancel`、不发激活切换（`Cancel` 只对 Start 过的动作有意义，与现有启动失败路径一致）。
- 先改队列再发 Hook：Hook 里重入排进来的新动作留在队列里，不被这次丢弃误伤。
- 组合核对：`MissionRunner.EndCurMission` 在 `ending` 下调 `ClearActions`，新增的 OnEnded 到 `OnActionEnd` 时被吞，不推进任务；外部 `EndAll` 给任务送来的是非当前动作 ID，`PlanMission` 忽略；ai `SetStrategy` 的 EndActions 在 `switching` 下，通知不送达策略。

## 文件与行为

- `actionflow/action_runner.go`：`EndAll` / `ClearQueue` / `ClearMission` 改用 `discardQueued`；中文注释。
- `actionflow/queue_discard_promises_test.go`：三种丢弃各一条子用例 + `ClearMission` 不动别的任务的控制用例。

行为变化：丢弃排队项时多发 OnEnded（取消）。无格式 / API / wire 变化。

## 回归与结果

- 修前：[red](evidence/noncore-bugfix-20261005-n10/red.txt)；修后：[green](evidence/noncore-bugfix-20261005-n10/green.txt)。
- 接线控制（[probes](evidence/noncore-bugfix-20261005-n10/probes.txt)，ActionRunner + MissionRunner 按 ActionList 注释最小接线）：两步计划推进、旧 ID 结束不推进、取消任务时清动作且不推进下一步。

## 未验证 / 风险

自定义 Mission 若在 `OnActionEnd` 里对非当前 ID 也有反应，会多收到这些取消事件；仓内唯一实现 PlanMission 忽略非当前 ID。
