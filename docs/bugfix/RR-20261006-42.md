# RR-20261006-42 修复：重试退避期间送达的成功被丢弃，操作随后被关闭时这一步已生效却不计入、不补偿、不告警

问题：[RR-20261006-42](../bug/RR-20261006-42.md)（F06-S1）。基线 `0b223b4c`（main，v1.23.0 之后；WIP `wip/sagafix` `bcdb4bd4` rebase 到此）。codebase-memory 共享 generation 停在 09-30（比基线旧），定位与结论按 worktree 当前源码读取。
同一批（sagafix2）修 RR-20261006-42～47，一笔提交 `63bc1d66`。

## 根因

`saga/engine.go` `Complete` 的同一生分支（基线 `:443`）只认 `Waiting`：`accept = record.Status == StatusWaiting && record.OperationKey == completion.IdempotencyKey`。退避中的成功只能指望下一次尝试经收件箱回放，而关闭操作的三条路径（截止、人工 `Compensate`、定义缺失）都可能先于下一次派发发生。

## 决策

- **接收退避中送达的成功**：同一生、`openOperation(record) == completion.IdempotencyKey`（`Pending` / `Compensating` 且 `Attempt>0`，即这个操作已派发过、在重试退避）时，`Success=true` 的 completion 接收为该操作的结果，走与 `Waiting` 时相同的 `applyCompletion` + `stepTransition`（写成功回执、带结果关闭操作、前进一步）。与规则 2（旧一生的成功在记录停在该操作上时接收）同一理由：成功是操作的结论，收件箱保证之后的尝试只会回放它。
- **拒绝与可重试失败在退避中仍不接收**：拒绝会由下一次尝试回放（操作若先被放弃，拒绝本来没有要补的东西）；可重试失败按方向 ③ 只认正在等的那次尝试，退避中没有正在等的尝试。
- **与派发并发**：成功先写 → 记录前进，派发按版本冲突；派发先写 → 记录 `Waiting` 在 k+1 上，k 的成功按规则 3 接收。真实副本集上 `TestRealMongoSuccessDuringBackoffRacesTheNextDispatch` 20 轮并发，每轮这一步恰好计入一次、回执落库。
- **未采用**：① 让关闭操作的三条路径先查“有没有在路上的成功”（要额外读收件箱，且送达可能在关闭之后，仍要方向 ④ 兜底）；② 关闭时总按“可能已生效”补偿（对确实没生效的步骤做无谓补偿）。
