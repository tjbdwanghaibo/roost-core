# RR-20260919-01：顶层 nested 指针字段没有完成所有权交接（U-0249）

- 仓库：roost-codegen `internal/dao`
- 缺陷类：C2（生成物的不变量缺一条分支）
- 优先级：P1
- 相关：T-143；测试 `internal/dao/testdata/runtime/ownership_test.go` 的
  `TestTopLevelPointerFieldOwnership`、`TestClearingAPointerFieldDetachesTheValue`

## 问题

顶层 DAO 字段 `Mount *EquipInfo`，把它换成另一个对象：

| 场景 | 期望 | 修前 |
| --- | --- | --- |
| 提交后改 old | 0 条提交 | **1 条** |
| 提交后改 new | 1 条 | 1 条 |
| 回滚后改 old | 1 条 | 1 条 |
| 回滚后改 new | 0 条 | **1 条** |

置 nil 同理：被清出去的值继续报告自己的修改。

## 根因

同一条所有权不变量的第三个分支。U-0236 修的是嵌套结构内部，U-0238（RR-20260918-10）修的是顶层
**map / slice**，两者都改成了"值进入容器 = 绑定通知、离开容器 = 解绑"。顶层**单个指针字段**
走的是模板里的另一段（Kind 3），那段只在赋值后给新值 `SetNotify`，undo 只把 old 放回去再绑一次，
两条路径都没有先给离开的对象 `SetNotify(nil)`。

游离对象仍能产生真实的 `CommitRecord`：它写的是自己的内容，落到一个它已经不在的字段上。

## 方案

- 采用：**和 map / slice 同形**。生成 `bind<F>` / `unbind<F>`——只搬通知，不标脏、不记 undo
  （所以能在 undo 里调用，那时事务已经 rolledBack，任何 mutator 都会再记一条 undo）。
  setter 与 undo 都按"解绑当前 → 替换 → 绑定新当前"执行，`Init` 复用 `bind<F>`。
- 没采用：在 setter 里比对"要解绑的是不是我期望的那个对象"。审查建议里提到，但当前形状下
  解绑发生在替换之前、同一把锁内，没有第三者能插进来；等到别名问题（RR-20260919-02）定了契约，
  owner token 会自然带来这条校验。

## 改动

`internal/dao/template_dao.go`：Kind 3 且 `IsPtr` 且 nested 时生成 `bind<F>` / `unbind<F>`；
`Init`、setter、undo 三处改为调用它们。fixture `testdata/def/hero.go` 加 `Mount *EquipInfo`，
golden 重生成。

## 证明

修前（`scripts/dao-golden-runtime.sh`，对着真实 core 跑）：

```
--- FAIL: TestTopLevelPointerFieldOwnership/committed_old_is_detached
    mutating the old value produced 1 commit records, want 0
--- FAIL: TestTopLevelPointerFieldOwnership/rolled_back_new_is_detached
    mutating the new value produced 1 commit records, want 0
--- FAIL: TestClearingAPointerFieldDetachesTheValue
    a value cleared out of its field still produced 1 commit records
```

修后全部通过；`go test ./...`（含 golden 文本门与运行时门）全绿。

## 未做 / 边界

- **别名仍然是未修的**：同一个 nested 指针同时放进两个字段 / 两个 key，通知是单槽的，后绑的赢。
  那是 RR-20260919-02，需要先定"唯一父所有权"的契约（owner token、失败方式），本轮没有动。
- `Del`、raw hydrate 路径在 map / slice 上已经走统一 helper；单指针字段没有 `Del`，清空即 `Set(nil)`，
  已覆盖。
