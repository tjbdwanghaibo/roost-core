# RR-20261006-64 修复：全部座位已报且无多数时判 NoMajority

问题：[RR-20261006-64](../bug/RR-20261006-64.md)（F04-8）。基线 `a7285da6`，分支 `lockstep`，提交 `4ce70763`。

## 根因

检测器只认“某个哈希有 quorum 份一致上报”，不知道座位数，无法判断一帧已经不会再有上报；2 人房的 1:1、4 人房的 2:2、全不同都永远停在“未裁决”。

## 决策（产品语义）

按维护者给的方向（“2 人时 hash 一不一致就判双方 desync 并上报”）推广为一条规则，不需要另请维护者定：**一帧的全部座位都已上报、存在分歧、且没有任何哈希达到 quorum 时，裁为 NoMajority——全部座位都是离群者**。多数规则不变（有哈希达到 quorum 就按多数裁，少数是离群者）。NoMajority 不能指认某个玩家，业务应按“整局已分叉”处理（中止，或从权威状态重同步），而不是踢某一方。

## 修复

- `sync/lockstep/desync.go`：`DesyncDetector` 增加座位数（不导出，Room 设置；单独使用检测器时为 0，行为不变）；`Report` 在未达 quorum、上报数 ≥ 座位数且哈希不止一种时返回 `NoMajority` 裁决，`Outliers` 为全部座位（升序），`Majority` 为 0。
- `DesyncVerdict` 新增 `NoMajority bool`。Room 的集合语义不变：NoMajority 裁决触发一次 `OnDesync`，`lockstep.desync.total` 按新离群者计（2 人房 +2）。
- `RoomConfig.HashQuorum` 注释写明该规则。

## 兼容性

新增 `DesyncVerdict.NoMajority`。2 人房的哈希分歧之前静默，现在触发 `OnDesync` 并计数——demo 的 `OnDesync` 只记 Error 日志，机器人诚实时不会触发。未部署。
