# RR-20261003-NC-04：完整单值 JSON 请求校验

2026-10-04，修前 `183b0bddc5b46f6d3b50c5edda2d08da45150a69`。[原问题](../bug/REVIEW-2026-10-03-noncore-01.md#rr-20261003-nc-04p2-bindjson-接受首个-json-后的垃圾或第二个值)。已修复、具名场景验证，未发版。

根因：BindJSON 已读完整限长 body，却只用 Decoder.Decode 解析首个值。`httpserver/server.go` 改为 json.Unmarshal 校验整段单个值，错误仍返回原来的 JSON 400，HandleJSON 不进入业务函数；不新增 reader/HTTP 框架。

采用 Unmarshal 是因为当前已有完整 raw body，不需要第二次 Decode 的 EOF 分支；没有取消限长，也没有只扫描字符串尾部。合法尾随空白保持，空 body 按已有代码返回零值，超限仍 413，响应格式/业务函数 API 不变。

正式回归 `httpserver/json_boundary_promises_test.go` 修前：尾随 garbage/第二对象均 `status=200 calls=1, want status=400 calls=0`。修后原七个分支全部通过：正常、空白、非法首部、超限、当前空 body 行为及两个拒绝分支。

兼容性：此前非法的额外 JSON/垃圾现在拒绝；发送方需改成单个值，不应把多个业务请求拼成一个 body。不涉及 wire 字段或存储迁移。大 body/网络断开、正式 Webroute 进程还需后续接入审查。
