# RR-20260927-34：生产镜像自带 `configs/data`，放在相对 `config_data.dir` 按 `WORKDIR /app` 解析到的位置

问题：[RR-20260927-34](../bug/RR-20260927-34.md)（OPEN-ITEMS 批次 7 C04 / B34 / B32 实跑发现）。日期 2026-09-27。基线 `e0d38f7`，分支 `fix-r8-b14`。
状态：已修复，本地验证通过（含本机 docker compose 全部 10 个服务到 healthy），本地提交，未推送 / 发布。codebase-memory 图谱过期（09-26），本轮以当前源码、`rg` 与实跑为准。

## 根因

- `codegen/internal/roost/catalog.go:31`（基线行号）：configdata Mod 的生成配置是 `config_data.dir: configs/data`，相对路径，按进程工作目录解析；
  `kit/configdata/configdata.go` `Init` 的缺省值也是这个相对路径。
- `codegen/internal/roost/render.go:1043-1045`（基线行号）：运行阶段 `WORKDIR /app`，只拷二进制、healthprobe 与（有 WAL 时）WAL 目录。
- compose（`render_cicd.go` `renderProductionCompose`）与 k8s（`render_deploy.go` `renderKubernetesWorkload`）只挂 `config.yaml`、`/tmp` 与 WAL。

于是容器里 `/app/configs/data` 不存在，`mod config_data start: configdata: stat dir configs/data: ... no such file or directory`，按 `restart: unless-stopped` 反复重启。

## 决策：镜像自带数据（修复约束的方案一），不改 `config_data.dir`

采用：运行阶段加 `COPY --from=build /src/configs/data /app/configs/data`（仅当工程启用了 configdata Mod）。`WORKDIR /app` 原本就有，配置不变。

理由：

1. **数据是发布内容，不是环境配置。** `configs/data` 由 `make generate` 从 `configs/table` 产出，表结构由二进制里的生成代码注册（`RegisterGeneratedConfigData`），
   数据与代码必须同版本；和按环境不同、含密钥的 `config.yaml` 性质不同。放进镜像，staging 与 production 晋级的是同一份制品（部署说明的既有约束）。
   “配置和密钥不进镜像”这条不变：运行阶段仍然不拷 `configs/service` 或任何 `config*.yaml`（新回归逐行检查）。
2. **不需要改配置，dev / 容器用同一份值。** 相对路径在开发机按工程根目录解析，在镜像里按 `WORKDIR /app` 解析，两边都是 `<根>/configs/data`。
   方案二（容器配置里写镜像内绝对路径）要让容器配置与开发配置分叉，而且数据仍然要有来源——要么还是进镜像，要么在部署时另外供给。
3. **按环境覆盖与热更新仍可做。** 挂卷整目录遮盖 `/app/configs/data` 即可（compose 用只读 bind，k8s 用 ConfigMap / 卷）；configdata 按注册的文件名逐个读取
   （`configdata/configdata.go` `readJSON(filepath.Join(ctx.Dir, d.File))`），不遍历目录，所以 ConfigMap 挂载带的 `..data` 符号链接不影响读取；
   更新后经 configdata Reload（demo 的 `gm.config.reload`）重新读同一目录。方案二若靠部署时供给数据，k8s 要从仓库生成 ConfigMap（kustomize 不允许引用 base 目录之外的文件，
   单个 ConfigMap 还有 1 MiB 上限），复杂度和失败面都更大。

没有采用的：给 compose / k8s 显式加 `working_dir: /app` / `workingDir: /app`。镜像的 `WORKDIR` 已经固定了锚点，生成的 compose / k8s 都不覆盖它；
新回归断言两者既不改工作目录、也没有挂载遮住 `/app/configs/data`，以后有人加了会先红。

## 文件与行为

- `codegen/internal/roost/catalog.go`：新常量 `defaultConfigDataDir = "configs/data"`，configdata 的生成配置与 Dockerfile 的拷贝路径都从它来，二者不会再各写各的。
- `codegen/internal/roost/render.go` `renderDockerfile`：启用 configdata 时在运行阶段、healthprobe 之后加一行 `COPY --from=build /src/configs/data /app/configs/data`
  （root 所有、只读；进程以 65532 运行，只需要读）。中文注释写明路径如何解析、之前为什么错、为什么进镜像、如何覆盖。
- `codegen/internal/roost/render_deploy.go`：生成的 `deploy/docker/README.md`、`deploy/k8s/README.md`、`docs/DEPLOYMENT.zh-CN.md` 在启用 configdata 时各加一段
  `configDataImageNote`：数据随镜像、位置、覆盖方式（整目录挂到 `/app/configs/data`）与热加载；并说明把 `config_data.dir` 改成别的路径时镜像里的数据不会跟着移动。
  部署说明 Docker 一节“不包含配置”改为“不包含环境配置与密钥”。未启用 configdata 的工程生成内容不变。
- 仓库文档：`docs/DEPLOYMENT.md` §5、`codegen/docs/PROJECT_GENERATOR.zh-CN.md` 部署入口表、`PRODUCTION_READINESS.md` 同步同一口径。
- `codegen/internal/roost/image_configdata_promises_test.go`：`TestProductionImageCarriesConfigDataWhereConfigDataDirResolves`。四种工程（磁盘上真实生成的 game-demo、
  默认 Mod、只有 configdata、没有 configdata）：按 YAML 读出每个服务的开发与生产示例配置里的 `config_data.dir`，解析 Dockerfile 最后一个阶段的 `WORKDIR` 与 `COPY`，
  断言存在 `COPY --from=build /src/<dir> <WORKDIR>/<dir>`、构建上下文里有 `<dir>/_manifest.json`、运行阶段不拷环境配置；compose 与每个 k8s workload 不改工作目录、
  不挂载遮住数据目录；没有 configdata 的工程不拷数据。

## 兼容性

- Dockerfile、compose、部署说明是 codegen 受控文件，`roost project sync` 即更新（实测见下）。
- 已有工程若手工把 `config_data.dir` 改成别的路径：镜像里的数据仍在 `/app/configs/data`，要自己挂到新路径（生成的说明里已写）。
- 启用了 configdata 却删掉了 `configs/data` 目录的工程，`docker build` 会在这一行失败；这种工程原本在开发机与容器里启动都会失败，现在提前到构建时暴露。

## 另外发现（未修，已报主会话）

1. **stats_log 在容器里从不落盘，且没有任何告警。** 生成配置 `stats_log.dir: log` 是相对路径，容器里是 `/app/log`；compose `read_only: true`、k8s `readOnlyRootFilesystem: true`
   都让它不可写。`kit/statslog/statslog.go` `Start` 的循环里 `_ = m.FlushOnce()` 丢弃了 `MkdirAll` / `OpenFile` 的错误。实测 game 运行 75s（`interval: 1m`）后
   `docker cp b14demo-game:/app/log -` 报不存在，日志里也没有相关 WARN。systemd 部署同理（`WorkingDirectory=$APP_ROOT`、`ProtectSystem=strict`，`ReadWritePaths` 只有状态与日志根目录）。
2. **Shell / systemd 部署同样没有 `configs/data`。** `render_deploy.go` `renderShellInstall` 只把二进制与 `config.yaml` 装进 release 目录，unit 的 `WorkingDirectory=$APP_ROOT`，
   相对的 `config_data.dir` 解析为 `$APP_ROOT/configs/data`，没人安装它；按源码推断，用 configdata 的服务按生成脚本安装后启动即失败（未实跑）。本问题的范围是镜像 / compose / k8s，没有顺手改。
3. **game-demo 的 `config.game.prod.example.yaml`（及 k8s Secret 示例）缺少 `game_route` / `activity` / `platform` 段。** demo 只把它们追加进开发配置；
   `internal/service/game/service.go:123` `NewPlayerOwners` 在 Init 里要求 `game_route.key_prefix` 非空（`activity.key_prefix` 同样必需），按生产示例起 game 会在 Init 失败（按源码推断；演练时已补齐，未单独实跑失败形态）。
