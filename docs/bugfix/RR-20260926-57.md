# RR-20260926-57 修复：生成 GetOrCreate 对 ErrEntityRemoved 有界重试；删除 flush.go 被遮蔽的死分支并更正 RR-35 记录

问题：[RR-20260926-57](../bug/RR-20260926-57.md)（探针见 [REPRO-2026-09-26-05 §1 探针 C](../bug/REPRO-2026-09-26-05.md)）。
日期 2026-09-26；实施基线本地 main `3e26f91`，建立在同批 RR-48（`49f99e0`）、RR-49（`c162b93`）、RR-53（`a43227b`）之上。
状态：已修复、本地验证通过，已本地提交，未推送 / 未发布。方向按维护者批准的修复约束：GetOrCreate 对 `ErrEntityRemoved` 有界重试
（再 Get / 再 Create）；删除死分支并更正 RR-35 修复记录中的负对照描述。

## 根因

- `codegen/internal/roost/add_workflow.go` 生成的 `<Entity>Lifecycle.GetOrCreate` 只把 `ErrEntityExists` 转为再 `Get`。同 ID 的上一个实例
  正在撤销（RR-35 的事务内创建被回滚 / 拒绝）或销毁收尾时，`EntityManager.TryAdd` 看到 `removing` 标记返回 `ErrEntityRemoved`：索引已摘除、
  锁已释放，只差收尾回调结束。这是瞬时状态，GetOrCreate 把它当业务错误原样返回（探针 C：200 次中 103 次）。
- `sync/entitysync/flush.go` 的 `errors.Is(err, entity.ErrSubjectSyncClosed) && subj.retiring` 分支排在 RR-30 的
  `errors.Is(err, entity.ErrSubjectSyncClosed)` 之后，`switch` 永远先命中前者，是死代码。两条分支动作相同（不计失败、不重试），
  删除不改变行为。

## 决策与实现

- 模板（`add_workflow.go`）：`GetOrCreate` 改为最多 3 轮（首轮 + 两次重试）的循环，每轮 `Get` → 未找到才 `Create`；`ErrEntityExists`
  照旧再 `Get` 返回；`ErrEntityRemoved` 且未到上限时进入下一轮；其余错误与上限后的 `ErrEntityRemoved` 原样返回。上限写成字面量：
  同一 lifecycle 包里每个 Entity 各一个文件，包级常量会重复声明。不加 sleep：GetOrCreate 也可能在 Nest handler 内（快 worker）调用，
  快池不得等待；撤销收尾在持有者释放锁后立即执行，一次重试通常足够，重试用尽说明收尾异常，交给调用方。
- 生成工程文档（`render_workflow_docs.go` 的 lifecycle 方法语义）补一句重试语义。
- 与 RR-48 的关系：handler 内 `Create` 在 TryAdd 失败时归还本次取得的锁（RR-48 的修复），所以同一 Guard 作用域里重试新建的实例会重新取锁，
  不会以“已持有”的旧记录在未加锁时发布。handler 内对被占用 ID 的新建按 RR-48 返回锁超时并整条重排，重试只处理锁已释放、收尾未完的窗口。
- `flush.go`：删除死分支，把“已退役 subject 在捕获期间关闭状态”的说明并入 RR-30 分支的注释。
- `nest/lifecycle_create_commit_boundary_promises_test.go` 的 `generatedShapeLifecycle.GetOrCreate` 同步为新模板形状（fixture 与生成物逐行同形）；
  `codegen/internal/roost/roost_test.go` 对生成的 `game/lifecycle/player.go` 增加重试片段断言。
- RR-35 修复记录末尾追加“更正”：原负对照是在 RR-35 的实施基线 `49f20ee`（flush.go 尚无 RR-30 分支）上做的，合并后不成立。

## 兼容性

- 生成的 GetOrCreate：撤销 / 销毁收尾窗口内不再返回 `ErrEntityRemoved`，而是重试后创建成功；3 轮仍被挡住时才返回它。已生成的工程需要
  重新运行生成器才能获得新形状（lifecycle 文件是生成物）。签名不变。
- flush.go 行为不变。

## 对抗性自查

- **快池不阻塞**：重试不 sleep、不等待，最多 3 轮内存查找与构造；handler 内的锁冲突仍按 RR-48 try-lock。
- **重试不越过事务边界**：每轮都是完整的 Get → Create；handler 内的新建仍经 RR-35 的捕获 / 撤销，发布失败时锁已归还（RR-48）。
- **RR-35 撤销发布**：撤销流程未改；重试只在 `removing` 标记存在时发生，收尾完成后同 ID 才能再建，remove-before-create 语义保持。
- **同 ID 顺序 / 内部续行**：不涉及派发队列。

## 未验证项

- 已生成的外部工程不会自动获得新模板，需重新生成。
- 撤销收尾里的业务 `OnDestroy` 若很慢，3 轮重试可能仍看到 `ErrEntityRemoved`；这种情况返回给调用方。
