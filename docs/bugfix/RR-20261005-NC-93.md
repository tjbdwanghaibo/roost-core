# NC-93 修复：正常 Resign 改走 election 持有的有界撤销，按调用方期限返回

[问题](../bug/RR-20261005-NC-93.md) · [证据](evidence/noncore-bugfix-20261005-n03/README.md) · [本轮](../review/REVIEW-2026-10-05-noncore-n03.md)。已修复、声明场景验证（含真实 etcd），未发版。

## 根因

基线 `etcd/driver/election.go:301-317` 的 `Resign` 在 `elect.Resign(ctx)` 之后调用 SDK `Session.Close`（经 `campaignSession.Close`）。SDK 用 session 自己的 context 加 TTL 秒（默认 60s）发 Revoke（etcd client v3.7.1 `concurrency/session.go:108-115`），调用方 ctx 管不到。

## 修法

`Resign` 改用 RR-20261004-06 为失败竞选写的 `abandon`：同步 `Orphan()` 停 keepalive，Revoke 由 election 持有、用 `cli.Ctx()` 派生并带 5s 截止；调用方在等就等它并拿到 Revoke 的结果，ctx 先到就立即返回 ctx 错误；下一次 Campaign 等这次 Revoke 结束。`abandon` 为此改为返回结果（Revoke 错误、ctx 错误，或 session 已被关闭时的关闭错误），失败竞选的调用点忽略返回值、行为不变。测试替身那种没有 lease 句柄的 session 仍回退到 `Close()`。

这样正常 Resign 与失败放弃只剩一条撤销路径，`campaignSession.Close` 只在测试替身回退里使用。

未采用：把调用方 ctx 直接传给 SDK——`Session.Close` 不接受 ctx；自己包一层 goroutine 等 `Close` 会留下一个最长 TTL 的后台调用，且下一次 Campaign 无从等待它。

## 兼容与边界

- `Resign(ctx)` 现在可能返回 `context.DeadlineExceeded` / `Canceled`（修前会一直等）。此时本地领导权已结束（`IsLeader=false`、`LeaderChan` 关闭）；`elect.Resign` 若已成功，领导键已删除；Revoke 失败或超出 5s 时 lease 在 TTL 后过期。
- 健康 etcd 上 Background ctx 的 Resign：Revoke 截止从 SDK 的 TTL（60s）变为 5s，超过时返回该超时错误（lease 随 TTL 回收）。
- 仓内没有生产调用方（`71c6fb6b` 起 kit 不再发布选举工厂）；USER_GUIDE 选主段落同步改写。
