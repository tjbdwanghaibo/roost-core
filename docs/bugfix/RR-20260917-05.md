# RR-20260917-05：嵌套 DAO 的第二层变更不通知父级（U-0232）

- 仓库：roost-codegen `internal/dao`
- 缺陷类：C2（脏传播）
- 优先级：P2；来源 Wanted-02 转入
- 相关：T-126；测试 `internal/dao/testdata/runtime/roundtrip_test.go`（经 `scripts/dao-golden-runtime.sh`）

## 问题

DAO 会把**自己的**嵌套字段接到 `markXDirty`（`template_dao.go`），但一个嵌套结构**内部**的嵌套
（`EquipInfo` 的 `gems map[int32]*GemInfo`）从来不 `SetNotify`。于是业务

```go
gem, _ := equip.GetGems(1)
gem.SetLevel(99)
```

改到了 child，`EquipInfo` 不脏，DAO 顶层也拿不到补丁——内存里变了，落库时不在 patch 里，
回滚快照与同步同样看不见。

## 根因

`template_nested.go` 里三个装载入口（公开 setter `SetGems`、raw 恢复 `setGemsRawMap`、BSON 恢复 `setBSONDoc`）
都只是把值放进容器，没有任何一处把 child 的 `DirtyHook` 接到父级的 `Mark`。U-0224 修的是"嵌套值有没有 BSON 表示"，
是另一个契约；两者互不否定。

## 方案

- 采用：**三个入口统一接线**，并在替换时解绑旧 child。
  - `setXRawMap` / `setBSONDoc`：装载时 `val.SetNotify(s.Mark)`（恢复正是"加载出来的文档怎么拿到 children"的路径）。
  - `SetX`：先把**被替换掉**的旧值 `SetNotify(nil)`，再装新值并接线——一个已经脱离的 child 还在标记它不再属于的父级，
    是没人能解释的脏标记。
  - slice 与单个 struct 字段同形处理（指针元素才有 hook 可接）。
- 没采用：只在 getter 里懒接线。`GetGems` 是读路径，且 child 可能被业务持有后才改；接线必须在装载时完成。
- 没采用：让 child 持有父指针。那要给每个嵌套类型加字段并处理拷贝语义，`DirtyHook` 的回调已经够用。

## 改动

`internal/dao/template_nested.go` 三处 + 重生成 golden（`gen_equip_info_nested.go` 等）。

## 证明

修前（dao 运行时门，三个入口各一条）：

```
--- FAIL: TestNestedChildChangeMarksItsParentThroughEveryEntry
    bson round trip: changing a child gem did not mark its EquipInfo; the DAO cannot see the change
    raw restore: ...
    public setter: ...
```

修后：`sh scripts/dao-golden-runtime.sh` → `ok daogoldenruntime/gen`，另含"被替换的 child 不再标记旧父级"一条；
`go test ./internal/dao` 与全仓测试全绿。

## 未做 / 边界

- 只做到**两层**（DAO → 嵌套 → 嵌套的 child）。更深的层级按同一模板递归生成，但测试只覆盖两层。
- 没有处理"同一个 child 被多个父级共享"的所有权问题：`SetNotify` 是单个回调，后接线的赢。
  review 提到的这一点仍然开放，demo 与 fixture 都不共享 child。
- 通知只证明"父级被标脏"，**没有**端到端证明补丁进了真实 Mongo 事务（那需要真实驱动的提交路径）。
