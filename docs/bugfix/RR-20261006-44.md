# RR-20261006-44 修复：原生步骤消费者对坏信封 nak 到 MaxDeliver，与其余四个 saga 消费者及 SAGA.md 不一致

问题：[RR-20261006-44](../bug/RR-20261006-44.md)（F06-S2）。基线 `0b223b4c`（main，v1.23.0 之后；WIP `wip/sagafix` `bcdb4bd4` rebase 到此）。codebase-memory 共享 generation 停在 09-30（比基线旧），定位与结论按 worktree 当前源码读取。
同一批（sagafix2）修 RR-20261006-42～47，一笔提交 `SHAFIX`。

## 根因

`saga/command_consumer.go` `SubscribeDataEngineStep` 回调里 `decodeStepCommand` 失败时 `return err`（基线 `:411-414`）；五个消费者各自处理坏信封，没有一处统一的口径。

## 决策

- **统一口径**：新 `rejectEnvelope(consumer, err)`（`saga/nest_start_consumer.go`）：计 `saga.consumer.rejected_total{consumer}`（`mongo_step` / `native_step` / `result` / `native_result` / `start`），返回 `Permanent`（Term）；ERROR 由各自的 `logConsumerError` 记。五个消费者的坏信封路径都经它。
- 普通结果流的解码拆成 `decodeCompletionMessage`，Mongo 步骤消费者改用与原生相同的 `decodeStepCommand`，两边判定一致。
- **未采用**：保留 nak 等人工修消息——坏信封重投永远不会变好，nak 只占名额。
