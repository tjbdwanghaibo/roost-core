# RR-20261004-NC-14：Layered 不交付准入拒绝的回填

2026-10-04，基线`1502f973`。**已修复、声明场景验证、尚未发版。** [原问题](../bug/REVIEW-2026-10-04-noncore-10.md#rr-20261004-nc-14) · [本轮](../review/REVIEW-2026-10-04-noncore-11.md) · [证据](evidence/noncore-bugfix-20261004-06/README.md)。

## 根因与实现

[layered.go](../../cache/layered.go) 的Get把一致性拒绝当普通回填可用性故障，仍交付已捕获的L2值；stale还续expiry。本轮区分ErrStaleWrite/ErrConflictingWrite，读回L1已准入值；stale且L1 miss保持miss，conflict且miss返回拒绝错误。读回失败合并准入与读取原因，返回零值/false，不泄漏captured。拒绝不续TTL，conflict指标仍计数；普通L1故障继续计指标并返回L2值。

复用现有Store/expiry与errors.Is，没有版本旁表、墓碑生成或线性化协议。不以“任何L1故障都导致读取失败”代替准入修复；没有改变合法TTL缓存与TTL<=0重查。

## 红绿与消费者

原门闩三项修前失败：stale/conflict返回captured，tombstone返回被删除值。修后返回published/published/miss。补充wrapped stale/conflict+读回失败、conflict+miss、普通outage四项通过，两个错误都能errors.Is提取。

共同41正式项、五包race/vet通过。正式`codegen/cmd/dao`生成Raw DAO到独立业务module，NewCachedRecordRedisDAO读remote v4而local已持v5时交付v5；消费者race/vet通过。此生成控制不代表所有ref-hmap Patch消费者通过，另见[新审查](../review/REVIEW-2026-10-04-noncore-12.md)。

## 边界

行为收紧仅针对L1明确准入拒绝；API/存储格式未变。L1必须实现相应准入，不把其未提供的Conflict/Superseded能力凭空补出来。没有承诺全部并发Get/Set线性化，也没有修复expiry高基数容量观察；吞吐、真实并发Redis CAS、Cluster/HA与长稳未执行。

## 复核后的补修（2026-10-04，A 线）

独立复审（[REVIEW-2026-10-04-nc-audit-3 §3 D1](../review/REVIEW-2026-10-04-nc-audit-3.md)）发现：本修复“回填遇 `ErrStaleWrite` 一律读回 L1”没有区分 L1 副本是否仍在 TTL 窗口内，与 NC-15 叠加后，过期副本（或 ttl≤0 下的任何副本）会永久否决权威值，登记为 [RR-20261004-02](../bug/RR-20261004-02.md)。补修见 [bugfix/RR-20261004-02](RR-20261004-02.md)：只有 `localValid` 为真才按本修复读回 L1，窗口外先删 L1 再回填。本修复的三条红用例 `TestCacheAdmissionBackfillAdmission/layered/{stale,conflict,tombstone}` 未改、仍绿；补充用例 `TestCacheAdmissionLayeredRejectedReadFailures/stale_read_error` 改到有效窗口内（原在 ttl=0 下钉住了 D1 行为）。
