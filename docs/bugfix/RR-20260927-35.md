# RR-20260927-35：demo 模板测试改用 kit 导出的流名解析 `kitsyncbus.JetStreamStreamFromConfig`

> 2026-10-08 当前边界：后续 A4 配置声明已移除旧段 fallback；现行只读 syncbus。本文保留当时 configuredPrefix 修法的历史证据。

问题：[RR-20260927-35](../bug/RR-20260927-35.md)（OPEN-ITEMS 批次 7 B32 升级演练发现）。日期 2026-09-27。基线 `e0d38f7`，分支 `fix-r8-b14`。
状态：已修复，本地验证通过，本地提交，未推送 / 发布。codebase-memory 图谱过期（09-26），本轮以当前源码为准。

## 根因

`demo/internal/service/game/syncbus_config_test.go.tmpl:46-48`（基线行号）在测试里自己推期望流名：未写 `syncbus.stream` 时用
`syncbusdriver.JetStreamSyncStream(cfg.GetString("syncbus.prefix"))`。kit 的真实规则在 `kit/syncbus/mod.go` `jetStreamStream`：未写 prefix 时缺省 `roost.room`，
并且 `roost.room` 兼容映射到 `ROOST_SYNC`（RR-20260926-56，保持已部署的流与游标）。driver 函数只认 `roost.sync` / 空串，于是按迁移说明保留 `prefix: roost.room`
的工程，测试期望 `ROOST_ROOM`、Mod 实际用 `ROOST_SYNC`，误报失败。新生成的工程写的是 `roost.sync`，不受影响。

## 决策（按修复约束）

- kit 导出 `kitsyncbus.JetStreamStreamFromConfig(cfg *viper.Viper) string`：与 `Init` 同一规则（`syncbus` / `room` / `sync` 三段的键优先级、缺省 prefix `roost.room`、
  `roost.room` → `ROOST_SYNC`、显式 `stream` 优先）。`Init` 与它共用抽出的 `configuredPrefix`，规则只有一份，不会再有第二处实现漂移。只读 cfg，不校验 transport。
- 模板测试：
  - `TestTheConfiguredSyncBusTransportIsTheOneThatStarts` 的期望流名改为调用这个函数；原来“`roost.sync` 必须仍是 `ROOST_SYNC`”的独立检查扩到 `roost.room`。
  - 新增 `TestTheSyncBusStreamFollowsThePrefixRules`：同一份生成配置分别把 prefix 换成 `roost.room`、`roost.sync`、`zz35.sync`，
    对照写死的 `ROOST_SYNC` / `ROOST_SYNC` / `ZZ35_SYNC`，既查函数返回值也查真实 Mod 启动日志里的流名；工程若显式写了 `syncbus.stream` 则跳过（prefix 不再决定流名）。
  - 启动 Mod、解析启动日志的逻辑抽成同文件的 `startSyncBusMod`，两个用例共用。
- kit 单测 `kit/syncbus/stream_name_test.go` 的表驱动用例（生成默认 `roost.sync`、未写 prefix、写出 `roost.room`、隔离 prefix、显式 stream、旧 `room:` 段）
  逐条断言 `JetStreamStreamFromConfig` 与 Mod 实际确保的流一致。

## 文件

- `kit/syncbus/mod.go`：`configuredPrefix`、`JetStreamStreamFromConfig`（中文 godoc 写明规则、之前为什么错、编号）；`Init` 改为调用 `configuredPrefix`，行为不变。
- `kit/syncbus/stream_name_test.go`：`TestSyncBusStreamIsDerivedFromThePrefix` 每个用例加一条断言。
- `demo/internal/service/game/syncbus_config_test.go.tmpl`：见上；不再 import `sync/syncbus/driver`。
- `kit/README.md`：JetStream 流名一段加一句：测试或工具要算流名用这个函数。

## 兼容性

- 新 API 只增不改；`driver.JetStreamSyncStream` 保留，语义不变。
- **已生成工程的测试文件不会经 sync 更新**：`internal/service/game/syncbus_config_test.go` 是 demo 脚手架“生成一次”的业务文件（`codegen/internal/roost/demo.go` 的 `write:` 步骤），
  `project sync` / `upgrade` 不改写它。实测：基线生成器建的旧工程执行新生成器 `project sync` 后，这个文件保持旧内容（与新生成工程不同），旧测试仍能编译、在默认 `roost.sync` 下通过。
  从旧版升级并保留 `prefix: roost.room` 的工程需要手工把新模板的这个文件拷过去（或把期望流名改成调用 `kitsyncbus.JetStreamStreamFromConfig`）。
