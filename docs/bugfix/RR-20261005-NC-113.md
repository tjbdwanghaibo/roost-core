# NC-113 修复：Combatant 进出组件边界都复制 map

[问题](../bug/RR-20261005-NC-113.md) · [本轮](../review/REVIEW-2026-10-05-n09-batch1.md)。已修复、声明场景验证，未发版。

## 根因与修法

`combat.Combatant` 唯一的引用类型字段是 `ElementMultipliersBP`；`Combatant()` 的值拷贝与 `InitCombatant` 的直接赋值都共享它。`skill/combatcomponent/component.go` 新增 `cloneCombatant`，`Combatant()` 返回它的结果、`InitCombatant` 存它的结果。DAO 自身从不原地改这张 map，所以只要进出边界的值都各自持有 map，存储的 map 就不可变，`undoVitals` 的浅拷贝 `before` 仍然精确。

未采用：把 map 换成有序切片——会改 `combat` 包的公开类型与持久化格式，需要迁移。

## 兼容

公开 API、BSON / JSON 格式不变。每次 `Combatant()` 多一次小 map 分配（map 为 nil 时没有）；依赖“改副本就能改实体”的调用方（误用）不再生效，应改用 `InitCombatant`。

## 验证

- 修前：`TestCombatantCopiesDoNotShareElementMultipliers` 两条断言红（原文见问题记录）。
- 修后：`GOWORK=off go test -race -count=3 ./skill/combatcomponent` 通过；本轮 4 种 Nest 回滚组合探针在修前已通过，修后由既有 `TestNestUndoRollbackRestoresCombatStateExactly` 等覆盖。
