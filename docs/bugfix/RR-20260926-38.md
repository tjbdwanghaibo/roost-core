# RR-20260926-38：Durability 1/2 的 Remote 事务由投影器完成，finalizer 不再并发回源发布

问题：[RR-20260926-38](../bug/RR-20260926-38.md)（探针 [REPRO-2026-09-26-04](../bug/REPRO-2026-09-26-04.md) §6）。日期 2026-09-26。
实施基线：main `49f20ee` + RR-46 提交。状态：已修复，本地验证通过，已本地提交，未推送/发布。

## 根因（基线行号）

- `remoteentity/transaction_manager.go:235-262` `processDeferredRemoteClose`：Durability 1/2 与 0 一样，每轮先 `RemoteCommitStatus`；
  `transaction_tracking.go:192-215` 对 Admitted 也回源 Mongo（RR-19 为“拒绝可回源得到结论”加入）。投影器尚未完成时读到 Unknown → 隔离实体 + 退避重试；
  投影器 Mongo 事务提交后、发布完成前读到 Applied → 与投影器的 `ApplyRemoteCommits` 并发 `publishAppliedRemoteTransaction`。
- `acknowledgeRemoteCommit`（`:1012-1023`）先读 ownership 状态再转换，两个发布者交错时后到者拿着过期的 Quarantined 做
  `Quarantined→Recovering`，报 `invalid ownership transition: local_owned -> recovering`（投影失败 +1），或 finalizer 失败后把已确认实体重新隔离、继续占 gate 重试。
- Committed 分支 `reconcileRemoteEntries` 对本进程刚发布过的事务再走一遍 `afterRemoteCommit`，快照每笔发布两次。
- 附带代价：finalizer 首轮读到 Unknown 后按 `FinalizeRetryInterval`（默认 500ms）退避，投影器早已完成时 gate/写额度仍要等到下一轮才释放，
  同实体连续 async 写被限制在约 2 笔/秒。

## 决策（维护者批准的修复约束）

1. **Durability 1/2 由投影器负责完成**：finalizer 对 durability≠0 的延迟收尾只读本进程 tracker；投影器写入 Committed / Rejected（持久结论）或
   Indeterminate（发布失败＝“报告未知”）之前，收尾项挂在 tracker 的 `done` 上等待（`awaitRemoteProjection`：不占 finalizer worker、不回源、不隔离、不发布）。
   `done` 关闭或 `FinalizeProjectionTimeout`（新配置，默认 30s，kit 键 `remote_entity.finalize_projection_timeout`）到期后才进入原有回源流程。
   RR-19 的“拒绝可回源得到结论”保持：投影器报告未知、停滞或 DataEngine fence 时，超期回源仍能拿到 Applied / Rejected。Durability 0 没有 WAL，行为不变。
2. **ack 幂等**：`acknowledgeRemoteCommit` 解冻（Quarantined→Recovering→LocalOwned/Shared）失败时，若实体版本向量**等于**本提交且状态已是
   LocalOwned/Shared，说明同一事务已被另一发布者确认并解冻，视为成功返回（`remoteCommitAlreadyAcknowledged`）。只接受“已解冻”的事实，从不自行解冻；
   向量不等（例如更新的 fence）仍走原有错误 / obsolete 判定（RR-11 不变）。未采用按 txID single-flight：投影器停在 ack 时它会让回源兜底的 finalizer
   阻塞在同一把锁上，而超期回源本来就是投影器失联时的兜底；幂等 ack 已消除两个发布者交错的所有权冲突。
3. **不重复发布**：tracker 增加 `published`，只在本进程完成快照发布与 `MarkRemoteCommitPublished` 后写 Committed 时置位
   （`completePublishedRemoteTransaction`：投影器 `ApplyRemoteCommits` 与 finalizer/outbox 的 `publishAppliedRemoteTransaction`）。finalizer 的 Committed 收尾在
   `published` 时只做回执校验 + 本地 ack + 版本唤醒；Committed 来自回源（本进程没发布过）时仍完整发布（与旧行为一致，保证至少一次发布）。
4. 观察缝：`remoteState.finalizeTrace`（生产为 nil）在每步收尾后报告 `released / retry / await_projection / abandoned`，回归据此按事件顺序同步，不参与决策。
   停机排空统一走 `abandonDeferredRemoteClose`（隔离 + 交还 gate/fence/写额度），与旧行为一致。

## 兼容性

- 行为变化：Durability 1/2 延迟收尾期间实体不再被 finalizer 隔离（gate 仍由收尾项独占，其他写者照旧排队）；投影完成即释放 gate，不再等 `FinalizeRetryInterval`。
  投影器超过 `FinalizeProjectionTimeout` 仍无结论时才回源（旧实现立即回源）。
- 同一事务不再重复发布快照（本进程已发布时）；Committed 来自回源时仍发布。
- 新配置项有默认值，无需迁移；持久格式不变。

## 未验证项与边界

- 没有在真实 Mongo / 正式生成工程上做吞吐对照（生成链路 `scripts/test-remote-generated.sh` 只做功能验证，见 RR-37 记录）。
- 两个发布者同时处于解冻中途（一方已 `Quarantined→Recovering`、另一方读到过期 Quarantined）时，后者仍会报错：投影器按原退避重试、finalizer 隔离后下一轮
  读到 Committed 再确认解冻，最终收敛；本轮未构造该极窄窗口。
- `FinalizeProjectionTimeout` 内投影器进程级停滞（DataEngine fence）期间，gate 与写额度保持占用，直到超期回源（旧实现立即回源，但同样拿不到结论）。
