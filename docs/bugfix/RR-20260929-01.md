# RR-20260929-01：platform 迟到发货与人工结算

状态：已实施并通过本轮定向回归，未发版。源码基线 `f46db3e7d504bbd73581aa4119baa71171352519`。

根因：计时 backoff 耗尽不等于外部调用已停止；旧成功回包无条件写 delivered。

实现：Order 持久化单调 AttemptSequence 和 PendingAttempts；结算/重开拒绝未知在途结果，回包按 attempt 身份归档。增加 owner-only ResolvePendingAttempts，只有人工确认全部外部请求已停止并对账后才清理未知项。

改动：kit/service/platform/service.go、admin.go、types.go。

回归：`TestReviewSettledOrderSurvivesLateDelivery；TestReconciledSettlementRejectsStaleDeliveryCompletion`。修前证据保留在 [第一轮](../bug/REPRO-2026-09-29-services.md) / [第二轮](../bug/REPRO-2026-09-29-services-02.md)；RR-09 修前是源码接线缺口，其他项有动态 FAIL。正式行为回归位于对应包，含 race；排行及 session ABA 使用隔离真实 Redis。统一命令、实际计数与未测边界见 [本轮总记录](SERVICE-BUGFIX-2026-09-29.md)。

兼容与边界：升级前须排空旧版本外部调用；旧订单没有 PendingAttempts，不能凭零值证明没有在途请求。人工接口不暴露 bus；未知实际发货仍需外部幂等和对账。
