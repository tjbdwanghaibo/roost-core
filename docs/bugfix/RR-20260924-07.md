# RR-20260924-07 修复：准入后释放失败仍完成持久化责任

[问题与修前证据](../bug/RR-20260924-07.md)。已修复，未提交、未发布。

- `releaseAfterAdmission` 仅在 pipelined 成功准入后将释放 panic 转成错误；原闭包仍负责 defer 清理剩余 Guard 锁。业务失败的回滚逻辑不进入这个恢复边界。
- `completionHandoff.releaseErr` 在关闭解锁屏障前写入，完成方在屏障后读取；与 ticket 或回调错误合并回复。队列满继续在当前 worker 完成，不能因释放失败丢掉 complete。
- 普通路由的幂等释放使用 `sync.Once.Do`，保留首次异常，防止兜底 defer 重放已处理的 panic。
- 新增 `ErrEntityReleaseFailed`，保留原 panic 为 error 时的 errors.Is 链。它代表准入后释放失败；同时出现 `ErrCommitIndeterminate` 时仍按不确定提交 fencing，不能据释放错误重试整笔业务。

同一回归覆盖 inline / queued / saturated × durable / indeterminate 六个子用例，校验单次回复、错误链、回调和通知、fencing、锁与排序链释放、已准入状态不回滚。原 durable 三个子用例已实际证明修前失败；新增 indeterminate 三个子用例是修后补充边界验证，不冒充修前红证据。

相关包 race、vet、全仓编译及真实生成工程结果见 [Nest 截止复核](../feature/NEST-COMPLETION-2026-09-24.md#8-截止复核与收口结论)。不改变 strict / memory 的 Guard post-release 策略，也不改变 Sync 发送模式。
