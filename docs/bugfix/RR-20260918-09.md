# RR-20260918-09：运行期实体的 id 由进程本地计数器发号，多实例碰撞

- 单元：U-0242 · 缺陷类 C4（跨层契约不一致）· 等级 P1
- 仓库：roost-codegen `demo/`
- 排障行：T-136

## 问题

`spawner` 从常量 `monsterUniqueIDBase` 开始本地自增。两个 game 进程第一次发号都得到 900001，
而 demo 的 room subject、spatial subject 与 Nest/Entity 寻址都把完整 entity id 当**全局身份**——
撞了之后不同实体共用订阅、路由与状态槽。

## 根因

运行期创建的实体没有分配器：玩家 id 由 account 服务的 Redis 块分配器发，而怪物是进程自己造的，
于是"随便找个基数自增"看起来够用——单进程确实够用，而这正是 demo 其余部分一直在拆掉的假设。

## 方案选择

- **（选中）把进程身份编进 id**，用框架自己的位布局：`unique id (52) = [静态半区 (1)][shard (16)][序列 (34)]`。
  `entity.StaticUniqueIDBase` 标记 unique 区间的上半，框架**明确保留**给显式指定的 id（下半是块分配器发的），
  运行期 id 正属于前者，因此与任何玩家 id 都不可能撞。shard 取进程的 sid——稳定、每部署唯一、
  demo 其余部分本来就以它为键。
- 每只怪跨网络 INCR：热路径上一次跨服务调用，审查也点名不要。
- 按段租赁 Redis 号段：正确且可扩展，但要引入一个新的持久组件；等真有跨进程持久实体时再说。

## 改动

roost-codegen `demo/game/runtimeid/runtimeid.go`（新）：`New(sid)` / `Next()` / `Shard(uniqueID)`。
两条判据在**启动时**校验而不是第一次刷怪时：sid 必须能编码（1..65535），序列耗尽**报错而不是回绕**——
回绕会重新发出仍在使用的 id，正是这个包要防的碰撞从另一个方向到达。
`spawner` 改用它，sid 从进程配置 (`fctx.RuntimeConfig()` 的 `sid`) 读。

## 证明

`demo/game/runtimeid/runtimeid_test.go`（随工程生成）五条：两个 shard 各发 1024 个 id 无重复；
同一 sid 重启会重用序列（**这条安全只因为运行期实体本来就不跨重启存活**，写成测试是为了让这个假设可见）；
id 落在静态半区且仍在 52 位内；无法编码的 sid 在 `New` 就被拒；序列耗尽被拒。
修前：审查独立复现两个 spawner 首次 `mintID` 均得 900001。

## 未做 / 边界

- **sid 的唯一性没有被验证**，只被编码：两个进程配同一个 sid 仍会撞。这与 demo 其余部分的假设一致
  （account 也按 sid 注册服务器），但它是个前提而不是保证。
- 34 位序列是**每进程生命周期**的，不跨重启续接；对 `noPersist` 的实体正确，对将来要持久化的运行期实体不正确。
- 没有做审查提的"边界溢出拒绝"的端到端场景（只在单元层面测了 `Next` 的拒绝）。
