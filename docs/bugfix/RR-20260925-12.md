# RR-20260925-12 修复：现有对象全量替换走更新调度

[问题与修前证据](../bug/RR-20260925-12.md)。日期：2026-09-25，随本轮 Sync 收尾提交，未部署。

以本次不可变 session 引用表判断客户端是否持有对象：

- 数量预选只为缺少引用的冷快照分配额度，现有对象刷新不挤占它们的名额。
- Flush 在当前会话身份核验后选中现有对象全量刷新；数量额度耗尽的空选择也不拦截它。
- 准入跳过现有引用的 Full 更新，不扣新对象的对象/字节/每会话额度。

保留 Full 字段替换、授权 Profile、实体锁内捕获、提交确认、会话身份与逐帧采纳。
Hold/Ready 重置后引用表为空，恢复仍限流；不会为新对象发送无基线 delta。
这是调度语义修复，不改线协议，不增加包和配置项。全量更新可能超过恢复额度，实际
帧硬上限、冻结内存和 AsyncTransport 容量继续约束它；恢复额度不再解释成所有 Full 的限额。

修前定向三个场景均失败；修后 `go test -race ./sync/... ./entity ./nest ./scripts/perf/sync-aoi`
11 包通过，`go test -race ./sync/entitysync -run TestExistingObjectRefresh -count=10` 通过。
回归包含周期模式的冷额度独立性及 Hold/Ready 重置。相同范围 go vet、glsvet，以及
`GOCACHE=/tmp/roost-nest-go-cache bash scripts/test-sync-modes-generated.sh` 正式生成工程通过。
验收日志位于 `artifacts/perf/sync/refresh-budget-20260925/`。

追加关闭诊断的 1%/5% 集中恢复各两轮，1% 最大 42.475 / 47.057ms，5% 最大
54.283 / 47.512ms；后一组第一轮仍有 10 个变化延迟超过 50ms。全部已记录超标均为
冷对象创建，现有对象刷新未再出现旧诊断中的数百毫秒等待。严格门禁未放宽，失败记录保留。
