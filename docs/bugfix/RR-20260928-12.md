# RR-20260928-12：切换 release 时先按当前 unit 停机，再装入目标 unit 启动

问题：[RR-20260928-12](../bug/RR-20260928-12.md)（第八轮独立审计，P4 推断，RR-20260928-10 引入）。日期 2026-09-28。基线 `3a58811`，分支 `fix-r11-b21`。
状态：**已修复**，临时根演练回归修前红、修后绿，本地提交，未推送 / 发布。仍是对 systemd 语义的建模（daemon-reload 之后的 stop 用新装载 unit 的 `TimeoutStopSec`），未在真 systemd 上验证。codebase-memory 图谱过期（09-26），本轮以当前源码、`rg` 与实跑为准。同一提交顺带处理审计疑点 D4（rollback.sh 版本号拒绝 `.` / `..`）。

## 根因

`codegen/internal/roost/render_deploy.go`（基线行号）：

- install.sh `:199` `use_unit "$RELEASE_ROOT"`（装入新 unit 并 `daemon-reload`）之后 `:201` `systemctl restart`；失败路径 `:209` `use_unit "$PREVIOUS" || true` 之后 `:210` `systemctl restart`。
- rollback.sh `:370` `use_unit "$TARGET"` 之后 `:371` `systemctl restart`；目标 readiness 失败 `:388` / `:389` 同样。

`restart` 里的 stop 发生在 reload 之后，用的是刚装载的**目标** unit 的 `TimeoutStopSec`；正在运行的进程是按另一个 release 的 Mod 算出的停机预算（RR-20260926-66）启动的。rollback.sh 回到预算更短的旧版本时，新版本进程按旧预算被停，超时 SIGKILL。另外 rollback.sh `:370` 在 `current` 已切换之后，没有兜底；set -e 下 install / `daemon-reload` 失败就退出，留下 `current` 已切、unit 与进程都没换。install.sh `:199` 同样如此。

D4：rollback.sh `:355` 的版本号校验接受 `.` / `..`。`TARGET=$APP_ROOT/releases/..` 是 `$APP_ROOT` 本身，脚本会把 `current` 指过去，然后才因 readiness 失败恢复。

## 修复

两个脚本都按 **stop（当前装载的 unit）→ 切 `current` → `use_unit` → start** 的顺序切换，停机窗口仍是一次 stop 到一次 start（切 `current` 与装 unit 只是本地文件操作）：

- install.sh：`[ ! -f "$UNIT_PATH" ] || systemctl stop`，首次安装时没有 unit，不 stop。这一步失败时，set -e 在切换之前退出：服务还在运行时 `start` 是空操作，吞掉 stop 失败会让旧进程冒充新版本通过 readiness。之后依次切 `current`、`use_unit` + `enable`、`start`。unit 装不上时打印 `failed to install the systemd unit ...; rolling back`；readiness 失败时照旧打印 `deployment health check failed ...; rolling back`。两种情况走同一条回滚路径：`systemctl stop`（此时装载的是目标 unit，停的是目标进程）→ 切回 `$PREVIOUS` → `use_unit "$PREVIOUS"`（失败时打印 `failed to restore the systemd unit of <v>`）→ `start` → readiness。首次安装失败仍是停服。
- rollback.sh：新增 `switch_current` 与 `restore_previous`（stop → 切回 → `use_unit "$PREVIOUS"` → start）。正向流程依次是 stop（有 unit 时）→ 切到 `$TARGET` → `use_unit "$TARGET"`；这一步失败时 `restore_previous`，打印 `failed to install the systemd unit of release <v>; restored previous release`，退出码 1。`start` 失败或 readiness 超时同样 `restore_previous`，打印 `rollback target failed readiness; restored previous release`，退出码 1。
- D4：rollback.sh 版本号校验加上 `.|..`，报 `invalid version`，退出码 2，在动任何东西之前拒绝。install.sh 的 `releases/.` 与 `releases/..` 必然已存在，会被“release already exists and is immutable”拒绝，所以不改。

没有做：`use_unit "$PREVIOUS"` 在恢复时也失败（`daemon-reload` 持续失败）时，仍会尝试启动上一个 release，并打印要求人工恢复的提示，与修前 `|| true` 的尽力而为一致。

## 文件与行为

- `codegen/internal/roost/render_deploy.go`：`renderShellInstall`、`renderShellRollback` 按上面的顺序改写；`renderShellUnitRecord` 的注释补上顺序及原因；生成的 `deploy/shell/README.md` 说明停机顺序、unit 装不上时的回退，以及版本号不能是 `.` / `..`。
- `codegen/internal/roost/shell_rollback_unit_promises_test.go`：共用的 systemctl 替身补上 `start`（服务运行中时是空操作）与 `stop` 记录。记录内容是被停进程所在目录、它启动时 unit 的 `TimeoutStopSec`、停机时已装载 unit 的 `TimeoutStopSec`；`restart` = stop + start。标记文件存在时，`daemon-reload` 失败一次，且什么也不装载。legacy unit 带 `TimeoutStopSec=7s`，与生成器给这份 Manifest 算出的 22s 不同。RR-10 回归不变，仍通过。
- `codegen/internal/roost/shell_rollback_stop_promises_test.go`（新）：
  - `TestShellReleaseSwitchStopsTheRunningProcessUnderItsOwnUnit`：依次跑 legacy v1 → install v2 → rollback.sh v1 → install 起不来的 v3（自动回滚）→ rollback.sh 到起不来的 v2（恢复）。每次停机都断言“停机时的 TimeoutStopSec = 该进程启动时的 TimeoutStopSec”，并核对被停的 release 序列。
  - `TestShellReleaseSwitchRestoresCurrentAndUnitWhenTheUnitCannotBeInstalled`：`daemon-reload` 失败一次时跑 rollback.sh v1 与 install.sh v3。断言非零退出，`current`、`$UNIT_PATH`、已装载 unit 都回到 v2 的记录，v2 重新在跑，且按自己的 unit 停机。
  - `TestShellRollbackRejectsDotVersions`（D4）：`.` / `..` 报 `invalid version`，`current` 不动。
- 使用说明：`docs/DEPLOYMENT.md` §4 与 `codegen/docs/PROJECT_GENERATOR.zh-CN.md` 部署入口表。

## 兼容性

install.sh / rollback.sh 与 `deploy/shell/README.md` 是 codegen 受控文件，`roost project sync` 即更新。service 配置与 unit 内容不变，`$APP_ROOT/units/` 记录格式不变。停机窗口不变（修前是 `restart`，现在是分开的 `stop` 与 `start`，中间只多了本地文件切换）。

## 未验证 / 风险

- 未在真 systemd 上验证“reload 之后 stop 用新 unit 的 TimeoutStopSec”，这是对 systemd 语义的建模，与审计探针的建模相同。修后的顺序不依赖这一点：stop 总是在 reload 之前。
- 替身里 `start` 在服务运行时是空操作，与 systemd 一致；真 systemd 下 `Restart=on-failure` 的崩溃重启循环会被 `stop` 终止，替身没有模拟这一点。
