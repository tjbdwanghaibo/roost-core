# RR-20260910-06:聚合注册的固定 entity 导入与业务包别名冲突

**仓库 / 位置**:roost-codegen `internal/registry/gen.go`,`importAliases` 的保留集。
**修复单元**:U-0167(C2)。**定位文档**:TROUBLESHOOTING T-61。
**引入来源**:M-05(聚合注册末尾调 `ValidateEntityRegistry`)本次新增的场景。

## 问题

某个注册函数来自包路径 `example.com/alias/entity`。`importAliases` 的保留集是
`{registry, sync, fmt, err}`,于是这个业务包被分配到别名 `entity`。生成物同时导入 core 的
entity 包和 `entity "example.com/alias/entity"`,消费者编译失败:
`entity redeclared in this block`、`undefined: entity.RegisterEntity`。

## 根因

M-05 让模板**无条件**导入 core 的 entity 包(末尾要调 `ValidateEntityRegistry`),但没有把这个
新的固定导入名加进别名分配器的保留集。保留集是手写的字面量清单,和模板的 import 块各自演进。

顺带说明为什么 `fmt` 与 `sync` 没出问题:它们本来就在保留集里,所以同名的业务包会被改名。
这恰好证明机制是对的,只是清单漏了一项。

## 方案选择

- 只加一个 `"entity"` 字面量。改动最小,但下次模板再加固定导入还会漏。
- **抽成一个具名清单 `aggregateReservedNames`(采用)**,注释写明它必须与模板的 import 块保持
  同步,并解释每一项为什么在里面(包名、stdlib 导入、错误检查里绑定的局部变量 `err`)。
  同样一行改动,但把"为什么"留在代码里。

## 改动

`internal/registry/gen.go`:新增 `aggregateReservedNames = []string{"registry","sync","fmt","err","entity"}`,
`importAliases` 从它初始化 `used`。

## 证明

`internal/registry/entity_alias_promises_test.go`:三个注册包分别以 `entity`、`fmt`、`sync`
结尾,生成后解析,断言 import 名互不重复、`entity` 这个名字确实指向 core 的包、`fmt` 与
`sync` 指向标准库,并且三个业务注册函数在各自别名下都仍被调用。

修前红:

```text
import name "entity" is used by both "github.com/tjbdwanghaibo/roost-core/entity"
and "example.com/alias/entity"; the consumer would fail to compile
the name entity resolves to "example.com/alias/entity", not the core package the template calls
```

修后 codegen 全仓测试绿。

## 未做 / 边界

- 只检查名字碰撞与指向,没有在测试里编译消费者模块,理由同 RR-20260910-05。
- `err` 留在清单里是对的:它不是 import,而是模板在错误检查里绑定的局部变量,一个叫 `err` 的
  别名会把它遮住。注释里写明了这一点,以免以后有人当成冗余项删掉。
