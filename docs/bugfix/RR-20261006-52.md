# RR-20261006-52 修复：启动步被拒的衍生物经 requestSpawnStop 停掉

问题：[RR-20261006-52](../bug/RR-20261006-52.md)（F08-R R2）。基线 `47abe511`，分支 `skspawn`，与 RR-20261006-51～55 同批；端到端用例与验证见 [RR-20261006-51 修复](RR-20261006-51.md)。

## 根因

`startEntitySpawn` 在启动步成功之后才 `spawns.add`，失败分支只 `detachMotionCarry`（基线 `skill/spawn_owned.go:43-53`）；Host 已因 Frame 等前几步登记了衍生物，Runtime 没有记录，不会停它。

## 决策

记录先入表、再跑启动步；启动步任一步失败时 `requestSpawnStop(cast, spawn, StopCauseFailure, "")`，停掉后 `drop`（`startEntitySpawn` 本来就是 `spawnDropSites` 登记的删除点），宿主拒绝停止时转入待停止、由 Runtime 重试，`Shutdown` 也停得到——与同一函数里 snapshot / area / 信号失败三条分支同一形状。`requestSpawnStop` 的 `terminateSpawn` 先解除 carry，原来单独的 `detachMotionCarry` 不再需要。`startEntitySpawn` 已在 `spawnStopEntries`（“failed spawn start”）登记，守卫不变。

未采用：只在 Frame 之后的失败上补一次 `StopSpawn`——绕过统一停止入口，宿主拒绝停止时又是没人管的残留。

## 文件与行为

`skill/spawn_owned.go` `startEntitySpawn`；用例 `TestRefusedMotionStartStepLeavesNoHostSpawn`（projectile / beam / orbit × trajectory / completion 被拒）。

## 兼容性

线上未部署。启动步失败时 Host 多收到一次 `StopSpawn`（Host 契约要求幂等，对没登记的 ID 是空操作），表现队列多一条 `spawn_stop`。
