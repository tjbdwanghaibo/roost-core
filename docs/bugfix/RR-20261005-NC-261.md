# NC-261 修复：Call 的发送与 Notify 同用 sendWithContext

问题：[RR-20261005-NC-261](../bug/RR-20261005-NC-261.md)。分支 `revleft`，基线 `dc877c04`，[本轮](../review/REVIEW-2026-10-06-revleft.md)，[证据](evidence/noncore-bugfix-20261006-revleft/README.md)。

## 修复

`call` 改用 `sendWithContext`：ctx 到期即返回 `ctx.Err()`、撤销 pending、直方图记 `timeout`（会话已关记 `closed`，其余发送错误记 `send_error`）。放弃等待的那次写在后台完成或随会话关闭失败；它若之后送达、服务端回了应答，按 NC-262 丢弃。

未采用：给 net.Conn 设写截止时间——写超时会留下半个帧，之后只能关会话，把一次调用超时放大成断线。代价：每次 Call 多一个短命 goroutine（与 Notify 一致；robot 是压测客户端，调用率受网络限制）。

文件：`robot/session/session.go`、`robot/session/session_promises_test.go`。

## 兼容

Call 在写阻塞时按 ctx 返回 `context.DeadlineExceeded` / `Canceled`，之前会一直等。
