# RR-20260926-46：已提交的 Remote 回复统一带 ErrAfterCommitFailed

问题：[RR-20260926-46](../bug/RR-20260926-46.md)（探针 [REPRO-2026-09-26-04](../bug/REPRO-2026-09-26-04.md) §11）。日期 2026-09-26。
实施基线：main `49f20ee`（v1.17.0 + RR-33～47 登记）。状态：已修复，本地验证通过，已本地提交，未推送/发布。

## 根因（基线行号）

- `nest/msg.go:98-108` `finishRemoteWriteBatch`：Commit 成功后 Close 的错误与 postRemoteCommit 回调错误原样 `errors.Join` 返回；
  `nest/nest_dispatch.go:75-77` 再包一层 `nest: finish remote write batch: %w`。回复里没有“已提交”的身份。
- 同一 `entity.ErrRemoteReleaseIncomplete` 也出现在 Abort 路径（`remoteentity/transaction_manager.go:458`），调用方无法区分已提交与未提交。
- 提交后 release hook panic（RR-32 场景）经 `runNestLogic` recover 成普通错误，同样没有哨兵。

## 决策

维护者批准沿用 `nest.ErrAfterCommitFailed`：

- `Msg` 增加 `remoteConfirmed`：只在 `finishRemoteWriteBatch` 的 `remoteCommitted` 分支 **Commit 成功**时置位（本地持久提交成功且 Remote 批次确认）。
- `dispatchNest` 收尾（Remote 收尾与预加载引用释放之后、回复之前）：`remoteConfirmed && err != nil && !errors.Is(err, ErrAfterCommitFailed)` 时
  `err = fmt.Errorf("%w: %w", ErrAfterCommitFailed, err)`。`%w` 双包装保留原因的 `errors.Is` 链（`ErrRemoteReleaseIncomplete`、hook 自身错误等）；
  已带哨兵的回调错误不重复包装。
- 未提交路径不置位：Abort（业务失败、准入失败）、Remote 确认结果未知（strict 等待超时、Durability 0 未知，Commit 返回错误）、明确拒绝。
  “结果未知”不是“已提交”，因此也不带哨兵（与 RR-37 的“超时/未知≠未提交”一致：调用方拿到的是 `ErrRemotePersistenceIndeterminate`）。

未采用：在 `finishRemoteWriteBatch` 内部只包装 Close/回调错误——提交后 release hook panic 来自 dispatch 错误而非收尾错误，会漏掉；在 remoteentity
另造“已提交释放失败”哨兵——批准的约束明确沿用 Nest 已有哨兵，业务只需判断一个错误。

## 文件与行为

- `nest/msg.go`：`remoteConfirmed` 字段与注释；Commit 成功时置位（`clean()` 随消息回收清零）。
- `nest/nest_dispatch.go`：回复前统一包装。
- 回归 `nest/remote_after_commit_sentinel_test.go`：
  - `TestRemoteReplyDistinguishesCommittedFromUncommitted`：已提交后 Close 失败 → 带哨兵且 `errors.Is(ErrRemoteReleaseIncomplete)`；业务失败后 Close 失败
    （Abort 路径）→ 不带哨兵、保留 `ErrRemoteReleaseIncomplete`；Remote 确认未知 → 不带哨兵、保留 `ErrRemotePersistenceIndeterminate`。
  - `TestRemoteReleaseHookPanicAfterCommitCarriesSentinel`：strict 持久提交后 release hook panic → 带哨兵且保留 hook 错误。

## 兼容性

- 行为变化：已提交的 Remote 请求若收尾失败，回复错误现在满足 `errors.Is(err, nest.ErrAfterCommitFailed)`；错误文本多一个前缀
  `nest: transaction committed but after-commit work failed: `。原因链不变。按错误文本匹配的调用方需要改为 `errors.Is`。
- 未提交与未知结果的回复不变。Nest 内部重排判断（`ErrLockTimeout` / `ErrEntityLockGroupChanged` 等）用 `errors.Is`，不受包装影响。
