# RR-20260926-55：退役完成后登记的正式入口；快速重连不丢 Join，会话打开的“稍后重试”有界退避

问题：[原始记录](../bug/RR-20260926-55.md)（复现 [REPRO-2026-09-26-05 §6](../bug/REPRO-2026-09-26-05.md)）。日期 2026-09-26。
实施基线：本地 main `3e26f91`（本轮 RR-52 修复之上）。状态：已修复，适用本地验证通过，已本地提交，未推送/发布。

## 根因（复核）

- 断线 settle 的 `Leave` 调 `Manager.Unregister`：仍持有该对象的观察者欠一个 ObjectRemove，subject 进入 retiring，要到下一次 Flush 把 remove 发出（或最后一个订阅者的会话关闭）
  才被 `forget`。同一 tick 里玩家立即重连，`Join` → `Register` → `rebind` 遇 retiring 返回 `ErrSubjectRetiring`，`Join` 直接报错，EnterGame 记
  “player did not join the replicated scene”——本次 Join 丢失，玩家直到下次登录都不在复制场景里。entitysync 没有“退役完成后再登记”的入口，调用方只能轮询。
- 传输实现 `SessionLifecycle`（如 `entitysync.AsyncTransport`）时，`OpenSession` 在旧 lifetime 仍在退出时返回 `ErrSessionClosing` / `ErrSessionOpening`（RR-15 补修的可重试哨兵）。
  demo scene 的重同步（`resyncLocked`）遇到它们只 Warn 后放弃；`Join` 打开会话遇到它们整个 Join 失败。

## 修复（按维护者批准的约束，正式 API 层优先）

1. **entitysync 正式入口**（`sync/entitysync/manager.go`、`subject.go`、`errors.go`）：
   - `(*Manager).RegisterAfterRetirement(state, done func(error)) (queued bool, err error)`：不在退役中时就是 `Register`（`queued=false`，done 不调用）；
     subject 正在退役时把 state 排在退役完成之后登记并返回 `queued=true`。`forget`（最后一个 remove 交付、或最后一个订阅者会话关闭）在同一步里以排队的
     state 调 `Register`，done 恰好报告一次结果。remove-before-create 不变：退役期间对它的订阅仍被拒绝（`ErrSubjectRetiring`），登记后的订阅以新对象（新 ObjectRef 代际）创建。
   - 有界与取消：每个 subject 至多一个排队登记（`subject.successor`），后到的替换先到的（被替换的 done 得到新哨兵 `ErrRegistrationCancelled`）；
     退役完成前再次 `Unregister`（玩家又离开）、排队的 state 已关闭 → `ErrRegistrationCancelled`；`Manager.Close` → `ErrManagerClosed`。
     `subject.forgotten` 标记 forget 已取走 successor，之后的排队改走 `Register`（循环至多 3 轮，不会无界自旋）。
   - done 在 Manager 自己的调用路径上执行（Flush / CloseSession / Unregister / Close），不持有 Manager 的锁，不得阻塞或调用 Flush——文档写明，调用方把工作交给自己的 goroutine。
   - `entitysync.SessionOpenRetryable(err)`：`ErrSessionClosing` 或 `ErrSessionOpening` 为真，即 OpenSession 文档里的“本次未创建会话、可重试”，把契约落成代码供调用方分类。
2. **demo scene 只做正式调用**（`demo/internal/service/game/scene.go.tmpl`）：
   - `Join` 先分配代际，再用 `RegisterAfterRetirement` 登记；排队时 Info 一行，done 回调 `registeredLater` 交给独立 goroutine，在 `transitions` 锁内按代际复查后 `apply()`，
     让政策重说退役期间被拒绝的 pair（Interest 的重试表）。退役期间 `ErrSubjectRetiring` 的订阅拒绝降为 Debug（它们一定会被重说）。
   - 会话打开（`Join` 的 `OpenHeldSession`、断线 settle 的重开）遇 `SessionOpenRetryable` 不再放弃：成员记 `reopening`，`reopenLater` 以
     25ms 起翻倍、上限 1s 的退避重试，总共至多 8 次（`sessionReopenAttempts` / `sessionReopenFirstDelay` / `sessionReopenMaxDelay`）。每次重试在 `transitions` 锁内按代际复查：
     玩家已离开、已重新登录、场景已 Close 则什么也不做；成功后 `Resubscribe` + `apply()`，与原重同步相同；用尽次数只 Warn，玩家保留在场景里（他人仍看得见），自身视图等下次登录。
   - `Ready` 在会话尚待打开（`reopening`）时记下 ready 并返回 nil，重试会以 ready 状态打开。
   - `resyncLocked` 改名 `reopenLocked(subjectID, member, attempt)`；`newScene` 拆出 `newSceneOn(lane, …)`（测试借它放入带 SessionLifecycle 的 lane）；新测试缝 `Scene.after`（nil 为 `time.AfterFunc`）。

未采用：在 scene 里轮询 `Register` 直到退役完成（demo 特判、无界轮询）；让 `Register` 本身对 retiring 静默排队（改变全部调用方的语义，`RetractSyncSubject` 等依赖
`ErrSubjectRetiring`）；在 Join 里同步等待退役或旧发送退出（Join 持 `transitions` 锁，且不能在调用路径上阻塞等待）。

## 兼容性与行为变化

- core 新增导出：`Manager.RegisterAfterRetirement`、`ErrRegistrationCancelled`、`SessionOpenRetryable`；`Register`、`Unregister`、`OpenSession` 的既有语义不变
  （`Unregister` 额外取消该 subject 的排队登记——只有调用了新入口才会有）。无配置项变化。
- demo（生成的 game-demo）：快速重连不再返回“subject is retiring”，玩家进入复制场景；观察者先收到旧对象的 remove，再收到新对象。
  换成带 SessionLifecycle 的传输时，会话打开的“稍后重试”最多再试 7 次（延迟 25ms、50ms…封顶 1s，累计约 2.6s），不再只 Warn。每个成员同一时刻至多一条重试链（`reopening` 期间 settle 不另起）。
- 重试用 `time.AfterFunc`，不是每请求 goroutine；Close 后到期的重试什么也不做（计时器至多 1s 后自行结束）。

## 交付前对抗性自查

- **Join 排队有界且会话关闭时取消**：core 每个 subject 至多一个排队登记，替换 / 再次 Unregister（玩家连接关闭 → settle → Leave）/ state 关闭 / Manager 关闭都取消并报告一次；
  scene 的会话重开至多 8 次、每成员至多一条链，玩家离开 / 重新登录（代际变化）/ Close 后到期的重试什么也不做（回归覆盖“离开后不打开、不续排”）。
- **代际一致性（RR-40）**：`registeredLater`、`reopenLater` 都携带 Join 代际，在 `transitions` 锁内经 `memberLocked` 复查（成员仍在、代际相同、场景未关闭）才动作；
  `setReopening` 与 `Ready` 只改同一代际的成员；settle 的代际复查未改。新 Join 重置 `reopening`，旧链因代际不符自然结束。
- **remove-before-create**：排队的登记只在旧 subject 被 forget 之后才 `Register`，退役期间订阅一律被拒；core 回归断言 create 在 remove 之后且是新 ObjectRef，模板回归断言观察者先收到 remove。
- **锁序 / 回调**：done 在 Manager 释放自己的锁之后调用；scene 的 done 只把工作交给 goroutine，不在 Manager 路径上取 `transitions`（Leave 持 `transitions` 调 Unregister 时 done 触发的 goroutine 之后才取锁），无反向锁序。
- **快池**：新入口不等待，可在快池调用；重试等待在计时器 goroutine 上，不在 Nest 快 worker 上。
- **关闭失败连接 / 连接槽 / 流名**：本修复不涉及（见 RR-52 / RR-56）。

## 未验证项与已知边界

- 没有真实网关的“同 tick 断线 + 重连”端到端复现；集成机器人不覆盖快速重连（模板回归用 recorder 与可控 settle 覆盖）。
- 生成的 demo 传输（同步 push lane）不实现 SessionLifecycle，`ErrSessionClosing` 在当前 demo 里不会出现；退避分支由带 lifecycle 的测试 lane 覆盖，未在 AsyncTransport + 真实网络上跑。
- 退役若因观察者会话长期 held 且持有对象而迟迟不完成，排队登记会一直等（有界：一个；随 Leave / Close 取消），期间其他人看不到重连玩家。
