对应[问题](../bug/RR-20260926-04.md)。日期：2026-09-26；基线 aaada47 / a22c5a5。状态：已修复、已验证，未提交/部署。

字节预算首个不适配候选阻止后续插队；会话内按意图入队顺序排队，不再被不断到来的更大/更小 Entity ID 越过。on_change 在已使用额度导致阻塞后抑制本窗口重复捕获；下一窗口重启。

涉及文件：sync/entitysync/snapshot_budget.go、snapshot_requests.go、session.go、manager.go。维持原包结构，不改公开协议或 WAL 格式；行为与豁免详见[复审核实记录](../review/REVIEW-2026-09-26-followup.md#决策边界)。

旧版所有指定饥饿探针失败；修后两个模式及 ID 到达变体通过。字节-only periodic 预捕获成本仍存在，不承诺带宽最优。

## 复核后的补修（2026-09-26）

对应[复核残留](../bug/RR-20260926-04.md#复核后的补修2026-09-26)。基线 main `87d9499`；状态：已修复、已验证，本地提交，未 push。

### 根因

冷创建先按对象数预选、全部捕获打包，再在 `scheduleSnapshots` 按实际编码做字节准入（`87d9499` 的 `snapshot_budget.go:201-225` → `flush.go:184` → `snapshot_budget.go:283`）。已知放不下的大对象和其后积压每个窗口都被重新打包后再延后；`windowByteBlocked` 只覆盖 on_change 同窗口。

### 方案

- `snapshotRequests` 增加 `estimates`（与快照请求索引同锁、同生命周期）：`scheduleSnapshots` 在准入前记下本轮捕获的每个冷创建的大小（对象头 18 + `subjectUpdateBytes`，含随后被挡、被延后的项）；订阅不再是待快照（结算、退订、会话关闭）时随索引项删除，没有独立缓存或内容副本。
- `planSnapshotCaptures` 在设了 `MaxBytes` 时按与准入相同的顺序和规则做字节预判：窗口已有对象且预估放不下时，把该候选及后缀留在本轮之外（不捕获、不推进游标、标记 byteBlocked）；从未捕获过的请求按最小可能大小（18+64）计，只会让预估偏小，不会误挡后面的候选。窗口内首个对象照常独占软预算，保持 RR-04 原修复的进度保证。
- 预判只决定“是否值得捕获”。真正准入仍在本轮捕获后按实际编码判断，发出去的永远是准入当轮的最新冻结内容，不保存或复用旧编码。内容变大：预选后准入发现放不下，按原路径延后并刷新预估（多一次捕获）；内容变小：旧预估偏大，最迟在它成为窗口首位时被选中。
- 只设对象数预算（交接文档的正式恢复压测口径）时不走这条路径，行为不变。

涉及文件：`sync/entitysync/snapshot_budget.go`、`snapshot_requests.go`、`wire.go`；回归与基准：`snapshot_progress_test.go`、`recovery_benchmark_test.go`。无公开 API、协议或持久格式变化。

### 回归

- `TestByteBlockedSnapshotsAreNotRecapturedEveryWindow`：periodic/on_change × 积压 30/60；断言大对象最多打包 2 次、`SnapshotsCaptured` 不超过实际交付对象数 + 2。修前红见问题记录（242/882），修后 33/63。
- `TestByteBlockedSnapshotDeliversLatestContent`：等待期间内容先变大（1200 字节）再变小（40 字节），交付的必须是最新 40 字节内容。修前修后都通过（防止以预估换陈旧编码）。
- `TestOverHardLimitSnapshotStillFailsExplicitly`：传输帧上限 150、软预算 300，1000 字节对象在 3 个窗口内以 `ErrFrameTooLarge` 只关闭所在会话，另一会话随后排空。修前修后都通过。

### 未验证项与边界

- 仍会有常数次多余捕获：未知大小的新请求按最小大小预选，排在大对象之后时在其独占窗口被捕获一次；内容变大时多一次捕获。
- 同一 subject 被多个会话在不同窗口冷创建时各自捕获一次（共享编码只在同一 Flush 内），这不是被挡重复，本次未改。
- 端到端字节预算场景（`sync-aoi` 未提供字节预算参数）未压测。
