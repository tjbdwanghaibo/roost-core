# RR-20261006-67 修复：仪表盘与 demo README 的指标名、标签对齐源码，并由门禁守住

问题：[RR-20261006-67](../bug/RR-20261006-67.md)（F11 N1、N2）。分支 `guards`，基线 `c78d0c34`。

## 根因

仪表盘查询和文档里的指标名、标签都是手写字符串，没有任何测试和源码对照（F11 N3）。N1 是名字写错；N2 是标签写错，开关键也写错了。

## 修复

- `observability/grafana-roost-overview.json`：`entitysync_flush_gate_deferred_total` 改为 `entitysync_durability_gate_deferred_total`。`docs/TROUBLESHOOTING.md` T-100 同步改名。
- `demo/.../roost-demo.json.tmpl`：`sum by (subject)` 改为 `sum by (reason)`，图例改为 `{{reason}}`；面板说明写清 `max_deliver` 与 `permanent` 两种原因。
- `demo/.../README.md.tmpl`：`nats_jetstream_terminal_total{reason}` 写明两种原因。`bus_rpc_*` 的开关改为 `nats.rpc.transport: jetstream`。
- 守卫：根包 `metric_names_gate_test.go`，见 [REFACTOR-2026-10-07-structural-guards](../feature/REFACTOR-2026-10-07-structural-guards.md) §1。之后这四处再出现不存在的名字或标签，常规 `go test .` 就会红。

没有采用的方案：只在 `codegen/internal/roost/demo_test.go` 的生成仪表盘断言里多加几个名字。这样只能守住点名的那几个，总览仪表盘与 `OBSERVABILITY.md` 仍然没有守卫，所以改为从源码收集全量名字来核对。

## 兼容性

只改仪表盘查询与文档。已导入旧总览仪表盘的，重新导入即可。已生成的工程，`roost project sync` 会刷新生成器管理的 `deploy/dev/observability/` 文件。未部署。
