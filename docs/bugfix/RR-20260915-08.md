# RR-20260915-08:Import / Restore 绕过绑定 journal 的持久化替换

**仓库 / 位置**:roost-core `syncstream/syncstream.go`,`Import`(`Restore` 经它)。
**修复单元**:U-0213(C8)。**定位文档**:TROUBLESHOOTING T-107。

## 问题

绑定 journal 的 History 上 Import / Restore 一个新快照,只替换 streams / epoch,journal 不知道;之后 Append 成功、重启:
同 epoch 时第一包又变回 old(运行时已是 replacement),换 epoch 时 WAL 混入不同 epoch → `ErrInvalidSnapshot`。四个场景失败;
替换后显式 Checkpoint 再追加的对照通过(但那不是原子的)。

## 根因

Append / ACK / Delete 都先写 journal 再改内存,Import 例外(C8)。

## 方案选择

- **拒绝持久化实例的 Import / Restore。** 要另开一个"持久化替换 API",公开接口变更。
- **Import 先经 journal.Checkpoint 发布再切内存(采用)。** 在 `history.mutex` 写锁内:校验 → 构造新 streams →
  `journal.Checkpoint(exportStreams(...))` → 成功才切换;失败内存不变。锁序 History → journal 与 `History.Checkpoint`
  一致。`NewHistoryWithJournal` 在挂 journal 之前 Import,构造期加载不写 journal。发布失败若是不确定结果,由 U-0212 的
  fail-stop 兜底。

## 改动

`syncstream.go`:`Import` 末段;`exportLocked` 抽出 `exportStreams(epoch, floor, streams)` 供两处复用。

## 证明

`syncstream/import_durability_promises_test.go`:Import / Restore × 同 epoch / 新 epoch 四个场景,替换后追加再重启,
第一包是 replacement 且 epoch 正确;两个显式 Checkpoint 对照仍过。
修前红:`replacement reverted on restart: "old"` / `successful replacement and append cannot restart: syncstream: invalid history snapshot`。

## 未做 / 边界

- Import 现在在持久化实例上是一次 checkpoint 的代价;非持久化实例行为不变。
