# RR-20260909-06:多 Entity 配合显式 `-output` 静默覆盖生成结果

**仓库 / 位置**:roost-codegen `internal/entity/main.go`,`run` 的生成循环。
**修复单元**:U-0162(C2)。**定位文档**:TROUBLESHOOTING T-56。

## 问题

同一目录两个有效实体,调 `entity -dir <目录> -output <目录>/entities_gen_wire.go`。循环对每个
实体都用同一个 `-output` 路径,后写的覆盖先写的,连同伴随的守卫测试文件。工具 exit 0 并**两次
报告"生成同一路径"**,消费者编译报 `undefined: RegisterEntity` —— 活下来的那个文件不是按名排序
的第一个,包级 `RegisterEntity`(U-0160 之后只生成在第一个实体的文件里)随被覆盖的文件一起消失。

## 根因

`-output` 是给 `go:generate` 的单文件模式用的,它和"一个包多个实体各占一个文件"在语义上冲突,
而循环没有察觉这个冲突。默认模式(不给 `-output`)按实体名派生文件名,一直是对的。

## 方案选择

- **把整包内容聚合成一个文件写出。** 模板要改成一个文件容纳多个实体,而 `guardTestFileFor`
  从 `outFile` 派生守卫测试文件名,两个实体的守卫测试也会撞同一个路径,要一并重新设计。
  代价与 `-output` 这个选项的实际用途不相称。
- **在写任何文件之前拒绝(采用)**,报错里点出目录、实体个数与实体名,并说清"拿掉 `-output`
  就能并排生成"。exit 非零,不留半成品。单实体配 `-output` 照旧工作,这正是这个选项存在的场景。

## 改动

`internal/entity/main.go`:`parseDir` 之后、生成循环之前,`*output != "" && len(entities) > 1`
就返回错误。检查放在写入之前,所以失败的一次运行不留任何输出。

## 证明

`internal/entity/output_multi_entity_promises_test.go`:从 `testdata/player.go` 派生第二个实体放
同一临时包,跑 `Run(-dir, -output)`,断言报错、错误里点出两个实体名与 `-output`、输出文件不存在;
再断言单实体配 `-output` 仍然生成成功。

修前红,失败输出正是报告里的症状:

```text
two entities with an explicit -output were accepted; stdout:
generated: /…/entities_gen_wire.go
generated: /…/entities_gen_wire.go
```

修后 codegen 全仓测试绿。

## 未做 / 边界

- 没有实现"聚合成一个文件"。若以后确有需要,那是新增一种输出契约,不是修这个缺陷。
- 只覆盖同一目录内多实体。`-dir` 递归模式下 `-output` 本来就不会被使用(有 `-output` 时不做
  递归查找),不受影响。
