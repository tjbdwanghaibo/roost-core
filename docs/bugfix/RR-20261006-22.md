# RR-20261006-22 修复：reset 条目带上增量里的 PrimaryTarget（不下发），过滤按增量的形状

问题：[RR-20261006-22](../bug/RR-20261006-22.md)（SKILL-3 补测）。基线 `37338490`，分支 `sktest2`，未发版。
读代码：codebase-memory 共享 generation 停在 09-30，以当前源码为准；`ActivePresentation` 的使用点用 `rg` 穷举（`skill/presentation_recovery.go`、`skill/skillsync/coordinator.go` 与测试）。

## 根因

`ActivePresentation` 没有 PrimaryTarget，`activePresentationEvent`（基线 `skill/skillsync/coordinator.go:499`）用 `Anchor.Target` 代替。仍归施法的进程，增量的 `PrimaryTarget` 是施法目标、`Anchor.Target` 是 lifecycle 实体，两者不同。

## 方案取舍

| 方案 | 做法 | 结论 |
| --- | --- | --- |
| ① `ActivePresentation` 加 `PrimaryTarget`，`json:"-"`（采用） | `PresentationSnapshot` 按增量的来源填：施法条目与未移交进程取 `cast.primaryTarget`，移交后取 lifecycle（`processPresentationTargetLocked`）；`activePresentationEvent` 用它；过滤后回写过滤结果 | 采用。reset 与增量交给策略的事件同形；字段不进 JSON，wire 与 Applier（`decodeStrict`）不变 |
| ② 字段进 wire | `json:"primary_target,omitempty"` | 未采用：旧 Applier 严格解码会拒绝未知字段；客户端渲染只用 Anchor，不需要它 |
| ③ skillsync 自己查施法 | 用 `InspectCast` / `OwnedProcesses` 拼 | 未采用：两次加锁之间状态可能变，且要在 skillsync 里重复 Runtime 的“移交与否”规则 |
