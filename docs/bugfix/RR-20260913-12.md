# RR-20260913-12:EnterShared 执行后丢回复,恢复独占写准入

**仓库 / 位置**:roost-core `remoteentity/ownership.go`,`EnterRemoteSharedMode` / `LeaveRemoteSharedMode` 的失败分支。
**修复单元**:U-0189(C8)。**定位文档**:TROUBLESHOOTING T-83。

## 问题

owner 原为 `local_owned`,`EnterSharedExpected` 的 Lua 已把权威改成 shared、推进 lease,回复丢失、客户端拿到
I/O 错误。本地直接 `restoreOwnershipAfterTransitionFailure(expected)` 回到 `local_owned`,不清热 marker、不重查
权威;随后 `PrepareRemoteWriteBatch` 走独占快捷准入成功 —— 与权威的共享模式不一致,跳过共享写所需的分布式锁
协调。审查实测 `authority_shared=true state=local_owned admission=<nil>`。LeaveShared 是同一形状(执行后丢回复
测得 `authority_shared=false state=shared`,本次准入被拒但状态没同步)。

## 根因

U-0188 只把 Transfer 的失败分支改成"失效 marker → 独立重查 → 按权威结果收尾/冻结",Enter/Leave 仍是"任何存储
错误都恢复旧状态",把 I/O 错误等同"没执行"(C8)。我在 U-0188 的记录里明确写了这两条"留给后续",这轮收掉。

## 方案选择

- **照抄 Transfer 的判定。** Transfer 的"已生效"判据是 `owner == 新节点`,Enter/Leave 的目标是模式不是 owner,
  直接套会把"仍是我们、模式已切"判成"别人",错误地 fence 自己。
- **任何错误都 fence。** 发送前失败的对照要求恢复原模式继续可写。
- **把 U-0188 的骨架参数化(采用)。** `settleIndeterminateOwnership(wrapper, expected, cause, op, applied, appliedState,
  excludeSID)`:失效 marker;独立有界 ctx 重查权威;权威 == expected → 证明没执行,恢复原模式;`applied(current)`
  → 按成功收尾(live 进 appliedState,返回权威 lease、err=nil);权威仍是我们但另一种 lease → 把 live 同步到
  权威所示的模式并报告失败;别人/无人 → fence;查不到 → 冻结进 `Recovering`。三个入口各给自己的 `applied`:
  Transfer `owner == newOwner`(Fenced),Enter `owner == 我 && Shared`(Shared),Leave `owner == 我 && !Shared`
  (LocalOwned)。冻结要走 `freezeAttachedLive`:Sharing 不能直接到 Recovering,状态表只允许 Sharing → Fenced →
  Recovering;Draining 直达。解冻复用 U-0188 已加的准入分支(权威读成功后按 marker 进 LocalOwned / Shared)。

## 改动

`remoteentity/ownership.go`:`settleIndeterminateTransfer` 泛化为 `settleIndeterminateOwnership`,Transfer / Enter /
Leave 三个失败分支都调它;新增 `freezeAttachedLive`。不改状态表、不改公开 API。

## 证明

`remoteentity/ownership_mode_indeterminate_promises_test.go`,替身 `lostReplyModeStore` 让 mock 的 Enter/Leave 真正
改权威后再返回 I/O 错误:
- `TestEnterSharedPromiseLostReplyFollowsAuthorityIntoSharedMode`:live 必须是 shared、返回的 lease `Shared=true`
  且 err=nil、live 的 MarkerEpoch 等于权威、wrapper marker 为 shared,之后的准入走共享路径成功。
- `TestEnterSharedPromiseLostReplyFreezesUntilAuthorityAnswers`:执行后权威黑屏,Enter 报错、live 不是可写模式、
  准入被拒;权威恢复后准入成功且 live 解冻为 shared。
- `TestLeaveSharedPromiseLostReplyFollowsAuthorityIntoLocalOwned`:对称。
- `TestSharedModePromiseFailureBeforeSendRestoresPreviousMode`(对照):Enter/Leave 发送前失败各恢复原模式并可写。

修前红:`authority_shared=true state=local_owned admission=<nil>: entered shared at authority but old local-owned write admitted`、
`unknown outcome restored a writable mode: live=local_owned`、`leave-shared applied but reported err=… reply lost … state=shared`;
对照修前修后都过。修后 remoteentity 含 `-race` 全绿。

## 未做 / 边界

- 仍是 mock marker store,不是真实 Redis;审查在 overlay 里用的也是可控 store。
- Enter 的 `applied` 只看 `Shared` 标志与 owner,不比较 epoch 前进量;权威说 shared 且是我们,就按权威 lease 同步。
- 重查用 `OpTimeout`,与 U-0188 一致,没有单独配置项。
