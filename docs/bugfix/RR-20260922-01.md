# RR-20260922-01：断线的观察者撤不掉订阅，一个死会话让整个房间的下发停摆（U-0277）

- 单元：U-0277 · 缺陷类 C3（回调外累积状态；伴随 C5 静默吞错）· 等级 P1
- 仓库：roost-core `entitysync` + `room`
- 排障行：T-172
- 来源：[REVIEW-2026-09-22](../bug/REVIEW-2026-09-22.md) · 原始输出 [REPRO-2026-09-22 §6–§8](../bug/REPRO-2026-09-22.md)

## 问题

16 机器人冷进程实跑，3–6 个客户端自己的 `pos_x` 永不到达（40 秒超时仍红），另一场丢 `equipment`。服务端全程零 WARN / ERROR。
观察者 × subject 矩阵把现象钉成一句话：**某一时刻起，按 id 排在某个位置之后的 13 个会话再没收到任何帧，排在前面的 3 个照收、还收到同一版本的重复帧**。
那个位置就是第一个跑完脚本断线的机器人；6 个失败者是 move 落在它断线之后的 6 个。

## 根因

三段代码，一条链：

1. `entitysync/subscription.go:300-312`（修前）：`SubscriptionCoordinator.Unsubscribe` 把订阅置为 Closing 后，**必须**把一条
   `EnvelopeLeave` 经 sink 投递给被撤的观察者；投递失败就 `restoreActive` 并返回 `ErrEnvelopeAdmission`。
   `TestSubscriptionUnsubscribeFailureRestoresActive` 把这当契约。对一个会话已经不在的观察者，投递永远失败，订阅永远 Active。
   `RetireSubject → retryRetirement` 同样要向它投 Leave，失败则 subject 永远 retiring，`UnregisterSubject` 因 `ErrRoomSubjectHasSubscribers` 拒绝。
2. `room/room_broadcast.go:320 lessRoomFrameGroupKey`：一次 flush 的全部帧按 subscriber id 升序排成**一批**交给 sink；订阅仍 Active 的死观察者每次都在批里。
3. 生成工程（codegen 模板 `internal/service/game/scene.go:107-131`）的 `sceneLane.AdmitBatch` 逐个 `PushPlayer`，第一个失败就整批返回错误
   （`SlowConsumerFailBatch`）；已推出的不回滚、后面的一个没推。coordinator 收到失败 `AbortWithError` 保留脏位，下一 tick 重试，又在同一处失败。
   `pushPlayer` 对无会话返回 `ErrSessionNotFound` 且不计指标，所有失败只进 `slog.Debug` 与 `flushFailures` 计数。

RR-20260918-06 加的会话关闭钩子（`watchSessions → Leave`）确实被调用了，但 `Leave` 的每一步都要向已死会话投递——钩子在这条路上等于没有。
room / coordinator 没有任何"不投递、直接遗忘一个不可达观察者"的入口；sink 的 `ReleaseSession` 没有调用者。

## 方案选择

- **（选中）撤订阅无条件完成，Leave 尽力投递**：`Unsubscribe` 投递失败也删掉订阅，返回新哨兵 `ErrLeaveNotDelivered`（同时 wrap
  `ErrEnvelopeAdmission` 与原因）；room 的 `unsubscribeTracked` 见到它照样释放 budget / sink 状态并把错误传回；`retryRetirement`
  把它记为"已撤、未通知"，退役**完成**（注销 subject、清 retiring），把未投递的 Leave 用返回值报一次；`handleSlowConsumer` 忽略它。
  理由：通知是对观察者的礼节，不是撤订阅的前置条件。兴趣系统已经判定它不该再看这个 subject，"通知失败就继续给它发"在两种情形下都错——
  活着的观察者会一直收到 AOI 之外的 subject，死了的观察者会拖死整批。这条修法不依赖应用侧任何配合，v1.16.1 的生成工程升 core 即生效。
- **（未采用）给 coordinator / room 加 `EvictSubscriber` 不投递入口，由会话关闭钩子调用**：语义最干净，但要改 codegen 模板才生效，
  且钩子与 Leave 路径是两套并行的清理。留作后续（见 WANTED W-2026-09-22-03 的候选修法）。
- **（未采用）sink 加 `MarkSessionGone`，让死会话的帧像 Evict 那样被跳过**：同样要应用侧配合；而且"跳过"会让 Unsubscribe 假装投递成功。
- **（未采用）退役对投不到的 Leave 做有界重试**：要在 coordinator 之外再记一份"欠着的 Leave"，机器多、收益小；一个死会话的重试永远不会成功。

## 改动

- `entitysync/subscription.go`：新增 `ErrLeaveNotDelivered`；`Unsubscribe` 的投递失败分支改为 `forgetClosing` + 返回
  `fmt.Errorf("%w: %w: %w", ErrLeaveNotDelivered, ErrEnvelopeAdmission, err)`；成功分支共用 `forgetClosing`（同一把 Revision 守卫）。
  `restoreActive` 只剩 sink 为 nil 那条路在用。
- `room/room_broadcast.go`：`unsubscribeTracked` 对 `ErrLeaveNotDelivered` 仍 `releaseSubscriber` 并把错误传回；`retryRetirement`
  三分：成功 / 未找到 → 无事，`ErrLeaveNotDelivered` → 收进 `undelivered`，其他 → 仍算退役失败；注销 + `clearRetiring` 之后
  `return errors.Join(undelivered...)`；`handleSlowConsumer` 的忽略列表加它。
- 测试：新增 `entitysync/unreachable_subscriber_promises_test.go`、`room/unreachable_subscriber_promises_test.go`；
  旧契约测试改写：`TestSubscriptionUnsubscribeFailureRestoresActive` → `…RemovesEvenWhenTheLeaveIsRejected`，
  `TestRoomReplicationRetriesRetirementUntilLeaveAdmitted` → `…RetirementCompletesAndReportsAnUndeliveredLeave`，
  `TestRoomReplicationStopReturnsFinalAdmissionError` → `…StopIsNotHeldByAnUndeliverableLeave`。**行为变化**：`RetireSubject`
  对投不到 Leave 的观察者不再挂起重试，而是完成并返回 `ErrLeaveNotDelivered`；`Stop` 不再因此返回 `ErrRoomFrameAdmission`。
  核对过的消费方：room 内三处调用（上面已改）、生成工程 `scene.go` 的 `applyChanges` / `Leave`（只 `slog.Debug` 错误，行为即"记一条、继续"）。

## 未做 / 边界

- **活着的观察者遇到一次瞬时投递失败会少收一条 ObjectRemove**（那个 subject 在它的视图里成为幽灵，直到它重新订阅拿到全量）。
  修前的代价是"永远继续收到 AOI 之外的 subject 的 delta"或"整批停摆"，两者相比选前者；sink 的 Evict / FailBatch 策略是处理瞬时背压的地方。
- **生成工程 `sceneLane.AdmitBatch` 仍是逐个推、遇错整批放弃**：本修复后死会话会在会话关闭钩子那一 tick 被撤掉，窗口从"永远"缩成"一个 tick"，
  但同一批里死会话之后的人在那一 tick 仍收不到；`pushPlayer` 的 `ErrSessionNotFound` 仍不计指标。登记为 W-2026-09-22-03，属 codegen 模板（P2），不在本单元——**同日由维护者拍板，U-0278 修掉**。
- 未发版。rv21 生成工程钉 v1.16.1，本轮端到端用 `replace` 跑；发版后需再按 §11 用不带 replace 的工程跑一遍。
- 探针（观察者 × subject 矩阵）与 debug 配置只在 scratch 工程，仓库未收。
- 生成工程 `Scene.Leave` 在 `RetireSubject` 之后还调一次 `UnregisterSubject`，现在退役已经注销，于是每个离开者多一条
  `scene: subject not unregistered … not registered` 的 Debug 日志（修前这条日志的原因是 `has subscribers`）；`RetireSubject` 返回的
  `ErrLeaveNotDelivered` 也被它记成 `subject not retired`。两条都只是 Debug 措辞，已随 U-0278 的模板改动收掉。
