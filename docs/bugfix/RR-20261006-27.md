# RR-20261006-27 修复：直方图分位数收在观测范围内；loadtest 失败说明点名阈值

问题：[RR-20261006-27](../bug/RR-20261006-27.md)。基线 main `0db819b0`，未发版。来源：[真实进程演练](REAL-PROCESS-DRILLS-2026-10-06.md)第 1 项的“观察”。

## 根因

- `metrics/metrics.go` `histogram.quantile`：在命中的桶里按桶的 `[下界, 上界]` 插值。桶翻倍，排名落在桶内最后一个样本时估计等于桶上界，最多是真实值的两倍；小样本（≤ 10 个）时 p95 就是最慢样本，于是 p95 = 最慢样本所在桶的上界。排名落进溢出时返回最大桶上界 65.536s，低于每个溢出样本。
- `robot/loadtest/manager.go` `evaluate` / `execute`：判定按设计（`actual > max`），但 `Error` 只在运行出错时填，阈值失败时没有任何一行说明；生成的 `cmd/loadtest` 只打印 `ended failed (threshold)`。
- 生成的 `-max-p95` 说明“健康运行落在 8s 桶，所以上限取下一个桶”与数值 16 自相矛盾（下一个桶的上界是 16.384）。

## 改动

| 位置 | 改动 |
| --- | --- |
| `metrics/metrics.go` | 直方图多记最小 / 最大观测值（`newHistogram` 把最小值初始化为 `math.MaxInt64`，`observe` 先 CAS 更新最小 / 最大、再记桶、最后加计数，读到计数的读者一定看得到它拓宽的范围）。`quantile` 的插值区间收窄到 `[max(桶下界, 最小值), min(桶上界, 最大值)]`；排名落进溢出时在 `[最大桶上界, 最大值]` 里插值。任何分位数的真值都在 `[最小, 最大]` 里，收窄只会减小误差：10 个样本的 p95 现在就是最慢样本，全部样本相同时任何分位数都是那个值。Prometheus 导出（桶计数）不变 |
| `robot/loadtest/manager.go` | `ThresholdResult` 加 `Samples`（JSON `samples`：error_rate 是完成的场景数，分位数是成功场景耗时的样本数）。阈值失败时 `RunSnapshot.Error` 写成 `threshold violated: p95 = 9.6s > max 9s (10 samples)`（多条用 `; ` 连接，无样本、未知指标各有说法），`run done` 日志多一个 `verdict` 属性 |
| `demo/cmd/loadtest/main.go.tmpl` | 退出错误带上 `snapshot.Error`：`loadtest: run … ended failed (threshold): threshold violated: …`；`-max-p95` 说明改为实际依据（健康运行最慢的机器人 7～10s，两个 game 同机在上沿，上限约为两倍；p95 由翻倍桶估计并收在最快 / 最慢机器人之间，≤ 10 个机器人时就是最慢的那个） |

阈值 `-max-p95 16` 不改：修正估计之后，10 个机器人的 p95 是最慢机器人的真实耗时——单 sid 7.4～8.3s，两个 sid 9.8～10.0s（下面的实测），16s 约为两倍余量，仍是“回归界”而不是 SLO。改成 16.384 或更大只是迁就错误估计，没有采用。

未采用：
- loadtest 自己保存每个样本算精确分位数——持续时间模式下样本无界，直方图就是为了定长内存才用的；收窄插值区间对小样本已经精确（排名在两端时就是最小 / 最大样本）。
- 只在 loadtest 里把分位数夹到运行时长——运行时长不是样本的上界的精确值，也修不了溢出一侧和其他调用方。`HistogramQuantile` 目前只有 loadtest 用，改在 `metrics` 一处。
- 阈值违反写进新字段而不是 `Error`——`Error` 本来就是“这次运行为什么失败”，运行出错时也写在这里，调用方只看一个字段。

## 兼容

- `HistogramQuantile` 的估计值变小（或在溢出侧变大），总是更接近真实值；桶计数、`HistogramCount`、Prometheus 导出不变。用自定义 `Quantile` 的 loadtest 不受影响。
- `ThresholdResult` 的 JSON 多一个 `samples`；阈值失败的运行 `error` 不再为空。生成工程的 loadtest 错误行变长（多了说明）。
- 生成形状：`cmd/loadtest/main.go` 两处文本，已有工程不受影响，重新生成或手工合并即可。
