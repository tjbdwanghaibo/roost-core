# RR-20260927-06 修复：引擎 fence 之后，外层自己的事务在交给 committer 之前返回 ErrNestFenced

问题：[RR-20260927-06](../bug/RR-20260927-06.md)（清单 [OPEN-ITEMS-2026-09-27](../review/OPEN-ITEMS-2026-09-27.md) B03 → C07）。
日期 2026-09-27；实施基线 `d4234c9`，分支 `fix-r7-nest`。状态：已修复、本地验证通过、已本地提交，未推送 / 未发布。
前序：[RR-20260926-76](RR-20260926-76.md)（嵌套独立事务结果未知时 fence）、[RR-20260926-65](RR-20260926-65.md)、[RR-20260926-84](RR-20260926-84.md)。
codebase-memory 图谱停在 09-26，已过期；结论全部来自当前源码与实跑。

## 决策与实现

按清单 §H C07 推荐（维护者 2026-09-27 决定按推荐执行）：

- `nest/rollback.go` 新增 `(*RollbackTx).refuseCommitAfterFence`：消息自己的事务（`tx.dispatch != nil`）在交给 committer 之前读一次
  `tx.dispatch.engine.FenceError()`；已 fence 时返回 `fmt.Errorf("%w: … (fence cause: %v)", ErrNestFenced, …)`。
- 调用点：`durableCommit` 在记录非空、RR-74 的 `refuseWriteUnderEnclosingRollback` 之后、`committer.Commit` 之前；`pipelinedEnqueue`
  在记录非空之后、`committer.Enqueue` 之前。记录为空（没有要持久的内容）时不检查，行为不变。
- 这是**明确拒绝**：记录没交给 committer。`commitDurable` / `commitPipelined` 走既有 `rejectCommit`，外层修改回滚；Remote 批次（若有）按
  既有拒绝路径 Abort；pipelined 没有 ticket，不 `markTransactionAdmitted`。
- 错误里 fence 原因用 `%v` 而不是 `%w`：`FenceError()` 链上有 `ErrCommitIndeterminate`，若保留，`commitDurable` 会误走结果未知分支
  （`abandon` 而不回滚），回复也会误报“可能已提交”。
- 只拦消息自己的事务，不拦嵌套独立事务（C07 推荐只针对外层自己的提交）。

`dispatch.engine` 是 RR-76 已加的字段（`dispatchNest` 设置），不新增字段。

未采用：在 `RunIsolatedTransaction` 返回后让业务自行检查——不能依赖业务；在 fence 时让 WAL 进入 terminal——fence 是 Nest 的准入状态，
WAL 被其他引擎 / 组件共享时不能由这里代为终止，且与 RR-76 “同一 fence 入口”的约束不符。

## 快池

检查只在 `lifecycleMu` 下读一个字段（与 `runNestLogic` 在快 worker 上读 `FenceError` 相同），没有等待、没有 I/O，不改变锁内 WAL 准入的豁免范围。

## 文件与行为

- `nest/rollback.go`：`refuseCommitAfterFence` 与两个调用点。
- `nest/execution.go`：`RunIsolatedTransaction` godoc 补一句。
- `docs/USER_GUIDE.md`：§4 判别表下 `ErrNestFenced` 的含义；RR-76 那一段之后说明外层提交被拒绝。
- 回归：新 `nest/nested_fence_outer_commit_nestwal_promises_test.go`（`package nest_test`：nestwal 依赖 nest，包内测试不能 import 它）。

## 兼容性

- **行为收紧**：引擎已 fence 时，仍在执行的消息自己的事务不再写 WAL，回复 `ErrNestFenced`（嵌套事务已提交 / 结果未知时同时带
  `ErrNestedTransactionCommitted`，按判别表第 4 行），修改已回滚。这也覆盖“别的消息 fence 了引擎、本消息正在快 worker 上执行”的情形：
  此前这类在途消息会继续提交（WAL 健康时被接受），现在同样在提交点被拒绝。
- 无新导出、无签名 / 配置 / 持久格式变化。

## 验证

### 回归

`TestOuterCommitAfterNestedAcceptFailureIsRefusedBeforeWAL/{undo_strict,state_strict,undo_pipelined}`：真实 `nestwal.Open` +
`nestwal.NewCommitter`（WriterVersionV2，临时目录）。嵌套事务 Cast 一个锁组更高的实体、`MarkPersist`，它的 DAO `AcceptMutation` 返回错误；
业务吞掉结果未知后改声明实体并 `MarkPersist`。前提断言：嵌套事务结果未知且错误链带 `AcceptMutation` 的原因、WAL `Admitted=1`、
handler 内 `FenceError` 满足 `ErrNestFenced`、WAL 未 terminal。承诺断言：请求结束后 WAL `Admitted` 仍为 1；回复满足 `ErrNestFenced` 与
`ErrNestedTransactionCommitted`、不满足 `ErrCommitIndeterminate`；声明实体值 / tracker 版本回到 1 / 0。
