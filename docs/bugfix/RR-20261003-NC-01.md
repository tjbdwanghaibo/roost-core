# RR-20261003-NC-01：单 Mod 启动前校验

2026-10-04，修前 `183b0bddc5b46f6d3b50c5edda2d08da45150a69`。[原问题](../bug/REVIEW-2026-10-03-noncore-01.md#rr-20261003-nc-01p2-单-mod-绕过依赖和输入校验)。已修复、具名场景验证，未发版。

根因：`app/app.go` 的 sortMods 把长度 0 和 1 一起快速返回，单 Mod 不经过名字/依赖/环检测。修复只允许空集合快速返回；单元素使用现有拓扑校验，保留 external、optional 和稳定顺序，无新抽象。

正式回归 `app/mod_validation_promises_test.go` 在修前真实失败：nil、空名、缺失硬依赖、两类自循环均 `error=<nil>`；共享/服务专属两次 Execute 均 `initialized=true err=serve failed`，已进入错误图的 Init。修后原 12 场景全部通过，非法图在 Init 前返回错误。

兼容性：不改变 Mod API；合法单 Mod、空集合、外部共享依赖和缺失 optional 保持合法。过去被误接受的无效单 Mod 现在启动失败，需要补齐配置/修正依赖，不得以删除校验绕开。不涉及数据格式或生产迁移。

[四项验证总证据](evidence/noncore-bugfix-20261004-01/README.md)：正式红/绿、原 review overlay 及相关包 race/vet。没有重新验收整个 App、生产启动部署或自定义 Init 资源清理契约。T-183。
