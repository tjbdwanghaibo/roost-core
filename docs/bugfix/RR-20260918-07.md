# RR-20260918-07：syncTopic 的裸标识符被静默当成字面量

- 单元：U-0239 · 缺陷类 C4（跨层契约不一致）· 等级 P2
- 仓库：roost-codegen `internal/entity`
- 排障行：T-133

## 问题

`//roost:entity ... syncTopic=SyncTopicPlayer`（同包常量名）生成出来的是

```go
Sync: entity.EntitySyncBuilderParam{Topic: "SyncTopicPlayer"}
```

——**常量的名字，不是它的值**。生成成功、编译通过、实体订阅到一个没人选过的 topic。
生成器自己的 fixture 就是这么写的，所以这个行为还被 golden 锁住了。

## 根因

`syncTopicExpr` → `isConstExpr` 要求标识符**带点号**（`pkg.Const`）才算常量引用，其余一律 `quoteString`。
于是"看起来像 Go 常量"与"字面量"两种意图在语法上无法区分，而选错的那种不会报错。

## 方案选择

- **（选中）在解析时拒绝歧义写法**：首字母大写、无引号、无包名的值一律拒绝，错误信息给出三种明确写法。
  同时让 `syncTopicExpr` 认已经加引号的字面量（此前 `syncTopic="Player"` 会被二次加引号成 `"\"Player\""`，
  是同一个歧义的另一半，红测试一并抓到）。
- 让裸的大写标识符当常量引用：会悄悄改变既有工程的行为——原本得到字符串 `"Foo"` 的现在变成引用 `Foo`，
  可能编译不过，也可能引用到另一个同名常量。破坏性更大且无法察觉。
- 只写进文档：审查明确否掉——标记看起来是合法 Go，生成成功却订阅错 topic，不能降为提示。

## 改动

- `internal/entity/parse.go`：`validateSyncTopicParam`，在 marker 校验阶段拒绝裸标识符。
- `internal/entity/gen.go`：`syncTopicExpr` 先认引号字面量（`unquoteGoString`），再认限定常量，最后才加引号。
- 迁移内置 fixture 与断言：`testdata/player.go`、`testdata/syncruntime/entity.go` 改成 `syncTopic="player"` /
  `"avatar"`，`parse_test.go` / `marker_promises_test.go` / `sync_packer_markers_promises_test.go` 的期望同步。
- demo 的两个实体标记改成显式引号，注释更正为"marker 不是 Go"。

## 证明

`internal/entity/sync_topic_promises_test.go`：

- `TestSyncTopicRejectsABareIdentifier`：两种裸标识符必须被拒。
- `TestSyncTopicAcceptsLiteralsAndQualifiedConstants`：小写字面量、引号字面量、限定常量、空值四类的渲染结果。

修前：前一条编译不过（`undefined: validateSyncTopicParam`），改成只用既有入口后返回 `"SyncTopicPlayer"`——
即审查独立复现的那个结果；后一条的 `quoted literal` 叶子实测 `"\"Player\""`。
修后 `go test ./internal/entity -count=1` 全绿，codegen 全套绿，生成工程 `Topic: "player"`。

## 未做 / 边界

- 审查建议的"合法 Go 表达式按 parser 校验后原样生成"没有做：现在仍是"带点号即视为限定常量"的启发式，
  只是把**歧义**的那一类拒掉了。一个真正的表达式（`pkg.A + pkg.B`）仍会被当字面量加引号——它不歧义（不像常量名），
  但也不正确。若要支持，应走 `go/parser` 校验，归下一轮。
- 已经用旧写法生成过的工程：升级后 `make generate` 会**报错而不是静默改行为**，这是有意的；改标记即可（见 T-133）。
