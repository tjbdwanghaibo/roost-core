# NC-65 修复：玩家加载时按身上装备重建 Gear 层并写 attr_final

问题：[RR-20261005-NC-65](../bug/RR-20261005-NC-65.md)。2026-10-05，分支 `revn07b`，基线 `3d4fe9f3`。

## 根因

`demo/game/entities/player/attribute_component.go.tmpl:81` 加载时装一个空 Gear 层；Gear 只在 equip handler 调用的 `RefreshGear` 里按穿戴重建。重组后的 Final 只经 `persist()` 写回 `attr_final`，`OnInitFinish` 不写，而 `attr_final` 是 nopersist，没有别的路径在加载后把它带回来。

## 决策

- 把“按穿戴求 Gear 数值”提成 `wornGear()`，`RefreshGear` 与 `OnInitFinish` 共用，避免两处各算一遍。
- `OnInitFinish` 只写 `attr_final`（新 `writeFinal()`），不写 `attr_base`、不 `PublishSyncDirty`：`attr_final` 是 `nopersist,sync`，生成的 setter 只做 `MarkSync`，加载期不需要事务、不产生持久写；此时实体还没注册成复制主体，首次快照本来就是全量。
- 未采用：在加载后补跑一次 `RefreshGear`——它会 `captureRollback` 并 `persist()`（写 `attr_base`、要求事务），加载期没有这些前提。
- 未采用：把 Final 改成持久字段——DAO 注释写明“derivable，不存第二份真相”，那是正确的取舍。

## 文件与行为

- `demo/game/entities/player/attribute_component.go.tmpl`：`OnInitFinish` 用穿戴装上 Gear、重组后 `writeFinal()`；新增 `wornGear()`、`writeFinal()`；`persist()` 复用 `writeFinal()`；原因写在注释里（RR 编号；模板注释沿用英文）。
- `demo/game/entities/player/attribute_component_test.go.tmpl`：新增 `TestFinalIsRecomputedFromWornGearWhenThePlayerLoads`。

行为变化：加载后的 Final 包含穿戴装备、`attr_final` 在新建与加载后立即有值（首个同步帧就带上合成属性）。不改存储格式，不需要迁移；存量玩家下次加载即正确。
