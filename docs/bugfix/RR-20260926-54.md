# RR-20260926-54 修复：实体共享加载与调用方 ctx 解耦——每个等待方按自己的 ctx 离开，加载只受框架加载上限与 loader 注销约束

问题：[RR-20260926-54](../bug/RR-20260926-54.md)。相关：[RR-20260926-36 修复](RR-20260926-36.md)（2s 登录预算）、RR-20260919-08（flight 用 defer 收尾）。
日期 2026-09-26；实施基线 main `3e26f91`（RR-51 提交之后）。状态：已修复、本地验证通过，已本地提交，未推送/未发布。

## 根因

`entity/manager_access.go` `loadEntityShared` 由第一个调用方（领头方）在自己的 goroutine 上以**自己的 ctx** 调 `loader.LoadEntity`。
RR-36 让 EnterGame 以 2s 登录预算领头冷加载后，领头方截止 → `WaitEntityProjection` / store 读取随之返回 `DeadlineExceeded` →
flight 以该错误结束，同一 flight 里预算更长的等待方（同一玩家的 Nest 慢阶段准备、其他请求）一起失败；只剩一个等待方且它离开时，加载也被放弃。

## 决策（按修复约束：`context.WithoutCancel` 派生 + 框架加载超时 / 停机取消；每个等待方按自己的 ctx 离开；最后一个等待方离开不取消在途加载）

1. **加载在独立 goroutine 上运行**（`runEntityLoad`）。ctx = `context.WithoutCancel(领头方 ctx)`（保留 trace 等值）→ `WithTimeoutCause(框架加载上限, ErrEntityLoadTimeout)`
   → loader 注销时 `cancel(ErrEntityLoaderStopped)`。fctx 请求数据沿用领头方快照，`Base` 换成解耦后的加载 ctx；该 goroutine 不是快 worker。
2. **每个等待方（含领头方）** `select flight.done / 自己的 ctx.Done()`，离开时返回自己的 `ctx.Err()`，不影响加载。加载完成后结果照常经 loader 发布进
   EntityManager；之后的 Get 直接命中。ctx 已结束的调用方不再发起新的 flight。
3. **框架加载上限**：`entity.DefaultEntityLoadTimeout = 30s`，`ManagerAccess.ConfigureLoadTimeout(d)` 可改（<=0 忽略，对之后的加载生效）。
   取值远大于各调用方预算（Nest 请求 / dispatch 3s、登录 2s），只作兜底：保证无人等待、投影持续失败或 store 不作答的加载最终结束、释放 flight。
   超出时等待方的错误满足 `errors.Is(err, context.DeadlineExceeded)` 与 `errors.Is(err, entity.ErrEntityLoadTimeout)`。未新增配置键。
4. **停机取消**：`ConfigureLoader` 的注销函数除清空 loader 外取消这次注册下的全部在途加载（Cause `ErrEntityLoaderStopped`，错误同时满足 `context.Canceled`）。
   DataEngine `Runtime.stop` 在 Flush / Projector.Close 之前就调用它，停机后加载不会继续等投影或读 store。注销可重复调用；loader 被新注册替换时只取消自己的在途加载。
5. **本地执行器交接**（解耦带来的必要调用点）：加载里需要 Entity 锁的发布经 `RunLocal(ctx)`。修前它用领头方 ctx 上的执行器——Nest 慢阶段即本条消息的快续行
   （`dispatchFastContinuation(msg, …)`）。领头方离开后该消息会结束并被回收，继续用它的续行是悬空引用。因此：
   - 领头方仍在等待：沿用它自己的执行器（未指定则就地执行），与修前相同；执行期间持 `flight.leaderMu`，领头方此时离开要等这一步结束。
   - 领头方离开后：改走 `ManagerAccess.BindLocalExecutor` 绑定的入口；`nest.NewEngine` 对 Getter 做与 Committer / RemoteManager 相同的
     `LocalExecutorBinder` 绑定（`NestMgr.RunLocal`，仍在快 worker 上执行）。未绑定（没有 Nest）时就地执行，与独立使用 Entity 时的 `RunLocal` 相同。
   - 这样 Nest 停机排空期间，仍在等待的领头消息照常用自己的快续行发布；只有领头方已离开的加载才走 `NestMgr.RunLocal`（停机中返回 `ErrNestStopped`，等待方拿到错误）。
6. **panic**：加载 goroutine recover，记 `slog.Error`（含堆栈），flight 以错误结束，所有等待方得到错误；领头方若仍在等待，继续以 panic 看到它（RR-20260919-08 的约定），
   不在加载 goroutine 上重新 panic（那会让进程退出）。flight 仍先从 map 删除（只删自己）再 close(done)，失败后重试会发起新加载。

未采用：领头方离开时把执行器换成其他等待方的（等待方各自的执行器寿命同样不可控）；始终使用绑定的 `NestMgr.RunLocal`（Nest 停机排空时它拒绝投递，会让已准入的慢阶段消息冷加载失败）。

## 交付前对抗性自查

- **共享加载失败 / panic 时所有等待方都得到结果**：flight 的收尾在加载 goroutine 的 defer 里（先删 map 再 close(done)），loader 返回错误、panic、上限、停机取消四种情形都会走到；
  等待方要么收到 done 上的结果，要么按自己的 ctx 离开。RR-20260919-08 两条回归（领头方仍见 panic、并发等待方得到含 “panic” 的错误、重试重新调 loader）通过。
- **无 goroutine 泄漏**：每个 flight 恰一个加载 goroutine，最迟在框架上限（默认 30s）或 loader 注销时结束——前提是 loader 尊重 ctx（与修前领头方 goroutine 被不尊重 ctx 的 loader 卡住相同）；
  `context.AfterFunc` 的停机监听与两个 cancel 在 goroutine 退出时释放。等待方不再额外起 goroutine。
- **快池契约**：`Get` 在启动加载前拒绝快阶段（`LoadedEntitiesOnly` 含 `fctx.InFastWorker`）；加载 goroutine 不是快 worker，`NestMgr.RunLocal` 的 fail-fast 检查对它放行；发布始终在快 worker 上（nest 回归断言）。
  领头方离开时等待 `leaderMu` 只发生在慢 worker / 普通 goroutine 上，所等的快续行不依赖该 goroutine。
- **停机链与 RR-17“超时保留所有权”**：loader 注销早于 DataEngine Flush / Projector.Close，取消的加载只读不写，不影响 WAL / checkpoint；`Runtime.stop` 的“Close 返回 nil 才标记已关闭”未改。
  Nest 先于 DataEngine 停止：仍在等待的领头消息用自己的快续行发布（排空期可用）；领头方已离开的加载在 Nest 停止后得到 `ErrNestStopped`，不发布。
- **加载超时值的来源与默认**：代码常量 `DefaultEntityLoadTimeout = 30s`；`ManagerAccess.ConfigureLoadTimeout` 可改；未接入配置文件（kit / 生成配置未新增键）。
- **与 RR-48 的边界**：未触碰 `entity/manager_factory.go`、`entity_guard.go` 与 Create 路径。
