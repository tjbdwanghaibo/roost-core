# RR-20261004-NC-02：Engine 一次启动尝试

2026-10-04，修前 `7e0d6ee2`。[原问题](../bug/REVIEW-2026-10-04-noncore-02.md#rr-20261004-nc-02)。已修复、声明场景验证，未发版。

根因在原 manager/engine.go:119–125：starting 只关闭注册集合，未限制第二次取得快照。现在在同一个状态锁下检查 starting/stopping，确认 Provide 后取得唯一启动权；成功、Order 失败、manager.Start 失败或已经 Stop 后的再次 Start 返回 ErrStartState。未 Provide 的前置拒绝不取得启动权，可补注册/Provide 后再调用。Kit 提供 ErrManagerStartState 同值别名，errors.Is 适用于两层。

选择显式拒绝，而非成功后的静默幂等：调用者能发现重复生命周期装配，失败后也不自动重启已部分清理的 singleton。需要新生命周期时创建新 Engine，并按业务资源契约准备 manager 实例；新 Engine 不自动证明旧 manager 可复用。未新增状态框架、不持锁调用业务、不改变 Start 中收到 Stop 的清理接管。

修前正式顺序反例 `starts=2 stops=2`；修后 `starts=1 stops=1`。新增 16 个并发重复调用全部 ErrStartState、唯一成功尝试只启停一次；Order/start 失败、Stop 前后、补 Provide、最后 Start/Stop 交错均通过。[证据](evidence/noncore-bugfix-20261004-02/README.md)。正式回归 manager/engine_lifecycle_promises_test.go，T-188。

这是公开行为收紧和新增 sentinel，未改已有函数签名：依赖同一 Engine 自动重试的业务必须调整。没有迁移持久数据；所有用户 manager 的 Start panic/永久阻塞、完整 App 重启链未验证。
