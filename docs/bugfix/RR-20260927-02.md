# RR-20260927-02 修复：`CloseSessions` 按“这次调用是否关掉了会话”计数

问题：[RR-20260927-02](../bug/RR-20260927-02.md)（[OPEN-ITEMS-2026-09-27](../review/OPEN-ITEMS-2026-09-27.md) A02）。
日期 2026-09-27；实施基线 main `d4234c9`（worktree `scratchpad/wt-r7-gen`，分支 `fix-r7-gen`，在 RR-20260927-01 之后）。状态：已修复，本地验证通过，已本地提交，未推送 / 未发布。
图谱说明：codebase-memory 图谱已过期（generation 09-26），行号与结论来自源码。

## 决策（按清单推荐）

生成的 `session` 增加未导出的 `close(reason) (first bool)`：原 `Close` 的 `closeOnce.Do` 主体原样搬进来，在 `Do` 的函数里置 `first = true`；
`Close` 改为调用它并照旧返回 `closeErr`（对外签名、返回值、`gateway.Session` 语义不变）。`closeSessions` 改为 `if current.close(reason) { closed++ }`。
于是：

- 本次调用关掉的会话计 1；
- 已被别的路径（网络错误、同 SessionID 替换、上一次 `CloseSessions`）关掉、只是读循环还没注销的会话不重复计数；
- `Close` 的返回值仍是关闭原因（`reason` 与连接关闭错误的 join），其他调用方不受影响。

未采用：改 `Close` 的返回值（`gateway.Session` 接口的语义，其他调用方依赖返回原因）；在 `closeSessions` 里比较 `closeErr` 与 `reason`（关闭原因可能相同，判不出是谁关的）。

## 文件与行为

- `codegen/internal/roost/render_player_tcp.go`（生成 `internal/access/player/tcp/server_gen.go` 与 `server_gen_test.go`）：`closeSessions` 计数方式与注释、`session.close`；
  生成测试新增 `TestCloseSessionsCountsTheSessionsItClosed`（真实 loopback 服务器上一个玩家两条连接：第一次 `CloseSessions` 返回 2，紧接着再调返回 0，
  两条关闭事件各一次、连接槽释放后再调仍为 0）。
- 生成工程行为变化：`Runtime.CloseSessions` 返回实际关掉的会话数；game-demo 所有权围栏日志的 `sessions_closed` 随之是真实值。已生成工程需重新生成（`server_gen.go` 是生成文件）。

## 兼容性

无导出 API 变化；`CloseSessions` 返回值从恒 0 变为真实计数——仓外若有人依赖“返回 0”判断什么，行为会变（godoc 一直写的是“reports how many it closed”）。
