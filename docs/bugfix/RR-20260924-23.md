# RR-20260924-23：整批 Remote 准入共享可取消预算

问题见 [RR-20260924-23](../bug/RR-20260924-23.md)。已实施，未发布。

## 修复

1. `manager.go:getOrCreate` 仅构造本地协调状态，不预读 Redis。保留 `markerUnknown`，由既有写入/ownership 准入路径进行必要的权威读取，读取失败仍拒绝准入。
2. `PrepareRemoteWriteBatch` 在遍历实体前建立唯一准入 deadline，所有实体共享剩余时间。
3. `ownershipContext` 统一使用 `context.WithTimeout`，取调用方 deadline 与框架 `OpTimeout` 的较早值；`beginWrite` 使用同一规则，保留写闸排队预算。
4. 补充中文契约注释，不新增包或公开 API。

## 验证

- 修前冷写入、冷 ownership 取消及多实体共同 deadline 三项失败；修后 Remote 全包 race 通过。并发 wrapper 构造测试保持 32 请求共用同一对象，并断言构造不执行 RPC。
- 真实 Redis 经独立 Toxiproxy 注入 1500ms 下行延迟，调用方 50ms deadline、框架 1s `OpTimeout`：冷准入在 **51.960166ms** 返回 `context deadline exceeded`。这是单次故障观察，不是生产延迟保证。
- 关联 10 个有测试包 race、集成标签 vet、真实 Redis 所有权/精确锁计数和 Mongo/WAL 恢复回归通过。
- 正式 DAO/Entity 生成工程的 Nest → WAL/Mongo → Remote → NATS 接收，在 async/strict/pipelined 三种模式下通过。

复跑入口及故障结果见 [Remote 第三轮验收](../feature/REFACTOR-2026-09-24-remote.md#第三轮进程故障与正式业务链路)。修前日志 `/tmp/roost-remote-admission-red.log`，修后 `/tmp/roost-remote-admission-green.log`，网络延迟 `/tmp/roost-remote-round3-process-final.log`；核心证据已记录于本文。

## 边界

此预算覆盖准入阶段的排队、权威读取和加锁，不是业务执行、提交、发布与失败清理的总期限。清理仍需履行已有解锁责任；第三方实现若忽略 context，框架无法强制中断它。
