# NC-142 修复：过期截止时间武装为下一次 Tick 触发

[问题](../bug/RR-20261005-NC-142.md) · [证据](evidence/noncore-bugfix-20261005-revn11/README.md) · [本轮](../review/REVIEW-2026-10-05-n11.md)。已修复、声明场景验证，未发版。

## 根因与修法

`ScheduleActivityPhase` 把已过期的 `delay` 置 0，而 `timer.NewTimer` 拒绝非正延迟、返回 0；方法仍报告 armed。改为 `delay <= 0` 时用 `overdueDeadlineDelay`（1ms，节点存储精度）——下一次 Tick 触发；返回值改为 `(id, id != 0)`，不会再在没有节点时报告已武装。`timer.NewTimer` 的拒绝契约不变。

旧用例 `TestADeadlineThatIsAlreadyPastStillFires` 是空断言（节点不存在时“剩余 0 个节点”照样成立），替换为 `TestAnOverdueDeadlineIsArmedAndFires`：断言 id 非 0、节点在堆和 DAO 里、下一次 Tick 带着 phase effect 触发，覆盖过期一小时与恰好到期。

## 兼容

模板改动；当前唯一调用方 `openCurrentWindow` 武装的 closeAt 总在 now 之后，正式路径行为不变。
