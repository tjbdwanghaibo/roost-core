# NC-214 修复：effect、filter、cost 里的 status / attribute / resource 名字在 authority pass 检查

[问题](../bug/RR-20261005-NC-214.md) · [本轮](../review/REVIEW-2026-10-05-n09-batch4.md)。已修复、声明场景验证，未发版。

## 根因与决策

`lower.go` 的 `lookupStatusHandle` / `lookupAttributeHandle` / `lookupResourceHandle` 对未知名字返回 handle 0，而这些名字在编译期没有检查（`skill/README.md` 的 pass 表却写着 authority_capability “不在目录内即拒绝”）。在 `compile_capability.go` 补两处：

- `validateCatalogReferences`：costs / sustain costs 与 resource effect 的 `resource`、add / remove_status 的 `status`、attribute_modifier 的 `attribute`；
- `validateTargetFilterList`（select 与 area 共用）：has / missing_status 的 `status`、attribute_compare 的 `attribute`。

都报 `CAPABILITY_UNKNOWN` 到对应字段，与 damage_type、element、tag、collision 的既有检查同一形态。

## 文件与行为

`skill/compile_capability.go`、`skill/README.md`（pass 表补“effect、filter、cost 里的引用”与 key 唯一）。名字不在 catalog 的定义编译失败；合法定义不变（控制 `TestCatalogConsistentEffectsStillCompileAndRun` 修前修后都 ok，含 mul_bp 修饰、加减状态、spend、两种 filter、chain fixture）。

## 回归

`TestCompileRejectsUnknownCatalogNames` 八个子用例（add_status、remove_status、attribute_modifier、resource、cost、has_status、attribute_compare、sustain cost）修前全部 `compiled; diagnostics=[]skill.Diagnostic(nil)`，修后 ok。
