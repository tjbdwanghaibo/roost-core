# NC-165 修复：Close 撤下文件 sink 后重建默认 logger，写控制台或 stderr

问题：[RR-20261005-NC-165](../bug/RR-20261005-NC-165.md)。2026-10-05，分支 `revn12`，基线 `45d4bc1c`。

## 决策

- `Init` 记住非文件输出（`Output` 或 stdout，只配文件时为 nil）与选项；`Close` 关文件后用同格式重建默认 logger：有控制台输出就只写它，否则写 `os.Stderr`。
- 调用方在 Init 之后自己 `slog.SetDefault` 过别的 logger 时，Close 只更新本包 `Default()`，不覆盖调用方的 slog 默认值。
- 未采用：Close 后保持旧 logger、让写失败时回退——需要在 handler 里感知写错误，复杂且每行多一次判断。也未改 `app.run`（属 N01 / singleton 另一线）：让它在关闭前把最终错误写进文件仍是建议，见运行记录观察。

## 文件与行为

`log/log.go`（抽出 `newLogger`）；回归 `log/close_fallback_promises_test.go`（只配文件时 Close 之后写 stderr；有控制台输出时 Close 之后仍写控制台；Close 前的行在文件里）。行为变化：只配文件 sink 的进程在 Close 之后的日志出现在 stderr。
