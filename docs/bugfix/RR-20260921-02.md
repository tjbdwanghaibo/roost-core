# RR-20260921-02：demo-publish 从未发布过任何东西（U-0274）

- 等级：P2
- 位置：`.github/workflows/demo-publish.yml`
- 审查记录：[REVIEW-2026-09-21](../bug/REVIEW-2026-09-21.md)
- 缺陷类：C5（静默吞错：一条从未成功的流水线与一条不存在的流水线，在日志之外没有区别）

## 问题

`gh run list --workflow demo-publish --limit 30` → **0 次成功**，合仓前后都一样。固定失败在最后一步：

```text
! [remote rejected] demo-generated -> demo-generated
  (refusing to allow a GitHub App to create or update workflow
   `.github/workflows/ci.yml` without `workflows` permission)
```

`demo-generated` 分支被 README 与 GENERATED.md 当作"可克隆可阅读的最新 demo"，而它从来没有被更新过。

## 根因

生成工程**自带一份 `.github/workflows/`**（`roost new` 的产物包含 CI），而 Actions 的 `GITHUB_TOKEN`
不被允许创建或修改 workflow 文件。三仓合一仓（P5）修好了它前面的所有步骤，反而让这最后一段露出来——
在那之前它总是更早地失败。

## 方案选择

| 方案 | 取舍 | 结论 |
| --- | --- | --- |
| 换带 `workflow` scope 的 PAT | 内容完整，但多一个要轮换的密钥，且本仓当前没有这个 secret | 未采用 |
| 推到另一个仓库 | 同样要凭据 | 未采用 |
| **把 `.github/workflows/` 挪成 `generated-github/workflows/`** | 不需要任何新凭据，内容一份不少，只是换了个目录名 | **采用** |

**没有删掉那些 workflow**：它们是读者想看的东西之一，而且是从本仓模板生成的。GENERATED.md 里加了一节
说明它在哪、为什么换名、克隆后改回来即可。维护者将来愿意配 PAT 的话，换回原路径是一行改动。

## 改动

- 推送前把 `.github/workflows` 移到 `generated-github/workflows`（目录不存在时跳过）。
- GENERATED.md 增加 `## generated-github/` 一节，写明原因与恢复方法。
- 触发恢复为 push main + 手动（合仓期间它被改成只手动）。

## 证明

`actionlint` 通过。**这一条的真正验收是"流水线成功一次"**——这个条件从未被满足过，要等它在 main 上跑一遍。
本地无法复现远端的 workflow-file 拒绝（那是 GitHub 侧的策略）。

## 未做 / 边界

- 没有验证 PAT 方案；如果维护者更希望发布的树保留原始 `.github/` 路径，那是配一个 secret 加改两行的事。
- 发布内容变了：克隆下来的树不能直接被 GitHub 识别为带 CI 的仓库，要先把目录改回去。
