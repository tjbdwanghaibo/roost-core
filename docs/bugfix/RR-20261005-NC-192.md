# RR-20261005-NC-192：生产校验只要求有读取方的设置，生成的生产配置打开 `env: production` 可以启动

2026-10-05，基线 `bb3aa647`。**已修复、声明场景验证，未发版。** [问题](../bug/RR-20261005-NC-192.md) · [维护者决定 C1](../review/DECISIONS-PENDING-2026-10-05.md)（随 A4 按方案 1）· [A4 方案](../feature/REFACTOR-2026-10-05-strict-config-reads.md) · [证据](evidence/a4-config-20261005/README.md)。

## 根因

`app/config_validation.go` 的 `validateProductionServiceConfig` 按服务名要求一组开关为 true：`player.login_auth_required`、非 dev 的 `player.login_secret`、`player_protocol.rate_limit.enabled`、`save_load.wal.enabled` / `required` / `mode=durable`、拒绝 `instance.client_mode=local`、`instance.state_store_required`、非 dev 的 `account.ops_token`、`account.redis_required`、`global.redis_required`、`match_group.redis_required`。这些键来自开源初版的服务形态，之后接入、持久化与服务实现都换了，全仓没有任何读取方（`app.go` 只对 `player_protocol.rate_limit.enabled` 设了缺省值）。生成的生产配置不写它们，打开 `env: production` 后 game / account / global 起不来；写上它们只是让校验放行，却让人以为限流、登录鉴权、WAL 持久已经打开。

## 修法（方案 1）

- `validateProductionServiceConfig` 只保留有读取方的要求：ops 端点不绑公网（或声明 `ops.allow_public_addr`）；game / instance / account / match_group / global 写了 `redis.addr`；account 的 `session_secret`、platform 的 `session_secret` / `payment_secret` 不是空的或 `dev-` 开头；admin_gateway 的令牌。函数注释写明删掉了什么、为什么，以后接入真实的限流 / 鉴权开关时再加回。
- 删掉 `app.go` 对 `player_protocol.rate_limit.enabled` 的 `SetDefault`。
- 生成器与模板里没有这些键（`rg` 无结果），不用改。
- `docs/USER_GUIDE.md` §10 新增“`env: production` 校验什么”。

没采用：方案 2（把要求换成真实生效的键）需要先在生成接入里装配按请求限流与真实鉴权开关，属于 N02 / N08 的功能工作；方案 3（只改措辞）误导仍在。

## 兼容

放宽：以前为了通过校验写下的这些键不再被要求，留在配置里也没有影响（它们本来就不控制任何行为）。仍有读取方的要求不变。`env: production` 不再给出“框架有限流 / 登录鉴权开关”的提示——生成的游戏服接入层既没有按请求限流，也只有演示凭据，上线前要自己接入（USER_GUIDE 写明）。
