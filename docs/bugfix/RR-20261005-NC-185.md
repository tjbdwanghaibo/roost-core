# NC-185 修复：KeyMap.Range 每桶先复制再调用回调

[问题](../bug/RR-20261005-NC-185.md) · [证据](evidence/noncore-bugfix-20261005-revn13/README.md) · [本轮](../review/REVIEW-2026-10-05-n13.md)。已修复、声明场景验证，未发版。

## 根因与修法

`container/keymap.go` 的 `Remove` 交换删除，`Range` 遍历活切片，回调删当前键后漏掉换过来的键并交出清零的末尾。改为：每个桶从 `m.buckets` 现读、复制进一个复用的局部切片后再调用回调。回调里 Set / Remove 不再影响本桶的遍历；回调里 Clear 后，后续桶已是空的，不再交出。

未采用：保持活遍历、按“当前位置是否被换”回退下标——回调删除一个已经走过的键时，换过来的未到达键仍会被跳过，修不全。

## 兼容

语义与 `SmallSafeMap` / `ShardedSafeMap` 相同：本桶开始遍历后被删除的未到达键仍会交出。每次 Range 至多一次随最大桶增长的分配。仓内零调用方。
