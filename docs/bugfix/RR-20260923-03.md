# RR-20260923-03 修复：对象替换先释放引用，再分配

- 问题：[RR-20260923-03](../bug/RR-20260923-03.md)。状态：已修复并验证，未发布。

## 改动

`session.encode` 将 remove 排在其他操作之前，组内仍按 subject ID 升序。使用项目 Go 1.27.0 工具链提供的 `slices.SortFunc` 与 `cmp.Compare` 表达顺序，不使用相减比较，避免整数溢出。

容量仍然检查会话实际持有量，真实超限仍拒绝。删除与新建在同一帧或按 MaxObjects 分成多帧时，旧引用均先释放，新 generation 仍由现有 allocate 逻辑分配。

公开 API 与线格式不变；含增删混合操作的帧内/跨帧顺序变成先 remove。同类操作仍确定排序，客户端按协议顺序应用。

未抬高 Go 版本，未改变容量配置，未运行游戏客户端端到端。
