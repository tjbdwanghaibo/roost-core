# RR-20260928-01 修复：卸载重载积压 gauge 按进程汇总

问题：[RR-20260928-01](../bug/RR-20260928-01.md)（OPEN-ITEMS B42）。日期 2026-09-28；基线 `9568140`；worktree 分支 `fix-r9-b15`。
codebase-memory 图谱停在 09-26，已过期，未使用；以源码为准。

## 根因

`entity/unload_resync.go:172`（基线）`publishBacklogLocked` 对无标签 gauge `entity.unload_resync.backlog` 写本接线的绝对值 `len(r.jobs)`；
`:101` 的注释假设“每个服务一个 ManagerAccess”。一个进程里有多个 ManagerAccess（多个 EntityManager、测试或工具进程）时，gauge 只是最后写入者的值，
一个接线 `stop` 写 0 还会抹掉其余接线仍在的积压。

## 决策

- 按修复约束：gauge = 进程内全部接线积压之和；每个接线记住自己已计入的份额 `unloadResync.published`（受 `r.mu` 保护），`jobs` 变化时只把差值
  `len(jobs) - published` 记进包级 `unloadResyncBacklog.total`，并**在同一把锁下**写出 `total`。加法和写出放在一起，是为了不让两个接线并发时一个用旧和
  覆盖另一个的新和（只用 `atomic.Add` 再 `SetGauge` 会有这种乱序）。
- `stop` 仍 `clear(jobs)` 后调用 `publishBacklogLocked`，份额变 0，只撤回本接线自己的部分；已停止接线之后的 `delete`（空操作）也不会再改份额。
- 仍写绝对值（`SetGauge(total)`）而不是 `AddGauge(delta)`：测试会切换默认 `metrics.Registry`，按差值累加在新 Registry 上会从旧接线的份额中间开始，出现负数；
  绝对值写到当前 Registry 与原行为一致。
- 标签仍为空，不按实例打标签（低基数）。`UnloadResyncStats.Backlog` 仍是本接线的值（godoc 写明 gauge 是各接线之和）。
- 快池约束：`schedule` 在快池里调用，新增的是一把叶子锁（持有 `r.mu` 时再取，锁内只有一次加法和一次 `SetGauge`，没有 I/O 或等待其他任务），不是新的等待入口。
  锁顺序固定为 `r.mu` → `unloadResyncBacklog.mu`，后者内不取任何其他锁（`SetGauge` 只取 Registry 自己的锁）。
- 未采用：`metrics` 注册回调式 gauge（`metrics` 没有此能力，新增 API 超出本条范围）。

## 文件与行为

- `entity/unload_resync.go`：`unloadResyncBacklog`（包级 `mu` + `total`）、`unloadResync.published`、`publishBacklogLocked` 改为调整本接线份额；
  `unloadResyncBacklogMetric`、`UnloadResyncStats`、`UnloadResyncConfig` 的注释改为“进程内全部接线之和 / 本接线”。
- `docs/USER_GUIDE.md` 卸载后重载段：积压 gauge 是进程内全部 ManagerAccess 之和，`UnloadResyncStats().Backlog` 是单个 ManagerAccess。
- 回归：`entity/unload_resync_backlog_promises_test.go` `TestUnloadResyncBacklogSumsAcrossManagerAccesses`（由探针 `probes-r15/zz_b42_probe_test.go` 改写）：
  两个接线各自 Workers=1、loader 卡住，积压 3 + 2 → gauge 5、无标签；停掉第二个 → gauge 3（= 第一个的 Backlog）；两个都停 → 0。

## 兼容性

一个进程只有一个 ManagerAccess（生成的单服务进程）时数值与之前完全相同；多个时 gauge 从“最后写入者”变为总和（此前的值本来就不可用）。无 API 变化。

## 未验证项 / 风险

- 没有在真实多 EntityManager 进程里观测；汇总逻辑由单测覆盖。
- 若将来某个接线在未调用 `stop` 的情况下被丢弃（当前 `ConfigureUnloadResync` 只替换已停止的接线），它的份额会留在总和里；现有唯一的接线来源（kit Nest Mod）在停止时调用 `stop`。
