# RR-20261006-70 修复：JetStream RPC handler 执行期间发 in-progress，只持续到请求期限

问题：[RR-20261006-70](../bug/RR-20261006-70.md)（F05-3）。基线 `c78d0c34`（main）。codebase-memory 共享 generation 停在 09-30（比基线旧），按 worktree 当前源码。分支 `remfix`（同批 RR-20261006-68～74，F05-1～F05-7、F09-R2、F09-R3）。

## 决策

- 维护者给的二选一里选 **in-progress ack**：`fnats.JetStreamMsg` 新增 `InProgress func() error`（驱动填 nats.go 的 `msg.InProgress`，测试替身为 nil）；`bus.onJetStreamRPCRequest` 在 handler 执行期间每 `AckWait/2` 调一次（`keepJetStreamRPCInProgress`，一个可停的定时器，不是每请求一个 goroutine）。
- **心跳只到请求期限**：`processCtx` 结束（调用方截止到达或 Bus 停止）后不再续。期限之后调用方已放弃，broker 重投，收到的实例按 `DeadlineAt` 判过期、直接确认、不执行；handler 卡死时也不会无限占着这条消息。
- **未采用**：把 handler 期限封顶到 AckWait 以下并在启动时校验“处理期限 < AckWait”——会把调用方给的更长期限静默截短（正是 F09-R2 那类问题），而且 `call_timeout` 与 `ack_wait` 分属调用方与被调方进程，启动校验只能看见一端。
- 心跳失败（连接抖动）只记 `bus_rpc_in_progress_failures_total` 与 Warn 日志，退回 at-least-once。

## 文件与行为

| 文件 | 改动 |
| --- | --- |
| `nats/jetstream.go` | `JetStreamMsg.InProgress` |
| `nats/driver/jetstream.go` | 投递时填 `InProgress` |
| `bus/jetstream_rpc.go` | `keepJetStreamRPCInProgress`；`onJetStreamRPCRequest` 在构造 `processCtx` 后启用 |
| `kit/nats/jetstream_rpc_ackwait_real_promises_test.go`（新，integration） | 先红：真实 JetStream，两实例共享 durable，handler 2.5s > AckWait 1s，只执行一次 |
| `bus/jetstream_rpc_in_progress_promises_test.go`（新） | 心跳边界：期限之前持续、期限之后停、stop 之后停、无能力时不出错 |

## 兼容性

`JetStreamMsg` 加字段（结构体字面量按字段名写的调用方不受影响）。新指标 `bus_rpc_in_progress_failures_total`。
