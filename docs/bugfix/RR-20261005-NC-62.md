# NC-62 修复：生成期拒绝框架无法表示的属性声明

[问题](../bug/RR-20261005-NC-62.md) · [证据](evidence/noncore-bugfix-20261005-n07/README.md) · [本轮](../review/REVIEW-2026-10-05-noncore-n07.md)。已修复、声明场景验证，未发版。

## 修法

`codegen/internal/attribute/parse.go` 的 `buildProfile`：

- `max` 超过 64（dirtyMask 位数）或 `index + max - 1` 超过 65535（AttrID）时报错，说明哪条限制；
- 字段类型是 `float32` / `float64` / `complex64` / `complex128` / `bool` / `string` 时报错并建议用缩放整数（如万分比）。float 会编译、会静默截断，是本条要堵的；其余本来编译不过，生成期报出字段名更好定位。

## 兼容与限制

已有整数声明不受影响（新增控制覆盖 int8～int64、uint8～uint64、int、uint 与满 64 位 + 贴近 AttrID 上限的范围）。之前声明了 float 字段的工程会在下次生成时失败——此前它的值本来就在导出 / 持久化时丢失，失败是把静默丢值变成可见错误。具名类型（`type Rate float64`）语法上无法判断底层类型，仍按原样生成，写在 `notCarried` 注释里。`SetAttr` 对超范围值按 Go 转换回绕保持不变（文档写明的“生成 setter 转换”）。

## 验证

- 修前：`TestParseDirRejectsAttributesTheWireCannotCarry` 6 叶子全部被接受；临时模块中 float 0.15 导出为 0、65 字段生成物编译失败。
- 修后：同用例 6 叶子 + 整数控制通过；`go test -race -count=3 ./codegen/internal/attribute/`、`sh codegen/scripts/attribute-runtime.sh` 结果见本轮记录。
