# RR-20261006-56 修复：标记选项收敛到 `marker.Spec`，未知键一律报错

问题：[RR-20261006-56](../bug/RR-20261006-56.md)（F12 G1、F09-R4 marker 拼写一项）。基线 `a9c211e9`，分支 `genfix`，提交 `63573f33`。代码阅读以当前源码为准（codebase-memory 共享 generation 停在 09-30，未用它下结论）。

## 根因

每个生成器自己拆 `key=value`，多数只取认识的键、其余丢掉；缺省值在键缺席时生效，于是拼错的键 = 没写 = 缺省（指到行见问题记录）。

## 决策

- `codegen/internal/marker/options.go` 新增 `Spec{Kind, Keys, Flags, Renamed}`、`Spec.Parse`、`CheckFile`，以及全部 15 种带选项标记的词表（nest、dao、redisdao、attribute、proto、protocol、msg、view、table、object、rpc、entity、mirror、web、register）。`Parse` 拒绝未知键、重复键、非 flag 的裸词、带值的纯 flag、空键、改名的旧键；`CheckFile` 在生成器解析完一个文件、读任何选项之前跑一遍，错误形如 `path:line: unknown marker option "durabilty" in //roost:nest (known: rollback= durability= sync= target= targets= sync)`。
- 宽松的生成器（nest、dao/redisdao、attribute、protocol 四种、tablegen 两种、servicerpc）调用 `CheckFile`；原本已严格的 entity / mirror / web / register 的拆分改走 `Spec.Parse`（entity 的 `syncTopic` 改名提示成为 `Renamed`；web 仍要求三个键齐全且值非空；register 的未知键检查前移，不再被“缺 phase=”盖住）。
- 兼容现有写法：nest 的 `sync` 既可裸写也可 `sync=true`；dao 的 `nocoll` 只能裸写（`nocoll=true` 仍报“bare flag”）。
- `rpc` 一份词表覆盖接口与方法两处（`service_type`、`capability`、`affinity`、flag `reliable`）：拼错一律报错；“键放错位置”（如把 `affinity` 写在接口上）不在本条范围。
- protocol 的四个正则改用 `marker.Regexp`，`id.go` 的扫描正则改为 `//(?:roost|cube):`，不再接受任意前缀。
- eventgen、errcode 不读标记（已核对），不涉及。

结构性守卫（`codegen/internal/marker/typo_guard_test.go`）：
1. `TestEveryMarkerRefusesAMisspeltKey`：每种标记经它所属生成器的 `Run` 喂一个拼错的键，错误必须带 `"<键>"` 和 `文件:行`（16 例，rpc 接口 / 方法各一）。
2. `TestEveryMarkerKindHasASpecAndAGuardCase`：扫描 `codegen/internal` 非测试源码，凡经 `marker.Cut/Has/Regexp`、`hasMarker`、`markerKind` 读取的标记种类都必须有 `Spec`，每个 `Spec` 都必须有上面的用例；源码里出现手写的 `//[a-z]+:` 正则即失败。

未采用：各生成器各自补白名单——会再出现第 16 种标记忘记补的情况，守卫也无处挂。
