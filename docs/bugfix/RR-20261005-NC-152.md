# NC-152 修复：作者写的 tick 非负在 shape pass 集中检查

[问题](../bug/RR-20261005-NC-152.md) · [本轮](../review/REVIEW-2026-10-05-n09-batch3.md)。已修复、声明场景验证，未发版。

## 根因与决策

`Tick` 是 `int64`，非负规则按字段散落在 shape / typecheck / motion / budget 各 pass，五个字段没有规则；负 wait 只被预算 pass 在 `$` 以饱和后的 MaxInt64 报出。`compile_shape.go` 新增 `requireNonNegativeAuthoredTicks`，与已有的 global_cooldown / cast window 检查放在一起：`cooldown_ticks`、`phases[i].timeout_ticks`、wait `ticks`、repeat `interval_ticks`、chain `hop_interval_ticks`、add_status `duration_ticks`，负值报 `SHAPE_INVALID` 并指向字段。

未采用：给 `Tick` 加拒绝负数的 `UnmarshalJSON`——`Tick` 同时用于 Runtime / checkpoint / sync 的 JSON，影响面超出 wire；按键名后缀在扫描器里检查——依赖命名约定。已有检查的字段（motion、process、numeric track、状态生命期、policy）不重复。

## 文件与行为

`skill/compile_shape.go`。负值定义在启动期编译失败；0 与正值不变；负 wait 现在先在 shape pass 以字段路径失败，不再走到预算 pass。
