# RR-20261006-35 修复：带索引写的 NaN 分数在发出前拒绝

[问题](../bug/RR-20261006-35.md)。分支 `a2t`（A2 ③ 实施中发现，同一提交）。

## 根因

`redis/cas.go` 的 `compareAndSetIndexedScript` 先写值、后 `ZADD`；`ZADD` 拒绝 NaN 时值已写入，脚本不回滚。`CompareAndSet` 只校验了索引 key 与 member 非空，没有校验分数。

## 决策

- 在 `CompareAndSet` 里发出前拒绝：`Index.Remove == false` 且 `math.IsNaN(Index.Score)` 时返回包了 `ErrCASInvalidCommand` 的错误，什么都不发。`±Inf` 是 Redis 合法分数，不拒绝；`Remove` 时分数不用。
- 未采用：在 Lua 里先校验分数再 `SET`——要在脚本里复刻 Redis 的浮点解析规则，跨语言更容易不一致；Go 侧拒绝更早、更明确。未采用：versionstore 里校验——`CompareAndSet` 是带索引写的唯一入口，放在这里所有调用方都受保护。
- 替身先改忠实：`fakeRedis` 的带索引 compare-and-set 在 ZADD 拒绝 NaN 时（值已写入）返回带 `RedisError()` 的错误回复，在修前实现上确认变红，再改实现。

## 文件与行为

- `redis/cas.go`：`CompareAndSet` 拒绝 NaN 分数（`ErrCASInvalidCommand`）。
- `versionstore/fake_redis_test.go`：ZADD 拒绝 NaN 时 SET 已生效、返回错误回复（与 Redis 一致）。
- `versionstore/index_score_promises_test.go`：替身上的红绿。
- `versionstore/write_token_integration_test.go`：`TestRealRedisAnIndexedWriteWithANaNScoreChangesNothing`（真实 Redis）。

## 兼容性

行为收紧：`Entry` 返回 NaN 的写现在返回 `ErrCASInvalidCommand`、不写入；以前会“写入但报错”。仓内调用方的分数都来自整数时间，不受影响。

## 未验证 / 风险

带索引脚本里 `SET` 之后的 `ZADD` / `ZREM` 遇到 `WRONGTYPE`（索引 key 被别的类型占用，属于键空间配置错误）同样会“值已改、报错”；那是部署错误，A2 ③ 对服务端错误回复原样返回、不核对不重发，行为与改前相同，本条不处理。
