# RR-20260920-10：后台工作取得的所有权永不归还（U-0269）

- 等级：P2（可用性；定级低是因为不毁数据，不是因为后果轻——这是一个付费玩家进不来且不会自愈的故障）
- 仓库 / 位置：roost-codegen `demo/internal/service/game/playerowner.go.tmpl`
- 审查记录：[REVIEW-2026-09-20-03](../bug/REVIEW-2026-09-20-03.md) · 复现附录 [REPRO-2026-09-20-03](../bug/REPRO-2026-09-20-03.md)
- 缺陷类：C8（快慢路径不对称：登录取得的所有权有人管，后台取得的没人管）

## 问题

一次给**离线**玩家的赠礼步骤（或邮件、或已付款订单）落在 A 进程：`Owns` 发现无人持有，就地 Claim 并答 true。
这把租约之后再也回不去——`Release` 没有调用方，Player 实体永不 Destroy，`refreshLoop` 无条件续租。
登录侧是 fail-closed 的（U-0259 的正确部分），于是这个玩家此后**只能**从 A 登录，落在别处按名拒绝
`player_elsewhere`。A 不重启就不会结束。

## 根因

`Owns` 取得所有权是对的：离线玩家的工作不能等他上线。错的是取得之后没有任何东西表达"这把租约是为一件事借的"。
`local` 里一个 id 就是一个 id，刷新循环分不出它是一条活着的会话还是一次后台工作的残留。

## 方案选择

| 方案 | 取舍 | 结论 |
| --- | --- | --- |
| 后台租约标记成一次性，工作完成即 Release | 需要每个消费者在正确的位置调用归还，漏一处就退化成原样 | 未采用 |
| 登录侧加跨进程移交协议（owner 收到请求后卸载并 Release） | 最干净，但要新增一条跨进程请求与它的失败语义 | 未采用：超出本单元 |
| **按"有没有人在用"自动归还** | 判据是本地已有的事实，不需要消费者配合，也不需要新协议 | **采用** |

规则一句话：**这个玩家在本进程没有连接，且这把租约在 `HandBackIdle`（两个刷新间隔）内没有回答过任何问题，
就还回去。** "回答过任何问题"= 一次 `Admit` 通过（网关上的每条消息、每个消费者的 `Owns` 都走它），
所以正在重试的步骤不会被从脚下抽走。

顺序是全部的安全论证：**先扔副本，再归还租约**。反过来正是 U-0259 明确拒绝过的事——放走一份仍然常驻的实体，
等于邀请另一个进程加载第二份。扔不掉就保留租约（测试固定了这一条）。因此这条修复依赖 U-0268 引入的
`residentEvictor` 缝，两条一起才构成"租约与副本同生共死"。

## 改动

- `sessionFencer` 从"怎么断开"扩成"有几条连接 + 怎么断开"（`ActiveSessions`）；`*accessplayertcp.Runtime` 两个方法都有，装配不变。
- `leaseState` 加 `lastUsed`：`Admit` 通过时记一次（锁已经拿着，免费），首次 `confirm` 记一次，续租**不**记
  （否则永远不会空闲）。
- `renew` 末尾调用 `handBackIdle`：挑出空闲的 id（每轮至多 `handBackBudget=8` 个，因为每次归还都可能等一个事务），
  锁外再问一次 `ActiveSessions`（这期间重连的玩家保住租约），然后 evict → `Release`。

## 证明

新测试（生成工程 `internal/service/game/playerowner_test.go`）：

- `TestABackgroundClaimIsHandedBackWhenNobodyIsPlaying`
- `TestAPlayerWithASessionIsNeverHandedBack`（在线玩家再安静也不归还）
- `TestWorkInProgressKeepsTheLease`（每次 `Owns` 都是一次使用）
- `TestAHandBackThatCannotDropTheCopyKeepsTheLease`（扔不掉就不还）

变异验证：把 `renew` 末尾的 `owners.handBackIdle(ctx)` 去掉，
`TestABackgroundClaimIsHandedBackWhenNobodyIsPlaying` 立刻红（`the player's copy was kept: []`）。
修后生成工程 `go test ./... -race` 全绿，codegen 仓 `go vet` + 全量测试全绿。

写测试时被实现打回两次，都是**新行为正确而旧测试的世界观过时**：`TestAnUninterruptedLeaseKeepsItsPlayer`
没有给玩家一条连接，于是 50 秒之后被当成空闲归还（补 `fencer.connect`）；
`TestAHandBackThatCannotDropTheCopyKeepsTheLease` 一开始就装了会失败的 evictor，
结果连第一次认领都过不去（U-0268 的行为），改成认领之后再换上。

## 未做 / 边界

- **登出的在线玩家现在也会被归还**：`HandBackIdle` 之后没有连接的玩家，实体被卸载、租约被归还。
  这是本条的正面效果（内存回收 + 换进程登录立刻可用），但它确实改变了 demo 的常驻行为；
  下一次登录是一次冷加载。
- **没有移交协议**：玩家在 B 登录而 A 还在 `HandBackIdle` 窗口里时，仍然会被拒绝一次，等几秒重试才进得去。
  要做到"立刻可登"需要跨进程移交，记在这里备查。
- **判据依赖 `ActiveSessions` 忠实**：连接已死但传输层还没清理时会多留一会儿租约，这是保守方向。
- 没有跑两进程实测；本单元是确定性单测 + 变异验证。
