# RR-20260925-02 修复：统一 Mongo Remote 写协议

[问题](../bug/RR-20260925-02.md)。用户确认尚无新部署，因此删除未发布的兼容路径，而非增加迁移开关。

- `MongoCommitter` 默认只使用带 ownership epoch、最新 fence、base version 的批量 CAS。删除 `requireAuthority`、旧 `applyCommit` 与隐式创建提交 metadata；claim/grant 是唯一准入路径。
- `WriteAuthorityProvider.WriteAuthority()` 只返回能力，无启用副作用；Backend、Assembly、进程夹具同步改名。
- 删除 `MigrateLegacyAuthority` 及专属旧字段；不支持的 metadata 返回 `ErrRemoteAuthorityInvalid`，不自动清库或丢弃 WAL。
- 手工存储测试、真实多实体 WAL 回放夹具先取得正式 grant。新建冲突现在直接返回版本冲突，不再依赖 duplicate-key 的副作用，WAL 保留和停止准入语义不变。
- 共享 `versionedLock` 保存本代 grant，Manager 直接使用其中的 ownership，避免再读 Mongo 并拼接不同代际的信息；关闭/失效的锁不能提供有效 grant。正式 Assembly 保证锁与提交使用同一 authority。

相关 `remoteentity/nest/dataengine/engine/kit/dataengine/kit/remoteentity` race 与 integration-tag vet 已通过。新测试验证默认构造拒绝未授予写入、同事务任一过期 grant 回滚全批、冷准入仅 1 次独立 ownership 读取/缓存命中后 0 次、锁关闭后 grant 不可用。事务 digest、DAO/快照协议不变；导出 getter 改名是未发布 API 调整。真实集群与负载结果见 [报告](../feature/REMOTE-UNIFIED-2026-09-25.md)。
