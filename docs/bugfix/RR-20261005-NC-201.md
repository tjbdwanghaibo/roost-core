# RR-20261005-NC-201 修复：redis-cluster-suites.sh 清掉单机 / 全环境准入变量

日期 2026-10-05。基线 `8597046c`（审查提交 `345488e4`）。状态：已修复、声明场景验证，未发版。问题：[RR-20261005-NC-201](../bug/RR-20261005-NC-201.md)。

## 决策

`kit/scripts/integration/redis-cluster-suites.sh` 在 go test 前 `unset ROOST_DATAENGINE_IT REDIS_ADDR`，兑现注释“同包里以这两个变量准入的用例在这里照常 skip”。Cluster 用例的准入（`ROOST_REVIEW_CLUSTER`、remoteentity 的 `ROOST_REMOTE_CLUSTER_IT`）不受影响；逐个核对过 5 个包的 Cluster 用例都不依赖被清掉的变量（`remoteentity/snapshot_l2_key_prefix_integration_test.go:213-219`、`service/mail/batch_pipeline_integration_test.go:23-31` 等）。

未采用：给 go test 加 `-run`——各包 Cluster 用例名没有统一前缀，列名单会和文件漂移；准入变量才是这些用例自己的开关。

## 验证

- 红：替身 go 收到 `ROOST_DATAENGINE_IT=1`、`REDIS_ADDR=127.0.0.1:1`（[脚本](../review/evidence/noncore-review-20261005-n15/cluster_red.sh) · [输出](../review/evidence/noncore-review-20261005-n15/nc201-red.txt)）。
- 绿：两者为 `<unset>`，`ROOST_REVIEW_CLUSTER` 照常传入（[输出](evidence/noncore-bugfix-20261005-n15/nc201-green.txt)）。
- 根包 `TestRedisClusterScriptNamesEveryClusterKeyedSuite` 通过（go test 行未改）。

## 未验证

没有真实 Redis Cluster，未实跑修后的整套 Cluster 套件（与 N06 / N05 的 Cluster 外部验证同一排期）。
