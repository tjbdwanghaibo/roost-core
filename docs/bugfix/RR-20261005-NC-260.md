# NC-260 修复：driver 层 Client.Close 幂等：已断开按已关闭返回 nil

问题：[RR-20261005-NC-260](../bug/RR-20261005-NC-260.md)。分支 `revleft`，基线 `dc877c04`，[本轮](../review/REVIEW-2026-10-06-revleft.md)，[证据](evidence/noncore-bugfix-20261006-revleft/README.md)。

## 修复

`mongo/driver/client.go` `Client.Close`：`Disconnect` 返回 `mongo.ErrClientDisconnected` 时返回 nil（与 etcd `Client.Close` 的 NC-173 残余补修同处、同形）；其余错误（FLE 客户端断开失败）照常返回，Mod 保留 client 供重试。Mod 本身不改。

未采用：照 NC-233 在 Mod 里“第一次 Close 之后不论结果都交出 client”——Mongo 的 Disconnect 只有 FLE 失败这一条真正的失败路径，那时拓扑还连着，交出引用就泄漏了；在 driver 层识别“已断开”更准确，也让直接调用方受益。

文件：`mongo/driver/client.go`、`kit/mongo/stop_retry_promises_test.go`。

## 兼容

直接对已断开的 `*mongodriver.Client` 再调 `Close` 现在返回 nil（之前是 `client is disconnected`）。没有其他行为变化。

## 验证

修前红见[问题记录](../bug/RR-20261005-NC-260.md)；修后 `GOWORK=off go test -race -count=3 ./mongo/driver ./kit/mongo` 通过；不连真实 Mongo（客户端不拨号即可构造），真实部署上的断开路径未另验。 全仓 `go build ./... && go vet ./...`、根包 `go test -count=1 .`、`go test -count=1 ./codegen/...` 通过，gofmt 空（[绿](evidence/noncore-bugfix-20261006-revleft/green.txt)）。
