# RR-20260908-03：`--consolidate` 对单行 import 的混合分流产出非法 Go

**仓库 / 位置**：roost-codegen `internal/roost/consolidate.go`，`consolidateFile` 插入新 import 处
（原第 271–275 行；审查报告写的 330 是 U-0118 删掉 renames 表之前的行号）。
**修复单元**：U-0156（C2）。**定位文档**：TROUBLESHOOTING T-52。

## 问题

旧业务文件只有一条不带括号的 `import "github.com/tjbdwanghaibo/roost-kit/redis"`，又同时用到
留在 kit 的 `redis.NewRedisMod` 与搬到 core 的 `redis.NewClient`。"混合"分流保留 kit import、
为搬走的符号新增 `coreredis "…/roost-core/redis/driver"`。实现把新 spec 的文本无条件塞在
`file.Imports[0]` 之后并补 `\n\t`，默认外面有 `import ( … )`，单行输入得到一条顶层裸露的
`coreredis "…"`，`format.Source` 报 `expected declaration, found coreredis`，该文件升级失败。

## 根因

用字节偏移拼文本而不是改 AST 的 import 声明，只覆盖了括号块这一种形态；既有混合导入测试也只
用了括号块。

## 方案选择

- 把单行声明改写成括号块再插入：要重写既有 spec 的文本，可能与同一 spec 上的其他编辑（改路径、
  加别名）重叠。
- **在该声明之后另起一个 `import ( … )` 声明（采用）**：Go 允许多个 import 声明，gofmt 保留；
  插入点是声明结束偏移，与 spec 内部的编辑不重叠（编辑按偏移从后往前应用）。
- 完全按 AST 重建 import：改动最大，收益不明显。

## 改动

`internal/roost/consolidate.go`：先在 `file.Decls` 里找到包含 `file.Imports[0]` 的 `*ast.GenDecl`；
`Lparen` 无效（单行）→ 在声明结束处插入 `"\nimport (\n\t…\n)"`；否则沿用原来的块内插入。

## 证明

`internal/roost/consolidate_single_import_promises_test.go`：单行 import + 混用两类符号的工程跑
`ConsolidateProject`，断言成功、结果可 `format.Source`、同时含 kit import、`coreredis` import、
`redis.NewRedisMod` 与 `coreredis.NewClient`。

修前：`rewritten source does not format: 4:2: expected declaration, found coreredis`。修后
internal/roost 全绿（含 golden）。
