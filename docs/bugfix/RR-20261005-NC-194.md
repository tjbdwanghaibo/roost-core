# RR-20261005-NC-194：saga 步骤覆盖原样查不到时按小写回退

2026-10-05，基线 `f6245613`（审查 `efe219c1`）。**已修复、声明场景验证，未发版。** [问题](../bug/RR-20261005-NC-194.md) · [本轮](../review/REVIEW-2026-10-05-n14.md) · [证据](evidence/noncore-bugfix-20261005-n14/README.md)。

## 根因

viper 把 `saga.steps.<type>.<step>` 的键转成小写；`StepBudgetsFromConfig` 没拿到定义时只能以小写键保存覆盖，`StepBudgets.Resolve`（`saga/record.go`）按定义里原样的 `{Type, Step}` 精确查找。

## 修法

`Resolve` 先原样查找，查不到再按 `{ToLower(Type), ToLower(Step)}` 查找；原样写法的覆盖优先（代码里同时给两份时）。`StepBudgetsFromConfig` 注释补上无定义时的行为。有定义的路径（生成工程）不变。

没采用：无定义而 `saga.steps` 非空时让 Mod Init 失败——会让 `NewMod()` + `Register` 的用法完全不能按步骤覆盖。

## 验证

- 修前红见 [nc194-red.txt](../review/evidence/noncore-review-20261005-n14/nc194-red.txt)；修后 `TestPerStepOverrideAppliesToMixedCaseNamesWithoutDefinitions`（有 / 无定义）与 `TestExactOverrideWinsOverTheLowercaseFallback` 通过；`saga`、`kit/saga` `-race -count=3` 通过。

## 未验证 / 边界

只差大小写的两个类型（`Gift` 与 `gift`）同时登记时，配置无法区分它们（审查 O2），本条不处理。
