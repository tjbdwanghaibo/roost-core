# RR-20261006-69 修复：发布失败不挡投影，已 Applied 的提交由补发循环补发

问题：[RR-20261006-69](../bug/RR-20261006-69.md)（F05-2）。基线 `c78d0c34`（main）。codebase-memory 共享 generation 停在 09-30（比基线旧），按 worktree 当前源码。分支 `remfix`（同批 RR-20261006-68～74，F05-1～F05-7、F09-R2、F09-R3）。

## 决策

- **区分“已持久、发布失败”**：`ApplyRemoteCommits` 在 `CommitRemote(Batch)` 拿到回执之后（权威里已是 Applied）的失败——`afterRemoteCommit`（缓存 / 同步总线）或 `MarkRemoteCommitPublished`——返回值同时带 `ErrRemotePersistenceIndeterminate` 与新哨兵 `entity.ErrRemotePublicationPending`，并唤起补发循环。之前只带前者。
- **投影器不再为它重试**：`MongoStore.ProjectFenced` 见到 `ErrRemotePublicationPending` 把这条记为已投影（记 `dataengine.projector.remote_publication_deferred.total` 与 Warn 日志），后面的记录照常投影。其他错误（含回执读回失败——这时结果确实未知）照旧退避重试。
- **补发循环（`Manager.scheduleOutboxRepublish` / `runOutboxRepublish`）**：发布失败时唤起，按 `finalize_retry_interval` 起步、翻倍到 5s 退避执行 `RecoverOutbox`（与启动时同一路径），某一轮成功且这一轮开始后没有新的失败才退出；循环在跑时新失败只记 dirty。登记在 finalizer 的 `retryWG` 上、随 `finalizeCtx` 结束，停机排空规则不变。
- **`RecoverOutbox` 一条失败不挡同页其他提交**：之前遇到第一条失败就返回，一条反复失败的提交让排在后面的都补不上；现在继续发布同页其余的，有失败时不翻页、返回汇总错误。启动时仍以错误结束 Start（行为不变，只是失败前多发布了能发布的）。

## “发布最终会补上”的论证

1. 提交在 Mongo outbox 里是 Applied，直到某次发布成功把它标成 Committed（`MarkRemoteCommitPublished` 只认 Applied）；投影器把这条记为已投影不改变它。
2. 进程活着：补发循环反复扫 outbox 直到成功；有写者在等的事务，finalizer 照旧按持久结论（tracker 是 Indeterminate → 回源读到 Applied → `publishAppliedRemoteTransaction`，失败按退避重试）自己发布。
3. 进程停机或崩溃：outbox 仍是 Applied，下次 `Assembly.Start` 先 `RecoverOutbox` 再接受工作（已有）。
4. 重复发布无害：发布幂等，`IRemoteCommitParticipant.AcknowledgeRemoteCommit` 按契约并发安全（RR-20260926-63），投影器、finalizer、补发循环同时发布同一提交不改变结果；缓存按版本 CAS，不会被旧提交回退。

修前已有的“重放旧回执”能力（RR-20260926-11、OPEN-ITEMS B08）仍覆盖“投影失败 → 重放”：这两个端到端用例原来用“标记已发布失败”作注入，现在那种失败不再触发重放，改为注入回执读回（`CommitRemote`）失败，断言不变。

## 兼容性

- 行为变化：发布失败时投影器不再重试这条（`ProjectionFailures` 不再随总线故障增长，改看 `dataengine.projector.remote_publication_deferred.total` 与 `remote_entity.remote.republish_total{result}`）。等这条事务的 strict 写者仍得到结果未知（tracker 是 Indeterminate，由 finalizer 收尾），只是其后的写不再被一起拖住。
- 补发循环扫的是整个 outbox（不分 owner），与启动时相同；多个进程同时补发时会重复发布（幂等）。
- 新指标：`dataengine.projector.remote_publication_deferred.total`、`remote_entity.remote.republish_scheduled_total`、`remote_entity.remote.republish_total{result}`。

## 未验证 / 风险

- 一条提交的发布永久失败（例如 L1 / L2 报同版本异值）时，补发循环按 5s 上限一直重试并告警，与 finalizer 的行为相同；它不再挡投影，但会一直出现在 outbox 里，需要人工处理（T 行写了判别方法）。
- 补发循环每页最多 256 条；一页全部永久失败时排在后面的要等前面的被处理（极端情况，日志与指标可见）。
- 未在真实 Mongo 副本集上跑这条（伪 Mongo + 正式 MongoCommitter / MongoStore 代码路径）。
