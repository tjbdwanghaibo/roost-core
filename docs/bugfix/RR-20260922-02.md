# RR-20260922-02：故障矩阵合仓后烂了三处，并且没有家（U-0276）

来源：[REVIEW-2026-09-22](../bug/REVIEW-2026-09-22.md) · 复现 [REPRO-2026-09-22 §1](../bug/REPRO-2026-09-22.md)。
等级 P2，缺陷类 C2（宽容替身 / 空洞测试：报绿却漏跑）。

## 问题

`kit/scripts/integration/dataengine-env.sh test`：

1. `:120` 跑 `./dataengine ./saga ./remoteentity ./nats`——`kit/saga`、`kit/remoteentity` 的集成测试 09-08 已随实现下沉 core，
   两个目录只剩 `mod.go`，`go test` 打印 `[no test files]` 且退出 0：**两个绿格子里什么都没有**。
2. `:130` `core_dir="${ROOST_CORE_DIR:-$repo_root/../roost-core}"`——`repo_root` 合仓后是 `roost-core/kit`，
   `../roost-core` 指向不存在的目录；`:139` 打一行 "NOT run" 后退出 0：core 侧 `redis`、`redis/driver`、`etcd/driver`、
   `mongo/driver` 四个套件**静默跳过**。
3. `.github/workflows/` 里没有任何 workflow 调用它。合仓前它在 roost-kit 自己的 `nightly.yml` 的 `fault-matrix` job 里；
   `git subtree` 搬进了 kit 的代码与脚本，没搬 kit 的 `.github/`。

## 根因

三处都是同一件事：合仓把"两个仓、两份 CI"变成"一个仓、一份 CI"时，只搬了代码，没有搬**关于代码的元数据**
（包列表、路径、调度）。交接文档 §"路径即数据" 说的正是这个，这里又漏了一层。

## 方案选择

| 方案 | 取舍 | 结论 |
| --- | --- | --- |
| 脚本里包列表改成动态 `grep -rl 'go:build integration'` | 不会再漏，但脚本自己决定跑什么，读者看不出矩阵有哪些格 | 不采用 |
| 显式列表 + promise test 钉到文件系统 | 列表可读，漏了在本地就红 | **采用** |
| nightly 里重新装 mongod / nats / toxiproxy（照搬 kit 旧 job） | 每晚 ~3 分钟安装；已知在 ubuntu-latest 上跑过 | **采用** |
| 用 GitHub `services:` 容器代替脚本起服务 | Mongo 副本集三节点 + toxiproxy 用 services 写不出来 | 不采用 |

## 改动

- `kit/scripts/integration/dataengine-env.sh`：加 `module_root="$(cd "$repo_root/.." && pwd)"`；`environment_test` 改成在
  `$module_root` 下一条命令跑 `./kit/dataengine ./kit/nats ./redis/... ./etcd/driver ./mongo/driver`；删掉
  `ROOST_CORE_DIR` / "NOT run" 那一段。`up` / `down` / `fault` / `heal` 不动（它们只碰 `$ROOST_IT_ROOT`）。
- `.github/workflows/nightly.yml`：加 `fault-matrix` job——照搬 kit 旧 nightly（`/Users/whb/roost-archived/roost-kit/.github/
  workflows/nightly.yml`）的安装步骤（mongodb-org 8.0 apt、nats-server v2.14.5、toxiproxy v2.12.0、redis），
  `ROOST_IT_TOXIPROXY=1`，脚本路径改为 `kit/scripts/integration/dataengine-env.sh`。actionlint 通过。
- `integration_coverage_promises_test.go`：`TestFaultMatrixScriptNamesEveryFullEnvironmentSuite`（脚本参数必须**恰好**
  是"要整套环境"的那些包：漏一个红、多一个没有测试文件的目录也红、出现 `ROOST_CORE_DIR` 红）；
  `TestSomeWorkflowRunsTheFaultMatrix`（某个 workflow 的非注释行里必须有 `kit/scripts/integration/dataengine-env.sh test`）。

它 skip）。单独重跑 3 次：1 绿 2 红。**这不是本条的一部分，也不在本单元修**——登记为
[W-2026-09-22-01](../bug/WANTED.md)。一个"报绿却漏跑"的矩阵被修好之后立刻报出一个真红，正是这条 RR 存在的理由。
