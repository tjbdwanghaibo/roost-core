# RR-20261006-58 修复：`generate --changed` 按工程根换算 git 路径

问题：[RR-20261006-58](../bug/RR-20261006-58.md)（F12 G3）。基线 `a9c211e9`，分支 `genfix`，提交 `a461ee2f`。

## 根因

`gitChanged` 把 porcelain v1 的输出（相对仓库根、需要转义的路径加引号、rename 写成 `old -> new`）原样当作相对工程根的路径（基线 `codegen/internal/roost/generate.go:590-609`）。

## 决策

- `git rev-parse --show-prefix` 取工程在仓库里的前缀；`git status --porcelain=v1 -z --untracked-files=all -- .` 取原始、不加引号的路径，且只看工程目录内的改动；去掉前缀后交给 `filterChanged`（未改）。
- `-z` 下 rename / copy 的源路径是下一个 NUL 字段：两侧都算改动——定义文件移出生成器输入时，该生成器要运行才能回收旧产物（修前只取 `->` 右侧）。

未采用：`git ls-files -m -o --exclude-standard`——不报删除，删掉一个定义文件时对应生成器不会跑。

## 文件与行为

`codegen/internal/roost/generate.go`（`gitChanged`）；用例 `generate_changed_promises_test.go`（新）：工程在仓库子目录 + 路径带空格 + 工程外改动、rename 两侧。

## 兼容性

无配置 / 接口变化。工程在仓库根时结果与之前相同（前缀为空）。
