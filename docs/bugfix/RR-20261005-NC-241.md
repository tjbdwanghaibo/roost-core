# NC-241 修复：回调里的 SetStrategy / Shutdown 延后到最外层回调返回后执行

问题：[RR-20261005-NC-241](../bug/RR-20261005-NC-241.md)。分支 `revn10b`，基线 `81d7cb16`，[本轮](../review/REVIEW-2026-10-06-noncore-n10b.md)，[证据](evidence/noncore-bugfix-20261006-n10b/README.md)。

## 修复

Controller 记录策略回调层数（`callbacks`，Tick 里同步送达的 OnActionEnd 叠一层）；回调里的 SetStrategy / Shutdown 记为 `pending`（以最后一次为准）并返回 nil，最外层回调返回时（`leaveCallback`）执行；延后切换的错误（旧策略拒绝、新策略 Init 失败）经 OnError 报告。方向与维护者对 actionflow 的 B7 决定（回调里的变更延后执行）一致。

文件：`ai/controller.go`、`ai/switch_in_callback_promises_test.go`。

## 兼容

回调之外调用不变（同步返回错误）。回调里：SetStrategy 返回 nil、错误改经 OnError；回调返回前 `Strategy()` 仍是旧策略；同一轮多次请求以最后一次为准。`BehaviorStrategyOptions.OnResult` 里切换（树已完成并 Reset）照常生效，只是推迟到 Tick 返回。Freeze / Recover 仍立即生效。未采用：回调期间拒绝（ErrReentrantSwitch）——会让 OnResult 里切换这种安全用法失败。
