# RR-20261006-43 修复：Nest 启动消费者对确定性错误 nak 到 MaxDeliver，启动意图静默丢失；EmitStart 与 MaxPayloadBytes 上限不一致

问题：[RR-20261006-43](../bug/RR-20261006-43.md)（F06-S7）。基线 `0b223b4c`（main，v1.23.0 之后；WIP `wip/sagafix` `bcdb4bd4` rebase 到此）。codebase-memory 共享 generation 停在 09-30（比基线旧），定位与结论按 worktree 当前源码读取。
同一批（sagafix2）修 RR-20261006-42～47，一笔提交 `63bc1d66`。

## 根因

两处：`saga/nest_start_consumer.go` `handleNestStart`（基线 `:106`）不区分 `StartSaga` 的确定性错误；`saga/nest.go` `NewStartEffect`（基线 `:36`）按 4 MiB 硬上限而不是协调器的 `MaxPayloadBytes` 校验。

## 决策

- **消费者**：`startRefusalReason` 把 `ErrInvalidRecord`、`ErrIdentityConflict` 归为永久拒绝 → `Permanent`（Term），计 `saga.start.rejected_total{saga_type,reason}`（reason = `invalid_record` / `identity_conflict`），记点名 `saga_type` / `saga_id` / `business_key` / `data_bytes` 的 ERROR。`ErrDefinitionMissing` 不在其中：与结果消费者同一口径，滚动发布中定义会随新进程上线（守卫子用例断言仍可重试）。
- **EmitStart 在 Nest 事务里拒绝**：`Engine.Register` 把 `Options.MaxPayloadBytes` 按 saga 类型登记进进程表（同类型多个 Engine 取最小值），`NewStartEffect` 按它校验，超过返回 `ErrInvalidRecord`，handler 拿到错误、实体修改随事务回滚。为什么是按类型的进程表：`EmitStart` 在 Nest handler 里调用，拿不到 Engine（生成的 `<saga>.EmitStart` 是包级函数）；查表是一次内存读，不做 I/O、不等待，可以留在快池。本进程没有这个类型的协调器时只按线上硬上限 4 MiB 校验，协调器若拒绝由消费者 Term + 告警兜底。`DecodeStartEffect` 仍按线上硬上限。
- **未采用**：① EmitStart 一律按缺省 64 KiB（会拒绝协调器配了更大上限的合法意图）；② 消费者把被拒的意图写进死信集合（需要新存储与运维入口，计数 + 点名 ERROR 已够定位；业务键在日志里）。
