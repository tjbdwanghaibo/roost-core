# RR-20260924-11：统一 DataEngine 启停与清理责任

[问题](../bug/RR-20260924-11.md)。2026-09-24；已修复、未发布。

- Assembly 与 Runtime 各自用既有 operationGate 串行启停；等待者遵守自己的 context。
- Runtime ready 后重复 Start 幂等；开始停止后 Start 返回 ErrRuntimeStopped。两个入口注册成功后才启动 Outbox。
- Assembly Start 逐步记录已取得的 WAL、Projector、Outbox；失败时取消/关闭，不重新排空失败 WAL。清理超时则暴露一个 **Ready=false** 的 Runtime，下一次 Shutdown 继续等待；Start 在清理完成前拒绝覆盖它。
- Runtime 只尝试一次停机 Flush，之后重试等待同一批组件；Projector 退出后 Runtime 明确回收自己拥有的 WAL，不依赖 Projector.CloseWAL。
- API 签名、持久化格式、业务事务与 Sync 边界不变。Assembly.Runtime 在失败清理未完成时可能非 nil，调用方必须检查 Ready；Kit 的准入/健康检查已核对这一条件。

| 状态 | Start | Shutdown |
| --- | --- | --- |
| Assembly 未启动 | 构造资源并恢复 | 无资源，成功 |
| 启动中 | 等待同一所有者 | 等待或返回调用者 deadline |
| ready | 返回已有运行实例 | 撤销入口，排空一次，再关闭 |
| 失败清理/停机未完成 | 拒绝覆盖原实例 | 继续回收原资源 |
| Assembly 清理完成 | 可构造新 Runtime | 幂等成功 |
| 旧 Runtime 已停止 | ErrRuntimeStopped | 幂等或继续等待 |

新增回归覆盖上述五类问题，以及 Projector/Outbox 构造失败后重试；使用真实临时文件 WAL 和通道控制时序。修前五类分别复现，修后定向 race 通过（与 RR-12 同组 1.805s）。更大范围回归与正式依赖验证见 [DataEngine 实施记录](../feature/REFACTOR-2026-09-24-dataengine.md)。
