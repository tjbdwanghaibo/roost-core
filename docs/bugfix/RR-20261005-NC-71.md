# RR-20261005-NC-71 修复：预览先做与 sync 相同的 shutdown 块刷新；文档写准 sync / upgrade 的改写范围

[问题](../bug/RR-20261005-NC-71.md) · [证据](../review/evidence/noncore-review-20261005-n08/README.md) · [本轮](../review/REVIEW-2026-10-05-n08-codegen.md)。2026-10-05，基线 `be7bcc18`（审查基线 `50e9a4e8`）。状态：已修复、声明场景验证，未发版。

## 根因

`diffManifest`（`codegen/internal/roost/doctor.go`，`project diff` 与 `upgrade --dry-run` 共用）用磁盘上的旧配置渲染模板，并跳过已存在的非 Owned 文件；`SyncProject`（`project.go:204`）在渲染前先把三份配置里未手改的生成 `shutdown:` 块刷新到当前 Mod 计划并随同提交（RR-20260926-80）。预览缺了这一步。

## 决策

- `diffManifest` 把服务的三份 shutdown 配置（`shutdownConfigTargets`，与 `configuredShutdownTotal` 读取的集合相同）复制到系统临时目录，对副本调用同一个 `refreshGeneratedShutdownConfigs`，再用 `m.withConfiguredShutdown(副本目录)` 渲染模板——与 sync 的暂存树同一顺序、同一函数。被刷新的配置加入预览列表；`roost.yaml`（upgrade 预览）仍排第一，其余按路径排序。工程本身不被写。
- 生成器输出不进预览（`project diff` 原本就不跑生成器，`generate --check` 负责），本次只把文档写准，不扩大预览为“在暂存树里跑完整 sync”——那会让 `project diff` 也跑全部生成器、在生成输入有错时失败，成本与失败面都变了。
- 文档：生成工程 `docs/USAGE.zh-CN.md`（`render_docs.go`）改为“project diff 预览 sync 将改写的受控模板，以及配置里未手改、随 Mod 计划刷新的生成 shutdown: 块（生成器输出用 roost generate --check 检查）；sync 不覆盖业务拥有的 Service 实现，配置只刷新这一块”；`roost help project` 的 “upgrade 只覆盖 codegen 受控文件” 补上同一例外；`codegen/docs/CODEGEN_REFERENCE.zh-CN.md` 的 `project diff` 注释同步。

## 文件与行为

- `codegen/internal/roost/doctor.go`：`diffManifest` 前置刷新预演；中文 / 英文注释写明 RR 编号和“与 SyncProject 暂存树相同”的理由。
- `codegen/internal/roost/render_docs.go`、`help.go`、`codegen/docs/CODEGEN_REFERENCE.zh-CN.md`：措辞。
- 新增 `codegen/internal/roost/diff_preview_promises_test.go`：在 configdata 工程上给 `game` 加 `redis`，(a) `DiffProject` 列出的集合等于随后 `SyncProject` 的 Created+Updated+Removed，且包含三份配置，预览前后工程逐字节不变，sync 后预览为空；(b) `project upgrade --dry-run -core latest` 列出的集合（去掉 `roost.yaml`）等于随后 `commitManifestSyncResult` 的改写集合，预览不写工程。

## 兼容性

`project diff` / `--dry-run` 的输出格式不变（路径列表 + `summary: N file(s) would change`）；在 Mod 变化或停机预算公式变化后，列表多出被刷新的配置，N 随之变大。依赖 “diff 为 0” 判断模板最新的脚本：sync 之后仍为 0（`assertProjectDiffEmpty` 系列既有用例通过）。生成工程文档有一处措辞变化（`docs/USAGE.zh-CN.md`，下次 sync 更新）。
