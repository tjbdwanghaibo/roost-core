# NC-110～112 修复：施法失败只走一个终态入口

[NC-110](../bug/RR-20261005-NC-110.md) · [NC-111](../bug/RR-20261005-NC-111.md) · [NC-112](../bug/RR-20261005-NC-112.md) · [本轮](../review/REVIEW-2026-10-05-n09-batch1.md)。三条同根因，一个修复单元；NC-111 / NC-112 的记录指向本文。已修复、声明场景验证，未发版。

## 根因与修法

8 个终止点各自手写收尾（见本轮 §7 方向判断），失败路径漏掉的步骤各不相同：`startLocked` 不撤任务却复用 ID（NC-110），`Cancel` / `Interrupt` / `releaseCast` 出错直接返回（NC-111），`failScheduledCast` 与 `executeScheduledTask` 通用错误分支不释放 policy 槽位、对外 API 只看窗口阶段不看 failed 终态（NC-112）。

改法（`skill/scheduler.go`、`skill/runtime.go`、`skill/runtime_cast_window.go`）：

- 新增 `failCastLocked`：记 failed（保留第一次的原因）→ `cancelCastTasks` 撤掉本 cast 名下全部排程任务与帧（按 cast ID，不分 phase token）→ 停进程 → `releasePolicySlot` → `markAbilityCastFinished`。可重复调用。`failScheduledCast`、`executeScheduledTask` 通用错误分支、`startLocked` 的 prepare 失败都改为调它；`startLocked` 在它之后才删 cast、还 ID。
- `Cancel`、`Interrupt`、`releaseCast`（charge 重新进窗口、toggle / hold 的 release 回调）在已经改动 cast 之后出错，调 `failCastLocked` 再返回原错误。
- 新增 `castEnded`：failed / finished / 逻辑结束 / 恢复期 / 完成 / 已取消都拒绝 Cancel / Interrupt / Release，替代三处重复的窗口阶段判断。

未采用：
- 启动失败不复用 ID——ID 进入随机键派生（`deriveCastRandomKey`），改变复用规则会改变失败启动之后所有 cast 的随机序列和回放；只要残留被撤掉，复用就是安全的。
- 让 Release 付费失败保持可重试（不进终态）——同一错误经 auto release 排程本来就终止 cast，而手动路径已撤掉 auto release 任务，保留只会继续占住施法者；统一为失败终态。

## 兼容（行为收紧）

- 手动 `Release` 在 charge 重新进入施法窗口后失败（如付费不足）：cast 进入 failed，不能再重试 Release；之前停在 preparing、可重试但占住施法者。
- 对 failed cast 调 `Cancel` / `Interrupt` / `Release` 返回 `ErrCastInputRejected`；之前会执行它的 cancel / release 回调。
- 排程失败的 toggle / hold / charge 释放槽位：下一次激活开始新 cast；之前是对失败 cast 的 toggle-off。
- 已提交后失败的 cast，其失效排程任务立即撤掉（之前留到触发时丢弃），`pendingTasks` 归零后按 `CompletedCastLimit` 正常回收。checkpoint 格式与 wire 不变，只是少了这些失效任务。
