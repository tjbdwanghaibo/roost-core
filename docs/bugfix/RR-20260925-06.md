# RR-20260925-06 修复：Remote I/O 与业务执行分段

[问题记录](../bug/RR-20260925-06.md)。已实施；最终 race/vet 与 80 TPS × 10 分钟全量容量验收通过，21/21 故障矩阵通过，未部署。

## 实现

- Dispatcher 新增 Remote 慢池，默认 worker 数跟随业务 worker；`NestOptionWithRemoteWorkers` / Kit `nest.remote_workers` 可单独调整。HasRemote 或参数声明 RemoteAccessProvider 的消息进入此池，普通本地路由保持原行为。
- 慢 worker 获取快照和写批次；通过独立 Msg 信封借用原请求在 cost 逻辑池执行。原请求引用始终归慢 worker；逻辑信封回收后才关闭完成屏障，避免 RefCount 和 Msg 池竞争。
- 逻辑 worker 通过 fctx snapshot 建立独立上下文，执行 handler、FinalizeLocked、WAL 准入、Guard 解锁；随后把上下文传回慢 worker，执行 Commit、Close、确认后回调与一次性回复。
- 前置与后置由同一个慢 worker 连续持有请求，中间只等待逻辑完成，没有“所有前置 worker 都等门，而后置释放任务排在它们后面”的依赖环。
- Shutdown 排空 Remote 池后才关闭逻辑池；已准入请求可继续内部投递。内部队列满返回背压并在慢 worker 清理批次；取消/Fence 在逻辑入口再次检查。
- 增加 Remote pool stats、logic_queue/remote_prepare 阶段指标，正式负载采样分别记录 cost/remote 队列。

## 行为边界

同 key Remote 请求由慢池保持生命周期顺序；跨 key 的交叉实体继续由 Remote 写门与 Entity Guard 仲裁。RemoteAccess 的预取先于业务逻辑入队；它与不需要 Remote 的本地请求之间不承诺到达顺序。依赖这种跨路由全局 FIFO 的业务应在同一消息事务内表达依赖。

不修改 WAL/DAO/网络格式，不改变 strict 成功条件、Sync 确认时机或 5 秒默认请求等待。锁内纯内存 Abort/Indeterminate 保持原位。可配置慢池仍受依赖服务吞吐限制；隔离不等于数据库容量无限提升。
