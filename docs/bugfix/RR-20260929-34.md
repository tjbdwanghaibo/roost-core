# RR-20260929-34：Pipeline 缺失回复掩盖写错误

**已实施；原触发及下列声明场景已通过回归。**问题与修前真实反例见[第十轮记录](../bug/REVIEW-2026-09-29-services-10.md)。源码基线 `328fc6ef31fdc91f21035389b2110d15f2e1c4e3` 加本轮四文件，[实际内容摘要](evidence/service-bugfix-20260929-09/SOURCE.json)。未发布、未部署、未执行生产迁移。

## 行为与实现

原先 GET 缺失 key 在前、HSET string key 在后时，go-redis aggregate error 是 redis.Nil；wrapper 忽略该 aggregate，未检查后续命令，Exec 返回 nil，实际 HSET 已被 WRONGTYPE 拒绝。

现在 `redis/driver/pipeline.go` 保留 Exec 返回的 Cmder 列表。先完成全部 bytes/int/map future 赋值，保留真实 aggregate/传输错误；aggregate 为 nil 或 redis.Nil 时，逐命令返回首个非 nil、非 redis.Nil 错误。defer 继续清空本批 future 跟踪数组。仅缺失读取仍允许 Exec 为 nil，由对应 future 返回 ErrNil；已有成功结果在批次失败时仍可读取。

复用现有 go-redis 命令结果，不引入客户端、重试层、事务或新 future 类型。IPipeline 方法签名、RPC、key/JSON/存储格式不变；接口注释明确部分执行不会回滚。调用方过去误把 nil 当写成功，现在会收到真实错误；不能据错误自动重放非幂等写。
