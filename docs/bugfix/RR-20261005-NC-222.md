# NC-222 修复：`process` / `on` 只能写在 spawn 上

[问题](../bug/RR-20261005-NC-222.md) · [本轮](../review/REVIEW-2026-10-06-n09-batch5.md)。已修复、声明场景验证，未发版。

## 根因与决策

只有 spawn 启动实体进程，但 normalize / lower 对任何效果的 `process` / `on` 都生成进程模板。修法在 `skill/compile_shape.go` 的 effect flow 分支：效果不是 spawn 时，`process` 报 `SHAPE_INVALID at <flow>.process`，`on` 报 `SHAPE_INVALID at <flow>.on`。放在 shape pass（最早的结构检查），在类型检查给回调报别的错之前就指出根因。

未采用：让 lower 对非 spawn 效果忽略这两个键——仍是“编译接受、不执行”。

## 文件与行为

`skill/compile_shape.go`。非 spawn 效果上的 `process` / `on` 从“静默丢弃”变为编译失败。

## 回归

`TestCompileRejectsProcessesOnEffectsThatDoNotSpawn` 三个子用例修前全部 `compiled; diagnostics=[]skill.Diagnostic(nil)`，修后 ok；全部 fixture（spawn + process / on）与性质测试照常通过。

## 兼容性

行为收紧；仓内 fixture、生成骨架、examples 没有这种写法。
