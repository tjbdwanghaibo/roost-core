# RR-20261005-NC-204 修复：glsvet 对没检查到的输入以 2 退出

日期 2026-10-05。基线 `8597046c`（审查提交 `345488e4`）。状态：已修复、声明场景验证，未发版。问题：[RR-20261005-NC-204](../bug/RR-20261005-NC-204.md)。

## 决策

`cmd/glsvet/main.go`：`expandArgument` 返回错误——普通参数必须是已存在的目录，`<root>/...` 的走查错误（根不存在、读不了）上抛；`vetDirectory` 返回 `(int, error)`，仍检查能解析的包，再把 `parser.ParseDir` 的错误交给调用方。`main` 分别统计违例与“没能检查的输入”：后者非 0 时以 2 退出（与用法错误同级），否则有违例以 1 退出。没有 Go 文件的目录 ParseDir 本就不报错，照常通过。

## 行为与兼容

退出码含义收紧：路径不存在 / 文件解析失败从 0 变 2。仓库 `./...`、核心四包、全新生成 game-demo 的 `./...` 实跑均 exit 0，现有 CI 与生成工程不受影响。

## 验证

- 红 / 绿：`cmd/glsvet/inputs_promises_test.go`（测试二进制经 TestMain 充当命令，断言退出码）修前两条红（[输出](../review/evidence/noncore-review-20261005-n15/nc204-red.txt)），修后三条通过（含控制：无 Go 文件目录，[输出](evidence/noncore-bugfix-20261005-n15/nc204-green.txt)）。
- `go test -race -count=3 ./cmd/glsvet`、`go vet` 通过；`go run ./cmd/glsvet ./nest ./entity ./dataengine/engine ./sync/entitysync` 与 `./...` exit 0。
