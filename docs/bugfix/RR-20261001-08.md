# RR-20261001-08：chat 无游标最新页 / 翻到保留边缘不再因普通容量淘汰报 `Gap`，`history.gap` 只计真正的洞

问题：[docs/bug/RR-20261001-08.md](../bug/RR-20261001-08.md)（来源 [B 线 service 修复复审（后半）§4.2](../review/REVIEW-2026-10-01-bline-audit-service-2.md)，W-2026-10-01-03 拍板）。等级 P3。基线 main `c38e0b08`（worktree HEAD `815ac535`）。状态：已修复、已验证（Memory + 隔离真实 Redis），已提交，未推送、未发版。

## 根因（到行，worktree HEAD `815ac535`）

- `kit/service/chat/store.go:616-617` `pageOf` 的无 `AfterSeq` 分支（无游标最新页与 `BeforeSeq` 向前翻共用）：`selected[len(selected)-1].Seq < upper || (!page.HasMore && selected[0].Seq > 1)`。后半个条件把"本页到达 ring 头部且头部序号 > 1"当作洞。容量淘汰（`trim`，`:168-179`）永远从头部丢，所以任何曾溢出过的频道 `ring[0].Seq > 1` 永真；无游标取最新页只要整页装得下 ring（`HasMore=false`）就 `Gap=true`，`BeforeSeq` 翻到保留边缘同样命中。
- `:540-541` `History` 对每个 `page.Gap` 打一次 `history.gap.<kind>`，于是指标从"游标早于保留窗口"变成"频道曾淘汰过 × 拉最新页次数"。
- RR-20260929-27 修法引入（[记录](SERVICE-BUGFIX-2026-09-29-05.md) 与 CHANGELOG 只写"页内 / 尾部洞"，没写这条）。`AfterSeq` 分支（`:593-603`）只看游标到首条的距离与尾部，不受影响。

图谱：`Users-whb-roost-roost-core` generation `2026-09-30T11:28:30Z`，早于 worktree HEAD；`search_graph` / `trace_path` 定位了 `pageOf`（调用方 `History` → `Service.Conversation` / `Scrollback`，仓内无其他 `Page.Gap` 消费者），`check_index_coverage` 对 `store.go / chat.go / chat_test.go / redis_store.go / bugfix_retention_gap_test.go` 为 `no_recorded_issue`；行级证据按当前源码核对。

## 决策与未采用方案

采用：删掉头部洞条件，`Gap` 只剩三种来源——页内序号不连续、游标点名的消息已不在、尾部缺失。修后各查询形态：

| 查询 | 情形 | Gap |
| --- | --- | --- |
| 无游标 | ring 连续、头部序号 > 1（容量淘汰，或年龄清理只清了前缀） | **false**（旧：true） |
| 无游标 | 页内不连续 | true |
| 无游标 | ring 最后一条 < `LastSeq`（尾部被年龄清理） | true |
| 无游标 | ring 被年龄清理清空、`LastSeq > 0` | true（尾部洞的退化情形，RR-27 既有行为） |
| `AfterSeq` | `AfterSeq+1` 已不在（游标落在已淘汰区间） | true |
| `AfterSeq` | `AfterSeq` 恰为最后一条已淘汰序号 | false（客户端已看过它，下一条就是 ring 首条） |
| `BeforeSeq` | 翻到保留边缘（本页选到 `ring[0]`，`HasMore=false`） | **false**（旧：true） |
| `BeforeSeq` | `BeforeSeq-1` 已不在（含 `BeforeSeq ≤ OldestSeq`，空页） | true |

未采用：

1. **只补记录、保留头部洞**（复审给的另一选项）：指标口径失真不是文档能解决的；客户端把 `Gap` 当"需要重同步"会在溢出过的频道上空转，`OldestSeq` 已经把保留边界告诉了客户端。
2. **区分容量淘汰与年龄清理造成的头部缺失**（例如 state 记一个 `PrunedBelow`）：对无游标客户端两者都是"保留窗口之前的历史没了"，多一个持久字段换不到新信息，且年龄清理清前缀本来就等价于容量淘汰。
3. **无游标且 ring 被清空时也改报 false**：那是 RR-27 "exhausted retained tail" 的退化情形——客户端要的最新消息确实丢了；容量淘汰造不出空 ring（`Retain ≥ 1`），与本条"正常容量淘汰不算"不冲突，保持。

## 文件与行为

- `kit/service/chat/store.go`：`pageOf` 删去 `(!page.HasMore && selected[0].Seq > 1)`，注释写明三种洞与"到达 ring 头部不是洞"的理由。
- `kit/service/chat/chat.go`：`Page.Gap` 字段注释改为上表语义（容量淘汰之前的历史不算洞，溢出过的频道最新页 `Gap=false`）。
- `kit/service/chat/latest_page_gap_promises_test.go`（新增）：
  - `TestLatestPageAfterCapacityEvictionIsNotAGap`：`Retain=4` 写满 + 1 条 → 无游标最新页 `[m2..m5]` `Gap=false`、`HasMore=false`、`history.gap` 为 0；`BeforeSeq=5` 翻到边缘 `[m2 m3 m4]` `Gap=false`、指标仍 0；再发一条让 seq 2 也被淘汰 → `AfterSeq=1` `Gap=true` 指标 1、`AfterSeq=2`（边界）`Gap=false` 指标仍 1、`BeforeSeq=3` 空页 `Gap=true` 指标 2。Memory 默认，`ROOST_BUGFIX5_BACKEND=redis` + `ROOST_REVIEW_REDIS` 时走真实 Redis（与 RR-27 同一道门，一次 Redis 运行覆盖两条）。
  - `TestLatestPageReportsOnlyInteriorAndTailHoles`：`pageOf` 纯表驱动——连续 ring `[2 3 4 5]` / 单条 `[5]` 为 false；页内洞 `[2 4 5]`、尾部洞 `[2 3]`（`LastSeq=5`）、空 ring 为 true。
- 行为变化（wire）：`Page.Gap` 只在游标落在已淘汰区间或页内 / 尾部洞时为真；无游标最新页与翻到保留边缘在普通容量淘汰后为假。`history.gap.<kind>` 回到只计这些情形、每页一次。`NextCursor` / `PrevCursor` / `HasMore` / `OldestSeq` / `LatestSeq` 不变。

## 兼容性

- 无配置、持久格式、API 签名变化；`Page` 字段集不变，Memory 与 Redis 状态存储不动。
- 客户端看到 `Gap=true` 的次数减少。此前靠 `Gap` 判断"频道曾淘汰过"的客户端应改看 `OldestSeq > 1` 或 `Stats.Evicted`。监控上 `history.gap.<kind>` 在溢出过的频道上会骤降，这是口径修正，不是流量变化。
- RR-20260929-27 的两条回归（`TestBugfix5AgePruneHandlesInteriorAndTailGaps` / `TestBugfix5GapOnlyReportsTheRangeActuallyPaged`）与 `TestRetentionEvictsOldestAndReportsAGap`（游标早于 ring → `Gap=true`、指标 1）不改、仍绿。
