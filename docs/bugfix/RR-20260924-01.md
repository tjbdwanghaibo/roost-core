# RR-20260924-01 修复：准入回调回到 pipelined 锁内阶段

[问题记录](../bug/RR-20260924-01.md) · 状态：已修复、已验证，未提交/发布。

## 决策与实现

`nest/rollback.go` 提取内部 `runAfterAdmission`，pipelined 在 Enqueue 和版本接受成功、Entity CommitLSN 写入后执行，再进行完成泵交接与提前解锁。清空已领取的回调，后续 Commit 不重跑。空记录没有 ticket，也要在提前解锁前执行。

回调逐项捕获 panic，累计 admissionErr，后续 Commit 报告 `ErrAfterCommitFailed` 并继续 AfterCommit/释放通知。已准入状态不回滚，最终回复仍等待 ticket。准入拒绝不执行回调；Rollback/abandon 清理错误和回调。普通 Commit 保留消费该阶段的能力。

公开 API、WAL 格式、同步线格式不变。修复的是已有 AfterAdmission 契约；没有把 Sync 网络发送放入 Nest 的实体锁内，也没有新增即时同步调度。

## 验证

Go 1.27.0 / darwin arm64。定向回归修前失败，详见问题记录；修后 inline/async 锁内回调、LSN、一致执行次数、panic 后完成、拒绝与空记录场景通过。
