# RR-20261006-01 修复：删除提交确认时实例已被清空，确认视为完成、照常发布墓碑

问题：[RR-20261006-01](../bug/RR-20261006-01.md)。基线 `7d837dab`（v1.21.0 之后）。发现于 [Mirror 第 6 步本机替代](../feature/MIRROR-STEP-6-LOCAL-2026-10-06.md) S4。

## 根因

删除随事务走 `deferEntityDelete`，准入之后实例就被实体管理器清空（`doClear`，ID 归零）；strict / pipelined 的 Remote 确认在投影器里稍后才到。
`Manager.acknowledgeRemoteCommit` 从登记取出这个已清空的实例，把删除提交交给生成的 `AcknowledgeRemoteCommit`，后者按身份核对拒绝，
`afterRemoteCommit` 在确认处返回，`publishCommitted`（L1 / L2 带版本删除 + 推送删除）整段不执行。

## 决策

确认的职责是推进**这个实体**的内存实例（版本向量、DAO 版本、解冻）。登记里的实例已经不是这个实体（`live.ID() != commit.EntityID`：被同一事务删除后清空，
或已被回收）时没有可推进的内存状态：把它从登记上摘掉（`detachEntity`），确认返回 nil，调用方照常发布。回执在调用方已由 `validateRemoteReceipt` 核对，
提交 / 发布 / 回执的顺序与格式都不变。不是设计变化，不需要交回维护者。

未采用：

- 放宽生成代码的身份核对（接受 ID 为 0 的实例）：生成代码的核对防的是把别的实体的回执用到自己身上，问题在 Manager 把回执交给了已不是该实体的实例。
- 只按 `commit.Delete` 跳过确认：确认到达时实例若还没被清空（身份相符），跳过会改变那条路径；按身份判断两种情况都对，也挡住“实例被回收给别的实体”时
  `SetRemoteVersionVector` 写到别人身上。
- 在 Destroy 时立刻摘登记：要改实体删除与 Remote 登记的接线（跨 entity / remoteentity），这次只修确认点。

## 文件与行为

- `remoteentity/transaction_manager.go`：`acknowledgeRemoteCommit` 在拿到登记实例、判过期之后，实例身份与提交不符即摘掉并返回 nil。
- 删除 Managed Remote 实体（strict，实测）：调用方得到成功（之前是 `ErrRemotePersistenceIndeterminate`），L2 写入带版本墓碑，推送删除；
  只读方在推送延迟内读到“不存在”（S4：26～36ms），L2 TTL 内的新读者也读不回删除前的版本。

## 兼容

- 公开 API、wire、L2 键、Mongo 文档格式不变；生成代码不变（不需要重新生成）。
- 行为变化：上面这条删除从“结果未知”变为成功，并且会发布。依赖“删除总是返回结果未知”的调用方（不应存在）会看到 nil。
