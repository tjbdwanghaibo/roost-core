### 残留

复核指出回归弱：(1) 并发用例每次用全新库（集合不存在），修前只有少数轮失败，而真实触发场景“集合已存在但无计数文档”没有覆盖；
(2) 上限用例只断言 `err != nil`，修前的 duplicate key 同样满足；(3) `-run '^TestGuildIDs'` 匹配不到 `TestGuildIDExhaustion…`；
(4) CI 没有 `ROOST_GUILD_IT_MONGO_URI`，真实 Mongo 用例在 CI 里一直 skip。

### 修改

- `demo/game/controllers/player/guild_ids_test.go.tmpl`：
  - `TestGuildIDsRealMongoConcurrentFirstMint` 改为两个子用例——“集合已存在、无计数文档”（先插一条无关文档建出集合）与“全新库”，各 5 轮 × 64 并发，
    断言零错误且号恰为 1..64（每次 `$inc` 恰好成功一次）；每轮独立库 `roost_guild_it_first_*`，`t.Cleanup` 删除。
  - 上限用例改名 `TestGuildIDsExhaustionDoesNotWrapOrUseRuntimeIDs`（被 `^TestGuildIDs` 覆盖）；种子改为 `StaticUniqueIDBase-2`，先断言拿到最后一个合法号
    `StaticUniqueIDBase-1`，再断言越界时报 “outside dynamic range” 且不是 duplicate key、不回绕；未配置时断言 “persistent counter is unavailable”。
- `.github/workflows/framework-compat.yml`：demo 场景在 dev compose 的 Mongo 副本集就绪后、启动服务前，以
  `ROOST_GUILD_IT_MONGO_URI='mongodb://127.0.0.1:27017/?replicaSet=rs0'` 运行 `go test -race -count=1 -run '^TestGuildIDs' -v ./game/controllers/player/`
  （minimum / released / source-head 三格都跑）。用例只用自建并删除的 `roost_guild_it_*` 库，不碰 DAO 的 `game` 库。
