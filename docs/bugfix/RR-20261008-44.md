# RR-20261008-44 修复：读取与兴趣广播分离

问题见 [RR-44](../bug/RR-20261008-44.md)。读路径同步完成本机兴趣准入，广播交给每个 SnapshotClient 至多一个 worker、256 条等待容量的队列；同 key 的有效租约避免重复入队，满队列撤销本次准入并计数，读取照常按原一致性模式走缓存/L2/权威。

不改变 Cached/Monotonic/Linearizable 的语义，不让 Cached 在缺少 L2 时擅自向权威加载。显式 `RenewInterest` 仍同步报告错误，`ReleaseInterest` 仍分配新的代际撤销；后台发送前丢弃已过期/撤销/替换的项，传输在途重排仍由既有代际判断防复活。广播失败只撤销对应 ExpiresAt 的登记。

worker 空队列即退出；受 operation.Lifetime 管理，Stop 取消发送预算、排空队列，未配合取消的在途 publisher 结束前 Stop 如实超时、后续重试继续等待。无长期空转 worker、无每个读请求独立 goroutine。

新增权威预算反例、有界队列和共用 stopcontract 回归。旧同步循环总线用例先等后台兴趣完成，再按原断言验证远端兴趣/续租次数，不把“读返回”误认为“总线已确认”。Mirror S2 增加 SIGCONT 清理和失败子进程诊断，防止一次失败污染其余场景；失败原文保留。

真实 S2 修后通过（20.48s）：SIGSTOP 收敛 2967ms/2968ms，SIGCONT 后 63ms，两个读者 errors=0。完整矩阵、全包 race 与 1h 负载结果回填本轮总记录。
