## 根因与取舍

[源码](../../cache/ref_hmap.go):65–94、281–311。原Patch只写叶hash，没有Get需要的parent引用。现在patchTarget提供根到叶键/引用，单一同槽Lua先检查所有TYPE、要求已有root，再补父引用、叶、registry与路径TTL；不重写整个对象，不在Eval错误后fallback。 优先复用现有反射、layout、同槽Redis和分页能力，没有新包、后台任务或自动重试。

## 实际验证

patch_nil_parent修前nil但读取仍nil；修后可见。补深层nil、已有路径、root miss无键、错误TYPE无前缀副作用、Delete登记键与祖先TTL；正式生成ref-hmap DAO实际消费通过。 共同修前16正式叶子10fail/6控制，原实现overlay实际复跑相同；修后最终41新正式叶子通过，十包race/vet、252叶子pass、0fail/skip，正式DAO CLI业务消费通过。原始失败保留，不能据此推断全仓审完。

## 兼容与边界

Patch需要支持Eval；缺整条root现在明确Unsupported，nil父自动建立。续TTL扩大到路径祖先，旁支仍保持原TTL；签名和合法键/字段格式不变。不增加版本CAS，Get仍非原子跨hash快照。 真实Mongo、Cluster/HA、长期容量和性能未执行；后续新NC-21～25见[审查](../review/REVIEW-2026-10-04-noncore-14.md)，与本RR修复分开。

## 复核后的补修（2026-10-04，A 线）

复审第三组 D3 登记为 [RR-20261004-03](../bug/RR-20261004-03.md)：本记录“续TTL扩大到路径祖先，旁支仍保持原TTL”的后果是兄弟 hash 先于根过期后，`Get` 报 `ok=true` 返回部分记录（真实 Redis 写入的 `Other.X=42` 读回 0）；根标量 Patch 原本就有，本修复把它扩大到所有嵌套路径。另一个分支：没有 `__keys` 的旧数据被 Patch 后注册表只剩路径键，Delete 漏删兄弟 hash。

补修（[记录](RR-20261004-03.md)）：Patch 脚本在路径之后声明记录布局里其余全部 hash，对全部声明键续期，注册表并入全部布局键；`TYPE` 检查与 `HSET` 仍只作用于路径。Get 遇到被引用、必然非空却不存在的子 hash 时整条报 miss。脚本只访问声明过的同槽键（同一 `{name:key}` tag）。本记录“兼容与边界”中“旁支仍保持原TTL”一句以此为准，其余结论不变。
