# NC-282 修复：cast_start / phase_start 读取的实体在采样点不能是可缺省的

[问题](../bug/RR-20261005-NC-282.md) · [本轮](../review/REVIEW-2026-10-06-n09-batch6.md) · [求值上下文表方案](../feature/SKILL-EVAL-CONTEXT-TABLE-2026-10-06.md)。已修复、声明场景验证，未发版。

## 根因与决策

采样点求整个读取，读取处的 exists 收窄在那里不存在。

- **采用**：编译期拒绝（`checkCachedRead`：实体里的引用按采样上下文的作用域取类型，可缺省即 `ATTRIBUTE_SNAPSHOT_INVALID`）；表里 `$primary_target` 在 cast_start / phase_start 列为 ✗。
- 未采用：Runtime 采样时跳过缺省的实体、让读取处回落到 current。这会在作者不知情时把 cast_start 变成 current，语义漂移比失败更难发现。

## 文件与行为

`compile_typecheck.go` `checkCachedRead`（同时收拢 NC-220 的局部变量 / process_start 位置检查）；`eval_contexts.go`。

## 回归

`TestCompileRejectsOptionalEntitiesInCachedReads` 四个子用例修前 `… compiled; casting without it: skill: runtime value type mismatch` → 修后 ok；控制 `TestGuardedOptionalReadsAtCurrentStillRun` 修前修后都 ok。验证：`GOWORK=off`，`go test -race -count=3 ./skill/...`、`SKILL_MUTATION_FULL=1` 性质测试、根包、`go build ./... && go vet ./...`，见 [N09 第六批 §5](../review/REVIEW-2026-10-06-n09-batch6.md#5-修复与验证)。

## 兼容性

行为收紧：可缺省实体的 cast_start / phase_start 读取被拒，改用 current（或非可缺省的 `$input.target`）。entity 输入的技能里 `$primary_target` 实际总在，但它的类型是可缺省的，同样被拒，作者应改用 `$input.target`。
