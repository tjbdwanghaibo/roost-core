# RR-20260926-37：Remote 确认无结论时，Sync Confirm 与 AfterCommit 随收尾交给 finalizer，拿到持久结论后执行一次

问题：[RR-20260926-37](../bug/RR-20260926-37.md)（探针 [REPRO-2026-09-26-04](../bug/REPRO-2026-09-26-04.md) §5）。日期 2026-09-26。
实施基线：main `0452569` + RR-39 提交（首版 `649ba12` 基于 `49f20ee`，本版随 RR-39 的机制统一在 `0452569` 上重做）。状态：已修复，本地验证通过，已本地提交，未推送/发布。

## 根因（基线行号）

- `nest/execution.go:215-218` 本地持久提交成功后置 `remoteCommitted`；`remoteentity/batch.go:456-466` strict 等待超时（或 Durability 0 结果未知）
  标 indeterminate 并返回错误；`nest/msg.go:88-108` 于是 `committed=false`，**跳过** `postRemoteCommit`（Sync Confirm、AfterCommit）。
- finalizer `processDeferredRemoteClose`（`transaction_manager.go:252-290`）拿到 Applied/Committed 时只发布、对账、释放，与原消息的回调没有任何连接；
  Nest 只对 `ErrCommitIndeterminate` Fence（`execution.go:45-47`），不会恢复。
- 结果：同实体后续事务的 Sync 门串在这道永远不 Confirm 的门后（`entity/sync_commit.go:39-46,99-104`），实体 Sync 永久冻结；AfterCommit 永远丢失。
  Durability 0 被权威明确拒绝时同样跳过、门同样永久冻结。

## 决策（维护者 2026-09-26 批准：finalizer 放行）

1. **交接**：`finishRemoteWriteBatch` 在“本地已提交、Remote Commit 返回错误”时，Close 之前调用 `deferPostRemoteCommit`：把 `postRemoteCommit`
   与本事务的 `SyncMutation`（`commitDurable` 记在 `Msg.remoteSyncMutation`）装进只捕获值的闭包，交给批次
   （新接口 `entity.RemoteOutcomeDeferrer.DeferUntilDurableOutcome`）。`remoteWriteBatch` 只在结论待定（indeterminate → Close 交给 finalizer）
   或已明确拒绝（Durability 0 同步拒绝 → Close 自己收尾）时接手；接手后闭包随 `deferredRemoteClose.onOutcome` 走。
2. **只执行一次**：finalizer 只在终态分支、资源释放之后调用 `deliverRemoteOutcome`，调用后该项不再入队：Applied 发布成功或 Committed 对账成功 →
   `true`；Rejected → 回滚、隔离、释放、仅内存卸载（RR-39）成功之后 → `false`。执行经 `Manager.localContext` → `NestMgr.RunLocal`（`NewEngine` 经 `LocalExecutorBinder` 绑定，与 RR-30 驱逐同一入口，快池续行通道）；
   消息自己的 Close 路径沿用消息的快池续行。`RunLocal` 在 Nest 未启动 / 停机中 / 已 fence 时拒绝投递（fn 不执行），此时持久结论已经拿到、不能丢：
   提交后工作不取实体锁（Sync Confirm/Reject 是原子标记，AfterCommit 与 pipelined 完成池一样在解锁后运行），就地执行一次，计数 `remote_entity.deferred_outcome_inline_total`。
3. **结论为已提交**：闭包在快池按注册顺序运行回调，每个回调独立隔离 panic（`runCommitCallback`）；原请求此前已经带“结果未知”错误回复，
   回调错误只记日志与指标 `nest.remote.deferred_after_commit_error_total`。这就是“AfterCommit 在回复失败之后延迟执行”的语义。
4. **结论为拒绝**：`SyncMutation.Reject()`——门不再阻塞后续提交、不 Confirm、本提交自己的兴趣事实按丢弃处理（后续提交的事实不受影响），
   AfterCommit 不执行。被拒绝实例在锁内冻结的内容由 RR-39 的卸载关闭其同步状态时丢弃，所以 Reject 必须在卸载成功之后；loader 不支持卸载时
   （旧实例仍持有被拒绝的冻结内容）不 Reject，门保持冻结（与修复前相同），计数 `remote_entity.rejected_unload_unsupported_total`。
5. **没有结论**：停机排空（finalizer 停止、收尾项被 abandon）或批次不接手（替身批次 / 自定义实现）时闭包不执行：没有持久结论就不 Confirm，门保持冻结，
   计数 `nest.remote.post_commit_without_outcome_total`。
6. **未改**：本地 WAL 结果未知（`remoteIndeterminate`，Nest 已 Fence）路径；Durability 1 的推测确认（Commit 成功即 Confirm）；Commit 成功时的同步执行。

## 兼容性

- 行为变化：strict 确认超时 / Durability 0 结果未知后，请求仍返回可 `errors.Is(ErrRemotePersistenceIndeterminate)` 的错误（不带 `ErrAfterCommitFailed`，
  见 RR-46）；之后持久结论为已提交时，该事务的 AfterCommit 由 Nest 快池执行一次，Sync 随之放行。执行时机不早于 Remote Commit 返回错误，
  与回复的发送并发或在其后——业务不能假设 AfterCommit 在回复之前执行，也不能因回复是“结果未知”就在别处重复这些副作用。结论为拒绝时 AfterCommit 永不执行，同实体后续提交的 Sync 不再冻结。
- Durability 0 被权威明确拒绝时，同实体后续提交的 Sync 不再永久冻结（修复前同样冻结）。
- 自定义 `RemoteWriteBatch` 未实现 `RemoteOutcomeDeferrer` 时行为不变（门冻结、AfterCommit 不执行）。

## RR-38 复核补充（本提交）

## 交付前对抗性自查（RR-37 / 38 / 39 / 46 合并后的最终工作树）

1. **只对持久结论执行一次回调，无重复、无对未提交执行**：提交后工作只在“本地已持久提交且 Remote Commit 返回错误”时移交（`postRemoteCommit` 同时清空，
   Nest 侧不会再执行）；批次只接受一次（`onOutcome != nil` 时拒绝）。finalizer 只在终态分支、资源释放之后调用 `deliverRemoteOutcome`，终态分支都 `return`、
   不再入队；重试 / 等待 / 卸载重试入队的是同一项的值拷贝，只有终态时才调用。`true` 只来自 Applied 发布成功或 Committed（持久结论）；Rejected 只给 `false`
   且不跑 AfterCommit；未知、停机排空、finalizer 拒收都不调用。Durability 1 的推测确认与 Commit 成功的同步路径未改。
2. **RR-28 内存≠权威不解冻**：拒绝路径只回滚 + 隔离 + 卸载，旧实例始终 Quarantined（回归断言）；新实例来自权威重载。RR-38 的幂等 ack 只在“版本向量等于本提交
   且已 LocalOwned/Shared”时返回成功，从不自行解冻；被拒绝事务的实例版本向量停在 BaseVersion，不可能等于 NextVersion。RR-38 期间不再预先隔离，但 gate
   仍由收尾项独占，拒绝后照常隔离。
3. **RR-11 obsolete 判定**：`acknowledgeRemoteCommit` 仍先做 `remoteReceiptObsolete`；只在解冻失败之后加一道“已被同一提交确认”的判断；Committed 收尾的
   ack-only 分支同样经 `acknowledgeRemoteCommit`，obsolete 规则不变。`TestCommittedReplay*` 全部通过。
4. **至少一次发布与 outbox 重放**：投影器发布失败仍把 tracker 置 Indeterminate，finalizer 随即回源并在 Applied 时发布；Committed 来自回源（本进程没发布过）时仍完整
   发布；只有本进程确实完成发布（`published`）才跳过。`RecoverOutbox` 未改（改为 `completePublishedRemoteTransaction`，只多记一个标记）。
   `TestMemoryCommitPublishFailureQueriesStatusAndReconciles` 在首版被它抓住后修正。
5. **gate / 锁 / 写额度唯一释放**：终态分支各释放一次；`settled` 项（拒绝已收尾、只剩卸载）在处理、重试、排空时都不再释放；Close 同步拒绝路径自己释放后如需重试，
   交给 finalizer 的是 `settled` 项；等待投影与重试在停机时统一走 `abandonDeferredRemoteClose`（隔离 + 释放一次）。`writeSlots` 归零在各回归里断言。
6. **快慢池边界**：慢池不取实体锁——消息收尾（Close / 同步拒绝卸载 / 通知）经消息的快池续行，finalizer 的回滚、卸载、通知经 `NestMgr.RunLocal`
   （与 RR-30 驱逐同一入口）进入快池续行通道；快池里只做实体锁、内存索引与业务回调，不做 I/O 等待；`entity.RunLocal` 在快 worker 上就地执行、`NestMgr.RunLocal`
   在快 worker 上返回 `ErrBlockingInFastWorker`，不会自投自等；finalizer 等待快池不形成环（快池从不等待 finalizer）。未装配 Nest（纯 remoteentity）时就地执行。
7. **停机排空**：Nest 停机开始后 `RunLocal` 拒绝投递：卸载 / 回滚按重试处理（实例保持隔离，直到 finalizer 停止被 abandon，与 RR-30 驱逐“重试到关闭”一致）；
   已拿到持久结论的提交后工作就地执行一次（不取实体锁）。Remote `StopFinalizer`：
   等待投影 / 重试 / 卸载重试的项被 abandon，不调用提交后工作（门保持冻结），资源交还；`runRemoteFinalizers` 仍在最终排空前等 `retryWG`。
8. **回复语义（RR-46）**：只有本地与 Remote 都确认提交才带 `ErrAfterCommitFailed`；确认未知的回复不带，之后延迟执行的 AfterCommit 错误只进日志 / 指标，
   不会改写已经发出的回复。
