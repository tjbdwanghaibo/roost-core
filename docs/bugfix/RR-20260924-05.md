# RR-20260924-05 修复：异步完成等待本事务解锁

[问题与修前证据](../bug/RR-20260924-05.md)。已修复，未提交、未发布。

`completionHandoff` 显式保存完成所有权、排序位置释放函数和 `unlocked` 通道。排序位置仍在锁内登记；完成任务首先等待 `unlocked`，再等待同主实体的前序完成，然后执行 AfterCommit 和回复。实体锁、组锁与 Guard 中动态获取的锁清理后才关闭屏障；即使 release hook panic，defer 仍清理剩余 Guard 并开放屏障，避免完成池永久悬挂。

完成队列满时仍由当前 worker 等待 ticket 并执行同一个 complete；没有转移成功时保留排序位置的 defer 兜底释放。完成闭包只持有回复 channel、返回值、事务和排序位置，不持有可复用 Msg。

定向回归修前失败、修后通过。整个 Nest race 包含既有队列满降级、同实体顺序、停机、回调异常与不确定提交用例；跨模块验证见 [收尾验收](../feature/NEST-COMPLETION-2026-09-24.md)。本次不扩大原有“按主实体排序”的契约，也不声称完成回调可重入同步等待同一路由 worker。
