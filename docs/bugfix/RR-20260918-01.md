# RR-20260918-01：sync=true 实体生成物与 Core 配置不兼容（U-0229）

- 仓库：roost-codegen `internal/entity`
- 缺陷类：C4（生成物与运行时 API 漂移）
- 优先级：P2
- 相关：T-123；测试 `internal/entity/sync_packer_markers_promises_test.go` + `scripts/entity-sync-runtime.sh`

## 问题

任何带 `sync=true` 的实体，生成物编译不过：

```
avatar_gen_wire.go:37:5: unknown field FlushPolicy in struct literal of type entity.EntitySyncBuilderParam
avatar_gen_wire.go:37:34: undefined: entity.SyncFlushOnEntityRelease
avatar_gen_wire.go:38:5: unknown field SubjectPackerFactory in struct literal of type entity.EntitySyncBuilderParam
```

## 根因

`internal/entity/gen.go` 的 wire 模板写三个 Core 没有的东西：`FlushPolicy` 字段、`entity.SyncFlushOnEntityRelease` 常量、
`SubjectPackerFactory` 字段。Core 的 `entity.EntitySyncBuilderParam` 只有 `Enabled`、`Topic`、`PackerFactory`。
两个 packer 标记（`syncPacker` / `subjectPacker`）也是历史遗留：它们现在指同一个字段。

为什么没被发现：codegen 没有运行时依赖，`go test ./internal/entity` 只比对生成文本，
而 golden 里恰好写着同样的过时字段——文本自洽，编译不过。demo 不用 `sync=true`，所以整条 feature 没有任何使用方。

## 方案

- 采用：**按 Core 现有契约收敛**。模板只写 `Enabled` / `Topic` / `PackerFactory`；
  `subjectPacker` 是现行标记，`syncPacker` 保留为别名（老工程不必改），两者同时出现在一个 marker 上当场报错
  （一个字段不能有两个值），packer 没配 `sync=true` 也报错。
- 采用：**加运行时门**。`scripts/entity-sync-runtime.sh` 把当场生成的实体放进临时模块、钉当前 core pin，
  编译并断言 `BuildEntity` 真的建立了 Sync 状态（标脏后能 Prepare 出内容——工厂被丢掉的话这里是 `ErrSubjectSyncPacker`），
  另有 `sync=false` 对照。只修到"编译通过"是不够的。
- 没采用：给 Core 补回 `FlushPolicy` / `SubjectPackerFactory`。刷写时机现在由 entitysync 协调器与房间决定，
  往回加字段等于把一个已经搬走的职责塞回实体配置。

## 改动（roost-codegen）

- `internal/entity/gen.go`：sync 块只写三个字段；新增模板函数 `syncPackerFactoryExpr`（subjectPacker 优先，回落 syncPacker）。
- `internal/entity/parse.go`：同时设置两个 packer 标记 → 可操作的报错；packer 没有 `sync=true` → 报错。
- `internal/entity/testdata/player.go` 与重生成的 `player_gen_wire.go`：fixture 改用现行标记。
- 新增 `internal/entity/testdata/syncruntime/`（最小实体 + `sync=false` 对照 + roundtrip 测试）与 `scripts/entity-sync-runtime.sh`，接进 ci.yml。
- 三条编码旧契约的老测试改成断言新不变量（`TestParseDir`、`TestGenerate`、`TestParseDirAcceptsEveryDocumentedMarkerForm`），没有删。
- `docs/CODEGEN_REFERENCE.zh-CN.md` §11 写清"一个 packer 工厂、两种拼写、同时写两个报错"。

## 证明

修前（运行时门）：上面那三条编译错误，`FAIL entitysyncruntime/syncruntime [build failed]`。

修后：`sh scripts/entity-sync-runtime.sh` → `ok entitysyncruntime/syncruntime`，两条用例
（sync=true 建出实体且 Sync 状态可用、sync=false 没有 Sync 状态）通过；`go test ./internal/entity` 全绿。

## 未做 / 边界

- 只覆盖"无 packer / 现行 packer / 旧标记 / sync=false"四种；没有覆盖多实体包里混用两种拼写的组合。
- 运行时门只建实体并 Prepare 一次，不跑 room / entitysync 的投递链（那是 RR-20260918-02 的范围）。
- `syncTopic` 仍按常量表达式判断是否加引号，本轮没有动。
