# RR-20260926-62：新增可重试哨兵 `entity.ErrRemoteEntityReloading`，区分“拒绝后卸载 / 重载中”与真正的 fence

问题：[RR-20260926-62](../bug/RR-20260926-62.md)。日期 2026-09-26。
实施基线：main `3e26f91`（本批 RR-58、60、61 提交之后）。状态：已修复，本地验证通过，已本地提交，未推送/发布。

## 根因（基线行号）

- RR-39 的拒绝收尾顺序是：回滚 + 隔离（`transaction_manager.go:521-532` `settleRejectedRemoteEntries`；Durability 0 明确拒绝在 `batch.go:465-471`）→ 释放 gate /
  锁 / 写额度 → 经快池仅内存卸载（`local_runtime.go` `unloadRejectedEntities`）。gate 释放到卸载完成之间，下一写者在写准入（`batch.go:256-270`）见旧实例
  Quarantined，得到与真正 fence 相同的 `ErrRemoteFenced`。
- 卸载经 `EntityManager.Destroy`：实例先移出索引、ID 记为 removing，再跑生命周期回调（`entity/entity_manager.go:268-292`）。其间下一写者查不到本地实例，
  经 loader 重载，`TryAdd` 以 `ErrEntityRemoved`（`%d is being removed`，`entity_manager.go:113-115`）拒绝，写准入包成通用的
  `remote_entity: load entity …` 错误（`batch.go:222-230`）。
- 业务无法区分这两个几毫秒级的可重试窗口与真正的 fence / 隔离（结果未知、loader 不支持卸载等，重试无用）。

## 决策（修复约束：新增可 errors.Is 的哨兵，包裹 ErrRemoteFenced 以兼容，两处返回，文档化为可重试）

1. **哨兵**：`entity.ErrRemoteEntityReloading = fmt.Errorf("%w: rejected instance is being unloaded and reloaded from the authority (retryable)", ErrRemoteFenced)`。
   `errors.Is(err, ErrRemoteEntityReloading)` 与 `errors.Is(err, ErrRemoteFenced)` 同时成立，既有调用方不受影响。
2. **窗口一（gate 释放 → 卸载完成）**：拒绝收尾隔离成功之后，把批次内旧实例登记在各自 wrapper 上（`markRejectedReloadPending`，`rejectedStale`，由 `entityMu`
   保护）；写准入对 Quarantined 实例先判断“是否为登记的待重载实例”，是则返回本哨兵。两个收尾入口都登记：finalizer 的 `settleRejectedRemoteEntries` 与
   Durability 0 明确拒绝的 `batch.Commit`。
   登记的撤销：卸载完成（`detachEntity`）、关联上新实例（`attachEntity`）、loader 不支持卸载（`unloadRejectedEntities` 返回 `ErrRemoteUnloadUnsupported`——
   不会由框架重载，回到通用 `ErrRemoteFenced`）。Backend 不实现卸载能力时根本不登记。
3. **窗口二（Destroy 过程中重载）**：写准入的重载错误满足 `errors.Is(loadErr, entity.ErrEntityRemoved)` 时返回
   `fmt.Errorf("%w: entity %d: %w", ErrRemoteEntityReloading, id, loadErr)`，原错误仍可 `errors.Is`。
4. 只改写准入的错误分类；所有权状态、隔离 / 解冻规则（RR-28：内存≠权威时不解冻）、卸载时机与执行位置（RR-39，快池）都不变。

未采用：给 Quarantined 增加新的所有权状态（要改状态机与迁移校验，影响 Mongo/Redis 以外的所有状态消费者，收益只是错误分类）；在 `ManagerAccess` / `EntityManager`
里改“being removed”的错误（属于 entity 生命周期的通用语义，另一组正在处理卸载后重载，避免改动其文件）。

## 文件与行为

- `entity/remote_protocol.go`：`ErrRemoteEntityReloading`。
- `remoteentity/wrapper.go`：`rejectedStale`、`markRejectedReload` / `clearRejectedReload` / `rejectedReloadPending`；`attachEntity` / `detachEntity` 撤销登记。
- `remoteentity/local_runtime.go`：`markRejectedReloadPending`、`clearRejectedReloadPending`；`unloadRejectedEntities` 在不支持卸载时撤销登记。
- `remoteentity/transaction_manager.go`：`settleRejectedRemoteEntries` 隔离成功后登记。`remoteentity/batch.go`：写准入两处返回哨兵；`Commit` 明确拒绝隔离后登记。
- 回归 `remoteentity/rejected_reload_sentinel_test.go`（正式 Manager + MongoCommitter + ManagerAccess；窗口由本地执行入口 / OnDestroy 钩子按事件停住，不靠 sleep）：
  - `TestRejectedWriteBeforeUnloadReturnsReloadingSentinel`：Durability 0 从未到达 → finalizer 持久拒绝；本地执行入口放行回滚、停住卸载 → 下一写者得到
    `ErrRemoteEntityReloading` 且 `errors.Is(ErrRemoteFenced)`；放行后从权威重载、可写（沿用 RR-39 的 `assertReloadedFromAuthority`）。
  - `TestDefinitelyRejectedWriteBeforeUnloadReturnsReloadingSentinel`：Durability 0 版本冲突 → Close 里的卸载被快池拒绝投递、交 finalizer 重试 → 窗口内同一哨兵；恢复后重载可写。
  - `TestReloadDuringUnloadReturnsReloadingSentinel`：卸载停在 `OnDestroy`（实例已离开索引）→ 重载被 `being removed` 拒绝 → 同一哨兵，且保留 `errors.Is(ErrEntityRemoved)`。
  - 既有 `TestRejected*IsNotCarriedByNextWrite`（loader 不支持卸载，仍断言 `ErrRemoteFenced`）、`*ReloadsFromAuthority` 保持通过。

## 兼容性

- 新导出 `entity.ErrRemoteEntityReloading`。错误文本在这两个窗口里变化（原 `writer fenced: entity=… state=quarantined` 前缀变为
  `writer fenced: rejected instance is being unloaded and reloaded … (retryable): entity=… state=quarantined`；重载被拒由 `remote_entity: load entity …`
  变为 `writer fenced: … (retryable): entity …: entity manager: entity removed: … is being removed`）。按 `errors.Is` 判断的调用方不受影响；匹配错误文本的调用方需要改用 `errors.Is`。
- 窗口二的新分类还会覆盖“业务 Destroy 进行中恰好有写者重载同一实体”的情况：同样是可重试的卸载重载窗口（重试后得到重载的实例，或实体已删除时的 not found）。
- 停机时 finalizer 被停止、卸载不再进行，已登记的旧实例在本进程剩余时间里仍返回本哨兵；进程重启后从权威加载，不受影响。
- USER_GUIDE 写明：本哨兵可重试；仍是裸 `ErrRemoteFenced` 的是真正的 fence / 隔离。

## 交付前自查（本项）

- **不破坏既有 `errors.Is(ErrRemoteFenced)`**：哨兵用 `%w` 包裹 `ErrRemoteFenced`，两处返回都满足二者；回归逐项断言。仓内按 `ErrRemoteFenced` 分类的调用方
  （`ApplyRemoteCommits` 的拒绝判定等）只看提交 / 投影路径的错误，本哨兵只出现在写准入，不进入这些路径。
- **RR-28**：只有“隔离成功”之后才登记；登记不改变所有权状态，旧实例仍 Quarantined、从不解冻，下一写者仍被挡住，只是错误可区分。
- **快慢池边界**：登记 / 撤销只取 wrapper 的 `entityMu`（与 `e` 同一把内部互斥，不是 Entity local 锁），不在慢池取实体锁、不在快池等待。
