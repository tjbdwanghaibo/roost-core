# RR-20260913-09:Transfer 回复丢失后恢复旧 owner 并放行写准入

**仓库 / 位置**:roost-core `remoteentity/ownership.go`(`TransferRemoteOwnership`、`transitionLiveOwnership`),
`remoteentity/wrapper.go`,`remoteentity/batch.go`(准入状态开关)。
**修复单元**:U-0188(C8)。**定位文档**:TROUBLESHOOTING T-82。

## 问题

`TransferExpected` 的 Lua 已把 owner 改成新节点,回复在路上丢了(I/O 错误)。Manager 对任何错误都调
`restoreOwnershipAfterTransitionFailure`:live 回到 `local_owned`,wrapper 的热 marker 仍是旧 lease,
`MarkerCacheTTL` 内 `ensureMarker` 直接信任它,紧接着旧 owner 的 `PrepareRemoteWriteBatch` 成功——
而权威里 owner 已经是 2000。

## 根因

"确定被拒(CAS 冲突)"和"结果不确定(超时 / 回复丢失)"走的是同一条恢复分支,I/O 错误被当成
"没执行"(C8)。本地 marker 缓存在这个瞬间恰恰是最不能信的东西。

## 方案选择

- **区分错误类型,只对 CAS 冲突恢复。** 类型区分只能靠 store 实现配合(Redis 的 CAS 失败是一段字符串),
  而且"确定被拒"时权威 owner 也已经不是我们,恢复 `local_owned` 本来就不对。
- **任何错误都直接 fence。** 发送前就失败的场景(权威没变)会把一个好端端的 owner 变成 fenced,
  需要人工恢复;审查的对照用例明确要求这种情况继续可写。
- **失效 marker + 独立有界重查,让权威决定(采用)。** 出错后 `invalidateMarker()`,用不依赖调用方的
  `context.WithTimeout(Background, OpTimeout)` 调 `refreshMarked`:
  - 权威 lease 与 `expected` 相同 → 证明没执行,照旧恢复本地所有权;
  - 权威 owner 等于目标节点 → 转移其实成功了,按成功收尾(`applyLiveOwnership(Fenced)`,返回新 lease、
    err=nil);
  - 权威是别人 / 无人 → fence,返回 fence 错误;
  - 权威查不到 → live 进 `Recovering`,marker 保持 unknown,返回错误。之后任何准入都必须先成功
    读一次权威(`ensureMarker` 对 unknown 强制刷新):读不到就拒绝;读到仍是我们,`batch.go` 把
    `Recovering` 解冻成 `LocalOwned` / `Shared` 再放行;读到不是我们,按既有路径 fence。
    `transitionLiveOwnership` 同样把 `Recovering` 视为可解冻的起点(它之前 `beginOwnershipTransition`
    已经刷新过权威),否则冻结后的下一次 Transfer 会因 `recovering -> draining` 非法而永远失败。

## 改动

`remoteentity/wrapper.go`:`invalidateMarker`。`remoteentity/ownership.go`:失败分支改调
`settleIndeterminateTransfer`;新增 `transitionAttachedLive`;`transitionLiveOwnership` 对 `Recovering`
先转回 lease 对应的初始态。`remoteentity/batch.go`:准入状态开关新增 `Recovering` 解冻分支。
不改状态表:`Draining → Recovering`、`Recovering → LocalOwned/Shared/Fenced` 原本就合法。

## 证明

`remoteentity/ownership_transfer_indeterminate_promises_test.go`,替身 `lostReplyMarkerStore` 让 mock
的 Transfer 真正改 owner 之后再返回 I/O 错误:
- `TestTransferPromiseLostReplyFencesOldOwnerWhenAuthorityConfirmsTransfer`:旧 owner 准入必须
  `ErrRemoteFenced`,live 为 fenced,Transfer 按成功返回新 lease。
- `TestTransferPromiseLostReplyFreezesOldOwnerUntilAuthorityAnswers`:执行后权威也不可用;Transfer 报错、
  live 不是 local_owned/shared、准入被拒;权威恢复后准入为 `ErrRemoteFenced`。
- `TestTransferPromiseFailureBeforeSendRestoresOldOwner`(对照):发送前失败,恢复 local_owned,仍可写。

修前红:`transfer applied but reported err=remote_entity: transfer …: i/o timeout: transfer reply lost`
(修前旧 owner 也被放行,断言顺序后来调整为先看准入)和 `unknown outcome restored old owner: live=local_owned`;
对照用例修前修后都过。修后 remoteentity 含 `-race` 全绿。

## 未做 / 边界

  留给后续验收;形状相同,可以复用 `settleIndeterminateTransfer` 的骨架。
- 重查用的是 `OpTimeout`(默认 30s),没有单独的配置项。
- 用的是 mock marker store,不是真实 Redis;审查第三轮已在真实 Redis 上复现原问题。
