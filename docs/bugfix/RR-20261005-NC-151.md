# NC-151 修复：编译期拒绝 Runtime 不派发的 phase 事件，timeout_ticks 不再豁免 fallthrough

[问题](../bug/RR-20261005-NC-151.md) · [本轮](../review/REVIEW-2026-10-05-n09-batch3.md)。已修复、声明场景验证，未发版。

## 根因与决策

phase 事件集合在编译侧（parse / normalize / lower）与 Runtime 派发点各维护一份：编译侧多了 `recast`、`timeout`，Runtime 从不派发；`timeout_ticks` 只被 `compile_lifetime.go` 读来豁免 enter fallthrough，Runtime 没有 phase 计时（`phaseTimeoutTask` 在 live 代码里从不构造）。

采用问题记录里的方向 B（编译期 fail-closed），在 `runLifetimePass` 里新增 `requireDispatchedPhaseEvents`：

- `on.recast`、`on.timeout` → error `CAPABILITY_UNKNOWN`，路径 `$.phases[i].on.<event>`；
- 非零 `timeout_ticks` → **warning** `CAPABILITY_UNKNOWN`，路径 `$.phases[i].timeout_ticks`，说明它不被执行（负值由 NC-152 报 error）；
- enter fallthrough 不再以 `timeout_ticks != 0` 豁免，消息改为“end it with finish or goto (the runtime has no phase timeout)”。

未采用方向 A（在 Runtime 实现 phase 计时与 recast 触发）：语义缺失（计时到期时挂起中的 enter 续行、进程、recovery 怎样收尾；recast 与 toggle 二次激活的关系；checkpoint 形状），需要维护者决定。非零 `timeout_ticks` 选 warning 而不是 error：不依赖 fallthrough 的现有定义（`area_heal.json` 5、`dynamic_numeric.json` 4 一类）照常编译，只提示这个值不起作用；升级为 error 或实现 A 留给维护者。

## 文件与行为

- `skill/compile_lifetime.go`：fallthrough 条件去掉 `timeoutTicks == 0`；新增 `requireDispatchedPhaseEvents`。
- `skill/testdata/recast_combo.json` 删除（它声明的 recast 分支从未执行，现在编译即拒绝）；`acceptance_test.go` 去掉对应行；`skill/README.md` 的事件列表与 fixture 数（37 → 36）、`docs/skill/skill-implementation-guide.md` 的 fixture 数同步。
- 测试辅助（`motion_test.go` 的 `motionSkillJSON`、`numeric_test.go` 的 `numericProcessSkillJSON`、`area_test.go` 三处）此前靠 `timeout_ticks: 10` 让“只有一个进程效果、不 finish 的 enter”通过编译——这些 Program 一旦 `Activate` 就 `ErrProgramInvariant`（修前探针：motion 形状 Activate 即失败；area 回调 finish 的形状在区域内没有成员时 Activate 即失败）。改为 `sequence[进程效果, wait N → finish]`，与已有的 `TestAreaFinalLeaveFinishSuppressesTerminalCallback` 同一写法；被测的运动 / 数值 / 区域行为不变，全部用例通过。

兼容：升级后带 `on.recast` / `on.timeout`、或 enter 落空且靠 `timeout_ticks` 的定义在启动期 CompileAll 失败（错误带 JSON 路径），此前这些定义运行时要么分支不跑、要么每次施法失败。`timeout_ticks > 0` 的定义多一条 warning：game-demo 的机器人（`cmd/loadtest` 断言 `Warnings == 0`）会因此失败，fireball 与 `roost add skill` 骨架都是 0，不受影响。Program 摘要、wire 与 checkpoint 格式不变。
