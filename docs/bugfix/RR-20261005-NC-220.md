# NC-220 修复：缓存型快照点按采样上下文检查

[问题](../bug/RR-20261005-NC-220.md) · [本轮](../review/REVIEW-2026-10-06-n09-batch5.md)。已修复、声明场景验证，未发版。

## 根因与决策

`runSnapshotPass` 只核对“属性存在、采样点在 catalog 允许列表里”，把“整个读取在采样点求值”的前提留给运行期。修法在同一个 pass 里补两条（`skill/compile_snapshot.go` 的 `snapshotCapturableWhereRead`）：

- 缓存型采样点（cast_start / phase_start / process_start，与 `shouldCacheSnapshot` 同一判定）的实体不能引用 `$local.*`：采样点上还没有任何流程局部变量；
- process_start 只能写在 spawn 的进程回调（`on`）里（`readsInsideProcessCallbacks` 收集这些读取的源路径）：只有 owned 实体进程启动时采样它。

都报 `ATTRIBUTE_SNAPSHOT_INVALID`，分别定位到 `.read_attribute.entity` 与 `.read_attribute.snapshot`。cast_start / phase_start 写在进程回调里原来就由 owned entity pass 拒绝，不重复。

未采用：在 Runtime 里让 `captureOwnedProcessSnapshots` 只采样属于本进程回调的计划——那只能消掉 ErrProgramInvariant，phase 流程里的 process_start 仍然没有可定义的含义（“哪个进程的启动？”），且局部变量情形仍是 lower 的兜底报错。

## 文件与行为

`skill/compile_snapshot.go`。上表定义从“编译通过、每次施法失败 / 退化成第一次读到的值”或“LOWER_UNRESOLVED at $”变为在读取处报 `ATTRIBUTE_SNAPSHOT_INVALID`。读取处求值的采样点（current / each_tick / on_hit / on_event）不受影响。

## 回归

`skill/compile_capture_context_promises_test.go`：

- `TestCompileRejectsSnapshotsThatCannotBeCapturedWhereTheyAreRead` 六个子用例修前全部 FAIL（三个 `compiled; diagnostics=[]skill.Diagnostic(nil)`，三个 `missing error ATTRIBUTE_SNAPSHOT_INVALID at … in [… LOWER_UNRESOLVED … Path:"$" …]`），修后 ok；
- 控制 `TestSnapshotsCapturedAtTheirPointStillRun`（cast_start 读 `$caster`；进程回调里 process_start / current 读 `$owner`，启动后改属性 5 → 40，目标生命 90 / 55）修前修后都 ok。

性质测试新增种子 `seed.process_start_read`（cast_start + spawn 回调里的 process_start）。

## 兼容性

行为收紧，只影响此前要么每次施法失败、要么语义未定义、要么已经编译失败的定义；正常定义的 Program 与 digest 不变（42 个既有种子修前修后 gameplay / presentation digest 逐一相同）。

## 后注（2026-10-06，v1.23.0 发版文档重核）

本记录写的修复位置（`skill/compile_snapshot.go` 的 `snapshotCapturableWhereRead`，以及收集回调读取的 `readsInsideProcessCallbacks`）描述的是 `5c04726f` 当时的提交。同一版本（v1.21.0）内求值上下文表（`4ed038d9`，SKILL-15）把按 pass 各写一份的检查收拢到表上，这两个函数已删除；现在由 `skill/compile_typecheck.go` 的 `checkCachedRead` 按 `skill/eval_contexts.go` 的快照点表 `evalSnapshotTable` 判断。承诺不变，回归用例（`skill/compile_capture_context_promises_test.go`）仍在。
