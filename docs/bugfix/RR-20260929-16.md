# RR-20260929-16：mail 正文失败后同请求不能恢复

状态：已实施并通过本轮定向回归，未发版。源码基线 `f46db3e7d504bbd73581aa4119baa71171352519`。

根因：send ledger 先提交，但未保存正文意图；正文失败后重试只看到缺失 ID。

实现：SentRecord 保存独立克隆 Intent；同 RequestID 恢复固定 MailID/正文/原期限，读回确认一致后投递。未成功投递且已过期则拒绝；已交付正文 TTL 过去可返回原 intent 而不重新投递。

改动：service/mail/service.go、store.go、send_intent.go。

回归：`TestReviewTransientEnvelopeFailureCanRetrySameRequest`。修前证据保留在 [第一轮](../bug/REPRO-2026-09-29-services.md) / [第二轮](../bug/REPRO-2026-09-29-services-02.md)；RR-09 修前是源码接线缺口，其他项有动态 FAIL。正式行为回归位于对应包，含 race；排行及 session ABA 使用隔离真实 Redis。统一命令、实际计数与未测边界见 [本轮总记录](SERVICE-BUGFIX-2026-09-29.md)。

兼容与边界：旧 ledger 没 Intent 且缺正文时仍 ErrConflict；不能用重试者的不同请求伪造原内容。Intent 增加 ledger 内存/Redis体积，未测容量。
