# RR-20260926-27 修复：快 worker 上的 Remote 删除在副作用前确定拒绝，不再 fence 全进程

问题：[RR-20260926-27](../bug/RR-20260926-27.md)（探针见 [REPRO-2026-09-26-03 §3](../bug/REPRO-2026-09-26-03.md)）。
日期 2026-09-26；实施基线 main `87d9499`（本批 RR-26/25 提交之上）。状态：已修复、本地验证通过，已提交未推送/未发布。

## 根因

- `dataengine/engine/entity_delete.go:43-44`（基线）：没有 RollbackTx 的 Remote 托管实体删除直接走
  `admitRemoteEntityDelete` → `remoteentity/batch.go:43` `PrepareRemoteWriteBatch` 入口的 `fctx.AssertBlockingAllowed` panic；
- `entity_delete.go:26-31`：准入的 recover 不区分 panic 来源，一律标 `DeleteAdmissionIndeterminate` 并 `runtime.fail(err)`
  （kit `onFatal` → `Nest.Fence` + RuntimeFailure，`kit/dataengine/mod.go:357-375`）；`entity/entity_manager.go` 对不确定结果防御性摘除实体；
- 同一处用 `%v` 格式化 recovered 值，`errors.Is(err, fctx.ErrBlockingInFastWorker)` 与任何 panic 原因都丢失。

此时远端批次、WAL、内存都没有被动过，却被当成“持久化可能已删除”处理——一次误用即 fence 全进程。

## 决策

- 在 `admitRemoteEntityDelete` 调用 `PrepareRemoteWriteBatch` **之前**用 `fctx.BlockingError` 显式检查：快 worker 上返回
  `DeleteAdmissionImmediate` 和 `%w` 包裹的 `ErrBlockingInFastWorker`（含实体 ID 与 handler 名）。EntityManager 对 Immediate
  + 错误的既有处理是解锁、保留实体、返回错误；不 fence、不摘除。
- 准入 recover 其余 panic 仍按不确定处理（fatal + 摘除），但 recovered 值是 error 时改用 `%w`，保留 `errors.Is` 链。

未采用：**在 recover 里按错误类型把 `ErrBlockingInFastWorker` 归为确定拒绝**。recover 只能看到 panic 的类型，看不到它发生在
哪个阶段：今天快 worker 上唯一可达的断言恰好在 Prepare 入口，但 Commit/Close/等待入口同样会抛这个错误，将来任何一处
出现在副作用之后，类型推断就会把“远端可能已提交”误判为“确定未发生”——这正是 RR-32 要消除的“按错误类型推断是否已提交”。
在已知的副作用前位置显式检查，确定性来自代码位置而不是错误分类；这与 roost-coding“快池检查须早于等待和副作用”一致，
也和 `ManagerAccess` / `EntityRepository` 的写法相同。行为结果与任务要求一致：快池断言类拒绝返回 Immediate 并保留 `errors.Is`，
其余 panic 保持不确定。

本地删除（`admitLocalEntityDelete`）走锁内 WAL 准入，是 roost-coding 明确豁免的快池路径，不受影响；声明在消息里的 Remote 删除走
`deferEntityDelete`（随 Nest 事务），也不受影响。

## 文件与行为

- `dataengine/engine/entity_delete.go`：`admitRemoteEntityDelete` 副作用前的快 worker 检查；准入 recover 对 error 值使用 `%w`，注释说明为何其余 panic 仍不确定。
- 回归 `dataengine/engine/entity_delete_fast_worker_promises_test.go`：
  - `TestFastWorkerRemoteDeleteIsDefiniteRejection`（REPRO §3 探针改写，真实 `remoteentity.Manager`）：错误可 `errors.Is(ErrBlockingInFastWorker)`、fatal 0 次、实体仍在内存；
  - `TestDeleteAdmissionOtherPanicStaysIndeterminate`：非快池 panic 仍 fatal 一次、摘除实体，且错误与 fatal 都保留 panic 原因。

## 兼容性

快 worker 上直接删除 Remote 托管实体（无 RollbackTx）从“fence 全进程 + 实体被摘除”变为“返回错误、实体保留”。
调用方应把目标声明进 Nest 消息，让删除随事务走 `deferEntityDelete`，或在慢阶段调用。其余 panic 的错误文本不变，
但现在可以 `errors.Is` 到原因。
