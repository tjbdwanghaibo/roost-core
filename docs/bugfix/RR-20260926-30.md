## 2. 链路与根因（指到行）

1. 原生 saga 步骤：`saga/command_consumer.go:358-378` 在慢路径 `inbox.Reserve` 拿到 claim（owner、token、digest），把 reservation 挂到 ctx；
   业务 Nest handler 里 `inbox.Bind`（`saga/dataengine_step_inbox.go:115-136`）→ `saga.BindCommand`（`saga/nest.go:66-91`）把 lease fence control receipt
   加进同一 CommitRecord。Nest 在 Guard 内完成内存修改并准入 WAL，向调用方完成。
2. 租约只在 Reserve 设置（`dataengine_step_inbox.go:184-193` 新建、`:208-221` 过期后 `$inc lease_token` 续到新 token），投影期间不续期。
3. 投影：`dataengine/engine/mongo_projection.go:83-101` 在 Mongo 事务里调 `leaseFencesMatch`（`mongo_store.go:300-330`），谓词来自
   `coredata.LeaseFence.Predicate`（`dataengine/lease_fence.go:63-72`：owner、token、digest、`pending`、`lease_until > now`）。不匹配 → 只写
   `Skipped: true` 的事务 marker 并 ack，不应用 mutation/effect。
4. 但 Nest 内存已经应用了这笔事务：实体版本是 v+1。同实体下一笔事务按 v+1 → v+2 投影，`mongo_store.go` 的版本 CAS 判 fatal 冲突（设计正确，
   不能放宽），Projector fence；重启回放同一 WAL，被跳过的记录仍跳过、后一笔仍冲突，起不来。
5. 同进程重投放大：JetStream AckWait < LeaseDuration；首个投递卡在 `waitReplay` 等 receipt，租约过期后的重投在 `:208-221` 拿到 token+1，
   handler 在已扣过的内存上再扣一次，形成 token=T（将被跳过）与 token=T+1（ExpectedVersion 基于前一笔的内存）两条记录，后一条同样冲突。

RR-19 只在 WAL 前拒绝了 Remote 写 + lease fence 的组合（`projector.go` `reserve`，`ErrRemoteLeaseFenceUnsupported`）；本地实体 + lease fence 未处理。
文档层面 `SAGA.md:77-82`、`kit/README.md:499` 承诺“旧 worker 晚到不产生副作用、不会成为永久 poison WAL”，对本地实体的内存与后续 WAL 不成立。

## 3. 必须同时满足的约束

- 不能跳过冲突 WAL、不能自动删/改 WAL 记录、不能放宽版本比较、不能伪造持久确认（roost-coding “DataEngine 与 Remote”）。
- 已准入并向调用方完成的事务不能丢（同一实体上、跟在被跳过记录后面的那些记录都已完成）。
- 快池不得阻塞等待、不得做 I/O；准入发生在 Guard 内的快路径上。
- roost-coding 明确写着：“若未来要支持投影时拒绝后的在线恢复，先设计完整内存与 Sync 回滚契约。”——被跳过的记录已经改了内存，
  且 on_change/periodic 可能已把效果同步给客户端。

## 4. 候选方案与反例

### (a) 跳过时让受影响本地实体失效，并确定处理其后基于旧内存的同实体记录

- 失效本身需要一条“从投影侧让 Entity 下线并重载”的正式路径：Projector 在后台 goroutine，不能直接取 Entity local 锁（慢池/后台不得持业务锁），
  要么新增一个投递到快池的驱逐任务，要么把实体标成“中毒”由 Nest 拒绝后续事务。两者都要决定 Sync 侧怎么处理已经发给客户端的效果（回滚帧/强制 resync）。
  这正是 roost-coding 要求先设计的“内存与 Sync 回滚契约”。
- “其后同实体记录”的确定处理：这些记录在跳过被发现之前就已准入并完成，业务逻辑读到的是含被跳过效果的内存。
  - 级联跳过它们 = 丢已完成事务、跳过冲突 WAL（禁止）。
  - 把它们的 patch 重放到 Mongo 状态上 = 放宽版本比较，并产出一个没有任何 handler 计算过的状态（禁止，且语义错误）。
  - 反例：投影积压 2 分钟（租约期），这 2 分钟内同一玩家的其他正常操作（背包整理、领奖）都已进 WAL 并回复成功；被跳过的扣减一旦确定，它们全部无法落库。
- 要让 (a) 成立，必须再加**实体屏障**：只要实体上有未投影的 lease-fence 记录，就在 WAL 准入处（`reserve`，Guard 内、无 I/O）以可重试错误拒绝该实体的其他事务，
  Nest 在 Guard 内回滚。这样 WAL 里不会出现依赖被跳过记录的后续记录；跳过后仍需把实体驱逐/重载才能解除屏障。
  代价：每次原生步骤后该实体在投影完成前只读（正常毫秒级，Mongo 慢/中断时可达分钟级），玩家在此期间的操作被拒绝；需要一个对外可见的错误码与重试约定。
- 结论：屏障可以在 DataEngine 内实现，但“跳过后驱逐 + Sync 回滚”缺契约；只做屏障不驱逐，跳过后下一笔仍冲突。**需要拍板。**

### (b) inbox 层保证同进程同一 claim 的 WAL 记录未投影前不被重新 Reserve / 租约随投影续期

- 同进程不重新 Reserve：能消除第 5 条的“内存再扣一次”，但第一条记录仍会因租约过期被跳过，内存仍领先，下一笔仍冲突——**单独做不是修复**。
- 租约随投影续期（心跳）：续期是独立的 Mongo 写。投影延迟的典型原因就是 Mongo 慢或中断，此时续期同样失败；租约过期后另一 worker 可合法接管
  （`$inc lease_token`），我方记录必须被跳过以保证“至多一次”，回到原问题。反例：Mongo 主从切换 3 分钟、租约 2 分钟。
- 改谓词为“token 未变即有效”（过期但无人接管时允许投影，并在投影事务里写 claim 文档与并发 Reserve 串行化）：可以消除“过期但没人接管”这一类跳过；
  但仍有接管后跳过：进程崩溃→租约过期→别的进程接管（token+1）→本进程重启回放 WAL，被跳过记录之后若有同实体记录就启动即 fatal；
  或实体所有权在本进程 WAL 未排空时迁走。要排除这些，需要把“实体所有权只在该实体的 WAL 记录投影完成后才能迁移、步骤只在所有者进程执行”
  从 demo 约定（`gift_saga.go.tmpl` 的 `Admit`/`OwnedHere`）升格为框架契约。
- 结论：这是**改变 lease fence 语义**（从“租约未过期”到“claim token 未变”，停滞但存活的 owner 会一直占着命令直到有人 bump token），并新增跨进程所有权契约。**需要拍板。**

### (c) 准入时以持久时间约束拒绝

- 在 reservation 里带上 `lease_until`，准入（Guard 内、无 I/O）时要求剩余租约 ≥ 某个投影余量，否则在 WAL 前拒绝。
- 反例：投影延迟没有上界（Mongo 中断、积压、退避到 RetryMax），任何固定余量都可能被超过，超过后仍然跳过且内存领先。它只能降低概率，
  不能保证“跳过的记录没有改过内存”。另外跨机时钟偏差直接进入判定。**不是正确修法。**

### (d) 其他被否定的方向

- 本地 fenced 记录租约过期时判 fatal 而不是跳过：把“下一笔冲突 fatal”提前成“这一笔 fatal”；重启后记录仍过期，只能跳过，跟在后面的同实体记录照样冲突——不解决且更伤可用性。
- 跳过时改写/删除 WAL 中后续记录或其 ExpectedVersion：明确禁止。
- 像 RR-19 一样在 WAL 前一律拒绝“本地 mutation + lease fence”：等于禁用原生 saga 步骤（它的全部意义就是本地 DAO 修改与 fence 同一事务），是功能删除，需要产品决定。

## 5. 需要维护者拍板的契约点

1. **跳过后的内存与 Sync 恢复**：被 fence 跳过的事务已改内存（并可能已同步给客户端）时，框架是否提供“驱逐并重载实体 + Sync 回滚/强制 resync”的正式路径？
   由谁触发（DataEngine 投递快池任务 / Nest 中毒拒绝 / 业务层）？
2. **实体屏障是否可接受**：原生步骤提交后、投影完成前，同实体其他事务在 WAL 准入处以可重试错误拒绝（对外错误码与重试语义）。这是 (a) 成立的前提，
   也能消除“跳过后 WAL 里有依赖记录”这一不可恢复形态。
3. **lease fence 的语义**：维持“租约未过期”（当前），还是改为“claim token 未变”（过期但无人接管仍可落库，投影事务写 claim 串行化并发 Reserve）？后者要求同进程在记录未投影前不重新 Reserve。
4. **跨进程所有权**：是否把“实体所有权只在其 WAL 记录全部投影后才迁移、原生步骤只在所有者进程执行”写成框架契约（目前是 demo 的 `Admit` 约定）？
5. 若以上都不做：是否接受把“本地 mutation + lease fence”也在 WAL 前拒绝（禁用原生步骤），或在文档中把 `SAGA.md` / `kit/README.md` 的承诺改为
   “投影积压超过租约期会导致 fence，需人工处理”，并给出运维判别与处置？

推荐组合（供决策参考，未实施）：2 + 1（屏障 + 跳过后驱逐重载，Sync 走强制 resync），不改 lease 语义；它不依赖跨进程所有权契约，
重启路径天然成立（屏障保证 WAL 中被 fence 记录之后没有同实体依赖记录，启动恢复在加载前完成，跳过后实体从 Mongo 读取）。

## 6. 相关疑点（未登记，供审查分流）

`leaseFencesMatch`（`mongo_store.go:300-330`）在投影事务里只**读** claim 文档。Reserve 的接管是另一个事务里的 `FindOneAndUpdate`（`lease_until <= now`）。
两个事务在租约到期附近并发时：投影事务的快照读到租约有效，接管事务在到期后提交 token+1；投影事务没写 claim，不产生写冲突，也会提交——两边都执行。
窗口是一个投影事务的时长，并受两台机器时钟偏差影响。修正方向是投影事务对 claim 文档做一次写（例如条件更新 `updated_at`）以与 Reserve 串行化。

### 1. 采用的契约

维护者采用 §5 推荐组合 **2 + 1**，**不改 lease 语义**（fence 仍是“owner/token/digest/pending 且 `lease_until > now`”），不引入跨进程所有权契约（契约点 3、4 不采用），
同时收敛 §6 写偏斜。

1. **实体屏障（契约点 2）**：原生步骤记录（本地 mutation + lease fence receipt）准入 WAL 后、投影结果确定前，写到同一实体的其他事务在 WAL 准入处以
   `dataengine.ErrFencedEntityPending` 拒绝。检查与登记都在 `Projector.reserve` 的 `heldMu` 临界区内（`fenced_step.go` `checkFencedEntitiesLocked`、
   `entity_projection.go` `trackEntitiesLocked`），不读 Stats。屏障挂在该记录的 `entityProjection` 上，与它同生命周期：投影成功（`completeProjection`）、
   驱逐完成、`discard`（WAL 追加失败）、fatal 与关闭（`completeAllTickets`）、pipelined 写入结果未知（`signalWhenDurable`）都经 `finishEntitiesLocked`
   解除，没有单独的释放路径可漏。实体 ID 与冷加载等待用同一规则（DAO 共用完整 Entity ID）。
2. **同一步骤的重投**：重投若在租约过期后接管，拿到新 token、是另一条记录，同样被挡；它只被挡到上一条记录结果确定（投影成功，或跳过并驱逐完成）为止。
   `SubscribeDataEngineStep` 在 handler 以该错误失败时交还本次刚拿到的租约（`releaseLease`：只对仍属本 owner/token 的 pending claim 把 `lease_until` 设为
   现在），屏障解除后的重投可立即重新 Reserve，不必等本次租约自然过期。依据：该错误说明这次 Nest 事务在 WAL 前整体回滚、没有带本 token 的记录；即使 handler
   另有一笔用了本 token 的已准入记录，交还后它最多被跳过，被跳过的原生步骤会被驱逐，不会重复副作用。
3. **跳过后驱逐重载（契约点 1）**：`MongoStore.ProjectFenced` 报告记录是否因 fence 失效被整笔跳过（含重放时读到的持久 skipped 标记）。被跳过（或 Store 报告
   不了结果）的、本进程这次准入的原生步骤，保留其 `entityProjection`（屏障与冷加载等待都保留），交给按需启动的单个驱逐 worker（`runEvictions`，队列空即退出）。
   worker 经 `entity.RunLocal` + Nest 绑定的执行器在**快池**持锁执行 `EntityManager.Destroy(..., DestroyReasonCommon, false)`（不删库），只驱逐开始时看到的
   那个对象；成功后才 `completeProjection` 解除屏障与等待，失败按 RetryMin→RetryMax 退避重试，期间屏障保持（宁可可重试地拒绝写入，也不在含被跳过效果的
   内存上继续接受事务），关闭时统一解除。驱逐 worker 不在快 worker 上，允许同步等待快池。
4. **正式快池入口**：`nest.NestMgr.RunLocal(ctx, fn)`：fn 在快 worker 上运行、调用方同步等待；走续行通道（与慢阶段借用快池同一条），**不排在任何实体的
   同 ID 链上**，所以同一实体的慢准备（例如正等该实体投影/驱逐的冷加载）不会与它互相等待；快 worker 上调用返回 `fctx.ErrBlockingInFastWorker`；引擎未启动、
   已开始停机或已 fence 时返回错误且不执行 fn；投递后等到 fn 结束，不因 ctx 提前返回。实现 `nest.LocalExecutorBinder` 的 committer 在 `NewEngine` 时自动
   拿到它（Projector 与 kit/dataengine Mod 已实现；Mod 经 `AssemblyDeps.LocalExecutor` 转交启动后才创建的 Projector）。未绑定（独立使用 DataEngine）时
   按 `entity.RunLocal` 的既有约定就地执行。
5. **Sync**：驱逐会关闭实体的 `SubjectSyncState`。entitysync 对关闭的状态不捕获、不重试、不计失败（`flush.go` `ErrSubjectSyncClosed` 分支），订阅者保留原对象。
   `entitysync.Manager.Rebind(state)`（`Register` 遇到旧状态已关闭的同 ID subject 走同一路径）把 subject 接到重载出来的新状态：订阅关系不变，每个非 leaving
   订阅者 `baseVersion` 清零、改为等待全量、`revision` 前移（与换 profile 同一机制，旧状态在途捕获作废），下一帧收到整份全量（已持有对象是 ObjectUpdate + Full，
   引用不变），之后增量从这份全量的版本继续，而不是接着旧版本链续发。重载触发点是 `EntityRepository.OnEntityLoaded`（与发布同一次本地执行，回调 panic 被隔离），
   kit nest Mod 在装配了 entitysync 时于 Start 注册、Stop 注销。`subject.state` 现在由 `subject.mu` 保护（`CaptureSync`、flush、forget、Close 都在锁下取用）。
6. **§6 写偏斜**：`leaseFencesMatch` 用 `LeaseFence.Predicate` 做一次条件 `UpdateOne`（`LeaseFence.Confirmation`：`$set updated_at`，字段名
   `LeaseFenceFieldUpdatedAt` 由 coredata 共享），与 `reserveInTransaction` 的过期接管写同一文档；Mongo 只允许其一提交，输家经驱动重试后看到对方结果。
7. **重启路径**：屏障保证被跳过记录之后 WAL 中没有同实体依赖记录（本进程准入时已被挡住）；启动恢复（`Runtime.Start` 的 Flush）在 loader 安装、实体可加载之前
   排空 WAL，被跳过记录此时没有常驻实体（未被本进程跟踪，不驱逐），之后实体从 Mongo 读取。ack 丢失后的同进程重放同理：第一次投影时已驱逐，之后常驻的实体都
   来自 Mongo。

未采用：在跳过路径里同步驱逐（投影 goroutine 等快池）——同实体上一个“只读该实体、写 Remote”的消息若正在等自己的投影结果，会与投影 goroutine 互等到超时；
经同 ID 链的 Nest 消息驱逐——冷加载等驱逐、驱逐排在冷加载之后会互等；原地用 Mongo 数据覆盖内存——需要快池内 I/O 或额外的一致性论证，且生成 Entity 的派生状态
不会随 DAO 恢复。

### 3. 兼容性与对外错误

- **行为收紧**：原生步骤未投影期间，同实体写事务（含 `EntityManager.Destroy(..., true)` 的删档准入、同一命令的重投）返回 `ErrFencedEntityPending`
  （`errors.Is` 同时满足 `nest.ErrCommitRejected`），Nest 已回滚、未写 WAL。**可重试**：业务应回复“稍后重试”或延迟重投，不得当作业务拒绝；正常持续一次投影，
  Mongo 慢或中断时与投影积压同量级。只读 handler 不受影响。
- 跳过后实体被驱逐：`OnDestroy(DestroyReasonCommon)` 会被调用（业务无法与普通卸载区分），不删库；自建 entitysync 装配需要在 `OnEntityLoaded` 里调用 `Rebind`，
  否则驱逐后的 subject 停在关闭状态直到 `Unregister`。
- entitysync：`Register` 对“旧状态已关闭”的同 ID subject 由返回 `ErrSubjectRegistered` 改为重新绑定；关闭状态的 subject 不再每 tick 报 prepare 失败。
- 投影会写 claim 的 `updated_at`；`WaitEntityProjection` 现在也等被跳过步骤的驱逐完成（RR-31 的所有权交接因此在驱逐完成后才放行，Nest 已停止时等到调用方 ctx）。
- 自定义 `ProjectionStore` 未实现 `ProjectFenced` 时，每个原生步骤投影后都保守驱逐一次（多一次重载，不影响正确性）。直接使用 `NewProjector`、不经 `NewRuntime`
  的装配没有驱逐器：被跳过步骤的屏障一直保持并告警，直到关闭（不会 fatal，也不会在含被跳过效果的内存上继续准入）。
- 新增导出 API：`dataengine.ErrFencedEntityPending`、`LeaseFenceFieldUpdatedAt`、`LeaseFence.Confirmation`；`engine.FenceOutcomeProjectionStore`、
  `MongoStore.ProjectFenced`、`Projector.BindLocalExecutor`、`ProjectorStats` 三个字段、`EntityRepository.OnEntityLoaded`、`AssemblyDeps.LocalExecutor`；
  `nest.NestMgr.RunLocal`、`nest.LocalExecutorBinder`；`entitysync.Manager.Rebind`；kit/dataengine `Mod.BindLocalExecutor` / `Mod.OnEntityLoaded`。
  无删除、无改名、无持久格式变化（WAL 记录与 skipped marker 不变）。
- 运维可见：指标 `dataengine.fence.evictions.started.total` / `dataengine.fence.evictions.failed.total`（既有 `dataengine.fence.skipped.total`），
  日志 `evicted an entity whose lease-fenced step was skipped` / `evicting entities of a skipped lease-fenced step failed`。

### 6. 未验证项与风险

- 屏障只看写集合：一笔只**读**含被跳过效果的实体、写另一实体的事务不在屏障内，其结果以幻影数据为基础，但不会造成版本冲突；这是既有“同步/读取在投影前可见”
  语义的一部分，没有额外处理。
- 客户端在准入时已收到被跳过的效果（on_change/periodic 都一样）；驱逐到重载之间该对象不再同步，重载后的全量纠正。未重载前不会主动发 remove。
- 驱逐的 `OnDestroy` 用 `DestroyReasonCommon`；业务若在 `OnDestroy` 里做不可逆动作，需要自行判断。
- 多进程：实体所有权在本进程 WAL 未排空时迁走（契约点 4）没有纳入，仍依赖 demo 的 `Admit`/RR-31 交接屏障约定。Remote 写 + lease fence 仍在 WAL 前拒绝（RR-19）。
- 未跑故障矩阵（按任务要求）；未用 game-demo 生成工程做端到端（机器人 + 礼物 saga + 投影积压超过租约）；Mongo 主从切换下的驱逐重试只由单元测试的注入失败覆盖。
- `roost-coding` SKILL.md 中“若未来要支持投影时拒绝后的在线恢复，先设计完整内存与 Sync 回滚契约”一句未改；本修复只为本地原生步骤建立了该契约，是否更新规范由维护者决定。

### RR-20260926-50：驱逐按事务身份只登记一次；WAL terminal 唤醒全部等待方

- 上文“1. 采用的契约”第 3 条“交给按需启动的单个驱逐 worker”在 ack 失败重投时不成立：每轮重投都再入队一次、再计数一次，驱逐成功后多余项会卸载刚从
  Mongo 重载的新对象。现在 `entityProjection.evicting` 在 `heldMu` 下登记，同一记录只驱逐一次。
- 上文“3. 兼容性与对外错误”中“`WaitEntityProjection` 现在也等被跳过步骤的驱逐完成”补充：WAL terminal 时（`nestwal.WAL.Terminated()` 或 checkpoint 返回
  `ErrCommitIndeterminate`），Projector 唤醒全部待投影等待方（含等驱逐的），错误 `errors.Is(err, nest.ErrCommitIndeterminate)`，屏障随之解除，之后的准入在
  WAL 前拒绝。驱逐 worker 仍重试到成功或关闭。
- 详见 [RR-20260926-50 修复记录](RR-20260926-50.md)。

### RR-20260926-59：驱逐后仍有订阅者时主动重载并全量重绑

- 上文“1. 采用的契约”第 5 条与“6. 未验证项与风险”中“驱逐到重载之间该对象不再同步，重载后的全量纠正。未重载前不会主动发 remove”补充：订阅者在驱逐前
  已收到被跳过的效果，若没人再访问该实体就一直停在这份从未成为权威的内容上。现在 `ManagerAccess.Unload` 卸载时立即关闭同步状态，subject 仍有订阅者时由
  `ConfigureUnloadResync` 的重载 worker 在快池之外经正式 `EntityRepository`（等本记录的驱逐完成、屏障解除后再读 Mongo，发布与 `OnEntityLoaded`→`Rebind`
  回快池）主动重载，订阅者收到 Mongo 状态的全量；Mongo 里没有该实体（例如被跳过的正是它的首次落库）、有界重试用尽或重载队列已满时退回 `ObjectRemove`；
  无订阅者不重载。kit `NewModWithEntitySync` 自动接线；上文“3. 兼容性与对外错误”中“自建 entitysync 装配需要在 `OnEntityLoaded` 里调用 `Rebind`”之外，
  自建装配还需调用 `ManagerAccess.ConfigureUnloadResync` 才有主动重载。
- 回归：`dataengine/engine/fenced_step_resync_test.go`（正式 EntityRepository + fake Mongo + Nest 快池驱逐）。详见 [RR-20260926-59 修复记录](RR-20260926-59.md)。
