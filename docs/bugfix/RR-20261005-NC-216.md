# NC-216 修复：NegotiateSchema 拒绝任一边的空区间

[问题](../bug/RR-20261005-NC-216.md) · [本轮](../review/REVIEW-2026-10-05-n09-batch4.md)。已修复、声明场景验证，未发版。

## 根因与决策

`SchemaRange.Contains` 与 `NewApplier` 把 `Min == 0` 当空区间，`NegotiateSchema` 只在合并后的 minimum 为 0 时失败。`skill/skillsync/schema.go` 在合并前先检查两边：任一边 `Min == 0` 或 `Min > Max` 返回 `ErrSchemaNegotiationFailed`；其余逻辑（交集取最大）不变。

## 回归

`skill/skillsync/schema_negotiation_promises_test.go`：`TestNegotiateSchemaRequiresBothRangesToContainTheResult` 修前 `NegotiateSchema({0 5}, {2 3}) = 3; server contains=false client contains=true, want ErrSchemaNegotiationFailed`，修后 ok；有效区间取交集最大值的控制与既有 `skillsync_test.go:308` 修前修后都 ok。

## 兼容性

仓内无生产调用方；调用方若把 `SchemaRange{}` 当“任意版本”传入，现在会协商失败——这与 `Contains` 的口径一致。
