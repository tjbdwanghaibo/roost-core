# RR-20260927-20 修复：nest 包注册全局 handler 的用例收尾清表，单用例可重复运行

问题：[RR-20260927-20](../bug/RR-20260927-20.md)（OPEN-ITEMS A07）。
日期 2026-09-27；实施基线 `d4234c9`，分支 `fix-r7-hyg`（批次 2 卫生）。状态：已修复、本地验证通过，已本地提交，未合入 main / 未发布。
codebase-memory 图谱已过期（generation 09-26），结论来自当前源码与实跑。

## 根因（基线 `d4234c9`）

`nest/handler.go:50-63` 的包级 `handlerMap` 拒绝同名重复注册；25 个用例用 `MustRegisterHandler*` 写这张表却不在收尾清理
（清单见主记录），同一进程第二轮注册即 panic。整包运行能过，是因为后续用例开头的 `ResetHandlersForTest()` 恰好清掉了残留。

## 决策、文件与行为

- 采用清单推荐的第一种：每个用例开头加一行 `t.Cleanup(ResetHandlersForTest)`（行尾注释写 RR 编号与原因）。
  放在函数第一行，使它在 `t.Cleanup` 的后进先出顺序里最后执行——用例自己登记的停机 / 断言清理先跑完，再清 handler 表。
- 未采用“改唯一 handler 名”：名字唯一只能躲开同名冲突，全局表仍会跨用例累积；与同包已有的 `ResetHandlersForTest` 惯例（`client_test.go`、`group_*_test.go`、`nest_test.go` 其他用例）也不一致。
  未改成实例级 `mgr.RegisterHandlerWithMeta`：这些用例经 `InitNest` / 包级 `Request*` 跑，改注册入口会改变被测路径，超出卫生范围。
- `ResetHandlersForTest` 同时调用 `hotcode.ResetForTest()`；nest 测试里没有 `t.Parallel()`，也没有在 `init()` 里注册 handler（`init` 只注册 entity builder），清表不会影响其他用例。
- 文件：`nest/nest_test.go`（11 处）、`nest/pipelined_commit_test.go`（6）、`nest/pipelined_async_test.go`（5）、`nest/persist_change_test.go`（1）、`nest/sync_modes_test.go`（2）。无生产代码、配置、导出 API 变化。
