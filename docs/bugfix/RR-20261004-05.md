# RR-20261004-05 修复：mongotest 唯一索引按真实 Mongo 的 null / sparse 规则查重

问题：[RR-20261004-05](../bug/RR-20261004-05.md)（来源 [NC 复审第三组 §3 D4](../review/REVIEW-2026-10-04-nc-audit-3.md)；NC-27 留项，见 [RR-20261004-NC-27 复核后的补修](RR-20261004-NC-27.md#复核后的补修2026-10-04a-线)）。
日期 2026-10-04；实施基线 main `91ab67f7`（v1.19.0 + RR-20261004-02～05 登记）。等级 P3。状态：已修复，本地验证通过，已提交（worktree），未推送、未发版。

## 根因（基线行号）

- `mongo/mongotest/mongotest.go:960-971` `checkUniqueFieldsLocked`：待查文档任一索引字段 `lookupPath` 失败就 `values = nil` → `return nil`，整条文档不参与唯一检查；`:976-981` 对已有文档同样“缺字段即不相同”。
- `:393` `uniqueIndexes map[string][]string` 只存字段名，`:903-919` 登记时丢掉 `IndexModel.Sparse`；全文件没有 `Sparse`。
- 结果：非 sparse 唯一索引上两条缺唯一字段的文档（或一条缺字段、一条显式 null）在替身里建索引、插入、`$unset` 都成功，真实 Mongo 都报 11000。替身比真实宽松，会让“写入多条缺唯一字段文档”这类缺陷在测试里通过。

## 真实 Mongo 语义核对（隔离副本集）

结论：

- **单字段非 sparse**：缺字段按 null 建键，与显式 null 相等（S1～S4）；`$unset` 让文档变成缺字段同样撞 null 键（U1）。
- **单字段 sparse**：缺字段的文档不进索引（S5 前三步），显式 null **进**索引，两条显式 null 撞键（S5 末步）。
- **复合非 sparse**：缺的字段按 null（C1）。
- **复合 sparse**：只有**全部**索引字段都缺才跳过（C2 前两步、C4）；只要有一个字段存在（含显式 null），其余缺字段按 null 参与比较（C2 `{a:1}` 两条撞 `{a:1,b:null}`、`{a:1}` 与 `{a:1,b:null}` 相撞、`{b:2}` 与 `{a:null,b:2}` 相撞；C3 建索引失败）。
- **点路径**：穿过标量父字段（`{m:5}` 上的 `m.n`）与父字段缺失等同“缺字段”：非 sparse 按 null（P1），sparse 跳过（P2）。替身 `lookupPath` 对两者都返回 `ok=false`，与之一致。

## 决策

- 唯一索引登记保存 `Sparse`：`uniqueIndexes` 从 `map[string][]string` 改为 `map[string]uniqueIndex{fields, sparse}`。
- 新增 `uniqueKey(doc, index)`：缺字段的值取 `nil`（替身里 BSON null 解码后就是 `nil`，`valuesEqual(nil, nil)` 为真，显式 null 与缺字段因此相等）；sparse 且全部字段都缺时返回 `ok=false`，文档不进索引。
- `checkUniqueFieldsLocked` 对待查文档用 `uniqueKey`；扫描已有文档时内联同一规则（缺字段按 nil 比较，sparse 且已有文档一个字段都没有时不算冲突），不对每条存量文档分配切片。
- NC-27 的“先验存量、失败不发布”不变：`EnsureIndexes` 用同一个 `uniqueIndex` 先验证存量、成功才登记与发布，失败返回 `duplicateKeyError()`。
- 错误形状不变：仍是 `duplicateKeyError()`（`errors.Is(err, fmongo.ErrDuplicateKey)` 成立、不带 `TransientTransactionError` 标签），与 `mongo/driver` 对 E11000 的分类一致；回归里两点都断言。
- **partial 索引**：`fmongo.IndexModel` 没有 `PartialFilterExpression` 字段（`mongo/index.go:11-20`），框架与替身都不支持，本次不涉及；`uniqueIndex` 的注释写明。

### 未采用的方案

1. **只把“缺字段跳过”改成“缺字段按 null”，不看 Sparse**：sparse 唯一索引会比真实 Mongo 严格（S5、C2 前两步、C4 会误报 11000），替身从“宽松”变成另一方向的失真；按真实语义同时实现 sparse 不多花代码。（仓内现有唯一的 sparse 索引 `remoteentity/mongo_committer.go:233` 不是唯一索引，不受影响。）
2. **sparse 时任一字段缺就跳过**（单字段 sparse 的直觉推广）：与真实复合 sparse 行为（C2 / C3）不符，会重新放过 `{a:1}` 两条这类冲突。
3. **把缺字段写成 `bson.Null{}` 之类的哨兵**：替身存储的文档都经 `bson.Marshal/Unmarshal` 规整，显式 null 已经是 `nil`，直接用 `nil` 与 `valuesEqual` 现有的 nil 分支一致，不引入新类型。

## 文件与行为

- `mongo/mongotest/mongotest.go`：`Collection.uniqueIndexes` 类型；`EnsureIndexes` 登记 `uniqueIndex{fields, sparse}`；新增 `uniqueIndex`、`uniqueKey`；`checkUniqueLocked` / `checkUniqueFieldsLocked` 按上述规则比较。插入、upsert、update、replace、bulk 都经 `checkUniqueLocked`，一并生效。
- 回归 `mongo/mongotest/unique_null_promises_test.go` `TestUniqueIndexMissingFieldPromises`：12 个子用例逐一对应探针 S1～S5、C1～C4、P1/P2、U1，期望值取自上面的真实输出；建索引失败的用例同时断言索引未发布（`HasIndex` 为假），撞键用例断言 `ErrDuplicateKey` 且无 transient 标签，U1 断言被拒的 `$unset` 没改文档。

## 兼容性

- **行为收紧（仅测试替身）**：依赖 mongotest、在非 sparse 唯一索引上写入多条缺唯一字段（或缺字段与显式 null 混写）文档的测试，现在得到 `ErrDuplicateKey`，与真实 Mongo 一致；需要“允许缺字段”的应在 `IndexModel` 上设 `Sparse: true`（真实部署同样需要）。
- 生产代码、`mongo/driver`、公开 API、持久格式不变；`Collection.Indexes` 照旧保存原始 `IndexModel`。
- 仓内生产唯一索引核对：`dataengine/engine/mongo_store.go:116`（`effect_id`）、`saga/mongo_store.go:74`（`type,business_key`）、`saga/dataengine_step_inbox.go:112`（`namespace,command_id`）的字段都没有 `omitempty`，`BusinessKey` 由 `StartSaga` 校验非空，写入时总存在，不受影响。

- `demo/game/controllers/player/guild_ids_test.go.tmpl`、`demo/internal/service/game/gift_recipient_test.go.tmpl` 使用 mongotest，但只在生成工程里编译运行；两者只 `Seed` / `InsertOne` 序列与玩家集合、不建唯一索引，按代码判断不受影响，未生成工程实跑。

- 探针只覆盖升序单字段 / 复合、点路径与 `$unset` 的 null 键语义；哈希、文本、2dsphere 等索引类型替身本来就不区分，未核对。
