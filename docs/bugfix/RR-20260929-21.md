# RR-20260929-21：Directory 删除原子校验身份

状态：已实施，Memory/真实 Redis 回归通过；未发版。[原问题](../bug/REVIEW-2026-09-29-services-03.md#rr-20260929-21) · [本批验证](SERVICE-BUGFIX-2026-09-29-03.md)。

Cancel/Release 的外层 Token/Owner 检查与普通版本 Delete 分离，删除重建后版本重复，旧删除会移除新条目。Redis Lua 原子性本身不能补足缺失的逻辑身份。

`kit/service/directory/store.go` 使用现有 ConditionalDeleter.DeleteIf：
- Cancel 原子匹配 Claim.Token、读到的 Owner、reserved 状态。
- Release 原子匹配调用 Owner、读到的 Token/State，保护同 Owner 换代。
- Cancel 保留 stale no-op，Release 保留 owner mismatch；不改泛型 Store.Delete 的原有版本契约。
- New 拒绝不支持身份删除的 store，计数/故障 wrapper 显式转发该能力，禁止不安全降级。

正式回归包含 Memory/Redis × Cancel/Release × 不同/相同 owner，共 8 个确定性重建交错，以及不支持能力的构造拒绝。新 B 的 Token/Owner 始终保留。已有目录重试、过期、并发、指标测试通过；versionstore 的现有索引一致性与 ConditionalDelete 回归随完整服务检查通过。

无需数据迁移；自定义 backend/wrapper 必须实现/保留 DeleteIf，其 predicate 检查针对原子删除的值。未做 Redis HA/断网或生产目录修复；此前已误删的名字记录需业务对账，不由升级自动重建。
