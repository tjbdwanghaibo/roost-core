# RR-20260924-24：连接失败后刷新 Cluster 拓扑，不重放写操作

对应 [问题](../bug/RR-20260924-24.md)。新增同包 `redis/driver/cluster_recovery.go`，仅为 Cluster 客户端注册 hook。

- 命令或 pipeline 返回网络错误、EOF 后，请求客户端已有的合并异步拓扑刷新。
- 保留原错误；不增加命令执行次数，不重放可能已执行的 Lua。
- 调用方取消、deadline 和普通业务错误不触发刷新；单节点客户端不注册此 hook。
- 不改变 key、Lua、协议、版本、事务或公开 API。

真实六节点故障测试修前 20 秒窗口接管失败，修后 **2.282580333s** 接管、fence 1 → 2，旧 owner 解锁被拒绝。全停时 300ms 调用预算内拒绝获取锁，AOF always 全节点重启后版本仍为 2、fence 增为 3。集成测试 race 通过（15.26s 测试主体）。这次主故障明确等待了 replica 实际接收状态，不声称 Redis 异步复制在未复制写丢失时仍保证 fence 单调。

hook 回归断言单命令/pipeline 均只执行一次、错误身份不变；Redis、driver、Remote、Kit Remote race 及相关 vet 通过。正常生成三种持久化策略业务链路也重新通过。复跑及完整矩阵见 [验收记录](../feature/REMOTE-ACCEPTANCE-2026-09-24.md)。
