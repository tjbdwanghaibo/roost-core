# RR-20261005-NC-38：保存 Saga Resume 的持久代际

[问题](../bug/RR-20261005-NC-38.md)，基线af2f67fb；已修复、声明场景验证，未发版。

## 实现与取舍

[mongo_store.go](../../saga/mongo_store.go) 的 recordDoc 增加 `incarnation,omitempty` uint32，toRecordDoc / record 双向保留 Record.Incarnation。不修改 Resume、CommandID、OperationKey、receipt digest、版本 CAS 或事务处理。复用框架已有代际，没有新命令规则、缓存或迁移器。

不能用忽略旧回执冲突、覆盖已有回执或放宽判重解决问题：相同命令身份必须保持原语义；真正丢失的是派发代际。保留两次恢复的 r1/r2 身份及同一业务 OperationKey。

## 证据与兼容

[正式状态消费](../../saga/mongo_resume_incarnation_promises_test.go)：正向与补偿两个旧反例红→绿；各自经过两次失败/Resume、每次创建新 Store/Engine 重新加载、outbox 身份、第三代成功和重复回执。四个读写控制覆盖0、1、17、uint32最大值的 Create/Get/GetByBusinessKey/List/Replace；最大值只验 BSON 往返，不验 Resume 溢出。

旧失败 `persisted generation=0, want 1` / `redispatch reused old command ID` / 第二次相同错误回执后仍 waiting；旧产品 overlay 两条再现。[输出、计数与复跑](evidence/noncore-bugfix-20261005-15/README.md)。真实 Mongo 未运行，mongotest 检验了正式 BSON 转换和状态消费，不证明网络、事务重试和副本集一致性。

字段为兼容性增加；历史缺字段默认为0，0仍不写字段，历史 CommandID 格式保持。**旧版本 writer 的完整 Replace 会丢掉新增字段，不能把混合新旧写入当成已支持的滚动恢复方案。** 不需重生成 DAO/Entity 或改命令 wire，但参与写 Saga 记录的协调器须使用修复版本。

没有自动修复历史已卡 waiting / 已复用的命令或回执，不能从现存数据可靠重建全部过去代际。先保留记录与回执定位；failed/manual_required 可走既有 Resume，waiting 则按既有超时/结果确认流程进入可恢复状态，禁止删除回执或篡改版本来让它前进。升级后的实际处置还需按业务状态核对。

相关race498叶子、根包14、build/vet/glsvet与正式生成双模式通过；本批没有真实 Mongo/NATS、HA、长容量或旧版 writer 混跑验收，未发版。
