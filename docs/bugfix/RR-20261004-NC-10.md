# RR-20261004-NC-10：发现与传输共用调用预算

2026-10-04，起点`e62729ac`。[原问题](../bug/REVIEW-2026-10-04-noncore-06.md#rr-20261004-nc-10)。**已修、声明场景验证，未发版。**

修前配置20ms但Discover没有deadline，协作发现依赖实际等待150ms父期限。CallDiscoveredChecked在组合入口创建child context，覆盖PickServer、picker与CallChecked；Call既有子期限受该parent约束，不会在发现之后重置完整预算。发现/选择返回后再次检查ctx.Err，晚到成功候选不能启动过期业务传输。

保留短父期限、nil ctx规范化、errors.Is发现cause、候选过滤、显式SID与业务status。nil client/bus在发现前返回ErrBusNil；独立PickServer仍采用调用方ctx，不偷偷增加它自己的默认timeout。组合调用的可等待发现阶段收紧为配置timeout；不在timeout后自动重试或向随机实例回退。

控制检查discovery/picker/transport的**同一deadline**，包括nil ctx、正常parent、更短parent与晚到候选；原发现budget与原错误cause反例转绿。三项最终28正式叶子、17原overlay、六包race/vet通过。[证据](evidence/noncore-bugfix-20261004-04/README.md)。发现为协作替身，未跑真实etcd/生成服务端消费者；配置期限是协作取消预算，不能强制中断忽略ctx的用户picker或status方法。
