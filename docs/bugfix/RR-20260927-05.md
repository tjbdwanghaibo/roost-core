## 决策（按清单推荐，沿用 `kit/dataengine/mod.go:292` 的写法）

- **生成的 Mod**（`codegen/internal/roost/render_player_tcp.go` → `internal/access/player/tcp/server_gen.go`）：新增
  `func (mod *Mod) StopBudget() time.Duration { return mod.config.ShutdownTimeout }` 与接口断言 `_ app.ModStopBudgetProvider = (*Mod)(nil)`。
  与 dataengine 一样：未 Init 时为 0（App 视为未声明）；Init 后是 `player_access.tcp.shutdown_timeout`（缺键或 0 为默认 10s；负值 `validateConfig` 拒绝启动）。
  监听关闭（`enabled: false`）时 Mod 仍注册、仍声明——停止是立即返回，声明值只是上限，不会让停机变慢；生成公式据此不区分 enabled。
- **生成公式**（`shutdown_budget.go` `serviceShutdownPlan`）：托管 player TCP 接入的服务（`serviceOwnsPlayerTCP`，与 `serviceModConstructors` 注册 `accessplayertcp.NewMod()` 同一条件）
  多一个声明方，声明值 `generatedPlayerTCPShutdownTimeout = 10s`（`player_tcp_config.go` 写进配置的默认值改为引用同一常量）。
  `total_timeout = 声明预算之和 + 3s × 未声明 Mod 数 + 5s` 不变，于是该服务 total 与宽限期各多 10s − 3s = 7s。其余服务不变。
- **doctor**（`checkShutdownBudgets`）：声明预算按每个声明方自己的配置键读（新增 `configuredDeclaredBudgets`）：dataengine 读 `dataengine.shutdown_timeout`（非正按 30s，RR-20260927-04），
  player TCP 读 `player_access.tcp.shutdown_timeout`（缺键或 0 按 10s，负值报“Mod 拒绝启动”：dev 配置 FAIL、示例 WARN 只指明文件与键）。
  之前这里是“dataengine 值 × 声明数”，多一个声明方后必须分开。建议值沿用 RR-20260927-04 的逐文件算法。
- **配置段自动更新**：`refreshGeneratedShutdownConfigs` 按“段是否与它注释里记录的那次计划逐字相同”判定未手改。生成段的注释文字（`renderShutdownConfig`）**刻意未改**——
  改了就认不出旧工程里未手改的段、sync 不再更新它们；注释里 `a Mod that declares one (dataengine.shutdown_timeout)` 的举例因此仍只写 dataengine，Mod 数、声明值合计与结果都是新值。
- `project sync` 的公式仍按生成值计声明方（dataengine 30s、player TCP 10s），不读配置（D11 同理）；调大 `player_access.tcp.shutdown_timeout` 要同时手动调大 total（doctor 提示）。

## 兼容性与迁移

- **新生成工程**：托管 player TCP 的服务 total 与宽限期 +7s（见上表）；App 停机时 TCP Mod 拿满 `shutdown_timeout`（默认 10s）排空连接，不再只有 3s 保底。
- **已生成工程重新 sync**：`server_gen.go` 是生成文件，sync 后 Mod 开始声明预算；配置里**未手改**的生成 `shutdown:` 段随之改写为新值（如 101s → 108s），部署模板宽限期同步 +7s。
  **手改过或 RR-66 之前格式**的段不改写：此时 total 没变而 TCP 多拿 7s，其余 Mod 可分的时间相应减少；若 total 覆盖不了新的“声明值 + 保底”，doctor WARN 并给出建议值（按配置里的 `player_access.tcp.shutdown_timeout` 计算），按提示调大三份仓内配置后再 sync。
- **未重新生成的工程**：行为不变（生成代码与配置都是既有文件）。
- 把 `player_access.tcp.shutdown_timeout` 调大（上限 5m）时，total 也要同步调大；生成公式不读该配置（与 dataengine 相同）。
- 无 app / kit 导出 API 变化。
