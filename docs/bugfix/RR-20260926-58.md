# RR-20260926-58：Remote 部分被拒绝时只丢弃 Remote 实体的 Sync 内容与事实，已提交的本地实体照常生效

问题：[RR-20260926-58](../bug/RR-20260926-58.md)（探针 [REPRO-2026-09-26-05](../bug/REPRO-2026-09-26-05.md) §7）。日期 2026-09-26。
实施基线：main `3e26f91`。状态：已修复，本地验证通过，已本地提交，未推送/发布。

## 根因（基线行号）

- `nest/msg.go:131-135`：`deferPostRemoteCommit` 交给批次的闭包在结论为拒绝时调用 `mutation.Reject()`，对整个 `SyncMutation` 生效。
- `entity/sync_commit.go:47-58,263`：拒绝标记在 `SyncMutation` 上（整笔），门的 `ready()` 与 `SyncCommitCondition` 都按 `batch.rejected` 判断。
  同一提交里每个实体各有一道门（`syncCommitGate`），但拒绝不区分实体：混合事务（本地实体 + Remote 实体）里本地部分已经持久提交、
  内存保留新值（没有任何路径回滚它），它排队的兴趣事实（AOI 移动、关系）却按“本提交被拒绝”丢弃，AOI 成员与位置不一致，直到该实体下次移动。
- 本地实体的冻结内容在修前已经照常交付（Reject 只让门不再阻塞），受影响的是事实。

## 决策（修复约束：Reject 只丢弃被拒绝 Remote 实体相关的内容与事实）

1. **拒绝按实体记录**：`syncCommitGate` 增加自己的 `rejected`；`passed()` = 已拒绝，或已释放且已确认。`ready()`、`Include` 的头结点修剪、
   `SyncCommitCondition`（只有本提交自己的门被拒绝才丢弃事实）都改看门自己的标记。
2. **新增 `SyncMutation.RejectEntities(ids []int64)`**：`ids` 是 Remote 批次的实体 ID。只把这些实体的门标为拒绝（不阻塞后续提交、本提交里
   关于它们的事实丢弃）；其余实体的提交已经持久，按 `Confirm` 放行，事实与冻结内容照常交付。`ids` 覆盖全部实体时等同 `Reject`
   （纯 Remote 事务行为不变）。先发布被拒绝实体集合再 `Confirm`，看到 confirmed 的读者一定也看到拒绝标记。
3. **没有 SubjectSyncState 的实体**（`SyncConditionFor` 的回退路径，看整笔提交）：按实体 ID 查 `RejectEntities` 的集合判断自己是否被拒绝。
4. **`Reject()` 保留**，语义明确为“整笔拒绝、没有其他已持久提交部分”，现在逐门标记。
5. **Nest 接线**：`deferPostRemoteCommit` 在交给批次前取 `batch.EntityIDs()`（闭包只捕获值），拒绝时 `mutation.RejectEntities(remoteIDs)`。
   AfterCommit 在拒绝结论下仍不执行（RR-37 语义不变）；被拒绝 Remote 实例的冻结内容仍由 RR-39 的仅内存卸载关闭同步状态时丢弃，
   所以 finalizer 仍在卸载成功之后才交付拒绝结论（未改）。

未采用：让 `Reject()` 自己按“是否 Remote 托管 kind”挑实体——mutation 里还有 Cast 动态加入、事务内新建等实体，是否属于被拒绝的 Remote 写
只有批次知道；按批次 ID 显式传入更直接。

## 交付前自查（本项）

- 混合事务 Sync 内容与事实一致：本地实体——内存保留、冻结内容交付、事实应用，三者一致；Remote 实体——实例被卸载（冻结内容随同步状态关闭丢弃）、
  事实丢弃、重载后 Rebind 全量，三者一致。
- 纯 Remote 事务：`RejectEntities` 覆盖全部实体时走 `Reject`，与修前完全相同（回归保护）。
- 只执行一次 / 不回退 RR-37：交接、只接受一次、终态后才交付的机制未改；拒绝结论下 AfterCommit 仍不执行，Confirm 只作用于本地已持久提交的实体。
- RR-28：被拒绝的 Remote 实例仍隔离到卸载，从不解冻；本修复只动 Sync 门，不动所有权状态。
