# RR-20261006-17 修复：OpenActivity 按活动组文件核对 expected 集合

问题：[RR-20261006-17](../bug/RR-20261006-17.md)。分支 `oa`，基线 `ac913a60`，未发版。

代码阅读：codebase-memory 共享 generation 停在 09-30（`groups.go` 未入索引，`service.go` / `activity_mod.go` metadata_changed），本轮以当前源码为准。

## 根因

`Service.OpenActivity`（`kit/service/global/activity/service.go`）只调用 `validateExpectedGames` 检查形状；Mod 读到的 `Groups` 只用于启动校验和 sweep 组，
没有交给 `Service`（C4 方案当时写“会改 Service 逻辑，留待需要时再做”）。

## 组定义在协调器侧从哪来、为什么这样选

协调器侧已经有来源：生成器给托管协调器的工程写 `activity.groups_file: configs/activity_groups.yaml`（`codegen/internal/roost/framework_services.go`），
文件随镜像 / release 发布，game 读同一份。所以不新增配置、不新增 RPC：Mod 把 `Init` 里已经加载的 `Groups` 经 `Config.Groups` 交给 `Service`，用户什么都不用多写。

- `activity.groups_file` 仍是可选键：未设置时（C4 之前生成、维护者决定不迁移的工程）协调器不做组核对，行为与修前相同。没有改成必填，因为那会让旧工程的协调器启动失败，
  而它们的 game 本来也不读组文件。
- 核对规则：Key 的组必须在文件里；expected 的每个 sid 必须是该组成员。**子集是正常的**——game 只把 `Live` 查到的活着的成员放进 expected。
- 时机：在 `admitToWindow` 之前，拒绝不留 opening 条目，sweep 没有东西可“帮着推进”。sweep 恢复已持久化的开窗计划时不再核对：计划在准入时已经被核对过，
  文件之后改动也不能让已接受的窗口变成另一个 expected 集合。
- 错误：`ErrInvalid`（RPC 报调用方错误码），文本点名文件路径、Key 的组、sid 及它实际所属的组（或“不在任何组”），没有定义的组附上文件里的全部组 id。
- 文件只在启动时读，与 game 侧一致；改组要重启两边（C4 方案 §3“文件是随代码版本发布的内容”）。

未采用：协调器从 game 的 RPC 里取组成员（多一份事实来源，正是 C4 要消除的）；组文件改为协调器必填（破坏未迁移的旧工程）。

## 改动

- `kit/service/global/activity/groups.go`：`Groups` 记录组 id → 下标；`checkExpected(groupID, expected)`。
- `kit/service/global/activity/service.go`：`Config.Groups *Groups`；`OpenActivity` 在形状校验之后、写入之前核对。
- `kit/service/global/activity/activity_mod.go`：`Init` 保存加载的组；`Provide` 的装配拆成 `newService(stores, now)`（测试用同一份装配接内存存储）。
- `codegen/internal/roost/activity_groups.go`、`framework_services.go`：只改注释（生成内容不变）。
- `kit/service/global/activity/open_expected_group_promises_test.go`（新）。

## 兼容（行为收紧）

设置了 `activity.groups_file` 的协调器拒绝 Key 的组不在文件里、或 expected 含组外 sid 的开窗（修前接受）。按生成配置运行、game 与协调器读同一份文件时不会触发；
两边文件版本不一致的部署会在开窗时得到点名的拒绝，而不是一个等不齐或发错的窗口。未设置该键的协调器不受影响。

## 验证（`GOWORK=off`）

- 修前红：见问题记录（四种不一致全部被接受）。
- 修后：`go test -race -count=3 ./kit/service/global/activity` ok；新用例覆盖四种拒绝（`errors.Is(err, ErrInvalid)`、点名文件 / 组 / sid、窗口与活动存储都没有写入）、
  组成员的任意子集都能开窗、未设置组文件时不核对。C4 原有用例（64 个全活开窗、Mod 读文件得 sweep 组）照常通过。

  （生成工程的 game 测试直接 `activity.New` 内存协调器，不设 `Groups`，不受影响）。
