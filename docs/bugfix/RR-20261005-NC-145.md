# NC-145 修复：默认排序先比动态类型

[问题](../bug/RR-20261005-NC-145.md) · [证据](evidence/noncore-bugfix-20261005-revn11/README.md) · [本轮](../review/REVIEW-2026-10-05-n11.md)。已修复、声明场景验证，未发版。

## 根因与修法

`defaultLess` 只看左操作数的 Kind。改为：nil 排最前；动态类型不同时按类型名排（同名再按格式化串）；同类型才按原来的数值 / 字符串 / 格式化串规则比较。同类型的数值序（此前已修的 `[9, 10]`）保持不变。

## 验证

`TestDefaultOrderHandlesKeysOfDifferentDynamicTypes`（9 种键、9 种插入顺序，要求不 panic 且顺序一致）修前 panic，修后通过；既有 `TestOrderedIndexDefaultOrdersIntegersNumerically`、`TestOrderedIndexCustomLessWins` 通过。
