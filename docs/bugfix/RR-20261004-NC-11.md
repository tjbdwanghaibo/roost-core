# RR-20261004-NC-11：竞选 setup 取消与长期 session 分离

2026-10-04，基线 `3560a19b5c2b2fbeb936bf1bb6a9c1fa0be1f956`。**已修复，声明场景验证，尚未发版。** [原问题](../bug/REVIEW-2026-10-04-noncore-08.md#rr-20261004-nc-11) · [本轮运行](../review/REVIEW-2026-10-04-noncore-09.md) · [红绿证据](evidence/noncore-bugfix-20261004-05/README.md)。

## 根因与决策

旧 [election.go](../../etcd/driver/election.go) 的 create 没有 context，NewSession 默认用 client.Ctx，caller 取消到不了 Grant。直接把 caller ctx 用作 session 生命周期又会破坏成功后取消等待不丢领导权的既有契约。

使用 client 的长期 context 派生 session context，通过可解除的 context.AfterFunc 将 setup 期间的 caller 取消连接过去，传给 NewSession 的 WithContext。成功时先解除连接并核对 caller/当前 session，再发布 fence 和领导权；取消竞争失败、已结束 session 不晋升。建立失败合并 caller 原因与 SDK 原因，真实 deadline 不再只得到 context.Canceled。

新增内部 campaignSession 管理这一个派生 context：失败关闭、主动 Resign 或 session loss 释放；Close 幂等、保留实际关闭错误。它的短状态锁与关闭锁分开。SDK Session.Close 会先触发 Done、再 Revoke，因此正常 Close 和退出观察者的 context 释放要串行，避免观察者提前取消 Revoke。未引入公开接口或新包，已有内部测试 factory 调整为接收 context。

未采用每次调用后台 goroutine 包装阻塞 NewSession、或成功时 defer cancel caller session；前者掩盖取消且丢失资源责任，后者让合法领导权失效。

## 实际验证

原测试经过正式 clientv3 → concurrency.NewSession → 专属本机 gRPC LeaseGrant。确认 RPC 入场后取消：修前 `returned_after_campaign_cancel=false err=context canceled`，关闭专属 client 才结束；修后按 caller 取消返回。

补充真实 Grant deadline 控制时，中间实现出现 `returned_after_campaign_cancel=true err=context canceled`，未通过错误原因判据；合并 caller/SDK 原因后通过，保留中间失败日志。成功后 caller 取消、session context 最终释放、取消与成功竞争、已取消请求不创建 session、Done 先于 Revoke 结束、session loss/重复竞选/fence 控制均通过。

最终相关两个测试包 `go test -race -count=1 -timeout=120s -json ./etcd ./etcd/driver ./kit/etcd`、三包 vet 通过：61 test pass 事件、59叶子/独立项、0fail/skip；其中新增正式生命周期15项（含NC-12）。KitEtcd没有测试，仅编译/vet。原overlay8项也转绿。命令和计数不能把两个 RR 的共同验证重复当成两倍覆盖。

## 兼容与边界

公开签名、租约格式、fence 格式及成功后生命周期不变；Campaign 的 nil ctx 归一化，已取消 ctx 在 setup 前拒绝，超时可通过 errors.Is 提取 DeadlineExceeded。没有迁移或自动重试业务。

取消停止 keepalive 不等于服务端已 Revoke。失败清理使用已取消 lifetime，Grant 的服务端结果也可能未知；没有证明 lease 已即时删除，应依赖租约 TTL/服务端状态处理，不能凭 caller 退出宣布权威已释放。正常 Resign 的 SDK Close 仍可能等待 TTL 级 Revoke（SDK默认60秒），本修复没有把 Resign 改成全链 caller 有界。真实 etcd、HA、lease失联恢复及长稳未执行；本机 gRPC LeaseServer不是完整 etcd 集群。短锁/取消桥/每成功 session 的观察者没有性能基准。[留项](../bug/CARRYOVER.md)。
