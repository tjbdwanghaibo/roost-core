# NC-51 修复：sweep 对已确认 Keys 执行与 Opening 相同的键合法 / 归属边界

[问题](../bug/RR-20261005-NC-51.md) · [证据](evidence/noncore-bugfix-20261005-revn06/README.md)。已修复、声明场景验证，未发版。

## 决策与实现

`kit/service/global/activity/service.go` 抽出 `windowKeyProblem(key, groupID)`（`Key.Validate` + `GroupID == groupID`），Opening 循环与 `openingIntentProblem` 改用它（行为不变），已确认 Keys 循环在任何 `Activities` 读写之前调用它：坏条目跳过、**保留**在 Keys（不剪、不移入 Delivering、不读不写别的组的活动），每 tick 计 `sweep.window_key_malformed`，日志与 Opening 一样只在出现 / 消失时各写一次（`malformedConfirmed` 按所属窗口分组，与 `malformedOpening` 分开，同一个键可能同时在两处）。

没有自动清理坏条目：本包从不写出它们，删除依据（“记录不在了”）对一个不该在这里的键不成立，与 RR-20261001-09 残余对 Opening 的决定一致。键约束自 v1.1（`cab72dfc`）起不变，不存在合法的旧格式键会被新校验挡住。已经混进 Delivering 的跨组键不处理（需运维）；`RetireDelivered` 对“不在该窗口”也返回 true 只记观察。

## 验证与边界

`confirmed_key_ownership_promises_test.go`：跨组确认键——修前 group-a 的 sweep 结算了 group-b 的活动，修后只结算本组、group-b 活动仍 collecting、无派发、不进 group-a Delivering、条目保留、计数 1，group-b 自己的 sweep 随后恰好结算一次；非法确认键——修前被剪掉，修后两 tick 均保留、计数 1→2，本组活动照常完成。`./kit/service/global/activity` `-race -count=3` 与既有 RR-09 / NC-42 回归全绿。真实 Redis / Cluster 未跑（纯窗口逻辑）。

## 复核后的补修（2026-10-06，维护者决定 B9）

[问题补记](../bug/RR-20261005-NC-51.md#复核后的补修2026-10-06维护者决定-b9) · [方案](../feature/B9-C5-WINDOW-ENTRIES-ROLE-TABLE-2026-10-06.md)。按维护者决定把“读已存窗口条目”收成一个入口，而不是在第五个循环再补一处判断。

- `kit/service/global/activity/window_entries.go`：`readWindowEntries(groupID, stored)` 把窗口拆成 `usable`（只含 `windowKeyProblem` 为空的条目）与 `malformed`（列表 + 键 + 原因）。`PendingActivities`、`DeliveringActivities`、`RetireDelivered`、`AdvanceExpired`（含 oversized 轮转的批次）全部从 `usable` 读；CAS 写路径只按显式键改，坏条目原样保留。
- 计数 / 日志合成 `noteMalformed(groupID, list, …)`：Keys 计 `sweep.window_key_malformed`、Opening 计 `sweep.opening_intent_malformed`（沿用）、Delivering 计 **新的** `sweep.delivering_key_malformed`；日志仍只在出现 / 消失时各一次。键坏的条目不需要 I/O 就能判断，所以每拍都报、不受批次限制；计划坏仍只在 sweep 要执行计划时判断，批次外的旧报告保留（RR-20261001-09）。
- `RetireDelivered`：先经入口确认键在本组 usable Delivering 里，不在就返回 false、不读活动、不写窗口；返回值改为“本次 CAS 确实移走了它”。
- 运维入口（`Admin`，持有方专用、无 `//roost:rpc`）：`MalformedWindowEntries(groupID)` 列出坏条目（含 Opening 里计划不可执行的）；`RemoveMalformedWindowEntry(groupID, list, key, note)` 在 CAS 里重新判断，只删确实坏的那一条（同列表里全部相同副本），健康条目 `ErrStatus`、不在 `ErrMissing`，note 必填并写到窗口 `admin_note` / `admin_action_at_unix`，计 `admin.remove_malformed_window_entry`。NC-42 说明过不自动修复，这就是人工处置的入口。

C4 核对：组 id 由 `LoadGroupsFile` 校验（trim 后非空、不含 `/`），与 `Key.Validate` 对 GroupID 的要求一致；game 的 `gameactivity.Key(groupID, …)` 用同一个组 id，协调器按 `Key.GroupID` 选窗口，`windowKeyProblem` 用同一个 id 比较——按组的 key 与统一入口一致，无需改动。
