# RR-20260918-06：连接关闭不驱动在线状态清理

- 单元：U-0243 · 缺陷类 C3（回调外累积状态）· 等级 P2
- 仓库：roost-codegen `internal/roost`（生成的接入层）+ `demo/`
- 排障行：T-137

## 问题

生成的 player TCP `Runtime` 只导出 push 与 `ActiveSessions`。`Server` 在连接退出时执行 `unregisterSession`，
但**不通知任何人**。于是所有维护"在线集合"的东西都只能靠推送失败懒清理，而**没有流量时永远不会失败**：
审查的独立复现先加入一个成员、让它的活动会话数降到 0、等两个复制周期——成员数仍是 1。

## 根因

框架侧知道会话什么时候关（`session.Close(gateway.ErrSessionClosed)` 就在那条路径上），只是没有往外发。
于是每个消费者各自发明一遍懒清理，而懒清理的触发点在**错误路径**上——正确性还在，错误归属与可观测性都是错的
（实跑日志里能看到 `scene: peer did not subscribe to the newcomer ... session not found`：
别人入场时才发现有个早就断线的成员）。

## 方案选择

- **（选中）生成一个异步、多订阅者的会话生命周期源**：关闭路径只把 `{PlayerID, SessionID}` 投进有界队列，
  单独 goroutine 调用订阅者；`OnSessionClosed` 返回 unsubscribe；Mod 停机时先停 server 再排空队列
  （关服路上产生的关闭仍然值得送达）。
- 在 socket 清理栈上同步回调：审查明确点名不要——一个慢订阅者会拖住连接清理。
- 让消费者自己轮询 `ActiveSessions`：把 O(在线数) 的扫描放进每个消费者，且延迟由轮询周期决定。

## 改动

- roost-codegen `internal/roost/render_player_tcp.go`：`SessionClosed` 类型、`Runtime.OnSessionClosed`、
  有界队列（`sessionClosedQueue = 256`）与派发 goroutine、`publishClosed`（**非阻塞**，满了丢弃并计
  `player_tcp_session_closed_dropped_total`）、`stopLifecycle`（排空后退出）。
  `Server` 多一个指向传输 `Runtime` 的回指，由 Mod 在 `Start` 之前装上。
- `demo/internal/service/game/scene.go`：订阅该源；收到关闭且该玩家已无活动会话时，在**自己的 goroutine** 上离场
  （派发 goroutine 是共享的，订阅者不该在上面做事）。`Close` 时退订。

**丢弃是有意的**：每个消费者都必须能承受漏掉一条——"谁在线"是被**对账**的状态，不是被重放的日志。
入场时的 `ActiveSessions` 扫描因此保留，作为第二道。

## 证明

`demo/internal/service/game/scene_test.go` 的 `TestAClosedSessionLeavesTheSceneWithoutAnyTraffic`：
加入一个玩家，把它的会话标记为已关闭并触发源，**不产生任何其他流量**，断言两秒内成员归零。
修前红：把 `scene.watchSessions(recorder)` 一行去掉即
`the scene still holds 1 members two seconds after the session closed, with no traffic to notice it`
——与审查的独立复现是同一件事。

## 未做 / 边界

- **chat presence 没有改**：它有同样的问题（`chat_push.go` 里推送失败才 `Remove`），但它的在线集合还兼作
  "世界频道的收件人列表"，改动要连带定"收件人从哪来"，本轮没做。审查建议 scene 与 presence 订阅同一个源，
  这条只做了一半。
- 只有"关闭"一个事件，没有"打开"。订阅者因此只能收敛，不能靠这个源重建在线集合。
- 队列满时丢弃只计数、不告警；没有暴露队列深度。

## 复核后的补修（仍归 U-0243）

09-19 的审查把这一条更正为**部分修复**：新增的关闭源和 scene 接线都通过了验收，但记录里自己写的
"chat presence 没有改"就是剩下的一半——push 失败时的懒清理在安静的世界里永远不触发，离线玩家
一直留在世界频道的收件人集合里。

补修：`game/chatroom` 的 presence 变成进程级单例（`DefaultPresence()`，此前它住在 controller 里，
而需要清理它的是服务），`internal/service/<game>/presence.go` 用同一个会话关闭源订阅，
在玩家最后一个连接关闭时把他移出集合；订阅回调只做一次 map 删除，不做 I/O。
测试 `internal/service/game/scene_test.go` 的 `TestAClosedSessionLeavesTheWorldChannel`
（含"还有另一条连接的玩家不被移除"）；把 `presence.Remove` 注释掉即红。
