# RR-20260920-07：`SmallSafeMap` 说它会编码 BSON，而它并不会（U-0265，C2）

## 问题

`safemap/small.go:121-133` 实现了

```go
func (m *SmallSafeMap[K, V]) MarshalBSONValue() (bson.Type, []byte, error)
func (m *SmallSafeMap[K, V]) UnmarshalBSONValue(t bson.Type, data []byte) error
```

驱动（`go.mongodb.org/mongo-driver/v2@v2.6.0`）要的是 `(byte, []byte, error)` 与 `(byte, []byte) error`。
`bson.Type` 是 `type Type byte`——**定义类型，不是别名**，所以签名不匹配、接口没有被实现、方法被静默忽略。
类型退回默认结构体编码器，而它的字段（`mu`、`entries`）都是未导出的，于是被写成**空文档**。

## 根因

C2（空洞测试 / 宽容替身）：原有的 `TestSmallSafeMapBSONV2RoundTrip` **直接调用这两个方法**，
所以它证明的是"方法本身能工作"，而不是"bson 会调用它们"。签名错了多久，这条测试就绿了多久。

Go 在这件事上不给任何提示：实现接口不需要声明，签名不匹配只是"没有实现"。

## 方案选择

- **采用**：改成驱动的签名，并加 `var _ bson.ValueMarshaler / ValueUnmarshaler = (*SmallSafeMap[...])(nil)`。
  断言才是修复的主体——它让下一次写错在**编译期**红，而不是等到某个文档变成 `{}`。
- 放弃 **给类型加导出字段**：那是让默认编码器凑合，等于放弃自定义编码。
- 放弃 **只改签名不加断言**：这个坑我在 U-0261 里刚踩过一次（`entity.RemoteChecksum` 的第一版也是
  `bson.Type`），两次都靠人眼发现，说明需要机器来管。

## 改动

`safemap/small.go`：两个方法改签名（内部 `byte(typ)` / `bson.Type(typ)` 转换），加两条接口断言，
注释写明 `bson.Type` 是定义类型这件事。

## 证明

`safemap/bson_promises_test.go`：

- `TestSmallSafeMapSurvivesABSONRoundTrip`：empty / one / several 三组，走 `bson.Marshal` → `bson.Unmarshal`。
  修前红：

  ```text
  round trip produced 0 entries, want 3 (map[])
  round trip produced 0 entries, want 1 (map[])
  ```

  注意 **empty 那一组修前也是绿的**——所以有了第二条。
- `TestSmallSafeMapEncodesItsContentsNotItsFields`：断言编码结果是一个**带内容**的文档。修前红：
  `encoded as {}, want the map's own entries`。
- 两条编译期断言。它们在修前直接让包编译不过（`have MarshalBSONValue() (bson.Type, []byte, error)` /
  `want MarshalBSONValue() (byte, []byte, error)`），所以捕获上面那段行为级红文本时把它们临时注释掉了。

`TestSmallSafeMapBSONV2RoundTrip` 保留并加注释说明"直接调用方法不足以证明 bson 会用它"——
按规矩改成不再声称它证明了往返，而不是删掉。

## 未做 / 边界

- **没有扫描其它类型的同类问题以外的接口**。本次只扫了 `MarshalBSONValue` / `UnmarshalBSONValue`：
  三仓内除本条外只有 `entity.RemoteChecksum`，签名正确。其它"隐式实现"的接口（`json.Marshaler`、
  `driver.Valuer` 等）没有逐一核对，值得作为一次独立的清扫。
- 存量数据不受影响：这个类型从来没有成功写进过 Mongo，所以没有需要迁移的旧文档。
