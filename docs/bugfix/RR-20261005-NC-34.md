# RR-20261005-NC-34：注册表变化前校验完整兴趣消息

[问题](../bug/RR-20261005-NC-34.md)，基线 b2232db5；已修复、声明场景已验证，未发版。

## 决策与实现

[interest.go](../../remoteentity/interest.go) L176 起复用发布端的 `remoteInterestReplicaKey`，检查 payload key.Valid、SID非零、Envelope.OpUpsert、hash key 和 ExpiresAt 版本相等，再进入 renew/release。发布格式、哈希维度、代际逻辑和注册表容量不变；错误在任何注册表副作用之前返回。

不将 Envelope.Version 改成 Generation：旧发布者使用纳秒到期时间，合法撤销常早于原 lease 到期；排序仍由 payload.Generation 负责。没有把 release 转为缺少完整订阅身份的通用空 Delete，也没有新增重复协议或权限系统。

## 兼容与验证

合法 renew/release wire 不变；错误操作/身份/版本现在明确拒绝。通用 Replicator 仍负责补全省略的内层字段；本修复只检查补全后的 Envelope 与业务 payload。Generation=0 旧格式保持，空 payload Delete 仍无副作用返回，不据哈希猜测待撤销的订阅。

[正式回归](../../remoteentity/interest_payload_identity_promises_test.go) 八项旧行为红→绿；错误消息之后预置 lease 保持 generation10/原 expiry/total1，随后正式发布的合法 renew/release 仍成功。修前真实副作用包括 `generation:11` 和 `exists=false total=0`，不是只有返回值失败。

一项额外 wire 控制覆盖 Generation=0、generation12续租后generation11迟到撤销、空 Delete 无副作用及generation13正常撤销。完整测试结果见[证据](evidence/noncore-bugfix-20261005-13/README.md)。进程内同步传输夹具不证明 broker ACK/retry、跨节点时钟回拨或 HA。

为什么此前没发现：历史 Snapshot 身份回归只覆盖 snapshot 适配器，interest 回归主要直调注册表检查 generation，未在真实 Replicator 与 payload 之间检查身份一致性。本次将两个第三层接收入口分别验证，并检查拒绝后的正常恢复，不能以相邻包通过代替同类入口审查。
