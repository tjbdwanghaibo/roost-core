# RR-20261006-37 修复：motion 步骤需求按 Runtime 实际发出的步骤收集

问题：[RR-20261006-37](../bug/RR-20261006-37.md)。随 B3 ③ 一起实施（[方案](../feature/B3-3-HOST-CAPABILITY-TABLE-2026-10-07.md)）。

## 决策

`EnabledSlots` / `HostFeatures` 并入 Host 能力表的 `motion_step` 列，编译器收集的需求与 Runtime 发出的步骤一一对应：frame、steering、offsets、completion 每个运动衍生物都要，collision / carry 写了才要（`skill/compile_host_capability.go` `collectSpawnHostRequirements`）。

没采用“Runtime 只在定义写了 steering / offsets 时才发这两种步骤”：这两步交出的是每 tick 的方向与最终位置，Host 侧状态（`SpawnHostState.Position`）依赖它们，改发送规则会改变 Host 交互序列与 checkpoint / replay 行为，范围远大于本缺陷。

## 文件与行为

| 文件 | 改动 |
| --- | --- |
| `skill/compile_host_capability.go` | 运动衍生物固定需要 frame / steering / offsets / completion |
| `skill/compile_motion.go` | 删掉按定义查槽位的检查（并入能力表） |
| `skill/compile_environment.go`、`compile_authority.go` | `MotionCapabilityCatalog` 删 `EnabledSlots` / `HostFeatures`，校验与 digest 随之调整 |

## 兼容

环境格式变化与 digest 变化随 B3 ③ 一并说明。行为收紧：声明不接受 steering / offsets 的 Host，任何运动衍生物在编译期被拒（`HOST_CAPABILITY_MISSING`，点名 `motion_step "steering"`），Runtime 准入时同样被拒。

## 回归

- `TestHostCapabilityMissingIsRejectedAtCompileTime/moving_spawn_without_steering_on_a_host_without_steering_steps`：环境取自不接受 steering 的 Host，不写 steering 的运动衍生物报 `HOST_CAPABILITY_MISSING` at `$.phases[0].on.enter.steps[0].spawn.motion.steering`。
- `TestRuntimeRefusesProgramsOutsideTheHostTable` 同名子用例：默认环境编译的 Program 交给该 Host，`Activate` 返回 `ErrHostCapabilityMissing`，mana 未扣。
- `TestRuntimeAsksHostOnlyForCompiledRequirements`：全部种子上 Runtime 发出的 motion 步骤都在需求里；把 steering 改回“写了才要”时它与上一条都红（方案 §7.4）。
- `GOWORK=off go test -race -count=3 ./skill/...` 通过。

## 未验证 / 风险

无生产调用方；只有声明不接受 steering / offsets 的 Host 会受影响。
