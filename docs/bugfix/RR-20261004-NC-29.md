# RR-20261004-NC-29：事务回滚只丢弃自己的私有状态

2026-10-04，P3，基线 `3d3b22c9`；**已修复、声明场景验证，未发版**。[原问题](../bug/REVIEW-2026-10-04-noncore-16.md#rr-20261004-nc-29) · [运行](../review/REVIEW-2026-10-04-noncore-17.md) · [证据](evidence/noncore-bugfix-20261004-09/README.md)。

旧 abort 恢复全 client 快照，A 中止会抹掉 B 已提交的旧集合或新集合文档；两项修前 count=0，顺序回滚控制通过。单纯在 callback 外加全局锁会让 callback 等待 B 时死锁，也不能隔离事务外写，故未采用。

复用 transaction context、collection 身份和已有深复制。每个 attempt 保有私有 docs/order；单次集合操作在其 mutex 下临时选用私有数据，退出恢复共享视图，Calls/Errors/LastFilter 仍属于原对象。Seed/Lookup/Documents 无事务 ctx，始终访问已提交数据。所有实际写和索引发布更新 revision。提交按数据库名/集合名固定锁序，先验证全部写集合的基线 revision，全部通过再发布；冲突保留 ErrTransactionConflict 并标 TransientTransactionError，沿用原有限重试。abort/forced retry 只丢私有数据；finished context 拒绝后续操作，取消及 panic 不发布，panic 原样传播。

原 channel 排序的 A 写→B 提交→A abort 两项转绿。新增验证 own-write 可读、外部不可见、快照不读到后续提交、普通写存活、跨数据库同名集合、冲突重试/耗尽不发布前缀、异集合提交、取消/panic/escaped context、跨 client 拒绝和事务索引拒绝。

受影响的 `dataengine/engine/stage_effect_race_test.go` 原注入依赖共享写可见性和全库 restore，首轮两个叶子失败。仅调整这个测试夹具：在 snapshot miss 后保留真实事务外 Seed，并显式注入其承诺的 ErrDuplicateKey；增加 abort 不抹并发提交断言，移除 abort 后重建数据。原错误分类、mutation/marker 回滚、同身份幂等和异身份 fatal 断言保留。生产 DataEngine 未修改，最终消费者回归通过，初始失败保留。

这是**集合粒度冲突的有界替身**，比 Mongo 文档级冲突更保守；全部已存在集合在每次 attempt 深复制，提交锁序只保证已有 namespace 的数据发布。事务内索引明确不支持，Drop/同名 namespace 并发替换、真实 Mongo 写冲突时点、commit reply unknown、HA 未建模；aborted 新集合可能保留空句柄。callback 必须等待自身操作结束，不能把逃逸 ctx 当后台事务。复制和全集合短锁增加测试成本，未作 benchmark。无生产协议/格式迁移，不发版。
