# NC-41 修复：outbox 原子领取复查重试期限

[问题](../bug/RR-20261005-NC-41.md) · [证据](evidence/noncore-bugfix-20261005-17/README.md)。已修复、声明场景验证，未发版。

## 决策与实现

ClaimOutbox 的 Find 只是候选发现。FindOneAndUpdate 增加 `next_attempt_at <= request.Now`，与已有 lease_until 条件一并原子检查。Store 补中文契约。没有修改退避配置、租约时长、publisher 错误分类、业务回执或重试层；并发 Nack 后不再依赖旧扫描决定发布权。

不在 Find 后再单独 Get：仍留下 Get→领取的竞争窗口且增加 I/O。不使用进程锁：跨进程无效。ClaimDue 已有候选 version 条件，状态机更新版本会挡住陈旧候选；本轮不对它作无证据改造。

## 验证与边界

`outbox_backoff_promises_test.go` 两个独立 Store 共用 mongotest，钩子在候选读取结束后实际执行另一发布者的领取/Nack；没有任意 sleep。future_nack 原失败，still_leased/due_nack 控制通过；旧产品 overlay 同样1红2绿，最终3绿。后续到期领取成功、新 token 拒绝旧 Ack/Nack、最新 Ack 后排空。

相关 race、根包/build/vet、正式 DAO/Entity CLI 两同步模式消费者通过，准确计数见证据；包绿不等于真实 Mongo / HA / 长容量已验。旧消息无需迁移，BSON/wire/API 不变，自定义 Store 应遵守相同原子条件。未测试吞吐，不声称性能收益。
