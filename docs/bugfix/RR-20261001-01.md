# RR-20261001-01：Redis job 导出全部 Redis 门变量，并由根包测试钉住

问题：[RR-20261001-01](../bug/RR-20261001-01.md)。日期 2026-10-01。基线 `db4b7009`。状态：已修复，本地验证通过。

## 根因

`.github/workflows/ci.yml` `service-redis` job 的 `env:` 只有 `REDIS_ADDR`，skip 守卫正则也只有 `REDIS_ADDR`；09-29 的 service 修复用了另外四个变量名做 Redis 门（见问题记录），没人把它们加进 job。

## 决策

- ci.yml：`env:` 加 `ROOST_REDIS_TEST_ADDR` / `ROOST_REVIEW_REDIS`（同一地址）与 `ROOST_REVIEW3_BACKEND` / `ROOST_REVIEW4_BACKEND`（`redis`）；守卫正则扩成 `REDIS_ADDR|ROOST_REVIEW_REDIS|ROOST_REDIS_TEST_ADDR|ROOST_REVIEW[0-9]*_BACKEND`。
- `integration_coverage_promises_test.go` 新增 `TestCIRedisJobSetsEveryRedisGateVariable`：扫 `kit/service/**`、`service/**` 的 `_test.go` 里 `os.Getenv("…REDIS…")` 与 `os.Getenv("ROOST_REVIEW<n>_BACKEND")`，每个名字都必须在 ci.yml 里被设置（`ROOST_REVIEW_CLUSTER` 除外，它有自己的手动入口）。
- 未采用：把各测试统一改回只读 `REDIS_ADDR`——那是 B 线的测试约定，改名会和它们的记录与证据脱节；统一变量名另列。

## 文件与行为

- `.github/workflows/ci.yml`：Redis job `env:` 四个变量；守卫正则。
- `integration_coverage_promises_test.go`：`redisGateVariable` 正则与 `TestCIRedisJobSetsEveryRedisGateVariable`。

## 兼容性

只影响 CI；本地跑 Redis 变体要自己导出这五个变量（`docs/agent-skills/roost-bugfix/reference/lessons.md` 已记）。

## 命令与结果

- 修前红（`git stash push -- .github/workflows/ci.yml` 后 `GOWORK=off go test -run TestCIRedisJobSetsEveryRedisGateVariable .`）：
  `ci.yml never sets ROOST_REVIEW4_BACKEND, but [kit/service/platform/bugfix_external_outcome_test.go] gate their Redis variants on it …`、同形 `ROOST_REDIS_TEST_ADDR`、`ROOST_REVIEW3_BACKEND`、`ROOST_REVIEW_REDIS`（共 4 条）→ `FAIL`。
- 修后：`GOWORK=off go test -count=1 -run CIRedisJob .` → 两条 PASS。
- 本地按 job 口径实跑（隔离 Redis 17379，五个变量都设）：`go test -tags integration -count=1 -p 1 -json ./kit/service/... ./service/...` → exit 0，15 个包 pass，守卫正则匹配到的 skip 为 0（另有 6 个 skip 是 Cluster / Toxiproxy 等其他门，不在本条范围）。
