# RR-20260926-16：checkpoint 不超过持久 WAL

问题：[原始复审](../bug/RR-20260926-16.md)。日期 2026-09-26。
实施基线：main `381efc9` 加上一轮 RR-03～09 的未提交修复；原报告基线 `aaada47` 保留。
状态：代码已修复，适用本地验证通过，尚未提交/发布。完整证据和限制见[本轮汇总](../review/REVIEW-2026-09-26-release-fixes.md)。

## 修复与依据

Ack 在写 checkpoint 前同步覆盖日志内容；段轮转已有同步保证。成功投影的前缀即使请求取消也继续确认，保留原有取消语义。

涉及：`nestwal/wal.go`。

## 验证

TestAckSyncsAsyncRecordBeforeCheckpoint（修前失败）；TestMultiCheckpointCancellationConfirmsOnlySuccessfulPrefix。命令、负对照范围与环境见汇总；没有把全部测试绿色当成生产故障已穷尽。

## 兼容与边界

异步投影确认可能增加一次文件同步。测试验证调用顺序/持久边界，不冒称物理断电实验。

结论（退化如实记录）：WAL 直接追加 strict 不变（p=0.684），async 并行 +0.85%（p=0.004，+1 µs）。async 投影准入：writers_1 吞吐 +1.7%（p=0.000），
writers_8 / 32 无差异；p99 writers_1 +7.2%（p=0.043）、writers_8 +13.7%（p=0.002）、writers_32 无差异；**每笔多 5 次分配**（61 → 67、40 → 45、36 → 41，p=0.000）。
回放 + Ack 4 档时间与 acks/op（1 / 5 / 51 / 256）全部不变——RR-16 的“Ack 前同步日志”在此基准的 ack 路径上没有可测时间差（每次 Ack 本就 fsync checkpoint）。
这与 v1.17.0 triage 的 macOS 口径（group-commit 2 ms 时慢 4～9%）同向、幅度更小；Linux 对照仍在 C03。差异归因到 RR-16 单条修复无法从合并提交分离。
