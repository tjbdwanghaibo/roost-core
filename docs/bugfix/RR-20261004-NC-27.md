# RR-20261004-NC-27：唯一索引建立先验证存量

2026-10-04，P3，基线 `3d3b22c9`；**已修复、声明场景验证，未发版**。[原问题](../bug/REVIEW-2026-10-04-noncore-16.md#rr-20261004-nc-27) · [运行](../review/REVIEW-2026-10-04-noncore-17.md) · [证据](evidence/noncore-bugfix-20261004-09/README.md)。

旧 EnsureIndexes 先发布 Indexes/uniqueIndexes，已有重复数据也返回 nil/HasIndex=true。现在先解析单个索引字段，复用 lookup、精确比较及唯一检查验证存量；成功才发布。重复错误保留 `errors.Is(mongo.ErrDuplicateKey)`，比较错误不吞掉。正式 driver 逐个 CreateOne，因此后面失败保留前面成功的索引，不制造整批原子承诺。

原重复失败和不同值控制转绿，追加复合索引拒绝、不发布失败索引、不残留约束、批次前项成功与后续约束仍生效。发布索引增加集合 revision，让正在写入的旧事务快照检测冲突；事务内建立索引明确 ErrUnsupported，不绕过私有快照修改共享定义。

缺字段沿用替身的跳过规则，不等价于真实非 sparse Mongo 唯一索引；null/sparse、同名定义冲突、数组 multikey、真实服务端建立与重建语义留项。当前存量检查是成对比较，最坏 O(n²×字段数)，只用于有界测试数据，无性能收益承诺。
