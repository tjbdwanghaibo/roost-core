# RR-20260924-25：在部署初始化时拒绝无效 Cluster 锁前缀

对应 [问题](../bug/RR-20260924-25.md)。Kit Remote 在 `redis.cluster_addrs` 非空时要求 `remote_entity.lock_key` 的首个 hash tag 非空、闭合。例如 `{roost:remote}`。无效时 Init 返回包含配置项与示例的错误；单机配置和所有既有 key 原样保留。

没有自动重写 key：锁身份改变会让滚动发布的新旧节点各自持有不同锁。现有部署调整 prefix 应按停写/排空/统一切换处理，不能将它当作无状态配置热更新。直接使用 core Assembly 或自定义 Redis 适配器的调用者仍需自行提供同槽 key 前缀；此校验位于拥有拓扑配置的 Kit 入口。

五个无效配置修前红、修后绿；合法 tag 和单节点默认值通过，且断言不改写 key。真实 Cluster 以显式 tag 完成主故障与全停重启，关联 race/vet 通过。单个固定 tag 会使所有此类锁落在一个槽位，本次只验证正确性；不能据此宣称跨分片扩容。每实体 hash tag 的迁移设计另议。
