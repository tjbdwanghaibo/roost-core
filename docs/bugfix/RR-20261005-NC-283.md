# NC-283 修复：投射引用按表拆成根 + field

[问题](../bug/RR-20261005-NC-283.md) · [本轮](../review/REVIEW-2026-10-06-n09-batch6.md) · [求值上下文表方案](../feature/SKILL-EVAL-CONTEXT-TABLE-2026-10-06.md)。已修复、声明场景验证，未发版。

## 根因与决策

类型检查、lower、Runtime 三处对“引用的根”各有一份认识。

- **采用**：让 lower 与 Runtime 跟类型检查一致——`lowerReference` 用求值上下文表的行匹配（精确名字优先、否则最长根 + field），输入槽位按根 + field 解析；`evalReference` 已有的 field 分支（实体 → 读位置，hit → 实体 / 位置）求值。`$caster.position` / `$owner.position` 仍是单列的行，lower 结果不变。
- 未采用：编译期拒绝投射。类型检查与文档都把投射当作可用写法，拒绝会让正常需求（以目标位置为起点）无处表达。

## 文件与行为

`lower.go` `lowerReference` / `inputIndexMap`；`program_operation.go` `referenceProgramValue.row`（不进 digest）。

## 回归

`TestProjectedReferencesCompileAndRun` 六个子用例修前失败（`LOWER_UNRESOLVED` / `immutable program invariant failed: builtin "…"`）→ 修后 ok，含位置值断言。性质测试新种子 `seed.projected_reference`，引用变异候选含实体行的 `.position`。验证：`GOWORK=off`，`go test -race -count=3 ./skill/...`、`SKILL_MUTATION_FULL=1` 性质测试、根包、`go build ./... && go vet ./...`，见 [N09 第六批 §5](../review/REVIEW-2026-10-06-n09-batch6.md#5-修复与验证)。

## 兼容性

放宽：此前每次求值失败（或 B3 起编译失败）的定义现在能执行。今天能执行的 Program 的 lower 结果逐字段不变（45 个既有种子 gameplay / presentation digest 修前修后相同）。
