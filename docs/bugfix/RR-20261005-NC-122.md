# NC-122 修复：启动失败分支在 Cancel 之后识别重入

问题：[RR-20261005-NC-122](../bug/RR-20261005-NC-122.md)。2026-10-05，分支 `revn10`，基线 `197f7bb9`。

## 根因

`actionflow/action_runner.go:308-309`（基线）调失败动作的 Cancel 之后无条件 `unit.cur = nil`；`finish` 的同类位置有 `unit.cur != entry` 判定，这里漏了。

## 决策

- Cancel 之后 `unit.cur != entry` 就返回 `errors.Join(startErr, cancelErr, ErrReentrantMutation)`：重入路径（嵌套 Start 里的 finish）已经替失败动作发了离开切换与 OnEnded，外层不再清当前位、不再重复发、也不再越过重入装上的动作启动下一个排队项。与 `finish`、以及 U-0100 钉住的四处重入语义一致（外层报重入，内层装上的动作留在当前位）。
- 未采用：Cancel 之前先清当前位（这样嵌套 Start 不会再 Cancel 一次失败动作）。那会让失败动作的离开切换排在新动作的进入之后，也和 `finish` 的顺序不同；失败动作被 Cancel 两次与 `finish` 里 Cancel 重入时的现状相同，记观察，不在本条改。

## 文件与行为

- `actionflow/action_runner.go`：`start` 失败分支补判定与中文注释。
- `actionflow/start_failure_reentrancy_promises_test.go`：直接 Start 与排队（Freeze → Enqueue → Recover）两条用例。
