# RR-20261006-53 修复：衍生物回调继承施法的事件链，每次结算一个新 EventID

问题：[RR-20261006-53](../bug/RR-20261006-53.md)（F08-R R3）。基线 `47abe511`，分支 `skspawn`，与 RR-20261006-51～55 同批；端到端用例与验证见 [RR-20261006-51 修复](RR-20261006-51.md)。

## 根因

衍生物的 `eventContext` 不带施法的 `EventID` / `RootEventID` / `ProcDepth`（基线 `skill/spawn_owned.go:38`）；回调效果的事件 ID 按 `castID<<32 | (effect+1)` 编号（`skill/runtime_cast.go:232`），而回调跑在 `cast.id` = 所属施法的脱离 cast 上，同一回调效果每次结算同一个 ID。

## 决策

- 衍生物属于施法的因果链：`startEntitySpawn` 以施法的 `eventContext` 为底（EventID 作为回调事件的父事件、RootEventID、ProcDepth、proc 系数、标签），再填 tick / target / spawn 等。
- 每次回调派生一个新事件（`runOwnedSpawnCallback`：`deriveEvent(…, nextSpawnEventID())`，`$event.*` 求值用它），回调里的每次效果结算再从它派生一个新 ID（`effectEventContext` 对脱离施法的 cast 用 `nextSpawnEventID`）。
- 编号空间（`skill/ir_event.go`）：根施法 `castID`；proc 施放自己 `castID<<32`；施法效果 `castID<<32 | (i+1)`；衍生物回调与回调里的效果 `1<<63 | 序号`。序号是 Runtime 级计数 `spawnEventSequence`，随 checkpoint 保存（payload `spawn_event_sequence`，版本 8），恢复后不重复、回放确定。castID 小于 2^31 时与前三类不相交（castID 到 2^32 时前两类本来就回绕）。
- 语义（写进注释与本记录）：衍生物的每一次结算与施法自己的效果同属施法的根事件。`once_per_root` 对整条链（施法效果 + 衍生物整个寿命里的每次结算）只触发一次，`max_events_per_root` 跨 tick 累计，`max_depth` 按施法深度判断（被动召唤的衍生物回调伤害深度 = 被动施法深度）。
- 根事件淘汰：`rootEventReferencedLocked` 只看 Runtime 仍负责的衍生物（`spawnLivePartitions`）——活着的衍生物还会在这个根下产生事件，根不能被淘汰（否则 once_per_root 账本随根删掉、再触发一次）；已停止 / 已放弃的记录不再钉住根。之前衍生物的根恒为 0，这一项从未生效。

未采用：每个 tick 一个新根——`max_depth` 仍在衍生物处清零，正是本问题要堵的“被动 → 召唤 → 回调 → 被动”链。

## 文件与行为

`skill/ir_event.go`（编号空间、`nextSpawnEventID`）、`skill/runtime_cast.go`（`effectEventContext`）、`skill/spawn_owned.go`（`startEntitySpawn`、`runOwnedSpawnCallback`）、`skill/runtime_retention.go`、`skill/runtime.go`（字段）、`skill/runtime_checkpoint.go`（字段、版本 8）。用例：生命周期用例的事件链断言、`TestSpawnCallbacksShareTheCastRootForOncePerRoot`、`TestProcCastSpawnCallbacksKeepDepthAndRoot`、施放中 checkpoint 恢复子用例。

## 兼容性

线上未部署，checkpoint 版本 8。行为变化：衍生物回调事件的 `RootEventID` / `ProcDepth` / `ParentEventID` 有值、`EventID` 每次不同；挂在衍生物伤害上的被动会因 `once_per_root` / `max_events_per_root` / `max_depth` 比以前少触发（这是修复本意）。按 `skill/combat/roll.go` 推荐用（RootEventID, EventID, EffectIndex, 目标）作掷骰坐标的业务 Host，同一目标每 tick 的结果不再相同。

## 未验证 / 风险

- 长寿命、多目标的衍生物会更快用完施法根的 `max_events_per_root`（缺省按程序的 proc 策略），之后这条链上的被动按 `max_events_per_root` 抑制。若业务希望“每 tick 一条链”，需要另定语义。
