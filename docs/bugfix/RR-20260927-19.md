## 决策

维护者 2026-09-27 决定 C 类按推荐执行：**接受**“重开重试用尽（或被拒绝）时只记 Warn、玩家留在场景、自己的视图下次登录恢复”，不继续重试、不踢下线；
补一个低基数计数，让运营能按比率告警。

## 文件与行为

- `demo/internal/service/game/scene.go.tmpl`：`reopenLocked` 放弃时 `metrics.IncCounter("scene_session_reopen_failed_total", {"reason": …}, 1)`，
  `reason` 只有两个值：`exhausted`（`SessionOpenRetryable` 的“稍后”用尽 `sessionReopenAttempts` 次）、`refused`（不是“稍后”的拒绝，例如会话数上限）。
  Warn 带上同一个 `reason`。指标名是 `sceneReopenFailedMetric` 常量；不带玩家 / 会话标签（低基数），每个玩家每次放弃计一次。
  Join 时会话尚未能打开的重试链与推送失败后的重开走同一个 `reopenLocked`，一处计数覆盖两条路径。
- 计数写进进程默认注册表（`app.NewRegistry` 装到 `mods.ModMetrics` 并设为默认），由 ops 端点以 Prometheus 文本导出，与 `player_tcp_*` 同一方式。
- `demo/internal/service/game/scene_test.go.tmpl`：`TestASessionReopenRefusedWhileTheOldOneClosesIsRetried/bounded` 断言 `reason=exhausted` 恰好 +1；
  新子用例 `a refusal that is not "not yet" is counted apart`：传输以普通错误拒绝打开，断言不重试、玩家留在场景、`refused` +1 且 `exhausted` 不变。
  测试替身 `closingLane` 增加 `breakOpens`。
- 文档：`demo/deploy/dev/observability/README.md.tmpl`（指标表加一行）、`demo/README.md`（服务端权威状态同步一节）。
