# RR-20260922-03：`service/mail` 的五个 Redis 集成用例没人跑（U-0275）

来源：[REVIEW-2026-09-22](../bug/REVIEW-2026-09-22.md) · 复现 [REPRO-2026-09-22 §2](../bug/REPRO-2026-09-22.md)。
等级 P2，缺陷类 C2（空洞测试：写了、提交了、不跑）。

## 问题

`service/mail/redis_integration_test.go` 有 5 个 `TestIntegration*`，`//go:build integration`，没有 `REDIS_ADDR` 就 `t.Skip`。
`ci.yml` 的 `service-redis` job 只跑 `./kit/service/...`（`:106`），race 步骤只列 `kit/service/{integration,mail,rank}`（`:120`）。
`./service/mail` 在两处 glob 之外。同一个 job 里"no Redis test was skipped"的守卫（`:113`）解析的是同一份 `test.json`，
对一个**从没跑过**的包自然看不见任何 Skip。09-08 把 mail 的传输半边从 kit 下沉到 core（M-11）之后一直如此。

## 根因

"要跑什么"是手写在 workflow 里的一份列表，而真相是文件系统里哪些文件带 `//go:build integration`。列表在包搬家时没有跟。
守卫也只守列表内。

## 方案选择

| 方案 | 取舍 | 结论 |
| --- | --- | --- |
| 把 `./service/mail/` 加进两条命令 | 一行改动，但下一次搬家还会漏 | 不够 |
| 两条命令改成 `./kit/service/... ./service/...`，并加一条 promise test 把列表钉在文件系统上 | 多跑几个没有 Redis 用例的包（几秒），换来下一次搬家在本地 `go test .` 就红 | **采用** |
| 守卫改成全仓 `-json ./...` 找 Skip | 覆盖最全，但 Redis job 跑全仓要十几分钟 | 不采用，promise test 已经把"列表 vs 文件"钉住 |

## 改动

- `.github/workflows/ci.yml`：`service-redis` 的两条 `go test` 都加上 `./service/...`（race 步骤具体列 `./service/mail/`）；
  注释写明为什么两半都要列。
- `integration_coverage_promises_test.go`（新，仓库根包）：`integrationTestPackages` 遍历工作树，按文件**首行**
  是否 `//go:build integration` 归类（首行判定是必要的——这个测试文件自己就在字符串里写了那个字面量），
  再按文件是否读 `REDIS_ADDR`（且不读 `ROOST_DATAENGINE_IT`）分成"只要 Redis"与"要整套环境"两类；
  `TestCIRedisJobRunsEveryRedisIntegrationSuite` 要求 `ci.yml` 里带 integration tag 的每条 `go test` 的参数并集
  （字面 `./dir` 或 `./dir/...`）覆盖前一类的每个包。

## 证明

修前（`go test . -run TestCIRedisJobRunsEveryRedisIntegrationSuite`）：

```text
--- FAIL: TestCIRedisJobRunsEveryRedisIntegrationSuite (0.11s)
    integration_coverage_promises_test.go:131: service/mail has Redis-backed integration tests that no ci.yml step runs
    (they skip without REDIS_ADDR, and the skip guard cannot see a package it never ran);
    go test args: [./kit/service/... ./kit/service/integration ./kit/service/mail ./kit/service/rank]
```

修后绿。变异验证：把两条命令都改回去（只撤第一条不够——race 步骤字面列了 `./service/mail/`，并集仍覆盖，
这是对的），测试回到同一条红。

用例本身在本机 Redis 上：`REDIS_ADDR=127.0.0.1:16379 go test -tags integration ./service/mail/ -run Integration` 5/5 PASS，1.4s——
所以是覆盖缺口，不是失败。

## 未做 / 边界

- 守卫仍只看 Redis job 自己跑过的包；promise test 负责"列表完整"，守卫负责"跑了没 Skip"，两者合起来才是完整承诺。
- `kit/service/mail/` 现在没有 integration 文件（传输半边走了），留在 race 列表里无害，没有动。
