# RR-20261006-59 修复：带 affinity 的方法经 discovery + 按键 picker 路由，缺 discovery 启动时拒绝

问题：[RR-20261006-59](../bug/RR-20261006-59.md)（F09-R1）。基线 `a9c211e9`，分支 `genfix`，提交 `8dd984eb`。

## 根因

生成的客户端只有一条调用路径 `CallChecked(ctx, 0, …)`（队列组），构造也不带 discovery（基线 `codegen/internal/servicerpc/template.go:205`、`:184-198`）；picker 和上下文里的键都装上了，但没有任何路径去读。

## 决策

产品选择（维护者要求先按此实施）：**有 affinity 就必须有 discovery，缺了就启动时拒绝**，不退回随机路由。

生成的传输半（`*_rpc_gen.go`，只依赖 roost-core）：
- 有 affinity 的服务多一个 `const AffinityMethods`；`NewBusClient(b, discovery, serviceType, timeout, opts...)`，`discovery == nil` 返回错误并列出这些方法；内部用 `servicerpc.NewDiscoveredBusClient` + `WithKeyAffinity(AffinityKeyFromContext)`。
- 带 affinity 的方法走 `callByAffinity` → `CallDiscoveredChecked`（发现 → `KeyAffinityPicker` 按键选 sid → `CallTo`，三步共用一个超时）；不带 affinity 的方法仍走队列组 `CallChecked(ctx, 0, …)`。
- 无 affinity 的服务签名不变。

生成的装配半（`ClientMod`）：有 affinity 时 `DependsOn` = `[nats, etcd]`，`Provide` 从注册表取 `etcd.discovery`，取不到就返回“add the etcd Mod to this process”。

项目生成器：`frameworkCatalog` 给 match、activity 标 `Affinity`；托管它们的进程（owner 要注册进 discovery，调用方才找得到它的 sid）与 `uses` 它们的业务进程，`effectiveServiceMods` 自动加 etcd Mod（bootstrap、配置、compose 随之带上 etcd）。守卫 `TestFrameworkCatalogAffinityMatchesTheGeneratedClients`：catalog 的标记必须与生成的传输里是否声明 `AffinityMethods` 一致。

配置与启动顺序（论证）：
1. etcd Mod 的 `Provide` 发布 `etcd.discovery`（不做 I/O）；`ClientMod` 依赖 etcd Mod，App 按依赖先跑 etcd 的 Init / Provide，`ClientMod.Provide` 只取引用、构造客户端。
2. owner 进程在 etcd Mod `Start` 时注册 `<service_prefix><server_type>/<sid>`；`Start` 在 App 拿到单实例锁之后，同一 sid 同时只有一个进程注册。
3. 发现只在调用时发生。owner 还没注册 / 租约过期时，`PickServer` 返回 “no match service discovered”，调用失败（而不是随机落到别处）；owner 崩溃而租约未过期的窗口内，按键落到它的调用超时，直到 `etcd.lease_ttl` 到期——这是“同一个键只去一个实例”的代价，与修前“随机去一个活着的实例、但跨副本竞争”是换了一种失败形态。
4. etcd 端点用 `etcd.endpoints`（缺省 `localhost:2379`），生成的 dev compose 起 etcd 服务。

未采用：
- 缺 discovery 时退回队列组并告警——就是修前的静默随机，维护者要求拒绝。
- 所有方法都走 discovery——无 affinity 的方法没有理由多一次 etcd 读取。

## 兼容性（行为收紧，排查见 TROUBLESHOOTING T-301）

线上未部署。**行为收紧**：调用 match / activity（及任何带 affinity 的项目 rpc）的进程必须装 etcd Mod，否则启动失败；`match.NewBusClient` 多一个 discovery 参数。生成工程里 game-demo 的 game 进程多一个 Mod，关闭预算 111s → 114s、宽限 116s → 119s（相关用例的数字随之更新）。项目自己用 `roost add rpc` 加的带 affinity 的服务，生成器不能从 `roost.yaml` 得知，调用方需要自己在 mods 里加 etcd，缺了在启动时按上面的错误提示。
