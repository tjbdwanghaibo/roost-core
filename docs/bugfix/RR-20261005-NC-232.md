# RR-20261005-NC-232：停机开始之后的 RuntimeFailure 在 run 返回时并入错误

2026-10-06，基线 `c8ecbabb`。**已修复、声明场景验证，未发版。** [问题](../bug/RR-20261005-NC-232.md) · [本轮](../review/REVIEW-2026-10-06-n01b.md) · [证据](evidence/noncore-bugfix-20261006-n01b/README.md)。

## 根因

`run` 只在两处把 RuntimeFailure 放进返回值：启动检查点 `startupFailure` 与 select 的 `Done` 分支。select 因信号 / Serve 退出醒来之后，`Done` 不再有人读，`Err()` 也不再被看。

## 修法

`run` 改为命名返回值 `runErr`；拿到 `runtimeFailure` 之后登记一个 defer：若失败还没进过返回值（`failureReturned`，由 `startupFailure` 与 `Done` 分支置位），把 `runtimeFailure.Err()` 包成 “app: runtime failure after shutdown began: …” 并入。这个 defer 登记在单实例锁 `finish` 之前，因而在它之后执行，收尾期间（包括启动失败收尾期间）发生的失败也能看到。已经由 `Done` 并入的失败不重复追加。

安全动作不由这里负责：Nest 围栏由 `OnFail`、失锁不 Release 由 `finish` 按状态判断，均未改动。

没采用：在 select 之后继续读 `Done`——`Done` 只投递一次，读走后启动检查点之类的其他读者就拿不到；`Err()` 是合并后的诊断值，正适合收尾时看一次。

## 兼容

停机期间发生 fail-stop 的进程从 0 退出变为非零退出（错误文本见上）。停机期间失锁的进程同样非零退出（N01/S4 O1 所说的探针 B）。没有失败的正常停机返回值不变。

## 验证

- 修前红见问题记录；修后 `TestRuntimeFailureDuringShutdownIsReturned`（并且 Mod 照常停完、Release 一次——Release 规则不变）与对照 `TestRuntimeFailureThatStartsTheShutdownIsReturnedOnce`（只出现一次）通过。
- `GOWORK=off go test -race -count=3 ./app/`（含 `singleton_test.go`、`startup_cleanup_promises_test.go`）通过；根包通过。
