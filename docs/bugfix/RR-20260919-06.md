# RR-20260919-06：已付款的 grant 会在没履约的情况下过期删除（U-0251）

- 仓库：roost-codegen `demo`（`game/purchase`、`game/handler`、`game/entities/player`、
  `internal/service/<game>`）
- 缺陷类：C4（不变量选错了锚点）
- 优先级：P1
- 相关：T-145；测试 `game/handler/grant_purchase_test.go` 的 `TestAnOldPaidGrantIsStillHonoured`

## 问题

第十五批给付费发货加了一条 30 天的窗口：`handlerGrantPurchase` 拒绝超过
`paid_at + ClaimRetentionSeconds` 的 grant，`PurchaseClaims` 账本按同一个数清理，
而 drain 在拒绝之后**照样 `HDEL`**。

于是：玩家付款 → platform 在 grant 落 Redis 的那一刻把订单标成 delivered（它做的那件事确实完成了）
→ 玩家 30 天没上线 → 下次登录时 grant 被拒绝并删除。订单是 delivered、grant 没了、账本也忘了，
**玩家永远收不到已付款的东西**。而且当时的测试把"过期拒绝"写成了成功契约，稳稳地证明着这个行为。

## 根因

把邮件那条规则照搬到了付费资产上，而两者的权威时刻不是一回事。

邮件有一个**信封过期时刻**：过了它，任何重放都到不了发放路径，所以账本可以在那一刻忘记
（这正是 RR-20260918-05 的修法）。付费订单没有这样的时刻——`delivered` 是在 grant 变持久时盖的章，
不是在玩家收到东西时盖的。于是"准入判据 = 清理判据"这条对的规则，被挂在了一个**不存在的**权威时刻上。

规则应当写成：**付费资产的去重记录，不能早于"履约已确认"被丢弃。**

## 方案

- 采用：**取消未领取 grant 的过期，取消账本清理**。grant 永远可领；`PurchaseClaims` 只增不删，
  存的值改成付款时刻（留给审计，不再参与判断）；drain 里不再有"过期就删"这条分支——
  这个循环里没有任何失败能让一笔已付款的订单变成不可发货。
- 代价说清楚：账本只增。要收界得靠**第二个权威事实**——把"这笔订单已履约"幂等地报回 platform
  （Nest 事务提交物品与 claim id，之后 RPC 把订单推进到 fulfilled，再删 grant），
  只有在"不会再出现这个 grant"被确认之后，账本条目才可以压缩。这个握手本轮没有做。
- 没采用：把 30 天改大。审查说得对——当前 grant 没有更早的权威终止时刻，改大只是把同一个错误推远。

## 改动

`demo/game/purchase/purchase.go`（删 `ClaimRetentionSeconds` 与 `ClaimWindowClosesAt`，
把规则写成注释）、`demo/game/handler/grant_purchase.go`（去掉过期拒绝）、
`demo/game/entities/player/bag_component.go`（`ClaimPurchase` 不再清理，签名去掉 now）、
`demo/internal/service/game/purchase_drain.go`（去掉过期分支）、删除
`demo/internal/errors/purchase_expired.go`（错误码 100015 随之退役）。

## 证明

`TestAGrantPastItsWindowIsRefusedRatherThanRepeated`（把旧行为当契约的那一条）替换为
`TestAnOldPaidGrantIsStillHonoured`：一年前付款的 grant 仍然发货，且十年后重放仍被账本挡住。
`TestAPaidOrderIsGrantedOnce`、`TestAnUnidentifiableGrantIsRefused` 不变；生成工程
`go build ./...` 与 `go test ./...` 全绿。

## 未做 / 边界

- **履约确认的握手没有做**，所以账本真的会无限增长。demo 的量级无所谓，真实工程在上线前必须补上
  这一步，或者接受按玩家的记录数收界并给出运维口径。
- 错误码 100015 退役但没有回收：新工程不再生成它，已有工程里那个文件是业务拥有的，要不要删由工程决定。
- grant 的 Redis 哈希同样没有 TTL，这是同一个决定的另一面：在履约确认之前，删它就是删掉唯一的欠款凭据。
