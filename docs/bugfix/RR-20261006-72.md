# RR-20261006-72 修复：入站消息的指标标签与死信桶只取注册过的名字，其余归并为 _unregistered

问题：[RR-20261006-72](../bug/RR-20261006-72.md)（F05-5）。基线 `c78d0c34`（main）。codebase-memory 共享 generation 停在 09-30（比基线旧），按 worktree 当前源码。分支 `remfix`（同批 RR-20261006-68～74，F05-1～F05-7、F09-R2、F09-R3）。

## 决策

- 参照 RR-20261006-19 被调方 method 标签的规则：`Bus.incomingLabels(msg, isRpc)` 只有本进程注册过的 `(module, msg)`（RPC 看方法）用自己的名字，其余一律 `_unregistered`（与 JetStream RPC 同一个值）。上界是注册数 + 1。RPC 请求不带 module，module 标签固定为空。
- 用到它的：`bus_dead_letter_total`、`bus_dispatch_drop_total`、死信桶（Redis 列表键 `<prefix>:dlq:<module>:<msg>`）；管理命令的 `bus_dead_letter_requeue_total` / `_purge_total` 同样归并。
- **死信条目保留原名字**：`ReliableStore.DeadLetter` 增加 `bucket DeadLetterBucket` 参数，桶由 Bus 决定，条目里的 `ToModule` / `MsgName` 仍是原值；从 `_unregistered` 桶重投时按原名字发回（部署了对应 handler 之后可以重投）。
- **未采用**：在存储里自己判断——存储不知道注册表。

| `bus/reliable_test.go`、`dead_letter_admission_promises_test.go`、`reliable_redis_test.go` | 测试替身跟随新签名；原用例的消息改为注册过的名字（它们模拟的是 handler 失败进死信） |

## 兼容性

- 运维：未注册消息的死信改在 `module=_unregistered msg=_unregistered` 桶里查 / 重投。
