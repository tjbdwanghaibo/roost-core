# RR-20261004-NC-21：RefHMap未知写保留错误

2026-10-04，P2，起点 `ce90e90d`；**已修复、声明场景验证，未发版**。[原问题](../bug/REVIEW-2026-10-04-noncore-14.md#rr-20261004-nc-21) · [运行](../review/REVIEW-2026-10-04-noncore-15.md) · [红绿/完整矩阵](evidence/noncore-bugfix-20261004-08/README.md)。

## 根因与决定

evalWriteHashes把所有Eval错误解释成未执行并重放DEL/HSET，导致较新值丢失且返回nil。

采用保守透传而非按网络错误猜测是否提交，不引入CAS、重试或提交身份协议；Stale仍是建议性检查。

## 改动与兼容

cache/ref_hmap.go删除pipeline/串行降级，直接返回Eval原错，保留errors.Is。已应用写不自动回滚；未应用与未知结果都由调用方处理，不猜测错误文本。

公开签名/合法存储格式不变。以前Eval错误可能降级成功，现在明确返回错误；不支持Lua的适配器需实现已有Eval能力。删除误导性的write_degraded_total计数与降级告警，运维需看Set错误/原始原因；T-206。
