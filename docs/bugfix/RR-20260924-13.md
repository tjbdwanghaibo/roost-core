# RR-20260924-13：从发布失败返回时计算退避

[问题与复现](../bug/RR-20260924-13.md)。2026-09-24；已修复、未发布。

`dataengine/engine/outbox_worker.go` 在每次 Publish 失败后重新读取时钟，用失败时刻计算 Nack 的 available_at。保留当前 attempt 的指数退避、RetryMax 上限和 lease token CAS；不改变接口、存储格式或投递保证。补充中文注释解释为何不能使用整批开始时刻。

新增 `outbox_retry_test.go`，使用实际 MongoOutboxStore 的 claim/nack 逻辑（Mongo 是 mongotest 替身），以受控时钟检查 1/2/4/4 秒窗口：窗口之前不能领取，到期后下一轮能再次处理；4 次发布失败不计作 StoreFailure，也没有成功发布计数。

修前红、修后 `go test -race ./dataengine/engine -run '^TestOutbox' -count=1` 通过（1.718s）；日志 `/tmp/roost-dataengine-recovery/retry-green.log`。真实 Broker 延迟、连接重置、半开 ACK 丢失也通过，见 [恢复验收](../feature/DATAENGINE-RECOVERY-2026-09-24.md)。这些有限测试不构成永久 exactly-once 投递承诺。
