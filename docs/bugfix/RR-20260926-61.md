# RR-20260926-61：快池拒绝投递时不在 finalizer 线程执行提交后回调（计数告警）；延迟回调携带原请求上下文快照

问题：[RR-20260926-61](../bug/RR-20260926-61.md)。日期 2026-09-26。
实施基线：main `3e26f91`（本批 RR-58、RR-60 提交之后）。状态：已修复，本地验证通过，已本地提交，未推送/发布。

## 根因（基线行号）

- `remoteentity/transaction_manager.go:372-391` `deliverRemoteOutcome`：`NestMgr.RunLocal`（`nest/remote_dispatch.go:84-104`）在 Nest 未启动、停机中或已 fence 时
  拒绝投递，RR-37 的实现于是在 finalizer goroutine 上就地执行提交后工作（计数 `remote_entity.deferred_outcome_inline_total`）。提交后工作里有业务 AfterCommit：
  已 fence 的快池仍在跑在途 handler，就地执行与之并发；停机时可能在 Nest Shutdown 返回之后才执行——违反“慢池 / 后台不执行业务”。它与 pipelined 完成池
  不等价（完成池按 handler 白名单显式启用、按实体链保 LSN 顺序、由 Nest Shutdown 排空）。
- 延迟回调没有请求上下文：`RunLocal` 的续行快照为空（`remote_dispatch.go:97-100` 不带 snapshot），而正常路径经 `dispatchFastContinuation` 带慢阶段快照
  （`remote_dispatch.go:122-138`），同一 AfterCommit 在两条路径上看到的 fctx 不同（trace、handler 元数据、请求内写入的 KV 都丢失）。
- USER_GUIDE 未写停机 / fence 期间的例外。

## 决策（维护者 2026-09-26 批准：不离池执行，计数告警）

1. **不离池执行**：`deliverRemoteOutcome` 在本地执行入口拒绝投递时**不调用** fn：AfterCommit 不执行；框架的 Sync Confirm / Reject 与业务回调同在 fn 里，
   也不单独执行，Sync 门保持冻结（进程正在退出或已被隔离，重启后实体从权威重载）。持久结论本身不受影响，资源（gate、锁、写额度）照常在此前交还。
   未执行按结论计数 `remote_entity.deferred_outcome_not_run_total{outcome=committed|rejected}`（低基数），并记一条 Warn 日志（含事务 ID）。
   原 `remote_entity.deferred_outcome_inline_total` 删除。
2. **框架 Confirm 不借机执行业务**：约束允许“框架原子 Sync Confirm 按原子语义处理”，本实现选择不单独 Confirm（与“Sync 门保持冻结”一致），
   因此不存在借 Confirm 执行业务回调的路径。
3. **延迟回调携带原请求上下文**：`deferPostRemoteCommit` 在慢阶段交接时捕获 `fctx.CaptureSnapshot()`（快阶段写回的请求数据已在其中），闭包在快池执行
   已提交回调前 `ApplySnapshot`，结束后恢复。与原样有两处不同（`deferredRequestSnapshot`）：去掉慢阶段注入的本地执行器（执行器属于正在结束的这次派发，
   不能随快照进入快阶段）；Base 经 `context.WithoutCancel` 与请求 ctx 的取消脱钩——结论到达时回复早已发出、请求 ctx 通常已取消，取消等待不等于撤销业务。
4. **未改**：交接、只接受一次、终态后才交付（RR-37）；Rejected 在卸载成功之后才交付（RR-39）；未装配 Nest（独立使用 remoteentity，没有 Nest 的提交后工作）
   时 `entity.RunLocal` 就地执行。

## 兼容性

- 行为变化：持久结论到达时 Nest 已停机 / 已 fence，该事务的 AfterCommit **不执行**、Sync 门保持冻结（修前在后台 goroutine 上就地执行）。
  业务不能依赖“结果未知的 Remote 事务最终一定执行 AfterCommit”；需要可靠副作用的业务应以持久记录 / outbox 实现。写入 USER_GUIDE。
- 行为变化：延迟执行的 AfterCommit 能读到原请求的 fctx（trace、handler、KV、Config），`fctx.BaseContext()` 不再是空 / 已取消的 ctx。
- 指标：新增 `remote_entity.deferred_outcome_not_run_total{outcome}`；删除 `remote_entity.deferred_outcome_inline_total`（仅 RR-37 本地提交引入，未发布）。
- 内部签名 `deliverRemoteOutcome` 增加 txID（未导出）。无公开 API、配置、持久格式变化。CHANGELOG 由主会话合并时更新。

## 交付前自查（本项）

- **RR-37 只执行一次、不回退**：交接只在“本地已持久提交且 Remote Commit 返回错误”时发生，批次只接受一次，终态分支之后才交付；本修复只把“拒绝投递 → 就地执行”
  改为“拒绝投递 → 不执行”，从“恰好一次”变为“至多一次”，不会重复。没有持久结论时仍不 Confirm。
- **快慢池边界**：提交后工作只在 Nest 快池（`NestMgr.RunLocal` 的续行通道）执行；finalizer goroutine 上不再有任何业务回调。快照在慢阶段捕获、在快阶段应用，
  慢阶段执行器被屏蔽，不会让快阶段自投自等（`entity.RunLocal` 在快 worker 上本就就地执行）。
- **Rejected 与 RR-28**：拒绝结论仍在回滚、隔离、释放、卸载之后才交付；快池拒绝投递时 Reject 也不执行，门保持冻结——被拒绝实例此时已卸载，不会交付被拒绝内容。
