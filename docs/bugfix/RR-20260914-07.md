# RR-20260914-07:超协议座位数配置生成不可解码帧

**仓库 / 位置**:roost-core `lockstep/sequencer.go` `NewSequencer`,`lockstep/room.go` `NewRoom`,`lockstep/wire.go` `MaxFrameInputs`。
**修复单元**:U-0196(C4)。**定位文档**:TROUBLESHOOTING T-90。

## 问题

257 个玩家、`MaxInputBytes=1`、`RedundancyDepth=1`、`MaxDatagramBytes=8192` 被接受(字节预算放得下);全员提交后
`Tick` 成功,`DecodeBroadcast` 却报 `input count 257`——解码侧 `MaxFrameInputs=256` 与配置侧没有对齐。

## 根因

同一个上限在两处各自成立:wire 解码有条数上限,配置只校验字节(C4)。

## 方案选择

- **放大 `MaxFrameInputs`。** 那是对抗敌意包的解码侧内存放大上限,不该随配置漂。
- **`NewSequencer` 对齐协议条数上限(采用)。** 座位数 > `MaxFrameInputs` 在创建时拒绝;同包常量,不会漂移。

## 改动

`lockstep/sequencer.go`:`NewSequencer` 对 `len(Players) > MaxFrameInputs` 返回 `ErrConfigInvalid`。

## 证明

`lockstep/seat_identity_promises_test.go` 的 `TestRoomPromiseSeatCountIsBoundByTheWireDecoder`(257 拒绝;256 满员帧可解码)。
修前红:`accepted room emits undecodable frame: lockstep: frame encoding corrupt: input count 257`。修后 lockstep 含 `-race` 全绿。

## 未做 / 边界

- 超过 256 座位的规模需要协议升级 / 拆分,本轮只把边界对齐。
