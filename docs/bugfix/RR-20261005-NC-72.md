# RR-20261005-NC-72 修复：cfggen 帮助与参考文档改用独立的 `configs/cfg`

[问题](../bug/RR-20261005-NC-72.md) · [证据](../review/evidence/noncore-review-20261005-n08/README.md)。2026-10-05，基线 `be7bcc18`（审查基线 `50e9a4e8`）。状态：已修复、声明场景验证，未发版。

## 决策

`roost help cfggen` 的 Usage 改为 `-out ./configs/cfg -pkg cfg`、Example 的 `package: generated` 改为 `package: cfg`，与 `roost next` 的提示一致；`codegen/docs/CODEGEN_REFERENCE.zh-CN.md` §8 同步，并写一句为什么不能放进 `configs/generated`（tablegen 的输出目录，同包会重复声明 `RegisterConfigData`）。

未采用：让 cfggen / tablegen 能同包共存（改入口函数名或合并注册）——改变两个生成器的生成形状和既有工程的调用方，超出“帮助指错目录”的范围。

## 文件与行为

- `codegen/internal/roost/help.go`：cfggen 主题 Usage / Example。
- `codegen/docs/CODEGEN_REFERENCE.zh-CN.md`：§8 命令与说明。
- 新增 `codegen/internal/roost/cfggen_help_promises_test.go`：从 `findHelpTopic("cfggen")` 的 Usage 取 `-out` / `-pkg`，在 configdata 工程（默认 features 含 config）里用这组参数跑 `cfggen.Run`，再跑 `Generate`，并检查输出目录里没有别的生成文件声明 `RegisterGeneratedConfigData` / `RegisterConfigData`。这测的是“照帮助做之后工程还能生成”的行为，不是文案镜像。

## 兼容性

只改帮助与文档；已经按旧帮助把 cfg_gen.go 放进 `configs/generated` 的工程本来就编译不过，挪到独立目录（并改包名与 import）即可。

## 验证

修前红：`roost generate after following roost help cfggen (-out ./configs/generated): generator registry: registry: example.com/planet/configs/generated.RegisterConfigData is marked twice`。修后通过；矩阵见 [NC-71 修复记录](RR-20261005-NC-71.md#验证)。
