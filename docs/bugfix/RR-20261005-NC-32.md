# RR-20261005-NC-32：父对象就位后绑定嵌套通知

2026-10-05。问题见[发现记录](../bug/RR-20261005-NC-32.md)。基线 `c3aa0eddf67be234ba742188c53d18bbc1be9604`；已修复、声明场景已验证，未发版。修改身份以交付提交及[源码摘要](evidence/noncore-bugfix-20261005-12/source-hashes.csv)为准。

## 实现与选择

[template_nested.go](../../codegen/internal/dao/template_nested.go) 增加私有 `loadBSONDoc`：只恢复数据，不建立父子通知。`FromBSONDoc` 用它返回未绑定值；现有 `bindDirty` 在成功验证父归属后调私有 `bindChildren`，在最终地址递归绑定。独立 `UnmarshalBSON` 的原址 `setBSONDoc` 仍恢复后绑定。raw map 恢复与公开 setter 继续使用既有归属辅助函数。

没有标脏、登记新 undo、改提交协议或跳过唯一父检查。金样由正式生成器重生成，正式运行回归新增[九个 Nest 提交承诺](../../codegen/internal/dao/testdata/runtime/restored_descendant_promises_test.go)，文件头有中文旧行为说明。

没有采用“只让 PtrFromBSONDoc 原地构造”：值字段及更深值转换仍会复制；没有采用“通知指针共享”：会改变 DirtyHook 的复制/归属语义；没有采用恢复后反射修补：绕过生成的字段类型与归属能力。最终地址递归接线覆盖同一模板的指针、值和受控容器入口。

## 兼容与迁移

公开方法、BSON 字段、schema/version、WAL/CAS 格式保持。新增生成方法均私有。应用必须升级生成工具并重生成 `gen_*_nested.go` 等关联生成物，再编译并跑实际消费回归；只升级 runtime 不会改既有生成代码。历史已经漏落库的数据仍需按业务来源恢复，本轮不自动修生产数据。

唯一父归属仍有效。不能把已经绑定且含指针子对象的 nested 结构浅复制后当作独立树：复制不会转移子对象所有权，冲突仍应拒绝。确需独立值应从数据重新构造，不能靠改通知覆盖原持有者。

## 复盘与限制

旧测试主要检查“数据值 roundtrip”和“独立嵌套对象原址恢复后能通知”，没有在正式 DAO 的 wire 值复制之后验证深层 setter 进入业务提交。因此它们通过仍不能证明 loaded entity 可持续写回；本次把正常恢复后的下一次业务事务纳入承诺，避免只验加载成功。

绑定增加对可达嵌套子对象的递归遍历，发生在恢复/绑定阶段，不引入 I/O；原已绑定树重新绑定时仍校验同一归属。未做分配/延迟 benchmark，不宣称性能提升或容量验收。后端 mongotest 不等于真实 Mongo replica set；HA、未知提交和长期容量仍保留。
