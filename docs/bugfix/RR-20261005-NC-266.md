# NC-266 修复：Duration 也加在 manager 的 run ctx 上

问题：[RR-20261005-NC-266](../bug/RR-20261005-NC-266.md)。分支 `revleft`，基线 `dc877c04`，[本轮](../review/REVIEW-2026-10-06-revleft.md)，[证据](evidence/noncore-bugfix-20261006-revleft/README.md)。

## 修复

`Manager.Start`：`profile.Run.Duration > 0` 时 run ctx 用 `WithTimeout(rootCtx, Duration)`。runner 在其上再套同一 Duration，`WithDeadline` 取较早的父截止时间，两者同时到期；`stopReasonFromContext` 看到 `DeadlineExceeded` → `duration`。手动 stop / shutdown 先写 StopReason，不受影响。

顺带（N12 O9，无行为变化）：`Runner.Run` 不再先 `WithCancel` 再覆盖成 `WithTimeout`（第一个 cancel 丢失，那个 ctx 到父 ctx 结束才释放）；`Stats` 注释与 README 改正 “Started == Success+Failure+Canceled” 对 looping 不成立。

文件：`robot/loadtest/manager.go`、`robot/runner/runner.go`、`robot/loadtest/duration_stop_reason_promises_test.go`、`README.md`。

## 兼容

Duration 到期的运行现在 `stop_reason=duration`（之前 `completed`）。自定义 `RunnerFactory` 的 runner 若不自己执行 Duration，现在也会在 Duration 到期时被 manager 取消——`Profile.Run.Duration` 的既有含义就是“限定运行时长”。
