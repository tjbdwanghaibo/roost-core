# RR-20260930-12：fence 之后拒绝带 Remote 批次、无 effect 的 memory handler 的 Durability 0 直写

问题：[RR-20260930-12](../bug/RR-20260930-12.md)（REMAINING §3 N21，维护者 2026-09-30 拍板“收紧”）。日期 2026-09-30。基线 `4784ef82`，独立 worktree。
状态：已修复，本地验证通过，本地提交，未推送 / 发版。codebase-memory 图谱 generation `2026-09-30T11:28:30Z`（`41af71c0` 刷新），所引文件 `check_index_coverage` 无记录缺口；行号以当前源码为准。

## 根因

`nest/rollback.go` `durableCommit` 对 `DurabilityMemory && len(effects) == 0` 直接返回 nil，在 `refuseCommitAfterFence` 之前；`commitDurable` 把 nil 当作提交成功、置 `remoteCommitted`，`finishRemoteWriteBatch` 随即 `batch.Commit`。RR-20260927-06 的 fence 拒绝只覆盖交给 committer 的记录。

## 决策

在 `durableCommit` 的 memory 早返回分支里，消息带 Remote 批次时先调既有的 `refuseCommitAfterFence`。理由：

- 这是唯一让 Remote 直写绕过 fence 的路径；检查放在同一函数、复用同一判据（只读一次 `FenceError`，不等待、不做 I/O），拒绝沿 `commitDurable` 既有的明确拒绝分支（Abort 批次 → `rejectCommit` 加 `ErrCommitRejected`），回复形态与 `fenced/memory_remote_with_effect` 完全一致。
- 只在 `tx.dispatch.RemoteWriteBatch != nil` 时检查：memory + RollbackState 而无 Remote 批次的事务也走这个分支，但它没有任何持久或 Remote 写，拒绝它超出维护者的决定范围。

未采用：

- 在 `finishRemoteWriteBatch` 的 `remoteCommitted` 分支再读一次 fence——那时锁已释放、`remoteCommitted` 已置位，拒绝会与“已提交事实”矛盾，回复也无法带 `ErrCommitRejected`。
- 在 `commitDurable` 外层统一检查——会同时改变 memory + RollbackState 无 Remote 批次的行为。

## 文件与行为

- `nest/rollback.go`：`durableCommit` memory 分支补 fence 检查；`refuseCommitAfterFence` 注释补这条路径。
- 回归 `nest/fenced_memory_remote_no_effect_promises_test.go` `TestFencedMemoryRemoteWithoutEffectIsRefused`：fence 后带 Remote 批次、无 effect 的 memory 消息回复 `ErrNestFenced` + `ErrCommitRejected`、不带任何“可能已提交”哨兵，Remote 批次 Commit 0 次、Abort ≥ 1 次，committer 0 次，声明实体的内存修改（77）不撤销。

## 兼容性与迁移

**行为收紧**：引擎 fence 之后，带 Remote 批次、没有 effect 的 memory handler 现在得到 `ErrNestFenced`（与 `ErrCommitRejected`）而不是成功回复，Remote 权威不再被写。此前这类消息在 fence 之后仍成功并直写权威。fence 是本进程已有事务结果未知后的保护态（此后所有新请求本就被拒），受影响的只是 fence 发生时正在执行的这类 handler；调用方按判别表第 12 行处理，RollbackNone 的内存修改不撤销，确认幂等后重试（第 6 行语义）。公开 API、持久格式不变。
