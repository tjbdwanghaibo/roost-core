# RR-20261006-57 修复：生成器随 `versions.core` 运行，`versions.codegen` 废弃

问题：[RR-20261006-57](../bug/RR-20261006-57.md)（F12 G2）。基线 `a9c211e9`，分支 `genfix`，提交 `410392e0`。

## 根因

合仓后生成器就是 roost-core 的一个包，`versions.codegen` 却仍按独立模块校验（下限 v1.15.0）并驱动 Makefile 的 `@版本`（基线 `manifest.go:86-90`、`:389`，`render.go:873-875`、`:1044-1049`）。

## 决策：Makefile 直接用 `versions.core`，废弃 `versions.codegen`

对用户最简单的是**一个号**：工程编译用哪个 roost-core，就用那个版本的生成器重新生成。理由：
- 生成器与它生成的代码所依赖的 kit / core API 是同一个 tag 发布的；两个号只能出现“生成器比 core 新（生成用到 core 还没有的 API）”或“比 core 旧（把模板改写回旧形状）”两种不一致。
- `versions.core` 已有下限（v1.23.0 ≥ 第一个含 `codegen/cmd/roost` 的 v1.16.0），合法值一定能 `go run`。
- 仍可单次覆盖：`make generate CORE_VERSION=vX.Y.Z`。

未采用：
- 把 `versions.codegen` 下限抬到 ≥ core 下限：两个号仍可彼此不一致，问题只是推迟。
- Makefile 不带 `@版本`、按 go.mod 解析（或 Go 1.24 `tool` 指令）：要把生成器的全部依赖写进业务工程的 go.mod / go.sum，改动面大，留作以后的选择。

实施：
- Makefile：`CORE_VERSION ?= <versions.core>`、`ROOST := go run $(CODEGEN_MODULE)/cmd/roost@$(CORE_VERSION)`；`make project-upgrade` 去掉 `-codegen latest`。
- 清单：`VersionSpec.Codegen` 改 `omitempty`、不再写出；`Validate` 见到非空 `versions.codegen` 即拒绝：“versions.codegen (…) is retired: the generator ships inside roost-core and the Makefile runs it at versions.core; delete the line, or run roost project upgrade, which drops it”。`project upgrade` 合并版本后删掉它并打印 `dropped versions.codegen …`。
- CLI：`project new -codegen-version`、`project upgrade -codegen` 删除（不做兼容）；帮助、生成的 `docs/ROOST_YAML.zh-CN.md`、依赖更新工作流同步。
- CI：`framework-compat.yml` minimum lane 去掉 `-codegen-version`，新增一步：`make -n sync generate check-generated doctor id-check` 里每条生成器调用都必须是 `cmd/roost@<core 下限>`，并真跑一次 `make id-check`；`upgrade-compat.yml` 去掉 `-codegen latest`。
- 等价测试（不依赖网络，CI 的 codegen 测试即跑）：`TestTheMakefileRunsTheGeneratorAtTheCoreVersion` 用 `make -n` 断言 core 钉版本 / latest 时三个目标的生成器版本等于 `versions.core`，并断言 core 下限 ≥ v1.16.0；`TestFrameworkCompatMinimumSetMatchesTheGeneratorFloor` 同时钉住 minimum lane 里那个检查的版本号。

## 兼容性（行为收紧，排查见 TROUBLESHOOTING T-300）

线上未部署，不做兼容。**行为收紧**：`roost.yaml` 里仍有 `versions.codegen` 的工程，`make sync` 等现在报错并给出处置（删行或 `roost project upgrade`）；`-codegen-version` / `-codegen` 参数不再存在。

**发版必须同步抬下限（已实测）**：本修复之后生成的 `roost.yaml` 不再有 `versions.codegen`，而 v1.23.0 的生成器要求它非空——在重新生成的 game-demo 里执行 `make id-check CORE_VERSION=v1.23.0` 得到 `versions.codegen must be latest or a semantic release such as v1.15.0; got ""`。所以 v1.23.1 发版时 `minimumVersions.Core` 与 `framework-compat.yml` 的 minimum 行（含新增检查里的 `cmd/roost@v1.23.0`）都要升到 v1.23.1；在此之前 minimum lane 新增的 make 步骤会红，这正是本条要它抓的问题（下限低于“能读懂当前清单的生成器”）。

## 回归

修前红见问题记录；修后 `go test -count=1 ./codegen/...` 全绿（含升级旧清单删 `versions.codegen` 的用例）。生成 game-demo 后 `make -n … CORE_VERSION=v1.23.0` 五条调用均为 `cmd/roost@v1.23.0`。其余见 [RR-20261006-59 修复](RR-20261006-59.md#回归goworkoff实际执行四个-rr-共用)。
