# NC-140 修复：World 定时器堆登记进事务回滚

[问题](../bug/RR-20261005-NC-140.md) · [证据](evidence/noncore-bugfix-20261005-revn11/README.md) · [本轮](../review/REVIEW-2026-10-05-n11.md)。已修复、声明场景验证，未发版。

## 根因与修法

`timer.Scheduler` 的堆是 `TimerComponent` 的内存，Nest 的 undo / state 回滚只覆盖生成 DAO（与 NC-61 同一缺口）。`demo/game/entities/world/timer_component.go.tmpl`：

- 新增 `captureRollback`：若当前有可回滚事务（`nest.CurrentRollbackTx()` 非空且不是 `RollbackNone`），复制 `Nodes()` 与 `Seed()`，`tx.RecordUndo(component, timerHeapUndo, …)` 登记逆操作——按快照重建堆。Nest 对同一 (owner, slot) 只保留第一次登记，所以一笔事务里先武装再 Tick 也恢复到事务开始时。
- `ScheduleActivityPhase` 在真正武装（`NewTimer`）之前调用；`Tick` 只在堆顶已到期（`NextTime` 不晚于 now）时调用，每秒那次什么都不触发的 Tick 不复制。
- 抽出 `rebuild(seed, nodes)`：加载（`OnInitFinish`）与回滚走同一条“按 DAO 的定时器重建堆”路径。

逆操作恢复的种子与 DAO 的 undo 恢复的种子相同；回滚事务里铸出的 id 不在 DAO 里，复用不会撞号。World 只武装带类型的定时器（`Nodes()` 不含闭包定时器），快照是完整的。

未采用：
- 让 `timer.Scheduler` 自己参与 Nest 事务——`timer` 是不依赖 nest 的基础包，引入依赖改变分层，且调度器不知道哪笔事务在改它；
- 每次 Tick 从 DAO 重建堆——把一次重建变成每秒的成本，且改掉“堆是 DAO 的缓存、钩子写穿”的分工。

方向判断（组件内存回滚契约第三次出现）见本轮记录 §5。

## 后续：回滚统一走 DAO（A1，2026-10-05）

本修复的组件内做法（组件 `captureRollback` 自己登记 undo、加载时重建常驻堆）已被维护者决定 A1 取代：可回滚状态一律放进 DAO（属性三层 `attr_base` / 新增 `attr_gear` / `attr_final`，定时器 `timers` / `timer_seed` / 新增 `timer_next_due`），组件不持有状态、不登记 undo，派生值由加载与改源字段的事务写入。本记录的回归用例保留并在新实现上通过，另加两种回滚策略 × 两条失败路径的真实 Nest 派发组合用例。见[方案与实施记录](../feature/REFACTOR-2026-10-05-dao-unified-rollback.md)。
