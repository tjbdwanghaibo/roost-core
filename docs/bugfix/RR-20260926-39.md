# RR-20260926-39：持久拒绝收尾后框架自动仅内存卸载被拒绝的实例，下一次访问从权威重载

问题：[RR-20260926-39](../bug/RR-20260926-39.md)。日期 2026-09-26。
实施基线：main `0452569`（已含 RR-46、RR-38，以及 RR-30 / RR-35 / RR-44 / RR-47 等其他组修复）。状态：已修复，本地验证通过，已本地提交，未推送/发布。
首版提交 `d488e1b`（基于 `49f20ee`）自带一套快池入口与 Sync 回收，与 main 上 RR-30 / RR-35 已有机制重复；本版在 `0452569` 上重做，改为复用，见“与 RR-30 / RR-35 的统一”。

## 根因（基线行号）

- `remoteentity/transaction_manager.go:354-365` `settleRejectedRemoteEntries`：持久拒绝后回滚（生成实体 no-op）并隔离批次内实体，按 RR-28 复核不解冻。
- 解除隔离的唯一路径是 `acknowledgeRemoteCommit`（`:1012`，需要一笔新提交），而写准入对 Quarantined 直接 `ErrRemoteFenced`（`batch.go:256-265`）；
  被拒写没有推进版本，`beginWrite` 的版本比较不会触发重载；`ManagerAccess.Get` 实例已在内存时返回原实例（`entity/manager_access.go:85-92,291-304`）。
- 框架没有“丢弃内存实例、从权威重载”的 Remote 入口；RR-28 的回归用测试专用 `loader.add(reloaded)` 替换实例（`rejected_memory_quarantine_test.go:188-189`），
  生产路径上一次瞬时错误后实体直到重启都不可写。

## 决策（维护者 2026-09-26 批准：拒绝收尾后框架自动仅内存卸载）

1. **卸载入口（与 RR-30 驱逐共用）**：`entity.ManagerAccess.Unload(ctx, e)` = `EntityManager.Destroy(ctx, e, DestroyReasonMemoryUnload, deleteFromDB=false)`，
   实例已被卸载或已不是当前托管实例时返回 nil。DataEngine 驱逐被 lease fence 跳过的原生步骤留下的实体（RR-30 `evictStaleEntities`）与 Remote 拒绝后的卸载
   都走它：Remote 侧的能力接口 `entity.IRemoteEntityUnloader`（`Backend` 转发给 loader）由 `ManagerAccess.UnloadRemoteEntity` 直接转到 `Unload`；loader 不支持时返回
   `entity.ErrRemoteUnloadUnsupported`，维持旧行为（隔离到业务重载）。Destroy 自己取实体锁、先从索引删除再运行生命周期回调，在途引用由 Touch 计数保护
   （归零才清理，Guard 对已移除实体拒绝加锁），之后 `Get` 未命中、经 loader（正式为 `EntityRepository`，会等该实体在途投影）从权威重载。
   新增 `entity.DestroyReasonMemoryUnload`（255）；RR-30 的驱逐原先传 `DestroyReasonCommon`，统一后也传它，业务 `OnDestroy` 可据此区分“只卸载内存”与业务删除。
2. **执行位置（复用 RR-30 的 `NestMgr.RunLocal`）**：finalizer 不属于任何 Nest 消息。`NewEngine` 原本只把 `RunLocal` 经 `nest.LocalExecutorBinder` 交给
   committer（DataEngine Projector）；现在同一个 `runLocal` 也交给实现了 `BindLocalExecutor` 的 Remote Manager。后台收尾的回滚（`settleRejectedRemoteEntries`，
   顺带补上 RR-28 记录的“finalizer 回滚不在快池执行”）与卸载经 `Manager.localContext` → `entity.RunLocal` 进入快池续行通道（不排同 ID 链、不占外部准入额度）；
   消息自己的收尾（`batch.Close` 的同步拒绝）沿用消息的快池续行。`RunLocal` 在 Nest 未启动 / 停机中 / 已 fence 时拒绝投递、fn 不执行：卸载保持隔离并按退避重试，
   直到 finalizer 停止（与 RR-30 驱逐“重试到成功或关闭”同一规则）。未装配 Nest（独立使用 remoteentity）时 `entity.RunLocal` 就地执行。
3. **时机**：拒绝收尾（回滚 + 隔离）→ 释放 gate / 分布式锁 / 写额度 → 卸载（`unloadRejectedEntities`）。旧实例始终保持 Quarantined，从不解冻（RR-28 复核约束）；
   卸载失败时实例保持隔离，收尾项标记 `settled`（资源已交还，排空与重试都不会再释放）并按退避重试；已卸载的条目记在 `entry.unloaded`。Durability 0 被权威明确拒绝
   （Commit 同步回滚）时，`batch.Close` 在释放后卸载，失败交给 finalizer 重试。
4. **Sync（与 RR-30 同一规则，不另设回收路径）**：卸载关闭旧实例的 `SubjectSyncState`（`ClearBase` → `Close`，被拒绝的冻结内容与脏标记一并丢弃；
   flush 对关闭的状态不捕获、不重试、不算失败）。subject **保持登记、不发 remove**，订阅者保留卸载前最后交付的对象（那是拒绝之前的、与权威一致的状态）〔更正：此说法不成立，见[复核补修](#复核补修2026-09-26rr-20260926-59)〕；
   实例从权威重载后，kit 在 `EntityRepository.OnEntityLoaded` 上调用 `entitysync.Manager.Rebind`（或业务再次 `Register`，同一路径），原订阅者下一帧收到整份替换的
   全量 `ObjectUpdate`，之后增量从全量续上。首版的 `RetireSubjectSync`（先 remove 再允许新实例登记）已删除。

### 与 RR-30 / RR-35 的统一（最终规则）

| 场景 | 内存 | Sync |
| --- | --- | --- |
| 实例内存含未持久的效果、实体在权威里仍存在（RR-30 原生步骤被跳过、RR-39 Remote 被持久拒绝） | `ManagerAccess.Unload`，经 `NestMgr.RunLocal` 在快池执行 | 状态关闭，订阅保持；重载后 `Rebind` 强制全量，**不发 remove** |
| 事务内新建的实体被回滚 / 拒绝、权威里根本不存在（RR-35） | CreateInScope 撤销发布 | `RetractSyncSubject`：已持有者收到 `ObjectRemove`，之后同 ID 才能重新登记（remove-before-create） |
| 业务删除 / 业务卸载 | `Destroy(..., deleteFromDB)` | 业务自行 `Unregister`（不变） |

区分依据是“实体在权威里是否仍存在”：仍存在就换代（Rebind 全量），不存在才移除（Retract）。快池入口只有 `NestMgr.RunLocal` 一个，经 `LocalExecutorBinder`
接给 DataEngine Projector 与 Remote Manager。首版的 `runDetachedLocal` / `continueDetached` / `entity.RemoteLocalRuntimeBinder` 已删除；它与 `RunLocal` 的唯一差别是
“Nest 停机排空期间仍接纳、排空后就地执行”，统一后改用 `RunLocal` 的“停机即拒绝”：卸载按重试处理；RR-37 的提交后回调另有就地兜底（见 RR-37 记录）。

未采用：在 gate 释放前卸载（约束要求释放 gate 之后；卸载回调里的业务逻辑也不应在持有写 gate 时运行）；给 Quarantined 实例原地“刷新内存”（生成实体没有可靠的
全量前像回滚，无法证明内存等于权威）；让 finalizer 在自己的 goroutine 上取实体锁（Nest 在场时违反“本地步骤归快池”）；卸载时对订阅者发 remove（实体仍存在，
与 RR-30 规则冲突，且重载前客户端会短暂看不到一个存在的实体）。

## 兼容性

- 行为变化：正式装配（`ManagerAccess` 作 Remote loader）下，持久拒绝的实例在 gate 释放后被仅内存卸载，业务收到一次 `OnDestroy(DestroyReasonMemoryUnload)`；
  下一次访问从权威重载，不再需要重启。卸载与重载之间的极短窗口里，下一写者仍可能拿到旧实例的 `ErrRemoteFenced`，重试即可。在途请求若已引用旧实例，加锁时按
  “实体已移除”失败，重试得到新实例。
- RR-30 驱逐的 `OnDestroy` 原因由 `DestroyReasonCommon` 改为 `DestroyReasonMemoryUnload`（只按原因做业务删除清理的代码需要注意）。
- Sync：订阅不注销；实体经正式仓储重载时 kit 自动 `Rebind` 全量；业务自己的加载路径再次 `Register` 同样走 Rebind。不要在 `OnDestroy(DestroyReasonMemoryUnload)` 里 Unregister。
- 自定义 loader 未实现 `IRemoteEntityUnloader`：行为与修复前相同（隔离到业务重载），计数 `remote_entity.rejected_unload_unsupported_total`。
- Remote 后台收尾的回滚现在在 Nest 快池执行（此前在 finalizer goroutine 上就地取实体锁）；Nest 未装配时仍就地执行；Nest 停机中时回滚与卸载按重试处理。
- 新增指标：`remote_entity.rejected_unload_total`、`remote_entity.rejected_unload_error_total`、`remote_entity.rejected_unload_unsupported_total`。持久格式不变。

## 未验证项与边界

- 正式生成工程里没有构造 Remote 持久拒绝（Remote 与 lease-fence 混合事务在 WAL 前即被拒绝，版本冲突走 DataEngine fatal），卸载/重载只在 remoteentity 层用
  正式 `ManagerAccess` / `EntityManager` 与替身 AggregateLoader 验证；替身不经过 `EntityRepository.OnEntityLoaded`，Sync 重绑在回归里以等价的 `Register` 路径触发，
  kit 的自动 Rebind 接线由 RR-30 的回归覆盖。
- Durability 2 的 WAL 记录被投影器整笔拒绝时，同一事务里的**本地**实体修改同样没有进 Mongo，但本地实体不在 Remote 批次内、不会被卸载；这是 RR-19 以来的
  既有边界（该组合现在在 WAL 前拒绝），本轮未改。
- 卸载在 gate 释放之后进行，二者之间的窗口里下一写者可能得到一次 `ErrRemoteFenced`；业务按可重试错误处理。
- 旧实例被卸载但一直没人重新访问时，订阅者保留卸载前的对象（与 RR-30 相同）。〔已由 RR-20260926-59 补修：有订阅者时框架主动重载，见下节〕

基线 `3e26f91`。修复合并后独立审计 [RR-20260926-59](../bug/RR-20260926-59.md)（[REPRO-2026-09-26-05](../bug/REPRO-2026-09-26-05.md) §8）。

### 更正

上文“4. Sync”称卸载后“订阅者保留卸载前最后交付的对象（那是拒绝之前的、与权威一致的状态）”，**不成立**：

- Durability 1 在 Commit 返回时推测性确认 Sync（`remoteentity/batch.go`、`nest/msg.go` 的推测性确认），投影器拒绝之前订阅者可能已经收到**被拒绝的**内容；
  卸载只关闭同步状态、不发修正帧，订阅者停在从未成为权威的内容上，直到有人重新访问该实体。
- RR-30 的原生步骤同理：准入时已按正常路径外发了之后被跳过的效果。
- 只有“拒绝发生在任何帧外发之前”（例如 Durability 0 同步拒绝、Durability 2 等到拒绝再确认）时，卸载前最后交付的对象才与权威一致。

上文“未验证项与边界”最后一条“旧实例被卸载但一直没人重新访问时，订阅者保留卸载前的对象”也随本次补修改变。

### 补修

维护者批准“主动重载并全量重绑”：`ManagerAccess.Unload`（RR-30 与本记录共用）卸载后，若 subject 仍有订阅者，框架在快池之外的重载 worker 上经已配置的
loader 从权威重载实例（发布回快池、`OnEntityLoaded` → `Rebind`），订阅者下一帧收到同一对象的权威全量；权威里没有它、有界重试用尽或重载队列已满时，
订阅者收到 `ObjectRemove`；无订阅者不主动重载。kit 的 `NewModWithEntitySync` 装配自动接线；自建装配调用 `ManagerAccess.ConfigureUnloadResync`。
卸载时实例的同步状态立即关闭（不等在途引用归零）。上文统一规则表的第一行改为“有订阅者时框架重载并 Rebind 全量；重载不了退回 remove”，
更新后的表见 [RR-20260926-59 修复记录](RR-20260926-59.md#rr-30--rr-35--rr-39-统一规则表更新)。

回归：`remoteentity/rejected_resync_test.go`（REPRO §8 正式版：Durability 1 推测性交付 `a=rejected`，拒绝卸载后订阅者收到 `a=` 全量；无订阅者不重载）。
本记录原有回归（`ReloadsFromAuthority` 四条、`TestRejectedWriteUnloadsOnNestFastPoolAndRebindsSync` 等）保持通过；后者不接重载器，仍覆盖“未接线时
卸载后不产生帧”。修前红、验证命令与自查见 [RR-20260926-59 修复记录](RR-20260926-59.md)。
