# RR-20260918-05：邮件账本的去重寿命短于合法的信封寿命

- 单元：U-0241 · 缺陷类 C4（跨层契约不一致）· 等级 P1
- 仓库：roost-core `service/mail`（交出权威时刻）+ roost-codegen `demo/`（改用它）
- 排障行：T-135 · 与 U-0237（副本那条）同一个教训的第二次

## 问题

`ClaimMailReward` 按固定 31 天清理账本，论证是"31 天 > `mail.send_ttl`（生成配置里 720h）"。
而 Kit 对 `send_ttl` **只校验为正数**：把它配成 40 天是受支持的配置，于是账本先忘掉，信封还可领，
同一封邮件再发一次奖。审查的独立复现：把已领取记录的时刻放到保留期之前、信封仍可领，
调用真实生成的 handler，得到 `Claimed=true`、背包从 2 涨到 3。

## 根因

**资产正确性被绑在另一个服务的配置上。** U-0237 修副本那条时我写下过这句话，然后在邮件这条上
保留了同一形状的论证——只因为那条 TTL "真实存在"就以为够了。真实存在不等于不可更改：
一条合法的配置改动就能让不变量失效，而且没有任何测试会红。

正确的锚不是别人的**配置**，是别人的**权威时刻**。邮件服务知道这个时刻（`Envelope.ExpiresAtUnix`，
`ReserveClaim` 里已经用它拒绝过期邮件），只是没有交出来。

## 方案选择

- **（选中）服务把水位交出来，账本按它记与清。** core 的 `mail.Claim` 增加 `ExpiresAtUnix`（信封的过期时刻，
  不是预留的租约 `DeadlineUnix`）；demo 的账本存这个值，清理谓词换成 `rewards.ClaimWindowClosed(expiresAt, now)`。
  于是"记录被清掉 ⟺ 该邮件已不可预留 ⟺ 任何重放都到不了发放路径"，与副本那条同形，且不引用任何配置。
- 跨层校验 `send_ttl < claim retention`：审查点出它"会继续把资产正确性绑定到另一个服务的存储策略"，
  而且要在启动时跨服务读配置。
- 领取提交成功后即删记录：看起来最省，但 `CommitClaim` 失败正是账本要挡的那条路径，删早了就把窗口重新打开。

## 改动

- roost-core `service/mail/service.go`：`Claim.ExpiresAtUnix`，在 `ReserveClaim` 构造 `Claim` 时取自信封。
- roost-codegen `demo/game/rewards/rewards.go`：`ClaimRetentionSeconds` / `ClaimExpired` 换成
  `ClaimWindowClosed(expiresAtUnix, nowUnix)`；**过期时刻为 0（无法在时间上定位）的记录保留而不是遗忘**——
  拒绝遗忘是安全方向，而且账本不再收缩是运营看得见的。
- `demo/game/entities/player/bag_component.go`、`demo/game/handler/claim_mail_reward.go`：多一个 `expiresAtUnix` 参数，
  账本存它、按它清。
- `demo/game/controllers/player/claim_mail.go`：把 `claim.ExpiresAtUnix` 传进事务。

**依赖**：demo 这半需要 core ≥ 下一个版本。

## 证明

- core：`service/mail/claim_expiry_promises_test.go`——预留必须报告信封的过期时刻，且它必须**长于**租约 deadline
  （两者可混淆，所以一起断言）。修前红：`claim.ExpiresAtUnix undefined`。
- demo：`game/handler/claim_mail_reward_test.go` 的 `TestMailClaimsArePrunedByTheMailsOwnExpiry`——
  已过期的邮件记录被清、仍可领 40 天的邮件记录保留，且在第 39 天重放仍被拒（旧的 31 天保留期在这里必然放行）；
  `TestAClaimWithNoExpiryIsNeverPruned`——无过期时刻的记录不被遗忘。
  审查的独立复现是同一件事的另一种造法（`Claimed=true`，背包 2→3）。

## 未做 / 边界

- **账本仍然靠"别的服务的时刻"**，只是从可改的配置换成了不可改的事实。若邮件服务将来允许延长某封信的过期时间，
  这条又会被打回——真正无条件安全的是"永不遗忘 + 压缩水位"，demo 没做，因为它需要第二个事务。
- `send_ttl` 与账本之间不再有任何隐含关系，所以也**没有**加跨层校验。
- 没有验证：邮件服务把过期时刻改小（记录会提前被清，而邮件也确实提前不可领，方向安全但未测）。
