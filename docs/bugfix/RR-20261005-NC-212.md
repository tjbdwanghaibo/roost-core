# NC-212 修复：CompileEnvironment 检查 catalog key 非空且唯一

[问题](../bug/RR-20261005-NC-212.md) · [本轮](../review/REVIEW-2026-10-05-n09-batch4.md)。已修复、声明场景验证，未发版。

## 根因与决策

`validateCatalogHandles` 只查 handle；编译器按 key 查 catalog 时有 last-wins（authority 表、owned entity 模板表）和 first-wins（`unitTemplateEntry`、typecheck 属性表）两种写法。在 `validateCatalogHandles` 末尾为 attributes / resources / statuses / unit_templates / collision / damage_types / elements / tags / shared_states 增加 `checkKeys`：key 为空或重复报 `CATALOG_DUPLICATE_HANDLE` 到 `…[i].key`（沿用 handle 唯一的诊断码，环境错误本来就是 `DiagnosticCatalog*` 一族）。temporal 与 process property 已有自己的 key 检查，不重复。

未采用：把所有按 key 的查找统一成同一种 wins 规则——重复 key 本身就是 catalog 数据错误，应该拒绝而不是选一个。

## 文件与行为

`skill/compile_authority.go`。带重复或空 key 的环境在编译时以环境诊断失败（所有定义都编不出 Program）；默认环境与仓内全部测试环境不受影响。

## 回归

`TestCompileEnvironmentRejectsDuplicateCatalogKeys` 修前 `missing error CATALOG_DUPLICATE_HANDLE at $.gameplay.unit_templates[1].key in []skill.Diagnostic{}`，修后 ok（含 attributes / statuses / resources / tags 四个子用例，以及原触发“bool 绑定到 int 参数”不再编译）。

## 兼容性

行为收紧：业务 catalog 若有重复 key，升级后启动期 CompileAll 失败，需要修正 catalog 数据。
