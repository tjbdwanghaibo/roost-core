# RR-20261004-NC-04：Ops Shutdown 的资源所有权

2026-10-04，修前 `7e0d6ee2`。[原问题](../bug/REVIEW-2026-10-04-noncore-02.md#rr-20261004-nc-04)。已修复、声明场景验证，未发版。

根因在原 kit/ops/ops_mod.go:145–158：Shutdown 返回取消后仍清空 server。现在短锁取出 server、锁外 Shutdown；错误保留引用，成功后只清除同一实例。Start 在短锁内拒绝已有/仍待排空实例，监听 goroutine 捕获局部 server，不读取可能变动的 m.server。多个 Stop caller 保留各自 context，不把 Shutdown 等待放进状态锁。

复用标准库 Shutdown，不强行 Close 活跃 handler，不后台无限重试。成功关闭后仍可 Start 新 server；Init/Provide 属串行装配，不承诺与运行期 Start/Stop 并发重配配置。

正式修前真实回环请求：`first=context canceled server_retained=false handler_active=true`、重试 nil；修后 server_retained=true，释放 handler 后再次排空成功。新增真实期限超时、排空前拒绝 replacement/排空后可重启、独立取消 caller、并发 Start/Stop race 均通过。[证据](evidence/noncore-bugfix-20261004-02/README.md)。正式回归 kit/ops/shutdown_ownership_promises_test.go，T-190。

公开签名不变，运行中重复 Start 现在返回 error；取消/超时后的调用者须保留 Mod 并在预算允许时重试关闭。未实现 bind 失败传播、hijacked/WebSocket 连接排空或外部进程 HA；未发版/部署。
