# RR-20261005-NC-231：停机阶段的 lifecycle hook 在停机总预算内等，超时按“停机不完整”保留依赖

2026-10-06，基线 `c8ecbabb`。**已修复、声明场景验证，未发版。** [问题](../bug/RR-20261005-NC-231.md) · [本轮](../review/REVIEW-2026-10-06-n01b.md) · [证据](evidence/noncore-bugfix-20261006-n01b/README.md)。

## 根因

`App.run` 对 service.stopping / service.stopped 同步调用 `emitLifecycle`；`shutdownCtx` 只传给了 hook，没有约束 run 自己的等待。Service.Shutdown（当前 `:444-470` 的 select）与 Mod 停机（`stopModSafely`）早已是“goroutine + 在 ctx 内等”，hook 是停机路径上唯一没这样做的回调。

## 修法

- 新增 `App.emitLifecycleWithin(ctx, event) (finished, err)`：在 goroutine 里 `emitLifecycle`，在 ctx 内等；到期返回 `finished=false` 与 “hooks did not return within the shutdown budget: context deadline exceeded”，hook 留在自己的 goroutine 里。与到期同时返回的按已返回算。
- service.stopping：`finished=false` 时与 Service.Shutdown 不完整相同——不调 Shutdown、不停 Mod、`singletonReleasable` 保持 false，run 返回。hook 自己返回的错误（含配合 ctx 返回的 ctx 错误）仍按原样并入、继续停机。
- service.stopped：此时 Mod 已停完、释放与否已按 Mod 的结果定好；卡住只让 run 按预算返回，剩余时间不够时 Release 跳过（键在 ttl 内过期）。**单实例锁的 Release 规则不变**。
- 启动阶段（app.init / mods.started / service.started）没有停机预算，仍同步派发（启动由 k8s startupProbe 兜底）。

没采用：hook 超时后继续 Service.Shutdown 与 Mod 停机——hook 可能正用着 Service / Mod 的能力，在它底下拆依赖违反三步停机③。

## 兼容

只改变“hook 不在预算内返回”的情形：之前 run 不返回，现在按预算返回错误。按时返回的 hook 行为不变；`TestAppReturnsServiceStoppingLifecycleError`（hook 返回普通错误）不变。

## 验证

- 修前红见问题记录；修后两个阶段的用例通过（run 在预算附近返回 DeadlineExceeded；stopping 卡住时 Shutdown 0 次、Mod 停 0 次、不 Release；stopped 卡住时 Shutdown 1 次、Mod 停 1 次）。
- `GOWORK=off go test -race -count=3 ./app/`（含 `singleton_test.go` 全部用例）、`go vet ./app/` 通过；根包通过。
