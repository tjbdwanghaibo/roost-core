# RR-20261006-46 修复：步骤 Timeout 与步骤消费者 AckWait 的关系没有校验，Timeout 不短于 AckWait 时处理中被重投

问题：[RR-20261006-46](../bug/RR-20261006-46.md)（F06-C1）。基线 `0b223b4c`（main，v1.23.0 之后；WIP `wip/sagafix` `bcdb4bd4` rebase 到此）。codebase-memory 共享 generation 停在 09-30（比基线旧），定位与结论按 worktree 当前源码读取。
同一批（sagafix2）修 RR-20261006-42～47，一笔提交 `63bc1d66`。

## 根因

saga Mod（`kit/saga`）没有跨键规则比较步骤 `Timeout` 与步骤消费者的 `AckWait`；`AckWait` 的缺省值是两处字面量 30s，没有可引用的名字。

## 决策

- **A4 ① 跨键规则**：`kit/saga/config.go` 的 `config.ValidateConfig` 拒绝 `saga.step_defaults.timeout` 与 `saga.steps.<type>.<step>.timeout` 不短于 `saga.DefaultStepAckWait` 的配置（App 启动前 / `CheckConfig` / doctor 共用，错误点名键）；定义里写死的 `Timeout` 不在配置里，`Init` 在解析步骤预算之后用 `checkStepTimeouts` 查，错误点名 `saga "<type>" step "<name>"`。
- **`saga.DefaultStepAckWait`**（30s）：步骤消费者不写 `AckWait` 时的取值，两个步骤消费者都引用它；`StepConsumerConfig.AckWait` 注释写明“必须长于路由到这个主题的每个步骤的 Timeout”。
- **不新增 `saga.step_ack_wait` 配置键**：步骤消费者由业务 / 生成代码订阅，Mod 不读这个键，声明了没人读会被 A4 ① 守卫拒绝（RR-20261006-38 的教训）。自己写更短 `AckWait` 的业务要相应缩短 `Timeout`，文档写明。
