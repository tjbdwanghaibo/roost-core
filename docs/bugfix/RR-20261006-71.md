# RR-20261006-71 修复：Assemble 与 NewSnapshotClient 共用快照段校验

问题：[RR-20261006-71](../bug/RR-20261006-71.md)（F05-4）。基线 `c78d0c34`（main）。codebase-memory 共享 generation 停在 09-30（比基线旧），按 worktree 当前源码。分支 `remfix`（同批 RR-20261006-68～74，F05-1～F05-7、F09-R2、F09-R3）。

## 决策

把 `validateSnapshotClientConfig` 里只看配置的部分拆成 `validateSnapshotConfig(cfg, hasL2)`，`NewSnapshotClient` 与 `Assemble` 都调它（`Assemble` 总带 Redis L2，`hasL2 = true`）。`NewManager` 保持不返回错误的签名，仍用不校验的构造；正式 owner 入口是 `Assemble`。

## 文件与行为

| 文件 | 改动 |
| --- | --- |
| `remoteentity/snapshot_client.go` | 拆出 `validateSnapshotConfig` |
| `remoteentity/assemble.go` | `Assemble` 在构造之前校验 |
| `remoteentity/assemble_snapshot_config_promises_test.go`（新） | 五组非法配置（interest_ttl / load_timeout / l2_ttl 为 0、cache_ttl 为负、per_consumer > subs）都被拒；缺省配置照常通过 |

## 兼容性

行为收紧：直接调 `Assemble` 且传入上述非法组合的装配现在启动失败（错误点名键）。kit 从 `DefaultConfig` 起步并按声明校验，不受影响。
