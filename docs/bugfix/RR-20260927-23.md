# RR-20260927-23 修复：game-demo 场景接 `OnEntityLoaded → Rebind`，业务重新加载的玩家绑回场景

问题：[RR-20260927-23](../bug/RR-20260927-23.md)（来源：[RR-20260927-18 修复记录](RR-20260927-18.md)自报的剩余边界）。
日期 2026-09-27；实施基线 `3d325be`（已含 RR-18 / 19），分支 `fix-r7-extra`。状态：已修复、本地验证通过，已本地提交，未合入 main / 未发布。
codebase-memory 图谱已过期（generation 09-26），以下行号与结论来自当前源码与生成工程实跑。

## 根因（基线 `3d325be`）

- `demo/internal/service/game/scene.go.tmpl:177-205` `NewScene` 只取了 `ManagerAccess`（`:198` `scene.unloads = access`），`:289-305` `Scene.Start` 只接
  `ConfigureUnloadResync`；kit 给自己的 Manager 同时接了 `OnEntityLoaded → Rebind`（`kit/nest/nest_mod.go:163-170`、`:212-223`），场景没有。
- 框架的重载只在还有人看着时发生：`entity/manager_access.go:596-601` 卸载后 `resync.schedule(id)`，`entity/unload_resync.go:151-153` 先问
  `SubjectAwaitsReload`，没有非 leaving 的订阅者就不排重载（RR-59 约束）。
- 于是玩家被卸载时恰好没人订阅（自己的复制会话掉了且重开被拒 / 用尽、附近没人），之后业务再访问它、DataEngine 从权威加载出新实例，场景的 subject
  仍停在关闭的旧状态上（不捕获、不发送）；稍后进入视野的观察者订阅成功却永远收不到这个玩家，直到它离场重进。

## 修复（按主记录修复约束）

`demo/internal/service/game/scene.go.tmpl`：

- 新接口 `entityLoadNotifier`（`OnEntityLoaded(func(IThreadSafeEntity)) (func(), error)`，与 kit/nest 同形的可选能力，kit/dataengine `Mod` 实现），
  `Scene` 增加 `loads` 与 `unhookLoads`。
- `NewScene` 从注册表 `mods.ModDataEngine` 取该能力，取不到返回错误——与 RR-18 对实体运行时的处理一致：生产装配一定有 DataEngine，缺了就等于重新加载的玩家
  永远绑不回场景，不做静默降级。
- `Scene.Start`：先 `ConfigureUnloadResync`（RR-18），再 `OnEntityLoaded(bridge.rebindLoaded)`，最后启动复制循环；挂钩失败时停掉已接的重载，复制循环启动失败时
  先解钩再停重载——没启动成功的场景不留下任何接线。kit/dataengine 的 `OnEntityLoaded` 要求 Runtime 已启动，服务 `Init` 在全部 Mod 启动之后才建 / 启场景，满足。
- `rebindLoaded`：取加载出的实体的同步状态（无同步或未启用则跳过），`Manager.Rebind`；`ErrSubjectNotRegistered`（不在场景里的实体，普通冷加载都是这种）、
  `ErrSubjectRegistered`（已绑在活状态上）、`ErrSubjectRetiring`（离场仍欠 remove，重进走 `RegisterAfterRetirement`）、`ErrManagerClosed`（停机中）忽略，其余 Warn。
  比 kit 多忽略后两种：场景的离场 / 停机都是常态，照 kit 那样 Warn 只会制造噪音。
- `Scene.Close`：先停重载（RR-18），再解钩，再关 Interest 与 Manager。服务 `Shutdown` 先于 Mod 停止，所以解钩时 Nest 仍在运行；解钩之后发布的加载不再 Rebind，
  随即 Manager 关闭，没有需要跟随的 subject。

执行位置：钩子在 DataEngine 发布加载的那一步执行（`dataengine/engine/entity_repository.go` 在 `entity.RunLocal` 内 `Create` 之后 `runLoadedHooks`，Nest 快池）；
`Rebind` 只取 subject 锁、换状态、装脏通知并唤醒同步，不等待、不做 I/O，没有在快池新增等待。

未采用：只在 `SubjectAwaitsReload` 为假时也强制重载——那是改框架的 RR-59 约束（没人看着就不读权威），超出本条；主记录约束也指定走 `OnEntityLoaded`。

## 后续验证（2026-09-30，B27 第 3 批）

来源：[REMAINING-2026-09-28 §1.1 B27 分批第 3 行](../review/REMAINING-2026-09-28.md)（“未验证项 / 风险”第 1 条：真实 DataEngine（Mongo）的 `OnEntityLoaded → Rebind` 端到端）。基线 `96f0f7c5`。环境与生成工程同 [RR-20260926-25 同批追加节](RR-20260926-25.md)；两个 game 进程同 [RR-20260927-02 同批追加节](RR-20260927-02.md)。脚本与输出：scratchpad `b27-batch3/drill-rr23.sh`、`rr23-drill.log`（两次实跑一致）、`rr23-game.log`。

- **场景**：观察者 Q 与玩家 P 都在 game（1300）登录并互相可见（Q 收到 P 的 create delta）；game `SIGSTOP` 40s；P 在 game2（1301）登录、写入；`SIGCONT` game。game 的下一次刷新（21:04:36.96）同时做了两件事：对 P `fenced … sessions_closed=1`（P 的连接被关，见 RR-20260927-02），对 **仍然连着、仍在场景里的 Q** 记 `player owners: lease had lapsed and was retaken; the stale copy was dropped`（`PlayerOwners.renew` → `Claim` → `dropResident` → `EvictPlayer` → `Destroy`，`internal/service/game/playerowner.go`）。之后 P2 断线、game2 交还租约，P 于 21:05:04 再次在 game 登录（`created=false`，加载走 `EntityRepository.OnEntityLoaded`），在 Q 的 AOI 内移动两次；Q 于 21:05:16 自己发一次 `move`（`code=0`，实体为此从 Mongo 冷加载，也走 `OnEntityLoaded`）。
- **结果：暴露缺陷（候选，未登记 RR）**。stale copy 被丢弃之后 Q 就再没有收到任何帧：没有 P 被围栏的 remove、没有 P 重新登录后的 create / 两次移动 delta、连自己 `move` 的 delta 也没有；反过来 P 重新登录拿到的全量只有自己 + 3 个怪（**看不到 Q**），Q 的 `move` 之后 P 也没有收到 Q 的 create。也就是说：进程自己的续租中断超过租约（Redis 分区、长停顿）后，`Claim` 为“换到重载”而丢掉常驻副本，但玩家的连接与场景成员身份都还在——他从此对场景**既看不见也不被看见**，重新加载（`OnEntityLoaded → Rebind`）没有把他救回来，直到重新登录。两次实跑一致。复现命令、日志原文与根因候选行见本批报告缺陷清单；本条的 Rebind 接线在这条路径上没有观察到效果，因此“真实 Mongo 下 Rebind 端到端”**未通过验证，转入缺陷登记后再补**。
- 与 RR-20260927-18 的“剩余边界”一致的地方：丢弃发生时 Q 自己的会话就是订阅者，却没有触发重载给 Q 一份 Mongo 全量。

## 后续（2026-10-01）

上文"后续验证（2026-09-30，B27 第 3 批）"暴露的缺陷已登记为 [RR-20260930-23](../bug/RR-20260930-23.md) 并修复（[修复记录](RR-20260930-23.md)）：续租中断后重取租约时，`PlayerOwners.renew` 对仍连着的玩家像围栏一样关闭连接（日志 `lease had lapsed and was retaken; the stale copy was dropped` 新增 `sessions_closed`），客户端重连走正常登录重新加载并 `Join`。本条的 `OnEntityLoaded → Rebind` 接线在那条路径上本来就不会起作用——副本是被 Destroy、场景已 `Leave`，不是框架重载；修后的演练里观察者重新登录时的冷加载经 `OnEntityLoaded` 触发 `rebindLoaded`，但 subject 已不在场景里（`ErrSubjectNotRegistered`，按设计忽略），随后 `Join` 正常登记。"真实 Mongo 下 Rebind 端到端"仍按上文的结论：未在生成工程上观察到，不随本条关闭。
