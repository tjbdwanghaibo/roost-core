# RR-20260924-26：持久化所有权与最新写许可

2026-09-25。对应 [原始问题与失败证据](../bug/RR-20260924-26.md)，方案见 [Remote 权威与投影批量优化](../feature/REFACTOR-2026-09-25-remote-authority.md)。状态：代码已修复，针对性真实故障与生成业务链已验证；未发布。历史失败证据保留在问题文档和 2026-09-24 验收报告。

## 修复

- `mongo_authority.go`：`_remote_entity_meta` 同时保存已提交版本、所有权和最新 grant。正式驱动使用 majority+journal。授予通过一次 FindAndModify 原子递增 fence 并返回版本，丢回复时只按本次唯一 token 查询结果，禁止未知结果换 token 自动重试。
- `versioned_lock.go`：共享写先竞争 Redis，再取得 Mongo 许可，并检查 Redis token 仍属于本次持有者；失败只清理本 token，不覆盖版本缓存或别人的锁。对外 Version/Fence 来自持久权威。
- `batch.go`：owner-routed 写也取得许可；两种模式都按权威版本检查实体加载结果，过期数据不得准入。
- `mongo_committer.go`：业务事务在同一 metadata 文档上原子校验 BaseVersion、最新 fence、所有权 epoch 和有效 token。所有已准入实体的 CAS 按事务合并为一次 BulkWrite，匹配数必须等于实体数；任一失效则全部回滚。所有权变化撤销旧许可；grant 与 commit 并发由 Mongo 写冲突串行化。已经提交的同一 transaction ID 保留 digest 幂等重放。
- `assemble.go` / `backend.go`：正式装配必须提供 `WriteAuthorityProvider`，不自动退回 Redis 权威。Mongo 后端自动接入，无需新增业务开关。
- `mongo_payload.go`：同一事务的 DAO 和快照操作按实际数据库/集合合并，保留集合内顺序；任何集合失败仍回滚所有实体 CAS、payload 和 outbox。

没有修改 Entity/WAL 编码字段、transaction digest 或持久确认语义。所有改动仍位于原 `remoteentity` 包。

补充边界：真实 Mongo 多数派恢复耗时可能超过短 Redis 租期。仅当 grant 已明确成功、业务尚未准入且 Redis 返回 token 已失效时，允许重新争锁并取得新许可；grant 结果未知或 Redis 校验网络错误不自动换 token。对应确定性单测覆盖首次租约过期、第二次获取成功。

## 当前接口与历史更正

用户随后确认没有新部署，原先假定既有部署而增加的 `MigrateLegacyAuthority` 和 `EnableWriteAuthority` 已移除。`MongoCommitter` 默认强制持久许可；`WriteAuthority()` 是无副作用能力 getter。原文关于停服迁移工具的操作建议不再适用，历史问题证据保留。

Redis-only 工厂只保留低层协调能力，正式 Assembly 使用 Mongo authority。损坏或不支持的 metadata 仍拒绝启动，不自动清库。详见 [RR-20260925-02](RR-20260925-02.md)。
