# RR-20260926-56：syncbus JetStream 流名缺省由 prefix 派生，默认 prefix 仍为 ROOST_SYNC，可显式配置，启动日志输出实际流名

问题：[原始记录](../bug/RR-20260926-56.md)。日期 2026-09-26。
实施基线：本地 main `3e26f91`（本轮 RR-52、RR-55 修复之上）。状态：已修复，适用本地验证通过，已本地提交，未推送/发布。

## 根因（复核）

`sync/syncbus/driver/jetstream.go` 的 `normalizeJetStreamSyncConfig` 在 `Stream` 为空时一律用常量 `ROOST_SYNC`，与 `Prefix` 无关；kit `SyncBusMod`
原样传入 `syncbus.stream`（生成配置不写）。`EnsureStream` 是 `CreateOrUpdateStream`：prefix 不同的两个部署共用一个 NATS 时，后启动者把同名流的
subjects 改成自己的 `prefix.>`，先启动者的发布从此不再入流（持久投递静默失效），两边的 durable 也挂在同一个流上。启动日志只有 transport，看不出用的是哪个流。
`syncbus.stream` 键此前已被读取，但未写进生成配置与文档。

## 修复（按维护者批准的约束）

1. **driver**：新增导出 `JetStreamSyncStream(prefix)`，`Stream` 为空时由它派生：
   - 默认 prefix（`roost.sync` 或空）→ `ROOST_SYNC`，已部署的流不变；
   - 只由小写字母、数字与单个 `.` 分隔组成的 prefix 大写、`.` → `_`（`zz3640.sync` → `ZZ3640_SYNC`），映射可逆，不同 prefix 不相撞；
   - 其他 prefix（含 `_`、`-`、大写、连续/首尾 `.`、超长）折叠后追加 prefix 的 SHA-256 前 8 字节（十六进制），折叠后相同的 `zz.sync` / `zz_sync` / `ZZ.sync` 仍各得其流。
   - `EnsureStream` 失败的错误带上流名与 subjects，便于定位“subjects overlap”。
2. **kit `SyncBusMod`**：`syncbus.stream`（或兼容段的 `stream`）显式配置优先；否则由 prefix 派生。未配置 prefix 时本 Mod 的缺省 prefix 是 `roost.room`，
   修复前它也落在 `ROOST_SYNC` 上，所以 `roost.room` 同样映射到 `ROOST_SYNC`（常量 `defaultPrefix`）。启动日志 `syncbus mod: started` 新增 `prefix`，
   JetStream 时再加 `stream`（实际流名）。
3. **生成配置**（`codegen/internal/roost/catalog.go`）：`syncbus:` 段在 `prefix` 后写入注释说明派生规则与 `# stream: ROOST_SYNC`（只在要沿用已有流 / 游标时显式写）。
   生成的 `config.game.yaml` / `.prod.example.yaml` 因此多 4 行注释，键值不变。
4. **生成工程测试**（`demo/internal/service/game/syncbus_config_test.go.tmpl`）：在 RR-12 的断言上增加“启动日志的 stream 等于配置 / 派生值，生成的 `roost.sync` 仍是 `ROOST_SYNC`”。
5. 文档：`kit/README.md`、`docs/USER_GUIDE.md` 同步。

durable consumer 名（`durableSyncName`）不变，仍只依赖 prefix / topic / sid。

未采用：流名改成 `ROOST_SYNC_<hash>` 一律带摘要（默认部署的流名会变，违反兼容约束）；在 kit 里直接拼 prefix（driver 的直接使用者得不到隔离，规则会分叉）。

## 兼容性与迁移

- **默认部署不变**：生成配置（`prefix: roost.sync`）、未写 prefix 的 kit 部署（`roost.room`）、显式写 `stream` 的部署，流名与 durable 游标都与修复前相同。
- **行为变化**：写了非默认 prefix、没写 stream 的 JetStream 部署，升级后流名从 `ROOST_SYNC` 变为派生名。
  - 若它当时是 `ROOST_SYNC` 的 subjects 持有者（共用流的最后启动者，或独占该 NATS），新流的 subjects 与旧流重叠，`CreateOrUpdateStream` 报 subjects overlap，**启动失败**（不会静默）。
    要沿用旧流与游标：配置 `syncbus.stream: ROOST_SYNC`；要迁移：确认旧流无未消费消息后删除或改 subjects，再启动。
  - 若它的 subjects 早已被别的部署从 `ROOST_SYNC` 挤掉（即本问题的受害方），新流直接创建，从此各自隔离；那段时间未入流的消息修复前就已丢失，不可补回。
- 新增导出 `driver.JetStreamSyncStream`；`JetStreamSyncConfig` 字段不变。启动日志多两个字段。

## 交付前对抗性自查

- **流名兼容已部署游标**：默认 prefix（`roost.sync`、空）与 kit 缺省 `roost.room` 仍为 `ROOST_SYNC`；显式 stream 原样；durable 名算法未改。回归逐项守护。
  非默认 prefix 且未写 stream 的部署升级会换流：旧流仍持有其 subjects 时启动失败（显式、可定位），已写入迁移说明；不会出现静默双写或丢游标后从头重放。
- **派生不相撞**：可逆映射 + 其余情况追加摘要；回归覆盖折叠后相同的 prefix。
- **关闭失败连接 / 连接槽 / Join 排队 / 代际**：本修复不涉及（见 RR-52 / RR-55）。
