# RR-20261005-NC-36：检查权威读取最终保留的最低版本

[问题](../bug/RR-20261005-NC-36.md)，基线40d89ac6；已修复、声明场景已验证，未发版。

## 决策与实现

[entity/remote_snapshot.go](../../entity/remote_snapshot.go) 的 LoadAuthoritative 在 Publish 后读回 L1，并在过期检查后重新比较 StateVersion 与 minVersion。不足返回已有 ErrRemoteSnapshotStale / found=false。

保留 Publish 的 epoch 准入与正常 stale 去重，未采用放宽 epoch、盲重试 loader 或返回未被准入的原始结果。这样既保护较新 epoch，也让调用方知道最低版本没有满足。Manager 的 Monotonic 路径已有有界 WaitForVersion/再加载，本次不改它的等待策略；SnapshotReplicaStore 已透传 LoadAuthoritative 错误，不需要另改消费者。

## 红绿、恢复与兼容

[正式读取](../../entity/snapshot_authoritative_admission_promises_test.go) Monotonic/Linearizable 两项红→绿，验旧 epoch 被拒、较新 epoch/version2/原内容保留，随后同 epoch/version4 恢复。[正式消费](../../remoteentity/snapshot_repair_admission_promises_test.go) retained-epoch 一项红→绿，error 可 errors.Is(ErrRemoteSnapshotStale)，重新投递合法权威结果后 version9/full 到位；正常 gap/epoch/schema 三项与 loader-error 控制通过。

旧失败：`minimum version violated after admission: found=true version=2 err=<nil>`、`failed authoritative repair returned success to publisher`。[运行证据](evidence/noncore-bugfix-20261005-14/README.md)。

API/wire/存储格式不变；此前错误的低版本成功改为既有 stale 错误，不新增递归或后台任务。最终 miss 仍是 miss，未将其假装成持久业务 ACK。没有验证真实 Mongo/Redis HA、broker retry 或 epoch 切换长期负载。
