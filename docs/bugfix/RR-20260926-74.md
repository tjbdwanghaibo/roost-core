# RR-20260926-74 修复：嵌套独立事务不得持久写外层可回滚事务已快照的实体，在写持久记录之前拒绝并自身回滚

问题：[RR-20260926-74](../bug/RR-20260926-74.md)（探针 [REPRO-2026-09-26-07](../bug/REPRO-2026-09-26-07.md) §1 探针 2）。
日期 2026-09-27；实施基线本地 main `62fdbe6`，建立在同批 [RR-20260926-73](RR-20260926-73.md) 之上。状态：已修复、本地验证通过，已本地提交，
未推送 / 未发布。方向按维护者 2026-09-27 批准的修复约束（拒绝）。codebase-memory 图谱对 `nest/` 已过期（generation 09-26 08:36），
结论来自当前源码。

## 根因（基线源码核对）

- `nest/execution.go:77-87` `RunIsolatedTransaction` 总是新建 undo / strict 事务（`invokeWithTransaction` `:155` `NewRollbackTx`），与外层事务
  没有任何关联：它不知道外层已为哪些实体登记了回滚。
- 外层 `CaptureEntities`（`nest/rollback.go:738-797`）对声明目标、Cast、新建实体按策略登记恢复：`captureDao`（`:810-847`）在 RollbackState 下
  登记 `RestoreRollbackState` + tracker `Restore`，在 RollbackUndo 下登记 tracker `Restore`；外层 `MarkPersist` 的 `persistChange` 同样登记
  tracker 快照。
- 嵌套事务在 `durableCommit`（`:571-603`）里持久提交并 `acceptPersistence`（值 100、tracker 版本 1）；外层随后失败，`Rollback` 逆序执行这些
  恢复：RollbackState 把值与版本都退回（1 / 0），RollbackUndo 值保留、版本退回（100 / 0）。内存与已持久的记录分叉，下一次写以旧
  `ExpectedVersion` 投影撞版本冲突。

## 决策与实现

- `RollbackTx` 新增 `enclosing`（本事务开始时的 `CurrentRollbackTx()`，`invokeWithTransaction` 设置；消息自己的事务为 nil）与 `snapshotted`
  （以可回滚策略捕获的实体，`CaptureEntities` 在 policy 非 none 时追加，首次按 `len(es)+2` 一次分配）。
- `durableCommit` 在 `prepareCommitRecord` 之后、记录非空、调用 committer **之前**执行 `refuseWriteUnderEnclosingRollback`：沿 `enclosing` 链，
  对每个可回滚且未关闭的外层事务，若本事务的任一持久参与者（`participantOrder`，即 `MarkPersist*` 的 DAO）是外层 `MarkPersist` 过的 DAO，
  或属于外层快照过的实体（`RangeDao` 按实例比较），返回 `fmt.Errorf("%w: id … (nested …, enclosing … transaction …)", ErrNestedTransactionRollbackConflict)`。
  它不是 `ErrCommitIndeterminate`，`commitDurable` 走明确拒绝路径 `rejectCommit` → 嵌套事务 `Rollback`（undo 与 tracker 快照恢复），
  没有任何记录交给 committer；`nestedTxCommitted` 不置位（RR-65 判据），外层快照不动。
- 按 DAO 实例而不按 ID 匹配：生成 DAO 的 `Id()` 是 `param.StorageID()`，不保证等于实体 ID，按 ID 比较会漏判或误判。
- 外层是 RollbackNone 时不检查：memory 快路径没有 RollbackTx（`CurrentRollbackTx()` 为 nil，`enclosing` 为 nil），带 Remote 批次的 memory
  handler 的事务不登记快照。仓内唯一生产调用 `dataengine/engine/entity_delete.go:92` `admitLocalEntityDelete` 只在没有 RollbackTx 时走到，行为不变。
- 只检查“要持久写”的实体：记录为空（嵌套事务只改内存、不 `MarkPersist`）时没有持久结果可被覆盖，不拒绝。

未采用：改外层快照的基准（把嵌套提交后的值 / 版本写回外层快照）——维护者明确不做；在 `MarkPersist` 时立即拒绝——业务可能忽略该返回值
继续提交，必须在提交点兜底，且约束只要求“写任何持久记录之前”；按记录里的实体 ID 匹配——见上。

## 兼容性与迁移

- **行为收紧**：外层 state / undo handler 里，`RunIsolatedTransaction` 持久写外层声明目标、外层 Cast / 新建的实体或外层 `MarkPersist` 过的 DAO，
  此前照常提交（外层失败后内存与持久分叉），现在返回 `ErrNestedTransactionRollbackConflict`，嵌套事务什么都没提交。需要这种写法的业务把写入
  并入外层事务，或让独立事务只写它自己 Cast 取得的实体。外层 memory handler 不受影响。
- 新导出：`nest.ErrNestedTransactionRollbackConflict`。无删除 / 改签名，无配置、持久格式变化。
- 性能：可回滚事务的 `CaptureEntities` 多一次小切片分配。`BenchmarkHandlerCreateEntity/state_strict`（同机、`-count=3`、未做 benchstat）
  91 → 92 allocs/op、约 4.56 → 4.64 KiB/op，时间在噪声内；memory 与 `ClientRequestSingle` 不变。

## 对抗性自查

- **拒绝早于任何持久记录**：检查位于 committer 调用之前；回归断言 committer 收到 0 条。拒绝走 `rejectCommit`，嵌套事务的 undo 与 tracker 快照
  都恢复，`acceptPersistence` 不执行。
- **外层快照不改**：检查只读外层的 `participantChanges` / `snapshotted`，不修改外层任何回滚函数；外层回滚后恢复到它自己的快照。
- **memory 外层不变**：`enclosing` 为 nil 或 policy none 时跳过；删除路径的既有 `./dataengine/engine` 删除用例全部通过。
- **RR-65 不回退**：被拒绝的嵌套事务不置 `nestedTxCommitted`，外层可照常重排；已提交的嵌套事务（写外层未捕获的实体）仍按 RR-65 处理。
- **快池不阻塞**：只增加内存比较；不新增等待。

## 未验证项 / 风险

- 外层 undo 事务里业务用 `RecordUndo` 登记了对非 DAO 对象的撤销、而嵌套事务持久写的正是这份数据（不经 DAO / tracker）——框架无法识别，
  未覆盖；生成代码的持久写都经 DAO。
- 嵌套事务内 `AddMutation` 直接写原始 mutation（不经 `MarkPersist`）不在检查范围：它没有 DAO 实例可比，按实体 ID 比较又不可靠（见上）。
  仓内生产代码没有这种写法。
- 未在真实 WAL + Mongo 环境验证，回归使用受控 committer。
