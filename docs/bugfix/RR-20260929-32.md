# RR-20260929-32：保留首次持久化购买奖励

**已修复、声明场景验证。**[原问题](../bug/REVIEW-2026-09-29-services-08.md#rr-20260929-32稳定-orderid-不能使可变-grant-内容幂等)。基线 bcebb805；仅改生成 demo 的 producer 模板与正式生成测试，不改 Platform 公共 RPC、订单 JSON、grant JSON/key、Nest/DAO。

`grantDeliverer.Deliver` 先 HGet：已有字段通过 Decode 与 OrderID/PlayerID/ProductID/PaidAtUnix 身份核对后恢复成功，不重新查当前 catalog。只有 ErrNil 才查商品并编码；单键 Lua 原子 HGET→已有则返回，否则 HSET，始终返回 durable winner 的字节，再检查实际返回的身份。跨进程插入可在预读后胜出，仍保留它的 ItemID/Count。

读取错误、Eval 写后回复丢失、非法回复或已有坏/不匹配内容，均返回错误且不带 ErrDeliveryNotApplied；未知结果不能解释成未发货。未绑定、缺商品等确定未执行本次写入的拒绝保持原分类。不清理坏证据，不替调用方决定退款或二次发货。首次字段已经存在时可恢复已下架商品；首次写前商品不存在仍拒绝。

修前独立三阶段消费者：Count10 写后丢回复、同 catalog 重试正常，Count3 新二进制覆盖为3（失败）。修后同业务断言 3/3 通过，catalog 升级仍读到10。故障钩子由 HSet 改为真实 Eval 已执行后返回 DeadlineExceeded，原历史源码/失败保留；未触发钩子的超时不算证明。

正式[生成测试模板](../../demo/internal/service/platform/purchase_delivery_test.go.tmpl)已接入 demoScaffoldSteps 并由 embed/步骤一致性门禁覆盖。在实际新生成消费者上执行 standalone/Cluster 两种后端共 26 叶子/29 事件、race、0 skip/fail：写后失联与重建、旧 goods/curr catalog 不同、下架恢复、预读/插入交错、16 并发重试、读取未知、未存在缺商品，以及四类身份不匹配/空/损坏字段保护。实际 consumer 另执行 handler/game 回归，验证永久 ledger 的现有行为。

**升级边界**：collaborators.go 是 write-once 业务文件，普通 project sync/upgrade 不覆盖已有项目；已有项目须将本补丁合并进自有 producer 并补本测试。新模板不等于存量服务已升级。混合旧 producer 仍能无条件 HSet，需升级所有投递 owner；已经被覆盖的旧奖励需凭原商品版本/持久资产回执人工对账，不能自动猜回10。

consumer 删除 outbox 后，迟到 producer 仍可再次生成字段；现有永久 ClaimPurchase ledger 拦截重复入账。修复不实现 fulfilled、不允许按时间删 ledger，不保证“支付时立即快照商品”这一不同契约。归档设计见[学习文档](../review/IMPLEMENTATION-SERVICE-FINAL-SPECIALTIES.md)，真实资金/资产与 HA 未验证。更多命令和证据见[第七批](SERVICE-BUGFIX-2026-09-29-07.md)。
