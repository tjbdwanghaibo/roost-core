# RR-20261007-03：glsvet 漏查方法 handler 的异步执行

[问题与修前证据](../bug/RR-20261007-03.md)；对应 F02-3。

## 根因与修法

`cmd/glsvet/main.go:386`：handler 枚举与 isNestHandler 都排除了带接收者的声明；闭包捕获集合也未计入 receiver。简单把方法放入名字 map 又会产生同名覆盖。

逐声明枚举 handler；保留包级函数表只用于同文件直接 helper；递归访问集合按 AST 声明身份区分，接收者计入闭包捕获集合。

选择在原入口修正既有契约，不新增包、运行时 worker 或旁路机制。

## 兼容与边界

静态检查现在会拒绝过去漏报的方法 handler。没有新增运行时机制或改写业务 handler。

## 验证

- 修前：`GOWORK=off go test ./cmd/glsvet -run TestMethodHandlerConcurrencyChecks -count=1` 确实失败，原文见问题记录。
- 修后：`GOWORK=off go test ./app ./cmd/glsvet -race -count=3` 通过（app 38.808s，glsvet 13.191s）。
- 覆盖指针/值接收者、同名 helper、不同类型同名方法、receiver 捕获；合法显式 worker 参数与普通非 handler 方法保持通过。仍是同文件直接函数调用分析，不承诺跨文件/动态方法调用全覆盖。
- `GOWORK=off go build ./...`、`GOWORK=off go vet ./...`、`GOWORK=off go test -count=1 ./...` 均通过：130 个包通过，包含根包 19.156s；三大模块 glsvet 退出码 0。
- 未执行：生产部署、长稳、远端故障注入。本次没有改变持久化、网络或生成模板。
