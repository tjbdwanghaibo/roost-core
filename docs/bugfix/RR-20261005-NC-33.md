# RR-20261005-NC-33：写缓存前绑定副本 payload 身份

[问题](../bug/RR-20261005-NC-33.md)，基线 b2232db5；已修复、声明场景已验证，未发版。

## 决策与实现

[cache/mirror.go](../../cache/mirror.go) L105 起在解码后、Store.Set 前比较配置的 KeyOf/VersionOf 与 Envelope。null 身份 payload 在调用提取器之前明确拒绝，避免 nil 指针在新的校验位置 panic。没有吞掉 Store 错误或改变 Set 的 stale 策略。

保留提取器可选性：没有 KeyOf 的接收配置仍不凭空推导泛型 K/V 身份，没有 VersionOf 的接入仍无该字段校验。要声明版本一致性，发送端和接收端都必须配置相同提取规则。未采用在通用 Replicator 中反射业务字段，也未扩展 Store API 来伪造版本化 Delete。

## 兼容与验证

合法 wire/API 格式不变；以前被接受的身份不一致更新现在返回错误且不调用 Set。携带身份的 JSON null 也明确拒绝。提取器应是对解码值的纯函数，业务字段完整性仍由 Store 的 ValidateValue 管理。不要把检查成功视为发布者认证。

[正式回归](../../cache/replica_payload_identity_promises_test.go) 两项旧行为红→绿，均检查键7/8保持 version2/before，并验证拒绝之后合法 version3 能写入。另两项控制覆盖无 VersionOf 发布/删除和指针 null 拒绝后合法恢复。修前失败：`refused message changed key 8: {ID:8 Version:3 Data:bad}`、`payload identity mismatch returned success`。

[执行命令与结果](evidence/noncore-bugfix-20261005-13/README.md)包含最终受影响包 race、根包、全仓 build、vet/glsvet。无新 I/O、锁或缓存；增加提取器调用与常数次比较，未做延迟 benchmark。Delete 仍调用普通 Store.Delete，不能宣称防止迟到消息复活；已有墓碑/权威加载方案另行实施。
