# NC-116 修复：Applier 被拒绝的包不改变 epoch 状态

[问题](../bug/RR-20261005-NC-116.md) · [本轮](../review/REVIEW-2026-10-05-n09-batch2.md)。已修复、声明场景验证，未发版。

## 根因与决策

`admit` 在 epoch 判定处直接置 `pendingEpoch`（`skill/skillsync/applier.go:190, 195`），随后的 full 包 `BaseSequence` 检查拒绝时不复位。改为先记 `switchesEpoch`，全部准入检查通过、占用 inflight 时才置 `pendingEpoch`。未采用“在每个拒绝分支补一句复位”：以后新增检查仍会漏，状态只在准入成功处改一次最不易出错。

## 文件与行为

`skill/skillsync/applier.go` 的 `admit`。准入成功的路径行为不变；被拒绝的包不再留下 pendingEpoch。

## 回归

`GOWORK=off go test ./skill/skillsync -run TestRejectedFullPacketDoesNotWedgeTheApplier -count=1`：修前 FAIL（原文见问题记录），修后 ok。覆盖第一包与 epoch 切换两种情形。

## 未验证

没有接真实传输；其他拒绝分支（schema、observer、gap、epoch mismatch）本来不置 pendingEpoch，由既有 `applier_*_promises_test.go` 覆盖。
