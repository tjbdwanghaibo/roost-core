# RR-20261006-24 修复：nats 驱动 Close 之后的订阅、JetStream 与 RPC CallAsync 同样返回 fnats.ErrClosed

问题：[RR-20261006-24](../bug/RR-20261006-24.md)。基线 main `37338490`，未发版。来源：[真实进程演练](REAL-PROCESS-DRILLS-2026-10-06.md)第 4 项。

## 根因

[RR-20261006-10](RR-20261006-10.md) 把 `Publish` 的“连接已关闭 / 正在排空”映射到 `fnats.ErrClosed`（`Request` / `RPC.Call` 经 `wrapError` 早已映射），但 `Subscribe` / `QueueSubscribe`（`nats/driver/client.go:119`、`:139`）、`JetStreamClient` 的三个方法（`jetstream.go:37`、`:50`、`:71`、`:80`）与 `RPCClient.CallAsync` 的订阅收件箱 / 发布失败（`rpc.go:206`、`:235`）原样返回 nats.go 的错误；RPC 停止后发起的 `CallAsync` 只回 `fnats.ErrCancelled`（`:190`、`:217`）。

## 改动

| 位置 | 改动 |
| --- | --- |
| `nats/driver/client.go` | 新增 `closedError`：nats.go 的 `ErrConnectionClosed` / `ErrConnectionDraining` 包成 `connectionClosedError`，`errors.Is` 同时命中 `fnats.ErrClosed` 与原错误，**文本取原错误**（两者同为 `nats: connection closed`，用 `%w: %w` 拼接会重复一遍；`Publish` 原来就是 `…: nats: connection closed: nats: connection closed`，一并改用它）。`Subscribe` / `QueueSubscribe` 的错误经它返回 |
| `nats/driver/jetstream.go` | `EnsureStream` / `Publish` / `Subscribe`（建 consumer 与 Consume 两处）的错误经 `closedError` |
| `nats/driver/rpc.go` | RPC 停止之后发起的 `CallAsync`（入口检查与“停止先于登记”两处）回 `errRPCStopped`：同时 `errors.Is` 到 `fnats.ErrCancelled`（旧结果）与 `fnats.ErrClosed`；订阅收件箱与发布失败的错误经 `closedError`。停止时已登记的在途调用照旧只收到 `ErrCancelled` |

WIP 草稿（`976086d6`）已有 client / jetstream 的映射与单元用例，注释误写为 RR-20261006-17；本次补红文本、改编号、扩到 RPC CallAsync、去掉重复文本。

未采用：在 `Client` 里加自己的 closed 标记、所有方法先查它——nats.go 已经给出准确的“已关闭 / 排空中”错误，映射即可；`RPC.Call` 经 `wrapError` 已对，不动。

## 兼容

- 这些调用关闭之后的错误现在多了 `fnats.ErrClosed`，原来的 nats.go 错误仍可 `errors.Is`；文本不变（`Subscribe` 等仍是 `nats: connection closed`）。
- `Publish` 关闭后的错误文本由 `nats: publish to X: nats: connection closed: nats: connection closed` 变成 `nats: publish to X: nats: connection closed`。
- RPC 停止后发起的 `CallAsync`：错误由 `nats: request cancelled` 变成 `nats: request cancelled: nats: connection closed`，仍 `errors.Is(fnats.ErrCancelled)`；仓内消费方（bus 的 `CallAsync` 透传、测试）都用 `errors.Is`，没有 `==` 比较。

## 验证（`GOWORK=off`）

- 修前红见问题记录（单元 + 真实 NATS）；修后 `nats/driver` 全包、`kit/nats` `TestRealNatsModCloseContract`（真实 NATS：IClient / IRpc / IJetStream / IBus 共 11 个调用全部 `errors.Is(fnats.ErrClosed)`、0～2ms 返回）通过。
- `go test -race -count=3 ./nats/driver/ ./kit/nats/`；`-tags integration -race -count=3` 真实依赖；相邻 `./nats/... ./bus/... ./kit/nats/...`；根包；`go build ./... && go vet ./...`——见[演练记录的验证节](REAL-PROCESS-DRILLS-2026-10-06.md#验证goworkoff)。
- 组合复核：新错误追到调用方——bus 的 `Send` / `Call` / `CallAsync` 透传驱动错误（真实 NATS 上 `IBus.Send` / `IBus.Call` 关闭后 `errors.Is(fnats.ErrClosed)`）；驱动之外没有按 `fnats.ErrClosed` 分支的非测试代码（`rg 'fnats.ErrClosed'` 核对，含模板），按 nats.go 原错误判断的调用方仍能 `errors.Is` 到原错误，所以不会有调用方因此改走别的分支。
