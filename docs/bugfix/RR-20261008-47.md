# RR-20261008-47：唯一协调者内部有界并行

[问题](../bug/RR-20261008-47.md)。RecoverOutbox仍是唯一入口，扫描/重试/停止屏障不变；每页最多256项，按事务涉及的全部Entity及事务ID建立前序依赖。协调者只派发就绪事务，等待前序不占worker；跨页先排空，防止越过上一页的同Entity发布。

新增正式配置`remote_entity.outbox_publish_workers`，默认8，0也取8，上限64；核心Config同名Go字段。与Nest慢worker/写额度独立，设1用于串行诊断。事务内部快照仍按既有路径发布，全部成功才写Committed。失败记录仍保留Applied，后继在前序本次尝试结束后可继续尝试，与旧串行循环保持相同失败语义；不跳过或删除坏记录。

取消停止新派发，但已开始的发布必须退出后协调者才返回，避免释放SnapshotClient时仍有worker访问它。不相交事务并行；两个事务仅第二个Entity相同也会串行，不能用首Entity哈希近似。

新增低基数计时：`remote_entity.outbox.scan`、`remote_entity.outbox.snapshots`、`remote_entity.outbox.mark_published`、`remote_entity.outbox.transaction`（histogram），以及`remote_entity.remote.confirm_wait`、`remote_entity.remote.release_latency`。确认等待与发布时长可能重叠，不能把它们简单相加当请求总耗时。保留所有持久/回复/额度释放语义。

独立进度/同Entity顺序、分页、停止与配置定向回归已通过（Remote0.830s、Kit0.866s）。Remote、Entity、Kit等目标race三轮通过；新补worker上限/取消断言及最终资源、全仓结果见本轮收口验收。未重跑压测，不能宣称TPS已恢复到80或更高；原4分钟失败仍保留。无存储或wire格式变更，未发版。
