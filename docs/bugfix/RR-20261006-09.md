# RR-20261006-09 修复：robot Stage 序号只增不回收

问题：[RR-20261006-09](../bug/RR-20261006-09.md)。批次：[第十二轮 kit 批](../feature/DECISIONS-R12-KIT-2026-10-06.md)。基线 `53fd9e9c`，未发版。

## 改动

`robot/runner/runner.go` `runPopulation`：在线目标数 `launched`（缩容减回去）与已发出的最大序号 `lastOrdinal`（只增）分开。扩容时新机器人的序号是 `++lastOrdinal`，不再是 `launched + i + 1`。`IdentityProvider` 的注释写明：一次运行内序号不复用，有过“缩了再扩”的 staged 运行会用到超过 `Count` 的序号（`Count` 加上每次扩回的数量），身份方案要覆盖到。

未采用：缩容时等被停机器人收尾结束再把序号放回池里。要等就得在调度循环里阻塞或另建回收队列，换来的只是序号连续；序号本来就只是身份方案的输入，不需要连续。

## 兼容

行为变化：staged 运行先缩后扩时，新机器人的序号 / PlayerID 不再与停掉的重叠，而是接着往后排。仓内唯一的 `IdentityProvider`（game-demo `cmd/loadtest`：`firstPlayerID + index`）没有上限，不受影响；自定义的、按 `Count` 预分配身份表的提供方要扩大到“`Count` + 扩回数量”。pool / arrival-rate 执行器与没有 Stages 的 looping 不受影响（arrival-rate 本来就只增）。
