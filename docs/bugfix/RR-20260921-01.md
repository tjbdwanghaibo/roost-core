# RR-20260921-01：贡献落进哪个窗口没有回传通路（U-0273）

- 等级：P2
- 位置：`demo/internal/service/game/activity.go.tmpl`、`demo/game/controllers/player/finish_dungeon.go.tmpl`、
  `demo/protocol/def/finish_dungeon.go.tmpl`、`demo/cmd/loadtest/main.go.tmpl`
- 审查记录：[REVIEW-2026-09-21](../bug/REVIEW-2026-09-21.md) · 复现附录 [REPRO-2026-09-21](../bug/REPRO-2026-09-21.md)
- 缺陷类：C5（静默吞错：写侧知道的事实被丢掉，读侧只能猜）

## 问题

`framework-compat` 的 demo 格偶发红在
`window race-1789906500 counted score=0 progress=0 ... want 1/1`。
`1789906500` 是 12:15:00 UTC 且被 `WindowSeconds = 300` 整除——机器人在上一个窗口清的本、在新窗口读的榜。

## 根因

不是"窗口会滚"（那是对的，`ApplyProgress` 对已完成窗口明确拒绝）。是**信息在一条没人接的返回值上断掉**：

1. `Contribute` 现算 `gameactivity.ID(time.Now().Unix())`，拿它写 coordinator 与 board，然后只返回
   `Participant`——而 `Participant` 里没有窗口 id；
2. 端点连那个返回值也丢掉：`_, err := runner.Contribute(...)`，`FinishDungeonResponse` 只有
   `State` / `Outcome`；
3. `Standing` 再各自算一次窗口。

于是机器人只能对"读的时候恰好是哪个窗口"下精确断言。跨过边界必然红，而错误信息把原因说成计数不对——
**下一次真的计数错会被当成"又是那个窗口问题"**，这才是这条的代价。

## 方案选择

| 方案 | 取舍 | 结论 |
| --- | --- | --- |
| `Standing` 接受窗口 id 参数 | 协议定义里写着反对：`ActivityStandingRequest` 无字段是因为"当前是哪个窗口由服务端决定，客户端指定会问到一个服务端没在跑的窗口" | 未采用（与现有设计冲突） |
| 只改机器人（贴近边界时跳过断言） | 最省事，但让门禁绕开问题而不是覆盖它 | 未采用 |
| **贡献回传它落进的窗口** | 与 `Standing` 已有的"返回窗口 id"形状一致，客户端第一次有了对齐两端的依据 | **采用** |

## 改动

- `ActivityRunner` 加 `now func() time.Time` 时钟缝（`clock()` 带默认值，零值 runner 不 panic），
  `Contribute` 与 `Standing` 都从它取窗口——**没有这条缝，边界就只能靠等待真实时钟，无法测**。
- `Contribute` 返回 `(string, Participant, error)`；失败时也返回窗口 id（日志里"哪个窗口拒绝了它"值钱）。
- `FinishDungeonResponse` 加 `ActivityID`（`pb:"7"`），端点成功时填上。
- 机器人：`finish_dungeon` 记下 `contributed_activity_id`（缺失即失败）；`activity_standing` 按窗口分支——
  同窗口维持精确 1/1 的强断言，换了窗口则断言**新窗口不得继承那一点**（score 必须是 0）。
  换句话说，原来抖动的那条路径现在也在检查一个真实不变量。

## 证明

新测试 `demo/internal/service/game/activity_test.go`（登记进 `codegen/internal/roost/demo.go` 的文件清单）：
`TestAContributionSaysWhichWindowTookIt`——把时钟停在窗口末尾前一秒贡献，同窗口查得到，
跨过边界后是另一个窗口且分数为 0，而那一点仍在原窗口里。

变异验证两处，各自独立红：

```text
# Standing 改回 time.Now()
--- FAIL: the window did not roll across the boundary: still "race-1789962000"
# Contribute 不返回窗口 id
--- FAIL: contribution reported window "", want "race-1789962000"
```

生成工程 `go test ./...` 全绿；core 仓 `go vet` + `glsvet` + 全量测试全绿。

## 未做 / 边界

- **贡献仍然是 best effort**：窗口未开时 `ApplyProgress` 返回 `ErrMissing`，端点只记一条日志就继续
  （`finish_dungeon.go.tmpl:126-129` 的注释明说"一个窗口少了一点不是失败的副本"）。这是**有意**的，
  本单元没有改它——只是现在日志里带上了是哪个窗口拒绝的。
- **没有端到端实跑**：机器人分支逻辑没有在真实跨边界的运行里验证过（那要等 CI 恰好跨过整 300 秒）。
  确定性覆盖在上面那条单测里。
- `ActivityRunner` 的其他 `time.Now()`（sweep、世界 tick）没有改用这条缝——它们与窗口 id 无关。
