# RR-20260930-04 · Entity 退役生成文件

原问题：[Codegen 第二轮 RR-04](../bug/REVIEW-2026-09-30-codegen-02.md)。基线 Core `5fedc6526d49378246f76fa6ea9cf9e582435eee`。**原触发已修复、声明场景通过；未发布。**

`codegen/internal/entity/main.go` 原来只扫描当前含 `//roost:entity` 的目录，删除最后一个标记后连目录都不再进入。现在扫描范围内的旧 wire 或 companion guard test 如带 `tool/entity` 生成头，也会使其目录进入对账；解析并生成当前实体后，只移除不再属于当前实体集合的 `_gen_wire.go` 和 `_gen_wire_test.go`。同包第一个实体退休时，剩余实体会接管唯一的 `RegisterEntity`。显式 `-output` 在该目录无实体时只退役该指定文件及 guard test。手写同名文件和符号链接不会被删除。

先加入的 `TestRunRetiresEntityWireAfterLastMarkerRemoved` 在修前失败，旧 wire 和 guard test 均留存；修后该用例、同包首实体退休及手写文件保留通过。`TestStagedProjectCommitSeesEntityRetirement` 用真实 NewProject/Add/Generate 工程，验证暂存树删除进入 `planStagedProjectCommit` 并提交到项目目录。定向 `-race` 通过；全 Codegen 回归见[本轮证据](../review/evidence/codegen-review-20260930-03/README.md)。

删除生成 wire 会删除相应工厂/注册入口；保留对它的手写调用须由业务方在同一变更中清理。直接 CLI 跨目录写入不是原子事务；`roost` 暂存模式维持原有逐文件提交与回滚契约。生成头被修改或使用非默认旧文件名时保守保留，需人工对账。正式外部业务工程的 `go mod tidy`/消费编译本机未完成：本机默认模块缓存写锁拒绝；暂存提交链用本地测试独立验证，不把它写成端到端业务编译通过。
