# RR-20260916-07：首个 manager 启动期间 Register 被接纳，新对象永久未启动

**仓库 / 位置**：roost-core `manager/engine.go`（`Engine.Register` 的判定、`Start` 取 pending 快照处）。
**修复单元**：U-0220（C2）。**定位文档**：TROUBLESHOOTING T-114。

## 问题

Start 复制 `managers` 为 pending 后进入第一个管理器的慢 Start，此时 `started` 仍是 nil。Register 用 `started != nil`
判断"是否已开始"，于是返回 nil 并把新管理器加进 `managers`。pending 已固定，它不会启动；Stop 只清 `started`，它也不会停止；
`Manager(name)` 却能看见它——业务拿到一个未初始化的对象。

## 根因

C2：用"是否已有一个成功启动者"代替生命周期状态。`ErrRegisterAfterStart` 的契约是"Start 之后拒绝"，实现的判据却晚了一整个管理器的 Start。

## 方案选择

- 支持动态加入（补启动协议）：要定义接纳时机、失败回滚、与 Stop 的交接，是另一套设计。不采用。
- **采用**：在 Start 取 pending 的同一临界区置 `starting=true`（永不清除：集合从此关闭）；Register 按 `starting || started != nil` 拒绝。
  启动校验失败 / 启动失败后也不重新开放注册——契约保持"一次 Start 即关闭"。

## 改动

- `manager/engine.go`：`Engine.starting` 字段、Start 置位、Register 判定。
- 测试：`manager/register_during_start_promises_test.go`。

## 证明

- 修前：`Register during the first Start = <nil> (late starts=0 stops=0, managers=2); want ErrRegisterAfterStart`。
- 修后：`manager` `-race` 绿。
