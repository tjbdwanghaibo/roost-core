# RR-20261006-45 修复：MongoStore.ClaimDue 遇到一条坏记录整批丢弃、List 整次失败

问题：[RR-20261006-45](../bug/RR-20261006-45.md)（F06-S3）。基线 `0b223b4c`（main，v1.23.0 之后；WIP `wip/sagafix` `bcdb4bd4` rebase 到此）。codebase-memory 共享 generation 停在 09-30（比基线旧），定位与结论按 worktree 当前源码读取。
同一批（sagafix2）修 RR-20261006-42～47，一笔提交 `63bc1d66`。

## 根因

`saga/mongo_store.go` `ClaimDue`（基线 `:236`）与 `List`（基线 `:144-151`）把单条记录的校验失败当作整次调用失败。

## 决策

- **单条隔离**：`ClaimDue` 与 `List` 遇到校验不过的记录只跳过那一条，`reportCorruptRecord` 计 `saga.store.corrupt_record_total{op}`（`claim` / `list`），记点名 `id` 的 ERROR；其余记录照常返回。`Store` 接口注释写明这一约定。
- **不改写坏记录、不 fence 到 ManualRequired**：记录已读不出可信的状态，改写只会覆盖运维要看的现场（“不许自动删 / 改坏记录、生产数据”）。它保留刚领取的租约，每个 `LeaseDuration` 被领取并告警一次，直到运维修好文档。登记表建议的“单条进 ManualRequired”因此没有采用。
- 领取本身的 Mongo 错误（`FindOneAndUpdate` 失败）仍返回错误：那是暂时故障，不是坏记录。
