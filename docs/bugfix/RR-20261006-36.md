# RR-20261006-36 修复：订阅方停止等传输层排空

问题：[RR-20261006-36](../bug/RR-20261006-36.md)。随 A3 ② 一起实施（[方案](../feature/A3-2-SYNCBUS-DRAINING-UNSUBSCRIBE-2026-10-07.md)）。

## 决策

不在三个订阅方各补一层准入门（那正是同一不变量被打破 11 次的写法），而是让传输层的退订本身排空：`ISyncBus.Subscribe` 返回 `*syncbus.Subscription`，`Unsubscribe(ctx)` 返回 nil 即没有在途回调、也不会再有新回调。订阅方的停止只等它。

## 文件与行为

| 文件 | 改动 |
| --- | --- |
| `sync/syncbus/patch_syncer.go` | `Stop()` → `Stop(ctx) error`：对还没确认排空的订阅逐个 `Unsubscribe(ctx)`，超时返回 ctx 错误、保留，重试再等；返回 nil 后可再 `Start`。`Apply` 收到投递 ctx（原来是 `context.Background()`，同为不取消的 ctx） |
| `cache/mirror.go` | `ReplicaSyncer.Stop()` → `Stop(ctx) error`，转 `Replicator.StopWithContext` |
| `syncstream/publisher.go` | `Subscribe*` 返回总线的 `*syncbus.Subscription`；重组表随排空后释放的 handler 引用一起回收，不再手工清空 |

## 兼容

签名变化（线上未部署，维护者决定不留兼容期）：`PatchSyncer.Stop(ctx) error`、`ReplicaSyncer.Stop(ctx) error`、`syncstream.Subscribe*` 返回 `*syncbus.Subscription`。行为收紧：停止在回调返回前不报告完成，回调不配合时停止如实超时。

## 回归

- `sync/syncbus/patch_syncer_stop_promises_test.go`、`cache/replica_stop_promises_test.go`：屏障卡住回调 → 短预算停止返回 `DeadlineExceeded` → 放行后重试 nil 且回调已返回 → 迟到投递返回 `ErrUnsubscribed` 不再执行。修前对应用例红（文本见问题记录），修后 `GOWORK=off go test -race -count=3 -run StopWaits ./sync/syncbus ./cache` 通过。
- syncstream 的排空由 `Subscription` 自身的用例覆盖（`sync/syncbus/subscription_promises_test.go`）。

## 未验证 / 风险

无生产调用方，未在生成工程里验证这三处；传输层排空在真实 NATS 上的验证见方案 §7。
