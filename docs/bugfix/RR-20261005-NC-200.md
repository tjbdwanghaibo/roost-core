# RR-20261005-NC-200 修复：gapmap.sh 在跟踪文件不干净时拒绝启动

日期 2026-10-05。基线 `8597046c`（审查提交 `345488e4`）。状态：已修复、声明场景验证，未发版。问题：[RR-20261005-NC-200](../bug/RR-20261005-NC-200.md)。

## 决策

`scripts/gapmap.sh` 开头检查 `git status --short --untracked-files=no`，非空即列出文件、以 2 退出，提示先提交或 stash。收尾的 `git checkout -- .` 保留：它在“开始时干净”这一前提下只会恢复取样器留下的副作用。

未采用：记录运行前的修改清单、收尾只恢复清单之外的文件——同一文件既有使用者修改又被取样器留下副作用时无法区分，仍会丢数据或留下被中和的守卫。`git stash` 自动暂存再恢复也被放弃：中断时把使用者的工作留在 stash 里，比明确拒绝更难发现。

## 行为与兼容

CI（nightly-gapmap，干净 checkout）不变；本地带未提交跟踪修改运行时改为拒绝（exit 2）。未跟踪文件不受影响。

- 红：[`gapmap_red.sh`](../review/evidence/noncore-review-20261005-n15/gapmap_red.sh) 修前 `RESULT: uncommitted work LOST`（[输出](../review/evidence/noncore-review-20261005-n15/nc200-red.txt)）。
- 绿：同一脚本 `gapmap exit=2`、`RESULT: uncommitted work kept`（[输出](evidence/noncore-bugfix-20261005-n15/nc200-green.txt)）。
- 控制：干净树正常跑完、exit 0（[`gapmap_control.sh`](evidence/noncore-bugfix-20261005-n15/gapmap_control.sh) · [输出](evidence/noncore-bugfix-20261005-n15/nc200-control.txt)）。
