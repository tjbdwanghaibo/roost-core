# RR-20261004-03 修复：RefHMap 一条记录的所有 hash 同生共死——Patch 续期整条记录，Get 不再拼出部分记录

问题：[RR-20261004-03](../bug/RR-20261004-03.md)（来源 [复审第三组 §3 D3](../review/REVIEW-2026-10-04-nc-audit-3.md)；扩大它的是 B 线 [NC-18](RR-20261004-NC-18.md)）。
日期 2026-10-04；实施基线 main `91ab67f7`（含 v1.19.0 `74e1ba39`）。状态：已修复，本地验证通过，已提交，未推送、未发版。

## 根因（基线行号）

- `cache/ref_hmap.go:87-90`（`ce90e90d` 引入的 NC-18 Patch 脚本）：`PEXPIRE` 只遍历 `KEYS`，而 `KEYS` 只有根到叶的路径。兄弟 hash 保留上一次 Set 的 TTL，先于根过期。
- `cache/ref_hmap.go:632-663` `decodeRefHMapNode`：父 hash 里有子 hash 的引用、子 hash 却不存在时直接留零值；`Get` 只看根 hash 是否为空，于是报 `ok=true` 返回从未写过的部分记录（写入的 `Other.X=42` 读回 0）。
- 附带：`:80-85` 把注册表 `__keys` 与路径键合并。没有注册表的旧数据被 Patch 后注册表只剩路径键，`registeredKeys` 不再回退到布局全集，之后 Delete 漏删兄弟 hash（复审 §6 列为未验证分支，本轮真实 Redis 实测确认）。

修前（NC-18 之前）旧 Patch 只续期叶子 hash，根先过期时整条 miss；根标量 Patch（`name`）已经会出部分记录。NC-18 让路径上所有祖先一起续期，把它扩大到所有嵌套路径。

## 决策

两处都改：续期是根治，Get 侧是兜底。

1. **Patch 续期整条记录的全部布局 hash。** `Patch` 把 `KEYS` 设为“根到叶路径 ++ 布局里其余的 hash”（`plan.keys()` 去重），`ARGV[4]` 传路径长度，`ARGV[5..]` 是各层引用字段名。脚本只对路径键做 `TYPE` 检查和 `HSET`（行为同 NC-18），对全部声明键 `PEXPIRE`；注册表并入全部声明键。
   - 为什么用布局全集而不是“注册表 ∪ 路径”：Set 写的注册表本来就是 `plan.keys()`（`withRegistry`），二者对当前布局相同；Get 只读布局里的 hash。差别只在注册表里残留的、旧布局（字段改名 / 删除后）留下的键：Get 不读它们，续期只会延长垃圾的寿命，而且它们不在 `KEYS` 里，Lua 访问它们就是“未声明键访问”。布局全集全部声明在 `KEYS` 里，脚本不访问任何未声明键。
   - 注册表并入布局全集后，Patch 之后的注册表 ⊇ 布局键，与 Set 的注册表一致，修掉了旧数据 Patch 后 Delete 漏删兄弟的分支。
2. **Get：被引用、必然非空的子 hash 缺失 → 整条记录 miss。** layout 构建时给每层算 `alwaysWritten`：该层有任一非指针字段（非指针标量一定编码；非指针 struct 字段一定写引用），Set 写它时 hash 必然非空。解码时父 hash 引用了这种子 hash 而它不存在，返回包内哨兵 `errRefHMapPartialRecord`，`Get` 转成 `(zero, false, nil)`。
   - 为什么还要兜底：修复前写入、Patch 过的数据里兄弟可能已经过期或即将过期，续期救不回来；`loadHashes` 用 pipeline 逐个 `HGETALL`，同一过期时刻也可能落在两条命令之间，读到“根在、子刚过期”。这两种情况都是“记录已过期”，报 miss 让 ReadThrough / DAO 按缺失重载最自然。
   - 为什么报 miss 而不是损坏错误：这是 TTL 的正常后果，不是持久损坏；下一次 Set 会整条重写。报错会让读在根 TTL 到期前一直失败。
   - 为什么限定 `alwaysWritten`：字段全是指针的层（例如 `Opt *struct{ Note *string }`，值为 `&{}`）全 nil 时，Set 写父引用但不写它的 hash——“被引用但不存在”是合法状态，无条件报 miss 会让这种记录永远读不到（回归里的控制用例钉住）。

### 未采用的方案

1. **只做 Get 兜底，不改续期**：记录在兄弟过期后变成 miss，不再返回错值，但 Patch 过的记录会在 Set 的 TTL 到期时整条丢失，Patch 的续期名存实亡；对 DAO 等于每次 Patch 后最长 TTL 内必然缓存击穿一次。
2. **只做续期，不做兜底**：修复前写入的数据、pipeline 跨过期时刻的读仍会返回 `ok=true` 的部分记录。
3. **脚本里按注册表内容续期（不声明这些键）**：同槽时 Cluster 下实际能跑，但违背“脚本访问的键都要在 KEYS 里声明”的 Redis 约定；注册表是数据，内容理论上可以不在本记录的 hash tag 下。布局全集已经覆盖 Get 读的全部 hash，不需要它。
4. **Go 侧先 `HGET __keys` 再把注册表键放进 KEYS**：多一次往返，读与 Eval 之间注册表可能变化，而且仍会续期 Get 不读的旧布局键。
5. **Set 给每个子 hash 写一个哨兵字段，让“空子 hash”也落盘**：改变存储格式，旧数据和旧版本进程不认识；兜底只需按布局判断。
6. **Get 报损坏错误（不是 miss）**：见上。

## Cluster 安全性

- 键形如 `<prefix>:{<name>:<key>}<suffix>`（`layout`：`prefix + ":{" + name + ":"`，`plan`：`+ keyString + "}"`）。一条记录的所有 hash 共享同一个 `base`；`base` 内一定有 `{`，并以 `}` 结尾，所以每个键的“第一个 `{` 到其后第一个 `}`”都落在 `base` 内，hash tag 只由 `base` 决定 → 同一条记录的全部布局 hash 同槽。
- 修后 Patch 脚本访问的键全部在 `KEYS` 里声明（注册表只作为字符串读写，不再按其内容访问键），与 Set 的写脚本相同。唯一例外是 Prefix 自身含空 tag `{}`（整个键参与哈希），那时 Set 的多键写脚本早已 CROSSSLOT，不是本修复引入的。
- 实测：临时起本机 3 主 Redis Cluster（Redis 8.10.1，127.0.0.1:27801-27803，scratchpad 目录，跑完 `shutdown nosave`），探针（未入库）对 64 条分布在不同槽 / 节点上的记录执行 Set → 缩短兄弟 TTL → Patch `meta.label` / `name` → 兄弟 TTL 回到 1h、Get 完整；去掉 `__keys` 后 Patch + Delete 不留键；D3 原样（600ms / 400ms / 400ms）读回 `Other.X=42`。`PASS (0.98s)`。仓库里的 Cluster 套件以 `ROOST_REVIEW_CLUSTER` + `-tags integration` 准入、由 `redis-cluster-suites.sh` 运行，探针没有入库，以免新增一个无人运行的 Cluster 格。

## 兼容性

- **存储格式不变**：键、字段、引用值与注册表格式都不变。Patch 之后注册表包含全部布局键（与 Set 写的一致），以前只含路径键。
- **已有数据**：修复前写入、兄弟 hash 已经过期而根还在的记录，修前读出 `ok=true` 的部分值，修后报 miss（缺失的层有非指针字段时）；ReadThrough / 生成的 ref-hmap DAO 会按缺失重载并整条 Set。缺失的层字段全是指针时无法与“合法的空子结构”区分，仍按旧行为读出零值——但修后写入 / Patch 的记录全部 hash 同一 TTL，不再单独过期。
- **Patch 成本**：仍是一次 EVAL；`KEYS` 从路径深度增加到布局 hash 数，脚本多做（布局 hash 数 − 路径长度）次 `PEXPIRE`，注册表合并的字符串查找同步增加。布局 hash 数由 V 的嵌套 struct 个数决定（`MaxDepth` 默认 8），没有跑基准。
- **滚动升级**：EVAL 每次发脚本全文，两版脚本互不混用。旧版本进程的 Patch 仍只续期路径，旧版本的 Get 仍会返回部分记录；新版本的 Get 兜底对旧进程写出的数据同样生效。Patch 脚本的 `ARGV` 布局是包内实现细节，没有外部调用方。
- `Set` 的 Stale 预读走 `Get`：部分记录现在视为 miss，跳过 Stale 比较、整条重写。
- 公开 API、配置、生成代码形状不变。

## 未验证项与风险

- 字段全是指针的层被单独删除 / 过期时，Get 仍读出零值（无法与合法空子结构区分）；修后写入的数据不会单独过期，只剩外部删除或修复前数据。
- Get 仍不是跨 hash 的原子快照（NC-18 已声明）：并发 Set 与 Get 交错仍可能读到新旧混合，本修复不涉及。
- 注册表里旧布局遗留的键不再被 Patch 续期，按上一次 Set 的 TTL 自然过期；Delete 仍会按注册表删除它们。
- 没有测 Patch 的延迟 / 分配变化；生成的 game-demo ref-hmap DAO 端到端消费（`scripts/test-dataengine-generated.sh` 等）没有跑，只跑了 `codegen/...` 单测。
- 代码图谱 generation 为 09-30（`cache/ref_hmap.go` `metadata_changed`），本轮结论以当前源码为准。
