# RR-20260923-05 修复：Stop/Close 等待 Flush 忽略 deadline，并允许旧循环未退出就重启

[问题与修前证据](../bug/RR-20260923-05.md) · [收尾验收](../feature/SYNC-COMPLETION-2026-09-23.md)

状态：已修复并验证，未发布。

## 修复

用可取消的 flushGate 串行化；run/stop 状态区分停止请求和真正退出，Start 在 stopping 期间返回 ErrManagerStopping。周期 Flush 接收可取消 context，取消触发整轮重试而非踢会话。Close 超时后保留 closing 供重试清理。

改动位于 `sync/entitysync/` 下的 manager.go、flush.go、errors.go。不改变实体帧线格式，不新增包。

## 验证

`go test ./sync/entitysync -run 'TestStopAndCloseRespectDeadlineWhileAnotherFlushIsInFlight|TestStopCancelsPushAndPreventsRestartUntilItReturns' -count=1` 定向回归已通过。整块 race、调用方与构建结果统一记录在[收尾验收](../feature/SYNC-COMPLETION-2026-09-23.md#验收记录)，避免将定向通过等同全场景验证。

## 契约与限制

Transport 须响应 context；忽略取消的外部调用无法被 Go 强制终止。Stop 的等待可以超时，旧循环未退出前保持 stopping。真实游戏客户端、生产集群和多进程故障注入未在本轮运行。
