## 复核后的补修（2026-09-26）

针对[复核残留](../bug/RR-20260926-07.md)：同类漏计在 nestwal Committer。基线 main `87d9499`（含本轮前两笔本地提交）。

根因：`nestwal/committer.go:463`（基线行号）在批次最后一条记录应用完之后、同一个 consume 回调里返回 `errReplayBatchComplete`；
`WAL.Replay` 只对返回 nil 的 consume 计数，于是每批最后一条已应用却不计入 `Stats.Replayed`。

修法：照 projector 的修法——批次已满的判断挪到 consume 开头，在下一条 lookahead 记录上返回截止哨兵；lookahead 不应用、不确认，下一轮重新读取；
已应用的最后一条返回 nil，如实计数。ack 边界（`lastFence` 为最后一条已应用记录）、held 停止与失败语义不变。代价：满批时多解码一条 lookahead 记录（与 projector 相同）。

回归：`nestwal/replay_count_test.go` 的 TestCommitterReplayCountsBatchBoundaryRecords——`ReplayBatchRecords=2`、真实文件 WAL（1KiB 段，20 条跨多段），
停掉后台循环后外部 Flush：`Stats.Replayed` 等于 20，且每笔事务恰好应用一次（lookahead 不重复应用）。

```text
修前：GOWORK=off go test -count=1 ./nestwal -run TestCommitterReplayCountsBatchBoundaryRecords -v
    replay_count_test.go:48: WAL Stats.Replayed=10 want 20 (records applied by the committer)
--- FAIL: TestCommitterReplayCountsBatchBoundaryRecords (0.32s)
修后：GOWORK=off go test -race -count=5 ./nestwal -run TestCommitterReplayCounts   # ok
      GOWORK=off go test -race -count=3 ./nestwal                                  # ok
```

兼容性：只影响观测计数；无 API、持久格式或 ack 语义变化。
