# RR-20261006-73 修复：轻量 RPC 按调用方期限计时，超时 / 取消保留 ctx 错误链

问题：[RR-20261006-73](../bug/RR-20261006-73.md)（F09-R2）。基线 `c78d0c34`（main）。codebase-memory 共享 generation 停在 09-30（比基线旧），按 worktree 当前源码。分支 `remfix`（同批 RR-20261006-68～74，F05-1～F05-7、F09-R2、F09-R3）。

## 决策

- `RPCClient.Call`：调用方 ctx 带期限时直接用它计时；没有期限才用 5s 的单次上限（`defaultRPCAttemptTimeout`）。调用方期限到达或取消后不再重试（之前进入下一轮、在退避处把期限到达报成“取消”）。
- 错误链：`requestWithContext` 与重试等待处统一经 `contextRPCError`：期限到达 = `fmt.Errorf("%w: %w", fnats.ErrTimeout, ctx.Err())`，取消 = `fnats.ErrCancelled` + `ctx.Err()`。原有 `errors.Is(err, fnats.ErrTimeout / ErrCancelled)` 的判断不变，新增可 `errors.Is` 到 `context.DeadlineExceeded` / `context.Canceled`。`isRetryable` 改用 `errors.Is`。
- `CallAsync` 没有 ctx，仍是固定 5s（`kit/README.md` 已写明），不在本条范围。

## 文件与行为

| 文件 | 改动 |
| --- | --- |
| `nats/driver/rpc.go` | `Call` 按调用方期限、期限 / 取消后不重试；`contextRPCError`；`isRetryable` 用 `errors.Is` |
| `nats/driver/client.go` | `requestWithContext` 的 ctx 错误保留错误链 |
| `nats/driver/rpc_deadline_real_promises_test.go`（新，integration） | 先红：真实 NATS，6s 处理 + 8s 期限成功；300ms 期限 / 取消的错误链 |
| `nats/driver/guards_promises_test.go` | 更正旧断言：调用方期限已到时期望“超时 + DeadlineExceeded、不等重试”，原来期望 `ErrCancelled`（期限到达被报成取消，正是本条的错误链问题） |

## 兼容性

行为变化：`call_timeout` 大于 5s 现在生效；期限到达的错误由 `ErrCancelled`（重试路径）改为 `ErrTimeout`，两者都带 ctx 原因。缺省 `MaxAttempts = 1` 的路径之前已经报 `ErrTimeout`。
