# RR-20261006-25 修复：停机 hook 超时的错误点名卡住的 hook

问题：[RR-20261006-25](../bug/RR-20261006-25.md)。基线 main `37338490`，未发版。来源：[真实进程演练](REAL-PROCESS-DRILLS-2026-10-06.md)第 3 项。

## 根因

`App.emitLifecycleWithin`（`app/app.go`，NC-231 引入）在 goroutine 里调 `lifecycle.Registry.EmitAll`，到期时只知道阶段；`EmitAll` 不对外报告当前在跑的 hook。

## 改动

| 位置 | 改动 |
| --- | --- |
| `lifecycle/lifecycle.go` | 新增 `Registry.EmitAllWatched(ctx, event, starting func(hook string))`：与 `EmitAll` 相同，每个 hook 开始前用它的名字调 `starting`（同步、在派发 goroutine 里，nil 不调）。`EmitAll` 改为转调它 |
| `app/app.go` | `emitLifecycleWithin` 用 `atomic.Pointer[string]` 记下最后一个开始的 hook，到期错误为 `app: lifecycle <阶段> hook "<名字>" did not return within the shutdown budget: <ctx 错误>`（还没有 hook 开始时保持原文）。顺带把取 lifecycle 注册表的重复代码收成 `lifecycleRegistry`，停机阶段的派发收成 `emitStopLifecycle`，行为不变 |

卡住的 hook 就是最后一个开始、还没返回的那个：`EmitAll` 串行派发，它之后的 hook 都没运行。

未采用：在 App 里自己遍历 hook——要复制 `EmitAll` 的排序、错误合并与 panic 恢复；超时时额外打一行 Warn——`app run failed` 已经带上完整错误，停机路径不再多一处日志。

## 兼容

- 错误文本变化：`hooks did not return` → `hook "<名字>" did not return`；`errors.Is(err, context.DeadlineExceeded)` 不变。匿名登记的 hook 名字是 `anonymous`。
- `lifecycle` 多一个导出方法，`EmitAll` 行为不变。
- T-264 现象列与判别列、USER_GUIDE 停机一段已按新文本更新。

## 验证（`GOWORK=off`）

- 修前红见问题记录；修后 `TestShutdownLifecycleHooksStayWithinTheShutdownBudget` 两个阶段通过，新增 `lifecycle` `TestEmitAllWatchedReportsEachHookBeforeItRuns`（按 Order 报名、前一个失败不跳过后面）。
- 真实进程（game-demo，10s 预算）修后：`app run failed err=app: lifecycle service.stopping hook "drill-stuck-service.stopping" did not return within the shutdown budget: context deadline exceeded`（stopped 同），时序不变（10.006s / 10.005s）。
- `go test -race -count=3 ./app/ ./lifecycle/`、根包、`go build ./... && go vet ./...` 通过。
