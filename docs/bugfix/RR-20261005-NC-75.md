# RR-20261005-NC-75 修复：生成的 loader 检查 `ref=`；`tablegen -json -check` 按 schema 规则校验 JSON

[问题](../bug/RR-20261005-NC-75.md) · [证据](../review/evidence/noncore-review-20261005-n08/README.md)。2026-10-05，基线 `80802200`。状态：ref 与 `-check` 已修复、声明场景验证，未发版；运行时 required 存在性待维护者选择（见问题记录）。

## 决策

- **ref**：`generateGo` 先 `resolveRefs`——目标必须是本次 schema 里的表，字段类型（去掉指针）等于目标主键类型，否则生成失败（以前这类声明被静默忽略）。模板给带 ref 的表生成 `ValidateTable`：用 `configdata.TableFrom` 取目标表（不在快照里报错），逐行检查非零值（指针字段为非 nil）是目标表的主键。只用 v1.20.0 已有的 `TableDef.ValidateTable` / `BuildContext.Snapshot` / `TableFrom` / `Table.Rows`，生成工程的 Core 下限不变；configdata 先加载全部表再校验，前向引用合法。语义与 cfggen / configdata auto 表的 `ref=` 一致（零值表示“无”）。
- **`-check`**：`checkJSONFiles` 按 configdata 的读法取行（行列表，或只含 `rows` / `records` / `data` 一个键的包装对象；object 文件按单行），检查 required 列出现且不为 null，再走 `validateRows`（unique / 主键 / min）。生成器从合法 CSV 写出的 JSON 总带全部列，照常通过。
- 帮助（`roost help tablegen`）与 `CODEGEN_REFERENCE` 写明各规则在哪里检查、直接改 JSON 后 reload 前跑 `-check`、运行时不检查 required 是否出现。
- 新增 `codegen/scripts/tablegen-runtime.sh` 与夹具 `codegen/internal/tablegen/testdata/runtime/`（与 cfggen 门同构：临时模块 + pin 的 core + 真实 configdata），并加入 `.github/workflows/ci.yml` 的 runtime 步骤。

未采用：运行时 required 存在性（两种候选的代价见问题记录）；让 `roost generate` 自动跑 `-check`（generate 产出的 JSON 本就经过同一套规则，没有收益）。

## 兼容性（行为收紧）

已有工程里悬空的 ref 数据此后加载 / reload 失败（旧快照保持）；ref 指向非表 / 类型不符的 schema 此后 `roost generate` 失败。没有 ref 的表生成物不变（game-demo 的 `gen_table_config.go` 逐字不变，`generate --check` 通过）。
