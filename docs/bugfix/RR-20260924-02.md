# RR-20260924-02 修复：组锁在异常路径也归还

[问题记录](../bug/RR-20260924-02.md) · 状态：已修复、已验证，未提交/发布。

`nest/group_lock.go: lockDispatchEntitiesWithGroup` 用本地 releaseGroup 统一清理 scope 和组锁。加锁阶段由函数 defer 持有清理责任；成功后 handedOff 将责任交给返回的 release closure。release closure 先登记 defer，再执行可能 panic 的 Entity release hooks。

因此正常释放、加锁返回错误、部分加锁回退中的 panic 均归还 scope/groupEntry。原 panic 仍传递到已有调度恢复边界，不把 hook 失败伪装成成功。无新增包或公开 API，不改变锁获取顺序及正常事务语义。

验证：`TestGroupReleasePanicStillReleasesGroupLockAndScope` 两个子场景修前均有失败证据，修后通过；channel 控制锁占用，无 sleep。相关 Nest/Entity/Sync/DataEngine race、vet 与全模块 build 通过，命令见 [同轮验收](RR-20260924-01.md)。未运行真实跨服负载，未宣称修复所有用户回调的异常传播问题。
