# RR-20260926-15：重连不复用正在退出的传输队列

问题：[原始复审](../bug/RR-20260926-15.md)。日期 2026-09-26。
实施基线：main `381efc9` 加上一轮 RR-03～09 的未提交修复；原报告基线 `aaada47` 保留。
状态：代码已修复，适用本地验证通过，尚未提交/发布。完整证据和限制见[本轮汇总](../review/REVIEW-2026-09-26-release-fixes.md)。

## 修复与依据

SessionOpened 透传 ErrSessionAlreadyExists。旧发送未退出时明确拒绝 Open，不创建新会话、不把新 lifetime 交给旧队列。

涉及：`sync/entitysync/transport.go`。

## 验证

TestReopenRefusesDrainingTransportLifetime（通道控制在途发送；修前失败、修后通过）。命令、负对照范围与环境见汇总；没有把全部测试绿色当成生产故障已穷尽。

## 兼容与边界

复用 SessionID 的调用者应在旧发送退出后重试，或为新连接分配新 ID；不在快池等旧发送。


## 复核后的补修（2026-09-26）

对应[复核残留](../bug/RR-20260926-15.md#复核后的补修2026-09-26)。基线 main `87d9499` + 本轮 RR-04 `2b770f6`、RR-05 `a5b164f`；状态：已修复、已验证，本地提交，未 push。

### 方案

- **传输确认后才发布会话**：`OpenSession` 对实现 `SessionLifecycle` 的传输先在 `Manager.opening`（受 `m.mu` 保护）登记 ID、解锁调用 `SessionOpened`，成功后才把新 lifetime 放进 `m.sessions`；失败时什么也不留下。确认期间 `Subscribe`/`HoldSession` 返回 `ErrSessionUnknown`、Flush 看不见它，不会向未注册的传输 Push，也就没有假的 SessionLost（复核疑点 (3) 确认成立并修复）。确认期间 Manager 开始关闭时，由 `OpenSession` 自己 `SessionClosed` 归还传输资源并返回 `ErrManagerClosed`。`MaxSessions` 把确认中的 ID 计入。无 SessionLifecycle 的传输仍直接发布。
- **并发同 ID Open 与实际状态一致**：已有会话仍幂等返回 nil；同 ID 正在确认时返回 `ErrSessionOpening`，不再返回 nil，也不再重复调用 `SessionOpened`。每个返回 nil 的调用方返回时会话确实存在。
- **可 errors.Is 的哨兵与重试语义**：新增 `entitysync.ErrSessionClosing`（同 ID 上一个 lifetime 的旧发送仍在退出）与 `ErrSessionOpening`；`AsyncTransport.SessionOpened` 把 `nettransport.ErrSessionAlreadyExists` 包装成 `ErrSessionClosing`（两者都能 `errors.Is`，原因保留）。`OpenSession` 文档注释写明：两者都表示本次未创建会话、可重试；本方法不等待旧发送或另一次打开，可在快池调用，等待与重试由调用方放在慢阶段或下一次调度（遵守“快池内不得阻塞等待”）。`SessionLifecycle` 注释要求其他传输同样以 `ErrSessionClosing` 表达“ID 仍被旧 lifetime 占用”。适配器注释注明它独占所包装 nettransport 的会话注册，注册冲突只可能来自旧队列未退出。

没有增加“旧队列已排空”的通知：调用方仍需重试（轮询间隔由业务决定），但现在可以按哨兵区分“可重试”与真正的失败。

涉及文件：`sync/entitysync/subscriptions.go`、`manager.go`、`errors.go`、`transport.go`；回归：`reconnect_transport_test.go`；使用说明：`sync/README.md`、`docs/USER_GUIDE.md`（未改 CHANGELOG，按本轮约束留给发版）。

### 行为与 API 变化

- 新增导出错误 `ErrSessionClosing`、`ErrSessionOpening`。旧代码 `errors.Is(err, nettransport.ErrSessionAlreadyExists)` 仍成立。
- 并发同 ID `OpenSession` 在确认期间由返回 nil 改为返回 `ErrSessionOpening`；确认期间的 `Subscribe` 由“成功但随后可能丢失”改为 `ErrSessionUnknown`。
- 自定义 `SessionLifecycle` 的 `SessionOpened` 在返回前不会再看到针对该会话的 Push。

### 回归

- `TestConcurrentOpenResultMatchesSessionState`（受控 SessionOpened，接受/拒绝两种）：修后 `first open=transport refused concurrent open=entitysync: session with this id is being opened; retry OpenSession later sessions=0`。
- `TestSessionInvisibleUntilTransportOpened`（确认期间 Subscribe + Flush）：修后 `subscribe=entitysync: session is not open flush=<nil>; open=<nil> SessionLost=[] sessions=1`，拒绝时 `sessions=0`、无 SessionLost。
- `TestConcurrentReopenWhileDrainingIsRetryable`（正式 `nettransport.AsyncTransport`，旧发送在途、8 个 goroutine 并发重开）：断言每个调用都得到两种哨兵之一且会话数 0（一次 `-v` 实跑为 1 个 `ErrSessionClosing`（包装 `ErrSessionAlreadyExists`）、7 个 `ErrSessionOpening`，分布随调度变化）；放行旧发送后重试成功，新会话收到帧、无 SessionLost。放行后的重试循环只 `runtime.Gosched()` 让出调度，不用 sleep。
- 既有 `TestReopenRefusesDrainingTransportLifetime` 保持通过。

### 未验证项与边界

- 没有真实网关/客户端重连压测；demo 模板 `scene.go.tmpl` 的 `OpenHeldSession` 仍在出错时直接返回（错误以 `%w` 包装，可被 `errors.Is` 识别），未为它加重试策略。
- `OpenHeldSession` 仍是 `OpenSession` 后再 `HoldSession` 两步，二者之间会话短暂处于非 held 状态；这是既有行为，本次未改。
- 仍无“旧队列已排空”的通知，重试节奏由调用方决定。
- 本项不涉及热路径（只改会话打开），未做性能对照。
