# RR-20260920-03：玩家租约的"只动自己的"必须是一个操作（U-0258，C8）

## 问题

生成工程 `game/playerroute` 的三条路径都是"先 `GET` 确认 SID、再发第二条命令"：

| 路径 | 旧写法 |
| --- | --- |
| `Claim` 的"已经是我"分支 | `GET` → `EXPIRE` |
| `Refresh` | 逐 id `GET` → `EXPIRE` |
| `Release` | `GET` → `DEL` |

两条命令之间租约可以过期并被另一个进程取得，第二条命令于是落在**别人的** key 上：
旧 owner 给新 owner 续了期，或者直接把新 owner 的租约删了。代码注释写的
"only if it is ours" 不是实现提供的保证。

## 根因

`Owner()` 读到的 SID 是一个**瞬时事实**，而 `EXPIRE` / `DEL` 是在它之后才执行的。
判据与被判据的对象之间隔着一次网络往返，这是 C8（对同一状态的判据取自另一个时刻）。

第二个根因是身份太粗：值里只有 sid。同一个 sid 的进程重启之后，新实例和旧实例
在任何比较下都相等，于是新实例会"认领"旧实例留下的租约——而旧实例可能还活着。

## 方案选择

- **采用**：值升级为 `<sid>:<token>`（token 是每个 `Store` 实例随机生成的进程化身），
  三条路径改成单次原子操作——`SetNX`（取）、compare-and-expire（续）、compare-and-delete（放）。
  比较的是**整个 Route**（含 token），所以同 sid 的前一次化身算作别人。
- 放弃 **加锁**：这是跨进程的事实，本地锁不参与。
- 放弃 **缩短 GET 与第二条命令的间隔**：只是把窗口变小，没有关掉它。
- 放弃 **在 demo 里手写 Lua**：core 是放这类原语的地方（ARCH-01）。`CompareAndSet` 已经能
  表达 compare-and-expire（把原值原样写回并带 TTL）；缺的 compare-and-delete 补进 core。

## 改动

- **roost-core v1.15.13**：新增 `redis.CompareAndDelete(ctx, client, key, expected)`，
  一个脚本里比较后删除。`Expected` 必须非 nil——不比较就删等于 `DEL`，从这个名字进来会读出
  一个它并不提供的保证。测试跑真 Redis（`ROOST_REDIS_TEST_ADDR`），因为要验证的是 Lua 本身。
- **roost-codegen**：`demo/game/playerroute/playerroute.go.tmpl`
  - `Route` 增加 `Token`，`encode` / `decodeRoute` 定义存储形态 `<sid>:<token>`；
    没有 token 的旧值被**拒绝**而不是当成"有 sid 无 token"（那是升级前留下的 key，
    当成可拥有会让两个进程同时认为自己持有它），它自己会在 `Lease` 内过期。
  - `keyspace` 接口从 `SetNX/Get/Expire/Del` 变成 `SetNX/Get/CompareAndExpire/CompareAndDelete`；
    新增 `redisKeyspace` 适配器，两个 compare 操作直接调 core 的脚本，demo 侧不重写 Lua。
  - `Refresh` 返回 `[]RefreshResult{PlayerID, Held, Err}`：错误是 **UNKNOWN 而不是 held**。
    这是 RR-20260920-04 的修复要站的地基。

## 证明

红测试（`game/playerroute/playerroute_test.go`，与审查附录同形）：

- `TestAStaleReleaseMustNotDeleteTheNewOwner`
- `TestAStaleRefreshMustNotExtendTheNewOwner`

修前（生成工程跑已发布模板）：

```text
--- FAIL: TestAStaleReleaseMustNotDeleteTheNewOwner
    a release from the previous owner deleted the new owner's lease: route={SID:0} found=false
--- FAIL: TestAStaleRefreshMustNotExtendTheNewOwner
    the previous owner extended a lease that is no longer theirs: deadline=06:13:50 want=06:13:30
```

修后全绿，并新增：

- `TestARestartOnTheSameSidIsADifferentOwner`：同 sid 重启既不能续期也不能释放前任的租约，
  租约自然到期后才能重新 Claim；
- `TestRefreshReportsPerPlayerOutcomesIncludingUnknown`：读不出来时 `Held=false`、`Err!=nil`。

**变异验证**：把 fake keyspace 的两个 compare 操作改成忽略 `expect`（模拟一个不兑现比较的
keyspace），四条所有权测试同时变红——说明它们判的确实是这个不变量，不是形状。

替身的忠实性：fake 的 compare-and-X 在同一把锁内完成"读—比较—动作"，与 core 的 Lua 同形；
竞争通过 `beforeCompare` 钩子注入在**原子操作评估之前**，这正是真实世界里租约易主的时刻。

## 未做 / 边界

- 租约丢失之后**本地写入仍然不被阻断**——那是 RR-20260920-04，另一条单元。本单元只保证
  "对 Redis 的每一次改动都只动自己的那把租约"。
- 升级期间旧格式（裸 sid）的 key 不可用，靠 `Lease`（30 秒）自然过期；没有做在线迁移。
- `Claim` 的 `SetNX` 之后紧跟一次 `Owner()` 读，两者之间仍可能变化——但那条路径只用于**报告**
  当前持有者，不再据此写入，所以不构成上面的缺陷。
