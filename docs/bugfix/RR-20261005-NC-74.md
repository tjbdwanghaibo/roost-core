# RR-20261005-NC-74 修复：复制、输入快照与提交计划共用一条按路径判断的工程边界，跳过 `.dev` 与 `data/wal`

[问题](../bug/RR-20261005-NC-74.md) · [证据](../review/evidence/noncore-review-20261005-n08/README.md)。2026-10-05，基线 `80802200`。状态：已修复、声明场景验证，未发版。

## 决策

- `skippedProjectDirectory` 改为接收相对工程根的路径：原有按名字跳过的目录不变，另跳过 `.dev`（`make dev-run` 的日志 / pid）与 `data/wal`（生成配置里 DataEngine 的默认 WAL 目录）。`data/wal` 按路径匹配，`configs/data`（生成器输出）不受影响。
- `copyProject`、`snapshotProjectInputs` 与 `planStagedProjectCommit` 对真实工程的遍历都用它。最后一处原来是另一份更短的名单；只改前两处会让暂存树里没有的 `.dev/*.log`（内容恰好引用 “Code generated”）被当成退役生成物删除——负对照 `nc74-negative.txt` 证明这一点，所以三处一起改。
- 未采用：按名字跳过 `data`（会漏掉 `configs/data`）；读 `config.<svc>.yaml` 的 `dataengine.wal.dir` 动态跳过（配置可能在工程外、多服务多份，复杂度与收益不成比例，记为范围限制）。

## 兼容性

`.dev/` 与 `data/wal/` 不再复制进暂存树、不再参与输入核对与退役判断；这两处本来就不是生成器输入。`.roost-*`、`.testcache` 现在也不再出现在提交计划的真实工程遍历里（只会更安全：暂存树从未收到它们）。

## 验证

- 修前红：`TestGenerateAndSyncIgnoreTheProjectsRuntimeOutput` 的 generate / sync 两条报 `project inputs changed …: .dev/game.log, data/wal/dataengine/000001.wal`；控制（生成期间改 `configs/service/config.game.yaml` 仍被拒绝）通过。
- 修后三条通过；负对照（只还原 `project.go` 的遍历）红在 `.dev/quoted.log did not survive`。
- 矩阵见 [NC-75 修复记录](RR-20261005-NC-75.md#验证)。
