# RR-20260924-03 修复：Cast 事务保护与 Sync 解耦

[问题与修前证据](../bug/RR-20260924-03.md)。日期：2026-09-24。已修复并验证，未提交、未发布。

## 决策与行为

- [cast.go](../../nest/cast.go)：成功加锁的新实体独立加入当前 RollbackTx。Sync 存在时另行加入 SyncMutation；两者不是相互启用的条件。
- `ReleaseCast`：存在事务或正式 Sync 作用域时，由框架在回滚/准入之后统一释放；普通无事务上下文仍支持提前释放。避免持久化或回滚发生在实体解锁之后。
- [execution.go](../../nest/execution.go)：pipelined 在原始 dispatch 锁释放后清理 Guard 中的动态锁，再等待 WAL；LSN 也覆盖 Guard 当前持有的动态实体，不要求 Entity 启用客户端同步。保留无 Guard 调用的原始参数水位处理和 SyncMutation 接线。
- [cast_transaction_test.go](../../nest/cast_transaction_test.go)：真实 Request 的业务失败、strict 拒绝，以及可控 ticket 的锁释放/水位边界。

不新增包或公开 API，不改变持久化格式。`ReleaseCast` 在事务内延迟释放是可见的正确性修复：依赖事务中途放锁的调用方需要改为独立业务操作，不能在同一事务里等待另一个任务取得该实体锁。

setter 仍只标脏；Sync 仍在成功准入、Guard 持锁期间收集，解锁且提交条件满足后发送。
