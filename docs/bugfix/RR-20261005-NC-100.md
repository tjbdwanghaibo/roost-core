# NC-100 修复：Redis 驱动的脚本命令不再自动重放

问题：[RR-20261005-NC-100](../bug/RR-20261005-NC-100.md)。证据：[evidence](evidence/noncore-bugfix-20261005-revn04/)。

## 根因与决策

`redis/driver/client.go` 的 `Eval` / `EvalSha` / `EvalBatchDurable` 把脚本交给 go-redis 的普通重试路径；回复丢失（EOF、部分回复、无截止的读超时）时驱动换连接重发，脚本第二次执行。CompareAndSet 第二次执行看到自己的写，versionstore 把它当作竞争失败，再写一次。

采用：脚本命令包成 `scriptCmd`（嵌入 `*goredis.Cmd`，`NoRetry() == true`，`Clone` 保留标记），由 `runScript` 经 `rdb.Process` 发送；`EvalBatchDurable` 的 pipeline 用同一命令，含 NoRetry 命令的 pipeline 整体不重发。参数与首键位置和 go-redis `cmdable.eval` 相同，集群槽位计算不变；`ClusterClient.process` 的 MOVED / ASK 重定向分支在 NoRetry 检查之前，照常跟随（脚本在错误节点上没有执行）。普通读写命令保留驱动重试。

未采用：

- 把 `fredis.DefaultConfig` 的 `MaxRetries` 改成 -1：也会关掉读命令的透明重试，并且 Cluster 的换节点重试不看 `MaxRetries`、只看 `NoRetry`（`osscluster.go:1378`），不能单独解决脚本。非脚本写命令的重放（`RPush` / `SetNX`）另列观察，待维护者按命令幂等性统一定。
- 在 versionstore 里把“Applied=false 且 Current 等于自己的 Next”判为已应用：另一个写者可能写出字节相同的信封（同基线、同结果），会把一次丢失的更新报成成功。
- 信封带一次性写令牌：能把未知结果变成确定结果，但改持久格式，留作方向建议。

## 文件与行为

- `redis/driver/client.go`：新增 `scriptCmd` / `newScriptCmd` / `runScript`；`Eval`、`EvalSha`、`EvalBatchDurable` 改用它们。
- `versionstore/versionstore.go`：`Store.Update` 注释写明传输错误是结果未知、重试需要幂等 mutate、store 自己不重放。
- `kit/scripts/integration/dataengine-env.sh`：故障矩阵加入 `./versionstore`（新增的 integration 用例按 `ROOST_DATAENGINE_IT` 门控，根包 `TestFaultMatrixScriptNamesEveryFullEnvironmentSuite` 要求列入）。
- 回归：`redis/driver/script_no_retry_promises_test.go`（RESP 替身：一次 Eval / EvalSha 服务端只执行一次且返回错误；只有脚本命令带 NoRetry、克隆保留）、`versionstore/lost_reply_integration_test.go`（真实 Redis + 本用例自建随机端口 toxiproxy 代理，不动共享 `redis` 代理、不 `/reset`）。

兼容性：行为收紧。回复丢失的脚本调用以前可能被驱动“救回”成成功（也可能被重放成错误的结果），现在返回传输错误；调用方本来就要处理这些错误（versioned lock 的未知结果认领、服务层的请求 ID 去重）。无 API / 持久格式 / wire 变化。

## 未验证 / 风险

Redis Cluster 下脚本的 MOVED / ASK 与节点故障（本机无 Cluster）；非脚本写命令仍被驱动重放（观察 3）；remoteentity marker / snapshot L2 在回复丢失时现在看到错误而不是驱动重放，它们的未知结果处理只经既有单元与真实锁用例验证，未在故障矩阵上跑。

## A2 后续（2026-10-05，维护者决定 A2）

“未验证 / 风险”里记的“非脚本写命令仍被驱动重放”（观察 3）已经由 A2 关闭：全部写命令、含写的 pipeline、DistLock 都不再经驱动重放。另外，脚本在“确定没执行”的错误上（LOADING、拨号失败等）恢复了重发，补回本修复关掉驱动重试后丢掉的那部分可用性。`scriptCmd` 并入通用的 `noReplay`（`redis/driver/replay.go`）。方案、红绿与调用方核对见 [A2-DRIVER-REPLAY-CONTRACT-2026-10-05](../feature/A2-DRIVER-REPLAY-CONTRACT-2026-10-05.md)，契约表见 [redis/driver/README.md](../../redis/driver/README.md)。
