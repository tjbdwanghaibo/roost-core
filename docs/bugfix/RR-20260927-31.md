# RR-20260927-31 修复：Cast 捕获失败在事务上留记号，业务吞错也整条回滚

问题：[RR-20260927-31](../bug/RR-20260927-31.md)（第六轮审计 → OPEN-ITEMS 批次 13 追加；RR-20260927-11 的同类，修前即有）。日期 2026-09-27。基线 `a136c98`，分支 `fix-r8-b13`（在 RR-20260927-29、30 之后）。
状态：已修复，本地验证通过，本地提交，未推送 / 发布。codebase-memory 图谱过期（09-26），未使用；以当前源码为准。

## 根因（基线行号）

`nest/cast.go:188-192`：取锁后 `tx.CaptureEntities(lockedNow)` 失败只把错误还给业务，事务上不留记号。`nest/execution.go:208-218` 在 handler 结束时只看
handler 返回值、`createLockBusy` 与 RR-11 的 `createCaptureFailed`（只由 `CaptureCreatedEntity` 设置）。业务吞掉 Cast 的捕获错误返回成功时事务照常提交：
一个未进入回滚 / 持久化参与的实体随事务落地，捕获失败前已登记的提交参与者照样准备记录。

## 决策：与 RR-20260927-11 同一机制

按修复约束先读了 [RR-20260927-11 修复](RR-20260927-11.md)：它在 `RollbackTx` 上记第一次新建捕获失败，`invokeWithTransaction` 在 handler 结束时
`errors.Join` 进结果（业务已返回它时不重复拼接）、走同一回滚分支，不是锁超时、不重排。本条直接复用这一记号：

- `RollbackTx.createCaptureFailed` 改名为 `captureFailed`（包内私有字段，注释写明两个来源），新增 `noteCaptureFailed(err)` 记第一次失败；
  `CaptureCreatedEntity`（RR-11）与 `castMulti` 的捕获失败分支（本条）都调用它。
- `invokeWithTransaction` 的并入与回滚逻辑不变（只换字段名、注释补 RR-31）。
- 锁：Cast 已取得的锁（`lockedNow`）在事务内不提前释放（`ReleaseCast` 在事务内本就是空操作），事务结束时由 Guard 统一释放——与修前相同的既有路径。
- 不区分回滚策略（与 RR-11 相同）：捕获错误不是 `ErrLockTimeout`，不会重新准入，RollbackNone 事务不会因此重复执行，强制失败只阻止提交。
  memory 快路径没有 `RollbackTx`，Cast 不捕获，不受影响。
- 嵌套 `RunIsolatedTransaction` 内的 Cast：`CurrentRollbackTx()` 是嵌套事务，记号只让嵌套事务失败，外层照常由业务处理其错误（与 RR-11 相同）。

- `nest/execution.go`：读 `captureFailed`，注释补 RR-31。
- `docs/USER_GUIDE.md` §4：handler 内新建的约束段后补 Cast 捕获失败的同一处理。
- `docs/bugfix/RR-20260927-11.md`：末尾追加“后续”，指向本条。
- 回归：`nest/cast_capture_failure_promises_test.go` `TestCastCaptureFailureFailsTheTransactionEvenIfSwallowed`（审计探针 `TestAud8CastCaptureFailureSwallowed` 收正，kind 199；
  RollbackState strict handler 改声明实体并 `MarkPersist`，`CastOne` 一个 `CaptureRollback` 恒失败的实体）。子用例 `swallowed`（吞错返回成功）与 `returned`（业务返回该错误）：
  回复 `errors.Is` 捕获错误、不含 `ErrLockTimeout`、committer 0 次、声明实体值恢复、Cast 目标仍在且锁已归还。

## 兼容性

行为收紧：此前“Cast 捕获失败 + 业务吞错”的 handler 会提交，现在整条回滚并把捕获错误交给调用方（判别表不命中前 12 行，按“其余”行：未提交，见 RR-20260927-32）。
Cast 捕获失败本身（DAO 不可快照、durable 事务内 Cast remote-managed 实体未声明 Remote 批次等）已有文档约束，正常生成工程不会触发。无导出 API / 配置变化。
仓内 `ErrDurableRemoteWriteUnsupported` 的非测试使用只有定义、`CaptureEntities` 与 DataEngine 删除准入（`dataengine/engine/entity_delete.go:59`，不经 Cast 捕获），没有依赖“吞掉后继续提交”的调用方。
