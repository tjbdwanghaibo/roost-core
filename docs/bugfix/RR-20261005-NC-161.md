# NC-161 修复：没有样本的阈值判违反，并写明 no_samples

问题：[RR-20261005-NC-161](../bug/RR-20261005-NC-161.md)。2026-10-05，分支 `revn12`，基线 `45d4bc1c`。

## 决策

- `evaluate` 先算样本数：`error_rate` 用完成场景数（Success+Failure，取消不计）；分位数用 Success，并在默认 Quantile 下再取直方图观测数（序列从未观测或被每指标序列上限丢弃时为 0）。样本数为 0 → `Violated: true, Reason: "no_samples"`。未知 Metric 原来就判违反，现在带 `Reason: "unknown_metric"`。
- `metrics` 新增 `Registry.HistogramCount` / `metrics.HistogramCount`，让调用方区分“0 ms”与“没有数据”。
- `loadtest.Config` 新增可选 `SampleCount`；只自定义 `Quantile` 时只用 Success 判样本。
- Markdown 报告的 verdict 写出原因（`**FAIL** (no_samples)`）。
- 未采用：运行结束后删除 per-run 序列（需要 metrics 增加删除 API，影响面更大），记为观察；本修复保证门禁不再因序列被丢弃而假绿，丢弃本身由 `obs.series.dropped` 与告警暴露。

## 文件与行为

`metrics/metrics.go`、`robot/loadtest/manager.go`、`robot/loadtest/admin.go`；回归 `robot/loadtest/threshold_no_samples_promises_test.go`（全部取消的运行、直方图序列被丢弃的真实 runner 运行）。

行为变化：没有完成场景或没有耗时样本的运行判 failed/threshold（以前 finished）。`ThresholdResult` 增加可选字段 `reason`（JSON omitempty），兼容。
