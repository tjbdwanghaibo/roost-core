# RR-20260930-15：实体实现必须是指针——契约 + `BuildEntity` / `TryAdd` 入口校验

问题：[RR-20260930-15](../bug/RR-20260930-15.md)（REMAINING §3 N29，维护者 2026-09-30 拍板“契约 + 启动期校验”）。日期 2026-09-30。基线 `4784ef82`，独立 worktree。
状态：已修复，本地验证通过，本地提交，未推送 / 发版。codebase-memory 图谱 generation `2026-09-30T11:28:30Z`，所引文件无记录缺口；仓内实体实现以 `rg 'func \([a-z]+ [A-Za-z]+\) Base\(\)'`（值接收者 `Base()`）为准。

## 根因

`entity/entity_guard.go` `holding` / `doReleaseEntity` 直接比较实体接口值；实体进入框架的入口（`BuildEntity`、`EntityManager.TryAdd`）不校验实现类型，值类型（尤其不可比较的）实现走到比较时 panic。

## 决策

- 契约：实体实现必须是指针。写进 USER_GUIDE §3“必须遵守”与 `holding` 注释。
- 校验放在入口、只看动态类型的 Kind：`requirePointerEntity`（`entity_guard.go`，与被保护的比较放在一起）在 `BuildEntity`（builder 返回、Remote 策略校验之后，错误带 kind）与 `TryAdd`（`Add` 经它 panic，与重复 ID 一致）各调一次；`reflect.TypeOf(e).Kind() != reflect.Pointer` 即拒绝，返回 `ErrEntityNotPointer` 并以 `%T` 点名类型。一次 `reflect.TypeOf` 加 `Kind()`，不做逐字段反射，不缓存（每次构建 / 发布本就远重于它）。
- 可比较的值类型同样拒绝：值类型经接口传递每次都是一份拷贝，Guard 的“同一实例”对它没有意义，放行只会把问题推迟到别处。
- **热路径不改**：`holding` 的 `current == ent` 保持直接比较，注释写明由入口校验保证。

未采用：

- 在 `holding` 用 `reflect.Value.Comparable` 做安全比较（RR-30 对 Mutex 的做法）——维护者明确不改热路径；对实体而言指针是唯一合理形态，安全比较只是掩盖违约。
- 在 `RegisterEntityBuilder` 时校验——那时只有 builder 函数、没有实体实例，Go 反射拿不到函数会返回的动态类型；所以在 builder 第一次构建出实体时（`BuildEntity`）校验，效果相同。

## 文件与行为

- `entity/entity_guard.go`：`requirePointerEntity`；`holding` 注释补契约。
- `entity/entity_manager.go`：`ErrEntityNotPointer`；`TryAdd` 校验。
- `entity/entity_factory.go`：`BuildEntity` 校验（错误前缀 `entity kind %d:`）。
- `kit/nest/entity_sync_test.go`、`kit/nest/entity_sync_resync_test.go`：值类型替身 `reloadedEntity` 改为指针（`*reloadedEntity`、`&reloadedEntity{...}`）——它被 `manager.Add`，修后按契约被拒绝而 panic，替身本身违约。
- 回归 `entity/entity_pointer_contract_promises_test.go` `TestValueTypeEntityIsRejectedAtRegistrationAndPublish`：值类型（含 func 字段）实现在 `TryAdd` 与注册 builder 的 `BuildEntity` 处都被拒绝，`errors.Is(err, ErrEntityNotPointer)` 且错误点名 `valueTypeEntity`、未发布；指针实体照常接受。kind 219（同包未占用）。

## 兼容性与迁移

- **行为收紧**：值类型的实体实现现在在 `BuildEntity` / `TryAdd` 被拒绝（`Add` panic），此前照常进入框架、直到同 ID 两实例在同一 Guard 相遇才 panic。生成实体（`codegen` 的 `NewXxx` 返回指针）、kit、demo 都是指针，不受影响；自定义 / 测试替身若是值类型需改为指针（仓内只有 `kit/nest` 的 `reloadedEntity` 一处，已改）。
- 新增导出 `entity.ErrEntityNotPointer`。公开 API 签名、持久格式不变。

- 只校验动态类型的 Kind：指针指向的结构体含不可比较字段没有问题（指针恒可比较），所以没有做逐字段检查；如果将来有人用“接口值类型”实现（interface 嵌套 interface），`reflect.Kind` 会是底层动态类型，仍按同一规则。
- 没有跑 codegen 生成工程的实编（生成实体是指针，`codegen/internal/entity/testdata` 的 fixture 未重生成）。
- `kit/nest/entity_sync_test.go` 的另一个 hook 用例（`hook(&reloadedEntity{...})`）只是经 `OnEntityLoaded` 回调、不进 EntityManager，改指针只是与契约一致。
