# RR-20260930-13：生成名称冲突在写入前拒绝

状态：已修复，固定函数/导入冲突、输出保留与正常消费者均通过；未发版。[原问题](../bug/REVIEW-2026-09-30-codegen-05.md#rr-20260930-13)，修前基线 `4784ef820cab599e0b1321a96a5843af2ab95e58`。

`validateMeta` 的生成名称登记漏掉默认注册 wrapper 和 import。现在预占 RegisterConfigData/configdata；当完整 schema 有启用的非 string 索引时，用 RR-12 的 usesStrconv 同步预占 strconv。两种固定登记原有名称继续保留。校验完整 schema 先于分组导出，因此一个完整 schema 在任一 target 会启用该导入时，冲突也会被提前拒绝。

没有选择静默给 bean 或注册 wrapper 改名：那会改变生成公开类型/aggregate 接口并掩盖 schema 问题；也没有永久禁止 strconv bean，未启用需要该 import 的索引时仍可使用。命名错误点名冲突来源，在现有输出目录写入前返回，旧 cfg_gen.go 字节保持。

正式 `namespace_promises_test.go` 在修前真实失败三项：RegisterConfigData、configdata、带真数字索引的 strconv 均被接受（error=nil）；另两个原有固定名称控制被正确拒绝。修后五项均按 collision 诊断拒绝且保留输出；Configdata、RegisterConfigDataBean 与无索引的 strconv 三个正常 bean 的真实消费者编译通过。`go test -race ./codegen/internal/cfggen -count=1 -v` 全包通过，并包含 RR-12 的四项真实编译回归。[修前日志](evidence/codegen-bugfix-20260930-12-14/RR13-red.log)、[全包修后日志](evidence/codegen-bugfix-20260930-12-14/cfggen-green.log)。

兼容：以前生成不可编译代码的冲突 schema 现在被提前拒绝，需要改 bean 名和相关 type 引用；不自动改公开 API。无实际冲突的已有名称、注册和数据格式保持。既有输出不会因拒绝而删除；修正 schema 后重新生成。真实数据加载、发布 tag、不同分组的所有组合仍非上述消费者测试的完整证明。全轮验证与进度见[第六轮](../review/REVIEW-2026-09-30-codegen-06.md)。
