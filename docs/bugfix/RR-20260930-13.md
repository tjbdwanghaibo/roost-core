# RR-20260930-13：`SetEntityVersion` 同一 fence 下拒绝 StateVersion 回退，并返回 error

问题：[RR-20260930-13](../bug/RR-20260930-13.md)（REMAINING §3 N26，维护者 2026-09-30 拍板）。日期 2026-09-30。基线 `4784ef82`，独立 worktree。
状态：已修复，本地验证通过，本地提交，未推送 / 发版。codebase-memory 图谱 generation `2026-09-30T11:28:30Z`，所引文件无记录缺口；调用方以 `rg SetEntityVersion`（全仓含 kit / codegen 模板 / demo）为准。

## 根因

`entity/entity_remote.go` `RemoteEntityBase.SetEntityVersion` 的 CAS 循环不与当前 StateVersion 比较；接口签名无返回值，拒绝无处报告。RR-20260927-15 只在 `SetRemoteVersionVector` 加了判据。

## 决策

- 判据：`SetEntityVersion` 只改 StateVersion、沿用当前 fence，所以“同 fence 回退”在这里就是“写更小的版本”：`uint64(v) < current.StateVersion` → `ErrRemoteVersionConflict`、不写；相等 / 更大照常 CAS。负数仍按 0 处理（旧行为），已推进过的实体写负数因此被拒。
- **接口签名改为 `SetEntityVersion(int64) error`**（`IThreadSafeRemoteEntity`）。不返回 error 的替代是“拒绝时静默不写”，那是隐藏副作用，与“准入失败要能判别”的契约冲突；也没有采用新增 `TrySetEntityVersion` 保留旧方法——两条入口一条静默一条报错更难用。
- 调用方核对（`rg -n 'SetEntityVersion' --include='*.go' --include='*.tmpl'`）：生产代码只有 `remoteentity/transaction_manager.go` `acknowledgeRemoteCommit` 的非 `IThreadSafeRemoteEntity` 分支（`live` 的静态类型已是 `IThreadSafeRemoteEntity`，该分支实际不可达）——改为处理错误并像向量分支一样再核对 `remoteReceiptObsolete`；测试 3 处改为检查错误。codegen 模板、kit、demo 没有调用；生成实体经嵌入 `RemoteEntityBase` 获得该方法，没有自己的实现。

## 文件与行为

- `entity/entity_remote.go`：接口方法与 `RemoteEntityBase.SetEntityVersion` 改为返回 error，同 fence 回退拒绝，中文注释写明规则与之前为什么错。
- `remoteentity/transaction_manager.go`：非向量分支处理返回值。
- 测试：`entity/entity_remote_test.go`、`remoteentity/batch_test.go`、`remoteentity/rejected_memory_reload_test.go` 改为检查错误。
- 回归 `entity/set_entity_version_no_rewind_promises_test.go` `TestSetEntityVersionRejectsRewindUnderSameFence`：更小 / 负数 → `ErrRemoteVersionConflict`、向量不变；相等 / 更大 → nil、只有 StateVersion 变。

## 兼容性与迁移

- **Go API 签名变化（源码不兼容）**：`entity.IThreadSafeRemoteEntity.SetEntityVersion(int64)` → `SetEntityVersion(int64) error`。仓外自己实现该接口（不嵌入 `RemoteEntityBase`）的类型必须改签名；把它当语句调用的代码仍能编译（Go 允许丢弃返回值），但会错过拒绝，应检查错误。
- **行为收紧**：同一 fence 下写更小的 StateVersion 现在被拒绝（此前静默接受）。依赖“把版本写小”的自定义代码需改用新 fence（经 `SetRemoteVersionVector`）。持久格式、wire 不变。
