# RR-20260927-33：生成的生产 compose 把 `tmpfs` 写成单条带引号的挂载

问题：[RR-20260927-33](../bug/RR-20260927-33.md)（OPEN-ITEMS 批次 7 C04 / B34 / B32 实跑发现）。日期 2026-09-27。基线 `e0d38f7`，分支 `fix-r8-b14`。
状态：已修复，本地验证通过（含本机 docker compose 实跑），本地提交，未推送 / 发布。codebase-memory 图谱过期（09-26），本轮以当前源码、`rg` 与实跑为准。

## 根因

`codegen/internal/roost/render_cicd.go:451`（基线行号）`renderProductionCompose` 为每个服务写 `tmpfs: [/tmp:rw,noexec,nosuid,size=64m]`。
这是不带引号的 YAML flow 序列，逗号是项分隔符，解析结果是 `/tmp:rw`、`noexec`、`nosuid`、`size=64m` 四项；docker 把后三项当成挂载点，
`docker compose up` 报 `invalid mount path: 'noexec' mount path must be absolute`，所有服务都起不来。生成工程 CI 只跑 `docker compose config --quiet`，
这一步只校验语法，四项都是合法字符串，所以一直是绿的。

## 决策（按修复约束）

- 输出改为 `tmpfs: ["/tmp:rw,noexec,nosuid,size=64m"]`：整项加引号，仍是单行 flow 序列，与同段其他键的写法一致；没有改成块序列，因为块序列要多占两行、
  且与 `cap_drop` / `security_opt` 的风格不一致，语义完全相同。
- 全仓核对其他带逗号的 flow 序列 / flow 映射（生成的 game-demo 全部 74 个 YAML 文件，以及仓库内 `*.go` / `*.tmpl` / `*.yaml` / `*.yml` / `*.md` 中形如 `[a,b]`、逗号两侧无空格的值）：
  - 只有这一处是“一个值里本来就含逗号”。
  - `security_opt: [no-new-privileges:true]`、`cap_drop: [ALL]`、`healthcheck.test: [CMD, /app/healthprobe, http://127.0.0.1:9100/readyz]` 都按预期分项
    （URL 里的 `:` 后面不是空格，是普通标量）。
  - 开发 compose 的 `command` / `entrypoint`（含 `rs.initiate({_id:'rs0',members:[...]})`）整项带双引号。
  - k8s 的 `{name: config, mountPath: /etc/roost, readOnly: true}`、`httpGet: {path: /healthz, port: ops}`、资源 `{cpus: "2", memory: 2G}` 等 flow 映射，逗号本来就是键之间的分隔。
  - `docs/DEPLOYMENT.md` 与生成的 `deploy/docker/README.md` 里的 `--tmpfs /tmp:rw,noexec,nosuid,size=64m` 是 `docker run` 命令行参数，不经过 YAML，本来就是对的。

### 本机 docker compose 实跑

环境：Docker Desktop 29.7.2 / Compose v5.5.1（aarch64）。只用本地镜像，不拉取、不推送：镜像按生成 Dockerfile 的运行阶段原样构建，只把
`FROM gcr.io/distroless/static-debian12:nonroot` 换成 `FROM scratch`、`USER nonroot:nonroot` 换成 `USER 65532:65532`（scratch 没有 `/etc/passwd`），
构建阶段换成预先交叉编译的 `linux/arm64` 二进制（做法同 [RR-20260926-66 后续验证](RR-20260926-66.md) 的 C04）。配置根目录由生成的 `config.<svc>.prod.example.yaml`
改写，依赖直连本地隔离环境（经 `host.docker.internal`），资源一律 `zz14`；详见 [RR-20260927-34](RR-20260927-34.md) 实跑一节。compose 项目名 `-p zz14`。

- 基线 compose：`docker compose up -d game` 退出码 1，`Error response from daemon: invalid mount path: 'noexec' mount path must be absolute`；
  `docker compose config` 显示 `tmpfs` 为 `- /tmp:rw`、`- noexec`、`- nosuid`、`- size=64m`。
- 修后 compose（仍用基线镜像）：容器创建并启动，`HostConfig.Tmpfs = {"/tmp":"rw,noexec,nosuid,size=64m"}`；随后因 RR-20260927-34（镜像缺 `configs/data`）退出重启。
- 修后 compose + 修后镜像：全部 10 个服务 `up -d` 成功并到 healthy，见 RR-20260927-34。
