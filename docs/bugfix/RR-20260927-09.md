# RR-20260927-09 修复：提交路径与 ValidateEntityRegistry 对“remote=managed + dbscope=sid”fail-fast

问题：[RR-20260927-09](../bug/RR-20260927-09.md)（OPEN-ITEMS A10 + C15）。日期 2026-09-27；基线 `d4234c9`；worktree 分支 `fix-r7-ent`。
codebase-memory 图谱停在 09-26，已过期，未使用；代码发现以源码与实跑为准。

## 根因

见问题记录：RR-45 的运行时拒绝只有装配期一处，且只看注册的 `DaoBuilders`（`remoteentity/assemble.go:260`）；提交路径（`remoteentity/batch.go:390`
的 `FinalizeLocked` → `RemoteCommit.Validate`，`entity/remote_protocol.go:267`）不看 mutation 自带的 `DatabaseScope`，投影却按它选库
（`remoteentity/mongo_payload.go:36,39`）；`entity.ValidateEntityRegistry`（`entity/category_order.go:197`）不检查 DAO 作用域。

## 决策

1. **一条规则、一个哨兵**：`ErrRemoteManagedServerScopedDAO` 与校验函数从 remoteentity 移到 entity（`entity.ErrRemoteManagedServerScopedDAO`、
   `entity.ValidateRemoteManagedDaoScopes`）。`remoteentity.ErrRemoteManagedServerScopedDAO` 改为 `= entity.ErrRemoteManagedServerScopedDAO`（同一个值，
   既有 `errors.Is` 与错误文本不变），Assemble / Start 调 entity 的同一函数。托管判定沿用 RR-60 / 71 的“kind 在注册表里的实际策略”
   （`GetEntityKindRemotePolicy`），未声明 `DbScope` 按 global。
2. **ValidateEntityRegistry**：逐 kind 检查时，对有 builder 的 kind 追加同一规则的问题，每个违规 DAO 一条（与本函数其他问题一样用 `%w` 串联，
   `errors.Is` 可判）。它只做报告，不在注册时拒绝——注册顺序（builder 先、kind 定义后）由 RR-71 的注册期校验处理生命周期，这里不重复。
3. **提交路径选在 `FinalizeLocked`**：`RemoteCommit.Validate` 之后调用 `refuseServerScopedRemoteData`，mutation 或 delete 的 `DatabaseScope` 为
   `DatabaseServer` 即返回包裹哨兵的错误，并与 Validate 失败同样 `RollbackRemoteCommit` + `rollbackFinalizedLocked`，批次不产生任何提交，Nest 按准入失败回滚。

未采用：

- **放进 `RemoteCommit.Validate` 或 `mongo_payload.go` 选库处**（清单 A10 列出的两个候选）：`Validate` 同时被 WAL 编码 / 解码（`nestwal/codec.go:566,789`）、
  投影（`dataengine/engine/projector_remote.go:35`、`remoteentity/mongo_committer.go:179`）与投影重放经过的 `ApplyRemoteCommits`
  （`dataengine/engine/mongo_projection.go:157` → `remoteentity/transaction_manager.go:658`）调用，选库处本身就在投影里。在这些位置拒绝会把已准入
  WAL 的记录变成投影毒丸、重启重放失败——正是 bf-45“未采用”一节排除的做法。`FinalizeLocked` 是 Remote 提交进入 WAL 前唯一的定稿点，
  属于清单约束“提交路径 fail-fast”的范围；`DatabaseScope` 字段、WAL 编码与 `dataDB` 的 sid 分支原样保留。
- 注册时（`RegisterEntityBuilder`）拒绝：DAO 工厂在注册时实例化会改变注册的副作用面，且 builder / kind 定义的注册顺序不固定；整表校验放在
  注册全部完成之后（生成 registry 末尾）更准确。

## 兼容性

- **行为收紧**：生成 registry 末尾的 `ValidateEntityRegistry` 现在对该组合返回错误（进程启动失败），此前要到 Remote 装配才失败；手写实体漏报 DAO
  工厂时 Remote 事务在准入前被拒绝。该组合在基线上跨服写或迁移后本就不可写（RR-45），不会误伤可正常工作的部署。替代写法：DAO 改 `dbscope=global` 并重新生成。
- 新导出：`entity.ErrRemoteManagedServerScopedDAO`、`entity.ValidateRemoteManagedDaoScopes`。错误文本仍以 `remote_entity:` 开头（沿用 RR-45 的文本，便于日志检索）。
- 无 WAL / 协议 / 配置 / 生成物变化；已写入 WAL 的 sid 记录重放不受影响。
