# RR-20260923-01 修复：按已交付引用表决定是否欠删除通知

- 问题：[RR-20260923-01](../bug/RR-20260923-01.md)。状态：已修复并验证，未发布。

## 改动与理由

`sync/entitysync/manager.go` 增加包内 `sessionHoldsSubject`，在 Manager 读锁下查询当前会话的引用表；已关闭、held 或没有引用的会话不欠删除通知。`Unsubscribe`、`Unregister` 使用同一判据。

`subject.go` 的中文注释明确：`kindSnapshot` 可以是首次订阅，也可以是旧对象的视图更新。复用现有引用表，不为“客户端是否持有”再增加一份布尔状态。

公开 API、包路径与线格式不变；原先漏发的 ObjectRemove 现在会正确发出。

## 验证

- 问题文档所列四个场景：修前全部失败，修后全部通过；验证删除引用与首次创建一致，并确认无对象的会话不被发送多余帧。
- `go test ./sync/entitysync ./sync/entitysync/policy -count=1` 通过。
- `go test -race ./sync/... ./entity -count=1` 通过，含 UDP/KCP/QUIC 本机回环。

## 边界

本次覆盖 profile/退订的顺序状态转换，不宣称已经验证 Flush 与会话重建、订阅更改的全部并发交错。未运行真实游戏客户端端到端。
