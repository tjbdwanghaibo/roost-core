# RR-20260927-26：并发 Touch 推迟清理时 `ReleaseCast(旧实例)` 释放了同 ID 新实例的锁

问题：[RR-20260927-26](../bug/RR-20260927-26.md)（OPEN-ITEMS B07 → 12 追加）。日期 2026-09-27。基线 `7b56060`，分支 `fix-r7-b12`（在 RR-20260927-25 之后）。
状态：已修复，本地验证通过，本地提交，未推送 / 发布。codebase-memory 图谱过期（09-26），调用方以当前源码与 `git grep`（全仓，含 kit、codegen 模板）为准。

## 根因（基线行号）

`nest/cast.go:205` `ReleaseCast` 调 `entity.GetEntityGuard().ReleaseEntity(e.GUId())`；`entity/entity_guard.go:428` `ReleaseEntity(id)` 释放的是
**eMap 里 id 当前登记的实例**。handler 内 Destroy X 再新建同 ID 的 X 时，RR-67 把新 X 登记为当前、旧 X 连同锁移到 `superseded`。
无并发时 Destroy 返回前旧 X 的 ID 已清零，`ReleaseCast(旧X)` 是空操作；但另一个访问者按 Cast 顺序 Touch 了旧 X 并在等它的锁时，
清理推迟到最后一次 UnTouch，旧 X 的 GUId 仍是 X——`ReleaseCast(旧X)` 把新 X 的锁在 handler 中途放掉（旧 X 反而回到 eMap 继续被持有）。

## 决策（按主记录修复约束）

- `entity.EntityGuard` 新增 `ReleaseEntityInstance(ent)`：按实例释放。`ent` 是当前登记（或与它共用同一把锁，与 RR-67 `holding` 同一判定）时同 `ReleaseEntity`；
  `ent` 已被同 ID 新实例取代、锁在 `superseded` 时只释放这把旧锁；本 Guard 没为它登记锁时什么也不做。`ent` 的 ID 已清零时按 ID 查不到当前登记，只查 `superseded`，
  与原来的空操作一致（被取代的旧实例本来就只能按实例找到）。
- 旧入口 `ReleaseEntity(id)` 保留原语义，godoc 标明“按 ID、不论调用方手里是哪个实例”，并指向按实例入口。
- 释放 `superseded` 里的旧锁是 `ReleaseCast(旧X)` 本来承诺的事（提前释放这个实例），也与基线“无重建时 `ReleaseCast(已销毁实例)` 提前释放它的锁”一致；
  等待者随即拿到旧锁、看到已销毁退出。只在 handler 所在 goroutine 上执行，没有新增等待。

## 回归

nest 用例：pilot 消息的 memory handler 里 `CastOne(X)`，起一个 goroutine 按 Cast 顺序 `Touch` 旧 X 后在自己的 GuardScope 里等锁；handler `Destroy(旧X)`、`Create(X)`、
`ReleaseCast(旧X)`。断言：前提（旧 X 的 GUId 仍非零、新 X 被持有）；`ReleaseCast(旧X)` 后新 X 仍不能被别的 goroutine 取得；等待者在 handler 中途拿到旧锁并看到已销毁；
`ReleaseCast(新X)` 照常释放当前实例；handler 结束后新 X 可取得。

## 兼容性

新增导出方法 `EntityGuard.ReleaseEntityInstance`；`ReleaseEntity(id)` 行为不变。`ReleaseCast` 只在“传入实例不是 id 当前登记”时行为改变：之前释放当前登记（别的实例），现在释放传入实例自己的锁或什么也不做。

## 未验证项 / 风险

- `broadcastDispatch` 按 ID 逐实体释放：广播 handler 内 Destroy 后同 ID 重建时，按 ID 释放放掉新实例、旧（已销毁）实例回到 eMap，直到整轮广播结束才解锁；
  按实例释放则是新实例留到整轮结束。两种都有一把锁跨后续广播目标持有，是修前即有的形状，不在本条范围，未构造回归。
- Remote 实体的 `ReleaseCast`：Remote 目标由声明准备、不经 Cast 取锁，未单独构造回归。
