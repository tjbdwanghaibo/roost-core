# RR-20260925-04 修复：事务外读取已提交回执

[问题](../bug/RR-20260925-04.md)。不拆分首次原子提交，也不新增“已经落库”的布尔开关或发布专用绕过接口。

`MongoCommitter.CommitRemoteBatch` 先验证提交、计算完整 digest，再通过正式 Mongo driver 的 majority read 查询持久 transaction 文档。存在且 digest 一致、状态成功时直接返回原回执；不同内容复用 TxID 仍拒绝，失败状态不当作成功。

不存在时继续开启原 Mongo 事务，事务内仍检查幂等状态并原子校验版本/最新许可，覆盖并发首次提交。CAS 冲突后的回执查询复用 `committedRemoteReceipts`，合并三处相同的摘要/状态判定。尚未提交的数据不会走快路，新 grant 生效后重放旧的成功事务仍是合法幂等读取。

改动位于同包 `mongo_committer.go`；没有改变 DAO/WAL/快照格式、持久级别、checkpoint、发布重试和未知结果语义。首次独立调用 CommitRemoteBatch 会多一次存在性读取；正式 DataEngine 新写仍直接使用调用方 Mongo 事务，发布阶段省掉第二次事务。

验证：相关五个包 race、integration-tag vet 通过；向 StartSession 注入错误后成功重放回执，TxID 内容冲突拒绝。禁用快路的负对照失败，日志在 `artifacts/perf/remote/unified-verification-20260925/fastpath-negative-control.log`。最终故障矩阵、发布失败恢复与原规模性能结果见 [报告](../feature/REMOTE-UNIFIED-2026-09-25.md)。
