# RR-20260927-13 修复：kit 暴露卸载后重载与共享加载超时的配置键

问题：[RR-20260927-13](../bug/RR-20260927-13.md)（OPEN-ITEMS C13）。日期 2026-09-27；基线 `d4234c9`；worktree 分支 `fix-r7-ent`。
codebase-memory 图谱停在 09-26，已过期，未使用；以源码为准。

## 决策

- **键名放在 `nest.` 下**：这两项都由 kit 的 Nest Mod 接到它的 getter（正式装配里就是生成的 `EntityAccess`，`*entity.ManagerAccess`）上，与其他 Nest Mod 键
  （`nest.fast.*`、`nest.request_timeout`…）同处；生成配置已有 `nest:` 段。
  - `nest.entity_load_timeout`（duration）：`Init` 里调 getter 的 `ConfigureLoadTimeout`。缺省或 0 不调用（沿用 `entity.DefaultEntityLoadTimeout`）；
    负值拒绝；设置了但 getter 没有该能力时拒绝启动（不静默忽略显式配置）。在 Init 接线，早于任何 Mod 的 Start 触发冷加载。
  - `nest.unload_resync.workers` / `attempts` / `queue_capacity`（int）：`Init` 读取并校验（负值拒绝），`Start` 交给 `ConfigureUnloadResync`，替换原来的
    `entity.UnloadResyncConfig{}`。0 / 缺省字段由 `UnloadResyncConfig.normalized` 取框架默认，所以缺省行为逐字不变。
  - 退避（`RetryMin` / `RetryMax`）不开放：清单只点名三项，退避是实现细节；需要时再加键。
- **配置校验**：只在 kit Mod 的 `Init` 做（负值、能力缺失），错误信息带键名；仓内没有独立的配置 schema 校验器。
- **生成配置**：`codegen/internal/roost/catalog.go` 的 `nest:` 段写出与默认相同的值（`entity_load_timeout: 30s`、`unload_resync: {workers: 4, attempts: 5,
  queue_capacity: 4096}`）并附注释，让部署看得到这些旋钮；取值与 entity 默认相同，生成工程行为不变（codegen 不能 import entity，数值是字面量，改默认时两处同步）。

## 文件与行为

- `kit/nest/nest_mod.go`：`engineConfig.unloadResync`、`loadTimeoutConfigurer`、`initEntityLoadConfig`；Start 传 `m.config.unloadResync`。
- `codegen/internal/roost/catalog.go`：生成配置的 `nest:` 段新增键与注释。
- `docs/USER_GUIDE.md`：共享冷加载段（`nest.entity_load_timeout`）、RR-59 段（三项键与默认值）。
- 回归：`kit/nest/unload_resync_config_promises_test.go` `TestNestModWiresUnloadResyncAndLoadTimeoutConfig`（configured：键值原样交给
  `ConfigureUnloadResync` / `ConfigureLoadTimeout`；defaults unchanged：无键时零值、不调 `ConfigureLoadTimeout`；四个负值各自被 Init 拒绝且错误含键名）。

## 兼容性

新增配置键，缺省值不变；未设置这些键的既有部署行为逐字不变。新生成的工程配置里多出这几行（值即默认）。显式设置 `nest.entity_load_timeout` 而 getter 不是
`ManagerAccess`（自定义 getter 未实现 `ConfigureLoadTimeout`）时启动失败——这是有意收紧，避免配置了却不生效。
