# NC-163 修复：websocket 拨号用 DialContext，DialTimeout 覆盖建连与升级握手

问题：[RR-20261005-NC-163](../bug/RR-20261005-NC-163.md)。2026-10-05，分支 `revn12`，基线 `45d4bc1c`。

## 决策

`dialWebSocket` 接收 ctx，按 `DialTimeout` 包一层截止时间，设置 `wsCfg.Dialer` 并调用 `wsCfg.DialContext(ctx)`（x/net v0.58：ctx 到期时设连接截止、等握手 goroutine 退出）。DialTimeout 覆盖 TCP 建连加 HTTP 升级握手；tcp 拨号没有握手，保持原样。

## 文件与行为

`robot/transport/transport.go`；回归 `robot/transport/dial_bounds_promises_test.go`（DialTimeout 先到 / ctx 先到两种都在期限内返回；正常 websocket 端点握手并往返一个包）。

## 回归与结果

修前 [red](../review/evidence/noncore-review-20261005-n12/nc163-red.txt)（3s 后仍阻塞）；修后 [green](evidence/noncore-bugfix-20261005-n12/nc163-green.txt)（约 200ms 返回 `context deadline exceeded`）；`go test -race -count=3 ./robot/transport` 通过。

## 未验证 / 风险

wss（TLS）路径只经同一 DialContext，未单独起 TLS 端点验证。
