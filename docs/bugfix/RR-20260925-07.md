# RR-20260925-07 修复：Nest 快慢双池

[问题记录](../bug/RR-20260925-07.md) · [设计与验收](../feature/REFACTOR-2026-09-25-nest-fast-slow.md)

## 实施

- `nest/dispatch_queue.go` 用共享快/慢就绪队列替代四套哈希池；准入时记录全部显式目标 ID 的前驱。等待前驱不占 worker；独立 ID 不受哈希碰槽影响。
- 所有 Nest handler、Guard、事务封装与锁释放前 Sync 在快池。Cost/Slow 只标记前置加载需要慢池；Remote 获取/确认/释放使用慢池。同 ID 顺序保留到慢阶段整体收尾。
- 慢请求通过独立 Msg 信封借用快池，延续不再次参加自身的 ID 排序，也不消耗外部快队列预算；满队列不阻断已接受请求收尾。两池一起排空后停止。
- `entity.WithLocalExecutor/RunLocal` 给 I/O 调用链提供同步返回快池的边界。Remote 内存 Commit 失败的本地回滚、EntityRepository 初始化/发布、加载引用释放和确认后回调回到快池。连接、队列、租约元数据的内部互斥仍合法。
- `WorkerPoolConfig`、`NestOptionWithWorkerPools` 和 Kit fast/slow 配置分别控制并发与整池等待容量。旧 main/remote Stats 是 Fast/Slow 兼容别名；Heart/Cost 为空，JSON/指标只输出两池。旧 HB worker 参数不再建立执行池。

## 兼容与限制

新 QueueCap 为整个池的等待预算，旧版为每 worker 的队列容量，升级需要核对配置。默认快并发 GOMAXPROCS，慢并发至少 32 且为快并发的四倍，慢等待容量 64。增加并发不能增加后端无限吞吐。

顺序覆盖显式目标；动态实体仍由 Guard 保证互斥。重排请求在再次准入时取得新顺序位置，Pipelined 提前释放的完成通知语义保持。可选的 WAL 完成泵、投影和定时器属于基建，未改持久化协议或通知契约。

自定义 Getter/Loader 必须把本地加锁和初始化业务步骤交给 `entity.RunLocal(ctx, fn)`，不能把任意阻塞 RPC 写在 handler 中再期望自动迁移。`RunLocal` 是同步交接；不能递归调用或在 fn 返回后继续使用借用状态。独立调用未安装 Nest 执行器时维持就地执行。

未部署；此改动没有替代生产环境长稳和容量验收。

真实链路：100 TPS ×120 秒完成 12000 笔，零错误/丢弃，99.638 TPS；p99=860ms，max=945ms。Mongo/NATS/rollback/outbox 全量校验通过，脚本退出 0，最终积压为零。不是 30 分钟长稳结论。

补充：七包 race（增加 `sync/entitysync`）通过；两项加载/回滚边界测试以临时 overlay 恢复旧逻辑后均失败，当前逻辑通过。120 TPS ×120 秒为 12653 成功/1747 错误，错误样本均队列满，不作为通过档；详情和复跑参数见设计文档。

本轮隔离集群 21/21 故障矩阵通过，脚本退出 0；见 `artifacts/perf/remote/two-pool-matrix-20260925/results.tsv`。图谱已更新并复核本轮源码覆盖。
