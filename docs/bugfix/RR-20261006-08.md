# RR-20261006-08 修复：mongotest `$in` 按 reflect 展开具名切片，saga 用例去掉绕行

问题：[RR-20261006-08](../bug/RR-20261006-08.md)。批次：[收尾第 4 批](CLOSING-BATCH-4-2026-10-06.md)。基线 `8a292a5a`，未发版。

## 改动

- `mongo/mongotest/mongotest.go` `valueList`：`bson.A` / `[]any` 照旧；其余用 reflect——Slice / Array 展开，元素经 `underlyingScalar` 换成内置类型（有符号整型 → `int64`、无符号 → `uint64`、浮点 → `float64`、字符串、布尔），其余类型原样。元素类型恰好是 `byte` 的切片 / 数组（含 `type blob []byte`）仍报 `ErrUnsupported`：驱动把它编成二进制标量，服务端对非数组的 `$in` 报错。`_id` 的 `$in` 候选（`idCandidatesLocked`）走同一个函数。
  - 为什么要换成内置类型：`valuesEqual` 只认内置数值类型，具名整型会落到 `fmt.Sprint` 比较，带 `String()` 的（如 `saga.Status`）会比成名字。
  - 驱动行为已用 `bson.Marshal` 核对：`[]S`（`type S uint8`）、`[2]S`、`[]int` 编成 array，`[]byte`、`type B []byte` 编成 binary。
- `saga/coordinator_takeover_review_test.go`：删掉 `claimSecondStage` / `claimDue` / `claimFunc`，`runCoordinatorTakeoverCases` 直接调 `store.ClaimDue`；`saga/cross_process_real_integration_test.go` 的调用与文件头注释随之修改。
- `saga/step_operation_promises_test.go` `TestMongoStoreTombstoneTellsAbandonedFromResolved`：库里的记录先经 `Apply` 推进到第 2 次尝试，再 `ClaimDue` 领取（带租约 fence）后 `processClaimed`；之前是在内存里改 `Attempt` 后跳过领取。

## 兼容

只影响测试替身：之前被拒的具名切片 / 整型切片 `$in` 现在按驱动语义匹配。
