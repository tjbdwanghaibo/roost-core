# NC-120 修复：Freeze 只暂停 Tick，结束通知照常交给策略

问题：[RR-20261005-NC-120](../bug/RR-20261005-NC-120.md)。2026-10-05，分支 `revn10`，基线 `197f7bb9`。

## 根因

`ai/controller.go:138`（基线）`ready()` 把“能否决策”和“能否收通知”合成一个判断，冻结时连 `OnActionEnd` / `OnMissionEnd` 都丢弃。

## 决策

- 拆成两个判断：`notifiable()`（非 nil、未切换、有策略）管通知，`ready()` = `notifiable() && !frozen` 管 Tick。冻结只暂停决策，不暂停记账，与 actionflow 冻结组“不 Tick、不启动，但 End 照常并发 OnEnded”一致。
- 切换期间仍然丢弃（那时结束的是旧策略的动作）。
- 未采用：冻结期间缓冲通知、Recover 时重放。要多一份待投递状态，还要在冻结中换策略 / Shutdown 时清空，状态与分支更多；BehaviorStrategy 本来就只是缓冲到下一次 Tick。代价写进注释：自定义策略若在 OnActionEnd 里直接发起动作，冻结期间也会被调用，需要自己判断时机。

## 文件与行为

- `ai/controller.go`：新增 `notifiable()`，`OnActionEnd` / `OnMissionEnd` 改用它，中文注释写明原因与 RR 编号。
- `ai/frozen_completion_promises_test.go`：新增两条用例（树在 Recover 后完成并重新决策；冻结期间不 Tick 但动作 / 任务结束都送达）。

行为变化：冻结中的 Controller 会把结束通知交给策略。无格式 / API / wire 变化。
