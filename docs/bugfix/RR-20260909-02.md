# RR-20260909-02：Session 撞 RequestID 的撤回误删同 owner 重新取得的 claim（ABA）

**仓库 / 位置**：roost-kit `service/session/service.go`，`Enter` 撞键分支的撤回（U-0154 引入）。
**修复单元**：U-0158（C8）。**定位文档**：TROUBLESHOOTING T-53。

## 问题

U-0154 让同一 RequestID 的落败者撤回自己刚建的 run 与 claim。撤回顺序是先删 run、再按版本删
claim。run 一删掉，同一 owner 的另一次 `Enter`（另一个 RequestID）看到 claim 指向的 run 不存在，
按既有规则把它当孤立 claim 清掉，然后建新 run、拿新 claim——合法且应当成功。但 MemoryStore 与
RedisStore 的 `Create` 都从版本 1 开始，删后重建的新 claim 版本与旧 claim 相同；落败者随后只比版本
的 `Claims.Delete` 把新入者的 claim 删了。owner 再进一次又成功：两个 run 同时 open，"每个 owner 一个
live run"被打破。

## 根因

版本号只在一个键的一次生命周期内单调；跨删除重建会重复。`releaseClaimIfCurrent` 的前提"被别人替换
一定版本不匹配"不成立。更根本的是撤回顺序：先删 run 主动制造了"claim 孤立"的窗口，让别人有理由
替换它。

## 方案选择

- **让版本跨删除重建保持单调**：MemoryStore 可记每键上次版本；RedisStore 键删了就没了，要另留
  tombstone 键，且改变 `Store` 契约（今天多处测试依赖 Create 后版本为 1）。代价大、收益只在本处。
- **删 claim 前 Get 校验 RunID**：`releaseClaim` 已经是这样做的，但 Get 到 Delete 之间仍有窗口。
- **先释放 claim 再删 run（采用）**，并用带 run-id 校验的 `releaseClaim`。不变量：`resolveClaim` 只在
  claim 指向的 run 不存在或不再 live 时才释放它；落败者的 run 在它释放 claim 之前一直 open，所以
  这段时间没有任何人能合法替换这个 claim，版本比较成立。新入者要么在释放前被 `ErrAlreadyRunning`
  暂时拒绝（重试即成功），要么在释放后干净地进入；之后落败者删的是自己那条 run，与新入者无关。

## 改动

`service/session/service.go`：撞键分支 `undo := errors.Join(s.releaseClaim(ctx, ownerID, runID),
s.discard(ctx, stored))`，注释写明顺序为何重要；删除只比版本的 `releaseClaimIfCurrent`；两处
`Claims.Create` 不再保留返回值。

## 证明

`service/session/enter_collision_cleanup_promises_test.go`：Runs 与 Claims 两个存储的 `Delete` 都挂
钩，落败者的第一次删除一完成，同 owner 立刻用新 RequestID 重入。断言：重入成功、其 claim 仍指向它、
第三次 Enter 被 `ErrAlreadyRunning` 拒绝、`Current` 是重入的 run、落败者的 run 不在存储里。

修前：`the re-entry's claim was removed by the loser's cleanup (found=false …); a third Enter then
answered (run-4, <nil>) instead of ErrAlreadyRunning`。修后 session 含 `-race` 全绿。审查附录的
`TestReviewCollisionCleanupPreservesReacquiredClaim`（只挂 Runs.Delete）在新顺序下同样通过。

## 未做 / 边界

- 版本单调性未改；`Store` 契约仍是"版本只在一次键生命周期内有意义"，调用方要靠顺序或身份校验。
- 若 `EnterRequest` 的 deadline 短到 run 建好即过期，`resolveClaim` 可把它当 lapsed 处理并释放 claim，
  理论上重开窗口；deadline 校验拒绝这种请求，未单独钉测试。
- 未在真实 Redis 上重放该交错。
