# NC-280 修复：memory 默认值不能读 memory（求值上下文表 memory_default 列）

[问题](../bug/RR-20261005-NC-280.md) · [本轮](../review/REVIEW-2026-10-06-n09-batch6.md) · [求值上下文表方案](../feature/SKILL-EVAL-CONTEXT-TABLE-2026-10-06.md)。已修复、声明场景验证，未发版。

## 根因与决策

memory 默认值是独立的求值上下文（Activate 里、早于 cast_start 采样、按槽位顺序），编译期却混在施法作用域里、且边填类型表边检查。可选方案：

- **采用**：memory_default 列没有 `$memory.*`。确定、简单，Runtime 不需要依赖槽位顺序。
- 未采用：允许读“排在前面”的 memory。槽位顺序是 lower 的名字排序，作为语义暴露给作者不合适；也要求编译期复制同一排序。

## 文件与行为

`compile_typecheck.go`：memory 类型先全部就位，再按名字顺序用 `scopeFor(evalMemoryDefault)` 检查默认值；`runtime.go` Activate 在 memory_default 上下文里求默认值（表外引用 `ErrReferenceOutOfContext`）。

## 回归

`TestCompileRejectsMemoryDefaultsReadingMemoryDeterministically`（修前：`attempt 0 compiled (cast error <nil>); the compile result must not depend on map order` / 另一顺序被拒时码为 `REFERENCE_UNKNOWN`）→ 修后 ok；控制 `TestMemoryDefaultsReadingTheCastStillRun` 修前修后都 ok。验证：`GOWORK=off`，`go test -race -count=3 ./skill/...`、`SKILL_MUTATION_FULL=1` 性质测试、根包、`go build ./... && go vet ./...`，见 [N09 第六批 §5](../review/REVIEW-2026-10-06-n09-batch6.md#5-修复与验证)。

## 兼容性

行为收紧：memory 默认值读另一个 memory 的定义一律被拒（此前编译结果随机）。仓内 fixture、示例、生成骨架没有这种写法；45 个既有种子 gameplay digest 不变。
