# RR-20261006-03 修复：checkpoint 恢复按 corrupt 拒绝 `phase_timeout` 任务，删除任务类型（O20）

[问题](../bug/RR-20261006-03.md)。收尾第 3 批 A5（分支 `cb3`）。已修复、声明场景验证，未发版。

## 决策

维护者 B3④ 定 phase 计时保持方向 B（编译期拒绝 `timeout_ticks > 0`），Runtime 不会产生 `phase_timeout` 任务。恢复时出现它只能是伪造或非本实现的 checkpoint，按 `ErrCheckpointCorrupt` 拒绝；`phaseTimeoutTask` 类型及其编码、`scheduledTaskIdentity` 分支删除。checkpoint 格式只拒绝不迁移。`restoreCheckpointTask` 保留显式的 `case "phase_timeout"` 并注释原因（落到 default 也是 corrupt，显式分支只为说明）。

## 文件与行为

- `skill/scheduler.go`：删除 `phaseTimeoutTask` 与 `scheduledTaskIdentity` 的分支。
- `skill/runtime_checkpoint.go`：删除编码分支；恢复时 `phase_timeout` → `ErrCheckpointCorrupt`。
- `skill/checkpoint_phase_timeout_promises_test.go`：回归（对照：未改动的 checkpoint 能恢复）。

## 兼容

`RuntimeCheckpointVersion` 不变。旧 checkpoint 只有含 `phase_timeout` 任务的会被拒绝；`git log -S '&phaseTimeoutTask{'` 显示自 V1.9（`67c9df54`）起除 checkpoint 恢复外没有任何代码构造这个任务，已发布版本产生的 checkpoint 不含它，实际不影响旧 checkpoint。

## 验证

- 修前红：`GOWORK=off go test ./skill -run TestCheckpointRestoreRejectsPhaseTimeoutTask -count=1` → `checkpoint with a phase_timeout task restored with err=<nil>; phase timeouts are rejected at compile time, so the task must be refused as corrupt`。
- 修后绿：同命令通过。
