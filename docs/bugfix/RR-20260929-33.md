# RR-20260929-33：Mail Cluster 多封分页修复

2026-09-29；[原问题](../bug/REVIEW-2026-09-29-services-09.md#rr-20260929-33mail-在-cluster-上接受配置但正常多封分页失败)。基线 `68cf87fc79bb3d63c970bb0ce1439dd05466f039` 加本轮工作树内容，实际源摘要见 [SOURCE](evidence/service-bugfix-20260929-08/SOURCE.json)。**已实施，原触发及下述场景已验证；未发布/部署。**

## 根因与最终实现

普通 Mail prefix 下，单 key Mailbox/SendLedger CAS 和 Send 可以成功，信封页的原始多 key MGET 却要求同槽，正常两封页报 CROSSSLOT。保持已有 `:env:` / `:box:` / `:send:` 键及 JSON/TTL，改 `service/mail/redis_store.go` 的 GetMany：先验证空批次、MaxPageSize 与空 id，再通过既有 IPipeline 排队单 key GET、一次 Exec、逐项 FutureBytes.Result。ErrNil 才是缺失；空字节、坏 JSON、WRONGTYPE、取消与其他后端错误返回错误和 nil map。Discard 清理本次缓冲，不共享 pipeline。

不改变通用 MGet 的行为：Redis MGET 对非 string key 返回缺失，GET 会报 WRONGTYPE，Mail 采用后一种明确坏数据语义。Cluster 是每节点批次，没有跨节点原子快照或一次全局网络往返保证；信封写后不可变，TTL 过期可造成缺失，List 保持原有窗口/缺失计数规则。公开 EnvelopeStore、Service、RPC 和配置形状不变，纠正接口和 List 的过强往返次数注释。

## 兼容与恢复

不要求迁移旧邮件、不强制共同 tag。所有执行 Mail 读取的 owner 都要升级，混合旧 owner 仍可能发出失败 MGET；调用方的重试不替代升级。`NewRedisEnvelopes` 参数虽是私有窄接口，外部仍可传结构实现：现在要求 `Pipeline() redis.IPipeline`，自定义仅实现 SetNX/Get/MGet 的客户端需补 Pipeline 或改接正式 IRedis，属于源码兼容变化。自定义 EnvelopeStore 不受影响，框架 driver/kit 装配与生成消费者已编译验证。

原 key 若是 hash 等非字符串，过去 MGET 可能隐藏为缺失，现在分页明确错误；先核对异常键的业务身份/备份再修复，不自动删除存量数据。未操作生产迁移、历史对账或回滚数据。
