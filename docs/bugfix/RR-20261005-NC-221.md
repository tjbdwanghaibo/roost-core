# NC-221 修复：被动的 max_depth 至少为 1、输入只能是 none / entity

[问题](../bug/RR-20261005-NC-221.md) · [本轮](../review/REVIEW-2026-10-06-n09-batch5.md)。已修复、声明场景验证，未发版。

## 根因与决策

编译期不知道被动的两个运行期前提（`runtime_proc.go`：`ProcDepth >= max_depth` 压制；`passiveCastInput` 只填事件 target）。修法在 `skill/compile_shape.go` 的被动分支：

- `proc_policy.max_depth < 1` 报 `SHAPE_INVALID`（原来只拒绝负数，消息改为说明 0 永不触发）；
- input_schema 不是 none / entity 报 `INPUT_UNAVAILABLE at $.input_schema`。

未采用：让 `max_depth: 0` 表示“不限深度”——那是语义扩展，且与 `MaxProcDepth` 上限的设计相反；让 ActivatePassive 接受位置 / 方向输入——事件里没有这些事实。

## 文件与行为

`skill/compile_shape.go`。这些被动从“编译通过、每次 passive_suppressed”变为启动期编译失败。

## 回归

`TestCompileRejectsPassivesThatCanNeverActivate` 五个子用例修前全部 `compiled; diagnostics=[]skill.Diagnostic(nil)`，修后 ok；控制 `TestPassivesWithEventInputsStillActivate`（none / entity）修前修后都 ok。性质测试新增种子 `seed.passive_entity_input`。

## 兼容性

行为收紧。仓内没有 `max_depth: 0` 或非 none / entity 输入的被动（fixture、生成骨架、examples 都不含）。
