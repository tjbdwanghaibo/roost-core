# RR-20261006-49 修复：排队模式下永远不会被接受的 retry pair 让 Drain 永不结束

问题：[RR-20261006-49](../bug/RR-20261006-49.md)（F04-2）。基线 `47abe511`。codebase-memory 共享 generation 停在 09-30，结论按当前源码读取。同一批（`syncfix`）修 RR-20261006-48～50，一笔提交 `04378f7c`。

## 根因

`queuedPending`（`sync/entitysync/policy/interest_queue.go`）把 `in.retry` 整体当作“还有工作”，而 retry 里的 pair 可能永远不会被接受；Drain 没有任何上界。排队模式的 `applyQueued` 又丢掉 `Apply` 返回的 Refusal，没有日志。

## 决策

- **按 pair 计连续被拒次数**（`Interest.refused`）：被接受时清零，pair 被释放（所有来源都放手）或 Interest 关闭时删除，条数不超过 `held`。
- **到上界判定为停滞**：同一 pair 连续被拒 `retryStallAfter = 10` 次（按 Flush 轮次；默认周期 50ms 下约 500ms）即停滞：计数 `entitysync_interest_retry_stalled_total` 并 `slog.Warn` 一次（observer、subject、session、最后一次错误），不再计入 `queuedPending`，Drain 能结束。
- **停滞不等于放弃**：pair 仍留在 retry 里，每次 `Apply` 照旧重说（保持 RR-20260920-06“拒绝不是对 pair 的裁决”）；会话重开、容量释放后照常订阅（测试断言重开后订阅成功、retry 清空），所以不丢合法的兴趣变更。上界选 10：覆盖“本轮 remove 释放容量、下一轮接受”这类暂时拒绝，又让停机不必等满 ctx。

未采用：从 retry 里删掉停滞的 pair（会话之后重开就再也收不到，丢变更）；Drain 不看 retry（刚被拒、下一轮就会被接受的 pair 在停机时被漏发）；Drain 遇停滞返回错误（kit 停机照样走不到 Close）。

## 文件与行为

| 文件 | 改动 |
| --- | --- |
| `sync/entitysync/policy/interest.go` | `refused` 字段；`subscribe` 成功清零、被拒计数；pair 释放 / `Close` 时清理 |
| `sync/entitysync/policy/interest_queue.go` | `retryStallAfter`、`noteRefusedLocked`（计数 + 告警一次）；`queuedPending` 只算未停滞的 retry |
| `sync/entitysync/policy/interest_queue_retry_drain_promises_test.go`（新） | 会话关闭后 Drain 结束、计数 1 次、不重复计数、重开后订阅 |
