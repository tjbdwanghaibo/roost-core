# RR-20260929-31：Activity Cluster 前缀准入

**已修复、声明场景验证。**原问题见[第八轮](../bug/REVIEW-2026-09-29-services-08.md#rr-20260929-31activity-的同槽启动承诺没有执行)。源码基线 bcebb805，本轮实现未改变 Redis 键/活动/dispatch 格式。

Activity Mod.Init 在读 KeyPrefix 后调用现有 `mods.ValidateClusterKeyPrefix`。Cluster 配置的无 tag、空 tag、未闭合 tag、空首对后有有效 tag 均在启动时拒绝，错误点名 activity.key_prefix；有效共同 tag 和单机普通前缀继续使用。注释同步说明多 key dispatch/owed 原子写需要同槽。

修前原 overlay 4 个坏配置失败，tagged 控制通过；修后原 5 个叶子全过。正式[回归](../../kit/service/global/activity/bugfix_cluster_prefix_test.go)有 7 叶子/8 事件，race 与真实三 master Cluster 通过；覆盖配置、单机兼容、Open→Notify→Owed→Attempt→Ack，以及第二个 game 的 dispatch 创建失败、聚合 complete、服务对象重建后 AdvanceExpired 补齐记录且第一个 token 不变。这是对象重建和可控失败，未冒称进程强杀。

不迁移历史错误前缀。直接加 tag 会改变旧 key 空间；应停旧 owner 后按实际记录、window、dispatch/token/owed 状态审查迁移，再使用既有恢复入口。这里的恢复回归是有效 keyspace 内的部分提交修复，不证明跨 slot 旧数据已搬迁。仓外直接构造器仍由调用者提供正确 prefix。

命令、真实后端、计数与 hash 见[第七批修复](SERVICE-BUGFIX-2026-09-29-07.md)和[复跑入口](evidence/service-bugfix-20260929-07/README.md)；未发布/部署或执行生产迁移。
