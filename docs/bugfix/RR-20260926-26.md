# RR-20260926-26 修复：快阶段冷缺失返回 ErrColdLoadInLogic，不再 panic

问题：[RR-20260926-26](../bug/RR-20260926-26.md)（探针见 [REPRO-2026-09-26-03 §2](../bug/REPRO-2026-09-26-03.md)）。
日期 2026-09-26；实施基线 main `87d9499`。状态：已修复、本地验证通过，已提交未推送/未发布。

## 根因

`entity/manager_access.go`（基线行号）：

- `Get` 的 `:99-101` 在原有 `LoadedEntitiesOnly` 错误分支（`:102-104`）**之前**调用 `fctx.BlockingError` 并 `panic`；
- `GetMany` 的 `:211-214` 在同一分支（`:215`）之前同样 `panic`。

RR-06 修复为覆盖“快 worker 上的阻塞入口”把这两处也改成 fail-fast，但这两条分支发生在任何 I/O、加载 goroutine
与 singleflight 等待之前，本身不阻塞。panic 被 Nest 变成整个 handler 的失败，业务再也拿不到 RR-02 契约
（`entity/entity.go` Getter 注释）承诺的可判别错误，“好友离线”之类的降级无法实现。

## 决策

- 快阶段（快 worker 或 `WithLoadedEntitiesOnly` ctx）冷缺失统一走新的 `coldLoadInLogicError`：返回
  `ErrColdLoadInLogic`，在快 worker 上额外 `%w` 包裹 `fctx.ErrBlockingInFastWorker`（保留定位入口与 handler 名，
  既有 `TestFastStageRejectsDirectColdAccessBeforeIO` 断言两者都可 `errors.Is`）。不 panic、不 I/O、不等 flight。
- `LoadedEntitiesOnly(ctx)` 本身已包含 `fctx.InFastWorker()`，所以保存的 Background ctx 在快 worker 上也走这条分支；
  到达 `loadEntityShared`（真正会等待）的只能是池外调用，不需要再断言。
- 真正会等待的入口保持 fail-fast 不变：`dataengine/engine/entity_repository.go` 冷加载（等待投影 / I/O）、
  `WaitEntityProjection`、Remote 准备/Commit/Close/等待、`dispatchFastContinuation` 自投递。

未采用：

- 只在带 `LoadedEntitiesOnly` ctx 的调用返回错误、保存的 Background ctx 继续 panic——两者对快 worker 同样不阻塞，
  区别对待只会让业务降级依赖“拿的是哪个 ctx”，不可读也不可预期。
- 去掉快 worker 标记包裹、只返回 `ErrColdLoadInLogic`——会丢失 RR-06 的定位信息并打破既有断言。

## 文件与行为

- `entity/manager_access.go`：`Get` / `GetMany` 的快阶段冷缺失返回错误；新增 `coldLoadInLogicError` 并注释原因。
- `entity/entity.go`：Getter 注释写明“不能 panic、冷缺失本身不阻塞、快 worker 上同时包裹 ErrBlockingInFastWorker”。
- `docs/USER_GUIDE.md`“回放、快阶段访问与观测”段：区分非阻塞冷缺失（返回错误）与阻塞入口（fail-fast）。
- 回归：`entity/fast_cold_miss_promises_test.go`（快 worker 上 Get/GetMany，含 Background ctx：不 panic、双 `errors.Is`、
  loader 0 次）、`nest/fast_cold_miss_promises_test.go`（REPRO §2 探针改写：快阶段动态 CastOne 冷目标 → 业务降级，loader 0 次）。

## 兼容性

行为回到 RR-06 之前（aaada47）的错误返回语义，错误文本额外包含快 worker 定位信息。依赖“快阶段冷访问会 panic、
整个 handler 回滚”的调用方（仓内无）会改为收到错误，需要自己返回它；Nest 对 handler 返回的错误照常回滚。
阻塞入口的 fail-fast 与 `Nest.Request` 的 `ErrSyncInHandler` 不变。
