# RR-20261006-07 修复：`app.run` 关闭文件日志前写出最终错误

问题：[RR-20261006-07](../bug/RR-20261006-07.md)。批次：[收尾第 4 批](CLOSING-BATCH-4-2026-10-06.md)。基线 `8a292a5a`，未发版。

## 改动

`app/app.go` `run`：原来的 `defer func() { _ = flog.Close() }()` 改为先 `if runErr != nil { slog.Error("app run failed", "err", runErr) }` 再 `Close`。这个 defer 是 `run` 里最先登记的，最后执行，此时 `runErr` 已经并入停机期间的 RuntimeFailure（RR-20261005-NC-232 的 defer）与单实例锁收尾的结果。

决策：只在出错时写；Serve / Shutdown 错误会和此前的 `service exited with error` 等行各出现一次，属于有意的重复——这一行是“进程以什么结论退出”，前面的是“哪一步出的错”。生成的 main 里 `server exit` 那行不动（codegen 不在本批范围，且 stderr 那一行对没开文件日志的部署仍有用）。

## 兼容

只多一行 Error 日志（`msg="app run failed"`），返回值与退出码不变。按日志告警的部署会多看到一条。
