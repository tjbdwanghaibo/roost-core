# RR-20261006-40 修复：业务服务声明自己读的键，doctor 读回进程声明，生成工程同样守住“读配置只经声明”

问题：[RR-20261006-40](../bug/RR-20261006-40.md)。方案见 [A4 ① §7](../feature/A4-1-MOD-CONFIG-SCHEMA-2026-10-07.md)。

## 决策

- **谁声明**：业务服务（`RegisterServer` 注册的 Service）实现 `app.ModConfigSchema`，与 Mod 同等进入启动检查、`--print-config` 与新的 `--print-config-schema`。
  没有给生成器加“业务 Mod 注册钩子”：那要每个工程多一个文件、bootstrap 形状变化，业务还要把 Mod 读到的值经 registry 转交给服务；服务直接声明是同样两行。
  本进程框架 Mod 的键（saga.*、dataengine.*）不在业务里重复声明，经 Mod 自己的声明读（新 `kitsaga.StreamSettings`、`kitdataengine.EffectSettings`）。
- **doctor 怎么知道**：编译一次进程、每个服务跑一次 `--print-config-schema`，框架快照之外的键就是业务声明。`--check-config` 不够：它不报“没有声明的键”
  （生成的配置会带别的进程才注册的 Mod 的键），生成工程的 CI 也不跑它。
- **生成工程的守卫**：实现挪到 `internal/configschema/guard.go`（标准库叶子包），app 守卫、codegen 用例、doctor 的新 `config-reads` 检查共用。
