# RR-20260927-07 修复：原始 mutation 按实体 ID 命中外层已快照实体时，嵌套独立事务同样拒绝

问题：[RR-20260927-07](../bug/RR-20260927-07.md)（清单 [OPEN-ITEMS-2026-09-27](../review/OPEN-ITEMS-2026-09-27.md) C06）。

## 决策与实现

按清单 §H C06 推荐（维护者 2026-09-27 决定按推荐执行）：

- `nest/rollback.go` `refuseWriteUnderEnclosingRollback` 在 RR-74 的 DAO 检查之后，对每个可回滚、未关闭的外层事务再调
  `snapshotsRawMutationOf`：遍历嵌套事务的 `tx.mutations`，跳过 `preparePersistence` 由 DAO 生成的那几条，其余（业务 `AddMutation`、
  `CommitParticipant.PrepareCommit` 加入的）按实体 ID 与外层 `snapshotted` 的 `GUId()` 比较，命中即返回
  `ErrNestedTransactionRollbackConflict`（错误文本带 `raw mutation for entity <id>`）。它和 RR-74 同一调用点：记录非空、交给 committer 之前，
  `commitDurable` 按明确拒绝回滚嵌套事务，外层快照不动。
- 实体 ID：旧形式取 `EntityID`，DocumentKey 形式取 `Key.ID`——与 `AddMutation` 去重用的身份一致。新增 `keyOfMutation` 把这段身份计算
  从 `AddMutation` 里提出来供两处共用（`AddMutation` 行为不变）。
- DAO 生成的 mutation 按去重身份识别（`preparedMutationKey`：`AddMutation` 按同一身份去重，同一 key 在 `mutations` 里只有一条），不按 ID
  重复判断：它们已由 RR-74 按 DAO 实例判断，而生成 DAO 的 `Id()` 是 StorageID，不一定等于实体 ID，按 ID 比较会误判。
- 外层 `snapshotted` 为空（memory 外层没有 RollbackTx；带 Remote 批次的 memory handler 不登记快照）时直接返回，RR-74 的 memory 外层行为不变。

## 兼容性

- **行为收紧**：外层 state / undo handler 里，嵌套独立事务用 `AddMutation` 写外层已快照实体（声明目标、外层 Cast / 新建的实体）的 ID，
  此前照常提交，现在返回 `ErrNestedTransactionRollbackConflict`、什么都没提交。原始 mutation 写其他 ID 不受影响。
- 边界：原始 mutation 用的 ID 恰好等于外层快照实体的 ID、却不是在写这个实体（例如 DocumentKey 形式的别的文档碰巧同号）时也会被拒绝；
  原始 mutation 本身没有归属实体的信息，只能按 ID 判断，这是推荐方案的取舍。
- 无新导出、无签名 / 配置 / 持久格式变化。性能：只在嵌套事务、外层可回滚时多一次 `mutations × snapshotted` 的比较，热路径（消息自己的事务）不执行。
