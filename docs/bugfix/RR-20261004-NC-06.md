# RR-20261004-NC-06：Recover 隔离上报失败

2026-10-04，起点 `c4aa1e7d`。[原问题](../bug/REVIEW-2026-10-04-noncore-04.md#rr-20261004-nc-06)已修、声明场景验证，未发版；T-192。

`gateway/middleware.go` 在 recover endpoint 后先赋 ret=nil / ErrEndpointPanic，再调用独立保护的 reportBoundaryPanic。report string/error/nil panic 均不能突破固定响应边界；失败写入标准 slog 的 `gateway: panic reporter failed`，日志 handler 自身 panic 也被隔离。不把私有 panic 放进返回 error，不加每请求 goroutine、不重试失败 reporter。

回调仍同步拿到原 context 与原 panic，健康 endpoint 不报告，正常业务返回保持。阻塞 reporter 不会被 context 自动终止；本修复只隔离异常，不承诺时间预算。诊断日志依赖有效 logger，logger 也失败时允许丢失该诊断，不能因此替换请求结果。

`gateway/recover_promises_test.go` 原 reporter 三种 panic 都失败，实际 `err=nil escaped=reporter failed` / `panic called with nil argument`；三个正常控制通过。修后三失败转绿，追加诊断 sink panic 控制也通过，共七项。[真实红绿/回归](evidence/noncore-bugfix-20261004-03/README.md)。没有更改传输鉴权、HTTP 状态映射或引入新的网关服务。
