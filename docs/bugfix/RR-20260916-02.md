# RR-20260916-02:不同 Prefix 共用 Stream 时持久消费者身份冲突

**仓库 / 位置**:roost-core `room/jetstream_syncbus.go`,`durableSyncName`。
**修复单元**:U-0210(C8)。**定位文档**:TROUBLESHOOTING T-104。

## 问题

两个总线配置不同 Prefix(`one` / `two`)、共用 Stream 与 LocalSid、订阅同一 topic:消费者都叫
`sync_state_7_aeabf91c58d07db1`,同一 (Stream, Durable) 对应两个不同的 FilterSubject(`one.state` / `two.state`)。
散列只含 topic 与 sid,Prefix 不在身份里。

## 根因

身份由路由键的一个子集构成(C8)。

## 方案选择

- **一律把完整 subject 散列进名字。** 默认 Prefix 的部署升级后 durable 全部改名,已部署消费者的 ACK 游标被抛弃,
  留存的流(MaxAge 30 分钟)会被重放一遍——审查明确"改名需要迁移 / 重放策略,不能把新名称当作沿用原游标"。
- **非默认 Prefix 进入身份、默认 Prefix 逐字不变(采用)。** `durableSyncName(prefix, topic, sid)`:prefix 为默认值时
  散列输入与升级前完全相同;否则用 `prefix.topic`。任何非默认 Prefix 都与默认、与彼此区分;默认部署零迁移。
  不对称之处写进注释与本记录。

## 改动

`room/jetstream_syncbus.go`:`durableSyncName` 加 prefix 参数;调用点与老测试跟着改。

## 证明

`room/jetstream_durable_identity_promises_test.go`:两个 Prefix 不同的总线在同一 Stream 上得到不同 durable;默认 Prefix 的
名字与审查记录的升级前值 `sync_state_7_aeabf91c58d07db1` 逐字相等;非默认不撞默认;名字稳定。
修前红:`same (stream, durable) "SHARED"/"sync_state_7_aeabf91c58d07db1" for different subjects "one.state" vs "two.state"`。

## 未做 / 边界

- 共享 Stream 的**配置所有权**没有动:每个总线仍对 Stream 提交只含自身 `Prefix.>` 的 Subjects 并 CreateOrUpdateStream,
  后建实例可能改掉 Stream 的收集范围。IJetStream 没有读取 Stream 信息的入口,构造期无法校验;审查也说这部分是源码推导。
  部署上不同 Prefix 应各用一个 Stream。
- 消息去重 MsgID 的作用域(`room:topic:key:version:sid:part`,不含 prefix)未一起改:不同 Prefix 共用 Stream 时同 key/version
  的消息会被 Duplicates 窗口去重——这是共享 Stream 不受支持的又一个理由,记录在此。
