# RR-20260926-60：RR-45 装配期校验改按 kind 在注册表里的实际 Remote 策略判断

问题：[RR-20260926-60](../bug/RR-20260926-60.md)（探针 [REPRO-2026-09-26-05](../bug/REPRO-2026-09-26-05.md) §9）。日期 2026-09-26。
实施基线：main `3e26f91`（本批 RR-58 提交之后）。状态：已修复，本地验证通过，已本地提交，未推送/发布。

## 根因（基线行号）

- `remoteentity/assemble.go:260` `validateRemoteManagedDaoScopes` 以 `builder.RemotePolicy.RemoteManaged()` 判断是否托管。
- `entity/entity_factory.go:186-197`：kind 先经 `MustRegisterEntityKindDefs` 声明 managed，手写 builder 再以 `RemotePolicyNone` 注册时，注册表把它当作
  “部分重复声明”接受并忽略，kind 的实际策略仍是 managed（`IsEntityKindRemoteManaged`=true，全部 Remote 路径按托管处理），但 builder 上的字段是 none，
  RR-45 的装配 / 启动校验因此跳过这个 kind，`dbscope=sid` 的 DAO 通过装配。

## 决策（修复约束：改用 `entity.GetEntityKindRemotePolicy(builder.Kind)`）

校验改为读取 kind 在注册表里的实际策略。`RegisterEntityBuilder` 总会先用 builder 的策略声明 kind（未声明时写入、策略为 none 时补全），
所以注册表的策略不弱于 builder 自带的字段；只看注册表即可，不需要取并集。Assemble 与 Start 共用这一函数，两处同时生效。

## 文件与行为

- `remoteentity/assemble.go`：`validateRemoteManagedDaoScopes` 改用 `entity.GetEntityKindRemotePolicy(builder.Kind)`，注释说明原因。
- 回归（`remoteentity/assemble_dao_scope_test.go`）：
  - `TestAssembleRejectsRemoteManagedServerScopedDAO/kind_def`（REPRO §9 改写，子进程隔离全局注册表）：kind 217 经 kind 定义声明 managed、手写 builder 省略
    RemotePolicy 并带 sid DAO → Assemble 必须返回 `ErrRemoteManagedServerScopedDAO`。
  - `TestValidateRemoteManagedDaoScopes`：新增“kind 定义 managed + builder 省略策略 + sid”用例；既有用例改为同时登记 kind 定义（只登记定义、不注册 builder，
    不影响本包其他 Assemble 用例），错误信息断言改按用例 kind。

## 兼容性

行为收紧，只影响“kind 定义为 managed、builder 未声明策略、DAO 为 dbscope=sid”的组合：修前装配通过、运行中跨服写或迁移后不可写（RR-45 所述），
修后 Assemble / Start 返回 `ErrRemoteManagedServerScopedDAO`，替代写法同 RR-45（改 `dbscope=global`）。无 API、配置、持久格式变化。
