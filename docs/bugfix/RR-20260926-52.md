# RR-20260926-52：生成传输层关闭写失败的那一条连接，其余连接收到则推送成功

问题：[原始记录](../bug/RR-20260926-52.md)（复现 [REPRO-2026-09-26-05 §5](../bug/REPRO-2026-09-26-05.md)）。日期 2026-09-26。
实施基线：本地 main `3e26f91`。状态：已修复，适用本地验证通过，已本地提交，未推送/发布。

## 根因（复核）

生成 TCP 传输 `pushPlayer`（`codegen/internal/roost/render_player_tcp.go`，生成 `internal/access/player/tcp/server_gen.go`）把一帧写给玩家的全部连接，
任一写失败就整体报错，而写失败的那条连接仍留在 `sessions` / `playerSessions` 里，要等它的读循环遇到 EOF 或 `idle_timeout`（90s）才注销。
重连窗口里旧连接停止读取（半死 socket），每次推送都在它上面等满 `write_timeout` 后失败 → entitysync 关闭复制会话、回调 `SessionLost` →
demo scene 的 settle 看到仍有活连接（RR-40 修复）→ 重开会话 + `Resubscribe` → 活客户端收到新 lifetime 的全量快照 → 下一帧再次写旧连接失败 → 循环。
同一原因还使“玩家全部连接都写不进”时 `ActiveSessions` 仍大于 0，settle 永远走重同步而不 Leave（修前红第二条）。

## 修复（按维护者批准的约束）

生成传输层正式行为（`render_player_tcp.go`）：

- `writeFrame` 区分两类失败：写到了连接上才失败的（`SetWriteDeadline`、`WriteTo` 出错，或会话已关闭）包装新的包内哨兵 `errConnectionBroken`
  （仍可 `errors.Is` 原错误，如 `os.ErrDeadlineExceeded`、`gateway.ErrSessionClosed`）；写之前就拒绝的（调用方 ctx 已结束、payload 超限）不带这个标记。
  取得写锁后再查一次 ctx：等锁期间 ctx 结束的调用一个字节也没写，不能被当成连接写失败。
- `pushPlayer`：某条连接出现 `errConnectionBroken` → `dropBrokenSession`：先 `forgetSession`（从两张查找表移除，只移除仍是同一 `*session` 的条目），
  再 `session.Close`（关 socket、取消该连接在途 Dispatch）。读循环随之退出，连接槽、按 IP 计数与会话关闭事件仍由 `serveConnection` 的 defer 各释放 / 发布一次。
  返回值：至少一条连接收到、且其余失败全是已关闭的写失败 → `nil`；没有任何连接收到（此时全部已关闭）→ 返回错误；有连接在写之前就拒绝 → 返回错误且不关闭任何连接。
- `pushSession` 同一规则：写失败即关闭该会话并返回错误。
- 指标：新增 `player_tcp_push_closed_total`（因推送写失败关闭的连接数）；`player_tcp_push_total` 改为按实际收到的连接计数。
- `unregisterSession` 的表移除提取为 `forgetSession`，行为不变。
- demo `scene.go.tmpl` 只更新注释（settle / sessionLost 说明失败连接已被传输层关闭，重同步对同一失败连接至多一次）。

“重同步对同一失败连接最多一次”由结构保证：失败连接在第一次写失败时就被注销，之后的推送不再发给它，不会再触发 `SessionLost`；
scene 只有在“推送时刻的全部连接都失败、之后又来了新连接”时才重开会话，这是新连接自己的一次全量。

未采用：在 scene 里按连接计数去抑制重同步（scene 看不到连接身份，只能靠猜；根因在传输层）；推送失败后不关闭只忽略（失败连接的客户端错过帧、流已错位，
仍留在表里继续失败）；每连接独立发送队列（引入每连接 goroutine 与无界/有界队列取舍，超出本修复范围）。

## 兼容性与行为变化

- 生成工程（`add transport tcp` / game-demo）行为：连接一次推送写失败就被服务端关闭（此前要等读循环 EOF / `idle_timeout`）。
  客户端表现为断线，需要重连；正常客户端不受影响。`write_timeout`（默认 5s）因此也是“慢到这个程度就断开”的阈值。
- `PushPlayer` 在部分连接失败、其余收到时返回 `nil`（此前返回错误）。调用方若依赖“任一连接失败即报错”，需改为看 `ActiveSessions` 或会话关闭事件。
- 生成符号：新增 `errConnectionBroken`、`forgetSession`、`dropBrokenSession`（均未导出）；无删除、无改名，`Runtime` / `Config` 公开面不变，无新增配置项。
- 已生成工程需重新生成 `internal/access/player/tcp/server_gen.go`（生成文件，`roost generate` 覆盖）。

## 交付前对抗性自查

- **关闭失败连接不误关活连接**：只有带 `errConnectionBroken` 的错误才关闭连接，它只在字节真正交给 socket（或会话已关闭）之后产生；
  ctx 结束（含等写锁期间结束）与 payload 超限不关闭（守护回归覆盖）。`forgetSession` 按指针比对，同 SessionID 的新连接不会被旧连接的失败移除。
  写到一半 ctx 截止属于真实写失败（流已错位），会关闭该连接，这是有意的。
- **连接槽 / 按 IP 计数唯一释放**：`dropBrokenSession` 不碰计数，只关 socket；释放仍只在 `serveConnection` 的 defer，关闭事件仍只由 defer 里的
  `unregisterSession` 发布一次。回归逐项断言计数回到仍打开的连接数、每个 SessionID 的关闭事件恰好一次。
- **Join 排队 / 代际（RR-40）**：本修复不改 scene 的成员与代际逻辑；settle 仍按代际复查。失败连接被注销后，scene 的 `watchSessions` 收到关闭事件、
  `ActiveSessions>0` 时不动作，与正常断开同一路径。
- **不引入每请求 goroutine**：关闭在推送调用方的 goroutine 上同步完成，没有新 goroutine 或队列。
- **流名兼容**：不涉及。

## 未验证项与已知边界

- 没有真实客户端的旧 socket 写超时端到端复现（回归用回环 TCP 上“停读”的客户端模拟）；集成环境机器人只覆盖正常负载。
- 推送是同步写：一个慢连接仍会让该次推送等满 `write_timeout`（此后它被关闭，不再拖累后续推送）；这是既有背压设计，未改。
- 其他传输（生成物目前只有 TCP）无此改动。
