# RR-20261005-NC-73 修复：`roost id` 的错误码改用 errcode 生成器自己的 AST 扫描

[问题](../bug/RR-20261005-NC-73.md) · [证据](../review/evidence/noncore-review-20261005-n08/cli-id-errcode.txt) · 来源 [NC-63 残余](RR-20261005-NC-63.md#残余)。2026-10-05，基线 `be7bcc18`。状态：已修复、声明场景验证，未发版。

## 决策

“什么算一个错误码定义”只保留一份实现：

- `codegen/internal/errcode/main.go`：原 `extractDefinitions` 拆成导出的 `ScanDefinitions(root)`（遍历 + AST，认别名 / 点导入、跳过注释与字符串，按码排序，**保留重复**）与 `extractDefinitions`（`ScanDefinitions` + 原有的码 / 名重复检查）。生成器行为与错误文本不变。
- `codegen/internal/roost/id.go`：删除 `errcodeDefinePattern`，`ScanIDs` 在扫完 `//roost:` 标记后调用 `codeerr.ScanDefinitions(root)` 收集错误码。`NextID`、`CheckIDs`、`add.go` 的显式 ID 冲突检查随之一致。

未采用：在 `id.go` 里另写一份 AST 扫描——又是两套实现，下一次改动仍会漂移。

## 兼容性（行为收紧 / 变化）

- 别名 / 点导入的定义现在占号；注释、字符串里的文字不再占号。
- 与生成器一致，`_test.go` 里的 `errcode.Define` 不再计入（以前正则会把测试文件里的定义也算占用）。
- 与生成器一致，`errcode.Define` 的参数不是字面量、或含 errcode 导入的 Go 文件解析失败时，`roost id next / check`、`roost add`（需要分配或检查 ID 的种类）、doctor 的 ID 检查返回同一条错误（以前静默跳过）；这些工程 `roost generate` 本来就失败。
- 无持久格式、生成物变化。
