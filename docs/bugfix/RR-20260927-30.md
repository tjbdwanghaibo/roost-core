# RR-20260927-30 修复：`sameMutex` 按值判定可比较性，含装着 func 的接口字段的自定义 Mutex 不再 panic

问题：[RR-20260927-30](../bug/RR-20260927-30.md)（第六轮审计 N2 → OPEN-ITEMS 批次 13 追加）。日期 2026-09-27。基线 `a136c98`，分支 `fix-r8-b13`（在 RR-20260927-29 之后）。
状态：已修复，本地验证通过，本地提交，未推送 / 发布。codebase-memory 图谱过期（09-26），未使用；以当前源码为准。

## 根因（基线行号）

`entity/entity_guard.go:338` `sameMutex`：`ta == nil || (ta.Comparable() && a == b)`。`reflect.Type.Comparable` 只看类型：含接口字段的结构体在类型层面可比较，
接口里装着 func / slice / map 时 `a == b` 在运行期仍 panic（reflect 文档明写 “Even if Comparable returns true, the comparison may panic”）。
调用点：`holding`（`:317`，`RequireEntity` / `TryRequireEntity` / `GuardedEntity` 经它判断）与 `ReleaseEntityInstance` 的 superseded 查找（`:477`）。

## 决策

- 改为 `reflect.ValueOf(a).Comparable() && a == b`（Go 1.20+）。`Value.Comparable` 检查接口字段的动态值，并保证为 true 时 `v.Interface() == x` 对任意 x 都不 panic，
  所以只需判 `a`。类型不同的分支、`nil` 分支不变。
- 框架锁的快路径不变：`*lock.ReentrantMutex` 仍先按指针比较，不经反射。反射只在自定义 Mutex 上多检查一次值（结构体逐字段），与修前同一路径。
- 不可比较的值仍按“不是同一把锁”处理（RR-25 的定案）。未采用“在比较外 recover”：`Value.Comparable` 是标准库给的判定，不需要借 panic 做控制流。

## 文件与行为

- `entity/entity_guard.go`：`sameMutex` 判定与注释（RR-30、之前为什么错）。
- `entity/entity_guard_instance_promises_test.go`：`TestGuardCustomMutexWithFuncInInterfaceFieldDoesNotPanic`（`ifaceFieldMutex{hook any; id; mu}`，hook 装 func）。
  子用例 `RequireEntity` / `TryRequireEntity` / `GuardedEntity` / `ReleaseEntityInstance`（旧实例被取代后释放旧实例，走 `holding` 与 superseded 两处）：不 panic、各自的锁
  正确持有与归还；`comparable_value_in_interface_still_same_lock`：接口字段装可比较值、两份包装共用同一把不可重入底层锁时仍认出是同一把锁（不退化成各自加锁而自锁）。

测试形状说明：结构体 `==` 逐字段比较、遇到不等即停；hook 必须排在会不相等的字段之前才会被比较到，所以用例把 hook 放在第一个字段（审计探针靠共用底层锁让前面的字段相等）。

## 与审计探针的差异

审计探针 `TestAud8InterfaceFieldMutexValue` 让两份包装值共用**同一把不可重入的 `*sync.Mutex`**、hook 都装 func。修后它不再 panic，但会在
`RequireEntity(fresh)` 里自锁挂起：装着 func 的值无法判定是否同一把锁，按 RR-25 的定案当作不同的锁、为新实例再加一次锁。这正是 `sameMutex` 注释里 RR-25 已写明的边界
（“这种值类型若内部共用同一把不可重入的锁，第二次加锁会自锁——自定义 Mutex 应当用指针或可比较的值实现”）。清单给的两种修法（按值判定 / 比较外 recover）在这个形状上结果相同；
要让它不自锁只能“猜”两份不可比较的值是同一把锁，会把确实不同的锁当成已持有（RR-20260926-67 要防的就是这个），所以不做。回归用各自的底层锁验证“不 panic”这一承诺，
另用可比较的接口值验证共用底层锁仍被认出。

## 兼容性

无 API 变化。之前会 panic 的自定义 Mutex 现在按“不是同一把锁”处理；可比较的自定义 Mutex 行为不变。

- 共用同一把不可重入底层锁、又装着不可比较值的自定义 Mutex 会自锁（RR-25 既有边界，见上）。
