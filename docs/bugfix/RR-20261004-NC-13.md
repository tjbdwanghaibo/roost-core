# RR-20261004-NC-13：ReadThrough 读取与删除的 fatal 裁决

2026-10-04，基线`1502f97372139a238e73850ff7337b9454146f9e`。**已修复、声明场景验证、尚未发版。** [原问题](../bug/REVIEW-2026-10-04-noncore-10.md#rr-20261004-nc-13) · [本轮](../review/REVIEW-2026-10-04-noncore-11.md) · [证据/复跑](evidence/noncore-bugfix-20261004-06/README.md)。

## 根因与实现

[read_through.go](../../cache/read_through.go) 的loadOne原先只看IgnoreRemoteError，绕过FatalRemoteError；Delete同样吞掉错误并删除L1。Set和loader回写已有degradable分类。本轮Get复用degradable，fatal在调用loader和发布L1前返回；Delete先识别fatal并直接返回，保留L1。普通故障仍清掉L1：strict返回远端错误，IgnoreRemoteError吸收；没有将既有普通故障清理改成一律中止。

错误原样返回，wrapped errors.Is保留；指标继续计数。没有新增抽象、异步load、重试或改公开接口。未采用“返回错误但继续loader/删L1”，因为这仍会执行被权威拒绝的副作用。

## 红绿与兼容

修前正式21叶子中本RR Get/Delete两项失败：`fatal L2 verdict was degraded: <nil>`，Get产生loader/L1发布，Delete清掉L1。原Set控制通过。修后41项正式准入用例全部通过，新增Get/Delete×fatal-ignore/fatal-strict/outage-ignore/outage-strict/unclassified十项：wrapped原因、loader次数与L1副作用分别断言。

共同五包race/vet通过，186 test pass事件/170叶子、0fail/7环境skip；KitRedis无测试。七项Redis后续独占实测全绿，与此错误分类测试是不同证据。命令见证据，不把包测试当成全部消费者审完。

FatalRemoteError配置者的行为收紧：Get/Delete不再降级fatal，Delete不再因此清L1。未配置分类器的降级行为保持；本地命中仍不请求L2。已获成功或未知远端结果不在本修复中重做/回滚。真实网络、全局冷key容量和非协作loader关闭未验证。
