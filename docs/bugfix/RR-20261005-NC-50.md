# NC-50 修复：account 建角补偿失败重新计入 `rollback.failed`

[问题](../bug/RR-20261005-NC-50.md) · [证据](evidence/noncore-bugfix-20261005-revn06/README.md)。已修复、声明场景验证，未发版。

## 决策与实现

`kit/service/account/create_role.go` 新增 `compensated(err)`：补偿（`releaseCreationSlot`、外来 player id 时的 `Names.Cancel`）返回非 nil 时 `Dropped("rollback.failed", 1)`，原样返回错误。三处既有补偿与 RR-06 残余新增的换名释放都经过它。沿用历史事件名 `rollback.failed`（`docs/history/ledger.md` U-0021 的口径、`create_role_tail_test.go` 已在断言它），不新造名字；`Config.Metrics` 注释的承诺因此重新成立。`releaseCreationSlot` 把版本不符视为“别人已处理”返回 nil，不计失败。

不改错误返回、不加重试；不在 `Lookup` 失败（判死之前的读）时计 rollback——那不是补偿。

## 验证与边界

`TestAFailedReleaseOfADeadPlanIsCountedAndRetriedByTheNextName`、`TestAFailedReleaseOnTheSameNamePathIsCounted`：修前 `counted 0 times, want 1`（换名用例修前更早失败于“从未尝试释放”），修后 1；成功释放的用例断言 `rollback.failed`=0。Memory 与隔离真实 Redis 均通过。未核对其他服务的补偿失败计数；account / activity 没有 `Conflict` 上报属框架级口径，见本轮观察。

## 复核后的补修（2026-10-06，维护者决定 B9）

[问题补记](../bug/RR-20261005-NC-50.md#复核后的补修2026-10-06维护者决定-b9) · [方案](../feature/B9-C5-WINDOW-ENTRIES-ROLE-TABLE-2026-10-06.md)。`releaseCreationSlot` 改为返回 `(released, err)`：版本不符仍不是错误、不计 `rollback.failed`，但也不是“本次释放”；`plan_released` 只在本次真的删掉死计划时计。随 B9 建角判定表一起改（换名路径与同名重试被拒路径都经它）。`TestConcurrentReleasesOfOneDeadPlanCountOnce` 修前 2、修后 1，恰好一个请求建角成功、另一个 `ErrRoleLimit`，`rollback.failed`=0；`go test -race -count=3 ./kit/service/account/`。
