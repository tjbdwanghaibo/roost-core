# RR-20260917-04：platform 后台订单重试没有可用的候选入口（U-0234）

- 仓库：roost-kit `service/platform`
- 缺陷类：C4（装配缺口）
- 优先级：P2
- 相关：T-128；测试 `service/platform/pending_orders_promises_test.go`

## 问题

支付回调记录了订单、第一次发货临时失败；随后渠道不再回调，部署依赖 `Server` 的后台重试。
订单有剩余次数、退避已到期、发货服务已恢复——但 `run` 每 30 秒执行一次，
`retryOrders()` 固定返回 `nil`。该方法未导出，外包覆盖不了，`Server` / `Mod` / `Config` 都没有注入点；
注释写着"由部署提供订单列表"，但没有任何实现。一次可恢复的故障因此长期挂起，而且日志里没有任何痕迹。

## 根因

`Server` 是生成代码（`platform_rpc_assembly_gen.go`），不能加字段，所以候选来源只能落在手写的 `Service` 上——
但 `Config` 没有这一项。"空回调"看起来像"默认没有待办"，实际是"这条路没接通"。

## 方案

- 采用：**显式的可选 collaborator**。
  - `PendingOrders` 接口：`PendingOrders(ctx, limit) ([]string, error)`——**有界**（limit 是这一 tick 能用多少，
    来源自己分页）且**可报错**（读失败记日志、下一 tick 再来，不结束循环）。
  - `Config.Pending` + `Mod.WithPendingOrders(...)`：与 `NewMod` 的三个必填协作者分开——那三个没有安全默认，
    这一个有可辩护的"没有"（渠道会重投回调的部署不需要）。
  - `run` 改为向 `Service.pendingOrderIDs` 要这一 tick 的订单，并在**启动时说明自己处于哪种模式**：
    接了索引就说批量与间隔，没接就说"后台重试是关的，怎么打开"。关掉后台恢复必须是看得见的选择。
  - `RetryBatch = 128` 是那个界。
- 没采用：在 kit 里扫 Redis 枚举待发货订单。正是这个包拒绝做的无界扫描。
- 没采用：把候选来源做成必填参数。会破坏 `NewMod` 的签名，且"没有"是合法选择——只是不能是静默的。

## 改动

`service/platform/service.go`（`PendingOrders` 接口与 Func 适配、`Config.Pending`、`RetryBatch`、
`pendingOrderIDs`、`BackgroundRetryEnabled`）、`server_run.go`（从索引取候选、失败只记日志、启动时说明模式）、
`platform_mod.go`（`WithPendingOrders` 与传递）。

## 证明

修前：测试编译不过——`undefined: PendingOrders`，因为入口不存在；review 实测
`grants=0, State=reserved, Attempts=1`，业务时钟已过退避 55 秒，后台什么也没做。

修后（`pending_orders_promises_test.go` 四条）：配置了索引的服务把候选交给循环且是有界请求；
没配索引不报错但 `BackgroundRetryEnabled()` 为 false；索引报错被报告且下一次调用照常恢复；
**端到端**：回调 → 首次发货失败 → 渠道不再回调 → 推进时钟 → 从索引取到该订单 → `AttemptDelivery` 成功发货。
`go test ./service/platform` 全绿。

## 未做 / 边界

- 索引本身（持久 Delivering 段、重启续接、分页公平性、终态退休、与订单记录的恢复协议）是**部署的**，
  本轮只给出接入点与契约。review 建议里参考 activity 的"先登记、确认、对账"仍然适用，没有在 kit 里实现。
- `Server.run` 的真实 30 秒 ticker 没有在测试里跑（会让测试等半分钟）；测的是循环组合起来的那几件事。
- 外部发货结果不确定时的幂等仍由 `AttemptDelivery` 的预留/回执承担，本轮没有改。
