# NC-61 修复：属性组件把容器登记进事务回滚

[问题](../bug/RR-20261005-NC-61.md) · [证据](evidence/noncore-bugfix-20261005-n07/README.md) · [本轮](../review/REVIEW-2026-10-05-noncore-n07.md)。已修复、声明场景验证，未发版。

## 根因与修法

属性层是组件内存，Nest 的 undo / state 回滚只覆盖生成 DAO（`nest/rollback.go` `CaptureEntities` 只遍历实体与 DAO），组件没有登记逆操作。`demo/game/entities/player/attribute_component.go.tmpl` 新增 `captureRollback`：`LevelUp` 与 `RefreshGear` 在第一次改层之前调用，若当前有可回滚事务（`nest.CurrentRollbackTx()` 非空且策略不是 `RollbackNone`），复制所有层并 `tx.RecordUndo(component, attributeLayersUndo, ...)`。Nest 对同一 (owner, slot) 只保留第一次登记，所以一笔事务里先升级再换装也恢复到事务开始时的层。逆操作移除事务中新增的层、重装复制的层，与层里是什么无关。

用 `(*RollbackTx).RecordUndo` 而不是包级 `nest.RecordUndo`：后者只在 `rollback=undo` 下生效，方法在 `RollbackState` 下同样登记（`Rollback()` 不分策略倒序执行全部逆操作）。

未采用：
- 每次读时从 DAO 重建容器——Base 可由 `attr_base` 恢复，但会把一次组合变成每次读的成本，并改掉模板“容器是属性的家”的分工；
- 在框架 `attribute.Container` 里内建事务参与——框架半不依赖 nest，引入依赖会改变分层（`TestCoreDependencyBoundary`），且容器不知道哪些层该随哪笔事务；这条留作方向判断里的候选。

## 兼容

只改 game-demo 模板（生成物）。已生成的工程需要 `roost project sync` 或手工合入；成功路径行为不变。已经被污染的存量 `attr_base` 不会自动修正（等级与属性的对账需要业务决定，本轮不做迁移）。

## 验证

- 修前（生成工程 replace 到基线源码）：`TestAttributeLayersRollBackWithTheTransaction` 两叶子失败；持久后果“level 1 stored base HP 120, want 110”。
- 修后：生成工程 `go test -race -count=3 -run 'TestAttributeLayersRollBackWithTheTransaction|TestFinalIsBasePlusGear'` 通过；全新生成 game-demo build / vet 与 player / handler / attribute 包测试见本轮记录。
- 未验证：真实 WAL / Mongo 三进程链路；暂时性冲突重排重跑 handler 的路径只由同一 undo 机制推出，未单独写用例。

## 后续：回滚统一走 DAO（A1，2026-10-05）

本修复的组件内做法（组件 `captureRollback` 自己登记 undo）已被维护者决定 A1 取代：可回滚状态一律放进 DAO（属性三层 `attr_base` / 新增 `attr_gear` / `attr_final`，定时器 `timers` / `timer_seed` / 新增 `timer_next_due`），组件不持有状态、不登记 undo，派生值由加载与改源字段的事务写入。本记录的回归用例保留并在新实现上通过，另加两种回滚策略 × 两条失败路径的真实 Nest 派发组合用例。见[方案与实施记录](../feature/REFACTOR-2026-10-05-dao-unified-rollback.md)。
