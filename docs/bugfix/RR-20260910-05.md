# RR-20260910-05:category 引用业务包常量时生成物遗漏 import

**仓库 / 位置**:roost-codegen `internal/entity/parse.go`,`collectEntityImports`。
**修复单元**:U-0166(C2)。**定位文档**:TROUBLESHOOTING T-60。
**引入来源**:M-05(`category=` 进标记)本次新增的场景,不是历史缺陷。

## 问题

合法标记 `category=view.EntityCategoryPlayer`,而 `view` 只在 category 表达式里用到:
EntityKind 与字段都不需要它。源文件自己合法导入了 view。生成成功,消费者
`go test ./...` 失败:`player_gen_wire.go:25:14: undefined: view`。

**Go 的 import 作用域是单个文件**,源文件导入不能替代生成文件导入。

## 根因

`collectEntityImports` 逐项收集需要导入的限定包:EntityKind、SyncTopic、SyncPacker、
SubjectPacker、component 类型、dao 类型。M-05 把 category 加进标记时没有把它加进这份清单。

M-05 的测试只覆盖了 `entity.EntityCategoryPlayer` 这种 core 常量 —— 而 core 的 entity 包是
`buildImportBlock` 无条件导入的,所以恰好不缺 import,这个洞被绕过去了。

## 方案选择

只有一种修法:把 `ent.Category` 加进 `add()` 的清单。有选择的是**怎么防止同类再犯**:

- 断言生成物包含某个字符串。会漏掉"这次加了 category、下次加了别的字段"。
- **解析生成物,要求每一个 `pkg.Sel` 限定名都有对应 import(采用)**。这一类缺陷
  ——"用了某个包却没导入"——一次覆盖住,不管将来又往标记里加了什么。

## 改动

`internal/entity/parse.go`:`collectEntityImports` 增加 `add(ent.Category)`,注释写明 import
作用域是单文件、以及为什么源文件的导入不算。

## 证明

`internal/entity/category_import_promises_test.go`:构造一个 category 指向业务包常量、而该包
只在 category 表达式里出现的实体,生成后用 `go/parser` 解析生成物,遍历所有 `SelectorExpr`,
把每个未被 import 的限定名收集起来;非空即失败。另外单独断言 `view` 确实在 import 列表里。

修前红:

```text
generated wiring qualifies [view] without importing it
```

修后 codegen 全仓测试绿。

## 未做 / 边界

- 没有在测试里真正编译一个消费者模块(那需要临时 module 与 go.work)。解析级断言证明的是
  "生成物自洽",审查附录里的三模块消费者编译是更强的验收,可作为发版前的人工步骤。
- 自定义 import 别名(`foo "…/view"`)由同一条断言覆盖,因为它比较的是别名而不是路径末段。
