# RR-20261004-NC-22：Mongo替身嵌套复制隔离

2026-10-04，P3，起点 `ce90e90d`；**已修复、声明场景验证，未发版**。[原问题](../bug/REVIEW-2026-10-04-noncore-14.md#rr-20261004-nc-22) · [运行](../review/REVIEW-2026-10-04-noncore-15.md) · [红绿/完整矩阵](evidence/noncore-bugfix-20261004-08/README.md)。

## 根因与决定

cloneDoc顶层复制令嵌套M/D与快照、输出及写工作副本共用。

不采用反复Marshal/Unmarshal以免把已存M变回D并改变现有路径行为；复用输入真实codec归一后的值类型，未增加业务存储/新包。

## 改动与兼容

mongo/mongotest/mongotest.go在既有cloneDoc递归复制BSON M/D/A、maps/arrays、Binary、CodeWithScope、Raw/RawValue/bytes；保持容器形状，没有失败时退回浅复制。BSON标量保持值语义。

仅替身内部数据所有权收紧，签名/codec形状不变；输出修改不再改库存储。增加与可变数据大小相关的复制成本，无性能测量。
