# NC-263 修复：轮转失败继续写当前分片、1s 后再试；sink 逐个写；`log.rotate_failures` 与 `log.write_errors{sink}`

问题：[RR-20261005-NC-263](../bug/RR-20261005-NC-263.md)。分支 `revleft`，基线 `dc877c04`，[本轮](../review/REVIEW-2026-10-06-revleft.md)，[证据](evidence/noncore-bugfix-20261006-revleft/README.md)。

## 修复

- `rotation.go`：打开新分片失败时计 `log.rotate_failures`、记下 `retryAt = now + 1s`，`Write` 有当前分片就照常写入；重试间隔内不再尝试打开。首次打开（没有当前分片）失败仍返回错误。成功轮转后清零 `retryAt`。
- `log.go`：`io.MultiWriter` 换成 `fanOutWriter`，每行写给全部 sink，出错的 sink 计 `log.write_errors{sink=console|file}`，返回第一个错误。单 sink 也经它写，文件写失败（ENOSPC）同样可数。

未采用：失败时往 stderr 打一行提示——日志自身出错时再写日志容易递归，且 stderr 可能就是出错的 sink；改用指标，由 `/metrics` 观察。`log` 包新增对 `metrics`（只依赖标准库）的依赖，无环。

文件：`log/rotation.go`、`log/log.go`、`log/write_failure_promises_test.go`、`OBSERVABILITY.md`、`docs/TROUBLESHOOTING.md`（T-255）。

## 兼容

轮转失败期间的日志写进上一分片（文件名的时间段与内容不再严格对应，直到下一次重试成功）。新增两个计数器。没有配置变化。
