# RR-20260924-08 修复：用实际释放边界决定完成回调

[问题与修前证据](../bug/RR-20260924-08.md)。已修复，未提交、未发布。

RollbackTx 的公开 Commit 保持原语义，内部 `commit(entitiesReleased bool)` 明确区分是否已经完成统一释放。仅 pipelined 的 inline/queued/saturated 在统一解锁或等待解锁屏障之后传 true，直接逐项运行 AfterCommit、汇总错误，再回复和释放排序位置。

strict / memory / 独立调用继续通过 Commit 传 false，由 Guard 或远端批次安排原有完成时机。没有简单删除 Guard 回调机制，也没有把 setter 改成同步入口。

回归使用生产 NestDispatch：第一个回调 panic，后续回调和 TransactionReleased 仍各执行一次，三种路径都收到 ErrAfterCommitFailed。inline/saturated 修前红、修后绿，queued 作为兼容对照。既有完成顺序与队列满测试也通过。

完整验证与收口边界见 [Nest 截止复核](../feature/NEST-COMPLETION-2026-09-24.md#8-截止复核与收口结论)。本次只统一已解锁的 pipelined 完成语义，不扩大 strict / memory 路径原有 post-release 回调错误报告契约。
