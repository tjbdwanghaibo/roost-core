# RR-20260926-44 修复：未定稿的 Remote 批次 Abort 就地收尾，不再投递快池续行

问题：[RR-20260926-44](../bug/RR-20260926-44.md)（探针见 [REPRO-2026-09-26-04 §10](../bug/REPRO-2026-09-26-04.md)）。
日期 2026-09-26；实施基线 main `49f20ee`。状态：已修复、本地验证通过，已提交未推送/未发布。

## 根因

`remoteWriteBatch.Abort`（基线 `remoteentity/batch.go:475-507`）无条件 `entity.RunLocal`。`PrepareRemoteWriteBatch` 在慢阶段失败时
（`:88-98`：wrapper 容量耗尽、`beginWrite` 失败）调用 Abort，ctx 带慢阶段注入的本地执行器，RunLocal 于是经
`dispatchFastContinuation` 占一次快池续行；而此时批次没有任何已定稿的本地状态可回滚，也没有登记事务，快池续行只是空转。
Remote 争用（marker/锁/加载失败）越多，快池被这类空续行占用越多。`nest/msg.go` `finishRemoteWriteBatch` 在 handler 定稿前失败时同样走到这里。

## 决策

按修复约束：

- Abort 先在 `b.mu` 下看 `finalized`。**未定稿**：若尚未提交 / 不确定 / 关闭，就地置 `aborted`，直接返回，不走 RunLocal。
  未定稿意味着：`FinalizeLocked` 从未成功（其失败路径已在调用方持锁上下文内 `rollbackFinalizedLocked`），`b.outcome` 为空、没有登记事务，
  没有需要快阶段执行的本地回滚。标记与定稿共用 `b.mu`，之后的 `FinalizeLocked` 见 `aborted` 拒绝；写门与写许可仍由 `Close` 统一释放。
- **已定稿**：保持原逻辑——经 RunLocal 回到快阶段持锁回滚、置 aborted、把事务标为 Rejected；进入快阶段后重新检查状态
  （期间可能已提交 / 不确定 / 关闭）。

不改 `nest/msg.go`（另一组修复范围），调用方契约不变：Abort 之后照常 Close。

## 文件与行为

- `remoteentity/batch.go` `Abort`：增加未定稿就地分支与注释；已定稿分支未改。
- 回归 `remoteentity/batch_abort_local_test.go`（本地执行器计数替身，与 REPRO §10 探针同法）：
  - `TestPrepareRemoteWriteBatchFailureAbortsWithoutFastPoolHop`：单实体缺失、多实体（前一个已取得写权限、后一个缺失）两种 Prepare 失败，
    本地执行器 hops=0；随后能重新 Prepare 前一个实体（写门/锁已由 Close 释放），`WritesInFlight==0`；

    `ErrRemoteCommitNotFinalized`，重复 Abort 无副作用，Close 释放写许可；

## 兼容性

无 API / 配置变化。未定稿批次的 Abort 不再调用本地执行器（少一次快池续行）；已定稿批次行为不变。

## 对抗性自查：各失败点的回滚完整性与唯一收尾

| 失败点 | 定稿状态 | Abort 行为 | 本地回滚 | 事务登记 | 释放 |
| --- | --- | --- | --- | --- | --- |
| Prepare：wrapper 容量耗尽 / `beginWrite` 失败 | 未定稿 | 就地置 aborted | 无本地修改 | 无 | 随后 `Close` 释放已取得条目与写许可 |
| handler 在定稿前失败（`finishRemoteWriteBatch` 默认分支） | 未定稿 | 就地置 aborted | handler 的本地修改由 Nest 事务回滚负责，不经批次 | 无 | `Close` |
| `FinalizeLocked` 中途失败（build/validate/delete intent/track 失败） | 失败时已 `rollbackFinalizedLocked`，`finalized=false` | 就地置 aborted | 已在定稿持锁上下文内完成 | `trackRemoteTransaction` 失败时未登记 | `Close` |
| 定稿后被拒绝 / 业务失败 | 已定稿 | RunLocal 回快阶段持锁回滚（不变） | `RollbackRemoteCommit` | 标 Rejected（不变） | `Close` |
| 已提交 / 不确定 / 已关闭 | — | 无操作（不变） | — | — | 由 Commit / finalizer / Close 负责 |

- 就地分支与 `FinalizeLocked` 都在 `b.mu` 下读写 `finalized/aborted`，不存在“判定未定稿后被并发定稿”的窗口：先置 aborted 则定稿被拒；
  先定稿则 Abort 走快阶段回滚分支。
- 未定稿批次没有 `outcome.TransactionID`，原实现在此分支也不会 `completeRemoteTransaction`，收尾责任没有转移或遗失。
