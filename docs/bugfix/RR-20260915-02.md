# RR-20260915-02:重叠准备的视图已送达后,拒绝 Commit 仍可静默分叉

**仓库 / 位置**:roost-core `statesync/session.go`(`prepare` / `commitPrepared` / 新增 `pinView`),`statesync/replicator.go`(`prepareLatest`)。
**修复单元**:U-0205(C8)。**定位文档**:TROUBLESHOOTING T-99。关联 RR-20260914-10 / U-0200。

## 问题

同一 tick 的两个 PreparedFrame 都在任一 Commit 之前准备好:A 只含对象 1,兴趣变化后 B 含 1、2。A.Commit 成功;
自定义运输接受并交付了 B,客户端应用 B;B.Commit 按 U-0200 的规则返回 stale——符合"接受整批发送后才 Commit"的接口契约。
ACK(1) 被接受;服务端 `sent[1]` 是 A,客户端持有 B。tick 2 兴趣回到 A 的视图:A→A 的 delta 零变化,客户端 `ApplyDelta`
成功,仍多对象 2(反向则永远少对象 2),没有 `ErrObjectNotFound`,不会触发 resync。

## 根因

U-0200 把视图在**提交时**冻结,留下了"两次准备之间、第一次提交之前"的窗口——那里不同视图的第二帧可能已经在
线上。我在 U-0200 记录里写的"靠 delta 操作幂等 / 客户端 resync 收敛"是错的:幂等只保证已有操作重复安全,
生成不出服务端基线认为无需发送的创建 / 删除。审查的反例成立。

## 方案选择

- **发送前保证同 tick 视图唯一——在第一次投影时就钉住(采用)。** `prepareLatest` 投影完成后 `pinView`;同 tick 的
  后续 `prepare` 直接复用钉住的视图(与 U-0200 复用已提交视图是同一条路径)。`PrepareLatest` / `SendLatest` 都持
  `sendMu` 贯穿准备,所以投影 → 钉住是按会话串行的,不存在两个投影抢钉。于是 A 与 B 字节相同,哪一份被交付、
  哪一份被提交都无所谓。代价:兴趣 / 质量档变化对**已经准备过**的 tick 不再生效,顺延到下一 tick——U-0200 已经
  对"已提交的 tick"如此,这里补齐"仅准备过的 tick";`SetQualityTier` 的注释同步改。每会话只多保存一份快照。
- **提交被拒时进入恢复态(作为兜底一并做)。** `commitPrepared` 的"同 tick 不同视图 → stale"分支经 `PrepareLatest`
  已不可达,但对绕过它构造的帧仍保留,并在触发时 `forceFull = true; generation++`:该 tick 的基线已歧义,不能再当
  delta 基线,下一帧全量且作废所有在途的 PreparedFrame。
- **帧 / ACK 带修订号。** 协议变更,仍不在本轮范围;审查提到的"恢复帧之后旧在途报文的序号关系"本轮没有展开。

## 改动

`session.go`:`pinnedTick` / `pinnedView` / `pinned`;`prepare` 在 `sent[targetTick]` 缺失时查 pin;`pinView`;
`commitPrepared` 的分叉分支加恢复;`Close` 清 pin。`replicator.go`:非冻结路径投影后 `state.pinView(current)`;
`SetQualityTier` 注释。

## 证明

`statesync/pinned_view_promises_test.go`:
- `TestPrepareLatestPromiseOverlappingPreparesShareOneView`:审查的三个子例(多对象 / 少对象 / 显式全量对照),
  客户端应用的是第二份准备,最终对象数与服务端一致;
- `TestCommitPromiseRejectedDivergentViewForcesRecovery`:直接对 `SessionState` 提交一个分叉视图,被拒的同时
  `ForceFull` 置位,下一次 `prepare` 为全量(兜底路径只能这样测,记录在案)。

修前红:`stale commit followed by successful delta: objects=2 want=1 changes=0` / `objects=1 want=2 changes=0`;
兜底:`a refused divergent view left the ambiguous tick usable as a baseline`。修后 statesync 含 `-race` 全绿,
core 全仓 `-race` 全绿。
