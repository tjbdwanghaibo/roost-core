# RR-20260926-45 修复：禁止 remote=managed 实体使用 dbscope=sid 的 DAO（生成期 + 装配期双重校验）

问题：[RR-20260926-45](../bug/RR-20260926-45.md)。日期 2026-09-26；实施基线 main `49f20ee`。
状态：已修复、本地验证通过，已提交未推送/未发布。决策依据：维护者 2026-09-26 批准“禁止该组合”（见问题记录“修复约束”）。

## 根因

Remote 提交按 mutation 的 `DatabaseScope` 选库：`remoteentity/mongo_payload.go:36` → `MongoCommitter.dataDB`
（`mongo_committer.go:366-372`）在 scope=1 时 `DatabaseForSid(name, s.serverID)`，即**提交方**的 sid；加载经 DataEngine
（`dataengine/engine/mongo_store.go:272-273`）按**本服** ServerID 选库；权威 meta 在全局 controlDB。托管实体可被共享模式的任一进程写入、
所有权可迁移，payload 于是分散在多个 `db_<sid>`，另一进程加载到旧版本或缺失 → `ErrRemoteVersionConflict` / not found（`batch.go:268-273`），
实体不可写。codegen 对 DAO 只校验 `dbscope` 拼写（`codegen/internal/dao/gen.go:314-319`），不知道 DAO 被哪个实体使用；实体生成器不看 DAO 作用域；
运行时也没有任何校验。

## 决策

按修复约束两处拒绝，错误都给出“改 dbscope=global”的替代：

1. **生成期（codegen 实体生成器）**：`remote=managed` 实体的每个 DAO 字段，定位 DAO 所在包（同包或实体所在模块内的 import path，
   经 go.mod 映射到目录），读取 DAO 生成器写出的 `DbScope()` 方法；直接返回 `DatabaseServer` 即报错，整包不落 wire 文件。
   `roost generate` 先跑 dao 再跑 entity，读到的是本轮生成的 DAO。选在实体生成器而不是 DAO 生成器：DAO 定义（`db/def`）不知道被哪个实体引用，
   只有实体一侧同时知道 `remote=managed` 与 DAO 类型。
2. **装配期（`remoteentity.Assemble` 与 `Assembly.Start`）**：遍历实体注册表（`entity.GetAllEntityBuilders`）中 RemotePolicy 为 managed 的 kind，
   实例化其 `DaoBuilders`，DAO 实现 `entity.DatabaseScopedDao` 且返回 `DatabaseServer` 即拒绝，返回
   `ErrRemoteManagedServerScopedDAO`（可 `errors.Is`，多个违规用 `errors.Join` 汇总，信息含 kind、DAO 类型、集合名与替代写法）。
   Assemble 覆盖装配前已注册的实体，Start 在开始订阅/接收写入前复查装配之后注册的实体；手写 DAO 同样被拦下。

生成期无法判定时（DAO 位于模块外、源码不可读、`DbScope` 不是直接返回常量）不报错，交给装配期校验。

未采用：

- 在 `MongoCommitter` / 投影时拒绝 scope=1 的 mutation：那已是 WAL 准入之后，会把事务变成投影毒丸；而且会让已有 WAL 记录的重放失败。
  `DatabaseScope` 字段、WAL 编码与 `dataDB` 的 scope 分支原样保留。
- 在 `entity.ValidateEntityRegistry`（生成的 registry 聚合末尾调用）里校验：本组修复范围限定在 remoteentity 装配与 codegen；
  Assemble/Start 已覆盖同一注册表。可作为后续加固另议。
- 自动把 sid 改成 global：会改变既有数据所在库，属于破坏性迁移，交给业务决定。

## 仓内既有组合核对

`remote=managed` 的定义只有三处，均不是 sid：

| 位置 | DAO | 作用域 |
| --- | --- | --- |
| `demo/game/entities/guild/entity.go.tmpl`（game-demo Guild） | `demo/db/def/guild.go.tmpl` `//roost:dao coll=guild db=game` | 缺省 global |
| `codegen/internal/entity/testdata/remote/guild.go` | 同包手写 `GuildDAO`，无 `DbScope` | global |
| `codegen/internal/entity/testdata/remoteflow/vault.go`（`scripts/test-remote-generated.sh`） | `testdata/remoteflow/def/state.go` 两个 DAO | 显式 `dbscope=global` |

仓内 `dbscope=sid` 只出现在非托管实体 / 纯 DAO 夹具（`codegen/internal/dao/testdata/def/hero.go`、`codegen/internal/entity/testdata/syncmodes/def/state.go`）
与文档示例（`codegen/README.md`、`CODEGEN_REFERENCE.zh-CN.md`、`help.go` 的 players 示例），不受影响。remoteentity / nest / dataengine 单测里的
托管测试实体 DAO 均未声明 `DbScope`（global）；`nestwal/remote_codec_test.go` 的 `DatabaseScope: 1` 只测 WAL 编码往返，不经装配。

## 兼容性

- **行为收紧**：已有项目若把托管实体的 DAO 声明为 `dbscope=sid`，`roost generate` 会失败，Remote 装配 / 启动会返回
  `ErrRemoteManagedServerScopedDAO`。替代：改为 `dbscope=global`（缺省）并重新生成；已写入 `db_<sid>` 的数据需业务自行迁移到全局库。
  该组合在基线上跨服写或迁移后本就不可写（本问题），不存在可正常工作的既有部署被误伤。
- 生成物内容不变（校验不改模板）；无 WAL / 协议 / 配置变化。

## 对抗性自查：codegen / 装配校验不误伤合法组合

- 只对 `RemotePolicyManaged` 生效；`none`、`mirror`（只读缓存，不经 Remote 提交）不受影响——单测含 local/sid、mirror/sid。
- 未声明 `DbScope` 的 DAO（手写 / 旧生成物）按 global 处理，与 `dataengine.ResolveDatabaseScope` 的缺省一致。
- 生成期：DAO 在模块外、目录不存在或方法体不是直接返回常量时放行；模块内但源码有语法错误时报告解析错误（这类工程本就无法编译）。
  game-demo 实测：Guild DAO 缺省 global 时 `roost generate` / build / vet / test 全绿；临时把 `db/def/guild.go` 改为 `dbscope=sid` 后 `roost generate`
  在 entity 步骤拒绝并给出替代，恢复后重新生成正常。
- 装配期：DAO 工厂返回 nil 或工厂为 nil 时跳过；只在 Assemble / Start 各跑一次，按注册的托管 kind 数实例化 DAO，不在写路径上。

## 未验证项

- 没有在真实多进程共享模式下复现“sid 作用域导致迁移后不可写”的原始故障（问题为源码判定）；本修复只阻止该组合被生成 / 装配。
- 没有覆盖“注册的 DaoBuilders 与实体实际持有的 DAO 不一致”的手写实体：Remote 提交里 mutation 的 `DatabaseScope` 来自实体实际 DAO，
  若手写实体漏报工厂，装配校验看不到；提交路径（`FinalizeLocked` / `RemoteCommit.Validate`）未加拒绝，属于本组范围外的后续加固点。
