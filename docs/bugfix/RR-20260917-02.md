# RR-20260917-02：ScoreWindow 的距离与窗口算术溢出

**仓库 / 位置**：roost-core `service/match/grouping.go`（`ScoreWindowGrouping.Group`、原 `absInt64`）。
**修复单元**：U-0222（C2）。**定位文档**：TROUBLESHOOTING T-116。

## 问题

距离用 `absInt64(a-b)`：0 与 MinInt64 相减回绕、`abs(MinInt64)` 仍为负 → 远端进窗口且排序把它排到锚点前；MaxInt64 与 MinInt64
相减回绕成小距离。窗口 `Initial + Widen*waited` 先溢出为负再与 MaxWindow 比较，cap 失效（该成组的不成组）。Score 是调用方语义的 int64，
API 未限区间，通用实现不能把回绕当合法距离。

## 方案选择

- 改浮点：大整数丢精度。不采用。
- 先有符号相减再转 uint64：回绕已发生。不采用。
- **采用**：`scoreDistance(a,b) uint64`——大者在左做无符号减（int64 之差必落在 uint64 内，二补码减法恰好得到它）；筛选与排序共用它。
  窗口在 uint64 里做**饱和**乘加，最后 cap；配置合同明确非负：`InitialWindow` / `WidenPerSecond` / `MaxWindow` 任一为负返回
  `ErrQueueInvalid`。时钟回拨（waited<0）视作 0。

## 改动

- `grouping.go`：`Group` 校验 + `window(waited)` + `scoreDistance`；删 `absInt64`。
- 测试：`score_window_overflow_promises_test.go`（审查表四个溢出场景 + 常规近 / 远 / 负分 / 回拨；排序按真实距离；负配置拒绝）。

## 证明

- 修前：`zero vs MinInt64 outside a window of 10: formed=true, want false`；`the far candidate sorted ahead of the near one: far anchor`；
  `{InitialWindow:-1 …} accepted: <nil>`。
- 修后：`service/match` `-race` 绿。

## 未做 / 边界

- **行为变化**：负窗口配置以前被静默接受（等价于"永不成组"或未定义），现在报错；demo 用 FirstCome，不受影响。已随 core v1.15.6 发出。
