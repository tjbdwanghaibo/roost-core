# NC-181 修复：RangeAll / RangeWithCursorCnt 在回调返回 false 时跨桶停止

[问题](../bug/RR-20261005-NC-181.md) · [证据](evidence/noncore-bugfix-20261005-revn13/README.md) · [本轮](../review/REVIEW-2026-10-05-n13.md)。已修复、声明场景验证，未发版。

## 根因与修法

`container/bucket.go` 的 `RangeAll` 不知道 `Bucket.Range` 因 false 提前结束，接着遍历下一个桶。新增包内 `rangeBucket`，包一层回调记录“是否要求停止”；`RangeAll` 与 `RangeWithCursorCnt` 见到停止即返回。`RangeWithCursorCnt` 的游标照常跨过已开始遍历的桶（下一次从下一个桶开始），零调用方，一并按“立即停止”处理。

`Bucket.Range` 签名不变（不加返回值），避免改公开 API。

## 兼容

回调返回 false 的调用方少收到后续调用；正式调用方 `kit/statslog` 总是返回 true，不受影响。

## 验证

- 修前：`TestRangeAllStopsAtTheFirstFalse` 8 次、entity 组合叶 `false stops Range and RangeByCategory` 4 次（[原文](evidence/noncore-bugfix-20261005-revn13/red.txt)）。
- 修后：两条通过；`go test -race -count=3 ./container ./lock ./entity` 通过。
