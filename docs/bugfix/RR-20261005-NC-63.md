# NC-63 修复：errcode 扫描读不懂的 Define 一律失败，并查重名

[问题](../bug/RR-20261005-NC-63.md) · [证据](evidence/noncore-bugfix-20261005-n07/README.md) · [本轮](../review/REVIEW-2026-10-05-noncore-n07.md)。已修复、声明场景验证，未发版。

## 修法

`codegen/internal/errcode/main.go`：

- 按文件解析 `github.com/tjbdwanghaibo/roost-core/errcode` 的本地名（默认 `errcode`、别名、`.` 点导入；空白导入跳过；文件没有任何 import 时沿用原来的 `errcode.` 匹配）；
- 匹配到的 `Define` 调用若编号不是整数字面量、名字或消息不是字符串字面量，返回 `file:line: errcode.Define must be called with integer and string literals ...`，不再跳过；
- 在重复 code 之后再查重复 name，报两边的编号与文件。

## 兼容

业务工程里用常量编号 / 名字、或以别名导入后用常量的 `Define`，下次 `roost generate`（errcode 生成器）会失败并指出位置，需要改成字面量——这正是使用说明一直写的要求。字面量定义（生成的 game-demo 全部 21 处）结果不变。框架 kit/service 的常量定义不在业务工程扫描根内，不受影响。

## 残余

`roost id check / next errcode`（`codegen/internal/roost/id.go:15`）仍用 `errcode\.Define\(\s*([0-9]+)` 正则，别名导入的字面量编号不进占用表；errcode 生成器现在会在 generate 时报出由此造成的重复。是否让 id 扫描也走 AST 留给 N08。

## 验证

- 修前：`TestExtractDefinitionsRefusesWhatItCannotRead` 5 叶子全部被接受。
- 修后：5 叶子 + 字面量 / 别名 / 点导入控制通过，原有 3 个用例不变；`go test -race -count=3 ./codegen/internal/errcode/`，以及对全新生成的 game-demo 跑 errcode 生成器的结果见本轮记录。
