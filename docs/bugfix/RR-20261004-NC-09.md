# RR-20261004-NC-09：RPC 停止预算与回调排空所有权

2026-10-04，起点`e62729ac`。[原问题](../bug/REVIEW-2026-10-04-noncore-06.md#rr-20261004-nc-09)。**已修、声明场景验证，未发版。**

修前已确认callback进入后，已取消ctx下Assembly.Close在100ms内不返回，放行callback后才返回nil。只替换最后pool.Stop无法覆盖pending遍历内的同步fallback；只将停止扔到每次调用的新goroutine则会失去资源责任。

RPCClient新增StopWithContext：sync.Once关闭准入并启动**每实例唯一**停止任务，stopDone支持后续/并发重复等待；取消只让caller返回。停止任务取消pending、等待终态回调，然后复用Pool.StopWithContext排空。callbackMu将pending准入和LoadAndDelete后的terminal计数与关闭串联；先登记责任再释放锁，rpcTask的once guard只在第一次实际完成时释放计数。reply/timeout已经删除pending但正在执行队列拒绝fallback的回调也属于停止责任；锁内不执行业务、不等待pool或做网络I/O。

停止任务中的fallback panic以既有goroutine.SafeFunc独立隔离，不中断后续pending取消。Assembly.Close传递ctx，callback等待失败保留Assembly/连接，重试同一对象；KitNats只在Bus/Assembly实际成功结束后释放引用，Bus失败时先返回，不提前关闭它仍使用的连接。IRpc没有新增必选方法，原Stop仍为无期限排空，重复Stop现在等待同一任务。

新增控制覆盖满256队列/阻塞fallback、取消后重试、16个并发等待、callback内可取消的自身停止等待、fallback panic后其他pending，以及在停止前已被其他goroutine领取的终态。原唯一完成竞争和100k既有回归保留。28正式叶子、17原overlay、六包race/vet通过；[证据](evidence/noncore-bugfix-20261004-04/README.md)。

**限制**：业务callback必须最终退出；永久阻塞会保留唯一停止任务和资源，不伪装结束。callback内不能用Stop/Background同步等待自身，应只请求停止并采用可取消等待，由外部生命周期最终排空。Kit生命周期由App串行调用，本次没有把Mod改成任意并发Start/Stop安全。没有真实connected Assembly/Kit stop、断线重连、多机HA或吞吐实测；新增短锁与计数成本尚未bench，不把100k功能回归当性能结论。

## 复核后的补修（2026-10-04，A 线）

复审（[REVIEW-2026-10-04-nc-audit-2](../review/REVIEW-2026-10-04-nc-audit-2.md) §3 D2，登记为 [RR-20261004-07](../bug/RR-20261004-07.md)）指出上文“KitNats 只在 Bus/Assembly 实际成功结束后释放引用”与 CHANGELOG “取消后保留资源供再次排空”在 Bus 一侧不成立：`Bus.StopWithContext` 第一次就丢了 pool 并缓存超时错误，重试永远失败，Assembly 永不关闭。补修见 [RR-20261004-07](RR-20261004-07.md)：

- `Bus.StopWithContext` 现在可重新等待同一次排空，ctx 错误不再是终态；NatsMod 只在 ctx 错误时保留 bus / asm，Bus 终态错误照常关闭 Assembly。“取消后保留资源供再次排空”现在对 Bus 与 Assembly 都成立。
- 上文“重复 Stop 现在等待同一任务”更正为：**`RPCClient.Stop()` 在停止已发起时立即返回**（恢复本修复之前的语义，复审 S2：callback 内 `Stop()` 曾永久自锁）；重复等待同一任务用 `StopWithContext`。
- 复审 S1：`drainCallbacks` 的 `Wait` 前缺锁屏障是真实窗口（加测试缝后确定性复现：`StopWithContext` 返回 nil 时被 Range 跳过的终态 callback 尚未执行），已加 `callbackMu` 屏障并改正注释。
- 复审 S4：`TestRPCBudgetStopRetainsFullQueueFallbackAndAllowsRetry` 回退实现后改为 2s 内断言失败，不再挂到 `-timeout`。
