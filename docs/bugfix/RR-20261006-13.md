# RR-20261006-13 修复：glsvet A1 提示跟进一层同包 helper 函数

问题：[RR-20261006-13](../bug/RR-20261006-13.md)。基线 `87d8d91e`，分支 `fixn`，未发版。

## 做法

与停止类函数提示（`cmd/glsvet/stophints.go`）同样跟进一层：`packageUndoHelpers` 先收集同包里**直接**调用 `RecordUndo` / `RecordUndoToken` / `DeferRollback` 的包级函数；组件方法里以 `f(...)` 形式调用这样的函数时，在调用处打印

```
<pos>: hint: component BuffComponent.push registers undo through rememberPop (RecordUndo); keep transaction state in the DAO ...
```

仍然只是提示，不计入 findings、不改退出码。

取舍：

- **只跟包级函数，不跟方法调用 `x.f()`**：没有类型信息时按名字匹配方法，组件调 DAO 的 setter（`c.dao.SetLevel(v)`，DAO 方法自己登记 undo，是 A1 要求的写法）会撞上 DAO 的 `SetLevel` 被误报。组件自己的方法（`c.f()`）已经各自被直接检查，跟进它们只会重复提示。
- **只跟一层**：与 stophints 一致；两层以上的链（`outer → rememberPop`）不提示，回归里钉住。更深的跟进需要调用图，误报和成本都上去，A1 是提示不是门禁。
- 名字本身就是 `RecordUndo` 等的包级包装函数已经被直接检查命中，不再当 helper 重复提示。

## 未覆盖（不属于本修复）

同一段源码观察还提到“组件字段持有可变状态但根本不登记 undo（直接漏回滚）”没有自动检查。那是缺少登记而不是登记的位置不对，语法检查分不出“事务会改的字段”和组件只读配置 / 缓存，按名字或类型猜误报率很高；A1 靠规范、生成形状与组件骨架约束，本修复不处理。
