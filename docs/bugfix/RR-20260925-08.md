# RR-20260925-08 修复：独立计算执行额度与等待预算

[问题](../bug/RR-20260925-08.md) · [双池复核](../review/NEST-FAST-SLOW-2026-09-25.md)

`nest/dispatch_queue.go` 在准入时先检查全部目标 ID 的前驱；无前驱且存在执行额度时，为就绪请求预留额度，其余请求受整池 QueueCap 限制。增加就绪/执行中计数，取任务和完成任务时在同一调度锁下维护。拒绝请求不会修改 ID 尾指针或后继列表。

等待长度排除已经预留外部执行额度的就绪请求；所有 ID 前驱等待始终计入。每池外部请求总预算不超过 Workers + QueueCap。内部快延续继续独立计数、与外部就绪请求交替服务，不再占一次外部执行额度；预留额度是逻辑准入许可，并不保证抢占正在执行的内部延续。

`nest/worker_budget_test.go` 覆盖突发、热点与独立 ID 混合、真实 1024 worker / 16 等待位排空。修前失败、修后通过；七包 race/vet 通过，相关边界 race ×20 通过，日志见复核记录。没有更改默认并发值、持久化协议、显式 ID 顺序或慢阶段禁止本地业务锁的契约。

兼容影响：QueueCap 仍是整池等待预算，Stats.QueueLen 现在也排除已预留执行额度的就绪消息。配置很小的队列时能接纳更多独立并发请求；下游压力受 Workers 控制，不能把 QueueCap 当作全部在途上限。本轮未重跑真实 Remote 性能负载，旧性能证据仅作基线。
