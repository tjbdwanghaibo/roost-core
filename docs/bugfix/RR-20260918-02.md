# RR-20260918-02：RoomBroadcaster 隐藏的 coordinator 无法接入持久化水位（U-0233）

- 仓库：roost-core `room`
- 缺陷类：C4（装配缺口）
- 优先级：P2（仅 pipelined 提交部署）
- 相关：T-127；测试 `room/durable_watermark_promises_test.go`

## 问题

`EntityBase.LastCommitLSN` 的契约是：尚未达到 committer durable 水位的内容不外发。
`entitysync.SubscriptionCoordinator` 早就有 `SetDurableWatermark`，但 `RoomBroadcaster` **自己 new 了一个
coordinator 并私有持有**，`RoomBroadcasterConfig` / `RoomManagerConfig` 都没有水位源字段，内部也不安装。
于是走默认房间链的部署拿不到这道屏障：首次订阅快照、单体 flush、批量 flush 三条路径都会把尚未持久的内容发出去。

## 根因

能力存在、装配不存在。房间在构造函数里建 coordinator（`room_broadcast.go` 的 `NewRoomBroadcaster`），
这本身是对的（不该暴露一个可变裸指针），但既然它独占这个 coordinator，就得由它的配置把水位源转交进去。

## 方案

- 采用：`RoomBroadcasterConfig.DurableWatermark func() uint64` 与 `RoomManagerConfig.DurableWatermark`，
  在**房间可被订阅、可启动 worker 之前**装进内部 coordinator。管理器把它传给它创建的每个房间——
  部署只写一次。nil 表示无门，正是同步持久提交的情形。
- 没采用：另建一个平行 coordinator。review 已经明确否掉，房间本来就有一个。
- 没采用：暴露 `Coordinator()` 让调用方自己装。那是把可变裸指针交出去，任何人都能在运行中改掉屏障。

## 改动

`room/room_broadcast.go`（配置字段 + 构造时安装）、`room/room_manager.go`（配置字段 + 传给每个房间）。

## 证明

红的形式是**这个入口不存在**：加上测试后 `room` 包编译不过（`unknown field DurableWatermark in struct literal of
type RoomBroadcasterConfig` / `RoomManagerConfig`）；review 那一轮用真实生成实体测得的行为是三条路径各放行 1 帧，
而同一个实体接上真实 coordinator 的水位函数后三条全部拦下。

修后（`room/durable_watermark_promises_test.go` 三条）：

- 水位 9、实体 LastCommitLSN 10：`Subscribe` 返回可识别的 `entitysync.ErrDurabilityDeferred`，
  单体 flush 静默跳过（那是 tick 自己的路径，推迟不算错误），批量 flush 把推迟作为错误抛出；三条都没有帧出去。
- 水位推到 10：订阅成功、批量 flush 把内容发出去。
- 没有配置水位的房间照常立即投递（同步持久提交的部署）。
- 管理器配置的水位对它创建的房间生效。

`go test ./room ./entitysync -race` 全绿。

## 未做 / 边界

- 没有"pipelined 装配漏配水位时拒绝启动"的校验：房间不知道部署是不是 pipelined 的。review 建议里的这一条留给
  装配层（kit）——它知道 committer 是哪种。
- 测试用受控水位模型与记录型 sink，**不是**真实 WAL group-commit / 断电 / 网络到达测试。
- 与 RR-20260915-03 的关系不变：那条是 coordinator 已配水位时某些分支漏检查，本条是上层没有安装入口。
