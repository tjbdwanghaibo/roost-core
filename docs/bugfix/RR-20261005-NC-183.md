# NC-183 修复：TaskPool 的受理与关闭互斥

[问题](../bug/RR-20261005-NC-183.md) · [证据](evidence/noncore-bugfix-20261005-revn13/README.md) · [本轮](../review/REVIEW-2026-10-05-n13.md)。已修复、声明场景验证，未发版。

## 根因与修法

`goroutine/task_pool.go` 的 `taskWorker.submitTask` 先读 `closed` 再非阻塞发送，`close()` 先置 `closed` 再关 channel，两步之间没有互斥。给 `taskWorker` 加 `closeMu sync.RWMutex`：`submitTask` 在读锁内检查 `closed` 并做非阻塞发送，`close()` 在写锁内置 `closed` 并关闭 channel——与 `worker.Worker.closeMu`（`worker/worker.go:89-112`）同一做法。受理即已进入 channel，worker 的 `range` 会把它排空执行；关闭之后的 Submit 返回 `worker[i] is closed`。

## 兼容

公开 API 不变；Submit 多一次无竞争读锁。仓内零调用方。
