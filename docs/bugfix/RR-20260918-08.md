# RR-20260918-08：一个观察者能订阅多少格没有上界

- 单元：U-0240 · 缺陷类 C6（常量指标 / 无界资源）· 等级 P2
- 仓库：roost-core `spatial`
- 排障行：T-134

## 问题

`InterestConfig.validate` 校验半径与分带，`BlockIndex` 限制**整图**格数，但没有任何一处限制
**单个观察者**订阅的格数——而那才是 `resubscribe` 每次观察者移动都要差分的集合。

`Bounds 10000×10000`、`BlockSize 10`、`EnterRadius 900`、`LeaveRadius 1000` 是一份合法配置，
构造成功、加观察者成功，实际登记 **40,401 个 block**（每格两处 map 条目）。配错了不报错，只是慢慢变慢。

## 根因

格数是 `(⌈2·LeaveRadius/BlockSize⌉+1)²`，即**比值**决定成本；而校验只看了两个半径各自的合法性。
增量 AOI 的全部收益（主体移动只惊动一格的订阅者）在比值失衡时被观察者侧的差分成本吃光，
且没有任何信号告诉部署方。对照 cube 的 `BlockAOI` 拦的是单个观察者的**窗口面积**（`MaxAOIArea`），
roost 拦的是整图格数——两道闸防的不是同一件事。

## 方案选择

- **（选中）`InterestConfig.MaxObserverBlocks` + 构造时按最坏情况拒绝**。最坏情况是**算出来的**不是采样的：
  一个只在"某个位置不好的观察者到来时"才拒绝的检查，会通过所有启动检查然后在生产里拒绝。
  算式用饱和加法，半径接近 int64 上限时答"巨大"而不是回绕成"很小"；box 同时被地图裁剪，
  所以小地图不会因为大半径而被判超限。默认 `DefaultMaxObserverBlocks = 1024`（与既有 AOI 的经验值一致），
  但它是**配置**：真想要大视野的部署写明白，而不是在生产里发现代价。
- 只在运行时告警：审查点名不接受——代价是渐进的，告警会被淹没。
- 按 LeaveRadius 自动推导 BlockSize：更激进，且会让"格边长"这个部署自己该定的参数变成框架决定。

## 改动

roost-core `spatial/interest.go`：`ErrInterestBudget`、`InterestConfig.MaxObserverBlocks`、
`DefaultMaxObserverBlocks`、`worstObserverBlocks()` / `boundedSides()`，接进 `validate()`。
`BlockSize <= 0` 时跳过该检查，让 `NewBlockIndex` 报它自己的错——否则会用一个不存在的网格的预算
盖住真正的原因（这条是写测试时发现的，两条既有守卫测试先红了一次）。

## 证明

`spatial/observer_budget_promises_test.go` 四条：

- `TestObserverBlockBudgetRefusesARatioThatSubscribesTheWholeMap`：审查那份配置必须被 `ErrInterestBudget` 拒。
- `TestObserverBlockBudgetIsConfigurable`：显式给足预算则放行。
- `TestTheNineBlockShapeFitsTheDefaultBudget`：格边长≈视野半径的经典形状不受影响（≤16 格）。
- `TestObserverBlockBudgetSaturatesInsteadOfWrapping`：半径接近上限时不回绕。

修前：前两条编译不过（`undefined: ErrInterestBudget` / `unknown field MaxObserverBlocks`），
按审查的复现路径构造则实测 40,401 格被接受。修后 `go test -race ./spatial ./entitysync ./room` 全绿。

## 未做 / 边界

- **没有暴露运行指标**。审查建议"同时暴露实际 block 数分布，便于发现接近上限的配置"——没做，
  因为 `spatial` 现在完全不依赖 metrics，加它要先定这个包要不要有观测面。留作后续。
- `InterestCluster` 走同一个 `InterestConfig`，所以它也被这条预算覆盖；但**跨房间镜像的观察者**
  是否该按每房间还是合计计预算，没有单独考虑。
- 默认值 1024 是沿用经验值，不是测出来的。
