## 根因与实现

Runner 原先把 `Migrator.Migrate` 的 nil error 当成可提交证明；目标 DAO 的类型解码位于提交、投影、重读之后。字段类型错误会污染权威记录，坏 BSON/身份会留下无法投影的 WAL。

历史 `dataengine/engine/migration_runner.go` 的 `MigrationRunner.Migrate` L59～85 在生成事务 ID / CommitSystem 之前增加三个检查：

1. 候选实现现有 `entity.PersistedDaoLoader` 和 `Id() int64`，缺能力返回 `ErrMigrationUnsupported`。
2. 解码 BSON、复用 MongoStore 的 `documentInt64` 身份比较。int32/int64 兼容行为保留，缺 `_id` 或不同 ID 返回包裹 `dataengine.ErrInvalidDocumentKey` 的错误。
3. 用目标 schema、旧持久 version 调 `RestorePersisted`，随后再检查候选 `Id()`。目标 schema 避免再次调用迁移，旧 version 不假装下一版本已经投影。解码错误保留 `errors.Is` 根因。

仍然执行原来的 strict SystemCommit → WaitProjection → 整聚合重读。没有改 CAS、WAL 格式、schema/version 归一化、Remote 信封拒绝或 Repository 发布顺序。没有反射加载器、新保存入口或自动重试抽象。

使用 `Id()` 的最小结构契约，而非要求整个 DaoInterface，避免与验证无关的 DbName/Dirty 方法限制已有迁移消费者。Repository 创建的 DAO 是未发布候选；直接调用 Runner 的应用也必须使用候选，不能传在线对象，失败后丢弃它。预校验可能修改候选字段/tracker，**不承诺候选内存回滚**。

未采用“只检查 BSON”：不能查目标业务字段类型；未采用“先提交再回滚”：持久结果可能未知，且坏 WAL 已进入恢复链；未采用“全聚合一次迁移事务”：属于额外语义改变。本次沿用逐 DAO 提交，有效前序迁移不因后序失败而回滚。

## 兼容性、设计与风险

公开签名、生成物、持久格式不变。**行为收紧**：手写 DAO 不能再仅声明 Descriptor/Migrator 就持久提交，必须提供目标装载和解码身份能力；当前 schema 的无提交路径仍可直接返回 false。Loader 收到目标 schema 后不应二次迁移，业务迁移步骤仍必须幂等、可测试。

冷加载增加一次 BSON/目标类型预解码，属于防止不可恢复准入的成本；热实体访问不经过该路径。本轮没有吞吐/分配 benchmark，不宣称性能改善；保留原有全聚合重读和每 DAO 一笔提交的往返成本。

修复只防止新增坏迁移进入 WAL。已污染文档/已准入坏 WAL 需备份、定位版本和事务后制定具名恢复方案；没有自动跳过、删除或生产数据迁移。真实 Mongo replica set、网络未知结果、HA、真实部署掉电与长期容量未验。17 历史外部 skip 不能由本轮正常单测关闭。更细范围和后续见[接续 review](../review/REVIEW-2026-10-05-noncore-21.md)。
