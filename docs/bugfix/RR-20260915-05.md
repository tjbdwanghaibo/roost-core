# RR-20260915-05:SetDownstream 未迁移慢消费者回调,替换后剔除不清理 room 订阅

**仓库 / 位置**:roost-core `room/room_broadcast.go`,`RoomBroadcaster.SetDownstream`(对照 `NewRoomBroadcaster` 的注册与 `Close` 的解注册)。
**修复单元**:U-0208(C8)。**定位文档**:TROUBLESHOOTING T-102。

## 问题

`NewRoomBroadcaster` 向初始 sink 注册 `handleSlowConsumer`(默认剔除 → room 退订、释放名额),`Close` 用保存的
`unregisterSlowConsumer` 解注册;`SetDownstream` 却只换 `envelopeSink.downstream`。替换后:新 sink 没有本 room 的
回调——它正常剔除、跑完自己的 `OnSlowConsumer`,room 里的订阅原封不动;旧 sink 的回调一直保留到 `room.Close`,
还持有 room 引用。审查刻意在第一次订阅之前替换,排除了传输基线热迁移这个额外前提。

## 根因

构造路径把"注册回调"当成 downstream 的一部分,替换路径没有(C8:两条建立 downstream 的路径对同一件事的处理不同)。

## 方案选择

- **让 sink 侧的回调查找不按 room 注册、改成广播给所有 sink。** 打散了现有的按 room 注册模型,也没解决旧 sink 残留。
- **替换当作一次交接(采用)。** 顺序:同一实例直接返回(不重复注册);新 sink 若实现 `roomSlowConsumerLifecycle`
  先注册,失败则返回错误、旧 sink 与旧回调原样保留;成功后切换 `downstream`、调用旧的 unregister、接管新的
  unregister 所有权。整段在 `lifecycleMu` 写锁内,与 `Close` 里对 `unregisterSlowConsumer` 的使用同锁。同实例判断
  用 `sameRoomFrameSink`(按动态类型可比较性保护,func 类型的 sink 不会 panic)。

## 改动

`room/room_broadcast.go`:`RoomEnvelopeSink.currentDownstream`、`sameRoomFrameSink`、把匿名接口抽成
`roomSlowConsumerLifecycle`(构造处复用),`SetDownstream` 改为交接。

## 证明

`room/downstream_handover_promises_test.go`:
- `TestSetDownstreamPromiseHandsOverTheSlowConsumerHandler`:审查的三个子例(初始 sink 对照 / 订阅前替换后新 sink
  剔除应清掉订阅 / 旧 sink 不再持有该 room 回调,新 sink 恰好一个);
- `TestSetDownstreamPromiseIsIdempotentAndKeepsTheOldSinkOnFailure`:同一实例重复设置注册数不变;已关闭的新 sink
  拒绝注册 → SetDownstream 报错、旧注册仍在、旧 sink 仍是 downstream。

修前红:`new sink callback finished but stale membership=[{… SubjectID:101 …}]`、`old sink still holds 1 room callback
after replacement`、`a sink that refuses the room handler must not be installed`。修后 room 含 `-race` 全绿,core 全仓
`-race` 全绿。

## 未做 / 边界

- 旧 sink 上已经入队、尚未执行的回调在解注册后仍可能跑一次 `handleSlowConsumer`(退订一个旧 sink 已剔除的订阅者,
  方向是对的);没有加 generation 校验。
- 已有传输基线(`RoomTransportSink.rooms`)不随替换迁移——那是审查也单独列出的另一前提,本单元不涉及。
