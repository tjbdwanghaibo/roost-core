# RR-20260924-10：Outbox 统一启停状态

[问题](../bug/RR-20260924-10.md)。2026-09-24；已修复并验证，未发布。

用同一生命周期 Mutex 保护 closed 与 cancel，替代互不协调的 startOnce/closeOnce。Start 在 closed 或已有 cancel 时返回；Close 设置终态，并根据是否已经启动选择取消 run 或直接关闭 done。等待退出在锁外，保留各调用 context 的截止时间和重复 Close 的等待责任。

| 状态 | Start | Close | done 的关闭者 |
| --- | --- | --- | --- |
| 尚未启动 | 安装 cancel，启动唯一 run | 进入 closed | 未启动时的 Close |
| 已启动 | 幂等返回 | 取消 run 并等待 | run |
| 已关闭/关闭中 | 不再启动 | 等待同一 done | 保持原责任 |

不改变 Outbox claim/lease、重试、Broker 去重或业务 effect 契约；不新增包。

修前 `TestOutboxCloseBeforeStartIsTerminal` panic；修后 close-before-start 和 100 轮并发启停 `-race` 通过（1.660s）。DataEngine、engine、nestwal、remoteentity、kit/dataengine、kit/nest 六包 race 通过；既有关闭超时后重试、Outbox 发布失败/恢复等测试同时保留。实际集成与整体优化范围见 [DataEngine 方案](../feature/REFACTOR-2026-09-24-dataengine.md)。
