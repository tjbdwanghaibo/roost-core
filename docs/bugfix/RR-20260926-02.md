# RR-20260926-02 修复记录

对应[问题](../bug/RR-20260926-02.md)。

Nest 在 runNestLogic 中安装仅供当前消息使用的 loadedGetter。约束只包装实体访问的 context，
保留 handler 收到的原始请求 context 身份、取消和超时。GetMany 同样约束；preparedGetter
回退与动态 Cast 都不能绕过。慢准备先用原始 Getter 加载声明目标，再交回快池。

ManagerAccess 缺失目标且配置了 loader 时返回可 errors.Is 判断的 ErrColdLoadInLogic，
不启动 I/O、不启动 GetMany 加载 worker、不等待 singleflight。已有实体保持内存访问；
未配置 loader 时仍保留原来的 nil/缺失语义。

行为收紧与迁移：可能访问冷实体的调用使用 `nest.SendOptionSlow()`，并把所有目标列入
消息的 ID 集合。自定义 Getter 必须遵守 `entity.LoadedEntitiesOnly(ctx)`；这是公开接口契约，
框架无法拦截自定义 handler 主动调用的任意网络或数据库代码。

验证：Entity/Nest/Metrics 的 race 全包通过（`/tmp/roost-nine-logic-race-2.txt`）。
第一版曾包装整个请求 context，现有身份传递测试发现不兼容，已改成仅包装 Getter 的调用，
该失败日志保留于 `/tmp/roost-nine-logic-race.txt`。正式生成工程与性能验收见九项实施记录。
