# NC-174 修复：mirror Replicator 每次订阅一个准入门，Assembly.Stop 等已准入的 ApplyReplica

[问题](../bug/RR-20261005-NC-174.md) · [证据](evidence/noncore-bugfix-20261005-stopshape/README.md)。提交 `c99a687d`。已修复、声明场景验证，未发版。

## 决策与实现

范围限于停机生命周期，未改 owner / grant / fence、快照 L2 与兴趣表逻辑；动手前核对 `wt-revn05`（N05 mirror / ownerroute 审查）的提交：它改的是 `snapshot_l2.go`、`entity/remote_snapshot.go`、`assembly.go` 的 Stats，与本修复的 `assemble.go` / `mirror/envelope.go` 不重叠，且已先合入 main。

- `sync/syncbus/mirror/envelope.go`：每次 `Start` 建一个 `deliveryGate`（准入 + 在途计数），handler 入口先取得准入，关闭后到达的投递直接返回 nil（等同退订先一步生效）。`Stop()` 保持原语义——关闭准入并退订、不等待——把门移进 `draining`；新增 `StopWithContext(ctx)`：先 `Stop()`，再在 ctx 内等 `draining` 里每个门的在途 handler 归零，超时返回 ctx 错误，重试再等。停止后重新 `Start` 仍可用（N05 的 `TestMirrorStopAndRestartWithOldDeliveryInFlight` 保持），旧订阅的在途 handler 仍由之后的 `StopWithContext` 等待。
- `remoteentity/assemble.go`：`Assembly.Stop` 在 finalizer 停完后先 `stopReplicators()`（两个 replicator 都发起），再 `drainReplicators(ctx)`；超时返回 ctx 错误、`started` 保留，重试时 finalizer 已停（立即返回），只再等复制。Start 失败的清理仍只发起、不等待。

## 兼容性

`Assembly.Stop` 在复制 handler 未返回时返回 ctx 错误（kit Mod 原样返回，App 判定不完整并保留 Redis / SyncBus）。`cache.ReplicaSyncer.Stop` 仍调用不等待的 `Replicator.Stop()`，只多了一条：停止后迟到的投递不再进入 Store。公开 API 只增加 `Replicator.StopWithContext`。

## 验证

- `remoteentity/assembly_replica_drain_promises_test.go`：测试持兴趣表锁使 `renewIfNeeded` 卡住，在 Stop 等待时取消 ctx。修前红（`Stop reported success while a replica handler was still applying`），修后绿：返回 `context.Canceled`、订阅已撤、放行后重试 nil、已准入的续租生效。
- `sync/syncbus/mirror/stop_drain_promises_test.go`（新 API）：超时、迟到投递不入 Store、停止后重启、重试、完成后再调用返回 nil。
- `GOWORK=off go test -race -count=3 ./remoteentity/ ./kit/remoteentity/ ./sync/syncbus/... ./cache/` 通过；新用例 `-race -count=10` 通过。
