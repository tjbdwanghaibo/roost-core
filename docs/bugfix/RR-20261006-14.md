# RR-20261006-14 修复：stepTransition 自己调 Store.Apply，守卫改为全包类型检查

问题：[RR-20261006-14](../bug/RR-20261006-14.md)。分支 `fixs`，基线 `b549e4df`，未发版。

代码阅读：codebase-memory 共享 generation 停在 09-30（早于 saga 方向 ①），本轮以当前源码为准，未调用图谱。

## 决策

维护者要求让绕过“编译期不可能，或守卫覆盖全包全部构造与改写点”。Go 的可见性以包为界，同一个包里任何代码都能构造导出的 `ApplyRequest` 并调用 `Store.Apply`，
不拆包就做不到纯编译期约束；把 `Engine` 与 `ApplyRequest` 拆进不同包会动 saga 的公开 API（`Store` 实现方依赖 `saga.ApplyRequest`），代价远大于收益。所以两步合用：

1. **结构收拢**：`stepTransition` 从“返回 `ApplyRequest` 的纯函数”改为 `func (e *Engine) stepTransition(ctx, before, after, t) (Record, ApplyOutcome, error)`，
   在里面构造请求并调 `e.store.Apply`，只返回写入的记录与结果。出口手里不再有请求，修前那份 helper 绕过（把 `stepTransition(...)` 的结果交给 helper）在修后**编译不过**；
   `after.Incarnation` 由它按 before 与原因重写（出口写的值不起作用），原守卫里的 Incarnation 规则因此不再需要。
2. **类型守卫覆盖全包**：`saga/step_transition_guard_test.go` 用 `go list -export -deps` 拿依赖的导出数据、`go/types` 检查 saga 包全部非测试文件（与编译器同一文件集），三条规则：
   - ApplyRequest（或其指针）类型的**值**只能在 `stepTransition` 里产生；别处只能读收到的参数（Store 实现读请求落库）。复合字面量、`new`、零值变量、类型转换、
     函数 / 泛型返回、取下标、解引用都算产生；
   - `stepTransition` 之外**不能改写**请求：对请求或其字段 / 元素的赋值、自增、`range` 赋值、取地址（链上任一段是请求即算）；
   - Store 的 `Apply`（参数含 ApplyRequest 的 `Apply` 方法，调用或方法值）只在 `stepTransition` 里出现。
   另有两条防失明：必须在 `stepTransition` 里看到 `Store.Apply`，必须看到至少一次对请求参数的读取（`MongoStore.Apply`）。

未采用：继续加语法规则（参数也查、包级函数也查）——别名、泛型、方法值、类型转换、结构体嵌套都能再绕，语法层没有类型就补不完；把请求字段改成未导出——同包仍可写，
还会破坏外部 Store 实现。反射与 `unsafe` 不在检查范围（包内没有对 ApplyRequest 用它们）；其他包构造 `saga.ApplyRequest` 直接调 `Store.Apply` 不经过协调器，不属于本守卫的不变量
（全仓除 saga 外没有引用 `ApplyRequest`）。

## 改动

- `saga/step_transition.go`：`stepTransition` 改为 `Engine` 方法，内含 `e.store.Apply`；`after.Incarnation = before.Incarnation`，Resume / 补偿方向人工 Compensate 再加一。
- `saga/engine.go`：8 个出口改调 `e.stepTransition(ctx, ...)`；Resume / Compensate 返回它写入的记录（原来读 `request.After`）。
- `saga/step_transition_guard_test.go`：重写为类型守卫；新增 `TestStepTransitionAloneDecidesTheIncarnation`（五种原因下出口把 `after.Incarnation` 写成 99，写入的代际只取决于 before 与原因）。
- 删除 `saga/testdata/stepguard/bypass.go` 与 `TestStepTransitionGuardSeesBypassesWithoutALiteral`：维护者要求负对照不留在仓库；那两种写法在修后的结构里一种编译不过
  （改 `stepTransition` 返回的请求——它不再返回请求），另一种（零值变量逐字段拼 + store 别名）被新守卫报出，见下。

## 兼容

无行为变化：每个出口写进 Store 的请求与修前逐字段相同（`stepTransition` 的四条决定不变，只是由它自己交给 Store）；代际重写对现有出口是恒等的（它们都从 `record.Clone()` 起算，不改代际）。
不涉及持久格式、公开 API。
