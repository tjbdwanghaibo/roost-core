# RR-20260909-01：接入文档与三仓发布组合不一致

**仓库 / 位置**：roost-core `docs/QUICKSTART.md`、`docs/README.md`、`docs/DEVELOPMENT_WORKSPACE.md`。
**修复单元**：U-0157（文档）。

## 问题

Quickstart 固定 codegen v1.7.0，并给出没有 `-module` 的 `project new` 示例；当前 CLI 在生成前
检查 module，直接 exit 1（`-module is required so generated imports do not use someone else's
repository`）。README 的版本基线仍列五仓与旧版本，研发说明仍写五仓发布顺序。

## 改动

- Quickstart：改为"版本以 roost-codegen `ci/framework-release.yaml` 为准（2026-09-09 为 codegen
  v1.15.3 / core v1.15.1 / kit v1.14.2）"，示例补 `-module example.com/planet` 并说明它必填。
- README 版本基线：三仓当前 tag、发布顺序 core → kit → codegen，注明 skill / service 已并入并归档。
- DEVELOPMENT_WORKSPACE：五仓 → 三仓。

## 证明

文档改动，无测试。Quickstart 里的命令与 `internal/roost/cli.go` 的必填参数一致；版本号与发布
清单一致。

## 未做 / 边界

Quickstart 第 1 节仍写"Docker + Docker Compose 用于本地依赖"——这是生成工程的 `make dev-up`
所需，与框架自身的集成脚本（用本机二进制）是两回事，保留。把指南命令纳入干净消费者验收
（审查建议）未做。

## 2026-09-09 第二轮复核后的收尾（U-0161）

复核指出版本快照已落后一版（当时清单已是 v1.15.2 / v1.14.3 / v1.15.4）且 DEVELOPMENT_WORKSPACE 仍有"五个仓库 / 四仓"措辞。已对齐；快照类数字以后随每次发版同步改，避免再出现同类残留。
