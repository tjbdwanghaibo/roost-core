# RR-20261006-68 修复：兴趣广播移出条带锁

问题：[RR-20261006-68](../bug/RR-20261006-68.md)（F05-1）。基线 `c78d0c34`（main）。codebase-memory 共享 generation 停在 09-30（比基线旧），按 worktree 当前源码。分支 `remfix`（同批 RR-20261006-68～74，F05-1～F05-7、F09-R2、F09-R3）。

## 决策

- 条带锁只保护“分配代际 + 本机表 + 本机兴趣表”这一段（新函数 `admitInterestRenewal`），广播 `publishInterest` 在锁外；`ReleaseInterest` 同样先在锁内分配代际、改表，再锁外广播。
- **为什么锁外不破坏顺序**：线上的 renew / release 都带锁内分配的代际，接收端按代际判新旧——`renewIfNeeded` 拒绝比当前租约旧的续租、撤销水位挡住撤销之前发出的迟到续租，`release` 只撤销不新于它的租约（Mirror 第 4 步、RR-20261006-11）。所以到达顺序与分配顺序不同也收敛到同一结果。同一个 key 的其他读在发布期间看到本机表里的新租约（剩余超过一半），不重复续租。
- **回滚语义不变**：广播失败仍 `rollbackLocalInterest(key, ExpiresAt)`，按 ExpiresAt 比对只撤掉这一次续租；发布期间同 key 已被 release 或更新的续租覆盖时不动。下一次读再续。
- **未采用**：改成异步发布（每次续租起 goroutine 或队列）——要另管停机排空和失败回滚的时机；移出锁已解决“同条带其他 key 排队”，触发续租的那一次读自己仍等发布（每个 key 每半个 TTL 至多一次）。
