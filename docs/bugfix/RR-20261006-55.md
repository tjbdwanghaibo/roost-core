# RR-20261006-55 修复：被拒的被动候选只告警、事件照常前进；付费之后不再有能失败的派发

问题：[RR-20261006-55](../bug/RR-20261006-55.md)（F08-H+ H1）。基线 `47abe511`，分支 `skspawn`，与 RR-20261006-51～55 同批；验证见 [RR-20261006-51 修复](RR-20261006-51.md)。

## 根因

`dispatchEvent` 把第一个入队失败的候选的错误整个返回；`collectHostEvents` / `drainHostEvents` 在派发成功之后才推进 cursor；`payCostList` 在 `PayCosts` 成功之后才 drain，drain 的错误让未提交的启动被删。

## 决策（错误分类）

| 错误 | 性质 | 处理 |
| --- | --- | --- |
| 候选 Program 不在 Host 能力表里（`ErrHostCapabilityMissing`） | 永久：Host 的表在生命周期内不变，重试同一事件永远失败 | 记 `passive_suppressed`（Result `host_capability`）、计 `skill.passive.dispatch_rejected.total{reason}`、写 Warn，跳过该候选，其余候选照常入队，事件前进 |
| 其他入队错误 | 同一事件重试不会变好 | 同上，Result `rejected` |
| `ErrCastInputInvalid`（不是被动、没有 owner） | 路由的正常过滤 | 原样静默 |
| 根事件表满且都被引用（`ErrRuntimeCapacityExceeded`） | 容量：引用根的施法 / 衍生物结束后表就腾出来；此时还没有候选入队，重试不会重复入队 | **保持原约定**：`collectHostEvents` 留在原处、把错误报给 `Advance` 的调用方，下次重试（既有用例 `TestCollectHostEventsDoesNotAdvanceOrCompactFailedEvent` 原样通过） |

**费用顺序**：`drainHostEvents` 不再返回错误。它跟在已提交的宿主操作（付费、效果、衍生物步进、停止）之后：候选被拒只告警；根事件表满时停在这个事件前、留给 tick 上的 `collectHostEvents`（事件顺序不变）。于是 `payCostList` 在 `PayCosts` 成功之后没有任何能失败的步骤，“付费失败 = 没有付”这一前提成立，不会扣了费又删 cast。被拒的被动 Program 在它自己扣任何费用之前就被拒（`enqueuePassive` 的准入核对），B3 ③ 对两边都成立。`drainHostEvents` 的 8 个调用点去掉了不再可能的错误分支。

未采用：
- 付费之前先派发 / 预检路由——事件由付费产生，派发不了尚未发生的事件。
- 派发失败时退费——要给 Host 加一个可靠的退费操作，失败时又是一层补偿。
- 根事件表满也一律跳过——见“未完成”。

## 未完成 / 待维护者确认

- **根事件表满时 Runtime 仍会停在这个事件上**：引用根的施法要靠排程任务推进才能结束，而排程任务在同一次 `Advance` 里排在事件派发之后，表满且都被引用时只有调用方 `Cancel` / `Interrupt` / `Release` / `RemoveProgram` 能腾出表。是否把它也当成永久拒绝（跳过这个事件的被动路由、告警、前进），与既有用例 `TestCollectHostEventsDoesNotAdvanceOrCompactFailedEvent` 的约定冲突，本批按“原有用例原样通过”保留原约定，留给维护者定。
