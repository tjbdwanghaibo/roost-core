# RR-20261003-NC-02：Clone timeout 的实例所有权

2026-10-04，修前 `183b0bddc5b46f6d3b50c5edda2d08da45150a69`。[原问题](../bug/REVIEW-2026-10-03-noncore-01.md#rr-20261003-nc-02p2-clone-的-withtimeout-不生效)。已修复、具名场景验证，未发版。

根因：Clone 只改包装层 timeout，实际仍共享父 http.Client。`httpclient/client.go` 新增私有 ownsHTTPClient 标记：New 创建的 client 为库拥有，WithHTTPClient 注入的为外部拥有。库拥有的 Clone 改 timeout 时复制标准库 client 并改副本 Timeout，Transport/连接池、Jar、重定向策略继续沿用；父 client 不改。未改 timeout 的 clone 沿用旧共享行为。

没有直接修改共享 client.Timeout，也没有每次请求重建 Transport。显式 WithHTTPClient 的 Timeout 优先于 WithTimeout，这与修前 New 的行为一致，两个选项顺序都保持此规则；没有将调用方的自定义 client 偷偷重配。

正式回归修前红：请求 Transport 看到 `deadline=300ms, want approximately 20ms`。修后相同断言通过；补验证长/短子链、父实例不变、非法 timeout 忽略、nil Clone、context 较短期限优先、自定义 client New/Clone/替换/选项顺序、16 个并发 Clone 请求和父请求。观察标准库实际 request context，不用 sleep 或读取 timeout 字段作断言。

兼容性：公开 API、默认 5 秒和非正数选项忽略均保持；只修正库拥有 client 的 Clone timeout。外部 client 如需不同 timeout，由调用方自行提供相应 client，仍共享其连接池能力。不涉及数据迁移。race 验证不等于所有外部 RoundTripper/重定向/TLS 兼容认证。
