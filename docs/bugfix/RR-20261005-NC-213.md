# NC-213 修复：只接受 Runtime / Host 实际执行的 chain 与 attribute_modifier 字段（方向 B）

[问题](../bug/RR-20261005-NC-213.md) · [本轮](../review/REVIEW-2026-10-05-n09-batch4.md)。已修复、声明场景验证，未发版。方向 A（实现 chain 间隔 / 重复、modifier 叠层）留给维护者。

## 根因与决策

chain `allow_repeat` / `hop_interval_ticks` 与 attribute_modifier `stack_policy` / `max_stacks` 被 lower 进 Program、算进摘要，但 `ChainSelectShape` / `AttributeModifierCommand` 没有对应字段。与 NC-151 一样选方向 B：`compile_shape.go` 新增 `rejectValuesTheRuntimeDoesNotExecute`，`allow_repeat: true`、`hop_interval_ticks > 0`、非空 `stack_policy`、非零 `max_stacks` 报 `SHAPE_INVALID` 并指向字段；默认值照常接受。负的 `hop_interval_ticks` 仍由 NC-152 的检查报。

未采用：现在实现方向 A——需要先定 hop 间隔中目标死亡 / 离开的处理、叠层与 status 叠层的关系，属于新语义。

## 文件与行为

`skill/compile_shape.go`。写了这些非默认值的定义编译失败；仓内 fixture（`chain_lightning.json` 写的就是默认值）、skillcompose 测试、生成的骨架与 fireball 都不受影响。wire、Program 结构与摘要不变。
