# RR-20261006-38 修复：生成的 `shutdown` 段不再写没有读取方的 `serve_wait_timeout`

问题：[RR-20261006-38](../bug/RR-20261006-38.md)。随 A4 ① 一起实施（[方案](../feature/A4-1-MOD-CONFIG-SCHEMA-2026-10-07.md)）。

## 决策

删掉这一行，而不是给 App 补一个“等 Serve 返回”的配置：App 取消 Serve 的 ctx 之后的停机顺序与预算由 `shutdown.total_timeout` 统一管
（Service.Shutdown 的 5s 已计入生成的预算），再加一个独立的等待只会让预算算不清。

## 文件与行为

| 文件 | 改动 |
| --- | --- |
| `codegen/internal/roost/shutdown_budget.go` | `renderShutdownConfig` 的两种形状都以 `total_timeout` 结尾 |
| `codegen/internal/roost/shutdown_budget_test.go`、`shutdown_budget_promises_test.go` | 测试里的段结束标记改为 `total_timeout` 行 |

## 兼容

已生成工程的配置是应用自有文件，不迁移；留着这一行没有影响（它本来就不生效）。`roost project sync` 只重写与生成形状完全相同的 `shutdown:` 段，
旧形状（带这一行）的段被当作手改过、保持原样，doctor 照常检查它的预算。
