# NC-141 修复：Tick 期间对仍在堆里的定时器，取消与改期立即生效

[问题](../bug/RR-20261005-NC-141.md) · [证据](evidence/noncore-bugfix-20261005-revn11/README.md) · [本轮](../review/REVIEW-2026-10-05-n11.md)。已修复、声明场景验证，未发版。

## 根因与修法

`timer/scheduler.go` 的 `RemoveTimer` / `ChangeTimer` 在 `s.running` 时不看目标在哪，一律推迟到 Tick 结束；目标若本次 Tick 也已到期，就先按旧期限被弹出触发。

- `RemoveTimer`：先查 `byID`。目标在堆里 → 立即出堆、发 Delete（Tick 期间也一样）；不在堆里且正在 Tick → 推迟（正在触发的自己、本次 Tick 新建尚未入堆的），与之前相同。
- `ChangeTimer`：目标在堆里且正在 Tick → 立即出堆（不发变化），推迟到最外层 Tick 结束再按新期限入堆、发一次 Upsert。这样它既不按旧期限触发，也不会在本次 Tick 按新期限触发——两个 handler 互相改期不会在一次 Tick 里循环。不在 Tick 中时仍是原来的 `heap.Fix`。

没有新增状态；“目标不在堆里”的推迟语义原样保留，返回 true 仍表示“已接受”（观察 O5）。

## 兼容

行为收紧：Tick 期间取消 / 改期一个尚未触发的到期定时器，以前它会按旧期限触发一次，现在不会。仓内唯一调用方 World 不这样调用。改期期间（同一次 Tick 内）该定时器暂时不在 `Nodes()` 里。

- 修前：`TestRemoveFromAHandlerStopsATimerDueInTheSameTick`、`TestChangeFromAHandlerPostponesATimerDueInTheSameTick`、`TestChangesSeenByTheHookDuringATickMatchTheFinalState` 失败（[原文](evidence/noncore-bugfix-20261005-revn11/red-nc141-nc147-timer.txt)）；邻近分支 `TestDeferredOperationsDuringTickKeepTheirMeaning` 在修前、修后都通过。
- 修后新增组合 `TestPostponedTimerDuringTickComposesWithLaterOperations`（改期后取消、改期两次、改期后 handler panic 节点放回）；`go test -race -count=3 ./timer` 通过。
