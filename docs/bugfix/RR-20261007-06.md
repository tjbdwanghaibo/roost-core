# RR-20261007-06 修复：App 统一等待启动阶段

[问题与修前证据](../bug/RR-20261007-06.md)

App 在 registry 初始化前注册信号，锁等待和正常 Serve 沿用同一来源。增加声明式 `startup.timeout`，默认 2m，供 Mod Init / Provide / Start、Service.Init、启动生命周期 hook 共用。较长 WAL 恢复需调大该预算；单实例获取本身仍按 singleton.startup_wait 控制。

启动阶段通过同一 runStartupStep 等待。期限或信号结束等待时返回明确错误；回调未结束不能并发调用 Stop / Shutdown，依赖保持，单实例锁停止续期但不主动释放，交给进程退出和 TTL 回收。Go 无法杀死不配合取消的回调，App 返回错误后调用方必须退出进程，不能复用同一 App 启动下一实例。启动回调 panic 带栈转为错误；不改变正常停机预算。

`GOWORK=off go test -race ./app -count=1` 已通过；补充 Mod.Start 中断禁止进入 Service.Init 的回归，随组合验证执行。原始日志在主检出 `artifacts/perf/remaining-fixes-20261007/`。

方向判断：此前停机 hook 已因同类无限等待采用“预算结束保留依赖”（NC-231）。本次把启动所有阶段放到同一等待入口，不给各 Mod 增加独立信号状态机。
