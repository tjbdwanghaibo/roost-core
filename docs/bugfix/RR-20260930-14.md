# RR-20260930-14：广播每个目标自己的 Guard 作用域，按实例释放并在目标结束时释放全部锁

问题：[RR-20260930-14](../bug/RR-20260930-14.md)（REMAINING §3 N28，维护者 2026-09-30 拍板）。日期 2026-09-30。基线 `4784ef82`，独立 worktree。
状态：已修复，本地验证通过，本地提交，未推送 / 发版。codebase-memory 图谱 generation `2026-09-30T11:28:30Z`，所引文件无记录缺口。

## 根因

`nest/nest_dispatch.go` `broadcastDispatch` 整轮广播共用 runNestLogic 作用域的一把 Guard，目标结束按 ID `ReleaseEntity`：Destroy 后同 ID 重建时放掉的是新实例的锁，被取代的旧实例回到 eMap、锁持有到整轮结束。

## 决策

每个目标 `entity.NewGuardScope("nest:broadcast:<name>")`，在这个作用域里取锁、执行 handler、`ReleaseEntityInstance(e)` 释放目标自身实例，作用域结束释放本目标取得的其余锁（重建的新实例、Cast 取得的实体、superseded）与 post-release 回调。理由：

- 维护者的决定是“按实例释放，并在单个目标结束时释放”。只把 `ReleaseEntity(id)` 换成 `ReleaseEntityInstance(e)` 满足前半，但新实例仍留到整轮结束；目标结束时 `ReleaseAll` 也可以，但按作用域做与 `singleDispatch` 的锁边界一致，handler 里 `CurrentGuardScope()` / `GetEntityGuard()` 看到的就是本目标的 Guard，memory 快路径的 `memoryHandlerCreates` 与事务的 `CreatedEntityCapturer` 也绑在它上面。
- post-release 回调（Sync 的 `syncMutation.Release`）随目标结束执行，之前累积到整轮广播结束——目标之间本就是独立事务，提前到目标结束只是把 Sync 门的放行时机与单目标派发对齐，不改变提交确认语义（Confirm 仍在各目标事务的 AfterCommit）。
- 快池内没有新增等待：作用域只是从池里取一把 Guard；取锁仍是原来的 `RequireEntity`。

未采用：把新实例的锁转交给外层 Guard 留到整轮结束（RR-26 记录里的另一种形状）——维护者明确要“单个目标结束时释放”。

## 文件与行为

- `nest/nest_dispatch.go`：`broadcastDispatch` 每目标一个 Guard 作用域，目标实例按实例释放；函数注释写明边界与之前为什么错。
- 回归 `nest/broadcast_release_per_target_promises_test.go`：
  - `TestBroadcastReleasesDestroyedAndRecreatedLocksPerTarget`（memory / state_strict）：目标 X 的 handler 里 Destroy 后重建同 ID，下一个目标的 handler 里旧 X 与新 X 都可被别的 goroutine 锁到；广播后新 X 是已发布实例、两把锁空闲。
  - `TestReleaseCastOnDeclaredRemoteTargetIsNoopUntilMessageEnds`（RR-20260927-26 §未验证项补的 Remote 回归）：带 Remote 批次的消息里对声明的 remote-managed 目标 `ReleaseCast` 是空操作（事务上下文内保留锁），锁保持到消息结束、随后释放，批次照常 Commit 一次。修前修后相同，只是钉住。

## 兼容性与迁移

- 行为变化（广播路径）：目标之间不再有任何锁跨越；handler 内 Cast / 新建取得的锁、Sync post-release 回调在目标结束时释放 / 执行，而不是整轮广播结束。依赖“广播期间前一目标 Cast 的实体仍被持有”的代码本就不在契约内（广播是每目标一个事务）。
- 公开 API、Remote、持久格式不变；`ErrRemoteBroadcastUnsupported` 不变。

## 未验证项 / 风险

- 没有用 entitysync 装配跑广播（Sync post-release 提前到目标结束的效果只按代码核对：`syncMutation.Release` 开放完成屏障、Confirm 仍在事务 AfterCommit）；`bash scripts/test-sync-modes-generated.sh` 未跑。
- 每目标一次 Guard 池取还，广播热路径多一次 `sync.Pool` Get/Put；没有做基准对照。
- Remote 实体 `ReleaseCast` 只钉住了“带 Remote 批次的消息里空操作”这一种形态：remote-managed 目标不能在 memory 快路径（无事务）里持有，另一种形态不可达。
