# RR-20261005-NC-202 修复：toxiproxy pid 按命令名 + API 端口认领

日期 2026-10-05。基线 `8597046c`（审查提交 `345488e4`）。状态：已修复、声明场景验证，未发版。问题：[RR-20261005-NC-202](../bug/RR-20261005-NC-202.md)。

## 决策

`kit/scripts/integration/lib/toxiproxy.sh` 新增 `toxiproxy_owned_pid`：pid 存活且命令行含 `toxiproxy-server` 与 ` -port <本环境 API 端口> `（末尾补空格防前缀误认）才算本环境的；否则返回 1（无）/ 2（拒绝，打印 `refuse foreign pid`）。`toxiproxy_running` 改用它；`toxiproxy_down` 与 `stop_owned_pid` 一致：没有 → 删 pid 文件；别人的 → 拒绝并保留 pid 文件；自己的 → TERM 并等待。API 端口按偏移平移、每套环境唯一，足以作为所有权标识（核对过共享环境里运行中的 toxiproxy 命令行是 `toxiproxy-server -host 127.0.0.1 -port 19474`，与脚本启动格式一致，升级后能被认领）。

## 行为与兼容

pid 被复用时 `down` / `reset` 以 2 拒绝（与 mongo / nats / redis 的陈旧 pid 一致），需人工确认后删 pid 文件；`up` 发现 pid 不属于自己时按“未运行”处理，端口空闲则重新启动并覆盖 pid 文件。

- 控制：临时根（偏移 31000）自起的 toxiproxy-server（API 49474）被认领并停止，pid 文件删除（[脚本](evidence/noncore-bugfix-20261005-n15/toxipid_control.sh) · [输出](evidence/noncore-bugfix-20261005-n15/nc202-control.txt)）。
- `dataengine_env_test.sh` 通过；shellcheck 无新增告警。
