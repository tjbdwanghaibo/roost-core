# RR-20260917-07：默认 Saga Assembly 没有接收原生 Nest 完成效果（U-0231）

- 仓库：roost-core `saga`（+ roost-kit 配置键、roost-codegen 生成配置）
- 缺陷类：C4（装配缺口）
- 优先级：P2；来源 Wanted-04 转入
- 相关：T-125；测试 `saga/nest_completion_promises_test.go`

## 问题

原生 Nest 步骤（`SubscribeDataEngineStep` + `inbox.Bind` + `saga.EmitCompletion`）把完成结果作为 Nest effect
提交，于是它经 Data Engine 的 outbox 到达**效果流**：`<effect_prefix>.saga.result.<sagaID>`。
`Assembly.Start` 只订两条：`<saga_prefix>.result.>`（普通完成）与 `<effect_prefix>.saga.start`（启动）。
原生完成不匹配任何默认消费者——saga 停在 waiting，步骤按超时重发，inbox 判为重放只回放回执、不重跑业务，
协调器仍然收不到，直到 deadline 触发补偿。

## 根因

start 与 result 两条效果路径是对称的，却只做了一半：`SubscribeNestStarts` 存在，`SubscribeNestCompletions` 不存在。
`NewCompletionEffect` 产出的 Topic 是 `saga.result.<id>`（每个 saga 一个 subject），需要通配订阅，
而 start 是单一 subject，可能是"照着抄一条"时被漏掉的原因。

## 方案

- 采用：**补上对称的第三个消费者**。`SubscribeNestCompletions` 与 `SubscribeNestStarts` 同形：同一效果流、同一前缀、
  自己的 durable，过滤 `<prefix>.saga.result.>`，解 `nestwal.EffectEnvelope` → `DecodeCompletionEffect` → `Engine.Complete`。
  `AssemblyConfig.NestResults` 留空时从 `Starts` 派生（流、前缀、各项限额），durable 默认 `<start durable>-result`——
  两个消费者共用一个 durable 会共用一个游标，每条消息只到得了其中一个。
  `Start` 里第三条订阅失败会把前两条 Drain 掉（与既有的部分启动清理一致），`Stop` 一并排空。
- 采用：**把"重投也没用"的结果判成 Permanent**。`ErrNotWaiting` / `ErrNotFound` / `ErrInvalidRecord` /
  `ErrDefinitionMissing` 不重试——`Engine.Complete` 对已记录的回执是幂等的，所以走到这几个错误说明结果已被记账，
  一条陈旧消息不该把消费者堵在后面。
- 没采用：改全局 effect 前缀让原生完成落到 saga 流。前缀是 Data Engine 的全局设置，动它会牵动所有 effect 消费者。
- 没采用：在 Nest 事务之外补发一次普通完成。那正是原生路径要避免的——完成与变更必须同一条 WAL 记录。

## 改动

- roost-core：新增 `saga/nest_completion_consumer.go`（`NestCompletionConsumerConfig`、`Completer`、
  `SubscribeNestCompletions`、`handleNestCompletion`、`isTerminalCompletionError`）；
  `saga/assembly.go` 加 `NestResults` 配置与派生、第三条订阅、失败清理与 Stop 排空。
- roost-kit：`saga/mod.go` 读 `saga.result_effect_*` 配置键（缺省回落到 `start_effect_*`）。
- roost-codegen：生成配置的 saga 段补 `result_effect_*` 默认值。

## 证明

修前：

```
--- FAIL: TestAssemblyConsumesNativeNestCompletionEffects
    no consumer claimed "roost.effect.saga.result.>"; subscribed subjects: [roost.saga.result.> roost.effect.saga.start]
--- FAIL: TestAssemblyKeepsItsExistingConsumerSubjects
    no consumer for "roost.effect.saga.result.>"
```

修后：两条通过——投一条真实 `NewCompletionEffect` 产出的效果信封，waiting 的 saga 推进到 `CompletedSteps=1`；
三条订阅的 subject 与 durable 各不相同。`go test ./saga -race` 全绿。

## 未做 / 边界

- 用记录型 JetStream 替身核对订阅与投递，**没有跑真实 broker、没有跑 inbox → outbox → Engine 的完整投递**；
  review 的那条限制仍然成立。
- 没有补"重启重放""坏消息""部分启动失败"的专门用例（部分启动失败的清理与既有两条同形，靠代码审读）。
- kit 的配置键要等 core 发版后才编译得过（本仓改动随下一组发版）；codegen 的生成配置同理。
