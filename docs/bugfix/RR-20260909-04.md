# RR-20260909-04：同包多个 Entity 生成重名注册符号

**仓库 / 位置**：roost-codegen `internal/entity/gen.go`（`wireTemplate`、`generate`）、`main.go`。
**修复单元**：U-0160（C2）。**定位文档**：TROUBLESHOOTING T-55。

## 问题

同一个 Go 包放两个合法的 `//roost:entity` 实体，`roost entity -dir` 为每个实体各生成一个
`*_gen_wire.go`，每个文件都声明包级 `var registerEntityOnce sync.Once` 与 `func RegisterEntity()`。
生成 exit 0，消费者 `go build` 报 `redeclared in this block`。

## 根因

模板按"一包一实体"写死了包级符号名；生成器逐实体调用 `generate`，不知道兄弟的存在。

## 方案选择

- 拒绝多实体包：把限制写明。但 registry 收集器按包收 `//roost:register` 标记，多实体一包在业务里
  是自然的组织方式（同一聚合根的主从实体）。
- 每实体独立命名 + 另起一个聚合文件：单实体包也多出一个文件，`-output` 单文件语义被破坏，
  还要像 companion test 那样在实体数回到一个时清理多余文件。
- **每实体独立命名 + 聚合入口放进按名排序的第一个实体文件（采用）**：文件与实体仍一一对应；
  `//roost:register phase=entity` 标记每包仍只有一个，registry 收集器与 `cube` 这类已有消费者的
  `pkg.RegisterEntity()` 调用方式不变；每个实体保留自己的 once 守卫（STATIC_REGISTRATION 依赖的
  幂等性不变）。

## 改动

- `gen.go`：`generateInPackage(ent, siblings, …)`，模板生成 `register<Name>EntityOnce` 与
  `register<Name>Entity()`；`Primary`（本实体是排序后第一个）时再生成包级 `RegisterEntity` 逐个调用
  所有兄弟；`generate` 保留为单实体包装，既有测试不改。
- `main.go`：按包收集实体名排序后传入。
- `testdata/player_gen_wire.go` 用新工具重生成。core `docs/STATIC_REGISTRATION.md` 的 once 守卫命名
  同步。

## 证明

`internal/entity/multi_entity_package_promises_test.go`：从 `testdata/player.go` 派生第二个实体
（不同类型名 / kind / category / 集合名）放同一临时包，跑 `Run(-dir)`，用 `go/parser` 收集两份生成物
的包级声明：任何重名即失败；`RegisterEntity` 恰好一个、带标记、调用 `registerNpcEntity` 与
`registerPlayerEntity`。不编译消费者（要拉 core 依赖），重名就是编译失败的直接原因。

修前：`registerEntityOnce redeclared`、`RegisterEntity redeclared`、`package declares RegisterEntity
2 times`。修后 codegen 全套测试绿。

## 未做 / 边界

- 生成物形状变了：已有消费者重新生成后 `RegisterEntity` 体变为调用 `register<Name>Entity()`，
  外部调用方式不变，不需要改业务代码。
- `-output` 指定单文件配多实体时仍会互相覆盖（各实体写同一路径），与本项无关，未处理。
- 没有实际编译双实体消费者；审查附录的 PowerShell 步骤仍可作为人工验收。
