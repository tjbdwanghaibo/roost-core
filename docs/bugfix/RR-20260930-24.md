# RR-20260930-24 修复：活动租约续租失败按原因分类，过期 / 不持有时重新 acquire

问题：[RR-20260930-24](../bug/RR-20260930-24.md)（B27 第 3 批真实环境端到端暴露，P3；最早记在 [RR-20260927-02 修复记录](RR-20260927-02.md) 的附带观察）。
日期 2026-10-01；实施基线 main `db4b7009`。状态：已修复，模板回归与生成工程验证通过，已提交，未推送、未发版。

## 根因（基线行号，模板 `demo/internal/service/game/activity.go.tmpl`）

- `:466-470` `renewLease`：`RenewLease` 返回错误只 `slog.Warn("activity: lease not renewed")`，不区分原因，没有任何重新 `AcquireLease` 的路径；`runActivity`（`:208-222`）每 `activityLoopInterval`（5s）调一次，于是过期后每 5s 一条 Warn 直到停机。
- global 服务侧 `kit/service/global/service.go:321-371` `RenewLease`：过期（`current.Expired(now)`）回 `ErrLeaseExpired`（"An expired lease is not renewable: the holder must re-acquire"），已释放也回 `ErrLeaseExpired`，incarnation 不符或 binding 变了回 `ErrLeaseNotHolder`，没有记录 / 路由回 `ErrLeaseMissing`；`AcquireLease`（`:253-311`）对过期 / 已释放的租约放行、对活着的回 `ErrConflict`。即服务端已经把"要重取"和"别人持有"分开说了，demo 没听。
- 错误跨 bus 到达时是 `errcode.Remote(code, reason)`（`servicerpc/status.go:29-31`），`errcode.IntError.Is`（`errcode/errcode.go:190-200`）按 code 比较，所以 `errors.Is(err, svcglobal.ErrLeaseExpired)` 对远端形态同样成立——`bindAndLease` 原注释"sentinel comparison silently never matches"不对，顺手改正（它用 `svcglobal.Code` 比较，行为不变）。

## 决策

`renewLease` 变成租约状态机，状态 `leaseStanding` 存在 runner 上（只有 `runActivity` 这个 goroutine 写；stop 函数在两个循环退出后才读）：

| 续租答复 | 处理 | 状态 |
| --- | --- | --- |
| 成功 | 无事（从 `leaseUnrenewed` 回来时 Info 一条 "lease renewed again"） | `leaseHeld` |
| `ErrLeaseExpired` / `ErrLeaseNotHolder` / `ErrLeaseMissing`（`leaseNotOurs`） | Warn "lease lost; retaking" 一条，立刻 `AcquireLease`：成功 → 换 incarnation、Info "lease retaken"；失败（别人持有 → `ErrConflict`，或 global 不可达）→ Warn "could not be retaken; standing by" 一条 | `leaseHeld` / `leaseStandby` |
| 其它（bus 超时、global 重启） | 首次 Warn "lease not renewed; retrying next heartbeat"，之后沉默；租约仍视为自己的 | `leaseUnrenewed` |

`leaseStandby` 下每个心跳不再 Renew（incarnation 已知无效），直接 `AcquireLease`；失败沉默、成功 Info 一条。standby 期间主循环照常（窗口 id 来自时钟、应付的 dispatch 从协调器读），只是 `LiveGames` 里没有它、协调器开窗不等它——拿回租约后自动回到 expected 集合。stop 函数在 `leaseStandby` 时跳过 `ReleaseLease`（用失效 incarnation 释放只会得到一次拒绝）。

判别用 `errors.Is` 对 `svcglobal` 哨兵，不做字符串匹配；回归里的替身按 bus 送达的形状（`errcode.Remote` 带 code）返回错误，证明跨 bus 也成立。

### 附带观察：`kill -9` 后 30s 内重启 Init 失败于 acquire conflict——**不改**

理由：启动时的 `ErrConflict` 分不清"自己上一个化身的租约还没到期（≤ TTL，等一下就好）"和"另一个进程正以同一 sid 运行（部署错误，`AcquireLease` 注释里明说拒绝顶替就是为了这个）"；把 Init 改成"冲突就 standby 异步重试"会让后者从启动失败变成一条日志加永久 standby，一台没有活动租约却在服务玩家的 game。现有重启工具（`run.sh start` 不重试，k8s / systemd 会）在 TTL 内重试即可，修后租约在运行中丢失的情形已经能自愈。另一种"Init 里等到 TTL 到期再 acquire"要阻塞启动 ≤ 30s 且同样掩盖部署错误，也不采用。观察里"失败的启动已把 saga Mod 起过"是 Mod 启动顺序问题，不属本条。

### 未采用的方案

1. **standby 里继续 `RenewLease` 再 acquire**：incarnation 已确认无效，续租只会每次多一次拒绝；直接 acquire。
2. **重取时走 `bindAndLease`（Bind + Acquire）**：Bind 是 insert-only、每次都是 conflict，只多一次 RPC；`AcquireLease` 自己 `Resolve` 路由，binding 变化（`ErrLeaseNotHolder: route binding changed`）也由它处理。
3. **standby 时停掉 `openCurrentWindow` / `applyDispatches`**：欠这台 game 的 dispatch 与它有没有租约无关（协调器按 sid 记账），停掉只会让结算晚；窗口开启本来就以 `LiveGames` 决定 expected 集合。保持不变。
4. **每次续租失败都 Warn**（旧行为）：主记录要求只在状态变化时打；三个状态各一条进入日志、一条恢复日志。
