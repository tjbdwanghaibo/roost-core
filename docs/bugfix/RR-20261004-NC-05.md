# RR-20261004-NC-05：超额需求不再占限流 key

2026-10-04，起点 `c4aa1e7dd69bbf795fee878b1fb68e0bba11525a`。[原问题](../bug/REVIEW-2026-10-04-noncore-04.md#rr-20261004-nc-05)已修、声明场景验证，未发版；T-191。

`security/ratelimit.go` 原先先创建 bucket/更新 lastSeen，再拒绝 n>burst。将实际 burst 判断移到取时钟、锁、扫描与 key 表副作用之前，复用现有 x/time/rate，不引入第二个 limiter。不可满足的需求不计 CapacityRejected，也不续已有 key 的 idle 活性；有效需求因 key 表满而被拒绝仍计该指标。nil limiter、n<=0 与同 key tokens 语义不变。

正式回归 `security/admission_promises_test.go` 修前六项中四失败、两控制通过：`Keys:1`、非法需求被计 key 拒绝、`removed=0`、clamped burst 需求占 key。修后六项通过，原审查同根因反例也转绿。[红绿、命令与最终摘要](evidence/noncore-bugfix-20261004-03/README.md)。

兼容变化：超额请求不再保活或触发 sweep，需要有效调用或显式 GC 维护活性；这是拒绝操作不消耗其他资源的修正。Gateway 当前 Allow(n=1) 接入不变。满表拒绝路径仍可能 O(MaxKeys) 扫描，本批没有吞吐基准或生产 key 洪泛验收。
