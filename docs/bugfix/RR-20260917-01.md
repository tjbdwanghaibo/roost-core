# RR-20260917-01：合法 Queue 的键碰撞，跨队列读票与成组

**仓库 / 位置**：roost-core `service/match/types.go`（`Queue.Key`）、`queue_store.go`（`Candidates`、`Commit`）；`redis_store.go` 用同一 Key 做逻辑键。
**修复单元**：U-0221（C2）。**定位文档**：TROUBLESHOOTING T-115。

## 问题

`Key()` 用冒号拼 `Mode:GroupSize:Partition`，Mode / Partition 不限制冒号：`{a:2, 3, x}` 与 `{a, 2, 3:x}` 都渲染成 `a:2:3:x`。
两个都过 Validate 的池共用一个 `queueState`：Candidates 跨池返回票，Commit 用二人队列把三人队列的票提交成功；
主体占位、幂等账本也混在一起。RPC affinity 也用这个键，同样并流。

## 根因

C2：身份映射不是单射，而存储与路由都把它当身份。

## 方案选择

- 拒绝含分隔符的 Mode / Partition：破坏现有含冒号配置，且"哪些字符保留"要另定。作为主方案不采用。
- 长度前缀 / 结构化编码：所有键换形，已部署 Redis 键全部迁移。不采用。
- **采用：只转义自由字段**——Mode / Partition 里 `%`→`%25`、`:`→`%3A`（先转义 `%` 保证单射）。不含这两个字符的键**逐字节不变**，
  已部署键零迁移；原来会碰撞的配置得到各自的键（旧共享键下的票不迁：它们本就不属于任何一方）。
  另加两道防御：Candidates 跳过 `ticket.Queue != queue` 的票；Commit 对这样的票返回 `ErrTicketMissing`。

## 改动

- `types.go`：`Key()` + `escapeKeyField`，注释写明兼容承诺。
- `queue_store.go`：Candidates 归属过滤；Commit 归属校验。
- 测试：`queue_key_collision_promises_test.go`（单射、纯键不变、保留字符集含转义字符本身；跨队列 Candidates / Commit）。

## 证明

- 修前：`two valid queues share key "a:2:3:x"`；`Candidates of queue b returned 2 tickets (…); a ticket from queue a leaked in`。
- 修后：`service/match` `-race` 绿。

## 未做 / 边界

- Mode / Partition 曾含 `%` 的部署：其键会变（之前 `%` 未转义），需要迁移或清空队列后升级；含 `:` 的部署之前就是碰撞状态。
- 未连接真实 Redis 复现；Redis 包装用同一 Key，逻辑一致。已随 core v1.15.6 发出。
