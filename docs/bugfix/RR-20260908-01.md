# RR-20260908-01：Session `Enter` 对同一 RequestID 的跨 owner 竞争

**仓库 / 位置**：roost-kit `service/session/service.go`，`Enter` 的账本写入（原第 311 行）。
**修复单元**：U-0154（C8）。**定位文档**：TROUBLESHOOTING T-50。

## 问题

两个不同 owner 并发用同一个 RequestID 调 `Enter`。两边都先读账本、都读到"不存在"，各自建
run、各自拿到自己 owner 的 claim（claim 键是 ownerID，互不冲突），最后竞争同一个账本键。
账本 `Create` 对落败者返回 `created=false, err=nil`，`Enter` 只接了 err，于是落败者也被告知成功、
计入 accepted。账本只记胜者，落败 owner 之后重试同一请求被拒 `request belongs to owner X`，而
他手里那个 run 还留在存储里。

## 根因

`Enter` 有两个串行化点，分别管两件事：owner 的 claim（insert-only）保证"每个 owner 一个 live
run"；账本保证"一个 RequestID 一个答案"。前者看不见另一个 owner 用同一个 RequestID，后者是这条
请求唯一的仲裁点，却被放在最后一步且不看结果。

## 方案选择

- **A 先占账本再建 run**：账本条目加 pending 状态，落败者一开始就被挡住、不需要回滚。代价是多
  一类中间状态和崩溃后的修复分支（占了账本没建 run）。
- **B 保持顺序，处理落败并回滚（采用）**：落败者撤回自己刚建的 run 与 claim，再拒绝。改动最小，
  回滚安全——那个 run 从未交给调用方、不持有资源。
- **C RequestID 按 owner 命名空间**：冲突从根上消失，但这是 API 语义变化（"按 RequestID 幂等"
  变成"owner 内幂等"），还要迁移 Redis 里的账本键；且如果客户端本来就该用全局唯一 ID，跨
  owner 撞键是客户端缺陷，拒绝比放行更安全。留给产品决定。
- **D 用 `Update` 的 CAS 闭包代替 Create + Get**：B 的原子化写法，少一次读、没有"Create 失败到
  Get 之间条目过期"的窗口。与 B 合并实施。

## 改动

`service/session/service.go`：

- 两处 `Claims.Create` 保留返回的 `Versioned[Claim]`（`claimStored`），供回滚用。
- 账本写入改为 `Requests.Update(RequestID, mutate)`：键不存在时写入本次条目；存在时不写并带回
  胜者条目。
- 撞键时：`discard(run)`（既有的版本删）+ 新增 `releaseClaimIfCurrent`（版本删 claim，
  `ErrVersionMismatch` 视为已被别人替换、不算错）。owner 不同 → `ErrRequestInvalid: request
  belongs to owner X`，计 `refused:enter:request_owner_collision`；owner 相同 → 按重放返回账本
  指向的 run（找不到则沿用 `ErrConflict: names missing run`）。
- 账本写入本身出错的语义不变：返回 run 与错误，调用方重试会撞自己的 claim 被拒。

`service/session/ledger_failure_test.go`：替身 `ledgerThatFailsOnce` 补 `Update` 也失效一次，
它钉的"账本写丢了不能报成功"承诺不随写路径改变。

## 证明

`service/session/enter_ledger_collision_promises_test.go`：屏障账本让两次初始读都完成后才允许写
（收自 `docs/bug/REPRO-2026-09-08.md` 的 `session_review_test.go`），写用真实内存存储的原子实现。

修前：
```
loser (owner 2) = ({ID:run-2 OwnerID:2 ... State:open ...}, <nil>), want ErrRequestInvalid
```
修后：胜者的 run 与账本一致；落败者 `ErrRequestInvalid`，`Current` 无 run，claim 已释放；落败者
重试得到同一拒绝；胜者重试得到重放。`go test ./service/session -race` 全绿。
