# RR-20261006-48 修复：Interest 排队事实就绪后、应用前同 id 被 Leave / Hide，之后每次 Flush 都失败

问题：[RR-20261006-48](../bug/RR-20261006-48.md)（F04-1）。基线 `47abe511`。codebase-memory 共享 generation 停在 09-30（比基线旧），定位与结论按 worktree 当前源码读取。
同一批（分支 `syncfix`）修 RR-20261006-48～50，一笔提交 `04378f7c`。

## 根因

`Leave` / `Hide`（`sync/entitysync/policy/interest.go`）改 AOI 与关系源，却不改排队事实 `in.facts`；而排队事实在调用顺序上早于它们、在下一次政策阶段才应用。应用时 `MoveSubject` 失败，`applyQueued` 把失败的事实留下并让错误传到 `Flush`，事实永不消失，于是每次 Flush 都失败。

## 决策

**把 Leave / Hide 的效果写进排队事实**，使应用结果与“先应用事实、再 Leave / Hide”逐项相同（`policy/interest_queue.go` 的 `supersedeQueuedRelationsLocked` / `supersedeQueuedMovesLocked`）：

| 排队事实 | Leave / Hide 做了什么 | 等价改写 |
| --- | --- | --- |
| 位置事实（被观察方那一半） | `RemoveSubject(id)` 成功 | MoveSubject 后 RemoveSubject ≡ RemoveSubject：这一半作废（`subjectGone`） |
| 位置事实（`observer=true` 的观察者那一半） | `RemoveObserver(id)` 成功（只有 Leave） | 同理作废；Hide 不动观察者，这一半保留、照常 `MoveObserver` |
| 关系事实（任何观察者） | 关系源 `Forget(id)`（Leave、Hide 都有） | Set(o, S) 后 Forget(id) ≡ Set(o, S\{id})：从成员里去掉 id |
| id 自己作为观察者的关系事实 | 关系源 `Clear(id)`（只有 Leave） | Set(id, S) 后 Clear(id) ≡ Clear(id)：整条丢弃 |

**不会丢掉合法的兴趣变更**：每条改写都是“先应用、再 Leave / Hide”的精确等价，只删掉被后来的 Leave / Hide 覆盖的部分；只按 AOI 实际发生的删除改写（`RemoveObserver` / `RemoveSubject` 返回错误时那一半不动）；Hide 留下观察者的移动和该 id 作为观察者的关系（测试 `hide` 子用例断言 3→1 的关系仍然生效）。作废的位置事实也不会套到之后重新 `Enter` 的同一 id 上（`leave` 子用例断言）。

**结构性守卫**：改写之后，AOI 只经 `Interest` 自己的方法在 `in.mu` 下变更，应用失败已不可达；万一将来出现绕过改写的移除路径，`applyQueued` 把应用失败的事实报告一次后丢弃（错误点名 id），不再留下来让之后每一次 Flush 都失败；同 id 之后的事实仍等到下一轮，保持顺序。

未采用：只在应用时跳过 `ErrInterestUnknown` 的事实——Leave 后又 Enter 的同一 id 会把旧位置套上去（时间顺序被打乱），关系事实也会在 Leave 之后复活关系；给事实加 TTL——掩盖而非修正顺序问题。
