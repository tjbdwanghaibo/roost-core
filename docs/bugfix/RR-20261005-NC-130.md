# RR-20261005-NC-130：L2 CAS 落败报 ErrStaleWrite，Publish 不再把旧快照装进 L1

2026-10-05，基线 `a80be80c`（审查 `173738a0`）。**已修复、声明场景验证（含真实 Redis），未发版。** [问题](../bug/RR-20261005-NC-130.md) · [本轮](../review/REVIEW-2026-10-05-n05-revn05.md) · [证据](evidence/noncore-bugfix-20261005-n05/README.md)。

## 根因

`remoteentity/snapshot_l2.go` 的 `Set` 在 CAS 脚本返回 0（L2 已有更新版本或更新 epoch）时返回 nil；`cache.ReadThroughStore.Set` 只把非致命 L2 错误当断网降级、照写 L1，nil 更是直接写 L1。`RemoteSnapshotCache.Publish` 以为“输了就说明存下的更新”，但 L1 冷的节点 L1 里存的恰恰是这份旧快照。

## 修法

- `remoteSnapshotL2Store.Set`：CAS 落败返回包着 `cache.ErrStaleWrite` 的错误（`cache.Store` 约定，与 RR-20261004-NC-15 对四个 cache Store 的修法一致）。
- `RemoteSnapshotCache` 的 `FatalRemoteError` 把 `cache.ErrStaleWrite` 也归为“不是断网”：`ReadThroughStore.Set` 在写 L1 之前就返回它。
- `Publish` 收到 `ErrStaleWrite` 后调用新的 `adoptNewerFromL2`：L1 已有不旧于本次的副本就不动；否则读 L2 现值，经同一 L1 准入（含墓碑）装入。L2 没有值（被删除 / 过期抢先）就保持 L1 原状；L2 读失败按断网降级，装入发布者这份（等同旧行为）。
- Stale 规则提成 `remoteSnapshotStale`，L1 准入与 adopt 共用。

没采用：只在 Publish 的冷 L1 预查里比较 L2 版本——预查与 CAS 之间 L2 仍可能前进，窗口还在；改 `ReadThroughStore.Set` 的通用语义——它只有这一个生产调用方，但属 N04 的 cache 包，改动面更大，用 `FatalRemoteError` 分类已能表达。

## 组合复核

- 新错误的调用方只有 `ReadThroughStore.Set`（`loadOne` 的 loader 回填路径显式放行 `ErrStaleWrite`，本缓存没有 loader）；`Delete` / `Get` 不会收到它。
- `LoadAuthoritative`：权威答案输给 L2 时 Publish 后 L1 是 L2 的较新值，后续过期与 minVersion 检查作用在它上面；L2 恰好为空（删除墓碑）时返回 miss——正是删除后的正确结果。
- owner 提交、复制消息、权威加载三条 Publish 入口共用；同版本重复发布（续期 ExpiresAt）仍走 CAS 成功分支。
- 行为收紧：直接调用 `remoteSnapshotL2Store.Set` 的代码会收到 `ErrStaleWrite`（仓内只有测试）；两个旧测试的 nil 期待同步改为 `errors.Is(err, cache.ErrStaleWrite)`，仍断言 L2 值不变。无格式 / wire 变化。

## 验证

- 修前红（`173738a0` 上，新测试）：见 [bug 记录](../bug/RR-20261005-NC-130.md)；真实 Redis：`older write on real Redis = <nil>, want cache.ErrStaleWrite`。
- 修后：`TestLateReplicaOnColdNodeDoesNotPinL1BelowSharedL2`（同 epoch / 迁移后新 route epoch）、`TestAuthoritativeLoadThatLosesTheL2RaceReturnsTheNewerSnapshot`、`TestStaleBackfillControls`（L2 断网降级、同版本重复发布、Store 约定）通过；`entity` / `remoteentity` / `cache` `-race -count=3` 通过。真实 Redis（隔离环境，前缀 `revn05:*`）`TestRealSnapshotL2StaleWriteIsReportedAndNotPinnedInL1` 与既有 `TestRealSnapshotL2KeyPrefixOnRedis` 通过；自起 Redis Cluster 的 `TestRealSnapshotL2KeyPrefixOnRedisCluster` 通过。

## 未验证 / 风险

L1 冷节点在 L2 不可达时仍会装下迟到的旧快照（断网降级的既有取舍）；L2 已过期而迟到消息更旧的情形不在本修复范围（审查 O5）。多节点真实时序、长时容量未做。
