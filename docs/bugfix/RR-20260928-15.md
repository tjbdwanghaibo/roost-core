# RR-20260928-15 修复：生成的 player TCP / scene 测试先等会话登记，再推送、关闭或计数

问题：[RR-20260928-15](../bug/RR-20260928-15.md)（[REMAINING-2026-09-28](../review/REMAINING-2026-09-28.md) §6 N70，同类残留 §5 N62）。日期 2026-09-28。基线 `b8a401a`，worktree `scratchpad/wt-r12-n70`，分支 `fix-r12-n70`。
状态：**已修复**（本地），已本地提交，未推送 / 未发布；framework-compat 是否转绿要等推送后的 CI。codebase-memory 图谱已过期（09-26），本轮以当前源码、`rg` 与实跑为准。

## 决策（按清单推荐）

只改测试。服务器先写 ack、再登记会话的顺序不动，它不是缺陷：客户端协议没有承诺“拿到 ack 时服务器的计数已经包含自己”，产品代码里也没有依赖这个时序的调用方（`scene` / `presence` / `playerowner` 读 `ActiveSessions` 时，都有会话关闭事件或下一次入场 sweep 兜底）。

- 生成 `server_gen_test.go` 新增助手 `waitRegistered(t, runtime, playerID, want)`：2s 有界轮询 `runtime.ActiveSessions(playerID) == want`，超时 `t.Fatalf("active sessions = %d, want %d")`。写法就是 `TestCloseSessionsCountsTheSessionsItClosed` 原来的内联等待，只是收成一个助手。
- 拨号之后要推送、关闭或计数的 6 个用例，都在 `waitReleased(t, server, 2)` 之后调用 `waitRegistered(t, runtime, 7, 2)`：`TestAConnectionThatCannotTakeAPushIsClosedAndTheOthersKeepIt`（替换原来那行直接断言，N70 本身）、`TestAPushNoConnectionTakesFailsAndClosesThemAll`、`TestAPushThatFailsBeforeWritingClosesNoConnection`、`TestASessionPushThatCannotBeWrittenClosesThatSession`、`TestAnExpiringCallerDeadlineClosesNoHealthyConnection`，以及 `TestCloseSessionsCountsTheSessionsItClosed`（内联循环换成助手，语义不变）。
- game-demo 的 `scene_connections_test.go`：两个用例在 `joinReady` 之前加 `waitActiveSessions(t, transport, moverID, 1)`，同时给已有助手 `waitActiveSessions` 补上注释，说明为什么需要它。
- 被测行为和原有断言都不变，也没有新增 sleep 或放宽阈值。等待有上界，超时照样失败。

**未采用**：
- 让 `dialAuthenticated` 自己等服务器登记 `sessions[token]`：同 SessionID 重连时（`TestClosingASessionCancelsItsInFlightDispatch`）旧会话已经在表里，这个判据立刻成立，等于没等，而且会让“替换”看起来和“新登记”一样。
- 把服务器改成先 `registerSession` 再写 ack：这是产品行为变化，清单要求只改测试。而且登记后 ack 失败的路径需要另外论证（会话已经可见、可被推送，然后才发现连接不可写）。

## 文件与行为

- `codegen/internal/roost/render_player_tcp.go`（生成 `internal/access/player/tcp/server_gen_test.go`）：助手 `waitRegistered`，以及上面 6 个用例里的调用。
- `demo/internal/service/game/scene_connections_test.go.tmpl`（生成 game-demo 的 `internal/service/game/scene_connections_test.go`）：两处 mover 登记等待，`waitActiveSessions` 的注释。
- `codegen/internal/roost/player_tcp_registration_wait_promises_test.go`（新）：
  - `TestGeneratedPlayerTCPTestsWaitForTheSessionsTheyUse`：用 `go/parser` 解析 game-demo 夹具里的 `server_gen_test.go`。先检查 `waitRegistered` 是一个有界的计数等待；再检查凡是先拨号（`dialAuthenticated` / `stalled`）、后使用 runtime（`PushPlayer` / `PushSession` / `CloseSessions` / `ActiveSessions` / `fillUntilOneFails`）的 `Test*`，`waitRegistered` 都出现在最后一次拨号之后、第一次使用之前。上面 6 个用例必须都被查到，防止检查空转。
  - `TestGeneratedSceneConnectionTestsWaitForEveryDialedPlayer`：对 `scene_connections_test.go` 里每一次 `dialScenePlayer(t, addr, X, …)`，要求在它之后、下一次 `joinReady` / `stallPlayer` / `transport.PushPlayer` 之前出现 `waitActiveSessions(t, transport, X, …)`，并且至少查到 6 次拨号。
  - 两条都只读缓存的夹具（RR-20260928-14），用 `t.Parallel`。

## 兼容性 / 已生成工程

没有产品代码、API 或配置变化。`server_gen_test.go` 是生成器受控文件：用新生成器对 `b8a401a` 生成的旧工程执行 `roost project diff`，结果是 `1 file(s) would change`（就是这个文件）；`roost project sync` 的结果是 `updated: internal/access/player/tcp/server_gen_test.go`，`created=0 updated=1 removed=0 unchanged=135`，同步后与新鲜生成的该文件只差模块路径，`go vet` 和 `-race` 测试都通过。另外，本地用 `replace` 指向 worktree 时，sync 调用的 go 工具会把 `require roost-core v1.17.2` 改写成 `v0.0.0-00010101000000-000000000000`（`go: downgraded …`）。这是本地 replace 造成的，与本修复无关，正式版本号的工程不会这样。

`scene_connections_test.go` 是 demo 的业务文件（`demo.go` 的 `write:` 项）：只在 `project new -template game-demo` 时写一次，sync / upgrade 不改写。已生成的 game-demo 要自己补这两行，或者重新生成。

## 未验证项 / 风险

- framework-compat 转绿要在推送后的 CI 上确认（本批不推送）。N70 在 CI 上只出现过一次，本地是 1/500 的概率复现，“修后 500 次通过”说明失败概率降下来了，并不能证明不会再失败。能证明时序已经处理掉的，是两个延迟探针：把窗口人为放大到 50ms / 300ms，修后全部通过。
- 其他生成测试是否还有同类依赖：本轮在 `codegen/`、`demo/`、`kit/` 里搜了 `ActiveSessions`、`dialAuthenticated`、`registerSession`、`net.Dial`，真实拨号的测试只有这两个文件，均已覆盖。`TestClosingASessionCancelsItsInFlightDispatch` 本来就是有界等待（2s 内等旧请求被取消），`TestADispatchThatOutlivesItsBudgetAnswersAndFreesTheSlot` 不依赖登记，所以两者都没有改。
- 已生成的 game-demo 里的 `scene_connections_test.go` 是业务文件，sync 不会更新，需要手工补。
