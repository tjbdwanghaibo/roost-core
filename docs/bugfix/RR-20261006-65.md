# RR-20261006-65 修复：LockstepBot 发现缺口即追帧，请求被放弃后重发

问题：[RR-20261006-65](../bug/RR-20261006-65.md)（F04-9）。基线 `a7285da6`，分支 `lockstep`，提交 `99a3e99f`。

## 根因

机器人把“缓冲溢出”当作唯一的缺口信号，而 `FrameAssembler.Gap()` 早就能告诉它冗余没补上的缺口；去重只看 `Next`，从不过期。

## 修复（`robot/lockstep.go`）

- `HandleBroadcast` / `HandleFrames` 应用完放出的帧后统一走 `checkGap`：`Ingest` 报错（溢出、包解不开，同之前）或 `Gap()` 为真即从 `Next` 请求追帧；缺口合上时清掉去重状态。
- 去重：同一个 `Next` 只请求一次；`Next` 在前进（追帧页在逐页补）时继续等，不从每个新 `Next` 重新请求；`Next` 停住超过 `CatchupRetryPackets`（新字段，缺省 64 个包）仍有缺口时重发一次请求（服务端放弃追帧后能恢复）。
- 只有乱序超过冗余深度时才会出现缺口（冗余能补上的丢包在下一包里按序放出，不会进缓冲），所以不会因正常冗余自愈而多请求。

## 兼容性

`LockstepBotConfig` 新增 `CatchupRetryPackets`。追帧请求比之前早（缺口出现即请求），压测里 `CatchupsRequested` 会比之前多。demo loadtest 的注释（“缺口太大就向房间要历史”）现在属实。
