## (a) 首次 checkpoint 前第一条 WAL 半截

**根因**：`FileHistoryJournal.Load`（`syncstream/file_journal.go`）在没有 checkpoint、`wal-1` 非空时把 `Epoch` 置 0，假定至少有一条完整记录来定 epoch；半尾不算记录，Epoch 留 0，`Import` 拒绝。

**修**：回放后一条完整记录也没有（`valid == 0`）时按空日志打开，用本次的 `initialEpoch`。半尾的 `Record` 从未返回成功，`appendLocked` 只在 `Record` 成功后才把包交出去，那个 epoch 从未被任何消费者见过，换成新 epoch 不破坏任何承诺。
**与 nestwal 尾部规则对齐**：Load 发现未换行半尾时（有无 checkpoint 都一样）计数 `syncstream.recovery.tail_truncated.total` / `.bytes{reason="torn_record"}`、`slog.Warn`（WAL 路径、偏移、字节数）；截断仍在首次续写前、独占所有权下完成（U-0211，`truncateTo`），Load 本身不写文件（保持 `NewHistoryWithJournal` 加载不写的约定）。完整行解不开仍是损坏，照旧拒绝启动，不当半尾处理。

## (b) 回放不恢复 LastActivity

**根因**：`HistoryMutation` 不带时间，`replayHistoryMutation` 无从恢复活动时间。
**修**：`HistoryMutation.At`（UnixNano，`omitempty`），Append 与推进 ACK 的记录带上与内存 `state.activity` 同一个时间；回放 Append / 推进 ACK 时写入 `LastActivityUnixNano`。没有 `At` 的记录回放为 0，`Import` 按“刚活动过”（now）处理——宁可晚删，不误删。

## (c) Recover 覆盖 provider 的 SchemaVersion

**根因**：`History.Recover`（`syncstream/syncstream.go`）无条件用 `request.SchemaVersion` 覆盖 provider 返回包的版本。
**修**：provider 标了版本（非 0）就以它为准；没标时才用请求方的版本补上（原有行为，`provider_unlabelled` 子用例锁住）。
