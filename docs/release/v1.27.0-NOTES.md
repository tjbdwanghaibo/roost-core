# v1.27.0：玩家接入目录改名与 Remote Rejected 精简

发布状态：**已发布**——tag `v1.27.0` 指向 `a147877c`（2026-10-14）；pretag、全仓 race、故障矩阵 21/21、govulncheck 与真实 tag 消费者验证见[验收篇](v1.27.0-VALIDATION.md)。日期 2026-10-14。范围：`v1.26.1`（`7a1f2363`）之后到本版 release 提交。

本版是次版本，含两项维护者 2026-10-14 批准的破坏性 / 精简改动。**运行时正式链路行为、配置、wire 与存储格式不变；生成物要求的最低 core 仍是 v1.26.0**（当前生成器生成的 game-demo 钉 v1.26.0 实编 build / vet 通过）。条目与[实现篇](v1.27.0-IMPLEMENTATION.md)同号；变更原文以 [CHANGELOG `[v1.27.0]`](../../CHANGELOG.md) 为准。

## 1. 升级清单（按操作顺序）

1. 启用了玩家接入（`game/player_agent`）的工程按 [B1](#b1) 手工迁移目录与 import，再 `roost project sync`。
2. 业务或测试代码若调用了 [S1](#s1) 删除的三个 `remoteentity` 导出函数，改为走 Durability 0 的真实拒绝路径构造测试状态。
3. 按错误判别表处理 Remote 回复的业务代码无需修改（[S1](#s1) 的收紧只发生在正式链路不可达的路径上）。

## 2. 破坏性变化

### <a id="b1"></a>B1 生成工程 `game/player_agent` → `game/playeraccess`

**原因**：`player_agent` 容易被理解为“每个玩家一个代理 / actor”，实际它是生成工程里的玩家接入层（协议解码 / 编码、请求上下文、中间件、调用业务 Controller），不是独立服务，也不是每玩家一个 goroutine。`playeraccess` 直接表达“玩家接入”。来源与讨论见 [ACCESS-SYNC-FOLLOWUPS §2](../maintenance/ACCESS-SYNC-FOLLOWUPS.md)；同篇 §1 的 Session 运行服务可选化维护者决定继续暂缓。

**变化**：只改名。包名 `player_agent` → `playeraccess`；`player_agent.Context` / `ProtocolRegistry` / `Response` / `Middleware` 等随包名变为 `playeraccess.*`；生成器常量 `protocol.PlayerAgentImportSuffix` → `PlayerAccessImportSuffix`。类型、方法与派发行为不变。同一份声明改名前后生成的 game-demo 与 game 模板工程，把旧产物里的 `player_agent` 替换为 `playeraccess` 并改目录名后与新产物 `diff -r` 为空。

**升级（未上线，不做兼容）**：`roost project sync` 只生成新目录、不删除旧目录，业务代码（`game/controllers/player` 等）也不会被改写：

```sh
git mv game/player_agent game/playeraccess
# .go 文件里作为完整单词的 player_agent 一律改为 playeraccess：import 路径、import 别名、
# player_agent. 标识符，以及随目录挪走的业务文件的 package 子句
grep -rlw --include='*.go' player_agent . | xargs perl -pi -e 's/\bplayer_agent\b/playeraccess/g'
roost project sync
```

第二步要连 import 别名一起改：v1.26.x 生成的 game-demo 写的是 `player_agent "<module>/game/player_agent"`，只改路径和 `player_agent.` 标识符会报 `undefined: playeraccess`；业务自己放进 `game/player_agent/` 的文件挪走后 `package player_agent` 子句也要改，否则同目录两个包名。漏改 import 时编译报 `wrong type for method HandleXxx ... have (*player_agent.Context ...) want (*playeraccess.Context ...)`。按这三步迁移后，工程与新生成的 game-demo 除 go.mod / go.sum 外逐字节一致；CI `upgrade-compat` 的 `player-access-project` lane 用 v1.26.1 生成器生成 game-demo，照这三步迁移后 upgrade、build / vet / test，并核对这条逐字节一致（2026-10-15 补；最初发布的说明第二步只写了路径和标识符，漏了别名与 package 子句）。未启用 player access 的工程只有生成文档的文字变化。

## 3. 精简

### <a id="s1"></a>S1 Remote WAL 级 Rejected 处理

**原因**：v1.26.0 移除“Remote 写 + lease fence”历史 WAL 记录投影后，Durability 1/2/3 的正式链路不再产生 Remote Rejected（投影器写权威冲突是 `ErrProjectionConflict` fatal）。Rejected 收尾只剩 Durability 0（明确拒绝与 finalizer 持久拒绝）一个来源；WAL 级分支和三个“仅供测试注入”的导出函数成为生产不可达代码。维护者 2026-10-14 选择“直接精简”。

**删除的导出 API**：`remoteentity.MongoCommitter.RejectRemoteCommitsInTransaction`、`remoteentity.Backend.RejectRemoteCommitsInTransaction`、`remoteentity.Manager.RejectRemoteTransaction`。

**行为**：Durability 0 的明确拒绝与 `RejectUnresolvedRemoteCommits`（唯一持久拒绝写入点）及其回滚、隔离、仅内存卸载、重载、交付 false 一行未改。仅在不可达路径上收紧一处：strict / pipelined 的 `Commit` 失败一律带 `entity.ErrRemotePersistenceIndeterminate`（判别表第 2 行“结果未知”），不再把 tracker 的 Rejected 原样回成第 4 行 `nest.ErrRemotePartRejected`；收紧后更保守——调用方核实而不是把可能已提交的写当作被拒。自带 remoteentity 只有 memory（Durability 0）会落在第 4 行。

**守卫**：`TestWALRemoteAuthorityConflictNeverProducesRejected` 在真实 nestwal / Projector / MongoStore / MongoCommitter 上模拟权威被接管，断言 WAL 级不产生 Rejected、无 Remote 事务记录、strict / pipelined 只得到结果未知。范围限正式 MongoStore / MongoCommitter；自定义投影存储不在保证内。
