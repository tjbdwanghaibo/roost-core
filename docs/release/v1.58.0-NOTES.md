# v1.58.0 候选说明：生成工程、服务修复与物理关卡流程

此文档用于准备发布，不代表 tag 已创建。以下为 v1.57.1 之后的候选变更：

- **Mongo 库名前缀**（维护者：同一台机器上的数据库撞名，“在框架层加一个前缀能力，这个前缀统一配置在配置中，对于 skill 生成的模式这个配置变成项目名”，并且不放在 MongoDB 客户端底层）：
  - 新配置键 `mongo.database_prefix`。非空时，Mongo Mod 交给其他 Mod 的客户端打开每个业务库都加 `<前缀>_`（按 sid 分库时 `<前缀>_<库名>_<sid>`），系统库 `admin` / `local` / `config` 不加；为空（运行期缺省）时库名就是配置与代码里写的名字。驱动与 `infra/storage/mongo` 不变。
  - 生成配置把前缀写成工程名，库名改写成不带工程名的 `game`、`saga`、`remote_entity`。工程 planet 在 Mongo 里的库是 `planet_game`、`planet_saga`、`planet_remote_entity`。
  - 直接用驱动的运维工具（`schemamigrate`、`sidmove players` 不传 `-db` 时，合服）按同一规则用加了前缀的实际库名。
- **超过每 subject 订阅者上限的订阅改为等空位**（M-9 处置 B）：被拒的 (玩家, 实体) 按实体排队等空位，不再每次 Flush 全部重说。2000 人联盟、缺省上限 1024 时，原来每轮 Flush 约 960 ms、分配约 600 MB，收敛期每个 pair 一条 WARN。玩家看自己的钉住订阅不受上限。
- **审查修复 RV-20261119-01～02**：
  - Unity 包的 `BrowserWebSocket` 拿到调用前已取消的令牌时，PumpDriven 的 `RelayClient.ConnectAsync` 永远挂起；现在以取消结束。在 Unity 6000.7 WebGL（IL2CPP）+ Chromium 里补跑了最小链路。
  - 不带方括号的 IPv6 WebSocket 地址现在被配置检查拒绝。

另有：M 系列正式测量第一批（S1 微基准、S2 心跳投递）的记录，C++ `native_weak` 夹具的期限竞态修正。

新纳入的内容还有：game-demo 共用 enter 进入编排、gift 送礼 Saga 模块及 demo 迁移、换服 / 邮箱 / 活动的恢复修复，以及 PhysX 区域触发、检查点、重生与流程视图。逐条变更见 [CHANGELOG](../../CHANGELOG.md)：切版前在 `Unreleased`，正式发版时由脚本一次归档。

**不兼容旧版。** 线上尚未部署，所以不做兼容。已有工程按下面的升级须知处理，或者用新版重新生成后把业务文件搬回去。

## 升级须知

1. **core 与生成器配套使用 v1.58.0。** 除 `mongo.database_prefix` 外，新邮箱模板还引用 `mail.BroadcastBinding` 和 `Mail.CloseBroadcastScope`，不能配 v1.57.1。切版前不预写清单、CHANGELOG 版本段或生成物最低版本。发布时用 `scripts/release.sh v1.58.0`（不带 `--min-core`）；tag 推送且模块可下载后，再单独提高 `minimumVersions.Core` 和 `framework-compat.yml` 的 minimum lane。提前抬下限会让 pretag 中的消费者尝试下载不存在的版本。过渡期间，main CI 用当前生成器配旧发布版的 demo lane 与 source-head 是不同组合，不能用后者通过代替前者。
2. **库名前缀**，二选一，不要两边都写工程名（否则成了 `<工程名>_<工程名>`）：
   - 照新生成配置改：加 `mongo.database_prefix: <工程名>`，`dataengine.database` / `dataengine.databases` / `saga.database` / `remote_entity.mongo.database` 去掉工程名部分，并把数据迁到新库名；
   - 或者不加前缀（空串或不写），保持原有库名不变。
3. **警告：改前缀等于换库。** 先停写并排空 WAL（没有未投影记录）、迁移数据，再改。WAL 目录的 `databases.json` 只记映射库名、不记前缀（维护者：前缀在项目初定下，正常不改，不加检查），有未投影记录时改前缀，重启不会拒绝，积压记录会投影进新前缀的库。
4. **前缀的限制**：只用字母、数字、`_`、`-`，不是系统库名，至多 40 字节；DataEngine 在 `--check-config` 与 Init 按加了前缀之后的名字核对 63 字节上限。
5. **运维工具**：`schemamigrate`、`sidmove players` 不传 `-db` 时打开加了前缀的库；显式 `-db` 仍写完整的实际库名，工具不再加工。
6. **Sync**：`InterestConfig.OnRefusal` 对等空位的 pair 只在进入队列时报告一次（`Err` 为 `ErrSubscriberLimit`），排队期间不再报告。上限以外原因的重说，每次政策阶段至多 4096 个。
7. **Unity**：重新执行 `scripts/client/build-unity.py`（或模板的同步脚本）拿到新的 `BrowserWebSocket.cs`。
8. **IPv6 地址**：`portal.websocket_servers`、`login.presence.ws_addr` 里写了不带方括号的 IPv6 的，启动与 `--check-config` 会报错，照提示写成 `ws://[…]:port/…`。

9. **物理房间三端须一起升级**：重建 ABI 3 原生库，以 schema 2 重发关卡，更新到只认 RP3 帧的客户端。自定义 `Commit` 也要适配新的 `Settled` 返回值，见[关卡流程手册](../framework/PHYSICS-ROOM-SERVICE.md)。Linux 和 Unity 双客户端人工试玩仍是外部验收项。
10. **邮件与换服**：暂停玩家换服（不要求停登录）；先升级全部 mail 实例，再升级 game 与自定义画像提交方，最后恢复换服。已跳过的历史广播不会自动补发。见 [mailbox](../../modules/mailbox/README.md)。

## 主要内容

### Mongo 库名前缀

- `wiring/mongo.WithDatabasePrefix(client, prefix)`：`Database(name)` 打开 `<前缀>_<name>`，`DatabaseForSid(base, sid)` 打开 `<前缀>_<base>_<sid>`；前缀为空时返回原客户端。DataEngine、Remote、saga 与业务代码都经这个客户端，所以只加一次。
- `mods.MongoDatabasePrefix`（配置声明）、`mods.PrefixedDatabase`（命名规则）、`wiring/mongo.DatabasePrefix(cfg)`（读配置）。
- `coredata.DatabaseMap` 新增 `Effective` / `Effectives`（加了前缀的实际库名）；`wiring/dataengine.NewDatabaseMap` 多一个前缀参数；`DAODatabaseFile` 返回实际库名。
- 契约见 [13-wiring §2.2](../framework/guide/13-wiring.md#22-mongo-库名前缀mongodatabase_prefix) 与 [03-dataengine](../framework/guide/03-dataengine.md)。

### Sync 超上限等空位

- `Manager.SubscriberRoom`、`Manager.MaxSubscribersPerSubject`、`ManagerStats.SubscriberLimitRefused`；指标 `entitysync_subscriber_limit_refused_total`、`entitysync_interest_room_waiting`、`entitysync_interest_room_waiting_subjects`、`entitysync_interest_room_refused_total`。
- 修了两处：同一 pair 被两个视野持有时每次结算说两遍（F1）；钉住订阅被上限拒绝（F2）。
- GroupView 的成员被上限拒绝后同样等空位，逐成员 WARN 改为每组每 10 秒一条。
