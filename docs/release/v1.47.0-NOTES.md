# v1.47.0：生成工程目录重整、DAO 默认同步、起服预加载与 CellWorld 正式模块

本版的重点有五项：

- 生成工程的目录重新整理，组件逻辑搬进各自的包，包之间只经 `game/view` 的接口相连。
- DAO 字段默认既落库又同步给客户端，服务端私有字段要显式写 `nosync`。
- 本地实体可以起服预加载、常驻内存；本地实体的 DAO 缺省按服分库（`dbscope=sid`）。
- CellWorld 固定分区成为正式模块，内部线上格式升到 v12，并做了第一轮千人容量优化。
- 收口一轮遗留问题，修掉一批缺陷，game-demo 的玩法开始产出金币。

逐条变更、决策出处、先红后绿与证据见 [CHANGELOG](../../CHANGELOG.md) v1.47.0 段；维护者对遗留问题的逐条答复见 [decisions](../maintenance/evidence/known-limits-remaining-20261114/decisions.md#维护者答复2026-11-14)。

**不兼容旧版。** 线上尚未部署（维护者 2026-10-06 起的口径）。存储、协议与生成物都不为旧进程、旧数据、旧生成工程留兼容：先停旧进程，清空受影响的数据，重新生成工程。

## 升级须知（不兼容，按这里逐项处理）

1. **重新生成工程**。目录重整、`game/view`、组件拆分只对新生成的工程生效，用旧版本生成的工程不迁移。core 与生成器同时升级到 v1.47.0；生成器清单里的最低 core 版本在本版 tag 推上去之后的下一笔提交才抬到 v1.47.0。
2. **DAO 字段默认同步**。无 tag、空 tag、只写 `persist` 或只写 `map=` 的字段现在也会同步给客户端。服务端私有字段（账本、内部状态）逐个改成 `nosync`，临时字段 `nopersist`，两项都不要用 `nopersist,nosync`。生成器只对持久键变化告警，不对“字段新开了同步”告警，必须人工复核（规则见 [tag 手册](../../codegen/docs/TAGS.zh-CN.md#dao-字段-tag)）。嵌套类型字段上的 `persist` / `nopersist` / `sync` / `nosync` 现在生成期报错，按报错拆字段。
3. **本地实体按服分库**。Player / World（game-demo 模板）与 room、monster、dungeon、terrain_building、terrain_chunk 模块的本地实体，以及 `add dao --entity` 新生成的本地实体 DAO 改为 `dbscope=sid`，文档在 `<物理库>_<sid>`。不迁移旧数据：清空这些集合（或整库），先停旧再起新。Remote 托管实体仍是 global。
4. **缺省 WAL 目录按服务分**。不写 `dataengine.wal.dir` 时由 `data/wal/dataengine/<sid>` 改为 `data/wal/<服务>/<sid>`。旧目录不再读取：升级前先排空 WAL（正常停机即排空），再换新版本。显式写了目录的配置不受影响。
5. **Remote 的 Redis 键带工程前缀**。生成配置的 `remote_entity.snapshot_l2_key_prefix` 由空改为 `roost:<工程名>`。已生成的工程重新生成配置或手工加上；改正在运行的部署的前缀要整体重启。
6. **运行期号上限降到 2^33−1**。game-demo 的 `runtimeid` 与 monster 模块的序号只用第 0～32 位，第 33 位留给 CellWorld 出生号；用完拒绝、不回绕。
7. **handler 里不能持久新建没声明的 Remote 托管实体**。原来会被本地投影写成普通文档并回复成功，现在返回 `nest.ErrDurableRemoteWriteUnsupported`、整条事务回滚。Remote 托管实体要由以它为声明目标的消息写，或在 Nest 之外新建。
8. **CellWorld 内部线上格式 v11 → v12**，game-demo PlayerDao schema 5。不兼容旧节点与旧数据，先停旧再起新。
9. **`lifetime=resident` 现在真的常驻**。原来只是声明；现在只从内存卸载的调用返回 `entity.ErrEntityResident`。常驻实体不要写空闲卸载。

## 主要内容

### 目录重整与 `game/view`

- 新目录：`services/<服务>/` 放托管框架服务的手写代码；`game/login/` 合并登录链；`game/components/<功能>/` 放组件逻辑；`game/entities/<实体>/` 只留实体本体、生成文件与每个组件的薄接线；`game/managers/managers.go` 是 manager 登记点。旧 → 新路径表见 CHANGELOG。
- `game/view/` 只放接口：每个组件一份 `component_<功能>.go`，每个实体一份生成的 `entity_<实体>.go`。组件对外方法用到的结构体也定义在 view 里。约束与豁免见 [KNOWN-LIMITS“组件包与 game/view”](../maintenance/KNOWN-LIMITS.md#组件包与-gameviewv1470)。
- 全部模块的组件都拆进了组件包；bag / wallet / attribute 可以挂到 Player 之外的实体上。

### 起服预加载、常驻实体与按服分库

- `//roost:entity ... preload=startup [preload_order=<N>]` 现在也能写在本地实体上，服务 Init 之前载完。有总时间预算与数量上限（`dataengine.preload.timeout` 缺省 10m、`max_entities` 缺省 1000000），超出让起服失败。
- `lifetime=resident`：起服载入后不被移出内存，只在换服交出、删档、运维强制刷新三处离开内存。
- 本地实体的每个 DAO 必须与主 DAO 同一库范围，起服时校验。
- rehome 模块换服时搬玩家的 sid 文档到目标服的库，提交后删源库。前提是两个服把同一逻辑库映射到同一个 Mongo、同一前缀。

### CellWorld 固定分区正式模块

- 共享 Redis CAS 写授权、持久入场高水位、NPC 出生目录与代次、死亡结算与奖励回执、Buff / 冷却恢复；正式 `cellworld` 模块，game-demo 用同一套 Runtime。
- 单实例锁的有效窗口过期后不可复活（对所有开了 singleton 的服务生效）。
- 容量第一轮（A + D）：witness 按区块合批、对齐全量刷新相位；复制缺口按对象 / 观察者修复，不再整 peer 退回全量。同机对照全量条目约 −43%、Cell 出站约 −34%。千人档 Witness P99 ≤ 50ms 仍未稳定达标，下一步（D13）等 M-15 复测再定。

### 遗留收口（主要修复）

- **自身视图驻留预算拒收**：`ErrRetryLater` 不再整轮作废，只作废没交付到的 subject，下一轮从被拒的会话轮转（取代原 C29“低 ID 总是先试”）。同参数演练 16 KiB 预算从 0 轮提交变为 171 / 200。
- **Interest 超额收紧真正腾出位置**：最远成员同时经块覆盖等别的来源被看见时，原来收紧一步不腾位置、循环不收敛；现在一直收紧到真正空出位置。
- **Remote**：handler 里新建未声明的 Remote 托管实体改为拒绝（见升级须知第 7 条）；L2 键带工程前缀（第 5 条）。
- **CellWorld 出生号与运行期号撞号**：同一 sid 下运行期序号 2^33+k 等于出生序号 k，已分开（第 6 条）。
- **机器人同步解码认建筑**：开地形场景里建筑进主视野后，`cmd/loadtest` 与演练客户端不再报 `unknown sync namespace "building"`。
- **WAL 目录按服务分**：同一 SID 起两个带 DataEngine 的服务不再争目录锁（第 4 条）。
- **Saga 原生步骤的推荐配置开准入**：把持续负载压在参与方投影速率以内；`scripts/perf/saga-js-scan.sh` 原生档按推荐配置跑，30s 追平是硬门槛，`@noadmission` 是诊断档。
- **地形坏块按原始地形包确认**：原始块坏了、或拥有者装不进的块，客户端原来永远等不到确认；协议与 C# 不变。
- 其余修复与新增的真实依赖验收（换服 SIGKILL、登录线、社交、运营、Room / Turn、地形 WAL 恢复等）见 CHANGELOG。

### game-demo

- **玩法产出金币**：副本通关在领奖事务里经 wallet 发 20 金币；活动结算按名次发金币邮件 300 / 200 / 100，领取时到账。此前金币只有 GM 邮件一个来源。
- **新玩家初始化写进 enter 钩子**：`game/login/enter_first.go` 在首次初始化事务里把新玩家放到世界场景出生点，只执行一次；不发初始道具或金币。
