## 2. 测试命令

```bash
GOWORK=off go build ./... && GOWORK=off go vet ./...
GOWORK=off go test -count=1 .
GOWORK=off go test -race -count=1 ./cmd/mongocheck/ ./framework/dataengine/... ./infra/storage/mongo/...
python3 scripts/check-doc-anchors.py docs CHANGELOG.md README.md AGENTS.md demo codegen/docs scripts/README.md gameplay wiring framework
scripts/pretag.sh v1.31.2
# 真实依赖（私有单节点副本集 + 私有三节点 NATS（scripts/nats-cluster.sh）+ Redis + toxiproxy），每个 Mongo 版本一轮：
export ROOST_DATAENGINE_IT=1 ROOST_DATAENGINE_IT_MONGO_URI='mongodb://<私有实例>/?replicaSet=<名字>' \
  ROOST_DATAENGINE_IT_NATS_URL="$NATS" ROOST_NATS_CLUSTER_URL="$NATS" ROOST_DATAENGINE_IT_REDIS_ADDR=<私有 Redis> \
  ROOST_DATAENGINE_IT_TOXIPROXY_URL=<私有 toxiproxy API>
GOWORK=off go test -tags integration -race -count=1 ./framework/dataengine/... ./infra/storage/mongo/... ./wiring/mongo/...
GOWORK=off go test -tags integration -race -count=1 ./framework/saga/
GOWORK=off go test -p 1 -tags integration -race -count=1 \
  -skip '^(TestRealMongoPrimaryFailoverContinuesProjection|TestRealNATSOutageDoesNotBlockProjectionAndRecoversOutbox|TestRealJetStreamLeaderFailoverPreservesDedupAndOrder)$' \
  ./wiring/dataengine/ ./wiring/sidmerge/ ./gameplay/movement/
GOWORK=off go test -tags integration -race -count=1 ./framework/remoteentity/
scripts/test-dataengine-generated.sh
# 部署检查
ROOST_MONGO_URI='mongodb://<…>' GOWORK=off go run ./cmd/mongocheck
```

`wiring/dataengine`、`wiring/sidmerge`、`gameplay/movement` 要加 `-p 1`：三个包并行时各自建 saga 流，每条流预留 8 GiB（`framework/saga/engine.go` `StreamMaxBytes` 缺省），超过 `nats-cluster.sh` 每节点 8GB 的 `max_file_store`，`TestSidMergeMigratesAndRevertsOnRealMongo` 报 `insufficient storage`；单独跑通过。这是测试环境容量，不是 Mongo 版本问题（[验收 V2](v1.31.2-VALIDATION.md#v2)）。

本版发版时实际执行了哪些、结果如何，见[验收篇](v1.31.2-VALIDATION.md)。
