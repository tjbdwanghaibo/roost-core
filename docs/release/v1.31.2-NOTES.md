## 1. 建议升级的原因与各项变化

### <a id="d1"></a>D1 DataEngine：单条 Put 投影把以 `$` 开头的业务字符串当成聚合表达式（正确性修复，本版的主要原因）

**影响谁**：v1.12.2～v1.31.1（自 2026-08-31 `c0251a04` 起）所有用 DataEngine 落库的工程。触发条件是某个 DAO 文档里有**以 `$` 开头的字符串值**（玩家名、宠物名、公会名、自由文本等用户输入最常见），并且这条记录走了单条投影路径。

**原来的问题**：`MongoStore.applyPut`（单 mutation 快路，以及多 mutation 记录在事务内的 Put：新建实体的首个提交、整文档写回）写的是 `FindOneAndUpdate(…, [{$replaceWith: doc}], upsert)`，`doc` 没包 `$literal`，MongoDB 把它当表达式求值：

- `name: "$nickname"` 是字段路径：新建时字段消失，覆盖时取到旧文档的 `nickname`；
- `"$$ROOT"` 变成旧文档（新建时是 `{_id}`）；嵌套 `{k: "$name"}` 变成 `{}` 或旧值；数组里的 `"$y"` 变成 `null` 或旧值；
- 单独的 `"$"`、未定义变量 `"$$foo"` 让这条投影报错并一直重试（投影卡住）。

批量路径（`ProjectBatch`，`ReplaceOne`）存得正确，所以同一份数据存成什么取决于投影走了哪条路径，用户输入可能被**静默改写**。

**现在**：改为 `[{$replaceWith: {$literal: doc}}]`，文档按原样写入；upsert、返回新文档、版本条件与冲突分类不变。内存替身 `mongotest` 的 `$replaceWith` 改为按服务器规则求值（原来把参数当字面量存，比服务器“更正确”，单元测试因此看不见这个缺陷）。其余管道更新与聚合表达式已逐个核对：saga 冷副本的门控替换本来就包 `$literal`，Patch、删档墓碑、outbox、Remote 提交与权限元数据都是普通更新文档，值按字面量写入。MongoDB 7.0.45 与 8.0.32 上都复现了修前的红、修后的绿（[验收 V3](v1.31.2-VALIDATION.md#v3)）。

**已有数据怎么查**（线上尚未部署，不做迁移；已经在测试服 / 内测服跑过的数据按下面查）：

1. **WAL 里还保留着的记录**（checkpoint 之后的段）：先用 `cmd/walinspect -dir <WAL目录> -snapshot <新目录>` 做隔离副本，再在副本上用 `nestwal.WAL.Replay` 逐条解出 Put 的 `Data`，与 Mongo 当前文档逐字段比较（框架没有现成的比较工具）。已确认并清理的段不在 WAL 里，只能用第 2 条。
2. **扫业务集合**：找应有字段缺失的文档、字段值意外是嵌套文档（`$$ROOT` 的结果，形如含 `_id` / `_version` 的子文档）、或与同文档另一字段相同的值。有用户输入字段的集合优先（例如 `db.<集合>.find({name: {$exists: false}})`，按业务字段调整）。
3. **投影器日志**：反复出现 `'$' by itself is not a valid FieldPath` 或 `Use of undefined variable` 说明有记录卡在投影上；升级后会自动投影成功，不需要人工处理。

被改写的数据无法从 Mongo 自身恢复原值：原值只在 WAL（第 1 条能覆盖的范围）或业务侧日志里。

### <a id="m1"></a>M1 `cmd/mongocheck`：Mongo 部署只读检查工具（新增）

给运维在生产 / staging 上核对 [DataEngine 对 MongoDB 的最低要求](../framework/guide/03-dataengine.md#dataengine-对-mongodb-的最低要求)。逐项输出 PASS / WARN / FAIL、原因与修复建议：

| 检查项 | PASS | WARN | FAIL |
| --- | --- | --- | --- |
| 服务端版本 | ≥ 5.0 | 4.4.x | < 4.4 |
| featureCompatibilityVersion | ≥ 5.0 且与服务端一致 | 4.4、与服务端不一致、读不到 | < 4.4 |
| 拓扑 | 副本集（单节点即可） | mongos（框架接受，未验证） | 单机（输出改单节点副本集的步骤） |
| 会话支持 | 有 | — | 没有 |
| `transactionLifetimeLimitSeconds` | = 20 | < 20、读不到 | > 20（服务端缺省 60） |
| 存储引擎 | wiredTiger | 其他、读不到 | 不持久化 |

**安全**：连接串只从环境变量读（缺省 `ROOST_MONGO_URI`，`-uri-env NAME` 改名），不接受命令行参数（避免进 `ps` 与 shell 历史）；输出与错误都不含连接串、主机名或账号：驱动错误只输出服务端错误名与错误码（如 `Unauthorized (code 13)`、`AuthenticationFailed (code 18)`），其余按类别描述（超时、网络错误、连接串无效）。只发 `hello`、`buildInfo`、`getParameter`、`serverStatus` 四个只读命令；后两个需要 `clusterMonitor` 角色，权限不够时对应项是 WARN 并说明要什么权限，不判 FAIL。

**退出码**：0 没有 FAIL（可以有 WARN），1 至少一项 FAIL，2 用法错误或连不上（没有完成检查）。

**用法**：

```bash
ROOST_MONGO_URI='mongodb://<账号>:<口令>@<主机>:27017/?replicaSet=rs0&authSource=admin' \
  go run github.com/tjbdwanghaibo/roost-core/cmd/mongocheck@v1.31.2
# 目标机器没有 Go：在本仓库交叉编译后拷过去
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o mongocheck ./cmd/mongocheck
```

**对下游迁移的意义**：自装 MongoDB 大概率是单机，工具会对拓扑判 FAIL，并对 `transactionLifetimeLimitSeconds` 判 FAIL（服务端缺省 60）。改造要点（已有数据原地保留）写在设计篇“单机改单节点副本集要点”：`replication.replSetName`、`setParameter.transactionLifetimeLimitSeconds: 20`、重启、`rs.initiate`（`host` 写应用可达的名字）、连接串加 `replicaSet`，开了认证时还要 `security.keyFile`。

### <a id="m2"></a>M2 MongoDB 7.0 实测（只验证，不改框架代码）

macOS arm64 上，官方 tarball **7.0.45**（FCV 7.0，sha256 校验通过）与 brew **8.0.32**（FCV 8.0）各起一个私有单节点副本集（`transactionLifetimeLimitSeconds=20`，WiredTiger），配私有三节点 NATS、Redis 与 toxiproxy，跑同一组真实依赖用例：DataEngine、Mongo 驱动（含单机拒绝、提交超时 / EndSession 的 toxiproxy 用例）、`wiring/mongo`、saga（冷副本、步骤收件箱、参与方 kill -9）、`wiring/dataengine`、`wiring/sidmerge`、`gameplay/movement`、`framework/remoteentity`（全部 `-tags integration -race`），以及 `scripts/test-dataengine-generated.sh`（正式生成工程三次独立进程）。**两个版本结果相同、没有失败，没有发现 7.0 不支持的特性**，最低要求不变（部署 ≥ 5.0）。用例数与命令见[验收 V2](v1.31.2-VALIDATION.md#v2)。

## 2. 升级

- `go get github.com/tjbdwanghaibo/roost-core@v1.31.2`，无配置、存储格式或生成物变化，不需要重新生成代码。
- 按 [D1](#d1) 检查已有数据（只有已经跑过数据的环境需要）。
- 部署前对每个环境的 Mongo 跑一次 `cmd/mongocheck`，FAIL 项按输出的修复建议处理。

## 3. 没有验证的

- MongoDB 5.0、6.0 没有实测；4.4 只按代码与官方文档判断（工具判 WARN）。
- Linux 上没有跑这组真实依赖用例（本次只有 macOS arm64）；`cmd/mongocheck` 的 linux/amd64 交叉编译做了，没有在 Linux 上运行。
- 分片集群（mongos）：框架启动检查接受，工具判 WARN；仓库没有在分片集群上验证过。
- 兼容 MongoDB API 的托管服务（如 AWS DocumentDB）不在验证范围内，工具也不识别它们（版本号可能显示为 5.0 而通过版本检查）。
- 7.0 / 8.0 两轮都跳过的用例：性能探针（`ROOST_PROJECTOR_PERF` 等）、需要 Redis Cluster 或 `scripts/mirror-local.sh` 私有环境的 remoteentity 用例、停共享环境 Mongo 主节点 / NATS 的三个故障用例（`wiring/dataengine/failover_integration_test.go`）。Remote 故障矩阵 `scripts/test-remote-matrix.sh` 没有在本版重跑。
