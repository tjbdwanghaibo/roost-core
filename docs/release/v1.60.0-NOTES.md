# v1.60.0：CellWorld 分区会话、攻击请求号、AOI 空间索引与最小分区配方

这是相对 v1.59.0 的升级说明，完整变更见 [CHANGELOG](../../CHANGELOG.md)。

## 对玩家和运维的影响

- **分区玩家断线有宽限，连接可接替。** 当前连接断开立即停步，`cellspace.reconnect_grace`（缺省 30s，`0s` 立即离场）到期才正式离场；宽限内重连或新连接接替保留同一化身。会话绑定不持久，进程重启后按冷恢复重新进场。移动与攻击在 Player 事务内核对“这条连接仍是当前绑定”，被接替的旧连接不能再写；入场已提交而视野没装好的连接也不能写。独立 Gate 与嵌入 TCP 走同一套核对（Gate 的接替顺序取 Game 绑定表的确认序号），Gate 断开仍按原来的结算离场。
- **分区攻击可带请求号安全补发。** `AttackTargetRequest.RequestID` 每玩家保留最近 64 个号，同号同目标取回原准入回执，不再次出手；回执只证明 Base 准入过，不是战斗结果。旧客户端不带号时行为不变。[契约](../../gameplay/cellworld/ATTACK-REQUESTS.md)。
- **Interest 空间索引三选一**（`AOIConfig.IndexMode`：`block` 缺省 / `crosslist` / `kdtree`），三者可见集与事件等价；KD 树在写查交替时每次整树重建，只适合批处理为主、位置较稳定的地图（[已知限制](../maintenance/KNOWN-LIMITS.md)）。AOICluster 里已可见的目标跨区时沿用离开半径，不再先消失后出现。
- **最小分区配方** `project new -template game -recipe cellworld`：标准登录、一个 Base、两个 Cell，完成入场、跨格和重连，不带 demo 的战斗、地形和怪物。普通图仍默认不启动分区。
- **game-demo 全服 World 写事务改为 `durability=pipelined completion=async`**：回复仍在 WAL 持久之后，吞吐不再受每条一次 fsync 限制；200 人同秒档未重测。
- **普通图与停机**：已保存的 `(0,0)` 是有效位置；分区停机时一名玩家离场失败不再中断其余玩家离场与 Node 排空。

## 升级与回退

1. **新生成工程需要 core v1.60.0。** game-demo 模板用到本版新增的 `gateway.GameIngress.SessionAdmission`、`cellworld.Node.AttackReceiptSession` 等接口；最小 core 在打 tag 后单独提交提升。只升级已有工程的 Go 依赖不会替换手写接线，分区接线按模板在独立目录生成后对比迁入。
2. **改名与接口变化要手工跟进。** 新生成工程把 `SceneActor` / `SceneActorDao` 更名为 `CellPlayer` / `CellPlayerDao`（数字实体种类不变），已装的旧模块不被覆盖，迁移见 [cellworld README](../../modules/cellworld/README.md#从旧名-sceneactor-升级)。手写的 `view.Actor` 实现需补齐新增方法；`cellspace` 不自动升级旧版 `cellworld`。
3. **协议向后兼容。** `RequestID` 是新增字段，旧客户端可继续连接；需要安全补发的客户端改为每次攻击带递增号。
4. **回退。** 会话绑定与宽限计时不落库，回退到 v1.59.0 时玩家按冷恢复重新进场；攻击回执账本是持久字段，旧版本不读取，回退后带号补发退化为普通攻击。
5. **上线前在目标环境验证。** 断线宽限、Gate 下的连接接替、带号补发与 World 吞吐只在本机测试与单机演练里通过；跨机、容量与长时间运行未验证。[已知限制](../maintenance/KNOWN-LIMITS.md)。
