# v1.40.0：稳定存储键与轻量持久标记

## 行为变化

- 生成 DAO 与嵌套类型的每个生成字段必须显式写 `store` tag；支持数字短键及稳定字母键。`nocoll` / `nopersist` 字段也必须声明，`dao:"-"` 排除字段例外。定义中的旧 `bson` tag 被拒绝；生成物仍使用 BSON 编解码。
- 生成前拒绝缺失、重复、非法键以及多个字段共用一条声明。重新生成会比较上次生成物，字段键或选项变化时输出 WARN，包含同类型字段交换键、嵌套与非持久字段；首次生成或删除基线后无法追溯历史。生成物应保留在版本控制中，不应通过删除基线消除告警。
- 标量及顶层完整替换使用事务 `FullMask`，只有递归子项维护持久路径树。父字段覆盖、revision、回滚与冻结契约不变；WAL codec、Mongo 持久级别和 Sync PB 格式不变。

规则见 [tag 手册](../../codegen/docs/TAGS.zh-CN.md)，实现边界见 [DataEngine 持久化说明](../framework/DATAENGINE-INCREMENTAL-PERSISTENCE.md)。

## 升级步骤

1. core 和生成器同时升级到 v1.40.0；新生成物依赖 `nest.MarkPersistField` 与 `PersistChange.FullMask`，不能混用旧 core。
2. 检查业务 DAO 定义及嵌套类型。把旧定义中的 `bson:"coins"` 改为 `store:"coins"`；此前隐式命名的字段按上次生成物里的实际 BSON 键补齐，保留原键和 `omitempty` 等选项，不凭 Go 字段名猜测或自动重新编号。手写 Mongo 编解码结构及生成物的 `bson` tag 不改。
3. 重新生成 DAO / Entity，并审查 WARN 和 diff。键不变时无需因本次声明变化转换 Mongo 数据或更换 WAL 目录。客户端 PB 字段号不由 store 键决定，本轮不要求客户端协议升级。
4. 若主动把已有长键改成数字短键，须处理业务 schema、已有数据与字符串字段选择/Values 消费者；遵循[离线 schema 处理流程](../framework/SCHEMA-MIGRATION.md)。本版不提供旧 tag、旧键双读或自动迁移。新业务可直接选稳定数字键，例如 `store:"1"`。

## 验证与性能边界

本轮实施验收包含全仓 build/vet/test、相关包 race、生成器失败不覆盖基线与变更告警、真实隔离 Mongo 8.0.32 的短键/嵌套/冷加载/WAL 回放、正式 heartbeat 和 Sync 双模式消费者，以及 13 类玩法生成工程。MOBA 断线恢复与派对房间首次视图各有首轮失败，原配置完整复跑通过，原因未确认；没有放宽测试门限。

真实 Nest/WAL/Mongo 对照共 39 组、216 万次业务事务，每次 2 Entity × 2 DAO，最终值和版本一致，WAL 全部排空，准入拒绝与投影失败为 0。标量准备微基准约降低 12.8%，短键完整 BSON 夹具减少 35.6%；**尚未证明稳定的端到端 TPS 提升**。strict 当前长键的 30 秒档出现约 1.10 秒发生器 P99 迟到，pipelined 高压轮次波动明显，保留全部退化样本与 43 条 WARN。详见[性能报告](../performance/DATAENGINE-PERSIST-PATHS.md)。

上述为 macOS 本机单成员 Mongo 和短时负载，不代表 Linux、跨机、生产长稳或整个框架的吞吐上限。发布不等于部署。发布脚本另执行 pretag，并在 tag 推送后用 `GOPROXY=direct` 验证真实下游生成工程。
