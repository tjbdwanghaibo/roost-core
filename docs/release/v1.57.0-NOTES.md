# v1.57.0：浏览器客户端连玩家接入（C# WebGL 与 TS）、portal 按连接方式给地址、业务代码不用 strict

这一版包含 v1.56.0 之后 2026-11-18 当天的工作，重点有四项：

- **浏览器里的客户端可以连 game**：玩家接入（Gate）本来就支持 WebSocket，这一版补齐客户端：
  - C# `Roost.Client` 能走 WebSocket，Unity WebGL 构建可以联机（`PumpDriven` 模式）；
  - 新增网页 TS 客户端 `@roost/client/gate` + `@roost/client/protobuf`（第 1 轮：连接、握手、请求、推送、心跳、重连；自身视图同步与配置表读取还没有）；
  - 协议导出 `client_export.languages` 可以加 `ts`。
- **portal 按客户端要的连接方式给地址**（维护者：“让C端发信息决定用哪个地址，portal只返回支持的方式即可”）：进服请求带 `transport: "ws"` 时返回该服的完整 `ws(s)://` 地址；不写时与以前相同（TCP）。
- **业务代码不再用 `durability=strict`**（维护者：“很多都不需要strick的方式，pileline就已经很严格了”）：
  - 普通写 handler 用缺省 async，只读用 memory；
  - 回复后马上有外部确认的地方用 `pipelined`：purchase 发货、mailbox 领奖、MOBA 原服到账、SLG 联盟到账、alliance 被 Saga 调到的 6 个写；
  - 覆盖业务模块、生成器骨架、玩法夹具、codegen 测试与 skill 样例；game-demo 本轮不改。strict 仍是框架能力。
- **生成器按组件包写法生成**：`roost add component` 写 `game/components/<包>/`，handler 收 `view` 接口。

另有：roost-genre skill 重写（入口版本 2026-11-18.1）、Unity 托管路线打包只要 .NET SDK（`--managed-only`）、pretag 按改动范围只跑受影响的测试。

逐条变更见 [CHANGELOG](../../CHANGELOG.md) 的 v1.57.0 段。

**不兼容旧版。** 线上尚未部署，所以不做兼容。已有工程按下面的升级须知处理，或者用新版重新生成后把业务文件搬回去。

## 升级须知

1. **core 与生成器同时升级到 v1.57.0。** 生成的 portal / login 模块用到新字段，最低 core 版本在发版后的单独提交里提高。
2. **TS 包改名**：`@roost/relay-client` → `@roost/client`，按子路径引用（`/relay`、`/web`、`/gate`、`/protobuf`）。不在 npm 上：拷同版本 `client/ts`，`npm ci && npm run build && npm pack`，游戏工程引用 tgz 或 `file:`。
3. **`roost.yaml`**：`client_export.csharp.protoc` 改为顶层 `client_export.protoc`（C# 与 TS 共用），旧写法报错。声明 `ts` 时服务端开发机要 node 22 以上与 protoc-gen-es 2.17.0。服务端两种语言都声明时，`roost client sync` 必须写 `--lang`。
4. **durability 标记**（已安装模块不会自动变，新装或重装才生效）：
   - 手工去掉业务 handler 上的 `durability=strict`；
   - 改成 `durability=pipelined` 的：purchase 的 `handlerPurchaseGrant`、mailbox 的 `handlerMailboxClaimReward`、alliance 的 6 个 Saga 调到的写，照 MOBA / SLG 手册生成过的工程还有 `MOBAAward`、`AllianceCredit`；
   - 工程写了非空 `nest.pipelined.allowlist` 时，把这些 handler 列进去（生成工程缺省 `allowlist: []`，即全部允许）。
5. **portal / login 模块**：已装 portal 的工程，`portal_rules.go` 归工程所有、不会被重写（`ServerChoice` 多了 `Transports` 字段），要用 WebSocket 地址就照模块模板手工更新；静态地址写 `portal.websocket_servers`，动态登记写 `login.presence.ws_addr`（开着嵌入 WebSocket 监听时可不写，会自动推导；前面有终结 TLS 的负载均衡时要自己写 `wss://`）。
6. **生成器**：
   - 老工程实体包里的旧组件不迁移；实体包里已有同名旧组件时 `add component` 拒绝；
   - 手写代码里引用 `IHeartbeatEntity`、`IBehaviorEntity`、`ITimeDomainEntity` 的地方改成 `view.<E>Entity` 加 `<e>.<X>Of(target)`。
7. **Unity**：重新执行 `scripts/client/build-unity.py`（可加 `--managed-only`）拿新的 `Roost.Client.dll`。C# 无破坏性 API 变化。

## 主要内容

### 浏览器客户端

- C#：`IGateTransport`，自带 `TcpGateTransport`（缺省）与 `WebSocketGateTransport`；`ConnectionOptions.WebSocketUrl` / `TransportFactory` / `PumpDriven`；`Connection.Pump`；`RoostClientDriver.Attach(client, beforePump)`。浏览器桥接 `BrowserGateTransport` 是参考写法，在 `client/dotnet/unity-webgl-smoke`。
- TS：`GameClient`、`Connection`（自动重连）、`request` / `subscribe` / `notify`；protobuf-es 2.17.0，int64 为 `bigint`。Sync 推送进 `unhandledPush`。
- 两者的握手首包、请求、推送、心跳与 TCP 相同；不 Pump（或后台页被冻结）就不发心跳，超过 `idle_timeout` 被断开，恢复后重连。

### portal transport

- `/portal/servers`、`/portal/enter`、`/portal/login` 的 `enter` 加可选 `transport`（`tcp` 缺省、`ws`）；推荐服只在支持该方式的服里挑；指定的服没有该方式地址时答新错误码 `portal_transport_unavailable`，不回落 TCP。
- `ServerPresence` 加可选 `WSAddr`；旧登记等同只支持 TCP，存储格式不升版本。

### durability

- async 在写进 WAL 文件后回复：进程崩溃不丢已回复的修改；整机掉电或内核崩溃可能丢最后一个组提交间隔（缺省 10ms）。
- pipelined：入队后放实体锁，fsync 之后才回复；吞吐远高于 strict（strict 在锁内等 fsync）。
