# v1.51.0：一条命令接入独立 Gate，roost-genre 增加“定接入方式”

本版有两项重点：

- **`roost add gate`**：一条命令把“玩家 TCP 嵌在 game 里”的工程改成独立 Gate 部署。`roost project doctor` 新增 Gate 接法的检查。
- **roost-genre**：按使用反馈补了三处：
  - 新增“定接入方式”一步：短连接用嵌入 TCP，长连接缺省加独立 Gate；
  - Unity 客户端接入要点；
  - 接入方式的限制。

  入口 skill 检查更新时不再把文件写到工作目录之外。

逐条变更见 [CHANGELOG](../../CHANGELOG.md) v1.51.0 段。

**不兼容旧版。** 线上尚未部署，生成物不为旧工程留兼容。

## 升级须知（不兼容，按这里逐项处理）

1. **core 与生成器同时升级到 v1.51.0。** 没有声明 Gate 的工程，重新生成的结果和 v1.50.0 逐字节相同，不用改。
2. **改用独立 Gate：**
   1. 先装登录链路（login 模块，需要托管 account）；
   2. 执行 `roost add gate`；
   3. 跑 `roost project doctor`，确认 `gate:*` 五项都是 OK；
   4. 部署时把生产配置里 `player_access.gate` 下的 `CHANGE_ME` 地址填成客户端连得到的 Gate 地址。
3. **以前手写过 Gate 的工程**：生成器不认识手写的接线。可以改用这条命令，也可以保持手写；手写的接法见 [GATEWAY §2](../framework/GATEWAY.md#2-正式接入方式)。
4. **`-services game,gate` 从来不会生成 Gate**：它只会多出一个名叫 gate 的普通业务服务。照旧示例建过这种服务的工程，删掉它，改用 `roost add gate`。

## 主要内容

### `roost add gate`

- **命令**：`roost add gate [<名字>] [--service <玩家服务>]`，缺省名 gate。
- **`roost.yaml` 的变化**：新增 `access.player.gate`。Gate 是一个普通业务服务（etcd、nats，uses account），跑生成的 `accessplayertcp.NewGateMod()`。
- **玩家服务（game）的变化**：
  - `bootstrap.New()` 改走 Game Ingress；工程里有 `NewAuthenticator` 时用它校验。
  - 配置里关掉嵌入 TCP，两边用同一个命名空间、都开单实例锁。
- **客户端地址**：
  - Gate 接管原来给客户端的 7000 端口，`portal.servers` 不用改；
  - 装了 login 时，`login.presence.addr` 写成 Gate 的地址；
  - 部署模板里的 7000 端口移到 Gate 上。
- **重跑与拒绝**：同名重跑不改任何东西。没有玩家 TCP、没有托管 account、已有别的 Gate、名字冲突时，拒绝并说明原因。
- **doctor 检查**：`gate:ingress`、`gate:player-tcp`、`gate:namespace`、`gate:etcd-singleton`、`gate:client-address`。
- **顺带修正**：帮助和生成器文档里误导的 `-services game,gate` 示例换掉了；托管服务 collaborators 的路径更正为 `services/<名字>/collaborators.go`。

### roost-genre

- **compose §1A“定接入方式”**：
  - 短连接（按请求交互）和开房间类用嵌入 TCP；长连接（长期在线、持续推送）缺省加独立 Gate。
  - 业余模式按缺省规则走，专业模式请开发者确认；结论写进 DEMO 第 5 节和 HISTORY。
- **DEMO 第 7 节“Unity 客户端接入”**：SDK 怎么构建和导入、客户端代码怎么生成、最小接线步骤和边界。
- **限制表**：写明玩家协议只有 TCP；HTTP 业务路由不是玩家协议；独立 Gate 没有跨机验证。
- **入口 skill**：检查更新时把新版取到变量里比较，不再写到 `$TMPDIR` 下的固定文件名。入口版本改为 2026-11-16.1。

## 验证范围

在本机（macOS arm64）：

- **Gate 命令和检查**：命令与 doctor 检查都有单测，doctor 每一项都有先失败后通过的测试；被改到的文件里原有的 codegen 测试也通过了。
- **离线生成工程**：`scripts/test-gate-generated.sh` 已加进 pretag。生成工程、装登录链路、执行 `add gate` 后，编译、检查、doctor、`generate --check` 都通过，同名重跑也不改任何东西。
- **单机真实进程演练**：`scripts/testdata/gate-drill/gate-drill.sh` 跑 account、经 Game Ingress 的 game、Gate 三个进程，接真实的 NATS、Redis、Mongo、etcd。经 Gate 完成一次登录、建角、进入，三个进程都没有错误日志。证据见 [gate-command-20261116](../maintenance/evidence/gate-command-20261116/README.md)。
- **发版**：发版脚本的 pretag 会在 main 上把全套再跑一遍，包括 codegen 全量和全部模块门禁。

## 已知限制

- **独立 Gate 没有跨机验证。** 生成的接线只在单机、单个 Gate、一次登录上做过真实进程演练；多个 Gate、game 或 Gate 崩溃重启，只由 game-demo 手写接线的脚本覆盖。
- **生成的 Gate 参数固定**：
  - 配置里只开放地址和命名空间；TCP 和内部上限取缺省值，两侧 Ready 恒真；
  - 只认 account 签发的票据；
  - doctor 只检查开发配置里的地址。
- 其余见 [KNOWN-LIMITS](../maintenance/KNOWN-LIMITS.md)“玩家接入方式”。

发布不等于部署。
