# v1.53.0：13 类玩法改为模块组合，前后端公共协议目录，地形按地图归属选库

这一版是 v1.52.0 之后 2026-11-17 一批工作的结果，有四项重点：

- **13 类玩法改为模块组合**（R9）：每类玩法的脚本与夹具改成“装模块 + 只写模块没覆盖的部分”，场景名与条数不变，REAL 全绿。room 补了公开的身份围栏 `Room().Authorize`；`roost module verify` 改为先装工程配置表、只统计模块自带的用例。
- **前后端公共协议目录 `client_export`**：
  - `roost generate` 把协议、自身视图同步、消息号、错误码的 C# 代码和 `manifest.json` 写进一个固定目录；
  - `roost client sync` 把它同步进客户端仓库；
  - `generate --check` 和 doctor 的 `client-export:fresh` 核对导出目录是否过期。
- **地形按地图归属选库**（R3）：普通场景按服分库，分区场景共用；换服时建筑留在原地图，全服邮件在离开前按旧范围合并一次。
- **两个 review bug 修复**：room 连接登记随提交、按代际更新（RV-20261116-01）；自定义 Gate / 玩家服务名能握手（RV-20261116-02）。

逐条变更见 [CHANGELOG](../../CHANGELOG.md) v1.53.0 段。方案与维护者的决定：
- [R9 方案](../maintenance/PLAN-2026-11-17-r9-genre-modules.md)
- [client_export 需求与决定](../maintenance/FEATURE-2026-11-17-client-export.md)
- [KNOWN-LIMITS](../maintenance/KNOWN-LIMITS.md)：“13 类玩法是模块组合”“模块组合时的边界”“地形的库范围按地图归属”

**不兼容旧版。** 线上尚未部署，新生成的工程直接可用；已有工程按下面的升级须知处理，或者用新版重新生成后把业务文件搬回去。

## 升级须知

1. **core 与生成器同时升级到 v1.53.0。**
2. **room**：
   - 模块模板新增 `Room().Authorize(playerID, epoch, connection)`，`view.Room` 接口随之增加；
   - turn 改调这个方法。
   - 已装 room 的工程，要用的话按模块模板手动补上。
3. **module verify**：新装模块时，会在放了模块测试的包里写 `roost_config_data_test.go`，用来在测试前装载工程的 `configs/data`。已有工程不会自动补，需要时手抄一份。
4. **地形**：
   - 新生成的 game-demo 中，`terrain_chunks`、`buildings`、`terrain_editors` 三个 DAO 改为 `dbscope=boot`：普通场景按服分库，分区场景共用一个库。
   - 已有 demo 工程原来写在 global 库里的地形数据不迁移。
   - 换服时只交出 Player，建筑与编辑账本留在原地图。
5. **Gate**：自定义 Gate 或玩家服务名的工程，重新生成后 `wiring/gate.Options` 会带上 `GateService` / `GameService`。
6. **client_export 不默认开启**：没有在 `roost.yaml` 声明它的工程，生成结果与 v1.52.0 逐字节相同。开启后 C# 生成要 protoc 31.1（与 SDK 锁定的 Google.Protobuf 3.31.1 同版本），版本不对会报错。

## 主要内容

### 玩法模块化（R9）

- 各类装的模块、留手写的部分、跟随模块语义带来的变化，见 CHANGELOG 和 KNOWN-LIMITS 一“13 类玩法是模块组合”。
- 房间类玩法（塔防、回合 PvP、合作、撤离、自走棋）的房间并入 room 模块的 `Room`：
  - 新命令先过 `Authorize`；
  - 重启后要先 `RoomReconnect` 接管席位才能续局。
- SLG 原服奖励保留 Player 上的永久到账回执，因为 wallet 的 `Apply` 只在最近 128 次内去重。新增一条回归，SLG 缺省场景从 7 条变成 8 条。

### client_export

- 导出 8 个固定文件：proto 两份，C# 五份（Protocol、DaoSync、DaoSyncApply、MessageIds、ErrorCodes），加 `manifest.json`。manifest 里记录版本、源头哈希、每个文件的哈希、消息号与错误码清单。
- 两次生成的结果逐字节相同。导出的 C# 与 `Roost.Client`、`Roost.Client.Codecs` 一起，在 netstandard2.1 下编译通过。
- roost-genre 的 compose 里，Unity 接入缺省改为托管路线（`GameClient` + `RoostClientDriver`）。

### game-demo

- demo 自有的 10 个组件迁到组件包写法，可以在这些组件上写 `//roost:listen`。
- 地形与换服按上面的“地形按地图归属选库”实现。

## 验证范围

在本机（macOS arm64）上：

- **全量 pretag**：`go test ./...`、13 类玩法与各生成脚本（模块矩阵）、C# SDK，都通过。
- **真实依赖演练**（Mongo、NATS、Redis、etcd）：
  - demo 真实档 25 条，其中包括地形的按地图归属；
  - demo 换服六个 SIGKILL 点加 checkpoint；
  - Gate 使用自定义服务名 edge / world 的握手演练。
- 证据见 [batch-20261117-final](../maintenance/evidence/batch-20261117-final/README.md)。

## 已知限制

- **CellWorld 业务适配进模块**：这一版不做（维护者 2026-11-17），记在 KNOWN-LIMITS 二。
- **client_export 的验证范围**：只在 .NET SDK 下按 netstandard2.1 编译过，Unity Editor / Player 没有实跑。只打托管 DLL 的打包入口还没做。
- **`dbscope=boot` 是进程级开关**：起服时选一次，进程运行中不能改，这一点只靠约定，代码里没有强制。
