# v1.24.0 稳定基线说明

状态：候选版本，性能与发布门禁完成后发布。配套 [实现与验收](v1.24.0-IMPLEMENTATION.md)，[本轮性能记录](../review/STABLE-PERFORMANCE-2026-10-08.md)。

维护者要求：“开始性能验证，如果性能通过直接新版本发布，这个版本会作为短期内的一个稳定版本”。本版汇总 v1.23.1 之后已经收口的三大模块及 Remote 变更；稳定基线限定在已声明的业务负载和验收环境，不等于新的部署或跨机容量承诺。

## 本版变化

| 条目 | 变化与原因 |
| --- | --- |
| S1 | Remote outbox 只保留一个发布协调者，内部按全部 Entity 依赖有界并行；独立事务不再互相阻塞。投影负责持久提交，finalizer 负责确认和释放，成功语义没有提前。包含 RR-20261008-42～45、47。 |
| S2 | WAL 只接受 codec 7，移除旧格式和旧 Committer/Runtime 入口；正式落库统一走 DataEngine Projector/Assembly。静态 Player 跨机迁移只依赖落库数据，WAL 不承担跨机热迁移。 |
| S3 | Nest 统一快慢池配置与统计，Sync 统一 PrepareViews/subjectPacker，DataEngine 批量接口统一多 DAO 契约；删除旧 API 转发与兼容分支。快池业务/本地锁、慢池 I/O、setter 标脏及 Guard 锁内冻结语义保持。 |
| S4 | 按维护者要求撤销 DAO schema 自动迁移；只接受当前 schema，加载在全部水合前校验。Remote interest 必须携带非零代际和完整身份，拒绝旧发布端与无 payload Delete。 |
| S5 | 增加 WAL 只读诊断与完整副本入口，完善 Sync 接收基线及缺口恢复；Destroy 等锁可取消，已准入删除仍承担收尾责任（RR-20261008-46）。验收时钟与 KCP 停机测试收口（RR-40/41）。 |
| S6 | 恢复 Remote 完整 1h 和 Sync AOI 两模式性能验证，新增正式 Nest 消息/Entity/heartbeat 负载与上限、Saga 正向/补偿专项，冻结最低框架版本与发布清单，执行 pretag、故障矩阵及真实 tag 生成工程验证。实际结果只以验收文档为准。 |

以上是已有已授权优化的发布汇总，不增加共享帧网关、静态 Player WAL 热迁移或 Cube 仓库适配。Cube 已废弃。详细 API 清单与历史红绿证据见配套实现文档。

## 升级要求

这是尚未上线阶段的接口与格式收敛版本。**先停旧再起新，重新生成并编译业务工程**；当前生成器要求 core 至少 v1.24.0，不能将新生成物接到旧 core 上。

- 需要保留的未落库写入，先由能读取该 WAL 的旧程序完成落库。新程序使用新的 WAL 目录；旧格式明确拒绝。程序不自动清空、跳过坏记录或转换旧 WAL。
- DAO 只接受当前 schema。旧程序完成落库不代表不同 schema 会自动变成当前 schema；数据库数据的清理或业务转换由维护者另行安排，本版不自动执行。
- 手写 Nest option/config、Entity packer、批量 Store、Remote participant、Repository 构造等调用方须按当前 API 迁移，不能只替换依赖版本。Remote 两端应同步升级，不支持旧 interest 发布端。
- WAL 保证当前进程落库与恢复；静态 Player 跨机迁移以已落库数据为准，没有搬运本地 WAL 的步骤。

本版没有生产部署动作。支持范围为 macOS/Linux，Windows 专属问题不作验收门槛；真实引擎、生产网络与 24h 长稳仍不是本次已验证能力。
