# v1.61.0：Entity 伴生与对等组、DAO 同步兼容门禁、区域视图、新业务模块与实体 AI

这是相对 v1.60.0 的升级说明，完整变更见 [CHANGELOG](../../CHANGELOG.md)。

## 对玩家和运维的影响

- **Entity 伴生（companion）。** 实体标记加 `companionOf=<主实体>` 后，主实体（如 Player）可以在同一进程里按类型直接取到伴生实体（如 ActivityPlayer）。两者共用一个本地锁域，但仍各自持久、各自回滚。
  - 只从内存卸载（`deleteFromDB=false`，不论 reason）会保留已脱开伴生的声明；只有真正删档才结束主实体身份。
  - `ownership=shared` 的 Remote 种类不能参与伴生，`roost generate` 时直接报错。
  - 见 [ENTITY-COMPANIONS](../framework/ENTITY-COMPANIONS.md)。
- **对等组改由框架持锁。** 派发时逐个 Try 锁全部组成员，纳入同一事务和 Sync。
  - 组越大，越容易被同步快照、卸载等持锁方挤到重排。
  - 可 Remote 的种类不能入组。
  - `DispatchBroadcast` 改为每个目标一条消息。
  - memory 快路径准入后，如果组关系发布复核失败，仍确认同步门，回复 `ErrAfterCommitFailed`，不会卡住后续 Sync。
  - 见 [ENTITY-PEER-GROUPS](../framework/ENTITY-PEER-GROUPS.md)。
- **DAO 同步 schema 发版兼容检查。**
  - `roost verify-dao-sync` 比较已发布的 DAO 同步 proto 和当前生成结果，拦下字段号易主、删除、类型变化等不兼容改动；在末尾追加字段可以通过。
  - 值为切片的 map 的包装消息改为按元素类型命名（`SyncListInt32`、`SyncListSyncPair`），不再按生成顺序编号。
  - 见 [DAO-SYNC-PROTOBUF](../framework/DAO-SYNC-PROTOBUF.md)。
- **场景区域详情与计数视图**（`gameplay/regionsummary`，scenespace 可选启用）。
  - 区域层失败关闭后，`Space.Nearby` 退回普通 AOI，不会整张图变空。
  - 移动发布晚于 Forget 时放弃这次发布，不会把已离开的对象重新计进区域。
  - 见 [REGION-SUMMARY](../framework/REGION-SUMMARY.md)。
- **新业务模块。**
  - 新增 unlock、reward、itemuse、quota、quota_alliance。
  - task 区分任务状态和累计进度；activity 恢复锚点。
  - 可选的实体 AI 模块 `modules/ai`（decisionai），配合 `gameplay/ai/decision` 的可配置决策策略。在回执投递期间调用 `Apply` 会返回 `ai.ErrReentrantSwitch`。
  - 见 [modules/README](../../modules/README.md)、[AI-DECISIONS](../framework/AI-DECISIONS.md)。

## 升级与回退

1. **新生成工程需要 core v1.61.0。** `companionOf` 生成的注册代码和新模块用到了本版新增的 `entity.RegisterCompanionKind`、`CompanionID` 等接口。最小 core 在打 tag 之后单独提交提升。
2. **Entity 外部取锁入口已收紧，手写代码要跟进。**
   - 以下接口改为要求框架内部的 permit，业务代码不能再直接调用：`NewGuardScope`、`WithGuardScope`、`EntityGuardRelease`、`EntityGuard.RequireEntity` 等，以及 `ManagerAccess.WithLocked` / `UpdateEntityGroup`、`EntityBase.BeginGroupTransition`。
   - `GetMutex()` 改为返回受限接口。
   - `EntityManager.WithLocked` / `UpdateEntityGroup` 已删除。
   - `GetEntityGuard()` 在作用域外返回 nil。
   - 实体访问统一走 Nest handler；生成代码和仓库内模块已跟进。
3. **DAO 同步 proto 里的包装消息改名了。** 如果 DAO 里有值为切片的 map，生成的 `SyncListN` 会变成 `SyncList<元素类型>`。客户端的同步 proto 需要和服务端一起重新生成。项目还没有部署，不做旧名兼容；从本版开始以新命名作为 `verify-dao-sync` 的发布基线。
4. **回退。** 伴生关系不进 WAL，重启后都是"已声明、已脱开"的状态。回退到 v1.60.0 时，伴生实体按普通实体单独加载。新模块的 DAO 字段旧版本不读取。
5. **上线前要在目标环境验证。** 伴生和对等组的锁竞争、重排开销，以及新模块的业务语义，都只在本机单测和生成工程验收里通过过；跨机、容量和长时间运行都没有验证。task 的 `held` 模式领奖只读当前库存，物品可以转移时同一批物品可能让多名玩家各领一次，详见 task README。[已知限制](../maintenance/KNOWN-LIMITS.md)
