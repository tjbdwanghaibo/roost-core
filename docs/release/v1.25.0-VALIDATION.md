### 已通过的功能验证

| 检查 | 实际结果与范围 |
| --- | --- |
| 正式生成消费工程 | 真实生成 NewIngressMod / ProtocolRegistry / PB / Sender / Entity / DAO；TCP→NATS→Game→Nest 修改两个实体；文件 WAL 只有一笔唯一双实体事务；Sync Interval=1h，仍收到全量与 handler 后的 on_change delta。子进程测试开启 race；投影记录器是测试存储，鉴权器是 fixture，不当作真实 Mongo/Account RPC 验收 |
| 双 Gate / 双 Game | 四个 runtime、四个连接在同一 Go 进程，使用私有真实 NATS 与 TCP；固定 SID、Game/系统广播、旧 Game 代次被 fence，另一 Game 继续服务；三轮 race 通过，不等于四个独立业务进程或跨机 |
| Lockstep | 实际 Room 单一 owner、Input、C7、Catchup、重连、迟到旧断线条件解绑、旧绑定发送拒绝；三轮 race 通过；未把原协议单测当新 Gate 的 Hash/旁观者/慢追帧矩阵 |
| 故障与容量 | Game 出站准入后 ACK 被适配器丢弃，旧 lifetime 关闭且不重放；广播 ACK 丢失保留 Unknown，同 ID 查询首次结果不重复写；旧 Unbind/Close 不影响替换；控制条目上限与排队过期；Stop 超时保留真实业务等待及重试；三轮 race 通过。适配器丢回信不是物理网络丢包 |
| 真实 ACL | 临时私有 nats-server 子进程，实际用户权限拒绝伪造 Gate/Game 来源及他人 inbox；合法请求与有限回信成功；三轮 race 通过；不是生产完整 ACL 已部署 |
| 启动订阅故障 | 错误回调在 Start 返回前发生，故障位不被末尾覆盖；真实 TCP 鉴权拒绝且业务零执行，三轮 race 通过 |
| 共享 TCP / NATS | 阻塞写被 Close 中断，push 序号与实际 stream 顺序一致；命名 inbox 每前缀一个有界订阅，256 并发、取消/迟到回信隔离、NoResponders、Client Close 唤醒通过 |
| 全仓检查 | 最新 `go test ./...` 通过（`/private/tmp/roost-gate-all-second.log`）；macOS arm64 Go1.27.0 build/vet、受影响包 race、Linux amd64 交叉构建通过；不是 Linux 实机测试 |
| 生成 | 两次 `go generate ./...`，精确 diff 相同，无漂移；正式生成 Mod 另有真实消费回归 |

TCP Close 原来先等 writeMu，慢 socket 正在持锁写时不能及时中断；现在先 Close socket，再维护状态。Room 迟到断线新增 DetachSession 校验数值 receiver，不无条件按 player 解绑。Game 控制通道新增有限条目/字节队列，避免只有 worker 数量而没有吸收同批请求的等待容量；期限从接收计算。响应入队使用原 dispatcher context，避免重新取得完整预算。NATS 订阅故障在启动期间到达后不能被重新置 healthy 覆盖。

### 2026-10-09：队列容量与 Block AOI 方案
