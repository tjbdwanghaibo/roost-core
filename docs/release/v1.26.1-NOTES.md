# v1.26.1：安全与构建修复补丁

发布状态：**待发布**（tag 提交与验收结果见[验收篇](v1.26.1-VALIDATION.md)）。日期 2026-10-14。范围：`v1.26.0`（`1e6f0e71`）之后到本版 release 提交。

本版是补丁版：**运行时契约、配置、wire / 存储格式不变；生成物要求的最低 core 仍是 v1.26.0**（当前生成器生成的 game-demo 钉 v1.26.0 实编 build / vet 通过）。条目与[实现篇](v1.26.1-IMPLEMENTATION.md)同号；变更原文以 [CHANGELOG `[v1.26.1]`](../../CHANGELOG.md) 为准。

## 1. 建议所有 v1.26.0 使用方升级的原因

| # | 变化 | 影响谁 | 你需要做什么 |
| --- | --- | --- | --- |
| P1 | 安全：`toolchain go1.27.2`、`golang.org/x/net` v0.60.0 | 所有使用方。go1.27.0 标准库有 11 个已公开漏洞（GO-2026-6599…6617，net/http、crypto/tls、html/template 等），x/net v0.58.0 有 GO-2026-6617；跑 govulncheck 的 CI 会失败 | 升级 core 到 v1.26.1；已生成工程在自己的 `go.mod` 加 `toolchain go1.27.2`（新生成的工程已带）；`GOTOOLCHAIN=auto`（默认）时自动使用 go1.27.2 |
| P2 | roost-core 放进 go.work 报 `ambiguous import`（`google.golang.org/genproto`） | 用 go.work 同时开发业务与框架的使用方 | 升级到 v1.26.1 即可；不再需要在工作区里 `go get google.golang.org/genproto@latest` 的绕法 |
| P3 | game-demo 账号计数器前缀与退役键冲突（RV-20261014-01） | 基于 game-demo 模板、且把 `account.key_prefix` 设为 `roost:demo` 的工程 | 该前缀现在在绑定时被拒；已在用的部署先停写，把该前缀下全部键迁到新前缀，再按当前模板重新生成 `internal/service/account/collaborators.go`；默认前缀不受影响 |
| P4 | game-demo 机器人 `scene_watch` 读不到场景帧 | 用 game-demo 的 `cmd/loadtest` 做验收的工程 | 按当前模板重新生成 `cmd/loadtest/main.go` 并加入 `cmd/loadtest/scene_watch_test.go` |

P3、P4 是生成物（业务所有）里的模板缺陷，`roost project sync` 不会覆盖业务已拥有的文件，需要按上表手工更新。

## 2. CI、测试与门禁（不影响使用方运行时）

- C1：CI `windows-compatibility` 只验证编译与 CLI（维护者 2026-10-14；平台保证范围仍为 macOS / Linux）。
- C2：CI `upgrade-compat` 按 v1.26.0 升级要求补齐删除 `event` feature 的手工步骤。
- C3：CI `nightly-gapmap` 取样时给测试二进制加地址空间上限，避免中和守卫后 OOM 拖垮 runner。
- C4：framework-compat 失败时输出各服务 WARN/ERROR 与进程状态。
- T1：integration 标签用例在真实依赖上补跑（21 包 186 用例，见 [EXTERNAL-VERIFICATION](../maintenance/EXTERNAL-VERIFICATION.md)），过时夹具 `TestRealDataEngineLargeBacklogRecovery` 修正。
- T2：需要真实依赖的 opt-in 用例挂到 CI / 脚本入口并由根包门禁钉住。
- T3：真实 Redis 用例按唯一前缀清理自己写的键（新增测试辅助 `infra/storage/redis/redistest`），CI 要求跑后 Redis 为空。
- T4：测试与基准名里的旧池名改为 short / io（只改测试名）。

至 2026-10-14，main 上全部 GitHub workflow 为绿（自 10-08 以来首次）；各失败的根因与修复见实现篇。
