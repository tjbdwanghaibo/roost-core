# v1.45.0：业务模块、登录链路与按需求组合的 skill

本版把 roost-core 从“框架”扩成“框架 + 业务模板”：42 个业务模块可以一条命令装进生成工程，客户端够得着的登录链路成形，game-demo 与两个配方改由模块组合，组合 skill 重写成“按需求复用模块、查限制、手写其余”。逐条变更、决策出处与证据见 [CHANGELOG](../../CHANGELOG.md) v1.45.0 段，模块清单见 [modules/README](../../modules/README.md)，组合流程见 [compose](../agent-skills/roost-genre/references/compose.md)。

**协议、存储与生成物都不兼容旧版。** 线上尚未部署（维护者 2026-10-06 起的口径），本版不做旧进程 / 旧数据兼容；模块的改动只对新生成的工程生效，已装模块不会随 core 升级自动更新。

## 主要内容

- **业务模块安装器 `roost module list | plan | add | verify`**：模块是 `modules/<name>/` 下的清单与模板，编进 CLI。安装做的事：
  - 分配协议号、错误码、组件号；
  - 把状态作为嵌套结构体追加到所挂实体的主 DAO；
  - 代办所需的 Mod、服务、配置段、Saga 与持久定时器类型；
  - 写入与已装模块之间的联动（`with/<另一个模块>/`）；
  - 失败整体回滚；
  - `verify` 跑每个模块的固定场景，外加工程级检查。
  没有卸载；分配过的号与存储键不回收。
- **42 个模块**，每个都有 README（能力 / 能力边界 / 复用方式 / 联动 / 验证范围）：
  - 进入与登录：enter、login、portal、servertime、rules、rehome（单个玩家换服）；
  - 档案与资产：profile、naming、wallet、bag、equipment、attribute；
  - 日常与经济：checkin、task、stamina、shop、gacha、idle、cdkey、purchase、mailbox；
  - 社交：chat、notice、friends、team、alliance（独立联盟服务 + 三个跨域 Saga）、leaderboard；
  - 对局：matchmaking、matchroom、room、turn；
  - 场景与战斗：actor、scene、monster、terrain、combat、dungeon、skillbook；
  - 活动与运维：activity、activity_world、activity_alliance、gm。
- **登录链路**（维护者 2026-11-12 定型）：
  - account 签发与校验全部票据，并提供区服清单；
  - portal 的三个 HTTP 端点（登录、区服清单与推荐、换进服票据）挂在 account 的进程上；
  - Gate / 玩家 TCP 握手时用 `enter:<进服票据>` 交 account 校验；
  - game 推 `EnterStatus{need_create}`，客户端发 `EnterCreate{name}` 再发 `EnterGame`。
  嵌入 TCP 与独立 Gate 各在单机真实进程上演练过一次。
- **配方**：`roost project new -recipe casual | turn-pvp`，在 game 底座上装好一组模块与登录链路。
- **game-demo**：进入、聊天、排行榜、背包、档案、邮件、属性、装备、组队、登录等改用模块。
- **gateway**：`GameDependencies.OnActivated(Binding, receiverID, Principal)`，会话激活之后把认证主体交给业务。生成的 `SessionObserver` 签名改为 `SessionActive(registry, principal)`，login 模块去掉了 30 秒的主体缓存。
- **生成器**：
  - 独立 Gate 部署时，game 用 `WithoutServiceRegistration()`，不再重复注册 etcd 服务；
  - 生产配置的 `web.addr` 保持回环地址，不再留 `CHANGE_ME`；
  - 模块代办 heartbeat / directory Mod、attribute feature 与显式 Sync packer。
- **框架其他**：
  - dataengine 新增交出实体 `Runtime.HandOffEntity`；
  - account 一侧支持单个角色换服；
  - 地形副本订阅超限时 `Replicator.Want` 返回错误，地图参数对外一律是副本，水深按 64 位计算；
  - combat 效果补齐 `ExpectedFailureNone`；
  - codegen 的嵌套类型识别不再依赖文件名顺序，DAO 超过 64 个顶层字段在生成期拒绝。
- **组合 skill**：
  - 四条规则：遵循框架核心思路；模块里有的逻辑复用；不能复用就借鉴最接近的模块；需求与限制冲突必须提出；
  - 玩家操作在提交之后打业务日志，用框架的日志。
  一个没有上下文的 agent 只按 skill 做出了八条需求的服务端，两条冲突按规则停下报告；试用暴露的文档与模块问题已在本版修掉。

## 升级步骤

1. core 与生成器同时升级到 v1.45.0，重新生成工程。新生成物要求 core 至少 v1.45.0（`wiring/modulehost`、gateway `OnActivated`）；生成器清单里的最低版本在本版 tag 推上去之后的下一笔提交才抬到 v1.45.0。
2. **先停旧进程再起新进程**。不迁移旧数据：Player DAO 追加了模块状态，demo 的 Player schema 升到 3。
3. 自己实现过 `SessionObserver` 的工程改成新签名；独立 Gate 部署按 login 模块 README 的接法配置（game 关闭嵌入 TCP 监听）。
4. 上线前要补、模块不替你做的：
   - 渠道验签（`internal/service/account/login_channels.go`）；
   - 登录入口前面的 TLS 与限流；
   - 生产地址与区服登记（`cmd/accountctl upsert-server`）；
   - chat / platform / session 托管服务的 collaborators。
   `login.dev_token` 只写在开发配置里。

## 验证

发版前在 main 上跑过（本机 macOS）：

- 全仓 `go test ./...` 165 个包；
- `scripts/test-modules-generated.sh`：42 个模块、47 组联动，正序与反序各建一个工程同装；
- 新生成的 game-demo：build / vet / `roost id check` / `roost generate --check`，自己的 62 个包，`roost module verify`；
- codegen 的 `TestDemo|TestModule|TestRecipe`，零 SKIP；
- 文档锚点 344 个文件无断链。

试用发现的 task / checkin / gacha 修复之后，又跑了 `TestModule`、`TestRecipe|TestDemo`、模块门禁脚本与 game-demo 生成检查。

真实进程演练（单机）：

- 登录链路：嵌入 TCP 与独立 Gate 各一次；
- Gate 联合回归：C# 客户端；
- 联盟管理全链路，以及 Scene / Terrain 的启动与业务拒绝后同连接继续。

**未覆盖**：

- Linux 与跨机部署；多个 Gate、account 多副本；
- C++ 客户端的 Gate 回归（本机没有 protobuf）；
- 容量与长时间稳定性；
- 模块的场景都是离线跑的（替身提交器）；
- 几个模块组合之后、联动没有覆盖的行为；
- shop、activity 等模块的自带场景在工程换配置表后会不会变红，尚未确认（见 KNOWN-LIMITS）。

发布不等于部署。
