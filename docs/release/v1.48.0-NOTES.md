# v1.48.0：后台 checkpoint 缺省打开、CellWorld 按来源分订阅、模块后台 manager 与登录潮修复

本版有四项重点：

- DataEngine 一轮回放内的后台 checkpoint 合入，经 M-19 开 / 关对照无退步后**缺省打开**。
- CellWorld 的 Base 按来源 Cell 分订阅、并行解码（D13 C），内部线上格式升到 v13。
- 模块清单可以声明后台 manager（D22）：login 的会话激活告知与 rehome 的后台步骤改由 `game/managers` 里的 manager 执行，manager Mod 统一启停。
- 千人登录潮下 game-demo 进入路径超时的两处根因修掉：登录不再同步等 World 的登录计数，chat 同一频道的写在进程内排队。

逐条变更与证据见 [CHANGELOG](../../CHANGELOG.md) v1.48.0 段；性能记录见 [M-19 结果](../maintenance/evidence/checkpoint-experiment-20261114/README.md#m-19-结果2026-11-14)、[D13 C 与 M-15](../performance/benchmarks/cellworld-d13c-20261114/README.md)、[登录潮](../performance/benchmarks/login-burst-20261115/README.md)。

**不兼容旧版。** 线上尚未部署，存储、协议与生成物都不为旧进程、旧数据、旧生成工程留兼容。

## 升级须知（不兼容，按这里逐项处理）

1. **重新生成工程**。manager 登记、demo 的登录改动只对新生成的工程生效；core 与生成器同时升级到 v1.48.0。
2. **后台 checkpoint 缺省打开**。`dataengine.projection.background_checkpoint` 不写时为 `true`；要回到逐单元同步确认写 `false`。`WAL.Ack` 的同步契约不变，未确认额度只在 checkpoint 持久成功后释放。直接构造 `engine.ProjectorOptions` 时零值仍为 false。
3. **CellWorld 内部线上格式 v12 → v13**。收件主题改为 `roost.cellworld.<world>.<to>.c.<from>`（托管格的进程发件）与 `roost.cellworld.<world>.<to>.b`（只托管玩家的进程发件）；`cellworld.Subject` 删除，改用 `SubjectFromCell` / `SubjectFromBase`。先停全部旧 CellWorld 节点再起新版本，混跑时消息按坏消息拒收。按旧主题配置的 NATS Subject 级 ACL 要按新形状更新。
4. **`NodeConfig.Ext` 处理器与 `PlayerEntity` 必须并发安全**。不同来源 Cell 的消息现在并行处理，这两个回调会被并发调用。
5. **模块的后台 manager**。装 login 或 rehome 的工程，`game/managers/managers.go` 的 `Managers()` 里要有 `NewLoginNotices()` / `NewRehomeBackground()`（新生成与安装器自动登记；服务缺 manager Mod 时安装器代办 `roost add mod manager`）。v1.47.0 之前的 `internal/service/<服务>/managers.go` 布局安装器拒绝。rehome 的后台执行者不在时，`RehomeApply` / `Move` 答 retryable。

## 主要内容

### DataEngine：后台 checkpoint

一轮 `ReplayPass` 内由单个后台写者确认“已成功投影、事务标记保证可幂等重放”的连续前缀，投影不等 checkpoint 落盘就继续下一单元。快路记录、非批量 Store、含快路的并行窗口、下一并行窗口之前与每轮退出仍等真实确认；回放返回前写者已排空。M-19（128 / 256 并发开 / 关各 3 轮）各阶段零失败，吞吐与延迟在噪声内持平：没有退步，也没测出收益；≥3 秒样本全部来自单联盟热点入会的排队，开 / 关一样。

### CellWorld：Base 按来源 Cell 分订阅（D13 C）

每个进程对 Grid 里每个格各订一个来源主题、再订一个共用主题；同一来源按序，不同来源并行，一个慢来源不挡别的来源。接收复制缓存按来源格分片，总量上限不变；每条消息自带完整成员表的契约不变。本机同机对照：4 个来源时 Base 接收吞吐约 2×。

### 模块后台 manager（D22 第一部分）

模块清单新增 `managers: [<构造函数>]`，安装器把它们登记进 `game/managers/managers.go`。Stop 不再接新工作、取消在途工作的 ctx 并在期限内排空。rehome 的后台步骤被停机取消时按崩溃处理，重启后 `Admit` 接着做。activity_world / activity_alliance 驱动与 cellworldhost 还没迁。

### 登录潮（M-15 排查）

- game-demo 的 EnterGame 改为投递 World 登录计数（`Send_RecordEnter`），不再在唯一的 World 上逐次等 fsync；chat 同一进程对同一频道的写先排队再 compare-and-set。千人约 5 秒登录潮下进入路径失败 422 → 0、请求超时 438 → 0。
- game-demo：进复制场景前请求期限已过时 EnterGame 答 `login_timeout`，loadtest 机器人退避重试；登录公告合并为每秒至多一条；新增 `scene.partition.spawn_spread`（缺省 0）。
- 性能段 s11（M-15）缺省进入点分散 1400，**测试条件已改**，不能与此前的 M-15 直接比较。

## 验证范围

在本机（macOS arm64）：

- 发版前在 feat/v148 上跑 pretag 全套（build、vet、tidy、全仓测试、18 类生成工程与模块门禁、C# SDK），发版脚本的 pretag 会在 main 上再跑一遍。

## 已知限制

- **M-15 千人仍不稳定**：进入点分散后三轮失败 240 / 21 / 417（中位 240，修复前同机 310～371，条件不同不能直接比较）；同一出生点两轮 962 / 0。剩余失败是“预热结束时未停在分散目标内”，原因尚未确认。Base 在千人同点下的兴趣 / 同步容量优化已决定另起一批。
- **热点单例实体的写吞吐**：经派发器打到同一实体的同步请求约每次 fsync 一条（strict、pipelined 第一阶段、async 都是），热点单例上的计数类写入要只投递。
- 其余框架限制、已决定待实施事项（换服在途清扫、地形库范围、模块配置声明、其余后台循环改 manager、portal 上报、room 断线与重启、13 类玩法改模块组合）与外部环境验收见 [KNOWN-LIMITS](../maintenance/KNOWN-LIMITS.md)。
