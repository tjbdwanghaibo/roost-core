## 2. 仓库验证结果

验证环境为本机 Windows、Go 1.27.0，命令关闭工作区模式（`GOWORK=off`）。框架正式支持范围仍是 macOS/Linux，本次检查不增加 Windows 支持承诺。

| 检查 | 结果与含义 |
| --- | --- |
| `go build ./...` | 通过，框架源码可编译 |
| `go vet ./...` | 通过，已执行 Go 静态检查 |
| `go test -count=1 .` | 通过；最后一次为 45.336 秒，包含根包文档和示例门禁 |
| `go test ./skill -run '^TestUserGuideExamplesCompile$' -count=1` | 通过；最后一次为 1.197 秒，实际解析并编译手册 JSON |
| `go vet ./skill` | 文档测试迁移后再次通过 |
| 入门示例 `examples/configgen` | 实际运行成功，按预期拒绝非法引用并完成后续热更 |
| Markdown 相对链接 | 发布记录回填后检查 3,356 个链接，未发现失效文件路径 |
| Git 补丁格式 | `git diff --check` 通过 |

完整 `pretag` 流程已经执行到全仓测试：生成物无漂移、发布清单、编译、vet 和 tidy 检查通过。首次生成和 tidy 曾触发 Windows Git 索引的换行状态变化；刷新索引后确认文件内容未变，没有把这类状态变化作为代码修改提交。

**全仓测试没有全部通过。** 删除 AI 文档引起的一项测试失败已经处理；另外六项失败在未改动基线上同样复现，见下一节。文档测试修正后，重新运行了受影响测试和根包门禁，没有把之前失败的整套测试重新记为通过。

### 文档测试为什么要修改

旧 `skill/prompt_test.go` 要求 AI 提示词文件存在，与本次清理目标冲突。现改为 `skill/documentation_test.go` 中的 `TestUserGuideExamplesCompile`：从保留的技能手册提取完整 JSON，要求至少有一个示例，并调用实际 `Parse/Compile` 验证。

这项修改让测试继续保护读者会复制使用的内容。没有修改 Skill 运行时，没有添加测试跳过条件，也没有放松原有运行时断言。

## 3. 六项基线失败

以下均在未改动的 `9d955fb0` 定向复现，其生产代码与 v1.24.0 相同。这说明它们并非本次文档清理新引入，但仍不能算作测试通过。

| 包 / 用例 | 本机现象与核实结果 |
| --- | --- |
| `codegen/internal/entity` / `TestMirrorDTOGeneratesReadOnlyView` | 工作区 fixture 使用 CRLF，生成输出使用 LF。独立重新生成后原始字节不等，统一为 LF 后相等；没有修改模板或基准文件。 |
| `kit/statslog` / `TestEntityGaugesReturnToZeroWhenAKindEmpties` | 清理临时目录时报日志文件仍被 Windows 进程占用。 |
| `log` / `TestRotationFailureKeepsWritingTheCurrentSlice` | 通过 `Chmod(0555)` 模拟不可写目录，在本机没有产生用例预期的轮转失败。 |
| `log` / `TestAFailingConsoleDoesNotStopTheFileSink` | 清理临时目录时报日志文件占用。 |
| `nestwal` / `TestInspectPreservesCorruptRecordAndSuffix` | Windows 区域锁阻止检查程序读取 `writer.lock`。 |
| `nestwal` / `TestInspectValidWALCancellationAndUnsafeDestinations` | 创建符号链接时缺少系统权限。 |

本次没有修改这些测试、生成模板或发布脚本。按维护者已明确的“本地编译通过即可，不等待 GitHub CI”要求发布文档补丁，同时保留这些失败记录。macOS/Linux 的运行时验收沿用 v1.24.0 具名记录。

## 4. 已发布版本的独立工程验证

发布后，从 GitHub 下载真实 v1.24.1 模块，并使用这个版本的生成器创建独立 `game-demo` 工程。这一步确认下载和工程生成入口可用，避免只验证本地工作树。

```sh
# 验证时使用已安装的 Go 1.27.0；以下为 macOS/Linux 写法。
export GOWORK=off
export GOTOOLCHAIN=go1.27.0
go mod download -json github.com/tjbdwanghaibo/roost-core@v1.24.1
go run github.com/tjbdwanghaibo/roost-core/codegen/cmd/roost@v1.24.1 project new docs-consumer \
  -module example.com/roost-docs-consumer -out ./docs-consumer -template game-demo
cd docs-consumer
go list -m -json github.com/tjbdwanghaibo/roost-core
go build ./...
go vet ./...
go test -count=1 ./...
```

实际验证使用 Windows PowerShell 的等价环境变量设置，并通过 `GOPROXY=direct` 下载。生成器创建 456 个文件，默认更新策略把启动依赖 v1.24.0 解析到本次最新标签 v1.24.1。`go list -m -json` 确认版本为 v1.24.1，没有本地 `replace`；模块下载记录的提交也与标签一致。

独立工程的 **build、vet 和全部包测试均通过**。这不等于已经启动全部线上服务，也不等于完成真实 Unity/Godot/Unreal、跨机故障或长时间负载验收。生成器默认解析最新发布版，未来复现时应先核对 `go list -m`，不能把未来的最新版本当作本次测试版本。
