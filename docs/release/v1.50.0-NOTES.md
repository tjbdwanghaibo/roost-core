# v1.50.0：生成工程的功能包统一放 game/modules，换服复制结果未知的修复

本版有两项重点：

- **生成工程的目录约定**：`game/` 下只留固定的框架层（`components`、`controllers`、`entities`、`handler`、`managers`、`view`）和 `game/modules/`。功能包统一放 `game/modules/<包>/`，包括模块自带的包、生成器的功能目录，以及业务自己手写的玩法包。
- **换服搬档（RV-20261114-01）**：复制到目标库时，即使结果未知（提交应答丢失），也不再直接中止并在目标库留下没人负责的副本。

逐条变更见 [CHANGELOG](../../CHANGELOG.md) v1.50.0 段。

**不兼容旧版。** 线上尚未部署，旧生成工程不做自动迁移，按下面的步骤手动改。

## 升级须知（不兼容，按这里逐项处理）

1. **core 与生成器同时升级到 v1.50.0。** 新生成的工程直接是新布局。
2. **旧工程手动迁移目录**（步骤与完整命令见 CHANGELOG v1.50.0 段第一条）：
   1. 用 `git mv` 把 `game/<包>` 挪到 `game/modules/<包>`。要挪的有：
      - 模块的 27 个包；
      - 生成器的 `skills`、`effects`、`heartbeat`、`gameplay`；
      - 工程自己手写的功能包。
   2. 改 import 路径：`<module>/game/<包>` 改为 `<module>/game/modules/<包>`，然后 `gofmt -w`。
   3. 同样改 `roost.yaml` 里 `modules` 段记录的文件路径，以及脚本、Makefile、CI 里写死的 `./game/<包>`。
   4. 依次跑 `roost project sync`、`roost generate`、`roost module verify`，再跑 `go build ./... && go test ./...`。
   - 包名和 import 关系都不变，只是路径多一层。
3. **安装器的新规则**：
   - 模块的模板文件只能放在六个框架层或 `game/modules/<包>/` 下；
   - `runtime.package` 必须在 `game/modules/` 或 `services/<服务>/` 下；
   - `game/modules/` 目录本身不能放文件。
   - 自写模块（非仓库自带）的清单要跟着改。
4. **`CopyHandedOffEntity` 出错时的返回值变了**：
   - 写目标库的事务出错（冲突除外）时，返回的 `EntityCopy` 连同错误一起，列出可能已经写进目标库的文档，`Outcome` 为 `unknown`（`wiring/dataengine.EntityCopyUnknown`）；
   - 自己调这个接口的代码不能再把“出错”当成“目标库里什么都没有”：要么重做复制，要么拿这份清单调 `DropEntityCopy` 清理。
   - rehome 模块的驱动器已按这个约定处理（见下）。

## 主要内容

### game/modules 目录约定

- **为什么改**：模块越装越多，`game/` 顶层跟着变多，模块的包和框架分层混在一起。
- **改成什么样**：现在 `game/` 的顶层固定不变，`game/modules/<包>/` 放所有功能包。
- **生成器**：`roost add skill`、`add effect`、`add heartbeat`、`add attribute` 都改为写进 `game/modules/` 下。
- **roost-genre**：玩法夹具和指南（目录约定）都改成同一规则。
- **game-demo**：从模块和生成器带来的部分已经跟着挪了；demo 自己手写的包暂时留在 `game/<包>`，后续用新框架和模块重构时一起处理。

### 换服复制结果未知（RV-20261114-01）

原来复制档出错时一律中止，不区分“确定没写入”和“已提交、只是回复丢了”，中止后目标库可能留下一份副本；开了预加载时，目标服还会把它装起来。

现在 rehome 驱动器的处理是：
1. 复制出错先重做，最多 3 次。复制可以原样重做，已经写进去的会答“已在”；拿到确定结果，就照常改绑。
2. 3 次都失败才中止，并在解除源服的迁出保护之前，按清单删掉目标库里的副本。
3. 中止时如果 account 答“已经在别处提交”，就按没复制过处理：先补复制，写成了再删本服的档。

rehome 的模块场景从 47 条增加到 50 条。

## 验证范围

在本机（macOS arm64）：

- **换服修复**：先失败后通过。核心层有提交应答丢失的用例，驱动器有三条场景；把“仍归本服才删目标库副本”这个判断去掉，对应用例会失败。
- **目录调整**：
  - 全部模块门禁通过，各模块场景数不变；
  - 新生成工程装模块、加 skill / effect / heartbeat 后，编译与测试通过；
  - pretag 的 17 个玩法脚本全部通过；
  - 根包、文档锚点检查通过。
- **发版**：发版脚本的 pretag 会在 main 上把全套再跑一遍。

## 已知限制

- **换服复制仍有一个窗口**：3 次都失败后，那次迟迟没生效的提交如果晚于删副本才落地，目标库仍会留一份，下次换到那个服时会被覆盖。结果未知期间源服重启的续做属于 D8，还没有自动恢复。
- **game-demo 的布局还没完全统一**：demo 自己手写的包仍在 `game/<包>`。
- 其余框架限制、已决定待实施事项与外部环境验收见 [KNOWN-LIMITS](../maintenance/KNOWN-LIMITS.md)。
