# v1.55.0：Remote 共享 kind、改密码吊销游戏 token、WebGL 单线程 SDK、机器人按步计时与 saga 分组、两轮审查问题修复

这一版包含 v1.54.0 之后 2026-11-18 当天的工作，重点有五项：

- **Remote 共享 kind**：`//roost:entity … ownership=shared` 声明的实体生来就是共享的，首次写入时一次认领到位。facebook 和 team 都已改用。另外修了一个框架缺陷：读一个根本不存在的 Remote 实体，原来也会把它认领下来。
- **改密码后游戏账号 token 自动作废**（交接 C6 选 B）：渠道提供的凭据版本变了，`Login` 就把 `GameTokenGeneration` 加一。
- **开房间 SDK**：
  - C# 支持 Unity WebGL（`PumpDriven` 单线程模式，A1）；
  - 高层离开返回“房间已不在”标志；
  - Go 版 deflate 复用压缩器。
- **机器人负载**：每一步单独计时；saga 轮询归到 `saga` 组，p95 门槛只算 saga 以外的时间（维护者：saga 有能力就行）。
- **遗留与审查**：
  - 换服遗留：合服时检查在途换服；预加载 Mod 把自己发布出来；补了 Cluster 演练。
  - `fix/core-game-server-review` 分支上两轮审查的 6 项，全部在 main 上修复。

逐条变更见 [CHANGELOG](../../CHANGELOG.md) 的 v1.55.0 段。

**不兼容旧版。** 线上尚未部署，所以不做兼容。已有工程按下面的升级须知处理，或者用新版重新生成后把业务文件搬回去。

## 升级须知

1. **core 与生成器同时升级到 v1.55.0。**
2. **account**：账号记录多了 `CredentialVersion` 字段。渠道实现可以在 `Verified.CredentialVersion` 里带上密码或凭据版本（不透明字符串，最多 128 字节）；不带就保持原来的行为。
3. **开房间 SDK 改了签名**：
   - Go `Client.Leave` 返回 `(LeaveResult, error)`；
   - C# `LeaveAsync` 返回 `RelayLeaveResult`；
   - TS `leave()` 返回 `{ roomGone }`。
   - 快照可能被丢弃：Go `ErrSnapshotStale`、C# `RelaySnapshotResult.Stale`、TS `pushSnapshot` 返回 `undefined`。调用方要能处理这种结果。
   - lobby 的席位多了 `presence_seq` 字段；旧的房间记录等它们过期。
4. **C# SDK（WebGL）**：
   - `LobbyClient` 的 HTTP 抽成了 `ILobbyHttp`，原来的 `UnityWebRequestHandler` 换成参考实现 `UnityWebRequestLobbyHttp.cs`。
   - WebGL 构建要打开 `RelayClientOptions.PumpDriven`，lobby 也要用 `pumpDriven`，并且每帧调用 `Pump`。
5. **C# 错误码常量**：与 `ErrorCodes`、`Name`、`Message` 或 object 继承成员同名的常量加了后缀 `_`（例如 `name` 变成 `Name_`）。用到这些常量的客户端代码要跟着改。
6. **`WriteAuthority.ClaimAuthorityState` 多了 `shared` 参数**，自定义的写权实现要跟着改。
7. **模块**（只对新生成或重新安装的工程生效）：
   - facebook 和 team 的实体声明 `ownership=shared`。旧数据里“认领了但还没切成共享”的记录不会自动转换，按清空处理。
   - mailbox 的 `with/rehome` 离开钩子：邮箱满、全服邮件没合并完时会中止换服。已生成的工程需要手动同步 `game/controllers/mailbox_rehome.go`。
8. **机器人**：
   - `cmd/loadtest` 的 `-max-p95` 默认判 `p95_excluding:saga`；传 `-p95-exclude-group ""` 回到按整个场景算。
   - 场景 YAML 里写 `group` 需要新版 core。

## 主要内容

### DataEngine / Remote

- 共享 kind 的声明：`entity.DeclareRemoteSharedKind` 与 `RemoteKindShared`。
  - 首次写入时插入的就是一条共享的所有权记录。两个进程同时第一次写，都会成功。
  - 不能退出共享。
  - Redis marker 这种非持久的所有权存储，不支持共享 kind。
- 请求一个内存和权威里都没有的 Remote 实体时，先确认它存在再认领。不存在就答 `entity_not_found`，不再留下一条空认领。
- facebook 的 `Ensure` 只做 `GetOrCreate`，去掉了 `ErrOpening`。team 建队一步就是共享认领。

### account

- 改密码自动吊销游戏 token：凭据版本变了就加一代。第一次见到只记录；版本为空或相同时不动；被封的账号照样记录版本。
- 合服前检查在途换服：`MergeServer` 遇到在途换服时报 `ErrTransferInProgress`，并在 `MergeResult.TransfersInFlight` 里列出这些换服。

### 开房间 SDK

- C# 的 `PumpDriven` 模式不使用线程池和计时器，心跳、超时和重连都由 `Pump` 推进。Unity 6000.7.0b7 的 WebGL 构建在浏览器里实测两次通过。
- 离开时如果 lobby 答 `room_not_found`，就当作离开成功，`RoomGone` 为 true。
- Go deflate 改用 `sync.Pool` 加 `Reset`：1KiB 快照每次压缩的分配从 1.08 MB 降到 836 B。

### 机器人

- 每一步都有计时（`steps`），还可以给步骤分组（`groups`）、按 `p95_excluding:<组>` 设门槛。
- game-demo 里 8 处 saga 轮询归到 `saga` 组。100 人同时起跑（机器忙时）：100 / 100 成功，除去 saga 组后 p95 为 8.32s。

### 审查修复（`fix/core-game-server-review` 上的两轮，修在 main，没有合并那条分支）

- RV-20261117-01：邮箱满时，换服离开钩子不再误判旧服邮件已合并完，而是中止换服。
- RV-20261117-02：C# 错误码常量与生成器自身的名字冲突。新增用 dotnet 实际编译的回归用例。
- RV-20261118-01：room 断线重试用例的时序（只改测试）。
- RV-20261118-02：开房间 SDK（Go / TS / C#）的快照绑定准备时的连接与房主任期；房主换过一圈后，旧状态不再拿新 seq 覆盖新任期。Go 新增 `ErrSnapshotStale`，C# 新增 `RelaySnapshotResult.Stale`，TS `pushSnapshot` 返回 `undefined`。
  同一任期内并发推快照也以发起顺序为准（按推荐定 A）：后发起的一份已发出时，较早发起的那份报过期、不发。
- RV-20261118-03：lobby 主动离开按成员自己的事实序号收敛；left 晚于心跳到达，已开局房间也不再给离开的人留座（席位新增 `presence_seq`）。
- RV-20261118-04：wsconn 与 gateway 的旧写期限回归在 Linux 上误报（只改测试）。

## 已知限制

- 共享 kind 的代价：所有写入方都要按“写后通知 + 上线时拉最新”来写；不能退出共享。
- 邮箱满时不能换服，要先清邮件。客户端没有专门的提示码。
- saga 的耗时单独统计，不计入 16s 门槛；saga 的吞吐只保证“有能力”。
