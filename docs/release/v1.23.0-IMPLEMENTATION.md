## 4. 反复出问题模块的方向判断汇总

roost-coding 第 107 行：“同一模块 / 同一机制在近期多轮里反复出缺陷，或某次 bugfix 之后又在同一处出 bug……不要只是继续打补丁”，要单列给维护者做方向判断。本版有四个模块走完了这条路：先是缺陷链，再是方向判断与维护者决定，最后落成**结构性守卫**（新写法绕过唯一出口时测试会红）。review 时重点不是再找同类缺陷，而是确认守卫本身没有漏口。
