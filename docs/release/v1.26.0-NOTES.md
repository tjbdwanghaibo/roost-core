## 1. 版本定位

v1.26.0 是 v1.25.0（目录分类、独立 Gate、Block AOI）之后的次版本，四条主线：

1. **Nest 执行模型收敛为 short / long / io 三池**：按 Entity Kind 选择长短业务池，新增 `nest.Await` 做锁外查询与匿名恢复；池名、配置、监控与生成 Sender 一次改名，不留旧别名。消息热路径做了六项局部优化，job 布局压缩。
2. **Sync 性能与接口**：OnChange 可配置固定合批窗口、Relation 增量入口 `QueueRelationDelta`、AOI 候选过滤与提前结束、Flush / AOI / Relation / Lockstep 的分配削减，Lockstep 长局历史改为滚动窗口；同步命名按职责收敛（`StreamID`、`lockstep.Match`、AOI area）。
3. **移除旧兼容**：项目尚未上线（维护者规则“线上尚未部署（2026-10-06 起）”），旧数据形态、旧进程协议、旧工程写法一律明确拒绝，不再读取或自动迁移；同时删除从未生效的实体事件链与仓内无引用的导出 API。
4. **全仓整理**：测试按有用价值合并与去重（跟踪的测试文件 1531 → 705），注释收敛为当前约束、长函数按步骤拆分、死代码删除、文档按当前代码重写；这一部分以“行为不变”为验收口径，证据方式见 [§6](#r)。

另修了 17 处缺陷（F1～F17），其中业务可直接观察到的有：停机超时后重试提前返回（F1）、Nest 请求外日志帧号恒为 0（F2）、队列满错误文本重复（F3）、组件初始化顺序随启动变化（F4）、手动回包后多回一条空响应（F5）；其余是测试夹具、观测遗漏、配置接线与文本问题。

本版**不包含**：部署、线上数据迁移工具、Windows 支持（平台范围仅 macOS / Linux）；15 分钟重档复测在发布后补做并通过（见 [§8](#limits)）。

## 3. 破坏性变化与升级要求（U）

### <a id="u1"></a>U1 Nest 执行池改名为 short / long / io

**变化**：Nest 三个执行池按职责命名：short（短业务）、long（长业务，见 [N1](#n1)）、io（I/O、冷加载、Remote 准备与收尾）。配置、Go API、Stats、指标标签、fctx 执行身份、生成 Sender 一起迁移，**不提供旧名别名**。调度、默认 worker / 等待预算、ID tail、Kind 路由均不变。

| 旧写法 | 新写法 |
| --- | --- |
| 配置 `nest.fast` / `nest.slow` | `nest.short` / `nest.io`；新增 `nest.long` |
| `NestOptionWithBusinessPools`、二参数 `NestOptionWithWorkerPools(fast, slow)` | 三参数 `NestOptionWithWorkerPools(short, long, io)`；不需要长池时中间传 `WorkerPoolConfig{}` |
| `SendOptionSlow` | `SendOptionIO`（只强制 I/O 准备，handler 仍按 Kind 进 short / long） |
| `FastPool` / `SlowPool`，Stats 的 `Fast` / `Slow` | `ShortPool` / `IOPool`，`Short` / `IO` |
| `WithFastWorker` / `InFastWorker` | `WithShortWorker` / `InShortWorker` |
| `ErrBlockingInFastWorker` | `ErrBlockingInBusinessWorker`（覆盖 short 与 long） |
| `FastContinuations`、指标 `nest.dispatch.fast_continuations` | `ShortContinuations`、`nest.dispatch.short_continuations` |
| 指标 `nest.dispatch.slow_reroute.total` | `nest.dispatch.io_reroute.total` |
| 压测变量 `ROOST_NEST_GAME_WORKERS` / `ROOST_NEST_GAME_SLOW_WORKERS` / `ROOST_NEST_GAME_QUEUE` | `ROOST_NEST_GAME_SHORT_WORKERS` / `ROOST_NEST_GAME_IO_WORKERS` / `ROOST_NEST_GAME_SHORT_QUEUE` |

`slow handler` / `lock hold` 等“耗时诊断”里的 slow 保留原义，不是池名。生成器 `_cost` 标记含义不变，重新生成后调用 `SendOptionIO`。完整迁移表见 [Nest 三池说明](../framework/NEST-AWAIT.md#池命名收敛2026-10-13)。

**升级**：Go 调用、YAML / 环境变量配置、监控查询与告警一起改；重新生成 Sender。回退须连同配置、生成代码与监控一起回退。

### <a id="u2"></a>U2 Nest 执行约束收紧（Cast、同步等待、I/O 池 Guard）

**变化**（随 [N1](#n1) 引入）：

- `Cast` 只能访问本执行段已声明的目标；动态 Cast 未声明的 ID 返回 `ErrCastUndeclaredTarget`。
- short / long 业务池内禁止阻塞等待池任务：同步 `Request`、`RunLocal` 等入口在投递前拒绝（`fctx.ErrBlockingInBusinessWorker`）。
- io 池内禁止 `GuardScope`、`RequireEntity`、`TryRequireEntity` 与 `Cast`。

**原因**：长短池共用一张 ID tails 表，持锁补 tail 或在业务 worker 上自等会破坏目标顺序或自锁；I/O 池不持有实体锁，不能直接改实体。

**升级**：把动态目标加入原消息声明，或用 `nest.Await(..., nest.WithResumeTargets(...))` 重新准入；业务池内的同步等待改为 Await 或拆成两条消息。glsvet 会报告 handler 与匿名恢复里显式的 Request / RunLocal / Wait / Sleep，但它是语法辅助检查，普通 channel 与第三方阻塞函数仍需人工审查。

### <a id="u3"></a>U3 Sync 与 Lockstep 命名按职责收敛

**变化**：源码 API 改名，**不保留旧别名**；帧二进制格式（字段宽度、位置、端序、版本）、指标名与业务行为不变。

| 旧名 | 新名 | 含义 |
| --- | --- | --- |
| `frame.SnapshotMeta.RoomID` | `StreamID` | 连接 / 同步上下文内的流身份；Entity Sync 固定填 1，不是地图或副本 ID |
| C# `RoomId` | `StreamId` | 读同一帧头字段 |
| `lockstep.Room` / `RoomConfig` / `NewRoom` | `lockstep.Match` / `MatchConfig` / `NewMatch` | 一场对局：帧序列、席位、观战、历史追帧、hash 分歧 |
| `ErrRoomConfigInvalid` / `ErrRoomClosed` | `ErrMatchConfigInvalid` / `ErrMatchClosed` | 错误文本改用 match，判断请用 `errors.Is` |
| AOICluster 内部 `rooms` / room | `areas` / area | 同一平面的区域；`AreaID`、`AddArea` 保留 |

`service/match` 仍是匹配服务，`lockstep.Match` 是对局，两者不同。业务自己的大厅 Room 不受影响。

**升级**：Go 消费者改字段、类型、构造函数与错误名；C# 改 `StreamId`；重新生成并编译。新旧源码不能混用。玩家协议处理新增教程，见 [PLAYER-ACCESS](../framework/PLAYER-ACCESS.md)。

### <a id="u4"></a>U4 roost.yaml 旧 mod / feature 名不再改写

**变化**：生成器不再把 `sync` / `room`（mod）与 `replication-quic` / `replication-kcp` / `replication-udp`（feature）改写成新名；它们和其他未知名一样被 `Validate` 点名拒绝。`roost help replication`、生成工程文档、release / framework-compat 工作流与 source-head-check 脚本已改用新名。

| 旧写法 | 新写法 |
| --- | --- |
| `mods: [sync]` / `[room]`（服务或 `shared_mods`） | `syncbus` |
| `features: [replication-quic]` 等 | `nettransport-quic` / `nettransport-kcp` / `nettransport-udp` |

**升级**：手工改 roost.yaml，再 `roost project sync`。

### <a id="u11"></a>U11 生成的 shell 部署拒绝未记录 unit 的旧 release

**变化**：`install.sh` / `rollback.sh` 删除为旧 release 补记 unit 的 `record_unit` 与“未记录就沿用已安装 unit”的回退；新增 `require_unit`：当前 release 或回退目标在 `$APP_ROOT/units/` 下没有 unit 时，在建 release、停服务、切 `current` 之前拒绝，并提示唯一处理办法。

**升级**：若实例有旧 `install.sh` 装的 release，先停服务，删除 `$APP_ROOT/current` 与 `$APP_ROOT/releases`，再用新 `install.sh` 全新安装。

### <a id="u12"></a>U12 SyncBusMod 缺省前缀改为 `roost.sync`，流名不再特例映射

**变化**：未配置 `syncbus.prefix` 时缺省由 room 时代的 `roost.room` 改为 `roost.sync`（与驱动缺省、生成配置一致）；删除 `roost.room → ROOST_SYNC` 的流名特例。JetStream 流名一律“显式 `syncbus.stream` 优先，否则由 prefix 推出”（`roost.sync` → `ROOST_SYNC`，`roost.room` → `ROOST_ROOM`）。配置声明 default 与 kitconfig 快照同步。生成的配置一直写 `prefix: roost.sync`，不受影响。

| 部署现状 | 影响 | 处理 |
| --- | --- | --- |
| 生成配置，写了 `prefix: roost.sync` | 无 | 无 |
| 没写 `syncbus.prefix` | 主题从 `roost.room.*` 变为 `roost.sync.*`，新旧进程不能互通 | 先停旧再起新；JetStream 部署清掉旧 `ROOST_SYNC` 流后全新部署，或显式配置 `syncbus.prefix: roost.room` + `syncbus.stream: ROOST_SYNC` 沿用旧主题与 durable 游标 |
| 显式 `prefix: roost.room`、没写 `stream` | 新推出的 `ROOST_ROOM` 与旧 `ROOST_SYNC` 的 subjects 重叠，**启动明确失败** | 补 `syncbus.stream: ROOST_SYNC`，或全新部署 |

### <a id="u13"></a>U13 SyncBus / NATS 停机只剩 `StopWithContext`

**变化**：删除 JetStream 同步总线不限时的 `Stop()`；`framework/sync/syncbus/driver` 新增 `Bus` 接口（`ISyncBus` + `StopWithContext`），普通 NATS 总线补 `StopWithContext`（无可等待资源，返回 nil），两种驱动编译期断言实现它；SyncBusMod 的总线字段收紧为 `driver.Bus`，NatsMod 直接调用 `*bus.Bus` 的 `StopWithContext`。停机契约由编译期保证，没有旧 `Stop()` 回退。无配置或数据变化。

**升级**：直接调用 `Stop()` 的代码改为 `StopWithContext(ctx)`。

### <a id="u14"></a>U14 Remote 快照 checksum 只读 8 字节 Binary

**变化**：旧版本写下的 BSON 数字形态（int32 / int64 / double）以及 null / undefined 报 `remote checksum has unexpected BSON type`，不再静默读成数值或 0。缺字段解为 0，由信封校验按 checksum mismatch 拒绝。现行写入全部经 `MarshalBSONValue` 写 8 字节，不会写出旧形态。

**升级**：先用旧程序完成落库，再清理含旧形态 checksum 的 Remote 快照文档（或清空该部署的 Remote 快照集合，由权威重建）。

### <a id="u15"></a>U15 WAL 中“Remote 写 + lease fence”历史记录不再投影

**变化**：投影器遇到这类历史记录以 `engine.ErrRetiredRemoteLeaseFenceRecord`（包裹 `ErrRemoteLeaseFenceUnsupported`）fatal：不写库、不推进 checkpoint、WAL 原样保留；`MongoStore.ProjectFenced` 在任何 Mongo 写之前拒绝。准入处的 `ErrRemoteLeaseFenceUnsupported` 与原生 saga 步骤的 lease fence 不变。删除只为这条历史路径存在的“投影为 Remote Rejected 并卸载重载”分支（RR-20260926-19 的历史路径）。

**升级**：**升级前用旧版本排空 WAL**。投影器 fatal 时不要删除 WAL 记录或手工推进 checkpoint，按[维护手册 §4](../maintenance/README.md#4-故障处理)“WAL 格式拒绝”处理：用匹配的旧程序完成落库。

### <a id="u16"></a>U16 Remote 快照副本拒绝无版本删除与无发布时刻更新

**变化**：`version <= 0` 的删除消息报 `remote_entity: snapshot delete message has no version`；无 `published_at` 的更新报 `remote_entity: snapshot update message has no publish time`。两者与其他畸形消息同一口径：返回错误、传输层记 handler 错误、不写或失效缓存。

**原因**：无版本删除无法排序，会清掉先送达的较新快照；无发布时刻的更新无法判断是否是比共享 L2 担保窗口更老的重放。现行发布者的更新与删除都带版本与发布时刻。

**升级**：**先停旧进程再起新进程**，不让旧发布者与新副本混跑。

### <a id="u17"></a>U17 Remote 控制库事务集合只建 `expires_at_ttl` 索引

**变化**：`EnsureRemoteStorage` 只建当前索引（名 `expires_at_ttl`、稀疏、不再 RecreateOnConflict），不再识别并替换旧名 / 旧键的 TTL 索引。

**升级**：清空 Remote 控制库的事务集合，或先手工删除旧的 `created_at_ttl` 索引。旧索引若建在 `expires_at` 上，新索引同键不同名，启动建索引报冲突；若是更早按 `created_at` 过期的形态，**不会报错，但会删掉未发布的提交**——这一种必须先处理。

### <a id="u18"></a>U18 account 旧账号 ID、无计划 slot、无 `CreationID` 角色被拒绝

**变化**：

- 登录不再回查未转义渠道的旧账号 ID；同一身份只用转义后的 `Identity.AccountID`。占着该 ID 的存量账号身份不符仍报 `ErrIdentityInvalid`。

- 缺 `CreationID` 的角色不可选、不可校验会话、不可改资料（`ErrConflict`）。

**升级**：升级前清理旧账号 / slot / 角色数据。

### <a id="u19"></a>U19 activity 无计划开窗条目为畸形条目；超限窗口不再轮转扫描

### <a id="u20"></a>U20 rank 只读 `:applied_v2` 请求账本；删除 `ErrConflictSentinel`

## 4. 新增与改进（N）

### <a id="n1"></a>N1 Nest 按 Kind 选择长业务池；`nest.Await` 锁外查询与匿名恢复

- **长业务池**：`EntityKindDef.BusinessPool` 可设 `entity.BusinessPoolLong`（缺省短业务）；生成实体支持 `//roost:entity ... businessPool=long`。一条消息只选一个业务池：任一目标是长业务 Kind，整条消息走长池。三池共用一张 ID tails 表，长消息执行期间同 ID 的短消息在依赖队列里等，不占短 worker。配置 `nest.long`（缺省 worker 数等于短池，等待容量 4096）。Kind 的执行策略在引擎构造时固化，禁止改已确定的长短属性。
- **Await**：`return nest.Await(work, resume, options...)`。当前执行段清理、释放实体锁与 tail 后，框架在 io 池执行 `work`（只访问复制出来的值），再按目标重新准入、加载、加锁，调用 `resume(实体..., 结果, error)`；原请求的最终回复延迟到恢复段完成。`nest.WithResumeTargets(fn)` 在 work 成功后按结果决定新目标。
- **适用边界**：第一版只用于明确注册为 memory 的无事务 handler（`durability=memory`、无 rollback）；拒绝有回滚事务或 Remote 写批次的段，不会悄悄降低持久化策略。恢复段也不建业务事务。内存闭包不保证掉进程后恢复；状态改变、防重、重试由业务负责。
- 新增约束见 [U2](#u2)。用法与例子见 [Nest 三池与 Await](../framework/NEST-AWAIT.md)。

### <a id="n2"></a>N2 Nest Msg 字段按职责整理；多目标标准化切片复用

Msg 字段按职责分组并写中文契约，保留全部提交 / 重排状态；多目标入口接管标准化后的切片，分组目标共用有容量边界的连续存储。单目标和业务参数顺序不变。多组场景分配下降，单组有少量耗时代价，测量见 [NEST-AWAIT §Msg 状态与目标存储](../framework/NEST-AWAIT.md#msg-状态与目标存储2026-10-13)。

### <a id="n3"></a>N3 Nest 消息热路径六项局部优化

分组展开一次分配、直接传 Snapshot option、同消息身份登记复用、锁列表与 Touch 列表合并分配、1～4 实体的小分组快照放栈上、相同前驱只登记一条依赖边。不改变三池数量、默认队列容量、ID tail、Guard / 事务契约与业务协议。同机 96 组矩阵中，8 worker / 热点 / 空 handler / 异步 Dispatch：单实体 3608 → 3020 ns/op、1506 → 1120 B/op；32 组 32823 → 24127 ns/op。目标视图缓存与指标预绑定**延期**（需先统一生命周期设计）。微基准不等于游戏混合负载容量。详见 [Nest 热路径报告](../performance/NEST-HOT-PATH-20261013.md) 与 [优化设计](../framework/NEST-OPTIMIZATION.md)。

### <a id="n4"></a>N4 Nest job 紧凑布局与 dispatchLane 聚合

保留 ID tail 调度，紧凑排列 job 字段，以队列单调原点偏移存储排队时刻：本机 job 由 160 降至 120 字节，每请求减少 32 B/op，业务 CPU 档吞吐基本不变。dispatchQueue 的 short / io 并列数组聚合为一个 `dispatchLane` 数组，明确字段归属；共享锁、跨通道 ID 顺序、容量与生命周期不变。证据见 [Nest 调度对照](../performance/NEST-DISPATCH-BENCHMARK.md)。

### <a id="n5"></a>N5 Nest 慢请求诊断不再自动抓全进程栈

**原因**：2026-10-12 同参数重档诊断复跑中，200ms 慢请求诊断调用 `runtime.Stack(buf, true)` 触发 330.160ms 的 stop-the-world，跨过 Gate 250ms 期限，Gate 通道超时并关闭绑定（[报告](../performance/REVIEW-20261012.md)）。5 秒限频只控制次数，不限制单次暂停。

**变化**：删除热路径的全进程抓栈与 256KiB 栈缓冲；保留 200ms 慢请求检测、消息身份 / 上下文详情、耗时与 5 秒限频。全栈由运维经已启用的诊断入口显式采集。修后同参数 15 分钟重档通过（Sync 提交→客户端 P99 18.66ms，零消息 / HB 拒绝、零 outbound 失败）；该结果对应可读性整理**之前**的代码，最终代码的复测见 [§8](#limits)。

### <a id="n6"></a>N6 Nest 共享调度与固定 worker 分片的对照基准

新增独立 benchmark：空 handler、1ms / 200ms CPU 或等待、慢任务混合、热点 / 碰撞。只增加测试与性能文档，不改生产调度策略；夹具的裸整数 ID 问题见 [F8](#f8)。

### <a id="n7"></a>N7 Sync OnChange 固定合批窗口

`entitysync.Config.OnChangeBatchWindow` / 配置 `sync.entity.on_change_batch_window`。默认 0 = 立即处理（原行为）；正值从首次唤醒起计时，后续通知**不续期**；周期 tick 可提前处理；显式 `Flush`、`Drain`、`Stop` 的最终 Flush 不等待窗口。负值、或 periodic 模式下非零被拒绝。配置显式 0 与未配置可区分（未配置沿用代码值，显式 0 关闭，最终 `Configure` 覆盖），见 [N15](#n15)。它减少 Flush / 发送批次，不减少提交时捕获变化的工作，不保证网络延迟。用法见 [Sync 指南](../framework/guide/04-sync.md)。

### <a id="n8"></a>N8 Sync Relation 增量入口 `Interest.QueueRelationDelta`

`QueueRelationDelta(entity, source, added, removed)` 只复制变化的 ID，经现有事实队列的提交确认、回滚、同 ID 顺序、预算与发布屏障后应用；底层 `RelationSource.ApplyDelta` 原子维护正反索引。语义 next = (previous ∪ added) − removed，同批删除优先，零 ID 忽略，重复幂等，自关系与负数 ID 合法；Leave / Hide 剔除退出 ID，防止旧新增在同 ID 重建后复活。1024 存量成员、每次换一人：全量 Set 72695 ns/op → 增量 455.8 ns/op（只含关系源与事件收集）。**需要业务显式接入**，仍调用全量 `QueueRelation` 的业务不会自动受益。

### <a id="n9"></a>N9 Sync Relation 重复 Set 复用有界候选表

不超过 1024 个输入成员的重复 Set 复用 RelationSource 锁内的一份候选表，关系变化时移交所有权；大集合仍锁外构表。重复 Set 分配降到 0（≤1024 成员）；**代价**：退出重加约慢 5%（10 观察者档 622.5 → 653.0 ns）。见 [Sync 优化](../framework/SYNC-OPTIMIZATION.md)。

### <a id="n10"></a>N10 Sync AOI 候选过滤与满额提前结束

候选排序前排除自身和半径外实体；满额且剩余候选无法替换时提前结束扫描；等距选择与事件顺序不变。同时修复合法负数 ID 无法被满额淘汰的问题（行为修复，归入本条）。

### <a id="n11"></a>N11 Sync 第二批：AOI 分类重算与工作区复用

AOI 按空间 / 额外覆盖变化分类重算，复用有上限的串行 / worker 工作区；Flush 复用编码临时结构，发送字节仍独立分配。补批量移动、集中布局、覆盖切换基准与事件 / 载荷所有权回归。

### <a id="n12"></a>N12 Sync 首批：Flush 修订表、AOI 事件扫描、Lockstep 名单、Relation 反向索引

减少 Flush 修订表分配、AOI 全观察者事件扫描与 Lockstep 每帧名单排序；Relation 增加退出反向索引。契约、内存代价与同机基准见 [Sync 优化](../framework/SYNC-OPTIMIZATION.md)。

### <a id="n13"></a>N13 Lockstep 历史滚动窗口

`History.TrimBefore` 清除旧引用后推进连续视图，大幅缩容时才复制，避免逐帧复制整段历史；空历史释放数组。保留 300 帧窗口：7086 → 40.37 ns/op；18000 帧：346829 → 74.49 ns/op（只含追加 / 裁一帧 / 读页）。同时修复 `ReadRange` 超大 limit 与 FrameID 上界裁剪两处溢出（见实现篇）。**宿主仍须主动调用** `TrimHistory` / `TrimHashReports`；本地 108000 帧逻辑长局不是真实网络一小时。

### <a id="n14"></a>N14 玩家协议 Controller 骨架自动补齐

协议定义写 `handler=player` 后，`go generate ./...` 创建缺少的 Controller 与方法文件（参数 `*player_agent.Context` 与 PB 请求，方法体为明确的未实现错误）；已有业务不覆盖、不删除，方法移到其他文件也不重复生成；类型与 FromRegistry 只有一半存在时报错。支持事务生成与 `--check` 缺失检查。教程见 [PLAYER-ACCESS](../framework/PLAYER-ACCESS.md)，说明主动回包与返回响应的边界。

### <a id="n15"></a>N15 `app.LoadConfigWithPresence`

需要区分“未配置”与“显式零值”的 Mod 用它：复用声明解码器，在同一次解码中返回声明键的来源存在性，失败时不返回部分结果。Mod 不再直接读 Viper，也不需要守卫白名单。普通 `LoadConfig` 不增加分配。

### <a id="n16"></a>N16 根包 gofmt 门禁

`TestTrackedGoFilesAreGofmtClean`：git 跟踪（及未忽略的新增）全部 `.go` 文件须 gofmt 无差异，失败列出文件。全仓先统一 gofmt 一次（95 个文件，主要是包迁移后未重排的 import 顺序）。

## <a id="r"></a>6. 整理（R）

这一部分**不改变业务行为**；它的价值是让维护者与 review agent 读到的代码、注释、测试名和文档都描述“现在的约束”，而不是开发过程。边界与证明方式如下，逐包证据见实现篇。

### <a id="r1"></a>R1 测试按有用价值整理

- 两轮：10-10 按功能主题合并 202 份零散测试为 80 份（4687 个测试 / 基准 / 示例 / fuzz 入口及全部声明语法一致）；10-13 全仓按价值整理，跟踪测试文件 1427 → 711、约 23.5 万 → 22.6 万行。当前 HEAD 跟踪的 `_test.go` 共 705 个（v1.25.0 为 1531）。
- 删除或并入约 60 个“同入口、同断言”的重复用例，每条先把独有断言并入保留用例；只测测试替身、不经产品代码的用例删除。并发、恢复、协议、状态机回归与结构守卫全部保留。测试名与头注释改写为当前承诺，过程只留一行“历史”。
- **证明方式**：每包整理前后全部非 import 声明的语法摘要一致（除列明删除）；逐函数语句覆盖率不变（个别计时分支跑间波动逐条说明）；受影响包 vet 与 race、`-tags integration` vet、根包门禁、全仓 test、`go generate` 无漂移。规则已写入[维护手册 §7](../maintenance/README.md#7-测试与生成代码维护)。
- **边界**：整理不等于证明所有测试互不重复；integration 标签用例只做了编译与 vet，不计作外部资源验收。

## <a id="limits"></a>8. 已知限制

未解决问题的唯一位置是 [KNOWN-LIMITS](../maintenance/KNOWN-LIMITS.md)。本版相关的：

- **重档性能**：v1.25.0 的重档失败经 2026-10-12 诊断确认由慢诊断全进程抓栈放大（[N5](#n5)），修后同参数 15 分钟通过；但该通过样本对应可读性整理与热路径优化**之前**的代码，仍有 0.1813% 的已订阅 delta 超过 50ms（最大 336.387ms），初始延迟未唯一归因。**v1.26.0 发布后同参数 15 分钟重档复测已通过**（2026-10-13，见[验收篇 §5](v1.26.0-VALIDATION.md#perf15) 与[复测报告](../performance/V1260-HEAVY-20261013.md)）：业务 P99 12.24ms、Sync 提交→客户端 P99 14.24ms、Gate 往返 P99 6.04ms，>50ms delta 占 0.0098%（最大 86.341ms）；单样本、多项改动叠加，不归因到某一项，也不作吞吐上限。
- **Await 范围**：只支持 memory、无事务的 handler；不保证掉进程后恢复；未做真实排行榜网络、生产持久发奖、跨机或长期重档验证。
- **Sync 新能力**：合批窗口、Relation 增量、Lockstep 滚动历史只有本地行为测试与微基准；真实客户端、跨机丢包 / 断线、生产负载与长期内存曲线未验收。Lockstep 宿主仍须主动裁剪历史与 hash。
- **Remote WAL 级 Rejected 收尾**：移除历史投影后正式链路不再产生，但收尾代码与注入点保留，待评估精简。
- **整理边界**：测试整理只做了 integration 标签的编译与 vet；Windows 不在支持范围。
