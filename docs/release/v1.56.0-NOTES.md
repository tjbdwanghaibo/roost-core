# v1.56.0：一套 account 服务多个游戏、portal 跨域与登录顺带进服、审查问题修复

这一版包含 v1.55.0 之后 2026-11-18 当天的工作，重点有四项：

- **一套 account 服务多个游戏**（维护者“现在就改”）：同一个人（渠道 + open id）在每个游戏里是不同的账号号；客户端、lobby、relay 与游戏只见到这个游戏的号，看不到别的游戏的号，也看不出“是同一个人”。
- **portal 的两项通用能力**：
  - `portal.cors_origins`：浏览器里的游戏页面（或替游戏登录的外壳页面）可以跨域调 portal；
  - `/portal/login` 可选 `enter`：登录时顺带进服，一个请求拿齐账号票据、握手票据与地址。
- **审查问题修复**：`fix/core-game-server-review` 上 `MAIN-REVIEW-20261118` 报的 RV-20261118-05～09 五项，全部在 main 上修复（没有合并那条分支）。上一轮的六项，审查者已按原场景复验关闭。
- Meshy 平台登录**不在 core 里**：验签包与接入 skill 在 Meshy 自己的服务端模板仓库；core 只加了上面两项通用能力。

逐条变更见 [CHANGELOG](../../CHANGELOG.md) 的 v1.56.0 段。

**不兼容旧版。** 线上尚未部署，所以不做兼容。已有工程按下面的升级须知处理，或者用新版重新生成后把业务文件搬回去。

## 升级须知

1. **core 与生成器同时升级到 v1.56.0。**
2. **account 存储要清空**：账号号按游戏分开，存储结构变了。清空 account 的 Redis 前缀下全部键，先停旧进程再起新进程。
3. **account 配置**：`account.games` 必填（新工程写工程名的游戏）；多个游戏时客户端登录要带 `game`，或配 `account.default_game`。已生成的工程手工补 `account.games`；自己构造 `svcaccount.Config` 的代码补 `Identities`、`AccountIDs`（`NewRedisStores` 已带）与 `Games`。
4. **account API**：
   - `Account` 去掉 `Channel` / `OpenID` / `Banned` / `GameTokenGeneration` / `CredentialVersion`，多了 `Game`；`Identity.AccountID()` 删除。
   - 账号票据 `at1` → `at2`（带游戏）；`IssueGameToken` 只给票据自己的游戏刷新，跨游戏答 `560120`。
   - 封号改为身份级：`Admin.SetIdentityBanned`；login 模块的 accountctl 新增 `ban` / `unban`。
5. **portal 模块**（只对新生成或重新安装的工程生效）：已安装的工程照模块模板更新 `services/account/portal/portal.go`、`portal_config.go`、`portal_test.go`。自己实现 `httpserver.RouteRegistrar` 的代码要补 `Options` 方法。
6. **跨域白名单写法**：`portal.cors_origins` 与 `lobby.cors_origins` 不接受浏览器发不出的 Origin（结尾斜杠、带路径、大写主机、写明默认端口 443 / 80），读配置时报错并给出该写的值。`lobby.cors_origins` 以前不检查，原来这么写的配置启动会失败。
7. **开房间协议（relay）**：
   - 主动转交（Transfer）的载荷改为 `[epoch 8B][交接数据]`，Rejected 新增原因 6 `stale_epoch`。relay 与三份 SDK 必须同版本一起升级，先停旧再起新。
   - C# `RelayClient.Transfer` 返回 `RelayTransferResult {Sent, NotConnected, Stale}`（原来是 `bool`）；Go 新增 `ErrTransferStale`；TS `transfer` 过期时返回 false。调用方要处理“过期不发”这种结果。

## 主要内容

### account：一套服务多个游戏

- 账号号由 account 的全局计数器按（游戏, 渠道, open id）发放，十进制、顺序（存储键 `<key_prefix>:account_id`）。
- 身份级记录存各游戏的号、封号、凭证版本与 gt2 代数：封一个人是封他所有游戏；改密码后在任一游戏登录，所有游戏的 gt2 一起失效。
- 票据签名改为严格 base64 解码（宽松解码时同一张票据有多种写法都能验过）。

### portal

- **跨域**：名单里的 Origin 四个端点预检 204、响应带 `Access-Control-Allow-Origin`，别的 Origin 预检 403；不发凭据头，`null` 永不放行。不写时与以前相同（不允许跨域）。跨域白名单不是访问控制（非浏览器客户端不看它）。
- **登录顺带进服**：`enter: {server_id}` 进那个服，`enter: {}` 进推荐的服（与 `/portal/servers` 同一条推荐规则，可加 `service`）。没有推荐时登录成功、不带 `enter`；进服失败整个登录失败；`enter` 写得不成样子在问 account 之前就拒绝，不浪费一次性的渠道凭据。不写 `enter` 时与以前相同。

### 审查修复（`MAIN-REVIEW-20261118`，修在 main，没有合并那条分支）

- RV-20261118-05：合服前检查在途换服改为一次读出在途索引的全集，扫描期间有换服了结不再漏检。
- RV-20261118-06：大厅里同一账号重新 join 得到的新预留，不再被上一个席位迟到的在线报告记成“连上过”；同类路径（房主经 lobby 离开后自己先掉线）一并修复。
- RV-20261118-07：旧任期发起的主动转交不再开启新任期（三份 SDK 核对 + relay 核对 epoch）。
- RV-20261118-08：跨域白名单拒绝写明默认端口；lobby 的跨域白名单同样检查。
- RV-20261118-09：Go 自动快照用例的等待点（只改测试）。
