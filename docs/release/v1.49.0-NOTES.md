# v1.49.0：热点实体写吞吐、模块后台 manager 收尾、区服动态目录与 room 在线状态

本版有五项重点：

- 热点单例实体的写吞吐：业务 handler 可以显式声明 pipelined 异步完成（`completion=async`），nestwal 的 fsync 移出写入协程。
- 模块后台循环全部改成 manager（D22 收尾）：activity_world / activity_alliance 的恢复扫描、cellworldhost；ManagerMod 改为排在基础设施之后启动、之前停止。
- 区服动态目录（D23）：game 定期向 account 的带过期登记表上报，portal 读它。
- room 断线订阅与重启后的在线状态（D24）。
- Remote 删空认领的运维命令与计数（D17）。

逐条变更见 [CHANGELOG](../../CHANGELOG.md) v1.49.0 段；性能记录见 [hot-entity-commit](../performance/benchmarks/hot-entity-commit-20261115/README.md)。

**不兼容旧版。** 线上尚未部署，存储、协议与生成物都不为旧进程、旧数据、旧生成工程留兼容。

## 升级须知（不兼容，按这里逐项处理）

1. **重新生成工程**。manager 登记、room / login / portal / activity / cellworld 模块的改动只对新生成的工程生效；core 与生成器同时升级到 v1.49.0。
2. **先升 account，再升 game / manifest**。account 新增 `ReportServerPresence` / `WithdrawServerPresence` / `ListServerPresence`，旧 account 不认这些方法。
3. **`gateway.PlayerRuntime` 接口新增 `ConnectionActive`、`SessionCount`**。自己实现这个接口的代码要补两个方法；`TCPSessionClosed` 新增 `ConnectionID`。
4. **room 在线状态不再落库**。`RoomSeat.Connected` 删除，改为 nopersist 的 `RoomDao.Online`：进程重启或房间重新装载后全部席位断线，成员用 `RoomReconnect` 重新上线。存储格式变化，升级时清空 room 数据。
5. **portal 进程内 `Registry` 目录删除**。缺省目录改为静态 `portal.servers` 叠加 account 登记表；自定义目录的 `newDirectory` 钩子多了 `reported Directory` 参数。
6. **ManagerMod 启停顺序**。现在排在 Nest、Remote / DataEngine（含预加载）、Redis、NATS、Saga、心跳之后启动、之前停止；manager 的 Start 晚于预加载。依赖“manager 先于 Nest 启动”的自写 manager 要调整。
7. **activity_world / alliance 服务要带 manager Mod**，cellworld 工程的 `Managers()` 里要有 `NewCellWorldHost()`（新生成与安装器自动处理）；`cellworldhost.Runtime.Start` 在没有 manager 发布的 `Host` 时拒绝。

## 主要内容

### 热点单例实体的写吞吐

- **pipelined 异步完成（显式声明）**：handler 写 `//roost:nest durability=pipelined completion=async`（`HandlerMeta.AsyncCompletion`），同一实体的下一条在上一条入队后就开始，回复仍在持久之后、按序返回；本机微基准同一实体约 120 → 约 2900 次/秒。**不是缺省**：打开后 AfterCommit 在完成池上执行、没有请求上下文、不持实体锁、不能同步等同一实体的 Nest 请求，只有写 handler 的人能确认钩子满足这些条件；理由见 [NEST_PIPELINED_COMMIT §12.3](../framework/NEST_PIPELINED_COMMIT.md#123-没做的与备选)。
- **nestwal 写入与 fsync 解耦**：fsync 在独立 goroutine 上做，进行中继续写入；async 追加不再排在 strict 的 fsync 后面（有 strict 负载时 async 吞吐 +135%）。strict 仍是回复前已持久。

### 模块后台 manager（D22 收尾）

activity_world / activity_alliance 的恢复扫描改成 manager，跑在属主服务里（清单新增 `services.<服务>.managers`）；cellworldhost 的 Node 由 manager `NewCellWorldHost` 托管，服务在心跳装好之后的就绪点交给它，manager 停时兜底排空。ManagerMod 的启停顺序修正：此前停机排空后台工作时 Nest 已经停了。

### 区服动态目录（D23）与 room 在线状态（D24）

- account 的区服入口登记表（Redis 一个 hash，按 Redis 时间判期，最多 256 个 sid）；login 模块的 manager `NewLoginPresence` 缺省每 10 秒上报、TTL 30 秒，没配上报地址时不上报。
- room 的 manager `NewRoomPresence` 订阅连接关闭自动 Disconnect，每 30 秒补扫丢失的关闭事件；房间内广播按 D24 A 暂缓。

### 其他

- **Remote 删空认领（D17）**：运维命令 `remote_entity.empty_claims`（列出 / 按所有权代际比较删除），指标 `remote_entity.empty_claim_total{event=left|deleted}`。
- **login**：`login.notice_dropped_total{reason=busy|stopping}`。
- **demo 机器人**：cellworld 预热分散改为分段到达（比例控制在位置回传延迟下来回摆的测试缺陷）；M-15 分散三轮 0 / 0 / 0。

- 发版前在 feat/v149 上跑 pretag 全套（build、vet、tidy、全仓测试、生成工程与模块门禁、C# SDK），发版脚本的 pretag 会在 main 上再跑一遍。

## 已知限制

- **strict 热点仍约每次 fsync 一条**（契约代价）；macOS 上 `F_FULLFSYNC` 进行中同文件 write 仍在内核里等，Linux 未对照测量。
- **M-15**：同一出生点时 Base 兴趣饱和此前 5 轮中 3 轮出现，触发条件尚未确认；本机容量不代替目标 Linux / 分机证据。
- **登录潮里 account CreateRole 超时尚未确认**：只在已去掉的抢写风暴条件下复现，Redis 被拖慢已排除，要给 account 加指标再查。
- **删空认领**：只由持有它的 sid 删自己的，已死且不再拉起的 sid 上的空认领删不了。
- **room**：只覆盖本进程的连接；房间内广播与 R11 暂缓。
- 其余框架限制、已决定待实施事项与外部环境验收见 [KNOWN-LIMITS](../maintenance/KNOWN-LIMITS.md)。
