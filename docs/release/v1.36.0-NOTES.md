# v1.36.0：Native 客户端、Unity 与负载诊断

## 升级要求

Native 网络 ABI 升至 2：事件增加结构化状态，配置增加独立心跳期限。重新构建 native 库、C/C++ 头文件、Unity 绑定与托管 DLL，一起升级；不要混用旧插件。业务 PB、DAO 同步与服务端使用同一份协议生成物。没有旧 ABI 兼容层，不改变当前 PB 同步或 BSON 持久化格式。

生成工程最低 core 仍为 v1.35.0，本轮没有要求默认生成业务使用更高版本 API。使用本版新增 Robot SyncProbe 或 native/Unity 能力的项目应固定 v1.36.0。

Unity 从 [构建入口](../../client/unity/README.md) 生成完整 UPM 包后导入，不直接导入仓库中的未构建目录。插件、DLL 和绑定由同一入口收集，不能重复安装托管程序集。已有纯 C# 网络路径保留；同一连接选择一种消费方式。

## 行为与能力

- Native 补齐 Lockstep 输入、哈希、追帧与分块快照恢复、场景时间域、PB 通知/请求取消、独立请求与心跳期限、可选有界重连，以及可选 Protobuf 视图 C ABI。网络线程独占 socket，业务在消费线程执行。超时不证明业务未执行；重连不自动重放请求，新票据由业务异步提供。
- Unity 提供插件导入规则、主线程 RoostNativeDriver、IL2CPP 保留声明和完整 PB/EntitySync/Lockstep 示例。Driver 禁用或进入后台时断开，恢复时通知业务重新取票；不承诺移动端后台保活。
- Robot 增加有界 SyncProbe 和三类同步应用延迟，完善 13 类玩法闭环、结算重试及真实 Gate 负载诊断；报告区分输入丢拍、请求完成、负载结束积压和排空状态。
- 修复 Gate 验收记录器隐藏 MongoStore 批量投影能力的问题。修前夹具降级到逐笔投影/checkpoint；修后保留目标能力，不降低 WAL/Mongo 持久级别。这是验收夹具修复，不宣称正式 MongoStore 新增相同倍数的性能提升。

## 已完成的专项验证与边界

macOS ARM64 / Apple M5，Unity 6000.3.12f1：Editor 加载插件，Mono 与 IL2CPP Player 构建及实跑通过。完整回环链路覆盖 PB、EntitySync 全量/增量/删除、64 位值、Lockstep 快照恢复与两代连接重连。两种 Player 均通过延迟分片，native 另覆盖心跳无响应、请求无响应、半帧、接收队列满和发送阻塞。详见 [客户端报告](../performance/CLIENT-20261101.md)。

Native、Mono、IL2CPP 各完成 24 组可见集解码测试：50～10000 实体，1%/5% 变化；这只是小型 DAO 的解码应用容量，不含 WAN、渲染或物理。移动设备、真实移动网络、UE 和本轮 Linux/Windows 客户端未实跑。

真实账号/Gate/Nest/strict WAL/Mongo/C# 联合链及批量能力回归在 race 模式通过。修复夹具后 100 请求/s 的两轮 30 秒负载，排空后 WALUnacked 均为 0，一致性通过；仍有 19/15 次输入丢拍，不能称为无丢拍持续容量。修前失败和测量边界保留在 [Robot/Gate 报告](../performance/ROBOT-GATE-20261101.md)。

首次 pretag 发现根目录测试覆盖清单仍使用旧 Gate 匹配式，且未登记新增 ProjectionCapabilities；已同步真实执行入口与清单，定向回归通过，没有增加豁免或跳过测试。发版脚本重新执行 pretag，再核对 main/tag 推送，并用 GOPROXY=direct 解析发布版本、生成 game-demo、build/vet。发布不等于生产部署；当前开放边界见 [KNOWN-LIMITS](../maintenance/KNOWN-LIMITS.md)。
