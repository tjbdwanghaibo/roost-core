# v1.54.0：开房间联机（大厅 lobby + 转发 relay，房主做 host），配置表导出给客户端

这一版是 v1.53.0 之后 2026-11-16、11-17 的工作，有四项重点：

- **开房间联机**：新增两个框架服务。大厅服 lobby 负责建房、列表、加入、离开和发 relay 令牌；转发服 relay 只读帧头、不解析载荷。玩法逻辑跑在房主的客户端上，房主掉线或离开时 relay 换 host，并把房主上传的快照交给新房主。
  - 客户端 SDK 有三份：Go、C#（TCP）、TS（WebSocket），三份对同一份金样逐字节一致。
  - TS 另有 Web 端房主辅助 `WebHost`：规则在 Worker 里跑，支持刷新后恢复、页面隐藏时让出房主。
- **Gate 的 WebSocket 接入层**：浏览器可以经 WebSocket 连玩家接入。Gate 与 relay 共用适配器 `infra/network/wsconn`，新依赖 `github.com/coder/websocket v1.8.15`。
- **account 发游戏账号 token（gt1），一套 account 可服务多个游戏**；登录协作者拆成 `account_auth` 模块，portal 不再依赖 login。这样不带 game 的 `-template lobby` 工程也能登录、拿到 gt1。
- **配置表导出给客户端**：一次 `roost generate` 同时产出两份东西：
  - 服务端的 JSON 与 Go 绑定；
  - 客户端的 JSON 与 C# 读取代码。

  表和字段可以按端分组（`side=c|s`）。新增竖排键值表 `layout=kv`、`index`、CSV 的 `#` 注释行。数据版本号记在 `manifest.json` 和 C# 常量 `ConfigTables.DataVersion` 里，**只记录，登录时不核对**。

**不兼容旧版。** 线上尚未部署，新生成的工程可以直接用。已有工程按下面的升级须知处理，或者用新版重新生成，再把业务文件搬回去。

## 升级须知

1. **core 与生成器同时升级到 v1.54.0。**
2. **relay 与 lobby 必须一起升级。** 新 relay 每条连接都要向 lobby 验权；旧 lobby 不答 `verify`，新 relay 就会拒绝全部连接（`Closed{lobby_unavailable}`）。lobby 依赖 account 的新总线接口，所以 account 要先于 lobby 升级。
3. **lobby 的房间记录**：新增字段 `connected`、`kicked`、`leaving`，旧记录不兼容。房间记录带 TTL，升级时等旧房间过期，或者清掉 lobby 的键。
4. **配置表**：已有工程重新生成后，`configs/generated/gen_table_config.go` 里每张横排表会多一行 `reader.Comment = '#'`。升级时要重新生成并提交。
5. **account_auth 拆分**（只对新装的模块）：
   - 已经装了旧版 login 的工程不会自动拆分。之后再装 portal 时，安装器要先装 account_auth；但它的文件已经被旧 login 写过，所以会被拒绝（`already exists and is not this module's file`）。
   - 这样的工程按新清单手工照搬，或者重新生成。
6. **不受影响的工程**：没有声明 lobby、relay、websocket、`client_export.config` 的工程，除第 4 条外，生成结果不变。

## 主要内容

### 大厅 lobby 与转发 relay

- **lobby**：HTTP + JSON，无状态，可以多开；房间目录在 Redis 里，所有修改都走 compare-and-set。
  - relay 实例经 etcd 发现；房间事件与命令走 NATS。
  - 被踢的账号记在 lobby 的被踢名单里。relay 每条连接都向 lobby 验权，验不到就拒绝（fail-closed）。
  - 已开始的房间里，掉线成员的席位一直保留，直到他主动离开、被踢或房间关闭。
- **relay**：
  - 帧分游戏通道和房间通道；
  - 成员上下线、踢人、禁言；
  - 换 host：房主宽限 5s，心跳超时 2s；
  - 快照：最小间隔 1s，上限 256KiB，换 host 时交给新房主，并带上已存的快照序号。
- **生成器**：
  - `-template lobby`、`roost add lobby|relay`；
  - 部署模板发布 lobby 与 relay 的端口，并注入 relay 令牌密钥；
  - doctor 新增相应检查。
- **修复**：成员经 lobby 离开后，迟到的 relay 在线名单不再把他加回房间（交接 A1）。

### 客户端

- **三份开房间 SDK**：
  - Go 的 `client/relay`，TCP；
  - C# 的 `Roost.Client.Relay`，TCP，netstandard2.1；
  - TS 的 `client/ts`，WebSocket。

  三份都有强类型的换 host 回调。快照缺省用 deflate 压缩，压缩方式可以替换。
- **测试**：pretag 新增 C# relay SDK 和 TS SDK 两步，TS 在没有 node 的机器上跳过。

### 配置表导出

- **`client_export.config`**：
  - 导出目录缺省 `shared/config`，里面有 `data/*.json`、C# 读取代码和 `manifest.json`；
  - C# 读取代码自带 JSON 解析器，不用反射，加载时核对数据哈希和约束。
- **检查与同步**：
  - `roost generate --check` 覆盖导出目录；doctor 新增 `config-export:fresh`；
  - `roost client sync` 新增 `--config-code-to` 和 `--config-data-to`。

## 已知限制

详见 KNOWN-LIMITS 的“大厅 lobby 与转发 relay”、“客户端：遗留”、“配置表导出”。

- **没在 Unity 里跑过**：C# relay SDK 和配置读取代码只在 .NET 上编译、运行过，没有在 Unity Editor 和 IL2CPP 下实跑。
- **Unity WebGL 连不上 relay**：C# SDK 只有 TCP。方案见 `evidence/open-work-c1-webgl-websocket-20261117`，还没定要不要做。
- **只在内置 Chromium 面板里演练过**：Safari、Firefox、手机浏览器都没测；页面真的切到后台时的表现也没有实测。
- **没有做的演练**：多进程演练（kill -9、两个 relay 实例）、跨机器、七层负载均衡与 wss。
- **生产 compose 不发布玩家 TCP 7000**：已确认是遗漏，这一版没有修。
- **方案已写、等维护者定（交接 C2～C6）**：
  - Welcome 帧不带 epoch；
  - 负载均衡后取不到真实 IP；
  - 快照不用 zstd；
  - 配置导出的类型范围；
  - gt1 不能单张吊销。
