# v1.54.0：开房间联机（大厅 lobby + 转发 relay，房主做 host），配置表导出给客户端，遗留问题集中收口

这一版是 v1.53.0 之后 2026-11-16 到 11-18 的工作，有五项重点：

- **开房间联机**：新增两个框架服务。大厅服 lobby 负责建房、列表、加入、离开和发 relay 令牌；转发服 relay 只读帧头、不解析载荷。玩法逻辑跑在房主的客户端上，房主掉线或离开时 relay 换 host，并把房主上传的快照交给新房主。
  - 客户端 SDK 有三份：Go（TCP）、C#（TCP 或 WebSocket）、TS（WebSocket），三份对同一份金样逐字节一致。
  - TS 另有 Web 端房主辅助 `WebHost`：规则在 Worker 里跑，支持刷新后恢复、页面隐藏时让出房主，并按页面可见性上报前台状态。
- **Gate 的 WebSocket 接入层**：浏览器可以经 WebSocket 连玩家接入，七层负载均衡后按可信代理取真实 IP。Gate 与 relay 共用适配器 `infra/network/wsconn`，新依赖 `github.com/coder/websocket v1.8.15`。
- **account 发游戏账号 token（gt2），一套 account 可服务多个游戏**，可按账号整代吊销；登录协作者拆成 `account_auth` 模块，portal 不再依赖 login。这样不带 game 的 `-template lobby` 工程也能登录、拿到 gt2。
- **配置表导出给客户端**：一次 `roost generate` 同时产出服务端的 JSON 与 Go 绑定、客户端的 JSON 与 C# 读取代码。表和字段可以按端分组（`side=c|s`）。新增竖排键值表 `layout=kv`、`index`、CSV 的 `#` 注释行。数据版本号记在 `manifest.json` 和 C# 常量 `ConfigTables.DataVersion` 里，**只记录，登录时不核对**。
- **遗留问题收口**：换服源服重启后自恢复（R2）、模块清单声明配置（R5）、新模块 facebook（跨 game 队伍邀请）、CellWorld 业务适配进模块、生产 compose 端口、多进程演练查出的 lobby / relay 问题，等等，见下文。

逐条变更见 [CHANGELOG](../../CHANGELOG.md) v1.54.0 段。方案与维护者的决定：
- [开房间联机方案](../maintenance/FEATURE-2026-11-16-lobby-relay.md)：§6 是 12 条决定；
- [配置表导出方案](../maintenance/FEATURE-2026-11-17-client-config-export.md)；
- 契约：[LOBBY](../framework/LOBBY.md)、[RELAY](../framework/RELAY.md)、[GATEWAY §6](../framework/GATEWAY.md)、[client/README“开房间 SDK”](../../client/README.md)、[CODEGEN_REFERENCE §2.2](../../codegen/docs/CODEGEN_REFERENCE.zh-CN.md)。

**不兼容旧版。** 线上尚未部署，新生成的工程可以直接用。已有工程按下面的升级须知处理，或者用新版重新生成，再把业务文件搬回去。

## 升级须知

1. **core 与生成器同时升级到 v1.54.0。**
2. **relay、lobby 与三份客户端 SDK 必须一起升级。**
   - 新 relay 每条连接都要向 lobby 验权；旧 lobby 不答 `verify`，新 relay 就会拒绝全部连接（`Closed{lobby_unavailable}`）。lobby 依赖 account 的新总线接口，所以 account 要先于 lobby 升级。
   - relay 协议变了：`Welcome` 固定 13 字节 `[角色][房主槽位 4B][epoch 8B]`（旧 5 字节），快照与交接数据带 1 字节压缩方式标识。新旧客户端与新旧 relay 互不认。
3. **游戏账号 token 改成 gt2**：旧 gt1 一律答 `ErrSessionInvalid`，客户端要重新取 token。账号记录多 `GameTokenGeneration`。
4. **lobby 的房间记录**：新增字段 `connected`、`kicked`、`leaving`、`alive_until_unix_ms`，旧记录不兼容。房间记录带 TTL，升级时等旧房间过期，或者清掉 lobby 的键。**relay 重启即丢房**：重启时所有已开的房间都丢，客户端拿到 `room_not_found` / `lobby_rejected`。
5. **account（换服 R2）**：先停旧 account 再起新的。新增在途换服索引 `<key_prefix>:transfers`；**Redis Cluster 上 account 的 `key_prefix` 必须带 hash tag**，否则 Mod 初始化报错。已有的在途换服不在索引里，需要时用 `accountctl transfer-role abort` 了结。
6. **生产 compose**：`docker-compose.prod.yaml` 给监听玩家 TCP 的服务发布 `"7000:7000"`（声明了 websocket 的还有 7080），给每个服务发布 ops `"127.0.0.1:<9100+端口块>:9100"`。已有工程 `roost project sync` 后生效。
7. **配置表**：已有工程重新生成后，`configs/generated/gen_table_config.go` 里每张横排表会多一行 `reader.Comment = '#'`，运行时转换报错改报文件行号。升级时要重新生成并提交。
8. **模块（只对新生成 / 新安装的工程生效，已有工程不迁移）**：
   - **模块配置（R5）**：`module.yaml` 可以声明 `config`；装了带配置模块的业务服务多一个只带配置的 modulehost Mod，生成的 `shutdown.total_timeout` 多 3s；模块配置写错时 `roost config check` 退出 3。
   - **account_auth 拆分**：已经装了旧版 login 的工程不会自动拆分；之后再装 portal 会被拒绝（`already exists and is not this module's file`），按新清单手工照搬，或者重新生成。
   - **facebook**：team `requires: [facebook]`；存储里 `PlayerDao.Team.Invited` 删除，新集合 `facebook`。
   - **game-demo**：PlayerDao `schema` 5 → 6，实体号与组件号顺移（cellworld、facebook 进模块）。旧 demo 数据清空，先停旧再起新。
9. **WebSocket 接入**：声明了 websocket 的已生成工程要 `roost project sync` 重新生成 `server_gen.go`，才读得到 `player_access.{tcp,gate}.websocket.trusted_proxies`。
10. **发版机器必须装 .NET 10 SDK**：pretag 缺 dotnet 时失败，不再静默跳过 C# 用例。
11. **不受影响的工程**：没有声明 lobby、relay、websocket、`client_export.config`、也没装模块的工程，除第 6、7 条外，生成结果不变。

## 主要内容

### 大厅 lobby 与转发 relay

- **lobby**：HTTP + JSON，无状态，可以多开；房间目录在 Redis 里，所有修改都走 compare-and-set。
  - relay 实例经 etcd 发现；房间事件与命令走 NATS。
  - 被踢的账号记在 lobby 的被踢名单里。relay 每条连接都向 lobby 验权，验不到就拒绝（fail-closed）。
  - 已开始的房间里，掉线成员的席位一直保留，直到他主动离开、被踢或房间关闭。
  - 房间寿命只由建房与 relay 报告续；客户端重连的 join 不再给已崩溃 relay 上的房间续命。
- **relay**：
  - 帧分游戏通道和房间通道；成员上下线、踢人、禁言；
  - 换 host：房主宽限 5s，心跳超时 2s；`Welcome` 带 epoch；成员可上报前台状态（`Presence = 85` → 房主收到 `MemberPresence = 70`），房主据此声明候选顺序；
  - 快照：最小间隔 1s，上限 256KiB，换 host 时交给新房主；状态字节带压缩方式标识（0 不压缩、1 deflate、2～255 归游戏）。
- **生成器**：`-template lobby`、`roost add lobby|relay`；部署模板发布 lobby 与 relay 的端口，并注入 relay 令牌密钥；doctor 新增相应检查。
- **修复**：
  - 成员经 lobby 离开后，迟到的 relay 在线名单不再把他加回房间（交接 A1）；
  - relay 在 `room_ttl` 内重启后，房主不再在新进程上重建同一房间号把成员关在外面（改为重启即丢房）；
  - 房间里最后一个人离开时三份 SDK 不再报 `room_not_found`；
  - WebSocket 连接不再被自己的旧写期限关掉（relay 成员偶发在心跳整 10s 点被断开，Gate 的 WebSocket 会话同样受影响）。

### 客户端

- **三份开房间 SDK**：Go 的 `client/relay`（TCP）；C# 的 `Roost.Client.Relay`（netstandard2.1，TCP 或 WebSocket，传输接口 `IRelayTransport` 可换）；TS 的 `client/ts`（WebSocket）。三份都有强类型的换 host 回调，快照缺省用 deflate 压缩，README 有接入 zstd / LZ4 的示例。
- **Unity**：新增 `client/dotnet/unity-webgl-smoke` 最小冒烟工程与 WebGL 桥接参考。Unity 编辑器上 TCP / WebSocket 实测可用；**WebGL 上 SDK 现在跑不起来**（见已知限制）。
- **测试**：pretag 新增 C# relay SDK 和 TS SDK 两步，TS 在没有 node 的机器上跳过。

### account 与登录

- 游戏账号 token gt2：`gt2.<过期秒>.<游戏>.<账号>.<代数>.<签名>`；`Accounts.RevokeGameTokens` 按账号整代吊销，`accountctl revoke-game-tokens`。
- `account_auth` 模块：不带 game 的开房间工程 `roost module add portal` 一条命令就能登录、拿 gt2。
- 换服 R2：源服重启后不等登录也能恢复，committed 崩溃窗口（Q4）关闭；期限之后的提交答 `ErrTransferStale`；`accountctl transfer-role list`。

### 模块

- **模块配置（R5）**：`module.yaml config: {package, type, use}`，安装器写起步 YAML，`--check-config`、`roost config check`、doctor 都看得见，运行时经 `modulehost.Value[T]` 读。
- **facebook**（新）：每名玩家一个伴生的共享 Remote 实体，记跨 game 的邀请收件箱；队伍邀请经它跨 game 投递。
- **cellworld**：CellWorld 业务适配进模块（D21 后半第一块），补了 AddIngress 失败分支的场景。

### 配置表导出

- **`client_export.config`**：导出目录缺省 `shared/config`，里面有 `data/*.json`、C# 读取代码和 `manifest.json`；C# 读取代码自带 JSON 解析器，不用反射，加载时核对数据哈希和约束。
- schema 包里的具名标量类型按底层类型处理；数字规范写法两端一致；横排表运行时转换报文件行号。
- **检查与同步**：`roost generate --check` 覆盖导出目录；doctor 新增 `config-export:fresh`；`roost client sync` 新增 `--config-code-to` 和 `--config-data-to`。

### 部署与测试

- 生产 compose 发布玩家 TCP 7000 与本机 ops（交接 A2）。
- 根包门禁跳过以 `.` 开头的目录；`scripts/test-seamless-demo.sh` 支持整体端口偏移。

## 已知限制

详见 KNOWN-LIMITS 的“大厅 lobby 与转发 relay”、“开房间 SDK”、“客户端：遗留”、“配置表导出”、“WebSocket 接入”。

- **Unity WebGL 上 C# 开房间 SDK 跑不起来**：WebGL 上线程池、计时器与 `ConfigureAwait(false)` 之后的续行都不运行。SDK 调度怎么改（推荐由 `Pump` 驱动）待维护者定。
- **IL2CPP 没实跑**：配置读取代码与 C# relay SDK 没在 IL2CPP 下跑过。
- **只在内置 Chromium 面板里演练过**：Safari、Firefox、手机浏览器都没测；页面真的切到后台时的表现也没有实测。
- **没有做的演练**：跨机器、真实七层负载均衡与 wss。
- **relay 重启即丢房**：包括只有房主的房间。
- **修复后的 relay 在 Unity 编辑器上没有复跑**（WebSocket 旧写期限修复）：机制已用确定性用例证明。
