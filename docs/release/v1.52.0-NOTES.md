# v1.52.0：单实例锁改存 etcd，controllers 合成一个包，组件钩子改为实体事件

本版是 2026-11-16 整理轮的结果，三项重点：

- **单实例锁改存 etcd**：与服务发现共用一个 etcd 集群，删除 Redis 版锁。
- **生成工程布局整理**：`game/controllers` 合成一个包；组件类型号挪进组件包；组件与实体经 `game/view` 的窄接口相连。
- **实体事件**：组件之间原来的通知类、拦截类钩子，改成实体上的 `Publish` 加 `//roost:listen`。监听和发布方在同一笔事务里执行，出错整笔回滚。

逐条变更、改名清单和旧工程手动迁移的八个步骤见 [CHANGELOG](../../CHANGELOG.md) v1.52.0 段。方案与维护者的决定见[本轮总览](../maintenance/FEATURE-2026-11-16-round-overview.md)。

**不兼容旧版。** 线上尚未部署，生成物不为旧工程留兼容：新生成的工程直接可用，已有工程按 CHANGELOG 的迁移步骤改，或者用新版重新生成后把业务文件搬回去。

## 升级须知（不兼容，按这里逐项处理）

1. **core 与生成器同时升级到 v1.52.0。**
2. **单实例锁**：
   - bootstrap 里的 `kitredis.SingletonStore` 换成 `kitetcd.SingletonStore`；
   - 开锁服务的配置补上 `etcd.endpoints`，`singleton.key_prefix` 改为 `/<project>/singleton`；
   - **先停全部旧进程，再起新进程**：新旧进程的锁不在同一个存储里，互相看不见。
   - 生产要求 etcd 三节点或更多。etcd 连续不可用超过续期窗口时，开锁进程会 fail-stop。
3. **`game/controllers`**：子目录合进 `<分组>.go`（`package controllers`），删掉各自的 Controller 样板。原来在 `FromRegistry` 里做的依赖检查，改成在 `init` 里调用 `requireAtStart` 登记。
4. **组件与 view**：
   - `game/entities/<实体>/<x>_component.go` 里的类型号和工厂登记挪进组件包；
   - handler 参数改为 `view.I<X>Entity`，调用由 `target.<X>Comp()` 改为 `target.<X>()`。
5. **钩子改事件**：
   - 在 `game/event/<模块>.go` 定义事件结构体，发布处改成 `owner.Publish(event.X{...})`，返回的错误原样外传；
   - 监听方改成组件或实体方法上的 `//roost:listen [priority=N]`。
6. **改名与删除**：
   - dungeon 的 `Open` / `Claim` 改为 `DungeonOpen` / `DungeonClaim`；cdkey 的 `Redeem` 改为 `CdkeyRedeem`；servertime / rules 的推送入口改为 `ServertimePushNow` / `RulesPushNow`；
   - 删除 `roost add module`，以及 Makefile 里的 `new-module`。

## 主要内容

### 单实例锁存 etcd

- 锁键挂在持有者的租约上；续锁时先续租约，再核对键值和租约。
- 生成的 `singleton.startup_wait` 由 30s 改为 35s，部署侧的启动等待随之加长。
- doctor 新增 `singleton:etcd-consistent`：所有开锁服务的 etcd 地址和 `singleton.key_prefix` 必须一致。
- **顺带修正**：停机时撤销服务发现注册最多等 5 秒。原来 etcd 不可达时，丢锁的进程会卡在撤销注册上，一直等到 etcd 恢复。

### 生成工程布局

- **`game/controllers` 一个包**：
  - 生成器写公共的 `controller.go`；每个模块一个 `<模块>.go`，联动文件为 `<模块>_<对方>.go`；
  - 模块的启动期依赖检查由 `CheckAtStart` 统一执行。
- **`game/event` 是第七个固定层**：放实体事件定义。
- **组件包写法**：
  - 模块清单新增 `component_package`，同一个组件只用一个类型号；
  - activity 挪到 `game/components/activity`。
- **view 窄接口**：
  - `roost generate` 写出 `view.I<X>Entity`；
  - 宿主方法中只交出 DAO 字段的，由生成器实现；
  - Nest 与 endpoint 按 view 类型判断归属，可以写 `target=`。

### 实体事件

- **core 接口**：新增 `Publish`、`RegisterEventListener`、`DispatchEvent`，以及三道上限：嵌套 8 层、同一事件在栈上 3 次、一次发布 256 次。
- **生成器**：`//roost:listen [priority=N]`；按 priority 等规则排序后登记；静态环提示。
- **替换范围**：19 个事件替换了原来的钩子，执行顺序与原来一致。
  - 事务或实体锁之外的登记点保留原登记方式，例如进入前检查、换服的离开与到达、排行提交。
  - 扩展提供方也保留原登记方式。

### game-demo

- 跟上上面的新布局。
- demo 自有的 5 个组件仍是实体包写法，这些组件上不能写 `//roost:listen`（KNOWN-LIMITS）。

## 验证范围

在本机（macOS arm64）：

- **全量**：本轮分支上跑了两次 pretag。第一次有 14 个用例失败，原因都是本轮的改动之前没跑过全量，根因和修复见证据；第二次 `go test ./...` 全部通过，18 个玩法与生成脚本通过，`test-modules-generated` 修正后单独重跑通过。发版时 `scripts/release.sh` 在 main 上再跑一次完整的 pretag。
- **单实例锁 etcd 真实进程演练**，四步全部通过：
  1. 同 sid 两个进程，后起的等待；
  2. 持有者被冻结后接管；
  3. 原持有者恢复后 fail-stop；
  4. etcd 停 20s，持锁进程 fail-stop，etcd 恢复后同 sid 重新拿到锁。

  第 4 步在修复停机撤销注册之前是失败的，有记录。
- **Gate 演练**：account、game、gate 三个进程，经 Gate 完成登录、新建、进入。
- **alliance-e2e**：11 条全部通过，包括断 Redis（锁已不在 Redis 上）和联盟成员跨 sid 换服。
- **实体事件**：core 测试验证真实 Nest 事务里监听出错时整笔回滚（memory 与 strict，含嵌套发布）；把 `Publish` 改成吞掉错误时这个测试会失败。
- **生成工程 TCP 写入冒烟**（5s，10 个连接）：通过。只作功能冒烟，不是容量数据。

证据见 [round-20261116](../maintenance/evidence/round-20261116/README.md)。没有覆盖：跨机、Linux、长稳、容量。

## 已知限制

- game-demo 自有的 5 个组件（monster、terrain、world、map、dungeonledger）本轮不迁组件包，所以不能写 `//roost:listen`（维护者 2026-11-17）。
- doctor 的 `event:*` 检查没有做，记为以后的增强（维护者 2026-11-17）。监听吞掉内层错误、拦截类监听改状态，这两种情况靠约定避免，没有静态检查。
- 旧工程不做自动迁移。
