# v1.44.0：saga 步骤按 sid 确切路由

本版只改 saga 原生步骤的投递：绑定玩家的步骤不再由所有游戏进程共用一个 durable 争抢，而是由协调器直接投给玩家所在 sid 的消费者。逐条变更与证据见 [CHANGELOG](../../CHANGELOG.md) v1.44.0 段，设计见 [方案](../maintenance/FEATURE-2026-11-11-saga-step-sid-route.md)，契约见 [SAGA](../framework/SAGA.md)。

**saga 线格式不兼容旧版**（WireVersion 3 → 4）。线上尚未部署，不做旧进程 / 旧数据兼容。

## 为什么改

v1.43.0 的本机压测发现：5 个游戏进程共用 saga 步骤队列时，绑定玩家的步骤落到非属主进程会被拒收、按 250ms 起倍增的退避重投，每步约多 3.75s，机器人场景多出约 22s（p95 约 30s）。维护者 2026-11-11 决定按 sid 确切路由：发起 saga 的一方本来就知道属主 sid，应该直接投给它，而不是让多个进程争抢再补救。

## 行为变化

- **路由步骤**：定义里 `Step.Routed = true`，启动时 `StartRequest.Route = saga.SidRoute(属主 sid)`。协调器把命令发到 `<prefix>.<k>.ev.to.<route>.<topic>`，每个 sid 一个 durable，只有属主收得到。属主自己确认消息、自己发布结果。
- **退回发送端**：属主收到步骤时玩家在换服中、或已不绑定本服，不执行、零写入，结果以“退回”回到协调器（可带新地址），由协调器改投或到截止补偿；不再 NAK 让别的进程争抢。退回**不消耗尝试次数**。
- **截止必填**：有路由步骤的 saga 启动必须带 `DeadlineAt`，Resume 可以改截止但不许清掉；补偿方向仍等属主收下。
- **拒收**：载荷里没有路由 sid 的步骤直接拒收、记错误日志，不兼容旧载荷。
- **game-demo**：赠礼扣款 / 退款与公会玩家步骤改为路由步骤，原来的错投交接代码删除；属主核对保留。“换服中”是钩子 `playerMoving`（缺省不在换服中，TODO）。
- **codegen**：`roost add saga ... -routed <step>`；生成的 `EmitStart` / `Start` 多一个 `route` 参数。
- **JetStream 资源**：每个路由步骤（每个方向）的 durable 数从 1 变为部署的 sid 数。

## 升级步骤

1. core 与生成器同时升级到 v1.44.0，重新生成工程（新生成物需要 core v1.44.0；生成器清单里的最低版本在本版 tag 推上去后的下一笔提交才抬到 v1.44.0）。
2. 先让全部 saga 到终态，**先停旧进程（协调器与步骤进程）再起新进程**，删除 saga 流与快照 / 准入桶；改成路由的步骤留下的旧共享 durable 可删除。
3. 调用生成的 `EmitStart` / `Start` 时给路由 saga 传 `route`（`saga.SidRoute(sid)`）和非零截止。

## 验证

发版前在 main 上跑过：全仓 build / vet / test（164 个包），`framework/saga`、`wiring/saga` 的 `-race`；生成 game-demo 全测（36 个包）及 `internal/service/game -race`；私有真实依赖（Mongo / Redis / NATS）上的 demo 集成用例 10 项、开地形分区多进程演练 6 步、普通无缝演练 14 步。普通无缝演练最后一步 p95 从 27.85s 降到约 5s，阈值恢复缺省 16s。

**未覆盖**：生成 game-demo 的 `internal/service/game -race` 失败过一次、复跑 5 次未复现（尚未确认）；跨机部署；单玩家换服（仓库没有这个功能，钩子待接）；一笔 saga 只能有一个路由地址（两名不同 sid 玩家之间的交易需要按步骤的地址，未实现）。发布不等于部署。
