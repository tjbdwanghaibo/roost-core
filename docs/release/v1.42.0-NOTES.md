# v1.42.0：独占 Remote 实体不再每次向权威确认

本版只改 Remote 实体在**独占状态**（所有权记录里是单个 owner）下的写准入与所有权查询；共享状态不变。逐条变更、前后数字与决策出处见 [CHANGELOG](../../CHANGELOG.md) v1.42.0 段，契约见 [REMOTE_ENTITY“独占写准入”](../framework/REMOTE_ENTITY.md#独占写准入)。

## 前提

一个实体同一时刻只有一个 owner，由 App 层的单实例与 fail-stop 保证：失去归属的进程先停，新 owner 才接手。框架不再在每次请求时向 Mongo 确认归属，不考虑旧进程与新进程同时以 owner 身份写的情况（维护者 2026-11-06 决定）。

前提万一被打破，投影写 Mongo 时仍校验版本号与所有权代际（与提交同一个事务，不增加往返），后到的写被拒、不会覆盖数据：

- Durability 0 的写：隔离并卸载实例，下一次访问重新对齐；
- 走 WAL 的写：投影器 fatal，进程 fail-stop，与改动前相同。

日志记 ERROR，计数 `remote_entity.commit_conflict_total`。

## 行为变化

- **独占实体稳定持有期间，读和写都不再取写许可**：原来每次写准入都要做一次 `GrantWrite`，即 `_remote_entity_meta` 上一次多数派 `findAndModify`，只读请求也一样。
  - 现在只在三个时刻各读一次 `_remote_entity_meta`，对齐版本：加载、取得归属、从共享退回独占。读是只读，不写。
  - 稳定持有期间不碰 Mongo。
  - handler 不改持久字段的请求不产生任何 Mongo 命令。它仍然过实体写门，所以读不到结果还没定下的写；没有新增只读声明。
- **首写认领直接带回权威状态**：新实体第一次写，认领前后都不再额外读一次；只有撞上已有记录时才读回一次。
- **`Manager.GetRemoteOwnership` 在本进程稳定独占持有时答本地缓存**，不读 Mongo。下列情况照旧读 Mongo：
  - 别的进程持有；
  - 共享模式；
  - 只认领、还没对齐；
  - 实例已卸载；
  - 转出中（Draining）、Fenced、隔离中；
  - 有归属变更正在进行。

  契约从“每次读权威”变为“本进程独占时以本进程缓存为准”，依赖上面同一个前提。
- **投影写 meta 的条件按模式区分**：独占提交校验 `_ver`、`_owner_epoch`、`_owner_route`；共享提交另外校验 `_grant_fence` 与非空 `_grant_token`，与之前相同。
- **新指标**：`remote_entity.exclusive_admission_total{path=held|aligned}`、`remote_entity.commit_conflict_total`。

## 升级步骤

1. core 与生成器同时升级到 v1.42.0，重新生成工程。业务代码不用改。
2. 存储不用迁移：`_remote_entity_meta` 字段不变，独占实体的 `_grant_fence` / `_grant_token` 不再推进，也不再校验。
3. 自己实现 Remote 权威存储（`remoteentity.WriteAuthority`）的工程要做两处改动：
   - 补上新增的必选方法 `ClaimAuthorityState(ctx, id, owner)`；
   - 适配 `GrantWrite` 的新签名：去掉了 owner 参数，现在只用于共享实体。

   用框架自带 `MongoCommitter` 的不受影响。
4. 部署上要保证同一个服务 sid 不会有两个进程同时在跑，这本来就是 App 单实例的要求。

## 验证与性能边界

发版前在 main 上跑过以下验证：

- 全仓 build / vet / test，相关包 `-race`；
- 真实隔离 Mongo / NATS / Redis 下 DataEngine 与 Remote 集成测试，含 outbox 代发的真实进程演练；
- game-demo、Remote 生成工程；
- 联盟真实进程端到端 7 条；
- 13 类玩法生成工程、Sync 双模式、C# / C++ 客户端测试。

本机同机前后对照（macOS 单机副本集，机器高负载，数字只看量级）：

| 场景 | 改动前 | 改动后 |
| --- | --- | --- |
| 联盟 `Info`，16 并发 | 约 1 070 次/秒，每次 1 条 Mongo 写 | 3.2～3.5 万次/秒，0 条 Mongo 命令 |
| 起服扫描 1 万个联盟 | 约 18 s | 0.5～0.8 s |
| 同实例已有玩家 `Join` 每次 Mongo 命令 | 16 | 12 |
| 同实例 `Leave` 每次 Mongo 命令 | 16 | 12 |
| 同实例新玩家 `Join` 每次 Mongo 命令 | 约 20 | 17 |

新玩家 `Join` 在 128 并发下的吞吐差别在噪声里，瓶颈在提交事务与新建认领。

未覆盖：Linux、跨机、生产 Mongo、长稳；需要 `ROOST_REMOTE_CLUSTER_IT=1` 的门控集成用例本轮没跑。发布不等于部署。
