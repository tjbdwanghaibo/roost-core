# v1.29.0 发版后重档 30 分钟与 Saga 复测（2026-10-19）

v1.28.0 改了运行时热路径：嵌入 TCP 出站、Sync 推送、DataEngine checkpoint 合并。v1.28.0 和 v1.29.0 发版时都没有压测，本篇补测，只测量，不改代码。维护者 2026-10-19 批准。

结论：
- **重档 30 分钟通过**。吞吐、计数、DAO 终值、AOI 可见集合、P99 门槛都通过；消息和 heartbeat 拒绝都是 0，200ms 慢 dispatch 是 0；堆与 goroutine 不随时间增长。
- **P50～P99 与 v1.27.0 基本一致**：业务、HB、Sync、Gate 的 P99 比 v1.27.0 高 0.2～0.7ms。
- **超过 50ms 的长尾比 v1.27.0 的 30 分钟样本多 5～7 倍**，最大值也更高。同日同机用 v1.27.0 tag 加跑了一次对照，长尾同样变多（业务最大值 407ms，比 v1.29.0 还高）。所以长尾变多主要来自今天的宿主状态，**不判定为 v1.28/v1.29 退化**。
- 和同日对照比，v1.29.0 的 Sync / Gate >50ms 条数是对照的 1.8 / 2.6 倍。每版只有一个样本，**这一点尚未确认**。
- **goroutine 多了 1000 个**（5452 → 6452），对应 v1.28.0 B3：每连接加了一个写协程，1000 个玩家连接正好多 1000 个。数量恒定，不增长。
- **Saga**：正向 20/s 和全补偿 10/s 各跑 10 分钟，都通过，十个分钟段都没有增长趋势。全补偿 10/s 的 P99 是 0.61s，2026-10-15 首测的 1.47s **第三次没有复现**，原因仍尚未确认。

### 3.2 服务端与压测端拆分（v1.29.0）

## 5. 解读与不能证明什么

- **能说明的**：
  - v1.29.0 在本机重档 30 分钟下稳定：计数、终值、可见集合、门槛都通过，资源不增长，吞吐按计划。
  - P50～P99 相对 v1.27.0 没有超过 1ms 的变化。
  - Saga 两档与 2026-10-15 样本同量级，没有随时间增长的趋势。
- **P99 小幅上升（+0.2～0.7ms）尚未确认**：
  - 数值：业务 13.09 对 12.73（同日对照）/ 12.49（10-14）；Sync 提交→客户端 15.43 对 14.72 / 14.71；Gate 6.78 对 6.50 / 6.15；HB 11.01 对 10.86 / 10.77。
  - 方向一致，幅度在以往同版本样本之间的波动内：v1.26.0 15m 到 v1.27.0 30m，业务 P99 从 12.24 变到 12.49。
  - 可能原因之一：v1.28.0 B3 把 Gate 的 TCP 推送 / 回包改成“入队 + 每连接写协程写出”（`infra/network/gateway/tcp_session.go`），每帧多一次协程交接。本次没有做单变量对照，**不能归因**。
- **长尾**：
  - 同日两次（v1.27.0 对照与 v1.29.0）的 >50ms 条数和最大值都比 10-14 样本高数倍，主要是宿主条件。
  - v1.29.0 的 Sync >50ms（21687 对 12300）和 Gate >50ms（6245 对 2445）高于同日对照，而业务最大值、HB >50ms、short 池峰值反而低于对照。两次的尖峰各自集中在一个时段（§1），每版一个样本，不能区分是代码差异还是尖峰落点不同，记为**尚未确认**。要判断需要同机交替多轮（A-B-A-B）。
- **不覆盖的路径**：
  - 本场景用独立 Gate（`gateway.NewTCPServer` + `wiring/gate`），不经嵌入式 `TCPRuntime`（B3 改的是二者共用的 `tcpSession`）。
  - 不调用 Await、Remote、Saga，io 池 Started=0。
  - 不经 DataEngine 投影器，所以 v1.28.0 的 checkpoint 合并不在本次重档和 Saga 旧路径上；它的效果见发版前的 [SAGA-CHECKPOINT](SAGA-CHECKPOINT-20261018.md)，本次没有复测。
  - 自身视图（self_sync）、Lockstep 追帧、非零合批窗口、跨机、Linux 实机、独占服务器，都不在本次范围内。
  - 这不是吞吐上限测试。
