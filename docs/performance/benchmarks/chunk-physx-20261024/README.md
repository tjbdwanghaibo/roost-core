# 原生 PhysX / Unity Chunk 功能对照

2026-10-24，基线 ee3aa6d1 加本轮工作树。macOS arm64，Go 1.27.3，Unity 6000.3.12f1，官方 PhysX 4.1 分支固定 a2c0428acab643e60618c681b501e86f7fd558cc（SDK 4.1.2，Mac arm64 构建适配见 [实现说明](../../../framework/CHUNK-PHYSICS.md)）。Unity 运行日志也报告 SDK 4.1.2，但集成方式不同，不代表完整求解参数相同。

## 已运行内容

50×50 米、20 个胶囊、1 个动态球、地面与四面墙；4 个 25 米 Chunk，共用物理 Scene。双方 50Hz 固定步长，按同一非对称输入带独立模拟。左侧收到 Chunk 绝对状态，右侧只在首次基线初始化，之后不纠正。纯 float32 载荷，不使用位置量化。

球在服务器第 599 拍位置约 (-1.094383, 2.000000, -1.982779)，已实际被推动；同拍最大旋转误差约 59.55°。两种发送档位的相同物理 Tick 结果一致，不将网络频率造成的画面时间差计入误差。这里的误差是 21 个动态物体当拍统计，不是多次独立试验的置信区间。

这些数据说明独立模拟会分歧，不是物理一致性验收通过。接触顺序、Unity 集成默认值及求解器配置尚未逐项定位；不能只根据同为 4.1.2 就声称结果应当一致，也不能未经诊断把全部差异归给浮点数。

## 数据口径

- `unity-20hz.csv` / `unity-50hz.csv`：真实 TCP 接收后，在本地 512 拍历史中取同 Tick 状态比较。末尾已显式 Flush。
- `local_step_ms` 是某渲染帧本地追赶多个物理步的合计，不是单拍延迟分布。
- `total_received_bytes` 含 RS v2 头与基线；这是应用层接收字节，不含 TCP/IP 开销。20Hz 最后约 337714 字节 / 11.98 模拟秒，即约 28.2 kB/模拟秒；不把模拟时间直接当墙钟吞吐验收。
- `host-*.txt` 含整个限时宿主运行的物理步均值和最大值。Unity 退出后宿主继续运行到限时，因此不能把其时间范围当成 CSV 的同一窗口。它们仅作功能诊断，不是容量上限或独立性能基准。
- `*-before-metric-fix.*` 是前一轮 50Hz 原始数据：界面 summary 曾把最后收到的 Tick 599 和最后已对比的 Tick 596 混在同一行。CSV 当时记录的 596 正确；已改成分列并按 ComparedTick>=599 结束。保留旧样本，不替换成通过数据。

最初对称推力让球几乎不动，已改成按胶囊编号分档的加速度。初次 Unity 批处理直接在编辑模式创建 PhysicsScene 失败，已改为实际 Play Mode。Unity 编辑器 QuickSearch 自身 `SearchDatabase.EnumerateAll` 在启动时仍输出过 `ArgumentOutOfRangeException`；非本项目调用栈，未修编辑器源码。报告为“物理/网络/渲染运行通过”，不声称日志零异常。
