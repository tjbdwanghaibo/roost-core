# 物理 Crowd AOI 验收（2026-10-25）

> 历史 50 人平地样本。当前 Crowd 已按维护者要求改为 20 人立体场景，不保留旧人数/地形兼容路径；本文数值和摘要保持原样，下面的旧场景命令不能用当前代码原样复现。当前入口见 [20 人 3D 报告](../chunk-physx-3d-20261025/README.md)。

基线为同日 [50 客户端全场测试](../chunk-physx-crowd-20261025/README.md)。本轮仍是 50 个控制客户端、50 个小球、50 个胶囊、1 个大球，50×50m 场地、50Hz 物理、每客户端 20Hz 控制。区别是控制连接只接收自己附近对象。

## 最终结果

| 同步上限 | 全场总下行 | AOI总下行 | 减少 | AOI每客户端 | 平均可见对象 | CPU（100%=1核） | RSS峰值 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 20Hz | 50.41Mbps | 10.50Mbps | 79.2% | 26.25KB/s | 19.90 | 16.38% | 23.11MiB |
| 50Hz | 128.29Mbps | 26.12Mbps | 79.6% | 65.29KB/s | 19.92 | 21.95% | 23.12MiB |

两档每次发送/接受 60,000 条输入，rejected=0，failed_clients=0。20Hz 共发生 18,770 次进入（含基线）、18,043 次离开、13,720 次重新进入；50Hz 分别为 18,365 / 17,826 / 13,315，均完成客户端状态校验。两档平均可见约 20 个对象，曾达到 101；不以硬截断隐去密集碰撞对象。

全场 CPU 基准为 15.90% / 23.05%，AOI 为 16.38% / 21.95%，没有证明显著稳定的 CPU 改善。主要收益是平均下行减少约 79%～80%；仍完整模拟全场，并增加了按连接选择视野的工作。首轮 20Hz 为 10.87Mbps、平均 20.82 个对象，最终复跑为 10.50Mbps、19.90 个对象，保留两者说明分布波动。此次没有测任意滑动窗口的链路峰值或 P99 输入延迟。

## 当前行为

- 以绑定小球的当前已提交权威 XZ 位置为中心，12m 内进入、14m 外离开，自己始终可见。客户端不能指定观察位置。
- 物理帧发布时建立一次共享只读 10m Block 索引；每个发送连接查询相交 Block 并精确检查中心距离。线协议仍按 25m Chunk 分组，不把 AOI Block 尺寸混入客户端位置解码。
- 上次成功发送的对象集决定滞留区；进入和重新进入发完整对象，离开生成 delete，成功写出后才推进 Cursor 和可见集。断线重连重建基线。
- 101 个物体一直参与物理模拟，AOI 只改变网络可见性。槽号 0 的 Unity 诊断旁观连接仍看全场；本轮资源测量只有 50 个控制连接，无 Unity。
- 中心距离不考虑遮挡和高度，不是硬性的“最多 20/50 个对象”。聚集时最多观察到 101 个对象；不能用平均带宽代替最坏峰值保证。
- 上述逻辑用于现有 Chunk 物理链路，未改既有 Entity Interest，也未声称接好了生产 Gate/AOI 鉴权。

## 验证方法

macOS 26.5.2 arm64、10 逻辑 CPU，Go 1.27.3，PhysX 4.1.2；GOMAXPROCS 未指定。物理 worker=1，Nest short/long/io=2/1/1。20Hz、50Hz 同步档分别运行约 60 秒，未并跑 Unity、编译、索引或其他本任务的压测。CPU 按服务器全部线程 user+system / 观测进程墙钟计算，100% 表示一核；RSS 为服务器峰值。下行包括 RSv2 与 Chunk 包头、首次基线，不含 TCP/IP/ACK。Python 客户端开销不计入服务器 CPU，但与服务器同机，因此不是生产多机测量。

每包检查流序号连续、对象数据有限、自己存在、ID 有效、可见对象距离不超过 14m（浮点容差 .001m），记录对象进入、离开和重入次数。AOI 模式不再要求全场 101 对象；`--aoi-radius 0` 仍严格校验全场完整性。确定性单测以全量距离扫描为独立 oracle，逐观察者/逐对象核对 Block 查询，无漏选；通过 Cursor/Replica 验证滞留、离开、重入和观察者跨 Block/Chunk。另验收只读旁观连接仍完整收到 101 个对象。

有真实的进出/重入，不能只把 101 改成某个固定可见数量让测试通过。客户端距离检查只能排除多发，漏发由上述独立 oracle 和迁移回归验证，不能将网络自检夸大为全量权威对账。

控制按固定序号生成，但网络到达的应用 tick 会受调度影响，各次轨迹并非逐帧一致。因此下面是同机同配置同输入规则的独立 60 秒样本，带宽比例有场景分布波动，不能宣称严格配对重放。平均可见数量包含自己；进入计数包含首次基线，重入只计曾出现后离开又出现的对象。AOI 后大球位移统计是相对首次看见的位置，不与全场样本的大球初始位移直接比较。
