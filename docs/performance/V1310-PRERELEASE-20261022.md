## 5. AOI 三点与两种应用模式

**目的**：D14 / D19 的前后对照（维护者要求的 benchstat）与 ApplySync / ApplyAsync 在发版候选上的对照。

```sh
# policy 微基准：P0 49897751（D14 前）/ P1 08432d4e（D14）/ P2 发版候选，同机交替 10 轮
GOWORK=off go test -run '^$' -bench 'AOI|Cluster|View' -count 10 -timeout 0 ./framework/sync/entitysync/policy/ > <label>.txt   # 各自 worktree
benchstat p0.txt p1.txt p2.txt
# sync-aoi：单视野三点，再在 P2 上跑多视野与共享视野，两种应用模式，Nest 与 direct
ROOST_PERF_COUNT=3 bash scripts/perf/sync-aoi.sh -players=1000 -entities=10000 -hz=20 -dirty=1 -visible=50
for v in 4 8; do for m in sync async; do
  ROOST_PERF_COUNT=2 bash scripts/perf/sync-aoi.sh -players=1000 -entities=10000 -hz=20 -dirty=1 -visible=50 -views-per-player=$v -apply-mode=$m
done; done
ROOST_PERF_COUNT=2 bash scripts/perf/sync-aoi.sh -players=1000 -entities=10000 -hz=20 -dirty=1 -visible=50 -views-per-player=16 -apply-mode=async
ROOST_PERF_COUNT=2 bash scripts/perf/sync-aoi.sh -players=1000 -entities=10000 -hz=20 -dirty=1 -visible=50 -alliance-size=1000
```

**判据**：单视野三点无差异（夜间 `ClusterFlushRandomWalk` +3.5% 为已知）；ApplySync 4 / 8 视野帧数满、Flush 不超过半个周期；ApplyAsync 16 视野不失守。缺省 `-mode=periodic` 下 50ms 门槛失败是结构性的，比较看各点之间的差异。诊断构建（16 视野 ApplySync）见 §2。

**结果（2026-10-22 晚）**：见 [NIGHT §14'.3](NIGHT-20261020.md#143-2026-10-22-晚在-v1310-发版候选上复测发版前压测第-5-项)，样本 [aoi-3pt](benchmarks/v1310-prerelease-20261022/aoi-3pt/)。policy 微基准 10 轮交替：`ClusterFlushRandomWalk` P1 +3.45%、P2 +4.31%（D14 引入的已知项），`AOIBatchRecompute` coverage=false 在 P2 −64%～−81%（`6304ffa0`），其余 ±2% 内；sync-aoi 单视野 P0 / P1 无差异，P2 P99 低 4～6ms（Interest 单写者）。多视野与两种应用模式的表在 [HB-DRIVEN-LOAD §4A](HB-DRIVEN-LOAD-20261021.md#4a-2026-10-22-晚正式测量v1310-发版前压测第-6-项)（全局循环一列）：ApplySync 4 / 8 视野帧数满、Flush 16～17 / 24～25ms；ApplyAsync 16 视野 19.8 万帧、P99 116～118ms，不再失守。

## 6. 心跳负载

**目的**：D20 P4 的正式对比（全局循环 vs 心跳驱动）、D19 多视野在心跳驱动下复测、驱动微基准与开环投递；结果决定压测工具的缺省（[DESIGN-TODO](../maintenance/DESIGN-TODO.md#待维护者决定不急)第 9 项）。

**命令**：[HB-DRIVEN-LOAD §4](HB-DRIVEN-LOAD-20261021.md#4-待补测2026-10-21-因宿主资源占用推迟) 的四组（sync-aoi `-move-driver=loop|heartbeat` 原场景各 3 轮交替；4 / 8 / 16 视野 × 两种应用模式 × 两种驱动；nest-game `ROOST_NEST_GAME_HEARTBEAT_DRIVER=ticker|heartbeat` 各 15 分钟；`BenchmarkDriverDispatch` 与 `TestDriverOpenLoop` 10 / 25 / 50 万拍每秒）。工具构造驱动时不设 `Delivery`，即缺省的批量作业；要对比单目标需临时在工具里加开关（KNOWN-LIMITS“压测工具的心跳驱动”）。

**判据**：心跳模式零跳拍、零动作失败、投递 = 执行；nest-game 心跳路径 `verified=true`、每 Unit 拍数 `时长 / 档位 ± 2`；开环投递记各速率下的进程 CPU、跳拍与间隔分布。

**结果（2026-10-22 晚）**：见 [HB-DRIVEN-LOAD §4A](HB-DRIVEN-LOAD-20261021.md#4a-2026-10-22-晚正式测量v1310-发版前压测第-6-项)，样本 [hb-load](benchmarks/v1310-prerelease-20261022/hb-load/)。sync-aoi 原场景三种驱动（loop / 心跳 100ms / 心跳 200ms）P99 都在 51～59ms，心跳模式服务端 CPU −11%；多视野下心跳驱动 16 视野 P99 70～84ms（全局循环 116～137ms），负载形状不同、不全归因于投递方式。nest-game 15 分钟两档都通过：心跳路径 `verified=true`、每 Unit 8999～9000 拍、跳拍 0；心跳驱动进程 CPU 约 −19%、short 等待峰值 2614 → 139、Sync 提交→客户端 P99 9.42 → 6.07ms，业务服务端 P99 0.87 → 2.13ms。ticker 档 21:40:57 有一次约 0.2 秒的整体停顿（同时刻宿主 GUI 活动），尚未确认。驱动微基准：批量投递在 50 万拍/s 档多 12% 驱动 CPU（inline 客户端，不含 Nest 节省），其余档无差异；开环 10 / 25 / 50 万拍/s 零跳拍、进程 CPU 0.9 / 1.45 / 2.15 核、间隔 P99 ≤ 104.7ms。压测工具缺省驱动仍交维护者决定（DESIGN-TODO 待决定第 9 项）。

## 7. 可选：移动 200ms（5Hz）口径（缺省已改，历史口径显式 100ms）

维护者 2026-10-22：MMO / SLG 的移动一般 2～5Hz（优化项见 [DESIGN-TODO](../maintenance/DESIGN-TODO.md#优化项下一阶段)第 1 组）。**缺省已改**（[v1.31.0 O1](../release/v1.31.0-NOTES.md#o1)）：`movement.DefaultMovePeriod` 与 sync-aoi `-move-period` 的缺省都是 200ms。所以 §6 引用的 [HB-DRIVEN-LOAD §4](HB-DRIVEN-LOAD-20261021.md#4-待补测2026-10-21-因宿主资源占用推迟) 心跳驱动命令显式写 `-move-period=100ms`，作为**历史口径**与之前的数字对照；新缺省（200ms）可选补一组（不加 `-move-period` 即是，下面写成显式）：

```sh
ROOST_PERF_LABEL=p4-aoi-heartbeat-100ms bash scripts/perf/sync-aoi.sh -players=1000 -entities=10000 -hz=20 -dirty=1 -visible=50 -move-driver=heartbeat -move-period=100ms   # 历史口径
ROOST_PERF_LABEL=p4-aoi-heartbeat-200ms bash scripts/perf/sync-aoi.sh -players=1000 -entities=10000 -hz=20 -dirty=1 -visible=50 -move-driver=heartbeat -move-period=200ms   # 新缺省
ROOST_PERF_LABEL=p4-game-heartbeat-5hz ROOST_NEST_GAME_HEARTBEAT_DRIVER=heartbeat ROOST_NEST_GAME_HZ=5 <其余同 §6 nest-game 命令> bash scripts/perf/nest-game.sh
```

§1 的投递对比夹具（`TestDeliveryRun`）的登记周期固定 100ms（`Periods[Tier100ms]`），没有开关；要补 200ms 口径需先给夹具加一个周期参数（本轮收尾没有改夹具）。

`-movers` 缺省按改值速率折算，200ms 档下移动者数翻倍、每秒改值不变；如要“同样移动者、频率减半”的对照，显式给 `-movers`。结论只作参照，不替换 100ms 口径的数字。
