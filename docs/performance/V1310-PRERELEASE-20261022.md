## 0. 纪律与顺序

- 本机只给压测用：每段开始前记录别处的 `go build` / `go test`（门控脚本见各项），不与 race、profile、索引重建、长尾采集并跑；长稳前看 `sysctl vm.swapusage`、记录 `sysctl -n vm.loadavg`。

## 7. 可选：移动 200ms（5Hz）口径

维护者 2026-10-22：MMO / SLG 的移动一般 2～5Hz（优化项见 [DESIGN-TODO](../maintenance/DESIGN-TODO.md#优化项下一阶段)第 1 组）。移动负载除原来的 100ms 口径外，尽量补一组 200ms（5Hz），方便对照真实游戏频率：

```sh
ROOST_PERF_LABEL=p4-aoi-heartbeat-200ms bash scripts/perf/sync-aoi.sh -players=1000 -entities=10000 -hz=20 -dirty=1 -visible=50 -move-driver=heartbeat -move-period=200ms
ROOST_PERF_LABEL=p4-game-heartbeat-5hz ROOST_NEST_GAME_HEARTBEAT_DRIVER=heartbeat ROOST_NEST_GAME_HZ=5 <其余同 §6 nest-game 命令> bash scripts/perf/nest-game.sh
```

§1 的投递对比夹具（`TestDeliveryRun`）的登记周期固定 100ms（`Periods[Tier100ms]`），没有开关；要补 200ms 口径需先给夹具加一个周期参数（本轮收尾没有改夹具）。

`-movers` 缺省按改值速率折算，200ms 档下移动者数翻倍、每秒改值不变；如要“同样移动者、频率减半”的对照，显式给 `-movers`。结论只作参照，不替换 100ms 口径的数字。

## 8. 可选：Linux 复测

macOS 的调度器 `usleep` 计入 CPU，可能高估单目标投递的成本、也就高估批量作业的收益；checkpoint 同盘、Sync 长尾也都等 Linux / 独占宿主。今晚不要求；有 Linux 实机时按 §1、§4 第 3～7 项、§6 的命令复测。
