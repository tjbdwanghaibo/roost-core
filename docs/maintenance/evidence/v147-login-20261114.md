## 新增阶段

| 阶段 | 实际断言 |
| --- | --- |
| embedded-seed | A 登录签票，B 验票并选服；真实 TCP 握手、EnterStatus、未建成进入被拒、新建、首次进入；100 金币购买一次后余额 90、道具 1，重复购买与改名回执不重复生效 |
| cross-sid-naming | game 1001 与 1000 同时运行，Redis Directory 返回 `directory.CodeKeyTaken`；失败后仍未建成，再使用对方改名释放的旧名成功建角，首次金币只有一份 |
| embedded-restart | 保持真实 TCP，game 1000 `SIGKILL` 后原 WAL / Mongo 重启；记录旧连接结果；同一身份重新握手、First=false、购买与改名回执仍成立 |
| gate-a-seed / gate-b-seed | 两个独立 Gate 同时在线，各完成入口、新建、购买与改名；各有独立 sid / ops / TCP / discovery 地址 |
| gate-a-restart / gate-b-restart | 两条客户端连接同时保持，Game Ingress `SIGKILL` 后重启；分别记录旧连接结果，再经各 Gate 重连，持久业务状态不变 |
| account-failover | 停掉 account A，B 单独完成同一身份登录 / 选服 / 换票；原 Gate A 的玩家经 Gate B 重连 |
| gate-process-restart | Gate A 自身 `SIGKILL` 重启，同一身份重新握手、进入、重放购买与命名 |

每次正常进入都验证 `ServertimeNow` 时间字段及收包帧号：推送先于 `EnterGame` 应答；再发真实 `ServertimeSync`，核对 `ClientTick` 回显和时间快照。完成业务后还用正式 entitysync Decoder 与生成 DAO `ApplySync` 核对自身视图的金币 90、道具 1、改后名字，重启前后分别检查；只恢复回执却漏掉实际状态不能通过。它只是无故障本机观测：模块仍是尽力推送，客户端必须允许丢推送并主动对时，不能依赖固定先后。

Gate 阶段由客户端 `-endpoint` 显式选择 A / B，HTTP 入口负责账号票据、选服与进服票据，实际握手仍由 Gate / Game Ingress 经 account 校验；不把客户端选中的 Gate 地址当成 portal 动态目录的验收。
