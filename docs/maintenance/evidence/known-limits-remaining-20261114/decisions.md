## 一、Sync

### D1 self_sync 的 RetryLater 语义（推翻 C29）
- **现状**：自身视图的驻留预算拒收（`ErrRetryLater`）时，当前行为是整轮作废、所有 subject 保留脏状态，下一轮仍按会话 ID 从小到大重试（C29“低 ID 总是先试”）。2026-11-14 演练确认这会自我放大：每轮在同一位置被拒，前面的会话每轮重收全量、版本从不提交，后面的会话一帧也收不到（16 KiB 预算 / 100 玩家：200 轮 0 提交）。
- **已有修复（未合）**：分支 `tmp/sync-fixes`（`8c86065f`、`a0f07234`）：只作废没交付到的 subject，已交付的照常提交；下一轮从被拒的会话开始按 ID 轮转。16 KiB：提交 0 → 167 / 200，每个已提交轮字节 2544914 → 5507；64 KiB：31 → 197 / 200。两条回归修前红，5 个变异都红。
- **选项**：A 合并修复（C29 的“低 ID 先试”改为“从被拒处轮转”；要 rebase 到 feat/v147 并改写文档）；B 保留 C29，只在文档里写明“驻留预算要配到一轮全量放得下”。
- **推荐 A**：放大已确认会自我维持，B 只能靠配大预算躲开，预算一紧就会复现。
