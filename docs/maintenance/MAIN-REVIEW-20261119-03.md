## 新确认的既有问题

**RV-20261119-05 · P2 · TS Gate 的底层完成回调抛出异常后，其他请求仍在等待，已关闭的连接仍显示 Ready。** 在公开 `Connection.beginRequest` 上登记请求 A，再用同一连接的 `requestAsync` 登记请求 B。A 的业务回调在关闭通知中抛出异常。写失败和对端断开两种入口均已关闭传输，但 B 在 100 ms 期限之后、虚拟时钟推进至 1000 ms 仍为 pending，连接状态仍为 Ready。

`GateSession.close` 在逐个通知前已清空 pending。A 抛错使循环提前退出，B 的完成回调和通知 Connection 切换状态的 onClosed 均未运行。B 的超时处理也因 pending 已经清空而直接返回。正常对照中，A 的底层回调正常返回时，B 得到 GateClosedError，连接转为 Disconnected；若 A 改走高层 GameClient.request，即使业务回调同样抛错，错误监听也能收到该异常，B 与连接照常收尾。旧基线和本轮 main 各跑三轮，两种关闭入口结果一致。本次 793b6c215 修复的普通写失败重复回调场景已经通过。验收应同时核对每个请求只结算一次、其他请求能结束、底层传输与 Connection 状态一致。[关闭循环](https://github.com/tjbdwanghaibo/roost-core/blob/66d6eab2f/client/ts/src/gate/session.ts#L146) · [公开回调入口](https://github.com/tjbdwanghaibo/roost-core/blob/66d6eab2f/client/ts/src/gate/connection.ts#L130) · [旧基线](evidence/main-review-20261119-03/ts-baseline.log) · [main](evidence/main-review-20261119-03/ts-main.log)
