## 1. 已定的决定

### 1.1 单实例锁改存 etcd

- **做法 A**：在 `wiring/etcd` 里实现 `SingletonStore`，生成工程全工程统一使用。锁和服务发现共用同一个 etcd 集群和同一个锁前缀。`framework/app` 不改。
- **etcd 侧实现**：
  - 抢锁：申请租约，再用事务做"键不存在才写入"；
  - 续锁：先续租约，再核对键值和租约；
  - business_time：不挂租约；
  - 读锁：一个事务读完所有要读的键。
- **删除** Redis 版的 `SingletonStore`。
- **接受**：etcd 不可用时，开着单实例锁的进程会停掉（fail-stop）。生产环境要求 etcd 至少三节点。
- **doctor 新增全工程检查**：所有服务的 `etcd.endpoints` 和 `singleton.key_prefix` 必须一致。

### 1.2 controllers 合包

- `game/controllers` 合成一个包，只有一个公共的 `controller.go`，放 Controller、FromRegistry 和推送辅助。
- 每个模块只有一个 `<模块>.go`，测试只有一个 `<模块>_test.go`。
- 协议生成器把缺少的 `Handle*` 存根追加到 `<分组>.go`，只追加，不改已有内容。

### 1.3 组件接口收进 view

- 窄接口返回 view 里的接口，不返回具体的组件结构体。
- 组件需要宿主实体提供的方法，也写进 view 的窄接口；实体总接口嵌入这些窄接口，由实体实现。
  - 纯 DAO 交接的方法由生成器实现；
  - 其余方法写在 `entities/<实体>/<模块>.go` 里手写实现。
- `//roost:component`、组件类型号和注册都挪进组件包。
- activity 只用一个组件类型号。
- 约 30 个 `entities/*/*_component.go` 会删除。

### 1.4 实体事件

- 事件定义放在 `game/event`（新增的第七个固定层）。
- 实体底层自带 `Publish`。
- core 提供"事件名 + 回调"的登记方法，只由生成代码调用。
- 用 `//roost:listen [priority=N]` 标记实体方法或组件方法：
  - 优先级大的先执行；
  - 同优先级时，实体自己的监听先执行，然后按组件初始化顺序，再按方法名。
- **嵌套**：事件里再发布事件时，立即按深度优先执行。
- **错误**：必须一路外传。拦截类监听只做检查，不改状态。
- **运行时上限**：嵌套 8 层；同一事件同时在栈上 3 次；一次最外层发布内总共 256 次。超过任一上限都报错，错误里带完整的事件链。
- 生成器会给出静态的环提示。
- 33 个现有钩子中，通知类和拦截类共 25 个改成事件；扩展提供方和连接层的钩子保持现状。

## 2. 依赖关系

```
单实例锁（etcd） ─────────────── 独立，可与其余并行
controllers 合包 ─────────────── 独立
组件接口收进 view ──┬─ 组件类型号挪进组件包（comp:"<包>.CompTypeX"）
                   └─▶ 实体事件（扫描组件包里的 //roost:listen 依赖新的 comp 标签）
```

- 单实例锁和 controllers 合包不依赖其他任何一项。
- 实体事件必须在"组件类型号挪进组件包"之后做。
- 模块模板的批量改动要把三项（不含锁）一次改完。这样每个模块只改一遍，模块门禁也只跑一遍。

## 3. 实施前先核实（第 0 步）

| 要核实的点 | 来源 | 结论会影响什么 |
|---|---|---|
| Nest 生成器：handler 参数类型挪到 view 后，还能不能找到目标实体 | layout §6.1 | 挂在多个实体上的组件，是否必须显式写 `target=` |
| 组件类型号只按组件分配：框架是否要求类型号在不同实体之间唯一，类型号会不会进存档或同步数据 | layout §6.2 | activity 能否只用一个类型号 |
| Nest 的 memory 快路径里有没有 `RollbackTx` | event §3.3 | memory handler 里能否发布事件 |
| controllers 合包后，各模块的测试辅助函数会不会重名 | layout §6.3 | 测试辅助函数是否统一加模块前缀 |
| etcd 换 leader 时租约被续满，对启动等待（2×TTL）的影响 | singleton §6.2 | 演练里要不要单独加一个用例 |

### 3.1 核实结论与决定（2026-11-16 晚，维护者已确认）

1. **Nest 参数类型挪到 view**：调度和锁不受影响。参数类型名里带 `Entity` 就会被认作锁目标，运行时做类型断言。
   - **受影响的是"handler 归哪个服务"的判断**（`codegen/internal/nest/owner.go`）。它按参数类型所在的包查 `service=`，类型挪到 view 后就查不到了。
   - **决定**：
     - `view.<E>Entity` 直接对应实体 E；
     - view 里的组件窄接口，按挂载这个组件的实体来确定归属。这些实体都属于同一个服务时，就用这个服务；属于不同服务时，生成失败，要求写 `target=<实体>`。
   - **命名**：组件窄接口在 view 里命名为 `I<X>Entity`（例如 `view.IProfileEntity`），避免和实体总接口 `<E>Entity` 重名。room 组件和 Room 实体就是会撞名的一对。
2. **组件类型号只按组件分配**：可以。
   - 组件存放在每个实体实例自己的组件表里；工厂表是全局的；类型号不进存档，也不进同步数据。
   - 唯一的影响：实体内各组件按类型号升序初始化，所以 activity 改号后，同一实体内的组件顺序可能变。模块里没有声明过组件依赖，不影响正确性。
3. **memory 快路径**：**允许发布事件**（维护者决定）。
   - `Publish` 只检查当前 Guard 是否持有这个实体，不要求有可回滚的事务。
   - 在 `rollback=none` 的 handler 里，监听返回的错误照常往外传，但前面已经做的修改不会撤销。这一点写进文档。
4. **controllers 合包**：测试文件之间没有重名。正式代码只有 §1.2 已知的那 5 个重名。
   - 有 25 个 controller 文件来自 `with/<对方模块>/`，这些文件只在两个模块都装了时才生成。
   - **规则**：每个模块一个 `<模块>.go`；联动文件命名为 `<模块>_<对方模块>.go`；测试文件按同样的规则命名。
5. **etcd 换 leader**：新 leader 会把所有租约续满。这是 etcd 公开的租约行为，本机没有 server 源码可以核对，留到演练里验证。
   - 最坏情况下，旧锁会多活一个 TTL 再加大约 1 秒，可能让 30 秒的启动等待差一点点。
   - **决定**：生成的 `startup_wait` 改为 35s，部署模板里的启动探测余量同步放宽。

### 3.2 试点结论与决定（2026-11-16 夜，维护者已确认）

试点 9aaebe7f 涉及 bag、profile、naming、activity、activity_world、activity_alliance。装上这些模块的生成工程能编译，`generate --check` 无差异。合包后全量 catalog 能加载。

1. **endpoint 生成器也认 `target=`**。组件挂在多个实体上时，endpoint 可以收 `view.I<X>Entity` 加 `target=<实体>`。
2. **activity 组件挪到 `game/components/activity`**。整个包改名，所有引用一起改。
3. **保留 `activity.Of(holder)`**：从 view 接口取回具体组件。Token 等带方法的类型不挪进 view。
4. **旧写法组件上的 `//roost:listen`**：阶段 4 把全部模块改成组件包写法之后，生成器把它从提示改成报错。
5. **泛化的导出方法名加模块前缀**：`Open` 改为 `DungeonOpen`，`Claim` 改为 `DungeonClaim`，`Redeem` 改为 `CdkeyRedeem`。
6. **模块门禁按前缀挑测试的问题**：在最终全量时核对各模块的场景数，有冲突就改用精确测试名。

## 7. 风险

- **etcd 故障的后果变重**：etcd 不可用时，所有开锁进程会停掉（维护者已接受）。部署文档写明 etcd 至少三节点。
- **改动面大**：一个模块的问题会让整个 `game/controllers` 包编译失败。试点阶段（3）先把生成器的路走通，再开始批量改。
- **事件改为立即深度优先执行**：这与现在钩子的行为一致，迁移前后语义不变。模块门禁中的联动场景数量必须保持不变。
- **第 0 步的核实结果可能改变局部做法**：如果组件类型号必须按实体区分，activity 就保留多个类型号，组件包里放多个常量。出现这种情况先报告，再改方案。
