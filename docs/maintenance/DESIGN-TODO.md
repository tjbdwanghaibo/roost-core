# 后续设计与优化候选

本页是需求与验证入口，不是必须全部清零的缺陷清单。2026-10-31 按当前实现和维护者决定收敛；现行能力见 [KNOWN-LIMITS](KNOWN-LIMITS.md)，部署验收见 [EXTERNAL-VERIFICATION](EXTERNAL-VERIFICATION.md)。已完成 D1–D23、旧性能样本与讨论见[历史快照](https://github.com/tjbdwanghaibo/roost-core/blob/132ed79f689df01dc8df0ea3a44e9a768ee126d9/docs/maintenance/DESIGN-TODO.md)。本页不恢复 Redis 权威路线，不增加旧格式兼容。

## 本轮收敛

- **状态回滚后观察者一致性**：已增加 Nest `AfterRollback`，全部逆操作成功后、实体锁释放前重建；State 按差发送 `Change.Rollback=true`，门控冻结无需等待下一次改动。该通知不能写 DAO、发奖励或网络消息。已经取消的动作不会复活。恢复失败时不发送代表成功恢复的通知。
- **Remote 与移动/心跳**：源码复核纠正旧提案。Remote 独占 owner 已支持移动与心跳，存在共享往返、转移和卸载重载测试；不能再“一律禁止 Remote”。共享模式登记拒绝，运行期变为共享后下一拍在锁内停止；回到独占后由业务重新启动。保留这些正式契约，不增加禁止已有能力的种类级开关。
- **默认移动档位**：已是 200ms/5Hz；旧 100ms/10Hz 只是历史基准参数。小改动、已完成文档和重复引用不再列作开发任务。

## 按需求触发的功能

| 功能 | 何时需要 | 实施边界 |
| --- | --- | --- |
| 按观察者过滤可见性 | 隐身/反隐、相位、阵营保密 | 过滤必须在服务端建立/撤销订阅前完成，明确权限变化失效与失败关闭，不能只隐藏客户端渲染 |
| 无观察者暂停 AI | 大量无人观察 NPC 消耗明显 | 可选、默认关闭；任务推进/动作暂停/恢复和计数口径先定，见 [AI 方案](FEATURE-2026-10-22-ai-idle-without-observers.md)。后台生产或持续战斗不能因无人看而停 |
| 多视点并集 | RTS 单玩家几十单位导致视野挂接成本高 | 先测现有多视野瓶颈；不能扩大可见权限或把所有单位共用一个中心 |
| MaxVisible 优先级 | 拥挤场景把当前目标/BOSS 挤掉 | 重要目标优先占预算，仍保留硬容量；不默认建立无限“必须可见”例外 |
| ApplyAsync 结算预算 | 实测政策阶段持续占用过长 | 保持日志顺序与事务边界，验证积压/饥饿，不只把耗时推迟到下一拍 |
| Gate Lockstep 写出回执/上限协商 | 确定使用独立 Gate + Lockstep，尤其大快照/弱网 | 当前 Game 准入不等于 Gate 写出；需协议设计与慢链路验证。普通状态同步使用现行有界队列及恢复契约 |
| RetryLater 跳过被拒会话 | 队列持续拒绝导致重试放大有实测证据 | 验证公平性、恢复、Remove 与生命周期，不静默丢帧 |

## 先测量再优化

1. **心跳批量投递与业务 P99**：默认时间片已经 100µs；先在当前版本做同负载 dispatch/try_batch 对照，记录回调耗时、批次占 worker 时间与排队，再决定是否调整。历史 200µs、100/200ms 两档单样本不能证明当前退化。
2. **game-demo 热点**：World 登录计数、公会目录与奖励链按当前实现复测。旧 Saga 每进程约 8/s、已删除 lease fence 的现象不再作为当前故障或容量；仅保留历史链接。若仍有热点，依次评估计数合批、移出登录关键路径、目录分片，不能为了跑通冒烟放宽错误阈值。
3. **客户端与新 PB 同步**：正式 Gate/C# 联合功能链已验证；CPU、内存、队列与带宽需要同负载测量。新增 native C++ 是共享网络线程的实现方向，不凭语言宣称性能提升。

## 未排期候选

- D2：SyncBus 框架级对账。当前定位允许丢失广播，要求最终一致的业务须有快照/对账；有通用需求再上升为框架协议。
- D3：Drain 明确放弃出口。先确定永久错误、操作者权限与数据责任，不能通过放弃把失败伪装成完成。
- D4：migration 生成骨架。仅在真实业务 schema 变更需求下实现；不恢复自动迁移、旧格式双读。
- D5：Player 迁服命令。以落库数据为准，不实现跨机 WAL 热迁移；部署需求出现后排期。
- D11：Remote/noPersist 持久定时器。需要明确持久归属、恢复身份和所有权；noPersist 不能被命名掩盖持久状态需求。
- D1：客户端上传快照、压缩/增量快照、game-demo 战斗恢复等按具体游戏排期。MOBA 已有持久 Room 与已提交快照恢复，不能再笼统记“框架完全没有崩溃续赛”。跨进程组合与 Unity/IL2CPP 未测部分仍保留。
- D21：其余 SSR 空间、战斗、经济、社交部件按实际玩法选取；先与 service/gameplay 现有能力对照，不批量移植、不开空壳包。

## 验收而非新增框架功能

真实账号票据、Mongo 持久化/崩溃恢复、目标 Linux/跨机网络与 Unity/UE/IL2CPP 按实际交付选择验收，不从本机替身推导生产保证。Windows 服务端仍不在支持承诺内；新 native 客户端按维护者要求面向 Windows/macOS/Linux/Android/iOS，其构建与设备测试状态单独记录。

本轮验证：`go test ./...` 通过；Nest/State/CombatComponent 与 Remote 心跳/移动相关包 race 通过。先前“回滚不通知”的状态与 Buff 测试已改为断言回滚返回前完成对齐，不删测试或放宽时序。native 的平台矩阵及复跑入口见 [客户端说明](../../client/cpp/README.md)。未重跑历史性能基准，不将功能验收写成吞吐优化收益。
