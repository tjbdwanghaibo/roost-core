# 可编辑地形大世界（方案稿，2026-11-08）

状态：**方案稿，未实施，待维护者拍板第 8 节的决策项。** 目标是在 cellworld 无缝大世界上支持玩家改地形（挖、填、抬高、整平、改材质）、由此形成湖泊和高地，并在地形上放置建筑。本文给出默认选型、数据模型、权威与同步、分期与验收；数字是按默认参数的估算，不是实测。

## 1. 现状（main v1.42.2）

| 部分 | 现状 | 位置 |
| --- | --- | --- |

## 2. 默认选型

- **2.5D 高度场**：水平面上按固定间隔采样，每个 (X, Y) 只有一个地面高度。能表达山、高地、坡、盆地、坑、河床、湖（盆地 + 水面）；不能表达洞穴、隧道、悬空与天然拱。桥、楼、地下室作为建筑物体放在地形上。
- **渲染 mesh 在客户端生成**：服务端只存高度场与各层数据，Unity 按块生成网格、做 LOD 与接缝；服务端不存三角网格。
- **块（chunk）64m × 64m，采样间隔 1m**，每块 64 × 64 = 4096 个点（相邻块共享边由右 / 上块持有，不重复存）。
- **每点的层**：高度 `uint16`（D2：1cm 精度、655m 高差，或 10cm 精度、6.5km 高差）；材质 `uint8`；建筑占位由建筑实体推出，不单独持久化（第 6 节）；水按规则计算，不逐点存（第 5 节）。

### 2.1 规模估算（1w × 1w，按米，1m 采样）

| 块大小 | 每边块数 | 总块数 | 每块原始（高度 + 材质） |
| --- | --- | --- | --- |
| 32m | 313 | 约 9.8 万 | 约 3KB |
| **64m（缺省）** | 157 | **24,649** | 约 12KB |
| 128m | 79 | 约 6,200 | 约 48KB |
| 256m | 40 | 1,600 | 约 192KB |

整图 1 亿个采样点，原始约 300MB（高度 200MB + 材质 100MB）；2m 采样为四分之一。原始地形是静态资源，不进数据库；数据库只存被改过的块；服务端内存只装有玩家附近的块。与分格对齐时（D4，`cell_size` 取块边长的整数倍，如 3072 = 48 块），1w 地图约 4 × 4 个格，每格约 2,300 块，全部装入约 27MB 原始数据。

## 3. 数据模型与持久化

**原始地形（base）**：按块切好的静态资源文件，带 `BaseRevision` 与每块 SHA-256，服务端与客户端用同一份（沿用物理房间关卡“版本 + SHA-256 加载”的做法）。服务端启动时只读索引，块按需加载。

**地形块实体 `TerrainChunk`**：Nest 实体，ID 由块坐标编码；只为被改过的块建持久记录。

| 字段 | 内容 |
| --- | --- |
| `BaseRevision` | 这块基于哪一版原始地形；原始地形升级时用于判定是否需要重放 / 迁移 |
| `Version` | 块版本，每次提交加一；同步与客户端缓存按它判定 |
| `Heights`、`Materials` | `[]byte`（整字段写，压缩后存），首版整块写 |
| `Applied` | 最近 N 个已应用的编辑 ID（幂等，见第 4 节），有界 |

加载 = 原始块 + 持久记录覆盖；从没改过的块不建实体、不读数据库，只读原始资源。

**写放大**：首版每次编辑整块重写（约 12KB 原始，压缩后通常几 KB）。编辑频率高时再考虑“编辑日志 + 定期压实”，需实测后决定（P5）。

## 4. 编辑：权威、校验与事务

**权威**：块归包含它的 cellworld 格所在进程；格到进程静态映射，块不迁移。要求 `cell_size` 是块边长的整数倍（D4），一块不跨格。

**编辑操作**（首版只做笔刷类，整数运算，客户端可同算）：

| 操作 | 参数 |
| --- | --- |
| 抬高 / 降低 | 中心、半径、增量、衰减曲线 |
| 整平 | 中心、半径、目标高度 |
| 改材质 | 中心、半径、材质 |

每个操作带玩家请求 ID（幂等）。

**链路**：客户端 → 玩家所在的 Base 进程（鉴权、领地 / 权限、频率）→ 按落点转发给目标格的 Real 所在进程（与 cellworld 跨格攻击“转发给目标 Real 结算”同一模式）→ Nest 多实体请求锁住受影响的块 → 校验 → 提交 → 提交后发增量（第 7 节）。

**服务端校验**：

- 单次最多影响的块数（缺省 4）；
- 单次最大高度增量、整平目标的范围；
- 不能低于基岩高度、不能高于上限；
- 不能改有建筑占位的点；
- 每玩家编辑频率；
- 领地 / 权限规则由业务提供钩子。

**跨格编辑（D5）**：首版拒绝或拆分跨格边界的编辑；拆分后各格独立提交（同一请求 ID 派生子 ID），边界接缝最终一致。跨格原子编辑要走 Remote 或 Saga，放到 P5 按需求决定。

**消耗资源（D6）**：改地形要扣玩家资源时，玩家在 Base 进程、块在格进程，是跨进程。可选：

- 先在 Base 预扣、编辑失败退还（结果未知时按请求 ID 查询编辑结果后决定，不能直接退）；
- 或走 Saga。

首版推荐预扣 + 按请求 ID 对账。

## 5. 水：规则水位（D3）

首版用**全局（或按区域配置的）水位线**：地面低于水位线的点就是水。挖到水位线以下自动成为池塘或湖，抬高到水位线以上就是陆地 / 高地。纯规则、可在任一端算出、不需要跨块计算，也不需要同步额外数据。

**后续可选：盆地水位**。编辑造出封闭盆地时有界洪水填充算出水面高度，水面按盆地记录。跨块、跨格的盆地要额外处理，P4 之后按需求做。

**不做流体模拟**（流动、漫溢、决堤）：跨格进程同步代价高，不在本方案范围。

## 6. 建筑

建筑是独立持久实体 `Building`，内容如下：

- 类型、锚点、朝向、占地形状（格子集合）、底面高度、状态（建造中 / 完成 / 损坏）。
- 归锚点所在格的进程。
- 放置校验：
  - 占地内坡度上限；
  - 不在水下（或按类型允许）；
  - 不与其他建筑重叠；
  - 权限。
- 放置时可选同一事务整平地基（地基整平是对块的编辑，受第 4 节约束）。

块的“占位”不单独持久化：格进程加载时由本格建筑实体推出，建筑变化时在同一事务里更新内存占位。

首版禁止跨格建筑（D7）；需要时由锚点格拥有，邻格只读占位副本。

## 7. 同步

**客户端订阅**：按视野半径订阅块（视野 200m 约覆盖 50～60 块）。进入区域时每块下发 `(BaseRevision, Version)`：

- 客户端本地已有原始地形且块没改过，什么都不发；
- 改过的块下发整块数据（压缩）。

**增量（D8）**：

- 首版推荐“下发编辑操作 + 新版本号”，客户端用同一整数算法重放，量小；
- 版本断档、重连或校验和不符时回退为整块下发。

另一选择是每次都下发整块，实现简单、流量大。

**载体**：

- 现有 entitysync 按 DAO 字段同步，块的 `[]byte` 字段变化即整字段下发，可作为首版“整块”路线；
- 操作重放路线需要新增地形消息（不复用 chunksync：它是物理对象的按区域增量，不是数据补丁）。

**格边界**：邻格需要 Ghost 带（缺省 500m）内的地形与建筑占位副本，用于视野、移动和交接判断。格进程之间像 Ghost 一样推送边界块的版本与编辑，副本只读。

## 9. 分期与验收

| 期 | 内容 | 验收 |
| --- | --- | --- |
| P1 地形底座 | 原始地形资源格式与加载；`TerrainChunk` 实体、持久化与“原始 + 覆盖”加载；`Height(x, y)` / `Material` / `IsWater` 查询（单进程） | 1w × 1w 原始资源加载与按需装块；改块重启后一致；查询与客户端同算法结果一致 |
| P2 编辑与同步（单格） | 笔刷操作、校验、幂等、多块事务；客户端订阅、基线与增量、断档回退 | 重复 / 乱序请求不重复生效；断线重连后客户端与服务端块版本、数据一致；单格编辑吞吐与下发流量实测 |
| P3 接入 cellworld | 块与格对齐、边界块副本推送；移动加入高度查询与坡度 / 台阶上限、游泳；寻路改为高度场 A* | 跨格移动、交接与边界视野在改地形后正确；寻路随块版本失效；现有 cellworld 回归不退化 |
| P4 水与建筑 | 水位线规则；`Building` 实体、放置校验、地基整平、占位推导 | 挖坑成湖、填平成陆的规则可复现；建筑占位重启后正确；不在水下 / 坡上违规放置 |
| P5 跨格与规模 | 按 D5 / D6 的跨格编辑与扣资源；按需编辑日志压实；1w 地图 + 目标在线的容量测试（并入首发清单 L06 / L07） | 跨格编辑无双写、接缝最终一致；内存、写放大、带宽在预算内 |
| P6 物理（可选） | PhysX 高度场形状、运行中更新地形、每格物理世界 | 投射物 / 载具与改过的地形碰撞正确；与 Unity 同 tick 对照 |

## 10. 不在范围

洞穴与隧道（体素）、流体模拟、地形的跨机物理世界迁移、客户端地形渲染与 LOD 的具体实现（只约定数据格式与版本）。cellworld 自身的生产化（崩溃恢复、交接验收、时钟前提）按首发清单 L04 另行推进。
