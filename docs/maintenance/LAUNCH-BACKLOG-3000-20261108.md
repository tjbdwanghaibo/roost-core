# 首发缺失项实施清单（2026-11-08）

目标：全部已选能力启用，3000 同时在线、单逻辑服累计 10 万玩家。来源：[上线评估](LAUNCH-READINESS-3000-20261107.md)，代码依据为 [v1.42.2](https://github.com/tjbdwanghaibo/roost-core/commit/6fba8a8b)。本清单收录该评估的全部缺失项，供维护者后续实施；不声称发现了框架所有潜在问题，也不将未验证事项全部归类为代码缺陷。

**当前所有任务均待实施或待提供实际项目证据。** 已修复并验收的问题保持关闭，见 [修复复验](FIX-REVIEW-1422-20261107.md)。本次只提交任务，不修改运行时、不部署、不执行压测、不新建 GitHub issue/PR。任务编号用于后续提交与证据关联。

优先级：A 为开放相应玩法前必须完成；B 为正式目标规模放量前必须完成。条件项仅在采用该架构时生效。任务可用已有业务实现及有效验收证据关闭，不要求重复开发已有能力。

## L01 首发规格

- [ ] 确认“10 万玩家”是累计注册、建角还是活跃存档；区分逻辑服、SID、进程、主机。
- [ ] 固定操作系统、CPU/内存、磁盘与持久盘特性、部署方式、地域/跨机延迟、依赖版本及副本策略。
- [ ] 定义各玩法在线占比、房间人数、物理 tick、刚体/约束预算、NPC/同屏峰值、跨格率、Saga 请求率、热点 key、断线重连峰值。
- [ ] 定义延迟 p99/max、可接受丢拍/拒绝率、RPO/RTO、积压恢复时间及验收持续时间。

验收：形成一份带版本的规格，所有容量报告引用同一规格；未知项写明，不用默认值填成已确认需求。

## L02 联盟迟到成功资产闭环

现状：`demo/internal/service/game/alliance_saga.go.tmpl` 的 `guildSteps.keep` 对退款后才成功的建盟/捐献只记 Warn，保留联盟/贡献。属于业务策略缺口，不是 Saga 新缺陷。

- [ ] 产品选择撤销、幂等追回、冻结待对账或其他明确方案；明确贡献已消耗、联盟已有成员时如何处理。
- [ ] 增加持久处置状态、原操作身份、处理结果查询和审计；不能只依赖瞬时日志。
- [ ] 撤销/追回入口具备权限与幂等语义，业务状态变化和处置记录一起可靠提交。
- [ ] 验证正常成功、明确失败、超时退款后迟到成功、重复/乱序通知、处置中崩溃重启、人工操作重复执行。

验收：按选定政策精确核对扣费、退款、联盟/贡献及处置账本；没有未记录的免费资产或重复扣回。不要未经产品决策直接扣回玩家资产。

## L03 UGC 联合玩法

入口：现有 `gameplay/level`、物理 Room、正式关卡版本加载、Unity 接入；沿用通用 Level，不另建重复结算状态机。

- [ ] 固定关卡版本与发布/撤回规则；新旧房间明确绑定版本，恶意或超预算关卡有可执行的拒绝路径。
- [ ] 串联账号/名单准入、进房、服务器输入判定、转轮/移动平台、抓取/约束/碰撞、Unity 预测纠偏。
- [ ] 串联检查点、淘汰、排名、结算和永久发奖；进程重启、房间终止、断线恢复采用明确业务规则。
- [ ] 用真实 Unity 构建经正式传输跑完整闭环，覆盖超时/重复输入、旧连接输入、弱网重连、结算途中崩溃和房间反复创建销毁。

验收：关卡不漂移、客户端不能自报通关或资产、奖励幂等，客户端表现与服务器裁决在规格预算内收敛。分别保存编辑器、目标 Player 构建和 Linux 服务端证据。

## L04 cellworld 生产化验收

- [ ] 明确非持久 SceneActor/Monster 的恢复语义，哪些战斗事实允许丢、哪些需要业务持久化；持久化只为业务要求补，不把所有模拟字段无条件落库。
- [ ] 验证 Base/格进程强杀、交接在途、跨机乱序/重复、租约到期离场、NPC 恢复与热点活动。
- [ ] 对 Entry 跨 Base 重启的时钟不回拨前提落实时钟策略与异常处理；若无法保证，设计可靠代际来源并验证。
- [ ] 核对集群内互信边界与消息发布权限；更新 README 中“只在原型分支上”的过时描述，明确已合入但仍有哪些生产保证未验收。

验收：约定窗口内没有双权威或永久冻结，离场收敛、视野与战斗恢复满足规格；分别记录分散玩家与同区域集中玩家结果。

## L05 独立 Gate + Lockstep 大快照（条件项）

- [ ] 确认是否采用此组合；如采用，补上 Game 到 Gate 的写出回执、超时/取消、连接代际与有界在途协议，或选择已验证的嵌入 TCP 路线。
- [ ] 验证慢链路、长快照、并发正常会话、重连、Gate 重启、迟到回执，防止仅凭准入持续堆积或断开循环。

验收：恢复按链路实际进度推进，内存有界，快会话不被拖死。嵌入 TCP 的现有 Linux 回归不能用于关闭独立 Gate 此项；不采用该组合时记录架构排除理由。

## L06 十万玩家积累

- [ ] 建立真实字段/成员规模的 10 万玩家历史数据、守卫、联盟、邮件、回执与 Saga 历史分布；保存造数种子与脚本。
- [ ] 测量访问不同玩家后常驻内存、路由登记/续期、冷启动预加载时间、Mongo 索引与数据增长、Redis 内存及负载。
- [ ] 根据测量选择分片、空闲卸载或归档；如新增卸载，覆盖在途请求、续期、定时任务及重新加载一致性。
- [ ] 明确回执/幂等记录保留与归档期限，覆盖最大重试、停机和积压时间；不能只为节省空间提前删除防重事实。

验收：按长期积累模型有资源预算和恢复耗时，超过预算有可执行措施。10 万个已加载路由实体每 10 秒续期约 1 万键操作/秒仅为条件估算，不是容量结论。

## L07 三千在线混合容量

- [ ] 在 L01 的目标硬件和实际数据上按 300/1000/3000 在线分档；真实请求混合、有效新业务写入、同步与 Saga/Remote 同时运行，禁止只建立空连接或重复查同一回执充数。
- [ ] 另测活动热点、批量登录/重连、全量同步峰值、跨格交接、物理房间分布；如果全员进入 20 人房间，则是 150 房间，不能外推单机八房间样本。
- [ ] 记录 p99/max、tick 丢拍、RSS/Go/原生堆斜率、带宽、WAL/投影/消息积压、续期、拒绝和恢复时间；执行声明时长的长稳及反复建房销毁。
- [ ] 明确准入、限流、排队/拒绝、降级和扩容阈值；在过载解除后验证恢复及资产最终状态。

验收：目标负载持续达到规格，积压不持续增长，过载有界且能恢复；报告包含配置、机器、版本、失败样本及余量。本任务仅登记，当前未授权执行新压测。

## L08 部署与恢复拓扑

- [ ] 编制服务到 SID、主机、WAL/PVC 的映射；固定 SID 的生成模板不能直接增加 replicas。
- [ ] 验证同 SID 单 writer、旧进程未退场时新进程不能接管写入、持久盘独占、SIGTERM 排空和超时处理。
- [ ] 落实 Remote 原 owner 同 SID 重启或受控迁移流程，不能假定 owner 死亡后任意新 SID 会自动接管。
- [ ] 明确 NATS/Mongo/Redis/etcd 的故障域、持久化与副本配置，验证 readiness、依赖不可用和单实例锁丢失后的进程管理。

验收：实际部署物与映射一致，重启不丢 WAL、不出现双 writer，预加载结束前不接业务，人工/自动恢复步骤可复跑。

## L09 生产配置与制品

- [ ] 固定 core/CLI/客户端/协议/配置表版本与镜像 digest；测试和生产晋级同一制品。
- [ ] 在真实业务工程执行 `make ci`、`make release-check`、doctor、生成物/ID 漂移检查。
- [ ] 对实际挂载的各服务文件执行 `roost config check --service <name> --file <实际文件> --production`，再核对整套配置的 SID、命名空间、数据源、票据签名和跨服务规则。
- [ ] 检查外置 Secret、卷、账号权限、限额、停机预算和证书生命周期；示例/开发配置通过不等于生产配置通过。

验收：保存脱敏校验报告和部署清单，无占位配置；不得提交真实密钥到证据或仓库。

## L10 真实业务接入

- [ ] 接入实际账号认证、票据颁发/验签/过期与重放处理，验证连接代际及异地/重复登录的产品规则。
- [ ] 接入实际支付回调验签与来源验证，以业务订单身份持久防重，处理重复回调、乱序、超时和对账；没有支付功能时明确标记不适用。
- [ ] ops/GM 管理面配置认证、网络可达边界及操作审计；业务命令校验权限，不能仅凭客户端传入玩家 ID。
- [ ] 按实际传输落地公网加密/终止方案、消息大小与请求频率边界，并验证客户端错误及重连流程。

验收：未经授权请求无业务副作用，合法重试不会重复发货/扣款，拒绝与补偿可查询可对账。

## L11 告警与处置

- [ ] 配置业务可用性/登录失败、p99、断线/拒绝、WAL/投影/outbox/JetStream 积压、磁盘水位、fence/fail-stop、Redis 续期、物理 tick、资产对账的适用告警。
- [ ] 每个告警给出接收人、阈值依据、诊断入口及恢复/升级处理步骤；故意触发验证能到人。
- [ ] 区分可重试、结果未知、明确拒绝和必须隔离的故障，不让运维按“再发一次扣款”处理未知结果。

验收：告警触达和一次完整处置演练留证，仪表盘不是唯一交付物。

## L12 备份恢复

- [ ] 列出 Mongo、未投影 WAL、Saga JetStream 日志/快照、所用 Redis 权威业务数据及配置表的备份范围，区别可丢缓存。
- [ ] 制定一致备份或停写排空步骤、保留周期、恢复到隔离环境与校验流程；禁止把活动目录直接复制当成一致备份。
- [ ] 实际恢复并核对实体版本、资产、未完成 Saga、幂等回执和恢复后的第一笔写入，记录 RPO/RTO。

验收：恢复后的业务状态可信且可继续写；不以删除 WAL、跳过冲突或手工改版本号来伪造通过。

## L13 故障矩阵

- [ ] 在扣款/提交/投影/发布/回执/补偿等关键窗口强杀，覆盖结果未知与重复执行。
- [ ] 在目标部署上注入 Mongo primary 切换、Redis 不可用/切主、NATS leader 切换/重投、etcd 连接中断或 watch 恢复、磁盘满和停机超时等实际使用的故障。
- [ ] 负载下验证恢复追平、单写者、永久资产守恒，以及重启/重连的用户可见结果。

验收：每格有触发方式、观察证据和准确预期；设计允许的 fail-stop 不算必须消除，但需满足恢复时限与数据正确性。单元替身不能代替真实部署故障证据。

## L14 上线后兼容政策

- [ ] 在正式上线时更新“尚未上线可清空格式”的维护政策，登记第一份受保护的线上数据与协议版本。
- [ ] 建立 schema/WAL/wire/配置版本变更评审和迁移步骤；按实际需要选择兼容窗口、双读或停服迁移，不默认所有协议永久兼容。
- [ ] 为每个发布声明旧程序能否读取新数据；不能回退二进制时准备前滚方案及匹配备份恢复边界。
- [ ] 在生产形态副本上验证升级、失败恢复及首笔业务写入，不靠清库通过。

验收：发布物附迁移和回退判定，真实玩家数据不受“原型格式随意变更”政策影响。

## L15 放量与关闭规则

- [ ] 汇总全部适用任务的通过证据，未完成项明确“不开放该功能”或阻止放量，不把待验标成通过。
- [ ] 制定小流量到目标在线的阶段、观察窗口、停止放量与回退/前滚条件、值班与公告方案。
- [ ] 每次升级/配置变化只重跑受影响的门禁及必要完整验收，保留历史失败与修复对应关系。

每项关闭记录统一填写：实现提交、目标版本/配置、环境与机器、执行命令、样本/时长、结果与失败样本、证据路径、剩余边界、负责人/日期。缺少实际数据时保持未完成。
