# 抽卡 gacha

`roost module add gacha` 自动安装 wallet、bag；新 game 工程可直接生成和验收。协议 `GachaDraw` 只收请求键、池号和次数（1 或 10），玩家身份来自认证会话。

- 数据：`configs/table/gacha_pool.csv` 设置单抽金币价格、保底次数、保底道具、是否关闭；`gacha_drop.csv` 设置每个奖励的非负整数权重。`roost generate` 转换数据；运行时读本条请求固定的配置快照。概率为本项权重 / 本池总权重，零权重只从保底发出。每次给一个道具；自然抽到保底道具也重置计数，十连逐次判断保底。默认池单抽10金币、10抽保底，奖励使用 bag 自带的1001/1002/1003。
- 组件入口：`GachaComp().Draw(key, poolID, count)` 必须在 Player 的 Nest 事务内调用，拒绝必须返回 Nest。扣款、发奖、保底、回执一起提交或回滚；不用钱包的请求键账本。`Gacha` 同步给玩家，`GachaLedger` 只落库。
- 重放：键为1～64字节 ASCII 字母、数字或 `- _ :`。同键换池或次数拒绝；配置改变/下架后已成功请求仍回放原结果。只保留最近64次成功请求，窗口外旧键会成为新消费；拒绝不留回执。回执序号耗尽拒绝新请求。
- 容量：每池至多256行，每玩家至多记64个池的保底；删表行不会清除旧进度，池号不得复用。抽样前按每种候选奖品最多来 `count` 个、最多新增 `min(count, 未持有候选种类数)` 个种类保守检查空间，含零权重保底项；可能拒绝实际能装下的结果。这样无法利用塞满低价值奖品后失败零扣费反复筛选稀有奖品。
- 边界：普通随机在服务器内产生，不接受客户端种子。失败尝试没有持久结果，重试可重新抽样；已成功结果由回执固定。不包含付费渠道、卡牌实例/碎片转换、跨池继承保底、永久消费账本或可验证随机承诺。保底数据热更对下一次新抽卡生效，旧回执不重算。

`module verify gacha` 为24个独立场景、零跳过，覆盖正式PB/controller/Nest、精确权重区间、单抽/十连、保底、重放冲突、容量拒绝、提交回滚、并发重复与各上界。生成专项 `TestModuleGachaIdleScenariosAndMutations` 验默认CSV与可编译变异（延后一抽保底、扣费减半、权重边界错误），并检查build/vet/ID/漂移。以上为离线替身提交器，不代表真实存储与业务TCP验收。
