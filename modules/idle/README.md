# 离线收益 idle

`roost module add idle` 自动安装 wallet；`IdleClaim` 只收单调 `Sequence`，不接受客户端时间、离线时长或奖励。服务器以两次结算之间的时间惰性给金币，在线停留也累计，不判断网络在线状态，不使用定时器。

第一次 `Sequence=1` 只建立计时起点、不追溯建档前时间。之后每次新领取用当前 `Idle.Sequence+1`；最新一次重试返回原回包，更旧或跳号都拒绝。状态和最近一次回执恒定大小，旧序号永远不会重新消费新区间。客户端从自身视图取得最新序号；超时应先重试相同序号。

- 规则数据在 `game/entities/player/idle_rules.go`：默认每60秒1金币，最多累计8小时或480金币，可按玩家属性调整。变更会作用于未结算的整个区间，已领取结果不重算。
- 不满一周期的零头保留给下次。达到时间或金额上限时消费到当前服务器时间，丢弃超量和零头，领取后不会马上再领同一段。时钟早于已结算时刻时拒绝且零写入。
- `IdleComp().Claim(sequence, nowUnixMilli)` 仅在持有 Player 锁的 Nest 事务内使用；正式 handler 的 `nowUnixMilli` 由 Nest 冻结。发钱、游标、序号和回执同一事务；钱包溢出或提交拒绝全部回滚，之后可重试。序号耗尽拒绝新请求。
- `Idle` 是同步状态，`IdleReceipt` 只落库。模块不挂进入游戏钩子、不带在线/离线判定、加速道具、生产队列、多货币或离线时段分段规则；这些由工程扩展。

`module verify idle` 为19个独立场景、零跳过，覆盖正式PB/controller/Nest、首次初始化、零头合并、双上限、回拨、旧序号拒绝、并发重放、两类提交回滚和极大整数。`TestModuleGachaIdleScenariosAndMutations` 通过去掉上限游标推进、破坏最新序号回放两种可编译变异验证守卫有效。以上为离线替身提交器，不代表真实存储与业务TCP验收。
