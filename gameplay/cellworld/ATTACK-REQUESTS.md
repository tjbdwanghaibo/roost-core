# 分区攻击：客户端重试与准入回执

`AttackTargetRequest.RequestID`（protobuf 字段 2）标识**玩家的一次主动操作**，不是连接、包序号、目标、伤害推送或服务端的 HitID。

| 请求 | Base 行为 |
| --- | --- |
| 不带号 / 0 | 旧协议；每次调用是新的攻击，补发不安全。 |
| 新的正号、玩家在场且已知 owner | 在此玩家的 strict 事务里登记号、目标和完整 HitID；只有提交成功才发布这次攻击。 |
| 窗口内，同号同目标 | 返回原 HitID；不重发、不重算伤害、不重推结果。先查回执，再看当前场景路由，因此不必等重登后的 owner 通知。服务端伤害配置或面板变化不影响重放。 |
| 窗口内，同号不同目标 | `attack_request_conflict` (100904)；旧回执不改，不出手。 |
| 号已过期 | `attack_request_expired` (100903)；即使槽已覆盖，也绝不当成新攻击。不能据此断定原攻击命中或没命中。 |
| 负号 | `attack_request_invalid` (100902)；不出手。 |

**开号约定。** 同一玩家所有重连会话共用一个正 `int64` 名字空间；不同玩家互不影响。从 1 起，主动新攻击取下一个号。同一账号跨设备须协调分配；连接序号可以从头开始，攻击号不能。客户端在首次发送前保存号与目标；超时、丢应答、结果未知时只能用原号原目标重试，不能自动换号或退化到 0。耗尽后不能回绕。未持久保存客户端分配状态时不要猜测原操作号。

**有界且不依赖时钟。** 令 H 为该玩家已登记的最大正号。`id <= H-64` **先拒绝**；`id > H-64` 才查 `id % 64` 槽中的完整号。窗口内未使用的号可以乱序到达，跳号会相应推进窗口。只有新号成功准入才替换槽、推进 H；普通移动、无号攻击、重登均不触碰账本。例如 H=65 时 1 永久过期，2 仍可取回。每玩家最多 64 槽和一个不回退的高水位，无历史全表扫描，无需目标一直保留 HitID。更改窗口宽度 / 取模规则需要迁移，不能在已有存量上直接改常量。

**准入不是结算。** `AttackTargetResponse.Code == 0` 仅确认 Base 接受过此操作，`Seq/AttackID` 用于关联异步的 `AttackResultPush`。提交后的发包可能丢失；甚至可能在 WAL 落盘后、发布前退出。重放能找回回执，但不会再发攻击以“补救”这种不确定性。只有 Cell 的结论可以说明 `applied` / `rejected`；`unknown` 或未收到推送时保持未知。这里不提供可靠最终送达、结论重播或无限期查询。

**接入。** 普通 `Node.Attack` 与 `BasePlayer` 无需变更。带号请求走 `Node.AttackWithRequest`；玩家需实现可选 `AttackRequestPlayer`，把高水位和槽写入该玩家的持久私有 DAO。生成工程使用 `PlayerDao.CellworldBase`（`nosync`）；回滚还原槽、高水位和显示序号，没有提交后发件。手工接入若缺少持久账本则失败，绝不回退到内存去重或无号攻击。新客户端启用带号重试前必须完成服务器升级；旧服可能忽略未知 protobuf 字段。
